## MEDIUM

### M1 — `--check-commit` grades a staged rename by its destination only (ids 2, 8, 18)

- **Where:** `tools/unattended/unattended.sh:9742`.
- **What:** porcelain `git diff --cached --name-only` applies `diff.renames` (on by default), so `git mv <undeclared> <declared>/x` lists only the destination. Check 23 grades the same commit with `diff-tree --name-only -r` (`check-unattended.sh:3797`), which does no rename detection and lists both paths. The commit passes the commit-time check, then the close counts the source deletion when `--dispatch` can no longer widen the declaration. The close still grades it, so this is contained.
- **Fix (judged SOUND by the skeptic):** use `git diff --cached --no-renames --name-only -z` (or `git diff-index --cached --name-only HEAD`) and read the result NUL-delimited, which also stops paths with spaces or quotePath-escaped bytes from splitting.
- **Left-shift gate:** an arm that stages a `git mv` out of an undeclared path into a declared directory and expects exit 1. As a class gate, assert in one arm that `--check-commit` and check 23 produce the same path set for one staged-then-committed tree.

### M2 — `--check-commit` parses the `Pass:` trailer and the subject differently from the close (ids 3, 24)

- **Where:** `tools/unattended/unattended.sh:9720-9721`.
- **What:** `sed 's/^Pass: *//'` is case-sensitive, and `git interpret-trailers --parse` keeps the key as typed, so `pass: TOOL-x-2` yields no trailer. The subject is read as the first non-blank line only. `pass_commit` and `log_attribution_tokens` use `%(trailers:key=Pass)`, which matches the key case-insensitively, and `%s`, which joins the whole first paragraph. A lowercase trailer or a wrapped subject therefore exits 0 at commit time with no grading, then check 23 attributes and counts the write at the close. Spec 2's Edges say the commit-time step "reads the same trailer reader", and it does not.
- **Fix (judged SOUND by the skeptic, both):** put one `read_pass_trailer_ids` in `lib-unattended.sh` with a case-insensitive key and ids split on `[^A-Za-z0-9-]`, and call it from `pass_commit`, `log_attribution_tokens` and `verb_check_commit`, using `interpret-trailers --parse` for a message file and `%(trailers:key=Pass)` for a commit. Collapse the subject's first paragraph exactly as `%s` does, after stripping comments.
- **Left-shift gate:** arms for a lowercase `pass:` key, a comma-separated value and a wrapped subject, each asserting that `--check-commit` and `pass_commit` agree on the unit.

### M3 — check 23's ambiguity test still reads the subject of a trailered pass commit (id 9)

- **Where:** `tools/unattended/check-unattended.sh:3778` (block 3771-3784).
- **What:** `pass_commit` attributes a trailered commit by its trailer alone, but the ambiguity branch runs `id_in "$dshitsub" "$dssunit"` over every sibling. A commit with `Pass: A` whose subject mentions sibling B prints "one commit names two passes" and `continue`s, so A's subset test and `ds_pend` entry are skipped and its undeclared writes go uncounted. This contradicts spec 2 ("its subject is never read"). The block predates the diff, but the trailer rule made the miscount reachable.
- **Fix (finder's fix judged UNSOUND; skeptic's corrected fix):** when the pass commit carries a `Pass:` trailer, compute ambiguity from the trailer's ids: the commit is ambiguous only when the trailer also names a sibling unit of the group. Read it with the same `%(trailers:key=Pass,valueonly,separator=%x20)` walk `pass_commit` uses. Keep the subject test for untrailered commits.
- **Left-shift gate:** an `odrow` arm with two units at one anchor where A's commit carries `Pass: A` and a subject naming B, A writes outside its declaration, and the arm expects `check 23 FAILED`.

### M4 — amending a pass commit is refused as "no open dispatched pass" (id 10)

- **Left-shift gate:** an arm that amends a trailered pass commit without changing its staged set and expects exit 0.

### M8 — `resolve_generated_indexes` re-derives `MAP_ROOT` with its own awk (id 25)

- **Where:** `tools/unattended/lib-unattended.sh:534`.
- **What:** the awk keeps an inline comment and misses an `export` prefix, where `map_lib.load_conf` (`map_lib.py:181-211`) deliberately tolerates both to match bash sourcing. `MAP_ROOT=docs/map  # x` resolves to `docs/map  # x/generated`, the space-joined list word-splits, and a bare `docs/map` index then excuses every write under the map root. The lens that filed id 13 had this refuted as off-grammar input. Id 25 survived as MEDIUM because the canonical reader accepts that input, which makes this two readers of one config with one re-deriving it.
- **Fix (finder's fix judged UNSOUND; skeptic's corrected fix):** port `load_conf`'s rules into the awk rather than sourcing the conf. Strip `\r`, match `^[[:space:]]*(export[[:space:]]+)?MAP_ROOT=`, take the text after the first `=`, treat it as empty if it starts with whitespace, take up to the matching quote if it starts with a quote, otherwise take the first whitespace-delimited word. The last assignment wins, and the default is `memory/map`.
- **Left-shift gate:** arms for an inline comment, an `export` prefix and a CRLF conf, each asserting the awk and `load_conf` agree.

### M9 — govkit selfcheck 6c certifies a `[[generated]]` row the shell reader drops (id 26)

- **Where:** `tools/govkit/govkit.py:1993`.
- **What:** 6c flags only extra tokens matching `\{[a-z_]+\}`, while the resolver skips ANY row whose resolved path still holds `{` or `}`. `{MEMORY_ROOT}/x`, `{memory-root}/x` or an unbalanced brace passes selfcheck and is silently skipped at runtime, so its hook-forced writes later read as undeclared. That defeats spec 4 S5, whose purpose is to red a row the shell reader does not resolve.
- **Fix (judged SOUND by the skeptic):** grade the row as the reader does: `re.sub(r"\{(memory_root|map_root|kit)\}", "", _gp)` and fail if `{` or `}` remains.
- **Left-shift gate:** a selfcheck arm with an upper-case token and one with an unbalanced brace.
