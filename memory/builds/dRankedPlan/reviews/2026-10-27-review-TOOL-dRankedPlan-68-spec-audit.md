### H1 — Unit 70's AC2 does not check S2's four-argument class (ids 1, 16)

- **Where:** TOOL-dRankedPlan-70 §6 AC2, observing §2 S2; §7 New arm line.
- **What:** S2 says every `read_ts_expr_end` call in ratify.py passes four arguments. AC2 greps `read_ts_expr_end\(toks, [a-z_]+\)`, which matches only a two-argument call whose index is a bare lowercase name. `(toks, eq + 1)`, `(toks, i+1)`, `(toks, k2)`, `(toks, k, c)` and `(toks, k, conts=c)` all leave it at 0. The facts are optional in the signature (lexicon.py:1587), so each of those runs and silently drops facts. The second clause asks for at least one call and pins no count. AC2 runs once at the unit's tip and is no gate, so units 71 and 72, which rewrite the same calls later in order 24, are never checked against it.
- **Consequence:** A call that drops `lits`, or spells its index as an expression, reads a continued binding short, and the deny-by-default ban passes. AC2 still certifies the class.
- **Fix (skeptic judged it SOUND):** Count calls by argument count. An `ast` probe over ratify.py finds every Call whose function is `read_ts_expr_end` and asserts `len(args) + len(keywords) == 4`, with a pinned number of calls expected at the tip so an empty match cannot pass. Or state the check as a fixture arm of the loop selftest so it re-runs after units 71 and 72. The staged break: a three-argument `read_ts_expr_end(toks, k, c)` must redden it.
- **Left-shift gate:** A spec-audit check that a criterion observing an "every X" class enumerates X and asserts the property on each, rather than grepping for one bad spelling.
