## 1. Goal

The spec audit of units 30 to 37
(`memory/builds/dRankedPlan/reviews/2026-10-27-review-TOOL-dRankedPlan-30-spec-audit.md`) confirmed
**finding 1 at HIGH**, item **H1**. `TOOL-dRankedPlan-32` S5 supersedes unit 22 S2's caller sentence,
and its S2 counts a shell or `.githooks/` file as a caller only when one of its commands invokes
`ratify.py`. A `read_plan_ratification(` line in a hook stops counting. So `TOOL-dRankedPlan-31` AC3,
which plants exactly that line in `.githooks/pre-commit` and expects exit 1, cannot pass, and the
`caller-guard` plant and `TOOL-dRankedPlan-30` AC2 go green on an absence. A hook that calls the
predicate in process, through `python -c` or a heredoc, is read by neither reader. This unit puts unit
22's textual rule back for shell and hook files, beside unit 32's invocation rule, and widens it from a
call to any naming of the predicate, so the in-process forms are refused too. It repairs
`TOOL-dRankedPlan-32`, so it sits one order above it.

## 2. Scope (IN)

- **S1** — The textual rule. `read_shell_callers(path, text)` (`TOOL-dRankedPlan-32` S2, in
  `tools/loop/ratify.py`) also reports every line of the file whose first non-blank character is not
  `#` and which matches `\bread_plan_ratification\b`. The rule reads raw lines, so a line inside a
  heredoc body, a `python -c` string or a quoted argument counts. Unit 32 S2's invocation rule stands
  beside it, and a line either rule reports is reported once. This supersedes unit 32 S5 where it
  leaves unit 22 S2's code-line rule out of the shell and hook reading.
  Observed by AC1, AC2 and AC3.
- **S2** — The plants. Two cases join `ratify.py --fixture --plant <case>`, each in its own scratch
  repository laid out from `TOOL-dRankedPlan-30`'s anchors. Observed by AC1 and AC2.
  - `caller-hook-inline` plants a `.githooks/pre-commit` running `"$py" -c 'import sys;
    sys.path.insert(0, sys.argv[1]); from ratify import read_plan_ratification;
    sys.exit(read_plan_ratification(sys.argv[2]))' "$d" "$slug"`. It is refused.
  - `caller-hook-heredoc` plants a `.githooks/pre-commit` feeding `"$py" - "$slug" <<'EOF'` a body
    whose one code line is `from ratify import read_plan_ratification`. It is refused at the body's
    line.
- **S3** — The sibling criteria re-pinned. `TOOL-dRankedPlan-31` AC3, the `caller-guard` plant of
  `TOOL-dRankedPlan-22` S3 and `TOOL-dRankedPlan-30` AC2 each plant a `read_plan_ratification(` line in
  `.githooks/pre-commit`, and S1 is the rule that refuses it. None of their texts changes. Observed by
  AC3.

## 4. Design

### Evidence

- `TOOL-dRankedPlan-22` S2 defines a caller as a code line matching `\bread_plan_ratification\s*\(`,
  or a shell line invoking `ratify.py` with no `--` argument.
- `TOOL-dRankedPlan-32` S2 reads shell by command structure only, and S5 supersedes unit 22's
  sentence. Unit 32's own §7 arm still stages its break as "a predicate that matches only
  `read_plan_ratification(`".
- `TOOL-dRankedPlan-31` S4 and AC3, unit 22 S3's `caller-guard` and `TOOL-dRankedPlan-30` S3 and AC2
  each plant a `read_plan_ratification(` call in `.githooks/pre-commit` and expect a refusal.
- `git grep -n read_plan_ratification -- '*.sh' '.githooks/*'` printed nothing at base 0689e7fa, run
  2026-10-27, so the widened rule refuses no line of today's tree.

### The two rules side by side

| Hook line | Unit 32 S2 | S1 | Answer |
|---|---|---|---|
| `"$py" "$d/ratify.py" "$slug"` | invocation | no name | caller |
| `"$py" "$d/ratify.py" "$slug" --exit` | mode flag | no name | not a caller |
| `read_plan_ratification(slug)` inside `python -c` | no invocation | name | caller |
| a heredoc body line importing the name | not read | name | caller |
| `# read_plan_ratification is asked only at the act` | not read | comment | not a caller |

Widening `\s*\(` to `\b` follows unit 32 S1, which counts a reference whether called or not. The
in-process forms bind the name before they call it, so the binding line is what S1 refuses.

### Alternatives rejected

- **Respell unit 31 AC3 and the `caller-guard` plant in an invocation form.** The in-process hook form

- **Keep unit 22's `\s*\(`.** An `import` line in a heredoc or a `-c` string binds the name with no
  parenthesis after it, so the caller would be found only where it calls, and a call through an alias
  would pass.
