## 1. Goal

The round-1 spec audit (`memory/builds/dDeclaredLoop/reviews/2026-10-24-review-TOOL-dDeclaredLoop-1-spec-audit.md`)
confirmed finding **id 51 at HIGH**, its item **H17**, alone in that item; its shell-resolution half
is id 28 (item M21, MEDIUM), batched into `TOOL-dDeclaredLoop-56`. `TOOL-dDeclaredLoop-17` built
`tools/loop/loop_witness.py#run_witness_commands` as its spec drew it: each command runs through
`subprocess.run` with `shell=True`, its output captured through a pipe and a `timeout`, and the
`ponytail:` comment above that call names this unit as its replacement. On win32 CPython's `run`
kills the direct child on a timeout and then calls `communicate()` with no bound, which reads the pipe
until every holder closes it (`Lib/subprocess.py`, the `except TimeoutExpired` branch of `run`, read
2026-11-14 on Python 3.15.2). A grandchild holding the pipe therefore holds `loop_witness.py
acceptance`, `rerun` and the `loop computed witness` leg past the bound: the class
`memory/gotchas/bounded-through-a-pipe-is-unbounded.md` records, measured twice in this repository.
On win32 `shell=True` is cmd.exe, which cannot run the bash-syntax criteria every spec writes. This
unit takes the report's fix, carrying the run-gates kit's tree kill rather than writing a second one.
It repairs `TOOL-dDeclaredLoop-17`.

## 4. Design

### Evidence

- `tools/loop/loop_witness.py#run_witness_commands` at HEAD `51b1e1a28`: `subprocess.run(command,
  shell=True, cwd=tree, env=env, stdout=subprocess.PIPE, stderr=subprocess.STDOUT, timeout=timeout)`,
  a `TimeoutExpired` answered `timeout` with `exc.output`, then in its `finally` a `worktree remove
  --force`, `remove_tree` over the temporary directory and a `worktree prune`.
- `tools/run-gates/regen.py#run_command` is this repository's bounded runner: output to a
  `tempfile.TemporaryFile`, `start_new_session` on POSIX only, `wait(timeout=bound)`, and on expiry
  `tools/run-gates/regen.py#run_tree_kill`, which runs `taskkill /F /T /PID` on win32 or `os.killpg`
  with `SIGKILL` on POSIX, then `proc.kill()`, then a reap bounded by `wait(timeout=10)`, each step
  best effort. Its comment records the pipe defect measured on this platform, by that comment:
  6.5 s for `sleep 6 & wait` under a 1 s bound, PINNED there.
- The gotcha's measurement, in `memory/gotchas/bounded-through-a-pipe-is-unbounded.md`:
  `out=$(timeout 1 bash -c 'sleep 6 & exit 0')` returned after 6 s, PINNED, and in 0 s to a file.
- The module docstring of `tools/process-monitor/reap.py` records that `taskkill /PID <win> /T /F`
  killed one of four MSYS descendants, so on win32 the tree kill is best effort and the file redirect
  is what bounds the caller.
- `tools/loop/loop_witness.py#resolve_bash` keeps a candidate only when `test -f` on the script it is
  given exits 0 under it, so a WSL launcher that cannot open a `C:/` path is passed over.
- `tools/memory-tree/deviation_join.py#remove_tree` catches `OSError`, so a held directory is left in
  the temporary folder rather than raised.

### The run of one command

```python
bash = resolve_bash(pathlib.Path(__file__).absolute())     # once per call, before the worktree
if bash is None:
    raise LookupError("no bash that can see %s: GOV_BASH, PATH and Git for Windows looked in" % ...)
...
for n, command in enumerate(commands, 1):
    out = os.path.join(tmp, "cmd-%d.out" % n)               # beside the worktree, never inside it
    with open(out, "wb") as sink:
        p = subprocess.Popen([bash, "-c", command], cwd=tree, env=env, stdin=subprocess.DEVNULL,
                             stdout=sink, stderr=subprocess.STDOUT,
                             **({} if os.name == "nt" else {"start_new_session": True}))
        try:
            code = p.wait(timeout=timeout)
        except subprocess.TimeoutExpired:
            run_tree_kill(p)
            code = "timeout"
    with open(out, "rb") as fh:
        runs.append((command, code, hashlib.sha256(fh.read()).hexdigest()[:12]))
```

`signal` joins the module's imports, since the carried block reaches `signal.SIGKILL` on POSIX.

### The teardown

The `finally` keeps its three steps in order and then checks the directory:

```python
finally:
    if added:
        read_git(repo, "worktree", "remove", "--force", tree, env=env)
    remove_tree(tmp)
    read_git(repo, "worktree", "prune", env=env)
    if added and os.path.isdir(tree):
        print("%s: leaked %s" % (SAY, pathlib.Path(tree).as_posix()), file=sys.stderr)
```

### Alternatives rejected

- **`subprocess.run(..., capture_output=True, timeout=...)`.** It reads through pipes, and on win32,
  after the kill, `communicate` waits for an EOF a grandchild holds: the defect itself.
- **`shell=True`.** cmd.exe on win32 cannot run a criterion's bash syntax.
- **`CREATE_NEW_PROCESS_GROUP` on win32.** `taskkill /T` walks the Windows process tree without it, and
  the carried `run_tree_kill` does not use it; it only groups the child for console control events.
- **A separate second wait after the kill.** `run_tree_kill` already reaps under its own bound.
- **`sleep 600` in the grandchild plant, the audit's figure.** On win32 the grandchild may outlive the
  tree kill, so every selftest run would leave a ten-minute orphan holding a temporary directory; a
  grandchild three times the plant's bound keeps the red case apart and the orphan short.
