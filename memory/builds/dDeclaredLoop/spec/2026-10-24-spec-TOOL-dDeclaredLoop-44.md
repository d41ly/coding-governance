## 1. Goal

The round-1 spec audit (`memory/builds/dDeclaredLoop/reviews/2026-10-24-review-TOOL-dDeclaredLoop-1-spec-audit.md`)
confirmed finding **id 50 at HIGH**, its item **H16**, alone in that item. `TOOL-dDeclaredLoop-2` S6
grades "every commit in the range whose diff changes `.governance/policy.toml`" and never defines a
merge's diff, nor the all-zero base of a new branch. Its built arm, `tools/loop/guard.py#check_push_range`,
reads the range through `tools/memory-tree/commit_trailers.py#read_commits` with `--no-merges`, so
every merge is skipped. The lander's `--prepare` merges the run branch onto the advertised tip with
`git merge --no-ff` (`tools/push-main.sh#cmd_prepare`), and on a conflict it tells the operator to
reconcile on the branch by `git merge`, resolve and commit, which can edit the policy file inside the
merge. With merges skipped, that resolution edit lands with no trailer and no change record and
bypasses `floor.record-changes`; diffed against its first parent instead, a prepared merge carrying
another build's trailered change would be refused, wedging the landing. This unit takes the report's
fix. It repairs `TOOL-dDeclaredLoop-2`.

## 2. Scope (IN)

- **S1** — The range is every commit `read_commits` names over `<base>..<tip>`, merges included. A
  non-merge commit is graded on its diff against its one parent, as the built arm grades it today.
  Observed by AC1, AC2.
  **Readers:** by name: `tools/loop/guard.py`, the read in its push arm that passes the merge filter
  today, its one caller; by value: `.githooks/pre-push`, the policy push arm block, which turns the
  arm's exit into the `policy-unrecorded` refusal.
- **S2** — A merge commit is graded on git's combined diff,
  `git diff-tree --cc -r --name-only --no-commit-id <merge>`, which lists a path only when the merge's
  blob of it differs from every parent's. A merge that takes one side's policy file whole is not
  listed and owes nothing, since the side's own commits are graded in the range. Where the list holds
  `.governance/policy.toml` and the first parent holds the file, the merge owes what a non-merge commit
  owes, keys read against its first parent: one `Gov-Policy:` trailer line per changed leaf, and a
  change record naming each leaf's row among the change records the same list holds at the merge
  (§8 F2). A missing one is refused naming the merge, the key and that the change is the merge's own.
  A first parent lacking the file is printed and not graded, as a non-merge adding commit is.
  Observed by AC1, AC2.
- **S3** — An all-zero base, a new ref, reads as the landed revision the policy kit's
  `tools/policy/policy.py#derive_landed_revision` returns: `refs/remotes/<remote>/<branch>` by the
  remote ladder that module carries inline, the `remote_ladder_py` block. Its `Refusal`, a ref that
  names no commit or a ladder that cannot choose a remote, is an exit 2 naming the refusal and so the
  ref, never a grade of the whole history. Observed by AC3.
- **S4** — The plants `push-merge-carries-trailered`, `push-merge-resolution-edit` and
  `push-new-branch` join `PLANTS` in `tools/loop/guard.py` and its `run_selftest` owed exits.
  Observed by AC1, AC2, AC3.
- **S5** — `help/policy.md`'s push-check paragraph says how a merge is graded, and the comment over
  the policy push arm block in `.githooks/pre-push` points at `guard.py` for the commits it grades
  rather than restating them. NOT OBSERVED by a criterion: prose, held by the `docs` leg and read at
  the closing review.

## 4. Design

### Evidence

- `tools/loop/guard.py#check_push_range` calls `read_commits` over `--no-merges` and the range with
  the key `Gov-Policy`, grades each commit whose first parent holds the file and whose blob differs,
  and catches `LookupError`, `LoopError`, `OSError` and `ValueError` as exit 2. The policy kit's
  `Refusal` is none of those, so S3's call catches it beside them.
- `tools/loop/guard.py#read_added_units` reads the records a commit adds through
  `git diff-tree -r --root --name-only --diff-filter=A <sha>`, which prints nothing for a merge.
- Probed 2026-11-15 on node `d`, git 2.54.0.windows.1, in a scratch repository: a `--no-ff` merge
  taking a side's policy file whole printed no path for `git diff-tree --cc -r --name-only`; a merge
  whose resolution edited the file and added a record printed both paths; the `--diff-filter=A`
  read above printed nothing for either merge; `git log` over an all-zero sha and `..HEAD` exited
  128 naming an invalid revision range. PINNED, that date.
- A clean merge in which each side changed the file also lists it (the round-2 spec audit's id 17),
  which S2 grades against the first parent until `TOOL-dDeclaredLoop-59` restates the grade.
- `tools/policy/policy.py#derive_landed_revision` returns the sha of `refs/remotes/<remote>/<branch>`
  and raises a `Refusal` naming that ref when it names no commit; with no remote it reads the local
  `refs/heads/<branch>`. `check_push_range` already holds the module through `read_policy_modules`.
- The lander's prepare and reconcile both merge with `git merge --no-ff` and a fixed message
  (`tools/push-main.sh#cmd_prepare`, and the reconcile loop of `tools/push-main.sh` that prints
  `reconcile CONFLICT`), so neither writes a trailer onto its merge.

### The rule

| Commit | Diff graded | Owed |
|---|---|---|
| non-merge changing the file | against its parent | trailer and record on that commit |
| merge whose combined diff lists the file | against its first parent | trailer and record on the merge, the record among the combined list's paths |
| merge whose combined diff omits the file | none | none: each side's commit carries its own |
| new ref (all-zero old sha) | `<landed revision>..<tip>` | per the rows above |
