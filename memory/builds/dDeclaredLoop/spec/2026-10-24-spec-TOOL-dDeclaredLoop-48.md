## 1. Goal

The round-1 spec audit (`memory/builds/dDeclaredLoop/reviews/2026-10-24-review-TOOL-dDeclaredLoop-1-spec-audit.md`)
confirmed finding **id 7 at HIGH**, its item **H7**, alone in that item. As `TOOL-dDeclaredLoop-30`
landed, `tools/loop/budget.py#record_draw` refuses every draw where `transitions.record` selects no
`log`, before it reads any home. The policy catalogue admits any non-empty subset of `trailer`, `log`
and `micro-format` (`tools/policy/catalogue.toml`, the `transitions.record` row), and architecture v2's
first preset column sets `trailer` alone, as the audit's H7 cites. Under such a set the driver refuses
every second review round and every second dispatch of a unit
(`tools/unattended/unattended.sh#verb_review`, `tools/unattended/unattended.sh#verb_dispatch`), and the
transition writer refuses every backward move, since `tools/loop/loop_transition.py#write_transition`
raises on the refused route-back draw: a legal policy value stalls builds. This unit gives the budget a
home under every set that stores a move, so no draw is refused for the set. It repairs
`TOOL-dDeclaredLoop-30`.

## 4. Design

### Evidence

Read on branch `unattended-declared-loop-d56bf0` at `b1d66ba26` through `git show`, its product code
unchanged since `50f5dea5d`, the commit that landed `TOOL-dDeclaredLoop-30`.

- `tools/loop/budget.py#record_draw` reads `read_record_channels` at HEAD and raises where `log` is
  absent, ahead of the patch origin and the home. With `lines` given it extends them and writes no file;
  otherwise it appends to the home `read_budget_rows` names, committing a log record alone with
  `git commit --only`.
- `tools/loop/budget.py#read_budget_rows` takes the rows of the build's log records where it holds any,
  and otherwise its `carried` rows, those of its `RUN.md` and each rotated `RUN.LANDED.*.md` beside it,
  sorted by stamp. Its `home` is the newest record, else `RUN.md` where it is a file, else none.
- `tools/loop/loop_transition.py#write_transition` resolves an anchor only where `log` is chosen, so
  under a set without it no record is written. Its budget rows then go to `RUN.md`; a route-back draw
  with neither an anchor nor `RUN.md` is refused, and the freeze row is written only where one of the two
  exists.
- `tools/loop/loop_transition.py#parse_transition_trailer` refuses a field outside `TRANSITION_FIELDS`,
  and `tools/loop/loop_transition.py#read_transition_commits` turns that refusal into a finding and
  leaves the move out of `read_transitions`, which is why S2 registers both names.
- `tools/memory-tree/commit_trailers.py#read_commits` returns each commit's committer `date` in ISO
  form, the stamp S5 orders a trailer row by.
- `TOOL-dDeclaredLoop-3` §4 "The trailer": a value matches `[A-Za-z0-9._:+@-]+`, which is why S2 joins
  its parts with `@` and `+` rather than ` · ` or `/`. A cause never holds `@`, so a `draw` value
  splits at its first `@` and its last, whatever `@` the item holds.

### Where a draw goes

The build is the one whose budget is drawn, a patch build's originating build for a patch draw.

| Set holds `log` | The build holds a log record | Drawn by | Home |
|---|---|---|---|
| yes | yes | any | the newest record, as landed |
| yes | no | any | `RUN.md`, as landed |
| no | yes | the transition writer | the newest record, staged into the move's commit |
| no | yes | `budget.py draw` | the newest record, committed alone, as landed |
| no | no | the transition writer | the move's trailer where the set holds `trailer`, else `RUN.md` |
| no | no | `budget.py draw` | `RUN.md` |
| no | no | a patch build, either site | the patch build's own `RUN.md`, each row suffixed ` · budget <origin>` |

A patch build's draw from the transition writer is written by `record_draw` itself, as landed, so it
takes the last row; the writer adds no field for it.

### Data model

```
budget · frozen · <units> unit(s) · <total>          budget=frozen@<units>@<total>
draw · <cause> · <item> · <spent>/<total>            draw=<cause>@<item>@<spent>+<total>
<ts> draw · patch:<patch slug> · <item> · <spent>/<total> · budget <origin>     in the patch build's RUN.md
```

A move carries at most one field of each name: a backward move draws once and owes a freeze row with
it only as the first recorded move of a build that defines a spec (`TOOL-dDeclaredLoop-30` S2), and the
move into `building` writes the freeze alone.

### The writer

`write_transition` reads the build's log records once where its set holds no `log`. One predicate says
whether the move has a home for its rows: an anchor, a newest record, the trailer under a set holding
`trailer`, or `RUN.md`. The route-back refusal and the freeze row both read it. After the record write,
where rows remain and no record was written: a newest record takes them through `write_budget_rows`,
staged beside the move's other files, its prior bytes written back where the move does not commit, as
`record_draw` restores them; the trailer takes them as `move.update(render_budget_fields(rows))`, before
the commit renders the trailer; `RUN.md` takes them through `write_budget_rows`, as landed.
`render_budget_fields` and `write_budget_rows` are imported inside the function beside the landed budget
imports, since `budget.py` imports this module.

### Alternatives rejected

- **The run-state file alone.** The writer has no caller in the driver (`TOOL-dDeclaredLoop-30` §3), so
  every route-back is attended, and an attended build has no `RUN.md` unless a run is live; it would
  still be refused.
- **A separate `budget` record kind.** It departs from the clause's "one per build in its transition
  record", where the trailer channel is a transition record and a new kind is not.
- **Trailer rows read beside log records.** A record's rows carry no stamp, so a trailer row could not be
  ordered against them (§8 F3).
- **The writer committing a log-dropped draw alone through `record_draw`.** A move refused after the
  draw would leave the draw spent; staged into the move's commit, the two land or fail together.
- **A patch build's writer draw on its own trailer.** The originating build's reader would walk every
  build's trailers and derive each one's origin; the patch run's `RUN.md` is one glob (§8 F4).

## 5. Production-readiness checklist

- security — the two trailer fields are derived, a `--field` giving either refused, and every value is
  held to `VALUE` by `render_budget_fields` at the write boundary; the suffix's slug is the origin
  `derive_patch_origin` reads, never a caller's value.
- perf / scale — a build holding no log record adds one `git log --grep` over its trailers per
  `read_budget_rows` call and one read of each build's `RUN.md` under the root; a build holding a record
  reads as landed.
- error / empty / loading states — the refusals that stand: a build with no home under its set, and a
  patch build with no `RUN.md` under a set without `log`. A trailer value or a row outside its grammar
  refuses naming its commit or its row.
- observability — every home holds one row grammar, and `budget.py draw` prints the row it wrote, its
  suffix included.
- risks — what this change could newly red, and what keeps each green, each read on branch
  `unattended-declared-loop-d56bf0` at `b1d66ba26`:
  - `loop budget fixtures`: every plant but `no-log` runs the default set, where no home moves; the two
    new populations add rows only where a trailer carries `budget` or `draw` or a `RUN.md` carries
    ` · budget <slug>`, which no other plant writes. `stale-verdict` and `route-backs` call `record_draw`
    directly, and `driver-draws` reads its rows from `RUN.md`, as landed.
  - `loop transition record`: every plant but `subset-trailer-line` runs the default set, so no field is
    written, and `subset-trailer-line` records one forward move from `planning`, which neither draws nor
    freezes. The `field` plant's `colour=red` refusal prints the longer `TRANSITION_FIELDS` list, and its
    case reads `colour` alone. `check`'s field-by-field compare reads only trailers whose commit's set
    holds `log`, which never carry the fields.
