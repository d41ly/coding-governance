## 1. Goal

The round-1 spec audit (`memory/builds/dDeclaredLoop/reviews/2026-10-24-review-TOOL-dDeclaredLoop-1-spec-audit-round1.md`)
confirmed finding **id 7 at HIGH**, its item **H7**, alone in that item. `TOOL-dDeclaredLoop-30` S9
refuses every draw when `transitions.record` excludes `log`. `TOOL-dDeclaredLoop-3` S4 and
architecture v2 admit any non-empty subset, and v2's first preset column sets `trailer` alone. Under
that preset, or any owner choice without `log`, every second review round, fix pass, re-dispatch and
route-back is refused, because each draw site stops on a failed draw: a legal policy value stalls
builds. This unit gives the budget a home in each channel the set can select, so no draw is refused for
the set. It repairs `TOOL-dDeclaredLoop-30`.

## 2. Scope (IN)

- **S1** — Where `log` is selected, the rows stay where `TOOL-dDeclaredLoop-30` S3 puts them, on the
  build's newest `transition` log record. Observed by AC1.
- **S2** — Where `log` is not selected, a draw made by the transition writer rides that transition's own
  `Gov-Transition` trailer as the extension field `draw=<cause>@<item>@<spent>+<total>`, and the freeze
  of `TOOL-dDeclaredLoop-30` S2 rides the trailer of the transition into `building` as
  `budget=frozen@<units>@<total>`; both names join `TRANSITION_FIELDS` in
  `tools/loop/loop_transition.py`, the tuple `TOOL-dDeclaredLoop-3` §4 says later units extend, and both
  values keep to that unit's value grammar `[A-Za-z0-9._:+@-]+`. Observed by AC1, AC2.
- **S3** — Where `log` is not selected, a draw made by a driver verb (`verb_review`, `verb_dispatch`) is
  appended to the run-state file of the run that made it, in `TOOL-dDeclaredLoop-30` S9's row grammar,
  with ` · budget <slug>` added when the budget drawn is another build's, a patch build's draw on its
  originating build. Observed by AC1, AC3.
- **S4** — The reader `budget_state` reads the rows of every home a build's budget can have, in commit
  order: its log records, the `draw` and `budget` fields of its `Gov-Transition` trailers read through
  `TOOL-dDeclaredLoop-23`'s `read_commits`, its own run-state file, and every run-state row under
  `memory/builds/*/RUN.md` naming `budget <slug>`. This supersedes `TOOL-dDeclaredLoop-30` S9's refusal of
  a set without `log`. Observed by AC1, AC3.

## 4. Design

### Evidence

- `TOOL-dDeclaredLoop-3` §4 "The trailer": every field but `build`, `item` and `sha` must be in
  `TRANSITION_FIELDS`, which later units extend, and a value matches `[A-Za-z0-9._:+@-]+`, which is why
  S2 joins its parts with `@` and `+` rather than ` · ` or `/`.
- The draw sites are `verb_review` and `verb_dispatch` in the driver, the transition writer of
  `TOOL-dDeclaredLoop-10`, and a probe re-entry, which is itself a transition (`TOOL-dDeclaredLoop-30` S4):
  a driver verb runs inside a run, which has a run-state file, and every other site writes a transition
  commit.

### Where a draw goes

| `log` selected | Draw site | Home |
|---|---|---|
| yes | any | the newest `transition` log record (`TOOL-dDeclaredLoop-30` S3) |
| no | the transition writer | the transition's `Gov-Transition` trailer, field `draw` |
| no | a driver verb | the run's run-state file, S9's grammar |
| either | before the first log record | the run-state file (`TOOL-dDeclaredLoop-30` S9, unchanged) |

### Files touched (estimate)

- `tools/loop/budget.py`
- `tools/loop/loop_transition.py`

### Alternatives rejected

- **The run-state file alone.** An attended route-back writes a transition commit and has no run-state
  file, so it would still be refused.
- **A separate `budget` record kind.** It departs from the clause's "one per build in its transition
  record", where the trailer channel is a transition record and a new kind is not.

## 5. Production-readiness checklist

- security — no new write surface: the trailer field and the run-state row are channels that already
  exist and are written by their own writers.
- perf / scale — `budget_state` adds one trailer read and a glob of run-state files per call.
- error / empty / loading states — a draw under any legal set is written somewhere; a run-state row
  naming an unknown build is read for that build only.
- observability — each home prints the same row grammar on `budget_state --rows`.
- risks — a patch build's rows live in its own run-state file; S4's glob is how the originating build
  reads them.
- testing — AC1 to AC3 as fixture plants; the arm under §7, observed at the close.
- migration — none: no budget row exists yet.
- user docs — the budget section of `help/loop.md`, `TOOL-dDeclaredLoop-30` S10's, names the homes.

  patch run's run-state file carries the row with ` · budget <origin>`, and the originating build's
  `budget_state` counts it.
  Red when: the row is written and the originating build's reader never sees it.
