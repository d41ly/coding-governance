## 1. Goal

Every witness the loop declares names its class, `history`, `hook-record` or `remote-verdict`; the
`actor` class, a fact the acting agent typed, is refused, and today's actor witnesses sit on a
shrink-only list, each row naming the build whose computed witness takes its place (the dClosedLoop
walkthrough, item 6). Guards today read agent-written state across stages (`gap-spine-02`), and the
driver's `tools/unattended/unattended.sh#checker_of` answers `machine` for a Definition-of-Done entry
that declares no class, without saying so.

## 4. Design

### Data model

```toml
# tools/loop/loop.toml
[witnesses]
classes = ["history", "hook-record", "remote-verdict"]
refused = ["actor"]

[[witness-alias]]          # the checker words of DOD_CORE in the unattended driver
word = "machine"
means = "history"

[[witness-alias]]
word = "agent"
means = "actor"

[[step]]
tag = "step.plan"
order = 1
state = "planning"
exit = "item.plan.exit"
witness = { class = "history", by = "the transition record into the next step" }
```

`tools/loop/actor-witnesses.txt` holds rows and nothing else, so `cut` reads it whole:

```
DOD_CORE	keepalive-reaped	dWellOiledMachine
DOD_CORE	parked-decisions-surfaced	dShippedRelease
```

| Class | What witnesses it (the dClosedLoop orientation record, its `[trust]` section) |
|---|---|
| `history` | a commit, its trailers, a tracked file at a SHA, a ref |
| `hook-record` | a record a hook writes, which the acting agent cannot type |
| `remote-verdict` | a verdict keyed by tree fingerprint from the remote's runner |
| `actor` (refused) | a status word, a typed return, an attestation by the acting agent |

### The checks

`check_witness_classes(data, where)` grades `[witnesses]`, then every `[[witness-alias]]` row, then
every `[[step]]` row's `witness`, and returns `(site, class, by)` per witness, a step's site being its
`tag`. Each refusal is a `LoopError` naming the file and the row, as `check_loop`'s are.

The alias rows. `tools/loop/loop_lib.py#check_loop` grades `[[disposition-alias]]` inline today: a
row's `word` is no member and no earlier row's, and its `means` is a member. The witness table is the
second instance, so the loop over rows moves into one function, `check_alias_rows(rows, members,
table, where)`, which `check_loop` calls for the disposition table with byte-identical messages and
`check_witness_classes` calls for `witness-alias` with the classes and the refused word as members.
`resolve_disposition`'s walk over the rows is the same shape and calls `resolve_alias(rows, word)`.

`check_actor_list(rows, base_rows, sites, root)` returns one refusal per S3 case. `base_rows` is None
for no comparison. `sites` maps each definition site to its witnesses' classes.

The base. `read_actor_base(kit_dir)` returns `(rows or None, why)`. The repository root and the
list's root-relative path come from `git -C <kit_dir> rev-parse --show-toplevel` and
`--show-prefix`, never a typed prefix. It finds the memory-tree kit with an inline copy of
`resolve_kit_dir`, between the canonical's `# >>> resolve_kit_dir` markers, imports
`resolve_compare_base` from that kit's `coverage_join.py` inside the function, and reads the list at
the base with `git show <base>:<rel>`, naming `encoding="utf-8"` on every text read. The import is
local to the function, so a reader that copies `loop_lib.py` alone and calls `load_loop` never
reaches it.

Under `--fixture`, the base is the shipped list as read, so only a plant moves it, and nothing runs
git. The plants are `witness-no-class`, `witness-bad-class` (class `agent-said`),
`witness-actor-unlisted` (step.plan's class set to `actor`), `witness-actor-listed` (that, and a list
row `step.plan\tstep.plan\tdWellOiledMachine` added to both the list and its base),
`actor-list-grown` (a row the base lacks), `actor-list-stale` (a row `step.design\tstep.design\t
dWellOiledMachine` in both, whose site holds a `history` witness) and `actor-list-no-build` (a row
naming `dNoSuchBuild` in both).

### The declaration-site join, `--grade-site`

`check_site_witnesses(kit_dir, site, entries)` returns `(lines, refusals)`. `site` must be one of
`DECLARATION_SITES`, else the verb exits 2. An entry is `<item>` or `<item>:<word>`, the shape
`DOD_CORE` and `DOD_EXTRA` are written in. The word resolves through `[[witness-alias]]` alone, so
only `machine` and `agent` pass at this unit. The list is read from the loop kit's own directory, so
the verb runs no git and needs no base. It prints `loop: site <site> · <item> · <word> · <class>`
per entry, with `· until <build>` on an actor entry, then each refusal as `loop: refused · ...`, and
exits 0, 1 on a refusal, 2 on usage.

### Check 53, the unattended side

A new block after the 28 region of `tools/unattended/check-unattended.sh`, opened by
`if check_selected 53; then` and the header line `# ---- check 53 - ...` that `--only` reads, the
shape checks 50, 51 and 52 take. It resolves a python with `resolve_python` and the loop kit with
`resolve_kit_dir "$_py" loop loop_lib.py "$HERE"`, the call `scan_foreign_anchors` makes for the
memory-tree kit, and runs `--grade-site DOD_CORE $DOD_CORE`, then `--grade-site DOD_EXTRA
$DOD_EXTRA` where that is not blank. It reads `$DOD_CORE`, set from the driver before the core block,
and `$DOD_EXTRA`, set from the conf, and never `$DOD`, which the core block sets and `--only 53`
skips. It decides on the exit code alone and strips CRs from the output it quotes. Two branches, each
one `fail 53` call site: exit 1, quoting the loop kit's refusal lines; and no python, no loop kit or
any other exit, naming which. Both are armed in `check-unattended.test.sh` (§7).

### The silent default

```bash
# tools/unattended/unattended.sh#checker_of, at HEAD
checker_of()  { local p; for p in $(dod); do case "$p" in "$1:"*) printf '%s' "${p#*:}"; return;; esac; done; printf 'machine'; }
# after: an entry that declares no class has no checker
checker_of()  { local p; for p in $(dod); do case "$p" in "$1:"*) printf '%s' "${p#*:}"; return 0;; esac; done; return 1; }
```

Every caller reaches it only for a declared entry. `verb_abort` asks for the two `agent` items of
`DOD_CORE` by name. `verb_attest` and the override pass of `verb_close` first match `" $item:"`
against `dod`, which an unclassed entry never matches. The walk of `verb_close` over `dod` passes an
unclassed entry's empty checker to `dod_met`, and check 53 refuses that entry before a run reads it.
The driver runs under `set -u` without `set -e`, so the new return ends no verb.

### The leg's refusal ceiling

`.memory-tree.conf`'s `REFUSAL_CEILINGS` budgets the leg at 264, under decision
`TOOL-aSparedSpawn-14`, and the leg's census is 264 at HEAD `157293192`: 264 `fail <n> "` call sites,
and its one `status=1` line is the `fail` helper's definition, which signature 1 keeps
(`tools/memory-tree/check-arms.py#discover`, its signature 2 note in the module docstring). Check 53's
two sites make 266, which `tools/memory-tree/check-arms.py#cmd_check` reds. A one-site check 53 still
makes 265. The driver's change adds no site: `return 1` is neither `exit 1` nor `status=1`.

**The retirement review** (`tools/memory-tree/README.md`, "Retiring a refusal, and the ceiling on
adding one"). A site is a candidate only when R1 to R4 all hold, so a row that fails R3 or R4 is not a
candidate, whatever R1 and R2 read. The population is check 53's two sites and the leg's sites that
grade the Definition-of-Done set. Those are the sites check 53 could absorb, and the shape
TOOL-dTrueNorth-27 reviewed, which was its own new sites.
