## 1. Goal

`TOOL-dDeclaredLoop-53` looked for `memory/builds/<slug>/README.md`, so in a tree whose `MEMORY_ROOT` is

under a root that is not `memory`, so the rule is observed in the adopter shape the finding named. It
repairs `TOOL-dDeclaredLoop-53`.

### The line

```
read_breakpoints(build, root, spec_audit, delegated), after TOOL-dDeclaredLoop-53's release:
  each owner gate line (cause autonomy) whose release reads held, the opening read None
      -> line["unopened"] = <memory root>/builds/<slug>/README.md, relative to root, /-separated
list --build <slug>:
  the breakpoint: lines, as TOOL-dDeclaredLoop-19 prints them
  some line carries unopened -> breakpoints: held · no commit adds <that path>       once, last
```

The path is the one `TOOL-dDeclaredLoop-53`'s opening read built, so no git read and no conf read is
added. The owner item, cause `ratification`, never carries the key: the placement rule does not reach it
(`TOOL-dDeclaredLoop-53` §8 F5). The head `breakpoints:` is not `breakpoint: `, so a reader that selects
owner or review lines by their head does not select this one. And the line prints only beside an owner
gate that reads `held`, so a reader that took it for a held line would refuse only what that gate already
holds.

### The plant

`pre-placement-records-root` stages the history `TOOL-dDeclaredLoop-53`'s `pre-placement` plant stages,
that staging taking the memory root and the builds' README paths as arguments rather than copied (M5).
After the kits' commit, which is the placement, it writes `.memory-tree.conf` as `MEMORY_ROOT=records`
and commits it with the policy file that staging commits, `autonomy = "three-gates"` among its keys. On
the root commit the kits' commit does not precede it adds `records/builds/tRec/README.md` and
`memory/builds/tWrong/README.md`, and merges that line in with `--allow-unrelated-histories`. It runs the
scratch's own copy of the module in the scratch, lists `tRec` and `tWrong`, then commits the policy
file's deletion and lists `tWrong` again.

### Alternatives rejected

- **The path in the release field**, rev-3's `held — no commit adds <path>`. The holders compare the
  release to `held`; a longer release can fall out of an exact compare and release a gate that holds
  (§8 F2).
- **A sixth field on the owner line.** It moves the line grammar `TOOL-dDeclaredLoop-19` fixes at five
  fields, which a reader matching the line's end would misread.
- **Asking the driver for the root.** No driver verb prints it; the root read is
  `TOOL-dDeclaredLoop-53`'s, and the driver's own root is `TOOL-dDeclaredLoop-72`'s question.
- **Treating a missing README commit as pre-placement.** It would exempt every build of a tree whose
  root is misread, the silent exemption `TOOL-dDeclaredLoop-53` S3 refuses.

## 5. Production-readiness checklist

  hold stays conservative where the README is not found.
- perf / scale — no read added; the path is the one the opening read built.

  the driver's readers of the new line; §4 "The line" is why they cannot release a gate.

- migration — none.
