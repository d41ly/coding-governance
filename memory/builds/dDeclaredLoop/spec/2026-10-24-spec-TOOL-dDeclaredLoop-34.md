## 1. Goal

Who may approve a departure is a policy value, `deviation.approval`, read by the deviation join's
approver check, with each of its values graded: `by-risk` (an editorial deviation its author's,
by dOrderedCharter's classifier and not by the record's own word; an additive or stricter one the spec
writer's with the changed sections re-audited at the new revision; a loosening or breaking one the
owner's), `owner-all`, and `author-recorded` (the owner's FQ-3, P41; v2:1293). At HEAD the value is a
CLI flag, `--approval`, parsed in `tools/memory-tree/deviation_join.py#main` with `author-recorded` its
default. `tools/memory-tree/deviation_join.py#APPROVALS` holds no `owner-all`, the editorial class is
the record's own word, and nothing asks for the re-audit. The key's catalogue row is already written
(`tools/policy/catalogue.toml`, default `by-risk`, owner dDeclaredLoop), and no tracked code reads it.

## 2. Scope (IN)

- **S1** — The value's reader, `read_approval(root)` in `tools/memory-tree/deviation_join.py`, returns
  the value and its source. It finds the policy kit with
  `backlog.resolve_kit_dir("policy", "policy.py", KIT)` and imports it in process, as `tools/memory-tree/gen_build_index.py#read_slot_mode` and
  `tools/memory-tree/gotchas.py#read_universal_cap` import that kit's caps module. It calls
  `policy.resolve("deviation.approval", str(root))` with the key as the call's string literal, the
  shape `tools/policy/check_policy.py#scan_reader_keys` counts as a reader. With no revision passed the
  resolver reads the landed revision (`tools/policy/policy.py#derive_landed_revision`), so a run's
  branch never sets its own approval value. The pair is the returned `Resolution`'s value and reason.
  A `policy.Refusal`, or a value outside `APPROVALS`, which only a catalogue row widened past this
  module can answer, raises `Unmeasured` naming the key and why, exit 2. Where the kit does not
  resolve, a `LookupError` or an `ImportError`, the pair is `by-risk` and a source saying the policy kit
  is not installed. `APPROVALS` gains `owner-all`. Observed by AC1, AC7 and AC9.
- **S2** — The flag `--approval` retires. The CLI, `--fixture` and the self-test read the value from
  the repository they grade, through S1. Each fixture repository commits `.governance/policy.toml` in
  its base commit on `main`, the landed revision of a fixture with no remote and the commit
  `add_fixture_remote` points the remote's `main` at, setting the value its plant declares (S8).
  `render_lines` keeps its `approval` argument, so an arm may grade one fixture under a named value,
  and gains a `source` keyword it prints beside the value.
  **Readers:** by name: `tools/memory-tree/deviation_join.py` (the usage block of its docstring, the comment above PLANT_EXITS, and in main the argument table and the calls passing the parsed value) and `tools/memory-tree/README.md` (the module's row, which names the flag and its default).
  by value: `tools/memory-tree/deviation_join.py#check_approver` compares the value with by-risk, reached through render_lines and check_approvers, and `tools/memory-tree/deviation_join.py#run_fixture` passes it on.
  Observed by AC1.
- **S3** — `owner-all`: `tools/memory-tree/deviation_join.py#check_approver` refuses every record whose
  approver is not the owner, naming its role and `owner-all`, and grades every owner approval by the
  decision-row citation it already grades under every value. Observed by AC2.
- **S4** — The editorial class from the classifier. Under `by-risk`, a record whose risk reads
  `editorial` is graded editorial only when dOrderedCharter-33 S1's `derive_change_mark`, over the
  record's `Before` and `After` texts, returns `editorial`. Otherwise the record is refused, naming the
  record and the first differing word, so an author cannot approve a semantic change by calling it
  editorial. `read_change_mark(before, after)` finds `pins.py` with
  `backlog.resolve_kit_dir("playbook", "pins.py", KIT)`, the resolver `tools/memory-tree/deviation_join.py#read_gen_region_awk` already calls
  for the unattended kit, and runs it as a subprocess, never imported, since a kit imports no sibling
  kit's code (TOOL-dGroundRules-1 §4), the way dOrderedCharter-33 S7 runs its `drift` verb. The verb it
  runs is the ask §8 F6 picks, `pins.py mark --before <path> --after <path>`, over the texts
  written to temporary files. At HEAD `tools/playbook/pins.py#main` answers `drift` and `--fixture`
  alone, and the ask is not filed (§8 F9), so S4, AC3 and AC4 wait on it. Where the playbook kit does
  not resolve, the typed risk stands and one line says so. A call that exits non-zero refuses the
  editorial claim, naming the exit and the first line the verb printed. Observed by AC3, AC4 and AC8.
- **S5** — The re-audit at the new revision. Under `by-risk`, a record at risk `additive` or `stricter`
  approved by the spec writer is refused by `check_reaudit` unless a bound `spec-audit` record pins the
  unit it departs at a revision past the departed one. For `Departs from` `<unit>@rev-<N>` the unit is
  that unit and the revision N. For a clause, the unit is the chain spec whose `**Carries:**` line
  names it, read with `tools/memory-tree/design_lib.py#parse_binding_lines` over the specs
  `read_population` keeps, and the pin must reach the first revision whose text carries the clause at
  a hash other than the departed one, read from the revisions `read_population` already holds

  the clause. The pins are the ones `tools/memory-tree/deviation_join.py#read_population` already

  bound audit record pins, and `check_approver` reads the facts. No plant observes the clause half,
  because the fixture's specs carry no `**Carries:**` line. Observed by AC5 and AC6.
- **S6** — The owner's ruling quoted: under every value, an owner approval cites a decision id whose

- **S8** — The plants, through `python tools/memory-tree/deviation_join.py --fixture --plant <case>`:

- **S9** — The key documented where its readers look: the `deviation.approval` row of

## 3. Non-goals (OUT)

- No classifier: `derive_change_mark` and its spelling map are dOrderedCharter-33's, called and never

- No change to the record grammar or the risk vocabulary, the deviation kind's closed `Risk` set in
  `tools/memory-tree/build_records.py#KINDS`.
- No write to the chain's records: a record graded under the new terms and found short is listed for
  its writer under `report`.
- No edit of the frozen instrument `deviations.py`, which grades `author-recorded` only (packet,
  Non-goals).
- No help page of the join's own: no page under `help/` describes the deviation join. S9's section of
  `help/reference/policy.md` documents the key, and `tools/memory-tree/README.md`'s module row names it.

## 4. Design

### The approver, by value

| Value | Least approver | Extra terms |
|---|---|---|
| `by-risk` | `LEAST[risk]` (`tools/memory-tree/deviation_join.py#LEAST`), the owner when the cause is an owner ruling | S4's classifier on an `editorial` claim; S5's re-audit on a spec writer's `additive` or `stricter` |
| `owner-all` | the owner, for every record | none |
| `author-recorded` | any role the grammar names | none |

Every value keeps the refusals `check_approver` already makes: an approver opening with no role,
and an owner approval citing no held decision row naming the departure.

### Where the value comes from

```
read_approval(root) -> (value, source)
  the policy kit imports -> policy.resolve("deviation.approval", str(root)) at the landed revision:
                            (its value, its reason), the file's value or the catalogue default
  the reader refuses     -> Unmeasured naming deviation.approval and the refusal, exit 2
  a value not in APPROVALS -> Unmeasured naming deviation.approval and the value, exit 2
  the kit does not resolve -> ("by-risk", "the policy kit is not installed; this module's fallback")
```

`render_lines` prints `approval <value> (<source>)` in its summary line, so a reader sees which value
graded the records and why. The CLI and `run_fixture` call `read_approval` once per run; the host
passes `HOST_APPROVAL` and its ruling as the source.

### The re-audit and the classifier

`check_reaudit(rec, facts)` returns why the record's spec writer approval lacks its re-audit, or None,
reading `facts["audited"]`, the carrying specs and their revisions, which `read_population` hands on.
`read_change_mark(before, after)` returns the mark and the first differing word, or raises naming the
exit and the verb's first printed line. Each runs only under `by-risk`, and only for the records its
term names.

### The fixture's value

`build_fixture` writes `.governance/policy.toml` holding `deviation.approval = "<value>"` in the
commit that declares the design keys, on `main`, before the run's branch is cut. The fixture's landed
revision is that commit with no remote and after `add_fixture_remote`, so every plant's value is read
where the live join reads gov's. The base also writes, after the last revision of each unit a spec
writer approves a departure from, a `spec-audit` record pinning that unit past the departed revision
(§8 F7), so no audit member is added and `BASE_MEMBERS` holds.

### Alternatives rejected

- **The host reads the key too.** Gov's catalogue default is `by-risk`, and the owner ruled the chain
  runs `author-recorded` (`PLAY-dClosedLoop-4`); the guarded policy file is the owner's to set, so the
  host keeps the ruling as its override until the chain closes.

  actor-typed claim the classifier exists to check.
- **The value read at the fixture's HEAD.** The plant's file could ride the run's branch, but the live
  join would then read whatever a branch commits; the landed revision is where the decision rows are
  read too (`tools/memory-tree/deviation_join.py#read_decision_ref`).
