## 1. Goal

A new kit, `tools/loop/`, holds the loop's definition: the five gov steps keyed by their stage tags
and the order each roles workflow runs in. The roles kit's `stage` integers move into it in this same
unit, and every reader of them is re-pointed here, never waiting for a live build's close
(`gap-spine-01`: no kit declares the stage it serves, and the loop exists only implicitly). The loop
kit owns WHAT runs and in which step; the roles kit keeps WHO (walkthrough.md:119-125, S1b).

## 4. Design

### Data model

```toml
# tools/loop/loop.toml — the loop's definition, read only through loop_lib.py
[[step]]
tag = "step.plan"        # a `step` namespace member (TOOL-dDeclaredLoop-18's extract_step)
order = 1
state = "planning"       # shared interface I3
exit = "item.plan.exit"  # the step's exit item, a tag in the `item` namespace

[[workflow]]             # the roles kit's stage table, moved
name = "spec-write"      # a roles workflow, the join key to tools/roles/workflows.toml
order = 3                # the moved `stage` integer, 0 for an any-time workflow
step = "step.design"     # the step the workflow serves, or "none"
```

| Step | `order` | `state` | `exit` |
|---|---|---|---|
| `step.plan` | 1 | `planning` | `item.plan.exit` |
| `step.design` | 2 | `designing` | `item.design.exit` |
| `step.build` | 3 | `building` | `item.build.exit` |
| `step.test` | 4 | `testing` | `item.test.exit` |
| `step.deploy` | 5 | `deploying` | `item.deploy.close` |

The exit items are flow-steps' `plan.exit`, `design.exit`, `build.exit`, `test.exit` and
`deploy.close`, spelled as tags (I2). This unit names them; the items themselves are
TOOL-dDeclaredLoop-12's rows, and a fixture witness stands in for each until its build lands
(TOOL-dDeclaredLoop-13).

### The phase-and-stage mapping (shared interface I3)

Unattended's UPPERCASE phases are run positions, not build states. Each maps onto a state or step:

| `PHASES_CORE` member (`tools/unattended/unattended.sh:852`) | Build state | Step |
|---|---|---|
| `PREFLIGHT` | none: the run's own preflight, before its build's state is read | none |
| `RESEARCHING` | `designing` | `step.design`: M12 research inside a spec pass |
| `TESTING` | `designing` | `step.design`: M12 candidate testing, never the Test step |
| `SPECCING` | `designing` | `step.design` |
| `REVIEWING` | `designing` | `step.design`: the spec audit |
| `FOLDING` | `designing` | `step.design` |
| `BUILDING` | `building` | `step.build` |
| `RUNNING` | `building` | `step.build`: a recipe run's pieces |
| `HELD` | `paused` | the step it held in |
| `VERIFYING` | `testing` | `step.test` |
| `LANDING` | `deploying` | `step.deploy` |
| `LANDED` | `landed` | none: terminal |
| `ABORTED` | `withdrawn` | none: terminal |

The roles stage integers map by the `step` column of the table above. The states are I3's spelling,
owned by TOOL-dDeclaredLoop-13's tables; this table is what that unit reads for the stand-in.
