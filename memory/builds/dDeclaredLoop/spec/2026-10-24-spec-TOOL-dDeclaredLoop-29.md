## 2. Scope (IN)

## 4. Design

### Data model

The schema's new row, beside `needs`:


An item carrying both gates; TOML 1.0, which `tomllib` reads, admits no inline table spanning lines,
so each entry is one line:

```toml
[[item]]
tag = "item.design.unit-spec"
# ... the row's other keys ...
outcomes = ["authored", "feature-fork", "finding"]
routes = { authored = "item.design.recommend", feature-fork = "item.design.decompose", finding = "item.design.decompose" }

  { item = "item.design.seams", gate = "record" },
  { item = "item.design.research", gate = "measured", measured-by = "memory/builds/<slug>/build/<record>.md", measured-line = "## Verdict: CLEAN" },
```

### The join

`check_upstream_answers(rows, answers, gates)` returns `(verdict, lines)`. It walks the handed ids in
order and the answered ids in order, and every id lands in exactly one of answered, `dropped`,
`invented` or `doubled`; an answered row is then graded `bad-answer` or `no-reason` where it fails.
Findings print as `upstream · finding · <class> · <row id> · <reason or the class's sentence>`,
answered rows as `upstream · <row id> · <answer> · <reason>`, and the verdict last as
`upstream · verdict · <verdict>`. `verdict` is `refused` with any finding other than `bypassed` on a
`measured` edge, else `finding` when any finding stands, else `clean`. `join` exits 1 on `refused` and
0 otherwise. `rows` exits 1 on a refused hand-on, and both verbs exit 2 on a usage error or a
composition that does not read; each prints a refusal as `upstream · refused · <why>`.

### The load checks

`check_upstream_rows(rows, root)` reads every composed row's `upstream` and refuses: a value that is
not a list of inline tables; an entry key outside `item`, `gate`, `measured-by` and `measured-line`; a
gate outside `record` and `measured`; an upstream item no composed row declares, or named twice; a
measurement key on a `record` entry; a `measured` entry whose `measured-by` HEAD holds no blob for, or
whose blob holds no line equal to `measured-line`; and an item with a non-empty `upstream` whose
outcome set lacks `finding`. Each refusal names the item, the upstream item where there is one, and
the key at fault. Git is read in one `read_blobs_at` batch, and not at all with no `measured` entry.

### The plants

`--fixture --plant <case>` runs one case; `--selftest` runs them all, each owing its exit and a line.
The handed rows are the three of "Data model".

| Case | Plant | Outcome |
|---|---|---|
| `clean` | every row answered `used` with a reason, on the `measured` edge | exit 0, `upstream · verdict · clean` |
| `drop-gating` | `must-2` unanswered, on a `measured` edge whose record holds its line | exit 1, `upstream · finding · dropped · item.design.seams#must-2` |
| `drop-recorded` | the same return on a `record` edge | exit 0, the same finding line |
| `bypassed` | `seam-1` `bypassed` with a reason, on each edge in turn | exit 0 on both, its finding line and `upstream · verdict · finding` |
| `invented` | a further answer for `item.design.seams#seam-9` | exit 1, `invented` and that id |
