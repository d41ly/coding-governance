## 1. Goal

A witness that decides a route is computed, never typed by the agent it judges (P2, `gap-flow-14`).
Three witnesses the clause names become computed: a unit's acceptance, re-run at its commit by a
command that writes `record-kind.acceptance`; a probe's commands, re-run at the probe's pinned SHA and
compared by output hash; and a red's attribution, joined to the run's own claim that a red is
inherited. The attest door already refuses every item whose witness is not `actor` (§8 F7). The
executor that owns `item.build.acceptance` is outside this build (v2's `gap-orient-08` entry places
it in dWellOiledMachine), so this unit declares the record and the computed witness kinds and arms
the stand-ins that build's executor takes over (I22).

## 4. Design

### The acceptance record

```
# TOOL-dExample-3 acceptance 1 — re-run at 3f9c2a71

**Serves:** acceptance TOOL-dExample-3

- **Sha:** 3f9c2a710b8e4d0c95f1e2a3b4c5d6e7f8091a2b
- **Writer:** stand-in
- **Caused-by:** TOOL-dExample-3

run · 0 · 9b1f04c2e7aa · python loop_table.py check
run · 1 · 41d2c0b9f310 · python loop_table.py --fixture --plant missing-row
```

The heading and the `**Serves:**` line are `write_record`'s, as for every typed kind. The unit is
`Caused-by` and the file name's, so the record carries no `Unit` field beside them. `Sha` is the full
commit the re-run read, resolved by the stand-in and never taken as typed. The record says what ran and
what came back; whether exit 1 was the expected answer is the criterion's, which the record keeps the
command for.

`write_record(root, build, unit, kind, title, fields, today=None, lines=())` gains `lines`, written
after one blank line below the fields. Each line is refused as a value is, before any write: a CR or an
LF, or a line that would read as a field. `write_acceptance(root, build, unit, sha, writer, runs,
today=None)` validates the three fields and each run at the write boundary and calls it, the title
naming the SHA's first eight hex digits. `read_acceptance(path, text)` is `read_record` with the kind's
own rules: `Sha` matches `SHA40`, at least one line reads `RUN_LINE`, `run · <exit> · <hash> ·
<command>`, the exit an integer or `timeout` and the hash twelve hex digits, and every line opening
`run ·` matches it. The `read` verb's dispatch gains the `acceptance` branch, since its fall-through
reads a record through `read_exception`.

### The re-run

```python
def run_witness_commands(repo, sha, commands, timeout=600):
    """[(command, exit, hash12)] for each command run in a detached worktree of `sha`."""
```

The worktree is added with `git worktree add --detach <tmp> <sha>` under `tempfile.mkdtemp()` and
removed with `git worktree remove --force` in a `finally`, so a crashed command leaves no worktree
registered. Each command runs through the platform shell with the worktree as its directory and every
name of the memory-tree kit's `GIT_ENV_LEAKS` (`tools/memory-tree/tree_lib.py#GIT_ENV_LEAKS`) unset,
read through the kit `resolve_kit_dir` finds, as `tools/loop/loop_lib.py#read_actor_base` reads that
kit. A timeout kills the command and records exit `timeout`. Output is hashed raw, so a command whose
output carries a timestamp is `refuted` on every re-run, which the stand-in reports rather than
normalises. The default timeout is 600 seconds PINNED at rev-1.

### The two stand-ins

`acceptance` resolves `--sha` with `git rev-parse --verify <sha>^{commit}` in the tree at `--root`,
runs S2 there and calls `write_acceptance` from the memory-tree kit `resolve_kit_dir` finds, then
prints `loop-witness: wrote <path>` and one line per run, exit 0. It exits 2 on a usage error, no
`--cmd` or a SHA that does not resolve, and 1 where `write_acceptance` refuses, writing nothing.

`rerun` takes one `--expect` per `--cmd`, paired in order, and prints `loop-witness: rerun · <verdict>
· <exit> · <hash> · <command>` per command. It exits 0 when every verdict is `confirmed`, 1 otherwise,
and 2 on a usage error, an unpaired `--cmd` included.

### The red-attribution join

In `run_hold`, after the vocabulary and hand-off-code refusals and before any write:

```bash
if [ "$code" = inherited-red ]; then
  check_inherited_override "$rel" "--hold --code inherited-red" record-only || return 1
fi
```

`record-only` is the tie `check_handoff_bar` passes: the run commits the record `gates-green` staged
before it may hold, which moves `HEAD` off the bar's head by that record and by the paths the bar's
run record lists in `staged` (`check_bar_tied`'s comment). That comment names `--handoff` as the one
caller passing the tie, and gains `--hold --code inherited-red` beside it. Without the join the code
is a sentence the run types; with it, the runner's attribution decides it.

### The staged set of a held close

`dod_met` reads a red bar's record through `read_gates_record` and, for the `land`, `hold` and
`other` states, calls `write_inherited_asks`, which stages the build's `BACKLOG.md` rows and the
views it re-renders. Only the `land` state then calls `write_gates_staged`. Under the `park` policy
the close prints the hold line, the run commits the staged records, and the tie excludes the run-state
file alone, so the `BACKLOG.md` row reads as a change the bar never graded and S5 would refuse the
hold the close prescribes. S6 makes the `hold` state call `write_gates_staged "$_gdir" "$WI_STAGED"`
too, and `write_gates_staged`'s comment names both states.

### The computed witness kinds

```toml
[[computed-witness]]
name = "acceptance"
serves = "item.build.acceptance"
writer = "stand-in:{prefix}/loop/loop_witness.py"
armed-by = "dWellOiledMachine"
```

| `name` | `serves` | `writer` | `armed-by` |
|---|---|---|---|
| `acceptance` | `item.build.acceptance` | `stand-in:{prefix}/loop/loop_witness.py` | dWellOiledMachine |
| `probe-rerun` | `none` | `stand-in:{prefix}/loop/loop_witness.py` | dPlacedRequest |
| `red-attribution` | `item.test.route` | `stand-in:{prefix}/run-gates/run-gates.sh` | dWitnessedBar |

The rows sit after the `[[witness-alias]]` rows, before the `[[item]]` rows the definition's header
keeps last, and the header comment gains the table's keys. `check_computed_witnesses(data, where)`
refuses, with `LoopError` naming the row: a `name` outside `SEG` or given twice; a `serves` that is
neither `none` nor the tag of a declared `[[item]]` row; a served item whose witness class is in
`[witnesses]`'s `refused`; a `writer` that neither matches `ROUTE_STAND_IN` nor is `<kind>:<name>` of
`ACTOR_KINDS`; and an empty `armed-by`. `read_computed_witnesses(kit_dir)` returns the rows graded,
each with its `class` derived from its served item's witness, `none` for a row serving `none`. Neither
runs inside `load_loop`, so the readers that copy the module keep reading. `--check` prints one
`loop: computed-witness <name> · serves <tag> · class <class> · writer <writer> · armed by <build>`
line per row after the actor-list lines, and a refusal as `loop: refused · ...`, exit 1. Two plants
join `PLANTS`: `computed-actor`, the acceptance row's served item's witness class set to `actor` in
memory, and `computed-unserved`, its `serves` set to `item.build.acceptanc`.

`TOOL-dDeclaredLoop-45` reads the `acceptance` row's `writer`: a `stand-in:` value leaves the
acceptance half of `built` unarmed.

### The leg and its plants

`loop_witness.py --fixture --plant <case>` runs one plant in a scratch repository under the host temp
directory, and `--selftest` runs every plant in order, printing a `PASS` or `FAIL` line each, exit 0
