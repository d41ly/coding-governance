### The line

```
loop: budget · drawn · draw · fix-pass · TOOL-tFix-3 · 3/4
loop: budget · disagrees · draw · fix-pass · TOOL-tFix-2 · 1/4 · typed 1, derived 2
```

The verdict line is first in every answer, then one `disagrees` line per row whose typed spent is not its
ordinal, in the order the reader read the rows. An `exhausted` verdict is followed the same way; a
refusal raises before any note exists and prints its one line.

### The plant

```
write_budget_plant(top, "parallel-append"); move to planning      -> the build's first record, <rel>
attr = git check-attr merge -- <rel>, asked at this kit's repository top
attr not unspecified/unset  -> fixture .gitattributes "<rel> merge=<attr>", committed
git branch side; draw TOOL-<fx>-1 on main            -> 1/4, committed
git checkout side; draw TOOL-<fx>-2                  -> 1/4, committed
git checkout main; read_git(top, "merge", "--no-edit", "side")  -> rc
budget_state                                         -> unfrozen 2/4
draw TOOL-<fx>-3 through the draw verb               -> drawn 3/4, then typed 1, derived 2
```

The repository top is `read_git(KIT, "rev-parse", "--show-toplevel")`, so the answer is this tree's
`.gitattributes` and not a literal in the plant. Where the kit sits in no repository, or the answer is
`unspecified`, the fixture gets no attribute and the merge conflicts, which the plant reports as MISSED
naming the answer. A ValueError from `budget_state` is caught and reported as MISSED naming it, so the
refusal the branch tip carries reads as a miss and not a traceback.

### Alternatives rejected

- **Keeping the typed-figure refusal.** Two parallel worktrees both type `1/4`; after a union merge the
  second row disagrees with its derived 2, and the refusal wedges every later read of the build.
- **Comparing the typed total.** Every row drawn before the freeze carries the base, so every recorded
  build that froze after a draw would print a line per such row.
- **Ordering rows by the commit that wrote each, rev-2's S1.** `spent` is a count, and no answer reads a
  row's place except the advisory line, which the reader's own order serves.
- **A fixture attribute written as a literal `merge=union`.** It passes with the tree's line deleted, so
  the plant would never see S3 red.
- **One budget record per build.** It moves where the rows live, `TOOL-dDeclaredLoop-48`'s concern.
