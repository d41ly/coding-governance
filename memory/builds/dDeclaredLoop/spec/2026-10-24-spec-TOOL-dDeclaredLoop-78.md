## 1. Goal

The round-4 spec audit (`memory/builds/dDeclaredLoop/reviews/2026-10-24-review-TOOL-dDeclaredLoop-68-spec-audit.md`)
confirmed finding **id 33 at HIGH**, its item **H3**, alone in that item. `TOOL-dDeclaredLoop-69` grades
a two-parent merge against its clean re-merge C wherever `TOOL-dDeclaredLoop-59`'s `read_remerge_policy`
answers a table, and falls to the parent branch, where the parent-equality exemption still applies,
wherever it answers none. When the audit ran, neither spec said whether a clean re-merge whose tree
lacks the policy path is a table or none. Read as none, it reopens the path 69 closes: main deletes or
empties the policy file, a run branch that never touched it merges main, the resolution keeps the run
branch's bytes, blob(M) equals that parent's, the merge is skipped, and the old policy keys reach main
with no `Gov-Policy:` trailer.

59 rev-4 S2 now reads a tree lacking the file as the empty table, so that half of the reading is 59's
and this unit does not restate it. Two parts of the finding stay open. 59 S3 still sends a re-merge
whose policy file does not parse to the parent branch, so a clean merge that yields a broken file
reopens the same exemption. And no plant observes a deleted or emptied file at C, so nothing goes red
if a later edit reads either as none.

This unit names C's three states once, refuses a `present` C that does not parse instead of falling to
the parents, and plants the deleted, emptied and both-absent histories. It repairs
`TOOL-dDeclaredLoop-69`.

## 4. Design

### Evidence

Every code claim below was read on `branch/unattended-declared-loop-d56bf0` at `a2ad508e9` through
`git show`; this worktree is cut from main, which lacks the loop kit.

- Probed 2026-10-24 on node `d`, git 2.54.0.windows.1, in a scratch repository under `%TEMP%`: PINNED,
  that date. With `p.toml` deleted on `main` and untouched on `run`, `git merge-tree --write-tree main run`
  exited 0 and `git ls-tree` of the printed tree held no `p.toml`: the `absent` state. With `p.toml`
  deleted on `main` and modified on `run`, `git merge-tree --write-tree --name-only main run` exited 1,
  listed `p.toml` among the conflicted paths and printed `CONFLICT (modify/delete)`, leaving run's
  version in the tree, so the conflict list and not a parse decides computability once 75 S27 admits
  exit 1.
- Probed 2026-11-15 on node `d`, Python 3.15.2, PINNED, that date: `tomllib.loads` raised
  `TOMLDecodeError: Cannot declare ('a',) twice` over a text declaring one table at two places with
  another table between them, and answered `{}` over empty text. So a clean merge of two sides that
  each declare the same new table apart is a `present` C that does not parse, and an emptied file is a
  `present` C with no keys.
- `tools/loop/guard.py#check_push_range`, built by `TOOL-dDeclaredLoop-44`, reads a merge only where
  `git diff-tree --cc` lists the policy file, skips a commit whose first parent lacks the file, and
  adds the finding `<kind> <sha8> · <policy path> does not parse on one side, so its changed keys are
  unknown` where either side does not parse. It makes no `merge-tree` call at that tip.
- `tools/loop/guard.py#parse_policy_bytes` answers `{}` for a missing blob and None for bytes that do
  not decode or parse, catching both errors, so no parse raises. `tools/loop/guard.py#read_policy_blob`
  reads `<rev>:<path>`, which a tree id names as well as a commit.
- `tools/policy/guard.py#derive_leaf_changes` answers each differing leaf as `(old, new)`, None for
  absent, so with an empty C every leaf M holds is owed, and two empty tables owe none.
- `tools/loop/guard.py#run_fixture` exits as the last scenario did when every one held, else 3, and
  `tools/loop/guard.py#run_selftest` owes each plant its owed-map exit, 0 by default.
- `TOOL-dDeclaredLoop-59` rev-4 S2 and S3, unbuilt at that tip, add `read_remerge_policy(parents)`: the
  clean re-merge's parsed table, a tree lacking the file read as the empty table, or none with a reason,
  one reason being a re-merge whose policy file does not parse. `TOOL-dDeclaredLoop-69` rev-3 S1 and S2,
  unbuilt, grade a table C by `derive_leaf_changes(C, m)` past 44's pre-filter and keep 59's grade for
  none. This spec is written on those committed texts.

### The grade, restated

```
for merge M in the range, with parents P1..Pn:
    blob(P1) is none -> 44's printed line, not graded                          # 44, unchanged
    state, C = read_remerge_policy(P1..Pn)                                     # 59 S2, its state named (S1)
        uncomputable   n != 2, merge-tree --write-tree missing, or it exits != 0, with 59 S3's reason
        absent         it exits 0 and its tree lacks the policy path; C = {}
        present        it exits 0 and its tree holds the policy path; C = its blob parsed
    present and C does not parse -> finding "does not parse at C"; next merge  # this unit (S3)
    if state is present or absent:                                            # 69 S1, unchanged
        m = parse(blob(M)); none -> finding "does not parse at M"
        owed = derive_leaf_changes(C, m)
    else:                                                                      # 59 S2, S3 and 69 S2, unchanged
        M or a parent that does not parse -> finding "does not parse at M" or "at parent <sha8>"
        owed = the leaves equal to no parent's value
    each owed leaf: the trailer and the record 69 owes
```

### The plants

Each plant builds on 59's plant base, the policy text 59's plants pass to `write_guard_plant`, setting
`budgets."AGENTS.md"`, `review.max-rounds` and `review.design.rounds` on lines git merges apart. `run`
is cut from the base, commits one file outside the policy file, and merges `main` with `--no-ff`. Each
range runs from main's tip to run's tip, the range its landing pushes, so main's own commits are
outside it. Every non-merge commit in a range carries its trailer and its change record.

| Plant | History | Owed |
|---|---|---|
| `push-merge-resurrect-deleted-policy` | `main` deletes the policy file; `run` merges with `--no-commit`, takes back its own policy file and commits with no trailer or record | exit 1, naming `merge <sha8> · .governance/policy.toml · review.max-rounds` |
| `push-merge-resurrect-emptied-policy` | as the first, `main` emptying the policy file to no keys instead | exit 1, naming the same |
| `push-merge-both-absent` | `main` deletes the policy file; `run` merges it cleanly, taking the deletion | exit 0, naming `0 finding(s)` |
| `push-merge-unparseable-c` | `main` and `run` each declare the same table the base lacks, with a key a catalogue row names, at places git merges apart, so each side's file parses and git's clean merge declares that table twice; `run` merges with `--no-commit`, takes back its own policy file and commits with no trailer or record | exit 1, naming `does not parse at C` |

In the first, second and fourth, the merge's policy blob equals its first parent's, so 44's combined
list never names it and 59's parent branch skips it.

### Alternatives rejected

- **Reading a missing path as an empty file.** It answers the same keys but makes "absent at M and at C"
