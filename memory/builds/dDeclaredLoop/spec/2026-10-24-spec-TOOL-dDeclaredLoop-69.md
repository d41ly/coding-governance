## 1. Goal

confirmed finding **id 2 at HIGH**, its item **H2**, alone in that item. `TOOL-dDeclaredLoop-59` S1 owes

`TOOL-dDeclaredLoop-44`'s combined-diff pre-filter, which reads a merge only where its policy blob

## 4. Design

### Evidence

Every code claim below was read on `branch/unattended-declared-loop-d56bf0` at `f395dba68` through
`git show`; this worktree is cut from main, which lacks the loop kit.

- `tools/loop/guard.py#check_push_range`, built by `TOOL-dDeclaredLoop-44`, reads a merge only where
  `git diff-tree --cc -r --name-only --no-commit-id` lists the policy file. It skips a commit whose
  first parent lacks the file, printing it where the commit adds the file, skips one whose blob equals
  the first parent's, and grades
  the leaves `derive_leaf_changes` returns with the first parent as the old side. Each changed leaf owes
  the trailer `render_policy_trailer` renders and a record whose tag `derive_row_tag` names among
  `read_added_units` of the combined list. Its docstring says a merge taking one side's file whole
  owes nothing. So the revert merge, whose blob equals its first parent's, is skipped twice over.
- `TOOL-dDeclaredLoop-59` rev-4, unbuilt at that tip, adds `read_remerge_policy(parents)`: the clean
  re-merge's parsed table from `git merge-tree --write-tree`, a tree lacking the file read as the empty
  table, or none with S3's reason. Its grade intersects the leaf changes from every parent and from C,
  behind 44's pre-filter, and keeps the first parent's value as a trailer's old value (59 §4 The grade).
- `tools/policy/guard.py#derive_leaf_changes` returns each differing leaf as `(old value, new value)`,
  `None` for absent, so with C as its old side it yields C's value as each leaf's old value.
  `tools/loop/guard.py#parse_policy_bytes` reads a missing blob as `{}` and an unparsable one as `None`.
- `tools/push-main.sh#cmd_prepare` lands with `git merge --no-ff` onto the advertised tip and refuses on
  a conflict, so a landing merge is git's clean merge and equals C at the policy file.
- `tools/loop/guard.py#run_fixture` prints `all held` when every scenario held and exits as the last
  scenario did; `tools/loop/guard.py#run_selftest` owes each plant its owed-map exit, 0 by default.
- No scratch probe was run: the harness refuses git outside this worktree. 59 §4 records the
  `merge-tree --write-tree` probe, PINNED 2026-10-24, and AC1's red observation is this unit's probe
  that the combined list never names the revert merge.

### The grade, restated

```
for merge M in the range, with parents P1..Pn:
    old = blob(P1); old is none -> 44's printed line, not graded
    listed = the --cc name list of M                         # 44, still read for the records
    C = read_remerge_policy(P1..Pn)                          # 59 S2: a table, or none and a reason
    if C is a table:                                         # this unit
        m = parse(blob(M)); m is none -> the arm's does-not-parse finding
        owed = derive_leaf_changes(C, m)                     # each leaf (val(C,k), val(M,k))
    else:                                                    # 59 S2 and S3, unchanged
        skip unless the policy file is in listed and blob(M) != old
        print 59 S3's line naming the reason
        owed = the leaves equal to no parent's value, each (val(P1,k), val(M,k))
    each owed leaf: the trailer render_policy_trailer(k, its old, val(M,k)) and a record naming
        derive_row_tag(k) among read_added_units(M, listed); each missing one is a finding
```

An absent key reads as its own value on both branches, as 59 §4 states. The summary line's
`changing` count takes a merge on the C branch only where its owed set is non-empty or its file does
not parse; on the parents branch it counts as 44 counts.
