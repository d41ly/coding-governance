## 1. Goal

The round-1 spec audit (`memory/builds/dDeclaredLoop/reviews/2026-10-24-review-TOOL-dDeclaredLoop-1-spec-audit-round1.md`)
confirmed finding **id 25 at HIGH**, its item **H11**, alone in that item; its canary half is id 36
(item M17, MEDIUM), batched into `TOOL-dDeclaredLoop-56`. `TOOL-dDeclaredLoop-4` writes `stage` on every
`tools/gate-legs.json` row and admits it to both canary `KNOWN` copies, and stops at gov's manifest:
no `[[gate_leg]]` table of a kit descriptor declares it, `write_gate_legs` builds an adopter's row from a
fixed key set without it (`tools/govkit/govkit.py#write_gate_legs`), and selfcheck 7h compares
descriptor and manifest one field at a time with no `stage` arm (`tools/govkit/govkit.py#selfcheck`).
So every leg gov ships reaches an adopter with no stage claim, and the two spellings of each claim can
disagree silently. This unit carries the claim the way `subject`, `doc_reads` and `ceiling` already
travel: on the descriptor, graded by 7h, written by the emitter under a runner-version floor, and that
floor named by a runner version this unit moves. It repairs `TOOL-dDeclaredLoop-4`.

### Alternatives rejected

- **Leaving the version to the lander's mint.** The floor is a constant written at build time, and the
  value a landing mints depends on the default branch's tip at that landing, so the floor could not
  name it.
- **Keeping the claims out of the manifest, as `[[leg]]` rows in `tools/loop/loop.toml`.** A second
  table keyed by leg name beside the manifest is two spellings of one fact with nothing comparing them.
- **Falling back to gov's manifest in the emitter.** `ceiling` is carried from the descriptor with no
  fallback, for the reason its comment in `write_gate_legs` gives; `stage` follows.
- **Recording `stage` in the receipt's emitted record.** The receipt's fields feed the drift compare
  and the keep rule, and neither reads a stage, so the field would be read by nothing.

## 5. Production-readiness checklist

- error / empty / loading states — below the floor, or with no value on the table, the key is omitted;
  an unreadable runner version reads below the floor, as for every sibling key.
- observability — 7h's line names the entry, the leg and both values; a below-floor omission prints
  nothing (§8 F4).
