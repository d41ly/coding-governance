## 1. Goal

The round-1 spec audit (`memory/builds/dDeclaredLoop/reviews/2026-10-24-review-TOOL-dDeclaredLoop-1-spec-audit.md`,
its item H5) confirmed finding **id 5 at HIGH**. `TOOL-dDeclaredLoop-33` S2 requires every state of a
level to reach a terminal. `[states]` in `tools/loop/loop.toml` declares feature and unit states that end
at `deployed`, while its one terminal key, `terminal`, lists the build's terminals alone
(`tools/loop/loop_table.py#read_transition_rows`). So `TOOL-dDeclaredLoop-33`, built at order 34 on its
rev-6, walks the build level and prints the feature and unit levels unchecked (its §8 F11). This unit
declares a terminal set per level, reads it through one reader, keys the from-terminal refusal by level,
and runs the termination rule over all three tables. It takes the report's first fix and repairs
`TOOL-dDeclaredLoop-33`.

## 2. Scope (IN)

- **S1** — Two keys in `[states]` of `tools/loop/loop.toml`, §4 "Data model": `feature-terminal =
  ["deployed"]` and `unit-terminal = ["deployed"]`, each member a state of that level's own list. The
  build level keeps `terminal` as it stands. The file's `[states]` comment names the two keys. Observed
  by AC1.
- **S2** — The reader. `tools/loop/loop_table.py#read_transition_rows` splits every `[states]` key ending
  `-terminal` out of the levels, as it splits `terminal`, into a new `level-terminal` entry keyed by the
  level each key names. `tables["states"]` keeps `build`, `feature` and `unit`, and `tables["terminal"]`
  stays the build's list. `read_terminal_set(tables, level)` in the same module returns
  `tables["terminal"]` for `build` and the level's `level-terminal` entry otherwise, and raises
  ValueError naming the level and its key where the set is absent. Observed by AC1, AC2.
- **S3** — The refusals, in `tools/loop/loop_table.py#check_transition_tables`. Each level's set is read
  through `read_terminal_set`, and a level with none is a refusal naming it. The refusal of a row
  leaving a terminal reads the row's own level's set over the row's `from` expanded by
  `tools/loop/loop_table.py#derive_from_states`, so a feature or unit row from `deployed`, or from
  `@open`, which holds `deployed`, is refused. The refusal of a terminal also listed among open states
  stays the build level's, because the feature and unit levels list their terminal among their states
  (§8 F5). `check` prints one `loop: terminal <level> · <states>` line per level, the build's first and
  unchanged. Two plants join `PLANTS`, `unit-terminal-from` and `level-no-terminal`, and the selftest
  gains a `terminal unit` case. Observed by AC1, AC2.
- **S4** — The termination rule, in `TOOL-dDeclaredLoop-33`'s `tools/loop/termination.py`.
  `read_termination_inputs` fills the composition's `terminal` for every level of the tables through
  `read_terminal_set`, and `check_terminal` walks each level by reverse reachability over its own rows,
  an empty set still a finding. The branch printing `unchecked — no terminal set` goes with its line and
  every selftest expectation of it, since every level now declares a set or the composition does not
  read (§8 F4). A plant `unit-dead-end` joins that module's plants. Observed by AC3.
  **Readers:**
  by name: READER NOT IN TREE — the line and its one selftest expectation live in the termination module, which lands one build order before this unit and is absent at the branch tip
  by value: NO VALUE READERS — the line is printed for a person, and no code compares, counts or derives from it
- **S5** — The carriers. `help/loop.md`'s transition-table section names the per-level sets, the
  per-level line and the two plants, and the termination section `TOOL-dDeclaredLoop-33` adds loses any
  sentence saying the feature and unit levels print unchecked. `tools/loop/README.md`'s transition-table
  section and `tools/loop/loop_table.py`'s module docstring say the same, the docstring's "WHAT THIS DOES
  NOT CHECK" gaining §3's last item. Observed by AC4.

### Data model

```toml
[states]
build = ["planning", "designing", "building", "testing", "deploying", "paused", "parked"]
feature = ["decomposed", "designed", "built", "tested", "deployed"]
unit = ["designed", "built", "tested", "deployed"]
terminal = ["landed", "withdrawn", ...]        # the build level's, as it stands
feature-terminal = ["deployed"]
unit-terminal = ["deployed"]
```

```
read_transition_rows(data, where) -> {
  "states":         {level: [state]},   # every [states] key but terminal and each <level>-terminal
  "terminal":       [state],            # the build level's, as at the tip
  "level-terminal": {level: [state]},   # each <level>-terminal key, keyed by <level>
  ... every other entry as at the tip
}
read_terminal_set(tables, level)
  build          -> tables["terminal"]
  other          -> tables["level-terminal"][level]
  empty, absent  -> ValueError: "the level <level> declares no terminal set: [states] holds no <key>"
```

### The refusals

```
check_transition_tables:
  ends[level] = read_terminal_set(t, level) for each level; on ValueError a refusal and ends[level] = []
  per row: each written from state outside ENTRY, OPEN, the level's states and ends[level]
             -> "<row> leaves <s>, no <level> state"
           each state of derive_from_states(row, states[level]) in ends[level]
             -> "<row> leaves <s>, a terminal: no move leaves one"
  per level with a set: "loop: terminal <level> · <states>"
  a build terminal among the build's open states -> refused, as at the tip
```

### The termination rule

`read_termination_inputs` reads the tables through `read_transition_rows` over the definition it
already reads, and sets `terminal` to `read_terminal_set(tables, level)` for each level of
`tables["states"]`; a ValueError reaches `TOOL-dDeclaredLoop-33`'s exit 2 for a composition that does not
read. `check_terminal` walks each level against its own set. `unit-dead-end` plants a unit state
`reviewed` and a unit row from `built` into it, and owes a `terminal` finding naming `reviewed` and exit
1. The `dead-end` case `TOOL-dDeclaredLoop-33`'s AC2 stages owes the build finding alone.

### Alternatives rejected

- **Limiting the rule to the build table.** The feature and unit tables would carry a termination claim
  no check makes, which is the false claim the finding names.
- **Re-keying `terminal` as a table of levels.** It moves the list four readers at the tip and
  `TOOL-dDeclaredLoop-52`'s check read; `TOOL-dDeclaredLoop-15` §8 F6 kept the key in `[states]` for this
  unit to key beside.
- **The two keys with no split.** The probe above: two empty levels, printed, and no refusal.
- **`read_terminal_set(level)` reading the shipped file.** Plants and the termination composition are
  made in memory over parsed data, as `derive_move` takes its tables.
- **Moving `deployed` out of the feature and unit lists, as the build's terminals sit outside its open
  states.** Every row into `deployed`, the to-state check and `derive_position_into`'s last-state read
  would move with it.
