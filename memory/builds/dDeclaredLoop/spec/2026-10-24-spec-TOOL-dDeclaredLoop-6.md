## 1. Goal

Six of the extension kinds the foundations record gives this build each gain a factory, a `new` arm
that writes an instance which already conforms, and a conformance gate over the kind's whole
population, registered as its `[[kind]]` row of the kinds register (I15): command, policy key,
stage, hook, role and workflow. The gates that exist, `check_roles.py`'s R2 and R6 to R9 and

(foundations C3 to C5 and the factory assignment,

tag = "kind.role"

A `population` reader command that its kit does not yet offer (`--names`, `--steps`, `--list`) is
added beside the factory as a read-only flag that prints one member per line.

### The factory contract

Every subcommand of `factories.py`, in order: validate its arguments against the kind's grammar;
write its files; run its gate's argv over the repository; on exit 0 print every path written; on any
other exit restore each written file from the bytes it held before and print the gate's output.
A factory never writes outside the files its kind names.

## 5. Production-readiness checklist

- security — the factories write only the files their kind names, from arguments validated first; a
  red gate restores every byte.
- perf / scale — each factory runs one gate once; the fixture runs twelve gate calls.
- error / empty / loading states — a factory with a bad argument exits 2 before writing; a gate red
  exits 1 after restoring; an empty population reads `unarmed` in its gate.
- observability — every factory prints the paths it wrote or the gate's red.
- risks — a factory's write racing a hand edit: the restore uses the bytes read at its start, and the
  write set is stated per kind.
- testing — the thirteen fixture cases, each gate seen red on its planted hand instance.
- migration — none; the register rows and the pending list change in one commit.
- user docs — `help/loop.md`, which unit 1 creates, gains a "Making a new part" section naming each
  `core.py new` arm.
