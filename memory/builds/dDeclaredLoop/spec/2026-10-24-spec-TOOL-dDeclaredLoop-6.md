## 1. Goal

Five of the extension kinds the foundations record gives this build each gain a factory, a `new` arm
that writes an instance which already conforms, and a conformance gate over the kind's whole
population, registered as its `[[kind]]` row of the kinds register: command, policy key, hook, role
and workflow. The gates that exist, `tools/roles/check_roles.py`'s R2 and R6 to R9,
`tools/check-hook-destinations.sh` and the policy kit's `policy check`, are wrapped by the rows and
never copied. Two kinds of the clause stay on dOrderedCharter's shrink-only pending list: preset,
naming dKeptSession, which takes presets (deviation record 61), and stage, whose gov members are the
five gov steps the loop definition closes, so its factory is the repository stage's (§8 F4). The
assignment is the foundations record's
(`memory/builds/dClosedLoop/build/2026-10-14-build-PLAY-dClosedLoop-1-foundations.md@01191e8514e8:290`
to :299, and :383 to :388; P16).

### The factory contract

Every subcommand of `factories.py`, in order: validate its arguments against the kind's grammar, exit 2
naming the flag where one fails; hold each path it names through `write_guarded`, imported from
`policy_edit.py` beside it inside the function; write; run its gate's argv, the kit found through
`tools/loop/loop_lib.py#resolve_kit_dir`; on exit 0 print every path written; on any other exit raise
inside the innermost hold, so each hold puts its path back on the way out, and print the gate's output.
A renderer the factory runs, `check_roles.py --write`, writes a path held before it runs. A factory
validates only its kind's grammar: a value the gate grades, a policy default its own row refuses
included, is the gate's to refuse, so no predicate is written twice. A factory never writes outside
the files its kind names, the roles kit's `check_roles.py` among them for role and workflow (§8 F5).

Two kinds run their gate otherwise than by its leg's argv:

- policy key: the module constant `POLICY_KEY_ARMS`, the four arm names S4 gives, each run through
  `check_policy.run_arm(check_policy.ARM[name], top, check_policy.KIT)` after
  `tools/loop/floor.py#read_policy_modules`, printing `policy-check: <arm> · <verdict>` and its
  findings as `check_policy.py#main` does; any finding is the red. The other arms read a revision, the
  mirror or files the factory never writes, so over a written catalogue they are either unmoved or red
  on the caller's step; §5 "testing" names what they check that this gate does not. A loop bound or
  deadline key reds `arm_direction`, since S4 writes no `direction`.
- hook: the leg's argv run with `GIT_INDEX_FILE` naming a copy of the caller's index, taken from
  `git rev-parse --git-path index` into a temporary directory, into which `git add` has put the files
  the factory wrote; a copy, never an empty index, since the gate also reads every tracked adopter. The
  directory is removed on the way out, green or red, and the caller's index is never written (§8 F8).

WHAT `check-commands` DOES NOT CHECK: that a `run` file is executable or does what its verb says, that
any harness wires the command, and a `[[command]]` row in a descriptor outside the kind's population.
Over a tree holding no row it prints `unarmed`, which is no coverage: its red is seen only through the
`command-hand` plant. The wrapped gates' own limits are their headers', unchanged.
