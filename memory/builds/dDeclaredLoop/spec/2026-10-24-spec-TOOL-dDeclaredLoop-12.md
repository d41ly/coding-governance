## 1. Goal

Each of the five gov steps becomes a program of items in the loop definition: every item declared with
its tag, actor, inputs by layer, allowance, return template, closed outcome set, witness and routes, its
instruction scope derived from the instruction units, and the items' declared needs forming an acyclic
graph. Today the definition holds no `[[item]]` row and the records disagree (`gap-flow-13`); flow-steps'
five step tables, which carry the item audit's fixes ("The audit's fixes are applied", in its opening),
are the input.

## 4. Design

### Data model

```toml
# tools/loop/loop.toml
[[item]]
tag = "item.plan.recommend"            # item.<step>.<name>
step = "step.plan"
actor = "command:plan.recommend"       # <kind>:<name>, one actor, of one kind
needs = ["item.plan.lease"]            # each entry a tag, or a list of tags any one of which serves
inputs = ["layer.memory:plan record"]  # <layer tag>:<what it reads>
allowance = "none"                     # what it may write
returns = "record-kind.recommendation" # its return template: the record kind it writes
outcomes = ["review", "no-review"]     # closed; or "dispositions"
witness = { class = "history", by = "the recommendation record" }
owner = "dDeclaredLoop"
routes = { review = "transition", no-review = "item.plan.exit" }
```

`routes` is an inline table on the row, never an `[item.routes]` sub-table: the tag index's
`tag_index.py#read_toml_tags` ends a row's span at the next line opening `[`, and one span per row keeps
each `item.*` tag's served text whole.

| Key | Required here | From the flow-steps table |
|---|---|---|
| `tag`, `step`, `owner` | yes | Item, its section, Owner |
| `actor` | yes | Actor, one per item (flow-steps `[rules]`: an item a policy chooses the actor of is one item per value) |
| `needs` | yes, `[]` for none | Needs, by "Transcription" below |
| `inputs` | yes for a non-role actor | Needs and Does, each with its layer |
| `allowance`, `returns` | yes for a non-role actor | Does and Proven by |
| `outcomes`, `routes` | yes | Then |
| `witness` | yes | Proven by |

A role actor's absent `inputs`, `allowance` and `returns` are its role's, which TOOL-dDeclaredLoop-9
resolves through `roles_lib.py`; this unit does not copy them.

### Transcription

A Needs cell is prose, and three of its shapes are not one item tag (§8 F8).

- Alternatives, such as `design.decompose`'s "`design.seams`, `design.inventory` or `design.reentry`",
  are one entry holding a list: the entry is met when any one of its tags is witnessed.
- A phrase naming no item, such as `plan.record`'s "a select" or `plan.exit`'s "every item the run
  reached", is one list entry holding the declared items whose Then cell routes into the row.
- A need on an item outside the five programs, such as `plan.dedupe`'s `entry.claim` or `design.ready`'s
  `review.dispose`, is not written. An alternative group keeps its declared members. The unit that
  declares that program adds the need with its rows.

A Then target outside the five programs is `stand-in:{prefix}/<home>/<file>`, naming today's tool
(flow-steps `[rules]`, "A route into a later build reaches today's stand-in"), or `transition` for a
cross-step move. The `{prefix}` token keeps the row clear of the install-prefix ban, which refuses a kit
path spelled under the tool root in any tracked file there.

### The program check

`check_program(data, where, layers)` reads `data["item"]`, refuses a table that is no array of tables or
a row whose `tag` opens no `item.<step>.` of a gov step, and builds one needs graph over every row, an
any-of entry contributing an edge to each of its tags. A need naming no row is refused before ordering.
It asks `derive_needs_order` for an order and turns a `NeedsCycle` into one refusal naming each cycle
once, as `scan_cycles` rotates it to its smallest member; a self-need is a cycle of one. Then, per item:
`derive_outcome_set(row, members, where)` returns its closed set, refusing an empty one or a word given
twice; `routes` holds exactly the outcomes as keys; each route's target is a declared tag, `transition`,
or a `stand-in:` value whose path opens `{prefix}/`; and, where `layers` is not None, each input's text
before its first `:` is a member of `layers`. Each `[[step]]` row's `exit` must be a declared item whose
`step` is that row's tag. It returns `{step tag: [item tags in needs order]}`, the one order filtered per
step. Every refusal is a `LoopError` naming the item and the field.

`--check` runs it after `check_witness_classes` and prints one line per step, `loop: program <step> ·
<n> item(s) · <tags>`. `read_items(kit_dir)` reads the definition, runs `check_loop` and `check_program`,
and returns the rows in file order.

### The scope verb

`--scopes` reads and checks the definition as `--check` does, then calls `derive_item_scope(kit_dir,
root, tags, units=None)`, which resolves `load_sets.py` once and runs `derive` once per item, serially,
`--units <path>` added where `units` is given. Each item prints `loop: scope <tag> · <derive's item
line> · <its listed tags, or none>`. The `item` row of `tools/playbook/namespaces.toml` has role
`selects` (TOOL-dDeclaredLoop-18), so while no unit's `scope` names an item tag derive prints
`item — 0 unit(s)`, and the line says so; derive's `item — unarmed —` line, in a repository whose
registry lacks that row, prints as derive wrote it.

The `scope-selected` and `scope-no-kit` plants run `--check`'s read and then the scope verb. The
first hands `derive_item_scope` a scratch manifest under the host temp directory, holding one unit
scoped to `item.plan.record`, and removes it after. The second hands `read_layer_tags` and
`derive_item_scope` a scratch directory as the `kit_dir` they resolve the playbook kit from.

### The helper

```python
class NeedsCycle(ValueError):            # .stuck: the nodes left unplaced, sorted
def derive_needs_order(nodes, needs):    # -> list; Kahn, each ready tier sorted; raises NeedsCycle
def scan_cycles(edges, live=None):       # -> [tuple]; each cycle once, rotated to its smallest member
```

`derive_needs_order` is the loop in `govkit.py#derive_install_order` with the descriptor read lifted
out: govkit builds `deps`, `{kit: requires within the selection, itself excluded}`, as it does today,
returns `derive_needs_order(ids, deps)`, and catches `NeedsCycle` to raise its own `Refusal` from
`stuck`, so its message is unchanged.
`scan_cycles` is `backlog.py#_scan_cycles` with the fold's terminal test passed as `live`, a predicate
over a node, so `derive_verdicts` passes `lambda a: fold.statuses.get(a) not in TERMINAL`. The block
imports nothing, so the verdict-epoch gate's import-closure walk over its `DELEGATES`, which lists
`backlog.py`, finds no new sibling.
