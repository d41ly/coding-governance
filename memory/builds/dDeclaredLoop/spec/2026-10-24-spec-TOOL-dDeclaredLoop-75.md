### The re-merge on exit 1 (S27)

`run_merge_tree` passes `--name-only`, so on exit 1 every line after the first, up to the first blank
line, is a conflicted path. `read_remerge_policy` then reads:

```
exit 0, first line a tree id                    -> absent or present, as at the tip
exit 1, first line a tree id, policy path absent from the conflicted paths

exit 1, policy path among them, or no tree id    -> conflicted                    (the parents' grade)
```

A `present` C that does not parse keeps 78's refusal `does not parse at C`. The docstrings of the module
and of `read_remerge_policy` say that `conflicted` is an exit 1 whose conflicts hold the policy path.
The stand-ins of the existing plants replace `run_merge_tree` whole and are unaffected by the flag.
