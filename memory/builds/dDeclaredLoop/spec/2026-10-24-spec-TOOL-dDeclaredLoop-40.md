## 1. Goal

The round-1 spec audit (`memory/builds/dDeclaredLoop/reviews/2026-10-24-review-TOOL-dDeclaredLoop-1-spec-audit-round1.md`)
confirmed finding **id 47 at HIGH**, its item **H13**, alone in that item: the one trailer reader
refuses any key the playbook kit's `edges.toml` does not register, its copies ship in kits that do not
require the playbook kit, and nothing said how a copy finds the table or what happens without it.
`TOOL-dDeclaredLoop-23` has since landed the reader, and with it the lookup:
`tools/lib/commit_trailers.py#read_key_table` finds the table through the inlined `resolve_kit_dir`.
What is left is the absent table. In an install holding no playbook kit `read_key_table` raises the
resolver's `LookupError`, so every read refuses, `tools/memory-tree/routed_commits.py#read_routed_commits`
and the unattended kit's `tokens` verb among them. This unit gives the reader a closed floor of keys
for that install. It repairs `TOOL-dDeclaredLoop-23`.

## 4. Design

### The read

```
read_key_table()
  try:    path = resolve_kit_dir("playbook", "edges.toml", <this file's directory>) / "edges.toml"
          keys = the key of every [[trailer]] row
  except LookupError:  keys = none
  if keys:  return keys, path                      # the table decides, S3
  note once on stderr; return set(FLOOR_KEYS), None   # S2

read_commits(repo, revs, keys)
  registered, table = read_key_table()
  refuse a requested key not in registered: ValueError naming the key,
    and the table's path, or that no table is installed where table is None
```

The note is guarded by one module-level flag, so a process that reads many ranges prints it once.
The `tokens` verb is one process per call, so a shell consumer prints it once per call.
A refusal message spells no kit path of its own: the path it names is the one the resolver answered.

### The probe

Every criterion is observed in a scratch git repository holding one commit whose message carries
`Pass: TOOL-tFix-2`, with the unattended kit's copy of the reader placed in a `kit` directory.
The table, where a criterion has one, is an `edges.toml` in a `playbook` directory beside `kit`,
which is the resolver's second probe. A read is `python -c` importing the copy from `kit`, with
`revs` a list and the scratch repository as the working directory.

### Alternatives rejected

- **Giving every copy's kit `requires` `playbook`.** It installs the playbook kit wherever the
  memory-tree or unattended kit goes, a widened install surface for a check that has a safe floor.
- **Skipping the check entirely where the table is absent.** It would let a consumer read any key,
  the property the registered-key refusal exists for.
- **A floor in each consumer.** The refusal lives in `read_commits`, so one floor there serves every
  caller, and a second copy of the list would be a second owner of it.

## 5. Production-readiness checklist

- security — the floor is a closed list, so an absent table never admits an arbitrary key.
- perf / scale — one resolver call per read, as today; the note is one line per process.
- error / empty / loading states — absent table or a table of no rows: the floor and one stderr note.
  A present table lacking a requested key: the named refusal, unchanged.
- observability — the stderr note says the check was skipped and names `edges.toml`.
- risks — a consumer reading a key outside the floor in an install with no playbook kit is refused
  by name, which is the intended contract. A shell consumer that runs `tokens` many times prints the
  note as many times, on stderr.
- testing — AC2 to AC7 as probes; the arm under §7, observed at the close. The arm does not check a
  malformed table, nor that each copy is the one a given install runs.
- migration — none.
- user docs — `help/tags.md`, the trailer paragraph, S4.
