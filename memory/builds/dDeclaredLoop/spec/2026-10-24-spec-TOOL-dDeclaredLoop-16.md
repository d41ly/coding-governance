## 1. Goal

One closed disposition set, declared once in the loop definition, replaces the two the records give:
placement's set and Plan's draft scope (`gap-flow-13`, "two disposition sets"; the item audit's F12,
research-flow-items-a.md:151-153). Plan's words map into it, the vocabularies that only look alike are
named as different, and the owner's disposition record is a typed record kind carrying one value.

## 2. Scope (IN)

- **S1** — The set, `[dispositions]` in `tools/loop/loop.toml`: `set = ["continue", "amend", "new",
  "patch", "repeat", "unit", "breakpoint", "ask", "none"]`, the members flow-steps' `entry.place` row
  lists (flow-steps.md:124). `tools/loop/loop_lib.py#check_loop` grades the table where a definition
  holds it: `set` is a non-empty array of words of the `seg` shape, none given twice. It returns the
  members under the key `dispositions`, empty for a definition holding no table, beside the step and
  workflow rows it returns today. `read_dispositions(kit_dir)` returns the members in file order and
  raises `LoopError` for a definition that declares none, and `loop_lib.py --check` refuses the kit's
  own definition the same way (§8 F7). Observed by AC1.
- **S2** — The mapping, `[[disposition-alias]]` rows with `word` and `means`: Plan's draft words
  `attach` to `amend`, `defer` to `ask`, and `refuse-as-duplicate` to `continue` onto the matched
  build. `check_loop` refuses a row whose `word` is a member or repeats an earlier row's, or whose
  `means` is no member. `resolve_disposition(kit_dir, word)` returns a member for a member or an alias
  and raises `LoopError` for any other word. Observed by AC2.
- **S3** — The vocabularies that are not this set, stated in `tools/loop/README.md` and in the
  definition's comment: the review round's exit `fold|promote`
  (`tools/unattended/unattended.sh#REVIEW_DISPOSITIONS`), the per-finding report grammar (`class:`,
  `new:`, `gate:`, `none`, dFairHearing-8), and triage's verdicts (flow-steps.md:182), which move a
  build in planning to one of its terminal states. Observed by AC5.
- **S4** — The record kind `disposition` in the typed build-folder record factory,
  `tools/memory-tree/build_records.py`: an entry of `KINDS` with the required fields `Item`,
  `Disposition`, `Channel` and `Caused-by`, the closed set of `Channel` (`mailbox`, `terminal` or
  `prompt`, the channels flow-steps' `[breakpoint]` section names for the owner's disposition record),
  and an optional `Reason`. `Item` is a tag opening `item.`, by shape, and `Disposition` is one word of
  the `seg` shape, the segment `build_records.py#TAG` composes. The kind joins the reader in the same
  pass: `disposition` is added to `tools/memory-tree/tree_lib.py#TYPED_RECORD_KINDS`, which the
  factory's table must equal at import. The kind gets a door (§8 F5): `disposition` joins `DOORS`,
  and `build_records.py new disposition --build <slug> --unit <id> --item <tag> --disposition <word>
  --channel <channel> [--reason <text>]` writes the next `<date>-build-<unit id>-disposition-<n>.md`
  through `write_record`, its `Caused-by` the unit, as every landed door fills it. A
  `write_disposition` validates each value before the write, a `read_disposition` reads one record,
  the `read` verb gains its branch for the kind, and `DOOR_ARGV` gains the kind's row, which the
  `typed-kinds` plant reads for every member of `DOORS`. The `new` row of `tools/govkit/usage.toml`
  gains the door's flags. Observed by AC3 and AC6.
- **S5** — The value join, `check_disposition_record(kit_dir, record)` in `tools/loop/loop_lib.py`,
  `record` a mapping holding `Item` and `Disposition`: the word, compared as written and never through
  an alias, is a member of the disposed item's closed outcome set. `read_outcome_set(kit_dir, item)`
  reads that set from the `[[item]]` row whose `tag` is the item: the set of S1 for a row declaring
  `outcomes = "dispositions"`, the row's own list otherwise, and `None` for an item the definition does
  not declare. The join returns `True` for a member, raises `LoopError` naming the item and its set for
  any other word, and returns `None` for an undeclared item, which a caller prints as `unarmed` and
  never as green. Observed by AC4.
- **S6** — The kind in the tree's own grammar: `disposition` joins the closed `<kind>` list of
  `tools/memory-tree/HYGIENE.template.md`, with the sentence that counts the typed kinds and one

  its render. Observed by AC7.
- **S7** — The help page: `help/loop.md` gains the set, the aliases, the record with its door, and

## 4. Design

### Data model

```toml
# tools/loop/loop.toml
[dispositions]
# The one closed disposition set (cl-dClosedLoop-0101). Not REVIEW_DISPOSITIONS (fold|promote), not
# the per-finding report grammar (class:, new:, gate:, none), not triage's verdicts.
set = ["continue", "amend", "new", "patch", "repeat", "unit", "breakpoint", "ask", "none"]

[[disposition-alias]]
word = "attach"
means = "amend"

[[disposition-alias]]
word = "defer"
means = "ask"

[[disposition-alias]]
word = "refuse-as-duplicate"
means = "continue"
```

| Word | Source | Means | Why |
|---|---|---|---|
| `attach` | flow `[plan]` draft scope | `amend` | attaching a request to a live build is its re-entry at Design |
| `defer` | flow `[plan]` draft scope | `ask` | a deferred request is filed as an ask (flow-steps.md:182) |
| `refuse-as-duplicate` | the item audit's F12 | `continue` | a duplicate is re-placed onto the matched build, which carries on; the re-placement after `plan.dedupe` ends the duplicate `merged` (flow-steps.md:738) |

`loop_lib.py --check` prints the set on one line and one line per alias, before its summary line,
which stays as it is:

```text
loop: dispositions continue amend new patch repeat unit breakpoint ask none
loop: disposition-alias defer · means ask
```

### The record

```markdown
# TOOL-tFix-1 disposition 1 — item.plan.exit disposed continue

**Serves:** disposition TOOL-tFix-1

- **Item:** item.plan.exit
- **Disposition:** continue
- **Channel:** terminal
- **Reason:** the plan record is ratified as written
- **Caused-by:** TOOL-tFix-1
```

The head line, the `**Serves:**` line and the bold-key bullets are `build_records.py#write_record`'s
shape, and `build_records.py#FIELD` reads each bullet. The record carries one word. Which words are
legal is the disposed item's: a placing item declares `outcomes = "dispositions"` and takes S1's set;
an owner gate such as `item.build.ratify` declares its own outcomes (`ratified`, `rejected`,
flow-steps.md:296), and its record carries one of those. So the record's value is graded against one
closed set per item, and the placement set is declared once. A record carrying an alias word is
refused by the join, since a writer resolves the word before it writes.

A build-level owner item that no unit owns names the build's first unit id in the record's file name,
the convention this build's own build-level records follow (`memory/builds/dDeclaredLoop/build/`,
every record named under `TOOL-dDeclaredLoop-1`), until a build-level grammar lands.

## 5. Production-readiness checklist

- security — the door writes one record in the session's own build folder; `write_disposition`
  checks every value before the write, and `write_record` refuses a value that would forge a field.
  No network.
- perf / scale — one TOML read per call.
- error / empty / loading states — an unknown word is a `LoopError` naming it and the set; a
  definition with no set is a `LoopError`; an item with no outcome set reads `None`, printed `unarmed`.
- observability — `loop_lib.py --check` prints the set and the aliases.
- risks — an alias hides a legacy word behind a member; the README names each so a reader can find
  it. Both kits ship changed bytes, so `KIT_LOOP_VERSION` in `loop_lib.py` and
  `KIT_MEMORY_TREE_VERSION` in `check-memory-hygiene.sh` move where the epoch legs name them at the
  close. A shipped file spells the tool root `<prefix>/`, as `build_records.py`'s own text does.
- testing — AC1 to AC8 are each a pass's own observation; the arms in §7 are observed RED then GREEN
  by the main loop at the close.
- migration — none.
- user docs — `help/loop.md` (S7).
