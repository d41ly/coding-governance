### The rule

```
read_breakpoints(build, root, ...), each owner gate line (cause autonomy):
  placement = read_first_add(root, KIT/breakpoints.py relative to root)    None outside root's tree
  opening   = read_first_add(root, <memory root>/builds/<slug>/README.md)
  placement and opening and not check_is_ancestor(root, placement, opening)
            -> release "passed before placement"
  otherwise -> TOOL-dDeclaredLoop-19's answer: authorization, released <stem> <word>, or held
read_first_add(root, rel) = the last line of `git log --diff-filter=A --format=%H -- <rel>` at HEAD,
                            the oldest add; None where it prints nothing or exits non-zero
```

The two reads run once per `read_breakpoints` call, and only where the list holds an `owner gate` line.
The line keeps its five fields, so a pre-placement plan gate reads
`breakpoint: owner gate · at item.plan.exit · owner · autonomy · passed before placement`. The first four
fields, which `TOOL-dCalibratedLens-1` parses, do not move.

### The plants

`pre-placement` builds its scratch with `tools/loop/loop_items.py#build_scratch_tree`, whose one commit
adds the kits, `breakpoints.py` among them, and is the placement. On a root commit that the kits' commit
does not precede, it opens build `tPre`, and merges that line in with `--allow-unrelated-histories`, the
shape of a build opened on history the placement does not reach. It then opens `tPost` after the kits'
commit, and leaves `tNone`'s README uncommitted. The policy file
(`tools/loop/loop_items.py#POLICY_FILE`) carries `autonomy = "three-gates"` and, under `[decisions]`,
`major = "author-owner-ratifies"`, committed. The plant runs the scratch's own copy of the module, in the
scratch, so its `KIT` lies inside the tree it reads. `driver-pre-placement` stages the same history as
`TOOL-dDeclaredLoop-19`'s `driver-close` plant stages its repository, with the driver copied beside the
scratch's loop kit so that it resolves the scratch's module.

## 5. Production-readiness checklist

- security — a narrowing of where a new refusal applies, to builds that existed before it; the owner

  shallow root, which both reads share; a build so read is held.
