## 1. Goal

Every iterative loop a build runs, spec audits under `review.design.rounds`' `until-*` values, closing-review
follow-ups under `review.follow-up`'s `while-*` value and fix passes against one acceptance red, ends at the
first round whose blocker and high count does not strictly fall, or at whichever of `review.max-rounds` and
`flow.route-backs` it reaches first. Its open findings are promoted to units while the build's rework budget
remains and to asks after it, never folded into another round, and a blocking item's open work past the
budget ends as `flow.on-exhausted` says. Today the driver's `review_state`
(`tools/unattended/unattended.sh:12610-12618`) counts blockers alone, promotes without reading any budget
(`:12783-12825`), and no rule bounds a fix pass at all (`gap-flow-23`, `gap-flow-24`).

## 4. Design

### The predicate

```
review_state <prior counts> <count> <bound> [<route-backs>] [<target>]   round = prior counts + 1
  (target, default count) == 0                  -> CONVERGED                (target new)
  prior non-empty and count >= last prior        -> NON-CONVERGENT
  round past max-rounds (TOOL-dDeclaredLoop-21)   -> CEILING
  round >= bound                                -> BOUNDED
  route-backs given and round - 1 >= route-backs -> NON-CONVERGENT          (new)
  otherwise                                     -> CONVERGING
```

The four existing tests and their order are `TOOL-dDeclaredLoop-21`'s and stay as that unit leaves them
(I18). The new test sits last, so a loop whose round bound comes first exits `BOUNDED` or `CEILING` as
before, and one whose `flow.route-backs` comes first exits `NON-CONVERGENT`, the "loop ends non-converging"
of flow-steps.md:44-45. Both are terminal and both promote, which is the clause's "both promoting its open
findings the same way". With neither new argument the function is byte-for-byte its predecessor, which
keeps the `tools/workflows/tier2-review.test.sh` parity arm's domain unchanged.

| Value | Key | Target count |
|---|---|---|
| `until-no-blocker` | `review.design.rounds` | blockers |
| `until-no-high` | `review.design.rounds` | blockers + round-highs |
| `until-clean` | `review.design.rounds` | blockers + round-highs + round-minors |
| `after-high` | `review.follow-up` | blockers + round-highs |
| `while-finding` | `review.follow-up` | blockers + round-highs + round-minors |
| `one`, `fixed-count`, `never` | either | the count; their bound alone ends them (`TOOL-dDeclaredLoop-21`) |

Under `until-clean` and `while-finding` a round standing on minors alone is not converged; its blocker and
high count of 0 does not fall below the round before's 0, so the next such round is `NON-CONVERGENT` and its
minors are promoted, which keeps the clause's count and still ends the loop.

### The count

`review_counts` reads `blockers <B>` today. It now also reads ` · round-highs <H>` and prints `B+H`. The
field is new and distinct from the exit's ` · highs <H>`: on the closing diff review the exit's `highs` is a
SUM over every round (`tools/unattended/VERBS.template.md:809-814`), so one field cannot carry both. A row
written before this unit carries no `round-highs` and reads as `B`, so a sequence recorded by an older driver
keeps the state it had. `verb_review` refuses a missing or non-integer `--round-highs` on every round, with
the same canonical-decimal rule `blockers` takes (`tools/unattended/unattended.sh:12705-12710`).

The planted flat follow-up the clause names is a sequence that falls in blockers and not in blockers plus
highs: rounds `(2, 1)` and `(1, 2)`. The blocker-only rule reads `2, 1` and re-arms; this rule reads `3, 3`
and ends.

### The target

| Loop | `promotion_target(build, subject, true)` | Row field |
|---|---|---|
| review | `unit` | ` · to units` |
| review | `on-exhausted` | ` · to asks` |
| fix-pass | `unit` | ` · to units` |
| fix-pass | `on-exhausted` | ` · to on-exhausted` |

A review loop's open findings go to asks once the budget is spent (flow-steps.md:47-49, stall-and-loop.md:186).
A fix-pass loop's open work blocks its unit's step exit, so with no budget left it cannot become a unit and
cannot be dropped to an ask; the build ends as `flow.on-exhausted` says. The driver calls `budget.py` on its
command line, as `TOOL-dDeclaredLoop-30`'s draw sites do, and parses nothing itself.

The field sits before ` · disposition promote`, because check 2 reads the disposition as the row's last
field (`tools/unattended/check-unattended.sh:845-848`).

### The fix-pass loop

```
<ts> fix-pass · item <unit id> · reason reds <N>[ · <STATE>][ · to <target>]
```

`run_fix_pass` validates the unit id with `_ids_of`, the count as `blockers` is validated, and the row's
fields with the newline, separator and bypass-flag refusals `verb_review` applies
(`tools/unattended/unattended.sh:12728-12747`), each spelled at its own call site with its own `fail` number, because check-arms finds a branch by its literal number (`:12738-12740`). It computes the prior counts by `review_counts`' own awk,
parameterised on the row kind rather than copied, and refuses a pass on a unit whose last `fix-pass` row
carries a terminal token, with the refusal `verb_review` gives a terminal subject. Its bound is
`review.max-rounds` and its route-back bound `flow.route-backs`; it has no round bound of its own. An
acceptance red that never greens records `reds 1`, then `reds 1`, and the second pass reads
`NON-CONVERGENT`: a terminal in two passes, whatever the bounds.

`fix-pass` joins `PARK_KINDS` (`tools/unattended/unattended.sh:875`), `PARK_KINDS` in
`tools/runlog/model.py:98` and `_RUN_PARK_KINDS` in `tools/drift-audit/drift_report.py:2427`, the two
read-side copies a driver kind is spelled in. It does not join `PARK_KINDS_OWED`: a fix pass asks the owner
nothing.

### Check 2

The awk at `tools/unattended/check-unattended.sh:822-870` keeps `b` as the blockers and adds `round-highs`
for its `flat` reading, and reads ` · to asks` on an exit row. For such a subject the owed floor is the same
count, compared with the ask ids `asks_filed_in` finds in the build's `BACKLOG.md` at HEAD and not at BASE.
A `to units` exit keeps today's comparison against the generated units region.

### Alternatives rejected

- **Make `--highs` a per-round count.** On the closing review it is the exit's sum over every round
  (`tools/unattended/VERBS.template.md:809-814`) and check 2's unit floor reads it so; one field cannot be
  both, and respelling it moves every landed record's meaning.
- **A third copy of the round rule in the loop kit.** `review_state` and `deriveRoundState` are already two,
  held equal by a parity arm. The route-back test is one line added to the bash source.
- **Record a fix pass as a `--review` round on a derived subject.** The verdict field's closed set
  (`CLEAN|CLEAN WITH FIXES|BLOCKED`) describes a review, and a fix-pass subject would take a spec subject's
  round bound.

## 5. Production-readiness checklist

- security — no new write surface beyond one more `park()` row kind, which inherits `park()`'s guards.
- perf / scale — one awk pass per round, as today.
- error / empty / loading states — a missing `--round-highs`, `--round-minors` or `--reds` refuses with
  fail 37; a `budget.py` that cannot be run refuses the exit rather than guessing a target, naming the
  module.
- observability — the target is on every promoting row and in the printed exit sentence.
- risks — `--reds` is typed by the pass, so a pass reporting a false green ends the loop CONVERGED; the
  executor's computed acceptance is the later fix.
- testing — the pass probes `review_state` sliced, the verbs on fixture repositories and check 2 on a
  fixture run-state; the arms in §7 are observed RED then GREEN by the main loop.
- migration — none.
- user docs — the verbs carrier is the reference; no help page covers the driver.
