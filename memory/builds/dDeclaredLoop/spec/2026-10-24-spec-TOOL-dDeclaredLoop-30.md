## 1. Goal

A build's total rework has a ceiling: one budget per build, `flow.rework-budget`, that every
repetition draws on and that units a loop mints cannot reset (P39, the owner's SL-1). Today the driver
bounds each review loop and each unit pass apart, keyed per subject, and a promotion cascade ran four
audit generations, about 12M tokens, before a run's own override stopped it (`gap-flow-23`;
`memory/builds/aWokenSentinel/BACKLOG.md:5` measured 7, 6, 4 and 4 promoted units on one build).

## 2. Scope (IN)

  reads `transitions.record`. Their catalogue rows are written (`tools/policy/catalogue.toml`), each

- **S2** — One budget per build, on its transition record (I19). Its total is the base until Design's
  exit, and the base for a build with no units. At the transition `designing` to `building`,
  `write_transition` calls `freeze_budget`, which writes the row `budget · frozen · <units> unit(s) ·
  <total>` as a line of that move's record, the total the base plus the per-unit share for each unit the

  draw made while it defines a spec, counting its units then (§8 F12). The freeze never refuses a move:

## 3. Non-goals (OUT)

- No ending: what a build does once its budget is spent, `flow.on-exhausted`'s three values, is
  TOOL-dDeclaredLoop-31's.
- No convergence rule and no promotion act: the strict-decrease routing of a closing-review follow-up
  under `review.follow-up`'s `while-*` value and of a fix pass, and promoting their open findings, are
  TOOL-dDeclaredLoop-32's, which calls `promotion_target`. A spec audit's stop and the disposal of its
  findings are BUILD-METHOD M4's spec-audit rule's.
- No lease, no admission queue and no serialization of concurrent draws on a closed root: leases are
  dPlacedRequest's; until then a draw is one appended row and two racing draws are two rows.
- No budget before `entry.claim`: the intake's content-keyed budget is dPlacedRequest's.
- No card line: the remaining budget on the card is dKeptSession's render of this record.
- No caller of the transition writer in the driver: TOOL-dDeclaredLoop-3 wired none, and this unit
  wires none, so the driver's draws land in the run-state file until a build records moves.
- No `research` draw site: no writer in the tree records `item.plan.record`'s `research` outcome.

## 4. Design

### Data model

The rows of one build's transition records, in order:

```
budget · frozen · 3 unit(s) · 10
draw · fix-pass · TOOL-dX-2 · 1/10
draw · review-round · TOOL-dX · 2/10
draw · patch:dXPatch · item.deploy.close · 3/10
```

`spent` is the draw's ordinal among the build's draw rows; `total` is the frozen row's figure, or the
base before it. Both are re-derived from the rows on every read, so a typed figure that disagrees with
the rows is a refusal naming the row. Before the build's first log record, the same rows sit in its
run-state files, each prefixed by its UTC timestamp.

### The answers

| Call | Answer |
|---|---|
| `record_draw` | `drawn`, with the row it wrote, or `exhausted`, writing nothing |
| `classify_repeat` | a cause of the closed set, or `contention` |
| `count_returns` | an integer per item, and `converging` or `non-converging` against `flow.route-backs` |
| `promotion_target` | `unit`, `ask` or `on-exhausted` |
| `budget_state` | `open <spent>/<total>`, `spent`, or `unfrozen <spent>/<base>` |

### The verbs

```
python budget.py draw --build <slug> --cause <cause> --item <item>
python budget.py value
python budget.py --fixture --plant <case>
python budget.py --selftest
```

`draw` runs at the repository's top level, as `adapt.py propose` does. It prints `loop: budget · drawn ·
<row>` and exits 0, `loop: budget · exhausted · <slug> · <spent>/<total> · flow.on-exhausted` and exits
3, or `loop: budget · refused · <why>` and exits 2, and `loop: unarmed · <why>`, exit 2, where the
policy or memory-tree kit does not resolve, never a default. `value` prints `base <n> per-unit <n>`.

### The driver, in shell

`run_budget_draw <slug> <cause> <item>` finds the script through `resolve_position_engine budget.py`
(`tools/unattended/unattended.sh#resolve_position_engine`), runs `"$PE_PY" "$PE_PATH" draw` with each
value joined to its flag, `--build=<slug>`, so none opening `-` is read as a flag, prints its output, and
leaves the first line in `_bd_why` and the exit in `_bd_rc`, 2 where the script does not resolve; it
calls no `fail`. `verb_review` reads `_bd_rc` 0 as drawn, 3 on a spec subject, any subject but the build
slug (TOOL-dDeclaredLoop-21 S3), as the round recorded all the same, and anything else through `fail 37
"the rework budget refused this review round, so no round is recorded: $_bd_why"`. `verb_dispatch`
reads 0 as drawn and anything else through `fail 49 "the rework budget refused this dispatch, so no
dispatch is recorded: $_bd_why"`. A first round and a first dispatch call nothing, so a build with one
review starts no python.
