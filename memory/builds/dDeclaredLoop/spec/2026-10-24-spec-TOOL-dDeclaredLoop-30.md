## 1. Goal

A build's total rework has a ceiling: one budget per build, `flow.rework-budget`, that every
repetition draws on and that units a loop mints cannot reset (P39, the owner's SL-1). Today the driver
bounds each review loop and each unit pass apart, keyed per subject, and a promotion cascade ran four
audit generations, about 12M tokens, before a run's own override stopped it (`gap-flow-23`;
`memory/builds/aWokenSentinel/BACKLOG.md:5` measured 7, 6, 4 and 4 promoted units on one build).

## 2. Scope (IN)

- **S1** — The two keys, read through dGroundRules-2's `resolve` (I10), their catalogue rows already
  written and each declaring `direction = "raise-loosens"` (dGroundRules-11), so raising either is the
  owner's alone. `flow.rework-budget` is `<base>+<per-unit>` or a bare count, which is a base with no
  per-unit share, default `4+2` (v2:1261); `flow.route-backs` is a count, default 3 (v2:1260). A value of
  another shape refuses naming the key. One module, `tools/loop/budget.py`. Observed by AC6.
- **S2** — One budget per build, on its transition record (I19). Its total is the base until Design's
  exit, and the base for a build with no units. At the transition `designing` to `building`,
  `freeze_budget(build)` appends the row `budget · frozen · <units> unit(s) · <total>`, the total the base
  plus the per-unit share for each unit of the roster at that commit, once: a later entry into
  `building` writes no second freeze. The budget is keyed to the build's slug, so a unit minted after the
  freeze adds no share. Observed by AC1, AC2 and AC8.
- **S3** — The draw, `record_draw(build, cause, item)`: one row
  `draw · <cause> · <item> · <spent>/<total>` appended to the build's newest `transition` log record
  (TOOL-dDeclaredLoop-3 S2) and committed with it, the freeze row of S2 likewise appended to the record
  of the transition into `building`; the rows are read back over every `transition` record of the
  build through the record factory's reader (`tools/memory-tree/build_records.py`). The cause from the closed set `route-back`, `fix-pass`, `review-round`, `re-dispatch`, `research`,
  `patch:<slug>` (flow-steps.md:40-42), `<item>` the item tag, or the unit id or subject a driver act
  names where no item tag reaches it yet. A cause outside the set refuses. Once spent equals total the
  budget is spent, and the next draw writes nothing and returns `exhausted`, the ending
  `flow.on-exhausted` says being TOOL-dDeclaredLoop-31's. Observed by AC1, AC2, AC9.
- **S4** — The draw sites in `tools/unattended/unattended.sh`: `verb_review` (:12669) draws
  `review-round` for every round of a subject after its first, a follow-up round included;
  `verb_dispatch` (:13584) draws `re-dispatch` for a dispatch of a unit pass whose earlier dispatch row
  left no pass commit, and `fix-pass` for a dispatch of a unit whose earlier pass committed; a backward
  transition TOOL-dDeclaredLoop-10 records draws `route-back` at its writer; an item's `probe` outcome
  re-entering draws `research`. Each site reads `exhausted` and stops the repetition. Observed by AC7.
- **S5** — Contention draws nothing. `classify_repeat(event)` returns `contention` for a verdict staled
  by another build's landing, a prepared merge conflicted by another build's landing, a wait on a lease
  another live build holds and an unreachable remote; the re-verification runs in its turn and no draw
  row is written. Observed by AC3.
- **S6** — The per-item early limit. `count_returns(build, item)` counts the draws naming the item; past
  `flow.route-backs` that item's loop ends `non-converging`. `promotion_target(build, item, blocking)`
  then answers `unit` for a blocking item while the budget remains, `ask` for a non-blocking item, and
  `on-exhausted` for a blocking item once the budget is spent; `blocking` is the caller's, an item
  blocking where its step's exit needs its witness (flow-steps.md:48-49). Observed by AC5.
- **S7** — A patch build's draw. A patch build draws on its originating build's budget with the cause

  is terminal, its spent and total continuing from that record's last row, and no transition row is
  written, so a draw never moves the build's terminal state. The originating slug is the first entry of

  dPlacedRequest's `entry.claim` carries it. Observed by AC4.
- **S8** — The fixture: `python tools/loop/budget.py --fixture --plant <case>` builds a scratch build

## 4. Design

### Data model

The rows on one build's transition record, in order:

```
budget · frozen · 3 unit(s) · 10
draw · fix-pass · TOOL-dX-2 · 1/10
draw · review-round · TOOL-dX · 2/10
draw · patch:dXPatch · item.deploy.close · 3/10
```

`spent` is the draw's ordinal among the record's draw rows; `total` is the frozen row's figure, or the
base before it. Both are re-derived from the rows on every read, so a typed figure that disagrees with
the rows is a refusal naming the row.

### The answers

| Call | Answer |
|---|---|
| `record_draw` | `drawn`, with the row it wrote, or `exhausted`, writing nothing |
| `classify_repeat` | a cause of the closed set, or `contention` |
| `count_returns` | an integer per item |
| `promotion_target` | `unit`, `ask` or `on-exhausted` |
| `budget_state` | `open <spent>/<total>`, `spent`, or `unfrozen <spent>/<base>` |

### The driver, in shell

Each draw site calls `"$py" "<prefix>/loop/budget.py" draw --build <slug> --cause <c> --item <id>`, the
python from the driver's inlined `resolve_python` (`tools/unattended/unattended.sh:392-422`), and reads
its one line; nothing is sourced. `exhausted` exits 3, and the verb refuses the repetition with a line
naming the budget and `flow.on-exhausted`.

### Inventory

| Minted | Kind |
|---|---|
| `freeze_budget`, `record_draw`, `classify_repeat`, `count_returns`, `promotion_target`, `budget_state` | functions, `tools/loop/budget.py` |
| `budget · frozen`, `draw` | transition record rows (I19) |
| `route-back`, `fix-pass`, `review-round`, `re-dispatch`, `research`, `patch:<slug>` | draw causes |
| `exhausted`, `contention`, `non-converging` | answers |

Each function name is put to `python tools/lexicon/lexicon.py --suggest <name> --as py.function` in
the build pass.

### Migration

None. A build whose Design exit predates this unit has no freeze row; it reads the base until its next
entry into `building`, which does not freeze, so such a build keeps the base alone, the stricter bound,
and the line it prints says so.

### Rollout

Live at landing, since the clause is the bound. With the default `4+2` a build of three units has ten
repetitions; v2:1261 sets that figure and only the owner raises it.

### Files touched (estimate)

- `tools/loop/budget.py` (new)
- `tools/unattended/unattended.sh`: the draws in `verb_review` and `verb_dispatch`
- `tools/loop/loop_transition.py`: `write_transition` calling `freeze_budget` at `designing` to
  `building`, and `record_draw` on a backward row TOOL-dDeclaredLoop-10 records
- `tools/loop/kit.toml`: the module and the leg declared
- `tools/gate-legs.json`: the leg `loop budget fixtures`
- `help/loop.md`: the section of S10

### Alternatives rejected

- **A counter per item or per edge.** The stall-and-loop prior art found per-item and per-edge counters
  never escalated once a loop minted new keys, and per-build did (its P1).
- **Shares recomputed from the current roster.** Each minted unit would add its share, which is the
  reset the clause refuses.
- **Contention counted.** A busy main would turn a healthy build into an exhausted one.

## 5. Production-readiness checklist

- security — the rows are appended by the loop kit's writer; raising the budget is a policy-file edit
  the owner's guard admits alone.
- perf / scale — one python start per repetition act; the derivation reads one record.

## 6. Acceptance criteria

- **AC1** — When `python budget.py --fixture --plant mint-each-lap` runs a loop that, after a freeze at
  two units, mints a new unit and draws `fix-pass` on each lap, the eighth draw writes 8/8 and the
  ninth answers `exhausted` with no row, the total reading 8 throughout.
  Red when: the total is derived from the current roster, so each minted unit adds 2 and the loop never
  ends.
- **AC2** — When `python budget.py --fixture --plant before-freeze` runs a loop in `designing` that draws
  `route-back` on each lap, the fourth draw writes 4/4 and the fifth answers `exhausted`.
  Red when: per-unit shares count before Design's exit, so the loop draws past the base.
- **AC3** — When `python budget.py --fixture --plant stale-verdict` re-verifies a gates verdict staled by
  another build's landing, `classify_repeat` answers `contention` and the record carries no new `draw`
  row.
  Red when: every re-verification draws, so another build's landing spends this build's budget.
- **AC4** — When `python budget.py --fixture --plant patch-draw` draws `patch:dFixPatch` on an originating
  build whose last transition is to `landed`, one `draw · patch:dFixPatch` row is appended to that
  build's record, and the build's state read after it is still `landed`.
  Red when: the draw re-opens the build through a transition row, so a terminal build reads open.
- **AC5** — When `python budget.py --fixture --plant route-backs` returns one item four times under
  `flow.route-backs` = 3, its loop reads `non-converging`, and `promotion_target` answers `unit` with
  `blocking` true and budget left, `ask` with `blocking` false, and `on-exhausted` with `blocking` true

  Red when: the early limit is counted across items, so one item's returns end another's loop.
- **AC6** — When `python budget.py value` reads policy files setting `flow.rework-budget` to `4+2`, `6`
  and `4+`, it prints `base 4 per-unit 2`, `base 6 per-unit 0`, and refuses the third naming the key.
  Red when: the bare count is refused, so v2's first value form cannot be set.
- **AC7** — When `python budget.py --fixture --plant driver-draws` runs the fixture's copy of
  `tools/unattended/unattended.sh` through two `--review` rounds of one subject and two `--dispatch`

  row where the first dispatch left no pass commit, and none for the first of each.
  Red when: the first round draws, so a build with one review spends its budget on it.
  cost: the plant runs the driver in a scratch repository, about a minute.
- **AC8** — When `python budget.py --fixture --plant re-entry` records `designing` to `building` with
  three units, routes back to `designing` and enters `building` again with four, the record carries one
  `budget · frozen · 3 unit(s) · 10` row and no second.
  Red when: every entry into `building` re-freezes, so a route back re-sizes the budget.
- **AC9** — When `python budget.py draw` is called with the cause `retry`, it refuses naming the cause
  and the closed set.
  Red when: an unknown cause is written, so a draw nothing can classify spends the budget.
- **AC10** — When `python budget.py --fixture --plant pre-spec` draws twice on a build with no spec and
  then once after its first log record exists, the run-state file carries the first two rows, the log

  Red when: a draw with no log record is dropped, so a planning loop runs undrawn.
- **AC11** — When `grep -n "flow.rework-budget" loop.md` runs over the help page at this unit's commit,
