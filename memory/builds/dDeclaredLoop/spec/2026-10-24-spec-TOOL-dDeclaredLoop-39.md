## 1. Goal

The round-1 spec audit (`memory/builds/dDeclaredLoop/reviews/2026-10-24-review-TOOL-dDeclaredLoop-1-spec-audit.md`)
confirmed finding **id 19 at HIGH**, its item **H10**, alone in that item. `TOOL-dDeclaredLoop-23`
defines `read_commits` by its format string alone. The reader it replaces in `routed_commits.py` runs
`git --no-replace-objects -c log.showSignature=false` under `build_git_env`, which sets
`GIT_GRAFT_FILE=/dev/null`, with `GIT_ENV_LEAKS` removed (`tools/memory-tree/routed_commits.py:86-95`,
`tools/memory-tree/tree_lib.py:232-276`); the shell readers run through `GIT()`, which pins
`core.useReplaceRefs=false` (`tools/unattended/lib-unattended.sh:45`, :61). None of that is carried, so a
replace ref or a graft can rewrite the subjects and trailers the routed-commit gate, pass-order,
brief-recorded and the commit check read, and a `--fixture` run started from a hook reads the real
repository through an inherited `GIT_DIR`. This unit takes the report's fix. It repairs
`TOOL-dDeclaredLoop-23`.

## 2. Scope (IN)

- **S1** — One runner in `commit_trailers.py`, `run_pinned_git(repo, args)`, the only place the module
  spawns git: argv `git --no-replace-objects -c log.showSignature=false -c core.useReplaceRefs=false -C
  <repo> <args>`, environment the caller's with `GIT_GRAFT_FILE=/dev/null` set and every name of
  `GIT_ENV_LEAKS` unset. `read_commits`, `resolve_commit` and the `message` verb's
  `interpret-trailers` call go through it. Observed by AC1, AC2.
- **S2** — `GIT_ENV_LEAKS` inline in the canonical block, its value equal to
  `tools/memory-tree/tree_lib.py`'s, because a copy in the unattended and loop kits cannot import the
  memory-tree kit; and a comparison of the two, run by `routed_commits.py --selftest`, whose kit holds
  both: the memory-tree copy's tuple equals `tree_lib.GIT_ENV_LEAKS`. Observed by AC3.
- **S3** — A failed git call raises, naming the command and git's first stderr line, as
  `tree_lib.read_git_output` does (`tools/memory-tree/tree_lib.py:278-297`); it never yields an empty
  commit list. Observed by AC4.
- **S4** — The module docstring states the pin policy and names `routed_commits.run_git` and `GIT()` as
  the readers whose pins it carries. Observed by AC3.

## 4. Design

### Evidence

- `routed_commits.run_git` (`tools/memory-tree/routed_commits.py:86-95`) is the Python pin today, and
  `build_git_env`'s docstring says callers add `--no-replace-objects` to the argv
  (`tools/memory-tree/tree_lib.py:238`).
- The shell pin is `GIT_PIN_REPLACE=core.useReplaceRefs=false` (`tools/unattended/lib-unattended.sh:45`),
  and the driver's comment records that the replace suppressions are not interchangeable and that only
  `GIT_GRAFT_FILE` stops a graft (`tools/unattended/unattended.sh:79-86`). Both are carried.
- `GIT_ENV_LEAKS` holds twelve names in two halves, eight location variables and four pathspec-mode
  variables (`tools/memory-tree/tree_lib.py:262-275`): PINNED, read 2026-10-24.

### Files touched (estimate)

- `tools/lib/commit_trailers.py`
- `tools/memory-tree/commit_trailers.py`
- `tools/unattended/commit_trailers.py`
- `tools/loop/commit_trailers.py`
- `tools/runlog/model.py`
- `tools/memory-tree/routed_commits.py`

### Alternatives rejected

- **Importing `tree_lib` from the canonical.** The unattended and loop copies cannot reach the
  memory-tree kit; the block must be self-contained, so the value is carried and compared.
- **Pinning only `--no-replace-objects`.** A graft file survives it, which is the driver's measured
  reason for `GIT_GRAFT_FILE`.

## 5. Production-readiness checklist

- security — closes a read-integrity gap: history rewritten by a local replace ref or graft can no
  longer change an attribution.
- perf / scale — no new spawn; the same one `git log` per read.
- error / empty / loading states — S3: a failed call is a named error, never an empty answer.
- observability — the error names the command and git's stderr line.
- risks — a caller that relied on reading a replaced history: none exists, and every replaced reader
  already pinned.
- testing — AC1 to AC4 as fixture probes; the arm under §7, observed at the close.
- migration — none.
- user docs — none.

## 6. Acceptance criteria

- **AC1** — When a probe builds a fixture repository under `%TEMP%` with a commit carrying
  `Pass: TOOL-tFix-1`, runs `git replace` on it with a commit carrying `Pass: TOOL-tFix-9`, and calls
  `read_commits` and `attribute(c, "replace")`, the attribution reads `TOOL-tFix-1`.
  Red when: the reader runs plain `git log`, so the replacement's `TOOL-tFix-9` is read.
  fixture: a fixture repository under a short `%TEMP%` path; the tree holds none.
- **AC2** — When the probe exports `GIT_DIR` naming the worktree's own repository and runs
  the canonical copy's `python commit_trailers.py --fixture`, the fixture's three commits are read and none of the
  worktree's.
  Red when: the inherited `GIT_DIR` points the read at the worktree, so its subjects appear.
- **AC3** — When `python tools/memory-tree/routed_commits.py --selftest` runs, its arm comparing the
  memory-tree copy's `GIT_ENV_LEAKS` with `tree_lib.GIT_ENV_LEAKS` passes, and fails when one name is
  removed from a scratch copy of the block.
  Red when: the arm compares the tuple with itself, so a drifted copy passes.
- **AC4** — When `read_commits` is called with a revision range naming an unknown ref, it raises naming
  `git log` and git's stderr line.
  Red when: the failure returns an empty list, which every consumer reads as no commits.
