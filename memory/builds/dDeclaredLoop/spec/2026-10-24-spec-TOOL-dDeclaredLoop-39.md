## 1. Goal

The round-1 spec audit (`memory/builds/dDeclaredLoop/reviews/2026-10-24-review-TOOL-dDeclaredLoop-1-spec-audit.md`)
confirmed finding **id 19 at HIGH**, its item **H10**, alone in that item: the one trailer reader
carried none of the git pins of the readers it replaced. `TOOL-dDeclaredLoop-23` has since landed, and
the gap is narrower than the finding and still open. A Python consumer hands `read_commits` its own
pinned runner, so the routed-commit gate is pinned today. The reader's default runner,
`tools/lib/commit_trailers.py#run_git`, is not: it spawns `git -C <repo>` under the caller's
environment, and its module docstring names this unit as the owner of that gap. Every CLI read goes
through it, so a replace ref or a graft rewrites what the `tokens` verb, `--print-commits` and
`--fixture` answer, and a `--fixture` run under an inherited `GIT_DIR` reads the real repository. The
shell side holds one stopgap, a `GIT_NO_REPLACE_OBJECTS=1` prefix on the `tokens` call, which covers a
replace ref for that one caller and nothing else. This unit pins the default runner. It repairs
`TOOL-dDeclaredLoop-23`.

## 4. Design

### Evidence

Each line was read at the branch head on 2026-11-13.

- `tools/lib/commit_trailers.py#run_git` spawns `["git", "-C", repo, *argv]` with no `env`, and its
  docstring says a Python consumer passes its own runner so its pins hold. The module docstring ends
  with a clause listing the git pins of the default runner as not here, owned by this unit.
- `tools/lib/commit_trailers.py#read_commits` takes `run=None` and calls `(run or run_git)`.
  `tools/memory-tree/routed_commits.py#read_routed_commits` and `#read_newest_unit` pass a lambda over
  that module's own `run_git`, which is pinned and counted. `commit_trailers.py#main` passes none for
  `tokens` and `--fixture`, and calls `run_git` directly for `--print-commits`.
- `tools/memory-tree/tree_lib.py#build_git_env` sets `GIT_GRAFT_FILE=/dev/null` and says callers add
  `--no-replace-objects`. `tools/memory-tree/routed_commits.py#run_git` is that shape, less
  `tree_lib.GIT_ENV_LEAKS`, with `-c log.showSignature=false`.
- `tools/lib/git_env_leaks.py` is a gated canonical: the `git_env_leaks_py` block, whose tuple its
  docstring states is the memory-tree kit's `GIT_ENV_LEAKS` member for member and in order. Its one
  inline copy is in `tools/policy/policy.py`. The parity table in `tools/lib/resolve-python.test.sh`
  finds copies by a grep for the block's opening marker over tracked Python and shell files, and
  excludes only the canonical's own path, so a new carrier needs no new row. No gate compares the
  canonical with `tree_lib.GIT_ENV_LEAKS`; S2's arm is the first.
- The reader's files already carry a second block this way: `resolve_kit_dir` sits above the
  `commit_trailers_py` block in each, and the canonical is itself a graded copy of that row.
- `tools/unattended/lib-unattended.sh#read_attribution_tokens` runs `GIT_NO_REPLACE_OBJECTS=1
  "$_rt_py" "$_rt_d/commit_trailers.py" tokens "$@"`. The driver's comment above its `export
  GIT_GRAFT_FILE=/dev/null` in `tools/unattended/unattended.sh` records that neither replace-ref
  switch stops a graft and that only `GIT_GRAFT_FILE` does.
- Measured on this node with a scratch probe over the canonical: with a replace ref on the fixture's
  newest commit, `derive_attribution(c, "replace")` answered the replacement's id; with a graft line
  for that commit, `read_commits` answered one commit of the fixture's planted set; and `--fixture`
  under an exported `GIT_DIR` naming this worktree printed this worktree's subjects.

### The runner

`run_git(repo, argv, stdin=None)` builds its environment from `os.environ`, sets
`GIT_GRAFT_FILE=/dev/null`, drops every name in `GIT_ENV_LEAKS`, and passes it as `env=`. The block
refers to `GIT_ENV_LEAKS` as a module name, exactly as it refers to `resolve_kit_dir`. No function is
added and none is renamed, so the generated symbol map does not move: it holds functions, and
`GIT_ENV_LEAKS` is a constant.

Stripping the location variables changes one thing for the CLI: `tokens` and `--print-commits` read
the repository holding the working directory, never one an inherited `GIT_DIR` names. Every caller in
the tree runs them from inside the repository it asks about.

## 5. Production-readiness checklist

- security — closes a read-integrity gap: history rewritten by a local replace ref or graft can no
  longer change what the trailer CLI attributes, and a hook's exported location variables can no
  longer point it at another repository.
- perf / scale — no new spawn; the same one `git log` per read.
- error / empty / loading states — unchanged: a failed call is the runner's named `OSError`.
- observability — unchanged: the error names the command and git's stderr.
- risks — a CLI caller that pointed the reader at a repository through `GIT_DIR` from outside it: none
  exists in the tree. `TOOL-dDeclaredLoop-38` and `-40` edit the same gated block at the same order,
  so the three land one after another, never in parallel worktrees.
- testing — AC1 to AC5 as fixture probes; the arm under §7, observed at the close.
- migration — none.
- user docs — none: no page under `help/` describes the runner.

## 10. Reuse audit

over `tools/memory-tree/tree_lib.py#build_git_env`. The leak list is the gated canonical
