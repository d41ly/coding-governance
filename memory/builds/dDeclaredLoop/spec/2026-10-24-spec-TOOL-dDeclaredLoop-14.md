## 1. Goal

A refused item routes by default: the refusal is recorded where history can read it, and `next`
returns the frontier, the unwitnessed items of the build's step whose needs are witnessed, so a
refusal no item's own routes name still leaves the build somewhere to go. Until dWellOiledMachine
lands `next`, its stand-in is the driver's `--plan`, which prints the frontier beneath its `next:`
line. The rule is flow-steps' `[rules]`
(`memory/builds/dClosedLoop/build/2026-10-15-build-PLAY-dClosedLoop-1-flow-steps.md@d73cb002d028:31`
to :33), and `tools/playbook/principles.toml@701c20bb8c9c:150` maps this clause to P24.

## 3. Non-goals (OUT)

### Data model

The two fields `Position` gains, beside unit 7's:

```python
"frontier": [{"item": str, "unit": str, "actor": str, "key": str}],  # derive_frontier, in order
"refusals": [{"item": str, "key": str, "reason": str, "at": str}],    # the run's refusal rows
```

`next` is `frontier[0]`, or `None` where the frontier is empty.

### The frontier

```python
def derive_frontier(items, witnessed, unheld, unit_id, head) -> list[dict]:
    """The rows of `items`, the build's step's in composition order, whose tag is not in `witnessed`
    and each of whose needs is met by a tag in `witnessed`; each entry as unit 7's `next`."""
```

`witnessed` maps each held tag to the inputs its witness read, and `unheld` each tag read whose
witness does not hold to its inputs; an unread tag is in neither, so it meets no need. Both come
from the `read_witness` results `derive_next_item` already takes, over the step's tags and every tag
their needs name. An entry is `{"item": tag, "unit": unit_id, "actor": row.get("actor", "?"), "key":
