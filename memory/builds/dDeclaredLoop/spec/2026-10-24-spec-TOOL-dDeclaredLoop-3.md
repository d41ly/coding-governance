## 1. Goal

A build's stage transition is recorded three ways: a commit trailer, a per-build log record and a
micro-format line. `transitions.record` selects which, any subset and never empty, all three by
default (v2:1156). The trailer is the source, and one check holds each other channel to it, so the
copies never disagree silently (the owner's S4,
`memory/builds/dClosedLoop/build/2026-10-14-build-PLAY-dClosedLoop-1-walkthrough.md:83-89`). Today the
trailer key `Gov-Transition` is registered in `tools/playbook/edges.toml` and in the trailer reader's
floor (`tools/lib/commit_trailers.py#FLOOR_KEYS`), and the build table's B4, B5, B7, B12 and T3 rows in
`tools/loop/loop.toml` name "the transition record" as their witness, yet nothing writes either. The
only move record is the `phase:` and `witness:` facts the unattended driver writes into a run's RUN.md
(`tools/unattended/unattended.sh#verb_phase`), and no check holds one copy to another. C2-F9 asks for
the key to be read, seen on a planted subset and red on an empty set.

## 4. Design

### The trailer

```
Gov-Transition: planning -> designing · build=dExample · item=item.plan.exit · sha=3f9c2a71 · stand-in=dRankedPlan
```

Grammar: the head `<from> -> <to>`, each a build state of `TOOL-dDeclaredLoop-13`'s `[states]`, open
(`build`) or terminal (`terminal`), or `none` for the level's entry; then ` · `-separated
`<name>=<value>` fields. `build`, `item` and `sha` are required and come first in that order; every
other name must be in `TRANSITION_FIELDS`, a tuple in `tools/loop/loop_transition.py` that this unit
ships holding `stand-in` and that later units extend. A value matches `[A-Za-z0-9._:+@-]+`, so it
never holds the separator. `sha` is eight to forty hex digits, and the writer writes the witness
commit's first eight. One trailer per transition commit; a second one in one commit is refused by
`check`. The key is registered (`tools/playbook/edges.toml`), so `read_commits` reads it, and it is a
floor key where no table is installed.

### The log record

The writer calls `write_record(root, build, anchor, "transition", title, fields)` of
`tools/memory-tree/build_records.py`, found through `read_memory_tree`, with one field each for
`Build`, `From`, `To`, `Item`, `Sha` and every extension field, its name capitalised (`Stand-in`).
`write_record` refuses a value holding a CR, an LF or a forged `**<Word>:**` opening, before it writes
anything. The record:

```
# TOOL-dExample-1 transition 1 — planning -> designing

**Serves:** transition TOOL-dExample-1

- **Build:** dExample
- **From:** planning
- **To:** designing
- **Item:** item.plan.exit
- **Sha:** 3f9c2a71
- **Stand-in:** dRankedPlan
```

The kind row declares `Build`, `From`, `To`, `Item` and `Sha` required and no closed set.
`read_transition(path, text)` reads it through `read_record` with its own rules: `Sha` is eight to
forty hex digits, and `From` and `To` are single words. The factory's `read` verb gains its
`transition` branch, since its fall-through reads a record as an exception. The record serves as
`transition`, never `journal`: `tools/memory-tree/tree_lib.py#read_bindings` reads a
`-transition-<n>.md` file whose Serves kind is not `transition` as malformed. The binding names one
id, the anchor, so every transition record lists in the anchor spec's records region alone, where a
`journal` binding naming every unit would list in every unit's region, as this spec's own region
shows for the build's agent ledger.

A move made while the build defines no spec writes no log record; the writer's next move after the
first spec writes one for every earlier trailer of the build first, each from its trailer, oldest
first, so `<n>` follows the move order. Until then `check` prints `pending — <n> move(s) before the
build's first spec` and reads not green for the log channel. `check` compares the record's
`**Key:**` fields only; a line a later unit appends to a record, such as `TOOL-dDeclaredLoop-30`'s
`draw` rows, is that unit's to grade. A record's adding commit is read through
`tools/memory-tree/tree_lib.py#read_adding_commits`, and the selection at that commit says whether the
record owed a trailer.

### The micro-format line

The writer prints `transition — <slug> · <from> → <to> · <item tag> · <sha>` after the commit, where
`micro-format` is selected, rendered by `render_transition_line(fields)` from the same fields the
trailer carries. It is an emitted line for the final message, as the block's other shapes are, and
stores nothing. `check` holds it to the trailer by holding its definition: the `transition` line of the
`<!-- microformats -->` fence of the toplevel `AGENTS.md`, the file the format guard and the run-log
prose reader key on, must equal `TRANSITION_LINE`, so a renderer and a definition cannot drift. The
definition passes `tools/check-microformats.sh`'s grammar: one joiner, a one-word head no other
definition uses, lowercase placeholders and ` · ` field breaks.

### The source, by selection

| Selected | Written | Source `check` and `read_transitions` read |
|---|---|---|
| `trailer`, `log`, `micro-format` (default) | all three | the trailer |
| `trailer` and one other | those two | the trailer |
| `log` without `trailer` | the record, committed with no trailer | the log record |
| `micro-format` alone | the line only, no commit | none: `check` prints `unstored` for the build and exits 1 |

### The writer, in order

1. Read the channel set at `HEAD`; a `Refusal` exits 2 naming `transitions.record`, and an unresolved
   policy kit exits 2 `unarmed`.
2. `derive_move("build", from, item, outcome, facts)` of `tools/loop/loop_table.py`; `TransitionRefused`
   exits 1 printing `refused`, and a `ValueError` exits 2 printing `unanswered`, as `loop_table.py move`
   does.
3. Resolve `--witness` with `tools/loop/loop_witness.py#resolve_commit` to a commit that is `HEAD` or
   its ancestor, else exit 2; when the item has a `[[stand-in]]` row (`read_stand_ins`), append the
   extension field `stand-in=<owner>`. A `--field` name outside `TRANSITION_FIELDS`, or a value outside
   the character class, exits 2.
4. Refuse with exit 2 when the index holds staged changes, so a transition commit never sweeps in
   other work.
5. Back-fill missing log records, then write this move's record where `log` is selected.
6. Commit the staged records, or an empty commit, with subject
   `loop transition(<slug>): <from> -> <to>` and the trailer where `trailer` is selected.
7. Print the micro-format line where selected.

### The fixture

`--fixture --plant <case>` builds a scratch repository under the host temp directory with
`tools/loop/loop_witness.py#run_fixture_git` and `#write_fixture_files`: a `.memory-tree.conf`, the
build `tFix` with one spec, an `AGENTS.md` whose micro-format fence holds the definition, a
`.governance/policy.toml` per plant, and a witness commit. It runs `record` and `check` in process,
deletes the scratch through `#remove_tree`, and prints each verdict. `check --selftest` runs every
plant through `tools/loop/loop_lib.py#run_selftest_cases`. The plants: `default`, `subset-trailer-line`,
`subset-log`, `empty-set`, `log-drift`, `orphan-log`, `no-row`, `line-drift`, `pre-spec` and `field`.
