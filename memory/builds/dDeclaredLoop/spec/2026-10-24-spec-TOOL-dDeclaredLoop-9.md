## 1. Goal

Every item of a step's program declares exactly one actor of one kind, its inputs, its allowance, its
return schema and its witness, and an item whose actor is a role takes the role's defaults through
`roles_lib.py`, never a copy of them. Items today carry more than one actor and many state no witness
(`gap-flow-13`); flow-steps' `[rules]` state the rule ("One actor per item, of one kind",
flow-steps.md:21-26) and nothing checks it.

## 2. Scope (IN)

- **S1** — The declaration check, `check_item_declarations(items, roles)` in `tools/loop/loop_lib.py`,
  over every `[[item]]` row TOOL-dDeclaredLoop-12 declares, each tag `item.<step>.<name>`: `actor` one
  string `<kind>:<name>` or the bare `executor` or `owner`, its kind in the closed set `role`,
  `command`, `executor`, `hook`, `owner`; `inputs`, `allowance` and `returns` present after defaults;
  `witness` present, its class graded by TOOL-dDeclaredLoop-5's `check_witness_classes`. Observed by
  AC1 and AC2.
- **S2** — The role defaults, `resolve_item_declaration(item, roles)`: for an actor `role:<slot>`,
  `roles` read by `roles_lib.load_roles` (`tools/roles/roles_lib.py:330`) through
  `resolve_kit_dir("roles", "roles_lib.py", here)`, an absent `inputs` is the role's `reads`, an absent
  `allowance` its `writes` and an absent `returns` its `returns`. A role item's explicit field equal to
  its role's value is refused as a copy; its `allowance` may only narrow to `none`. Observed by AC2 and
  AC3.
- **S3** — A role the catalogue does not hold: an actor `role:<slot>` with no
  `tools/roles/agents/<slot>.agent.md` is printed `pending`, with the roles the flow names that
  dBoundRoles lands (planner, architect, tester), counted and never green; its item's defaults are
  `unarmed`. Observed by AC2.
- **S4** — The allowance vocabulary read from the roles kit: `WRITES` (`tools/roles/check_roles.py:94`)
  moves into `tools/roles/roles_lib.py`, `check_roles.py` importing it, so a non-role item's explicit
  `allowance` and a role's `writes` are graded against one tuple. Observed by AC4.
  **Readers:** by name: `tools/roles/check_roles.py`, the tuple's one reader, re-pointed to the
  library's tuple · by value: `tools/roles/check_roles.py`, whose R2 and R3 compare each role's `writes`
  to it, unchanged in verdict.
- **S5** — The rows' actors normalised to S1's form: flow-steps' role names map to roles slots
  (`builder` to `role:gov-builder`, `spec writer` to `role:gov-spec-writer`, `researcher` to
  `role:gov-researcher`, `reuse scout` to `role:gov-reuse-scout`, `orientation scout` to
  `role:gov-orienter`), and each role row's fields that copy its role are dropped. Observed by AC1.

## 4. Design

### The actor

| Kind | Form | Resolves through |
|---|---|---|
| `role` | `role:<slot>` | `roles_lib.load_roles`, the slot a `tools/roles/agents/<slot>.agent.md` stem |
| `command` | `command:<tool path or verb>` | today's tool, named by its path (flow-steps `[rules]`) |
| `executor` | `executor` | the executor's stand-in (TOOL-dDeclaredLoop-17); the executor is outside this build (v2:2014) |
| `hook` | `hook:<event>` | the hook that writes the record |
| `owner` | `owner` | the owner's disposition record (TOOL-dDeclaredLoop-16) |

An item a policy value gives a different actor is one item per value (flow-steps `[rules]`), so an
`actor` holding a list, a comma, or two kinds is refused, naming the item.

### The defaults

```python
def resolve_item_declaration(item, roles):   # -> {inputs, allowance, returns, source}
    # source per field: "item" (declared), "role:<slot>" (inherited), "unarmed" (role pending)
```

For a role item, `roles[slot]["keys"]` is the front matter `load_roles` already parses
(`FRONT_MATTER_KEYS`, `tools/roles/roles_lib.py:31-32`): `reads` (the closed `READ_KEYS`, :35-39),
`writes` and `returns`. The loop kit does not `require` roles, since roles requires loop
(TOOL-dDeclaredLoop-1): the read is a declared optional one, a `requires_if` row in `tools/loop/kit.toml`
naming this unit, as the roles descriptor declares its review-harness edge (`tools/roles/kit.toml:19`).
Where roles does not resolve, every role item's defaults print `unarmed: the roles kit does not
resolve`, never green.

### The check, per item

```
actor     one string; kind in {role, command, executor, hook, owner}; a role slot resolves or is pending
inputs    non-empty after defaults
allowance one word of roles_lib.WRITES after defaults; a role item may narrow only to "none"
returns   non-empty after defaults
witness   present; check_witness_classes grades its class
copy      a role item's explicit field equal to its role's value is refused
```

`tools/roles/roles_lib.py`; the plants `actor-two`, `actor-bad-kind`, `witness-missing`,
