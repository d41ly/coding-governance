## 1. Goal

Every item of a step's program declares exactly one actor of one kind, its inputs, its allowance, its
return schema and its witness, and an item whose actor is a role takes the role's defaults through
the roles kit's `roles_lib.py`, never a copy of them. `TOOL-dDeclaredLoop-12` landed the item rows in
`tools/loop/loop.toml`, 61 of them (PINNED 2026-11-14), each with one actor string and a witness, and
`tools/loop/loop_lib.py#check_program` grades their structure alone. Nothing grades an actor's kind,
the fields a non-role actor owes, a role item's defaults or its copies, or an item witness's class:
the module docstring's WHAT THIS DOES NOT CHECK paragraph says each field's content is its own
unit's (`gap-flow-13`). Flow-steps' `[rules]` state the rule, "One actor per item, of one kind", and
this unit is what checks it.

## 2. Scope (IN)

- **S1** — The declaration check, `check_item_declarations(items, roles, why)` in
  `tools/loop/loop_lib.py`, over every `[[item]]` row, each tag `item.<step>.<name>`. The `actor` is
  one string, `<kind>:<name>` or the bare `executor` or `owner`, its kind in the closed set `role`,
  `command`, `executor`, `hook`, `owner`. A non-role item carries a non-empty `inputs`, `allowance`
  and `returns`; a role item's are resolved by S2. A role item's explicit `allowance` may only be
  `none`, and a role item's explicit field equal to its role's value is refused as a copy. It returns
  one printed line per item and the refusals. Observed by AC1 and AC2.
- **S2** — The role defaults. `read_role_defaults(kit_dir)` finds the roles kit through
  `resolve_kit_dir("roles", "roles_lib.py", kit_dir)`, imports its library inside the function body
  and returns `roles_lib.load_roles` of that directory, or None and why. `resolve_item_declaration(item,
  roles)` gives a `role:<slot>` item's absent `inputs` the role's `reads`, split on commas, its absent
  `allowance` the role's `writes` and its absent `returns` the role's `returns`, and names each
  field's source. Observed by AC1 and AC3.
- **S3** — A role the catalogue does not hold, and a roles kit that does not resolve. An actor
  `role:<slot>` whose slot `load_roles` does not return is printed `pending`, counted and never green;
  where `read_role_defaults` returns None every role item is printed `unarmed` with the reason. Neither
  is a refusal, so neither moves the exit. Observed by AC1 and AC2.
- **S4** — Out of scope from rev-2 (§8 F6). The allowance vocabulary keeps its one home,
  `tools/roles/check_roles.py#WRITES`, and a non-role item's `allowance` is the free text S1 grades
  non-empty. NOT OBSERVED: this item builds nothing.
- **S5** — The 18 role actors (PINNED 2026-11-14) in `tools/loop/loop.toml` spelled by their role
  file's stem (§8 F5): `role:planner` becomes `role:gov-planner`, and `builder`, `architect`,
  `researcher`, `reuse-scout`, `spec-writer` and `tester` take the same `gov-` stem. No role row
  carries a field copying its role at HEAD, so no field is taken off a row. Observed by AC1 and AC4.
  **Readers:** by name: `tools/loop/loop.toml`, whose 18 rows spell the short form (PINNED
  2026-11-14), and `help/loop.md`, whose item paragraph spells `role:planner` · by value: NO VALUE

- **S6** — Each item's witness classed. `tools/loop/loop_lib.py#check_witness_classes` walks the

## 4. Design

### The actor

| Kind | Form | Resolves through | Rows at HEAD (PINNED 2026-11-14) |
|---|---|---|---|
| `role` | `role:<slot>` | `read_role_defaults`, the slot a role file's stem under the roles kit's `agents/` | 18 |
| `command` | `command:<verb or tool>` | the command the supervisor runs (flow-steps `[rules]`) | 40 |
| `executor` | `executor:<name>` or `executor` | the executor's stand-in (`TOOL-dDeclaredLoop-17`) | 2 |
| `hook` | `hook:<event>` | the hook that writes the record | 0 |
| `owner` | `owner:<name>` or `owner` | the owner's disposition record (`tools/loop/loop_lib.py#check_disposition_record`) | 1 |

The closed set is a module constant, `ACTOR_KINDS`, and the form one pattern, `ACTOR_FORM`, fullmatched
as `([a-z]+):([^\s,:]+)`. An item a policy value gives a different actor is one item per value
(flow-steps `[rules]`), so an `actor` that is no string, a list included, or that carries a comma,
whitespace or a second colon is refused, naming the item and the value. A kind outside the set is
refused naming the kind.

### The defaults

```python
def read_role_defaults(kit_dir):              # -> (roles or None, why)
def resolve_item_declaration(item, roles):    # -> {inputs, allowance, returns, source}
    # source per field: "item" (declared), "role:<slot>" (inherited), "pending", "unarmed"
```

`read_role_defaults` follows `tools/loop/loop_lib.py#read_builds_dir`: `resolve_kit_dir` from the
loop kit's directory, the found directory put on `sys.path`, `import roles_lib` inside the body, and
`roles_lib.load_roles(<dir>)`. A `LookupError`, an `ImportError` or a `roles_lib.RolesError` returns
None and its message. It mirrors `tools/roles/roles_lib.py#read_workflow_order`, which reaches this
kit the same way, so neither module imports the other at load and no import cycle exists.

`load_roles` returns `{slot: {"path", "keys", "body"}}`, `keys` the raw front matter
`tools/roles/roles_lib.py#parse_front_matter` reads over `FRONT_MATTER_KEYS`: `reads` a
comma-separated line over `READ_KEYS`, `writes` one word, `returns` one line. A role's `reads` are
`READ_KEYS` members such as `input:spec`, not layer tags, and `check_program` grades only the
`inputs` a row writes, so an inherited `inputs` is never held to the layer tags.

### The check, per item

```
actor     one string; ACTOR_FORM or bare executor/owner; kind in ACTOR_KINDS; a role slot resolves,
          is pending, or the roles kit is unarmed
inputs    a non-role item: a non-empty list; a role item: its own or its role's
allowance a non-role item: a non-empty string; a role item: absent, or "none"
returns   a non-role item: a non-empty string; a role item: its own or its role's
copy      a role item's explicit inputs, allowance or returns equal to its role's is refused
witness   check_witness_classes, over the item rows after the step rows (S6)
```

The copy test compares an explicit `inputs` list with the role's `reads` split on commas and
stripped, and an explicit `allowance` or `returns` with the raw value. A role whose `writes` is
`none` therefore takes no explicit `allowance` at all, since `none` would copy it. A pending role's
explicit `allowance` is still held to `none`, and its copies go ungraded.

### Where it runs

`main`'s `--check` and `--fixture --plant` path calls `read_role_defaults(kit_dir)` after
`check_program` and before the witness lines, prints one line per item in file order and a count, and
adds the refusals to `check_actor_list`'s, each printed `loop: refused · ...`, exit 1:

```
loop: item <tag> · <actor> · inputs from <source> · allowance <value> from <source> · returns from <source>
loop: item <tag> · <actor> · pending · the roles kit holds no <slot> role
loop: item <tag> · <actor> · unarmed · <why>
loop: items · <n> read · <p> pending · <u> unarmed
```

`load_loop`, `read_items`, `read_workflow_order`, `--scopes` and `--grade-site` never reach the roles
kit. `--grade-site` calls `check_witness_classes`, so S6 grades item witnesses there too.
