## 1. Goal

A build whose rework budget is spent ends, and never laps again. `flow.on-exhausted` names how:
`best-effort-ending`, the default, takes the ending the build's evidence supports and records it for the
owner; `park-for-owner` parks the build until the owner's disposition record; `close-incomplete` closes it
`incomplete` with its branch and records kept. Each ending is a row of the build's transition table, and a
choice to lap again is refused. Today the only derived terminal the driver writes is LANDED
(`write_landed_record`, `tools/unattended/unattended.sh:7862-7875`), there is no `incomplete` state, no
exhaustion record and no refusal of another lap (`gap-flow-23`).

## 4. Design

### The rows

|---|---|---|---|---|---|---|
| E1 | `@open` | `@any`, `exhausted` | `ending = "close-incomplete"` | before-push | `incomplete` | the exhaustion record, and every open unit's `defer` row |
| E2 | `@open` | `@any`, `exhausted` | `ending = "park-for-owner"` | none | `parked` | the exhaustion record and the hold |
| E3 | `parked` | `@any`, `disposed` | `disposition = "continue"` | none | `@prior` | the owner's disposition record naming the hold's `decision` row |

| E5 | `testing` | `@any`, `exhausted` | `ending = "descope"` | none | `building` | the exhaustion record naming the descoped unit and its ask, and the revert commit |

These are flow-steps.md:758-765's rows. E1 also serves `best-effort-ending` where nothing can land, since
`derive_ending` answers `close-incomplete` there. Each carries `draws = "none"`, the field this unit adds to
`[[transition]]` and the termination check reads: a row that spends nothing is not a counted edge, and an
ending is not a lap. The engine is asked the move as `derive_move("build", state, "@any", "exhausted",
{"ending": <ending>})` (`TOOL-dDeclaredLoop-13` S5), through `loop_table.py move`. A
best-effort descope in Build moves no state and so has no row; its units go to asks, named on the exhaustion
record (flow-steps.md:768-770). Landing what is witnessed green also moves no state outside the table's own
`deploying` to `landed` row.

### The rule

```
derive_ending(value, units, state)                 units: {id: status}
  value == "park-for-owner"                      -> park-for-owner
  value == "close-incomplete"                    -> close-incomplete
  value == "best-effort-ending":
    every unit CLOSED and at least one unit      -> land-green
    some unit CLOSED                             -> descope   (row testing->building when state == testing)
    otherwise                                    -> close-incomplete
  any other value                                -> refused, naming the key and the value
```

A build with no units has nothing that can land, so best effort closes it incomplete; the flow-steps join a
planted build that spends its budget in planning must reach `incomplete` is that case. The function returns
an ending and the row it takes, never a draw, so no evidence it reads can produce another lap. It is a pure
function, and `python endings.py derive --value <v> --state <s> --units <id>=<status>,...` prints its answer
as one line, which is how the driver calls it: the module found with `resolve_kit_dir`
(`tools/unattended/lib-unattended.sh:191`), as the driver finds the index generator, and run with
`run_bounded "$_py"`, the shape at `tools/unattended/unattended.sh:10567`.

### The verb

```
--exhausted <slug>
  refuse while remaining budget > 0                      (fail, naming spent/total)
  value  = flow.on-exhausted, default best-effort-ending
  ending = derive_ending(value, the roster's units, the run's state)
  park "$rel" decision flow.on-exhausted "ending <ending> · spent <s>/<t> · open <ids>"
  close-incomplete | descope -> refuse while an open unit has no `rescope · … · defer` row
  close-incomplete           -> verb_abort … budget-exhausted
  park-for-owner             -> the hold, code owner-decision
  land-green | descope       -> print the landing path; the run continues
```

The `decision` kind is owed (`PARK_KINDS_OWED`, `tools/unattended/unattended.sh:893`), so the exhaustion
record is surfaced to the owner at the wrap-up without a new kind, and it is the `decision` park an
`owner-decision` hold requires. `budget-exhausted` joins `HALT_CODES_CORE` (`:1024`) and not
`HALT_CODES_HANDOFF` (`:1041`): an incomplete build lands nothing. The verb never edits a spec, a branch or
a record; the abort keeps both, which is "its branch and records kept".

### The lap refusal

`TOOL-dDeclaredLoop-30`'s `record_draw` writes nothing once spent equals total and answers `exhausted`, and
each draw site refuses the repetition on it. `print_exhausted_remedy <run-state file>` is the one line that
refusal prints: with no `decision · item flow.on-exhausted` row, `--exhausted <slug>`; with one, its ending,
and that only the owner raises `flow.rework-budget`. No second guard and no second count.

### The phase reading

`TOOL-dDeclaredLoop-1`'s I3 table reads ABORTED as `withdrawn` and HELD as `paused`. Two qualified readings
come first wherever `TOOL-dDeclaredLoop-13`'s engine applies that table: ABORTED with halt code
`budget-exhausted` reads `incomplete`, and HELD with hold code `owner-decision` whose `decision` row is an
exhaustion record reads `parked`.

### Alternatives rejected

- **A new INCOMPLETE phase.** Every reader of `PHASES_CORE` (`tools/unattended/unattended.sh:852`), the
  runlog model and the drift audit's copy would gain a member, for a state the phase map can already read

  derivation over the units' states, and a derivation cannot choose to lap.

## 5. Production-readiness checklist

- security — no new write surface: the verb writes one `park()` row and calls the abort and hold verbs.
  The budget raise stays behind the policy file's guard.
- perf / scale — one roster read and one Python call per exhaustion, once per build at most.
- error / empty / loading states — an absent budget reader reads as budget remaining, so `--exhausted`
  refuses rather than ending a build on a missing fact; an unknown `flow.on-exhausted` value refuses.
- observability — the exhaustion record names the ending, the spend and every open unit, and is surfaced.
- risks — `CLOSED` is a status header, typed at the build commit; a unit closed without its acceptance
  green reads as green to `derive_ending` until witness-derived state replaces the header.
- testing — the pass probes `derive_ending` directly and the verb on fixture repositories; the arms in §7
  are observed RED then GREEN by the main loop.
- migration — none.
- user docs — the verbs carrier; no help page covers the driver.
