## 4. Design

### Why grep, and why red at base

A re-point's observable is that the old parser is gone and the new call is present. Both are
properties of the source, so a grep over code lines is the direct observation, and its liveness is
the lines it lists at base. A behavioural equality cannot be that observation: it is satisfied by
the consumer that never changed.

### The probes

```bash
# S1, the class: no product file spells its own trailer parse
git grep -n -F -e 'trailers:key=Pass,' -e 'interpret-trailers --parse' \
  -- tools ':!*.test.sh' ':!*commit_trailers.py'
# the same probe at base: the revision goes before the `--`
git grep -n -F -e 'trailers:key=Pass,' -e 'interpret-trailers --parse' ed497191 \
  -- tools ':!*.test.sh' ':!*commit_trailers.py'
# S2, one per call site, each printing at least one line; at base add `ed497191` before the `--`
git grep -n -F 'read_commits(' -- tools/memory-tree/routed_commits.py
git grep -n -F 'derive_attribution(' -- tools/memory-tree/routed_commits.py
git grep -n 'derive_attribution(.*replace' -- tools/memory-tree/deviation_join.py
git grep -n 'commit_trailers.py.* tokens' -- tools/unattended/lib-unattended.sh
git grep -n -F 'read_attribution_tokens --reverse' -- tools/unattended/lib-unattended.sh
git grep -n -F 'read_attribution_tokens -1' -- tools/unattended/check-unattended.sh
git grep -n 'commit_trailers.py.* message' -- tools/unattended/unattended.sh
# S5, the predicate over this tree, then over base
python -c "import sys; sys.path.insert(0, 'tools/memory-tree'); import routed_commits as r; \
print(*r.check_trailer_parses(r.KIT.parent, *sys.argv[1:]), sep='\n')"
python -c "import sys; sys.path.insert(0, 'tools/memory-tree'); import routed_commits as r; \
print(*r.check_trailer_parses(r.KIT.parent, *sys.argv[1:]), sep='\n')" ed497191
```

The reader is the one place a trailer parse may live, so its files are left out by name: the
canonical `tools/lib/commit_trailers.py` and each kit's copy share that file name. At HEAD no line of
them holds either needle, because `read_commits` builds its format per key and `read_message_ids`
passes its arguments as a list. The `commit_trailers_py` marker filter of rev-2 matched no line and
is not carried.

### The predicate

```python
def check_trailer_parses(root, rev=None) -> list:
    """Every line under `root` that spells its own trailer parse, as `<path>:<line>` relative to
    `root`: ONE `git grep -n -F` for the two needles, run in `root`, over its tracked files, or
    over the tree of `rev` when given, less `*.test.sh` and any `commit_trailers.py`.
    [] where git greps and finds none; Refusal where git cannot grep `root`."""
```

- The call runs under the module's pinned environment, the one `run_git` in
  `tools/memory-tree/routed_commits.py` builds, so a fixture never reads the real repository when the
  selftest runs inside a hook.
- `git grep` exits 1 for no match, and `run_git` reads every non-zero status as a failure. The
  predicate tells the two apart: status 1 with empty output is no hit, and any other failure is a
  `Refusal` carrying git's line. An unreadable root is never an empty answer.
- The pathspecs are `.`, `:!*.test.sh` and `:!*commit_trailers.py`. The root is a parameter and the
  live arm passes `KIT.parent`, so no line of the kit spells gov's prefix, which
  `tools/check-install-prefix.sh` bans.
- Neither needle may match its own source line, nor may the planted format: each is written as
  adjacent string literals split inside the needle. Otherwise the S1 probe finds the arm itself.

### The two arms

Both sit in `run_selftest` in `tools/memory-tree/routed_commits.py`, beside the arms
`TOOL-dDeclaredLoop-23` re-ran through the reader.

- **The live arm** holds when `check_trailer_parses(KIT.parent)` returns no hit, and prints each hit
  when it does not. Where the predicate raises `Refusal`, the arm prints one line saying the tool root
  is not in a git work tree and that nothing was graded, and holds: a scratch copy of the kit is a
  legitimate place to run the selftest.
- **The planted arm** builds a scratch repository through `build_fixture` holding a consumer file with
  the `%(trailers:key=Pass,valueonly)` format, a `*.test.sh` holding the same line, and a
  `commit_trailers.py` holding the same line, and calls the predicate with the fixture commit as
  `rev`. It holds when the predicate names the consumer's line and no other. `build_fixture` writes
  objects through `git fast-import` and checks nothing out, which is why the predicate takes `rev`.

### What the arm does not check

- A parse spelled another way: an argument list, a lowercase or reordered key, a format built at
  run time. `TOOL-dDeclaredLoop-67` widens the pattern.
- A key other than `Pass`, so the runlog's `Decided` format is not read.
- An untracked file, and any file outside the tool root the kit sits in.
- A tool root outside a git work tree, where the live arm says so and grades nothing. The planted arm
  still runs there, so the predicate's failing case is observed on every run.
- Whether the leg is selected: its guard in `tools/gate-legs.json` names
  `tools/unattended/lib-unattended.sh` alone of the unattended kit, and `TOOL-dDeclaredLoop-67` widens
  it.

### What the write set leaves alone

The write set was checked against HEAD and holds nothing else. The unit adds no file, so the govkit
registry, the kickoff manifest's watch list and the verdict-epoch delegate list do not move. It adds
no flag, so the `routed_commits.py` row of `tools/govkit/usage.toml` does not move. The leg keeps its
name, subject and chunk, so `tools/govkit/subject-pins.tsv` does not move: a failure still means a
kit file is wrong.

## 5. Production-readiness checklist

- security — no new surface; the predicate reads tracked files and writes nothing.
- perf / scale — one `git grep` per arm and one fixture repository. The leg's wall-clock ceiling stays
  the `routed-commits selftest` row of `tools/run-gates/selftest-budgets.txt`, which this unit does not
