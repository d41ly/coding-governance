## 1. Goal

The round-1 spec audit (`memory/builds/dDeclaredLoop/reviews/2026-10-24-review-TOOL-dDeclaredLoop-1-spec-audit-round1.md`)
confirmed finding **id 4 at HIGH**, its item **H4**, alone in that item: two units relied on "the engine applying
I3's phase-to-step table", which `TOOL-dDeclaredLoop-1` §4 keeps in prose (its §8 F4) and no code reads. Both have
since been re-grounded onto this unit. `TOOL-dDeclaredLoop-31`, landed, reads an `ABORTED` run with halt code

`park-for-owner` as `parked`, and writes no reader, leaving both readings here (its §8 F8).

`tools/unattended/unattended.sh#verb_phase` moves a run between phases without asking which step exit
the move crosses. This unit gives the map one owner in code, and builds that hold on it.

A stepped row's state is its step's, read from the `[[step]]` row and never typed beside it. The schema
comment gains one paragraph after the `[[owed-row]]` one: one `[[phase]]` row per phase of the unattended
driver's `PHASES_CORE`, its keys, the qualifiers, and that `loop_table.py` beside the file reads and checks
them.

### The reader

```
PHASE_KEYS = ("phase", "state", "step")
QUALIFIERS = ("halt-code", "hold-code", "ending")

read_phase_map(data, where) -> {"rows": [[phase]] rows ungraded, "steps": check_loop(data, where)["step"]}
  LoopError where `phase` is no array of tables

derive_phase_position(phase, facts, phase_map=None) -> (state, step)
  phase_map None: read_phase_map over the shipped definition
  row = the first row of `phase`, in file order, carrying a qualifier, whose every qualifier
        equals facts[<its key>]; else the row of `phase` carrying none
  no row                                   -> LookupError naming the phase
  step = row["step"] or "none";  state = row["state"], else the state of the [[step]] row tagged step

derive_crossed_exits(from_step, to_step, steps) -> [exit tags]
  the `exit` of each [[step]] row whose order is at least from_step's, 1 where from_step is "none",
  and below to_step's; [] where to_step is "none"
```

A move out of a phase with no step, `PREFLIGHT`, counts from the first step, so a jump from the preflight
into Build crosses Plan's and Design's exits: a hold denies the jump by default rather than reading the
stepless start as already past every gate.

### The verb

```
python loop_table.py phase --from <PHASE> [--to <PHASE>] [--fact k=v]...
phase <PHASE> · state <state> · step <tag|none>                                     exit 0
phase <PHASE> · state <state> · step <tag|none> · to <PHASE> · crosses <tags|none>  exit 0, with --to
refused — phase <PHASE>: no row                                                     exit 1
loop: refused · <why>                                                               exit 1, a phase table that does not read
loop: unarmed · <why>                                                               exit 2, as `move` and `check`
```

### The check

`check_phase_rows(phase_map, core, states, terminal)` returns `(lines, refusals)`, `core` the
`PHASES_CORE` members or `None`:

- refused: a row whose `phase` is no word of `[A-Z][A-Z_]*`, or that carries a key outside `PHASE_KEYS`
  and `QUALIFIERS`; a row carrying both `state` and `step`, or neither; a `step` that is no `[[step]]` tag;
  a `state` that is no build state, terminal nor `none`; a qualifier whose value is no non-empty string;
  two unqualified rows of one phase;
- the join, where `core` is given: a member with no unqualified row, and a row whose phase is no member,
  each refused naming the phase;
- printed: `loop: phase map · <n> row(s) · <q> qualified`, then `loop: phase join · PHASES_CORE · <k>
  phase(s)`, or `loop: phase join · unarmed · <why>` where `core` is `None`.

`main`'s `check` path reads `core` through `read_core_registries(KIT, ("PHASES_CORE",))`, `None` on its
LookupError, and its refusals print as every other `loop: refused · ...` line. The plants pass `core` as the
shipped rows' unqualified phases, taken before the break, so each draws its refusal in an install
holding no driver; the shipped `loop transition tables` leg therefore stays green in a target holding the
loop kit alone.
