## 1. Goal

The round-1 spec audit (`memory/builds/dDeclaredLoop/reviews/2026-10-24-review-TOOL-dDeclaredLoop-1-spec-audit-round1.md`)
confirmed finding **id 4 at HIGH**, its item **H4**, alone in that item. `TOOL-dDeclaredLoop-19` S6 and §4
"The hold", and `TOOL-dDeclaredLoop-31` S7 and AC6, rely on "`TOOL-dDeclaredLoop-13`'s engine applying I3's
phase-to-step table". `TOOL-dDeclaredLoop-1` S8 marks that table NOT OBSERVED and its §8 F4 keeps it in
prose, `TOOL-dDeclaredLoop-13` §3 declines any change to phase handling, and `TOOL-dDeclaredLoop-7` §3 says
the uppercase phases decide no position. So `TOOL-dDeclaredLoop-19`'s `--phase` refusal past a gated step
exit has no table to read, unless a builder types a copy, which it forbids, and
`TOOL-dDeclaredLoop-31` AC6 observes a component no spec defines. This unit gives the map one owner in code.
It repairs `TOOL-dDeclaredLoop-19`.

## 2. Scope (IN)

- **S1** — The map as `[[phase]]` rows of `tools/loop/loop.toml`, one per `PHASES_CORE` member
  (`tools/unattended/unattended.sh:852`), each `phase`, `state` (a build state of `[states]` or `none`) and
  `step` (a step tag or `none`), transcribed from `TOOL-dDeclaredLoop-1` §4's I3 table; and qualified rows
  carrying `halt-code` or `hold`, `TOOL-dDeclaredLoop-31` S7's two: `ABORTED` with `halt-code =
  "budget-exhausted"` to `incomplete`, and `HELD` with `hold = "exhaustion"` to `parked`. Observed by AC1.
- **S2** — The reader, `read_phase_map(kit_dir)` in `tools/loop/loop_table.py`, `TOOL-dDeclaredLoop-13`'s
  engine module, and `derive_phase_position(phase, halt_code=None, hold=None)`, which picks the qualified
  row that matches and the unqualified one otherwise; and the CLI `python tools/loop/loop_table.py phase
  <PHASE> [--halt-code <c>] [--hold <h>]`, printing `state <s> · step <t>`. Observed by AC1, AC2.
- **S3** — The check, added to `check_transition_tables`: every `PHASES_CORE` member has exactly one
  unqualified row, read from the driver through `resolve_kit_dir("unattended", "unattended.sh", here)` and
  printed `unarmed` where the driver does not resolve; every row's `state` is in `[states]` or the
  terminal set, and its `step` a declared step tag. Observed by AC3.
- **S4** — The consumers pointed at it by name: `TOOL-dDeclaredLoop-19` S6's `--phase` refusal asks
  `loop_table.py phase` for the step of the phase it is moving to, and `TOOL-dDeclaredLoop-31` S7's reading
  is `derive_phase_position` with the run's halt code and hold. This supersedes both specs' reference to
  "`TOOL-dDeclaredLoop-13`'s engine applying I3's phase-to-step table". Observed by AC2, AC4.

  owns every state-table read.

- security — no new surface.
- perf / scale — one row read per `--phase` call, through one interpreter start the refusal already pays.
- error / empty / loading states — a phase with no row refuses by name; no driver prints the join

- observability — the CLI prints the row it matched.

## 6. Acceptance criteria

- **AC1** — When `python loop_table.py phase REVIEWING` runs, it prints `state designing · step
  step.design`; `phase ABORTED --halt-code budget-exhausted` prints `state incomplete · step none`; and
  `phase ABORTED --halt-code fork-unresolvable` prints `state withdrawn · step none`.
  Red when: the qualified row is not preferred, so a budget-exhausted run reads withdrawn.
- **AC2** — When `phase HELD --hold exhaustion` runs, it prints `state parked`, and `phase HELD` alone
  prints `state paused`.
  Red when: a hold qualifier is ignored.
- **AC3** — When `python loop_table.py --fixture --plant phase-missing` runs with one
  `PHASES_CORE` member lacking a row, the check exits 1 naming it.
  Red when: the join reads only the rows, so a new driver phase has no mapping and nothing says so.
- **AC4** — When `grep -n 'loop_table.py.* phase' tools/unattended/unattended.sh` runs on the built tree,
  it finds the `--phase` refusal's call.
  Red when: the refusal keeps a typed table, or reads none.
