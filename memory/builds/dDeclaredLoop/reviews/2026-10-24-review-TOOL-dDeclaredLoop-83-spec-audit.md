## High

### H1. 86: `derive_conf_constants` misses the repo's own conf-binding idioms, so `no-own-conf-read` certifies a module that reads its conf (id 29)

- **Where:** 2026-10-24-spec-TOOL-dDeclaredLoop-86.md, §2 S13; §4 "The conf-constant kind, after this unit"; §6 AC13.
- **What is wrong:** S13 lists the value forms one by one: a str Constant, a JoinedStr, a BinOp of strings, and Path(...) or PurePath(...) over one of those. It leaves out the forms this repo mostly uses to bind a conf path: `HERE.parent / ".unattended.conf"` (a BinOp Div with a non-str operand), `os.path.join(root, ".memory-tree.conf")`, and a Path call with several arguments. A `from loop_lib import NAME as alias` import is not covered either; only `import ... as ll` and the star import are.
- **Consequence:** If loop_lib binds `CONF = HERE.parent / ".unattended.conf"` and a loop module reads `ll.CONF`, the rule reports no `conf constant` hit. It then certifies a module as reading no conf of its own when it does. AC13 plants only the listed forms, so it stays green. tools/loop is unbuilt, so the path is plausible but not certain.
- **Fix (skeptic judged SOUND):** State the class rather than instances: a module-level binding whose value expression contains, anywhere in its subtree, a str Constant or JoinedStr part holding a conf name. Count `from loop_lib import X as Y` as binding Y. Add `conf-read-forms` rows for `CONF = ROOT / ".unattended.conf"`, `CONF = os.path.join(ROOT, ".memory-tree.conf")` and an aliased from-import, each answering one `conf constant` hit, and make AC13 name them.
- **Left-shift gate:** a checklist entry, "a syntactic matcher states the class it matches (any subtree containing X), never a list of node shapes; its fixture plants the repo's dominant idiom, found by grep".
