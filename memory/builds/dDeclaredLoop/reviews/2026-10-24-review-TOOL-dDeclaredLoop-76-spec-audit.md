## High

### H1. 76: the `no-own-conf-read` rule flags its own module's fixture code (id 20)

- **Where:** 2026-10-24-spec-TOOL-dDeclaredLoop-76.md, §2 S2 and S3, §6 AC1 and AC3.
- **What is wrong:** S2 counts every non-docstring string constant that ends in `.unattended.conf` or `.memory-tree.conf`. S3 runs that rule over the whole of budget.py and breakpoints.py. Those same modules hold `--fixture` plants that have to write exactly those conf files into scratch trees: 76's own AC3 `root-source`, 72 S4's `confs-disagree` and `unattended-root`, and 79 AC20/AC25's `trailing-slash-agree`, `unset-driver-root` and `no-confs`. No spec names an exported conf-name constant the fixtures could use instead.
- **Consequence:** Built as written, `no-own-conf-read` is red at 76's own pass and in the `loop budget fixtures` and `loop breakpoints fixtures` legs. The builder then has to exempt code ad hoc or weaken the rule, and the property 72 AC4 was meant to grade goes ungraded.
- **Fix (skeptic judged the finder's fix UNSOUND; this is the skeptic's corrected fix):** Use one syntactic boundary. S2 excludes every node under a function whose name opens `fixture_` or `plant_`, and says so. AC1 stages a conf constant outside that boundary and requires a non-zero exit. A new AC runs `no-own-conf-read` after 76 AC3's, 72 S4's and 79 AC20/AC25's plants exist in the module, and requires exit 0.
- **Left-shift gate:** a spec-lint check that, for any AC asserting that a static rule exits 0 over a module, finds every sibling spec that adds a plant to the same module and requires the rule's population to say where those plants sit. Where no gate fits, add a checklist entry: "a static scan over a module that also holds fixtures must name the fixtures' boundary".

### H2. 78: every non-zero merge-tree exit is treated as `uncomputable`, so a fatal error skips the policy check (id 28)

- **Where:** 2026-10-24-spec-TOOL-dDeclaredLoop-78.md, §2 S1, and §4 "The grade, restated" (first line of C).
- **What is wrong:** S1 makes C `uncomputable` on any `merge-tree --write-tree` exit other than 0. That puts git's fatal exit 128 in the same bucket as an octopus merge or a git without the feature. Exit 128 covers "refusing to merge unrelated histories" (the skeptic reproduced it), missing objects and a broken object store. Every such case takes 69 S2's parent-equality exemption.
- **Consequence:** A run branch built from an orphan commit keeps the old policy bytes and is merged into main with `--allow-unrelated-histories`. merge-tree exits 128, blob(M) equals the orphan parent's blob, the merge is skipped, and the old policy keys reach main with no `Gov-Policy:` trailer. A shallow or partial clone fails open the same way. The guard fails open on a failed dependency, on a narrow path.
- **Fix (skeptic judged the finder's fix UNSOUND; this is the skeptic's corrected fix):** Refuse by name every merge-tree exit other than 0, 1 (as 75 S27 admits it) and the feature-probed 129, and never take the exemption: `policy: <merge8> — the clean re-merge failed: <rc> <stderr first line>`. That covers 128 for unrelated histories, missing objects and death by signal. Probe for the `--write-tree` feature once instead of inferring it from the exit code. Add plant `push-merge-unrelated-histories`: an orphan run branch that keeps the old policy, merged into main with no trailer, expected to exit 1 printing `the clean re-merge failed`. Add a plant that stubs merge-tree to exit 128, expected to refuse and not skip.
- **Left-shift gate:** a bug-class checklist entry, "a guard that maps a subprocess's failure codes must refuse each one by name, and only a feature-probed absence may take an exemption", and a fixture convention that every exemption branch has a plant reaching it through a fatal exit.
