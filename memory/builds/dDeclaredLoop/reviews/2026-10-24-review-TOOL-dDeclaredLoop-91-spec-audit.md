## HIGH

### H1. AC16 says the guard plant exits 0, and four sibling criteria say it exits 1 (id 1)

- **Where:** 92 §6 AC16 and §2 S17. The siblings are 81 AC3, 83 S2, 88 S18 and 88 AC18.
- **What is wrong:** AC16 requires `python guard.py --fixture --plant push-merge-tree-fatal` to exit 0. The four siblings require that same plant to exit 1 on its refusal (`the clean re-merge failed: 128`). A named guard plant exits 1 by convention. AC16's "exits 0" was borrowed from the budget-plant convention in 92's own S7.
- **Consequence:** AC16 cannot pass on a build that satisfies 81 AC3 and 88 AC18. A builder who makes AC16 pass flips the plant's refusal verdict, and the siblings' "the merge is refused" checks then go red or get bent to match.
- **Fix (judged SOUND by the skeptic):** Restate AC16 to read: "`python guard.py --fixture --plant push-merge-tree-fatal` exits 1, as 81 AC3 states, and its `OSError()` row prints `the clean re-merge failed: start failed: OSError`". Another option is to name no exit code, as 86 AC22 and 90 AC21 already do.
- **Left-shift gate:** Have check-spec-tokens collect every `<command> exits N` claim across the build's specs and fail when one command line carries two different exit codes. Item M9 (id 11) is the same contradiction, kept as its own item because its binding grade is medium.

- **Fix (judged SOUND by the skeptic):** Narrow AC8's predicate to resolution forms: an `import tree_lib`, a `from tree_lib`, or a `resolve_kit_dir(..., "tree_lib.py", ...)` call outside `loop_lib.load_tree_lib`. Or exempt the plant rows inside 80's fixture boundary by name and say why. State whether the match is equality or substring. ### M2. AC8's attribute probe finds nothing in loop_witness.py, because the sketch reads the attribute straight off the call (ids 3, 17, 21)

- **Where:** 92 §6 AC8 first probe, against the §4 sketch "The tree_lib route, after this unit" (line 151).
- **What is wrong:** The probe checks only "every attribute read off a name that a `load_tree_lib()` call binds". The same gap covers a `tl` passed to a helper as a parameter, and `getattr(tl, "X")`.
- **Consequence:** The probe certifies loop_witness.py's tree_lib reads without inspecting any of them. A later `load_tree_lib().X` read whose X is missing from the tuple passes AC8, and the skew path then ends in an AttributeError traceback. Only the second probe catches the one current name, `GIT_ENV_LEAKS`. id 21 was re-graded high to medium for that reason.
- **Fix (judged SOUND by the skeptic):** Define the population as every `ast.Attribute` whose value is a `load_tree_lib()` Call, a Name bound from one, or a parameter that receives one. A simpler definition also works: every attribute name across `tools/loop/*.py` that is a module-level name of `tree_lib.py`, as 90 AC4 does for loop_lib.py. Each must be in TREE_LIB_SYMBOLS. Require the population to be non-empty, and state that over today's sketch it includes `GIT_ENV_LEAKS` from loop_witness.py. Stage a break in the build: a scratch loop_witness.py reads `loop_lib.load_tree_lib().derive_X` with derive_X missing from the tuple, and AC8 must go red.
- **Left-shift gate:** Add a bug-class checklist entry, `fixture-passes-by-finding-nothing`: every AST probe must state its population over the current sketch and assert that the population is non-empty.
