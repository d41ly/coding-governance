### H2 — Spec 74 skips every FETCH_HEAD written over an scp-form SSH remote (id 8)
- **Where:** spec-74 §2 S1; §4 The reading, restated; §5 risks.
- **What is wrong:** S1 keeps a FETCH_HEAD line only when its URL equals `git remote get-url <remote>` after stripping a trailing `/` and `.git`. When git writes the URL into FETCH_HEAD, it drops the user part. A skeptic probe with git 2.54 showed `git@example.com:up.git` written as `example.com:up`, and `ssh://user@example.com/up.git` written as `ssh://example.com/up`. The comparison never matches on these forms.
- **Consequence:** Take an SSH-remote adopter whose default branch has not moved. The fetch writes no tracking-ref reflog entry either. The engine then reads `stale-remote` after every successful fetch and ranks it above `act` indefinitely. AC2 uses a local-path remote, which has no user part, so it cannot catch this. §5 calls this the conservative side for unusual URLs, but SSH is the most common remote form. M16 is the same defect for https URLs that carry credentials, graded medium.
- **Fix (skeptic: sound):** Normalise both sides the way git does before comparing. Drop `user[:pw]@` from a `scheme://` authority and from an scp-form host, then strip trailing `/` and one `.git`. Alternatively, match the branch line and compare `refs/remotes/<remote>/<default>` against the FETCH_HEAD sha instead of comparing URLs. Add a fixture plant that fetches through `git@example.com:up.git` with a GIT_SSH_COMMAND shim, and assert that the line ends `from FETCH_HEAD`.
- **Left-shift gate:** a bug-class checklist entry: any comparison against a URL that git wrote runs a fixture over scp-form remotes and remotes that carry a user part.

### M1 — Spec 70's `read_driver_conf` lets an inherited environment value pass as the conf's value (ids 2, 16, 32)
- **Where:** spec-70 §2 S1; §4 The reader.
- **What is wrong:** The reader runs `bash -c '. "$1" ...; eval "v=\${$n-__UNSET__}"'` in a subshell that inherits the caller's environment and presets nothing. The driver behaves differently. It sets `ROOT`/`CONF` (unattended.sh:546-548) and assigns `MEMORY_ROOT=memory` and `PHASES_EXTRA=""` (:560-565) before it sources the conf (:617), so an inherited value never reaches it. check-unattended.sh:297 limits its import to the names the conf declares. 70 copies neither safeguard, yet S1 claims to compose the value "the way the driver does". The budget refills silently, which is the defect 72 exists to close. An exported `PHASES_EXTRA` admits phases the driver refuses. A conf that appends to a key or uses `$ROOT` also diverges. The path is narrow and depends on the environment.
- **Fix (skeptic: sound):** Before `. "$1"` in the subshell, assign each requested name its driver default, read from unattended.sh's initialiser lines rather than typed a second time, or unset each one. Set `ROOT`/`CONF` as the driver does. Alternatively, run bash with those names removed, or restrict the names to those the conf declares, as check-unattended.sh:297 does. Add a plant `env-leak` that exports `MEMORY_ROOT=elsewhere` and `PHASES_EXTRA=BOGUS` over a conf that sets neither, and assert `memory` and an empty population.
- **Left-shift gate:** a bug-class checklist entry: a second process that re-derives a driver's decision reproduces the driver's state before it sources the conf, and a fixture runs it under a polluted environment.
