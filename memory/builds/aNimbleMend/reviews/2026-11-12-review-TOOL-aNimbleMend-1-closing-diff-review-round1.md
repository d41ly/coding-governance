## HIGH

### H1 — The red-fix lane opens on any stale `fail` row of the gate ledger (findings 1, 7, 22; each high)

- **Where:** `tools/hooks/scratch-guard.js@e68c8d09:1180` (`readOpenReds`, lines 1173 to 1183; the same line at `@c428a23c`). The carry-forward is `run-gates.sh:5404`.
- **What is wrong:** `readOpenReds` returns the name of every ledger row whose status field is `fail` or `timeout`. It tests no head, no run id, no age and no manifest membership. The runner carries forward every row a run did not re-measure, so a red of a held or guard-skipped leg is never cleared. `checkRedLane` admits the main loop and any `writes = product` role whenever that list is non-empty and the key is on.
- **Consequence:** The write gate admits a spec-less product write that answers no current red, which the security model says the lane must never do. The primary checkout's ledger holds 9 `fail` rows from early September 2026, all in the old five-field format and all for legs a plain bar and a pass-leg run hold. `readOpenReds` over that git dir returned 9 names and `checkRedLane` returned the admitting witness. Six linked worktrees hold 1 to 4 `fail` rows. So with the key at its default the lane is open in those trees on landing and stays open. The commit grader does not close it: it accepts a trailer naming any manifest leg and reads no ledger. Only the 3-path and 60-line limits bound what lands, and the lane still never reaches a spec or a guarded file, which is why the grade is high and not blocker. `help/red-fix-lane.md` line 32 says the lane closes when the leg next runs green, which for a held leg is never in a pass.
- **Fix:** Count a row as open only when it belongs to this branch's present state.
  - The row carries the nine-field form. A shorter legacy row reads as not open.
  - The row's name is a leg of the conf's `LEG_MANIFEST`.
  - The row's head field (field 9) is HEAD, or an ancestor of HEAD not already reachable from the landed revision the key is read at. A row with no head, or a head outside that range, is not open.
  - Held legs stay eligible: a held leg redded at HEAD by a full bar still opens the lane.
  - Add scratch-guard suite arms: a `fail` row with no head, one whose head is a landed commit, one for a leg absent from the manifest, each leaving the refusal standing; and one for a held leg redded at HEAD that still opens the lane.
  - Update the closing sentence of `help/red-fix-lane.md` to match.
  - Probe the build must run: the hook against the primary checkout's own ledger must print the refusal, and `readOpenReds` over the primary git dir must return `[]`.
- **Fix verdicts:** The fixes of findings 1 and 7 were judged SOUND. The fix of finding 22 was REJECTED, and the head bound above is the skeptic's corrected fix. The rejected proposal dropped rows of held legs and kept only the most recent run's rows; it is not the fix.
- **Caveat on the sound fixes:** Finding 1's fix offers "the ledger's newest run" as an alternative to the head bound. The skeptic of finding 22 observed that a most-recent-run bound closes the lane on a bar red as soon as a later pass-leg run that does not measure that leg writes the ledger. Build the head bound.
- **Left-shift gate:** A scratch-guard suite arm class, "a carried-forward ledger row never opens the lane", holding the four arms above. Add the class to the bug-class checklist as `carried-forward-row-read-as-current`: any reader of a store whose writer carries old rows forward must bound a row by its own run or head field.
