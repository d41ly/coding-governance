## HIGH

### H1 — The hook's new word break splits `>>`, `2>>` and `<<`, and row D6 allows the suite (ids 1, 11)

**Where:** `tools/unattended/gate-guard.js@e3e8092e:396`

**What is wrong.** This range adds a break in `readTokenAt` that ends a word at a `>` or `<` glued to it. The test is `out !== '' && !/^\d+$/.test(out)`. It also holds when the word so far is `>`, `2>` or `<`, so the second character of a two-character operator becomes a word of its own. `>> x.log` is read as `>`, `>`, `x.log`. In `scanDenyHits` the first `>` is a bare operator and takes the second as its target (the skip at `:599`), and the real target stays in the candidate as an argument. `checkSuiteLeg` then sees a spelling longer than the leg and answers no hit. `scanSegments` on `a >> b 2>> c <<< d` gives `[a,>>,b,2>>,c,<<<,d]` at the base and `[a,>,>,b,2>,>,c,<,<,<,d]` at the head. The spec's stated mechanism, that an operator opening a word "is read as today", is not what was built.

**Consequence.** A regression of this range against the unit's own goal. Over the real `tools/gate-legs.json`, `python3 tools/memory-tree/gen_build_index.py --selftest` followed by ` >> x.log 2>&1`, ` 2>> err.log`, ` >> "$LOG"` or ` << EOF` is denied at the base and allowed at the head; `--selftest>> x.log` misses for the same cause. The same holds for every D6 flag-form leg (corpus-ids 2690 s, policy fixtures 2420 s). A build pass that appends a suite's output to a log, an ordinary spelling, runs the suite the hook exists to refuse. The README paragraph this range adds says a redirection hides neither form, which is now false. The lint still reads `>> x.log` and `2>> x.log` as hits (observed by id 11's skeptic; id 1's skeptic did not run `check_bar`), so the two readers disagree with the hook as the under-reader. No arm in either suite feeds a spaced `>>`, so both suites stay green. Single `>`, `&>`, `&>>`, glued `>>x.log`, `2>>err.log` and `<<< x` still hit, and rows D2 to D4 are unaffected. Both skeptics held the grade at high, not blocker: one spelling family, D6 flag-form legs only, inside a pre-VERIFYING unattended run, and the consequence is an over-bound suite running in a build pass, not a wrong result or data loss. <!-- PINNED 2026-11-14 -->

**Fix (judged SOUND by the skeptic, on both findings).** In `readTokenAt`, do not break while the word read so far is itself a redirection operator: change the guard to `out !== '' && !/^(?:\d*|&)[<>]*$/.test(out)`, so `>>`, `2>>`, `<<<` and `&>>` read on as one word and the break stays for a real word followed by `>` or `<`. Id 11's narrower `!/^\d*[<>]*$/.test(out)` was also applied to a scratch copy and judged sound; each skeptic re-ran the probes and saw every cited spelling hit again with the glued forms this unit added still hitting. Add `run_planted` deny arms over the 900 manifest, each observed red on the current tree first: `$M_FLAG >> x.log`, `$M_FLAG >> x.log 2>&1`, `$M_FLAG 2>> err.log`, `$M_FLAG >> "$LOG"`. Raise the floor by their count. Add `python t/over.py --selftest >> x.log` to the spec's spelling table for both probes.

**Left-shift gate.** The gate-guard suite carries one deny arm per operator of the redirection set (`>`, `>>`, `2>`, `2>>`, `&>`, `&>>`, `<`, `<<`, `<<<`) in both the spaced and the glued form, so a change to the word reader that splits any of them goes red. Class `two-answers-to-one-question`.
