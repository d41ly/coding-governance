## 1. Goal

The push-main descriptor declares its three hook self-tests `subject = "repo"`, so govkit emits them
that way and every adopter's bar runs them, under `GATE_FULL=1` too, because a guard does not decide
a hold. They test engine files an adopter ships verbatim and never edits. NicoCares paid 815 s to
more than 3500 s per bar for the pre-push self-test alone (owner's prompt, 2026-10-09). This unit
declares all three `kit` in the descriptor and in gov's manifest, so an adopter holds them unless
`GATE_SELFTESTS=1` after a normal `govkit update`, and gov's own bar is unchanged.

## 2. Scope (IN)

- **S1 — the descriptor.** In `tools/govkit/entries/push-main.kit.toml`, the `subject` key of the
  three `[[gate_leg]]` rows `push-main self-test`, `pre-push self-test` and `pre-push bar self-test`
  reads `"kit"`. No other key of those rows moves. One comment line above the first of them states
  why: each tests an engine file an adopter receives verbatim, the owner's rule of 2026-10-09 is that
  self-tests run on demand only, and the adopter's runner holds a `kit` leg. Observed by AC1, AC5.
- **S2 — gov's manifest, in step.** In `tools/gate-legs.json`, the same three rows read
  `"subject": "kit"`. Their `chunk`, `guard`, `argv` and `ceiling` are untouched. Observed by AC2,
  AC3.
- **S3 — the subject pin.** `tools/govkit/subject-pins.tsv` is regenerated by
  `python tools/govkit/govkit.py selfcheck --write`, so exactly the three rows move from `repo` to
  `kit` and their chunk field stays `selftests`. Observed by AC4.
- **S4 — gov's bar holds the same legs as before.** `tools/run-gates/run-gates.sh` holds a leg when
  `subject == kit` OR `chunk == selftests` (verified at ~2146, 2026-10-09), and all three already sit
  in the `selftests` chunk, so the set gov holds without `GATE_SELFTESTS` is identical before and
  after. Observed by AC3.
- **S5 — the prose sweep.** Every comment above the three rows, the descriptor's `[check] none`
  text, and every tracked non-record file naming the three legs or their argv files is read; any
  sentence saying these legs run on a default bar is corrected where this unit may write it, or
  recorded under §3 Edges where it may not. Observed by AC5.

- **The selfcheck arm that stops the class recurring.** This unit fixes the three instances only.
- **`tools/run-gates/run-gates.sh`.** Its hold comment at ~2133 says these legs carry

## 4. Design

### Data model

No field is added. The `subject` key already exists on every `[[gate_leg]]` row, and 7h of
`govkit selfcheck` already reds a descriptor and manifest that disagree on it. The three rows move
from one legal value of the closed set to the other.

### How the value reaches an adopter

`write_gate_legs` builds each adopter row from the descriptor and sets
`row["subject"] = leg.get("subject") or "repo"` when the target's installed runner is at or above
the subject floor (`tools/govkit/govkit.py` ~4022-4024, verified 2026-10-09). This unit does not
touch that code, so the emitted value is the descriptor's value; AC1 observes the descriptor through
the same reader the emitter uses. The adopter's runner then holds the leg by its own predicate, and
its pre-push hook demands held legs only when `GATE_SELFTESTS` is set in its environment
(`.githooks/pre-push` ~1244, verified 2026-10-09), so a default push does not force them back on.

### Alternatives rejected

- **Leave `repo` and rely on the guards.** A push to the default branch runs `GATE_FULL=1`, which
  ignores every guard, so the guard never decides; the owner's prompt names this.
- **Withhold the three suites from adopters, as the run-log suite is withheld.** Claiming the files
  `project-owned` stops them shipping at all, which also takes away the adopter's on-demand run the
  owner's rule keeps (`GATE_SELFTESTS=1`). It also withholds `.githooks/pre_push_bar_selftest.py`,
  which ships so NicoCares can retire its own copy.
- **Emit `chunk`.** Rejected under §3: a new field and floor for what the existing field already
  does for these three rows.
