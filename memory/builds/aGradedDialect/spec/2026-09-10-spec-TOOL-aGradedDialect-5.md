`TOOL-dScaffoldedMirror-13` against the revisit test that decision wrote for itself. A kit that reads
TypeScript sitting beside prose saying it cannot is one question with two answers, and the prose is
the copy that rots.

## 4. Design

### The correction the brief needs, verified against source on 2026-09-10

The spec brief says `tools/lexicon/LEXICON.md` carries a `.ts`/`.tsx` ruling to be replaced. It does
not. `grep -rn "typescript\|tsx" tools/lexicon/` returns no hit in that file at all, and the ruling
`TOOL-dScaffoldedMirror-13` §2 S4 promised to write there was never written, because that unit is
`DEFERRED` and was never built. So S1 is an addition to a file that has been silent on the question
since the kit shipped, not a replacement of a stale paragraph.

What DOES carry claims this build falsifies, each verified by reading the file on 2026-09-10:

| Carrier | The claim | Why it goes stale |
|---|---|---|
| `tools/lexicon/README.md` "Arming a language this kit does not ship" | a TypeScript adopter "could only declare their language `dark`" | TypeScript leaves that list |
| `tools/lexicon/README.md` "Coverage modes" | "TWO PARSERS SHIP" | a count of a derived population, typed in prose |
| `tools/lexicon/lexicon.py` `DEFINITION_SNIFF` header | "`TOOL-dScaffoldedMirror-13` still owns the `.ts`/`.tsx` question" | that decision is superseded here |
| `memory/map/features/lexicon.md` "Shared seams" | "an adopter with TypeScript, Go or C# could only declare their language `dark`" | the README claim, mirrored |
| `memory/backlog/TOOL.md` the `-13` row | "the adopter's primary language is INVISIBLE to the kit" | the condition the row tracks is removed |

The parser sentence is the interesting one and it is fixed by DERIVING rather than by recounting.
`TWO PARSERS SHIP` is a literal beside the `LANGS` rows that own the number, so a third parser
falsifies it and a fourth would falsify its replacement. It is rewritten to name the pattern-set ids
and let the row set say how many there are.

### Inventory

This unit MINTS no identifier. It claims keys minted elsewhere, in `memory/map/features/lexicon.md`,
and every one of those names is units 2 to 4's to choose — a claim invented here would be a claim
naming a dead key, which is the half of the map ratchet that reds in the other direction. No naming
cell grades anything this unit writes, because it writes no definition site.

### The version bump, and why it lands here

`KIT_LEXICON_VERSION` in `tools/lexicon/lexicon.py` is the source, and the same figure is repeated
in the `gov:kit lexicon@` marker of `lexicon.py`, `canon.py`, `LEXICON.md` and `README.md`, and in
the rendered `.claude/skills/lexicon/SKILL.md`. `tools/check-kit-versions.sh` compares the markers
against the source, so a bump in one carrier reds the bar. Bumping once, in the last unit that
touches the kit, is one edit set instead of three; §8 F2 records that allocation.

### Files touched (estimate)

`tools/lexicon/LEXICON.md` · `tools/lexicon/README.md` · `tools/lexicon/lexicon.py` (comment and
version only) · `tools/lexicon/canon.py` (marker only) · `.claude/skills/lexicon/SKILL.md`
(re-rendered, never hand-edited) · `memory/backlog/TOOL.md` ·
`memory/builds/dScaffoldedMirror/spec/2026-08-24-spec-dScaffoldedMirror-13.md` (header tail only) ·
`memory/map/features/lexicon.md`.

### Alternatives rejected

- **Write the `.ts`/`.tsx` paragraph into the kit README only, and leave `LEXICON.md` silent.**
  `LEXICON.md` is the file a human opens to decide what goes in a declaration, and after this build
  the answer for a TypeScript tree stops being "nothing". Silence there is what let the question be
  re-asked once already.
- **Fold this unit into `TOOL-aGradedDialect-3`.** The extractor's diff would then carry both a
  mechanism and every record edit in the kit, and a closing review could not tell which half a
  finding lands on. That is M2's one-mechanism-per-spec rule and it is the reason this unit exists
  separately.

  its backlog row?** The probe is `bash tools/memory-tree/check-memory-hygiene.sh` over a staged
  flip of that header to `WONTDO`, and the observation that decides it is check 12's resolved-§8
  rule: that spec's §8 F3 is marked UNRESOLVED and is explicitly the owner's, so a terminal status
  there reds. LIVENESS: the same probe run over the unstaged tree must pass, so a red is the arm
  firing rather than the tree being broken; if both runs agree, the probe decided nothing and this

  not. The two objects answer different questions — the row tracks "is the kit blind to the
