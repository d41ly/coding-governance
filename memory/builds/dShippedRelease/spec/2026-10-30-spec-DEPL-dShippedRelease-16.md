## 1. Goal

`gap-deploy-13`: `update` runs seven kinds of code the target authored, with the operator's whole
environment and the node's ambient credential, and `GOVKIT_RERENDER=0` declines four of them, so an
unattended update into an adopter would run that adopter's code with gov's push rights. This unit adds
`kits.offer`: a govkit mode that refuses every target-side spawn, run in a throwaway clone with an
emptied environment, whose checks are left to the adopter's lander and whose result is pushed to
`gov/update-<release>` through that adopter's own scoped grant, with an order naming everything it
left unrun.

### The offer

```
run_offer(root, key, release):
  row = adopter row; refuse an unknown key
  scratch = fresh temp dir; env = build_step_env(scratch) + the grant's helper
  git clone --template= --no-tags --single-branch --branch <branch> <remote> <scratch>/w
  check_target_local_config(<scratch>/w)
  spawn govkit.py update --target <scratch>/w --to <release> --write --offer --offer-report <report>
  disposition = derive_offer_disposition(report)
  write_offer_order(report, <scratch>/w)
  check_grant_scope(row, scratch), then write_offer_branch(row, <scratch>/w, release)
  return the disposition to the caller's record; clear scratch
```

A failed clone is `undeliverable`. `--offer-report` writes JSON: `unrun` (one list per kind),
`steps` (`applied`, `attended`), `exit` and `gov_commit`. It exists only with `--offer`.

### The disposition

| Case | Disposition | On `gov/update-<release>` |
|---|---|---|
| `update` exits 0, no attended stop | `update` | the update, and the order naming every `unrun` row |
| `update` exits 1, a walk stopped attended, or a conflict order written | `order` | the orders alone, on the default tip |
| clone refused, grant wider, `grant` not `branch-push`, no resolved secret, or the push refused | `undeliverable` | nothing |

## 5. Production-readiness checklist

- security — this is the unit's whole subject. No ambient credential: the environment is an allowlist,
  `HOME` and `credential.helper` redirected. The grant's secret reaches git only over the helper's
  stdout. The update process never holds it. The push names one ref under `gov/update-*`, and the remote
  rule is probed, not assumed. A hostile adopter's tree can influence file content on the branch and
  nothing that runs. Deny by default: an unknown kind of spawn has no `OFFER_MODE` row and reds.
- perf / scale — one clone and one `update` per offered row per release, on the cadence's own period.
- error / empty / loading states — every failure is one of three dispositions; an unregistered or `read`
  row never reaches here (DEPL-dShippedRelease-7 §4 "The route").
- observability — one line per step, the report JSON on the record, the order on the branch.
- risks — a rendered kit's branch reds at the adopter's bar until the order's regenerate is run, which
  is what the order says (§8 F2). `autocrlf` falls away under the emptied config, so a clone is LF;
  `update` compares blobs, and the order lands LF.
- testing — the arms of §7, each a scratch gov and a bare adopter remote with a `pre-receive` rule.
- migration — none.
- user docs — `help/offers.md`.
