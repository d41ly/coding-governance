## 1. Goal

No release has ever been cut, so nothing downstream can say "releases behind". This unit gives gov a sibling
of `cmd_mint`, `kits.cut`, that cuts an annotated `gov/v<date>.<n>` tag as `kits.cadence` says, its notes
generated from the landing records and version deltas since the previous tag, and red when the notes miss a
landing. It closes `gap-deploy-11`'s no-tag half, with DEPL-dShippedRelease-10 holding the version slot, and
`gap-deploy-06`'s changelog half.

- **S1** — The tag reader. `read_release_tags(root)` in the new `tools/govkit/kit_release.py` lists the tags
  matching `TAG_RE`, `gov/v(\d{4}-\d{2}-\d{2})\.(\d+)`, each an annotated tag on the default branch's
  first-parent line, ordered by (date, `<n>`), as rows of `tag`, `sha`, `date` and `n`. A lightweight tag or
  one off that line is skipped with one printed line, so an `archive/*` tag is never read. `read_releases`
  (`tools/govkit/shims.py`, TOOL-dSafePassage-6) returns this function's rows, so the shim window's stand-in
  answers the real list. Observed by AC1.
- **S2** — The span. `derive_cut_span(root, prev, head)` lists the landing records on the first-parent line
  `<prev>..<head>` through `python <loop kit>/deploy_items.py read-landing <sha>`, a subprocess, since a kit
  imports no sibling kit. With no previous tag, the first release's base is the first parent of the oldest
  commit holding a landing record (§8 F1), so a tree with no landing record has no span. A `dead probe` from
  the reader refuses the cut, and never reads as an empty span. Observed by AC2.
- **S3** — The notes. `derive_release_notes(prev, head, root)` returns the deterministic text of §4 "The
  notes": one line per landing, `<sha8> · <builds> · <units> · <outcome> · core <core>`, then one line per
  kit whose `resolve_version_value_at` (`tools/govkit/govkit.py:13325`) differs between `<prev>` and
  `<head>`. Two runs over one span give the same bytes. Observed by AC3.
- **S4** — The check. `check_release_notes(notes, prev, head, root)` returns each landing of the span the
  text does not name, by its `<sha8>`, and each kit delta it omits.
  `python govkit.py cut --check <file> --prev <rev> --head <rev>` prints each as one `MISSING` line and
  exits 1. A cut runs it over its own notes before the tag. Observed by AC4.
- **S5** — The cut. `python govkit.py cut [--tip <sha>]`, through `cmd_cut` beside `cmd_mint`
  (`tools/govkit/govkit.py:13497`) and a dispatch arm in `main` (`:14059`), reads the advertised
  default-branch tip, calls the span, and on none prints `cut — nothing landed since <tag>` and exits 0.
  Otherwise it makes the tag `gov/v<UTC date>.<n>`, `<n>` the next free number that date, as
  `git tag -a -F <notes file> <tag> <sha>`, the notes as the tag's message, and pushes `refs/tags/<tag>`. A
  push the remote rejects because the tag now exists is the tag number taken by another cut: refetch the
  tags, take the next `<n>`, regenerate since the tag now previous, and retry within `flow.route-backs`,
  read by a literal `read_policy_value("flow.route-backs", root)`. Any other refusal, or past that bound,
  raises `raise_owner_item("kits-cut", "kits-cut", ["retry", "decline"], "retry", key=<sha12>)`. Observed by
  AC5, AC6.
- **S6** — The cadence, `derive_cut_due(value, watch, now, root)`, reading `kits.cadence` by a literal
  `read_policy_value("kits.cadence", root)` and `kits.watch-cadence` likewise (§4 "The cadence"). `daily`
  and `weekly` are due when no release tag's date falls in the current ISO date or week, keyed by that
  period; `every-landing` is due once for each landing newer than the newest tag, each its own tag on that
  landed SHA, oldest first, keyed by the landed SHA; `owner-cut` raises
  `raise_owner_item("kits-cut", "kits-cut", ["cut", "decline"], "decline", key=<tip sha12>)` for the span's
  tip, and cuts once it reads `cut`, and a `decline` is witnessed by that item, keyed by the tip, so the
  next item opens only once a later landing moves it. Each value is seen on its own planted case. Observed
  by AC7, AC8, AC9, AC10.

## 4. Design

### Evidence

- `git tag` lists only `archive/aGatheredDeclaration`, `archive/aMendedWarden` and `archive/aPairedLexer`,
  measured at `5d1c82ac` (PINNED), so no `gov/*` tag exists.
- `cmd_mint` (`tools/govkit/govkit.py:13497`) is the sibling: it resolves a base and a head, reads
  `read_descriptors`, and states what it does not do. `main` parses a verb's own flags before `parse_args`
  (`:14084-14096`), the shape `cut` takes.
- `.githooks/pre-push:609-610` sets `main_local` only for the default branch, so a tag-only push takes the
  hook's non-default path, which `tools/push-main.sh` never drives. A branch bar a repository declares would
  run on it: UNVERIFIED for a declared one, and AC5's bare remote carries no hook.
- TOOL-dWellOiledMachine-13 §3 and -59 §3 leave `session-start` unregistered, and `hosts.py ready` asks only
  the OS tick probe, so at the default `kits.host` the tick would print `not ready` for ever. S7 is that
  registration.
- The `period` of a row is static and takes `daily` or `weekly` (TOOL-dWellOiledMachine-59 S1), and
  `kits.cadence` is policy, so S6 reads the value inside the program, under the daily row, as
  DEPL-dShippedRelease-7 does for its own key.

### The notes

```
gov/v2026-10-30.1

since gov/v2026-10-23.2 at 1a2b3c4d, through 5e6f7a8b

landings (2)
- 9f8e7d6c · dExample · TOOL-dExample-1 TOOL-dExample-2 · landed-gated · core green
- 0a1b2c3d · dOther · TOOL-dOther-4 · landed-ungated · core green

kit versions (1)
- memory-tree 2.153 -> 2.154
```

A first release's second line reads `first release, baseline <sha8>, through <sha8>`. A kit whose value is
`(…)` at either end prints that value rather than a fabricated number.

### The cadence

| `kits.cadence` | Due when | Witness | Key |
|---|---|---|---|
| `daily` | a landing since the last tag, and no tag dated today | the tag | the date |
| `weekly` | a landing since the last tag, and no tag in this ISO week | the tag | the week |
| `every-landing` | a landing record newer than the newest tag | the tag on that SHA | the landed SHA |
| `owner-cut` | a landing since the last tag, at the `kits.watch-cadence` period | the tag, or the declined item | the span's tip SHA |

The witness is the tag itself, read back from the remote, so two nodes need no extra lease: the second finds
the period witnessed, or loses the tag push and refetches. A span with no landing is `skip`, announced,
under every value.

### Alternatives rejected

- **A tracked changelog file.** A notes file written by a commit makes every cut a landing, and the design's
  kind is "the annotated tag and its notes blob" (layer-memory:434).
- **Notes hand-edited after generation.** Tested against S4: an edit that drops a line reds, so the check
  holds only if the generator is the one writer, which `cl-dClosedLoop-0414` says it is.
- **A release cut per landing from the lander.** It would run in `tools/push-main.sh`, which ships to every
  adopter, for a verb only gov holds, and the lander's mint already says so in one line for that reason.
- **`--period` as the key, through `cadence.py run`.** It would give each key its own lease ref, for no gain
  over a tag that is its own witness, and it grows the lease namespace by one ref per landing.

## 5. Production-readiness checklist

- security: the tag push runs on the node's own grant, as the lander's push does. The notes hold SHAs, slugs
  and ids from landing records, each of which `read_landing` checks against the default branch before use.
- perf / scale: one read per first-parent commit of the span with a landing ref; a cut per day at most,
  outside `every-landing`.
- error / empty / loading states: no landing is `skip`, a dead probe refuses, an unread policy key refuses
  the cut and never reads a default.
- observability: `cut —` lines, the hook's log, and the tag itself.
- risks: a wrong tag is public and an adopter counts it. A tag is never moved: a bad one is followed by a
  later one. `every-landing` at `weekly`-sized landing counts is cheap, and a burst after a dark period cuts
  one tag per landing, oldest first.
- testing: a bare remote and a clone, planted landing refs and each key value on its planted case.
- migration: N/A — nothing existing changes shape.
- user docs: S12.

## 6. Acceptance criteria

- **AC1** — When `python kit_release.py --fixture --case tags` plants `archive/old`, one lightweight tag and
  two annotated tags of `TAG_RE`'s grammar, `read_release_tags` returns the two annotated rows in date
  order, and `shims.read_releases` returns the same.
  Red when: an `archive/*` or lightweight tag is counted, or the stand-in still answers empty.
- **AC2** — When `--case span-first` plants landing refs with no tag, the span starts at the oldest record's
  first parent; `--case span-none` with no record prints `cut — nothing landed`; `--case span-dead` makes
  the reader exit 2 and the cut refuses.
  Red when: a dead probe reads as an empty span.
- **AC3** — When `--case notes` plants two landings and one version move, the text holds one line for each,
  and two runs give identical bytes, compared by `cmp`.
  Red when: a line depends on the wall clock or the fetch order.
- **AC4** — When `python govkit.py cut --check <planted notes> --prev <rev> --head <rev>` reads notes that
  drop one of the span's landings, it exits 1 printing `MISSING <sha8>`; with the line restored it exits 0;
  with a kit delta dropped it exits 1 naming the kit.
  Red when: planted notes that miss a landing pass.
- **AC5** — When `--case cut` runs `python govkit.py cut` against a bare remote, `git ls-remote --tags`
  shows the annotated tag, and `git cat-file tag` prints the notes `check_release_notes` passes.
  Red when: the tag is lightweight, or the notes differ from the generator's.
- **AC6** — When `--case tag-taken` plants the same tag on the remote during the cut, it refetches, tags
  `<n>+1` with notes since the tag now previous; with `--case tag-refused` the remote refuses for another
  reason and an owner item `kits-cut` is raised.
  Red when: a taken number fails the cut, or a refused push reads as done.
- **AC7** — When `--case cadence-daily` runs the tick twice on one planted day under a planted
  `.governance/policy.toml` reading `kits.cadence = "daily"`, it cuts once; a planted later day with a new
  landing cuts again; a day with no landing prints `nothing landed`.
  Red when: a period cuts twice, or an empty period tags.
- **AC8** — When `--case cadence-weekly` runs under `kits.cadence = "weekly"` on two planted days of one ISO
  week it cuts once, and under `kits.cadence = "every-landing"`, `--case cadence-every-landing` with three
  new landing records makes three tags, oldest first, each on its landed SHA, a re-run making none.
  Red when: `every-landing` collapses landings, or re-cuts one.
- **AC9** — When `--case cadence-owner` runs under `kits.cadence = "owner-cut"`, one `kits-cut` item opens
