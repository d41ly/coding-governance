## 1. Goal

Landing and release have no role (`gap-deploy-06`'s role half). dBoundRoles registers `gov-deployer`
on `layer.distribution` and `layer.integrations` and leaves its definition here (v2:1970). This unit
writes that definition, the two jobs the clause gives it, verifying generated release notes for
distribution and judging a verify for integrations, and makes the item arm admit the role on its own
expansion's items, which TOOL-dBoundRoles-1 S7 refuses as specced.

### The role file

```markdown
---
name: gov-deployer
description: Judges a release's generated notes and a verify's output for an expansion's item.
tools: Read, Grep, Glob, Bash
model: inherit
workflow: deploy
reads: input:notes?, input:landing?, input:verify?
writes: none
rules: verify, gate, class, security
mandatory: no — when `item.kits.cut` hands it notes, or `release.verify` a verify needing judgment
output: its judgment, to its harness
layer: layer.distribution
acts-as: item
never: writes a file outside the scratch path — scratch-guard.js role arm; runs a gate leg — scratch-guard.js role arm; promotes or rolls back an environment — unenforced — the adapter's lease and compare-and-swap are the guard, and the role holds neither
return: outcome:accurate|inaccurate|real-failure|probe-failure|undecided, subject:text, evidence:text, misses:list?
---
```

The body, under its ceiling, says: you are handed either a release's generated notes with the
landing records and version deltas since the previous tag, or one verify's output for a SHA and an
environment; for notes, you read each landing and each delta and judge whether the notes state it,
naming every miss; for a verify, you judge whether the failure is the release's or the probe's, and
answer `undecided` when the evidence does not decide it.

### Alternatives rejected

- **The role driven only by a workflow, never an item's actor.** Refuted by reading the design:
  layer-roles:480 calls the deployer an "item role" and I5 gives `acts-as` `item`; a role with no item
  is a `cycle` role, which S7 refuses on an item and which has no job here.

  for two expansions.

- **Keying the admission on `owner`.** `owner = "dShippedRelease"` also sits on core `deploy.*` rows,
  where the role must stay refused (flow-steps:483).

## 5. Production-readiness checklist

- security — `writes: none`, no gate, no secret; the role reads what it is handed and returns a
  judgment. A promote or rollback stays with the adapter's lease and compare-and-swap.
- perf / scale — none: one agent type, spawned per notes or verify.
- error / empty / loading states — `undecided` is a return value, so an unclear verify is said rather
  than guessed; a `layers.toml` absent leaves the roster whole.
- observability — the return's `outcome` and `evidence`.
- risks — one role serves two layers, so its one `layer` value reads as distribution in the index;
  `programs` is what scopes it to both.
- testing — the plants of §6.
- migration — none beyond the render.
- user docs — `help/roles.md`.
