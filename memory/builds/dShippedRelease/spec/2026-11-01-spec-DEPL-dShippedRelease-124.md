## 1. Goal

Close finding id 67 of `reviews/2026-11-01-review-DEPL-dShippedRelease-79-spec-audit-round1.md`, HIGH, item H10. Unit 86 S1
returns a SHA or `None`, and `None` also means "E is new" to unit 91 S1. `refs/gov/release/*` are remote
refs, and `read_release` has no absent-versus-dead rule, though unit 1 S4 and unit 13 S3 draw that line
for their readers. With a dead fetch, or on a node that never fetched those refs, a tick reads no stop and
takes the newest green SHA, re-promoting one that failed verify or one the owner refused. This unit gives
the read its third answer.

## 2. Scope (IN)

- **S1** — The read. `read_release_refs(E, root)` in `tools/integrations/release.py` runs one bounded
  `git ls-remote --exit-code origin 'refs/gov/release/*/<E>'`. Exit 0 answers the SHAs, exit 2 answers none,
  and anything else raises `ReleaseReadDead`, so a node that never fetched reads the same as any other.
  Observed by AC1, AC2.
- **S2** — The stop. `derive_pick_stop(E, root)` returns the newest first-parent SHA among S1's, `None` on
  an answered none, and lets `ReleaseReadDead` rise. Observed by AC1, AC2.
- **S3** — The tick. `run_release_pick` on `ReleaseReadDead` prints `release — <E> · nothing · dead probe`,
  promotes nothing and releases E's lease with no `--as`. Observed by AC1.
- **S4** — One record. `read_release(sha, E, root)`, reached as `python release.py read <sha> <E>`, keeps
  its name and fetches `refs/gov/release/<sha>/<E>` bounded after S1 named it, with `absent`, exit 1, and
  `dead`, exit 2, distinct, a dead fetch raising `ReleaseReadDead`. Observed by AC3.
- **S5** — The floor. `derive_pick_floor` reads through S1 and S4, so `release.route` under
  `rollback-and-ask` on a dead read ends `halted` and raises `release-halted`, as a missing verified SHA
  does. Observed by AC4.

## 4. Design

### Evidence

- Unit 15 §4 places records at `refs/gov/release/<sha>/<environment segment>`, and `read_release` is a name in its inventory and S12, with no read rule.
- Unit 1 S4: a failed fetch is "no answer and never `absent`". Unit 13 S3: a failed fetch with no file is a dead probe, never `none`.
- `git ls-remote --exit-code` exits 2 when no ref matches, which a fetch of a missing ref does not separate from a network failure.
- Unit 15 S4 refuses an environment name `git check-ref-format` rejects, so no glob character reaches S1's pattern.
- `tools/policy/catalogue.toml:1030` keeps `roll-forward` the default, so a re-promotion is on the default policy (report id 67).

### How a read ends

| `git ls-remote` | S1 | `derive_pick_stop` | Tick |

| exit 0, rows | SHAs | the newest on the first-parent line | unit 86 S2's walk |
| exit 2 | none | `None` | unit 91 S1, a new environment |
| any other, or the bound hit | raises | raises | `nothing · dead probe`, lease released |
