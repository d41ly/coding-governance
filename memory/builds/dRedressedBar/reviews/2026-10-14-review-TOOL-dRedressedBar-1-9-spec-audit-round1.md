### M1. Unit 1 AC1 counts lines with `grep -c` but expects 14 calls (ids 1, 11, 20)

- **Where:** `2026-10-14-spec-TOOL-dRedressedBar-1.md` §5 AC1 (lines 145-146), against §2 S1.
- **What is wrong:** AC1 says the spaced `build_gh33_writer [A-Z]-tB-[0-9] '` pattern, counted with `grep -c`, reads 14. `grep -c` counts matching lines. The 14 calls in `tools/workflows/unattended-build.test.sh` sit on 5 lines: 2471, 2483, 2496, 2503 and 2512. At base the `-o` count is 13 glued calls and 1 spaced call.
- **Consequence:** After a correct S1 build the count reads 5, so AC1's positive half can never pass. The builder either records a false red or reshapes the suite to one call per line to reach 14. Unit 5's forms table and fork counts do not expect that reshaping. The glued half reading 0 still works as a red signal.
- **Fix (judged SOUND):** Count occurrences instead of lines. `grep -o "build_gh33_writer [A-Z]-tB-[0-9]'" tools/workflows/unattended-build.test.sh | wc -l` reads 0, and the same command with a space before the quote reads 14. The alternative is to keep `grep -c` and state 0 lines and 5 lines.
- **Left-shift gate:** Add a spec-lint check that flags an AC pairing `grep -c` with an expected count larger than the number of lines in the target region. Failing that, add a checklist entry: "a `grep -c` count is a line count; for calls, use `grep -o | wc -l`."
