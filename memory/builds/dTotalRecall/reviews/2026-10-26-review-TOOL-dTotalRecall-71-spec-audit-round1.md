## Blocker

### B1. The S19 sweep greps a failure line the checker never prints (ids 1, 16, 23, 34)

- **Where:** spec 76 §4 "The sweep of S19" (line 207), §2 S19 and S20, §6 AC13.
- **What is wrong:** the sweep pipes `manifest-check.sh` through `grep -E 'fail (5|9)'`. The checker's `fail()` (manifest-check.sh:1279) prints `MANIFEST check N FAILED — ...`, so the literal `fail 5` or `fail 9` never reaches output. The pipe also discards the checker's exit status. A failed `git worktree add` short-circuits the `&&` and prints no line.
- **Consequence:** the sweep prints nothing at every pass commit, red or green. AC13's red-span ledger and its "tip prints nothing" clause are green whatever the leg did. The ledger would record that the kickoff-manifest ratchet leg was never red, although unit 75 §4 argues it is red on C9 before step 33. S20's pass(69) line, which answers unit 69's AC1, can never appear, so minors M15 and L5 close on an empty observation. The check certifies what it does not read.
- **Fix (skeptic: SOUND):** match the checker's own line, `grep -E '^MANIFEST check (5|9) FAILED'`, and record each commit's exit status beside it without a pipe that swallows it, for example `echo "$N rc=$?"`. Treat an empty `$P` or a failed `worktree add` as a printed red line, never a skip. Add a liveness read to AC13: run the same pipeline once at a commit known red on C9 (for example pass(68), before unit 69's re-stamp, or a scratch manifest with last-body-change ten watched commits back) and require one matching line. An empty sweep then counts as a broken probe, not as green. The build runs this staged probe.
- **Left-shift gate:** a spec-token lint that resolves any literal grepped from a named tool's output against that tool's emitted format strings, and reds a pattern no format string can produce.
