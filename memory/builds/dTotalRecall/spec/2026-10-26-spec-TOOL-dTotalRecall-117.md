## 4. Design

Read at `acbb74bb` on 2026-11-25. The report holds. Two points beyond it: the build is a supplied input too, its

### The reader

The rendered text and every candidate go through one closure, so both sides of the compare are one read:

```python
head_re = re.compile(re.escape(template[0]).replace(re.escape("<unit id>"), r"(?P<unit>\S+)")
                     .replace(re.escape("<n>"), r"\d+").replace(re.escape("<title>"), r"(?P<title>.*)"))
def read_key_fields(path, text):
    """The `(key, value)` pairs of what the caller of one record supplied, read back from its bytes; None where
    its header refuses to read."""
    lines = text.replace("\r\n", "\n").split("\n")
    m = head_re.fullmatch(lines[0])
    try:
        cause = [t for e in read_header_edges(text, path) if e["type"] == "caused-by" for t in e["targets"]]
    except ValueError:
        return None
    at = re.search(r"/builds/([^/]+)/", path)
    serves = next((ln for ln in lines if ln.startswith("**Serves:** ")), "")
    edges = [ln for ln in lines if ln.startswith("**Edges:** ")]
    return [("build", at.group(1) if at else ""), ("head", "" if m is None else repr(m.groupdict())), ("serves", serves),
            ("cause", " ".join(cause)), *(("edge", ln) for ln in edges), *read_ordered_fields(text)]
```

`template[0]` is `# <unit id> <kind> <n> — <title>` for a factory kind and `# <title>` otherwise (DERIVED,
`record_kinds.py#render_template`). The key is `derive_content_key(kind, read_key_fields(rel, text), given_id)`, over
the rendered text with the provisional `rel`, whose build segment is the call's. The listing compares a candidate's key
only where its reader answered.

The edge lines are compared as lines and not parsed: the door renders one canonical line per edge, so equal bytes are
equal edges, and no second parser of them appears. A hand-edited spelling reads as another record, which is the
refusing side. The cause goes through the one header reader, which reads a typed record's bullet too.

No stored key moves, since none is stored. A `<seq>` call that minted under the old key and never wrote would mint
another id on its replay; the unused id is the documented outcome of a refusal after a mint.
