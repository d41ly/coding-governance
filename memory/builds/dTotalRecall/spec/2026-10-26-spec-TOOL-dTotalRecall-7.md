## 1. Goal

An ask can be filed today with nothing saying what done means, and the only thing that notices is
`backlog.py`'s V14, after the row is written (gap-mem-01's open-world records; layer-memory F4-6).
This unit makes acceptance a property of filing: the record door's `new ask` verb grades the ask's
own clauses with the one predicate V14 already applies, and refuses or files as `asks.acceptance`
says (`refuse` by default, or `grade`, today's behaviour), and the ask kind lands its row in the
record-kind registry.

## 4. Design

### The predicate

```python
def check_ask_acceptable(clauses) -> bool:
    """Does a merged-clauses mapping state what done means? `accept`, or a `seen … run`."""
    return bool(clauses.get("accept")) or any(parse_seen(v).command
                                               for v in clauses.get("seen", ()))
```

V14 replaces its two `if … continue` lines with `if check_ask_acceptable(clauses): continue`; R5's
condition becomes `if not check_ask_acceptable(clauses)`. The door builds its mapping from the row it
is about to write, `{label: tuple(values)}` over the `--clause` pairs with `read_clause_values`, which is
the shape `derive_clauses` returns for an ask no `SCOPE` row names yet.

### The door verb

`new ask` is the ask kind's handler inside `gov_record.py`, the door TOOL-dTotalRecall-2 specs. Its
order: parse the arguments (refuse an unknown label), read `asks.acceptance`, mint the id, render the
row, grade it with S1, then write under `## Asks` of `memory/builds/<slug>/BACKLOG.md` or refuse. The
id is minted before the grade only because the rendered row carries it; a refused filing commits no
mint, as the door's idempotence rule (I2) treats any refused write. After the write the door parses the
file back with `backlog.parse_file` and confirms one ask with that id, the read-back
`write_ask_rows` already performs in shell (`unattended.sh:9980`).

| `asks.acceptance` | S1 true | S1 false |
|---|---|---|
| `refuse` (default) | row written, exit 0 | exit 2, nothing written, the two forms named |
| `grade` | row written, exit 0 | row written, `graded: not ready (R5)`, exit 0 |
| read refused | exit 2 naming the key, nothing written | the same |

### The policy read

The memory-tree kit imports no sibling kit (TOOL-dGroundRules-1, §4 Evidence), so it cannot import the
playbook kit's `policy_value.py`. It reads through its own thin adapter of the same contract,
`tools/memory-tree/policy_value.py` with `read_policy_value(key, root, rev=None)` and `PolicyRefused`,
built to PLAY-dOrderedCharter-7 §4 "The policy reads": an inline `resolve_kit_dir` block, then
`policy.py get <key> --explain` run in `root`. TOOL-dTotalRecall-8 (order 3), the first pass of this
build that reads a key from the memory-tree kit, creates it (its S10); this unit calls it and never
creates it (§8 F2).

### The ask row

One `[[record-kind]]` row in TOOL-dTotalRecall-1's cell shapes (its §4 "Data model"):

```toml
[[record-kind]]
name = "ask"
tag = "record.ask"
layer = "memory"
home = "memory/builds/<slug>/BACKLOG.md"
id-rule = "<FAMILY>-<slug>-<seq>"
schema = { form = "rows" }
writer = "gov_record.py new ask"
readers = ["backlog.py", "gen_build_index.py", "unattended.sh"]
lifecycle = "derived by the fold: OPEN to CLOSED or WONTDO, never typed on the row"
check = "memory hygiene"
```

`form = "rows"` names a row register its owner grades: the row grammar is `backlog.py`'s `ask`
production, parsed by `extract_row`, and V14 grades it through `check_ask_acceptable`, reported by
`gen_build_index.py --check` as hygiene check 9 inside the `memory hygiene` leg the `check` cell names.
The id is minted by the door under the build's claim, or an ask family's counter ref for a filer
outside a build (I4).

## 5. Production-readiness checklist

- security — a new write path into `BACKLOG.md`, reached only through the door, which validates once at
  the write boundary; deny by default: a refused policy read files nothing.
- perf / scale — one policy read and one file parse per filing.
- error / empty / loading states — the refusal names the key, the ask text and both forms; an unknown
  `--clause` label is refused by name.
- observability — the door prints the filed id, or the refusal, or the `graded` line.
- risks — under `refuse`, a filer used to filing first and curing later is refused; `grade` restores
  today's behaviour for that repository.
- testing — AC1 to AC9 by a pass; the arms of §7 at the close.
- migration — none, as §4 says.
- user docs — no page under `help/` covers asks or the door; the catalogue row's `summary` and
  `usage` document the key, and `tools/memory-tree/README.md` names the verb (S6).
