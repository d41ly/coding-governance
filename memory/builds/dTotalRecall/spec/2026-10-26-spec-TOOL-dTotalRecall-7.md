## 1. Goal

An ask can be filed today with nothing saying what done means, and the only thing that notices is
`backlog.py`'s V14, after the row is written (gap-mem-01's open-world records; layer-memory F4-6).
This unit makes acceptance a property of filing: the record door's `new ask` verb grades the ask's
own clauses with the one predicate V14 already applies, and refuses or files as `asks.acceptance`
says (`refuse` by default, or `grade`, today's behaviour), and the ask kind lands its row in the
record-kind registry.

## 4. Design

### The predicate

```python
def check_ask_acceptable(clauses) -> bool:
    """Does a merged-clauses mapping state what done means? `accept`, or a `seen … run`."""
    return bool(clauses.get("accept")) or any(parse_seen(v).command
                                               for v in clauses.get("seen", ()))
```

V14 replaces its two `if … continue` lines with `if check_ask_acceptable(clauses): continue`; R5's
condition becomes `if not check_ask_acceptable(clauses)`. The door builds its mapping from the row it
is about to write, `{label: tuple(values)}` over the `--clause` pairs with `read_clause_values`, which is
the shape `derive_clauses` returns for an ask no `SCOPE` row names yet.

### The door verb

`new ask` is the ask kind's handler, `write_new_ask`, keyed `ask` in TOOL-dTotalRecall-2's
`KIND_HANDLERS` inside `gov_record.py`. Its order: parse the arguments (refuse an unknown label or
level), read `asks.acceptance`, mint the id, render the ask row and its `SEV` row, grade the ask row
with S1, then write or refuse. The ask row goes under `## Asks` and the `SEV` row under
`## Dispositions` of `memory/builds/<slug>/BACKLOG.md`, the file made with its H1 and both headings
where absent, as `tools/unattended/unattended.sh#write_backlog_rows` makes it; the file is staged
with `git add` (TOOL-dTotalRecall-2 S8). The id is minted before the grade only because the rendered
row carries it; a refused filing commits no mint, as the door's idempotence rule (I2) treats any
refused write. After the write the door parses the file back with `backlog.parse_file`, under the
grammar `backlog.build_grammar` compiles from the conf's `FAMILIES` as
`record_kinds.py#read_open_asks` compiles it, and confirms one ask with that id and one `SEV` row
naming it; a failed read-back puts the file back as it was and exits 2, as
`unattended.sh#write_ask_rows` does through `#read_ask_back`.

| `asks.acceptance` | S1 true | S1 false |
|---|---|---|
| `refuse` (default) | rows written, exit 0 | exit 2, nothing written, the two forms named |
| `grade` | rows written, exit 0 | rows written, `graded: not ready (R5)`, exit 0 |
| read refused | exit 2 naming the key, nothing written | the same |

### The policy read

The memory-tree kit imports no sibling kit (TOOL-dGroundRules-1, §4 Evidence), so it cannot import
the playbook kit's `policy_value.py`. It reads through its own one policy read,
`tools/memory-tree/tree_lib.py#read_policy_value(key, root)`, which finds the policy kit beside it
through the kit's inline `resolve_kit_dir` and runs `policy.py get <key>` in `root`; every memory-tree
caller passes the key as a literal first argument (`build_records.py`, `ratchet.py`,

`tools/memory-tree/policy_value.py` (its §8 F4), so this unit calls the landed reader (§8 F2).

### The ask row

One `[[record-kind]]` row in the column grammar the registry's header comment states and
`record_kinds.py#check_row` grades (TOOL-dTotalRecall-1, -16, -18):

```toml
[[record-kind]]
name = "ask"
tag = "record.ask"
layer = "layer.memory"
home = "memory/builds/*/BACKLOG.md"
id-rule = "<FAMILY>-<slug>-<seq>"
schema = { form = "rows", fields = [] }
writer = "gov_record.py new ask"
readers = []
readers-none = "an ask row is read by backlog.py's fold and the index generator's views, never filled into a work order"
lifecycle = "current-state"

purpose = { text = "the ask kind's acceptance at filing; its writers are the items that file asks, each filing stating its acceptance", source = "memory/builds/dClosedLoop/build/2026-10-15-build-PLAY-dClosedLoop-1-layer-memory.md:455" }
```

`layer` is a `layer.<name>` tag (`record_kinds.py#LAYER_RE`); `home` is a tracked-path glob, which
`record_kinds.py#check_home` requires, no `<slug>` placeholder; `readers` is empty because
`tools/roles/roles_lib.py#READ_KEYS` holds no ask key, so `readers-none` gives the reason;
`lifecycle` is `current-state`, the value the `backlog-row` row of the same store carries and
TOOL-dTotalRecall-43 S3 names for `ask`, since an ask's status is folded from rows appended after it;
`purpose` cites the layer's kind table row for `ask`. `form = "rows"` names a row register its owner
grades: the row grammar is `backlog.py`'s `ask` production, parsed by `extract_row`, and V14 grades it
through `check_ask_acceptable`, reported by `gen_build_index.py --check` as hygiene check 9 inside the
`memory hygiene` leg the `check` cell names; `check_record_kinds` counts the row as `ask rows`, grading
no record of it by field. The id is minted by the door under the build's claim, or an ask family's
counter ref for a filer outside a build (I4).

### Alternatives rejected

- **A second refusal at filing with its own vocabulary.** layer-memory `[asks]` rules it out: V14
  already refuses, so the door extends V14's predicate (memory review b, finding at `:58`).
- **Grading against `derive_clauses` over the whole corpus at filing.** A new ask has no `SCOPE` row
  yet, so the merge is its own clauses; reading the corpus buys nothing and costs a full parse.
- **Widening `record_kinds.py new` to the `rows` form for this one row.** The factory writes the forms
  its populations grade by field or validator; a `rows` row has neither, and one hand row joins the
  `backlog-row` row of the same form.
