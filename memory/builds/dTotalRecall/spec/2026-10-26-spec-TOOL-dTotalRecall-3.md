## 1. Goal

Two clones that have not fetched each other can no longer mint one slug, and a filer outside a build
mints an ask id under its family's counter ref, advanced by a `--force-with-lease` push, so every
such mint is serialised (gap-mem-13, DA-M12, DA-M13, FL1; `layer-memory.md:318-334`). Every claim
commit carries its claimant key, so a replayed claim is idempotent; a slug claim ref is never pruned;
and an unreachable remote is handled as `leases.offline` says. Today `--entry-claim`
(TOOL-dPlacedRequest-21, `tools/unattended/unattended.sh#run_entry_claim`) creates
`refs/gov/claims/<slug>` for a placed request alone. `--new-build` claims nothing on the remote: its
`check_slug_claimed` (`tools/memory-tree/gen_build_index.py#check_slug_claimed`) reads the local
clone only, and no counter ref exists for an ask family.

## 4. Design

### The verbs

```
bash gov-claim.sh slug <slug> --claimant <key> [--offline <value>]
bash gov-claim.sh ask <FAMILY> <slug> --claimant <key> [--offline <value>]
```

`check_claim_args` validates every argument before any git call. `<key>` is twelve lowercase hex
digits, the shape of `tools/roles/handoff.py#derive_section_sha`. `<FAMILY>` is a family of the
`FAMILIES` pairs in `.memory-tree.conf`, which the script sources as `check-memory-hygiene.sh` does.
`<slug>` matches the admit grammar `id_grammar.py --print slug-re <root>` prints, run once through the
resolved python; the mint grammar is the caller's (§4 "The scaffold's claim"). `--offline` absent is
`refuse`. Ref names are built from validated parts only.

The remote is resolved by `resolve_remote_sh` (`tools/lib/resolve-remote.sh`): a refusal exits 2,
and no remote at all prints `local <ref> · no remote` and exits 0 writing nothing (§8 F9). Every git
call to the remote runs under `run_claim_remote`, this script's bounded runner in the shape of
`tools/run-gates/post-merge.sh#run_remote`, set as `GOVREF_RUNNER`; `GOVREF_REMOTE` is the remote's
name and `GOVREF_GITDIR` the clone's git dir. Each fetch lands in this node's cache namespace
`refs/gov/remote/claims/`, as `tools/unattended/unattended.sh#read_claim_ref` fetches, and is
followed by `add_feed_sightings refs/gov/remote/`.

| Exit | stdout | Meaning |
|---|---|---|
| 0 | `claimed refs/gov/claims/<slug> <sha>` | the slug is this claimant's, new or replayed |
| 0 | `minted <FAMILY>-<slug>-<n>` | the id, new or replayed |
| 0 | `local <ref> · no remote` | the clone declares no remote, so no other clone shares a namespace |
| 1 | `taken <ref> by <claimant-key>` | another claimant holds the slug |
| 2 | `refused <why>` | `offline` under `refuse`, a malformed argument, a refused remote, or a push not completed |
| 4 | `waiting offline <ref>` | offline under `warn` or `follow-leases`, nothing written or queued |

Each commit is `build_gov_commit <tip read or empty> <message>`. The message is the I23 shape of
`tools/loop/claim.py#render_claim_body`: a header `gov-claim claims/<tail>`, a blank line, then
`claimant-key: <key>` and `session: <CLAUDE_CODE_SESSION_ID, or absent>`, and for a counter
`family: <FAMILY>` and `seq: <n>`. `<tail>` is `<slug>` or `asks/<FAMILY>-<slug>`.

### The counter

1. Fetch the counter ref and the remote's default branch tip, one bounded fetch.
2. `read_claim_replay`: if the ref's first-parent history, read with `git log --first-parent -n 64`,
   holds `claimant-key: <key>`, print that commit's `seq` and stop, a replay.
3. `derive_ask_floor`: `floor` is the highest `<n>` of `<FAMILY>-<slug>-<n>` named in any tracked
   file of the default branch tip (`git grep -ohE` at that commit) or of `HEAD`. The next id is
   `max(tip seq, floor) + 1`, an absent ref reading `tip seq` 0.
4. Push leased on the tip read, empty when absent. A lost push (rc 1) repeats from 1, up to three
   times, then exits 2 naming the lost race; a push not completed (rc 2) exits 2 with `GOVREF_WHY`.

So two mints racing on one ref get two numbers, and a counter created late never re-mints an id the
default branch already holds. `asks` is no slug the grammar mints, since every word of `mint_re` is
capitalised, so the counter subtree never collides with a slug claim.

### The slug claim

One bounded fetch of `refs/gov/claims/<slug>`. Present: `read_claim_replay` reads its first-parent
history for `claimant-key:`; this claimant's key is a replay, exit 0, and any other is exit 1,
`taken`. Absent: a push leased on empty; a lost create is read again as present. A slug claim is
never deleted (S5). Later commits on it, `--entry-claim`'s `wait-since:` and `overlap:` lines
(`tools/unattended/unattended.sh#add_claim_key`), are parented on its tip, so its root commit, the
claim and its `claimant-key`, never changes.

### The scaffold's claim

`cmd_new_build` keeps its order through `check_slug_minted` and its readiness table. Three steps
change:

1. Before `check_slug_claimed`, `read_own_claim(root, slug, key)` reads this node's cache ref
   `refs/gov/remote/claims/<slug>` with no fetch. Its `claimant-key` equal to `key` is a resume, and
   the local pre-check is skipped, since that claim commit's message names the slug and
   `check_slug_claimed`'s `git log --all` probe would refuse it. `run_entry_claim` skips the
   pre-check for a resuming claimant for the same reason.
2. `key` is `derive_mandate_key(ids)`: the first twelve hex digits of the SHA-256 of the sorted ids
   joined by newlines, so one mandate re-run in any session is one claimant.
3. After the unfiled and every-`no` refusals and before `write_text`, `write_slug_claim(root, slug,
   key)` runs `gov-claim.sh slug` through `corpus_ids.py#resolve_bash`, with `--offline` read by
   `read_policy_value("leases.offline", root)`. A `LookupError` or `ValueError` from that reader
   passes no `--offline`, so the CLI's `refuse` applies, and prints the reader's reason. Exit 0 goes
   on; any other exit raises `Problem` naming the ref and the CLI's line, and nothing is written.

### The registry row

```toml
[[record-kind]]
name = "claim"
tag = "record.claim"
layer = "layer.memory"
home = ["refs/gov/claims/**"]

readers-none = "a claim is read by its writers' replay and the orphan check, never filled into a work order"

```

The row is hand-written: `record_kinds.py new` admits `--form fields` or `fence` only, and a `header`
row's message grammar is graded by its owner at write, S1's refusals. `check` names the leg whose
self-test carries §7's two-clone arm. `record_kinds.py --write` then re-renders the template's
`gen:record-kinds` region, whose count line moves by one.

### The ids rule

The rewritten bullet, in the template:

> Within a build, no reserve-above-a-marker, no shared counter and no renumber-on-merge: the slug,
> claimed once at `refs/gov/claims/<slug>`, is the guarantee. A filer outside a build, one filing an
> ask in another build's family, mints the id through `gov-claim.sh ask`, under that family's counter
> ref `refs/gov/claims/asks/<FAMILY>-<slug>`.

## 5. Production-readiness checklist

- security — a new remote write path: every argument is validated before any git call (`<key>` hex,
  `<FAMILY>` in `FAMILIES`, `<slug>` by the grammar), ref names are built only from validated parts,
  the push is leased, and deletion of a claim ref is refused at the one writer.
- perf / scale — one bounded fetch and one push per claim or mint; a lost race costs a re-read, at most
  three times.
- error / empty / loading states — offline follows `leases.offline` and writes nothing; no remote is
  `local`; a lost race past its retries exits 2 naming the ref; a hook's refusal is named through
  `GOVREF_WHY`.
- observability — every verb prints one line naming the ref and the result, and every write joins the
  change feed through `write_feed_success`.
- risks — an unpushed run branch's ids stay invisible (§3). A clone offline under `warn` waits rather
  than minting, so a filer with no remote access cannot mint until it answers.
- testing — AC1 to AC8 by a pass; the arms of §7 at the close.
- migration — none, as §4 says.
- user docs — none under `help/`: no page describes minting; S9 updates the ids rule.
