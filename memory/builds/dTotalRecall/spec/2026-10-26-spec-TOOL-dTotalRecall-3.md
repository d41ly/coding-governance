## 1. Goal

Two clones that have not fetched each other can no longer mint one slug, and a filer outside a build
mints an ask id under its family's counter ref, advanced by a `--force-with-lease` push, so every
such mint is serialised (gap-mem-13, DA-M12, DA-M13, FL1; `layer-memory.md:316-335`). Every claim
commit carries its claimant key, so a replayed claim is idempotent; a slug claim ref is never pruned;
and an unreachable remote is handled as `leases.offline` says. Today `check_slug_claimed`
(`tools/memory-tree/gen_build_index.py:3940`) reads the local clone only, and no claim ref exists for a
slug or an ask family.

## 4. Design

### The verbs

```
bash gov-claim.sh slug <slug> --claimant <key> [--offline <value>]
bash gov-claim.sh ask <FAMILY> <slug> --claimant <key> [--offline <value>]
```

`<key>` is twelve lowercase hex digits, the shape of `derive_section_sha` (`tools/roles/handoff.py:307`);
`<FAMILY>` one of `FAMILIES`; `<slug>` admitted by `mint_re` for `slug` and by `BUILD_SLUG_RE` for
`ask`. `--offline` absent is `refuse`. The remote is resolved by the inline `remote_ladder_sh` block,
and every git call to it runs under one bounded runner, `GOVREF_RUNNER`, the `run_remote` shape
`tools/run-gates/post-merge.sh` uses.

| Exit | stdout | Meaning |
|---|---|---|
| 0 | `claimed refs/gov/claims/<slug> <sha>` | the slug is this claimant's, new or replayed |
| 0 | `minted <FAMILY>-<slug>-<n>` | the id, new or replayed |
| 0 | `queued <ref> <provisional>` | offline under `warn` |
| 1 | `taken <ref> by <claimant>` | another claimant holds the slug |
| 2 | `refused <why>` | offline under `refuse` or `follow-leases`, a malformed argument, or a push not completed |

Each commit is `build_gov_commit <tip read or empty> <message>`, the message the `gov-claim` grammar
of `unattended.sh:2411-2412` with these keys: `slug`, `node`, `host`, `session`, `status` (`claimed`
or `minted`), `beat-utc`, then `claimant`, and for a counter `family` and `seq`.

### The counter

1. Fetch the counter ref and the remote's default branch tip, one bounded fetch.
2. If the ref's first-parent history, read to 64 commits, holds `claimant: <key>`, print that commit's
   `seq` and stop: a replay.
3. `floor` is the highest `<n>` of `<FAMILY>-<slug>-<n>` named in any tracked file of the default
   branch tip (`git grep -ohE` at that commit) or of `HEAD`; the next id is `max(tip seq, floor) + 1`,
   with an absent ref reading `tip seq` 0.
4. Push leased on the tip read (empty when absent). A lost push repeats from 1, up to three times,
   then exits 2 naming the lost race.

So two mints racing on one ref get two numbers, and a counter created late never re-mints an id the
default branch already holds.

### The slug claim

`check_slug_claimed` runs first and is unchanged. Then one fetch of `refs/gov/claims/<slug>`: present
with this claimant is a replay, exit 0; present with another is exit 1; absent is a push leased on
empty. A slug claim is never deleted and never moved after creation, so a slug is minted once.

### The registry row

```toml
[[record-kind]]
name = "claim"
tag = "record.claim"
layer = "core"
home = "refs/gov/claims/"
id-rule = "refs/gov/claims/<slug> | refs/gov/claims/asks/<FAMILY>-<slug>"
schema = { form = "header", fields = ["slug", "node", "host", "session", "status", "beat-utc", "claimant", "family", "seq"] }
writer = "gov-claim.sh"
readers = []
lifecycle = "append-only"
check = "build-index selftest"
```

The row takes TOOL-dTotalRecall-1's data model: `schema.form` `header`, a message grammar its owner
grades at write (S1's refusals), so no `source`; `check` names the leg whose self-test carries the
two-clone arm of §7. `layer`, `home` and `lifecycle` are filled as TOOL-dTotalRecall-18 requires them.

### The ids rule

The rewritten bullet, in the template:

> Within a build, no reserve-above-a-marker, no shared counter and no renumber-on-merge: the slug,
> claimed once at `refs/gov/claims/<slug>`, is the guarantee. A filer outside a build, one filing an
> ask in another build's family, mints the id through `gov-claim.sh ask`, under that family's counter
> ref `refs/gov/claims/asks/<FAMILY>-<slug>`.

## 5. Production-readiness checklist

- security — a new remote write path: every argument is validated before any git call (`<key>` hex,
  `<FAMILY>` in `FAMILIES`, `<slug>` by the grammar), ref names are built only from validated parts,
  the push is leased, and deletion of a claim ref is refused at the one writer.
- perf / scale — one bounded fetch and one push per claim or mint; a lost race costs a re-read, at most
  three times.
- error / empty / loading states — offline follows `leases.offline`; a lost race past its retries exits
  2 naming the ref; a hook's refusal is named through `GOVREF_WHY`.
- observability — every verb prints one line naming the ref and the result; a `yield` appends the
  `lease-yielded` health event S10 defines.
- risks — under `warn`, a provisional id can yield after its record is written; the `yield` line names
  it, and the filer re-mints before landing. An unpushed run branch's ids stay invisible (§3).
- testing — AC1 to AC7 by a pass; the arms of §7 at the close.
- migration — none, as §4 says.
- user docs — none under `help/`: no page describes minting; S9 updates the ids rule.

## 6. Acceptance criteria

- **AC1** — When two clones of a bare fixture remote under `%TEMP%/<short>`, neither having fetched the
  other, each run `bash gov-claim.sh slug dSame --claimant <their own key>` at the same moment, exactly
  one exits 0 with `claimed`, the other exits 1 with `taken` naming the winner's claimant; and in the
  losing clone, a probe calling `check_slug_claimed` for `dSame` before the claim returns the empty
  string, today's local-only answer that would have let both mint.
  Red when: the claim is checked locally only, so both clones claim `dSame`.
- **AC2** — When the same two clones each run `bash gov-claim.sh ask TOOL dSame --claimant <key>` in
  parallel five times, the ten printed ids are `TOOL-dSame-1` to `TOOL-dSame-10` with no repeat; and in
  a fixture whose default branch already names `TOOL-dSame-14`, the next mint is `TOOL-dSame-15`.
  Red when: a lost push is not retried on a fresh read, or the floor is not read.
- **AC3** — When `gov-claim.sh ask` runs twice with one claimant key, it prints the same id both times
  and the ref's tip does not move; and `git log -1 --format=%B` on the counter ref shows a
  `claimant:` line.
  Red when: a replay mints a second id.
- **AC4** — When `gen_build_index.py --new-build dSame` runs in the losing clone of AC1 with a filed
  ask list, it exits non-zero naming `refs/gov/claims/dSame` and writes no README.
  Red when: the scaffold writes the README on the local check alone.
- **AC5** — When a probe sources `gov-ref.sh` and calls `write_gov_ref
  refs/gov/claims/dSame <sha> ""`, it returns 2 with `GOVREF_WHY` naming `refs/gov/claims/`; and the
  `gov_ref_sh` block cut with the parity arm's `blk` awk range from `gov-ref.sh` and from
  `gov-claim.sh` is identical.
  Red when: a claim ref can be deleted through the writer, or the copy drifts.
- **AC6** — When the fixture's remote URL is pointed at a missing path, `gov-claim.sh ask TOOL dSame
  --offline refuse` exits 2 with `offline`; with `--offline warn` it exits 0 printing `queued` and a
  provisional id, and `gov-queue.log` in the git common directory gains one line; with `--offline follow-leases`
  it exits 2.
  Red when: an offline mint creates a ref, or `warn` refuses.
- **AC7** — When a probe reads `record-kinds.toml` with `tomllib`, it finds one row named `claim`
  whose `writer` is `gov-claim.sh`.
  Red when: the kind is unregistered.
