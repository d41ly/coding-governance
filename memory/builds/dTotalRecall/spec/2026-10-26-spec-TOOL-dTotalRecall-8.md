## 1. Goal

Derive a core `code` record from the tree: files, definitions with their ranges and body hashes,
imports, every Python definition with import-aware calls, shell and JavaScript edges under the
ambiguity test, cross-language invocation and registry edges, tests and kit membership. It is
derived per blob through the shared extraction primitive into the one index, cached by tree hash,
bounded on its inputs, and anchoring dossiers to symbol keys. Today `symbols.json` holds public
module-level names with no ranges and no caller index exists (gap-mem-04, gap-mem-28). A record that
loses its re-timing, over 30 s cold or over 1 MB on gov's tree or on a planted adopter-scale fixture,
is never built.

## 4. Design

### The derivation

`derive_code_record(root, tree)` lists the tree with one `git ls-tree -r -z`, applies the bounds,
reads the remaining blobs in one `git cat-file --batch` through the primitive's `read_defs_at` state
reader, and for each blob not already holding `code_row` rows runs `extract_ranges`. The Python
reader is `ast`, recording every `FunctionDef`, `AsyncFunctionDef` and `ClassDef` with `lineno`,
`end_lineno`, its dotted qualified name inside the module, and `hashlib.sha1` of the body's source
segment; every `Call` with its enclosing definition's key; every import as `_python_defs` reads it
today. Shell and JavaScript definitions come from `parse_shell_defs` and `parse_ts_source`, their
ranges from the brace or `fi`/`}` close the tokenizer already finds, their call sites from the token
stream. A definition key is `<path>::<qualified name>`; a nested definition's qualified name joins its
parents with `.`.

Resolution then runs per tree over the rows, never per blob, since an edge depends on two blobs:
imports map a local name to a module path among the tree's files; a call's text resolves through that
map, then the enclosing class and its bases. Each resolved call is a `calls` edge; an unresolved one a
`mention` edge whose `dst` is the call text.

### Bounds

| Input | Rule | Row |
|---|---|---|
| vendored, generated | `git check-attr --stdin linguist-vendored linguist-generated` set | none |
| binary | `git check-attr diff` is `unset`, or a NUL in the first 8000 bytes | `skipped: binary` |
| LFS | `git check-attr filter` is `lfs` | `skipped: lfs` |
| submodule | a gitlink, mode `160000` | `code_file` row, `lang = submodule` |
| oversized | blob size over `CODE_FILE_CAP`, 2 MiB | `skipped: over 2097152 bytes` |
| time | wall time over `CODE_RUN_CEILING`, 30 s | `code_meta.degraded = time ceiling` |

The attribute read is one `git check-attr --stdin` spawn over the listed paths, the batched shape of
`tools/check-wiring.sh:1141`. `CODE_FILE_CAP` keeps every tracked code file of gov's tree: the largest
is `tools/unattended/unattended.test.sh`, 1,303,145 bytes (PINNED, measured at base 2026-10-26). gov
registers its generated code paths in `.gitattributes`: `tools/workflows/*.js`, rendered from their
`.template.js`. A degraded record is kept and marked; every reader seeing `degraded` uses `git grep`.

### The fixture

`python code_record.py --fixture adopter` builds, under `%TEMP%`, a repository holding gov's tracked
text files at the base sha twice, once at the root and once under `vendor/` marked
`linguist-vendored`, plus 50 binary files, 20 LFS pointer files under `filter=lfs`, one submodule
gitlink and five 3 MiB source files. It then runs `--time` cold there. The vendored copy is the
discriminating plant: if exclusion fails, the derivation reads twice gov's code and its bytes double
past the losing line.

### Record size

`bytes` is the length of `python code_record.py --dump --tree <rev>`, the record's rows rendered as
sorted TSV, one row per line: the size an agent's read of the whole record would cost. The night pass
measured 13.1 s and 941 KB on a prototype (night-pass.md:202-206); that figure is not this record's.

### Alternatives rejected

- **Extend `map_lib.python_symbols`** (`tools/codebase-map/map_lib.py:318`): it reads public
  module-level names only, the 75.5% gap gap-mem-04 measures.
- **A JSON artifact committed beside the map.** A tracked caller file goes stale on every commit,
  which is why the map omits fan-in today (layer-memory.md:781-783); rows keyed by blob in the one

- **Re-implement invocation parsing over the shell tokenizer.** runlog's `extract_segments` already
  reads interpreter-and-path segments; a second parser is a copy, so it becomes a canonical block at
  this, its second instance.

## 5. Production-readiness checklist

- security — no new write surface beyond the index file under the git common dir; ctags is run only
  from `PATH` under an opted-in value, with `--output-format=json` and no shell.
- perf / scale — the losing line is 30 s cold and 1 MB, measured by S1 before anything is built; warm
  runs parse only blobs no `code_row` holds.
- error / empty / loading states — a missing ctags under a ctags value is exit 2; a degraded record
  says so in `code_meta` and its readers use `git grep`; an empty tree is `unarmed`, red.
- observability — `--time` prints seconds and bytes; `--check` prints counts of definitions, calls,
  mentions per language and skipped rows by reason.
- risks — the record losing its re-timing (§8 F1); an ambiguity over 10% shipping a language's edges
  as mentions, which the meta line reports.
- testing — AC1 to AC9 by the pass; the new arms of §7 at the close.
- migration — none: no record or conf changes; `.gitattributes` gains lines that change no checkout.
- user docs — `tools/memory-tree/README.md` gains the record's section; no `help/` page names the
  map's symbols today.

- **AC5** — When `--check` runs at the pass tip after one commit editing one `.py` file, it re-parses
  that one blob (its printed parse count is 1) and exits 0; with one cached `code_row` altered by hand

  Red when: a warm run re-parses unchanged blobs, or a stale row passes.
- **AC6** — When `--fixture adopter` runs, `--dump` holds no row under the vendored copy, `skipped: binary`
  for each binary file, `skipped: lfs` for each pointer, `skipped: over 2097152 bytes` for each 3 MiB

  Red when: a vendored path, a binary or an LFS blob is parsed.
- **AC7** — When the fixture runs with `CODE_RUN_CEILING` overridden to 0.01 s through `--ceiling`,
  `code_meta` carries `degraded = time ceiling` and `--check` prints the `git grep` floor line.
  Red when: a run past the ceiling writes a partial record that reads as whole.
