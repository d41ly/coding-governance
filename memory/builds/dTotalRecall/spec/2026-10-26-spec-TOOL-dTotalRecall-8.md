## 1. Goal

Derive a core `code` record from the tree: files, definitions with their ranges and body hashes,
imports, every Python definition with import-aware calls, shell and JavaScript edges under the
ambiguity test, cross-language invocation and registry edges, tests and kit membership. It is
derived per blob through the shared extraction primitive into the one index, cached by tree hash,
bounded on its inputs, and anchors dossiers to symbol keys. Today `symbols.json` holds public
module-level names with no ranges and no caller index exists (gap-mem-04, gap-mem-28). The first
design lost its re-timing on size (deviation 83); the owner ruled it redesigned under a bound it can
meet, and this is that record: one text per tree whose edges name definitions by their order in it,
the rest derived at read. A record that loses its re-timing is never built (S1, §8 F1).

## 2. Scope (IN)

- **S1** — The re-timing, first: before any other code of this unit, the derivation of §4 "The
  derivation" and the text of §4 "The record" are written and measured by `python code_record.py
  --time --tree <rev>`, which reads no cached row, on gov's tree at the pass base and on the planted
  adopter-scale fixture of §4 "The fixture", each run printing `seconds`, `bytes` and `facts`. A run
  over one of §4 "The bound"'s three lines, on either, loses, and the loss route of §8 F1 is taken.
  Observed by AC1.
- **S2** — The derivation in `tools/playbook/code_record.py`, beside the index it writes (§8 F6),
  through the playbook-render kit's copy of the primitive, `tools/playbook/extract_code.py`
  (TOOL-dTotalRecall-13's block, which its `PARITY_ROWS` row `extract_code` finds by marker), whose
  block gains `extract_ranges(src, ext)`: each definition with its qualified name, kind, `line`,
  `end_line` and a body hash, each import, each class's bases, and each call site with its enclosing
  definition and line. Observed by AC2.
- **S3** — Python calls resolved import-aware: a name resolves through its enclosing definitions, its
  module and its module's imports; a method through `self` or `cls`, a class name, or a local name
  assigned from a call of a class, then that class and its bases as imported. One that resolves to
  none is a `mention`, kept where its last segment is the last segment of a Python definition of the
  tree (§8 F8). The record counts calls, kept mentions and sites dropped. Observed by AC3.
- **S4** — Shell and JavaScript edges under the ambiguity test: a site is a word (shell) or a called
  name (JavaScript) naming a definition of that language, and it resolves within the caller's own
  file, then its sourced files, then its kit. Two or more candidates at the first level holding one is
  ambiguous, kept as a `mention`; a site with no candidate in reach is no site, which `git grep`
  answers. Past 10% of a language's sites ambiguous, all that language's edges ship as mentions and
  the record's `a` line says so. Observed by AC3.
- **S5** — Cross-language invocation edges, from an interpreter and a tracked path in a shell segment
  or a Python or JavaScript argv literal, read by `tools/runlog/extract.py#extract_segments` and
  `tools/runlog/extract.py#_derive_program`. Both move, with the helpers `_derive_basename`,
  `_remove_heredocs` and `_read_separator` and the constants they read, into a canonical block
  `invocation_segments` in `tools/lib/invocation_segments.py`; `tools/runlog/extract.py` keeps them
  inline as one contiguous marked region under a new `PARITY_ROWS` row, its other readers unchanged,
  and `code_record.py` carries a copy. A path ending in two or more tracked paths resolves among those
  the record holds. Registry edges: each `tools/gate-legs.json` row's `argv` path, its `{prefix}`
  resolved by the kit's inline `resolve_prefix_token` block, and each `kit.toml` `version_from` file.
  Observed by AC4.
- **S6** — Tests and kit membership, derived at read and stored nowhere: a file is a test when its
  name matches `*.test.sh`, `selftest.py` or `test_*.py`, and a `tests` edge is a `calls` or `invokes`
  edge out of one; a file's kit is the nearest `tools/<kit>/` holding a `kit.toml`. Observed by AC2.
- **S7** — Storage in the one index (I11), the file `tools/playbook/tag_index.py#derive_index_path`
  names, opened through `tools/playbook/tag_index.py#load_index`, two tables `code_record.py` creates:
  `code_facts(blob, lang, version, facts)`, one blob's facts as `zlib` bytes, and `code_tree(tree,
  version, record)`, the text of §4. `version` is the first 12 hex of the SHA-256 over the bytes of
  `code_record.py` and `extract_code.py`, the value of `memory.code-languages` and the ctags version
  (PLAY-dOrderedCharter-51's rule). A blob with a `code_facts` row at this version is never parsed
  again, one yielding no definition included (the round-1 audit's id 55); a degraded record is never
  written (id 54). Each write keeps only the trees a worktree's HEAD names
  (`tools/playbook/tag_index.py#read_worktree_trees`) and the blobs they hold. Every reader goes
  through `derive_code_record(root, tree)`, whose answer holds `code_row`, `code_file`, `code_edge`
  and `code_meta` rows in the shapes of §4 "The readers". Observed by AC5 and AC7.
- **S8** — Freshness: `python code_record.py --check` re-derives HEAD's record from the blobs and

## 4. Design

### The derivation

`derive_code_record(root, tree)` lists the tree with one `git ls-tree -r -l -z`, applies the bounds,
and reads the remaining blobs in one batch through `tools/memory-tree/tree_lib.py#read_blobs_at`,
reached by `tools/playbook/tag_index.py#load_memory_tree`. It runs `extract_ranges` over each blob
`code_facts` lacks at this version. The Python reader is `ast`, recording every `FunctionDef`,
`AsyncFunctionDef` and `ClassDef` with its dotted qualified name inside the module and the first 12
hex of the SHA-1 of its source lines; every `Call` with its enclosing definition; every import as
the block's `_python_defs` reads it. Shell and JavaScript definitions come from the block's
`parse_shell_defs` and `parse_ts_source`, their ranges from the close the tokenizer finds, their call
sites from the token stream. A definition key is `<path>::<qualified name>`; a nested definition's
name joins its parents with `.`, and a name defined twice in one file reads as its first.

Resolution then runs per tree over the facts, since an edge depends on two blobs. An import maps a
local name to a module path: beside the importer, at the root, or the one tracked file of that stem.
`write_code_rows` stores the new facts and the text in one `BEGIN IMMEDIATE` transaction, the index's
write pattern (`tools/playbook/tag_index.py#build_index`), and `remove_unheld_code_rows` keeps only
what S7 says. `load_index` drops every table of a file stamped with another `INDEX_SCHEMA`, these two
included, which costs one rebuild.

### The record

One UTF-8 text, LF-ended, paths sorted, TAB between cells. An ordinal is a line's place, from 0, among
the `f` and `d` lines, so `f` is the module's own ordinal.

```
code-record 1	<extractors>	<languages>
f	<path>                                 a code file
i	<module>[:<name>,…] …                  its imports
d	<depth>[C]	<name>	<line>-<end>	<hash12>   a definition, C a class, its depth under its file
c	<ordinal> …                            calls out of the f or d line above
m	<name> …                               mentions out of it
x	<ordinal> …                            files it invokes
r	<leg or kit>	<ordinal>                  a registry edge
a	<language>	<ambiguous>/<sites>          that language's edges ship as mentions
s	<path>	<reason>                        a skipped input
```

`--dump --tree <rev>` prints this text, its one form; `bytes` is its length, what a reader loads.
`facts` is the summed length of the tree's `code_facts.facts` values, what the index stores beside it.
No blob id, file outside the languages, test, kit, call line or body text is in it: each is the
tree's listing, a name rule or a blob read at a range, and the two figures leave nothing else stored.

### The neighbourhood

`print_neighbourhood` writes TOOL-dFurnishedOrders-17 §4 "The rows", that unit's `CODE_ROW_RE`:

```
<path>:<line>-<end_line> · <kind> <qualified name> · def
<path>:<line>-<end_line> · <kind> <qualified name> · caller <seed definition>
<path>:<line>-<end_line> · <kind> <qualified name> · callee <seed definition>
<path>:<line>-<end_line> · <kind> <qualified name> · test <seed definition>

```

`<kind>` is `function` or `class`; `<seed definition>` is the seed definition's qualified name. A
`caller` is a definition holding a `calls` edge into a seed definition, outside a test file; the same
edge from a test file is a `test` row instead. A `callee` is a definition a seed definition's `calls`
edge reaches; mentions print nothing. A call at module level prints kind `module`, its name the file's
stem, its range the call's line twice. A `sibling` is each other tracked file of a seed file's kit (S6).

### Alternatives rejected

- **The rev-9 record, a row per fact with full keys in both ends of an edge, under a raised line.** It
  is the losing record; its keys repeat two paths per edge and its mentions name no definition.
- **A bound per definition.** It tracks the tree's growth, and nothing grades the size after S1.
- **No `code_facts`.** It halves what is stored, and every new tree re-parses every blob.
- **Extend `map_lib.python_symbols`** (`tools/codebase-map/map_lib.py#python_symbols`): public
  module-level names only, the gap gap-mem-04 measures.
- **A JSON artifact committed beside the map.** A tracked caller file goes stale on every commit, which
  is why the map omits fan-in
  (`memory/builds/dClosedLoop/build/2026-10-15-build-PLAY-dClosedLoop-1-layer-memory.md@8b8b1374:781-783`).
- **Re-implement invocation parsing over the shell tokenizer.** runlog's `extract_segments` reads it
  already, so it becomes a canonical block at this, its second instance.
