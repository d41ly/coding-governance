## 1. Goal

Derive a core `code` record from the tree: files, definitions with their ranges and body hashes,
imports, every Python definition with import-aware calls, shell and JavaScript edges under the
ambiguity test, cross-language invocation and registry edges, tests and kit membership. It is
derived per blob through the shared extraction primitive into the one index, cached by tree hash,
bounded on its inputs, and anchoring dossiers to symbol keys. Today `symbols.json` holds public
module-level names with no ranges and no caller index exists (gap-mem-04, gap-mem-28). A record that
loses its re-timing, over 30 s cold or over 1 MB on gov's tree or on a planted adopter-scale fixture,
is never built.

## 2. Scope (IN)

- **S1** — The re-timing, first: before any other code of this unit, the derivation core of §4 "The
  derivation" is written and timed by `python code_record.py --time --tree <rev>`, which reads no
  cached row, on gov's tree at the pass base and on the planted adopter-scale fixture of §4 "The
  fixture", each run printing `seconds` and `bytes`. A run over 30 s or a record over 1 MB on either
  loses, and the loss route of §8 F1 is taken. Observed by AC1.
- **S2** — The derivation in `tools/playbook/code_record.py`, beside the index it writes (§8 F6),

  `end_line` and a body hash, each import, and each call site with its enclosing definition.
  Observed by AC2.
- **S3** — Python calls resolved import-aware: a module-level call resolves through the module's
  imports to a definition key; a method call resolves through its enclosing classes and their bases
  as imported; one that resolves to neither is a `mention`, and the record prints the count of each.
  Observed by AC3.
- **S4** — Shell and JavaScript edges under the ambiguity test: a call resolves within the caller's

  meta line. Observed by AC3.
- **S5** — Cross-language invocation edges, from an interpreter and a tracked path in a shell segment
  or a Python or JavaScript argv literal, read by `tools/runlog/extract.py#extract_segments` and

  resolved by the kit's inline `resolve_prefix_token` block, and each `kit.toml` `version_from` file.
  Observed by AC4.

  `selftest.py` or `test_*.py`, and a `tests` edge joins it to each definition it calls or invokes; a

## 4. Design

### The derivation

`derive_code_record(root, tree)` lists the tree with one `git ls-tree -r -l -z`, applies the bounds,
and reads the remaining blobs in one `git cat-file --batch` through
`tools/memory-tree/tree_lib.py#read_blobs_at`, reached by `tools/playbook/tag_index.py#load_memory_tree`
as the tag index reads its blobs. It runs `extract_ranges` over each blob `code_parsed` lacks at this
version. The Python reader is `ast`, recording every `FunctionDef`, `AsyncFunctionDef` and `ClassDef`
with `lineno`, `end_lineno`, its dotted qualified name inside the module, and `hashlib.sha1` of the
body's source segment; every `Call` with its enclosing definition's key; every import as the block's
`_python_defs` reads it. Shell and JavaScript definitions come from the block's `parse_shell_defs`
and `parse_ts_source`, their ranges from the brace or `fi`/`}` close the tokenizer already finds,
their call sites from the token stream. A definition key is `<path>::<qualified name>`; a nested
definition's qualified name joins its parents with `.`.

Resolution then runs per tree over the rows, never per blob, since an edge depends on two blobs:
imports map a local name to a module path among the tree's files; a call's text resolves through that
map, then the enclosing class and its bases. Each resolved call is a `calls` edge; an unresolved one a
`mention` edge whose `dst` is the call text. `write_code_rows` stores both halves in one `BEGIN
IMMEDIATE` transaction, the index's write pattern (`tools/playbook/tag_index.py#build_index`), and
`remove_unheld_code_rows` keeps only what S7 says. `load_index` drops every table of a file stamped with
another `INDEX_SCHEMA`, the tables of S7 included, which costs one rebuild.

### Bounds

| Input | Rule | Row |
|---|---|---|
| vendored, generated | `git check-attr --stdin linguist-vendored linguist-generated` set | none |
| binary | `git check-attr diff` is `unset`, or `read_blobs_at` answers None (not UTF-8) | `skipped: binary` |
| LFS | `git check-attr filter` is `lfs` | `skipped: lfs` |
| submodule | a gitlink, mode `160000` | `code_file` row, `lang = submodule` |
| oversized | blob size over `CODE_FILE_CAP`, 2 MiB | `skipped: over 2097152 bytes` |
| time | wall time over `CODE_RUN_CEILING`, 30 s | `code_meta.degraded = time ceiling` |

The attribute read is one `git check-attr --stdin` spawn over the listed paths, the batched shape of
`tools/check-wiring.sh#check_merge_rows`. `CODE_FILE_CAP` keeps every tracked code file of gov's tree:
the largest is `tools/unattended/unattended.test.sh`, 1,806,632 bytes (PINNED 2026-11-22, `git ls-tree
-r -l` at `d6de992c6`), and four tracked non-code files over it take skipped rows (PINNED 2026-11-22,
the same listing). No `.gitattributes` line names `linguist-` today (`git grep -n linguist
.gitattributes` at `d6de992c6`); this unit registers `tools/workflows/*.js` `linguist-generated`,
which TOOL-dTotalRecall-37 narrows to the four rendered scripts. A degraded record is kept and marked;
every reader seeing `degraded` uses `git grep`.

### The fixture

`python code_record.py --fixture adopter` builds, under `%TEMP%`, a repository holding gov's tracked
text files at the base sha twice, once at the root and once under `vendor/` marked
`linguist-vendored`, plus 50 binary files, 20 LFS pointer files under `filter=lfs`, one submodule
gitlink and five 3 MiB source files. It then runs `--time` cold there. The vendored copy is the
discriminating plant: if exclusion fails, the derivation reads twice gov's code and its bytes double
past the losing line.

### Record size

`bytes` is the length of `python code_record.py --dump --tree <rev>`, the record's rows rendered as
sorted TSV, one row per line: the size an agent's read of the whole record would cost. The night pass
measured 13.1 s and 941 KB on a prototype (PINNED 2026-11-22, that record's line 205 at `8b8b1374`,
`memory/builds/dClosedLoop/build/2026-10-18-build-PLAY-dClosedLoop-1-night-pass.md@8b8b1374:205`);
that figure is not this record's.

### The neighbourhood

`print_neighbourhood` writes TOOL-dFurnishedOrders-17 §4 "The rows", that unit's `CODE_ROW_RE`:

```
<path>:<line>-<end_line> · <kind> <qualified name> · def
<path>:<line>-<end_line> · <kind> <qualified name> · caller <seed definition>
<path>:<line>-<end_line> · <kind> <qualified name> · callee <seed definition>
<path>:<line>-<end_line> · <kind> <qualified name> · test <seed definition>
<path> · sibling
```

`<kind>` is the `code_row` kind, `function` or `class`; `<seed definition>` is the seed definition's
qualified name. A `caller` is a definition holding a `calls` edge into a seed definition, outside a
test file; the same edge from a test file's definition is a `test` row instead. A `callee` is a
definition a seed definition's `calls` edge reaches; `mention` edges print nothing. A call at module
level prints kind `module`, its name the file's stem, its range the call's line twice. A `sibling` is
each other tracked file of a seed file's kit (S6).

## 5. Production-readiness checklist

- security — no new write surface beyond the tables of S7 in the index file under the git common dir;
  ctags is run only from `PATH` under an opted-in value, with `--output-format=json` and no shell.
- perf / scale — the losing line is 30 s cold and 1 MB, measured by S1 before anything is built; warm
  runs parse only blobs `code_parsed` lacks; the leg's ceiling is S13's rule over its measured time,
  150 s at the 30 s line (PINNED 2026-11-22, `tools/run-gates/ceiling-margin.txt:26`), its evidence
  row in `tools/run-gates/ceiling-evidence.txt`.
- error / empty / loading states — a missing ctags under a ctags value is exit 2; a degraded record
  says so in `code_meta`, its readers use `git grep` and `neighbourhood` exits 2; an empty tree is
  `unarmed`, red.
- observability — `--time` prints seconds and bytes; `--check` prints counts of definitions, calls,
  mentions per language and skipped rows by reason.
- risks — the record losing its re-timing (§8 F1); an ambiguity over 10% shipping a language's edges
  as mentions, which the meta line reports.
- testing — AC1 to AC13 by the pass; the new arms of §7 at the close.
- migration — none for a record or a conf: the index is a cache, and `.gitattributes` gains lines
  that change no checkout.
- user docs — `help/reference/policy.md` gains the key's section by its render (S10);
  `tools/playbook/README.md` gains the record's section; no `help/` page names the index's tables.
