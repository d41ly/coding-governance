## 1. Goal

Give every record kind a declared purpose, in a `purpose` column of the registry, and review the
purposes of today's kinds and of the chain builds whose `purpose` field PLAY-dOrderedCharter-22
added, as `memory.map-purpose` says. Under its default `review`, a new node must declare one, and
each existing node's purpose is derived from what it already carries with the source cited, or put
to the owner in one ask per namespace, rendering `—` until answered (PM-5, gap-mem-27). The
namespace members' purposes are already held by PLAY-dOrderedCharter-22's `purpose` arm (§8 F4).
The level-0 map reads these purposes.

## 4. Design

### The values

| `memory.map-purpose` | New node with no purpose | Existing purposeless node | A `pending` the check admits |
|---|---|---|---|
| `review` (default) | refused | derived with its source cited, else one owner ask per namespace; `—` while pending | an open ask's id |
| `ledger` | refused | listed on the shrink-only ledger population `purpose-pending` (TOOL-dWitnessedBar-13 S2), drained by each owning build; `—` while listed | `purpose-pending`, the node a row of that ledger |
| `derive` | refused | derived as below, with no ask; `—` when nothing is found | `none-found` |
| `refuse` | refused | `--check` red while any registry row lacks a `text` | none |

The values are the project map's PM-5 options (project-map.md:740, :868); `review` is the owner's
answer. Under `ledger`, a ledger row naming a node that now carries a `text` is red, naming the row
to drain. The reader falls back as it was probed on 2026-11-22: a value outside the four in a
revision after a valid one reads the earlier valid value, and one with no valid revision before it
refuses, exit 2 (PINNED, `policy.py get` over a scratch repository).

### Derivation order

1. The H1 of the file the node lives in, the first `# ` line outside a fence by
   `tools/memory-tree/tree_lib.py#unfenced_lines`, after its slug or name and the dash, cited
   `<path>:<line>`. A chain build lives in `<MEMORY_ROOT>/builds/<slug>/README.md`; a record kind
   lives in the shared registry, which has no H1 of its own, so this step reads nothing for it.
2. The record that introduced it, the `--from` path: the row of a Markdown table outside a fence
   whose first cell, `-` read as a space and through `tree_lib.py#resolve_kind`, names the kind; its
   last cell is the text, cited `<path>:<line>`. The path is a tracked file, else exit 2 (§8 F5).

A text longer than `PURPOSE_BYTES` is cut at the last word boundary before it. A text that only
repeats the node's name is not a purpose and the next source is tried. A node's id is
`record-kind:<name>` or `chain:<slug>`, and its namespace is the part before the colon. At
`a3d6d07e`, every chain row's README holds an H1 of that shape (DERIVED, `grep -m1 '^# '` over
`memory/builds/<slug>/README.md` for each slug of `memory/project/chain.toml`), and 17 of the 25
registry rows name a row of the layer-memory kind table at layer-memory.md:397-481 (DERIVED, each
`name` against the table's first cells, `-` read as a space).

## 5. Production-readiness checklist

- security — the review reads tracked files only and writes the registry and `chain.toml`, each by
  one inserted line; a text is one line under `PURPOSE_BYTES`, written through `json.dumps` as
  `render_row` writes every value; an untracked `--from` path is refused.
- perf / scale — one read per registry, per README and of the `--from` record; `--check` adds one
  policy subprocess and one parse of the tracked `BACKLOG.md` files to the `record-kinds` leg.
- error / empty / loading states — an empty registry is `unarmed`, red, as today; an unresolved chain
  registry is `unarmed chain`; a refused key read exits 2 naming the key.
- observability — the review prints one line per node and one per ask draft; the view's line counts
  the pending kinds.
- risks — a derived purpose that misdescribes its node; the citation makes each one checkable, and
  the review record lists them for the owner.
- testing — AC1 to AC7 by the pass; the new arm of §7 at the close.
- migration — none: purposes are added, nothing renamed.
- user docs — `help/reference/kinds.md` and `help/reference/policy.md` by their renders (S2, S7); the
  map that renders purposes is TOOL-dTotalRecall-14's.
