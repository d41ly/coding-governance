## 1. Goal

Give every record kind a declared purpose, in a `purpose` column of the registry, and review the
purposes of today's kinds and of the namespaces and chain builds whose purpose fields
dOrderedCharter adds, as `memory.map-purpose` says: under its default `review`, a new node must
declare one, and each existing node's purpose is derived from what it already carries with the
source cited, or put to the owner in one ask per namespace, rendering `—` until answered (PM-5,
gap-mem-27). The level-0 map reads these purposes.

## 2. Scope (IN)

- **S1** — The column: `purpose` on every `[[record-kind]]` row of `tools/memory-tree/record-kinds.toml`
  (I1, after `check`), an inline table that is either `{ text = "<one line>", source = "<citation>" }`
  or `{ pending = "<ask id>" }`. `text` is at most 120 bytes on one line; `source` is `<path>:<line>`,
  `<path>#<field>` or `owner`. Observed by AC1.
- **S2** — New nodes must declare one: `record_kinds.py new` refuses a row with no `--purpose`, and
  `check_record_kinds` reds a row with no `purpose` table, or with `pending` naming no open ask of a
  `BACKLOG.md`. Observed by AC2.
- **S3** — The review, `python record_kinds.py --purpose-review`, over three populations: the rows of
  the registry; the members of each `[[namespace]]` row of `tools/playbook/namespaces.toml` whose
  `purpose-source` names a field (PLAY-dOrderedCharter-22 S2), a member being purposeless when that
  field is absent or empty; and the rows of `memory/project/chain.toml` that carry no `purpose`
  (PLAY-dOrderedCharter-22 S3, S4). For each purposeless node it tries, in order, the node's own doc
  field, its file's H1 or first docstring or header comment, and the record that introduced it, and
  prints `derived <node> · <purpose> · <source>` or `none <node> · <what was found>`. Observed by AC3.
- **S4** — The write, `--purpose-review --write`: each derived purpose is written into the node's
  own field (the registry row's `purpose`, the member's `purpose-source` field, the chain row's
  `purpose`), and each namespace with a `none` node yields one ask draft listing every such node with
  what was found; the pass files each draft as an ask in this build's `BACKLOG.md` and writes its id
  into the nodes' `pending`. Observed by AC4.
- **S5** — `memory.map-purpose`, read by `read_policy_value("memory.map-purpose", root)` from the
  memory-tree adapter `tools/memory-tree/policy_value.py` (TOOL-dTotalRecall-8 S10), as §4 "The values"
  states; the catalogue row's `summary` and `usage` filled and its name drained from
  `tools/policy/unsummarised-keys.txt` with `policy.py lists --write`. Observed by AC5.
- **S6** — The view: the `gen:record-kinds` region renders each kind's purpose, `—` while `pending`,
  and its header line counts the pending kinds. Observed by AC1.
- **S7** — The review record: the pass commits the review's printed lines as
  `memory/builds/dTotalRecall/build/<date>-build-TOOL-dTotalRecall-16-purpose-review.md`, `**Serves:**
  log TOOL-dTotalRecall-16`, the source of every derived purpose cited there. NOT OBSERVED by a

## 4. Design

### The values

| `memory.map-purpose` | New node with no purpose | Existing purposeless node |
|---|---|---|
| `review` (default) | refused | derived with its source cited, else one owner ask per namespace; `—` while pending |
| `ledger` | refused | listed on the shrink-only ledger population `purpose-pending` (TOOL-dWitnessedBar-13 S2), drained by each owning build; `—` while listed |
| `derive` | refused | derived from its first comment, H1 or README line, with no ask; `—` when nothing is found |
| `refuse` | refused | `--check` red while any node lacks one |

The values are the project map's PM-5 options (project-map.md:740, :868); `review` is the owner's
answer. A refused read of the key reds `--check` naming the key and the reader's line.

### Derivation order

1. The node's own declared field (`description` of a role or skill, the dossier's `title`, a
   registry row's `line`), cited `<path>#<field>`.
2. The H1 of the file the node lives in, after its slug or name and the dash, or the first line of
   its module docstring or header comment, cited `<path>:<line>`.
3. The record that introduced it: for a record kind, its row in layer-memory's kind table
   (layer-memory.md:400-480); for a chain build, its README's H1; cited `<path>:<line>`.

A text longer than 120 bytes is cut at the last word boundary before it. A text that only repeats the
node's name is not a purpose and the next source is tried.

### Data model

```toml
[[record-kind]]
name = "deviation"
# … I1's columns …
purpose = { text = "a departure from the design or from a spec, joined by the deviation join", source = "tools/memory-tree/HYGIENE.template.md:630" }

[[record-kind]]
name = "backlog-row"
purpose = { pending = "TOOL-dTotalRecall-28" }
```

The ask id above is illustrative; the pass mints the real one.

### Inventory

`purpose-pending`. Naming cells: `derive_purpose` is asked of the lexicon's `--suggest` under `--as
py.function` at the pass.

### Alternatives rejected

- **A `purpose` file beside each registry.** One fact in two places; the field sits on the row.
- **Derive every purpose at render time.** The owner's PM-5 asks for a review and a consultation,
  and a render-time guess is neither reviewed nor answerable.

## 6. Acceptance criteria

- **AC1** — When `python record_kinds.py --check` runs at the pass tip, every row carries a `purpose`
  table, and the `gen:record-kinds` view shows each `text` or `—` for each `pending`, its header
  counting the pending rows.
  Red when: a row has no purpose and passes, or a pending row renders as empty.
- **AC2** — When `python record_kinds.py new widget --tag record.widget --writer hand --check "memory
  hygiene" --field Serves` runs in the fixture without `--purpose`, it exits 2 and writes nothing; with
  `--purpose "a planted kind"` it writes a row whose `source` is `owner`.
  Red when: a new kind lands without a purpose.
- **AC3** — When `--purpose-review` runs over the fixture, whose registry holds one kind with a
  layer-memory table row, one whose file has an H1 and one with neither, and whose chain registry
  holds a row with a README H1, it prints `derived` for the first two and the chain row, each with a
  `<path>:<line>` source, and `none` for the third.
  Red when: a purpose is derived with no source, or the derivation order is skipped.
- **AC4** — When `--purpose-review --write` runs on that fixture, the registry and chain rows gain the
  derived `text` and `source`, and one ask draft is printed for the registry's namespace listing the
  third kind and what was found; with two `none` nodes in one namespace, still one draft.
  Red when: an ask is drafted per node, or a `none` node is written a purpose.
- **AC5** — When the fixture's policy sets `memory.map-purpose` to `refuse`, `--check` exits 1 naming
  each pending node; to `derive`, the review writes no ask draft; to `ledger`, it writes the
  `purpose-pending` ledger rows; and with the reader refusing, `--check` exits 2 naming
  `memory.map-purpose`.
  Red when: a value reads as `review`, or a refused read passes.
  fixture: the policy reader of TOOL-dGroundRules-2 and the adapter of TOOL-dTotalRecall-8, landed
