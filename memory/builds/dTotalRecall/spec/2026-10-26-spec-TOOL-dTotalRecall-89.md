### The reads

```bash
# run from the repository root; under $SCRATCH, sourced: unit 81 §4's first bash fence, unit 90 §4's s1 fence, then unit 93 §4's has_deviation fence
B=memory/builds/dTotalRecall/build; N='`absorbs` is absent'
cat > "$SCRATCH/s89.txt" <<'STRINGS'
`absorbs` is absent
STRINGS
check_ancestry() {  # record path · pass(83)'s sha or pass_of's red line -> one verdict line
  local a r
  case "$2" in red*) echo "rec $1 ungraded p83 $2"; return 0 ;; esac
  a=$(git log --diff-filter=A --format=%H -1 -- "$1")
  [ -n "$a" ] || { echo "rec $1 at-or-after-p83 untracked"; return 0; }
  git merge-base --is-ancestor "$2" "$a" 2>/dev/null; r=$?
  case $r in
    0) echo "rec $1 at-or-after-p83 $a" ;;
    1) echo "rec $1 before-p83 $a" ;;
    *) echo "rec $1 red ancestry rc=$r" ;;
  esac
}
s1 s1-59 59 '^' 59 "$SCRATCH/s89.txt"
has_deviation --paths "$B" 59 "$N"
has_deviation --paths "$B" 59 "$N" 'pass(59)'
P83=$(pass_of 83); echo "p83 $P83"
has_deviation --paths "$B" 59 | tr -d '\r' | sed -n 's/^rec //p' | while read -r f; do check_ancestry "$f" "$P83"; done
```

any git call. The walk takes every live record of unit 59, so it prints a line for each counted record
and for the roster record, which is its liveness. rev-2's walk read every record of the folder whose
text held both strings, so it walked a population its count did not hold. Its `&&` folded a git error and
an untracked record into the silence that also meant "before unit 83's pass". A record with no adding
commit reads as written at this pass. `tr` drops the carriage return Python prints into a pipe on Windows.
