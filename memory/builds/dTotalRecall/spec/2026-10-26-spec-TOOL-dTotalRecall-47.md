## 1. Goal

The round-1 spec audit of units 36 to 43
(`memory/builds/dTotalRecall/reviews/2026-10-26-review-TOOL-dTotalRecall-37-spec-audit-round1.md`)

which makes the writers emit `Caused-by`, runs at order 17 in parallel with `TOOL-dTotalRecall-21` and

## 2. Scope (IN)

  no cause: no `<path> -` legacy row, a kind that is not a root, and no `Caused-by`. The id is the first
  of the record's `tree_lib.py#read_bindings` row's `ids`, which `tree_lib.py#_expand_ids` already
  returns bare of any `@rev-<n>` pin. It prints each path it wrote and a count, writes nothing else, and

  and left byte-identical. Observed by AC1 and AC3.
  - A record whose Serves line names no id, the `read_bindings` row holding no `ids`.
  - A record that is not `.md`; its comment form is `TOOL-dTotalRecall-51`'s.

## 4. Design

### The selection

The verb calls `check_causes(root)` and keeps the findings whose rule is the absent cause, each finding
naming its record path, rule and target (`TOOL-dTotalRecall-19` §5, observability), so it selects what
the check reds and never a copy of the selection. A record whose cause is present but unresolved is the
check's to report and is never rewritten. The line is placed as `TOOL-dTotalRecall-36` §4 "The head
each writer emits" places it, directly under the Serves line, inside the first `BIND_HEAD_LINES`
unfenced lines that `read_header_edges` reads (`TOOL-dTotalRecall-19` S1). The file's own line ending
is kept. The window is 12 lines at HEAD (PINNED 2026-11-22, `tree_lib.py#BIND_HEAD_LINES`).

No tracked `.md` record has its Serves line on the window's last line today: every one sits on unfenced
line 1, 2, 3, 5, 6 or 7 (DERIVED 2026-11-22, a `python -c` walk of `tree_lib.py#BIND_RE` over the
`.md` members of `tree_lib.py#record_paths` at `ed5a7d523`). S2's window case is a guard, not a cleanup.

### Inventory

`backfill-refusals` in `tools/memory-tree/record_causes.py`. Naming cell: `py.function`, where
`python tools/lexicon/lexicon.py --suggest write_missing_causes --as py.function` answers OK at

## 5. Production-readiness checklist

- security — the verb writes one line into records already tracked; it touches no other file.
- perf / scale — one `check_causes` selection and one write per selected record.
- error / empty / loading states — an empty selection prints `0 backfilled` and exits 0; a record S2
  refuses is listed and leaves the exit 0, since `--check` still names it.
- observability — each written path and each `not backfilled` reason is printed.
- risks — the first served unit may be a weaker cause than the true one; the legacy reading assumes
  the same (`TOOL-dTotalRecall-19` S8).
- testing — AC1 to AC3 by the pass; the arm of §7 at the close.
- migration — S3's backfill of this run's own records.
- user docs — none under `help/`: no page covers record heads.
