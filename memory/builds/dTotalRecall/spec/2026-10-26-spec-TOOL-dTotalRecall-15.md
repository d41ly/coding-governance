## 1. Goal

Prove the level-0 map complete and true, three ways. Every part on disk is a node in the index,
every node in the index is on the map as a line or inside a count, and every line resolves to a
node. The map's other checks of the project map's `[checks]` table that this build owns run beside
it, as the `map` leg pack, so a map that loses a node, invents a relation or grows a date reds the
bar.

## 4. Design

### The three joins

```
disk  --compute_coverage-->  index nodes   unclaimed: on disk, no node   stale_claims: node, not on disk
index --every node-------->  map           a line, or inside its nsline count
map   --every line-------->  index         its key is a node
```

`compute_coverage(inventories, owners, baseline)` (`tools/memory-tree/coverage_join.py#compute_coverage`)
takes `inventories` as `{ns: [disk keys]}`, `owners` as `{"index": {ns: (node keys)}}` and `baseline` as
`{}`. Its four asserts reduce to the two this check needs, since an empty baseline makes the other two
vacuous. Those two are named in the summary, not counted as passes.

### The census

| ns | route, its own code | key |
|---|---|---|
| `kit` | `git ls-files` of `<tool root>/*/kit.toml` and `<tool root>/**/*.kit.toml` | path, against each `kit` node's row path |
| `leg` | `json.load` of `<tool root>/gate-legs.json`, each row's `tag` | tag |
| `policy` | `tomllib` of `<tool root>/policy/catalogue.toml`, each `[[key]]` name of literal segments, `policy.<name>` | tag |
| `class` | each `<MEMORY_ROOT>/gotchas/*.md` whose front matter, read line by line between its `---` fences, holds `kind: class`, `class.<name>` | tag |
| `record` | `tomllib` of this kit's `record-kinds.toml`, each `[[record-kind]]` row's `tag` | tag |

At HEAD the populations are 30 descriptors, 227 leg rows, 266 literal keys of 274, and 51 record-kind rows (DERIVED at `9d7afdc6a`).
Of 178 gotcha files, 174 say `kind: class` (DERIVED at `9d7afdc6a`, `grep -l '^kind: class$'`).
`class` and `record` join once unit 9 registers them. A route reads the file the extractor reads, so
it does not catch a source both misread the same way; it catches an extractor whose filter drifts
from its source, and a part the extractor never reaches, which is the instrument's rule.

### Alternatives rejected

- **The checks inside the hygiene leg.** A check inside an existing leg is cheaper
  (`memory/gotchas/a-new-leg-trips-a-growing-set-of-meta-gates.md`), but the clause names a `map`
  leg pack, which needs legs carrying the key.
- **Census through the extractors.** A census read through the code that writes the index can only
  agree with it; the instrument's rule is a route that shares nothing with the builder.
- **A second coverage join.** `compute_coverage` already holds both directions, and
  PLAY-dOrderedCharter-19 moved it to the core for this reason; `tag_index.py#check_namespace_joins`
  joins citations through it the same way.

## 5. Production-readiness checklist

  default, `with-hooks-report`, it reds no guarded leg; the unguarded `map` leg is red under neither.

- migration — none.
- user docs — `help/project-map.md` (unit 14's) gains a paragraph naming the `map` pack and its
  checks.

## 6. Acceptance criteria

- **AC1** — When `python map_checks.py` runs on gov's tree at the pass tip, it exits 0, its summary
  names every check of S2 to S10, and `census` names every registered namespace with no route.
  Red when: a check is skipped silently, or the run passes with no index read.
- **AC2** — When `python map_checks.py --fixture --plant newkit` runs, a `kit.toml` planted under
  `tools/newkit/` holding no `id`, so no kit node sits at it, it exits 1 with a `complete` line naming that path as
  unclaimed.
  Red when: the census reads kits through the index, so the planted descriptor is never seen.
- **AC3** — When `--plant unlisted-node` (an index node on no line and in no count) and
  `--plant ghost-line` (a line naming `feature.ghost`) run, each exits 1 with a `complete` line
  naming the node.
  Red when: either direction of the index-to-map join is not read.
- **AC4** — When `--plant ghost-rel` runs, a relation key whose target is no node, it exits 1 with
