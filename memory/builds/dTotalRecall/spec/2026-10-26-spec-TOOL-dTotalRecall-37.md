## 4. Design

### The registration

```gitattributes
tools/workflows/tier2-review.js linguist-generated
tools/workflows/unattended-build.js linguist-generated
tools/workflows/drift-audit-code.js linguist-generated
tools/workflows/drift-audit-state.js linguist-generated
```

Explicit paths rather than a glob, because the render set is four named outputs and a glob over a
kit's directory is the defect. The parity arm is what keeps the list from drifting when a fifth render
lands: its row in `kit.toml` makes the arm red until the line is added.

### The arm's two sets, at base

| Set | Members at base `fbe06249` |
|---|---|
| non-Markdown render outputs | the four `.js` renders above; every other rendered row's `to` is a `.md` (DERIVED, `grep -A2 'role = "rendered"' tools/*/kit.toml`) |
| `linguist-generated` under the tool root | none (`git grep -c linguist fbe06249 -- .gitattributes` printed nothing, PINNED 2026-11-25) |

At the pass base no line carries the attribute, so the arm names the four renders as `rendered but not
linguist-generated`, which is its red case on the real tree; AC3 stages the glob for the other side.

### The value the arm reads

The arm counts `set` alone, the value `TOOL-dTotalRecall-8`'s Bounds row reads, so the two never
disagree about a path: a `linguist-generated=true` line reads as unmarked to both, and the arm reds
the render it covers. An absent `.gitattributes` gives an empty attribute set, and the arm reds every
render; a descriptor that does not parse is already `read_descriptors`' refusal.

### Inventory

Minted: `check_generated_attributes`, `derive_home_ctx` and `read_attr_population` in
`tools/govkit/govkit.py`; `check_generated_attribute_arms(gcopy, run_selfcheck)` in
`tools/govkit/selftest.py`. Naming cells: `python tools/lexicon/lexicon.py --suggest <name> --as
py.function` answered OK for each on 2026-11-22.

### Files touched (estimate)

- `.gitattributes`
- `tools/govkit/govkit.py`
- `tools/govkit/selftest.py`
- `memory/map/generated/` (regenerated by `python tools/codebase-map/gen_map.py --write`)

### Alternatives rejected

- **Derive the attribute lines from the render rows with a generator.** A third generated artifact for
  four lines; the parity arm gives the same guarantee and leaves `.gitattributes` authored.
- **Exclude rendered files by reading the render rows inside `code_record.py`.** The record ships in
  the playbook-render kit to adopters whose tree it grades, and its Bounds rule is the attribute an
  adopter can set; the descriptor read belongs to the deployer, which already parses them.
