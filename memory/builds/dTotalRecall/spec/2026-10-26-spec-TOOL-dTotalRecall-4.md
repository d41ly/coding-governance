## 1. Goal

A build README's front matter becomes a declared schema: every key it may carry is named once in
`FRONT_MATTER_KEYS`, an unknown key is refused, and `node`, `roster` and `streams` are derived and no
longer typed. The README gains a generated region that routes a reader to each record by purpose; an
agent's root is its work order under `builds.agent-root`; and a design-only build's `ids:` defines its
units, so the bindings check stops reporting them (gap-mem-05, gap-mem-40; `layer-memory.md:509-529`).
Today `parse_front_matter` accepts any key, so a misspelled `parent:` is silently dropped, and the
README routes only to specs.

## 4. Design

### The schema

```python
FRONT_MATTER_KEYS = {
    # key:            (role,                   type,        required)
    "slug":           ("authored",             "slug",      True),
    "opened":         ("authored",             "date",      True),
    "ids":            ("authored",             "ids",       True),
    "parents":        ("authored",             "slugs",     False),   # alias of depends-on (unit 6)
    "depends-on":     ("authored",             "slugs",     False),
    "patches":        ("authored",             "ids",       False),
    "amends":         ("authored",             "ids",       False),
    "supersedes":     ("authored",             "slugs",     False),
    "implements":     ("authored",             "tags",      False),
    "may":            ("authored",             "ids",       False),
    "spec-audit":     ("authored",             "date",      False),
    "authorized-by":  ("authored",             "word",      False),
    "asks":           ("authored",             "id-ranges", False),
    "slug-grammar":   ("authored",             "grammar",   False),
    "status":         ("authored-until-spec",  "status",    False),
    "node":           ("derived",              "word",      False),
    "roster":         ("derived",              "families",  False),
    "streams":        ("derived",              "streams",   False),
}
```

| Type | Admits |
|---|---|
| `slug` | the folder name, compared as today (`:444-446`) |
| `date` | an ISO calendar date, four-digit year first, compared as today for `opened` (`:447`) |
| `ids`, `id-ranges` | whitespace-separated ids, a range `<id>..<n>` for `id-ranges`, each through `_id_alternation(conf)` |
| `slugs` | whitespace-separated tokens, each matching unit 5's `BUILD_SLUG_RE` |
| `tags` | whitespace-separated tokens holding no space, comma or bracket (PLAY-dOrderedCharter-24 S2's target rule) |
| `word` | one token of `[A-Za-z0-9._-]+` |
| `grammar` | a value `parse_slug_grammar` reads (TOOL-dTotalRecall-5) |
| `status`, `families`, `streams` | `STATUS_TOKENS`, `FAMILIES`, `DISCIPLINES` as today (`:1164-1169`) |

The census at `fb872a37e`: every one of 193 READMEs carries `slug`, `node`, `opened`, `streams`,
`roster` and `ids`; `authorized-by` 65, `parents` 33, `spec-audit` 26, `status` 22, `may` 22, `asks` 2,
and no other key (PINNED, measured 2026-10-26 with an awk over every tracked README's front matter;
AC1 re-derives it).

### The legacy population

A registration `build-readme.typed-derived` in TOOL-dWitnessedBar-13's ledger, seeded once by
`seed_population` (TOOL-dWitnessedBar-15 S1, I22) at the pass's SHA, holding each tracked README path
that types `node`, `roster` or `streams`. Its seed argv is `gen_build_index.py
--print-typed-derived`, which prints those paths one per line. Membership is read by README path. A
README written after the seed, the scaffold's included, is outside it. Until TOOL-dWitnessedBar-15
lands, the build run re-grounds on it (§8 F5).

### The routing region

`render_routes(build)` renders, between `<!-- gen:build-routes -->` and its close, one table:

| Purpose | Read |
|---|---|
| run state | `RUN.md`, when tracked |
| the units | the units table above (a pointer, never a second list) |
| briefs | each `prompts/` record |
| reviews | each `reviews/` record, with its `## Verdict:` token |
| `<kind>`, one row per member of `TYPED_RECORD_KINDS` | each `build/` record whose `**Serves:**` kind is that member |
| research | each `build/` record whose kind is `research` |
| journals | each `build/` record whose kind is `journal` |
| open asks | `BACKLOG.md`, with its count of OPEN asks from the backlog fold |
| card | `refs/gov/builds/<slug>/card`, the ref's name (TOOL-dPlacedRequest-2) |

The typed rows are read from `TYPED_RECORD_KINDS` (`tools/memory-tree/tree_lib.py`,
PLAY-dOrderedCharter-42 S1), never a list here: `deviation` is one member, and the card snapshot,
probe, probe-trigger, gate-health, flake and widen records a parent serves as its own kind
(TOOL-dPlacedRequest-2 S8, TOOL-dPlacedRequest-7 S6, TOOL-dWitnessedBar-51 S7, TOOL-dWitnessedBar-14 S5)
route under their kind's row once each parent adds its kind to the tuple. A row renders only when
its purpose has a member, except `card`. A purpose with more than three records names its three
newest by filename date and then `and <n> more under <folder>/`, so the region stays within the
per-line entry cap at any build's size. Kinds are read from the bindings
`plan()` already reads once (`binds_all`), never re-parsed. The card row names the ref and never reads
it, so the region's bytes are the same on every node.

## 5. Production-readiness checklist

- security — the parser is the write boundary for README front matter: an unknown key and a
  malformed value refuse before any render, and no value reaches a regex unvalidated.
- perf / scale — one dict lookup per key; the routing region reads the bindings `plan()` already
  holds.
- error / empty / loading states — an unknown key names the key, the line and the declared set; an
  empty purpose renders no row; the card row never reads a ref, so it cannot fail.
- observability — `--print-front-matter <slug>` prints the derived keys; the disagreement lines of S4
  print on every `--write` and `--check`.
- risks — a reader of the typed keys outside the tree (an adopter's own script) keeps reading the
  legacy README's line; a new README carries none, which `--print-front-matter` answers.
- testing — AC1 to AC8 by a pass; the arms of §7 at the close.
- migration — none for records, as §4 says.
- user docs — none under `help/`: no page describes the README front matter.
