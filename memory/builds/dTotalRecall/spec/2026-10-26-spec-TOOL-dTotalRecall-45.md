### The roots

The parser binds its slug class from `root`, None the tree its module lives in, and its families
from `alt`, else from `root`'s conf (`tools/memory-tree/id_grammar.py#parse_id_parts`). Each reader
passes what its id was validated under, as unit 38 S1 rules: root None where the validating regex
bound the default tree's slug class, and a family class as `alt` where that regex already narrowed
the family. So no reader reads a conf, a policy value or a tree its validator did not, and the
parser's slug grammar is the cached one the validator built first (`tools/memory-tree/id_grammar.py#derive_slug_grammar`).

- `derive_names`: `ID_RE` is bound through `_SLUG_GRAMMAR.SlugPattern` with no root
  (`tools/branch-reconcile/branch_reconcile.py#derive_slug_pattern`), and its family is any
  `[A-Z][A-Z0-9]{1,9}`, so `alt` is that class, `FAMILY_CLASS`. Without it an id of a family the tree
  does not declare, which `ID_RE` matches today, would add no slug. Both calls of `derive_names` sit
  in `tools/branch-reconcile/branch_reconcile.py#derive_coverage`, and no suite calls it (`git grep
  -n "derive_names" -- tools` lists the two and the definition, DERIVED 2026-11-22). A root read from
  `inv` would read the conf of each branch-reconcile selftest fixture repository, and those carry
  none (`git grep -n "memory-tree.conf" -- tools/branch-reconcile/selftest.py` prints nothing,
  DERIVED 2026-11-22).
- `render_spec_skeleton` holds no root, and `cmd_new_spec` already holds the slug. The self-test's
  fixture id `ARCH-aFix-3` names a family this repository does not declare (`.memory-tree.conf:42`),
  so a parse inside the function would raise on every self-test call (§8 F2).
- `scan_records`: its row regex binds the default tree's slug class (`read_slug_class()` in
  `tools/memory-tree/row_grammar.py#id_pattern`) and the conf's declared families, so the call
  passes None and `backlog.ANY_FAMILY`, the class unit 38 landed for an id already narrowed under a
  caller's families (`tools/memory-tree/backlog.py#ANY_FAMILY`). Its callers `check_relations`,
  `cmd_measure_relations` and `check_content` are unchanged. `backlog` is imported late, because a
  module-level import each way is a cycle one edit away (`read_backlog_mode`'s docstring).
  `scan_engine_imports` bans only the two engines `tools/memory-tree/row_grammar.py#ENGINE_OWNERS`
  names, and `backlog` is neither.
- `derive_run_kind`: its asks come from the same row regex over the landed revision's conf, so the
  call passes None and `backlog.ANY_FAMILY`, as unit 38's memory-tree readers do
  (`tools/memory-tree/gen_build_index.py#build_grade_row`).
