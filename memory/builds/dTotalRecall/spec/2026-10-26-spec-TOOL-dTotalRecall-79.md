## 4. Design

### The input

`$SWEEP` is the fenced block unit 78's AC1 answer holds, which takes over the lines unit 76's sweep
printed and adds the units that sweep did not read. It holds no `live` line; one found in it is left out.
`$LIVE` is a `sep rc=0` line, then the `live` lines unit 77's AC1 answer quotes. Every sweep prints
the same two line shapes, `<label>[ <sha>] rc=<n>` and `<label>[ <sha>] MANIFEST check <n> FAILED`, the
checker's own text (`skills/session-kickoff/manifest-check.sh@aec378661:2396`). A `population` line is
read by no rule of the script.

### The derivation

```bash
# run from the repository root, from a script file under $SCRATCH; SCRATCH is an absolute C:/ path
cat "$SWEEP" "$LIVE" > "$SCRATCH/spans-in.txt"
python - "$SCRATCH/spans-in.txt" <<'SPANS'
import re, subprocess, sys
LOG = ['git', 'rev-list', '--topo-order', '--reverse', '462d20f3..HEAD']
done = subprocess.run(LOG, capture_output=True, encoding='utf-8', check=True).stdout.split()
pos = {sha: i for i, sha in enumerate(done)}
rc, at, checks = {}, {}, {}
for raw in open(sys.argv[1], encoding='utf-8'):
    line = raw.strip()
    m = re.match(r'^(\S+)(?: ([0-9a-f]{40}))? rc=(\d+)$', line)
    if m:
        rc[m.group(1)] = int(m.group(3)); at[m.group(1)] = pos.get(m.group(2), len(done)); continue
    m = re.match(r'^(\S+)(?: [0-9a-f]{40})? MANIFEST check (\d+) FAILED', line)
    if m:
        checks.setdefault(m.group(1), set()).add(m.group(2)); continue
    m = re.match(r'^(\S+) red ', line)
    if m:
        rc.setdefault(m.group(1), None); at.setdefault(m.group(1), len(done))
spans, cur = [], None
for u in sorted(rc, key=at.get):   # stable: a label with no sha keeps the input's order, last
    if rc[u] is None:
        print('unresolved', u)
    elif rc[u]:
        cur = cur or [u, u, set()]
        cur[1] = u
        cur[2] |= checks.get(u, set())
    elif cur:
        spans.append(cur + [u]); cur = None
if cur:
    spans.append(cur + [None])
for first, last, cks, closer in spans:
    print('span', first, last, 'checks', ','.join(sorted(cks)) or 'none-printed', 'closed-by', closer or 'OPEN')
print('spans', len(spans))
SPANS
```

Run once with `$LIVE` and once over `$SWEEP` alone. The first run's last span line must be the staged
red, `span live live`. A real span it shows as `closed-by sep` is one the second run shows as `OPEN`.
The second run's spans are the leg's history.

The order is the history's and not the build order's, because a closer is a later commit. The two
orders differ: at step 28 unit 62's pass precedes unit 52's, which re-stamped, and at step 32 unit 68's
precedes unit 66's (DERIVED 2026-11-24 at `aec378661`, unit 76 §4's pass listing over the README's
`gen:build-order`). In build order a red at unit 62 would be closed by unit 53.

PINNED, measured 2026-11-24 at `aec378661` with this script. The sample held units 66 and 68 red on
check 5 and unit 69 green, unit 70 red on check 5, unit 75 with no pass commit, and a `population` line,
each read unit at its real pass sha. With `$LIVE` the script printed `unresolved 75`,
`span 68 66 checks 5 closed-by 69`, `span 70 70 checks 5 closed-by sep`,
`span live live checks 9 closed-by OPEN` and `spans 3`. Over the sample alone it printed
`unresolved 75`, the first span, `span 70 70 checks 5 closed-by OPEN` and `spans 2`. With the `live`
lines and no `sep` line it printed `span 70 live checks 5,9 closed-by OPEN`, the staged red folded into
a real span, which is why `sep` is there.

### The comparison's rule

Unit 76's AC13 lists, for check 5 and for check 9, each span of pass commits that printed it and the
pass commit that closed it. A derived span agrees with that list where, for each of those two checks it
names, AC13 lists a span of it inside the derived one, and where the latest closer AC13 names for them
is the derived closer. A derived span that also names a third check is compared without its closer. A
derived span naming neither check is outside AC13: it is listed, it is no departure, and S4 reads
whether the base still carries it. An AC13 span inside no derived span is a difference. Unit 76's sweep
ends at its own base, so units its block does not read are outside AC13 too: a derived span holding only
such units is no difference, and neither is an AC13 span with no closer whose derived closer is one.

### Alternatives rejected

- **Sweep again here.** Unit 78's block reads every pass commit of the steps below 36 with the checker's
  own text. A second run would read the same shas and print the same lines (`doc.build-method#m3-forks-the-decision-rule-and-the-limit-of-your-authority`).
- **Take the base verdict from the pass legs of the preceding pass.** Their record is replaced at each
  run and names no check (`tools/run-gates/pass-legs.sh`), and the remedy is chosen by the check.
- **Liveness at a pass commit predicted red.** Unit 69 found the stamp standing where the plan predicted
  a span, so such a commit reads green with a correct sweep. The staged red is red by construction.
- **Spans keyed on checks 5 and 9 only.** The leg is red on any failing check, and a span the
  derivation narrowed would hide one.
- **Leave a red base to the close.** A pass whose check is red is not followed by another
  (BUILD-METHOD M6), and units 80, 85, 86 and 90 follow at this order.
