## 1. Goal

A record's only typed link today is its Serves line (gap-mem-36): 10,534 tracked Markdown records (PINNED
2026-11-22, the `.md` members of `tree_lib.py#record_paths` over `git ls-files` at `e1ae60af8`), `Caused-by`
only as a field of the typed kinds whose `build_records.py#KINDS` entry requires it, no `Made-by` and no
`**Edges:**` line in any record, and no walk that finds a record nothing reaches. P35 says every record
names its cause and P34 that every relation is a typed edge on its own line. This unit makes the `record`
door write each record's header (Serves, Made-by, Caused-by) and each section's edge line, refuses a
missing cause on a kind that is not a root, and adds the causes check and the orphan check, each over a
legacy population `test.seed` seeds with today's records, so a planted causeless record and a planted
orphan are red and today's tree is green. `memory.legacy-anchors` says how a legacy record is read.

## 4. Design

### The header

```markdown
# <title>

**Serves:** log TOOL-dTotalRecall-19
**Made-by:** owner
**Caused-by:** TOOL-dTotalRecall-19
```

A typed kind writes the last two as `- **Made-by:** …` and `- **Caused-by:** …` among its fields, because
`build_records.py#FIELD` is the factory's one field grammar and a typed record's fields run past
`BIND_HEAD_LINES` (a deviation record's `Caused-by` is its last field). `read_header_edges` reads both
forms, so the 2,743 landed records carrying `- **Caused-by:**` (DERIVED 2026-11-22, `git grep -l` of
`^- \*\*Caused-by:\*\*` over the three record folders) read without a rewrite. `Caused-by` names one
target, the value shape `build_records.py#read_record` already refuses beyond. Under a lease the
`Made-by` value is `lease-<slug>` (S4).

### The section edge line

Under a heading, the PLAY-dOrderedCharter-24 S2 grammar, one line per type:

```markdown
## 4. Design

**Edges:** implements=feature.record-door
**Edges:** amends=TOOL-dTotalRecall-2
```

The door places each line on the line after the heading, in the order given, and reads the rendered
record back with `parse_edge_lines` before it writes, so a line the parser would refuse is never written.

### The walk

| Node | Reached when |
|---|---|
| build `<slug>` | its `README.md` is tracked at the graded tree, or `refs/gov/claims/<slug>` exists |
| unit id `<FAMILY>-<slug>-<seq>` | its build is reached and the README's `ids:` names it; for a claim-only build, the slug matches |
| record (new) | its `Caused-by` target is reached |
| record (legacy) | under `derived` or `retag`, one of its Serves units is reached; under `none`, always |

The walk is a fixed point over these rules from the roots outward, so a cycle of two new records each
naming the other is reached by neither rule and both are orphans. A legacy record is never red; a new
record caused by an unreached legacy record is.
