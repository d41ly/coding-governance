## 1. Goal

A record's only typed link today is its Serves line (gap-mem-36): 4,244 tracked records, `Caused-by`
only on deviation records (`tools/memory-tree/deviation_join.py:147`), no `Made-by` and no edge line
anywhere, and no walk that finds a record nothing reaches. P35 says every record names its cause and
P34 that every relation is a typed edge on its own line. This unit makes the `record` door write each
record's header (Serves, Made-by, Caused-by) and each section's edge line, refuses a missing cause on a
kind that is not a root, and adds the causes check and the orphan check, each over a legacy population
`test.seed` seeds with today's records, so a planted causeless record and a planted orphan are red and
today's tree is green. `memory.legacy-anchors` says how a legacy record is read.

## 4. Design

### The header

```markdown
# <title>

**Serves:** log TOOL-dTotalRecall-19
**Made-by:** owner
**Caused-by:** TOOL-dTotalRecall-19
```

A typed factory kind writes the last two as `- **Made-by:** …` and `- **Caused-by:** …` among its fields,
because `deviation_join.FIELD` (`:145`) is the factory's one field grammar, and a typed record's fields
run past `BIND_HEAD_LINES` (a deviation record's `Caused-by` is its last field). `read_header_edges` reads
both forms, so the 666 landed records carrying `- **Caused-by:**` read without a rewrite. `Caused-by` names one
target, the value shape `deviation_join` already refuses beyond (`:247`).

### The section edge line

Under a heading, the PLAY-dOrderedCharter-24 S2 grammar, one line per type:

```markdown
## 4. Design

**Edges:** implements=feature.record-door
**Edges:** amends=TOOL-dTotalRecall-2
```

The door places each line on the line after the heading, in the order given, and reads the rendered
record back with `parse_edge_lines` before it writes, so a line the parser would refuse is never written.

### The walk

| Node | Reached when |
|---|---|
| build `<slug>` | its `README.md` is tracked at the graded tree, or `refs/gov/claims/<slug>` exists |
| unit id `<FAMILY>-<slug>-<seq>` | its build is reached and the README's `ids:` names it; for a claim-only build, the slug matches |
| record (new) | its `Caused-by` target is reached |
| record (legacy) | under `derived` or `retag`, one of its Serves units is reached; under `none`, always |

The walk is a fixed point over these rules from the roots outward, so a cycle of two new records each
naming the other is reached by neither rule and both are orphans. A legacy record is never red; a new
record caused by an unreached legacy record is.

### The population

`--measure` prints the rows `seed_population` writes, so the seed and the check read one enumeration:

```
# ledger · legacy-records · key record path,section · direction shrink-only · drain key
memory/builds/dTotalRecall/build/2026-10-25-build-TOOL-dTotalRecall-1-reuse-scout-a.md	-	1	462d20f3	seeded
```

4,244 record rows at `fb872a37` (PINNED, measured 2026-10-26 with `git ls-files` over the three record
folders; AC6 re-derives it), plus one row per untagged heading under `derived`. A row drains when its
record gains a resolving `Caused-by` or is retagged; `shrink-only` refuses a row the base lacked, so a new
record can never be laundered into the population.

  kind then lands its own `root = true` row and the stand-in rows drain by data.
