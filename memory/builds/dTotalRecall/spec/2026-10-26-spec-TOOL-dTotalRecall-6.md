## 1. Goal

A build README may declare five typed relations, `depends-on`, `patches`, `amends`, `supersedes` and
`implements`, beside today's `parents:`, which stays as an alias of `depends-on`. Each is inverted
into its target's README, checked both ways, rendered as the relation graph, and `depends-on` may form
no cycle; a target on another node's unlanded branch is pending through the card and lease refs, and
a target found nowhere is pending, never red, until its build lands or is withdrawn (gap-mem-07;
`layer-memory.md:561-578`). Today `parents:` is the one relation, 33 READMEs use it, nothing types a
patch, an amendment or a supersession, no cycle is checked, and a parent that is not a folder in this
tree is refused outright (`tools/memory-tree/gen_build_index.py:2621-2623`).

## 4. Design

### The registration

```toml
# tools/playbook/edges.toml — the README site, beside [[trailer]]
[[front-matter]]
key = "depends-on"
type = "after"
target = "slug"

[[front-matter]]
key = "parents"            # the alias, read exactly as depends-on
type = "after"
target = "slug"
```

| `key` | `type` | `target` |
|---|---|---|
| `depends-on` | `after` | `slug` |
| `parents` | `after` | `slug` |
| `patches` | `patches` | `unit-id` |
| `amends` | `amends` | `unit-id` |
| `supersedes` | `supersedes` | `slug` |
| `implements` | `implements` | `tag` |

`depends-on` is the README-site spelling of the `after` type, which memory-plan `[edges]` spells for
build-to-build order (`memory-plan.md:184`); the type set stays closed. The rows widened so the
README site's sources and targets sit inside them: `implements.from` and `amends.from` gain `build`,
since a README is a build declaring; `patches.to` and `amends.to` gain `family-id`, since their
targets are unit ids, the native class PLAY-dOrderedCharter-28 S2 registers. `implements.to` already
holds `feature`, where a reuse entry lives. gen_build_index reads the file by path through its kit's
`resolve_kit_dir` copy; with no playbook kit, `parents` is read as today and any other relation key
refuses, naming `edges.toml`.

### Target states

| Target | `resolved` when | `red` when | otherwise |
|---|---|---|---|
| a slug | a tracked README `<memory-root>/builds/<slug>/README.md` exists | the lease ref's tip message carries `status: withdrawn` | `pending` |
| a unit id | a spec H1 defines it, or its build is design-only and lists it (TOOL-dTotalRecall-4's `defined_unit_ids`) | its build is in this tree with derived status `CLOSED` or `WONTDO` and does not define it, or its lease is withdrawn | `pending` |
| a tag | the index's tag table holds it | never | `pending` |

A `pending` target names the first of these that exists in this clone, else `found nowhere`: the card
`refs/gov/builds/<slug>/card` and the lease `refs/gov/leases/<slug>/build`, each matched by
`git for-each-ref` under `refs/gov/` so a cache copy the reader verbs keep counts too. The lease's tip
message is read with `git log -1 --format=%B`, its `status:` key the one TOOL-dPlacedRequest-1 S5
writes. The index is opened read-only with `sqlite3` at the path `tools/lib/common_dir.py` resolves;
no index file reads every tag as `pending`, said once.

### Inventory

`check_relation_cycles`, `resolve_relation_target`; the flag `--print-relations`. Naming cells:
the four functions are asked of the lexicon's `--suggest` under `--as py.function` at the pass.

### Migration

None. The 33 `parents:` READMEs read as `depends-on` and render byte-identically; no README carries
another relation key today (PINNED, measured 2026-10-26 at `fb872a37e`).

### Files touched (estimate)

### Alternatives rejected

- **A thirteenth type `depends-on`.** memory-plan already spells build-to-build order `after`; a
  second type for one meaning is two answers in the closed set.
- **Resolve a pending target with `git ls-remote` in the check.** It puts a network read in the bar
  and makes the verdict depend on the remote's reachability; the card and lease machinery already
  fetch the refs this reads.
- **Render the pending ref in the README.** The region's bytes would then differ between nodes with
  different ref copies, and `--check` would red on whichever node fetched last.

## 5. Production-readiness checklist

- security — no write path; every target is typed by its address form before it reaches a lookup, and
  a ref name is built only from a slug `BUILD_SLUG_RE` admits.
- perf / scale — one `for-each-ref` per unresolved target, of which today's tree has none; the cycle
  walk is linear in edges.
- error / empty / loading states — pending targets print and pass; red ones name the target, its state
  and the ref or status that made it red; no index reads tags as pending, said once.
- observability — `--print-relations` prints every edge with its state.
- risks — a withdrawn lease that is never fetched leaves its target pending instead of red; that is
  the clause's "until … withdrawn", read at the clone's knowledge.
- testing — AC1 to AC9 by a pass; the arm of §7 at the close.
- migration — none, as §4 says.
- user docs — none under `help/`: no page describes README relations.
