## 1. Goal

A build README may declare five typed relations, `depends-on`, `patches`, `amends`, `supersedes` and
`implements`, beside today's `parents:`, which stays as an alias of `depends-on`. Each is inverted
into its target's README, checked both ways, rendered as the relation graph, and `depends-on` may form
no cycle; a target on another node's unlanded branch is pending through the card and lease refs, and
a target found nowhere is pending, never red, until its build lands or is withdrawn (gap-mem-07;
`layer-memory.md:561-578`). Today `parents:` is the one relation, and 33 READMEs use it (PINNED
2026-11-22 at `94e17798f`, `git ls-files 'memory/builds/*/README.md' | xargs grep -l '^parents:' | wc -l`).
Nothing types a patch, an amendment or a supersession, no cycle is checked, and a parent that is not
a folder in this tree is refused outright (`tools/memory-tree/gen_build_index.py#plan`).

## 4. Design

### The registration

```toml
# tools/playbook/edges.toml — the README site, beside [[trailer]]
[[front-matter]]
key = "depends-on"
type = "after"
target = "slug"

[[front-matter]]
key = "parents"            # the alias, read exactly as depends-on
type = "after"
target = "slug"
```

| `key` | `type` | `target` |
|---|---|---|
| `depends-on` | `after` | `slug` |
| `parents` | `after` | `slug` |
| `patches` | `patches` | `unit-id` |
| `amends` | `amends` | `unit-id` |
| `supersedes` | `supersedes` | `slug` |
| `implements` | `implements` | `tag` |

`depends-on` is the README-site spelling of the `after` type, which memory-plan `[edges]` spells for
build-to-build order (`memory-plan.md:184`); the type set stays closed. The rows widened so the
README site's sources and targets sit inside them: `implements.from`, `amends.from` and
`supersedes.from` become `["any", "build"]`, since a README is a build declaring and `any` holds every
registered namespace and native id, which `build` is neither (the file's header); `patches.to` becomes
`["build", "item", "family-id"]`, since its README targets are unit ids, the native class
`tools/playbook/namespaces.toml` registers. `implements.to` already holds `feature`, where a reuse
entry lives. With no playbook kit, `read_relation_rows()` returns `None`, `parse_relations` reads
`parents` as today, and any other relation key refuses, naming `edges.toml`.

### Target states

| Target | `resolved` when | `red` when | otherwise |
|---|---|---|---|
| a slug | a tracked README `<memory-root>/builds/<slug>/README.md` exists | a lease copy's tip message carries `status: withdrawn` | `pending` |
| a unit id | TOOL-dTotalRecall-4's `derive_defined_ids(root, tracked, conf)` holds it: a spec H1 defines it, or its build is design-only and lists it | its build is in this tree with a derived status in `TERMINAL` (`tools/memory-tree/tree_lib.py#TERMINAL`, `CLOSED` and `WONTDO`) and does not define it, or its build's lease is withdrawn | `pending` |
| a tag | `tools/playbook/edge_grammar.py#resolve_edge` answers `resolved` | never | `pending`, `found nowhere` |

A `pending` slug or unit-id target names the first of these that exists in this clone, else
`found nowhere`: the card `refs/gov/builds/<slug>/card`, its cache `refs/gov/remote/builds/<slug>/card`
(the fetch in `tools/unattended/unattended.sh#write_card_ref`), the lease
`refs/gov/leases/<slug>/build` and its cache `refs/gov/remote/leases/<slug>/build`
(`tools/unattended/unattended.sh#LEASE_CACHE`). `read_build_refs(root, slug)` reads the four with one
`git for-each-ref`, and each lease copy's tip message with `git log -1 --format=%B`; its `status:` key
is the one TOOL-dPlacedRequest-1 S5 writes, whose words `tools/unattended/unattended.sh#read_claims`
admits. Either copy carrying `withdrawn` is red: a terminal status, which the claim's lease route
refuses whatever `leases` says (`tools/loop/claim.py#derive_claim_route`). A ref name is built only
from a slug `BUILD_SLUG_RE` admitted.

A tag's state is read by `--print-relations` alone, since a tag is never red and `plan()` needs no
state it cannot red on: `build_resolve_context(root, <kit>/namespaces.toml)` once per run, then
`resolve_edge(tag, ctx)`, imported from the kit directory `read_relation_rows` found (§8 F8). Every
answer but `resolved`, its `red` ("resolves to no row of the tag index") and `unarmed` among them, reads
`pending`.

### The render

`render_edges` keeps its two lines for `after`, `- **Parent builds:**` and `- **Child builds:**`, and
then writes, in the `[[front-matter]]` rows' order, a line `- **<type>:** <targets>` per other type the
build declares and a line `- **<inverse>:** <sources>` per inverse it receives, each list sorted. A slug

### Alternatives rejected

- **A thirteenth type `depends-on`.** memory-plan already spells build-to-build order `after`; a
  second type for one meaning is two answers in the closed set.
- **Resolve a pending target with `git ls-remote` in the check.** It puts a network read in the bar
  and makes the verdict depend on the remote's reachability; the card and lease machinery already
  fetch the refs this reads.
- **Render the pending ref in the README.** The region's bytes would then differ between nodes with
  different ref copies, and `--check` would red on whichever node fetched last.
- **Open the tag index with `sqlite3` from `gen_build_index`.** A second reader of the index's schema,
  which `tools/playbook/tag_index.py#derive_index_path` names per `INDEX_SCHEMA` and whose reads join
  temp tables `load_view` fills, and a copy of `tools/lib/common_dir.py`'s block (§8 F8).
- **Leave the loop's readers on `parents:`.** A README spelling `depends-on:` would then be invisible to
  the parent-withdrawal route, the patch draw's origin and the position's `blocked` answer (§8 F7).
