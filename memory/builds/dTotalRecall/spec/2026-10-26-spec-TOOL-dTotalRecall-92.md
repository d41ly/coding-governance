## 4. Design

### How the batch builds

One pass, after every unit of a lower step is terminal, in this order:

1. The main loop's `p79` read, and S9's second sweep where one is owed, before this pass is
   dispatched. Their output is in the build brief.
2. The read-only items: S1 to S3, S6, S7, S13, S16, S18 to S21 and S24's scan, then S4 and S17 over unit
   78's block, and the tip scan at this pass's base.
3. The tree items: S11's restore, S12's README rule, S13's worktree clearing and S23's docstring.
4. The records: S10, and S4, S5, S8, S11, S14, S15, S17 and S22 where a read is red, each through the
   door.
5. The tip scan again over the pass's own records, last.

Each fence below is written to a file under `$SCRATCH`, an absolute path, and run as `bash <file>`: an
isolated worktree session refuses an inline command that embeds git. `$SWEEP` is a file of the lines
inside the fenced block of unit 78's AC1 answer, and `$LIVE` a file of a `sep rc=0` line, then the two
`live` lines unit 77's AC1 answer quotes, as unit 79 §4 names them.
