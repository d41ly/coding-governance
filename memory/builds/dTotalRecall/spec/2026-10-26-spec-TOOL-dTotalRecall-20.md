## 1. Goal

Carry every adopter across the three changes this build makes to what an adopter can see, each as
a declared step that `update` walks (P38). The Serves kind `journal` is read through its alias, and
no record is rewritten. The `--new-build` and `--new-spec` scaffold verbs keep working, forwarded to
`record` by dSafePassage's shim and warning until their window closes. An adopter's README front
matter is graded against the schema before unknown keys are refused. The retag step rewrites an
adopter's own records only under `memory.legacy-anchors: retag`.

## 4. Design

### The rows

```toml
# tools/memory-tree/kit.toml
[[upgrade]]
id = "memory-tree/serves-journal-read-as-log"
up = ["python", "{gov}/govkit/steps/memory_journal_alias.py", "up", "{target}"]
down = ["python", "{gov}/govkit/steps/memory_journal_alias.py", "down", "{target}"]
witness = ["python", "{gov}/govkit/steps/memory_journal_alias.py", "witness", "{target}"]
resume = "atomic"
surfaces = ["serves-kind:journal"]
needs-target = false

# tools/govkit/shims.toml
[[shim]]
id = "memory-tree/new-build-to-record"
kind = "verb"
from = "{prefix}/memory-tree/gen_build_index.py --new-build"
to = "{prefix}/memory-tree/gov_record.py new build-readme"
closed = false
```

The front-matter and retag rows follow the journal row's shape with their own programs.
`needs-target = false` holds for all three: each runs gov's code over the target's files and runs
none of the target's. `upgrade_steps.py#run_step_isolated` spawns a program from gov's checkout
root, so each program passes the target as the working directory of the child it runs. The journal
and front-matter steps' `down` is a no-op that exits 0, since their `up` writes nothing.

### The forward

Today `--new-build <slug> --asks <IDLIST>` and `--new-spec <ID> --tier <1|2> [--order <n>]
[--base <sha>]` dispatch in `gen_build_index.py#main` to `#cmd_new_build` and `#cmd_new_spec`. After
this unit the two dispatch lines call `run_shim_new_build_to_record(argv[2:])` and
`run_shim_new_spec_to_record(argv[2:])`, the rendered blocks. `cmd_new_build` and `cmd_new_spec`
stay: `tools/memory-tree/gov_record.py#run_build_readme` and `#run_spec` import `gen_build_index` and
call them, never its `main`, so a forwarded call reaches each scaffold once and never loops. The
arguments pass through unchanged, so unit 2's two verbs take the flags `#NEW_BUILD_USAGE` and
`#NEW_SPEC_USAGE` state. The `runpy` run ends in `gov_record.py`'s own `sys.exit`, so the forwarded
call's exit is the door's.

### The anchors verb

`tools/playbook/gov_tag.py anchors <path>` reads the file at `<path>` and opens no index. It walks the
file's unfenced `##` headings in document order through `tag_index.py#scan_unfenced`, deriving each
one's anchor with `#derive_anchor` and one `seen` set, as `#extract_doc` walks them, so a repeated
heading takes `-2` and `-3` (unit 10). It prints one `tags: anchor <line> <anchor>` line per heading
outside a generated region (`<!-- gen:<name> -->` to `<!-- /gen:<name> -->`) whose text does not
open `[<tag>] `, and exits 0. An unreadable path exits 2 with the verb's `tags: refused` line. It
reads no policy key.

### The retag, in an adopter

Under `retag` the step reads each record's `##` headings outside fences and generated regions
through the anchors verb. It skips a heading that already carries a `[tag]`, and gives each other
heading the anchor `derive_anchor` gives it under `derived`. A repeated heading takes the `-2` or
`-3` suffix (unit 10). The plan is the whole rewrite, so `--dry-run` shows the exact bytes `up`
would write. An adopter that sets `retag` after the walk applied the step gets it on its next
`update`, because the witness exits 1 while an untagged heading remains under `retag`.

and `memory-tree/legacy-anchors-retag`; the shim ids `memory-tree/new-build-to-record` and
`memory-tree/new-spec-to-record`; the shim kind `verb`, its block and the parsed row keys
`from-words` and `to-words`; the rendered functions `run_shim_new_build_to_record` and
