## 1. Goal

Register the `stream-plan` record kind: a build's units grouped into streams, each stream's units in
order, with its schema and its check, so that Design's planner (`design.streams`, which
dIndexedDesign builds) writes it and Runtime's pick (dWellOiledMachine's) reads it, both against this
one registration. Today the only grouping is the build-order region `render_order` derives from each
spec's `order` verb, and no record maps a stream to its ordered units (the parked debt's review, the
owner's CL-3).

## 4. Design

### Data model

The record opens with its `**Serves:**` line naming the units it plans, then an H1, then one fence:

```toml
[[stream]]
name = "tooling"
units = [{ id = "TOOL-dTotalRecall-1", order = 1 }, { id = "TOOL-dTotalRecall-13", order = 2 }]

[[stream]]
name = "memory"
units = [{ id = "TOOL-dTotalRecall-8", order = 1 }]
```

Two units sharing an `order` in one stream are its parallel group, the meaning `order` carries on a
spec header (`memory/TEMPLATE-SPEC.md`, "the BUILD-ORDER verb"); gaps are permitted for the same
reason. The fence is found by the regex `parse_dossier` uses for a dossier's machine half
(`tools/codebase-map/map_lib.py#_TOML_FENCE_RE`), carried as its own constant here since the kits
do not import each other.

### The order grammar

An `order` passes when it is an `int` that is not a `bool`, above zero, and
`ORDER_RE.search(f"· order {n}")` matches it whole, so the plan and the spec header verb read one
grammar. The type test is owed: probed at `b4137f48`, `ORDER_RE` matches the text `· order 2` built
from the TOML string `"2"`, and matches `· order 0`. `ORDER_RE` is imported from `gen_build_index.py`,
the memory-tree kit's own module, inside `check_stream_plan`, as this file imports its siblings.

### The row

The pass edits `TYPED_RECORD_KINDS` and `KINDS` first, then writes the row with one call:

```
python tools/memory-tree/record_kinds.py new stream-plan --tag record.stream-plan --writer hand \
  --check record-kinds --home "memory/builds/*/build/*-stream-plan-*.md" --form fence \
  --validator record_kinds:check_stream_plan --layer layer.memory --lifecycle current-state \
  --readers-none "no role's reads: names a stream plan until dWellOiledMachine's pick lands" \
  --purpose "a build's units grouped into ordered streams, written by dIndexedDesign's planner, read by dWellOiledMachine's pick"
```

The purpose text fits `PURPOSE_BYTES` (TOOL-dTotalRecall-16 S1). `new` re-renders the view, so the
`gen:record-kinds` region gains the row in the same call.

### The grading arm

`check_fence_records(root, rows, typed_kinds) -> (reds, unarmed)` runs inside `check_record_kinds`
after the `fields` population. `resolve_validator(spelled)` imports `<module>` from the kit's
directory and returns the callable or the reason it did not resolve; `check_row` reds that reason,
and `check_fence_records` skips the row, so one fault is one red. For each resolved `fence` row the
arm reads every tracked record the row's home matches, a typed kind's kept only where
`derive_record_name(<kind>)` matches, and prefixes each red the validator returns with
`row <kind>: <path>:`. A typed `fence` row whose home matches nothing is unarmed: it prints S5's
line, its tail after `no record yet; ` the constant `STREAM_PLAN_UNARMED` beside
`check_stream_plan`, the text TOOL-dTotalRecall-42 S3 later moves onto the row's `unarmed` key. The
count line names the row `<kind> fence <n> graded`.

### Fixture

`python record_kinds.py --fixture --plant <case>` (TOOL-dTotalRecall-1) gains a `stream-plan` row in
the fixture registry, typed in the fixture's kind list, its `KINDS` entry in the fixture's
`build_records.py`, and one well-formed plan of two streams, which reads green. The plants:

| Plant | Staged | Red names |
|---|---|---|
| `stream-unordered` | a unit with no `order` | the plan, the stream, the unit |
| `stream-empty` | a stream with `units = []` | the plan, the stream |
| `stream-order-text` | `order = "2"` | the plan, the unit, `order` |
| `stream-unit-twice` | one unit id in both streams | the plan, the unit id |
| `stream-fence-missing` | the plan's fence deleted | the plan, `fence` |
| `stream-validator-missing` | the fixture row's validator `record_kinds:no_such_check` | `row stream-plan`, the validator |

`--selftest` asserts each plant red naming its subject, and asserts that `new` with `--form fence`
and an unresolvable `--validator`, and with `--form fence` and a `--field`, each exits 2 leaving the
registry's bytes unchanged.
