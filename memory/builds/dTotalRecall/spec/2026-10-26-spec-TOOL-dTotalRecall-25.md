## 1. Goal

Register the `stream-plan` record kind: a build's units grouped into streams, each stream's units in
order, with its schema and its check, so that Design's planner (`design.streams`, which
dIndexedDesign builds) writes it and Runtime's pick (dWellOiledMachine's) reads it, both against this
one registration. Today the only grouping is the build-order region `render_order` derives from each
spec's `order` verb, and no record maps a stream to its ordered units (the parked debt's review, the
owner's CL-3).

## 4. Design

### Data model

The record opens with its `**Serves:**` line naming the units it plans, then an H1, then one fence:

```toml
[[stream]]
name = "tooling"
units = [{ id = "TOOL-dTotalRecall-1", order = 1 }, { id = "TOOL-dTotalRecall-13", order = 2 }]

[[stream]]
name = "memory"
units = [{ id = "TOOL-dTotalRecall-8", order = 1 }]
```

Two units sharing an `order` in one stream are its parallel group, the meaning `order` carries on a
spec header (`memory/TEMPLATE-SPEC.md`, "the BUILD-ORDER verb"); gaps are permitted for the same
reason. The fence is found by the regex `parse_dossier` uses for a dossier's machine half
(`_TOML_FENCE_RE`, `tools/codebase-map/map_lib.py:72`), carried as its own constant here since the kits
do not import each other.

### The order grammar

An `order` passes when it is an integer above zero and `ORDER_RE.search(f"· order {n}")` matches it
whole, so the plan and the spec header verb read one grammar: `ORDER_RE` is imported from
`gen_build_index.py`, the memory-tree kit's own module.

### Fixture

`python record_kinds.py --fixture --plant <case>` (TOOL-dTotalRecall-1) gains the cases
`stream-unordered` (a unit with no `order`), `stream-empty`, `stream-order-text` (`order = "2"`),
`stream-unit-twice` and `stream-validator-missing`; a well-formed plan in the fixture reads green.

### Inventory

Minted: the row `stream-plan`, `check_stream_plan`, the schema form `fence` and its `validator` key,
the fixture cases above. Naming cells: `check_stream_plan` is asked of the lexicon's `--suggest`
under `--as py.function` at the pass.

### Files touched (estimate)

- `tools/memory-tree/record-kinds.toml`
- `tools/memory-tree/record_kinds.py`
- `tools/memory-tree/HYGIENE.template.md` (the view's new row)
- `memory/HYGIENE.md` (the render, never the edit)

### Alternatives rejected

- **`**Key:**` field lines.** A stream is a list of ordered units and a plan holds several streams;
  the field grammar refuses a repeated key, so it would need one record per stream.
- **A plan file at the build folder's root.** Hygiene check 3's structure lint admits a fixed set
  there; the `build/` folder holds a build's records.
