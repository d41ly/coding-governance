## 1. Goal

No atlas lives in the repository: the atlas is an online page derived from design records, and nothing
renders the product's own registries for a human (gap-mem-48, gap-register:231). This unit renders the
atlas under `help/atlas/`, as `help.atlas` says: generated Markdown pages with Mermaid diagrams, one per
namespace and the plan split per build, read from the one index's node table, the table `gov map` reads
(unit 14), never the design records; refused when stale by the merge bar's existing stale-output
refusal; parity-checked against index rows read on their own; and each node linked to its help page by
tag and back under one link check (the owner's FQ-8, v2:1296, P42).

## 4. Design

### The pages

```text
help/atlas/README.md                 index: one line per page, the over-budget line, the generated header
help/atlas/<ns>.md                   one namespace; past budget, a segment index over <ns>/<seg>.md
help/atlas/plan.md                   the chain builds as one Mermaid flowchart over their `after` relations
help/atlas/plan/<slug>.md            one chain build: its units as a table
help/atlas/design.md                 the design against the built, per chain build
help/atlas/help-index.md             one anchored row per node a help page declares
```

Every page opens `<!-- gov:generated by gen_atlas.py from the one index; edit the source, not this page
-->`. A node row:

```markdown
| <a id="policy.memory.map-overflow"></a>`policy.memory.map-overflow` | the map's overflow rule | — | `tools/policy/catalogue.toml:<line>` | `allowed = ["degrade", "refuse"]` · `default = "degrade"` |
```

Columns: key, purpose (`—` when none), counts and relations as unit 14's `line` grammar spells them,
source, declared fields. The declared cell reads the blob the index's `tree_path` row names for that
path, parses it with `tomllib` once per blob, and renders the scalar and list-of-scalar fields of the
array-of-tables entry whose header sits at the row's line, in key order; a non-TOML source leaves it
blank. The plan page reads the chain builds the node table holds (native keys `chain.<slug>`, the
chain registry's rows) and their `after` relations; a build page tabulates the units the node table
lists under that build with the same columns. With no chain registered the plan page says so in one
line.

A Mermaid node id is the tag with every `.` and `-` folded to `_`; its label is the key. An edge is a
relation whose target sits on the same page; a relation leaving the page stays a table cell.

### The split

`render_fitted_pages(ns_prefix, nodes)` renders the page; past any of the three limits it groups the nodes by
the segment after `ns_prefix`, writes one child page per group at `<prefix path>/<seg>.md`, and leaves
on the parent a segment index, one line per child with its node count, plus the rows of nodes whose
tag ends at the prefix. It recurses per child. Grouping never drops a node, so the parity arm's
exactly-once join holds by construction and is checked anyway.

### The check, the parity and the plants

`--check` exit 0 fresh, 1 stale or a parity finding, 2 refused (the index unreadable, a namespace file
that does not parse). Parity reads `namespaces.toml` with `tomllib` and the index with `sqlite3`
through the inline `common_git_dir`, and reads each page's `<a id="...">` anchors with one regex.
`--fixture --plant <case>` builds a scratch repository under the short `%TEMP%` path a fixture repository
needs, with a two-namespace registry, a catalogue, a loop definition and a built index, renders, then
plants one case and runs `--check`:

| Case | Plant | Expected |
|---|---|---|
| `default-flip` | a catalogue row's `default` changed, no regeneration | exit 1, the policy page named |
| `hand-edit` | one cell of a committed page edited | exit 1, that page named |
| `namespace-unrendered` | a namespace row with members, its page absent | exit 1, the namespace named |
| `new-step` | a `[[step]]` row added to the loop definition | exit 1 before `--write`; after it, the step's row, renderer blob unchanged |
| `orphan-page` | a page under the atlas root no render produces | exit 1, the page named |
| `render-skip` | the renderer, patched in memory, omits one node | byte compare green, parity exit 1 naming the tag |
| `index-only` | a member row inserted into the index after render | exit 1, the tag named |
| `over-budget` | 3,000 members in one namespace | split pages, every member once, each page in budget |
| `deviation` | a deviation record for a carried clause | `design.md` row names its id |

`render-skip` is the case that separates parity from the byte compare: both sides of the compare call
the patched renderer, so only parity can see the missing node.

## 5. Production-readiness checklist

- security: no new input crosses a trust boundary; the renderer reads tracked blobs and the local index
  and writes only under the atlas root or a named `--out` directory, which must not sit inside the tree.
- perf / scale: one node-table read and one parse per TOML blob. Research measured 275,094 B over 16
  pages at its scratch render (research-final-atlas.md:84, PINNED 2026-10-19); the stage-3 cost is
  measured at the build run and the leg's ceiling derived by `derive-ceilings.py`.
- error / empty / loading states: an unreadable index refuses with exit 2; an empty namespace renders
  `unarmed`; blank `DESIGN_*` keys render the design page's one line; no chain renders the plan
  page's one line.
- observability: `--check` prints pages, nodes, namespaces, unarmed namespaces and over-budget pages,
  each DERIVED at the run, and every finding names its page or tag.
- risks: GitHub documents no Mermaid version or limit, so the caps are Mermaid's own defaults
  (research-final-atlas.md:84); a host with lower caps shows the fence as source, and the tables stay
  readable. A reference page's back link breaks if `help.atlas` moves off `committed` without a
  re-render, which the link check reds.
- testing: AC1 to AC14, each on a planted case or the real tree.
- migration: §4 "### Migration".
- user docs: `help/atlas.md` and its `help/README.md` line (S10).
