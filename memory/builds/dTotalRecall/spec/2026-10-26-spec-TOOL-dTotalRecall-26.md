## 4. Design

### The pages

```text
help/atlas/README.md                 index: one line per page, the over-budget line, the generated header
help/atlas/<ns>.md                   one namespace; past budget, a segment index over <ns>/<seg>.md
help/atlas/plan.md                   the chain builds as one Mermaid flowchart over their `after` relations
help/atlas/plan/<slug>.md            one chain build: its units as a table
help/atlas/design.md                 the chain builds, each with its clause and deviation counts
help/atlas/design/<slug>.md          one chain build: its clauses, their specs and deviations
help/atlas/help-index.md             one anchored row per node a help page declares
```

Every page opens `<!-- gov:generated by gen_atlas.py from the one index; edit the source, not this page
-->`. A node row:

```markdown
| <a id="policy.memory.map-overflow"></a>`policy.memory.map-overflow` | the map's overflow rule | — | `tools/policy/catalogue.toml:<line>` | `allowed = ["degrade", "refuse"]` · `default = "degrade"` |
```

Columns: key, purpose (`—` when none), counts and relations as unit 14's `line` grammar spells them,
source, declared fields. The declared cell parses the node's defining row text, as
`tag_index.py#read_text_of` returns it, with `tomllib`, and renders its scalar and list-of-scalar
fields in key order, each in its own code span opening with the key. A text that does not parse, or
a non-TOML source, leaves it blank. A build page tabulates its units with the columns id, title,
status, order and source.

A Mermaid node id is the tag with every `.` and `-` folded to `_`; its label is the key. An edge is a
relation whose target sits on the same page; a relation leaving the page stays a table cell.

### The split

`render_fitted_pages(ns_prefix, nodes)` renders the page; past any of the three limits it groups the
nodes by the segment after `ns_prefix`, packs consecutive groups in tag order into child pages each
within budget, writes each at `<prefix path>/<first seg>.md`, and leaves on the parent a segment
index, one line per child with its node count, plus the rows of nodes whose tag ends at the prefix.
It recurses into a one-group child still over budget. Grouping never drops a node, so the parity
arm's exactly-once join holds by construction and is checked anyway.

### The check, the parity and the plants

`--check` exit 0 fresh, 1 stale or a parity finding, 2 refused (the index unreadable, a namespace file
that does not parse). Parity opens its own connection to `tag_index.py#derive_index_path`, fills its
view with `#load_view`, and selects with its own SQL over `path_row` joined to the view's three temp
tables, never `#read_rows`, `derive_nodes` or the renderer. A node is a `#`-free tag of a
`DEFINE_KINDS` row in a namespace `#read_namespaces` returns. It reads each namespace page's
`<a id="...">` anchors with one regex; the index, plan, design and help-index pages are not read.
`--fixture --plant <case>` builds a scratch repository under the short `%TEMP%` path a fixture
repository needs, on `gov_tag.py#build_tags_fixture`'s base, its registry rows from
`#derive_fixture_row` and its files committed by `#write_commit`: a two-namespace registry, a
catalogue at `#FIXTURE_CATALOGUE`, a loop definition at `#FIXTURE_LOOP`, a two-build chain registry
whose READMEs declare one `after` edge, and a built index. It renders, then plants one case and runs
`--check`:

| Case | Plant | Expected |
|---|---|---|
| `default-flip` | a catalogue row's `default` changed, no regeneration | exit 1, the policy page named |
| `hand-edit` | one cell of a committed page edited | exit 1, that page named |
| `namespace-unrendered` | a namespace row with members, its page absent | exit 1, the namespace named |
| `new-step` | a `[[step]]` row added to the loop definition | exit 1 before `--write`; after it, the step's row, renderer blob unchanged |
| `orphan-page` | a page under the atlas root no render produces | exit 1, the page named |
| `render-skip` | the renderer, patched in memory, omits one node | byte compare green, parity exit 1 naming the tag |
| `index-only` | a member `path_row` row inserted into the index after render | exit 1, the tag named |
| `over-budget` | 3,000 members in one namespace | split pages, every member once, each page in budget |
| `deviation` | a deviation record for a carried clause | the build's design page names its id |

`render-skip` is the case that separates parity from the byte compare: both sides of the compare call
the patched renderer, so only parity can see the missing node.

## 5. Production-readiness checklist

- security: no new input crosses a trust boundary; the renderer reads tracked files and the local
  index and writes only under the atlas root or a named `--out` directory, which must not sit inside
  the tree.
- perf / scale: one node-table read and one TOML parse per declared row. Research measured 275,094 B over 16
  pages at its scratch render (research-final-atlas.md:76). Unit 9 (order 18) registers `section`,
  one node per distinct heading anchor: 40,074 distinct heading slugs (DERIVED 2026-11-23) sit in
  the tracked `spec`, `build`, `reviews` and `prompts` files, so F10's packing bounds that
  namespace's page count. The stage-3 cost and the leg's
  wall are measured at the pass, its ceiling derived by `derive-ceilings.py --write`.
- error / empty / loading states: an unreadable index refuses with exit 2; an empty namespace renders
  `unarmed`; blank `DESIGN_*` keys render the design page's one line; no chain renders the plan
  page's one line.
- observability: `--check` prints pages, nodes, namespaces, unarmed namespaces and over-budget pages,
  each DERIVED at the run, and every finding names its page or tag.
- risks: GitHub documents no Mermaid version or limit, so the caps are Mermaid's own defaults
  (research-final-atlas.md:76); a host with lower caps shows the fence as source, and the tables stay
  readable. Every commit that moves a node's row or adds a heading leaves the atlas stale until
  `regen.py --write`, as the build index is. A reference page's back link breaks if `help.atlas`
  moves off `committed` without a re-render, which the link check reds.
- testing: AC1 to AC15, each on a planted case or the real tree.
- migration: §4 "### Migration".
- user docs: `help/atlas.md` and its `help/README.md` line (S10).
