## 1. Goal

Every edge type declares how many edges of it one source may carry and how many one target may
receive, and a check counts both over the merged tree after every merge, so two records superseding
one decision on separate branches, which git merges clean, are red on the merged tree (gap-mem-42;
`night-pass-two.md:237-240`, `:269-270`, probe D). Today the only per-target rule in the tree is the
as-built view's one-head-per-clause rule (`tools/memory-tree/asbuilt_view.py#resolve_clause_rows`), and the planned
edge gates count per source only ("a second edge line of one type", `memory-plan.md:366`).

## 4. Design

### The bounds

| Type | `per-source` | `per-target` | Why |
|---|---|---|---|
| `supersedes` | `many` | `1` | one node is superseded by one successor; probe D's merge (`night-pass-two.md:237-240`) |
| `caused-by` | `1` | `many` | a record has one cause; `tools/memory-tree/build_records.py#read_record` already refuses a `Caused-by` that is not one id, or a field given twice |
| every other declared type | `many` | `many` | the design states no bound |

The derived `cites` row carries no key: a derived type is never declared, so nothing counts it. The
declared rows number 26 (DERIVED, the summary line of `python tools/playbook/edge_grammar.py --list`).

### The mirror

A kind mirrors a bounded type when a member of its row's `schema.fields`, lower-cased, equals the
type's name; its cell holds exactly those types, each with its `edges.toml` bounds. At
`803a3b802` that is 10 rows (PINNED 2026-11-22, the rule run over `record_kinds.read_record_kinds`):
`build-readme` (`supersedes`, a front-matter key) and `caused-by` on `deviation`, `exception`,
`override`, `change`, `red-fix`, `disposition`, `acceptance`, `recommendation` and `widen`. The pass
writes the 10 cells (PINNED 2026-11-22, the same derivation), and `--registry` re-derives them
whenever it runs, so the list is never typed beside the rule.

```toml
[[record-kind]]
name = "deviation"
# ... unit 1's and unit 16's columns ...
cardinality = { caused-by = { per-source = "1", per-target = "many" } }
```

The registry's header comment gains the column's one clause beside `purpose`'s.
`record_kinds.py#render_row`, which `new` writes rows through, renders `COLUMNS` only, so a kind
`new` adds with a `Caused-by` field reds this leg until its cell is written; the red names the row
and the cell.

### The count

```python
check_edge_bounds(edges, bounds) -> list[Violation]
# edges:  iterable of (type, source, target, where)   where = "<path>:<line>"
# bounds: {type: (per_source, per_target)}            "many" or an int
# Violation(type, end, node, bound, members)          end is "source" or "target"
```

Pure, no I/O, and the one implementation both callers use: `resolve_clause_rows` passes the edges
`(head, member, clause)` for each member no other member supersedes, with bound per-target 1, and
maps a violation to its existing `unordered amends of <clause>` finding; `check_edge_cardinality`
passes every edge it read with the registry's bounds. The playbook kit reaches `design_lib.py` as it
does today, through `tools/playbook/tag_index.py#load_memory_tree`.

### The check

Population: the files `git ls-files` lists at `root`, read from its working tree, as `--check` reads
them, so on a merge commit it is the merged tree. Sites read: every site `read_tree_edges` reads
(record headers, `**Edges:**` lines, a spec's `**Carries:**` line, `gov:handoff` markers, change
records, instruction units, leg rows, `gov:note` refs), and the README relations, one edge per
`<source slug>\t<type>\t<target>\t<state>[\t<detail>]` line of `--print-relations`, its `where` the
build's `README.md`. An edge's source is its `path` (a README edge's, its slug); its target is
counted with its pin cut (`target.partition("@")[0]`, as `edge_grammar.py#resolve_edge` cuts it), so
`unit.x@1a2b3c4d` and `unit.x` count as one node. The landed resolver reads no alias
(`edge_grammar.py#read_tag_rows` passes none to `tag_index.py#resolve_address`), so no other address
form names one node twice. A line `read_tree_edges` refuses is counted, not graded: the `edges` leg reds it.
Output lines:

```
cardinality: supersedes per-target 1 exceeded at PLAY-xDec-1 by memory/builds/xA/build/…:7, memory/builds/xB/build/…:7
cardinality: registry · deviation · caused-by per-source is "many" here, "1" in edges.toml
cardinality: registry · <m> kind(s) mirror a bounded type; <d> differ
cardinality: read <n> edges of <k> types, <r> line(s) refused and not counted; <v> violations
```

What it does not check: two sources inside one file (unit rows, leg rows) count as one source, which
no bounded type reaches, since every type such a file declares is `many` per source.

### Alternatives rejected

- **Declare cardinality only in the kind registry.** The types live in `edges.toml`; bounds kept apart
  from their types would let a type be registered with none. The registry mirrors them under a parity
  arm (S2).
- **Copy `resolve_clause_rows`' rule into the new check.** Two per-target counters would drift; the
  brief and the reuse rule both ask for the generalisation.
- **A dedicated post-merge hook.** The bar already runs on every push to main and, where declared,
  on every landed sha, so a leg is checked there with no second mechanism.
- **Normalise targets through the tag index.** It returns the tag it was asked for, so it buys nothing
  over the pin cut and loads the index on every run.

## 5. Production-readiness checklist

- security — no write path; read-only over tracked files and the registry.
- perf / scale — one pass over the edges `read_tree_edges` already parses and one `--print-relations`
  run; the count is linear; no tag index is loaded.
- error / empty / loading states — an empty population prints its zero counts and exits 0, said on
  the line rather than silent; a malformed `edges.toml` row, an absent registry under `--registry` and
  a failed `--print-relations` each exit 2, nothing graded.
- observability — every violation names the type, the end, the bound and each member's path and line.
- risks — a supersession written in prose is invisible to the count; only the forms the adapters read
  are graded, and a kind `record_kinds.py new` adds reds the leg until its cell is written.
- testing — AC1 to AC8 by a pass; the arms of §7 at the close.
- migration — additive, as §4 says.
- user docs — `help/tags.md`'s edge bullets and the usage row (S7).
