## 1. Goal

Decide, before the map's first unit, whether a level-0 project map earns its bytes. The coherence
and reuse lenses replay three past audits with the map handed and without, and dFairHearing's
scorer factory scores the runs against those audits' known not-in-view items on the project map's
three losing terms (its `[test]`, project-map.md:690-709). A losing map is never built, and the loss
is routed to the builds that would have read it.

### The terms

- **Known items found** for one harness run: the known ids that `measure_recall` matches among the
  coherence and reuse lenses' findings in that run, each id counted once. An arm's figure is, summed
  over the audits, the mean of its two runs. The **twin difference** is, summed over the audits, the
  larger of the two arms' absolute differences between their runs.
- **An existence search** is a `Grep` or `Glob` call, or a shell segment whose program is `grep`,
  `rg`, `find`, `ls`, `git grep` or `git ls-files`, read by `extract_segments`. The figure is the
  median over an arm's 12 lens runs (3 audits, 2 lenses, 2 runs).
- **Bytes read before the first act** are the tool-result bytes a lens received before its first
  tool call outside runlog's `read` class (`TOOL_CLASSES`, `tools/runlog/extract.py:95`), or before
  its final message when it makes none. Bytes handed in the prompt are not counted, so the map's own
  bytes are the allowance the term compares against. The figure is the median over 12 lens runs.

### The manifest

`check_experiment`'s `review-replay` manifest (TOOL-dFairHearing-23 S4), one case per audit and
arm, `dispatched` 2 per case, each `candidates` entry `{case, report, matched}` with `report` the
run's per-lens result file and `matched` null. The `map-replay` instance adds, per entry, the lens
agents' transcript paths, and per manifest, the map file and the known ids.

### Inventory

`measure_bytes_before_act` and `derive_map_verdict`; the verdict record and its `**Verdict:**`
line. Naming cells: each function asked of the lexicon's `--suggest` under `--as py.function`.

## 5. Production-readiness checklist

- security — no new write path in product code; the runs write only under `%TEMP%` clones and this
  build's records.
- perf / scale — twelve full harness runs; see AC4's `cost:`.
- error / empty / loading states — a run with no lens result, an unreadable transcript or an empty
  known set is a refusal naming the case, never a zero.
- observability — the verdict record carries every figure and clone.
- risks — two runs per arm is a small sample; the twin difference is the term that prices its noise.
  The map is derived after the three audits' dates, so a leak of a later fact is possible and is
  limited by S5's commit.
- testing — AC1 to AC3 and AC5 by a pass on fixtures; AC4 is the replay itself.
- migration — none.
- user docs — none under `help/`: no user-facing surface; the verdict is a record.

## 6. Acceptance criteria

- **AC1** — When `python replay_scorer.py --instance map-replay --manifest <fixture>` runs over a
  fixture manifest whose known ids include one the fixture audit does not hold, it exits 2 naming
  that id; with the id removed, it prints each audit's known count as the parsed findings give it.
  Red when: a known id the audit lacks is scored, or a known set is read from typed addresses.
- **AC2** — When the instance scores three fixture manifests, each planted to fail exactly one term
  (a recall rise of 4 with a twin difference of 0, a median search fall of 0.5, a bytes rise one
  byte over the map's bytes), `derive_map_verdict` returns `lose` naming that term and no other; an
  all-passing fixture returns `win`.
  Red when: any term never decides, or a term decides on its boundary the wrong way.
  figure: each planted value is PINNED in the fixture.
- **AC3** — When `count_existence_searches` and `measure_bytes_before_act` read a fixture transcript
  holding a `Grep`, a shell `git grep ... | wc -l`, a `Read` of 900 bytes and then an `Edit`, they
  return 2 and 900 (plus the `Grep` result's bytes).
  Red when: a piped segment is missed, or bytes after the first act are counted.
- **AC4** — When the pass runs the twelve harness calls of S4 and the instance over their manifest,
  the verdict record exists with `**Verdict:**`, twelve clones each with an empty status line, the
  map's bytes, and each term's figures.
  Red when: a clone is reused or dirty, a lens result is missing from the manifest, or the map was
  derived anywhere but `01dcdd1ae`.
  cost: twelve full Tier-2 harness runs, on the order of hours and their token spend.
  fixture: the three audits' commits and blobs, all present in this repository at `462d20f3`.
- **AC5** — When a fixture verdict reads `lose` and the routing step runs over scratch copies of the
  three `BACKLOG.md` files, each gains one ask row naming this unit and the losing terms; a `win`
  fixture leaves all three unchanged.
  Red when: a loss files nothing, or a win files a row.
