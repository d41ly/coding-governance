## 1. Goal

Decide, before the map's first unit, whether a level-0 project map earns its bytes. Three past
audits are replayed with the map handed and without: the spec audit through its coherence and reuse
lenses, and each diff review through the lenses its own call runs, since the harness runs those two
on a spec audit alone (§8 F7). dFairHearing's scorer factory scores the runs against those audits'
known not-in-view items on the project map's three losing terms (its `[test]`, project-map.md:690-709).
A losing map is never built, and the loss is routed to the builds that would have read it.

## 4. Design

### The subjects

Each replay reproduces its audit's own call, read from its `Reviewed:` and Provenance lines.

|---|---|---|---|---|
| `reviews/2026-10-17-review-PLAY-dClosedLoop-1-systems-retrofit.md` | spec-audit | the systems and retrofit records at blobs `9335a353` and `cec90968`, first held together at `36fc6d572` | full | 37 |

| `reviews/2026-10-17-review-PLAY-dClosedLoop-1-debt-folds.md` | diff-review | `9b188202..cdcea2c9` | full | 16 |

No subject commit's tree holds its own audit's record (DERIVED 2026-11-23, `git ls-tree` at each).

### The terms

- **Known items found** for one harness run: the known items with a finding that `measure_recall`
  matches among the scored lenses' candidates, each item counted once. An arm's figure is, summed over
  the audits, the mean of its two runs. The **twin difference** is, summed over the audits, the larger
  of the two arms' absolute differences between their runs.
- **An existence search** is a `Grep` or `Glob` call, or a shell segment whose program is `grep`,
  `rg`, `find`, `ls`, `git grep` or `git ls-files`, read by `extract_segments`. The figure is the
  median over an arm's 20 scored lens runs: 2 runs of the spec audit's 2 lenses, the library's 3 and
  the debt-folds' 5 (DERIVED 2026-11-23 from `tools/workflows/tier2-review.js#LIGHT_LENSES` and
  `tools/workflows/tier2-review.js#DIFF_LENSES`).
- **Bytes read before the first act** are the tool-result bytes a lens received before its first
  tool call that is neither in runlog's `read` class (`tools/runlog/extract.py#TOOL_CLASSES`) nor an
  existence search, or before its final message when it makes none. A shell call is classed `other`
  by `derive_tool_class`, so without that exception a shell search would be the act. Bytes handed in
  the prompt are not counted, so the map's own bytes are the allowance the term compares against. The
  figure is the median over the 20 scored lens runs.

### The manifest

`check_experiment`'s shape, `instance` `map-replay`, requiring `instance`, `known`, `candidates`,
`arms` and `map`, and nothing else:

- `arms`: `without`, `{settings: {map: false}, dispatched: 6}`, and `with`, `{base: "without",
  settings: {map: true}, dispatched: 6}`, so `check_one_variable` prints `arm with: varies map from
  without`; `dispatched` is 3 audits by 2 runs (DERIVED).
- `known`: one `{case, record, items}` per audit, `record` a `<src>` and `items` its not-in-view ids.
- `candidates`: one `{case, arm, report, matched, transcripts}` per run, `matched` null and
  `transcripts` `{<lens>: <path>}` for every scored lens. The instance checks `transcripts` and takes
  it off before `read_replay_cases` reads the rest under `CANDIDATE_KEYS`.
- `map`: a `<src>` of the map file, whose bytes are the allowance.

The lines are the factory's head, then `known <case>: <items> item(s) over <findings> finding(s)`
per audit, each run's recall, each term's figures, and `verdict win` or `verdict lose <terms>`.

## 5. Production-readiness checklist

- security — no new write path in product code; the runs write only under `%TEMP%` clones and this
  build's records, and a loss writes three asks through the existing ask door.
- perf / scale — twelve full harness runs; see AC4's `cost:`. The three arms are in-memory fixtures
  inside `review-replay selftest`'s ceiling of 300 s (PINNED 2026-11-23, `tools/gate-legs.json`).
- error / empty / loading states — a run with no lens result, a scored lens with no transcript, an
  unreadable transcript, an empty known set or an absent runlog kit is a refusal naming the case,
  never a zero.
- observability — the verdict record carries every figure and clone.
- risks — two runs per arm is a small sample; the twin difference is the term that prices its noise.
  The map is derived after the three audits' dates, so a leak of a later fact is possible and is
  limited by S5's commit. The diff reviews are scored on lenses the clause does not name (§8 F7).
- testing — AC1 to AC3 by the factory's arms on fixtures; AC5 by the door in a scratch clone; AC4 is
  the replay itself.
- migration — none.
- user docs — none under `help/`: no user-facing surface; the verdict is a record.

## 6. Acceptance criteria

- **AC1** — When `python replay_scorer.py --experiment <fixture>` runs over a `map-replay` fixture
  manifest whose known items include one the fixture audit has no heading for, it exits 2 naming that
  item. It does the same for a heading naming a finding id no confirmed appendix row holds. With both
  removed, it exits 0 and prints each audit's `known` line, its counts those the headings and
  `parse_record_findings` give.
  Red when: an item the audit lacks is scored, or a known set is read from typed addresses.
- **AC2** — When `derive_map_verdict` reads three planted figure sets, each failing exactly one term
  (a recall rise of 4 with a twin difference of 0, a median search fall of 0.5, a bytes rise one byte
  over the map's bytes), it returns `lose` naming that term and no other. A set sitting on every
  boundary (a recall rise of 5, a search fall of 1, a bytes rise equal to the map's) returns `win`.
  Red when: any term never decides, or a term decides on its boundary the wrong way.
  figure: each planted value is PINNED in the fixture.
- **AC3** — When `measure_existence_searches` and `measure_bytes_before_act` read a fixture transcript
  holding a `Grep`, a shell `git grep ... | wc -l`, a `Read` returning 900 bytes (PINNED in the fixture)
  and then an `Edit`, they return 2, and 900 plus the two searches' result bytes.
  Red when: a piped segment is missed, a shell search is read as the first act, or bytes after the
  first act are counted.
- **AC4** — When the pass runs the twelve harness calls of S4 and the instance over their manifest,
  the verdict record exists with `**Verdict:**`, twelve clones each with an empty status line, the
  map's bytes, and each term's figures.
  Red when: a clone is reused or dirty, a scored lens's result or transcript is missing from the
  manifest, or the map was derived anywhere but `01dcdd1ae`.
  cost: twelve full Tier-2 harness runs, on the order of hours and their token spend.
  fixture: the three audits' commits and blobs, all present in this repository at HEAD.
- **AC5** — When the three calls of §4 "The routing" run in a scratch clone of HEAD with `origin`
  removed, so the counter takes `write_seq_mint`'s `local … · no remote` floor (`tools/memory-tree/build_records.py`),
  each prints `wrote` and each `BACKLOG.md` gains one ask row naming this unit and the losing terms.
  On a `win` verdict, `git diff --stat` over the pass's commits lists none of the three files.
  Red when: a loss files nothing, or a win files a row.
