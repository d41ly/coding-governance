## 4. Design

### The registration

```toml
[[ledger]]
population = "census-kept-paths"
leg = "record causes (causes and orphans over the legacy population)"
seed = ["python", "{prefix}/memory-tree/convert_registry.py", "read-back", "census-kept-paths"]
key = "key"
fields = ["census", "path", "reason", "records"]
drain = "key"
direction = "shrink-only"
home = "memory/project/census-kept-paths.txt"
```

It follows the tables of `docs-undocumented` and `playbook-kit-waivers` in the same file, two keyed
lists a person decides. The leg runs `record_causes.py --check`, which reads the `check_cause_writers`
rows; the `record-kinds` leg reads the one alias row, and a registration names one leg. The reason is a
key field, so a keep whose reason is reworded is a new key, and `shrink-only` refuses it as `gained`,
just as it refuses a new keep. A keep that must be added after the home lands goes through
`ratchet.py widen`, the pack's recorded door.

### The home

```text
# ledger · census-kept-paths · key key census,path,reason,records · direction shrink-only · drain key
check_cause_writers	memory/builds/dClosedLoop/build/2026-10-19-build-PLAY-dClosedLoop-1-asbuilt.py	pinned instrument	-	1	<sha>	seeded
check_alias_compares	memory/builds/dClosedLoop/build/2026-10-19-build-PLAY-dClosedLoop-1-deviations.py	pinned instrument	-	1	<sha>	seeded
```

Rows are TAB-separated, the factory's grammar. A reason of several words is one field. `-` in `records`
marks a plain keep, as `-` marks a record row with no section in `record-kinds-legacy`. The count is the
number of census hits the row keeps, 1 for every row (DERIVED 2026-11-24, `python record_causes.py
--cause-writers` from `tools/memory-tree/` and AC4's alias probe, each listing one kept line per file).
`<sha>` is the pass base.

### The reader

```python
KEPT_FIELDS = ("census", "path", "reason", "records")   # the registration's fields

def read_kept_rows(census, root) -> dict:
    import legacy_ledger as ll   # at call time: the factory imports coverage_join, a sibling
    ...   # unit 65's path, and `{}` where the file is absent
    rows, bad = ll.read_rows(path, len(KEPT_FIELDS))
    if bad:
        raise ValueError(f"{CENSUS_KEPT_REGISTRY}: " + "; ".join(ll.render_malformed(b) for b in bad))
    kept = [dict(zip(KEPT_FIELDS, key), count=n, sha=sha, disposition=disposition)
            for key, (n, (sha, disposition), *_rest) in rows.items()]
    ...   # unit 57's domain refusal over every row of `kept`
    return {r["path"]: r for r in kept if r["census"] == census}
```

It reads no registration, as `gen_build_index.py` and `row_grammar.py` read their keyed homes: an
adopter holds the reader and no table, and its own registry file reads all the same. AC1 holds
`KEPT_FIELDS` equal to the registered fields. A keep row's reason that ends in `:<digits>` is a
malformed row to the factory, a red naming its line.

### Alternatives rejected

- **Register in `tools/memory-tree/kit.toml`.** The kit ships to every adopter, and a registered home
  there is this repository's own list.
- **Read the rows with `read_rows(..., tail=("reason",))`.** That form serves a registry left in the

- **Key fields `census` and `path` only, with the reason outside the key.** The factory's row has no
  free-text column after the key, and its tail is count, SHA and disposition. The reason would have
  nowhere to live, and the census prints it.
- **Keep unit 65's parser and add a registration beside it.** That is two readers of one file.
