## 2. Scope (IN)

- **S1** — The Python split shape. `id_grammar.py --readers` lists a line that calls `.split("-")` or
  `.split('-')`, blanks inside the parentheses allowed as `_READER_SPLIT_SHAPE` allows them, with no
  maxsplit argument, unless the call is indexed `[0]` at once. The family is the
  text before the first hyphen, so a hyphen inside a slug cannot move index 0, while index 1, a later
  index, a slice, an unpacking and a bound list all can. A `.rsplit("-", 1)` indexed `[1]` or `[-1]` is
  not listed, because it reads the sequence after the last hyphen. The predicate reads no value name.
  Observed by AC1 and AC2.
- **S2** — The shell shapes `_READER_SPLIT_SHAPE` reads at HEAD (`cut -d-`, `cut -d '-'`, `cut -d "-"`,
  `IFS=-` and the four suffix and prefix expansions) are listed by shape too, whatever the variable is
  named, with no lookahead asking the line to name an id-, slug- or unit-named variable.
  Observed by AC1.
- **S3** — The plants. The `--readers` fixture of unit 38's arm, `_SPLIT_PLANTS` beside
  `tools/memory-recall/selftest.py#test_split_census_and_the_flip_probe_census_check`, gains five
  planted lines: three it must list (`i.split("-")[1]`, `spec_id.split('-')[1][0]` and

  the shape can fail both ways; unit 38's `control` plant, an index-0 split, stays unlisted. Observed
  by AC1.

## 4. Design

### The predicate

```text
python  \.split\(\s*(["'])-\1\s*\)(?!\[0\])                  a split with no maxsplit, not indexed [0]
shell   \bcut\s+-d\s*(?:-|'-'|"-")(?=\s|$) | \bIFS=-(?=\s|;|$) | \$\{[A-Za-z_]+(?:%%?-\*|##?\*-)\}
```

The predicate replaces `_SPLIT_NAME`'s condition in `id_grammar.py#_READER_SPLIT_SHAPE`, the split
arm unit 38 landed beside `TOOL-dTotalRecall-5`'s id and slug shapes, and the comment above it is
rewritten to say so. Its shell half is unit 38's spelling with the name dropped; its Python half drops
the `.rsplit("-"` arm (S1). Three reads take it unchanged: `id_grammar.py#scan_readers`, and
`id_grammar.py#run_flip_probe`'s `own_splits` and `stray` filters. The population is unit 5's, every
tracked `*.py`, `*.sh` and `*.js` file under `tools/` and `skills/` and every tracked file under
`.githooks/`, this module excluded. The JavaScript half of the census is unit 5's regex-literal arm and
is unchanged. Unit 38 S4's flip-probe census check runs `scan_readers` over the clone and over the
probe's own tree and fails on a clone-only hit, so it reads this predicate on both sides and stays a
differential.
