## 1. Goal

Declare every record kind once, in one registry, `tools/memory-tree/record-kinds.toml`, and make it the
record-kind factory: its conformance gate lands with it, each kind's template and field check are
generated from its row, and `HYGIENE.md` carries the kind list as a view rendered from it. Today kinds
are spread over three `tools/memory-tree/tree_lib.py` tuples, runlog's `RECORD_SCHEMA`, the typed
factory's `KINDS` in `tools/memory-tree/build_records.py` and `HYGIENE.md` prose, and nothing declares
a writer, schema or check per kind (gap-mem-01).

## 2. Scope (IN)

- **S1** — The registry `tools/memory-tree/record-kinds.toml`: one `[[record-kind]]` row per kind, its
  columns in shared interface I1's order, `name`, `tag`, `layer`, `home`, `id-rule`, `schema`, `writer`,
  `readers`, `lifecycle`, `check` (§4 "Data model"). Required here: `name`, `tag`, `schema`, `writer`,
  `check`, and `home` on a `fields` row; the rest are admitted, required from TOOL-dTotalRecall-18.
  Observed by AC1 and AC2.
- **S2** — Today's kinds as rows (§4 "The rows"): the four untyped Serves kinds of
  `tools/memory-tree/tree_lib.py#RECORD_KIND_TOKENS`, `spec`, runlog's run record, the three kinds this
  unit owns (`backlog-row`, `design-record`, `dossier`), and one factory row per member of
  `tools/memory-tree/tree_lib.py#TYPED_RECORD_KINDS` (PLAY-dOrderedCharter-42 S1, S2), `deviation`,
  `probe` and `probe-trigger` (TOOL-dPlacedRequest-7 S6) among them. Observed by AC1 and AC8.
- **S3** — The conformance gate, `check_record_kinds(root)` in `tools/memory-tree/record_kinds.py`, run
  as `python record_kinds.py --check` and as the new leg `record-kinds`, declared once in its

## 4. Design

### Data model

```toml
# tools/memory-tree/record-kinds.toml
[[record-kind]]
name = "deviation"
tag = "record.deviation"
layer = ""                       # required from TOOL-dTotalRecall-18
home = "memory/builds/*/build/*-build-*-deviation-*.md"
id-rule = "<date>-build-<unit id>-deviation-<n>.md"
schema = { form = "fields", source = "{prefix}/memory-tree/build_records.py:KINDS.deviation.required", fields = [
  "Departs from", "Hand-off", "Before", "After", "Cause", "Reason", "Evidence", "Risk", "Approver",
  "Follow-through", "Caused-by"] }
writer = "hand"
readers = []
lifecycle = ""
check = "memory hygiene"
```

- `tag` is `record.<name>`, the node id `record-kind.<name>`
  (`memory/builds/dClosedLoop/build/2026-10-15-build-PLAY-dClosedLoop-1-layer-memory.md@8b8b1374:303`).
- `schema.form` is `fields` (records carrying `**Key:**` lines, graded by S4), `header` (a status or
  front-matter grammar its owner grades), `rows` (a row register) or `generated` (a view its generator
  re-renders); a form other than `fields` names its owner's arm in `check`.
- `home` is a `git ls-files` pathspec glob, required on a `fields` row, the population S4 grades;
  another form's stays `""` until TOOL-dTotalRecall-18.
- `schema.source` is `<path>:<NAME>[.<key>]…`, optional, spelled through `{prefix}` (the
  `install-prefix (shipped surface)` ban covers every tracked file under `tools/`). S3 `ast.parse`s the
  file, takes the module-level `NAME` assignment, walks each `.<key>` into a dict display and reads the
  node with `ast.literal_eval`, never by import, so no kit boundary is crossed.
  `fields` and the literal agree both ways: a list or tuple by members, a dict by keys
  (TOOL-dTotalRecall-4's `FRONT_MATTER_KEYS`). The walk exists because
  `tools/memory-tree/build_records.py#KINDS` is no pure literal while each `required` tuple is one
  (probed at `8b8b1374`). A schema pure at no key carries no `source`, its owner's leg grading it:
  `tools/runlog/record.py#RECORD_SCHEMA` reads the name `RECORD_CAP_BYTES` (probed at `8b8b1374`).
- `writer` is a door: the command writing the kind with no kit path, `generator:<path>`, or `hand`
  where none does yet. A factory kind's is the one `tools/memory-tree/build_records.py`'s
  docstring names: `build_records.py new <kind>` for a member of `build_records.py#DOORS`, else the
  owner's command calling `write_record`, else `hand`. Empty is red (S3). TOOL-dTotalRecall-2 S9 moves
  only `fields`-form `hand` rows onto its door; another form's keeps `hand`, its door's owner named in
  that pass's `Decided:` trailer.
- `check` names a `tools/gate-legs.json` leg; `id-rule` is the name grammar, `""` for a kind keyed
  by path.
- S3 admits, and never reds, two later columns, each graded by its owner: `root`
  (TOOL-dTotalRecall-19, true on the `build-readme` and `claim` rows) and `sections`
  (TOOL-dTotalRecall-9).
