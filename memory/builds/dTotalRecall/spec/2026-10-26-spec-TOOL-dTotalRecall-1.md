## 1. Goal

Declare every record kind once, in one registry, `tools/memory-tree/record-kinds.toml`, and make it the
record-kind factory: its conformance gate lands with it, each kind's template and field check are
generated from its row, and `HYGIENE.md` carries the kind list as a view rendered from it. Today kinds
are spread over three tuples in `tools/memory-tree/tree_lib.py`, runlog's `RECORD_SCHEMA`, the typed
factory's `KINDS` table in `tools/memory-tree/build_records.py` and `HYGIENE.md` prose, and nothing
declares a writer, a schema or a check per kind (gap-mem-01).

## 2. Scope (IN)

- **S1** — The registry `tools/memory-tree/record-kinds.toml`: one `[[record-kind]]` row per kind, its
  columns in shared interface I1's order, `name`, `tag`, `layer`, `home`, `id-rule`, `schema`, `writer`,
  `readers`, `lifecycle`, `check` (§4 "Data model"). This unit requires `name`, `tag`, `schema`,
  `writer` and `check` on every row, and `home` on every `fields` row, the population S4 grades;
  `layer`, `readers`, `lifecycle` and the other rows' `home` are admitted and required from
  TOOL-dTotalRecall-18. Observed by AC1 and AC2.
- **S2** — Today's kinds as rows (§4 "The rows"): the four untyped Serves kinds of
  `tools/memory-tree/tree_lib.py#RECORD_KIND_TOKENS`, `spec`, runlog's run record, the three kinds this

## 3. Non-goals (OUT)

- The `record` write command that mints ids and renders templates at the write boundary:
  TOOL-dTotalRecall-2. This unit only renders a template on request (S5).
- Home on every row, lifecycle, readers and layer, the render of readers and writers from the role
  definitions, the pocket witnesses and the `journal` rename: TOOL-dTotalRecall-18.
- The `purpose` column: TOOL-dTotalRecall-16. Per-edge `cardinality`: TOOL-dTotalRecall-22.
- The rows of kinds other units of this build own (`claim`, `build-readme`, `ask`, `code`,
  `shape-run`, `view`, `registry`, `archive`, `instrument`, `witness`, `stream-plan`): each lands with
  its own unit, through S9's factory and S3's gate.
- Grading a record by its Serves kind's row alone, and the `unarmed` key: TOOL-dTotalRecall-42.
- Rewriting any record into a registered form. Legacy records keep their form (S8).
- Re-numbering hygiene checks or tagging them: the check catalogue stays authored prose.
- The gap register itself and any gap's status: this unit resolves gap keys, it does not grade gaps.
- An edge type naming `gap-key` in its `to`: none does at base, and S10 registers the class only.

## 4. Design

### Data model

```toml
# tools/memory-tree/record-kinds.toml
[[record-kind]]
name = "deviation"
tag = "record.deviation"
layer = ""                       # required from TOOL-dTotalRecall-18
home = "memory/builds/*/build/*-build-*-deviation-*.md"
id-rule = "<date>-build-<unit id>-deviation-<n>.md"
schema = { form = "fields", source = "{prefix}/memory-tree/build_records.py:KINDS.deviation.required", fields = [
  "Departs from", "Hand-off", "Before", "After", "Cause", "Reason", "Evidence", "Risk", "Approver",
  "Follow-through", "Caused-by"] }
writer = "hand"
readers = []
lifecycle = ""
check = "memory hygiene"
```

- `tag` is `record.<name>`
  (`memory/builds/dClosedLoop/build/2026-10-15-build-PLAY-dClosedLoop-1-layer-memory.md@8b8b1374:303`);
  the node id is `record-kind.<name>`.
- `schema.form` is one of `fields` (records carrying `**Key:**` lines, graded by S4), `header` (a status
  or front-matter grammar its owner grades), `rows` (a row register), `generated` (a view its generator
  re-renders). Only `fields` is graded by S4; the other forms name their owner's arm in `check`.
- `home` is a `git ls-files` pathspec glob, required on a `fields` row, the population S4 grades;
  another form's stays `""` until TOOL-dTotalRecall-18.
- `schema.source` is `<path>:<NAME>[.<key>]…`, optional, its path spelled through `{prefix}`, since the
  `install-prefix (shipped surface)` ban covers every tracked file under `tools/`. S3 parses the file
  with `ast.parse`, takes the module-level assignment to `NAME`, walks each `.<key>` as a string key of
  a dict display and reads the node it lands on with `ast.literal_eval`, never by import, so a sibling
  kit's literal is read without crossing a kit boundary. The row's `fields` and the literal agree both
  ways: a list or tuple by its members, a dict by its keys (TOOL-dTotalRecall-4's
  `FRONT_MATTER_KEYS`). The walk exists because `tools/memory-tree/build_records.py#KINDS` is no pure
  literal (its closed sets name constants), while each `required` tuple is one (probed at `8b8b1374`).
  A schema pure at no key carries no `source`, and its owner's leg grades it:
  `tools/runlog/record.py#RECORD_SCHEMA` reads the name `RECORD_CAP_BYTES` (probed at `8b8b1374`).
- `writer` is a door, spelled as the command that writes the kind with no kit path,
  `generator:<path>` for a generated kind, or `hand` for a kind no command writes yet. A factory kind's
  writer is the one `tools/memory-tree/build_records.py`'s docstring names for it: `build_records.py new
  <kind>` for a member of `build_records.py#DOORS`, else the owner's command that calls `write_record`,
  else `hand`. Empty is red (S3); `hand` is legal on any row TOOL-dTotalRecall-2 S9 does not move. S9
  moves only the `fields`-form `hand` rows onto its door, and a `hand` row of another form keeps
  `hand`, its door's owner named in that pass's `Decided:` trailer.
- `check` names one leg of `tools/gate-legs.json` by its `name`.
- `id-rule` is the record's name grammar, or `""` for a kind keyed by path.
- Two columns later units add are admitted by S3 and never red: `root` (TOOL-dTotalRecall-19, true on
  the `build-readme` and `claim` rows) and `sections` (TOOL-dTotalRecall-9). Each is graded by its
  owner's unit, not by this gate.

### The view

`record_kinds.py --write` replaces the body between `<!-- gen:record-kinds -->` and
`<!-- /gen:record-kinds -->` in `tools/memory-tree/HYGIENE.template.md` with a table of the rows, one

### Factory

`new` writes the row at the end of the file, refusing (exit 2) a duplicate `name`, a `tag` outside
`record.`, an empty `writer`, a `fields` row with no `--home`, or a `check` no leg carries. It is the
`factory` command the kinds register names, so PLAY-dOrderedCharter-7 S5's contract (factory names a
file, gate names a leg enforcing every tag of `binds`) holds for `kind.record-kind`, and
`tools/playbook/core.py#run_kinds` reds the pending row as stale once it does, which is why S9 deletes
it. D2 is settled in §8 F1.

### Empty states

An empty registry and an empty gap register each print an `unarmed` line and red. A non-typed
`fields` row whose home matches no tracked file reds; a typed kind's prints `<kind>: unarmed — no
record yet` and passes (§8 F7).

`gap <key>` in a deviation's `Follow-through` (`tools/memory-tree/deviation_join.py#FOLLOW`) through

  15,064 tracked files (PINNED, `git ls-tree -r --name-only 8b8b1374 | wc -l`, 2026-11-22).

  `unarmed` kind, and every red with its row.

  record of every `fields` kind, so the landing commit grades nothing old.

- migration — none: no record changes, and every registered column's source keeps its value.

  README.
