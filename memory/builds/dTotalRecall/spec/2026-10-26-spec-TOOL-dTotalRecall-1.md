## 1. Goal

Declare every record kind once, in one registry, `tools/memory-tree/record-kinds.toml`, and make it the
record-kind factory: its conformance gate lands with it, each kind's template and field check are
generated from its row, and `HYGIENE.md` carries the kind list as a view rendered from it. Today kinds
are spread over two tuples in `tools/memory-tree/tree_lib.py`, runlog's `RECORD_SCHEMA`,
`deviation_join.py`'s field table and `HYGIENE.md` prose, and nothing declares a writer, a schema or a
check per kind (gap-mem-01).

## 4. Design

### Data model

```toml
# tools/memory-tree/record-kinds.toml
[[record-kind]]
name = "deviation"
tag = "record.deviation"
layer = ""                       # required from TOOL-dTotalRecall-18
home = ""
id-rule = "<date>-build-<unit id>-deviation-<n>.md"
schema = { form = "fields", source = "tools/memory-tree/deviation_join.py:REQUIRED", fields = [
  "Departs from", "Hand-off", "Before", "After", "Cause", "Reason", "Evidence", "Risk", "Approver",
  "Follow-through", "Caused-by"] }
writer = "hand"
readers = []
lifecycle = ""
check = "memory hygiene"
```

- `tag` is `record.<name>` (layer-memory.md:303); the node id is `record-kind.<name>`.
- `schema.form` is one of `fields` (records carrying `**Key:**` lines, graded by S4), `header` (a status
  or front-matter grammar its owner grades), `rows` (a row register), `generated` (a view its generator
  re-renders). Only `fields` is graded by S4; the other forms name their owner's arm in `check`.
- `schema.source` is `<path>:<NAME>`, optional, pointing at a module-level literal that already
  declares the fields; S3 reads it with `ast.literal_eval` from the file text, never by import, so a
  sibling kit's literal is read without crossing a kit boundary. The row's `fields` and the literal
  must agree both ways: one fact, a gate comparing it. A list or tuple literal is compared by its
  members and a dict literal by its keys, so TOOL-dTotalRecall-4's `FRONT_MATTER_KEYS`, a dict of key
  to role, type and required, is compared with the `build-readme` row's `fields` by its keys. A
  schema that is not a pure literal carries no `source`, and its owner's leg, named in `check`, grades
  it: runlog's `RECORD_SCHEMA` reads the name `RECORD_CAP_BYTES` at `tools/runlog/record.py:178`, so
  `ast.literal_eval` refuses it (probed at base).
- `writer` is a door, spelled as the command that writes the kind (`gen_build_index.py --new-spec`,
  `build_records.py new probe`), `generator:<path>` for a generated kind, or `hand` for a kind no
  command writes yet. Empty is red (S3); `hand` is legal until TOOL-dTotalRecall-2 registers a door.
- `check` names one leg of `tools/gate-legs.json` by its `name`.
- `id-rule` is the record's name grammar, or `""` for a kind keyed by path.
- Two columns later units add are admitted by S3 and never red: `root` (TOOL-dTotalRecall-19, true on
  the `build-readme` and `claim` rows) and `sections` (TOOL-dTotalRecall-9). Each is graded by its
  owner's unit, not by this gate.

### The view

`record_kinds.py --write` replaces the body between `<!-- gen:record-kinds -->` and
`<!-- /gen:record-kinds -->` in `tools/memory-tree/HYGIENE.template.md` with a table of the rows, one
line per kind: name, tag, home, writer, check. It sits in a new `## Record kinds — the registry's
view` section after "Record bindings". `render_doc` substitutes only `{{…}}` placeholders, so the
region reaches `memory/HYGIENE.md` byte for byte through `adopt-memory-tree.sh --render`; the existing
`kit/dogfood doc parity` leg then holds the two equal. `--check` exits 1 naming the first differing
line when the committed region is not what `--write` would write.

### Factory

`new` writes the row at the end of the file, refusing (exit 2) a duplicate `name`, a `tag` outside
`record.`, an empty `writer`, or a `check` no leg carries. It is the `factory` command the kinds
register names, so PLAY-dOrderedCharter-7 S5's contract (factory exists, gate leg exists) holds for
`kind.record-kind`. D2 is settled in §8 F1.

### Gap keys

`GAP_KEY_RE = re.compile(r"gap-[a-z]+-\d{2,3}")`. `read_gap_keys(root)` lists tracked
`memory/builds/*/build/*-gap-register.md` with `git ls-files` and returns the set of first-cell keys
of their table rows. A `gap <key>` in a deviation record's `Follow-through` (the `FOLLOW` grammar,
`tools/memory-tree/deviation_join.py:157-158`) and a backticked gap key in a spec resolve through it.

### Fixture

`python record_kinds.py --fixture --plant <case>` builds a throwaway repository under the system temp
directory with a three-row registry, a two-leg `gate-legs.json`, a gap register and records, commits
it, and runs `--check` there. Cases: `writer-missing`, `check-unknown`, `source-drift`,
`factory-kind-unrowed`, `field-missing`, `field-missing-legacy`, `region-edited`, `gap-unresolved`.
With no `--plant` the fixture is green.
