## 4. Design

### How the batch builds

One pass, after every other unit is terminal. Inside it the order is:

1. The read-only items: S1, S3, S5, S6, S12, S17, S20, S21, S24, S28 and S29's reads. Each red they
   find decides a repair below or a deviation record.
2. The fixture base, S9 and S14 to S16, then the plants that rest on it: S7, S10, S11, S22 and S23.
3. The code items S2's probe, S18 and S26, and S4's removal where it is owed.
4. S8's README rule and S13's ask.
5. S19's merge, S27's removal, then the deviation records and the ledger lines, S25 last over every
   record the pass wrote.

### The fixture base

One function in `record_causes.py` makes every plant's scratch repository, so each class S9, S14
and S15 name is closed for every plant by construction and not by a list:

- the repository is made in a `tempfile.TemporaryDirectory(prefix=...)` of at most four characters;
- every git call runs under one child environment, built as `seed_env` builds its own, the caller's
  `GIT_*`, `GOV_REMOTE` and `GOV_DEFAULT_BRANCH` held out and a scratch global config put in;
- the tree tracks a `kit.toml` holding the `census-kept-paths` registration, unless the plant opts
  out, which only `kept-registration-absent` does;
- the repository has a remote whose `main` is the base commit and `origin/HEAD` is set, the shape of
  `deviation_join.add_fixture_remote` (`tools/memory-tree/deviation_join.py:1274`), unless the plant
  opts out, which only `kept-base-unresolved` does.

`tree_lib.GIT_ENV_LEAKS` (`tools/memory-tree/tree_lib.py:262`) is the kit's list of location
variables, and `seed_env` holds out every `GIT_*`, a superset; the base follows `seed_env`.
