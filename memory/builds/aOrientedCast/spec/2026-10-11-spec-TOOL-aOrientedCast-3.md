## 1. Goal

A role in the catalogue is a file no agent can be spawned as, and every agent spawned today holds the
60 KB charter and no role. This unit renders each role whose `agent` is true into a Claude Code agent
type under `.claude/agents/`, carrying `omitClaudeMd: true`, the role's rendered block and the charter
sections that role declares, beside the generated index `.claude/roles.json` the hooks read. Its
`--check` byte-compares both against a fresh render and is a gate leg, so a role edited without a
re-render reds the bar.

## 2. Scope (IN)

- **S1** — `render_agents.py` in the roles kit, with three modes: `--write`, `--check` and
  `--selftest`. Exit 0 when written, fresh or passing; 1 on drift or a failed arm, every offending path
  named; 2 on usage, a `RolesError` from the library, or a catalogue holding zero roles. It derives its
  own kit directory and the tool root through git and refuses an empty derivation. It reads the role
  files, the overlays, the workflow table, the conf and the governing doc only through
  `TOOL-aOrientedCast-1`'s library, `roles_lib.py`, and parses none of them itself. Observed by AC1,
  AC2 and AC5.
- **S2** — One agent type per role whose `agent` is true, at `.claude/agents/<name>.md`, in the shape
  of §4 "Data model": the role's Claude keys, then `omitClaudeMd: true`, then gov's `workflow` and
  `writes`, then a body holding the library's `render_role` output followed, under `## Charter`, by one
  `### charter §<n>` block per id the role's `charter` key names, as §8 F1 resolved. A role whose
  `agent` is false gets no file. Observed by AC1 and AC4.
- **S3** — `.claude/roles.json`, the generated index: every role with its `workflow`, `writes` and
  `agent`, and `harnesses`, the sorted, de-duplicated repo-relative paths of the `harness` of every
  workflow whose `driver` is `workflow`, each resolved by the library's `resolve_harness_path`. A
  harness the tree does not hold, the review harness in an adopter that did not install its kit, is
  listed at the path that resolver names for it and printed on one `note` line; it refuses nothing,
  so every mode still exits 0 on it and every file `--write` writes is whole. Observed by AC1, AC5
  and AC6.
- **S4** — Ownership. The files the renderer owns are the agent types its catalogue names plus every
  name the on-disk index lists. `--write` unlinks an owned file the catalogue no longer renders and
  rewrites the index; it never touches any other file under `.claude/agents/`. `--check` writes
  nothing, names every missing, drifted or stale owned path, and compares with carriage returns
  stripped from the on-disk side. Observed by AC2.
- **S5** — When `--write` creates, changes or unlinks an agent type, it prints one line naming the
  count and saying a session started before the write cannot spawn the change, so a new session is
  owed. When nothing moved it prints `unchanged` and no such line. Observed by AC3.
- **S6** — `--selftest` runs the renderer's own arms over a catalogue it builds in a temporary
  directory, never the repository's files, and prints `PASS (<n> assertions)` from a counter.
  Observed by AC6.
- **S7** — Gov's own render is committed, and `.gitattributes` pins the rendered agent types and the
  index `eol=lf`. Observed by AC1 and AC8.
- **S8** — Two gate legs land in `tools/gate-legs.json`, each with a `ceiling` of 300 and no `guard`:
  `roles render wiring` runs `--check` (repo, wiring) and `roles render selftest` runs
  `--selftest` (kit, selftests). The wiring leg carries the name `TOOL-aOrientedCast-8` gives the
  adopter's check, so that unit re-points one row's `argv` rather than adding a second leg over the
  same output. A guard on the roles kit's directory would owe the new leg on the leg line of every
  sibling spec touching that directory, which the spec-token checker's guards join enforces. Each
  gets its row in `tools/govkit/subject-pins.tsv`, the selftest
  its row in `tools/run-gates/selftest-budgets.txt`, the roles kit's dossier claims both leg names,
  the generated map artifacts are regenerated, and the kickoff manifest's `last-audit` is re-stamped,
  because `tools/gate-legs.json` is a watched path. Observed by AC9.
- **S9** — The agent-type probe is re-run against the RENDERED `gov-builder` and `gov-spec-writer`
  with the instrument of §4 "The probe re-run", and its result rows and instrument text are committed
  as a research record in this build's `build/` folder. Observed by AC7.
- **S10** — The roles kit's README gains a section: the render, its ownership rule, the restart rule,
  the CLI floor and the charter blocks of §8 F1. NOT OBSERVED by a criterion: prose. The review reads
  it against §4.

### Data model

An agent type, `.claude/agents/<name>.md`, LF only, one trailing newline:

```markdown
---
name: gov-builder
description: <the role's value>
tools: <the role's value>
model: <the role's value>
maxTurns: <the role's value; only when the role declares it>
omitClaudeMd: true
workflow: build
writes: product
---
<render_role(kit_dir, "gov-builder", MEMORY_ROOT): the base block, then House rules when non-empty>

## Charter

### charter §3

<the body extract_charter_sections gives for §3>
```

The library's front-matter grammar is one `key: value` per line at column 0, so each Claude key is
emitted as `<key>: <value>` in the order `name`, `description`, `tools`, `model`, `maxTurns`, which
reproduces the role file's own line. `omitClaudeMd`, `workflow` and `writes` are emitted by the
renderer. No other gov key is carried: `reads`, `charter`, `returns` and `agent` steer the handoff and
the index, not the type. `MEMORY_ROOT` is read by `read_conf_key` from `.memory-tree.conf` at the
toplevel. The charter blocks are spelled exactly as interface 7 spells a handoff's, `### charter §<n>`,
in the order the role's `charter` list names them; a role with an empty list gets no `## Charter`.

The index, `.claude/roles.json`, is `json.dumps(obj, indent=2, sort_keys=True, ensure_ascii=True)`
plus one newline. Its shape, not its bytes, which are whatever that call emits:

```json
{
  "harnesses": ["tools/workflows/tier2-review.js", "tools/workflows/unattended-build.js",
                "tools/workflows/unattended-unit.js"],
  "roles": {
    "gov-builder": {"agent": true, "workflow": "build", "writes": "product"},
    "gov-session": {"agent": false, "workflow": "handoff", "writes": "none"}
  }
}
```

`roles` holds every role, `agent` false included, so the guards can tell a known non-agent role from
an unknown name. `harnesses` is derived from the workflow table alone: the harness of each entry whose
`driver` is `workflow`, resolved, folded to a forward-slashed path relative to the toplevel,
de-duplicated and sorted. A `program` command and `none` contribute nothing. A harness the resolver
reports the tree does not hold is listed at the path it names, so the wiring check of
`TOOL-aOrientedCast-8` reads the absence from the index, and every mode prints
`render_agents: note — <path> is named by the workflow table and absent here; its kit is not installed`.

### The modes

- `--write` renders every owned file in memory first and writes nothing when any role, overlay or
  charter section fails to resolve. Then it writes each file whose bytes differ, unlinks each owned
  file the catalogue no longer renders, writes the index last, and prints one line per path written or
  unlinked, then the counts. Any agent-type change adds the S5 line:
  `render_agents: <n> agent type(s) changed — a Claude Code session started before this write cannot spawn the change; start a new session in this repository before spawning one.`
- `--check` renders the same set in memory and compares each owned path with the on-disk bytes, CR
  stripped on the disk side. It prints `render_agents: <a> agent type(s) and 1 index graded` with the
  derived counts, then one line per offender as `missing <path>`, `drift <path>` or `stale <path>`, and
  the remedy, `render_agents.py --write`, spelled through the derived kit directory. It writes nothing.
- `--selftest` builds a small catalogue in a `tempfile.TemporaryDirectory`: role files, overlays, a
  workflow table, a conf naming a governing doc, that doc, and one stub script per `workflow`-driver
  harness so the library resolves it. It renders into that directory, and asserts the arms of §4
  "Self-test arms". Each assertion increments one counter; the last line is `PASS (<n> assertions)`
  or `FAIL (<n> assertions)` with exit 1.

A zero-role catalogue exits 2 in every mode, because a render of nothing compares clean against an
empty directory. Every function below `main` takes the kit directory, the tool root and the target
root as arguments, so the self-test points them at its fixture. `main` derives them for the real
modes: the kit directory is `git rev-parse --show-prefix` run in the script's own directory, the tool
root is its parent, and the target root is `git rev-parse --show-toplevel`. No `tools/` literal is
spelled, and the governing doc is whatever `resolve_charter_path` answers.

### Self-test arms

1. Every rendered type carries `omitClaudeMd: true`, `workflow` and `writes` equal to its role's.
2. A role with `agent` false renders no type, and the index carries it with `"agent": false`.
3. An empty overlay adds no `## House rules`; a one-line overlay adds the heading and the line.
4. A `charter` list of two ids appends both blocks in list order, and an empty list adds no
   `## Charter`.
5. `harnesses` holds a harness once though two `workflow` entries name it, and holds no `program`
   command and no `none`.
6. `--check` over a temporary render with one byte appended to a type reports `drift` for that path
   and leaves its bytes unchanged.
7. A name listed in the on-disk index that the catalogue no longer renders is `stale`, and `--write`
   unlinks it while a foreign file beside it keeps its bytes.
8. A zero-role catalogue exits 2.
9. A CRLF copy of a correct render reads fresh.
10. A `workflow` harness whose script the fixture does not hold prints the `note` line naming it, is
    listed in `harnesses` at the resolver's path, and `--write` still writes every type and exits 0.

### The probe re-run

The instrument of the agent-type probe record, re-aimed at the rendered types and run after S7's
render exists, with three changes and the reason for each.

1. Clone: `git clone --local` of this worktree at the pass's commit to `%TEMP%/oc3r`, a short root,
   because a clone under the scratchpad hits MAX_PATH. If the pass has not committed yet, the rendered
   `.claude/agents/` files and the index are copied into the clone before the session starts.
2. One line appended to the clone's governing doc, the file `CLAUDE.md` imports:
   `PROBE-SENTINEL: the codeword for this repository is <a fresh codeword>.` It lands after the doc's
   last heading, outside every `§` section, and after the types were rendered, so no charter block of
   §8 F1 carries it into a type's body.
3. Gov's `.claude/settings.json` in the clone gains a logger hook on `PreToolUse` with matcher `*` and
   one on `SubagentStart`. CHANGE: every tool is logged, not only `Write`, because the rendered roles
   tell their agents to read documents, and a role agent that READ the governing doc would report the
   codeword without its context holding it. The logger writes `hook_event_name`, `tool_name`,
   `agent_id`, `agent_type` and `tool_input.file_path` per call and always exits 0.
4. One `claude -p --permission-mode bypassPermissions` session, started after the render is in place.
   Six arms with one task text, each writing to `probe-out/<arm>.txt` at the clone root, outside
   `ROUTED_PATHS`. CHANGE: the custom arms are the rendered types, not hand-written probes.
   - a1: `Agent`, `general-purpose` (control).
   - a2: `Agent`, `gov-builder`. a3: `Agent`, `gov-spec-writer`.
   - w1: `Workflow`, `agentType: 'gov-builder'`. w2: `Workflow`, `agentType: 'gov-spec-writer'`.
   - w3: `Workflow`, no `agentType` (control).
5. The task text: "This is a probe, not a build. Without reading any file and without running any
   command, write into `probe-out/<arm>.txt` the codeword named by any PROBE-SENTINEL line in your own
   starting instructions or context, or `NONE`." CHANGE: the no-command clause, because a builder role
   is told to verify with commands.

An arm is VALID only when its log holds one `SubagentStart` line and one `PreToolUse` `Write` line on
one `agent_id`, and no other `PreToolUse` line on that id before the `Write`. A role arm PASSES when it
is valid, its `agent_type` is the role's name on both lines, and its file reads `NONE`. The criterion
needs both controls valid and reading the codeword; a control reading `NONE` is a DEAD PROBE, because
the sentinel reached no context at all, and is never a pass. The record names the CLI version from
`claude --version` in the clone, the clone's commit and the codeword, and carries the logger and the
Workflow script as fenced blocks, so the instrument is in the tree beside its rows.

This probe runs before `TOOL-aOrientedCast-7` lands. After it, a direct `Agent` spawn needs a rendered
handoff, and a later re-run renders one per role arm.

### Alternatives rejected

- **Owning every file under `.claude/agents/`.** An adopter keeps agent definitions of its own there,
  and a renderer that unlinked them on `--write` would destroy them. Ownership is the catalogue's names
  plus the on-disk index's, which is exactly the set a previous render wrote.
- **A marker key in each rendered type to mark ownership.** It respells interface 9's key set, and the
  index already records every name a render wrote.
- **A plain byte compare with no CR strip.** A worktree checkout can land CRLF on a pinned path while
  `git status` stays clean (`tools/check-wiring.sh:989`), and the leg would then red every type on a
  file nobody touched. The pin governs the committed bytes; the strip governs the comparison.
- **The checks inside `TOOL-aOrientedCast-1`'s checker, as one leg.** The checker grades the catalogue
  against its grammar and runs with no generated file present; this grades generated output against
  the catalogue. Two questions, and a role edited without a re-render must name the renderer as its
  remedy, not the grammar.
- **A `.js` test over every harness value instead of the `workflow` driver.** The library's checker
  already refuses a `workflow` driver whose harness is not a resolving `.js` path, so the driver is the
  one predicate and a second shape test would be a second answer.
- **A rendered type with no charter section**, interface 9 as pinned. §8 F1.

## 8. Open questions

- **F1 — Does a rendered agent type's body carry the charter sections its role's `charter` key names?**
  The brief's interface 9 pins the body as the rendered role. Under `omitClaudeMd` an agent holds only
  its system prompt and its task, and the charter sections reach it only inside a handoff's `## Task`
  (interface 7). A harness composes its own prompts and is passed agent types, not handoffs
  (interface 10), so every role agent a harness spawns would start with no charter section at all:
  the builder would lose the cross-OS rules and the commit-attribution trailer `TOOL-aOrientedCast-1`
  gives it §3 and §11 for. This respells interface 9, so it is raised here and not applied silently.
  - (a) Keep the pin. Harness-spawned role agents run with no charter section.
  - (b) Append the named sections after the rendered role, as `### charter §<n>` blocks under
    `## Charter`. Only interface 9's body moves; the handoff keeps its charter blocks, so its
    `task-sha` and the spawn guard's join are unchanged, and a native-typed handoff carries those
    sections twice. `--check` reds when a cited section changes, until a re-render.
  - (c) Each harness takes charter text in its args. It respells interface 10, adds an argument to two
    harnesses' public surface, which M3's veto 2 discards, and has every caller read the governing doc.
  Recommendation: (b). (c) is vetoed, and of the two survivors (b) satisfies the roles' stated charter
  needs on every spawn route while (a) satisfies them on one.
  RESOLVED (agent, 2026-10-11, delegated): (b), S2 and §4 "Data model". The duplicated sections in a
  native-typed handoff are accepted as the cost.
