# TOOL-cFinalBerth-1 — the terminal transition: LANDED as an observation, ABORTED as a record

**Status:** CLOSED · rev-4 · 2026-08-14 · node c · Tier-2 · base f006691f · streams tooling · ratified 2026-08-13

## 1. Goal

Give the unattended driver a way to reach its two terminal phases, so a run can finish and stop
being counted as live. `LANDED` becomes an observation of the remote rather than a claim, and
`ABORTED` becomes a recorded refusal rather than an abandonment.

## 2. Scope (IN)

- **S1** — **`--landed <slug>`**, the sole producer of `LANDED`. It refuses unless the record's
  current phase is `LANDING`; it observes the anchor and refuses unless HEAD is an ancestor of the
  tip the remote advertises; it writes the phase and a witness of HEAD, and stages the file. The
  anchor observation is fatal and its message is NOT suppressed — the call is `observe_anchor ||
  return 1`, so the operator reads the observation's own refusal rather than a downstream symptom.
- **S2** — **`--abort <slug> --reason <text>`**, the sole producer of `ABORTED`. It refuses a
  missing reason, refuses a record already terminal, requires BOTH agent-attested Definition-of-Done
  items — the keepalive reap and the parked-decision surfacing — writes the phase and a witness of
  HEAD, records the reason as a parked entry, and stages the file.
- **S3** — **`--landed` does not call the branch guard.** Landing happens on the default branch,
  because the mandated lander refuses to run anywhere else. Its observation is AC13, which stands on
  the default branch explicitly, because that is the only state distinguishing this item from a
  branch guard nobody removed.
- **S4** — **Leg check 15, in two halves with different preconditions.** The witness at `LANDED` is
  sha-shaped: checked per run-state file, OUTSIDE the anchor loop, beside check 5's presence test.
  The witness is an ancestor of the anchor: checked INSIDE check 9's existing anchor loop, and
  therefore silent where no BASE is recorded or no anchor ref resolves. The leg's own header count
  and the charter's gate-suite entry move with the new check — both read thirteen against fourteen
  today.
- **S5** — **`--phase` stops lying and stops un-finishing.** Its terminal refusal names the two
  producing verbs instead of `--close`, and it gains a second refusal: a record whose CURRENT phase
  is terminal cannot be moved at all. That is the third of the three recommendations the review
  finding cited in section 9 made, and this unit is the one that makes it reachable.
- **S6** — **The protocol and the Skill.** The shipped protocol template gains the two verbs in its
  verb section, a sentence in its phase section stating how terminal is reached, and an explicit
  narrowing: a claim of a TERMINAL phase carries a sha, because the ancestry assertion IS the claim.
  The installed copy moves with it, because the gate byte-compares the pair. The shipped Skill
  template gains the close-land-mark sequence, and its render is regenerated by the adopter.
- **S7** — **The kickoff engine's Step 5b names the abort verb.** It instructs an unattended run to
  write an abort reason to the run-state file, and until now no verb did that. The edit does not
  disturb the numbered exits the gate counts.
- **S8** — **The kit version and its markers.** Both script constants move to 1.4, and the stale
  marker in the shipped protocol document is corrected with them. The arms floors for both files
  rise to cover the new refusal branches.
- **S9** — **`LANDING` becomes close-only.** `--phase` refuses `LANDING` with its own named refusal,
  in the shape of the terminal refusal, so `--close` becomes its only writer. Without this, S1's
  precondition gates nothing: `LANDING` is an ordinary non-terminal vocabulary member today, so
  `--phase` writes it and `--landed` would reach `LANDED` with the Definition-of-Done never
  evaluated.
- **S10** — **The driver's three verb enumerations are brought to one set.** The header docstring,
  the usage line and the unknown-argument refusal all name the two new verbs, and the arm pinning
  that refusal's text moves with them. The usage line lists four verbs today and is already two
  behind.
- **S11** — **`park` gains a KIND argument.** It is hardcoded to the override grammar and has one
  caller. An abort reason routed through it unchanged would record the abort as a Definition-of-Done
  override in the one turn the owner gets.
- **S12** — **`ABORTED` leaves check 9's work-claiming phase list.** An aborted run authorizes no
  landing, so a recorded base equal to HEAD buys nothing there — and a run that aborts before its
  first commit otherwise reds the bar with its own abort record.
- **S13** — **ONE terminal guard, shared by every verb that writes a phase.** The rule was spelled at
  each call site and was therefore missing from two of the five writers: `--close` re-opened a
  finished record to `LANDING` printing success, and `--preflight` preserved the terminal phase while
  rewriting the witness. Both are now the same single branch, and the self-test DERIVES the
  phase-writer population from source and drives a finished record through every member.
- **S14** — **An abort reason may not spell the declared bypass flag.** `park` writes the reason
  verbatim into the file leg check 11 greps whole, so a truthful reason naming the flag would red the
  bar permanently on a record no verb can rewrite.
- **S15** — **Check 15's second half judges only sha-shaped, resolving witnesses.** `fail` does not
  `continue`, so it ran on the witness the first half had just rejected and the record red twice with
  two contradictory sentences; and its resolvability branch was a second answer to check 6's question.

## 3. Non-goals (OUT)

- **Unwedging the existing run.** The record at `aSealedCaravan` was at `BUILDING` when this unit was
  written and this unit does not move it. Unit 2's S7 repairs it directly, and it now reads `LANDED`.
- **Gating the shipped protocol document's version marker.** The version pairing covers the
  unattended kit's two script constants and not the doc it ships, which is why the marker drifted
  unnoticed. This unit corrects the value; a gate is a separate mechanism and a separate unit, filed
  as a backlog row.
- **The leg's anchor independence**, owned by the open row `TOOL-aStandingWrit-6`. Distinct from
  what S4 discloses: check 15's ancestry half inherits check 9's SILENT skip where the anchor does
  not resolve, which is an ABSENT ref rather than a forged one, and is owned by nobody today. The
  three named refusals the `aMooredAnchor` spec scoped for those exits did not land with it.
- **A cross-component arm** that drives the driver and then the leg over one tree, owned by the open
  row `TOOL-aStandingWrit-8`.
- **Any change to the Definition-of-Done set or the phase vocabulary.** Both terminal members
  already exist; the core floors do not move.
- **Automating the records commit and the second push.** The verb writes and stages; committing and
  landing that commit is the operator's act, as it is for every other record this kit writes.

## 4. Design

### Data model

No new authored key. Both verbs write the two keys the file already carries, the phase and its
witness, through the existing fact writer. `park` gains a leading KIND argument so an abort entry is
distinguishable from an override entry; its one existing call site passes `override`, and `--abort`
passes `abort`. Nothing else new is recorded, because nothing new is observed that the phase and its
witness do not already express.

### The transition, and why it is shaped this way

The kit's own history decides the shape. The review finding recorded as F2 in the `aStandingWrit`
review established that `--phase` could reach `LANDED` from any phase, skipping the entire
Definition of Done — including the two items enforced nowhere else. Its recommended fix opens with
the words *a precondition, not a blanket rejection* and then supplies a code snippet that is a
blanket rejection. The snippet shipped and the precondition did not, which is why no verb produces a
terminal phase today.

This unit restores a producer without restoring the hole. `--landed` accepts only a record at
`LANDING`, and S9 makes `--close` the only writer of `LANDING` — it is NOT one today, which is the
whole reason S9 exists. Both halves are required: the precondition without S9 is satisfied by one
`--phase` call, and S9 without the precondition leaves `--landed` ungated.

The observation is the second half. A phase claim carries a witness because an unwitnessed claim is
the cheapest possible lie. A terminal claim of landing deserves more than a witness the run picks:
`--landed` re-observes the anchor and asserts that HEAD is an ancestor of the advertised tip. That is
the machine-checkable form of *this work is on the branch the remote calls its default*. It is not
proof against a run that seeded its own endpoint — the protocol's own boundary section enumerates
that — and the design claims nothing further.

`--abort` requires both agent-attested items and none of the four machine-checked ones. An aborted
run landed nothing, so the machine items assert obligations it does not have. It still owes both
attestations: the keepalive, because the store is session-scoped and an unreaped job is orphaned
where no later run can see it; and the parked-decision surfacing, because an abort is the maximal
case of decisions the owner never saw, and the build method derives the owner's only turn from those
entries. The ordering objection does not exempt it — `--close` demands the same attestation before
its own wrap-up, so the circularity is identical and was accepted there.

### Alternatives rejected

**Relaxing `--phase` to accept `LANDED` from `LANDING`.** Eight lines, no network, and it closes the
same hole. Rejected by the owner at the build's fork F1 because the terminal claim would remain an
agent assertion in a kit whose discipline is that a claim carries a checkable witness.

**Keying `--landed` on a close OUTCOME** — a fact `--close` writes — rather than on the phase.
Rejected because that fact would be run-written exactly as the phase is, which is the one-line
escape this kit already records against phase-keyed carve-outs. S9 achieves the same integrity by
narrowing who may write the phase.

**Letting `--close` write `LANDED` directly.** Rejected on sequence: `--close` runs before the push
it authorises, so it cannot know the landing happened.

**A leg check that skips terminal records.** Rejected because the `aMooredAnchor` spec already
rejected it in writing, for a reason that still holds: the phase is run-written, so a phase-keyed
carve-out is a one-line escape.

## 5. Production-readiness checklist

- security — the new surface is one remote observation and two record writes; no credential and no
  network write. S9 and S5's second refusal both TIGHTEN an existing verb.
- perf / scale — one remote listing per `--landed` call, on a verb invoked once per run.
- a11y — N/A — a shell driver with no user interface.
- i18n — N/A — this repo's tooling is English-only by charter.
- error / empty / loading states — every new branch is a named refusal; the anchor-observation
  failure reports in the observation's own words rather than as a downstream symptom.
- observability — both verbs print the phase and its witness on success, matching `--phase`.
- risks — the only rollback hazard is a record marked terminal in error, recoverable by editing the
  authored region; no data migration, no destructive write.
- testing + left-shift gates — a positive arm per new refusal branch in both sibling suites, arms
  floors raised to pin them, and AC14 covering the check-15 half that must fire with no anchor.
- migration / rollback — no existing record changes shape; rollback is a revert, after which the
  tree returns to having no terminal producer.
- user docs — the protocol, the Skill render and the kickoff engine's Step 5b move in S6 and S7, and
  their observations are AC20 and AC21 rather than the green bar, which cannot see them.

## 6. Acceptance criteria

- **AC1** — When `--landed` runs against a record whose phase is not `LANDING`, it refuses naming
  the phase it found, and the record is byte-identical afterwards.
- **AC2** — When `--landed` runs at `LANDING` in a tree whose HEAD is not an ancestor of the tip the
  remote advertises, it refuses naming both shas, and the record is byte-identical afterwards.
- **AC3** — When `--landed` runs at `LANDING` with HEAD published, the record reads phase `LANDED`,
  its witness equals HEAD, and the file is staged.
- **AC4** — When `--abort` runs with no reason, it refuses, and the record is byte-identical
  afterwards.
- **AC5** — When `--abort` runs against a record already terminal, it refuses naming the phase.
- **AC6** — When `--abort` runs with a reason but either agent-attested item unattested, it refuses
  naming the item as agent-attested; the control is that attesting both lets it through.
- **AC7** — When `--abort` runs with a reason and both attestations, the record reads phase
  `ABORTED`, its witness equals HEAD, the reason appears in the parked region, and the file is
  staged.
- **AC8** — When the leg runs over a fixture carrying a recorded BASE and a resolvable
  remote-tracking anchor, holding a record at `LANDED` whose witness is not an ancestor of the
  anchor, check 15 fires; when the witness is an ancestor, it is silent.
- **AC9** — When the leg runs over a tree holding a record at `LANDED` whose witness is not
  sha-shaped, check 15 fires.
- **AC10** — When `--phase` refuses a terminal phase, its message names the two producing verbs, a
  grep for the retired sentence naming `--close` as the producer returns nothing, and the driver's
  three verb enumerations list the same set.
- **AC11** — `bash tools/run-gates.sh` is green, including the arms meta-gate at the raised floors
  and the kit-version pairing at 1.4.
- **AC12** — When `--phase` is asked for `LANDING`, it refuses naming `--close` as its sole
  producer, and the record is byte-identical afterwards.
- **AC13** — When `--landed` runs at `LANDING` with the default branch checked out, it writes
  `LANDED`; the arm stands on the default branch explicitly, because that is the only state that
  distinguishes S3 from a branch guard nobody removed.
- **AC14** — When the leg runs over a `LANDED` record in a fixture with the default-branch
  environment variable unset and the remote HEAD symref absent, the sha-shape half of check 15 still
  fires.
- **AC15** — When `--abort` runs with the keepalive attested but the parked-decision item not, it
  refuses naming that item.
- **AC16** — When `--phase` runs against a record at `LANDED`, it refuses naming the current phase,
  and the record is byte-identical afterwards.
- **AC17** — When the leg runs over an `ABORTED` record whose recorded BASE equals HEAD, check 9 is
  silent; the control is that `LANDING`, `LANDED` and `VERIFYING` still fire.
- **AC18** — When `--landed` runs where the anchor cannot be observed, it refuses printing the
  observation's own refusal text, and the record is byte-identical afterwards.
- **AC19** — When `--abort` runs with a reason, the parked region gains a dated line naming the
  entry as an abort, and the word `override` does not appear in it.
- **AC20** — A grep for the two new verbs in the shipped protocol template and in the installed
  protocol copy returns a hit in each, in the verb section and the phase section.
- **AC21** — A grep for the abort verb in the kickoff engine returns a hit inside Step 5b, and check
  12's exit count is unchanged.
- **AC22** — When each verb that writes a phase is run against a finished record, it refuses with the
  shared guard's text and the record is byte-identical; the population is derived from the
  `set_fact … phase` sites in source and a count mismatch reds, so a sixth writer cannot be added
  without being driven.
- **AC23** — When `--abort` is given a reason spelling the declared bypass flag, it refuses naming the
  flag and writes nothing; the control is that an ordinary reason is accepted and leaves no occurrence
  of the flag in the record.
- **AC24** — When a `LANDED` record carries a non-sha witness, check 15 fires ONCE — the shape half —
  and the ancestry half is silent; when it carries an unresolvable sha, check 6 fires and check 15 is
  silent.
- **AC25** — When `--abort` refuses an unmet agent-attested item, its message names the RECORD KEY the
  driver reads, not only the Definition-of-Done item name.

## 10. Reuse audit

The reuse probe over *record a terminal phase after a run has landed on the remote* returned no
function-level seam for the transition itself; its top-ranked hits are unrelated name stems, and its
one relevant answer is the affordance seam this unit already sits on, the project declaration file.
So the seams are named from source rather than from the probe, and each was verified against the
file at this spec's base:

- `observe_anchor` in the driver — reused by `--landed`, with its refusal made fatal and unsuppressed
  per S1. Resolving a second anchor is the second-implementation class this kit has a gotcha record
  for.
- the fact writer and the stager in the driver — reused for the writes, so the new verbs add no file
  mutation path of their own.
- `park` in the driver — reused, with the KIND argument S11 adds, rather than a second parked-entry
  writer.
- check 9's anchor loop in the leg — check 15's ancestry half is placed inside it rather than beside
  it, so there is one anchor resolution in the leg. Its sha-shape half is placed outside, beside
  check 5, because it needs no anchor.
- check 5's per-file witness-presence test — the placement precedent the sha-shape half copies.

Recall terms used, recorded here because composing them is the expensive half and a regrounding
re-runs the query: unattended, terminal, phase, LANDED, ABORTED, close, verb, driver, run-state,
vocabulary, witness, landing, keepalive. The query returned the two review records above as its top
two hits, which is what made the root cause verifiable rather than reconstructed.
