### The marked scan (S1, S2)

govkit lands the review-harness kit's templates beside their renders, because its `**` engine rule
pools every tracked file under the home (`tools/govkit/govkit.py:6664-6667`) and the rendered rules
claim only the render destinations (`tools/workflows/kit.toml:61-91`). The kit's `kit.toml` lands

```python
#: A harness the resolver did not hold while its kit's own copy sits elsewhere under the tool root.
MISPLACED_LINE = ("render_agents: misplaced %s — the workflow table names it and it is absent "
                  "here, while its kit holds it at %s; the kit resolver did not find it")


def read_kit_home(descriptor):
    """The `home` a `kit.toml` declares, or None when it is absent, unreadable or not TOML."""


def scan_misplaced_harnesses(absent, tool_root, target_root):
    """`{rel: [found rel, ...]}` for each absent harness whose file sits directly inside a directory
    under the tool root beside a mark of its kit: the harness's template, `<stem>.template<suffix>`,
    or a `kit.toml` declaring the home its listed path names. Any other harness is not a key."""
    misplaced = {}
    for rel in absent:
        listed = pathlib.PurePosixPath(rel)
        template = listed.stem + ".template" + listed.suffix
        hits = [pathlib.Path(os.path.relpath(str(d / listed.name), str(target_root))).as_posix()
                for d in sorted(pathlib.Path(tool_root).iterdir())
                if d.is_dir() and (d / listed.name).is_file()
                and ((d / template).is_file() or read_kit_home(d / "kit.toml") == listed.parent.name)]
        if hits:
            misplaced[rel] = hits
    return misplaced
```

`read_kit_home` parses with `tomllib`, as `roles_lib.load_workflows` does
(`tools/roles/roles_lib.py:337-351`), and answers None on `OSError`, a decode error or a non-string
`home`. The listed path's home is its parent directory's name, because `resolve_harness_path` spells
an unheld harness `<tool root>/<home>/<file>` (`tools/roles/roles_lib.py:588-597`). `run_mode`
(`tools/roles/render_agents.py:264-280`) is unchanged.

**The kit.toml mark keys on `home`, not on `id = "review-harness"`.** The brief and the skeptic's
fix spell the id. The roles kit holds no map from a harness's home to a kit id, so the id would be a
typed literal of a fact another kit's descriptor owns. The home is the listed path's own segment and
the resolver's join key, and the same descriptor declares it (`tools/workflows/kit.toml:4`). The
test the brief asks for is unchanged: the directory shows the file is that kit's own.

At a root install the tool root is the repository root, so the scan walks every top-level adopter
directory. A directory with no mark contributes nothing, which is L1's case.

The arms build on `build_fixture` (`tools/roles/render_agents.py:297`), each in its own
`tempfile.TemporaryDirectory`. Every marker is derived from `listed`, never typed: a literal kit
segment followed by a file is an install-prefix hit (`tools/check-install-prefix.sh:47-48`).
