## HIGH

### H1 — The owner-stop writer admits a path its own reader refuses (ids 3, 5, 11)

`tools/unattended/unattended.sh@cfda7001:13718` (writer) against `tools/unattended/unattended.sh@cfda7001:13858` (reader).

**What is wrong.** `write_chain_round` strips the literal prefix `$M/builds/$slug/prompts/` at `:13717` and holds only the remaining file name to `^[A-Za-z0-9._-]+$` at `:13718`. It then writes the whole `$path` into the row (`round N · owner-stop · record <path>`). The reader, `derive_chain_verdict`, admits that row only when the whole path matches `^record [A-Za-z0-9._/-]+$`. `$M` is `MEMORY_ROOT`, a value sourced from `.unattended.conf` and held to no charset anywhere in the kit. The slug is held by `check_slug`, so the memory root is the one untested segment. The two patterns are one rule written twice, and they disagree.

**Consequence.** In an adopter whose memory root holds a character outside the reader's class (`+`, `@`, `~`), `--record-round <slug> --owner-stop <path>` exits 0 and stages the row. Every later `--chain-verdict` and `--dispatch` for that build then fails check 118 with "a body row is outside the grammar ... so it was edited by hand", blaming a hand edit for a row the verb wrote. The row can be removed while it is only staged. Once it is committed, `check-unattended.sh`'s append-only test reds its removal, and the build's chain record is wedged. The finder for id 11 ran it end to end with `MEMORY_ROOT=mem+ory`: the write printed `chain round recorded — dFix · round 1` with rc=0, and the next `--chain-verdict` printed the check 118 fault with rc=1. The path is narrow: gov's own root is `memory`, and the result is a refusal, never a wrong verdict.

**Grades.** Id 11 is HIGH: a wrong result on an unlikely path. Ids 3 and 5 are MEDIUM, graded on the containment to one build's chain record. All three are binding and kept; the item takes the highest.

**Fix (judged SOUND by the skeptic for ids 3, 5 and 11).** Make the writer test what the reader tests before the first byte. Add `[[ $path =~ ^[A-Za-z0-9._/-]+$ ]]` to the guard at `:13718`, folded into the existing folder-or-charset refusal so no new fail site appears. Better, hoist the one charset into a shared variable that the bash test reads and the awk takes with `-v`, as `CHAIN_SEVERITIES` already is, so the two cannot drift. Add a suite arm with `MEMORY_ROOT` set to a root holding `+`: run `--record-round --owner-stop`, assert the refusal and that no record was left.

**Left-shift.** Class `two-guards-one-question-two-answers`. The gate is the arm above plus the shared constant: with one charset variable there is no second copy to disagree. A wider gate, if wanted, is a charset test on `MEMORY_ROOT` where the conf is read; no finding asked for it.

### M1 — The owner-stop route runs the audit route's count test with empty operands (ids 4, 12)

`tools/unattended/unattended.sh@cfda7001:13768`.

**What is wrong.** `[ "${#b_ids[@]}" -lt "$blockers" ] || [ "${#h_ids[@]}" -lt "$highs" ]` is unconditional. On the owner-stop route `blockers` and `highs` are always empty, because the mixed-flag refusal at `:13713`-`:13716` requires it. Both tests therefore error, and the route passes only because a `[` error status of 2 reads as false. The test existed at the base, where all four flags were required on every call; this diff made the empty-operand path reachable.

**Consequence.** Every successful `--record-round <slug> --owner-stop <path>` prints `[: : integer expected` twice on stderr before its success line. The row itself is correct. The pass rests on an error status and not on a branch, so a later edit that negates or reorders the test turns it into a refusal or a silent pass. The suite cannot see either: `run_chain` at `tools/unattended/unattended.test.sh@cfda7001:2811` sends stderr to `/dev/null`, and the CS1 arms assert only stdout and rc. Id 12's finder observed the two lines from the verb itself in the spec's fixture.

**Fix (judged SOUND by the skeptic for ids 4 and 12).** Put the count test on the audit route only: wrap `:13768`-`:13771` in `if [ -z "$path" ]`, or prefix it `[ -n "$path" ] ||`. Defaulting the operands (`${blockers:-0}`, `${highs:-0}`) is the other sound form. Then add one CS1 arm that captures the stderr of a successful `--owner-stop` call, outside `run_chain` or with `2>&1`, and asserts it is empty. The build must see that arm red against the current bytes first.

**Left-shift.** New class `shared-tail-guard-reached-with-empty-operands`: when a verb gains a route that skips required flags, every test below the fork that reads those flags is re-read. The gate is the stderr-empty arm; a success arm that discards stderr certifies nothing about it.
