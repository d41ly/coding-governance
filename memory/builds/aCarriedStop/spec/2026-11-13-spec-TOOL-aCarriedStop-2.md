### The rule

A path is admitted when all of these hold, tested in this order ahead of the index test:

1. Stripping `$M/builds/$slug/prompts/` from its head changes it. This is today's prefix test.
2. What remains is not empty and holds no `/`. This is what the name's charset test proved beyond
   the class: a file directly under the folder.
3. The whole path matches `^$CHAIN_PATH_CLASS+$`.

Tests 2 and 3 together admit the paths the old name test admitted, whenever the root and the slug
sit inside the class: a name is inside the class less `/` exactly when it holds no `/` and the
path it ends is inside the class. `check_slug` already holds the slug. The one input whose answer
moves is a memory root with a character outside the class, which is the defect.

The guard at `tools/unattended/unattended.sh@cfda7001:13718` becomes one compound test with one
refusal, in the place it has:

```bash
{ [ "$named" != "$path" ] && [ -n "$named" ] && [[ $named != */* ]] && [[ $path =~ ^$CHAIN_PATH_CLASS+$ ]]; } || { check_chain_fault "--owner-stop names no file directly under this build's prompts folder, or its path leaves $CHAIN_PATH_CLASS, so the row would cite nothing a reader can open: $path"; return 1; }
```

The reader's call gains `-v pathre="^record $CHAIN_PATH_CLASS+\$"` beside `natre`, and its branch
reads `f[3] ~ pathre` where it held the literal pattern. No backslash reaches awk, so its `-v`
escape processing changes nothing.

Every path the writer admits therefore matches the reader's pattern by construction: the row is
`record `, then the path, and both tests expand one variable. The safe direction is also kept if a
later edit narrows the writer further, because the reader can only admit more than the writer.

Both forms were applied to a scratch copy of the driver on 2026-11-13 and run in the probe
fixture. Under `mem+ory` the verb exited 1 with the refusal above and left no record and no
`build/` folder. Under `memory` the verb, the verdict, the five refusals of AC2 and the reader's
refusal of AC3 answered as §6 states.

### Alternatives rejected

- **Add the whole-path test and keep the name's charset test.** It is the review's first form and
  it closes the defect. The driver would then spell two classes for one path, and the second form
  the review prefers, one shared spelling, would hold for the reader only.
- **Keep the refusal's text.** It would tell an adopter that a file name left a class when the
  memory root did.
- **A second refusal value for the root.** One wording is true of every case, so a second value
  adds a branch and a suite arm for no reader.
- **Test `MEMORY_ROOT` at the conf's read.** It refuses every verb of the driver in an adopter
  where only this one is affected, and no finding asked for it.
- **Widen the reader to whatever git tracks.** The class is what keeps the separator and the `|`
  field mark out of a line the verdict splits.
