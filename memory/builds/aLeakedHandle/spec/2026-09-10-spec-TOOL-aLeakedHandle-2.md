## 1. Goal

`tools/run-gates/derive-ceilings.py` builds its evidence from `ok` rows only, so a leg that has never
finished inside the retained window acquires no row and its ceiling is held above nothing. Admit the
one class of failing row whose seconds are a measurement of the work — a run that reached the leg's
own declared ceiling — so the gate that exists to catch an unsafe ceiling stops passing on the bar
where that ceiling fired.

## 2. Scope (IN)

- **S1** — `read_runs` admits a non-`ok` row when its seconds reach the leg's declared ceiling, and
  keeps excluding every other failing row. The docstring states the rule and states what the rule
  cannot distinguish. Observed by AC1, AC2 and AC5.
- **S2** — `cmd_check`'s failure line for a leg whose evidenced maximum is at or above its own
  ceiling says the ceiling was REACHED in a recorded run, instead of quoting headroom arithmetic
  over a number that is a lower bound rather than a duration. Observed by AC3.
- **S3** — four arms in `tools/run-gates/run-gates.evidence.test.sh`, each run against a COPY of the
  kit so no arm can write the tracked artifact, and each with its failing case observed RED before
  it lands. Observed by AC4.

## 3. Non-goals (OUT)

- **No ceiling is re-declared, raised, lowered or re-measured.** `aJoinedCanon` parked the raise-or-
  optimise question for `memory-hygiene self-test` with the owner on 2026-09-07, and
  `TOOL-aPooledSweep-4` carries a second reading of the same leg. This unit fixes the evidence
  pipeline and touches no number in `tools/gate-legs.json`.
- **`tools/run-gates/ceiling-evidence.txt` is NOT refreshed by this unit.** Refreshing it on a tree
  holding a reading at a ceiling turns that leg's gate row red, and the only remedies are ones the
  bullet above forbids. The artifact is regenerated by whoever answers the parked question. §4
  Rollout records why this is a decision rather than an omission.
- **No change to the format of the tracked artifact.** A censored reading is told apart from a
  completed one by comparing it to the ceiling at check time, so nothing is stored that could drift
  from what the comparison would say.
- **No change to what the runner records.** The `.leg` row already carries the verdict, the exit code
  and the seconds. This unit reads them differently and writes none of them.
- **No claim about WHY a leg reached its ceiling.** Slow, contended and hung are three causes with
  one signature in the record, and §4 states the consequence rather than inventing a discriminator.

### Edges

- **consumes-from** external — the retained `<git-dir>/gate-run/` window must still hold a reading at
  a ceiling for AC5 to be observable on the live tree. That window is node-local and the runner
  prunes it, so AC5 carries a fixture line and every other criterion is observed on a built fixture.
- **hands-off** external — the refresh of the tracked evidence artifact, and any ceiling decision it
  then forces, stay with the owner.

## 4. Design

### Data model

A `.leg` row is written by `runleg` in `tools/run-gates/run-gates.sh` as seven tab-separated fields:
name, status, rc, seconds, started, ended, key. `status` is `ok` when rc is 0 and `fail` otherwise,
so the row records what happened and not what caused it. `read_runs` reads fields 1, 2 and 4 today.
The change adds one comparison against a fifth number that is not in the row at all — the leg's
`ceiling` in `tools/gate-legs.json`, which `read_legs` already loads for every command path that
calls `read_runs`.

The admission rule becomes: a row counts when its status is `ok`, OR when its seconds are at or above
the ceiling that `tools/gate-legs.json` declares for that leg today. A leg with no integer ceiling
admits `ok` rows only, because there is nothing for a failing row to have reached.

### Why the elapsed comparison is the discriminator, and the exit code is not

The existing filter's stated reason is correct and stays correct: a leg that failed fast measures the
failure and not the work, and a monotone maximum that admits it holds every ceiling above a number
nothing did. The live window on node `a` carries five such rows, from 1.8 s to 39.5 s, plus
`govkit selftest` failing at 1177.363 s under an 11750 s ceiling. Every one of them stays excluded.

What the filter also excludes is the row where the CLOCK stopped the leg. `memory-hygiene self-test`
carries two of those in the same window, 900.481 s and 900.240 s, both rc=124, against a declared
ceiling of 900. A run that reached the ceiling did not stop for anything the leg decided; it stopped
because the bound expired, so its seconds are a lower bound on the work — the one property a monotone
maximum needs, and the property `ok` rows are admitted for.

**The exit code cannot carry that distinction and the elapsed time can.** rc=124 is what GNU
`timeout` reports when its deadline expires, and `run-gates.sh:1395` wraps every bounded leg in
`timeout -k 5s "$bound"`. But rc=124 is also what a leg exits when it runs a `timeout` of its own
that fires early, and the row carries no field saying which bound expired. rc=137 is weaker still: it
is SIGKILL, which an operator, an OOM killer or a CI cancel produce as readily as a `-k` escalation.
`TOOL-aLeakedHandle-3` establishes that the runner's own rc=137 branch mislabels such a kill as a
full-ceiling timeout, so the reporting side cannot be used as a witness for the recording side.

So the rule tests neither code. It tests whether the run reached the bound, which is a fact about the
row and the manifest and needs no belief about signals. The three cases settle themselves:

| row in the live window | rc | seconds | ceiling | admitted | why |
|---|---|---|---|---|---|
| `memory-hygiene self-test` | 124 | 900.240 | 900 | yes | the bound expired; the seconds bound the work |
| `unattended kit gate` | 137 | 4168.392 | 16040 | no | killed at a quarter of its bound, so no bound expired |
| `govkit selftest` | 1 | 1177.363 | 11750 | no | the leg stopped itself well inside its bound |

The rc=137 row is refused by the elapsed comparison alone, without trusting or distrusting the
signal, which is the answer this unit wants: a 137 row at or above its ceiling would be admitted on
exactly the same terms as a 124 one, because on those terms it is the same observation.

### What the rule cannot tell apart, stated in the docstring

A run that reached a ceiling is a slow leg, a contended leg or a hung leg, and the record holds one
signature for all three. `TOOL-aSurfacedLexicon-22` measures the trap precisely: `pass-order history`
costs 267 s standalone and was killed at 5400 s on a contended bar, and that row was twice written up
from contended figures read as the leg's cost. The evidence file is MONOTONE, so a contended or hung
reading admitted once holds a floor under that ceiling until somebody lowers it.

This unit does not invent a discriminator for that, for two reasons. The runner records nothing that
would support one — the pool width and neighbour count `TOOL-aSurfacedLexicon-22` asks for are not in
the `.leg` row, and adding them is that row's own candidate. And the escape already exists and is the
right shape: `--write --reset <leg>` lowers a row and, by the file's own header, records that
somebody chose it. The docstring says all of this where the predicate is, so a reader who meets a
surprising row is told what it does and does not mean.

### Why this is not the inference that was withdrawn

`TOOL-aReapedSpinner-23` was withdrawn for inferring, from one contended bar, that a class of
ceilings was mis-declared. The gate this unit repairs makes no such inference. It reports that a
declaration and a record disagree; it names no cause and prescribes no remedy, and whether the answer
is a bigger number, a cheaper suite or a quieter box stays outside it.

The stronger point is that the disagreement is already resolved in this repo's own tracked
declaration, and only the code dissents. `tools/run-gates/ceiling-margin.txt` sets the 1.0 fraction
against a worked example: `pass-order history` ran 5400.8 s against a 5400 ceiling, "IT WAS KILLED BY
ITS OWN BOUND", and "A 1.0 fraction demands 10802 there and catches it". It catches nothing.
`ceiling-evidence.txt` has no row for that leg at all, because the reading the margin was sized
against is the exact class `read_runs` discards. This unit makes the code agree with the declaration
sitting beside it.

### The check-time message

`cmd_check` already reds a ceiling below `evidenced_max + margin`, and a reached ceiling is a strict
sub-case of that, since the required headroom is never below the 120 s floor. So S2 changes no
verdict anywhere. It changes the sentence: for `row_max >= ceiling` the line says the ceiling has
been REACHED in a recorded run and that the figure is a lower bound rather than a duration.

The sentence matters because the arithmetic reads as an invitation to double a number that is not the
leg's cost. `memory-hygiene self-test` would report an evidenced maximum of 900.5 s while
`TOOL-aPooledSweep-4` measured the same suite completing in 972 s and 1126 s. An operator who sizes a
new ceiling from 900.5 sizes it from the bound, not from the work. Getting a wrong number out of a
diagnosis is what this build exists for.

The test is DERIVED at check time from the two tracked files, so there is no stored flag to keep
fresh and no way for the message to disagree with the row. It is also honest about an `ok` row above
its ceiling, which is what an inert-ceiling host produces: that row is not a kill, and "reached in a
recorded run" is true of it as well.

### Inventory

No function, method or class is defined by this unit, in either the python or the shell layer, so no
lexicon cell is engaged. `read_runs` gains a parameter and keeps its name; `cmd_write` gains one call
to the existing `read_legs`. The shell arms mint fixture leg names inside the suite's own scratch
manifest, which is data the fixture reads and not a declared surface.

### Rollout

The diff cannot change any verdict on the tree it lands on. `cmd_check` never calls `read_runs` — it
reads `tools/gate-legs.json` and `tools/run-gates/ceiling-evidence.txt` and nothing else — and S2's
branch is unreachable while every tracked row sits under its ceiling, which `--check` exiting 0 today
confirms. What the change alters is what a future `--write` or `--report` admits.

That is also why the tracked artifact is not refreshed here. A `--write` on this worktree today would
add a row for `memory-hygiene self-test` at 900.5 s, and `--check` would then red it, short by 900 s,
against a ceiling §3 forbids this unit to touch. Landing the pipeline fix and leaving the artifact
for whoever answers the parked question keeps the merge bar honest in both directions: nothing is
suppressed, and no red is manufactured on a number nobody is allowed to move.

### Alternatives rejected

- **Admit every failing row.** The filter's original reasoning holds for a leg that stopped itself,
  and the monotone file would carry a fast failure's duration as a floor forever.
- **Admit on rc alone, 124 or 124-and-137.** It grades the exit code rather than the observation, it
  trusts a signal number the runner itself mislabels, and it admits a leg's own inner timeout firing
  at three seconds under a nine-hundred-second bound.
- **Store a censored flag in a sixth evidence column.** A stored fact that a two-file comparison can
  derive is a fact that can go stale, and it changes a tracked format for nothing.
- **Fail on an unbacked ceiling as part of this unit.** A separate policy change with its own blast
  radius, and it is §8 F1 rather than a silent rider here.
- **Write the arms against the installed kit.** `--write` writes to the script's own directory, so a
  test that reaches the real file rewrites the tracked artifact. Every arm runs a copy.

## 6. Acceptance criteria

- **AC1** — When the copied `tools/run-gates/derive-ceilings.py --report` runs over a fixture
  `gate-run` holding one `fail` row at its leg's declared ceiling and one `fail` row below it, the
  report prints a table row for the first leg and names only the second on its UNBACKED line.
  Red when: both are admitted, which is the ceiling comparison dropped, or neither is, which is the
  change absent.
- **AC2** — When that same fixture gives one leg an `ok` row below its ceiling and a `fail` row above
  it, the reported `max_s` for that leg is the failing row's seconds.
  Red when: the maximum is the `ok` reading, so admission happened but never reached the number the
  gate consumes.
- **AC3** — When the copied `derive-ceilings.py --check` runs against a fixture evidence file whose
  row for a leg is at or above that leg's ceiling, it exits 1 and its line for that leg says the
  ceiling was REACHED in a recorded run.
  Red when: the line still reads `does not clear its evidenced maximum` for a reached ceiling, or the
  run exits 0.
- **AC4** — When each arm's subject is reverted in place and `tools/run-gates/run-gates.evidence.test.sh`
  is re-run, that arm prints `FAIL` and the suite exits non-zero; the four observations are recorded
  before the reverts are unstaged.
  Red when: an arm passes with its subject reverted, which is an arm asserting nothing.
  cost: the suite's own wall clock, whose recorded maximum is 1385.1 s.
  figure: PINNED — read from `tools/run-gates/ceiling-evidence.txt` on 2026-09-10, node `a`.
- **AC5** — When `derive-ceilings.py --report` runs on node `a` in this worktree after the change, it
  prints a row for `memory-hygiene self-test` at or above 900 s and emits no UNBACKED line at all,
  where before the change it printed no row for that leg and named it as the only unbacked one.
  Red when: the leg is still absent from stdout, or still named on the UNBACKED line.

  It held two on 2026-09-10, at 900.481 s and 900.240 s; the runner prunes that window, so a later
  session may have to run a bar before this criterion is observable.
  figure: DERIVED — the printed maximum is whatever the window holds. The two readings above are
  PINNED as what it held on 2026-09-10.

## 8. Open questions

- **F1 — should an UNBACKED ceiling stay REPORTED and not FAILED?**
  `cmd_check` names the unbacked legs on stderr and exits 0 for them, and today that is 67 of 104.
  The case for failing is this repo's own, one file over: `ceiling-margin.txt` refuses a missing
  margin outright, because "Headroom nobody wrote is headroom nobody decided", and a ceiling nobody
  measured is the same species of number. The case against is that the two refusals are not
  satisfiable the same way. A missing margin is fixed by writing a line; a missing measurement can
  only be fixed by running a bar and committing what it produced, so an unbacked-fails rule reds
  every newly added leg until a second commit lands its evidence, and the first of those commits is
  knowingly red at the push boundary.
  What this unit changes about the question is the input to it, in two ways worth measuring before
  anyone decides. The population is smaller than 67: `--report` over this worktree's retained window
  names exactly ONE leg with no reading of any kind, and it is `memory-hygiene self-test`, so most of
  the 67 are a stale artifact rather than an unmeasured leg. And the legs that could never acquire a
  row are exactly the ones this unit admits, so the rule stops being unsatisfiable by construction.
  Both facts point at the same prerequisite: somebody has to run `--write` on a tree that has
  executed a full bar and commit the result — which is the thing §3 forbids this unit to do, because
  its first consequence is a red on the ceiling the owner has already parked.
  RECOMMENDATION: keep it reported for now, and re-ask once the artifact has been refreshed by
  whoever answers the parked ceiling question. Left OPEN deliberately; deciding it here would be
  deciding a merge-bar policy from a measurement this unit is not allowed to take.

RESOLVED (agent, 2026-09-10, delegated) F1: an UNBACKED ceiling stays REPORTED, unchanged by this
unit. The spec's own analysis is the reason and not a deferral: the decision's inputs move when
this unit lands, the refreshed artifact cannot be produced without committing a bar result whose
first consequence is a red on the ceiling the owner has already parked, and section 3 forbids this
unit to touch that number. Deciding a merge-bar policy from a measurement this unit is not allowed
to take is the shape M3 refuses. Re-asked by whoever answers the parked ceiling question.
