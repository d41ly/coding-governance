## High

### H1. The SubagentStop hook persists and validates a field that does not carry a schema-forced return (ids 15, 49)

- **Where:** [spawn] "Returns are persisted and validated by a SubagentStop hook"; [build] unit 5; [tests] 6.
- **What:** The hook persists `last_assistant_message` and checks it against the item's schema. A schema-forced Workflow agent ends on a `StructuredOutput` tool_use, with no text block. A scan of this session's workflow transcripts found that 18 ended on `StructuredOutput`. The roles research measured 2,588 StructuredOutput endings against 226 final-text endings. The [spawn] fallback covers only the case where SubagentStop does not fire, not the case where it fires with no text return.
- **Consequence:** Built as written, every schema-forced role return is persisted empty or wrong, and every valid return fails validation. Exit 2 then holds each agent, or the durable return stores nothing. Invariant 4 rests on a channel that carries no result. Fixture 6 asks only whether the hook fires, so it passes anyway.
- **Fix (skeptic judged sound):** Read the return from `agent_transcript_path`, taking the input of the last `StructuredOutput` tool_use (or the journal's result). Use `last_assistant_message` only for free-text roles, and key the record by `agent_id`. Extend fixture 6 in two ways: one schema-forced role agent's persisted return must byte-match what `agent()` resolved to, and a hand-built payload whose final text is valid JSON but whose StructuredOutput call is not must be refused.
- **Gate:** A fixture class: each persisted-return channel is asserted byte-equal to the value the platform handed the caller, on the main path's real ending shape.

### H3. A fresh relaunch cannot replay a killed Workflow run (id 16)

- **Where:** [supervise] Relaunch; [spawn] "a run replays from its journal (resumeFromRunId)"; [policies] runtime.relaunch; [tests] 3.
- **What:** A dead driver is "relaunched fresh, never resumed". Yet [spawn] relies on `resumeFromRunId` replay. The spawn research says replay works only within the same session or after `claude --resume`, that a fresh session has "nothing to resume", and that a run "can only be recovered from a resumed session". Persisted SubagentStop returns do not fill the gap: a new run gets new agent_ids, and nothing makes the harness consult earlier returns.
- **Consequence:** Killing a driver mid-item re-runs and re-pays every agent that had already completed in the item's fan, which fixture 3 forbids. Otherwise the build quietly switches to resume and pays the 503k resume cost the design argues against.
- **Fix (skeptic judged sound):** State which way the design goes. Either the role harness skips any agent whose return is already persisted under the item's key (a per-agent work-order key, not agent_id), so a fresh driver re-runs only the missing agents; or a relaunch that finishes an in-flight Workflow item uses `--resume`, and fresh relaunch is kept for between items. Fixture 3 compares the journals' `totalTokens`, as the spawn research's test 1 does.
- **Related:** Item M1 (ids 1, 50) is the same defect, confirmed at medium.
- **Gate:** A checklist entry: every recovery claim names the platform primitive it uses and the research line showing that primitive works under the relaunch mode chosen.

### H7. A supervisor take-over does not fence the dead supervisor's drivers (id 51)

- **Where:** [supervise] "The supervisor's own death"; [act] act-binding rule.
- **What:** The record treats a supervisor's death as "loses only the tick in flight", with take-over from any node. The detached drivers that the dead supervisor launched keep running. No driver identity, lease epoch or fencing token lets act binding tell an old driver from a new one.
- **Consequence:** After a take-over, `next` re-names the old driver's unwitnessed act (invariant 3), so two drivers perform one act. The result can be a duplicate commit, a duplicate fan or a race into the lander. Act binding refuses neither driver, because `next` named both.
- **Fix (skeptic judged sound):** Bind each act to a lease epoch, or to the driver's `--session-id`, recorded in the witness store. Have act binding refuse a driver whose epoch is not current. Require a take-over to kill or fence the previous holder's process tree before relaunching. Add a fixture: kill only the supervisor mid-act, take over from a second process, and assert one witness and one commit.
- **Gate:** A checklist entry: every take-over path names its fencing token and a fixture that runs two holders at once.
