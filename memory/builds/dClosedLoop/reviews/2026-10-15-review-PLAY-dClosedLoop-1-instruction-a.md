### H1. Codex's override file replaces the charter instead of adding to it (ids 14, 39)

- **Where:** [recommendations] R-K, Codex row; [settled] through v2's dOrderedCharter row.
- **What is wrong:** R-K renders Codex's load points as "`AGENTS.md` within 32 KiB, plus the card's override file". The research the design cites (research-orientation-preserve:29) says Codex reads one file per directory, `AGENTS.override.md` or `AGENTS.md`, up to `project_doc_max_bytes` (32 KiB) for the combined text. - **Consequence:** In a worktree, a Codex session loads the card's override in place of the level-0 charter and runs without the charter's rules. If the override instead embeds the charter, a charter at its cap plus the card exceeds the limit and the card is silently truncated. Either way level 0 or level 1 is lost with no error, on a path where the runtime leaves Codex with instructions plus guards only.
- **Fix (skeptic judged id 14's proposal UNSOUND; this is the corrected fix, and id 39's fix was judged SOUND and agrees):** Render one combined `AGENTS.override.md` at the worktree root that holds the charter followed by the card. Budget their combined bytes against `project_doc_max_bytes` (32 KiB). State in R-K that Codex reads one file per directory, with the override replacing `AGENTS.md`. List as Codex load points, with budgets, the hook events the runtime layer measured (PreToolUse, SubagentStart, SubagentStop, PreCompact, SessionEnd) wherever they carry text. The build runs a fixture that starts a Codex session at a worktree root holding the override and checks that a sentinel line found only in the charter is followed.
- **Gate:** the Codex sentinel fixture, plus a render check that refuses an override whose combined bytes exceed `project_doc_max_bytes`.
- **See also:** M5 (id 6), what refreshes the override at a transition.

### H3. The instruction command cannot tell the owner from an agent (id 40)

- **Where:** [recommendations] R-I; [settled] `instructions.edit`.
- **What is wrong:** Under the default `owner-command-agents-propose`, R-I says the owner uses the command directly and an agent only proposes, but names no mechanism that tells the callers apart. - **Gate:** the negative probe as a fixture, and a design-lint rule that every owner-only write path names its proof key.
