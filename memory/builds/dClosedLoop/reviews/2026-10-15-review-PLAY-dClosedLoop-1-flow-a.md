## High

### H1. Owner breakpoints are not kept out of `run.on-owner-question` (id 6)

- **Where:** flow-steps [breakpoint], "An owner breakpoint parks the build until the owner's disposition is hook-written".
- **What is wrong:** The record parks a build at an owner breakpoint. It never says that `run.on-owner-question` cannot resolve one. The runtime layer, settled later, says the supervisor raises owner items "or resolves them as `run.on-owner-question` says", with no distinction. That key defaults to best-effort-recorded (v2:490). layer-flow limits FR-4's no-park rule to forks, but the cross-layer contract does not carry that limit.
- **Consequence:** Built from both records, an unattended supervisor could self-dispose `deploy.mandate`'s landing authorization under three-gates, or a `plan.exit` ratification. The build then lands or proceeds without the owner's authority.
- **Fix (skeptic judged SOUND):** In [breakpoint], state that an owner breakpoint is an owner item of its own kind, which `run.on-owner-question` never resolves: only a hook-written owner disposition clears it. Record this as input to the layer-relations revisit, so that runtime [act] separates fork questions from owner breakpoints.
- **Gate:** a fixture with `autonomy: three-gates` and the default `run.on-owner-question`, where `next` at `deploy.mandate` answers `blocked` and the supervisor journals no disposition.

### H2. `test.attribute`'s witness never joins the tester's class to the bar's label (id 17)

- **Where:** flow-steps [test] `test.attribute` row; [rules] "No witness is typed by the acting agent".
- **What is wrong:** The tester classifies each red as code-miss, spec-wrong, inherited, mixed, contended or dead probe. The witness only checks that every red leg has one disposition and that its artifact exists. The bar already computes OWN, INHERITED, MIXED, CONTENDED and DEAD PROBE when `GATE_ATTRIBUTE=<rev>` is set (run-gates.sh:19-21, README:922-934), and `test.verdict` never sets it.
- **Consequence:** Under the default `verdict.blocks: own-only`, a tester who labels an OWN red "inherited" routes it to an ask, and Test exits. The "computed join" certifies a classification it never checks, and an own red can land.
- **Fix (skeptic judged SOUND):** `test.verdict` runs the bar with `GATE_ATTRIBUTE` set to the landing base. `test.attribute`'s witness joins each red leg's disposition to the run record's `attribution` row. Inherited, mixed, contended and dead-probe dispositions must equal the bar's label, and only an OWN row may take "code misses its spec" or "spec wrong".
- **Gate:** stage a tester return that relabels an OWN leg as inherited, and see the witness refuse it.
- **See also:** M12 (id 29) is the reuse side of the same item, confirmed at medium.

### H3. `entry.intake` does not scope which sessions' prompts count as owner intake (id 56)
