## High

### H1. RF-5 puts all 27 registries on a shrink-only ledger, but several are append-only histories, growing declared sets or ceilings (finding 17)

- **Where:** retrofit [ledger] "The factory" and "A row"; [answers] RF-5; [owners] dWitnessedBar row; [ratchet] "never gains".
- **What:** Ledger rows are shrink-only debt with the dispositions seeded, carried, deferred and widened, and "never gains" reds on any key above the base that has no widen record. Research A's claim that "the factory shape fits all 27" does not hold. refusal-retirements.txt and transition-audit.txt declare themselves APPEND-ONLY. readme-contract.txt gains a row for every new build README, because its FORWARD arm refuses a README with no row. fork-ceilings.txt is a ceiling table, and legacy-files.txt is a permanent exemption.
- **Consequence:** After the migration, every new build owes a widen record. Either the bar reds on correct work, or widen records become routine and the ratchet stops meaning anything.
- **Fix (judged sound by the skeptic):** In [ledger], give each registration a direction: shrink-only debt, append-only history, declared set (checked both ways, growth allowed) or ceiling. Apply "never gains" only to shrink-only debt. List in RF-5's migration which of the 27 files takes each direction. Probe the build must run: migrate readme-contract.txt in a scratch tree, add a build README with its row, and expect the ratchet leg green.
- **Left-shift gate:** a registration check that refuses a population with no declared direction, plus a checklist entry: a migration onto a ratchet classifies each source by how it grows.

### H2. The memory acceptance re-measure counts only Read-tool bytes, so moving memory into work orders and `record show` passes it by construction (finding 18)

- **Where:** systems [design-memory-structure] "The acceptance re-measure"; [ms2] and [ms2-instrument].
- **What:** The acceptance criterion is "median memory bytes below 40 KB, measured as today's 52.7 to 68.9 KB were". The instrument counts only `Read` calls on `/memory/` paths. A re-probe found that Bash reads carry 57.1% of today's memory bytes (138.8 MB against 104.5 MB through Read). Under the design, sections are inlined into the work order and served by `record show` over Bash, and the measure counts neither.
- **Consequence:** The re-measure drops below 40 KB because the bytes move where the measure does not look. It certifies a saving it never checks. The [ms2] counts behind the 96 KB cap also miss most agents and most bytes.
- **Fix (judged sound by the skeptic):** Define the acceptance measure as a spawn's total memory bytes: the work order's inlined slices (from the slice manifest), plus Read results on memory paths, plus the output of Bash commands that name memory paths, `record show` included. Re-run [ms2-instrument] with the Bash arm before the cap's basis is cited. State in [design-memory-structure] that the journaled "read outside it" covers Bash reads.
- **Left-shift gate:** a test of the instrument: a planted transcript whose only memory read is a `record show` over Bash must count its bytes.

### H3. `test.seed` rewrites a whole population at every re-run, which resets the ratchet that today's adopters refuse to reset (finding 27)

- **Where:** retrofit [seed] `test.seed`; [placement] "Retrofit is not only adoption".

- **Fix (judged sound by the skeptic):** In [seed], state seed-if-absent per population. A re-run at a later SHA may only ADD the keys a new or widened predicate measures, written `widened:<record>` or seeded only for the new predicate's keys, and never rewrites an existing row. Add a `ratchet` pack row that reds when a seed run removes or re-dates an existing row. Name `adopt-codebase-map.sh:194-199` and `adopt-drift-audit.sh:239-245` as the seams `test.seed` extends or retires. Probe: seed, plant an offence, re-run `test.seed` at the new SHA, and expect the planted key absent from the population and the leg red.
- **Left-shift gate:** the `ratchet` pack row above, seen red on the planted re-seed.

### H5. A seed that fails, times out or reads a dead probe arms its check over an empty population that the check then certifies (finding 57)

- **Where:** retrofit [seed] and [ratchet].
- **What:** [seed] covers only a check with NO seed ("recorded unarmed"). It says nothing of a seed that exits nonzero, times out, reads a dead probe (drift's DEAD PROBE state) or dies partway through `adopt`. Research A's `populated` row, red on an empty population after the seed, was dropped from the `ratchet` pack.
- **Consequence:** The scan reads the same dead probe the seed did, so "never gains" and "both ways" stay green over a population nobody measured.
