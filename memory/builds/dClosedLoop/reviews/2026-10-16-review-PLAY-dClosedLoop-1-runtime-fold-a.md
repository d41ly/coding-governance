## High

### H1. Act binding and the epoch fence sit on the entry that fails open (ids 1, 13)

- **What and where:** The named-act check and the stale-epoch refusal run on "the PreToolUse entry for Workflow and Agent" (:450-457). The SessionStart witness is read "at the first PreToolUse" (:592). A PreToolUse hook fails open (:184), and the `onFailure` switch exists only from 2.1.295 (:571-572). The fold made the separate PermissionRequest entry the only fail-closed allow path (:564). That entry decides gated tools "by the act's allowance" (:376-378, :577-578). The allowance is the commands an act may run (:464), and it carries no act name, args digest or epoch.
- **Consequence:** Take a 2.1.292 node where the PreToolUse dispatcher crashes and the PermissionRequest dispatcher stays healthy. An unnamed Workflow or Agent call, or a call from a fenced old-epoch act session after a take-over, reaches the ask rule and is approved. That breaks `named-acts` and brings back the double-commit the `fencing` defect was folded to prevent. This is the "crashed guard sitting beside a healthy allowing hook" class that :570 says is closed. One entry per event (:539) makes the two entries separate processes. Neither `fencing` (:1056-1057) nor `binding` nor `fail-closed` (:1007) crashes PreToolUse alone, so the fixtures would still certify fail-closed.
- **Fix (skeptic judged sound):** Have the PermissionRequest decision check the named act, the args digest and the epoch for every gated call, either by moving the refusing checks there or by repeating them there. Keep PreToolUse advisory only. State this in [act] and [enforce]. Add a `fail-closed` arm, and extend `fencing` and `binding`: on 2.1.292 in auto mode, crash only the PreToolUse entry, keep PermissionRequest healthy, and make an unnamed call and a stale-epoch call. Both must be denied. See the arm red against today's split first.
- **Left-shift gate:** a class check that fails when any refusing guard named in [enforce] runs only on an event that lacks a fail-closed path on the floor version.

## Medium

### M1. PermissionRequest is missing from the event list and the owner-pack table (ids 2, 14)

- **What and where:** [enforce]'s list of events, each rendered as "one dispatcher entry per event" (:539-546), has no PermissionRequest. Neither does the owner-pack table (:548-559), which a gate compares with settings.json. Yet :564 and :907 make the dispatcher's PermissionRequest entry the only allow path for gated tools. The capability row (:727) names it apart from "every event in [enforce]". settings-merge renders entries from fragments (:541), and the class arm reads only fragments.
- **Consequence:** The entry the fail-closed guarantee rests on has no fragment, no owner pack, no row for the pack-table gate and no class-arm coverage. The pack gate either refuses the entry as unowned or never checks it. The `extension` fixture checks Codex against required events that leave this one out. :907 names the entry, so the risk is an inconsistency plus a missing check rather than a certain outage. The skeptic graded id 14 down from high for that reason.
- **Fix (skeptic judged sound):** Add PermissionRequest to [enforce]'s events. Give it a runtime row (the permission baseline) in the owner-pack table, render it through settings-merge from a fragment, and add it to the Claude Code capability row's event set so `extension` checks it. Extend the class arm so it fails when any gated tool's ask rule has no PermissionRequest dispatcher entry. See that arm red on a settings file with the entry removed.
- **Left-shift gate:** the class arm above, which gates the event list against the ask rules.

### M2. The record gives three rules for writing `onFailure` (ids 10, 15)

- **What and where:** [enforce] says settings-merge.py "writes `onFailure`" with no condition and compares it in `--check` (:534). Build unit 7 writes it "wherever the node registry shows the CLI carries it" (:909). The `binary` fixture says that on a 2.1.292 node "the dispatcher's entries then omit `onFailure`" (:1065-1067). settings-merge writes the tracked `.claude/settings.json` (settings-merge.py:561), which every node shares. The base set the key unconditionally (base :366).
- **Consequence:** One shared file cannot vary its bytes per node binary. Following the per-node rule makes `--check` report drift between nodes, and node d holds both 2.1.292 and 2.1.295. Following the unconditional rule makes the `binary` fixture's expectation wrong. A builder gets contradictory acceptance criteria. 2.1.292 ignores the key silently, so leaving it out buys nothing.
- **Fix (skeptic judged sound):** Always render `onFailure: "block"`, and record the switch only as a node-registry capability. Drop "wherever the node registry shows" from :909. Rewrite `binary` so it asserts that the registry records the switch as missing and that a gated call is still denied while the dispatcher is missing. Drop its "entries omit `onFailure`" clause.
- **Left-shift gate:** a bug-class checklist entry: a per-node capability may never decide the bytes of a tracked, shared file.

### M3. [answers] RT-2 claims a mid-run crash test that [tests] does not hold (id 3)

They are the attended 2.1.292 fallback and "a permission host that crashes mid-run". `fail-closed` (:1006-1015) holds only the first (:1011-1012). "mid-run" appears only at :1171. The burst-class replay (:1007-1008) fails the dispatcher at the call, not after a healthy start.
- **Consequence:** The research return names the mid-run crash as "the test the build must run" (research-runtime-floor:62, :98). The record says it is covered while nothing checks it.
- **Fix (skeptic judged sound):** Add a `fail-closed` arm: start an act session with a healthy dispatcher, kill the PermissionRequest host mid-run, and assert that the next gated call is denied. See it red against a stub that admits. Or reword [answers] so it names the case as unhomed.
- **Grade note:** Ids 11 and 16 (item L1) report the same defect, and their skeptics graded them low. Their reason is that the research's mid-run case is a `--permission-prompt-tool` MCP host the design never adopts, and the burst arm already covers a per-call hook failure. I judge low the right grade for this defect too. Id 3 stays medium here because its grade is binding.
- **Left-shift gate:** a check that every test named as owed in [answers] resolves to a fixture arm in [tests].

### M4. The `next` answer set has no answer for a frontier of awaited items (id 4)

- **What and where:** The closed set of position answers (:324-334) is act, blocked, terminal, stuck, invalid-input and stale-remote. [terms] promises "`next` reports it as awaiting that event" for hook items (:313). Hook items are never dispatched (:477), and [schedule] adds event waits such as `deploy.released` (:712-717). v2:944 mirrors the same six answers.
- **Consequence:** A build whose only open items are awaited must map onto a wrong answer. `act` would dispatch a hook item. `blocked` raises an owner item once nothing it waits on is in flight, while the sweep raises it only past `build.release-ceiling` (:429), so the two paths disagree on when the owner hears. `stuck` raises an owner item at once. The result is spurious owner items, or a dispatched hook, on a normal path.
- **Fix (skeptic judged sound):** Add an `awaiting` answer that carries each awaited item and its event or record, with the transition "hold, renew, re-ask on the event". Mirror it in v2's dDeclaredLoop answer list. Add a `next` fixture case in which a frontier of only a hook item answers `awaiting`.
- **Left-shift gate:** a fixture rule that every item kind in [terms] reaches a declared `next` answer.

### M5. The PermissionRequest decision has no arm for attended or unbound sessions (id 12)

- **What and where:** Under `runtime.hook-failure=closed` (:560), every gated tool carries an ask rule that the dispatcher answers "by the act's allowance" (:376-378, :574-578). Attended sessions (:466-470) and unbound sessions outside every build's workspace (:472) have no act and so no allowance. :466 says an attended session "keeps its freedom", but no decision is stated for either binding.
- **Consequence:** In an attended or unbound session, a dispatcher with no declared answer sends every Bash and Edit call to the person, which defeats auto mode. A background subagent cannot be asked, so its gated calls are denied. The `fail-closed` and `binding` fixtures test only act sessions, plus the attended case with a missing dispatcher. This costs friction, not safety.
- **Fix (skeptic judged sound):** Declare the decision for each binding. An act gets its allowance. Attended and unbound sessions are allowed once the existing guard packs pass, the write gate included. Add a fixture case in which benign gated calls from an attended session and an unbound session are approved without a prompt.
- **Left-shift gate:** a fixture rule that every binding value has a declared PermissionRequest decision.

### M6. The `next` fixture leaves three answers and route-back minting untested (id 17)

- **What and where:** [decide] declares six `next` answers, each "a declared supervisor transition" (:324-334). A route back mints a new item instance (:335-342). The `next` fixture (:976-980) checks only byte-identity, terminal, stuck and invalid-input. `once-per-instance` (:807) is observed by relaunch, idempotence and coverage, and none of them routes back.
- **Consequence:** `blocked`, `stale-remote` and route-back minting can each be built wrong and stay green. Examples: an owner item raised while the blocker is still in flight, a stale-remote that never parks, or a fix pass that reuses the old instance's witness and never re-runs.
- **Fix (skeptic judged sound):** Extend `next` with three cases. A blocked item whose blocker is in flight raises no owner item until the blocker ends, then raises exactly one. An unreadable lease ref answers `stale-remote` and parks after `leases.expiry-hours`. A failed check routed back to `entry.place` mints a new instance key and is dispatched again, while the old instance stays witnessed. See each arm red against a stub supervisor.
- **Left-shift gate:** a coverage check that every declared `next` answer and transition has a fixture arm.

### M7. The `coverage` arm checks the design text, not the built code (id 18)

- **What and where:** The `coverage` arm (:1074-1075) asserts that every `runtime.*` key in v2's catalogue "has a reader in this record's design". `policy-and-journal` (:812) names `coverage` as its only observer.
- **Consequence:** After the build, the arm passes whatever the code reads, because the design text never changes. A key the built supervisor ignores, such as `runtime.hold-ceiling` or `runtime.relaunch`, stays green. The invariant certifies something nothing checks.
- **Fix (skeptic judged sound):** Point the predicate at the built tree. Every `runtime.*` key in the catalogue must have a reader call site in dWellOiledMachine's code, found through the one policy reader's key registry (v2:394, :555). Assert the population is non-empty, and see the arm red on a planted catalogue key with no reader.
- **Left-shift gate:** a checklist entry: an owed fixture's predicate must read the built tree, never a design record.

- **Consequence:** A run under the owner-chosen weaker policy can go silent with nothing turning red.
- **Fix (skeptic judged sound):** Add a `fail-closed` arm: under `runtime.hook-failure=open`, every run's journal and the class check's output name the policy in force. See it red against a class check stubbed to stay silent.

### L6. The capability table claims PermissionRequest works "on every version" (id 21)

The research measured only 2.1.292 and 2.1.295 (research-runtime-floor:21-47). It records that 2.1.299 narrowed PermissionRequest's power to approve in Cowork cloud sessions (:54), and it advises treating such powers as detected capabilities (:78).

- **Fix (skeptic judged the finder's fix UNSOUND; this is the skeptic's corrected fix):** Restate :727 as "ask rules answered by PermissionRequest, measured on 2.1.292 and 2.1.295". Have the node registry record, per binary, whether PermissionRequest can approve each gated tool, as it does for `onFailure`. Do not add a launch refusal.
- **Left-shift gate:** a checklist entry: a capability row cites the versions it was measured on.
