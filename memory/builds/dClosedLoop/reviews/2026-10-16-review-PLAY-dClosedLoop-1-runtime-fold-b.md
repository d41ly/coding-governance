## High

### H1. A persisted return is keyed per act, so a relaunched fan cannot tell which agents returned (finding 1)

- **Where:** layer-runtime:496 (`[spawn]`), with :329, :335, :389-390, :512-513 and :989.
- **What:** `[spawn]` keys each return by "the item and the work order's task-sha". `[decide]` (:329) gives an act one work-order key and one task-sha, so every agent in a multi-agent fan shares one key. The key also leaves out the item instance (round or pass, :335).
- **Consequence:** Take the review fan the `relaunch` fixture kills (:989): five lens agents, five skeptics and a synthesizer in one act. The first lens return gives the act "a return". A relaunch then either skips the agents that never returned, losing their findings, or re-pays all of them. Either way the promise at :389-390 and :512-513 ("spawns only the agents with none") fails. The fold of the high defect relaunch-replay is therefore partial. A route back with an identical work order could also be handed the previous instance's returns.
- **Fix (judged sound by the skeptic):** Key each return by (item instance, act task-sha, spawn site and index from the harness's declared spawn sites, :456). State that SubagentStop derives the spawn site from the spawn marker it journals. Add a `relaunch` arm that kills a five-agent fan after two returns and asserts exactly three respawns, each for a named site.
- **Left-shift gate:** a `relaunch` fixture arm with a partial fan, seen red against a per-act key.

### H2. Fencing rests on an epoch no lease carries, and its fixture can pass without the refusal running (finding 2)

- **Where:** layer-runtime:400-407, :282, :365, :928, :1056-1057; coordination.md:77-82; v2 `[chain]` dDeclaredLoop row.
- **What:** :400 says "each run lease carries an epoch, bumped at every take-over". dDeclaredLoop owns the lease grammar, which has no epoch field and no run lease ("run claims migrate onto build leases"). :928 and v2 call the same lease the build lease, so one lease has two names. Nothing says where binding reads the current epoch.
- **Consequence:** Across nodes the current epoch sits on the shared remote. The old node's dispatcher sees only its local copy, so the old act session is never refused and keeps writing. On one node, :406 kills the old process tree at take-over, so the `fencing` fixture's "old act session's next call is refused" has no session left to refuse. The high defect `fencing` stays open while its fixture can read green.
- **Fix (judged sound by the skeptic):** Add the epoch field and its bump on take-over to dDeclaredLoop's lease grammar and v2 row. Use one name for the lease. State where binding reads the current epoch: a remote fetch per gated call, or a renewed local cache with a stated staleness bound and what an old session can do inside it. Run `fencing` across two nodes, or with the old act session outside the killed tree, and assert the refusal is the one in the old session's journal.
- **Left-shift gate:** a lease-field cross-check between layer-runtime and coordination.md's grammar, plus the two-node `fencing` arm.

### H3. Act binding and the stale-epoch refusal sit on PreToolUse, which fails open below 2.1.295 (finding 10)

- **Where:** layer-runtime:450-453, :550, :377-378, :577-578, :588.
- **What:** Act binding (the args-digest match, the act `next` named) and the stale-epoch refusal are only on "the PreToolUse entry for Workflow and Agent". After RT-2, the entry that fails closed on 2.1.292 is PermissionRequest, and it decides gated calls only "by the act's allowance". The two are separate per-event entries (:530).
- **Consequence:** Dispatch 36 measured that in auto mode a failed PreToolUse hook lets the classifier allow the call. Under the ask-rule baseline the call reaches PermissionRequest, which approves anything inside the allowance. A burst that crashes only the PreToolUse invocation therefore admits two kinds of call: an unnamed Workflow or Agent call, and any call from a stale-epoch session. This breaks `named-acts` and the fencing guarantee at :404. :588's claim that only ungated-tool rules stay open below 2.1.295 is false. RT-2's removal of the 2.1.295 floor exposed the gap.
- **Fix (judged sound by the skeptic):** Move the act-binding comparison (registered harness, args digest, act named by `next`) and the epoch check into the PermissionRequest dispatcher's decision for gated tools. Keep PreToolUse for early refusal and journaling only. Add a case on 2.1.292 where the PreToolUse entry crashes and PermissionRequest is healthy: a stale-epoch call and an unnamed Workflow call must each be denied.
- **Left-shift gate:** that `fail-closed`/`binding` case, seen red against a PermissionRequest stub that allows by allowance alone.
- Findings 3 and 17 describe this same defect at a binding grade of medium, so they sit in M1. Fix it once.

### M2. The cadence dedup checks the witness only before taking the lease (finding 4)

- **Where:** layer-runtime:709; `cadence` fixture :1029-1030; coordination.md:83-89.
- **What:** "The supervisor consults that witness before it takes the cadence lease", and nothing re-reads it after the lease is won.
- **Consequence:** Two nodes wake in one period and both read no witness. A wins, runs, writes the witness and releases. B's compare-and-swap acquire then succeeds and B runs the period again. This breaks `once-per-instance`. The fixture covers only the sequential late-wake case.
- **Fix (judged sound by the skeptic):** Re-read the period's witness after acquiring the lease, and release without running if it is present. Add a `cadence` arm with two supervisors released together on one period, asserting one run and one witness.
- **Left-shift gate:** that concurrent `cadence` arm.

### M3. `fail-closed` claims every gated call needs the dispatcher, but a local or user allow rule bypasses it (finding 5)

- **Where:** layer-runtime:810, :572-574, :371-382, `fail-closed` arm :1013.
- **What:** The invariant says that on every CLI version a gated call "runs only on the dispatcher's approval". The mechanism refuses allow rules only in tracked settings and only warns on local or user ones. Dispatch 36 lists any matching allow rule as uncovered. The act launch names no setting-sources restriction.
- **Consequence:** A `claude -p` act session loads user settings, and this worktree's `.claude/settings.local.json` already holds `Bash(git fetch *)`. A user-level allow on a gated tool runs the call with no dispatcher decision while the invariant reads as holding.
- **Fix (judged sound by the skeptic):** Have the supervisor's preflight refuse to launch an act session while any settings source it loads holds an allow rule matching a gated tool, or launch with setting sources that exclude user and local. Otherwise, narrow the invariant to tracked settings and name the gap. Add an arm that plants a user-level `Bash(*)` allow.
- **Left-shift gate:** that planted user-level allow arm.

### M4. A second PermissionRequest hook in local or user settings goes undetected (finding 20)

- **Where:** layer-runtime:570-574, :619-621, `fail-closed` :1006-1014.
- **What:** "One checking hook is the allow path" rests on the dispatcher being a single entry. The only scope checks are on allow rules, plus a warning on user-level guards lacking `onFailure`. Nothing looks for another PermissionRequest hook.
- **Consequence:** A PermissionRequest hook in `settings.local.json` or user settings that answers allow is the healthy-allower class :570 names. It opens a second door to the only allow path while every check stays green.
- **Fix (judged sound by the skeptic):** Extend check-wiring's session arm to warn on any PermissionRequest hook outside the dispatcher's entry, in every settings scope. Add a `fail-closed` case: a user-level always-allow PermissionRequest hook beside a crashed dispatcher must be reported, seen red first.
- **Left-shift gate:** that check-wiring arm and fixture case.

### M6. Attended slot reservations are never released (finding 12)

- **Where:** layer-runtime:418-422; `in-flight` :997-1000.
- **What:** Slots are released only when the act session exits or the reap kills its tree. An attended session's PreToolUse entry reserves against the same counter, and that session never exits per call.
- **Consequence:** Every attended Workflow or Agent call increments the shared counter permanently. Once it reaches `FANOUT_CAP` the supervisor queues every unattended act and the attended entry refuses further spawns, until the attended session dies.
- **Fix (judged sound by the skeptic):** Release an attended reservation at the harness call's completion (PostToolUse on the call, or the run's end record), plus a sweep keyed to the session's liveness. Add an `in-flight` case where an attended Workflow call completes and its slots are freed.
- **Left-shift gate:** that `in-flight` case.

### M7. `next` has no "awaiting" answer for a hook item or an event wait (finding 13)

- **Where:** layer-runtime:313 (`[terms]`), :327-334 and v2's dDeclaredLoop row, :712-717, `event-wait` :1044-1047.
- **What:** `[terms]` says `next` reports a hook item "as awaiting that event". The closed answer set (act, blocked, terminal, stuck, invalid-input, stale-remote) has no such answer. `blocked` raises an owner item once nothing is in flight, and `stuck` raises one at once.
- **Consequence:** When only a hook item or event wait is open, every candidate answer makes the supervisor raise an owner item at once. For `deploy.released` that contradicts the rule that its owner item opens only after `build.release-ceiling`, and only once.
- **Fix (judged sound by the skeptic):** Add an `awaiting` answer (the item and the event it waits on) whose supervisor transition is "hold; the ceiling sweep owns the owner item". Otherwise, state that `blocked` carries an awaited-event cause that raises no owner item. Add a `next` fixture case with a frontier holding only a hook item.
- **Left-shift gate:** that `next` fixture case.

### M8. The record says three things about whether `onFailure` is written (findings 14, 19)

- **Where:** layer-runtime:534-536, :909 (unit 7), `binary` :1065-1067, :581-582; `tools/settings-merge.py`:26, :31, :1005.
- **What:** :534 has settings-merge write `onFailure` unconditionally and compare it in `--check`. Unit 7 writes it "wherever the node registry shows the CLI carries it". `binary` asserts a 2.1.292 node's entries "omit `onFailure`". The entries go into the one tracked `.claude/settings.json`.
- **Consequence:** A per-node value in a shared tracked file either churns the file or makes `--check` report drift on a mixed fleet. Node d carries both 2.1.292 and 2.1.295. The class check would go red wherever the key is omitted. One of `binary` and `--check` is red by construction. Omitting the key gains nothing, because 2.1.292 ignores it silently.
- **Fix (judged sound by the skeptic):** Under `runtime.hook-failure=closed`, have settings-merge always write `onFailure: "block"`. The node registry's capability then affects only what the supervisor journals and what `fail-closed` claims for that node. Rewrite unit 7 and `binary` to match: entries carry the key, the journal records that it has no effect on that binary, and the gated call is still denied. The alternative is to move the switch into node-local settings and have `--check` compare only tracked, node-independent entries.
- **Left-shift gate:** a `binary` arm on a 2.1.292 node that runs `settings-merge --check` and asserts it stays green.

### M9. Two clauses of the `fail-closed` invariant have no observing fixture (finding 21)

A `hooks.bypass` commit and a `core.exceptions` entry each leave a journal line, and the lander's re-check reports the bypass. Otherwise, drop those clauses from the observed-by claim.
- **Left-shift gate:** a check that every clause of an invariant row is asserted by one of its observed-by fixtures.

### M10. The fold's own `[neither]` additions have no fixture, and `coverage` passes on prose (finding 22)

- **Where:** layer-runtime:382, :426, :688, :842 (`runtime.act-ceiling`), :642 (line endings from the node registry), `coverage` :1074-1075; compared:229-235.

Add a `workspaces` case: on a node registry whose autocrlf differs from the tree's, a fresh worktree is clean and `--preflight` passes. Re-point the coverage predicate at the built code's key readers, and see it red on a key with no reader.
