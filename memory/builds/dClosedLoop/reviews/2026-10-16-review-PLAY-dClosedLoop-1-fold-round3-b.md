### M1. role_matrix.py's widened arm 0 still drops indented or pipe-less rows without a finding (ids 1, 14, 16)

- **Where:** memory/builds/dClosedLoop/build/2026-10-15-build-PLAY-dClosedLoop-1-layer-roles.md:1170-1177 (the `if step is None or not line.startswith("|"): continue` test, which runs before `body` is counted at :1187). - **What is wrong:** the round-2 M10 fix decides whether a line is a table body row by its first character. ### M5. `entry.claim` has no idempotence key, so a lost ack mints a second slug (id 8)

- **Where:** memory/builds/dClosedLoop/build/2026-10-15-build-PLAY-dClosedLoop-1-flow-steps.md:72. Also flow-steps:60 (the rule that every command item declares idempotence or reconciliation) and layer-memory.md:325-326 (claim refs are never pruned). Against tools/unattended/unattended.sh:2077-2079.
- **What is wrong:** `entry.claim` is a command item that creates a never-pruned ref by compare-and-swap. It declares neither idempotence nor reconciliation, and its only retry outcome is "the slug claimed elsewhere → a fresh slug". Nothing lets a retry recognise its own claim, although unattended's model, which the item cites, writes the session into the claim commit.
- **Consequence:** suppose the push lands but the ack is lost, through a network drop or a crash. The retry then sees the ref as held elsewhere and mints a second slug. That leaves an orphan claim that is never pruned, two claims for one request, and a spent route-back.
- **Fix (skeptic judged it sound):** have the claim commit carry the claimant's key: the session plus the intake's or ask's content key. Make `entry.claim` idempotent on that key, so a claim ref whose key equals ours counts as claimed, not as claimed elsewhere. State the key in memory `[contract]` and in gap-mem-13.
- **Left-shift gate:** a lint over flow-steps' command items: each must carry an idempotence or reconciliation declaration (flow-steps:60), and an item that creates a ref must name its key.
