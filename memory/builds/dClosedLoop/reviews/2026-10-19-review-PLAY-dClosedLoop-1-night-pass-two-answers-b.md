## Findings

### HIGH

#### H1. The admission queue hangs on a declared fan larger than the limit (id 1)

- **Where:** memory/builds/dClosedLoop/build/2026-10-14-build-PLAY-dClosedLoop-1-architecture-v2.md:1511, dWellOiledMachine's admission-queue clause. It reads with layer-runtime:433.
- **What is wrong:** A call waits "in order". It starts only "with room for its declared fan" and is "never refused for want of a slot". Layer-runtime:433 makes a Workflow call's declared fan the harness's static maximum, a property of the harness file. Nothing bounds that fan by `runtime.agents-in-flight` or says what a larger fan gets.
- **Consequence:** A Workflow call whose harness declares more agents than the limit never starts, and nothing refuses it. Because the queue runs in order, every later direct spawn and Workflow call in that session or executor waits behind it. Before this diff the attended entry refused such a call, so the silent hang is new. The trigger is any fan larger than the limit, which includes the owner lowering the key by a policy write under NT-28. When the fan equals the limit, the call starts only with zero agents in flight, so it serializes against every other spawn.
- **Fix (judged SOUND by the skeptic):** State what the queue does with a fan larger than the limit. Either clamp the reservation to the current key, re-read at admission and never the session-start render, or refuse that one call with its reason, the only refusal the queue keeps. Say whether a head call that cannot fit blocks later calls or is skipped. Add a fixture arm that lowers the key under a waiting call's fan and shows it neither hangs nor holds the calls behind it.
- **Left-shift gate:** Add a bug-class checklist entry: "a wait whose start predicate has no bound on the waiting item's own size". Every queue or reservation clause must state its oversize case and carry a fixture arm for it.
- **Related:** id 19 (M8) describes the same hang from the verification lens. Its binding grade is medium, so it stays a separate item and is not counted here.

#### M1. The queue's only witness passes with no queue installed (id 2)

Seven agents in one Workflow run therefore satisfy the witness with no Runtime queue installed. The witness names no spawn kinds and has no arm seen red.

- **Fix (judged SOUND by the skeptic):** Name the spawns in the witness. Put six in flight across direct and Workflow spawns, then add a seventh direct Agent spawn and a seventh Workflow call. Each must be held, not refused, and must start when a slot frees. Show the arm red with the queue stubbed out, where the direct spawn is refused.
- **Left-shift gate:** Checklist class `fixture-passes-by-finding-nothing`. Every witness for a new mechanism must name an arm seen red with the mechanism removed.

#### M2. The change feed's "rebuilt equal from git" cannot hold and has no witness (ids 5, 17)

- **Where:** architecture-v2.md:1504, dPlacedRequest's change feed, and its join clauses at v2:1505 (dKeptSession mail writes) and v2:1508 (dTotalRecall `record` writes). Also memory-plan:95.
- **What is wrong:** The feed is "ordered, append-only, replayable from any point and rebuilt equal from git", but that claim fails in three ways:
  - The design prunes terminal run claims (`refs/gov/runs/*`, layer-runtime:449) and closed builds' mailbox refs (coordination:117), so events for pruned refs cannot be rebuilt from git.
  - Git gives no total order across independent lease, mail and register refs, and the clause defines none.
  - Only `record` and mail writes join the live feed, so a hand-committed record, such as this very diff, is in a rebuild but not in the live feed.

  The feed clause and both join clauses carry no "seen on" witness. The only related witness, in dWellOiledMachine, rebuilds the mirror from the feed, not the feed from git. The feed also sits in the git common dir with every session of the node appending, and no ordering or locking rule is given.
- **Consequence:** The feed's equality to git is asserted over an undefined population and order, and no check can turn it red. A feed that drifts from git, misses hand-written records or reorders across refs passes every stated witness. The mirror then serves that drift to other nodes.
- **Fix (judged SOUND by the skeptic, both findings):**
  - Key each event by (ref or record, blob, commit). Append only after the ref update or commit has landed, and make the append idempotent on that key.
  - Define the order key, for example per-ref commit order with a node-local sequence.
  - Define the population a rebuild covers: every `refs/gov/*` write and every commit touching records, or state hand commits as out of the feed with the reason.
  - Either narrow "rebuilt equal from git" to refs still present, or keep pruned refs' events in the feed.
  - Add arms seen red in dPlacedRequest: a retried `record` write that appends twice, a lost CAS attempt that appears in the feed, a feed rebuilt from git on a planted clone compared with the live feed, and a hand-committed record the live feed lacks.
- **Left-shift gate:** Checklist class `zero-witness-over-an-unnamed-population`. Any "equal to" or "rebuilt from" claim must name its population and order and carry a comparison arm.

#### M3. "Never read by a verdict" has no check that can fail, and the mirror pocket is misclassified (id 6)

- **Where:** memory/builds/dClosedLoop/build/2026-10-18-build-PLAY-dClosedLoop-1-memory-plan.md:96, and v2's `memory.mirror` row and dWellOiledMachine's memory-mirror clause ("every verdict computed locally").
- **What is wrong:** This is the guard that keeps the mirror inside P2 and P3, but the only witnesses cover dropped events and a cross-node read. No arm goes red if a verdict reads the mirror. The pocket is also classified "out", which memory-plan:59-60 defines as "a cache or a mechanic that no reader needs", yet its stated purpose is to answer other nodes' reads.
- **Consequence:** A position engine, gate or claim check that reads the mirror would compute a verdict from content not in that node's git, including another node's unpushed commits, and no planned arm would go red. The "out" label also keeps the mirror's read path out of the reader and key accounting that `[pockets]` requires.
- **Fix (judged SOUND by the skeptic):** Add an arm to dWellOiledMachine with a stand-in mirror that serves a record the local git lacks. Every verdict, `next` answer and gate must read the same as with the mirror absent, and the arm is seen red on a planted reader of the mirror. Reclassify the pocket as a witness, with its key (the feed's event key) and its readers named.
- **Left-shift gate:** Checklist class `rule-stated-with-no-check-that-fails`. A P3 invariant clause must carry a planted-breach arm.

#### M4. The NT-19 answer misstates the tree: a lock-free push clears the lander's verdict files (id 7)

- **Where:** memory/builds/dClosedLoop/build/2026-10-19-build-PLAY-dClosedLoop-1-night-pass-two.md:668, the NT-19 answer ("the one real contention was the lander's lock, which a push no longer takes"), and point 4 at lines 319-320 ("takes no lock the lander holds and runs no gate").

A push from the lander's git dir must still wait, or the hook must skip clearing the verdict files on non-default pushes. Add that condition to dWellOiledMachine's `build.push` clause with an arm in which a build-branch push during a landing from the same git dir leaves push-main's verdict files intact. Make "runs no gate" and "no bar but a branch bar the repository declares" one statement.

#### M8. The queue's only fixture never reaches an oversize fan (id 19)

- **What is wrong:** dBoundRoles checks a stage's cap against the limit only when the workflow is composed. dGroundRules lets the owner lower the key by a policy write, and nothing re-checks registered fans when the limit drops. Under the split fallback the Workflow budget can also fall to limit minus ceil(limit/2). A call whose fan exceeds what is admissible can never have "room", and the only fixture uses single-agent spawns.
- **Consequence:** The call sits at the head of the queue for good, and every later spawn in the session stalls with no refusal or report, while the fixture still passes. The finder graded it high. The skeptic re-graded it medium because the stall is visible and is not a wrong result or data loss. This is the same hang as H1 (id 1), seen from the fixture side. Its binding grade is medium, so it is listed separately and not counted twice.
- **Fix (judged SOUND by the skeptic):** State what a fan larger than the limit gets: a refusal at enqueue with a named reason, or admission in chunks that the harness's per-run cap queues. Add fixture cases that can turn red: a fan of 4 enqueued under a limit of 3, and a fan-1 spawn queued behind it that must not wait on it.
- **Left-shift gate:** Checklist class `route-names-an-output-its-actor-never-emits`. A queue fixture must include an item larger than the capacity.
