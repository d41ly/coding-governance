### H2 — life.quiesce no longer refuses withdraw or supersede of a landed build (id 3)

- **Where:** `memory/builds/dClosedLoop/build/2026-10-15-build-PLAY-dClosedLoop-1-flow-steps.md:453`.
- **What is wrong:** Base :452 read 'a push already made → refused: the build has landed', with the deploy.released wait as the only exception. HEAD reads 'a push already made → a pause is refused'. The only landed-build arm for withdraw or supersede covers a build 'waiting at deploy.released'. A withdraw of a landed build at any other Deploy item falls to 'withdraw or supersede → life.notify'. That covers deploy.core through deploy.notify, and every landed item under at-landing.
- **Consequence:** life.notify posts `withdrawn` or `superseded` to dependents, and life.close records a withdrawn terminal state for code that is on main. Dependents then run deps.on-parent-withdrawn for a parent that landed. The result is a wrong terminal state and a wrong cascade. No other text in the tree restores the refusal.
- **Fix (skeptic judged sound):** Restore the refusal for every landed build: pause, withdraw and supersede are all refused once a push is made. State the deploy.released wait's arm as the only exception.
- **Gate:** A flow-steps fixture plants a withdraw at each landed Deploy item under each release mode, and asserts refusal everywhere except the deploy.released wait.
