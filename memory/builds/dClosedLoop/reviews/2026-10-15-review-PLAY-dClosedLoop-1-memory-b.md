## High

### H1. `record` mints ids but is never specified as idempotent or safe under concurrent minting, and the runtime layer depends on both (ids 2, 21, 49)

- **Where:** [contract] "One write command, `record`" (:304-308); [names] "The record command mints the slug" (:357); [determinism].
- **What is wrong:** The contract says `record` "mints the id; renders the template; refuses an invalid value". It says nothing about idempotence, content addressing, retry or concurrent minting. P30 (v2:373) and v2:753 repeat "mints ids". The later runtime layer bases its take-over safety on "`record` is content-addressed ... So a take-over never pushes twice" (layer-runtime.md:408-414). Its `once-per-instance` invariant (:761) and its return keying by item and task-sha (:494) depend on that property. It also lists `record` as a command adapter with an idempotence or reconcile probe (:739).
- **Consequence:** A sequential minter that re-runs after a supervisor death writes the same return, ask or decision row a second time, under a fresh id. In this multi-machine product, two clones that mint the next per-build counter also get the same id. Duplicate ids already occur: `TOOL-aUnmannedHelm-5` appears at DECISIONS.md:46 and :50, and `.memory-tree.conf:688` pins ROW_DUPLICATE_PIN="3". Runtime's `idempotence` test (:986) covers only the lander, so nothing catches a duplicate record. A builder working from this record alone would not build the property.
- **Fix (skeptic judged SOUND, on all three):** In [contract], state that `record` is idempotent on every write. Name each kind's id rule. It is either a minted ordinal, or a content key: a content hash, a caller-supplied write key stored in the record, or item plus task-sha for returns. A re-run with the same payload returns the existing id and writes no second record. State the concurrency contract: ids are content-addressed, or they are minted under the build lease and epoch with a collision check against the remote at write time. Add a reconcile probe for the command adapter, so the contract agrees with runtime [supervisor].
- **Gate:** a criterion on the `record` unit. Write one record twice and assert one record and one id. Kill a `record` write, re-run it, and observe one record. Make two concurrent `record` calls from two clones on one build and observe distinct, non-colliding ids.
