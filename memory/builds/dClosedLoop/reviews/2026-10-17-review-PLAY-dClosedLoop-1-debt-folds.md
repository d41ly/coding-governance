### H1. An attended or unbound session's gated calls are approved once the guard packs pass, so nothing judges a destructive command (finding 1)

- **Where:** layer-runtime:476-478 (`[act]`), with :609-612, :578-591, :1047-1048, :648 and :875 in v2.
- **What:** The fold of `attended-no-allowance` added "An attended or unbound session's gated call is approved once the guard packs pass, the write gate included." The record keeps its premise (:609-612) that the ask rule on every gated tool resolves before auto mode's classifier, so the classifier judges only ungated tools. Because the dispatcher answers allow, the person is never asked either. The guard packs (agent-cap, scratch-guard, gate-guard) gate writes, the flagged bar, self-test suites and AskUserQuestion. None of them judges whether a command is dangerous.
- **Consequence:** Under `runtime.hook-failure=closed`, the default in every preset, an attended or unbound session's `rm -rf` or `curl … | sh` runs without a prompt whenever the governance guards pass. Today the classifier or the person judges that call. The new `binding` fixture (:1047-1048) asserts only that benign calls are approved, so no arm notices. This contradicts "Auto mode stays, as the owner ruled" (:609), and dWellOiledMachine's chain row will build the clause as written.
- **Fix (judged sound by the skeptic):** State what the dispatcher answers for a non-act binding. Either it makes no decision, so the ask goes to the classifier or the person, or it approves only inside a declared attended allowance, which is a policy key with its reader. Add a `binding` arm in which an attended session's gated call outside that allowance, such as a planted `rm -rf` of a scratch path, goes to the person and is never approved. See that arm red against today's "approved once the guard packs pass" wording.
- **Left-shift gate:** the `binding` arm above, plus a checklist entry: every dispatcher allow names the judge that replaced the one it bypasses.
