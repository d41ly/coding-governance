### M1. The memory plan's deploy-overlay row still makes deploy.toml a home of level-0 units (id 1)

- **Where:** memory/builds/dClosedLoop/build/2026-10-18-build-PLAY-dClosedLoop-1-memory-plan.md:64
- **What is wrong:** The row's Becomes cell reads "node: units at level 0, written only through `instructions.edit`". IA-1 appears only as a trailing clause. The adopter-instructions record (design item 1) leaves `.governance/deploy.toml` with only the install answers and the kit selection, and moves the adopter rules to `.governance/instructions.toml`. The record's own [decided] lists "two homes for the repository's rules" as a contradiction, and the fold leaves half of it standing.
- **Consequence:** govkit writes deploy.toml today, in `add_deploy_kits` (tools/govkit/govkit.py:1006) and `intake` (:12761), and neither writer is in `[doors]`. A one-door check built from this row would refuse govkit's own writes. The alternative is that install answers get routed through `instructions.edit` as instruction units, which is also wrong.
- **Fix (skeptic judged sound):** Rewrite the Becomes cell as: the install answers and the kit selection only, not instruction units, written by govkit's `intake` and kit-offer verbs under dGroundRules' minimal guard (SA-12), with the adopter rules gone to the instruction-overlay row. List govkit's deploy.toml writers as a door in `[doors]`. Probe: `grep -n 'deploy.toml' tools/govkit/govkit.py`.
- **Left-shift gate:** Add a doors check that cross-references every writer of a pocket path found in tools/ against that pocket's `[doors]` entry. Add a checklist entry for the class amendment-leaves-its-other-half-standing.

### M2. No owning build arms the step gate's later member classes (ids 2, 20)

- **Where:** memory/builds/dClosedLoop/build/2026-10-14-build-PLAY-dClosedLoop-1-architecture-v2.md:1444 (dSafePassage), :1445 (dOrderedCharter), the dTotalRecall row, and v2's [owed] (around :1591)
- **What is wrong:** The step gate says record-kind schemas, policy keys and gov's instruction-unit tags join "when its owning build lands it". dSafePassage plants reds only for an installed-file rename, an agent rename and a registry removal. Neither dOrderedCharter's row (unit tags) nor dTotalRecall's row (record-kind schemas) registers its class or plants a red for the join. dWitnessedBar and the namespace joins, by contrast, are armed by named owners. The design record's [owed] item "The map every restructuring release ships, checked by the step gate" (adopter-instructions.md:246) was also dropped from v2's [owed].
- **Consequence:** Nothing can fail when a landing drops a gov unit tag with no change record. Every adopter `amends` or `supersedes` edge pinned to that tag is then orphaned with no successor. That is the failure IA-2 and IA-3 exist to prevent, and it is the 63-of-102 burst that the history research measured.
- **Fix (skeptic judged sound):** On dOrderedCharter's row, register the unit-tag class into the step gate's population. Plant a removed gov unit tag with no change record (red) and one with `retired:<successor>` (green), and assert the population is non-empty. On dTotalRecall's row, do the same for record-kind schemas. In dSafePassage's clause, name the owning builds for policy keys and CLI verbs. Restore the "map every restructuring release ships" item to v2's [owed].
- **Left-shift gate:** Add a design-lint check that every "joins when its owning build lands it" population names an owner row, and that the owner row carries a planted-red clause for the join.

### M3. dOrderedCharter's native-id edge has no class it can resolve (id 3)

- **Where:** architecture-v2.md:1445, and memory-plan.md:21-22 ([frame])
- **What is wrong:** dOrderedCharter plants and resolves "one edge per address form, tag, section and native id". Every native-id class the clause names is registered by a later build: commits by dDeclaredLoop, acts and sessions by dWellOiledMachine, landings by dShippedRelease. The [frame] says "each native-id class registered with its owner", but `FAMILY-<slug>-<seq>` ids and gap keys have no registering owner anywhere.
- **Consequence:** At dOrderedCharter's landing the native-id arm either reds or is written against a stub. The rule in [frame] binds nothing for FAMILY ids and gap keys. This breaks the rule that a clause names no later build's key.
- **Fix (skeptic judged sound):** Give FAMILY ids and gap keys an owner (dOrderedCharter or dTotalRecall), and plant the native-id edge against a class that dOrderedCharter or an ancestor owns. State that each later class's resolution arm is armed by the build that registers it, as the namespace joins already are.
- **Left-shift gate:** Add a check that each class a clause names resolves to a registering build that is the clause's own build or an ancestor in the chain table (step-depends-on-a-later-build).

### M4. The systems record's unit schema was not folded for IA (ids 4, 5, 14)

- **Where:** memory/builds/dClosedLoop/build/2026-10-16-build-PLAY-dClosedLoop-1-systems.md:347-352 ([design-instruction-writing]) and :251-253 ([design-tags], "Mint, rename, retire"), against architecture-v2.md:1445
- **What is wrong:** v2's registry now gives each unit an `owner` (a kit or the repository), a `class` (fixed or open) and pinned `amends`/`supersedes` targets. The systems record's field list still reads `tag, type, level, select, when, text|source, required-by, enforced-by, budget, status (active | retired:<forward-tag>), help`, and it still says the overlay is "merged by row key". The change record still allows one successor (`retired → <new>` or `→ none`), although design item 10 widens it to a list for a split. v2's pins-and-drift clause re-points an edge on a rename and orphans it on a split, but with a single successor the two cannot be told apart.
- **Consequence:** A unit built from the schema of record has no `class`, so the IA-4 refusals have nothing to read. "Merged by row key" describes the override path that IA-2 rules out. A split recorded with one successor silently re-points an adopter's edge onto one half and keeps the old pin, so the edit is reapplied over changed text and nobody sees it.
- **Fix (skeptic judged sound):** Add `owner`, `class` (fixed or open) and `edges` (with the `<tag>@<hash>` pin on `amends` and `supersedes`) to the unit fields. Widen `status` to `retired:<tag>[,<tag>]` or `retired:none`, and make the change record's successor a list. Replace "merged by row key" with: composed with each kit's manifest, repository rows under `repo.` only, gov rows changed only through edges (IA-1, IA-2). Date a revision note that cites IA-2, IA-4 and design items 8 and 10. Have dOrderedCharter plant a split and see the edge orphaned, not re-pointed.
- **Left-shift gate:** Add a check that diffs the unit field list in the systems record against v2's registry clause, so the two copies of the schema cannot drift. Alternatively, single-source the field list.

### M5. The adopter-instructions [chain] puts gov's receipt and self-update on dShippedRelease, and [folded] drops it without a word (id 6)

### M6. `instructions.stale`'s `refuse` and `warn` values have no route (id 11)

- **Where:** architecture-v2.md:992 (catalogue), :1268 (presets: velocity `warn`, strict `refuse`), :1445 (pins and drift)
- **What is wrong:** dOrderedCharter routes only the order case ("filing an order as `instructions.stale` says"). Its planted cases (editorial, semantic, rename, split, retirement) are not per value. No clause says what `refuse` holds or what `warn` does. The sibling key `instructions.edit` does get "each value given its arm, witness and planted red".
- **Consequence:** A strict repository is configured with a value that nothing implements. When gov makes a semantic change under one of its pinned edges, the update's behaviour is undefined. dGroundRules' dead-key arm checks keys, not values, so nothing reds the gap.
- **Fix (skeptic judged sound):** `refuse` holds the update and names the stale edge (IA-3's second option). `warn` renders both texts and prints the stale edge with no order. Plant a stale pin under each of the three values and see each outcome.
- **Left-shift gate:** Extend dGroundRules' dead-key arm to dead values, so every catalogued value needs a named arm and planted red (memory/gotchas/policy-value-with-no-route.md).

### M7. The pinned target `<tag>@<hash>` is outside the address grammar and every edge check (ids 12, 23)

- **Where:** memory-plan.md:20 (address model), :150 (unit-site row), :133 (target resolves); architecture-v2.md:1445
- **What is wrong:** The fold adds `<tag>@<hash>` as the target form for `amends` and `supersedes`. The address model still lists three forms (tag, section, native id). dOrderedCharter plants "one edge per address form, tag, section and native id". No rule says how target-resolves parses the pin or checks its shape. (The skeptic refuted the claim that `supersedes` is typed as a retirement: "retirement" at :177 sits in the "Needed by" column.)
- **Consequence:** Target-resolves can go one of two ways. It may red every pinned edge, which a planted overlay would catch. Or it may strip the suffix unchecked, which lets a truncated hash or a pin on a non-instruction edge pass. That weakens the stale-pin detection IA-3 depends on.
- **Fix (skeptic judged sound):** Register `<tag>@<hash>` as a fourth address form, legal only on `amends` and `supersedes` from an instruction unit. Target-resolves resolves the tag and validates the hash's shape. Plant a well-formed pin (green), a malformed hash (red), a pin on a non-instruction edge (red) and an unpinned `amends` from an overlay unit (red).
- **Left-shift gate:** Add a check that every address form used in any edge row of the memory plan appears in the [nodes] grammar and in dOrderedCharter's planted forms.

### M8. A vanishing gov unit tag has two succession witnesses (id 13)

- **Where:** architecture-v2.md:1444
- **What is wrong:** The step-gate clause says a unit tag vanishes "only with a change record naming its successor". The same sentence reds any removal, rename or retirement of a member with no `[[upgrade]]` or `[[retired]]` row naming it in `surfaces`, and unit tags are members.
- **Consequence:** Either every unit rename states its successor twice, with the two copies free to disagree, or the leg silently exempts unit tags. The design does not say which witness the leg reads.
- **Fix (skeptic judged sound):** Pick one witness. Either the gate reads the change record's successor for the unit-tag class, stated as that class's exemption from the `[[retired]]` rule, or the `[[retired]]` row is derived from the change record and never typed. Plant a rename that carries only one of the two witnesses.
- **Left-shift gate:** Add a checklist entry: one question, one witness. Any rule that names two artefacts answering the same question must declare which one is derived.

### M9. A repository's own `repo.` policy keys have no reader or schema (id 15)

- **Where:** architecture-v2.md:1445 and :1443 (dGroundRules); adopter-instructions.md:150 (design step 7)
- **What is wrong:** Repository keys under `repo.` are "read only by its units and outside the presets' completeness check". dGroundRules, the only reader and schema owner of policy keys, resolves only file override, then preset, then catalogue default, and draws its dead-key arm from the catalogue. Nothing says which file holds a `repo.` key, how its values are declared, or whether the schema admits it. `repo.` is also the systems record's namespace for repository units.
- **Consequence:** A `repo.` key is either refused or read unvalidated. A unit and a key with the same `repo.<seg>` resolve to two nodes under one tag.
- **Fix (skeptic judged sound):** Either dGroundRules' schema admits a declared `repo.` key set, with each key's allowed values declared in the overlay and checked like catalogue keys, or the keys move to `policy.repo.<key>`. Plant a repository key and a same-named repository unit, and resolve both.
- **Left-shift gate:** Add a namespace-collision check across the tag registry: one prefix maps to one node kind.

### M10. The `editorial` mark that silences a stale pin is never checked (id 18)

- **Where:** architecture-v2.md:1445; adopter-instructions.md:155-157
- **What is wrong:** Each gov change record declares itself `editorial` or `semantic`, and a pin behind editorial changes alone stands. No check, witness or planted red verifies the mark.
- **Consequence:** A meaning change mislabelled `editorial` reaches an adopter's `supersedes` edge with no order, and `instructions.stale` never fires. The path is narrow, since it requires a mislabel inside gov's own review, hence medium.
- **Fix (skeptic judged sound):** Accept `editorial` only when the normalised before/after diff falls in a mechanical class (whitespace, punctuation, a declared spelling map), or after a review breakpoint rules on it. Otherwise grade the change `semantic`. Plant a meaning change marked `editorial` (red) and a punctuation-only change marked `editorial` (green).
- **Left-shift gate:** Add a checklist entry for inputs-inside-the-subject's-reach. A label typed by the side a check distrusts must itself be verified.

### M11. dOrderedCharter names no upgrade step for its three adopter-visible IA changes (id 19)

- **Where:** architecture-v2.md:1445 ("its own upgrade steps"), compared with :1450 (dBoundRoles) and :850-854 (P38)
- **What is wrong:** The row moves `[charter] adopter_rules` out of deploy.toml, retires the seeded charter template, and moves gov-only units out of the shipped set. Its upgrade-step list still names only agent-instructions' wiring and the `map_lib` re-export. dBoundRoles' house-file move in the same fold does name its step.
- **Consequence:** dOrderedCharter's own landing reds at the step gate. If the gate's population misses the key, an adopter's existing rules silently stop rendering at update. Adopter edges on census-moved units are orphaned with no change record.
- **Fix (skeptic judged sound):** Add three items. (1) A step converting each `adopter_rules` entry into a level-0 `repo.` unit, with a down step. (2) A `[[retired]]` row for the seeded template, with an inventory of its readers by value. (3) A change record naming successor `none` for every census-moved unit. Each must be red at the step gate without its row and green with it.
- **Left-shift gate:** Add a design lint that every chain row whose clauses move, retire or remove an adopter surface lists a matching item in its "own upgrade steps".

### M12. Fixed-unit class is hand-declared and unverified (id 21)

- **Where:** architecture-v2.md:1445; adopter-instructions.md:151-153
- **What is wrong:** A fixed unit is "every unit a gov tool parses", but no query derives that population and no arm reds a parsed unit declared `open`. The planted refusals test only units already classed fixed. This runs against the house rule that populations are "derived by query ... never typed" (:1443).
- **Consequence:** If a parsed unit (the micro-format grammar, the loop's contracts) is mis-declared `open`, an adopter can supersede or exclude it, and the parsing tool breaks in that repository.
- **Fix (skeptic judged sound):** Derive the parsed-unit population from the units read by registered parsers or extractors. Red any member not classed `fixed`, and treat an undeclared class as fixed. Plant a parsed unit declared `open`, which must red.
- **Left-shift gate:** Add a checklist entry: every typed classification that a refusal reads needs a derived population and a planted mis-declaration.
