## 1. Goal

Landing 12764ec21 aborted before its bar because `run_regen` left a tracked file dirty by line endings
only. `git add -A` then staged nothing, and the regen `git commit` failed. This unit gives the lander
one helper that stages the tree and answers whether the stage differs from HEAD. All four
dirty-then-stage sites in `tools/push-main.sh` call it, so a stage that changed nothing commits
nothing and the landing goes on to the bar.

## 2. Scope (IN)

- **S1** — `tools/push-main.sh` defines `write_staged_change`, the one place the lander stages its
  working tree. It returns 1, staging nothing, when `git status --porcelain
  --ignore-submodules=untracked` prints nothing. Otherwise it runs `git add -A` and then
  `git diff --cached --quiet`. It returns 1 when that exits 0, meaning the stage equals HEAD. It
  returns 0 on any other exit, so a real staged diff, or an error from `git diff`, reaches the
  caller's commit. Observed by AC2 and AC3.
- **S2** — The three attended commit sites call `if write_staged_change; then` in place of their
  inline dirty test and `git add -A`. These are the mint, gov-first and regen sites in the attended
  landing loop. Each site's `read_mint_unit` call, its `git commit -q --no-verify` line, its
  `Pass: none` trailer and its refusal line stay byte-identical. Observed by AC1, AC3, AC4 and AC5.
- **S3** — `write_merge_fold` opens with `write_staged_change || return 0` in place of its inline
  dirty test and `git add -A`. A fold over a stage equal to HEAD then leaves the prepared merge
  where it is, instead of rewriting it with a new commit over the same tree. Observed by AC2 and AC3.
- **S4** — `tools/push-main.test.sh` gains arm 42, the incident's shape on the attended landing. The
  regeneration rewrites a tracked file, checked out with CRLF bytes, with its committed LF bytes
  while `core.autocrlf=true`. Observed by AC1.
- **S5** — `tools/push-main.test.sh` gains arm 43. It cuts `write_staged_change` and
  `write_merge_fold` from the lander and runs the fold twice on a detached merge: once over a
  line-ending-only dirt, and once over a real content change as its control. Observed by AC2.
- **S6** — The lander's header paragraph on regenerated outputs states that each lander commit is
  made only when the stage holds a diff, so a regeneration that changed nothing commits nothing.
  Observed by AC6.

## 4. Design

### The defect, reproduced

The incident's shape was reproduced on node d with Git 2.54.0.windows.1, in a scratch repository
under `%TEMP%`, on 2026-11-19. The repository had `core.autocrlf=true`, a tracked file committed with
LF bytes and checked out with CRLF bytes. The file was then rewritten with its committed LF bytes.
`git status --porcelain` printed ` M f.txt`, because the index's cached size is the CRLF size and
git reports a size change without hashing the content. `git add -A` warned `LF will be replaced by
CRLF` and staged nothing, so `git diff --cached --quiet` exited 0. `git status --porcelain` was empty
afterwards. `git commit` exited 1 with `nothing to commit, working tree clean`. The same recipe
reproduces with `core.autocrlf` set through `GIT_CONFIG_COUNT`, the channel the suite already sets
its own identity and line endings through (`tools/push-main.test.sh@5235ec755ced:197`).

`.governance/instructions.lock` carries `text=auto` and `merge=ours` and is checked out as
`i/lf w/crlf` on this node, per `git ls-files --eol` and `git check-attr -a`. That is the shape
above.

### The four sites

All four sites are read at blob `cd8cf5622e82`, which is the base `12764ec2`'s blob. `tools/` is
unchanged between that base and HEAD `0563a02e`.

|---|---|---|

| regen | `tools/push-main.sh@cd8cf5622e82:1393` | `git commit` exits 1, and the landing aborts with `could not commit the regenerated outputs`, the incident |

The fold has two callers in `cmd_prepare`, after gov first's walk and after the regeneration
(`tools/push-main.sh@cd8cf5622e82:1160`, `:1177`). An empty fold does not refuse today. It only
rewrites the prepared merge, which S3 stops.

### The helper

```bash
# `write_staged_change` stages the working tree and answers whether the stage now differs from HEAD.
write_staged_change() {  # -> 0 the index differs from HEAD · 1 the tree was clean, or staging left nothing
  [ -n "$(git status --porcelain --ignore-submodules=untracked 2>/dev/null)" ] || return 1
  git add -A
  git diff --cached --quiet && return 1
  return 0
}
```

The comment above the definition names the incident, 12764ec21, and why a dirty status does not
imply a staged diff. The builder writes that prose.

- **The dirty predicate stays spelled as it is today.** Arm 13 counts that spelling in the lander
  (`tools/push-main.test.sh@5235ec755ced:490`), and it remains present in the helper and the
  attended path's opening check.
- **An error exit from `git diff --cached --quiet` returns 0.** The caller's commit then runs and
  refuses with its own line, which is today's behaviour on a broken index. Reading an error as
  "nothing staged" would land a tree the lander never committed.
- **The skip is silent.** The helper returns the same 1 for a clean tree and for a stage equal to
  HEAD, and the clean-tree path prints nothing today. Git's own line-ending warning is already on
  stderr when the shape occurs.
- **After `git add -A` the index's cached stat matches the rewritten file**, so the tree is clean
  for the push hook's dirty check. This was measured in the reproduction above.

The callers take these exact shapes, which AC3 counts:

```bash
  if write_staged_change; then
    mint_unit=$(read_mint_unit "$mt..HEAD")
    if ! git commit -q --no-verify -m "mint: …" -m "Pass: none"; then   # unchanged
      …
```

```bash
write_merge_fold() {  # signature and contract comment unchanged
  write_staged_change || return 0
  t=$(git commit-tree "$(git write-tree)" -p "$1" -p "$2" -m "$3") && git update-ref --no-deref HEAD "$t" || return 1
}
```

### Arm 42 — the attended landing over a line-ending-only regeneration

Arm 42 sits inside the existing `if [ -n "$_rg_k" ]` block of arms 28 to 32, and its skip line joins
theirs. It runs in a subshell, as arm 29 does (`tools/push-main.test.sh@5235ec755ced:1148`). It
reuses `build_regen_fixture` (`tools/push-main.test.sh#build_regen_fixture`).

1. `build_regen_fixture "$tmp/remote42.git" "$tmp/work42"`, then record `R42=$(git rev-parse HEAD)`.
2. Commit a tracked file `eol-only.txt` holding LF bytes, and a planted `regen.py` beside the lander
   that rewrites it with the same LF bytes, opened in binary mode. Commit with `--no-verify`, as
   arm 32 does. That commit is what the landing pushes.
3. `export GIT_CONFIG_VALUE_0=true` inside the subshell, so every git below runs with
   `core.autocrlf=true`, the lander's included. Then `rm eol-only.txt` and
   `git checkout -- eol-only.txt`, which writes CRLF bytes and caches their size.
4. **Liveness, before the landing.** Run the planted `regen.py`. Echo `eol-dirty=1` when
   `git status --porcelain` names `eol-only.txt`. Run `git add -A`, and echo `eol-empty=1` when
   `git diff --cached --quiet` exits 0. Restore the shape with `rm` and `git checkout --` again.
   Echo `clean=1` when `git status --porcelain` prints nothing. Without this step the arm passes on
   a git that no longer produces the shape (`memory/gotchas/fixture-passes-by-finding-nothing.md`).
5. `unset GATE_PUSH_BASE; bash "$lander" 2>&1`, echoing `rc=$?`.
6. Echo `landed=1` when `origin/main` equals HEAD. Echo `regen-commits=<n>` with the count of
   commits in `R42..HEAD` whose subject starts `regen: generated outputs`.

Passing means the output carries `eol-dirty=1`, `eol-empty=1`, `clean=1`, `rc=0`, `landed=1`,
`regen-commits=0` and the lander's `gating + pushing` line. The `ok` line says the lander skipped an
empty regen stage and reached the bar. The `bad` line prints the captured output whole, so the RED
observation shows the lander's own refusal text.

**The suite source never spells the refusal text.** `memory/project/unarmed-branches.txt` pins the
regen refusal as unarmed, and `check-arms.py` reds when a pinned branch gains a positive assertion
naming its text. This arm does not stage the commit failing, so the pin is still true, and the arm
must not read as arming it.

### Arm 43 — the fold over a line-ending-only stage, with its control

Arm 43 cuts `write_staged_change` and `write_merge_fold` out of `"$lander"` with
`eval "$(sed -n "/^$f() {/,/^}/p" "$lander")"`. That is arm 38's idiom
(`tools/push-main.test.sh@5235ec755ced:1541`). It runs them in a fresh `git init` repository under
`$tmp`, in a subshell. Against the base lander the first cut finds nothing and the old fold runs,
which is the RED case.

1. Commit `f.txt` with LF bytes on `main` under the suite's `core.autocrlf=false`. Commit a second
   file on a side branch. Make a detached `--no-ff` merge of the two, and record its parents
   `P1`, `P2` and the merge `M`.
2. `export GIT_CONFIG_VALUE_0=true`, then `rm f.txt` and `git checkout -- f.txt`, and rewrite it
   with its LF bytes. Export `GIT_COMMITTER_DATE` and `GIT_AUTHOR_DATE` as a fixed date years before
   the fixture, so any rewrite of `M` gets a sha distinct from `M`'s. Without the pin, a rewrite
   in the same second as the original merge reproduces the same sha and hides itself.
3. `t=$M; write_merge_fold "$P1" "$P2" "msg"` and echo `eol-rc=$?`. Echo `eol-head=same` when HEAD
   is still `M`.
4. **Control.** Write different content to `f.txt`, run the fold again, and echo `real-rc=$?`. Echo
   `real-moved=1` when HEAD is no longer `M`, both parents are `P1` and `P2`, and `HEAD:f.txt`
   carries the new content.

Passing means `eol-rc=0`, `eol-head=same`, `real-rc=0` and `real-moved=1`. The control is what
stops a helper that never stages from passing.
