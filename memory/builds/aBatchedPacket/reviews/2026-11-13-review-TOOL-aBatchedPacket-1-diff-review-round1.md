## HIGH

### H1 — Fixture T cannot fail on the content of the batched parent-spec read (finding 9, high)

**Where:** `tools/chain-packet.test.sh@d3ee4c14:253` (the trim to two parent specs, lines 253-259); the silent cache-off branch at `tools/chain-packet.py@d3ee4c14:160`.

**What is wrong:** The suite keeps only the first two tracked specs of the parent build dTrueNorth. The packet uses a parent's spec text only through `tree_state`'s two booleans. With those two specs the state is (False, False) for the real texts, for two empty strings, and for the two texts swapped; the full 30 specs give (True, True). So a `read_git` cache that returns a wrong blob, an empty string or a wrongly decoded text prints the same `specs done no, build done no` line, and CP3, CP4 and CP5 pass. The `OSError` branch and an all-None batch answer also empty the cache with no stderr line, so the arms cannot tell whether the cache answered at all.

**Consequence:** The spec names these equality arms as the standing check of `read_blobs_at`'s decode, and AC5's stated red condition (`read_git decodes a parent spec otherwise`) cannot occur on this fixture. No wrong result ships today. The check certifies a read it does not exercise, so a later defect in the cache key, the CR fold or the batch reader's decode would ship a wrong `specs done` or `build done` line in a real packet with the leg green.

**Fix (judged SOUND by the skeptic):** Make the parent state depend on the text. Keep the parent specs that together carry all of the parent's clauses with a CLOSED status, so the instrument prints `specs done yes` in T, and assert that string in CP3 and CP4. Add one arm that loads the door, calls `set_reads`, and compares `schedule.git("show", ref:path)` with the real git for each kept parent path, one of them holding a lone CR, and asserts the answer came from the cache. The probe the build must run: make `read_git`'s cached return `""` and see an arm red.

**Left-shift:** class `fixture-passes-by-finding-nothing`. The gate is the staged break itself, recorded in the suite: an equality arm over a shortcut is admitted only with a named mutation of the shortcut's answer that reds it.

### M6 — The batched parent read and the instrument's own git run under different environments (finding 6, medium)

**Where:** `tools/chain-packet.py@d3ee4c14:159` (`read_git`, lines 155-168); the scrub at `tools/memory-tree/tree_lib.py@d3ee4c14:325`.

**What is wrong:** `read_git` takes the path list from the instrument's ambient `git ls-tree`, then answers the following `git show HEAD:<p>` from `tree_lib.read_blobs_at(".", ...)`. That reader runs under `build_git_env` less `GIT_ENV_LEAKS`, so `GIT_DIR`, `GIT_WORK_TREE`, `GIT_INDEX_FILE` and the rest are stripped. The instrument's own `git()` inherits them. Probe, from the worktree root with `GIT_DIR` exported at the primary checkout: ambient `git rev-parse HEAD` printed `8db6f4bef58d`, and `read_blobs_at`'s own printed `d3ee4c1492c0`.

**Consequence:** Whenever a location variable is ambient (the door or the checker started from a git hook, or from a shell that exported `GIT_DIR` for another tree), the fast path fills its cache from a different commit than the one the instrument's `ls-tree` and `show` read. `tree_state`, and with it the parents section and the byte compare, can then differ from the instrument's verdict in either direction, with no `shortcuts off` line. The docstring's does-not-check list does not name it, and no arm or `--parity` run in a clean shell sees it. It is narrow: gov's own pre-push scrubs these variables, and under such a variable the instrument's own verdict is already a mix of cwd files and foreign history.

**Fix (judged SOUND by the skeptic):** In `read_git`, or as a `reasons` entry in `main`, skip the batch when any name of `tree_lib.GIT_ENV_LEAKS` is set in `os.environ`, so the instrument's own git answers. Add a suite arm that runs CP3's pair with `GIT_DIR` exported at another repository and asserts equal stdout. The probe the build must run: that arm red before the guard, green after.

**Left-shift:** new class `batched-read-scrubs-the-env-its-twin-inherits`: a shortcut that answers a child's git read in-process must read under the child's environment, or decline. The suite arm above is the gate for this instance; the class entry goes into the bug-class checklist.
