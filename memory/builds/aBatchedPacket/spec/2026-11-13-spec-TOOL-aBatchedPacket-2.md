### H1 — fixture T and CP8 (S1, S2)

Fixture T keeps the first two tracked specs of `$SLUG`, as it does, and every tracked spec of
`$PARENT` holding a line that matches `^\*\*(Carries|Moved|Retired|Deferred):\*\* cl-`. That
pattern is a copy of `schedule.py#CARRY`'s head. The copy is graded by CP4: a pattern that keeps
too few specs leaves a clause uncarried and the parent line reads `specs done no`. The precondition
becomes two kept specs for `$SLUG` and at least one for `$PARENT`, exit 2 otherwise.

The trim commit also appends one line holding a lone CR, a CR with no LF after it, to the first
kept parent spec. The line matches neither `STATUS` nor `CARRY`, so the state is unmoved.

CP4 gains one assertion inside its condition: the packet file the door's `--write` named holds a
line opening `- $PARENT: specs done yes, build done yes`. The instrument's `--check` in the same
arm already compares that file with its own render, so a door that read a parent text otherwise
fails both.

CP8 is a new arm. It feeds one Python probe on stdin to `"$PY" - "$DOOR" "$PARENT"` with T as the
working directory. The probe:

1. Loads the door by path, and exits 1 naming the role when `scan_moved(resolve_instruments())`
   is not empty.
2. Lists the parent's spec paths with its own `git ls-tree -r --name-only HEAD` over
   `memory/builds/<parent>/spec/`. For each path it takes the expected text from its own
   `git show HEAD:<path>` run with `text=True, encoding="utf-8"`, and the raw bytes from its own
   `git cat-file blob`, in which it counts a CR not followed by LF.
3. Loads `tree_lib` and the packet instrument as the door's `main` does, calls `set_reads`, and
   makes the instrument's `ls-tree` call through `packet.schedule.git`.
4. Rebinds the schedule module's `subprocess` name to a stand-in whose `run` raises. From here a
   `show` the cache does not answer raises.
5. Calls `packet.schedule.git("show", "HEAD:<path>")` for each path and compares the answer with
   the expected text.
6. Prints `chain-packet.test: cache answered <n> of <n> parent path(s) · <k> holding a lone CR`
   and exits 0. It exits 1 naming the first path that raised or differed, and exits 1 when `n` or
   `k` is 0.

The arm passes on exit 0 and that line. The expected text never passes through the door, so the
arm shares no state with the cache it grades.

### What it does not check

Added to the door's docstring and the suite header, beside unit 1's list, which stands.

- **A git variable outside `GIT_ENV_LEAKS`.** The batch reader and the instrument's git still run

  only on the twelve names the kit's reader strips.

  the parents the slow way and CP3 to CP5 would red on its notice.

  reads it; CP8 holds no such path.
