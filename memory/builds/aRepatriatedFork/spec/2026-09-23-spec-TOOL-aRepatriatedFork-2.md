## 1. Goal

Gov's shipped engines still spell gov's own `tools/` prefix, or a sibling kit's directory name, in
strings an adopter RUNS or READS at run time: argv, path joins, generated file content, and repair
or deny messages. At both adopters that breaks silently — a leg exits 2, a signal reports "not
asked", a hook prints "could NOT run" every session — and each adopter answers with a local fork.
This unit derives every such spelling, routes every sibling-kit lookup through one resolver, and
adds a zero-tolerance arm over CODE lines that the shipped-prefix ban cannot see.

### The resolver

```
resolve_kit_dir(home, anchor) -> the directory holding <anchor> of the kit gov homes at tools/<home>
  1. receipt  — .governance/install.json: the row whose `source` is tools/<home>/<anchor>
                and whose `path` exists in this tree -> dirname(path)
  2. probe    — <here>/<home>/<anchor>, then <here>/../<home>/<anchor>
  3. refuse   — a named error listing the three places looked; never a guessed prefix
```

The key is the kit's HOME directory under gov's `tools/`, not its registry id, because the two
differ for three directory kits: agent-cap homes at `tools/hooks`, review-harness at
`tools/workflows`, and playbook-render at `tools/playbook`. The flat kits have no directory to
resolve. The receipt's `source` column spells the home, so the home is the join key that resolves.

Rung 1 is what reaches inCMS, which homes memory-recall at `scripts/recall/` and memory-tree flat at
`scripts/`: no probe can find a renamed directory, and the receipt is the only record of where
govkit put the file. The receipt spells `source` in gov's own layout, which is correct there because
it is gov-side data. Rung 2 is nc's carve-out 8 order and is what answers in gov itself, which has
no receipt. `tools/run-gates/check-receipt.py:48` is the existing engine that already reads the
receipt at an adopter.

The receipt join (rev-4) compares the last two segments of `source` with `[<home>, <anchor>]`, so the
resolver spells no prefix of its own. It returns an absolute directory; the shell form,
`resolve_kit_dir <python> <home> <anchor> <here>`, runs the same block through a quoted heredoc and
prints the directory repo-relative.

Python consumers carry the function as an inline copy with a canonical source and a parity arm, the
pattern `resolve_python` already uses (`tools/lib/resolve-python.test.sh`). A shell consumer that
already resolves a Python gets rung 1 by calling it with a one-line import of the canonical copy,
and never parses JSON in bash; a miss on every rung is announced, never silent (§8 F1).
`tools/check-wiring.sh` has no resolved interpreter, so it alone reads the receipt with an awk rung
and a parity arm against the Python resolver, which `TOOL-aRepatriatedFork-19` owns. The one JS
consumer, `agent-cap.js`, only needs a message: it derives its own path from `__filename` and names
the review harness by probing `path.join(path.dirname(__dirname), 'workflows', 'tier2-review.js')`,
and prints the bare harness name when the probe misses.

### The runtime arm

Arm 3 of `tools/check-install-prefix.sh`, run only inside `TOOL-aRepatriatedFork-16`'s kit-source
branch. Its population is `govkit.py shipped` rows with role `engine` or `rendered`, minus the
gate's existing `SUFFIX_EXCL`. A `seed` is out: written once and adopter-owned after. So is
`merged` (rev-4): no writer lands that role (`tools/govkit/govkit.py`'s `UNLANDED_REASON`), which is
the reason §3 already gives for putting `.githooks/pre-commit` out, and the role's only other member
is a `.toml` snippet the arm does not read.

It classifies each line as code or prose, then applies three predicates to code only:

| Predicate | Matches | Language |
|---|---|---|
| P1 | `tools/<seg>` after a non-path lead character OR after `$VAR/` / `${VAR}/`, where `<seg>` names a tracked kit directory or a tracked loose file | all |
| P2 | a quoted `tools` segment joined by `/` or passed to `os.path.join` / `path.join` next to a segment P1 would accept | py, js |
| P3 | a quoted kit home name used as a path segment beside `/`, outside the resolver's own copy | py |

Code is: for `.py`, `tokenize` STRING and f-string tokens that are not a docstring, plus the source
text of path expressions; for `.sh` and extensionless hooks, every line whose first non-blank byte
is not `#`, heredoc bodies included because they are printed; for `.js`, text outside `//` and
`/* */`; for `*.fragment.json`, the `hook_path` value. P1's existence filter is the ban arm's
epoch-2 filter (`:460-470`), so fixture names like `tools/gate-a.sh` never hit. P1's non-path lead
class excludes `-`, as the ban's epoch 4 does, so a `${VAR:-…}` default is a hit (rev-4).

A hit exits 1 and names `<path>:<line>`. The marker is `gov:prefix-literal — <reason>`, with the
three-state reading `check_marker_reason` already applies to `gov:root-fixture` (`:258-264`): no
marker, a marker with no reason (a refusal), a marker with one. The header states what the arm
cannot see: a path assembled from two variables, a literal inside `eval` or `sh -c` text, and Python
paths built by `str.join`.

### Alternatives rejected

- **Widen the ban arm's predicate instead of adding an arm.** The ban counts prose and code alike
  and is shrink-only; a runtime literal is a defect today, not a count to drain, and folding it into
  a ratchet would let one ride on the next legitimate drop.
- **Render sibling-kit paths at install time.** `tools/hooks/README.md` says a sibling kit is a
  render token, but `govkit apply` writes engine bytes verbatim with no substitution
  (`tools/govkit/govkit.py:5712`, `dp.write_bytes(data)` with nothing between read and write), so a
  render token in an engine would ship as a literal brace.
- **A conf key per sibling kit.** It moves the literal into the adopter's conf, where it rots
  against the receipt that already records the answer.

## 5. Production-readiness checklist

- security — the resolver reads `.governance/install.json` and joins a `path` onto the repo root; a
  row whose path escapes the root or does not exist is skipped, never followed.
- perf / scale — arm 3 tokenizes the shipped Python once per run; measured at this scale the
  `tokenize` pass over 43 files takes under a second. The resolver reads the receipt once per
  process.
- error / empty / loading states — an empty shipped set is a dead probe and refuses. The resolver's
  third rung refuses by name. A shell consumer's miss is printed, never silent.
- observability — every arm-3 hit names `<path>:<line>` and its predicate; every marker is counted
  on the clean line, as the root-fixture markers are at `:320`.
- risks — the rollout touches eleven kits and each needs a version bump; one missed bump is exactly
  what `TOOL-aRepatriatedFork-15` gates. The resolver's receipt rung makes engines read a govkit
  file for the first time outside run-gates.
- testing — AC1-AC8 each observe one class on a `scripts/` fixture; AC9 and AC10 bracket the arm.
- migration — adopters take verbatim bytes and delete the records in §4's Migration table.
- user docs — `tools/hooks/README.md`'s "names nothing outside itself" rule gains one line: an
  engine resolves a sibling through `resolve_kit_dir`, because engines are not rendered.
