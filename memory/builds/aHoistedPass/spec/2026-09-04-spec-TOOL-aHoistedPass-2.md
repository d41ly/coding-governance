### The ratchet

Arm B today is six lines at `tools/unattended/check-unattended.sh:1589-1594`. The carrier guard is
`:1589`, the loop `:1590`, `sec=${pair#*:}` `:1591`, the whole assertion
`grep -qE "^## $sec( |\$)"` at `:1592`, and its refusal `fail 16` at `:1593`. **It asserts that the
section EXISTS and never opens its body.** The silence rule for a missing carrier is stated at
`:1586-1588` and the new term inherits it unchanged.

The term slices `$M/guides/BUILD-METHOD.md` from `^## <section>( |$)` to the next `^## `, strips
whole HTML comment blocks, and requires the handle in backticks in what is left.

**The comment strip is BLOCK-WISE, spanning lines, and that is the whole point of the term.** A
predicate that drops lines MATCHING `^[[:space:]]*<!--` drops only a comment's first line, so a
multi-line comment carrying the anchor on a continuation line satisfies it while the section still
states no rule. Measured here on four fixtures built from the real
`memory/guides/BUILD-METHOD.md`, with `passes-harnessed` as the probe:

| fixture | line-prefix filter | block strip |
|---|---|---|
| the file as it stands | RED | RED |
| an honest rule sentence carrying the backticked anchor | PASS | PASS |
| a single-line `<!-- anchors: … -->` | RED | RED |
| a MULTI-line `<!-- … -->` with the anchor on line two | **PASS** | **RED** |

The naive form admits the evasion and the block form refuses it, with the honest sentence green in
both. That is the measurement, and it is why the strip is written as a block.

**Three properties the term needs, each read at source.**

- **CORE-only.** `core` is built from `$DIRECTIVES_CORE $DIRECTIVES_EXTRA` at `:1475-1480` while
  `corescope` is built from CORE alone at `:1481-1486`, and the comment at `:1471-1473` gives the
  reason: a project's own rows are hand-authored and must not red an adopter for a column the kit
  never asked for. The body term takes a third CORE-only list on the same principle.
- **Backticks, not a word boundary.** Two holes close with one token shape. A bare
  `<!-- anchors: … -->` comment satisfies a naive term while the section states no rule, and
  `researched` is an ordinary English past participle a future prose edit would satisfy by accident.
- **No second table.** The required token is the handle the checker already parses, and it must be
  parsed the SAME way: `core`'s entries are `handle:section` with the scope segment already stripped
  at `:1475-1480`, which is why `sec=${pair#*:}` is correct for `researched:M12:prompt` only on that
  list.

**What the term does not check, and the leg header will say so.** It grades that the section NAMES
the handle in a form a comment cannot fake. It does not grade that the surrounding sentence states
the rule, so a dead anchor inside a real sentence still passes. The gate is strictly stronger than
existence-only and strictly weaker than semantics.

### The protocol corrections

Both halves are byte-identical today, 54772 bytes and 649 lines each, with 6668 bytes of headroom
against the cap. Every edit lands in both.

**Correction one, `:635-637`.** The live text reads that the harness "drives SPEC, AUDIT and BUILD
as stages of ONE program, so BUILD is unreachable except through both and on a TERMINAL `--review`
verdict." Both sentences are true today and false under the hoist. They become: the harness drives
SPEC, AUDIT and DISPOSAL as stages of one program and hands out the ordered roster only on a
terminal `--review` verdict, and what the program holds is that the ROSTER is not handed out early,
not that the build is unreachable early. **The third sentence at `:637` is not touched**, per §3.

**Correction two, `:642`.** The TWO LIMITS paragraph reads that "what refuses is `--dispatch` at the
moment of the act and the pass-order leg over the commit graph." The second half is false.
`check-pass-order.sh:21` says of itself "this measures ORDER and nothing else"; under WHAT THIS DOES
NOT CHECK it excludes "whether a build pass was DISPATCHED" at `:22` and "anything about a unit that
is not CLOSED" at `:23-24`. What it does check is at `:9-10`. **Strike
`and the pass-order leg over the commit graph`.**

**The state-refusal list.** Wherever §12 names what `--dispatch` refuses about a unit's state, it
names the two that exist and no others. `unattended.sh:4604` is `fail 49` for a unit no tracked spec
under this build defines, and `:4609` is `fail 49` for a unit whose spec grades THIN, the only arm
in its `case`. It does not refuse a FORKED unit, an already-CLOSED one, or a re-dispatch.

**The dispatch args.** §12's field list names the args BY NAME with no literal script path. Measured:
`tools/unattended/PROTOCOL.template.md` carries 0 install-prefix occurrences and has no row in
`tools/install-prefix-carried.txt`, so a literal path here would be a NEW carrier, which the ban
refuses outright rather than ratcheting.

**§9's three clauses** join the existing residual list at `:515-521`, whose own opening is "What it
does not close, stated so no reader has to discover it."

### The Skill loop bullet

`tools/unattended/SKILL.template.md` is 791 lines. `## While it runs` opens at `:465` and holds
`- ` items; `## While the work runs` at `:573` is prose and fenced blocks and is the wrong home. The
bullet goes between the `--dispatch` bullet opening at `:543` and the bug-class bullet at `:557`,
which are the two acts the child performs.

**The paths are LITERAL here and the reason is measured, not stylistic.**
`tools/unattended/adopt-unattended.sh:232-243` substitutes seven placeholders and `{{TOOL_ROOT}}` is
not one of them. A `{{TOOL_ROOT}}` spelling would survive into every adopter's rendered Skill as
brace text, which the renderer's own surviving-placeholder arm reds. So the bullet costs an
install-prefix rise, and that is priced in §4's migration block.

**The four `next:` branches, read from the driver rather than trusted.** `verb_plan` emits them at:

| branch | site | what the run does |
|---|---|---|
| `next: <id> (READY - build it)` | `:2149` | dispatch that unit |
| `next: <id> (THIN)` or `(FORKED)`, and `(MISSING - spec it first)` | `:2148` and `:2158` | do not dispatch |
| `next: none - every tracked spec is terminal` | `:2175` | the loop is done |
| `next: none - no tracked spec grades as a unit (see the NOT A UNIT rows above)` | `:2173` | NOT done — halt |

The fourth is the one a reader mistakes for completion. It is printed when `_graded` never reached
1, and `verb_plan` still returns 0 at `:2177`, so its exit code says nothing. **`--dispatch` refuses
THIN at `:4609` and MISSING at `:4604` and does NOT refuse FORKED**, so on a FORKED unit nothing but
the run stops the call.

The bullet also pins `scriptPath` over `name:`, orders a re-read of `--plan <slug> --paths` between
calls rather than trusting a held list, and states that a child returning `committed:false` stops
the loop. **It states plainly that nothing refuses the next dispatch for the run:** the order gate
treats an earlier unit's declaration row as dispatched, and `build-complete` at `--close` is the one
thing that refuses an early stop, with `--override build-complete` as its escape.

### Alternatives rejected

- **Re-point `passes-harnessed` at a non-M section.** Refused by arm A, which accepts only an
  `M<n>` carrier cell and marks anything else `:AMBIGUOUS`.
- **A hand-maintained anchor table beside the checker.** A second spelling of the handle set, which
  is the drift class this whole build is about. The term derives its token from the handle already
  parsed for arms A and B.
- **A word-boundary term instead of backticks.** `researched` is ordinary English; a prose edit
  would satisfy it by accident and certify a section that states no rule.
- **A line-prefix comment filter.** Measured above: it admits the multi-line evasion.
- **Landing the ratchet before the anchors, or after.** Measured: the term reds 17 of 17 handles
  against the file as it stands. Ratchet first reds the bar; anchors first is unguarded prose.
- **`{{TOOL_ROOT}}` in the Skill bullet.** The unattended renderer does not substitute it, so it
  would ship brace text to every adopter.

## 5. Production-readiness checklist

- **security** — N/A. No new write path, no new egress, no credential surface. The bullet instructs
  a run; it grants nothing.
- **perf / scale** — the body term adds one `sed` slice, one `awk` strip and one `grep` per CORE
  pair, seventeen times, over a 24 KB file. `unattended kit gate`'s declared ceiling is 16040 and
  this is milliseconds against it.
- **a11y** — N/A. No user interface.
- **i18n** — N/A. Governance carriers are English-only by construction.
- **error / empty / loading states** — the term inherits arm B's carrier-absent silence at
  `:1586-1588`. An adopter without the memory-tree kit gets no BUILD-METHOD and no refusal.
- **observability** — the refusal names the offending `handle:section` pair, as arm B's does today.
- **risks** — the LINE axis of the budget is ungated, so anchors written as their own lines could
  approach the ≤350 cap silently; woven anchors are the mitigation. The M6 sentence and the Skill
  bullet name `tools/workflows/unattended-unit.js`, which does not exist until a later unit, and
  nothing catches a dangling path until check 31 lands. Both halves of the protocol pair must move
  together or `unattended kit gate` reds, which is a correct red and not a hazard.
- **testing + left-shift gates** — the four-fixture arm goes into
  `tools/unattended/check-unattended.test.sh`. That file is not a gate leg, per the 2026-08-23 owner
  ruling keeping a kit's self-tests off the bar, so the arm is run by hand and this spec says so
  rather than claiming a boundary runs it.
- **migration / rollback** — every edit is a document or a shell term. Reverting the commit restores
  the tree; no data shape moves and no state is written.
- **user docs** — the carriers ARE the docs. No `help/` page exists for this repo.
