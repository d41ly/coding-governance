# TOOL-dFramedEntrypoint-5 — the document inventory and the records table leave the build README

**Status:** SPECCED · rev-5 · 2026-08-24 · node d · Tier-2 · base 9ddcc5c9 · order 6 · streams tooling · ratified 2026-08-24

## 1. Goal

A build README carries its records listed twice: a document inventory region of 56,177 bytes and a
records table inside the index region, together 28% and 27% of all generated bytes, both naming the
same files. Neither means anything at the entrypoint, which is the owner's ruling. This unit deletes
both, re-emits the two coverage joins the records table carried, and performs the marker surgery that
deletion forces — all in one commit, because a region whose registration is gone but whose marker pair
remains becomes authored content sitting after a generated marker, which the slot contract refuses.

## 2. Scope (IN)

- **S1** — the `build-docs` entry leaves `GEN_REGIONS`, and its renderer leaves the module.
- **S2** — the records table leaves `render_region`, and with it the sentence naming the record
  directories.
- **S3** — the two COVERAGE JOINS are re-emitted as standalone lines inside the index region, and they
  render UNCONDITIONALLY wherever the region renders. Today each hides behind a non-empty-gap test, so
  a build with FULL coverage renders nothing — which is the absence-reads-as-coverage class, and it is
  the common branch rather than the rare one. The zero-gap case gets its own explicit phrasing: every
  unit id is named by a record, and every unit id has a spec-audit record. The joins are computed from
  the build's records and units rather than parsed from the table, so the data survives the deletion —
  but the emitting branch does not, and re-emitting is what keeps the only spec-to-record coverage
  signal in this repo alive. The hygiene check that grades bindings grades the opposite direction.
- **S4** — the SELFTEST blast radius is THREE classes, not one, and each is enumerated with its
  post-deletion disposition. (a) Arms addressing the trailing regions by TUPLE INDEX are re-pointed to
  address them by name; deleting the entry without this raises an index error, which no marker grep can
  predict. (b) Arms asserting the records TABLE's literal row. (c) Arms asserting the derived folder
  sentence, including two that assert its OCCURRENCE COUNT — those go to zero and fail rather than
  raise, so no tuple rewrite reaches them.
- **S4b** — the derived folder sentence is the LIVENESS ASSERTION for the record selector, and one arm
  says so in its own label: nine arms detect a mis-segmented selector by noticing that sentence went
  missing. Deleting it removes the detector. This unit therefore REPLACES it with an explicit
  non-empty-population assertion over the record selector, so the mis-segmentation those nine arms

- **S4c** — `strip_records_sentence` and its anchors are RETIRED in the same commit, with their arms.
  Left in place with nothing re-rendering what it removes, it stops being a de-duplicator and becomes a

  guards against by name. Latent rather than immediate, and retired for that reason rather than parked.
- **S5** — marker surgery across every tracked build README, removing the orphaned pair, in the SAME
  commit as S1. Measured consequence of splitting them: 750 slot-contract violation lines.
- **S6** — the memory-tree kit version moves at every gated site, and the dogfooded parity copies move
  with it.
- **S7** — the generated map artifacts are regenerated in the same commit, because a byte-compare gate
  holds them.
- **S8** — the `build-readme-surface` dossier is refreshed, including its title, which names a region
  count this unit changes.
- **S-EPOCH** — this unit moves `tools/memory-tree/gen_build_index.py`, which is inside the
  verdict-epoch gate's scan set, so its landing carries a `KIT_MEMORY_TREE_VERSION` bump. The carrier

## 4. Design

### Data model

Unchanged. The bindings map that `plan` already builds is the source for both coverage joins and stays
exactly as it is.

### Inventory

Of the document inventory's 488 entries, 265 are specs already rendered as unit rows and 218 are
records already rendered as record rows. Exactly five files are reachable only through it, and all five
are headerless legacy specs carrying no status header, so they render no unit row and are not record
paths. Their loss is stated in the open questions rather than absorbed silently.

### Migration

One commit. It carries the tuple change, the two renderer deletions, the re-emitted joins, the rewritten
selftest arms, the marker surgery across the corpus, the kit version at four gated sites with three
dogfooded parity copies, the regenerated map artifacts and the dossier. The corpus half is reviewable
only as a mechanical diff — every hunk is a marker-pair deletion plus the region text — and it is
verified by re-running the write verb rather than by reading it.

### Rollout

Deletion-only, so there is no dark landing to arrange: the regions stop rendering and nothing reads
them. The rollback is the inverse commit, and it is clean because no data model moved.

### Alternatives rejected

**Delete the inventory region only.** It serves the owner's stated goal and is much cheaper — no
over-cap line moves and no coverage signal is touched. It was the recommendation put to the owner and
it lost: the ruling was both regions plus spec-side rendering, and the records table is where the
duplication actually costs bytes.

**Keep the records table and delete only the inventory.** Same as above, and it leaves the 17 over-cap
generated LINES in place. Those lines are not three registry rows — a debt row names a FILE and
silences a whole check on it, so the line count and the row count are different populations and the
acceptance measurement reports both.

### Files touched (estimate)

`tools/memory-tree/gen_build_index.py` · every tracked `memory/builds/*/README.md` · the memory-tree
kit version constant and its three template marker sites plus their dogfooded copies ·
`memory/map/generated/` artifacts · `memory/map/features/build-readme-surface.md` ·
`memory/project/curation-debt.txt` if rows drain · the `strip_records_sentence` seam and its anchors,
retired per S4c.

`build-readme-surface` dossier and already the shape every region write goes through, with a second

matters is negative and is recorded because it cost a research lens a wrong answer: `GEN_REGIONS` is
