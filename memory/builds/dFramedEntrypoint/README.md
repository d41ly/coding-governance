# dFramedEntrypoint — the build README becomes a closed, budgeted authored slot set

Node `d` · opened 2026-08-24 · streams tooling.

**The problem this build exists to solve.** A build README is the entrypoint a resuming session reads
first, and its authored half is unbounded: the slot contract shipped by `TOOL-aRuledFrontispiece-1`
constrains only WHERE authored content sits, never WHAT it is. The corpus reflects that. Across 61
tracked build READMEs the authored half is 347,503 B against 200,270 B generated, and the classes
filling it are owner-decision logs, fork rulings, research digests, spec-audit narratives, defect
records and hand-authored rosters — content that belongs to a unit, not to the entrypoint. This build
replaces the unbounded block with a CLOSED, budgeted, machine-graded slot set, derived wherever the
data already exists and authored only where it cannot be.

**This session's deliverable is not the implementation.** It is: ground in the shipped surface,
research the options adversarially, verify the load-bearing claims, put the forks to the owner, then
spec the build and adversarially review the spec set.

**Where the evidence lives.** Five research lenses under `build/`, and the adversarial verification
of their five load-bearing claims under `reviews/`. Every one of those five came back PARTIAL: each
claim survived on substance, none survived unedited. Read the verification first — where it and a
research record disagree, the verification wins.
