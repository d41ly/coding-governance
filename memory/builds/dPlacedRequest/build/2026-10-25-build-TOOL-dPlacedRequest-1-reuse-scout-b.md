## Proposed build order

1. **U19**: the content key and the project-level request record are what U14, U21 and U5 key on.
2. **U9**: the manifest facts as level-2 units, the input the card renders.
3. **U2**: the card's remote ref, cache and snapshot; every `entry.orient` writes it.
4. **U4**: the placement predicate, check and disposition record that every later entry feature consumes.
5. **U10**: scenario selection runs inside `entry.place` and `placement.check`, so it needs U4's facts.
6. **U14**: the pre-claim budget draws on U19's key around U4's placement loop.
7. **U5**: the breakpoint disposition needs U4's set and U19's provenance refusal.
8. **U21**: `entry.claim` writes the claim, lease and derived plan record after placement. It needs scout A's lease (U1/U11) first.
9. **U3**: the five item rows register what units 2, 4 and 21 implement, so they go last, once each witness exists.

The compare-and-swap ref writer should be extracted from `write_claim` into a factory before U2, U19 and U21 each add a namespace. That extraction belongs to scout A's group (U1/U11), and steps 1, 3 and 8 depend on it landing first.
