## 1. Goal

An owner's request that is not yet a build becomes a project-level record any node may claim by
lease. The owner's words are kept verbatim on the node where they were typed; the remote holds only
the record `refs/gov/requests/<content key>`, carrying the key, the fleet tag and the session, until
dWellOiledMachine publishes the text redacted. A request travels between nodes only by that key, and
a request that arrived that way is data with provenance, never the owner's consent (gap-conc-17;
P40; the owner's CL-4 and FR-1).

## 2. Scope (IN)

- **S1** — The content key, `request_content_key` (I11): `derive_request_content_key(text)` in
  `tools/loop/request.py` returns the first 12 hex digits of SHA-256 over the UTF-8 bytes of
  `derive_content_key(text)`, imported from the memory-tree kit's `row_grammar.py`
  (`tools/memory-tree/row_grammar.py#derive_content_key`), resolved with `resolve_kit_dir`; an empty
  normalised text is refused. `python request.py key <file>` prints it.
  It reads the file as bytes and decodes them strictly as `utf-8-sig`, so a leading byte-order mark
  never reaches the key and no platform default decoding is ever used; an undecodable byte exits 2
  printing `request — refused: <file> is not UTF-8 at byte <n>`. It keys the text alone, so an absent
  intake keys a request the same way (I11). Observed by AC1 and AC7.
- **S2** — The local text: `unattended.sh --request <file>` copies the file's bytes unchanged to
  `<git-common-dir>/requests/<content key>.md`, keeping the first copy when one exists, and appends
  this session's id once to `<git-common-dir>/requests/<content key>.typed`. Nothing under
  `requests/` is tracked or pushed. Observed by AC2, AC5.
- **S3** — The record: the same verb builds one commit over the empty tree with
  `build_gov_commit "" <message>`, the message `gov-request <content key>`, a blank line, and exactly
  three lines, `content-key`, `fleet-tag` and `session`, each validated at the write: twelve lower-case
  hex digits, this node's tag as TOOL-dPlacedRequest-1's `resolve_fleet_tag` reads it from
  `tools/playbook/fleet.toml`, and a session id of letters, digits and dashes. It writes `refs/gov/requests/<content key>` with
  `write_gov_ref <ref> "" <commit>`, a create. A create that loses means the request is already
  recorded and exits 0 saying so; a write not completed exits 2 with the text kept, and re-running the
  verb retries. This commit is the ref's root; TOOL-dPlacedRequest-14's pre-claim draw rows follow it
  on the same ref, each parented on the tip it read (I21). Observed by AC2, AC3.
- **S4** — The claim by lease. TOOL-dPlacedRequest-1's builder
  (`tools/unattended/unattended.sh#derive_lease_ref`) gains the kind `request`:
  `derive_lease_ref request <content key>` builds `refs/gov/leases/request/<content key>`, holds the
  key to twelve lower-case hex digits and takes no third segment. It refuses `request` as a build or
  unit lease's slug, as it refuses `run`. `unattended.sh --lease acquire request <content key>`
  acquires it through `tools/unattended/unattended.sh#run_lease_verb`, whose default arm already
  writes a non-build kind's record with `slug: -`, so the record carries `kind: request` and
  `slug: -`. Observed by AC4.
  - **The existence read.** Before `run_lease_verb` reads the claims, an `acquire` of kind `request`
    confirms the record by a separate bounded read of `refs/gov/requests/<content key>` alone:
    `observe_remote` running `git ls-remote --exit-code` against the claim remote for that one ref,
    as `tools/unattended/unattended.sh#branch_tip_quiet` asks for one branch. It fetches nothing and
    sights nothing into the change feed. The claim read
    (`tools/unattended/unattended.sh#read_claims`) keeps its refspecs unchanged (F5). A remote
    that answers with no such ref refuses with cause `no-record`, exit 1, and writes nothing. A read
    the bound kills or the remote does not answer prints `lease not written`, naming the cause, exit 2.
  - **The readers of a lease's kind**, each in `tools/unattended/unattended.sh`, learn
    `request`. The awk tail classifier inside `read_claims` reads a lease tail `request/<content key>`
    as kind `request` with slug `-`, where today it marks that row malformed. The `case` on the row's
    kind in `tools/unattended/unattended.sh#derive_claim_keys` keys a `request` row over the ref
    `derive_lease_ref request <content key>` builds, with `runstate=?`, as it keys a cadence row. The
    `check_cross_run_overlap` call in `run_lease_verb` passes a `request` acquisition no slug, as it
    passes a `run` one, because a request names no build whose specs declare paths.
  - Any node may claim; a live holder refuses the rest with `live-holder`.
- **S5** — The consent predicate: `check_request_consent <content key>` returns 0 only when this
  session's id is a line of `<git-common-dir>/requests/<content key>.typed`, and otherwise returns 1

## 3. Non-goals (OUT)

- Publishing the text. dWellOiledMachine publishes it redacted (`cl-dClosedLoop-0335`), through the
  run-log kit's `scan_secrets` (`tools/runlog/runlog_lib.py#scan_secrets`), which nothing in this unit calls
  because nothing in this unit publishes text.
- Binding the text to the owner's keystrokes. The hook-written intake is dWellOiledMachine's (FR-1);
  until it lands, `--request` trusts its caller that the file is the owner's words, and an agent in the
  typing session could record words the owner never typed. The consent predicate inherits that limit.
- The relay channel. A key travels in a mailbox message (dKeptSession) or an offer (the `fleet`
  expansion, TOOL-dPlacedRequest-20's keys); this unit ships no verb that sends a request anywhere.
- Placing a request, its budget, its probes and its claim commit: TOOL-dPlacedRequest-4,
  TOOL-dPlacedRequest-14, TOOL-dPlacedRequest-7 and TOOL-dPlacedRequest-21, which read
  `request_content_key`.
- The breakpoint disposition itself: TOOL-dPlacedRequest-5, which calls `check_request_consent`.
- The secret scan of coordination payloads (gap-rt-44): the record's three fields are shape-checked so
  no free text can ride them, which is the whole of this unit's boundary.

## 4. Design

### Evidence

Every citation below was read at `1ee23aaa`.

- No project-level request record exists. The verbatim record of a prompt today is build-scoped,
  under `<build>/prompts/` (`tools/unattended/unattended.sh#read_audit_ask_record`, the prompt record
  reader).
- The node-local store precedent is the card: `<git-common-dir>/orientation/<sid>.md`, resolved from
  `git rev-parse --git-common-dir` in the checker's top-level `--path` branch, which has no function
  (`skills/session-kickoff/manifest-check.sh@5bb5b695074d:331`).
- `derive_content_key` normalises only, links to text, dates and emphasis dropped, case and whitespace
  folded (`tools/memory-tree/row_grammar.py#derive_content_key`); the twelve-hex convention is
  `derive_section_sha` (`tools/roles/handoff.py#derive_section_sha`).
- A create is a compare-and-swap with an empty expected sha. A lost one reads `(stale info)` or
  `(fetch first)`, and `tools/unattended/unattended.sh#write_gov_ref` parses both to its rc 1 (I1);
  `tools/unattended/unattended.sh#build_gov_commit` builds the commit over the empty tree.
- The driver resolves a sibling kit's file with `resolve_kit_dir "$py" <kit> <file> "$KIT_DIR"`; the
  loop kit's own precedent is `tools/unattended/unattended.sh#derive_claim_keys`, which finds
  `claims.py` that way.
- The claim read fetches the legacy-claim and lease refspecs and no other, and sights every
  fetched commit into the change feed (`tools/unattended/unattended.sh#read_claims`). A single-ref
  remote probe that fetches nothing is `observe_remote` with `ls-remote --exit-code`, whose rc 2 is
  git's answer that the ref is not advertised (`tools/unattended/unattended.sh#branch_tip_quiet`).
- A lease's kind reaches these readers beside its builder, each a closed set of today's kinds: the
  tail classifier in `read_claims`' awk, which marks any other tail malformed; the `case` in
  `derive_claim_keys`, whose fallback arm would key a request row as a legacy claim; and
  `run_lease_verb`'s `check_cross_run_overlap` call, whose non-`run` arm passes the lease's name as a
  build slug (`tools/unattended/unattended.sh#run_lease_verb`).
- The loop kit's self-test convention is a module carrying `--selftest` over its plants, run through
  `tools/loop/loop_lib.py#run_selftest_cases` by a gov leg of its own: `loop claims fixtures` runs
  `claims.py --selftest`. That leg is registered in exactly five tracked files outside the generated
  map, found by `git grep -n "loop claims fixtures"` excluding build records: `tools/gate-legs.json`,
  `tools/govkit/registry.toml`, `tools/govkit/subject-pins.tsv`, `memory/map/features/loop.md` and
  `tools/run-gates/selftest-budgets.txt`. Two more name it in prose, `help/loop.md` and
  `tools/loop/README.md`, and `memory/map/generated/` re-derives it. The count is DERIVED by that grep.

### The record and the store

| Where | What | Pushed |
|---|---|---|
| `refs/gov/requests/<content key>` | `content-key`, `fleet-tag`, `session` | yes, create-only |
| `refs/gov/leases/request/<content key>` | the lease record, kind `request` | yes, by acquisition |
| `<git-common-dir>/requests/<content key>.md` | the owner's words, byte for byte | never |
| `<git-common-dir>/requests/<content key>.typed` | one session id per line, each session that recorded it here | never |

The record's session is the first typer's and is provenance; the `.typed` file is this node's own
evidence of who typed it, and is what consent reads.

### The verbs

```
--request <file>               -> key = request.py key <file>
                                  copy to requests/<key>.md (first copy kept), add session to .typed
                                  write_gov_ref refs/gov/requests/<key> "" <commit>
                                  rc 0 written · rc 0 "already recorded" on a lost create · rc 2 not written
--lease acquire request <key> -> bounded read of refs/gov/requests/<key> alone, ls-remote --exit-code
                                  rc 2 -> refused no-record · other non-zero -> not written
                                  read_claims as today, its refspecs unchanged
                                  acquire derive_lease_ref request <key>, kind request, slug -
check_request_consent <key>    -> rc 0 this session typed it here · rc 1 relayed
```

### Alternatives rejected

- **The text in the record.** That is the red case: the remote then holds the owner's words before any
  scan has read them.
- **A key hashed in the shell.** The normalisation would be a second copy of `derive_content_key`.
- **Consent read from the record's `session`.** Two sessions typing the same words share one record,
  so the second owner's own words would read as relayed; and the predicate would need the remote.
- **The existence check inside the claim read.** Adding `refs/gov/requests/*` to `read_claims`' fetch
  would fetch every request record on every claim read and sight each into the change feed (F5).
- **A loop `selftest.py`.** No loop module is tested that way; each carries its own `--selftest`
  run by its own leg (F4).
