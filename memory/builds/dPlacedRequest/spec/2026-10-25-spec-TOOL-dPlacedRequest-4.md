## 1. Goal

Every request a session or an unattended run receives gets one disposition from the closed set, made as
`placement` says and recorded with its reason, and `placement.check` re-checks the facts it rests on before
anything acts on it. Today placement is unaided and unrecorded: kickoff tells the agent to derive a request's
scope itself, an unattended run handed a prompt always opens a new build, and a mis-placement cannot be
audited (`gap-orient-01`, `memory/builds/dClosedLoop/build/2026-10-14-build-PLAY-dClosedLoop-1-gap-register.md:132`).

## 4. Design

### The facts per disposition

`check` reads each fact from its source at the time it runs, never from the scout's text.

| Disposition | Fact `check` re-evaluates | Source |
|---|---|---|
| `continue`, `amend` | the build exists and is live, and its build lease is free or this session's | `derive_status` (`tools/memory-tree/gen_build_index.py:793`) not in `TERMINAL` (`tools/memory-tree/tree_lib.py:31`); the lease ref `refs/gov/leases/<slug>/build` as TOOL-dPlacedRequest-1's reader prints it |
| `new` | the request's owner words are held verbatim | TOOL-dPlacedRequest-19's local text for the content key, or a prompt record's `## The prompt` at BASE |
| `patch` | the build it patches exists and is terminal; orientation.md:159's derived plan record is written by `entry.claim` after this check (flow-steps.md:127), so the check reads its input | `derive_status` in `TERMINAL` |
| `repeat` | the playbook its `playbook:` key names resolves | the path exists in the tree at HEAD |
| `unit` | refused: `build.unit-holders` is not landed, so the build's driver alone drives its units | flow-steps.md:140-145, the `driver-only` stand-in |
| `breakpoint` | TOOL-dPlacedRequest-5's facts | that unit's check function, called by name |
| `ask` | the ask is filed | the ask id names a row in the build's `BACKLOG.md`, read by `python tools/memory-tree/gen_build_index.py --asks --build <slug>` |
| `none` | no tracked write is routed | the session's orientation file carries no route (`tools/hooks/scratch-guard.js` refuses an edit under its routed paths without one) |

### Data flow


## 5. Production-readiness checklist

- security — the record is node-local; the three lines that reach the remote pass `render_redacted` and a
  byte cap. `none` placements are held to read-only by the existing routed-path guard.
- perf / scale — one status derivation and at most one lease read per `check`.
- error / empty / loading states — an empty return, an unknown word, a missing build and an unreadable lease
  each refuse naming the item; an unreadable lease is a refusal, never a pass.
- observability — every placement and every check verdict is a block in the request's placement file.
- risks — the record of a disposition that never claims stays on one node until the intake kind lands; S8's
  owner item and the claim commit are what other nodes see.
- testing — the fixture plants of AC1 to AC10, run by the pass; the suite arm in §7 at the close.
- migration — none; the prompt-mode refusal is cutoff-gated.
- user docs — `help/loop.md` gains a placement section naming the three values, the check and the record.

## 6. Acceptance criteria

- **AC1** — When `python placement.py --fixture --plant each-disposition` places one request per member of
  the nine, each block is written with that `disposition:` and a `reason:` line.
  Red when: a member is accepted with no reason, so a placement is unrecorded.
- **AC2** — When `python placement.py --fixture --plant unknown-word` places `adopt`, `place` refuses naming the
  word and writes no block, and with `attach` it records `amend` (TOOL-dDeclaredLoop-16 S2's alias).
  Red when: an unknown word is written as a disposition.
- **AC3** — When `python placement.py --fixture --plant agent-places`, `--plant declared-checked` and
  `--plant owner-places` each place one request, the block's `placer:` reads `agent`, `declared` and `owner`
  in turn, and under `owner-places` with no disposition record `place` prints the owner item and writes no
  disposition.
  Red when: `owner-places` takes the scout's return as the placement.
- **AC4** — When `grep -n "disposition · reason · evidence · observations" gov-orienter.agent.md` runs at this
  unit's commit, it finds the `returns:` line, and `python check_roles.py` reports the catalogue region
  current.
  Red when: the role's `returns:` line is unchanged, so the scout returns no disposition.
- **AC5** — When `python placement.py --fixture --plant secret-reason` places a request whose reason quotes a
  planted token, the block's `reason:` carries `<redacted:` and no token, and a 1 KB reason is cut to 240
  bytes.
  Red when: the reason is written raw.
- **AC6** — When `python placement.py --fixture --plant continue-closed` checks `continue` onto a CLOSED build
  and `--plant amend-leased` checks `amend` onto a build whose lease another session holds, under
  `placement.check` = `refuse` each exits 1 naming the fact, and under `record` each exits 0 with
  `check: recorded`.
