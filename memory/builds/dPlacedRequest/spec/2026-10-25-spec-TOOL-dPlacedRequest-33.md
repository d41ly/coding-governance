## 1. Goal

The spec audit of this build, round 1
(`memory/builds/dPlacedRequest/reviews/2026-10-25-review-TOOL-dPlacedRequest-1-spec-audit.md`),
confirmed **finding 6 at HIGH**, its item **H2**. `TOOL-dPlacedRequest-2` pushes
`refs/gov/builds/<slug>/card` at every READY append, with the `remote-ref` store selected by default,
"Live at landing" and no `RUN_CLAIMS` switch. The kickoff engine is linked into every project's skills
directory (`WIRE-INTO-PROJECT.md@76049fc990c5:71`), so on their next kit update every adopter's
sessions would write governance refs to the shared remote without opting in, while units 1 (§8 F2)
and 12 (§8 F3) settle the same question the other way. The engine never reads the conf's switch
itself: the driver is its one reader (`skills/session-kickoff/manifest-check.sh#derive_claims_line`,
its header comment). This unit repairs
`TOOL-dPlacedRequest-2` by moving the remote-ref write into a driver verb that answers `off` while
`RUN_CLAIMS` is not `on`, called by the engine under a kill bound, so the switch, the remote, the bound
and the writer each live once.

## 4. Design

### Evidence

- `derive_claims_line` resolves the driver, checks `.unattended.conf` and a working `timeout -k`, and
  runs `--claims` into a file under `CARD_CLAIMS_BOUND` with stdin closed; its header states the
  switch is the driver's and the engine never reads it
  (`skills/session-kickoff/manifest-check.sh#derive_claims_line`).
- `RUN_CLAIMS` is resolved once, by the driver's conf load, blank reading `off`
  (`tools/unattended/unattended.sh#load_driver_conf`); `print_claims` answers `claims: off` without
  reading the remote (`tools/unattended/unattended.sh#print_claims`). The same conf load runs
  `git rev-parse --show-toplevel` before any verb runs, so no verb's call is free of a git spawn.
- `resolve_claim_remote` refuses a clone without exactly one remote, check 24
  (`tools/unattended/unattended.sh#resolve_claim_remote`), and the claim read fetches with
  `observe_remote … --no-write-fetch-head` into the cache (`tools/unattended/unattended.sh#read_claims`).
- `read_card_ref` fetches the card ref and then calls `add_feed_sightings`
  (`skills/session-kickoff/manifest-check.sh#read_card_ref`), which only the `gov_feed_sh` block
  defines (`skills/session-kickoff/manifest-check.sh#add_feed_sightings`); `read_first_seen` reads
  those sightings back from the node's `gov-feed.log` (`tools/unattended/unattended.sh#read_first_seen`).
  `tools/push-main.sh` already carries `gov_feed_sh` without `gov_ref_sh`, so a feed-only carrier is a
  shape the parity arms grade today.
- The driver's `write_gov_ref`, on its one success exit, sets this node's cache ref
  `refs/gov/remote/<tail>` to the commit it wrote (`tools/unattended/unattended.sh#write_gov_ref`).
  `write_build_card` sets the local card ref and the cache's `# card-ref` from the full commit it
  built (`skills/session-kickoff/manifest-check.sh#write_build_card`).
- The refusal census counts `fail <n>` sites and literal `exit 1` and `status=1` sites
  (`tools/memory-tree/check-arms.py#scan_refusal_sites`). The driver stands at its ceiling, 343 sites
  against the 343 its `REFUSAL_CEILINGS` token allows (`.memory-tree.conf#REFUSAL_CEILINGS`), PINNED
  2026-11-20 from `check-arms.py`'s ceiling line. `write_register` already answers `not written` by
  printing its line and returning 2, which the dispatch exits with
  (`tools/unattended/unattended.sh#write_register`).

### The publish, end to end

```
manifest-check --card --append (READY)
  local-clone, build-folder        written as TOOL-dPlacedRequest-2 states
  remote-ref                       timeout -k 2 $CARD_FETCH_BOUND bash <driver> --card-ref write <slug> --message <tmp>
     RUN_CLAIMS off               -> card-ref — off            -> card — remote-ref not written: RUN_CLAIMS is off
     on, written                  -> card-ref — <tail> · <sha8>
     on, lost                     -> card-ref lost — <sha8>     -> re-render once, call again
     on, not written / killed     -> card — remote-ref not written: <why>
```

### After the driver answers

The driver's `card-ref —` line carries an abbreviated sha, so on a written answer the engine reads
`refs/gov/remote/builds/<slug>/card`, which the driver's `write_gov_ref` set to the commit it wrote,
and keeps the full sha from it. It sets the local `refs/gov/builds/<slug>/card` to that commit and
writes it as the cache's `# card-ref`, as `write_build_card` does today with the commit it built. A
cache ref that does not read back leaves the cache's `# card-ref` at `local`, the value an unwritten
remote-ref store leaves.

The verb refuses by printing its `card-ref not written — <why>` line and returning 2, which the
dispatch exits with, as `write_register` does; its lost answer returns 1 the same way. Neither is a
`fail <n>` site or a literal `exit 1`, so the verb adds no numbered refusal, the driver being at its
refusal ceiling.

### Alternatives rejected

- **Ship `card.store` without `remote-ref` by default.** It departs from v2:1173's default, a design
  record's value, to answer a question the switch already answers for every other remote write.
- **The engine reads `RUN_CLAIMS` from the conf.** A second reader of the switch, against the
  engine's own stated rule (`skills/session-kickoff/manifest-check.sh#derive_claims_line`).
- **The engine takes the written sha from the driver's line.** The line carries an abbreviated
  sha, and the local ref and the cache's `# card-ref` need the full one.
- **Ask `--claims` first.** One fetch more per publish, to learn a switch the write's own verb can
