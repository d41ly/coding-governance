## 1. Goal

The spec audit of the round-2 promotions
(`memory/builds/dPlacedRequest/reviews/2026-10-25-review-TOOL-dPlacedRequest-35-spec-audit.md`)
confirmed **finding 33 at HIGH**, its item **H3**: the threshold test `TOOL-dPlacedRequest-35`'s §4
wrote carried no guard for a commit the feed has not sighted. That guard is in the tree. The walk's
`step` inside `tools/unattended/unattended.sh#read_claims` tests the threshold only for a ref and
commit present in `seen`, and the walk fills `seen` only from feed lines whose `seen-utc` is
ISO-shaped, so neither an unset stamp nor the feed's `-` placeholder reaches the compare. The
verdict pass of the same function prints `unknown` with age `-` for a row whose tip or beat has no
sighting. Both came in with `TOOL-dPlacedRequest-34`'s bounded walk, commit 84130eaeb.

No arm pins the guard. The `TOOL-dPlacedRequest-35` block of `tools/unattended/unattended.test.sh`
says it does not drive an unsighted commit at the threshold test and hands that case to this unit.
This unit adds that arm: one mixed tenure whose reading separates the guarded walk from a scratch
copy that compares unguarded, so an edit that loses the guard reads red. It changes no driver code.

## 4. Design

### What the tree already holds

- `tools/unattended/unattended.sh#read_claims`, the walk's `step`: the threshold line tests `thr`,
  then that the pair of `rf[i]` and `c` is in `seen`, then the compare. A commit absent from `seen`
  reads on to its parent.
- `tools/unattended/unattended.sh#read_claims`, the walk's `BEGIN`: a feed line whose sixth field is
  not ISO-shaped is skipped before `seen` is filled, so a `-` stamp leaves its commit unsighted.
- `tools/unattended/unattended.sh#read_claims`, the verdict pass: an unsighted tip or beat indexes no
  age, so the row prints `unknown` with age `-`.
- `tools/unattended/unattended.sh#read_first_seen`: the same ISO-shape filter, `-` for an unsighted pair.
- `tools/unattended/unattended.sh#add_feed_sightings`, through `derive_feed_events`: a cached ref
  whose tip is the commit of the feed's newest line for that ref is skipped. Every other tip is
  appended at the read's clock. So a fixture that writes the tip's line last leaves a commit below it
  unsighted, and an "unsighted tip" is planted as a tip whose line carries `-`.

### The mixed input

One tenure of epoch 1, three commits, each `renews: no`, planted with the observer clock helpers of
`tools/unattended/unattended.test.sh` (`add_lease_commit`, `add_claim_sighting`, `read_clock_row`,
`remove_clock_refs`). Feed lines are written opener first and tip last.

```
commit  feed line                guarded walk (the driver)          unguarded copy
tip     sighted 60 s ago, last   sighted, not below thr: read on    same
middle  none                     not in seen: read on               "" < thr: stop, beat unsighted
opener  sighted 90000 s ago      below thr: stop, the beat           not reached
row                              stale, aged from the tip           unknown -
```

- Tip sighting age, 60 s (PINNED) before the read.
- Opener sighting age, 90000 s (PINNED) before the read, the 25-hour age.
- The bound, `leases.expiry-hours` at its default of 24 hours, read by `read_lease_bound expiry`
  (DERIVED at observation time).

### The unguarded copy

Written as the `TOOL-dPlacedRequest-35` block writes its copies: from `oc_src`, the guarded
threshold line, the block's `so_age` string, substituted by the same line without the `in seen`
clause, to `unguarded.sh` under `$oc_copy`. One assertion reads the guarded line once in `$SCRIPT`
and the unguarded line once in the copy, so a reworded guard reds that assertion before the arm can
pass with no substitution made.

### Evidence

- The builder's readings, run `wf_8db740e6-995` on 2026-11-20 (PINNED): the mixed input reads
  `stale` on the driver and `unknown` on the unguarded copy.
- The builder's readings, same run (PINNED): the AC2 and AC3 inputs read `unknown -` on the driver,
  on the unguarded copy, and on a second copy that also skips the ISO-shape filter, so neither input

- The spec writer's probe, 2026-11-20 (PINNED), over a scratch copy of the fixture: the mixed input

  feed line at all read `stale` on both, because `add_feed_sightings` sighted it at the read's
  clock; a tip whose only line carries `-` read `unknown -` on both, with the tip's `renews` either
  `no` or `yes`.
