### M5. 63's CRLF lift pastes `slice_fn`'s body without its guards and cannot show the staged break (ids 9, 21)

- **Where:** 63 §4 "The CRLF row's invocation (S7, S8)", against §10, §8 F2 and §6 AC8. The seam is `slice_fn` at tools/unattended/unattended.test.sh:708-714.
- **What is wrong:** §10 and F2 say S7 reuses `slice_fn`, and the sketch says it lifts "as slice_fn lifts a function". In fact it pastes a second copy of the body inline (the grep -n start, the awk end search, sed and eval) and drops both FAIL guards and the `st=1`. The skeptic re-ran the sketch on HEAD, where `CLAIM_KV_AWK=` is absent. It printed `s=[] e=[145]`, then a sed error. eval returned 0 with the variable unset, and awk then died with `function 'kv' not defined`. No FAIL line was printed. The sketch's END also prints the boolean `v["status"] == "live"`. The staged break, which reads `live` plus a CR, therefore prints the same 0 as an absent key. A failed lift prints nothing.
- **Consequence:** A missing or renamed variable is never flagged as a FAIL. On the staged copy, an assertion of "not 1" passes for any failure, so the staged break proves nothing about the CR strip. AC8's claim that the copy "reads live and a CR" cannot be seen in the output. The next lifted variable would get yet another hand copy. The damage stays inside one test arm.
- **Fix (skeptic judged it SOUND for both findings):**
  1. Extend the seam instead of copying it. Either give `slice_fn` a variable mode (start at `^$1='`, end at the first later line matching `'$`), or add `slice_var` beside it at unattended.test.sh:708 with the same FAIL messages and `st=1`.
  2. Make §4's sketch call that seam, and make §10 name the extension.
  3. Print the value itself, for example `printf '%s|%d', v["status"], length(v["status"])`. Require `live|4` on the shipped text and `live\r|5` (or `od -c` showing `\r`) on the copy without `sub(/\r$/, "", line)`.
  4. The build must stage that copy and observe both readings. It must also check that the arm goes red with a FAIL line when the variable name is misspelled in a scratch copy of the driver.
- **Left-shift gate:** Add a test-suite probe that flags any inline `grep -n ... | sed -n ... eval` lift outside `slice_fn`/`slice_var`. Add a checklist entry: a staged-break assertion must print the observed value, never a boolean that a failure also produces.
