## 1. Goal

Every definition the lexicon grades takes exactly one class (conforming, forced, out of scope, not a
name, debt), and only debt counts against one pin, `lexicon.pin`, held as a keyed ledger of offender
names that only shrinks against the base. Today three seams pin counts (`VERB_OFFENDER_PIN`,
`SUFFIX_OFFENDER_PIN` and the per-cell `PINS:` block), each a two-sided equality an edit can raise, so
a fixed offender plus a new one nets to zero and the verb pin rose from 412 to 1,087 (gap-mem-10).

### The registration


A row is `<path>\t<rule>\t<name>\t<count>\t<sha>\t<disposition>`, the factory's grammar. `--measure`
prints the whole file the tree produces, header included: a key already in the ledger keeps its sha
and disposition, a new key gets HEAD's sha and `seeded`, so `--measure > <home>` is a drain's edit.
The `lexicon naming predicates` guard gains `{memory_root}/project/lexicon-debt.txt`.

### The verdict table

`check_debt_pin` reads `lexicon.pin` once per run. Findings are the factory's: `undeclared site` and
`count rose` (measured above the ledger), `unmeasured row` and `count fell` (measured below it), and
against the base `gained` and `raised`.

| Finding | `shrink-only` (default) | `absorb` | `no-gate` |
|---|---|---|---|
| `undeclared site`, `count rose` | red, naming the key | red, naming the key | printed |
| `unmeasured row`, `count fell` | green, printed as drained with the row to delete | the same | printed |
| `gained`, `raised`, disposition not `widened:` | red | red | printed |
| `gained`, `raised`, disposition `widened:<record>` | red (TOOL-dMindYourWords-11 admits a vocabulary record) | green when `<record>` is a tracked path, else red | printed |
| no ledger at the base | printed as unresolved, never green | the same | printed |

The pin wording every carrier states (the sentence TOOL-dMindYourWords-14 sweeps in): "The debt pin
is the ledger `lexicon-debt`: every debt offender is a row, a new one reds, a drained one greens and
names the row to delete, and under `lexicon.pin = shrink-only` the ledger only shrinks against the
base."

### The policy read

```python
POLICY_DEFAULTS = {"lexicon.pin": "shrink-only"}   # each later unit adds its own key's row

def read_policy_value(key, root):
    policy = Path(__file__).resolve().parent.parent / "policy" / "policy.py"
    if not policy.is_file():
        print(f"lexicon: no policy kit beside this kit; {key} reads {POLICY_DEFAULTS[key]}")
        return POLICY_DEFAULTS[key]
    got = subprocess.run([sys.executable, str(policy), "get", key], cwd=root, ...)
    if got.returncode != 0:
        raise ConfError(f"policy read refused for {key}: {got.stderr.strip()}")
    return got.stdout.strip()
```

`POLICY_DEFAULTS` is the second carrier of a catalogue default, so a selftest arm compares each row
with `tools/policy/catalogue.toml` and reds on a difference (one fact, gated).

### The count form

`read_legacy_pin(conf)` returns the sum of the two scalars and every `.conv` row, or `None` when the
conf carries none of them. `.debt` and `.unruled` rows are partitions of the verb population and are
not added. The parser keeps `PINS` in `BLOCK_KEYS` and `_parse_pins` for this read alone; no verdict
reads a `PINS:` row per cell. Under the count form `shrink-only` and `absorb` grade alike and the base
half is not computed, which the `LEGACY PIN` line says.
