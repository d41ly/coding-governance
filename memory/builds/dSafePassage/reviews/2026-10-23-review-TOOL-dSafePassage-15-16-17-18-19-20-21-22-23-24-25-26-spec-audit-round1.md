### D-1 — A regen refusal after a successful gov-first walk keeps the walk's untracked files (ids 1, 35)

- **Where:** TOOL-dSafePassage-25 §2 S1, §3 Non-goals, §4 "The prepared path after this unit". Against `tools/push-main.sh:902-918` and TOOL-dSafePassage-8 S4.

The regen stage then takes `rgsnap` at `push-main.sh:910`, after the walk has created its receipt, before-images and outbox orders. A regen refusal (`:911-916`) runs `git reset -q --hard` (tracked files only) and `remove_new_untracked "$rgsnap"`. Remove `gfsnap` only after the regen stage. If the case is meant to be out of scope, state it in §3.
- **Acceptance to add:** A fixture where gov first passes and a planted regen refusal follows. Assert that `git status --porcelain` prints nothing and that the retried merge holds no `.governance/steps` or `.governance/outbox` file.

### D-3 — The local-config check reads one repository, but git runs a populated submodule's executors too (id 38)

- **Where:** TOOL-dSafePassage-24 §2 S1.
- **What is wrong:** S1 reads only the target's own local and worktree config. A populated submodule's config (`.git/modules/<name>/config`) can declare the same executors, and git in the superproject runs them because `git status` recurses into the submodule. - **Acceptance to add:** A plant `submodule-filter` whose step's `git status` must not run the canary, or whose check must refuse.
- **Left-shift gate:** A checklist entry: an isolation check names every repository git enters (superproject, submodules, worktrees), not only the one it was handed.

### D-4 — `platform` plus `boot_id` does not identify a pid namespace (id 13)

- **Where:** TOOL-dSafePassage-26 §2 S33 (`:271-273`) and §4 Data model (the lock record's `boot_id`, `:382-383`).
- **What is wrong:** S33 keys the namespace on `platform` plus `/proc/sys/kernel/random/boot_id`. Every WSL2 distro and a Docker Desktop container share one kernel `boot_id` and the Windows hostname, while each has its own pid namespace. The skeptic probed `wsl.exe -d Ubuntu` and `-d docker-desktop`: one `boot_id`, hostname `Compeeto` on both, and `readlink /proc/self/ns/pid` printed `pid:[4026532221]` and `pid:[4026532244]`.
- **Consequence:** An `update` run from one distro or container judges a lock held from another through a census that cannot see that pid (TOOL-2 `:80-84`). It reads the holder dead and reclaims a live lock while the holder writes, so two writers hit one receipt.
- **Fix:** Judged SOUND. On Linux, record the pid namespace itself: the inode from `readlink /proc/self/ns/pid` (for example `pid:[4026532221]`), beside or instead of `boot_id`. Read a holder as `unknown` whenever it differs.
- **Acceptance to add:** A plant `lock-foreign-pidns` whose lock carries the same `platform` and `boot_id` but a different ns inode. Assert that the take refuses.
- **Left-shift gate:** A checklist entry for the bug class "a proxy identifier stands in for the property the judgement needs". A liveness rule must name the identity it relies on (pid namespace) and record that identity, not a correlate.

### D-5 — The reuse estimate mixes wall-clock `started` with POSIX monotonic `etimes` (id 37)

- **Where:** TOOL-dSafePassage-22 §2 S2 and §4 Data model.
- **What is wrong:** The proof that the estimate "can only err early" assumes the lock's `started`, the judge's `t0` and the census's `age_s` share one clock. `take_write_lock` (`govkit.py:7429`) writes `started=time.time()`. On POSIX, `census.py:275` reads `ps ... etimes` and `:220` stores it as `age_s`. `etimes` is elapsed time and does not move with the wall clock. With a forward wall step D between the take and `t0`, `estimate = t0 - age_s` lands about D after the true creation. Windows is unaffected, because the CIM query (`:63-70`) is wall-relative. No non-goal covers wall-clock steps.
- **Consequence:** On Linux or WSL, a wall-clock correction of more than about 2 s while a holder runs makes a live holder read `reused`, so `dead`. The lock is reclaimed while the holder writes the receipt. NTP steps and WSL2's resync after host sleep both cause this.
- **Fix:** Judged SOUND. State the clock domain. On POSIX, compare in one clock: record the holder's creation from the census at take time, or record `boot_id` with a monotonic or `/proc` starttime and compare like with like. Alternatively, treat an estimate that exceeds `started + margin` by more than the elapsed monotonic time as `unknown`.
- **Acceptance to add:** A plant that shifts the judge's wall clock forward by 10 s. Assert a refusal, not a reclaim.
- **Left-shift gate:** A checklist entry: any comparison of two time values names each value's clock (wall or monotonic) and refuses a mixed-domain subtraction.
