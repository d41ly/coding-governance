### M5. 88's in-place test misses a case-only rename on a case-insensitive filesystem (id 18)

- **Where:** 88, section 2 S1; section 4 "S1" and "Adopters meet it".
- **What is wrong:** S1 decides that the occupant is the row's own file with an exact string test, `in_place = new_dest == row["path"]`. The guard at govkit.py:11070-11106 refuses on `ndp.exists()`. On Windows or macOS, a gov rename of `keep.txt` to `Keep.txt` gives a `new_dest` that differs as a string, while `ndp.exists()` is True on the row's own file. Section 4 names the class (the guard never asks whether the occupant is the row itself), and the string test leaves this spelling of it open.
- **Consequence:** an adopter updating past a case-only gov rename keeps the defect this unit closes. The row is refused with `ALREADY holds a file there` on every run, the kit is held back, and the remedy tells the adopter to remove their own installed file. Neither the probe nor the S2 arm exercises this spelling.
- **Fix (skeptic judged it sound):** split S1's predicate in two.
  - Skip the occupancy refusal when the destination IS the row's file: `new_dest == row["path"]`, or `ndp.exists() and ndp.samefile(target / row["path"])`.
  - Skip the move block (the staging lines and `git mv`) only on exact string equality, so that a case-only rename still runs `git mv` and the index and receipt take the new spelling.
  - State the case-only spelling in section 4 "Adopters meet it".
  - Add a check to the `[dSP-88]` arm that, on a case-insensitive node, renames `keep.txt` to `Keep.txt` in gov and requires exit 0 with the receipt path `pinned/demo/Keep.txt`. Stage that check red against the bare string test.
- **Left-shift gate:** add a checklist entry: any path-identity test in a write path must use filesystem identity (`samefile`), not string equality, or state why case and alias spellings cannot reach it.
