### M1. check_contained accepts a `..` key that the raw-key consumers resolve through a link [id 1]

- **Where:** `tools/govkit/upgrade_steps.py:1075-1099` (`check_contained`, through `derive_contained_rel`).
- **What is wrong:** TOOL-dSafePassage-72 replaced check_contained's outright refusal of a `..` segment with derive_contained_rel's lexical `posixpath.normpath`. The link walk then lstat-tests only the normalised segments. So a key like `lnk/../x`, where `lnk` is a directory link, passes as `x`, and `lnk` is never tested. But step programs write the raw key. The fixture up at `upgrade_steps.py:3529` writes `(target / p).write_bytes`, fanout_cap writes `target / POLICY`, and write_step_staged hands the raw keys to git as pathspecs. Spec 72 line 161 says `a/../b` is "the path that is actually opened". That premise is false for every raw-key consumer, and the spec's AC1 arm expects the case to be accepted.
- **Consequence:** On POSIX the kernel resolves `target/lnk/../x` through the link to `<link-dest>/../x`, which is outside the target. A step that names a `..` key can therefore write outside the target. It can also write into `.git/hooks` through a link that points into `.git/objects`: `d/../hooks/pre-commit` normalises to `hooks/pre-commit` and passes both the `.git` segment check and the resolve check. Meanwhile the image's down uses the normalised path, so it restores a different file. A probe on this node used a junction `target/lnk` to `outside/deep`. `check_contained(t, 'lnk/../x')` returned `target\x` with no refusal, while `lnk/x` was refused as a reparse point. It is not reachable today: the only real step uses the constant key `POLICY`, and the fixture writes `{slug}.txt`. It would bite a future step author on a POSIX node whose target holds a link.
- **Grade:** The finder graded it high. The skeptic re-graded it medium, because no current step carries a `..` key. The binding grade is medium.
- **Fix (the finder's fix was REJECTED by the skeptic; this is the skeptic's corrected fix):** Keep derive_contained_rel as govkit's shared dest predicate. In `check_contained` only, refuse any rel that has a `..` segment before normalising it: `if '..' in rel.replace('\\', '/').split('/'): raise Refusal(...)`. That restores the pre-72 refusal for before-image keys. Change the [dSP-72] AC1 arm so check_contained refuses `a/../b`. Add the POSIX `os.symlink` arm for `lnk/../x`.
- **Left-shift gate:** The POSIX `os.symlink` arm above is the gate. Also add to the bug-class checklist: "a containment check must test the same string its consumers open; never normalise before the test".
