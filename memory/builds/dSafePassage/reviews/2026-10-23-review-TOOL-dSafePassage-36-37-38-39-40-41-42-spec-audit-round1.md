### D-2 — The userinfo test refuses every `ssh://git@host/...` URL, which carries no credential (id 13)

- **Where:** TOOL-dSafePassage-38 §4 Data model (the userinfo regex), §2 S1 and §5 risks.
- **What is wrong:** The §4 regex `(?i)\b[a-z][a-z0-9+.-]*://[^/\s@]+@` matches `ssh://git@github.com/o/r.git`, because the bare user `git` before `@` matches `[^/\s@]+@`. The skeptic ran it: the ssh form and `https://u@h/r` match, while the scp form `git@github.com:o/r.git` and a plain https URL do not. S1 and AC2 carry only TOOL-dSafePassage-35 S8's scp-form exemption, and AC3's False cases cover only scp and https forms. `tools/runlog/redaction.tsv:23` already lists `ssh://git@github.com/o/r.git` as a negative example.
- **Consequence:** Built as written, `update` refuses every step on any target whose `remote.<x>.url`, `submodule.<name>.url` or `url.<base>.insteadOf` uses the ssh scheme form. That is a common adopter configuration with no credential in it. §5 prices only a remote that embeds a token, so nothing in the spec would catch it.
- **Fix:** REJECTED by the skeptic, whose corrected fix is the following. Exempt the ssh-family schemes (`ssh`, `git+ssh`, `ssh+git`) when the userinfo is a bare user with no `:password`. `ssh://git@host/...` is then not credential-bearing, while `ssh://u:p@host` still is. Keep every other scheme's bare user refused, as AC3's True case `("branch.main.remote", "https://u@h/r")` requires. Add `("remote.origin.url", "ssh://git@github.com/o/r.git")` to AC3's False cases and `ssh://u:p@h/r` to its True cases. State in §5 that the scp form and the ssh-scheme bare user are kept.
- **Left-shift gate:** A checklist entry: a credential pattern is tested against the repo's existing redaction negatives (`tools/runlog/redaction.tsv`), and an arm feeds those negatives to the new predicate.

### D-5 — Proxy keys take a scheme-less `user:password@host`, which the `://` regex misses (id 10)

- **Where:** TOOL-dSafePassage-38 §2 S1, §4 Data model, §7 "What the check does not cover".

Add a `proxy-schemeless-userinfo` plant to AC1 and check the planted tokens stay out of the output.
