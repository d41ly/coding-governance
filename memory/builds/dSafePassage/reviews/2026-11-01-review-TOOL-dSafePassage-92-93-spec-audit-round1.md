## High

### H1. `test_floor_fallback` forgives a FileNotFoundError or OSError raised before the spawn (id 6)

- **Where:** TOOL-dSafePassage-92 spec, section 2 S1; section 4 "S1: the predicate" (the `crashed` line, and the sentence "FileNotFoundError and OSError are the two spawn failures"); section 5 risks.
- **What is wrong:** The predicate exempts every traceback whose last line starts with `FileNotFoundError` or `OSError`, wherever it was raised. A stub that crashes before its spawn at `python_floor.py:36` therefore reads as the fallback. The skeptic reproduced this. A copy of `python_floor.py` with no `upgrade_steps.py` beside it crashes at line 30 (`exec_module`) with `FileNotFoundError: ... upgrade_steps.py`. The tail has no `subprocess.py` frame, and the predicate copied verbatim returns True. 91's needle reads the same tail as a crash, so 92 lets through a case that 91 catches.
- **Consequence:** `[dSP-91 L2]` would report "falls back to bare bash" for a stub that never reached `subprocess.run`. Two ways to get there are a moved or unloadable step module, and `resolve_kit_dir` raising an OSError subclass in place of LookupError. The path is narrow, but on it the check is a false green. Section 5's claim that a crash reads red is false for this class. None of the five `[dSP-92]` shapes stages it.
- **Fix (skeptic judged it sound):**
  - Exempt the error only when the traceback shows the spawn: `spawn_failed = last.startswith(("FileNotFoundError", "OSError")) and 'subprocess.py"' in tail`. The measured Windows spawn tail carries `subprocess.py` frames, and a Linux one would too.
  - Add a sixth `[dSP-92]` shape: the real stub copy with no stand-in `upgrade_steps.py`, which must read as a crash.
  - Stage the build's red by removing the `subprocess.py` condition, which must turn that shape FAIL.
  - Correct section 4's sentence and section 5's risk line to match.
- **Left-shift gate:** Add a checklist entry: a predicate that excuses an exception class must also pin where the exception was raised, and must carry one staged shape that raises the same class from the wrong place.

### M3. Only one member of the spawn-failure class is graded, and PermissionError reads as a crash (id 13)

- **Where:** TOOL-dSafePassage-92 spec, section 4 "S1: the predicate" (the `last.startswith` tuple) and section 2 S2.
- **What is wrong:** A failed spawn can raise OSError or any of its subclasses, but the tuple names only `FileNotFoundError` and `OSError`. Only the `dsp92-absent` shape covers a spawn failure, and it is a FileNotFoundError. Nothing grades the `OSError` member, although the spec says that is the shape the real fake87 run takes. The skeptic probed both cases. A text-file program ends `OSError: [WinError 216]`. A directory ends `PermissionError: [WinError 5]`, which the tuple reads as a crash.
- **Consequence:** Some hosts reach fake87's text-file `bash` through bare `bash`: Windows without a System32 bash.exe, or Linux with ENOEXEC. On those hosts the check depends on a tuple member that no arm stages. An edit that drops `"OSError"` stays green on node a and turns `[dSP-91 L2]` red on those hosts. An EACCES spawn (a noexec tmp, or a `bash` directory on PATH) turns `[dSP-91 L2]` red although the stub did reach its fallback. The effect is contained in a test arm.
- **Fix (skeptic judged it sound):** Grade the class, not two names. For example, build a name tuple from OSError and its `__subclasses__`, or match `^(\w+Error): \[(WinError|Errno) \d+\]`. Add a `[dSP-92]` shape whose stand-in `resolve_shell_argv` returns a text-file program, as fake87 is, expected to read as the fallback. Add a staged break that drops `"OSError"` and must turn that shape red.
- **Left-shift gate:** Add a checklist entry: every member of an exception-name allow-list carries a staged shape that only it admits.

### M4. The hard-link arm's "nothing is written" term cannot see a write to linked.txt (id 14)
