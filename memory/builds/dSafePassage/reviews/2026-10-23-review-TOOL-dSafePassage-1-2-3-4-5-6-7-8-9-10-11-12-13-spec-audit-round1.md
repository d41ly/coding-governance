### D-1 — The walk cannot start `govkit/receipt-schema-4` on a schema-3 receipt (ids 1, 50)

- **Where:** TOOL-dSafePassage-2 §2 S2 moves 2-3 and S3, against TOOL-dSafePassage-3 §4 Data model (`set_step_state`) and §3.
- **What is wrong:** Unit 2's walk persists an `interrupted:` `failed` row through `set_step_state` before every spawn (spec-2:44-45). It routes every record through that writer (:52-53). Unit 3's `set_step_state` raises `Refusal` on any receipt below schema 4 (spec-3:110-111, pinned by AC7). On a schema-3 receipt the first pending step is `govkit/receipt-schema-4`, and its witness exits 1 below schema 4, so move 3 refuses before the up runs. Unit 2 §3 (:117-118) hands "how the schema step's own row lands while the field does not exist yet" to unit 3. Unit 3 never answers it, and no other spec does either.
- **Consequence:** Every existing adopter receipt and the `ic` fixture gets a `Refusal` on the first `update --write`. So does the release-0 tree, which unit 5 AC2 requires at schema 3. No adopter reaches schema 4 through the walk. Unit 5 AC2/AC7/AC8 and unit 11 AC11 cannot pass on a correct build. Unit 2's fixtures s1..s4 carry no schema step, so they never meet the case.
- **Fix:** Id 1's fix was judged SOUND. Id 50's fix was REJECTED, and the corrected fix narrows the choice to one path. Use option (a) alone, stated in both specs. A walk move whose receipt is below schema 4 persists no step row. A failure or interruption of `govkit/receipt-schema-4` on such a receipt goes only into `update`'s output and findings. Its `applied` row is written through `set_step_state` after the post-spawn re-read, once the receipt is at schema 4. Id 1's sound fix also offered a writer-side exception for the one row. Id 50's skeptic rejected that path, so it is not the fix.
- **Acceptance to add:** `update --write` from a schema-3 receipt that `apply` wrote, run once clean and once with the schema step killed, red when any pre-spawn write refuses. A unit 2 criterion: `fixture walk` from a schema-3 receipt (no `steps`) reaches `govkit/receipt-schema-4 applied`.
- **Left-shift gate:** The spec-set lint should refuse a §3 hand-off phrase ("left to TOOL-X", "X owns") whose target spec has no matching text. Grep the target for the handed-off noun and fail on zero hits.

### D-2 — The reverse walk treats a witness that still holds as a failed down, and three steps' witnesses cannot be falsified (id 51)

- **Where:** TOOL-dSafePassage-4 §2 S4 move 5 and the §4 Data model table. Also TOOL-dSafePassage-1 §4 (S6/S7 downs) and TOOL-dSafePassage-11 (the floor row).

### D-6 — The lock reclaim's `now - age_s` errs toward "reused pid" under a slow census (id 16)

- **Where:** TOOL-dSafePassage-2 §4 "The reclaim and the census" (:185) and S7.
- **What is wrong:** A census row's creation time is `now - age_s`, and the spec never says when `now` is read. S7 treats a creation time more than 2 s after the lock's `started` as a reused pid, so it reads the lock as dead. On Windows `age_s` is sampled inside a PowerShell CIM query (`_CIM_QUERY`, `[int]`-rounded, up to 0.5 s off) that can take a second or more (BACKEND_TIMEOUT_S is 90).
- **Consequence:** If `now` is read after the census returns, which is the natural build, a live holder looks younger by the census latency plus the rounding. Under load that passes 2 s, the live lock is reclaimed, and two `update --write` runs interleave on one receipt.
- **Fix:** Judged SOUND. State that `now` is read BEFORE the census spawn, so the error falls on the safe side. State the window so it does not depend on latency, for example by comparing against the census start time.
- **Acceptance to add:** A `lock-live` plant whose holder took its lock within one second of starting, run while a fixture delay slows the census. It must refuse.
- **Left-shift gate:** A checklist entry for the bug class "clock read relative to a sampled age". Any "now minus age" comparison must name when `now` is read and which way the error falls.

### D-8 — The step contract leaves the target's own `.git/config` executors and credentials live (id 53)

### D-36 — The lock's `host` field conflates the WSL and Windows pid namespaces (id 58)

### D-37 — The `js` forwarder exits 0 when its target cannot start or is killed (id 59)

### D-39 — `read_page_commands` mishandles console prompts, continuations, comments and unbalanced quotes (id 63)
