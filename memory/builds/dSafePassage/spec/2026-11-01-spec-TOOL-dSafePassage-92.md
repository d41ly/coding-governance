### Why the needle cannot work

When `GOV_BASH` is unset and no bash resolves, `resolve_shell_argv` hands the stub the bare argv
(`upgrade_steps.py:437-440`). What runs it is the node's. The witness's tail is the last 20 lines of
stderr (`:1798`), decoded as UTF-8 with `errors="replace"` (`:1795`). Six host tails are possible, and
four of them defeat a needle. A launcher answering in UTF-16 leaves a NUL between every character.
A launcher answering on stdout leaves the tail empty. A spawn that finds no program, on Windows,
fills the tail with `subprocess.py` frames: the measured tail has neither its `Traceback` header nor
the echo of `:36`, and its last line, `FileNotFoundError: [WinError 2] ...`, names no program. A bare
`bash` that reaches a text file, as `fake87` holds, fails its spawn with a bare `OSError`. That
happens on Windows with no System32 `bash.exe`, or on Linux. A raise on `:36` does the reverse,
because the traceback echoes `:36`, and that line holds `"bash"`.

### S1: the predicate

At `selftest.py:4457-4467`, after `path87` (`:4451`) and the `[dSP-87 AC5]` check:

```python

        # TOOL-dSafePassage-92: the stub reached its spawn unless the tail shows a crash, its own early
        # exit or the Refusal. A crash is a traceback, its header or a frame line, unless it is a failed
        # spawn: its last line an OSError, by class, under a subprocess.py frame. The word bash is never
        # required: the WSL launcher with no distribution answers in UTF-16 or on stdout, and a failed
        # spawn's frames fill the 20-line tail on Windows.

        spawn_failed = 'subprocess.py"' in tail and last.split(":", 1)[0] in {
            c.__name__ for c in (OSError, *OSError.__subclasses__())}
        crashed = ("Traceback" in tail or 'File "' in tail) and not spawn_failed
        return not crashed and not any(s in tail for s in ("python_floor.py:", "upgrade_steps.Refusal", "Set GOV_BASH"))

    # `bash` resolves to (on Windows the loader's System32 WSL launcher, elsewhere PATH or nothing), and
```

The frame marker `File "` is the measured part of the skeptic's correction. The correction says a
crash is a tail holding `Traceback`. A raise eight frames below `:36` leaves 29 lines on stderr, so
its 20-line tail has no `Traceback` line, and the header alone reads it as the fallback. Every frame
line starts `  File "`, and Python 3.15 cuts a multi-line frame short with `...<n lines>...`. So
every 20-line traceback tail measured here holds a frame line. That is measured on 3.15 only.

`spawn_failed` is the round-1 spec audit's fix for H1, M1 and M3. Rev-1 forgave an `OSError` raised
anywhere: a stub copy with no step module beside it crashes at `python_floor.py:30` with
`FileNotFoundError: ... upgrade_steps.py`, and rev-1's predicate read that tail as the fallback.
Now the error is forgiven only when the tail holds `subprocess.py"`, the end of a frame line's file
name in `subprocess.py`. The measured spawn tails hold one, and the missing-module tail does not.
The name is graded by class, so `PermissionError`, which a `bash` directory on `PATH` raises, reads
as a failed spawn too. `OSError.__subclasses__()` lists direct subclasses only, and every errno
class `subprocess` raises at a spawn is one. A missing program raises `FileNotFoundError`, measured
`[WinError 2]`. A program that is a text file raises a bare `OSError`, measured `[WinError 216]`.

## 5. Production-readiness checklist

- security: no write path, spawn or surface. The arm runs the stub copy under the scratch root.
- perf / scale: five witness spawns of the stub copy through `run_step_isolated`, about 0.25 s
  each on node a, measured at rev-2.
- error / empty / loading states: an empty tail reads as the fallback by design, because it is the
  launcher on stdout. A crash, the early exit and the `Refusal` read red.
- observability: each `[dSP-92]` FAIL carries the tail's last 600 characters.
- risks: the predicate no longer requires evidence that the stub spawned. A stub that returned
  without spawning and wrote nothing would read `ok`. The skeptic's correction accepts that, and
  the early exit, the stub's one non-spawning return, stays a named red. An `OSError` raised before
  the spawn reads red unless a `subprocess.py` frame sits in the same 20-line tail. The predicate
  still accepts an `OSError`-class last line under any `subprocess.py` frame, which a pre-spawn
  raise chained under a spawn could show. The no-module shape stages the unchained case.
- testing: §7's two New arms, and AC1 to AC3.
- migration: none.
- user docs: none. No page under `help/` describes the selftest's floor checks.
