## 1. Goal

Every upgrade step this build's units declare, and every one a later build adds, is proven over a
real adopter tree of today's vintage before an adopter meets it: walked up, rolled down to
byte-identical, walked up again, each step skipped once, killed once after its first write and made
to fail once, and every planted adopter edit carried or ordered. Today no release-0 adopter tree
exists as a fixture: govkit's only fixture is a receipt, and its rename arm is graded by authored
fixtures alone (`gap-tool-10`, closed by this unit). The tree is generated by the pinned commit's own
`apply`, never hand-copied (brief S8), and the walk is the `upgrade-walk` leg, the supersession
research's losing test for its candidate E (`research-supersession.md`, section 4).

## 4. Design

### The fixture files

`tools/govkit/fixtures/release-0/`:

| File | Holds |
|---|---|
| `pin.txt` | the pin, one full sha and a newline |
| `deploy.toml` | no `kits` line, since `apply --all` derives the selection; the answers of gov's own `.governance/deploy.toml` rewritten to the characters `apply` admits, and `user_skills` inside the scratch |
| `seed/` | the project layer copied into the target before `apply`: the conf files and answers each kit's adopter refuses without |
| `plants.toml` | the `[[plant]]`, `[[gov_plant]]` and `[[condition]]` rows |
| `arms.toml` and `arms/` | the defective steps and plant of S7, and their scripts |

A `[[plant]]` row: `id`, `path`, `edit` (`append`, `replace` with `old` and `new`, or `create` with
`text`), `expect` (`carried` or `ordered`), and for `carried` one observation: `contains` (a text the
walked file holds), `unchanged` (the bytes as planted), or `policy` (a `key`, its `value`, and
`absent`, the paths the walked commit must not hold). A `policy` observation runs gov's own reader,
the clone's `tools/policy/policy.py get <key> --rev <the walked commit's sha>`, under
`sys.executable` with the target as its working directory. The reader takes its catalogue from the
clone's kit and reads the policy file and `.agent-cap.conf` only as committed at that sha
(TOOL-dGroundRules-2 S2 and S6, TOOL-dGroundRules-15 S1), so the release-0 target needs no reader of
its own. The observation holds when stdout is `value` and no `absent` path is in that commit. A
`get` exit of 2 is a red that carries the reader's `policy: refused` line. `ordered` holds when an order under
`.governance/outbox/` names the path. A `[[gov_plant]]` row: `id`, `what` and the edit, committed on
the clone's tip. A `[[condition]]` row: `step`, and either `plant` (a `[[plant]]`-shaped edit) or
`fakes` (launcher names and the version each prints, put first on the child's `PATH`).

The rows at this pass, each path re-read against the pin's tree when the row is written:

| Row | Kind | What | Expect |
|---|---|---|---|
| `engine-edit` | plant | one comment line appended to an `engine` row of the memory-tree kit | carried, `contains` |
| `project-owned` | plant | one value changed in a `project-owned` row | carried, `unchanged` |
| `fanout-cap` | plant | `.agent-cap.conf` created holding `FANOUT_CAP=2` | carried, `policy` `runtime.agents-in-flight` reads `2`, `absent` `.agent-cap.conf`, since a conf of `FANOUT_CAP=2` lowers the key to 2 whether the step ran or not |
| `wired-hook` | plant | an adopter's own hook entry in `.claude/settings.json` beside gov's | carried, `contains` |
| `old-shape-record` | plant | a spec under `memory/builds/` dated before `SPEC10_CUTOFF`, nine sections | carried, `unchanged` |
| `edited-render` | plant | one line edited in a `rendered` row's file | ordered |
| `edited-retired` | plant | one line appended to the file `withdraw-one` withdraws | ordered |
| `withdraw-one` | gov plant | one installed file dropped from its descriptor's `[[files]]` at the tip | — |
| `floor-below` | condition | `lib/python-floor-3.15`, fakes `python3`, `python` and `py` printing `3.14` | — |
| `size-limits` | condition | `govkit/template-size-limits-to-budgets`, `tools/template-size-limits.txt` created with one row | — |

### The cases

Every case starts from a fresh copy of the committed, planted release-0 target and walks to the
clone's tip, `update --target <t> --to <tip> --write`, committed after, as an adopter commits it.

| Case | Per step | What it observes |
|---|---|---|
| `up` | no | every step's row reads `applied` in `read_step_states`, and each step's witness, run through `run_step_isolated`, exits 0 on the walked tree |
| `down` | no | after `up`, `update --rollback --to <pin> --write`; the digest equals release-0's |
| `reup` | no | after `down`, the walk again; the digest equals `up`'s |
| `plants` | no | after `up`, each `[[plant]]` carried by its observation, or ordered |
| `skip` | yes | step k's first `witness` call answers `ok`, so the walk passes it unrun; k is load-bearing when the digest differs from `up`'s or k's real witness then exits non-zero; under k's `[[condition]]` the walk without the skip stops at k and with it gets past k |
| `kill` | yes | step k's `up` runs on a shadow copy of the target, its first write is applied to the target, and the child exits by `os._exit(137)`; the killed state holds the lock with a dead pid and k's row `failed` with `interrupted:`; a re-run's digest equals `up`'s, and from a copy of the killed state `update --rollback --to <pin> --write` reaches release-0's digest |
| `fail` | yes | step k's `up` answers `{"verdict": "failed", "rc": 1, "tail": "upgrade-walk: planted exit 1"}`; the walk exits 1, every step before k reads `applied`, the last `applied` row is k-1 (none for the first), k reads `failed` with `exit 1`, and no later step is recorded |
| `shims` | no | the clone holds no tag; `read_releases` over it returns none; `check_shim_windows` holds every row `read_shim_rows` reads; each forwarder whose `from` the receipt installs is in the walked target; zero rows prints `shims: 0 declared`, counted as measured-nothing |
| `isolation` | yes | `check_needs_target` over a scratch copy of release-0 returns `isolated` or `attended`; `breach` or `needs-target` is a red naming the step |

The first write. `derive_first_write(before, shadow)` lists the paths the shadow run changed and
orders them by modification time, a path the run unlinked timed by its parent directory's; the
earliest is applied to the target as its bytes, or as its absence. A step whose shadow run changes
nothing is killed at its end. The order is an approximation of the step's own write order, and
§5 says what it cannot see.

### The arms

| Arm | What it is | The case it must red |
|---|---|---|
| `witness-first` | a step writing its witness file before its payload | `kill`: the re-run skips it and the digest differs |
| `not-rerunnable` | a step appending one line on every run | `kill`: the re-run doubles the line |
| `no-op` | a step writing nothing, its witness always 0 | `skip`: not load-bearing |
| `lossy-down` | a step whose down leaves one byte | `down` |
| `drops-plant` | a step overwriting the `engine-edit` line with no order | `plants` |
| `held-shim`, `drops-shim` | a fixture shim row over an installed path, and a step unlinking that path | `shims` |
| `breaks-isolation` | a step whose up imports from the target's root | `isolation`: `breach` |
| `missing-plant` | a plant row whose path release-0 lacks | exit 2 |

An injected step's `introduced` is the clone's tip, so it walks last.

### The leg and its output

```
python tools/govkit/upgrade_walk.py
python tools/govkit/upgrade_walk.py --list
python tools/govkit/upgrade_walk.py --case <case> [--step <id>] [--inject <name> ...] [--pin <rev>]
```

count of steps passed and red, each arm's verdict, and the shims and attended counts, every figure
DERIVED. Exit 2, with its reason: the pin fails S1; release-0's `apply` exits non-zero, naming each
problem; a plant's path is absent at release-0; no step is declared. The leg row:
`{"name": "upgrade-walk", "argv": ["python", "{prefix}/govkit/upgrade_walk.py"], "chunk": "e2e",
"subject": "kit", "reads": {"history": "..."}, "doc_reads": []}`, with no `guard`, since steps live
in every kit descriptor, and a `ceiling` from its measured time. Temporary trees go under
`tempfile.mkdtemp(prefix="uw")`, a short path, and are removed in a `finally`. The module raises no
`Refusal` and appends to no report, so `govkit refusal join` gains no branch.

### Alternatives rejected

- **Release-0 from HEAD's `apply` rewound by `write_vintage_receipt`** (`tools/govkit/selftest.py:620-676`).
  It rewinds each row's commit and identity and leaves the receipt's `schema` as HEAD writes it, so
  after TOOL-dSafePassage-3 lands the schema step's witness already holds at release-0 and the `skip`
  case cannot see it load-bearing; and HEAD's renderer writes the renders. That reading of the
  helper's body is the test that rejected it (§8 F1).
- **A committed release-0 tree.** The brief's S8 forbids a hand copy, and a committed tree is an
  inventory typed beside what generates it.
- **A filesystem watcher killing the step at its first write.** A step that finishes inside one
  poll interval is never killed, so the case cannot be observed for every step (§8 F2).
- **Fail points in each step's code, armed by an environment name.** Every step script must call
  them, and TOOL-dSafePassage-7's environment is built from an allowlist, so the name never reaches
  the step (its S1).
