## 4. Design

### Why the runs move here rather than run twice

Units 1 and 15 hand these runs to this unit (§8 F1): spec 1 keeps S1 to S4 and replays 2 to 4, and
spec 15 keeps S1 to S4. Each hands-off bullet names the criteria this unit answers in its place, and
that unit's acceptance ledger records them as superseded by the criteria named here (spec 23 §8 F7's
form). Running first at order 15 or 16 would mean running spec 1's clone step, which exits 128, or
scoring on manifest terms the build already declared defective. It would spend about 130 agents on
verdicts this unit would then have to reverse.

### The run, per clone

The procedure is the replay section of `tools/workflows/README.md` (S8), run once per attempt clone,
`<name>` the clone's S10 name and `<commit>` the commit given. Its exact-commit check, unit 27 S22's,
is the liveness check. For replay 1, `<commit>` is the placement commit of S2, made by the step
below and reachable only from the transient ref. Unit 15's runs are unit 30's.

### What the opt-in pack reads from a replay call

The pack judges the call's structured `args` alone, read by `extractWorkflowArgs`
(`tools/workflows/spec-audit-optin.js:119`; `tools/hooks/agent-cap.js:603-609`, a JSON string parsed
first). A call whose `kind` is `spec-audit` (`:127`) needs four things.

1. **The subject's build folder.** `repo` is a non-empty string (`:128-130`). `reviewDir`'s parent is
   the build folder, and it must be a `builds/<slug>` folder with no `..` segment (`:138-143`). For
   `memory/builds/dFairHearing/reviews` the slug is `dFairHearing`. Every `subjects[].path` must then
   name that slug (`:159-164`), as `extractBuildSlug` reads it (`agent-cap.js:590-597`): the segment
   after the path's first `builds` segment. This is the refusal that denied both rev-5 calls, whose
   one subject named `dClosedLoop`. `specs` is never read: the only other path check, `:149-158`,
   covers `units[].specPath` on a build-harness call carrying `specAudit`, and a replay call carries
   neither.
2. **The README it reads in the clone.** It reads `<repo>/<build folder>/README.md`, `repo` folded from
   MSYS spelling on win32 and resolved against `cwd` (`:171-177`). Here that is the clone's
   `memory/builds/dFairHearing/README.md`, the file S2's placement adds.
3. **The `RUN.md` branch.** It reads `RUN.md` beside that README (`:186-190`). If the read fails with
   ENOENT, the session is attended and the check falls through. Any other read failure is a deny. A
   readable file whose `phase:` fact is outside `NO_AUDIT_PHASES` decides alone, by its pinned
   `spec-audit:` fact (`:191-208`). `6cfd21619` holds no file under `memory/builds/dFairHearing/`
   (`git ls-tree -r --name-only 6cfd21619 memory/builds/dFairHearing/` printed nothing on
   2026-11-03), and the placement adds only the README there and the placed subject below it, so the
   clone holds no `RUN.md` and the ENOENT branch is taken.
4. **The front-matter key.** `readFrontMatterKey(bytes, 'spec-audit')` (`:178`) must be a date
   (`:216`). It is refused when the README also carries an `authorized-by:` other than `slug`,
   because the run writes that README itself (`:212-215`). The README at `3708a705` carries
   `spec-audit: 2026-10-21` and no `authorized-by:` (`git show 3708a705:memory/builds/dFairHearing/README.md`),
   so the call is admitted at `:216` and `.unattended.conf` is never read (`:217-230`).

The same reading rules out the record's own build. dClosedLoop's README at `6cfd21619` carries
`spec-audit: 2026-10-14` under `authorized-by: prompt`, so a `reviewDir` under
`memory/builds/dClosedLoop/` is denied at `:212-215`. A probe calling `checkSpecAuditDeclared` with
`repo` `$TEMP/fhr1a` printed DENY for the dClosedLoop subject path and ADMIT for the placed subject
path on 2026-11-03.

### Why the placed subject path nests the record's own path

The known set's rows address the record at
`memory/builds/dClosedLoop/build/2026-10-15-build-PLAY-dClosedLoop-1-layer-runtime.md`
(`memory/builds/dFairHearing/build/2026-11-03-build-TOOL-dFairHearing-1-known-set.md:33`). A
candidate's ref matches a row's record by `check_same_file`, which holds when the paths are equal or
one ends with `/` followed by the other (`tools/workflows/replay_scorer.py:381-383`). Both the
`address-match` list and every adjudicated pair are held to that test (`:530`, `:542`). A ref the
auditors write against the placed subject path ends in `/memory/builds/dClosedLoop/build/…`, so it
matches, and so does a ref to the record's own path, which the clone also holds. A flat copy such as
