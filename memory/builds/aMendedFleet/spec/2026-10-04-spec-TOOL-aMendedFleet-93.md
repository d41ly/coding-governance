## 1. Goal

Unit 67 gives `tools/workflows/tier2-review.js` an optional `workerType` argument that spawns its
finders and skeptics as a built-in read-only type which omits the charter, and leaves every run as it
is until something measures the cost of doing so. The report asks for that measurement: one tier2
run with the charter and one without, compared on precision and on the tokens each judge spends on
its first turn `[B#29]`. This unit runs that pair from the main loop over one frozen, already-reviewed
range, commits every instrument and every result row to this build's folder, applies a decision rule
written down before either arm runs, and sets the review harness's default to whatever the rule
reads. It never claims an effect beyond the one pair it measured.

## 2. Scope (IN)

- **S1** — THE RUN BRIEF. A journal record under this build's `build/` folder carries the subject,
  the two arms' exact `args`, the arm order, the key-directory handling of S3, the decision rule of
  §4 verbatim, and the cost estimate. Written and committed before either arm runs. Observed by AC5.
- **S2** — THE INSTRUMENT. One Python file under `build/`, standard library plus the tree's own
  `tools/runlog/extract.py`, with four verbs. `selftest` builds a fixture session tree in a temporary
  directory and asserts the other verbs over it. `tokens` takes a session id and one workflow
  directory per arm, reads each agent's `.meta.json` beside its transcript, classifies the agent by
  its label (`find:` a finder, `verify:` a skeptic, `synth` and `resume:probe` orchestration, anything
  else unclassified), and for every judge writes one row: arm, label, role, the meta `agentType`, its
  first-turn context, the `in` plus `cache_read` plus `cache_write` of the first `usage` event of a
  one-file `SessionTree` built over that transcript as `scan_owner_turns` builds one, and its summed
  `out`. `arms` reads the two committed Workflow return objects. `aggregate` reads committed files
  only and prints the per-arm table, the two medians, both precisions and one verdict word.
  Observed by AC1, AC3 and AC4.
- **S3** — THE ROUTE. The first unit pass authors S1 and S2 and commits them with this spec at
  INPROGRESS, and returns to the main loop the need to run the arms, because a pass runs in a
  sidechain that holds no Workflow tool. The main loop moves any `review-lenses/<key>` directory the
  subject's key already has under the git common dir to a `.ab-held` sibling, runs arm B, then arm A,
  as two sequential Workflow calls, renames A's key directory to a `.ab-arm-a` sibling and restores
  the held one, and commits both return objects, both reports and the `tokens` rows. A second build
  pass then runs `aggregate`, writes the reading, applies S4 or S5, and sets this spec CLOSED.
  Observed by AC2 and AC5.
- **S4** — ON `DEFAULT-PLAN`. `tools/workflows/tier2-review.template.js` and its render take
  `workerType` absent as `Plan`; the literal `workerType: 'none'` spawns as today, durability
  instructions included. `tools/workflows/README.md` documents both. The review protocol's
  "Results are durable" paragraph, in `tools/workflows/REVIEW-PROTOCOL.template.md` and its render
  `memory/guides/REVIEW-PROTOCOL.md`, says the default judges are read-only and write no result
  file, so a resume reuses nothing unless the run passes `workerType: 'none'`. The drift harnesses
  keep their default: this pair measures none of their agents. Observed by AC6 and AC7.
- **S5** — ON `KEEP-DEFAULT`. No file under `tools/` or `memory/guides/` moves; the reading is the
  deliverable. Observed by AC6.
- **S6** — ON `INVALID`. The main loop re-runs the invalid arm once, with S3's key handling; a second
  `INVALID` is parked in the run-state file with the reading, the options and the reason, and this
  unit closes on the record without S4 or S5. NOT OBSERVED by a criterion here: it is a branch the
  route takes only on a failed arm, and AC4 prints the word that selects it.
- **S7** — THE ARM REPORTS. Each arm's synthesis report is renamed to hygiene check 5's grammar under
  `build/`, and its `**Serves:**` line, which names the subject build's units, is rewritten to read
  `**Serves:** journal TOOL-aMendedFleet-93`, so the subject's closed specs gain no record. Observed
  by AC8.

## 3. Non-goals (OUT)

- More than one pair, or a claim of a general effect. The reading is one sample per arm; the record
  says what it cannot show.
- The `Explore` type. Its model is `haiku`, so an arm under it would change the judge and the context
  at once, as unit 67 recorded.
- The drift-audit harnesses' default. Their skeptics are routable by unit 67, and nothing here
  measures them.
- A custom agent definition: unit 67 found the installed CLI lets none omit the charter.
- Extending runlog's tokens-to-READY mode. That mode measures a main thread to its READY point; a
  judge's first turn is one `usage` event of one sidechain file, which the extractor's existing
  readers already reach.
- The rule that an experiment's instruments are committed. Another unit of this build writes it;
  this unit obeys it.
- The review-harness kit version move, owed once at the close after the build's last move of the
  kit.

## 4. Design

### Evidence

Read at the worktree HEAD `8312d315`, whose bytes under `tools/` equal base `7af5f564`'s.

- The harness's return object carries `exit`, `lensesReused`, `batchesReused`, `lensesDead`,
  `skepticsDead`, `precision`, `confirmed`, `refuted`, `blockers` and `highs`, so validity and the
  precision half are read from what one Workflow call returns.
- A workflow script cannot read a subagent's context size: `tools/workflows/orient-counterfactual.js`
  says so in its header and measures output tokens only. The first-turn half must therefore come from
  the transcripts after the run.
- A Workflow agent's transcript sits under the session's `subagents/workflows/<run>/` directory as
  `agent-<id>.jsonl` beside an `agent-<id>.meta.json` whose `description` is the harness's label and
  whose `agentType` is the spawned type, read on node a 2026-10-04. The harness labels finders
  `find:<lens>`, skeptic batches `verify:ids-<a>-<b>`, the synthesis `synth` and the probe
  `resume:probe`. A first assistant record carries `input_tokens`, `cache_creation_input_tokens` and
  `cache_read_input_tokens`.
- `scan_owner_turns` in `tools/runlog/extract.py` builds a one-file `SessionTree` and runs
  `extract_session` over it, which is the shape S2 reuses per judge.
- The harness keys resume files by `deriveReviewKey(base, head)` under
  `<git-common-dir>/review-lenses/`, and this clone holds
  `diff-review-r1-886b089dfd9c-e252bafb3fe3-152dab81` today. A re-run with matching inputs reuses
  every file there and spawns no finder at all, which is why S3 moves the directory aside and AC2
  asserts zero reuse.

`INVALID`. The record also states each arm's confirmed counts by severity, its summed judge output
tokens and the subject's recorded round-1 figures, none of which moves the word.

## 5. Production-readiness checklist

- security — arm B narrows what a judge can do; the held key directory is renamed, never deleted.
- perf / scale — the unit's point; the saving is the measured median, not a claim.
- error / empty / loading states — a dead lens, a reused file or an unclassified agent makes an arm
  `INVALID` by name, never a zero; a session limit kills workflow agents silently, so the main loop
  resumes the run by its id.
- observability — every row names its arm and label, and the reading names the files it read.
- risks — one sample per arm; a read-only type's own prompt can move what a finder reports, which is
  exactly the precision half. Under `DEFAULT-PLAN` a review that dies mid-run resumes nothing unless
  it passed `none`, which S4's protocol line states.
- testing — AC1 to AC8; the instrument carries its own `selftest`.
- migration — none.
- user docs — S4's README and protocol lines under `DEFAULT-PLAN`; the reading otherwise.
