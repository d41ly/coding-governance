# aPromptedMandate — M4 spec audit

**Serves:** spec-audit TOOL-aPromptedMandate-1 TOOL-aPromptedMandate-2 TOOL-aPromptedMandate-3 TOOL-aPromptedMandate-4 TOOL-aPromptedMandate-5 TOOL-aPromptedMandate-6

## Verdict: BLOCKED

Spec-set audit (M4) at base `6517579f`, over all six units plus the build README and the anchor-reuse
reproduction record under `build/`.

Twenty-six confirmed defects across seventeen distinct sites, twenty-three refuted, none left
unverified. The build's headline finding survives the audit intact: the authorization layer needs no
change, and no confirmed finding asks for one. What blocks is one level up — the design's own
precondition and its own contradiction with the two documents an agent reads first:

- **The `ANCHOR_SCOPE="published"` precondition is stated nowhere in the spec set.** The word does not
  appear in any of the six specs. The prompt path is nevertheless written into `SKILL.template.md`, a
  KIT template whose shipped example conf declares `ANCHOR_SCOPE=""`, and whose render carries no
  placeholder for it. Every adopter at the shipped default receives a procedure that ends in
  `fail 6`, with the Skill's own quoted remedy inert.
- **The prompt path's defining act is flatly forbidden by the Skill's shared step 1 and by protocol
  §1**, and no spec scopes the amendment. Unit 5 declares the slug path out of scope; the slug path is
  where the prohibition lives.

Units 4 and 5 are additionally unbuildable as written — a builder following unit 4's enumeration of
leg consumers ships a red `check-unattended.sh`, and a builder following unit 1's stated awk change
ships a mode reader that always returns empty.

## How the audit ran

Tier-2 per `memory/guides/REVIEW-PROTOCOL.md`: **4 primed finder lenses** in one wave over the six
specs, the build README, the reproduction record, `memory/TEMPLATE-SPEC.md`,
`memory/guides/BUILD-METHOD.md`, `memory/guides/UNATTENDED-PROTOCOL.md` and the kit at
`tools/unattended/`; then **5 batched default-refute skeptics** (49 findings, groups of ten, the
protocol's hard cap and not one agent per finding); then this synthesis pass.

| Stage | Count |
|---|---|
| raw findings from the lenses | 49 |
| confirmed after the refute pass | 26 |
| refuted | 23 |
| unverified (no verdict returned) | 0 |
| precision — confirmed / (confirmed + refuted) | 0.53 |

Precision clears the protocol's 0.5 floor, so the scope was right-sized rather than over-fanned. The
lenses were briefed with the by-design list — the untouched authorization layer, protocol §9's
forgeability boundary, §1's already-priced cost 1, and the two owner-ratified forks — so nothing
below re-litigates those. Findings carry the audit-batch id in the first column so each traces back.

## What the audit did not find

Worth stating, because it is the build's central claim and it held. No confirmed finding asks for a
change to `check_authorization`'s verdict, to `resolve_base`, to `observe_anchor`, or to leg check 13.
The reproduction record under `build/` was checked against source by more than one lens and its four
measurements stand. What the audit found instead is that the design's precondition and its cost were
measured, understood, and then not carried into the artifacts an adopter and an agent receive.
