## MEDIUM

### M1. `GATE_REGEN_BOUND` bounds the verdict but not the wall clock on Windows, because the output goes through a pipe (ids 1, 15)

- **Where:** `tools/run-gates/regen.py:225-227` (`run_command`).
- **Defect:** on Windows, `subprocess.run`'s timeout handler calls `kill()` on the direct child and then `communicate()` with no timeout, which waits for EOF on the stdout pipe. Any grandchild still holding the pipe keeps the verb blocked. Both skeptics measured it on node `a` (Python 3.14.6, Git-Bash bash): `sleep 6 & wait` under `timeout=1` raised only after 6.5 s, and `sleep 8 & sleep 8` under `timeout=2` raised only after 8.1 s. This is not the by-design note that only the pid is killed. That note accepts that a descendant can outlive the kill, but it does not accept `regen.py` waiting for the descendant. No arm covers the timeout path.
- **Impact:** every declared check and write is a bash or python process that spawns git and python children, so a hung grandchild blocks three things with no bound. The runner's preflight runs before the turnstile and before `arm_wall` (`run-gates.sh:3627`), so nothing else stops it. `run-gates.sh --regen` blocks too, and so does the lander's `out=$(... regen.py --write)` between the mint and the push on both paths. Spec 2's promised `TIMEOUT` verdict is never reached, and an unattended run stalls until its gate backstop.
- **Fix** (both judged SOUND): send the child's output to a file, not a pipe. Pass a `tempfile.TemporaryFile()` as stdout with `stderr=subprocess.STDOUT`, using `subprocess.run` or `Popen` + `wait(timeout)` + `kill`, then `seek(0)` and read the file. The post-kill wait then waits only on the direct child's handle. Optionally kill the whole tree on timeout: `taskkill /F /T /PID <pid>` on Windows, or `start_new_session=True` plus `os.killpg` on POSIX.
- **Left-shift:** add a canary arm that MEASURES elapsed time: a fixture check `bash -c 'sleep N & wait'` under `GATE_REGEN_BOUND=2` must print the TIMEOUT line and return within a small multiple of 2 s. Keep N only a few seconds above the bound, because orphaned sleeps hold the scratch repo as their cwd and `rm -rf` fails on Windows until they exit (the id 15 skeptic's caveat). Separately, run a predicate for `subprocess.run(` with both `stdout=PIPE` and `timeout=` over `tools/**/*.py`, print hits and near-misses, and wire it as a gate for class C11 if the hits are clean.

### M4. `regen.py` prints non-ASCII without switching stdout to UTF-8 (id 5)

- **Where:** `tools/run-gates/regen.py:348`, and every print of `·`, `—`, `…` and of child output tails.
- **Defect:** on Windows without `PYTHONUTF8=1`, a piped stdout uses the locale code page. The skeptic measured it on this node with `PYTHONUTF8=0`: stdout was cp1251, `·` came out as the single byte 0xB7, and printing `→` raised `UnicodeEncodeError`. The repo treats this as a live class: TOOL-aMendedFleet-97 records that the hosted runner runs outside UTF-8 mode, and `gotchas.py`, `routed_commits.py` and `gen_map.py` reconfigure stdout for that reason. Node `a` avoids it only because it exports `PYTHONUTF8=1`.
- **Impact:** arms 1r and 1s match UTF-8 literals such as `regen: STALE · stage 1 · fake` (`run-gates.test.sh:396, 449`), so they red on such a host though the verb is right. `push-main.sh`'s `grep -v ' · moved: none$'` never matches. A tail, NOTE line or moved path holding a character the code page cannot encode crashes the report partway, before the remaining verdict lines and the count line. The exit codes mostly stay correct.
- **Fix** (judged SOUND): at the start of `main`, add `sys.stdout.reconfigure(encoding="utf-8", errors="replace")` inside `try/except (AttributeError, ValueError)`, as `gen_map.py` does.
- **Left-shift:** run arms 1r and 1s once with `PYTHONUTF8=0` to observe the red before the fix. Then consider a predicate over `tools/**/*.py`: a file whose string literals carry non-ASCII and that is run as a script must call `reconfigure` on stdout. Run it over the real tree and print hits and near-misses before wiring it.

### M5. `shutil.which("bash")` still resolves WSL's launcher when the parent PATH is the default Windows one (id 8)

- **Where:** `tools/run-gates/regen.py:217` (`run[0] = shutil.which(run[0]) or run[0]`).
