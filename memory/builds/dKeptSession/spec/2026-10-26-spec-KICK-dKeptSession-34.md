## 1. Goal

The round-1 spec audit of this build's spec set
(`memory/builds/dKeptSession/reviews/2026-10-26-review-KICK-dKeptSession-1-spec-audit.md`)
confirmed finding **id 2 at HIGH**, report item **H2**. Id 17 is the same defect, found by the
grounding lens, and shares the item; it is promoted as `KICK-dKeptSession-33`. Unit 33 is the store's
rule for the eight derived-default rows, and this unit is the reader's half of the same fix.

Under unit 33's rule six derived rows are assigned in no preset, and `review.<stage>` is assigned
only at its concrete keys. `KICK-dKeptSession-2`'s step misses on such a row and answers `None`, so
`read_default_value` runs next and raises `DerivedDefault`, the refusal it makes of every
`{ derived = ... }` default with no preset named (`tools/policy/policy.py#read_default_value`,
`tools/policy/policy.py#DerivedDefault`). `get` refuses it as any `Refusal`, and only the caps
module reads such a row, as no file value (`tools/policy/budgets.py#resolve_caps`). This unit pins
that answer down: it adds the unassigned class to unit 2's `preset-every-key` case, so the reader
never writes a value over the evidence-derived caps and role efforts, and it adds the case reading a
cap through the caps module under a preset. It builds one step after unit 2 (order 4).
