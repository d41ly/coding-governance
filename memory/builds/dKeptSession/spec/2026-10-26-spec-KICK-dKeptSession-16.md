## 1. Goal

No policy namespace declares what it is for: the catalogue gives a key an optional `summary` and
`usage` and gives a namespace nothing, so the project map's policy-namespace nodes carry no purpose
(the project map's CS4-F1,
`memory/builds/dClosedLoop/build/2026-10-17-build-PLAY-dClosedLoop-1-project-map.md@e918d08a8a9d:657`,
which gives the policy namespace's purpose to dKeptSession). This unit gives each policy namespace a
purpose row in the catalogue, refuses a new namespace that declares none, holds today's purposeless
namespaces on a shrink-only list awaiting review, and reviews them as `memory.map-purpose`'s default,
`review`, says (PM-5,
`memory/builds/dClosedLoop/build/2026-10-17-build-PLAY-dClosedLoop-1-project-map.md@e918d08a8a9d:660`),
reading that key as a stand-in until dTotalRecall lands it.

## 4. Design

### Evidence

- `load_catalogue` returns `doc.get("key", [])` (`tools/policy/policy.py#load_catalogue`), so a
  `[[namespace]]` table in the same file is invisible to every `[[key]]` reader, `check_shape`
  (`tools/policy/policy.py#check_shape`) included. The other catalogue readers read `[[key]]` alone
  too: `read_policy_members` (`tools/govkit/step_gate.py#read_policy_members`),
  `read_policy_usage` (`tools/govkit/docs_leg.py#read_policy_usage`) and `extract_policy`
  (`tools/playbook/tag_index.py#extract_policy`).
- Landed since this spec's base, read 2026-11-21: `check_shrink_list` takes a fifth argument, the
  reason a derived name the list lacks is given, and the factory, `check_unnamed_list` and the
  three-list `cmd_lists` are KICK-dKeptSession-19's; `build_repo` copies the catalogue,
  `policy.LIST` and the cap census alone into its kit copy; every shipped preset assigns
  `memory.map-purpose = "review"` (`tools/policy/presets.toml`), so the preset step answers as the
  default does. A seed case runs its one arm alone, so the planted `zz` reds no other arm's case, and
  the loop kit's `policy-key` factory gates on `POLICY_KEY_ARMS`, four arms without this one
  (`tools/loop/factories.py#POLICY_KEY_ARMS`). The reader-coverage scan skips `check_policy.py`
  (`tools/policy/check_policy.py#derive_scanned_files`), so the arm's read books no reader, and the
  mirror's `catalogue_blob` is re-rendered by the lander at each landing (`tools/policy/README.md`,
  "Regenerated at every landing"), so a catalogue edit owes no `.governance/policy.json` here.
- The hand-rolled lists today are `check_list` and `write_list`
  (`tools/policy/policy.py#check_list`, `#write_list`) and the legacy-home list
  (`#check_legacy_homes`, `#write_legacy_homes`), graded by `cmd_lists` against one
  `resolve_compare_base`; KICK-dKeptSession-19 (order 2) moves them onto its factory and adds the
  third, so this list is the fourth.
- The catalogue carries `memory.map-purpose`, allowed `review`, `ledger`, `derive`, `refuse`,
  default `review`, owner dTotalRecall (its row in `tools/policy/catalogue.toml`), so `resolve`
  already answers `review` from the default. dTotalRecall is DEFERRED in `memory/LIVE.md`, and no
  code in the tree reads the key.
- PM-5's `review`
  (`memory/builds/dClosedLoop/build/2026-10-17-build-PLAY-dClosedLoop-1-project-map.md@e918d08a8a9d:868`):
  a new node must declare a purpose; each existing node is reviewed by the unit that adds its
  namespace's purpose field, derived from what it carries with the source cited, and a node carrying
  nothing goes to the owner in one ask per namespace.

### Alternatives rejected

- **A purpose on the tag namespace row.** `tools/playbook/namespaces.toml` has one `policy` row for
  every key; it cannot say what `runtime.*` is for apart from `review.*`.
- **A separate namespaces file in the policy kit.** A second file read beside the catalogue would
  join the same names twice; one file keeps the population and its purposes in one read.
- **The awaiting set as the catalogue's own purposeless rows**, PLAY-dOrderedCharter-22 S4's form.
  There the existing set is fixed by the design baseline; here a namespace appears whenever a key is
  added, so only a list against a compare base can tell an old purposeless namespace from a new one.
