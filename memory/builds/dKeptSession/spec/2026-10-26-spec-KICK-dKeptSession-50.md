## 4. Design

### Evidence

Read at HEAD `c2a407b0`, 2026-11-21.

- `tools/policy/kit.toml`: `[[regenerate]]` is `["bash", "{kit}/adopt-policy.sh", "--scaffold"]`,
  and the `[[generated]]` row for `.governance/policy.json` names `policy.py mirror --write` and
  `mirror --check` at stage 2.
- `_cmd_update` reads `GOVKIT_RERENDER` once as `_rerender_on`, and `0` declines the re-render.
- `adopt-policy.sh --scaffold` keeps an existing policy file, then, wherever HEAD resolves, renders
  the settings and `policy.py mirror --write`; it defers the mirror only on the `uncommitted changes`
  refusal of an input. `--check` is `check_policy.py --repo <repo>`, whose exit it returns.
- `arm_mirror_parity` compares the working-tree mirror with `render_mirror(repo, "HEAD")` through
  `check_mirror_text`, which names the first differing field, `legacy_blobs` among them
  (`tools/policy/policy.py#check_mirror_text`).
- `build_landed_repo` (`tools/policy/check_policy.py#build_landed_repo`) copies the kit's reader
  files to the kit's own path in a scratch repository and commits them, so the kit's own adopter run
  with `--target` renders the same paths there.

### The pre-unit mirror

```
plant: .governance/policy.json, the render at HEAD less legacy_blobs[<kit>/presets.toml], committed
adopt-policy.sh --scaffold          -> legacy_blobs gains <kit>/presets.toml · mirror --check exit 0
re-render skipped, then --check     -> exit 1, arm_mirror_parity · legacy_blobs
```
