## 1. Goal

A compacted or fresh session reorients from its card, and the card says where the build started, not
where it is: `write_card_follow` re-publishes the build card at transitions under `card.follows`
(`skills/session-kickoff/manifest-check.sh#write_card_follow`), and nothing between two transitions
moves it. The owner's CX-1 answer asks for pointers updated as the build progresses, "the latest
records by tag, the open forks, the item in flight", beside `card.follows`
(`memory/builds/dClosedLoop/build/2026-10-15-build-PLAY-dClosedLoop-1-compaction-results.md@fa7f848f:336`;
`memory/builds/dClosedLoop/build/2026-10-14-build-PLAY-dClosedLoop-1-architecture-v2.md@9bf3b4c9:1240`).
This unit writes a `## pointers` section into the session and build cards by `card.pointers`, and
defines the item boundary, I12, the one point every later session unit reads at.

## 2. Scope (IN)

- **S1** — The item boundary, I12. `derive_item_boundary(repo, slug, pointer, pos=None)` in
  `tools/loop/position.py` reads `derive_position` (`tools/loop/position.py#derive_position`), or
  the `pos` its caller already derived, and returns the build's current item when it differs from
  `pointer`, else `None`. The current item is the `act` answer's `next.key`, the instance key
  `derive_instance_key` spells, `<item tag>@<pass>#<inputs>`; any other answer is `none`, except
  `stale-remote` and `invalid-input`, which keep `pointer` (§8 F5). The CLI `python
  tools/loop/position.py <slug> --boundary <key|none>` derives once and prints `boundary — <pointer>
  → <key|none>` or `boundary — none crossed · item <pointer>`, the second form ending ` · <answer>`
  for a kept pointer, then `forked — <unit id> · …` or `forked — none`, the units the same
  derivation's hand-over grades `FORKED`. Exit 0, and 2 on `invalid-input` after both lines. Observed
  by AC4.
- **S2** — The section, I11. `render_pointers <slug> <boundary file>` in
  `skills/session-kickoff/manifest-check.sh` prints `## pointers` and three lines: `records — <kind>
  <path> · …`, from S3; `forks — <spec path>§8 · …`, each `forked —` unit's tracked spec under the
  build's `spec/` folder, or `none`; and `item — <instance key|none> · at <sha8>`, the boundary's
  answer and the HEAD it was derived at. A source that does not resolve prints `<word> — skipped:
  <why>` on its line, and the `item —` line then still ends ` · at <sha8>`. KICK-dKeptSession-26 and
  KICK-dKeptSession-5 add the `budget —` and `mail —` lines below these. The required lines are one
  list, `POINTER_LINES="records forks item"`, which `check_card_pointers` reads inside `check_card`:
  a stored card whose `## pointers` section lacks a listed line fails `--card --check` naming the
  line, a card with no section passes, and each later unit appends its own word. Observed by AC1,
  AC11.
- **S3** — The records reader. `python tools/memory-tree/gen_build_index.py --latest-records <slug>`
  prints one `<kind> <path>` line per kind of `RECORD_KIND_TOKENS`
  (`tools/memory-tree/tree_lib.py#RECORD_KIND_TOKENS`) the build's bound records carry, the newest by
  filename, sorted by kind. It runs `read_bindings` (`tools/memory-tree/tree_lib.py#read_bindings`)
  over the build folder's tracked paths alone, so a typed kind a unit adds to `TYPED_RECORD_KINDS` is
  read with no change here. Observed by AC10.
- **S4** — The write. `write_pointers <tail file> <slug>` replaces the tail's `## pointers` section,
  its heading to the line before the next `## ` heading or READY line, or inserts it directly before
  the READY line, which stays last. `write_build_card` calls it on every tail it builds, in each of
  its `session`, `stored` and `none` modes, so every publish and every follow carries a fresh section
  (S8). `manifest-check.sh --card --pointers --build <slug> [--session <sid>]` publishes through
  `write_build_card` in `stored` mode to every store `card.store` selects; with `--session` it also
  writes the section into that session's card and re-renders its card file through
  `write_card_file`. A card the section pushes past `CARD_CAP_BYTES` is not written and prints `card
  — pointers not written: <n> bytes over the cap`. Observed by AC1, AC6.
- **S5** — The key. `card.pointers` joins `read_card_policy`'s keys, its default `every-item` and its
  closed set `every-item`, `at-transitions`, read by one literal `get card.pointers` line. Its
  catalogue row already stands (`tools/policy/catalogue.toml`, `name = "card.pointers"`, owner
  dKeptSession); this unit gives it `summary` and `usage`, runs `python tools/policy/policy.py lists
  --write`, which takes it off `tools/policy/unsummarised-keys.txt`, and re-renders
  `help/reference/policy.md` by `python tools/playbook/render_playbook.py --reference`. Observed by
  AC3, AC9.
- **S6** — The boundary verb, the one item-boundary point. `manifest-check.sh --card --boundary
  --build <slug> --session <sid> [--transcript <path>] [--out <file>]` first moves the `at` of the
  session card's `item —` line to HEAD, writing `## pointers` with `item — none · at <sha8>` where the
  card has none, and re-renders the card file. It then runs S1 once under `CARD_POSITION_BOUND` with
  the line's old key as `pointer`. On a crossing it prints `boundary — <from> → <to>` and rewrites
  the session card's section; under `every-item` it also publishes as S4 does, and under
  `at-transitions` it publishes nothing. With no crossing it prints S1's line and publishes nothing.
  `--out` writes every line the verb prints to `<file>` through a temp beside it and a rename,
  instead of stdout, and is refused, exit 2, where the file's directory does not exist. Every later
  item-boundary reader runs inside this verb after S1 answers: `context.on-full`
  (KICK-dKeptSession-14), `mailbox.reads` (KICK-dKeptSession-10), `mailbox.notice`
  (KICK-dKeptSession-21); `actions.free` (KICK-dKeptSession-8) reads the `item —` line it leaves.
  Observed by AC2, AC3.
- **S7** — The trigger, `checkItemBoundary(data, env, checker)` in `tools/hooks/scratch-guard.js`,
  run from `main` after every arm admits a Bash or PowerShell call, for the main session only, a

## 4. Design

### Evidence

- The card verbs: `render_build_card` renders the startup cells through `render_card` and appends
  the tail; `write_build_card` builds the tail per mode, renders and writes each store, refused past
  `CARD_CAP_BYTES`; `extract_card_parts` splits STARTUP from TAIL by `CARD_PARTS_AWK`, the tail
  ending in the one READY line (`skills/session-kickoff/manifest-check.sh#write_build_card`).
- The verbs parse at the `--card` block's case list, `--write` to `--lookup`, with `--build` held to
  `[A-Za-z0-9]+` before it reaches a ref or a path (`manifest-check.sh#CARD_VERB`).
- `derive_position` answers `act` with `next.key`; probed 2026-11-21 over this build it answered
  `item.build.base@KICK-dKeptSession-1#1f066366`, the pass field a unit id. Its `units` carry each
  unit's M2 state from the driver's `--plan` hand-over, `plan_state`'s answer
  (`tools/unattended/unattended.sh#plan_state`), so the `forked —` line costs no second read.
- Measured on this node, 2026-11-21, over dKeptSession, PINNED: `position.py dKeptSession --json`
  took 7.3 s, `unattended.sh --plan dKeptSession --paths` 10.3 s, and S3's reader 0.2 s.
- The hook: `main` runs `checkCommand`, `checkOriented` and `checkRoleGate` on Bash and PowerShell
  calls, then exits 0 (`tools/hooks/scratch-guard.js#main`). `readCard` spawns the checker's
  `--card --path` through `resolveCardBash` on every call it serves, while the tree's card file at
  `CARD_FILE_REL` is read with no spawn, as `readCardEnvelope` reads it; `write_card_file` writes it
  with a `card-owner — <sid> · <transcript>` line (`manifest-check.sh#write_card_file`).
- The harness admits `additionalContext` in a PreToolUse hook's `hookSpecificOutput`
  (KICK-dKeptSession-14 §8 F1 records the probe).

| routes a build, no `## pointers` | any | starts S6 detached |

| `item — K · at A` | `B` | starts S6 detached: its first act moves `at` to `B` |

## 5. Production-readiness checklist

- security — no new store: the section travels through `write_build_card`'s stores and the session
  card; the slug is held to `[A-Za-z0-9]+` at the `--card` block before it reaches a path or a ref,
  and the hook passes only a slug its card file's route names and an id-shaped session id. `--out`
  writes where its caller names, as a shell redirect does, and is refused where the directory is
  absent.
- perf / scale — the hook adds one fs read and one `git rev-parse` per main-session shell call of a
  routed tree, and one detached verb per commit; the verb pays one position read, S3's read and, at
  a publish, `render_card`'s startup cells, the same cost as every publish and follow, now plus one
  position read each.
- error / empty / loading states — each line names its own skipped source; an over-cap section is
  refused, the card left as it was.
- observability — every crossing prints `boundary — <from> → <to>`, reported at the session's next
  shell call.
- risks — a second shell call inside the moment before the verb moves `at` starts a second verb; both
  derive one answer, and a lost compare-and-swap re-renders once, as every publish does. Two
  sessions on one build race the ref the same way. A position read past its bound prints `item —
  skipped: <why> · at <sha8>`, so the hook does not retry until HEAD moves.
- testing — S9's plants and the hook arm, red and green.
- migration — none.
- user docs — `help/orientation-card.md`, S10; `help/reference/policy.md`, re-rendered.
