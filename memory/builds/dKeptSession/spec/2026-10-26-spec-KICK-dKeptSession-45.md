`resolve_projects_root` (`tools/runlog/extract.py#resolve_projects_root`) already resolves that

with `CLAUDE_CONFIG_DIR` set the literal scans the profile's tree, which holds none of that node's
transcripts, finds no observation and reads the 200000 rung, which is the defect unit 30 exists to
repair. This unit makes the scan's default root that resolver's answer. It repairs
`KICK-dKeptSession-30`, unbuilt at base `c2a407b0` and built at order 13, and builds one step after

## 4. Design

### Evidence

- `resolve_projects_root(env=None, platform=None, override=None)` returns `override`, else
  `$CLAUDE_CONFIG_DIR/projects`, else `<home>/.claude/projects`, the home read from `USERPROFILE`
  then `HOME` on Windows and from `HOME` elsewhere, and raises `ValueError` naming `--transcripts`
  when no root resolves (`tools/runlog/extract.py#resolve_projects_root`, read at `c2a407b0`).
- The runlog selftest's `main` aims every `DECOY_VARS` member at a decoy before any arm runs, and
  `build_arm_env` aims each at the arm's own scratch (`tools/runlog/selftest.py#DECOY_VARS`,
  `tools/runlog/selftest.py#build_arm_env`). `HOME` and `USERPROFILE` are decoyed beside
  `CLAUDE_CONFIG_DIR`, so a literal profile path still lands in a decoy; what the literal misses is
  `CLAUDE_CONFIG_DIR`, the decoy its home does not follow.
- `extract.py` spells `".claude"` once (DERIVED, `grep -c '".claude"' extract.py` at `c2a407b0`),
  in the resolver's own return (`tools/runlog/extract.py#resolve_projects_root`).
- `derive_context_window` is not in the tree at `c2a407b0`: unit 30 mints it, so this unit edits
  unit 30's landed function.

```
CLAUDE_CONFIG_DIR=<cfg>   derive_context_window("m")  -> scans <cfg>/projects
unset, HOME=<h>           derive_context_window("m")  -> scans <h>/.claude/projects
neither                   derive_context_window("m")  -> (200000, "no root: runlog: no transcripts root resolves ...")
```
