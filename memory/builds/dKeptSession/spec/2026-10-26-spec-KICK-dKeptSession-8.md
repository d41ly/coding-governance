## 1. Goal

About 63% of main-loop tool calls follow no protocol step, PINNED by orientation's measure
(`memory/builds/dClosedLoop/build/2026-10-14-build-PLAY-dClosedLoop-1-orientation.md@60854977:107`),
and nothing ties a Bash write, a commit, a push or a spawn to the work item that owns it. The write
gate ties an Edit or a Write to a routed unit (`tools/hooks/scratch-guard.js#checkRouted`) and a
commit to a READY card (`tools/hooks/scratch-guard.js#checkOriented`), never to an item, and the
item-boundary step reads the card's `item —` line only to start the boundary verb, never to refuse
(`tools/hooks/scratch-guard.js#checkItemBoundary`). This unit carries `actions.free` at the tool
call, as the owner settled it: off-item acts are read-only probes by default, free inside the
current item; every write, spawn, commit or push belongs to an item, and anything else is filed as
an intake
(`memory/builds/dClosedLoop/build/2026-10-14-build-PLAY-dClosedLoop-1-orientation.md@60854977:310`).
The catalogue row is v2's
(`memory/builds/dClosedLoop/build/2026-10-14-build-PLAY-dClosedLoop-1-architecture-v2.md@9bf3b4c9:1175`),
and strict's preset sets `item-reads-only`
(`memory/builds/dClosedLoop/build/2026-10-14-build-PLAY-dClosedLoop-1-architecture-v2.md@9bf3b4c9:1500`).

## 4. Design

### The decision

| Pointer | Class | `read-only-probes` | `item-reads-only` | `recorded-anything` |
|---|---|---|---|---|
| an item | any | admit | admit | admit |
| `none` | `read` | admit | refuse, unless a boundary command | admit |
| `none` | `write`, `commit`, `push`, `spawn` | refuse | refuse | admit, one log line |

`BOUNDARY_HEADS = ['position.py', 'manifest-check.sh']`: the two commands that move a session to its

them `item-reads-only` could never leave `item — none`.

### Alternatives rejected

- **A new hook file.** `scratch-guard.js` already reads the card file and classifies writes and
  commits; a second hook would read both again and race the first on one call.
- **Deriving the item in the hook.** Running the position engine per tool call costs a Python spawn
  on every Bash call and gives two places the boundary is decided.
- **Refusing reads off-item under `item-reads-only` with no exception.** It leaves no act that can
  move the pointer, so a strict session deadlocks between items.
- **The build card through `--card --path --build`, as rev-3 read it.** Under `at-transitions` the
  boundary verb rewrites the session card and does not publish, so that card names a finished item
  (§8 F3).
- **Spawning `node policy-mirror.js get` per read, as rev-3 did.** The hooks kit already requires the
  reader in process for rule 7 and for the red-fix lane, so a subprocess buys no isolation the kit
  keeps elsewhere and costs a node start per read (§8 F4).
- **A second `item —` parse beside `checkItemBoundary`'s.** Two regexes over one line drift; the
  arm and the step read one function.

## 5. Production-readiness checklist

- security — deny by default once armed: a throw refuses and so does a value outside the three; the
  value comes only from the landed mirror through the one reader; the log line carries the class and
  tool, never the command text.
- perf / scale — the pointer is one file read per call with no spawn; the policy read, the reader's
  git and shim spawns, runs only at `item — none`, and is unbounded inside the reader exactly as the
  red-fix lane's read is.
- error / empty / loading states — unarmed cases print their witness and admit; a reader that throws
  reads the default with a `NOTE`.
- observability — every refusal names the value, class, tool and the pointer; every recorded act is a
  log line.
- risks — between a commit and the detached boundary verb's rewrite the pointer still names the item
  just finished, so acts pass under it; a role agent still running when the pointer moves to `none`
  is refused under the default. Both are KICK-dKeptSession-13's latency, and `item-reads-only`'s
  boundary commands always run. Until KICK-dKeptSession-43 lands, one order later, an
  `item — skipped:` line reads `malformed` and refuses every act of an armed session, the boundary
  commands among them.
- testing — the fixture's plants by a pass; the arms in §7 observed RED then GREEN by the main loop.
- migration — none.
- user docs — `help/orientation-card.md`, and the hooks kit's `tools/hooks/README.md`.
