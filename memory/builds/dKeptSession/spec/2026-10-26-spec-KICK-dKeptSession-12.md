## 1. Goal

A resumed session trusts its card only once the card reaches the instruction slot after a move into a
worktree and a compaction, which PLAY-dOrderedCharter-8 S1's fixture `card-compaction.fixture.sh`
measures. TOOL-dPlacedRequest-2 S7 built the switch: `derive_resume_lines`
(`skills/session-kickoff/manifest-check.sh#derive_resume_lines`) reads `always-resume` as
`fresh-when-idle` unless `read_card_fixture_verdict` answers `pass`, reads `red: no recorded run`
while no such reader is defined, and never consults `CLAUDE.md`. Nothing records the fixture's
verdict or reads it, so the override is permanent, and a fresh recommendation names no tree. This
unit records the verdict, defines the reader the landed switch calls, names the build's worktree in
every fresh recommendation, and states the order of the replay lines the session units after it
extend (the owner's FK-1-6,
`memory/builds/dClosedLoop/build/2026-10-14-build-PLAY-dClosedLoop-1-architecture-v2.md@9bf3b4c91952:738`
and
`memory/builds/dClosedLoop/build/2026-10-14-build-PLAY-dClosedLoop-1-architecture-v2.md@9bf3b4c91952:1177`;
flow-roles H14).

## 2. Scope (IN)

- **S1** — The verdict's record. `manifest-check.sh --card --fixture-run <scratch-dir>`, a card verb
  beside the others the card argument loop takes, its value held as `--build`'s is, runs `bash
  card-compaction.fixture.sh <scratch-dir>`, the kickoff engine's sibling found beside the engine as
  `MC_DIR` names it. It takes no `--session` and reads no stdin: it is answered once `CARD_DIR`
  resolves and before `read_session_id`, as `--path --build` is, since that reader refuses every
  verb but `path` and `follow` without a session id; `--build` beside it is refused as it is beside
  `--write`, and the `--card needs one of` refusal names it. `write_card_fixture_verdict` then
  `write_card_fixture_verdict` writes one line to `<git-common-dir>/orientation/card-fixture.verdict`
  (the card directory `CARD_DIR` names): `card-fixture — <verdict> · fixture <blob8> · cli <version>
  · <iso>`. `<verdict>` is `pass` for exit 0, `red <limb>` for exit 1 with the limb the fixture's
  last line names after `FAILED limb`, `absent` for exit 2, the fixture's could-not-run exit, and
  `red exit <rc>` otherwise; `<blob8>` is `git hash-object` over the fixture file; `<version>` is
  `read_session_cli_version`'s answer, else `unknown`. `read_session_cli_version` is the `AI_AGENT`

  exits 2 and writes nothing. The verb writes nothing else outside the scratch directory but the
  harness transcripts the fixture names as its one outside write. It prints the line it wrote and
  exits 0, whatever the verdict. Observed by AC4.

## 4. Design

### Evidence

- `derive_resume_lines` holds the switch: under `always-resume` it sets `red: no recorded run`,
  calls `read_card_fixture_verdict` only when `declare -F` finds it, prints `resume — resume
  recommended (resume.context: always-resume)` on `pass`, and otherwise prints the fresh
  recommendation with this unit's override line. Its comment says the entry file is not consulted.
- `print_replay` prints the map block, the re-keyed card, the `card —` line and
  `derive_resume_lines`' three lines, then `derive_head_state` and the `now —` line, so `now —` is
  last today.
- The plants `context-always-resume` and `context-fixture-red` export a stub
  `read_card_fixture_verdict`; a function the engine defines replaces an imported one, so once S2
  lands the first plant reads the engine's reader, not its stub.
- The fixture exits 0 on a pass, 1 naming the failed limb on its last line, and 2 when `claude` is
  absent, no scratch dir is named, or it is not empty
  (`skills/session-kickoff/card-compaction.fixture.sh@b79ea80334bb:17`).
- `derive_cli_line` takes the session's version from `AI_AGENT`'s `claude-code_<version>`, the field
  before the next `_` with dashes as dots, then compares PATH's `claude --version` with it.
- `render_build_card` (`skills/session-kickoff/manifest-check.sh#render_build_card`) writes the
  publisher's startup cells, `tree —` among them, into the build card, and `resolve_build_card`
  re-keys it with the startup cells re-rendered here, so only its pre-re-key copy names the
  publisher's tree.
- `read_session_id` refuses every card verb but `path` and `follow` when no session id comes from
  stdin's payload or `--session`, after reading stdin when it is not a terminal; a plant runs the
  engine with stdin closed (`skills/session-kickoff/card-store.fixture.sh#run_card_engine`).
- `print_replay` calls `resolve_build_card` in a command substitution and keeps `CARD_TMP` across
  the re-key, so `$CARD_TMP/bc.found` is still on disk when `derive_resume_lines` runs; the plants
  `context-idle`, `context-always-fresh` and `context-transcript-absent` grep each `resume —` line
  whole, so each moves with S4.
- `manifest-check.sh` is on the kickoff manifest's `watch:` line
  (`memory/guides/SESSION-KICKOFF.md@e1fc70813070:7`), and the manifest check's staged leg refuses a
  commit staging a watched path that does not move `last-audit`.

```
card-fixture — pass · fixture 3f9c2a71 · cli 2.1.308 · 2026-10-27T09:14:02+0000
```

One line, overwritten by every `--fixture-run`, under the common dir so every worktree of the clone
reads one verdict: the harness that compacts is the node's, not the tree's.

## 5. Production-readiness checklist

- security — the verdict file holds a word, a blob id, a version and a time; it is written only by
  `--fixture-run` and read only as one line matched against its grammar, a malformed line reading
  `red: no recorded run`.
- perf / scale — the reader costs one file read and one `git hash-object` per replay.
- error / empty / loading states — every failure to read is a `red` with its reason, so the override
  can only fail towards recommending a fresh session.
- observability — the reason is printed on every overridden `resume —` line.
- risks — a pass recorded before a harness upgrade goes stale by version, so an upgrade re-arms the
  override until the fixture is run again.
- testing — S6's plants, red and green.
- migration — none.
- user docs — `help/orientation-card.md`, S7.
