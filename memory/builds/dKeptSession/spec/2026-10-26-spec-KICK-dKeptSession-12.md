## 1. Goal

A resumed session trusts its card only once the card reaches the instruction slot after a move into a
worktree and a compaction, which PLAY-dOrderedCharter-8 S1's fixture `card-compaction.fixture.sh`
measures. TOOL-dPlacedRequest-2 S7 already reads `always-resume` as `fresh-when-idle` and reports
the override, but it switches on the import line in `CLAUDE.md`, a stand-in for the fixture that a
hand edit of `CLAUDE.md` silently breaks (scout C's disagreement), and its recommendation names no
tree. This unit makes the fixture's recorded verdict the switch, so the fixture wins over
`resume.context` while it is red, names the build's worktree in every fresh recommendation, and
fixes the order of the replay lines the session units after it extend (the owner's FK-1-6, v2:738,
v2:1177; flow-roles H14).

## 4. Design

### Evidence

- At base `print_replay` prints the stored card and one `now —` line (`manifest-check.sh:719-725`).
- `CLAUDE.md` at base is `@AGENTS.md` alone, so TOOL-dPlacedRequest-2 S7's override is live today, and
  PLAY-dOrderedCharter-8 S5 adds the import only on a green fixture (its §8 F1). The two agree only
  while nobody edits `CLAUDE.md` by hand; the verdict read here holds either way.
- The fixture exits 0 on a pass, 1 naming the failed limb, 2 when `claude` is absent, and writes
  nothing outside its scratch directory (PLAY-dOrderedCharter-8 §4 "The fixture").
- `derive_cli_line` takes the version from `AI_AGENT`'s `claude-code_<version>` with no spawn (:414).

### The verdict file

```
card-fixture — pass · fixture 3f9c2a71 · cli 2.1.308 · 2026-10-27T09:14:02+0000
```

One line, overwritten by every `--fixture-run`, under the common dir so every worktree of the clone
reads one verdict: the harness that compacts is the node's, not the tree's.

### The resume lines

```
resume — fresh recommended: idle 1840s past 300s · in C:/work/repo/.claude/worktrees/dExample (resume.context: always-resume read as fresh-when-idle · card-import fixture red: no recorded run)
resume — resume recommended (resume.context: always-resume)
```

### Migration

None. A node with no verdict file reads `red: no recorded run`, which is the behaviour the import-line
stand-in gives today on a tree without the import, so the default recommendation does not change.

### Rollout

Live at landing. A node starts recommending resumption under `always-resume` only after someone runs
`--fixture-run` there and it passes.

### Files touched (estimate)

- `skills/session-kickoff/manifest-check.sh`: S1 to S5; `KIT_MANIFEST_VERSION` moved
- `skills/session-kickoff/manifest-check.test.sh`: the arm the §7 line declares
- `skills/session-kickoff/card-store.fixture.sh`: S6's plants
- `help/orientation-card.md`: S7's paragraph

### Alternatives rejected

- **The import line as the switch**, TOOL-dPlacedRequest-2 S7 as specced: a proxy that a hand edit
  decouples from the fixture it stands for.
- **The fixture run from the replay.** Two harness sessions inside a SessionStart hook would stall
  every resume for minutes.
- **The verdict committed as a record.** The fixture judges the node's harness, so a verdict in the
  tree would let one node's pass switch the override off on a node that never ran it.

## 5. Production-readiness checklist

- security — the verdict file holds a word, a blob id, a version and a time; it is written only by
  `--fixture-run` and read only as one line matched against its grammar, a malformed line reading
  `red: no recorded run`.
- perf / scale — the reader costs one file read and one `git hash-object` per replay.
- error / empty / loading states — every failure to read is a `red` with its reason, so the override
  can only fail towards recommending a fresh session.
- observability — the reason is printed on every overridden `resume —` line.
- risks — a pass recorded before a harness upgrade goes stale by version, so an upgrade re-arms the
  override until the fixture is run again.
- testing — S6's plants, red and green.
- migration — none.
- user docs — `help/orientation-card.md`, S7.
