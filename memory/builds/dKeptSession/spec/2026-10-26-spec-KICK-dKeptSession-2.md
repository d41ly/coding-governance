## 1. Goal

dGroundRules' one reader answers a key from the policy file, else from the catalogue default, and a
file naming `preset = "strict"` reads every key it does not set at its default: `hooks.bypass` reads
`allowed` where strict says `refused` (DA-M10,
`memory/builds/dClosedLoop/reviews/2026-10-18-review-PLAY-dClosedLoop-1-design-audit.md@d2f807838522:222`).
dGroundRules landed the slot and a reason clause saying the preset is not applied until this build
(`tools/policy/policy.py#read_default_value`). This unit adds the step between the file and the
default, so a key the file does not set reads the named preset's value where the preset assigns one,
and rewrites the clause, the texts that state it and the fixture case asserting it.

## 4. Design

### Evidence

- The step's `table` is `parse_policy`'s `{key path: value}` of leaves, never a nested table
  (`tools/policy/policy.py#parse_policy`, `#read_file_value`), while `derive_preset_assignment` reads
  a declared preset as `table.get(<name>)`, the nested `[presets]` table `read_repo_table` returns
  (`tools/policy/presets.py#read_repo_table`); passed the leaves, it refuses every declared name.
- `parse_key("review.<stage>")` refuses, `"review.<stage>" is not one TOML key` (probe 2026-11-21).
- Under `python policy.py`, `presets.policy` is not `sys.modules["__main__"]`, so its `Refusal` is
  another class than the one `cmd_get` catches (probe 2026-11-21 at `2bf35aa1`, `runpy` over the
  file as `__main__`).
- `derive_preset_assignment` over strict took 16 to 21 ms per call, the catalogue load included
  (PINNED, measured 2026-11-21 at `2bf35aa1`, twenty calls averaged).

### The order

```
RESOLUTION_ORDER = (read_file_value, read_preset_value, read_default_value)

read_preset_value(path, row, table, rev_phrase):
    if table is None or ("preset",) not in table:   return None   # absent file, or no preset named
    name = table[("preset",)]
    import presets                                   # beside this file; it imports this one
    a = read_preset_assignment(name, presets.derive_declared_presets(table))
    return Resolution(a[path], "preset", f"preset {name} at {rev_phrase}") if path in a else None

read_kit_presets():                                # one slot: the store, parsed once per process
    return presets.load_presets(KIT)

read_preset_assignment(name, declared):            # one slot, keyed (name, render_json(declared))
    return presets.derive_preset_assignment(name, read_kit_presets(), declared)

# each import of `presets`: ImportError -> Refusal(<kit>/presets.py, 0, ...)
# each call into it: presets.policy.Refusal as exc -> Refusal(exc.path, exc.line, exc.why)
```

`Resolution`'s source vocabulary already holds `preset`. A file naming a preset `validate` refuses
is not read here: `resolve_read` sends invalid text to `read_last_valid_value`, whose own
`read_ordered_value` runs this step over the last valid revision's table, flattened alike
(`tools/policy/policy.py#read_last_valid_value`).

### Migration

A repository whose policy file names a preset reads that preset's values from this unit's landing
where it read defaults before. `standard` equals the catalogue defaults (KICK-dKeptSession-1 S2), so
a `standard`-named file reads the same values with source `preset`; a `strict`- or `guarded`-named
file changes posture, which is the clause. gov's own `.governance/policy.toml` names no preset, so
its mirror and its reads do not move.
