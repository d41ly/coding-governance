## 1. Goal

The owner asked to hear about unattended progress "as it is now - microformats at the end of each turn",
each option owner-adjustable (flow-roles FR-3,
`memory/builds/dClosedLoop/build/2026-10-15-build-PLAY-dClosedLoop-1-flow-roles.md:183-185`, settled at
:204-206). No key selects anything today: the driver prints its own verb lines and the charter's
micro-formats end each turn. This unit carries `notify.owner` (v2:1226): `turn-micro-formats`, the
default, keeps today's behaviour exactly; `park-and-landing`, `every-transition` and `park-only` add one
owner-facing `progress —` line at the events each selects. Progress only: an owner item's push is
`notify.owner-items`' and Runtime's (v2:1228), and no push channel is built here.

### The line

```
progress — dExample · park · item design-fork-3
progress — dExample · landing · 3f9c2a71
progress — dExample · transition · designing → building · item.design.exit
```

It stores nothing. It is an emitted line for the final message, as the block's other shapes are, and the
renderer is the one producer, so the definition and the line cannot drift.

### Alternatives rejected

- **Gating the driver's own verb lines.** Suites and readers key on them (`phase LANDED`,
  `decision parked`), so a value that hid them would change what every caller sees.

- **A push under `park-only`.** Progress has no push channel by v2:1226, and a push is Runtime's.

## 5. Production-readiness checklist

- security — the line carries a slug, an event, an item tag or a sha; no request text and no secret.
- perf / scale — one policy read per park, landing or transition, each already a rare event.
- error / empty / loading states — an unknown event exits 2; the loop kit unresolved prints nothing; a
  reader refusal reads the default with a `NOTE`.
- observability — the line is the observation.
- risks — under `every-transition` with `transitions.record`'s `micro-format` selected the owner reads a
  `transition —` and a `progress —` line per move; the two answer different keys.
- testing — the plants by a pass; the arms in §7 observed RED then GREEN by the main loop.
- migration — none.
- user docs — `help/loop.md`.
