### Alternatives rejected

- **Gating the driver's own verb lines.** Suites and readers key on them (`phase LANDED`,
  `decision parked`), so a value that hid them would change what every caller sees.
- **Gating the `transition —` line.** Two keys would then decide one line; §8 F1.
- **A push under `park-only`.** Progress has no push channel by v2's row, and a push is Runtime's.
- **A second definition checker beside `check_transition_definition`.** It would copy the fence walk
  for a kind's second instance; S6 extracts the walk instead.

## 5. Production-readiness checklist

- security — the line carries a slug, an event, an item tag or a sha; no request text and no secret.
- perf / scale — one policy read per park, landing or transition, each already a rare event, and
  inside a transition one read beside the read the move already makes.
- error / empty / loading states — an unknown event exits 2; the loop kit unresolved prints nothing
  in the driver; a refusal is the verb's `unanswered` line, and inside a move one `unread` line.
- observability — the line is the observation.
- risks — under `every-transition` with `transitions.record`'s `micro-format` selected the owner
  reads a `transition —` and a `progress —` line per move; the two answer different keys.
- testing — the plants by a pass; the arms in §7 observed RED then GREEN by the main loop.
- migration — none.
- user docs — `help/loop.md`.
