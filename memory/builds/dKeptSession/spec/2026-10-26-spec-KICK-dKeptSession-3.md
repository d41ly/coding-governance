## 1. Goal

v2's preset rules have the charter render the preset's name and only the keys that differ from it,
"so a reader sees the posture and its exceptions, not the whole catalogue"
(`memory/builds/dClosedLoop/build/2026-10-14-build-PLAY-dClosedLoop-1-architecture-v2.md@9bf3b4c91952:1419`),
and v2's `[owed]` row gives that render to dKeptSession
(`memory/builds/dClosedLoop/build/2026-10-14-build-PLAY-dClosedLoop-1-architecture-v2.md@9bf3b4c91952:2010`).
The charter has no preset section today, and dOrderedCharter's landed instruction map prints its
preset line from a constant, `PRESET_LINE_PENDING`, until this build
(`tools/playbook/instruction_units.py#render_instruction_map`). This unit adds one policy kit verb
printing the name and the differing keys, renders it into a charter section through
dOrderedCharter's renderer and the playbook kit's one caller of the policy reader, and fills the
map's preset line from the same verb, seen red on a planted override the committed charter does not
show.

## 2. Scope (IN)

- **S1** — The verb `python tools/policy/policy.py preset --diff [--section | --line] [--rev <rev>]`
  (shared interface I5), `cmd_preset` over `render_preset_diff`, over one `read_revision` read of
  `rev`, else the landed revision. The name is the `preset` key as `resolve_read` answers it: the
  file's value, or `standard (the default)` when the file names none. The compared assignment is
  KICK-dKeptSession-1's `derive_preset_assignment` for that name, `standard` for a file naming none.
  A key is listed when the assignment holds it, by exact path or by the matched row's name for a key
  the file sets, and its resolved value differs from the assignment's; a key the assignment does not
  hold, a `never` key or an unassigned derived row (KICK-dKeptSession-33), is never listed. The
  default form prints `- preset — <name>`, then one `` - `<key>` — <value> (<name>: <preset
  value>) `` line per listed key sorted by key, each value spelled as `get` prints it, a list joined
  by `, `; `- no key differs` when none does. `--section` prints the same lines bounded for the
  charter: at most `PRESET_DIFF_LINES` key lines with a last `` - … (+<k>) — `policy.py preset
  --diff` `` line past it, each line cut at `PRESET_DIFF_LINE_CHARS` with a trailing `…`. `--line`
  prints the map's one line, `preset — <name> · <k> key(s) differ: policy.py preset --diff`. Each
  value is read through `resolve_read` over the one read, so the section and `get` cannot disagree.
  Exit 0, 2 on a refused read with the reader's `policy: refused` line. Observed by AC1 and AC2.
- **S2** — The reader `read_preset_diff(root, form, rev=None)` in `tools/playbook/policy_value.py`,
  beside `read_policy_value`: it finds the policy kit through that module's `resolve_kit_dir`, runs
  S1's verb with `form` (`--section` or `--line`) in `root`, in an environment holding no `GIT_`
  variable, and returns its stdout lines; no kit, a verb that cannot start or a non-zero exit
  raises `PolicyRefused` carrying the reader's last stderr line. Observed by AC3 and AC5.
- **S3** — The probe `derive_preset_section` in `tools/playbook/render_playbook.py`, registered in
  `PROBES` as `preset_section`: it substitutes `read_preset_diff(root, "--section")` verbatim, the

  <why>` on stderr and returns the empty string, so an unanswered miss refuses at
  `resolve_placeholder_raw` naming the key. Observed by AC3.
- **S4** — The placeholder row `PRESET_SECTION` in `tools/govkit/entries/playbook.kit.toml`,
  `class = "derived"`, `probe = "preset_section"`, `kit = "policy"`, beside `ROLE_ROSTER`. Observed

- **S5** — The section in `coding-governance-agents.template.md`, fenced `<!-- kit:policy -->`

- **S6** — The map's preset line: `render_instruction_map`'s last line is `read_preset_diff(root,

## 4. Design

### The section as rendered

```
<!-- kit:policy -->
## Policy preset — the posture and its exceptions

<!-- one-line -->
- preset — strict
- `hooks.bypass` — allowed (strict: refused)
- `leases.expiry-hours` — 12 (strict: 24)
<!-- /one-line -->

<!-- /kit:policy -->
```

Every line is a `- ` bullet because the renderer refuses any other line inside a one-line region
(`tools/playbook/render_playbook.py#check_one_line_regions`). A key differs when the file sets it
and its value is not the preset's: a key the file leaves alone reads the preset's value through
KICK-dKeptSession-2's step, so it never differs. A declared repository preset is its own name here,
and its keys are the assignment the verb compares against. With no preset named, the comparison is
against `standard`, which equals the catalogue defaults, so the section lists the keys the file moves
off its defaults.

### Bounds

`PRESET_DIFF_LINES = 12` and `PRESET_DIFF_LINE_CHARS = 160` in `policy.py` bound `--section`: past
the first, the section names how many keys it cut and the verb that prints them all; the second
keeps each line under the renderer's one-line rule cap, `ONE_LINE_MAX`
(`tools/playbook/render_playbook.py#check_one_line_regions`), a value the policy kit cannot import.
The `--line` form, a shipped name and a count, sits well under `MAP_LINE_BYTES`, the cut `run_map`
applies through `render_map_line` to every map line (`tools/playbook/instruction_units.py#run_map`).

figure: both bounds are PINNED constants chosen here, 2026-11-21; neither is measured.

### Migration

Every adopter's charter gains the section at its next render, `kit:policy` surviving only where the
policy kit is selected. A charter rendered before the policy kit's install drops the fence, as the
other kit blocks do. Every charter's map line changes from the pending constant to the verb's line.

### Alternatives rejected

- **The probe reading the policy file itself.** The roles kit's precedent: the kit that owns a file
  stays its one reader, and the probe substitutes its verb's stdout.
- **A diff against the catalogue defaults.** v2 says the keys that differ from the preset; a diff
  against defaults would list every key a strict repository inherits.

## 5. Production-readiness checklist

- security — read-only; the verb prints policy values, none of which is a secret (the catalogue's
  `runtime.secret-home` is a reference, never a value).
- perf / scale — one `read_revision` read per call, about 250 resolutions in process; the render and
  the map each run one subprocess.
- error / empty / loading states — an absent policy file prints `- preset — standard (the default)`
  and `- no key differs`; a refused read exits 2, the probe's miss names it, and the map prints the
  unread line.
- observability — the section is the observation.
- risks — the committed charter goes stale when the policy file changes; the renderer's `--check`
  reds it until re-rendered, which is AC4's red.
- testing — the cases of the acceptance section and the arms in the gates section.
- migration — the Migration sub-head above.
- user docs — `help/policy.md`, S7.

## 6. Acceptance criteria

- **AC1** — When the `preset-diff` case commits `preset = "strict"` with `[hooks]` `bypass =
  "allowed"` and runs `python policy.py preset --diff --rev HEAD`, it prints `- preset — strict` and
  exactly one key line, naming `hooks.bypass`, `allowed` and `strict: refused`.
  Red when: a key the file leaves alone is listed, or the override is missing.
- **AC2** — When the same case runs `python policy.py preset --diff --line --rev HEAD`, it prints one
  line of at most 160 bytes naming `strict` and `1 key(s) differ`; with 13 planted overrides the
  `--section` form prints 12 key lines and a `(+1)` line.
  Red when: the bound is past, or the cut is silent.
- **AC3** — When `python render_playbook.py --target <dir>` renders a fixture adopter with the policy
  and playbook kits installed and the strict override committed, the rendered charter carries the
  `## Policy preset` heading and AC1's two lines inside `kit:policy`.
  Red when: the placeholder is unanswered or the section is absent.
- **AC4** — When that adopter then commits a second override, `leases.expiry-hours = 12`, `python
  render_playbook.py --target <dir> --check` exits non-zero naming the charter; after a write it
  exits 0 and the section lists both keys.
  Red when: a planted override the charter does not show passes the check.
- **AC5** — When `python instruction_units.py map --root <dir>` runs over that adopter, its last line
  before the envelope's close is AC2's `--line` output, and `grep -rn "PRESET_LINE_PENDING\|presets join
  the policy reader"` over `tools/playbook/` and `AGENTS.md` prints nothing.
  Red when: the map and the charter carry different preset lines, or the pending constant survives.
- **AC6** — When `python instruction_units.py fixture --plant map-held` runs, its repository holding
  no commit for the verb to read, the map's last line is `preset — ` and `PRESET_LINE_UNREAD`.
  Red when: a refused read raises out of the map or prints a line naming no verb.
- **AC7** — When `grep -n "preset --diff" policy.md` runs in the help directory, it prints the
  paragraph naming the charter section.
  Red when: the page omits the verb.
