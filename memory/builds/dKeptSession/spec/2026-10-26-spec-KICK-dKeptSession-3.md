## 1. Goal

v2's preset rules have the charter render the preset's name and only the keys that differ from it,
"so a reader sees the posture and its exceptions, not the whole catalogue"
(`memory/builds/dClosedLoop/build/2026-10-14-build-PLAY-dClosedLoop-1-architecture-v2.md@9bf3b4c91952:1419`),
and v2's `[owed]` row gives that render to dKeptSession
(`memory/builds/dClosedLoop/build/2026-10-14-build-PLAY-dClosedLoop-1-architecture-v2.md@9bf3b4c91952:2010`).
The charter has no preset section today, and dOrderedCharter's landed instruction map prints its
preset line from a constant, `PRESET_LINE_PENDING`, until this build
(`tools/playbook/instruction_units.py#render_instruction_map`). This unit adds one policy kit verb
printing the name and the differing keys, renders it into a charter section through
dOrderedCharter's renderer and the playbook kit's one caller of the policy reader, and fills the
map's preset line from the same verb, seen red on a planted override the committed charter does not
show.

## 4. Design

### The section as rendered

```
<!-- kit:policy -->
## Policy preset — the posture and its exceptions

<!-- one-line -->
- preset — strict
- `hooks.bypass` — allowed (strict: refused)
- `leases.expiry-hours` — 12 (strict: 24)
<!-- /one-line -->

<!-- /kit:policy -->
```

Every line is a `- ` bullet because the renderer refuses any other line inside a one-line region
(`tools/playbook/render_playbook.py#check_one_line_regions`). A key differs when the file sets it
and its value is not the preset's: a key the file leaves alone reads the preset's value through
KICK-dKeptSession-2's step, so it never differs. A declared repository preset is its own name here,
and its keys are the assignment the verb compares against. With no preset named, the comparison is
against `standard`, which equals the catalogue defaults, so the section lists the keys the file moves
off its defaults.

### Bounds

`PRESET_DIFF_LINES = 12` and `PRESET_DIFF_LINE_CHARS = 160` in `policy.py` bound `--section`: past
the first, the section names how many keys it cut and the verb that prints them all; the second
keeps each line under the renderer's one-line rule cap, `ONE_LINE_MAX`
(`tools/playbook/render_playbook.py#check_one_line_regions`), a value the policy kit cannot import.
The `--line` form, a shipped name and a count, sits well under `MAP_LINE_BYTES`, the cut `run_map`
applies through `render_map_line` to every map line (`tools/playbook/instruction_units.py#run_map`).

`MAP_PRESET_SECONDS = 3` in `instruction_units.py` bounds the map's read: the replay gives the whole
`map` verb `CARD_MAP_BOUND = 5` and prints `map — skipped` past it, so the read ends with room left
for the interpreter's start and the registry read, and a slow read costs the one line, never the
map. The charter render passes no bound, as `read_policy_value` takes none: a render that cannot read
its section refuses rather than shipping one.

figure: the three bounds are PINNED constants chosen here, 2026-11-21; none is measured, and
`CARD_MAP_BOUND` is PINNED as `skills/session-kickoff/manifest-check.sh` reads at 2026-11-21.

### Alternatives rejected

- **The probe reading the policy file itself.** The roles kit's precedent: the kit that owns a file

## 5. Production-readiness checklist

- security — read-only; the verb prints policy values, none of which is a secret (the catalogue's
  `runtime.secret-home` is a reference, never a value).
