## 1. Goal

v2's preset rules have the charter render the preset's name and only the keys that differ from it,
"so a reader sees the posture and its exceptions, not the whole catalogue" (v2:1417-1420), and v2's
`[owed]` row gives that render to dKeptSession (v2:2010). The charter has no preset section today, and
dOrderedCharter's instruction map holds its preset line as a constant, `PRESET_LINE_PENDING`, until
this build (PLAY-dOrderedCharter-4 S2). This unit adds one policy kit verb printing the name and the
differing keys, renders it into a charter section through dOrderedCharter's renderer, and fills the
map's preset line from the same verb, seen red on a planted override the committed charter does not
show.

## 2. Scope (IN)

- **S1** — The verb `python tools/policy/policy.py preset --diff [--rev <rev>]` (shared interface
  I5): line one `preset — <name>`, `<name>` the file's `preset` or `standard (the default)` when the
  file names none; then one line per presettable key whose resolved value differs from the named
  preset's assignment, `` - `<key>` — <value> (<name>: <preset value>) ``, sorted by key, at most
  `PRESET_DIFF_LINES` lines with a last `` - … (+<k>) — `policy.py preset --diff` `` line past it;
  `- no key differs` when none does. `--line` prints the map's one line instead,
  `preset — <name> · <k> key(s) differ: policy.py preset --diff`. Each value is read through
  `resolve_read` over one `read_revision` read, so the section and `get` cannot disagree. Exit 0, 2
  on a refused read. Observed by AC1 and AC2.
- **S2** — The probe `derive_preset_section` in `tools/playbook/render_playbook.py`, registered in
  `PROBES` as `preset_section`: it runs S1's verb through `resolve_kit_dir('policy', 'policy.py',
  …)` and substitutes its stdout verbatim, the shape `derive_role_roster` keeps; a miss prints its
  cause and returns the empty string, so an unanswered miss refuses at `resolve_placeholder_raw`
  naming the key. Observed by AC3.
- **S3** — The placeholder row `PRESET_SECTION` in `tools/govkit/entries/playbook.kit.toml`,
  `class = "derived"`, `probe = "preset_section"`, `kit = "policy"`, beside `ROLE_ROSTER`. Observed
  by AC3.
- **S4** — The section in `coding-governance-agents.template.md`, fenced `<!-- kit:policy -->`
  after the Agent roles block: `## Policy preset — the posture and its exceptions` over a one-line
  region holding `{{PRESET_SECTION}}`. `AGENTS.md` is its render, rewritten by the renderer and never
  by hand. Observed by AC3 and AC4.
- **S5** — The map's preset line: `render_instruction_map`'s last line reads S1's `--line` output
  through the same probe route, and `PRESET_LINE_PENDING` goes, so the charter's map section and the
  replay carry one preset line. Observed by AC5.
  **Readers:** by name: READER NOT IN TREE — `PRESET_LINE_PENDING` and its one reader,
  `render_instruction_map` in `tools/playbook/instruction_units.py`, are PLAY-dOrderedCharter-4's,
  specced and unbuilt at this spec's base; that unit's AC1 reads the constant's text in the rendered
  map, and its fixture is rewritten here (AC5) · by value: NO VALUE READERS — the line is printed,
  never compared or counted.
- **S6** — The page `help/policy.md` names the verb and the section. Observed by AC6.

## 4. Design

### The section as rendered

```
<!-- kit:policy -->
## Policy preset — the posture and its exceptions

<!-- one-line -->
preset — strict
- `hooks.bypass` — allowed (strict: refused)
- `leases.expiry-hours` — 12 (strict: 24)
<!-- /one-line -->

<!-- /kit:policy -->
```

A key differs when the file sets it and its value is not the preset's. A key the file leaves alone
reads the preset's value through KICK-dKeptSession-2's step, so it never differs. A declared
repository preset is its own name here, and its keys are the assignment the verb compares against.

### Bounds

`PRESET_DIFF_LINES = 12` in `policy.py`: past it the section names how many keys it cut and the verb
that prints them all, so the charter's size caps (`charter size`, `template size <=48KiB`) bound a
repository with many overrides. The `--line` form is held to `MAP_LINE_BYTES` (160) by the cut
`render_instruction_map` already applies to every map line (PLAY-dOrderedCharter-4 §4).

### Migration

Every adopter's charter gains the section at its next render, `kit:policy` surviving only where the
policy kit is selected. A charter rendered before the policy kit's install drops the fence, as the
other kit blocks do.

### Alternatives rejected

- **The probe reading the policy file itself.** The roles kit's precedent: the kit that owns a file
  stays its one reader, and the probe substitutes its verb's stdout.
- **A diff against the catalogue defaults.** v2 says the keys that differ from the preset; a diff
  against defaults would list every key a strict repository inherits.

## 5. Production-readiness checklist

- security — read-only; the verb prints policy values, none of which is a secret (the catalogue's
  `runtime.secret-home` is a reference, never a value).
- perf / scale — one `read_revision` read per render, about 250 resolutions in process.
- error / empty / loading states — an absent policy file prints `preset — standard (the default)`
  and `- no key differs`; a refused read exits 2 and the probe's miss names it.
- observability — the section is the observation.
- risks — the committed charter goes stale when the policy file changes; the renderer's `--check`
  reds it until re-rendered, which is AC4's red.
- testing — the cases of §6 and the arms in §7.
- migration — §4.
- user docs — `help/policy.md`, S6.

## 6. Acceptance criteria

- **AC1** — When the `preset-diff` case commits `preset = "strict"` with `[hooks]` `bypass =
  "allowed"` and runs `python policy.py preset --diff --rev HEAD`, it prints `preset — strict` and
  exactly one key line, naming `hooks.bypass`, `allowed` and `strict: refused`.
  Red when: a key the file leaves alone is listed, or the override is missing.
- **AC2** — When the same case runs `python policy.py preset --diff --line --rev HEAD`, it prints one
  line of at most 160 bytes naming `strict` and `1 key(s) differ`; with 13 planted overrides the
  section form prints 12 key lines and a `(+1)` line.
  Red when: the bound is past, or the cut is silent.
- **AC3** — When `python render_playbook.py --target <dir>` renders a scratch adopter with the policy
  and playbook kits installed and the strict override committed, the rendered charter carries the
  `## Policy preset` heading and AC1's two lines inside `kit:policy`.
  Red when: the placeholder is unanswered or the section is absent.
- **AC4** — When that adopter then commits a second override, `leases.expiry-hours = 12`, `python
  render_playbook.py --target <dir> --check` exits non-zero naming the charter; after a write it
  exits 0 and the section lists both keys.
  Red when: a planted override the charter does not show passes the check.
- **AC5** — When `python instruction_units.py map --root <dir>` runs over that adopter, its last line is AC2's
  `--line` output, and `grep -rn PRESET_LINE_PENDING .` in the playbook kit prints nothing.
  Red when: the map and the charter carry different preset lines, or the pending constant survives.
- **AC6** — When `grep -n "preset --diff" policy.md` runs in the help directory, it prints the
  paragraph naming the charter section.
  Red when: the page omits the verb.
