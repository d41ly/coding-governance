## 1. Goal

Where the harness can message another session, a sender writes the mailbox first and then delivers
live, citing the message (coordination item 7,
`memory/builds/dClosedLoop/build/2026-10-14-build-PLAY-dClosedLoop-1-coordination.md@4a13cbc82a99:122`);
`deps.messaging` picks the channels, and the live message carries only the message's ref and id, so a
lost ring costs only latency (FI-6, the owner's NT-17). This unit gives `--mail post` that tail: one
ring point, called only after the mailbox write has landed, reading `deps.messaging` and ringing each
live channel the harness offers. The harness this repository runs in offers none between sessions
(§8 F1), so today the tail rings nothing and says so, and a registered doorbell joins at the point
dWellOiledMachine declares in Runtime's `[extend]`
(`memory/builds/dClosedLoop/build/2026-10-14-build-PLAY-dClosedLoop-1-architecture-v2.md@9bf3b4c91952:1167`).

## 2. Scope (IN)

- **S1** — The ring point, `run_mail_ring <ref> <id>` in `tools/unattended/unattended.sh`, called by
  `KICK-dKeptSession-5`'s `--mail post` (its S5) once `write_mail_ref` returned 0, after the post's
  `mail — posted <id> · <ref>` line, with the mail ref the message was appended to and the message's
  id, and with nothing else: it reads no field of the record and passes no fact. A post whose write
  was lost or not completed calls it never. Observed by AC2.
- **S2** — `deps.messaging` (`live-and-mailbox`, `live-only`, `mailbox-only`, or a registered doorbell;
  default `live-and-mailbox`; the landed row in `tools/policy/catalogue.toml`, owner dKeptSession), read
  as `read_lease_policy` reads its keys (`tools/unattended/unattended.sh#read_lease_policy`): the
  python `resolve_python` answers, the policy kit `resolve_kit_dir` finds, and its `get
  deps.messaging`, the key spelled whole on its own line. A doorbell name fails `check_value`
  (`tools/policy/policy.py#check_value`) until a registry admits it, so a policy file naming one is
  invalid and reads its last valid revision or refuses. A refusal, a printed value outside the three,
  or no policy kit found reads the catalogue default and prints one `unattended: NOTE` line naming the
  key. Observed by AC1 and AC4.
- **S3** — The ring, by value. Under `mailbox-only` the point rings nothing and the post prints
  `ring — off (deps.messaging: mailbox-only)`. Under `live-and-mailbox` and `live-only` it rings each
  live channel the harness offers, the empty set today (§8 F1), and prints
  `ring — none · no live channel in this harness (stand-in dWellOiledMachine)`. Under every value the
  mailbox was written first: `live-only` never skips it (§8 F2). Observed by AC1 and AC3.
- **S4** — A ring never fails a post. The post's exit is its write's; the ring point's own outcome is
  the `ring —` line alone. Observed by AC2.
- **S5** — The documentation. The `--mail` entry of the verbs guide `tools/unattended/VERBS.template.md`
  (`KICK-dKeptSession-5` S14, beside `--register` and `--card-ref`), rendered to
  `memory/guides/UNATTENDED-VERBS.md`, states the `ring —` line, its three values and the stand-in; the
  `--mail` paragraph `KICK-dKeptSession-5` S14 adds to `help/loop.md` under "Claim keys" gains the same
  sentence. Observed by AC5.

- The driver has no `--mail` verb at base; `KICK-dKeptSession-5` (order 16) lands the post this unit
  extends.

### The tail, in order

1. `--mail post` builds and writes the message (unit 5 S5); on any return but 0 it exits as unit 5 says.
2. On 0 it prints its `mail — posted` line and calls `run_mail_ring <ref> <id>`.
3. The point resolves `deps.messaging` and prints its one `ring —` line.

### Alternatives rejected

- **A same-node ring through a file the other session's hook watches.** The tool-call hook of
  `KICK-dKeptSession-21` already reads the node's local copy, which the post's own write updates, so
  a ring file would be a second copy of what the cache already holds.
- **A ring before the write.** A receiver could fetch before the message exists and find nothing,
  and a lost write would leave a ring for no message.
