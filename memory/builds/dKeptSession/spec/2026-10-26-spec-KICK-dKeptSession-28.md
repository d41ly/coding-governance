## 1. Goal

One grammar for who a mailbox message is for, checked once at the write: a build, one of its units,
a node named by its fleet tag, or the whole project. Today a recipient can only be "a build, or one of
its units" (`coordination.md:107`), so nothing addresses a node or the project (the cloud round's
deciding point 2, `cloud-and-scale.md:109`; P40; the owner's CL-4). The unit ships the grammar's
checker and its matcher; the mailbox that writes and reads messages is KICK-dKeptSession-5's.

## 2. Scope (IN)

- **S1** — The grammar (I14), four forms and nothing else: `build:<slug>`, `unit:<id>`, `node:<fleet
  tag>` and the bare word `project`. Observed by AC1.
- **S2** — The checker, `check_mail_recipient <to>` in `tools/unattended/unattended.sh`: rc 0 on a legal
  recipient, rc 2 with one `mail — refused · recipient <to>: <why>` line on stderr otherwise.
  `build:<slug>` passes `check_slug_shape` (`tools/unattended/unattended.sh:2890`); `unit:<id>` is
  `<FAMILY>-<slug>-<n>`, the family upper-case letters, `<n>` digits and the slug passing
  `check_slug_shape`, the driver's own id spelling (`:3796`, `:4620`); `node:<tag>` is a tag the fleet
  registry holds (S3); and any other text, an empty one included, is refused naming the four forms.
  Observed by AC1, AC2.
- **S3** — The fleet's tags: `python tools/playbook/render_playbook.py --fleet-tags` prints every tag of
  `read_fleet` (`tools/playbook/render_playbook.py:347`), one per line, sorted, the playbook kit's one
  fleet reader; its refusal exits 2 with `read_fleet`'s message. `check_mail_recipient` runs it once per
  process through the playbook kit's resolved path and refuses `node:<tag>` when the tag is absent or
  the flag exits non-zero, naming `fleet.toml`. Observed by AC2, AC3.
- **S4** — The matcher, `check_mail_addressed <to> <who>` in the same file, `<who>` itself a legal
  recipient: rc 0 when `<to>` equals `<who>`, or when `<who>` is `build:<slug>` and `<to>` is a `unit:`
  id whose slug segment is `<slug>`; rc 1 otherwise. Every reader decides "addressed to me" by this one
  predicate, asking once per recipient it answers for. Observed by AC4.
- **S5** — The documentation: the verbs guide's mailbox section (KICK-dKeptSession-5's) states the four
  forms; this unit writes the grammar paragraph it points at in `tools/unattended/VERBS.template.md`.
  Observed by AC5.

## 3. Non-goals (OUT)

- No message writer, reader or ref: KICK-dKeptSession-5 calls `check_mail_recipient` at the write and
  `check_mail_addressed` in its reader.
- No routing of a `project` message to a node, and no offer or claim of one: a project-level request
  any node claims by lease is dPlacedRequest's (cloud-and-scale.md:244-246).
- No resolution of this node's own tag: TOOL-dPlacedRequest-1 S11's `resolve_fleet_tag` answers "which
  tag am I", and this unit answers "is this a tag of the fleet".
- No gate on a transition from a `node:` or `project` message: which recipients gate a build's
  transition is KICK-dKeptSession-5's (its §8).

  registry (`tools/playbook/render_playbook.py:347-378`); `tools/playbook/fleet.toml` holds the rows.

  S11 calls "the playbook kit's one fleet reader".

## 5. Production-readiness checklist

- security — the recipient is validated at the write, once, against a closed grammar; a node tag
  must be the fleet's.
- perf / scale — one Python call per process for the tag list, only when a `node:` recipient appears.
- error / empty / loading states — an empty or unknown form is refused naming the four; an unreadable
  fleet registry refuses `node:` naming `fleet.toml`.
- observability — every refusal is one `mail — refused · recipient` line naming the cause.
- risks — a node removed from `fleet.toml` leaves earlier `node:` messages addressed to nobody; the
  matcher still matches them by tag.
- testing — the fixture cases under AC1 to AC4 and the suite arm in §7.
- migration — none: no message exists yet.
- user docs — the verbs guide; no page under `help/` describes the driver's verbs.

- **AC3** — When `python render_playbook.py --fleet-tags` runs, it prints the tags of `fleet.toml` one
  per line in order and exits 0; over a scratch copy of the registry with a duplicate tag it exits 2

  Red when: a tag is missing, or a malformed registry prints tags.
- **AC4** — When `check_mail_addressed` runs with `<who>` `build:fx`, it returns 0 for `build:fx` and

  returns 0 for `node:a` only, and with `project` for `project` only.

- **AC5** — When `grep -n "node:<fleet tag>" tools/unattended/VERBS.template.md` runs, the guide names
