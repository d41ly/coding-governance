## 4. Design

### The walker

```python
def scan_unfenced(text: str, unclosed: list | None = None):
    """(line number, line) for every line of Markdown `text` outside a fence, through memory-tree's one fence
    reader; the line an unclosed fence opens at goes to `unclosed`, a caller that does not ask reading on."""
    tree_lib, _ = load_memory_tree()
    for n, line in tree_lib.unfenced_lines("\n".join(text.splitlines())):
        if line is not None:
            yield n, line
        elif unclosed is not None:
            unclosed.append(n)
```

`unfenced_lines` splits on a newline, and this walker has always numbered by `str.splitlines`, as `extract_doc`'s
own `lines` does. Joining the `splitlines` result keeps every line number and value, a form feed and a CRLF included,
and the two opening and closing rules agree: a marker closes only the fence it opened. This writer ran both walkers
over the 10,458 tracked `.md` files at `62c5f0c5c` (PINNED). They disagree on 10 files, all empty files under
`tools/roles/house/`, where the new walk yields one empty line, `(1, "")`. Every caller treats an empty line as
nothing, so no row moves. The same run found one unclosed fence, the record the non-goals name.

The `(opened_at, None)` sentinel is the shape `tools/memory-tree/design_lib.py` and `tools/playbook/edge_grammar.py`
already refuse on. Those refuse a whole document. This one reports and reads on, because the rows above the
fence are real.

### The row and the check

`extract_citations` passes a list to `scan_unfenced` and, after its loop, appends `("", "unclosed", n, n, "")`
for each entry. `_write_path_rows` writes that row as it writes a `span`, so a dirty file and a blob of another tree
are served by the same view.

```python
def check_unclosed(con, ctx) -> tuple[list, list]:
    """The view's `unclosed` rows: red outside `<MEMORY_ROOT>/builds/`, printed under it (PLAY-dOrderedCharter-68)."""
    frozen, reds, lines = f"{ctx['memory_root']}/builds/", [], []
    for _tag, path, line, *_ in read_rows(con, ("unclosed",)):
        if path.startswith(frozen):
            lines.append(f"tags: unclosed fence, frozen record, printed · {path}:{line}")
        else:
            reds.append(f"tags: {path}:{line} · unclosed fence · it opens here and never closes, so every "
                        f"later line goes unread")
    return reds, lines
```

`run_check` calls it beside `check_resolves`, adding to `reds` and to `p_lines`. `DEFINE_KINDS` does not hold the
kind, so nothing resolves to the row.
