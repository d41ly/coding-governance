## 1. Goal

The charter says what each tool answers and never how an agent starts or advances the loop for its
role, so every agent re-derives that from many files (gap-found-05). This unit gives each kit's
descriptor a drive table, composes the charter's drive section from the adopted kits' rows alone,
checks the two both ways, repeats each subagent's role line in its handoff, and holds the rendered
charter inside the smallest harness's limit, 32 KiB, against the caps it has today (foundations R3, R6,
F1-6, F1-7; v2:961-965 P15).

## 2. Scope (IN)

- **S1** — The drive table, S17: `[[drive]]` rows in a kit's `kit.toml`, each with `stage`, `role`,
  `command` and `when`. `stage` names a workflow of the roles kit's `tools/roles/workflows.toml`
  (`orient`, `reuse`, `spec-write`, …) or `start`, for how a session starts by situation; `role` is a
  role slot such as `gov-builder`, or `main` for the main session; `command` is the CLI command, in
  backticks when rendered; `when` is the situation, one clause. Observed by AC1.
- **S2** — The seeded rows, in the descriptors of the kits that start or advance a stage:
  `kickoff-manifest`, `roles`, `unattended`, `review-harness`, `run-gates`, `push-main`, `memory-tree`,
  `codebase-map` and `memory-recall`. Each role the roles kit renders has at least one row (F1-7 "One
  line per role"), and the `start` rows cover a new task from the owner, a resumed session, an
  unattended run, a subagent's task and another harness without gov's hooks (foundations R3). Observed
  by AC1 and AC3.
- **S3** — The composition. The template gains a `## Drive — how to start and advance the loop` section
  holding one `{{DRIVE}}` line in a one-line region, and `render()`
  (`tools/playbook/render_playbook.py:979`) expands it, before it collects placeholders, into one
  `- ` line per row of the selected kits, `start` rows first, then by the workflow's `stage` integer,
  then kit and row order. A kit the target did not select contributes nothing. The renderer finds each
  selected kit's descriptor through the registry's `descriptor` path: in gov, under the tool root, as
  `resolve_declaration_paths` (`render_playbook.py:743`) finds its own; in an adopter, a dir kit's own
  installed `kit.toml`, and a flat entry's descriptor shipped beside the engine by a `root_relative`
  `[[files]]` rule in `tools/playbook/kit.toml`, the rule that already ships `playbook.kit.toml`.
  Observed by AC2.
- **S4** — The check both ways, `python tools/playbook/instruction_units.py drive --check`: each row's
  `stage` names a workflow or `start`, its `role` a rendered role or `main`, and its four fields are
  non-empty; every role of `tools/roles/workflows.toml`'s `roles` lists has a row; every line between
  the drive region's markers in the rendered charter is a selected kit's row; every selected kit's row
  is a line there. Each failure names the kit and the row. Observed by AC3 and AC4.
- **S5** — The role line in the handoff. `render_handoff` (`tools/roles/handoff.py:312`) adds the
  role's drive lines under a `### Drive` heading at the end of the `## Role` section, from the same
  rows, so a subagent holds its role's line as the main session does. Observed by AC5.
- **S6** — The charter inside 32 KiB. `tools/check-template-size.sh` gains a check: when its subject
  is the rendered charter, `AGENTS.md`, a declared row above the smallest harness's limit is refused,

  typed in the gate. The rendered charter is measured at this unit against its two caps in

- **S7** — The raise rule, as the clause states it. The header of `tools/template-size-limits.txt`
  gains one sentence: once a row moves under `budgets.*`, a run's raise goes through the one write
  shape dGroundRules' minimal guard admits until dDeclaredLoop's guard lands, argued in that write's

## 4. Design

### Data model

```toml
[[drive]]
stage = "start"
role = "main"
command = "/session-kickoff"
when = "a new task from the owner"

[[drive]]
stage = "build"
role = "gov-builder"
command = "python <prefix>/roles/handoff.py render --role builder"
when = "a unit whose spec is READY"
```

Rendered: ``- build · gov-builder — a unit whose spec is READY: `python <prefix>/roles/handoff.py render --role builder` ``,
one line each, under the one-line cap.

### Inventory

Minted: the `[[drive]]` row and its four fields; the stage value `start`; the role value `main`;
the template section `## Drive — how to start and advance the loop`; the placeholder `DRIVE`; the CLI verb
