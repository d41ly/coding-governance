## 1. Goal

The harness's auto-memory index loads into every session under instruction framing, and its
feedback entries carry standing directives; nothing measures it, nothing detects those directives,
and nothing promotes one into the instruction layer (`gap-found-14`). Gov never renders the index,
since the harness writes and injects it from outside the repository, so it "can only be measured at
session start and its directives detected" (the gap's own words). This unit adds that measurement
as a card cell, the detector behind it, and a promotion verb that turns a standing directive into an
instruction unit through PLAY-dOrderedCharter-15's command, so memory sits at level 7 as evidence
and instructs only by promotion (layer-instruction R-H).

## 4. Design

### Locating the index

`resolve_auto_memory_dir(root, declared)` is drift-audit's function unchanged in behaviour: `~` is
the home directory and `{checkout}` the primary checkout's path, the parent of the git common dir,
with every character outside `[A-Za-z0-9-]` turned into `-`. It becomes a canonical copy because the
core may not import an expansion (`cl-dClosedLoop-0046`), and every copy-installed kit carries a
shared primitive inline (the charter's Kinds fact). The core passes `AUTO_MEMORY_TEMPLATE`;
drift-audit keeps passing its project layer's own declaration
(`tools/drift-audit/drift_signals.py:476`), which answers a different question: which directory that
project audits.

### Measuring and detecting

`measure_index(root)` reads `<dir>/MEMORY.md`. Bytes are its byte length; lines its line count. The
budget is `memory.load-budget`, a key dTotalRecall owns (v2's `[policies]`, `memory.load-budget`,
values `4k, 8k, 16k`, default `8k`), read through dGroundRules' one reader once both have landed and
until then the catalogue default, held as `LOAD_BUDGET_DEFAULT = 8192` with that hand-over in its
comment. `scan_directives(root)` walks the index's markdown links (a `[<title>]` label, then its `<file>.md` target in parentheses), opens each
file under the memory directory only (a link resolving outside it is skipped and counted), and reads
its front matter: `type: feedback`, at column 0 or indented under `metadata:`, marks a directive; a
`promoted-to:` line marks it promoted. The detector states in its docstring what it does not read:
prose directives inside `project` or `reference` entries, and index lines with no link.

`main measure` prints one line, never more than 200 bytes:

```
memory — MEMORY.md 19830 B over its 8192 B budget (memory.load-budget default) · 110 lines · 54 standing directives unpromoted · list: memory_index.py directives
```

Under budget it reads `within its <n> B budget`. No directory prints `memory — skipped: no
auto-memory index at <dir>`, and an unreadable index the same with its error. The figures in the
sample are PINNED, measured on gov's node on 2026-10-23 (19,830 bytes, 110 lines, 54 of 109 entries
`type: feedback`); every run DERIVES its own.

### The card cell

`derive_memory_line` in `manifest-check.sh` sits after `live —` and before `claims —` in
`render_card` (`skills/session-kickoff/manifest-check.sh:517-546`). It follows `derive_overlaps_line`
(`:555-589`): `resolve_kit_file playbook memory_index.py` (`:854`), a working `timeout -k`, the call
bounded by `CARD_MEMORY_BOUND` (default 5) into a scratch file under `$CARD_DIR`, its first line
printed on exit 0 and a `memory — skipped: <why>` line otherwise. The card stays inside
`CARD_CAP_BYTES` (`:216`), since the line is bounded.

### Promotion

`promote <name> --level <n> --tag <tag>`:

1. refuses a name no detected directive carries, a `--level` outside `LEVELS`, a level the
   repository cannot write (1, 6 and 7, the adopter-instructions record's item 3), and a tag the
   tag grammar (S4) refuses;
2. composes one S10 row: `tag`, `level`, `type = "directive"`, `text` from the entry's `description`
   cut at 200 B, its origin left for the overlay's reader to derive, and the change record's
   `Promoted-from` value `auto-memory <name>` (PLAY-dOrderedCharter-15's S7 field);
3. calls `python tools/playbook/instructions_edit.py add --manifest overlay` with that row and prints
   its answer verbatim, which under `owner-command-agents-propose` without the owner's proof is the
   proposal and no write;
4. on exit 0 only, inserts `promoted-to: <tag>` into the entry's front matter; on any other exit
   writes nothing and exits with the command's status.

At this build every write through that command is refused until dDeclaredLoop's guard lands
(`cl-dClosedLoop-0045`), so step 4 is reached only once the guard admits the owner's write.
