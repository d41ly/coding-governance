## 1. Goal

A project map can only say what a node is for where the node's purpose is declared, and today a tag
namespace and a chain build declare none: a chain build has its stage word only (project-map
`[purpose]`). This unit makes the namespace registry's `purpose-source` and `owner` fields graded,
every namespace row naming where its members' purposes are read and the chain build that owns it, and
lands the chain registry, one row per chain build with a `purpose` field. A new row must declare its
purpose; the existing chain builds are left for dTotalRecall's PM-5 unit, which reads
`memory.map-purpose` and reviews them (H1; the project map's `[cross]` Tags and `[purpose]`).

## 2. Scope (IN)

- **S1** — The `owner` check over `tools/playbook/namespaces.toml`: every `[[namespace]]` row's
  `owner` names exactly one chain build of the chain registry (S3), so a namespace with no owner, or
  an owner no registry row holds, is red naming the row. Observed by AC1.
- **S2** — The `purpose-source` check: every row's `purpose-source` is `<path>` or `<path>#<field>`,
  the path tracked, and the field, where named, present on every member row the namespace's extractor
  yields; a row with none, a path that does not resolve or a member lacking the field is red naming
  the row. The values this build's ten rows carry are §4 "### The ten purpose sources". Observed by
  AC2.
- **S3** — The chain registry, `memory/project/chain.toml`: one `[[build]]` row per chain build with
  `slug` and `purpose`. Its slugs are joined both ways with the builds of the design view, read by
  `read_design_view` (`tools/memory-tree/design_lib.py:182`) through the `DESIGN_VIEW` key, so a
  registry row naming no chain build and a chain build with no row are each red. Observed by AC3.
- **S4** — The purpose rule. A registry row whose build is a row of v2's `[chain]` at the design
  baseline, read by `read_chain_clauses` (`tools/memory-tree/design_lib.py:254`), may carry no
  `purpose` and is printed as awaiting PM-5's review; every other row must carry a non-empty one.
  The awaiting set is the registry's own rows, never a second list. Observed by AC4.
- **S5** — The arm in `gov_tag.py check`, named `purpose`, running S1 to S4, and a fixture plant for
  each red. Under an adopter's conf, where the `DESIGN_*` keys are blank, the chain half prints one
  line saying it has no chain to read and the namespace half still runs. Observed by AC1 to AC5.

  Red when: a namespace with no owner, or a fictitious one, passes.
- **AC2** — When `--plant no-purpose-source`, `--plant bad-purpose-source` and `--plant member-no-field`
  run, each exits 1 naming the row and, for the third, the member.
  Red when: a namespace's purpose source is absent, unresolvable, or missing on a member.
- **AC3** — When `--plant registry-ghost` and `--plant registry-missing` run, a registry row naming no
  view build and a view build with no row each exit 1 naming the slug; and
  `python gov_tag.py check` on the tree prints the `purpose` arm with 22 registry rows
  joined to 22 view builds.
  Red when: the registry and the view disagree silently.
  figure: 22 is PINNED, measured 2026-10-23 over the as-built view at `ce13efbe`.
- **AC4** — When `--plant new-no-purpose` runs, a registry row for a build no baseline `[chain]` row
  names, with no purpose, exits 1; the same row with a purpose exits 0; and the tree's run prints 22
  rows awaiting PM-5's review.
  Red when: a new node passes with no purpose, or an existing one is refused before its review.
- **AC5** — When a scratch copy blanks the four `DESIGN_*` keys in `.memory-tree.conf` and runs
  `python gov_tag.py check`, the `purpose` arm prints its no-chain line and still
  grades the namespace rows' `owner` against the registry rows it can read.
