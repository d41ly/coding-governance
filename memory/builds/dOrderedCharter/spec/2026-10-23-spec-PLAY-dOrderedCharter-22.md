## 1. Goal

A project map can only say what a node is for where the node's purpose is declared, and today a tag
namespace and a chain build declare none: a chain build has its stage word only (project-map
`[purpose]`). This unit makes the namespace registry's `purpose-source` and `owner` fields graded,
every namespace row naming where its members' purposes are read, printed pending until that source
lands, and the chain build that owns it, and lands the chain registry, one row per chain build with
a `purpose` field. A new row must declare its purpose; the existing chain builds are left for dTotalRecall's PM-5 unit, which reads
`memory.map-purpose` and reviews them (H1; the project map's `[cross]` Tags and `[purpose]`).

## 2. Scope (IN)

- **S1** — The `owner` check over `tools/playbook/namespaces.toml`: every `[[namespace]]` row's
  `owner` names exactly one chain build of the chain registry (S3), so an owner no registry row holds
  is red naming the row; a row with no owner is already refused, exit 2, by unit 19's
  `read_namespaces` (`tools/playbook/tag_index.py:120-122`). Observed by AC1.
- **S2** — The `purpose-source` check, over a namespace's members: the `#`-free defining rows the
  view serves for it from its own extractor (`read_rows`, `tools/playbook/tag_index.py:678`). A row's
  `purpose-source` takes one of three forms:

  | Form | Graded, once its source is in the view |
  |---|---|
  | `<path>` | the path is tracked; nothing per member, printed as `path-only` |
  | `<path>#<field>` | every member the extractor yields at the path carries the field: a non-empty string key of its TOML row (`.toml`), or a top-level assignment of that name (`.py`); any other suffix is red, the arm reading no field in it |
  | `#<field>` | each member's own file carries the field: its TOML row's key, or `h1` for a Markdown member, the file's first `# ` line outside a fence (`scan_unfenced`, `tag_index.py:191`) |

  **Pending.** A row is `pending` while its source is not in the view: a `<path>` or `<path>#<field>`
  path not served, or a `#<field>` namespace with no member. A pending row is printed with its source
  and counted, never graded, the shape of S4's awaiting-review print; the unit that lands each source
  is §4's table, never a typed key (§8 F3). A row with no `purpose-source` is refused, exit 2, as S1
  says of `owner`. Red, naming the row: a member lacking the field; a field in a file of another suffix; a `<path>#<field>` path holding none of a
  namespace's members while it has some. So the pass that lands a source grades its row with no edit
  of the registry, and reds there if the source lacks the field. The ten rows' values are §4 "### The
  ten purpose sources". Observed by AC2 and AC6.
- **S3** — The chain registry, `memory/project/chain.toml`: one `[[build]]` row per chain build with
  `slug` and `purpose`. Its slugs are joined both ways with the builds of the design view, read by
  `read_design_view` (`tools/memory-tree/design_lib.py:186`) through the `DESIGN_VIEW` key, so a
  registry row naming no chain build and a chain build with no row are each red. Observed by AC3.
- **S4** — The purpose rule. A registry row whose build is a row of v2's `[chain]` at the design
  baseline, read by `read_chain_clauses` (`tools/memory-tree/design_lib.py:258`), may carry no
  `purpose` and is printed as awaiting PM-5's review; every other row must carry a non-empty one.
  The awaiting set is the registry's own rows, never a second list. Observed by AC4.
- **S5** — The arm in `gov_tag.py check`, named `purpose`, running S1 to S4, and a fixture plant for
  each red. Under an adopter's conf, where the `DESIGN_*` keys are blank, the chain half prints one
  line saying it has no chain to read and the namespace half still runs. The base fixture's rows
  (`FIXTURE_REGISTRY` and `FIXTURE_UNIT_ROW`, `tools/playbook/gov_tag.py:206-246`, and
  `derive_fixture_row`, `:281`), today `purpose-source = "fixture"`, carry `AGENTS.md`, a path every
  fixture tracks, and the fixture holds a chain registry with one row, `fixture`, with a purpose, so
  the plants units 19, 10 and 44 landed keep their exits. Observed by AC1 to AC6.
