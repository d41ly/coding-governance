## 1. Goal

The template-conformance check of `tools/memory-tree/check-memory-hygiene.sh` passes a revision entry
numbered rev-2 or higher only when the entry holds the section sign followed by a digit, or a whole
`S<n>` or `AC<n>` id. That is the `rs_has` predicate in the arm under the `TOOL-aJoinedCanon-1`
rev-scope comment. Unit 26's positional check grades the section-sign form, and unit 53's per-line
rule will red each such line added after that check landed. So an entry that moved only sections, with
no scope or acceptance id, cannot satisfy both gates. Spec 4's rev-4 entry hit this and holds the
section-sign form for now.

This unit adds one disjunct to `rs_has`: a section named in words, `section <n>`, matched in any
case, `<n>` a digit run. In the same pass it rewrites spec 4's rev-4 entry into words. It lands before
unit 53, so unit 53's rule never meets an entry that has no legal form.

## 4. Design

### The predicate

The arm's existing line in `tools/memory-tree/check-memory-hygiene.sh` assigns `rs_has` as the
section-sign disjunct OR the scope-id disjunct. The builder appends one more disjunct to that same
assignment, inside the same expression:

```awk
|| (tolower(rs_E) ~ /(^|[^a-z0-9])section[[:space:]]+[0-9]/)
```

- `tolower` makes `Section 7` and `SECTION 7` count. It is POSIX awk and works on gawk and on a
  byte-oriented awk alike, which the arm's comment requires of the section-sign half.
- `[[:space:]]+` admits a wrap between the word and the digit. The entry text joins a continuation
  line with one space plus that line's own indentation, so a single-space class would miss it. The
  same awk program already uses `[[:space:]]` in its terminal-status range walk.
- The left boundary mirrors the scope-id disjunct's `(^|[^A-Za-z0-9])`, so a word ending in `section`
  does not count.
- The digit is required, so `section` alone and `sections` name nothing.

The sentence added to the comment block above the arm, placed after the sentence explaining the
section-sign half, reads in substance: the words half lowers the entry and needs the word, whitespace,
then a digit, so a capitalised word and a wrap between the two count and the plural alone does not.
The whole awk program is one single-quoted shell string, so the sentence carries no apostrophe.

### The statements

Each S2 file inserts the words form into the token list it already writes, for example
`` a `§<n>`, `section <n>`, `S<n>` or `AC<n>` token ``. The section-sign token there is followed by
`<`, not a digit, so it is no section reference.

- `SPEC-TEMPLATE.template.md` and `memory/TEMPLATE-SPEC.md` also gain one sentence after the
  `<scope>` paragraph: the words form `section <n>` matches in any case, `<n>` a digit run, and may
  wrap between the word and the number; the word alone, or `sections`, names nothing.
- `HYGIENE.template.md` and `memory/HYGIENE.md`: the edited line opens with the revision log named by
  a section-sign reference, which becomes "Every revision-log entry".
- `.memory-tree.conf.example` and `.memory-tree.conf`: the token list sits on one comment line in
  each. The builder rewraps from that line forward to the paragraph's end, never the line above, so
  the line carrying the hygiene check number and the section-sign reference above it stays untouched.
- The `REV_SCOPE_CUTOFF=""` default's trailing comment in `check-memory-hygiene.sh` names the
  section-sign token list and the check number. It becomes "every rev-2+ revision-log entry must name
  a section, scope id or acceptance id (the template-conformance check); blank = never required". It
  states no token list, so it points at the template rather than restating it.

A paragraph that overflows is rewrapped to its existing width, and the rule of S2 binds every line
the rewrap touches.

### Alternatives rejected

- **The plural, `sections? <n>`.** The brief names the singular form, and spec 4's rewrite writes
  `section 4 ... section 7 · section 10`, one word per number. A plural opens a list grammar, as in
  `sections 4-7` or `sections 4 and 7`, that the arm would read as presence only. That costs nothing
  today and nothing in the tree asks for it.
- **The words reader of TOOL-dFairHearing-4**, which reads `section <n>` from a review finding's
  address. That spec is DEFERRED and unbuilt, and its reader is JavaScript in the workflows harness.
  The rev-scope arm is one awk program, so no shared code can serve both.
- **Giving spec 4's rev-4 entry an S or AC id instead.** The entry moved sections, not a scope item or
  a criterion, so an id would name something the fold did not move.
- **A waiver for spec 4's line in unit 53's population.** It cures one instance; the next
  sections-only revision meets the same two gates.
