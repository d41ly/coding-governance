## 1. Goal

Orienting on one feature, `roles`, took about 42 calls and 734 KB read whole (night pass, point 4). With one
grammar, one index and one resolver in place (unit 19) and one closed edge set declared at its sites (units 24
and 28), `gov tag bundle <tag>` answers that in one call: the node, then every inbound edge grouped by type,
each row a range to pull, folded past `tags.bundle-rows` and, by flag as `tags.bundle` allows, with content
inlined under the byte budget the call names (NP-14). Two checks keep the edges a bundle walks honest: every
edge's type is registered, and every target resolves, each seen red.

## 2. Scope (IN)

- **S1** — The verb. `python tools/playbook/gov_tag.py bundle <address>` (S5) resolves `<address>` through
  unit 19's resolver, then prints the node first and every inbound edge, grouped by edge type in the
  registry's order (`tools/playbook/edges.toml`). The typed rows are the declared edges
  `edge_grammar.read_tree_edges` returns (`tools/playbook/edge_grammar.py:560`) whose target
  `resolve_edge` (`:493`) resolves to the node, each read as the `(target, inverse, source)` triple
  `derive_inverse_edges` (`:672`) derives. The `cites` rows are the span citations `gov tag refs`
  returns (`tools/playbook/gov_tag.py:98-106`), which carry `path` and `line` and no type. Each row is one range,
  its text form `path:span · type · bytes`, `span` the extent the index holds for the source node or the
  whole file where it holds none, and `bytes` the size of that range. The three named sections are views
  of the rows: members are the `part-of` rows, instructions the `instructs` rows, and regions every row
  that carries a span. Observed by AC1.
- **S2** — The fold. Past `tags.bundle-rows` rows (`20`, `40` or `80`, default `40`), rows fold by their
  source's kit directory (`tools/<kit>/`, else the path's first segment), the group with the most rows
  first, one group at a time, until the count is within the budget; a fold row reads
  `<dir>/ · type · <n> rows · bytes` and `--under <dir>` lists that group's rows unfolded. A bundle still
  over budget after every group folds prints as folded with a line saying so, never cut. Observed by AC2
  and AC3.
- **S3** — Inline content. `--inline --bytes <n>` inlines each row's content in manifest order while the
  running total stays within `<n>`; the first row that would pass it, and every row after, stays a manifest
  row. No content is truncated mid-range. Observed by AC4.
- **S4** — `tags.bundle`. `manifest` refuses `--inline`, exit 2, naming the key; `inline` inlines every
  call and refuses one without `--bytes`, naming the missing budget; `both`, the default, prints the
  manifest and inlines on `--inline`. Both keys are read through `read_policy_value` in unit 19's `tools/playbook/policy_value.py`, as
  `read_policy_value("tags.bundle", root)` and `read_policy_value("tags.bundle-rows", root)`, the key
  literal first, the shape dGroundRules' reader-coverage arm counts: each is `root`'s committed policy
  at its landed revision, an unset key its catalogue default, `both` and `40` (v2:1353-1354). A
  `PolicyRefused`, an exit 2 from `policy.py get`, refuses the call with exit 2 naming the key. Observed by AC5 and AC3.
- **S5** — The type-registered arm. `python tools/playbook/gov_tag.py check --only type-registered` prints
  every red unit 24's `check_edges` (`edge_grammar.py:396`) returns over the edges `read_tree_edges`
  reads, an edge whose type is no row of `tools/playbook/edges.toml` among them, naming the declaring site
  and the type, and exits 1 on any. `cites` is derived, so a declared `cites` is red (`:412-413`, plant
  `declared-cites` at `:733`), unit 24 S4's rule. Observed by AC6.
- **S6** — The target-resolves arm. `python tools/playbook/gov_tag.py check --only target-resolves` prints
  every red unit 28's `run_resolve` (`:537`) returns over the same edges, naming the site, the type and
  the target, and exits 1 on any; each address form resolves by unit 28's `resolve_edge`. Both arms call
  the two functions and never re-derive them, and run only when `--only` names them, so
  `gov_tag.py check` keeps unit 19's verdict and no edge red prints twice. Observed by AC7.
- **S7** — Empty sections. A section with no rows renders one of S20's slot states: `searched-empty` when
  its population exists and holds nothing for this tag, and `not-installed: <fallback>` when no extractor
  feeds it, the regions section naming dTotalRecall's span extractors and the whole-file range as its
  fallback. Observed by AC8.
- **S8** — The leg and plants. The tree is graded by unit 28's `edges (every declared edge parses, is
  registered and resolves)` leg, in the `tags` pack, which runs the same two functions (its plants

## 4. Design

### Data model

```
bundle  := node-row  ( type-header  row* )*
row     := <path>:<span> · <type> · <bytes>          span := <first>-<last> | whole
fold    := <dir>/ · <type> · <n> rows · <bytes>
```

The bundle is assembled from existing reads, never a query path of its own: `show <address>` for the
node, `refs <address>` for the `cites` rows, and `read_tree_edges`, `resolve_edge` and
`derive_inverse_edges` for the typed rows. The output is text, every line opening `tags:` as unit 19's
verbs print, or JSON with `--json`, the row fields `path`, `span`, `type` and `bytes`.

### Inventory

Minted: the verb `bundle` with the flags `--inline`, `--bytes` and `--under`; the `check` flag `--only <arm>` and its arms
`type-registered` and `target-resolves`; the module `tools/playbook/tag_bundle.py`; the `bundle-*` fixture cases; the leg `tags bundle selftest`. No conf key; the two policy keys are this unit's owned nodes, their rows filled and never added.

### Migration

None. The checks run over the edges units 24 and 28 declared, which are clean at their landing.

### Rollout

Live at landing, at order 10, after units 19 (order 4), 24 (order 7) and 28 (order 8), and after unit 50,
which shares order 10 and ships `tools/run-gates/owed_rows.py`, the probe §3 says this pass runs (unit
50 §4 Order).

### Alternatives rejected

- **Content always inlined.** NP-14's `manifest` and `both` options exist because a feature's bundle runs
  about 44 rows; the owner chose `both`.
- **Cutting rows past the row budget.** A cut row is unreachable; a fold row with `--under` keeps every row
  one call away.
- **Truncating the range that crosses the byte budget.** A half range reads as the whole; it stays a
  manifest row instead.
