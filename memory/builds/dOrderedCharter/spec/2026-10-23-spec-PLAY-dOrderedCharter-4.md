## 1. Goal

After a `compact` or a `resume`, an agent today gets back its stored orientation card and one `now —`
line, and nothing that tells it which instruction outranks which (`gap-found-01`: "nothing restores
their order after a context reset"). This unit makes the existing replay hook print the instruction
map first: the ladder's levels, the documents at each and when they load, and the active policy
preset, inside the charter's level-0 envelope, so a reset agent can rebuild the hierarchy before it
acts (foundations R2, "Re-derivation after a reset"). The map is the one PLAY-dOrderedCharter-2
renders into the charter; the replay prints the same function's output, through the replay fragment
that already fires on `resume|compact`, and adds no third SessionStart entry.

## 4. Design

### The verb

```
[AGENTS.md · Level 0 · the instruction map: rebuild the hierarchy from it before acting]
<render_instruction_map's lines, one per level 0 to 7>
preset — none: presets join the policy reader at dKeptSession; each key reads its file value, else its catalogue default
[/AGENTS.md]
```

- The two envelope lines are `render_envelope`'s, called with the charter row's path and level as
  `read_document_registry` returns them; the module types no envelope.
- The level lines are `render_instruction_map`'s unchanged, except the cut below.
- `MAP_LINE_BYTES = 160`: a longer level line is cut at a character boundary and ends `… (+<k>)`,
  `<k>` the documents the cut dropped.
- `MAP_CAP_BYTES = 1792`: a map past it exits 2 printing one `instruction-map: <bytes> over
  MAP_CAP_BYTES` line and no map, because every field is bounded and an overflow means a derivation
  went wrong, the rule `write_card` keeps (`skills/session-kickoff/manifest-check.sh:703-718`).
- `--root <dir>` (default: the git toplevel of the working directory) names the tree whose
  registry is read. The verb exits 0 with the map, 2 on a refusal, never 1: it is a renderer.

### The preset line

`render_instruction_map` appends `preset — <value>` as its last line. Until dKeptSession adds presets
to dGroundRules' reader (`cl-dClosedLoop-0009`), the value is the constant above, held once as
`PRESET_LINE_PENDING` with that hand-over in its comment. The charter's own map section, which calls
the same function, carries the line too, so the two never differ.

### The replay

`print_replay` (`skills/session-kickoff/manifest-check.sh:721-725`) becomes: `derive_map_block`, then
the stored card (or `write_card replay`), then the `now —` line. The map goes first so the harness's
10,000-character cap on a hook's output (measured in the preserve research, section 3) cuts a
card's tail, never the level-0 map.

`derive_map_block` follows `derive_overlaps_line` (`:555-589`) rung for rung:

1. `resolve_kit_file playbook instruction_units.py` (`:854-866`) empty → `map — skipped: no playbook
   instruction map resolves in this tree`.
2. `resolve_python` empty → `map — skipped: no Python resolves on this node`.
3. No working `timeout -k` → the same `skipped:` form the overlaps cell prints.
4. The call runs under `timeout -k 2 "$CARD_MAP_BOUND"` with stdin `/dev/null`, stdout into a
   scratch file under `$CARD_DIR`, never a `$( )` capture. `CARD_MAP_BOUND` defaults to 5.
5. Exit 0 → the file's lines print verbatim, CRs dropped. Exit 124 or 137 → `map — skipped: the map
   did not answer within <n>s`. Any other exit → `map — skipped: <its first non-empty line, cut at
   160 B>`.

The function never changes the replay's exit status, never writes the card file, and removes its
scratch file on every path.

### Inventory

New: the verb `map` and its flag `--root` on `tools/playbook/instruction_units.py`; the constants
`MAP_LINE_BYTES`, `MAP_CAP_BYTES` and `PRESET_LINE_PENDING`; the shell function `derive_map_block`
and the knob `CARD_MAP_BOUND` in `manifest-check.sh`; the card prefix `map —`. Naming cells:
`lexicon naming predicates` grades the shell names.

### Migration

None. A tree without the playbook kit prints one `map — skipped:` line on replay and is otherwise
unchanged.

### Rollout

The replay's first line changes in every tree that takes this release. No switch: the map is
read-only output and the fallback is today's replay plus one line.

### Files touched (estimate)

- `tools/playbook/instruction_units.py`
- `skills/session-kickoff/manifest-check.sh`
- `skills/session-kickoff/manifest-check.test.sh`

### Alternatives rejected

- **A third SessionStart fragment printing the map.** Refused by the clause and by `check_card`
  (`tools/check-wiring.sh:1044-1046`), which iterates exactly the two card fragments, so a third
  entry would be wiring no arm grades.
- **Storing the map in the card at write time.** The card is per session and written at startup; a
  map stored there goes stale when a registry row changes mid-session, and the replay's job is to
  print what holds now.
- **Rendering the map in bash inside `manifest-check.sh`.** It would type the ladder a second time
  beside `LEVELS`, the one-fact rule's exact refusal.

## 5. Production-readiness checklist

- security: read-only; no new write path. The scratch file sits under the card directory the replay
  already writes to.
- perf / scale: one bounded Python spawn per `compact` or `resume`, capped at `CARD_MAP_BOUND`
  seconds; startup is untouched.
- error / empty / loading states: every failure is one `map — skipped:` line naming why.
- observability: the map's lines are the observation; a skipped map names its cause.
- risks: a card near its 8,192-byte cap plus the map can pass the harness's 10,000-character cap;
  the map-first order makes the card's tail what is cut.
- testing: the verb's arms (AC1-AC3) and the replay arms in `manifest-check.test.sh` (AC4-AC6).
- migration: none.
- user docs: N/A — agent-facing hook output with no command an owner runs; the instruction layer's
  pages are PLAY-dOrderedCharter-37's.
