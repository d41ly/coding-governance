## 1. Goal

A repository changes one of gov's structured rows (an item, a role, a leg, any kind a later build
registers) the way it changes one of gov's instruction units: from its own row in its overlay, through a
typed and pinned edge, never by editing gov's row. This unit builds that mechanism once, for every
registered kind, and proves it on one fixture kind that names no later build's kind. Today the only
adopter override of a shipped artifact is `[[own]]`, a whole-file claim (`resolve_owned_rows`,
`tools/govkit/govkit.py:1551-1598`), and a repository row placed beside gov's either reds `unique` or is
lost at update (`gap-found-29`, closed with units 32 and 33).

## 2. Scope (IN)

- **S1** — The rows' home and origin. A registered kind's repository rows sit in the overlay
  `.governance/instructions.toml` (S14, unit 32's file and reader) as `[[<kind>]]` tables in the
  grammar of the kind's schema (S10). Every row read from the overlay carries `origin` = the
  repository, derived from the file it was read from and never typed: a row typing any other
  `origin` is refused, naming the row. One reader, `read_overlay_rows` in
  `tools/playbook/overlay_rows.py`, reads them through PLAY-dOrderedCharter-32's overlay reader and
  parses no TOML itself. At 8d8e561d6 that reader's record, `tools/playbook/overlay.py#Overlay`,
  carries `units`, `policies` and `state` alone; it gains a fourth field, `tables`, each top-level
  key of the overlay other than `unit` and `policy` with its value from the one `tomllib` parse
  `tools/playbook/overlay.py#read_overlay` already makes, empty in the `unarmed` and `absent` states
  and empty by default, so the record's three constructions at 8d8e561d6 stand unchanged.
  `read_overlay_rows` refuses a table naming no kind the register lists with a `schema` and a value
  that is not an array of tables, each naming the table (section 8 F7). Observed by AC1.
- **S2** — `owned` admits the `adopter` segment. A repository row's tag sits in a registered
  namespace with `adopter` in the owner seat its kind's schema declares (`owner-seat`, S10), so
  `role.adopter.<name>` and `item.<step>.adopter.<name>` are the repository's and never collide with
  a gov tag. The composer's `owned` check, `check_row_owners` in `tools/playbook/overlay_rows.py`,
  admits such a tag only on a row `read_overlay_rows` returned, reds it on any row gov's packs ship,
  and reds an overlay row of a gov kind whose tag carries no `adopter` seat, each line naming
  `owned` and the tag; the composer runs it before it composes, and a red refuses the composition.
  The clause runs on the rows the composer holds and never over the tag index (section 8 F11): at
  8d8e561d6 no namespace extractor reads an overlay row table,
  `tools/playbook/instruction_units.py#extract_repo` reading the overlay's `[[unit]]` rows alone, so
  `tools/playbook/tag_index.py#check_owned`, the tags pack's layer-based `owned` predicate, cannot
  see an overlay row and this unit leaves it as PLAY-dOrderedCharter-19 built it. Observed by AC2
  and AC3.
- **S3** — Amend, as a field patch. An overlay row carrying an `amends` edge (S6) to `<tag>@<hash8>`
  names gov's row and changes only the fields it names: a set field takes `add` and `remove` lists,
  a scalar takes a value, each field's shape read from the kind's schema (S10). Every field the
  patch leaves alone flows from gov's row as shipped. Observed by AC4.
- **S4** — Replace, as a whole row. An overlay row carrying a `supersedes` edge to `<tag>@<hash8>`
  answers to gov's tag in the composition, so every dependent naming gov's tag resolves to it.
  Observed by AC5.
- **S5** — Exclude, over every registered kind. `instructions.exclude`, this unit's policy key, takes
  the empty set `[]`, v2's `none` and its default, or a set of gov tags of any registered kind the
  overlay holds; each listed gov row is absent
  from the composition and its state reads `excluded`. A listed tag no registered kind holds is
  refused. The key is read through unit 32's `read_excluded_tags(root)` in
  `tools/playbook/overlay.py`, the key's one reader, which unit 32 lands first and this composer
  calls, writing no second read; it calls `policy_reader("instructions.exclude")`, the playbook kit's
  callable that runs `policy.py get` as a subprocess (TOOL-dGroundRules-2 S7), passing `--rev HEAD` as
  PLAY-dOrderedCharter-46 S6 rules for every read the composition makes; `get` prints a set one member
  per line and the empty default as no line, and an exit 2 refuses the composition, naming the key and carrying the
  reader's line. The key's row lands with dGroundRules, owner dOrderedCharter (v2:1245), with no
  `summary` or `usage` and its name on the shrink-only `tools/policy/unsummarised-keys.txt`
  (TOOL-dGroundRules-1 S3, S6). This unit adds no row: it fills the row's `summary` and `usage`, a line
  the landed row's `allowed` admits (`{ type = "set", item = ... }` with `empty = "allowed"` and
  `default = []` in dGroundRules' built catalogue), and drains the name in the same commit with
  `python <prefix>/policy/policy.py lists --write`. Which exclusions are refused is unit 36's.
  Re-read at 05fd1b7f7: the callable is the playbook kit's one policy caller,
  `tools/playbook/policy_value.py#read_policy_value`, which unit 19's S8 built to unit 7's design,
  where this item had named a unit 9 callable; unit 32's reader binds it as `policy_reader`, a partial
  over the root with `rev` `"HEAD"`, the way `tools/playbook/instructions_edit.py#read_load` binds
  it, so the key stays the literal first argument the reader-coverage arm counts, and an exit 2
  reaches the composer as `PolicyRefused` carrying the reader's line. The landed row and the list
  hold the name as stated here, and a scratch repository whose committed policy sets one gov tag
  reads it back through `get --rev HEAD`, one member per line. Observed by AC6 and AC12.
- **S6** — Pins over a row's canonical form. A pin's `<hash8>` is S7's shared normaliser (unit 24's
  extraction of `derive_clause_hash`, `tools/memory-tree/design_lib.py:169-173`) applied to the row's
  canonical form (§4), so a reordering of keys or a re-wrap of a string is not a change. A pin missing
  its `@`, one with a malformed hash, and one matching no revision of gov's row are each refused.
  Re-read at 05fd1b7f7, unit 24 landed that normaliser as
  `tools/memory-tree/design_lib.py#derive_pin_hash`, and `derive_clause_hash` now calls it on a
  clause's text; the playbook kit reaches it through
  `tools/playbook/instruction_units.py#derive_unit_pin`, which resolves the memory-tree kit inside
  the call, and this module does the same. Observed by AC7.
- **S7** — Change records cover rows. The change record unit 15's `instructions.edit` writes (S12, S13)
  takes a row tag of any registered kind as its subject. Its `editorial` or `semantic` mark is unit
  33's classifier run over the two canonical forms, and its `successor` (a tag, a list for a split,
  `none` for an ending) re-points or orphans a patch edge: a renamed row's patch follows its successor
  and keeps its pin; a split or ended row orphans it, an orphaned amendment is held out of the
  composition and an orphaned whole-row replacement runs on its own, each filing an order. Observed by
  AC8 and AC11.
- **S8** — A semantic change acting on a row, as `instructions.stale` says. Behind a pin, gov's row
  changed by `semantic` records reads stale; behind `editorial` records only, the pin stands and
  nothing flags. Under `order` the patch is applied over gov's new row and an order is filed; under
  `warn` it is applied over gov's new row and the stale edge is printed and journaled with no order;
  under `refuse` the update is held until `instructions.edit` re-pins the edge. Under `order` and
  `warn` a patch that no longer applies (a patched field gov's new row lacks, or a composition that
  fails a check) is held and gov's row runs as shipped, the order or the warning saying why. Observed
  by AC9, AC10 and AC11.
- **S9** — Each gov row's state, from S22's closed set (`unchanged`, `amended`, `replaced`,
  `excluded`, `stale`, `orphaned`), returned by the composer for unit 34's delta report to print.
  Observed by AC13.
- **S10** — A kind's row schema, found through the kinds register. Unit 7's
  `tools/playbook/kinds.toml` `[[kind]]` row gains one optional key, `schema`, the path of the
  kind's row schema, written only by a kind whose rows an overlay may carry. The path is spelled
  tree-relative with the tool root as `{prefix}`, as the register's `population` key is, and
  resolves against the root of the tree whose register is read, through
  `tools/playbook/tag_index.py#resolve_prefix_token` with that tree's tool root (section 8 F9). One
  reader, `read_kind_schema(root, kind)` in `tools/playbook/overlay_rows.py`, finds the kind's row
  through `tools/playbook/pins.py#read_row_kinds`, PLAY-dOrderedCharter-33's list of the register's
  rows carrying a `schema`, and reads the minimal grammar this unit needs (section 8 F8 and F10): a
  `[kind]` table whose `name` is the kind and whose `owner-seat` is a positive integer, the index of

## 4. Design

### Data model

A repository row in the overlay, for a kind `fixture` whose schema declares `owner-seat = 1`:

```toml
[[fixture]]                                   # a new repository row
tag = "fixture.adopter.extra"
grants = ["read"]
ceiling = "low"

[[fixture]]                                   # a field patch of gov's fixture.alpha
tag = "fixture.adopter.alpha-tuned"
edges = "amends=fixture.alpha@1a2b3c4d"
add = { grants = ["write"] }
remove = { needs = ["fixture.beta"] }
ceiling = "high"

[[fixture]]                                   # a whole-row replacement of gov's fixture.gamma
tag = "fixture.adopter.gamma-own"
edges = "supersedes=fixture.gamma@5e6f7a8b"
grants = ["read"]
needs = []
ceiling = "low"
```

- `edges` is S6's one line, `type=target`; the pinned form `<tag>@<hash8>` is legal only for `amends`
  and `supersedes` (S6), and a row carries at most one of the two.
- `add` and `remove` are inline tables keyed by set fields the kind's schema declares; a key naming a
  scalar or an undeclared field is refused. A scalar key on a patch row is the new value.
- Every other key of an overlay row is `tag` or a field the schema declares; any other key is
  refused, naming the row and the key.
- `origin` is not a key an author writes. `read_overlay_rows` sets it to `repository` on every row it
  returns; gov's composer sets it to the kit for gov's rows.

The fixture kind's schema, in the grammar `read_kind_schema` reads (S10); PLAY-dOrderedCharter-36
adds its keys to the same file:

```toml
[kind]
name = "fixture"
owner-seat = 1          # fixture.adopter.<name>: segment 1, the namespace word at 0

[[field]]
name = "grants"
shape = "set"

[[field]]
name = "needs"
shape = "set"

[[field]]
name = "ceiling"
shape = "scalar"
```

**Canonical form.** The row as JSON with keys sorted, set-valued fields sorted, compact separators and
`ensure_ascii=False`, each string value first folded by S7's whitespace rule, and the keys `edges`,
`add` and `remove` left out of gov's row (gov rows carry none). The pin is S7's normaliser over that
text, so it is one function and never a second hash.

**The composer.** `derive_row_composition(kind, schema, gov_rows, overlay_rows, exclude, stale_mode,
records)` in `tools/playbook/overlay_rows.py`, `schema` what `read_kind_schema` returned for `kind`,
runs `check_row_owners` (S2) and returns `(rows, states, held, stale, orders)`:

1. gov's rows minus every tag `exclude` lists, each such tag's state `excluded`;
2. each `supersedes` row in its target's place, answering to the target's tag, state `replaced`;
3. each `amends` row applied to its target by `set_row_patch`: `add` is a set union, `remove` a set
   difference, a scalar a value, state `amended`;
4. each pin compared with the target's current canonical hash: equal, nothing; behind it with only
   `editorial` records between, nothing; behind it with a `semantic` record, the edge is stale and S8's
   arm for `stale_mode` runs, state `stale`;
5. a target whose change record names a successor tag re-points the edge to it, keeping the pin; one
   whose successor is a list or `none` orphans the edge, state `orphaned`;
6. every remaining gov row `unchanged`; every overlay row with no edge appended as the repository's own.

**The names, as of rev-9.** Before rev-9 this spec named the composer `compose_rows(kind, gov_rows,
overlay_rows, exclude, stale_mode, records)` and the patch `apply_row_patch`. The naming lexicon
refuses the first, `compose` being no declared verb, and answers the second with `set`, so they are
`derive_row_composition`, which also takes the kind's `schema` second, and `set_row_patch` (section
8 F6). A spec of dDeclaredLoop, dBoundRoles, dWitnessedBar or dShippedRelease that spells
`compose_rows` means `derive_row_composition`; this unit edits no spec outside its build, and that
build's own regrounding reads this paragraph.

`overlay_rows.py` imports `tools/playbook/pins.py` at load for `read_row_kinds`, so neither
`pins.py` nor PLAY-dOrderedCharter-36's `row_checks.py` imports `overlay_rows.py` at load; a later
caller in either reaches it inside the call.

The composer reads gov's packs and the overlay at the landed revision, `HEAD` (unit 46 S1), as every
composer does (flow-roles-adoption item 11), and returns data: it writes no file. Orders return as data
through unit 33's drift verb, whose caller `cmd_update` writes each with `write_row_order(outbox, kind,
key, text)` (TOOL-dSafePassage-9 S4; `tools/govkit/govkit.py#write_row_order`, four arguments at
`05fd1b7f7`), `kind` the row's registered kind, `key` the order's path
`.governance/instructions.toml#<overlay row tag>` and `text` the order the verb returned whole, its
own title included, as unit 33 S7 writes a unit's; `tools/govkit/govkit.py#render_row_order`'s title
says gov no longer ships the row, which is false for a stale edge, so no text is composed from it.
That handler iterates every kind the kinds register lists, and a register listing no
row kind prints `0 row kinds registered` rather than nothing. The `warn` journal is the stale-edge
journal unit 33 writes for units, one line per edge, the row's tag in its subject field.

**The `owned` clause.** `owned` today asks whether a tag sits under a namespace its declaring
contract owns (systems `[design-tags]`, its row "an expansion declaring `item.build.x`"); at
`8d8e561d6` that arm is layer-based, `tools/playbook/tag_index.py#check_owned` reading each indexed
definition's namespace and the layer of the kit its source sits in. The adopter clause is
`check_row_owners(schema, rows)` in `tools/playbook/overlay_rows.py`: a tag whose segment at the
schema's `owner-seat` is `adopter` is owned by the repository, legal only on a row whose `origin`
is the repository, and a row from gov's packs carrying it reds; an overlay row whose tag holds any
other segment at that seat reds. Each red names `owned`, the tag and the file the row came from. The
check reads the seat from the kind's schema, never a typed position, and `adopter` is never a
namespace word, so the tag grammar's first-segment rule stands (flow-roles-adoption `[renamed]`).
It runs on the rows the composer is handed, because no namespace extractor indexes an overlay row
table (section 8 F11), and `check_owned`'s reds stand as they are.
