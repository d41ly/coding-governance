## 1. Goal

The charter's 36 practices are one-line rules typed into the template's section 1
(`coding-governance-agents.template.md:13-54`), with no reach and no way for an adopter to choose them
except the one `when:cross-os` fence (gap-found-02). This unit moves them into a shipped catalogue,
`tools/playbook/practices.toml`, where each practice is a tag, a one-line rule and its reach per step
(foundations R1, F1-3 "Catalogue with reach"), and makes the active set a policy, `charter.practices`,
that the renderer reads to write the charter's practice lines (v2:1143, P14).

## 2. Scope (IN)

- **S1** — The catalogue. `tools/playbook/practices.toml` holds one `[[practice]]` row per practice, in
  render order, with the fields S15 fixes: `tag` (`practice.<name>`), `line` (the rule text after
  `[<name>] `), and a `[practice.reach]` table whose keys are `reach.<step>`. It is seeded with the 36
  rows of today's section 1, in today's order and bytes, and the three methodology rows foundations R1
  names, `practice.solid`, `practice.dry` and `practice.tdd`. A top-level `foundation` array lists the
  tags of the governance foundation set, today's 36. Observed by AC1 and AC2.
  **Selection.** `practice` is a `selects` namespace (`tools/playbook/namespaces.toml@c7269a97:49`), so
  once any `[[unit]]` row exists the tags join reds each declared member no unit's `scope` selects
  (`tools/playbook/tag_index.py#check_namespace_joins`). This unit writes no unit row and no
  `instructions.toml` is tracked at its pass, so the join prints `unarmed` for `practice`; who selects
  each of the 39 members is handed to the pass that lands gov's first unit rows (the fork record's F5).
  Observed by AC1.
- **S2** — One optional row field beyond S15, `kit`, naming the kit a line needs, so `practice.roles`
  keeps rendering only where the roles kit is adopted, as its `<!-- kit:roles -->` fence does today
  (template:47-49). Observed by AC5.
- **S3** — The reader and its check, `read_practice_catalogue` in `tools/playbook/instruction_units.py`
  (S10's one reader module). It refuses, naming the row: a tag outside the `practice.<seg>` shape of
  S4's tag grammar, a tag twice, an empty `line`, a row with no `reach.<step>` key, a reach key whose
  step is not of the `seg` shape, and a `foundation` entry naming no row. A line's length is the
  render's to grade, never the reader's: `check_one_line_regions` grades each rendered practice line
  against the census cap `one-line-rule`, which `tools/playbook/render_playbook.py#read_one_line_cap`
  resolves through `budgets.resolve_caps`, `ONE_LINE_MAX` (200, `tools/playbook/render_playbook.py:129`)
  being only its default, so no second copy of the cap exists. Observed by AC2.
- **S4** — The policy. `resolve_active_practices(catalogue, value)` returns the active rows in catalogue
  order. `value` is `charter.practices`, a non-empty set of practice tags (v2:1143), or `None`, which
  returns the `foundation` set. An empty set and a tag in no row are refused by name. The key is read
  with `read_policy_value("charter.practices", target)`, unit 19's
  `tools/playbook/policy_value.py#read_policy_value`, `(key, root, rev=None)` returning the value's lines
  and the `--explain` line: it runs `policy.py get charter.practices --explain` over the committed policy
  of `target`, the render's target, since the choice is the adopter's. A set of practice tags passes the
  row's value check: the fork record's F4 holds the probe. Observed by AC3 and AC8.
  **A set value.** The lines the reader returns go through
  `tools/playbook/instructions_edit.py#resolve_practices`, called with no `root`, so it reads the
  `packs.toml` and `practices.toml` beside the engine, the tables a scratch target need not hold. Its
  tags are `value`. That module loads the memory-tree kit at import

## 4. Design

### Data model

```toml
foundation = ["practice.yagni", "practice.reuse", "..."]   # the default of charter.practices

[[practice]]
tag = "practice.yagni"
line = "YAGNI: build what this unit needs now, never scaffolding for later, and delete rather than disable."
[practice.reach]
plan = "no build for a speculative need"
design = "no extension point, option or layer the unit does not use"
build = "delete rather than disable"
test = "no test for a path that is not built"
review = "speculative generality is a finding"

[[practice]]
tag = "practice.roles"
kit = "roles"
line = "Spec writing and review, building and the closing review run in role agents ..."
```

The `practice.yagni` reach is foundations R1's own example (foundations:72-76). Every other row carries
at least one reach entry, written by the builder from the rule's text; a step key is the flow's step
name, lowercase (P20: plan, design, build, test, deploy), plus `review` for the review breakpoint.

### Flow

`render()` first looks for the `{{PRACTICES}}` line, and a template with none reads neither the catalogue
nor the key. With one, it reads the catalogue from `engine_dir / 'practices.toml'`, which the `**` rule of
`tools/playbook/kit.toml` lands in an install, and maps `drop_blocks` by S6 before the loop that raises
the `no when fence` refusal. Once the fenced text is cut, `render_practice_lines` resolves the active set
by S4, leaves out each S6 member and each row whose `kit` is not adopted, refuses if no row is left, and
returns the lines, which replace the one `{{PRACTICES}}` line before `PLACEHOLDER_RE.findall` runs, so no
second placeholder pass is needed. The probe table `PROBES` (`render_playbook.py:565`) is not used: a probe's value is substituted after the
placeholder set is collected, and a practice line carries placeholders of its own.

### Inventory

Minted: the file `tools/playbook/practices.toml`; its `[[practice]]` row and `foundation` key; the
optional `kit` field; the functions `read_practice_catalogue`, `resolve_active_practices` and
`render_practice_lines`; the constants `POLICY_DERIVED_LINE` and `PRACTICES_LINE_RE`; the placeholder
`PRACTICES`; three tags `practice.solid`, `practice.dry`, `practice.tdd`; the template
marker `v4.5`; the page `help/charter.md`. The policy key `charter.practices` is v2's.

### Migration

A seeded template older than `v4.5` keeps its literal section-1 lines, reads neither the catalogue nor
the key, and renders as today. A `v4.4` template takes no reseed note: the `legacy` note on the path
`TEMPLATE_MARKER_RE` already takes (`render_playbook.py:344`) fires only on a major behind, the rule
`PLAY-dOrderedCharter-41` states. `govkit update` leaves a seeded template alone, its role being `seed`
(`tools/govkit/entries/playbook.kit.toml`), so only a fresh install or a reseed reaches S4's read. Gov's
own template is the source and moves at once.

### Rollout

Live at landing; gov's `AGENTS.md` practice lines do not change. S8 lands as two commits: the row fill
with the list drain, then `.governance/policy.json` alone as `policy.py mirror --write` regenerates it,
since a catalogue edit stales the mirror (TOOL-dGroundRules-5 S1, S2), which omits this derived-default key
(TOOL-dGroundRules-21 F4), and the guard admits a mirror commit only when the policy file and the
catalogue equal HEAD (TOOL-dGroundRules-19 S1). S7's anchor and the `docs-undocumented.txt` drop ride
the first, since the anchor's fingerprint is the filled row's, and so does the re-render's
`.governance/instructions.lock`.
