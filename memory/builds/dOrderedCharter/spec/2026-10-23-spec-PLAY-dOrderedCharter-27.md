## 1. Goal

The night pass gives each item a `code` slot, the seed's definitions with their ranges, callers,
callees and tests, handed as ranges and never bodies under `memory.code-budget` (night pass, point 3,
worked-in item 2; v2:1365, the owner's NP-8, "16KB default"). The slot's content is dFurnishedOrders',
and no role's load set has a place or a budget for it. This unit gives every role's load set a `code`
slot with its budget, so a work order carrying code is measured like every other load and the later
filler lands into a priced slot (v2:973-981 P27).

## 2. Scope (IN)

- **S1** — The slot. `derive_load_set` (`PLAY-dOrderedCharter-11`, `tools/playbook/load_sets.py`)
  adds a `code` slot to the load set of every role, the default reach `memory.code-roles` names
  (`every-role`, v2:1366). It is listed with its budget whether or not it is filled. Observed by AC1.
- **S2** — The budget. The slot's budget is `memory.code-budget`, dFurnishedOrders' key, read with
  unit 19's `tools/playbook/policy_value.py#read_policy_value`, as
  `read_policy_value("memory.code-budget", root)`,
  `root` the repository the load set is derived in. Its catalogue row lands with dGroundRules at v2's
  default `16k` (TOOL-dGroundRules-1 S3; v2:1365), so unset it answers `16k` with its source
  (TOOL-dGroundRules-3 S2): at HEAD `policy.py get memory.code-budget --explain` prints `16k` and
  `policy: memory.code-budget · default · … the catalogue default`. The row's `summary` and `usage` are
  dFurnishedOrders' to fill. A `k` is 1,000 bytes, as the systems
  record's `memory.item-budget` row defines the unit (`2026-10-16-build-PLAY-dClosedLoop-1-systems.md:570`),
  so the default is 16000 bytes. A value outside `<n>k` is refused naming the key, and so is a refused
  read, the reader's `PolicyRefused`, naming the line it carries too. Observed by AC1 and AC3.
- **S3** — The handoff block. `render_handoff` (`tools/roles/handoff.py:312`) renders a supplied slot
  as a `### input:code` block from `--input code=<path>`, the stand-in filler until dFurnishedOrders' code
  record fills it; the heading is the one its block loop gives every key, `### <key>` (the fork record's
  F3). `code` joins `INPUT_NAMES` and `PATH_INPUTS` (`handoff.py:98-99`), so its path is
  checked as a spec path is; unlike `spec` and `prompt`, whose blocks hold the path, the `code` block
  holds the file's text, since the ranges are the payload. No role's `reads:` names `input:code`
  (Migration in section 4), so two places take it as derived. The CLI's check that refuses an input the
  role does not read (`tools/roles/handoff.py#main`, which exempts `prompt` alone today, so
  `render --role gov-builder --input diff=x` exits 2 printing `input:diff is a key gov-builder does not
  read`) exempts `code` as it exempts `prompt`. `render_handoff`, whose block and absent loops walk only
  the role's `reads` (`tools/roles/handoff.py#render_handoff`), walks them with `input:code?` appended,
  a derived optional key, since S1 gives every role the slot. An unsupplied slot is named among the
  optional inputs not supplied, as `handoff.py` already names an absent optional key. Observed by AC2.
- **S4** — The measure. The filled block's bytes, CR stripped, are measured by `check_budget`
  (`PLAY-dOrderedCharter-11`) against S2's value, under a new cap `code-slot` of the cap census
  `tools/policy/caps.toml`: `class = "switch"`, `unit = "bytes"`, `family = true`, `research = 0` (no
  row of the caps research names it), `enforcer` and `installed` `{prefix}/playbook/load_sets.py`,
  `kit = "playbook-render"` as the `one-line-rule` row spells that kit, and
  `home = "policy:memory.code-budget"`. A family cap's value is handed in by its enforcer and the policy
  file may set none, so `memory.code-budget` stays the one home of the value. `check_budget` asks
  `python <prefix>/policy/budgets.py resolve code-slot`, the cap named literally as `arm_cap_census`
  grades an enforcer (`tools/policy/check_policy.py#arm_cap_census`), for the mode alone: `refuse` under
  `budgets.enforce = "refuse"` or a `budgets.pinned` naming `code-slot`, else `warn`
  (`tools/policy/budgets.py#resolve_caps`, whose family branch answers the mode and no value). The census
  gains one home form for the row: `policy` joins `HOME_FORMS` (`tools/policy/budgets.py#HOME_FORMS`),
  and `read_cap_census` refuses a `policy:` home on a row whose `family` is false, where
  `budgets.<cap>` in the policy file would be a second home for the key's value.
  `tools/policy/check_policy.py#CAP_CASES` gains the row's case, a plant rendering a handoff with a
  block one byte over the budget under `warn` and `refuse`, as the `role-body` case plants a role body
  past its ceiling. Over the budget the render warns or refuses as the mode says, naming the slot, its
  bytes and its budget (the fork record's F4). Observed by AC3 and AC4.

## 4. Design

### Data model

A load set entry for the slot: `{"slot": "code", "budget": 16000, "source": "memory.code-budget default 16k"}`.
The rendered block:

```markdown
### input:code

<ranges, as the caller supplied them>
```

### Inventory

Minted: the slot name `code` in a load set; the `INPUT_NAMES` and `PATH_INPUTS` member `code` and the
derived optional key `input:code?`; the census row `code-slot`, its home form `policy:<key>` and its
`CAP_CASES` case; the budget source string naming whether the value came from the key or its default.
The block heading `### input:code` is the existing `### <key>` form, not minted.

### Migration

None. No role file changes: the slot is derived for every role, never written into each role's
`reads:` value. The census row is additive: a census without it reads as before, and no policy file
holds a `budgets.code-slot` value to move.

### Rollout

Live at landing. Every role's derived set lists the slot; no handoff carries one until a caller
supplies it.

### Files touched (estimate)

- `tools/playbook/load_sets.py`
- `tools/roles/handoff.py`
- `tools/policy/caps.toml`
- `tools/policy/budgets.py`
- `tools/policy/check_policy.py`
- `help/roles.md`
- `help/size-caps.md`

### Alternatives rejected

- **`input:code?` added to each of the ten role files' `reads:`.** It types ten copies of one policy
  default; deriving the slot from the key's default keeps it one fact.
- **Truncating an over-budget block.** The night pass hands ranges under the budget at the filler; a
  render that cut a block would hand a reader half a range with no word said.

## 5. Production-readiness checklist

- security: the block is caller-supplied data, rendered under its heading like every `input:` block.
- perf / scale: one size measurement per handoff.
- error / empty / loading states: an unsupplied slot is named as not supplied; an input path outside
  the repository refuses as every path input does (`handoff.py:331-334`, in
  `tools/roles/handoff.py#render_handoff`); a refused budget read refuses the derivation naming the
  key, and a refused `budgets.py resolve` refuses the render printing the reader's line.
- observability: the derive verb prints the slot, its budget and the budget's source.
- risks: none beyond `PLAY-dOrderedCharter-11`'s.
- testing: §6 and the `New arm:` line of §7.
- migration: none.
- user docs: `help/roles.md` names the `code` input and its budget; `help/size-caps.md`'s "Where each
  cap's value is declared today" names the policy key that holds the `code-slot` value.
