## 1. Goal

The night pass gives each item a `code` slot, the seed's definitions with their ranges, callers,
callees and tests, handed as ranges and never bodies under `memory.code-budget` (night pass, point 3,
worked-in item 2; v2:1365, the owner's NP-8, "16KB default"). The slot's content is dFurnishedOrders',
and no role's load set has a place or a budget for it. This unit gives every role's load set a `code`
slot with its budget, so a work order carrying code is measured like every other load and the later
filler lands into a priced slot (v2:973-981 P27).

## 2. Scope (IN)

- **S1** — The slot. `derive_load_set` (`PLAY-dOrderedCharter-11`, `tools/playbook/load_sets.py`)
  adds a `code` slot to the load set of every role, the default reach `memory.code-roles` names
  (`every-role`, v2:1366). It is listed with its budget whether or not it is filled. Observed by AC1.
- **S2** — The budget. The slot's budget is `memory.code-budget`, dFurnishedOrders' key, read with
  `read_policy_value("memory.code-budget", root)` (PLAY-dOrderedCharter-7 §4), `root` the repository the
  load set is derived in. Its catalogue row lands with dGroundRules at v2's default `16k`
  (TOOL-dGroundRules-1 S3; v2:1365), so unset it answers `16k` with its source (TOOL-dGroundRules-3 S2);
  the row's `summary` and `usage` are dFurnishedOrders' to fill. A `k` is 1,000 bytes, as the systems
  record's `memory.item-budget` row defines the unit (`2026-10-16-build-PLAY-dClosedLoop-1-systems.md:570`),
  so the default is 16000 bytes. A value outside `<n>k` is refused naming the key, and so is a refused
  read, the reader's exit 2, naming the reader's line too. Observed by AC1 and AC3.
- **S3** — The handoff block. `render_handoff` (`tools/roles/handoff.py:312`) renders a supplied slot
  as a `### code` block from `--input code=<path>`, the stand-in filler until dFurnishedOrders' code
  record fills it. `code` joins `INPUT_NAMES` and `PATH_INPUTS` (`handoff.py:98-99`), so its path is
  checked as a spec path is; unlike `spec` and `prompt`, whose blocks hold the path, the `code` block
  holds the file's text, since the ranges are the payload. An unsupplied slot is named among the
  optional inputs not supplied, as `handoff.py` already names an absent optional key. Observed by AC2.
- **S4** — The measure. The filled block's bytes, CR stripped, go through `check_budget`
  (`PLAY-dOrderedCharter-11`): over the slot's budget, the render warns or refuses as `budgets.enforce`
  says, naming the slot, its bytes and its budget. Observed by AC3.

## 3. Non-goals (OUT)

  dTotalRecall's (night pass, point 3).
- `memory.code-roles` values other than its default: the role classes `working-roles` and
  `structural-roles` name are registered by a later build, and until then the slot goes to every role.
- `memory.code-budget` itself and its row's `summary` and `usage`: dFurnishedOrders'; the catalogue row
  and its reader: dGroundRules', landed before this build run.
- The memory slices and `memory.over-budget`: dTotalRecall.

## 4. Design

### Data model

A load set entry for the slot: `{"slot": "code", "budget": 16000, "source": "memory.code-budget default 16k"}`.
The rendered block:

```markdown
### code

<ranges, as the caller supplied them>
```

### Inventory

Minted: the slot name `code` in a load set; the `INPUT_NAMES` and `PATH_INPUTS` member `code`; the handoff block
`### code`; the budget source string naming whether the value came from the key or its default.

### Migration

None. No role file changes: the slot is derived for every role, never written into each role's
`reads:` value.

### Rollout

Live at landing. Every role's derived set lists the slot; no handoff carries one until a caller
supplies it.

### Files touched (estimate)

- `tools/playbook/load_sets.py`
- `tools/roles/handoff.py`
- `help/roles.md`

### Alternatives rejected

- **`input:code?` added to each of the ten role files' `reads:`.** It types ten copies of one policy
  default; deriving the slot from the key's default keeps it one fact.
- **Truncating an over-budget block.** The night pass hands ranges under the budget at the filler; a
  render that cut a block would hand a reader half a range with no word said.

## 5. Production-readiness checklist

- security: the block is caller-supplied data, rendered under its heading like every `input:` block.
- perf / scale: one size measurement per handoff.
- error / empty / loading states: an unsupplied slot is named as not supplied; an input path outside
  the repository refuses as every path input does (`handoff.py:331-334`); a refused budget read refuses
  the derivation naming the key.
- observability: the derive verb prints the slot, its budget and the budget's source.
- risks: none beyond `PLAY-dOrderedCharter-11`'s.
- testing: §6 and the `New arm:` line of §7.
- migration: none.
- user docs: `help/roles.md` names the `code` input and its budget.

  runs, the output carries a `### code` block holding the file's text; without `--input code=` it names
  `code` among the optional inputs not supplied.
  Red when: the block is dropped or an absent slot is silent.
- **AC3** — When the same render runs with a 16001-byte ranges file, it prints a breach line naming

  `refuse`; with a 16000-byte file it prints no breach.
  Red when: the boundary is off by one either way, or `warn` refuses.
