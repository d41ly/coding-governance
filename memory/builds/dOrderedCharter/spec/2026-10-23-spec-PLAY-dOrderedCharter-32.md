## 1. Goal

No seam changes or removes a gov instruction and keeps the change: the charter's `[charter]
adopter_rules` slot and the roles' house files only add, and an edit to a rendered instruction is
overwritten at the next update (`gap-found-29`). A repository's own rules render inside the charter's
one block rather than as their own project block, and gov's own `deploy.toml` says it selects every
kit while it lists 22, PINNED at base (`gap-found-19`). Gov's own rules ship in the set every adopter receives
(`gap-found-31`). This unit lands the repository's instruction overlay, `.governance/instructions.toml`:
one guarded home in the kit manifests' row grammar, whose units are the repository's, tagged `repo.`,
added at their level, `select` and `when`; which changes gov's units only through a repository unit's
`amends` (rendered after gov's unit) or `supersedes` (rendered in its place), each pinned as
`<tag>@<hash>`, or drops one through `instructions.exclude`; where every gov unit's class is derived,
and a fixed unit refuses all three; and where the repository declares its own policy keys under
`adopter.`, tagged `policy.adopter.<key>` (IA-1, IA-2, IA-4; P8).

## 2. Scope (IN)

- **S1** — The home and its one reader. `.governance/instructions.toml` holds `[[unit]]` rows in S10's
  grammar and `[[policy]]` rows (S7). `read_overlay(root)` in `tools/playbook/overlay.py` is the one
  reader that parses it, reading the file at the landed revision, never the working tree, as every
  composer does; an absent file is an empty overlay, never a refusal. Every unit it returns carries
  `origin = "repository"`, derived from the file and never typed, and a row typing another origin is
  refused. PLAY-dOrderedCharter-35's `read_overlay_rows` and PLAY-dOrderedCharter-34's composition read
  through it. Observed by AC1.
- **S2** — The `repo` namespace (`tag-namespace.repo`, PLAY-dOrderedCharter-10's row). Every overlay
  unit's tag is `repo.<seg>(.<seg>)*` under S4's grammar; a tag in any other namespace, and a `repo.`
  tag on a row gov's packs ship, are refused, naming the row. Observed by AC2.
- **S3** — Add. An overlay unit with no `amends` or `supersedes` edge takes its place by its `level`,
  `select` and `when`, like any unit. Levels 1, 6 and 7 are refused: the repository writes neither
  the card, the task nor memory (the adopter-instructions record, item 3). Observed by AC3.
- **S4** — Amend and replace, for prose units. `derive_unit_composition(gov_units, overlay_units, exclude)` in
  `tools/playbook/overlay.py` returns the ordered units a document renders: a repository unit whose
  `edges` hold `amends=<tag>@<hash8>` renders right after gov's unit, which keeps rendering; one
  holding `supersedes=<tag>@<hash8>` renders in gov's unit's place; a gov tag `instructions.exclude`
  lists is absent. The pin's `<hash8>` is `derive_pin_hash` (S7, `tools/memory-tree/design_lib.py`)
  over gov's unit text, whitespace-normalised. The renderer of record (S11) takes its unit list from
  `derive_unit_composition`. Observed by AC4, AC5.
- **S5** — The derived class. `derive_unit_class(unit, sources)` returns `fixed` or `open`: fixed when
  the unit is a `principle.` unit (PLAY-dOrderedCharter-7's registry), when its `fixed-by` names a
  `floor=<tag>` or a `parser=<path#symbol>` that resolves, the source grammar PLAY-dOrderedCharter-36
  declares for rows; open only when the unit declares `class = "open"` and nothing fixes it; fixed
  when it declares nothing. A unit typing `class = "fixed"` is refused, since a fixed class is derived;
  a unit declaring `open` that a source fixes is red, naming the source. Observed by AC6.
- **S6** — A fixed unit refuses all three. An `amends` or `supersedes` edge whose target is fixed, and
  an `instructions.exclude` entry naming a fixed unit, are each refused, naming the target and the
  source that fixes it. Observed by AC7.
- **S7** — The repository's own policy keys. A `[[policy]]` row declares `key` (`adopter.<seg>`),
  `values`, `default`, `summary` and `usage`; its value is set under `[adopter]` in
  `.governance/policy.toml` and its tag is `policy.adopter.<seg>`. This unit owns the row's grammar,
  and the policy kit parses it: inside `tools/policy/policy.py`, `read_overlay_policies(repo, sha)`
  reads the `[[policy]]` tables of `.governance/instructions.toml`'s blob at the revision the reader is
  reading, through the kit's own `read_blob_at` (TOOL-dGroundRules-21 S11) and `tomllib`, never
  importing `tools/playbook/` (TOOL-dGroundRules-1 §4), and returns each as a catalogue row whose
  `owner` is the repository. Those rows join the catalogue's wherever the kit matches a key to a row:
  `read_catalogue_row`, so `get` resolves an `adopter.` key (TOOL-dGroundRules-2 S4); `validate` and
  `arm_schema`, so an `adopter.` value is judged against its row and an `adopter.` key no row declares
  is the unknown-leaf problem (TOOL-dGroundRules-4 S1, S2); and the mirror, which renders each
  `adopter.` key beside the catalogue's and records the overlay blob's id in its staleness key beside
  the policy file's and the catalogue's (TOOL-dGroundRules-5 S1), while the guard's mirror shape also
  requires `.governance/instructions.toml`'s staged blob to equal HEAD's (TOOL-dGroundRules-19 S1;
  §8 F6). A `[[policy]]` key outside `adopter.`
  is refused, so the overlay never redeclares a catalogue key, and `adopter.` keys stay outside the
  presets' completeness check. Only repository units read them: a gov unit whose `when` names a

- **S8** — The route for writing the overlay. `write_overlay_units(target, rows)` is the one function

- **S9** — The selection claim. The comment above `kits` in `.governance/deploy.toml` (`:11-13`), which

## 4. Design

### Data model

```toml
# .governance/instructions.toml — this repository's own units and policy keys.
[[unit]]
tag = "repo.ships-charter"
level = 0
type = "fact"
text = "This repository ships the charter template and the kits under `tools/`, and dogfoods every kit it ships on itself."

[[unit]]
tag = "repo.verify-staged"
level = 3
type = "directive"
select = ["doc.build-method"]
text = "Verify against the staged bytes before every pass commit."
edges = "amends=practice.verify@1f2e3d4c"

[[policy]]
key = "adopter.release-train"
values = ["weekly", "monthly"]
default = "weekly"
summary = "how often this repository cuts a release"
usage = "set [adopter] release-train in .governance/policy.toml"
```

Field names are S10's, as PLAY-dOrderedCharter-9's reader lands them (§8 F1). `origin` is never
written; `read_overlay` sets it. `edges` is one S6 line, a type and a target per pair.

### Composition of prose units

`derive_unit_composition` walks gov's units in their render order and, for each:

1. excluded by `instructions.exclude` → skipped, its state `excluded`;
2. a repository unit `supersedes` it → that unit renders in its place, state `replaced`;
3. one or more repository units `amend` it → gov's unit, then each amendment in overlay order, state
   `amended`;
4. otherwise gov's unit, state `unchanged`.

Repository units with no edge are placed by `level`, `select` and `when` after gov's units of the
same placement. A target tag that names no gov unit is refused here unless PLAY-dOrderedCharter-33's
successor walk re-points it. The function returns `(units, states)` and writes nothing.
`instructions.exclude` is read through PLAY-dOrderedCharter-35's reader of that key.

### The derived class

The `fixed-by` sources are the three PLAY-dOrderedCharter-36 declares for rows, one grammar for both:
`principle=<tag>`, `floor=<tag>`, `parser=<path#symbol>`. A `principle.` unit is fixed without a
`fixed-by`, since its namespace says so. A `floor=` source is refused until the floor's namespace is
registered, as unit 36 refuses it. A `parser=` source resolves when the path is tracked and defines the
symbol, unit 26's form. Applying `derive_unit_class` to every gov unit in every kit's
`instructions.toml` is part of `overlay.py check`, so a parsed unit declared `open` reds on gov's own
tree, not only in an adopter's.

### The policy keys

The extension lives in the policy kit (S7): its matcher, `validate`, `arm_schema` and the mirror take
the catalogue's rows plus `read_overlay_policies` at the same sha, so one revision answers both a value
and its row, and a key under `[adopter]` with no row is the kit's existing unknown-leaf problem. The
policy kit parses only the `[[policy]]` tables, by S7's five fields; `read_overlay` (S1) parses the
