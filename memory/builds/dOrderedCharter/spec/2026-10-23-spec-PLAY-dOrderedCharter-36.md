## 1. Goal

The composition unit 35 produces is checked before it runs: a repository may not touch what gov
fixes, may not exclude a row something else still needs, and every widening it makes is classified
from declarations, never guessed. The checks are generic over every registered kind and declared per
kind in its schema, so a later build's kind joins by declaring its lists and planting its own reds.
They are seen red here on the fixture kind, which names no later build's kind. Today no kind declares
a fixed field or a widening direction anywhere: unit 7's kinds register `tools/playbook/kinds.toml`
has landed, and none of its rows names a row schema, so a patch of any field would pass unclassified
(flow-roles-adoption items 9 and 10, FA-1, FA-5).

## 2. Scope (IN)

- **S1** — The schema declarations each kind carries, in the row schema unit 35's optional `schema`
  key on a `[[kind]]` row of unit 7's kinds register `tools/playbook/kinds.toml` names. Per field,
  beside the `name` and `shape` (`set` or `scalar`) PLAY-dOrderedCharter-35 reads, an optional `ref`
  role (`needs`, `actor` or `grants`), and either `fixed-by` or `widens`; per row, `[[fixed-row]]`
  with a tag and `fixed-by`. `fixed-by` is a non-empty list of sources from IA-4's three:
  `principle=<tag>`, `floor=<tag>` and `parser=<path#symbol>`. A typed `class` key is refused, so
  the class is derived and never typed. The one reader is PLAY-dOrderedCharter-35's
  `read_kind_schema` in `tools/playbook/overlay_rows.py`, which reads the `[kind]` table and each
  field's `name` and `shape`; this unit adds these keys and the refusals of section 4 to it, and
  writes no second reader (PLAY-dOrderedCharter-35's section 8 F10). Observed by AC4 and AC5.
- **S2** — The derived class. A field or row is fixed when its `fixed-by` resolves, open when it
  declares `widens`, and fixed when it declares neither: an undeclared class reads as fixed. A field
  declaring both is refused as two answers. Each `fixed-by` source must resolve: a `principle` tag in
  unit 7's principle registry, a `floor` tag through the tag resolver once the floor's namespace is
  registered, a `parser` source as a tracked file defining that symbol. The grammar and its resolution
  are unit 32's: each field's and each `[[fixed-row]]`'s list is handed to
  `check_fixed_sources(entries, root)` in `tools/playbook/overlay.py`, which unit 32 lands for its
  units' `fixed-by`, and its reds are this reader's refusals for that list; this unit writes no second
  resolver. That function reads definitions through
  `tools/playbook/positional.py#read_symbol_defs`, unit 26's finder for symbol citations, which reads
  Python, shell and JavaScript, so a `parser=` path of any other suffix defines nothing and does not
  resolve. Observed by AC4 and AC5.
- **S3** — The fixed set refusals. An `amends` patch naming a fixed field, or patching a fixed row
  whatever field it names, is refused, and refused as a widening when the classifier reads it
  widening; a `supersedes` of a fixed row and an `instructions.exclude` entry naming a fixed row are
  each refused. The check reads each patch as written, so a patch of a fixed field refuses whether or
  not gov's row ships the field. Each refusal names the row, the field where one applies, and the
  `fixed-by` source. Observed by AC1, AC2, AC3 and AC4.
- **S4** — The exclusion refusals. An `instructions.exclude` entry is refused, naming the requirer, when
  another active row of any registered kind holds the excluded tag in a field whose `ref` role is
  `needs`, `actor` or `grants`; and refused, naming the key, when a tag-valued policy key's value names
  it. The excluded set is `instructions.exclude`'s value as unit 35 reads it, a value its landed row's
  `allowed` admits (TOOL-dGroundRules-1 §4), by default `[]`, v2's `none`, which excludes nothing.
  Each kind's composer call walks its own active rows against the whole excluded set, so a requirer of
  any registered kind is found when its own kind composes. The tag-valued keys and their values are
  the ones the policy kit renders for the revision `HEAD`: a placeholder row such as
  `roles.effort.<role>` contributes each key the policy file sets that it matches, and a row whose
  unset default is derived prose contributes nothing, since that prose names no tag (section 8 F5).
  Observed by AC6.
- **S5** — The widening classifier, named in section 4's Inventory. Each open field declares the direction that
  widens it: `add` on a permission set, `remove` on a constraint set such as `needs`, or an ordered
  list on a scalar whose later values are wider. Every patch operation is classified `widens` or
  `narrows` from those declarations alone. A field declaring neither key is fixed (S2), so a field
  lacks a direction only by declaring `widens` with none, an empty string or an empty list, which the
  schema reader refuses naming the field (section 8 F7). A patch value outside a scalar's order is
  refused; gov's own value outside it ranks below every listed value, so any listed patch value reads
  `widens` (section 8 F8). Observed by AC7 and AC8.
- **S6** — The widening list, `derive_widenings(checks)`, every operation in the composer's `checks`
  value whose class is `widens`, each with its row, field, operation and gov's value; unit 34's delta
  report prints it and is its one source. Observed by AC9.
- **S7** — The checks run on the composition, never on the overlay text: `check_rows(schema, entries,
  rows, exclude, policy)` is called by PLAY-dOrderedCharter-35's `derive_row_composition` after its
  edge loop, and a finding refuses the composition. The composer gains an eighth parameter, `policy`,
  and a sixth return value, `checks`, as section 4's The call states (section 8 F6). Observed by AC1
  to AC8 and AC10.
- **S8** — The fixture kind's planted reds, added to `tools/playbook/fixtures/row_kind.py`: its schema
  gains a fixed field, a fixed row, an undeclared field and a reference field of each `ref` role, and
  each refusal of S3 to S5 is one plant. The fixture gains `--policy <key>=<tag>`, merged into the
  `policy` value it hands the composer. Three of PLAY-dOrderedCharter-35's plants meet these checks,
  and section 4's PLAY-dOrderedCharter-35's plants states what each keeps and what this unit changes
  (section 8 F8 to F10). No plant names a later build's kind. Observed by AC1 to AC8, AC10 and AC11.
- **S9** — The page section on what a repository may not change and how a widening is reported, in
  `help/overlay-rows.md` (unit 35's page). Observed by AC12.

- Printing widenings at update: unit 34's report reads S6.

**The classifier.** For a patch operation on an open field:

| Field | Operation | Class |
|---|---|---|
| set, `widens = "add"` | `add` | `widens` |
| set, `widens = "add"` | `remove` | `narrows` |
| set, `widens = "remove"` | `remove` | `widens` |
| set, `widens = "remove"` | `add` | `narrows` |
| scalar, ordered list | a value later in the list than gov's | `widens` |
| scalar, ordered list | a value earlier in the list than gov's | `narrows` |
| scalar, ordered list | a value not in the list | refused, naming the field and the value |
| scalar, ordered list, gov's value not in the list | any value in the list | `widens` |

`derive_patch_class` classifies one operation: a set field's `add` or `remove` with the members gov's
row lacks or holds, or a scalar's new value. A value equal to gov's, and a member already present or
already absent, is no operation. Gov's value outside its field's order ranks below every listed
value, so the operation reads `widens`, the class the delta report prints, naming gov's value; the
class is never `narrows` on a baseline the order does not rank, and gov's off-order value is gov's
pack to correct, not a repository's patch to refuse (section 8 F8).

A whole-row `supersedes` is classified field by field against gov's row it answers to, so a
replacement cannot widen what a patch could not: a set field's members the replacement adds are one
`add` and those it drops one `remove`, a scalar it changes one new value, and a fixed field it
changes or drops refuses as S3's patch would.

## 5. Production-readiness checklist

- security: this unit is the deny half of the overlay's row write: an undeclared class reads fixed, a
  field with no direction refuses, and a fixed row cannot be patched, replaced or excluded, so a
  repository widens only what a kind opened.
- perf / scale: one schema read per kind; the exclusion walk is linear in the composition's rows per
  excluded tag, plus, when the excluded set is non-empty, one in-process policy read of `HEAD` per
  update, a mirror render and a revision read, each a few git calls, which the caller makes once and
  hands every kind's call.
- error / empty / loading states: a kind with no schema refuses naming the kind; an empty exclusion
  list and a composition with no patch return no finding and say how many rows they read.
- observability: every refusal names the row, the field, the source or the requirer; every widening is
  one line in the list S6 returns.
- risks: a kind that opens a field it should have fixed is not caught here, only by its own build's
  planted reds; a `parser=` source proves a symbol exists, never that it reads the field
  (`line-claim-matched-over-the-whole-output`, `memory/gotchas/line-claim-matched-over-the-whole-output.md`,
  for the assertions on refusal lines). The policy walk does not see a placeholder row's instance the
  policy file leaves unset, whose value is derived prose naming no tag, and it adds no literal read
  of any key, so the policy kit's reader-coverage arm counts no reader for it. Gov's own value
  outside its field's order is not refused here, only read as the bottom of the order; a kind's
  own build plants that red on its pack if it wants one.
- testing: the fixture plants of §6, run by AC1 to AC11 and the self-test arm of §7, each red plant
  paired with the clean plant so a check that finds nothing is seen to find something.
- migration: additive; no kind declares a schema yet. The composer's eighth argument and sixth value
