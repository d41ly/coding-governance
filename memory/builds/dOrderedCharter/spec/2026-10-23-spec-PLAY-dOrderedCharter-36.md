## 1. Goal

The composition unit 35 produces is checked before it runs: a repository may not touch what gov
fixes, may not exclude a row something else still needs, and every widening it makes is classified
from declarations, never guessed. The checks are generic over every registered kind and declared per
kind in its schema, so a later build's kind joins by declaring its lists and planting its own reds.
They are seen red here on the fixture kind, which names no later build's kind. Today no kind declares
a fixed field or a widening direction anywhere, and no kinds register exists yet (unit 7's), so a
patch of any field would pass unclassified (flow-roles-adoption items 9 and 10, FA-1, FA-5).

## 2. Scope (IN)

- **S1** — The schema declarations each kind carries, in the row schema unit 35's optional `schema`
  key on a `[[kind]]` row of unit 7's kinds register `tools/playbook/kinds.toml` names. Per
  field, its `shape` (`set` or `scalar`), an optional `ref` role (`needs`, `actor` or `grants`), and
  either `fixed-by` or `widens`; per row, `[[fixed-row]]` with a tag and `fixed-by`. `fixed-by` is a
  non-empty list of sources from IA-4's three: `principle=<tag>`, `floor=<tag>` and
  `parser=<path#symbol>`. A typed `class` key is refused, so the class is derived and never typed. One
  reader, `read_kind_schema` in `tools/playbook/row_checks.py`. Observed by AC4 and AC5.
- **S2** — The derived class. A field or row is fixed when its `fixed-by` resolves, open when it
  declares `widens`, and fixed when it declares neither: an undeclared class reads as fixed. A field
  declaring both is refused as two answers. Each `fixed-by` source must resolve: a `principle` tag in
  unit 7's principle registry, a `floor` tag through the tag resolver once the floor's namespace is
  registered, a `parser` source as a tracked file defining that symbol. Observed by AC4 and AC5.
- **S3** — The fixed set refusals. An `amends` patch naming a fixed field is refused, and refused as a
  widening of a fixed field when the classifier reads it widening; a `supersedes` of a fixed row and
  an `instructions.exclude` entry naming a fixed row are each refused. Each refusal names the row, the
  field where one applies, and the `fixed-by` source. Observed by AC1, AC2 and AC3.
- **S4** — The exclusion refusals. An `instructions.exclude` entry is refused, naming the requirer, when
  another active row of any registered kind holds the excluded tag in a field whose `ref` role is
  `needs`, `actor` or `grants`; and refused, naming the key, when a tag-valued policy key's value names
  it. Observed by AC6.
- **S5** — The widening classifier. Each open field declares the direction that widens it: `add` on a
  permission set, `remove` on a constraint set such as `needs`, or an ordered list on a scalar whose
  later values are wider. Every patch operation is classified `widens` or `narrows` from those
  declarations alone, and an open field with no declared direction is refused. Observed by AC7 and
  AC8.
- **S6** — The widening list, `derive_widenings(composition)`, every patch operation the classifier
  reads `widens`, each with its row, field, operation and gov's value; unit 34's delta report prints it
  and is its one source. Observed by AC9.
- **S7** — The checks run on the composition, never on the overlay text: `check_rows(kind, schema,
  composition, exclude, policy)` is called by unit 35's `compose_rows` after it composes, and a
  finding refuses the composition. Observed by AC1 to AC8 and AC10.
- **S8** — The fixture kind's planted reds, added to `tools/playbook/fixtures/row_kind.py`: its schema
  gains a fixed field, a fixed row, an undeclared field and a reference field of each `ref` role, and
  each refusal of S3 to S5 is one plant. No plant names a later build's kind. Observed by AC1 to AC8,
  AC10 and AC11.
- **S9** — The page section on what a repository may not change and how a widening is reported, in
  `help/overlay-rows.md` (unit 35's page). Observed by AC12.

## 4. Design

### Data model

The fixture kind's schema after this unit (S8), one file in the fixture's scratch tree:

```toml
[kind]
name = "fixture"
owner-seat = 1

[[field]]
name = "grants"          # a permission set: adding widens
shape = "set"
ref = "grants"
widens = "add"

[[field]]
name = "needs"           # a constraint set: removing widens
shape = "set"
ref = "needs"
widens = "remove"

[[field]]
name = "actor"
shape = "scalar"
ref = "actor"
widens = ["fixture.low", "fixture.high"]

[[field]]
name = "ceiling"         # an ordered scalar: a later value is wider
shape = "scalar"
widens = ["low", "mid", "high"]

[[field]]
name = "witness"         # fixed: a parser reads it
shape = "scalar"
fixed-by = ["parser=tools/playbook/fixtures/row_kind.py#read_witness"]

[[field]]
name = "note"            # undeclared: read as fixed
shape = "scalar"

[[fixed-row]]
tag = "fixture.delta"
fixed-by = ["principle=principle.p16"]
```

Rules the reader enforces, each a refusal naming the file and the field: an unknown key; `class`
anywhere; a `shape` outside the two; a `ref` outside the three; `widens` and `fixed-by` together; a
set field whose `widens` is not `add` or `remove`; a scalar whose `widens` is not a list of at least
two distinct values; an empty `fixed-by`; a source whose type is not one of the three.

**Resolution of `fixed-by`.** `principle=<tag>` resolves when the tag is a `[[principle]]` row of unit
7's principle registry `tools/playbook/principles.toml` (its example row is `principle.p16`, "The core
cannot be built around."); the fixture's scratch tree reads gov's own registry, read-only. `floor=<tag>` resolves through the tag resolver (`gov tag show`, S5) once the floor's
namespace is registered; before it registers, the source is refused naming the namespace, so no kind
claims a floor that does not exist. `parser=<path#symbol>` resolves when the path is tracked and an AST
or shell scan of it defines the symbol, the form unit 26 lands for positional citations.

**The classifier.** For a patch operation on an open field:

| Field | Operation | Class |
|---|---|---|
| set, `widens = "add"` | `add` | `widens` |
| set, `widens = "add"` | `remove` | `narrows` |
| set, `widens = "remove"` | `remove` | `widens` |
| set, `widens = "remove"` | `add` | `narrows` |
| scalar, ordered list | a value later in the list than gov's | `widens` |
| scalar, ordered list | a value earlier in the list than gov's | `narrows` |
| scalar, ordered list | a value not in the list | refused, naming the field and the value |

A whole-row `supersedes` is classified field by field against gov's row it answers to, so a
replacement cannot widen what a patch could not.

**The exclusion walk.** For each tag `instructions.exclude` lists, every active row of every
registered kind's composition is read for fields whose `ref` role is `needs`, `actor` or `grants`; a
row holding the tag in one is the requirer, and the refusal names its tag and the field. Every
catalogue key whose declared value type is a tag or a set of tags is read through the policy reader; a
value naming the tag refuses, naming the key. An excluded row that is itself the only requirer of
another excluded row does not refuse, because neither is active.

### Alternatives rejected

- **A typed `class = "fixed"` per field**: refused by the clause ("never typed") and by systems
  `[design-instruction-writing]`, where the class is derived from the parsers and the floor.
- **Widening judged per patch by its author**: FA-5's report would then compare a claim with nothing;
  the directions are declared once per field so the classifier and the report read one fact.

  (`tools/memory-tree/deviation_join.py:150`): it grades a record's departure, five classes, while a
  patch is only wider or narrower; the switch at landing maps the two.

## 5. Production-readiness checklist

- security: this unit is the deny half of the overlay's row write: an undeclared class reads fixed, a
  field with no direction refuses, and a fixed row cannot be patched, replaced or excluded, so a
  repository widens only what a kind opened.
- perf / scale: one schema read per kind; the exclusion walk is linear in the composition's rows per
  excluded tag.
- error / empty / loading states: a kind with no schema refuses naming the kind; an empty exclusion
  list and a composition with no patch return no finding and say how many rows they read.
- observability: every refusal names the row, the field, the source or the requirer; every widening is
  one line in the list S6 returns.
- risks: a kind that opens a field it should have fixed is not caught here, only by its own build's
  planted reds; a `parser=` source proves a symbol exists, never that it reads the field
  (`line-claim-matched-over-the-whole-output`, `memory/gotchas/line-claim-matched-over-the-whole-output.md`,
  for the assertions on refusal lines).
- testing: the fixture plants of §6, run by AC1 to AC11 and the self-test arm of §7, each red plant
  paired with the clean plant so a check that finds nothing is seen to find something.
- migration: additive; no kind declares a schema yet.
- user docs: the section in `help/overlay-rows.md` (S9).
