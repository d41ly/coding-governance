## 1. Goal

P34 holds that a record section and an instruction unit are written alike: addressed by a tag, one
subject each, every relation a typed edge, every quoted derived fact pinned, rationale kept apart
from what loads, one door and one owner per node, and a retired name never reused (the memory plan's
`[practice]` table). Today each of those is policed per instance or not at all, and over units only
where it is policed (`gap-found-23`: "one fact in one place is policed per instance, never as a
class"). This unit makes the practice a catalogue row whose rules each name a check, adds the checks
that do not exist, and widens the ones that do so they read records as well as units: `one-owner`
as a check of its own name, never the tags pack's `owned`, and `retired` over sections as well as
tags. Today's unpinned facts become a keyed list until dWitnessedBar's migration registers it.

## 4. Design

[[practice]]
tag = "practice.writing"

rules = ["address", "one-subject", "typed-relations", "pinned-facts", "one-door", "rationale-apart", "one-owner", "retirement"]

### The populations

- Units: every row the S10 reader returns, `text` or `source`, `help`, `owner`, `origin`, `tag`.
- Records: `git ls-files -- '<memory_root>/*.md'`, minus the generated regions between `<!-- gen:` and
  `<!-- /gen:` markers, which no writer authors. A section is a `##` heading and its lines up to the
  next; its slug is GitHub's.
- Registered documents: PLAY-dOrderedCharter-3's `read_document_registry`, their rendered files.

Each arm prints `<arm>: <n> units · <m> records · <k> documents` and refuses a zero in a population
it reads (the charter's `[gate]` rule: an empty population is not coverage).

### `pinned-facts`, its predicate

Reads: a number of one or more digits, commas allowed, followed within one space by a word of
`FACT_UNITS` (`bytes`, `B`, `KB`, `KiB`, `MB`, `lines`, `files`, `legs`, `units`, `rows`, `specs`,
`records`, `commits`, `citations`, `tokens`, `calls`, `seconds`, `s`), outside fenced blocks and inline
code. A pin on the same line: `\b[0-9a-f]{8,40}\b`, a `path:<n>` or `path@<oid>:<n>` citation, or
`PINNED` or `DERIVED`. Does not read: a fact spelled in words ("eight legs"), a percentage, a number
inside code or a fence, a pin on a neighbouring line, and whether a pin is true. `--explain` prints
both lists.

## 5. Production-readiness checklist

- security: read-only checks; the door list adds no write path, and S5 names a writer only by a
  tracked path.
- perf / scale: one pass over about 3,000 records (the recall index counted 3,168 records,
  2026-10-23, PINNED) and the unit rows; each arm reads the populations once.
- error / empty / loading states: an empty population refuses; a frozen record's red is printed and
  held by the keyed list.
- observability: each arm prints its population counts and, under `--explain`, its predicate.
- risks: `pinned-facts` is a lexical predicate and flags a number that is not a derived fact; the
  keyed list absorbs today's, and `--explain` says what it cannot tell apart.
- testing: `--fixture --plant` cases for every arm (AC2-AC9).
- migration: the keyed list's seed.
- user docs: `help/charter.md` lists the new practice from the catalogue; no command an owner runs.
