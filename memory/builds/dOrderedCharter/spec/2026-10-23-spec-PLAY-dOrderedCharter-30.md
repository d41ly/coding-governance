## 1. Goal

No practice gives each language its role: shell grows outside shims, and each kit picks its own
launch, encoding and path idioms (`gap-tool-19`). The charter carries two loose practices instead,
`[bytes]` (LF and staged bytes) and `[cross-os]` (slashes, installs, run modes), neither naming a
leg. This unit replaces both with one practice row, `practice.portable` (P37): Python carries logic,
shell is a thin shim, JavaScript serves only the harness, and one rule set for encoding, line
endings, paths, launch, temp files, interpreter floors and quoting, each rule paired with its named
leg in a core kit, the floor's in dSafePassage and the rest in dWitnessedBar's portability pack. The
pairing is a join the meta-check grades both ways, so a rule cannot exist as prose alone.

## 4. Design

### Data model

```toml
[[practice]]
tag = "practice.portable"
line = "Python for logic, shell as a thin shim, JavaScript for the harness; encoding, line endings, paths, launch, temps, the interpreter floor and quoting each have a leg."
rules = ["encoding", "line-endings", "paths", "launch", "temp-files", "interpreter-floor", "quoting", "language-roles"]

[practice.reach]
build = "text IO names its encoding, LF on execution-sensitive files, temps unpredictable, interpreters through the resolver"
test = "verify the staged bytes, never a pretty-printer's view of them"
```
