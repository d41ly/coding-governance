## 1. Goal

No practice gives each language its role: shell grows outside shims, and each kit picks its own
launch, encoding and path idioms (`gap-tool-19`). The charter carries two loose practices instead,
`[bytes]` (LF and staged bytes) and `[cross-os]` (slashes, installs, run modes), neither naming a
leg. This unit replaces both with one practice row, `practice.portable` (P37): Python carries logic,
shell is a thin shim, JavaScript serves only the harness, and one rule set for encoding, line
endings, paths, launch, temp files, interpreter floors and quoting, each rule paired with its named
leg in a core kit, the floor's in dSafePassage and the rest in dWitnessedBar's portability pack. The
pairing is a join the meta-check grades both ways, so a rule cannot exist as prose alone.

## 4. Design

### Data model

```toml
[[practice]]
tag = "practice.portable"
line = "Python for logic, shell as a thin shim, JavaScript for the harness; encoding, line endings, paths, launch, temps, the interpreter floor and quoting each have a leg."
rules = ["encoding", "line-endings", "paths", "launch", "temp-files", "interpreter-floor", "quoting", "language-roles"]
[practice.reach]
build = "text IO names its encoding, LF on execution-sensitive files, temps unpredictable, interpreters through the resolver"
test = "verify the staged bytes, never a pretty-printer's view of them"
review = "a portability rule broken while its leg stays green is a finding against the leg"
```

The rendered line `- [portable] <line>` is 177 bytes, under `ONE_LINE_MAX` (200,
`tools/playbook/render_playbook.py:129`), PINNED at writing; the reader's check re-derives it on every
read. `[bytes]`'s "verify the staged bytes" survives as the `test` reach; `[cross-os]`'s slashes and
native installs are the `paths` and `launch` rules.

### The pairing

| Rule tag | Leg carrying it in `enforces` | Pending, armed by |
|---|---|---|
| `practice.portable.encoding` | `encoding posture (text IO names its encoding)` | — |
| `practice.portable.line-endings` | — | dWitnessedBar, the line-ending class leg |
| `practice.portable.paths` | `shell hygiene (a location probe asked from a moved directory)` | — |
| `practice.portable.launch` | `python resolver (behaviour + inline parity + idiom ban)` | — |
| `practice.portable.temp-files` | `shell hygiene (a fixed-name temp renamed into place)` | — |
| `practice.portable.interpreter-floor` | `python resolver (behaviour + inline parity + idiom ban)`, whose floor arms TOOL-dSafePassage-11 lands | — |
| `practice.portable.quoting` | — | dWitnessedBar, the quoting arm |
| `practice.portable.language-roles` | — | dWitnessedBar, the shell-role ledger |

Each leg named is in `tools/gate-legs.json` at base; the table is the build run's input, and its
truth lives in the legs' `enforces` and the pending rows, never in a third place. When a pending
row's build lands its leg with the tag, the meta-check reds the pending row as stale, which is how
the join hands over.

### The meta-check's widening

`core.py meta-check` reads the practice population through `read_practice_catalogue`. For a row with
`rules`, the population holds the row's tag and each `practice.<name>.<rule>` tag; the row's own tag
is enforced when every rule tag is enforced or pending. The join is the one PLAY-dOrderedCharter-7
runs through S2's `compute_coverage`; this unit adds population members, not a second join.

### Inventory

`practice.portable.encoding`, `practice.portable.line-endings`, `practice.portable.paths`,
`practice.portable.launch`, `practice.portable.temp-files`, `practice.portable.interpreter-floor`,
`practice.portable.quoting`, `practice.portable.language-roles`; three pending rows. Retired: the tags
`practice.bytes` and `practice.cross-os` and the `rules:` values `bytes` and `cross-os?`. Naming
cells: unit 10's tag shape check grades every tag above.

### Migration

An adopter whose `charter.practices` names `practice.bytes` or `practice.cross-os` gets a refusal
naming the tag and its successor `practice.portable`; with no value set it reads the `foundation`
default, which carries the successor. An adopter's `drop_blocks` `cross-os` is unchanged in effect
on the toolchain section, and the render's note says it no longer drops a practice.
