## 1. Goal

About 25 load-bearing documents reach agents by six routes, and none carries its identity or its
level, so nothing tells an agent which one wins or rebuilds their order after a reset (gap-found-01).
This unit registers every load-bearing instruction document with its level and a one-line direction,
wraps each in the envelope S16 fixes, `[<doc> · Level <n> · <direction>]` … `[/<doc>]`, emitted by
whatever renders that document, and adds a gate holding every registered document to its envelope and
every load-bearing document to a registry row (foundations R2, v2:949-957 P13, layer-instruction R-A).
One registered document, `memory/guides/BUILD-METHOD.md`, is held out of its envelope until the owner
rules on its row (S9, F5): the gate names it as not checked on every run and never counts it as covered.

## 2. Scope (IN)

- **S1** — The document registry, `tools/playbook/documents.toml`: one `[[document]]` row per
  document with `tag` (`doc.<name>`), `path`, `level` (an S8 level, read from `LEVELS` in
  `tools/playbook/instruction_units.py`), `direction` (one line, no `]`), and `source` (the file the
  envelope is written from). A `path` may hold one `*` segment, so the role agent files and the Skills
  are each one row, every file the glob matches enveloped alike. Paths spell the adopter's roots through
  `{memory_root}` and `{prefix}`, resolved at read by the kit's own readers, as
  `tools/playbook/instruction_units.py#run_ladder_terms` resolves its sources: `{prefix}` first, through
  the inline `resolve_prefix_token` of `tools/playbook/tag_index.py` against
  `tools/playbook/instruction_units.py#derive_kit_prefix`, then `{memory_root}` from
  `tools/playbook/instruction_units.py#derive_instruction_tokens`. The registry itself is found through
  `tools/playbook/instruction_units.py#derive_kit_file`, so no line of the kit spells a kit path, which the
  shipped-surface ban reds since unit 72. The
  reader is `read_document_registry` in `tools/playbook/instruction_units.py`. A row for the charter or
  a guide carries the tag the `doc` namespace already derives for that file, `doc.charter` or
  `doc.<file stem, lower-cased>` (`PLAY-dOrderedCharter-19` S3); the class rows for Skills, path rules
  and agent files carry tags that namespace does not derive, so its extractor `extract_doc`
  (`tools/playbook/tag_index.py`) gains this registry's rows in its population, one declaring source
  for both. Each row whose tag that namespace does not derive, the class rows and the deploy Skill's,
  also carries `h1`, one line naming what its files are: the `doc` namespace's `purpose-source` is
  `#h1` (`tools/playbook/namespaces.toml@c7269a97:20`), and the purpose arm reads a `.toml` member's
  field off its own row (`tools/playbook/tag_index.py#check_namespace_purpose`, through
  `tools/playbook/tag_index.py#read_toml_field`), so a class tag with no `h1` reds on the first tags run.
  A charter or guide row carries none, its file's own `# ` line being its purpose. The `doc` row's
  `source` text (`tools/playbook/namespaces.toml@c7269a97:17`) gains this registry's rows, spelled
  `{prefix}/playbook/documents.toml`, the tool-root token every path of that file takes since unit 72. A row may also
  carry `hold`, S9's field, which the reader validates. Observed by AC1 and AC12.
- **S2** — The seeded rows (§4 Inventory): the charter at level 0, every guide under
  `{memory_root}/guides/`, `TEMPLATE-SPEC.md` and `HYGIENE.md` at level 3, every Skill and path rule
  at level 4, and the role agent files at level 5. The `memory/guides/BUILD-METHOD.md` row is seeded
  like its sibling guides and also carries S9's `hold`. Observed by AC1.
- **S3** — The helper. `render_envelope(doc, level, direction, body)` and `read_envelopes(text)` live
  canonically in `tools/lib/envelope.py`, and are carried inline, byte-identical, as a
  `# >>> render_envelope — canonical copy` block in `tools/playbook/render_playbook.py` and
  `tools/roles/roles_lib.py`, because both kits are copy-installed and `tools/lib/` travels to nobody.
  A `PARITY_ROWS` row in `tools/lib/resolve-python.test.sh` gates both copies. Each copy's marker line
  names its canonical file as the existing rows' markers do, `envelope.py in the gov lib dir`, never by a
  kit path. Observed by AC2.
- **S4** — Emission by the Python renderers. `render()` wraps the `gov:playbook` region's body in the
  charter's envelope, inside the two region markers. `render_agent_file`
  (`tools/roles/render_agents.py:144`) wraps each agent file's body after its front matter. Each finds
  the registry from the tree it renders, never from the module's own install: the charter's render
  through `tools/playbook/instruction_units.py#derive_kit_file` under the target, and the roles render
  through its inline `resolve_kit_dir`, homed at `playbook` with `documents.toml` its anchor, anchored at
  the `kit_dir` the render is handed. Where no registry is found, or no row's path matches the file, the
  render writes no envelope and prints nothing, so a fixture tree with no registry renders the bytes it
  renders today. Three exact-byte checks rest on that: the pipe-in-prose arm of
  `tools/playbook/render_playbook.py#run_selftest`, `tools/playbook/instruction_units.py#arm_slots`, and
  arm 4 of `tools/roles/render_agents.py#run_selftest`, whose fixture kit has no playbook kit beside it.
  `tools/roles/roles_lib.py#parse_charter` drops every line `read_envelopes` reads as an opener or a
  closer before it cuts the region into sections. It carries the Facts section to the region's end, so
  without the drop `[/AGENTS.md]` would ride into the Charter block of every agent file and handoff, and
  S6 would red each as a closer naming another document. Observed by AC3.
  **Readers:** by name: `tools/roles/roles_lib.py` defines `parse_charter`, and `tools/roles/check_roles.py`,
  `tools/roles/handoff.py` and `tools/roles/render_agents.py` call it; no name is retired, only lines
  from its output. by value: `tools/roles/roles_lib.py#render_charter_blocks`, which renders a role's
  Charter block from the sections `parse_charter` returns, and `tools/roles/check_roles.py`, whose rule
  tag checks read them; neither reads an envelope line today.

## 4. Design

### Data model

```toml
[[document]]
tag = "doc.charter"
path = "AGENTS.md"
level = 0
direction = "Non-negotiable project instructions, always enforced unless the owner explicitly overrides them; the override is recorded"
source = "coding-governance-agents.template.md"

[[document]]
tag = "doc.build-method"
path = "{memory_root}/guides/BUILD-METHOD.md"
level = 3
direction = "Read whole before a build of more than one pass; yields to levels 0 to 2"
source = "{prefix}/memory-tree/BUILD-METHOD.template.md"
hold = "PLAY-dOrderedCharter-3 F5"

[[document]]
tag = "doc.agents"
path = ".claude/agents/*.md"
level = 5
direction = "This role's static instructions; yields to levels 0 to 4"
source = "{prefix}/roles/agents/"
h1 = "The role agent files, one per rendered role"
```

The charter's direction is the owner's form (layer-instruction:376, v2:1094). An envelope line is
`[<path> · Level <n> · <direction>]`, the rendered path being the document's own repo-relative path,
and the closer `[/<path>]`; both are whole lines.

`hold` is optional, `HOLD_RE` is its shape, and `check_hold` in `tools/playbook/instruction_units.py`
owns S9's statement and arms. `read_cap_value(cap, root, rev)` sits beside `read_policy_value` in
`tools/playbook/policy_value.py`. It puts the policy kit on `sys.path` through `resolve_kit_dir`, as
`tools/playbook/instruction_units.py#load_memory_tree_path` does for the memory-tree kit, calls
`tools/policy/budgets.py#resolve_caps` with `rev`, and returns the cap's value. A `LookupError`, a
policy `Refusal` or a value of `None` raises `PolicyRefused`.

## 5. Production-readiness checklist

- security: no write path; the envelope carries no value from outside the registry.
- perf / scale: the gate reads about 35 files once, and one cap through the policy kit.
- error / empty / loading states: an absent registry or an empty load-bearing population refuses with
  exit 2, never reads green. So do a malformed `hold` and a held row whose cap reads no value.
- observability: the gate prints the covered count, one `HELD` line per held row, one `ALIAS` line per
  entry file it leaves out, and one line per offender.
- risks: four documents sit at or near their rows (S7), one the owner's (F5); a raise is a decision row,
  not a silent edit. That document is held (S9), so until the ruling it carries no envelope and an agent
  reading it sees no level. The gate states that on every run, and three arms end the hold once its
  state moves.
- testing: §6 and the `New arm:` lines of §7.
- migration: §4 Migration.
- user docs: `help/charter.md`, created by `PLAY-dOrderedCharter-1`, gains a paragraph on levels and
