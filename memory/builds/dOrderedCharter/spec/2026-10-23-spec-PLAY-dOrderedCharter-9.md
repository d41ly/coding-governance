## 1. Goal

Instructions map to almost nothing below them (gap-found-09): sections carry tags, only the roles kit's
`rules:` key joins a role to the charter, checklist items are numbered, and no registry joins an
instruction to the step, item, policy or layer it serves, so no loader can select an agent's instructions by
its item. R-A makes the unit the atom and every document a rendering of units. This unit lands the registry
(S10): one `[[unit]]` row per unit in each kit's `instructions.toml`, carrying the fields the clause lists,
`required-by` among them (C1-F1), one reader every consumer reads rows through, and the selection and
per-unit rendering a document is assembled from.

## 2. Scope (IN)

- **S1** — The row, `<kit>/instructions.toml`, one `[[unit]]` table per unit, with S10's fields:

  | Field | Holds |
  |---|---|
  | `tag` | the unit's tag in the `unit` namespace, `unit.<seg>[.<seg>]` |
  | `level` | an S8 level, read through `parse_level` |
  | `type` | an S9 statement type, one of `STATEMENT_TYPES` |
  | `scope` | the selector tags that load it, `reader.every` for every reader |
  | `trigger` | the condition under which it loads, a tag or `always` |
  | `budget` | its budget class, `line` (at most 200 bytes) or `block` (at most 600 bytes) |
  | `text` | its typed text, one line, for the four typed statement types |
  | `source` | where a derived unit's value comes from, `policy:<key>`, `probe:<name>` or `cmd:<command>` |
  | `owner` | the chain build that owns it |
  | `usage` | how a user invokes it, on a user-facing unit |
  | `help` | its rationale, which never loads |
  | `required-by` | the role and item tags that require it |
  | `enforced-by` | what refuses a bypass, spelled as `tools/roles/workflows.toml` spells it for `check_roles.py`: a list of descriptions, a hook's entry opening with its `.js` file name, or the one string `none — <why>` |
  | `class` | `fixed` or `open` |
  | `edges` | S6 edge strings, `type=target[,target]` |

  Observed by AC1.
- **S2** — The one reader, `read_units(root)` in `tools/playbook/instruction_units.py`, returning a `Unit`
  per row of every `instructions.toml` beside the kits, found as `<prefix>/*/instructions.toml` with
  `<prefix>` the parent of the module's own kit directory (`tools/` in gov), in path then row order. It
  derives `origin`, the kit id whose manifest holds the row, never read from the row; reads `class` as
  `fixed` where a row declares none; parses `level` through `parse_level` and `edges` through unit 24's
  parser; and raises `UnitRowError` naming the file and the row's index or tag for what it cannot read: a
  TOML error, a `[[unit]]` that is not a table, a field of the wrong TOML type, an unparseable level or
  edge. Field rules beyond that (required fields, known keys, closed sets, sizes) are unit 20's schema
  check, which reads rows through this reader. Observed by AC2 and AC3.
- **S3** — One reader in fact. Unit 19's `extract_unit` and unit 12's grammar leg read rows through
  `read_units` and parse no `instructions.toml` of their own; the overlay `.governance/instructions.toml`
  is composed onto these rows by unit 32's reader, which calls this one for the kit rows. Observed by AC4.
- **S4** — Documents rendered from units. `derive_unit_selection(units, selector)` returns the units a document
  holds: those whose `scope` holds a selector tag or `reader.every`, ordered by level, then manifest path,
  then row order. `render_unit(unit, policy_reader)` returns the line a unit loads as: its `text` for a
  typed unit, the value dGroundRules' reader returns for `policy:<key>`, and the output of its probe or
  command for a `fact`, never typed text. `render_units` joins them, one line per unit. Unit 20's renderer
  of record calls these for every template slot. Observed by AC5.
- **S5** — The leg arms. Unit 12's `instruction grammar (statement types, provenance lock)` leg grades every
  row `read_units` returns from this pass on, and unit 19's `unit` namespace reads its population from
  it; with no row in the tree each prints `unarmed`, naming the unit that writes the first rows, never
  green. Observed by AC4.
- **S6** — The plants. `python tools/playbook/instruction_units.py fixture --plant <case>` builds a
  throwaway tree in the system temp directory with two kits' manifests and runs the case. Observed by AC1
  to AC5.

## 4. Design

### Data model

```toml
# tools/<kit>/instructions.toml
[[unit]]
tag = "unit.reuse-first"
level = 3
type = "directive"
scope = ["role.spec-writer"]
trigger = "always"
budget = "line"
text = "MUST probe the map, then recall, once per spec set, and record the seam or that none fits."
owner = "dOrderedCharter"
required-by = ["role.spec-writer"]
enforced-by = ["spec tokens (a spec's own names resolve)"]
help = "A spec set that skips the probes rebuilds what exists."
edges = ["instructs=role.spec-writer"]
```

```python
@dataclass(frozen=True)
class Unit:
    tag: str; level: int; type: str; scope: tuple; trigger: str; budget: str
    text: str | None; source: str | None; origin: str; owner: str | None
    usage: str | None; help: str | None; required_by: tuple; enforced_by: tuple | str
    klass: str; edges: tuple; path: str; index: int
```

### Alternatives rejected

- **`origin` typed on every row.** The manifest's location already names the kit, and a typed copy can
  disagree with it (`[derive]`).
- **One registry file for every kit's units.** R-I gives each kit its own manifest, and a kit's units ship
  with the kit.
- **The schema check inside the reader.** One check in one place: unit 20's schema check grades rows the
  reader returns, so the reader refuses only what it cannot read.

## 5. Production-readiness checklist

- security: read-only; the reader opens only `instructions.toml` files under the kit prefix and runs no
  probe or command, which `render_unit` runs only through the source's own registered probe.
- perf / scale: one TOML parse per kit manifest per process.
- error / empty / loading states: an unreadable row raises `UnitRowError` naming its file and index; an
  empty population prints `unarmed`, never green.
- observability: every refusal names the manifest, the row and the field.
- risks: a kit outside the prefix's children is invisible to the reader; every kit installs as a child of
  `<prefix>` today.
- testing: S6's plants both ways.
- migration: none.
- user docs: N/A — unit 37 renders the registry's reference page from its rows.

## 6. Acceptance criteria

- **AC1** — When `python instruction_units.py fixture --plant row` runs, a row carrying every
  S1 field reads back as a `Unit` whose fields equal the row's, its `origin` the fixture kit's id and its
  `class` `fixed` where the row declares none.
  Red when: a field is dropped, `origin` is read from the row, or an undeclared class reads `open`.
- **AC2** — When `python instruction_units.py fixture --plant two-kits` runs, `read_units`
  returns the rows of both kits' manifests in path then row order, and a manifest outside the prefix's

  Red when: a kit's rows are missing or out of order.
- **AC3** — When `python instruction_units.py fixture --plant unreadable` runs, a TOML
  error, a `level = "nine"` and an `edges` entry with no `=` each raise `UnitRowError` naming the file and
  the row.
  Red when: an unreadable row is skipped or read as a default.
- **AC4** — When `git grep -n "instructions.toml" -- tools/playbook/` runs, the only parse of the file is in
  `read_units`, and `python instruction_units.py fixture --plant arms` shows unit 12's
  grammar half and unit 19's `unit` namespace each grading the fixture's rows, and printing `unarmed` with
  none.
  Red when: a second parser of the manifest exists, or an empty population reads green.
- **AC5** — When `python instruction_units.py fixture --plant render` renders the selector
  `role.builder` over four rows, one of them a `policy-value` with `source = "policy:tags.slice"` and one a
  `fact` with `source = "cmd:git rev-parse --abbrev-ref HEAD"`, it prints one line per selected unit in
  level order, the policy line carrying the key's value and the fact line the command's output.
  Red when: a unit outside the selector renders, the order breaks, or a derived unit renders typed text.
