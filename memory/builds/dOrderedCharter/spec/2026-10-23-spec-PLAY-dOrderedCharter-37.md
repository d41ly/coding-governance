## 1. Goal

A reader of `help/` finds each policy key, drive row, kind and instruction unit on a reference page the
one renderer writes from the registry row that defines it, so a page can never say something its row
does not; the concept, task and tutorial pages beside them are authored, and every command any page
shows is run, the tutorial in an adopter fixture. P42: "every user-facing surface is documented from
the fact that defines it", and the owner's FQ-5. Today `help/` holds two hand-written pages and an
index (`help/README.md`), no tool renders a page from a row, and the renderer only substitutes
placeholders (`render()`, `tools/playbook/render_playbook.py:979-1051`). The docs leg that gates pages
is dSafePassage's (TOOL-dSafePassage-13); this unit extends it and `tools/govkit/usage.toml`, never a
copy of either.

## 2. Scope (IN)

- **S1** — The reference declaration, `tools/playbook/references.toml`: one `[[reference]]` row per
  registry, with `registry` (a `doc.` tag), `reader` (`<path under the tool root>:<function>`,
  returning the registry's rows), `page` (a path under `help/reference/`) and `unit` (the instruction
  unit tag the page documents). It ships four rows: the policy schema's (dGroundRules' catalogue,
  `cl-dClosedLoop-0007`), the drive table's (unit 6's `[[drive]]` rows), the kinds register's (unit
  7's `tools/playbook/kinds.toml`) and the unit registry's (unit 9's `<kit>/instructions.toml` rows).
  A later registry joins by adding its row, which its own build lands. Observed by AC1 and AC2.
- **S2** — The render. `python tools/playbook/render_playbook.py --reference` writes each declared
  page from its reader's rows: one section per row, its tag, its `summary` and its `usage`, each
  section carrying the docs leg's anchor `<!-- usage: <id> <fp8> -->` with the fingerprint the leg
  computes, and the page carrying `<!-- unit: <tag> -->` for its row's `unit`. `--reference --check`
  compares every page with its render. A row with no `summary` or no `usage` refuses the render,
  naming the registry and the row. Observed by AC1, AC3 and AC4.
- **S3** — Both ways. A declared page with no rows (an empty population) refuses, a page under
  `help/reference/` that no row declares refuses, and a `reader` that does not load refuses, each
  naming it. Observed by AC2.
- **S4** — The docs leg, extended. `tools/govkit/docs_leg.py` (TOOL-dSafePassage-13) gains
  `--fingerprints`, printing `<id>\t<fp8>` for every member its rows declare, which the render reads
  in a child process so the fingerprint has one computation; and a `--run` arm that runs every command
  a page under `help/` shows, each page's fenced `bash` and `console` blocks in order in a fresh
  scratch adopter, each command expected to exit 0 unless the block is preceded by
  `<!-- expect: <code> -->`, and a block preceded by `<!-- run: no — <reason> -->` counted and printed
  with its reason. Observed by AC5 and AC6.
- **S5** — The classes. Each registry S1 declares is a class of `tools/govkit/usage.toml` with its
  usage shape, so the leg's stale-page and orphan arms grade the rendered anchors: the policy schema's
  rows are its `key` shape, already declared there; the drive rows, the kinds register's rows and the
  units with a `usage` field each gain a `[[class]]` row. Observed by AC3.
- **S6** — The authored pages: `help/concepts/instruction-layer.md` (the ladder, units, the overlay and
  composition, linking each unit's page), `help/tasks/change-a-gov-rule.md` (amend, replace, exclude and

  repository rule, render and read the delta report), each linked from `help/README.md`. Observed by
  AC6 and AC7.
- **S7** — The tutorial in an adopter fixture. `--run` runs `help/tutorial/adopt-gov.md` from an empty
  scratch repository with gov's checkout at `$GOV`, in the target `build_target` (TOOL-dSafePassage-5
  S12) builds, so the page is the install path an adopter follows. Observed by AC6.
- **S8** — Each page linked to its unit by tag. Every reference, concept and task page carries one or
  more `<!-- unit: <tag> -->` lines; each tag resolves through the tag resolver (`gov tag show`, unit
  19's), and every instruction unit carrying a `usage` is named by at least one page. Observed by AC8.

## 4. Design

### Data model

```toml
# tools/playbook/references.toml
[[reference]]
registry = "doc.reference.kinds"
reader = "playbook/core.py:<the kinds reader unit 7 lands>"   # returns [{tag, summary, usage, ...}]; named at the build run
page = "help/reference/kinds.md"
unit = "unit.kinds-register"
```

A reader returns a list of mappings, each with `tag`, `summary` and `usage`; the render reads no other
field. The policy schema's `reader` and the unit registry's are the parents' own readers, named at the
build run as they land; the drive table's is unit 6's. A reader is loaded from the tool root by path,
the way the step gate loads a class reader (TOOL-dSafePassage-10 §4 "### Data model").

The rendered page, one section per row:

```markdown
<!-- gov:rendered from tools/playbook/references.toml doc.reference.kinds; edit the registry, not this page -->
<!-- unit: unit.kinds-register -->
# Kinds

## `kind.skill`
<!-- usage: kind.skill 3f2a91c0 -->
A Skill under `skills/<name>/`, made by `core.py new skill`.

`python tools/playbook/core.py new skill <name> --description <text>`
```

### The run arm

`docs_leg.py --run [--page <path>]` reads every page under `help/`, collects fenced `bash` and `console`
blocks (a `console` line's command is the text
after its `$ ` prompt), and for each page builds one scratch adopter with `build_target` under the
short `%TEMP%` path a fixture repository needs, exports `GOV` as gov's checkout, and runs the page's
commands in order in that target with `bash -c`, each bounded by a timeout. A non-zero exit where the
block declares none, or an exit different from a declared `expect`, is a finding naming the page, the
line and the command's last stderr line. A page whose every block is `run: no` is printed as such and
counted, never green by silence. `help.enforce` governs the verdict, as for the leg's other arms.

## 5. Production-readiness checklist

- security: `--run` executes commands written in tracked pages, in a scratch adopter under the run's
  own temp path and never in gov's tree, with no network fetch: a page command reaching the network
  must carry `run: no` and its reason.
- perf / scale: one scratch adopter per page; the leg's ceiling is measured at the build run and its
  `tools/run-gates/ceiling-evidence.txt` row written by `derive-ceilings.py --write`.
- error / empty / loading states: an empty registry, an unloadable reader and an orphan page each
  refuse naming it; a page with no runnable block says so.
- observability: every finding names the page and line; `--run` prints the count of commands run and
  of blocks declared `run: no`.
- risks: a page command that passes in the fixture and fails in a real adopter; the tutorial runs the
  real install path to narrow that (`fixture-passes-by-finding-nothing`,
  `memory/gotchas/fixture-passes-by-finding-nothing.md`).
- testing: AC1 to AC8, each on a planted case of the render or the leg.
- migration: additive; new pages only.
- user docs: this unit is the user docs (S6).

## 6. Acceptance criteria

- **AC1** — When `python tools/playbook/render_playbook.py --reference --check` runs after the pass, it
  exits 0 over the four declared pages; after a planted edit to one row's `summary` in a scratch copy
  of its registry, it exits 1 naming that page.
  Red when: a reference page drifts from its row and the check passes.
- **AC2** — When `python tools/playbook/render_playbook.py --reference --check` runs with a planted
  page `orphan.md` that no row declares, and again with a declared registry whose reader
  returns no row, each exits 1 naming the page or the registry.
  Red when: an orphan page or an empty population reads green.
- **AC3** — When `python docs_leg.py` runs after the pass, every anchor on the four
  reference pages matches its row's fingerprint; with a planted `usage` change in a scratch copy of one
  row it reports that page stale.
  Red when: the rendered anchors are not graded by the leg.
- **AC4** — When `python tools/playbook/render_playbook.py --reference` runs on a planted kinds row with
  no `usage`, it exits 1 naming `kind.<name>` and the registry, and writes no page.
  Red when: a row with no usage renders a section.
- **AC5** — When `python docs_leg.py --fingerprints` runs, it prints one `<id>\t<fp8>`
  line per member, and the render's anchors equal those lines.
  Red when: the render computes a fingerprint of its own.
- **AC6** — When `python docs_leg.py --run` runs after the pass, every page's commands exit
  as declared, the tutorial among them; with a planted page whose command exits 3 with no `expect`, it
  reports that page, line and command.
  Red when: a failing page command passes, or the tutorial is skipped.
  cost: one scratch adopter per page, minutes rather than seconds; measured at the build run.
- **AC7** — When `git grep -n -e "concepts/instruction-layer.md" -e "tasks/change-a-gov-rule.md" -e
  "tutorial/adopt-gov.md" -- help/README.md` runs, it finds the three index lines.
  Red when: an authored page ships unlinked from the index.
- **AC8** — When `python docs_leg.py` runs with a planted page carrying
  `<!-- unit: unit.nowhere -->`, it reports the tag unresolved; and over the tree after the pass, every
  instruction unit with a `usage` is named by a page.
  Red when: a page links no unit, or a user-facing unit has no page.
