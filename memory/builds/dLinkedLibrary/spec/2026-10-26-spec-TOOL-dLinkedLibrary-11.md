## 1. Goal

Comment load is unbudgeted: comments are 41% of code bytes and about 29% of commits add a long block
(gap-mem-18). The systems round set the budget, "a block a commit touches is at most 12 lines, and a
head line at most 160 B", with the untouched legacy blocks over 12 lines a ledger population keyed by
path and block anchor, and the resolve check's legacy a second one, never a count a drained block could
offset (`memory/builds/dClosedLoop/build/2026-10-16-build-PLAY-dClosedLoop-1-systems.md:334-337`;
retrofit, `2026-10-17-build-PLAY-dClosedLoop-1-retrofit.md:155-157`). This unit adds the budget arm and
registers both populations through the ledger factory, so the `annotation-resolve-legacy` rows hold
what TOOL-dLinkedLibrary-4's resolve arm finds unresolved at seed, `untouched-long-blocks` holds every
long block no commit has touched, and each shrinks only.

## 8. Open questions

- **F1 — What happens to drift's `source_cited_ids_resolving_to_no_record` once the legacy is a keyed
  population?** Options: (a) the signal and its pin row retire, the resolve arm and its ledger the one
  reader; (b) the signal stays report-only and pinless; (c) both stay. (c) holds one tolerance in two
  homes, a scalar and a keyed list, and (b) keeps a second answer to "does a source citation resolve"
  over a population the arm reads differently, ids in any text against ids in comment lines, so the
  two disagree on a string literal. (a) narrows what is reported: an id cited only inside a string
  literal is graded by nothing, which §5's risks would otherwise hide, and the arm gates what drift only
  reported. RESOLVED (agent, 2026-10-26, delegated): (a), rung 3, the most feature-rich survivor, a
  gate where there was a report, by drift's own rule that two readers of one question are two answers
  to it. widens: none · relaxes: none
- **F2 — What keys a block?** Options: (a) `derive_pin_hash` of its first comment line, with an ordinal
  for a repeat; (b) the enclosing definition's qualified name; (c) the block's line number. (c) is
  refused by the factory, and (b) leaves a top-level block and two blocks in one definition without a
  key. RESOLVED (agent, 2026-10-26, delegated): (a), rung 3, the only option keying every block, and
  the tie-break's reuse of `derive_pin_hash`, the normaliser the chain's pins share. widens: none · relaxes: none
