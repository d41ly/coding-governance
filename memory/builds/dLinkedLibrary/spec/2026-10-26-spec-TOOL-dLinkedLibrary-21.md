## 1. Goal

A language other than Python, shell and JavaScript stays at file level in the `code` record, so an
adopter written in Go, Java or Rust gets no definitions, ranges or calls for it (gap-mem-34). This
unit adds the `ctags` extractor pack the owner chose as an opt-in (NP-10): under
`memory.code-languages: builtin+ctags` or `ctags`, Universal Ctags supplies definitions and their
ranges for every language the built-in extractors do not read, the record names its extractors and
the ctags version, and a missing or failing ctags stops the run rather than degrading to file level.

## 2. Scope (IN)

The `code` record, its tables, its key switch and its stop on a missing ctags are
TOOL-dTotalRecall-8's: S2 (`extract_ranges` and the definition key `<path>::<qualified name>`), S7
(`code_row`, `code_file`, `code_meta(tree, extractors, ctags, languages, degraded)`), S9 (the bounds and
`degraded`) and S10 (`memory.code-languages` read by `read_policy_value`, `builtin`, `builtin+ctags`,
`ctags`, a missing ctags exiting 2 naming the key), with its AC8. All are DEFERRED at base `5fede642`
and are a build-run precondition: this unit is built on their landed code and re-specs none of them.

- **S1** — The pack, `tools/memory-tree/code_ctags.py`, beside `code_record.py` in the memory-tree
  kit. `read_ctags_version(env)` resolves the binary with `shutil.which("ctags")` and runs
  `ctags --version` with no shell; it returns the version token of a first line starting
  `Universal Ctags`, and raises `CtagsRefused` naming `memory.code-languages` when the binary is
  absent, exits non-zero, or is not Universal Ctags (Exuberant Ctags has no JSON output). It is the
  one probe TOOL-dTotalRecall-8 S10's stop calls, so the stop and the pack never disagree on what
  "missing" means. Observed by AC1 and AC5.
- **S2** — The run, `extract_ctags_defs(blobs, env)`: the blobs to read are written, each under its
  blob id and its path's extension, into one `tempfile.mkdtemp()` directory, and one
  `ctags --options=NONE --output-format=json --fields=+nel -f - -L -` call over that list runs with
  the directory as its working directory, and the directory is cleaned up afterwards. `--options=NONE` and the working
  directory keep an adopter's `.ctags.d` option files out of the run. Each output line is one JSON
  object; a line that does not parse, or a non-zero exit, raises `CtagsRefused` naming the key and
  ctags's first stderr line, and no record is written. Observed by AC1 and AC5.
- **S3** — The rows. A tag becomes a `code_row` when its `kind` is in `CTAGS_DEFINITION_KINDS` (§4
  "The kinds"); its qualified name is its `scope`, with `::` folded to `.`, joined to its `name` by
  `.`, so its key is `<path>::<qualified name>` as I18 spells it. `line` is the tag's `line` and
  `end_line` its `end`; the body hash is `hashlib.sha1` over lines `line` to `end_line` of the blob
  text, the rule TOOL-dTotalRecall-8 §4 states for the built-in rows. A tag with no `end` gives a row
  with `end_line` and `hash` empty, which every reader treats as never fresh. Two tags of one blob
  sharing a key (overloads) keep the first key and suffix the later ones `#2`, `#3` in line order.
  Observed by AC2 and AC3.
- **S4** — The dispatch, in `derive_code_record` of `tools/memory-tree/code_record.py`. Under
  `builtin+ctags`, the pack reads every file whose extension `BUILTIN_ARMED` (TOOL-dTotalRecall-13)
  does not map, and the built-in extractors read the rest as before. Under `ctags`, the pack reads
  every file, the built-in extractors give Python, shell and JavaScript no definition rows, and each
  built-in call site's enclosing key is re-anchored to the innermost ctags definition whose range
  holds the call's line, or to the file key `<path>` when none does, so no `calls` edge has a
  dangling `src`. Under `builtin` the pack is never imported. Observed by AC2 and AC4.
- **S5** — The record names its sources. `code_meta.extractors` lists `builtin` and `ctags` as the
  value read them, `code_meta.ctags` holds S1's version token, and `code_meta.languages` lists each
  language read with its extractor, ctags's `language` field naming the ctags ones; each `code_file`
  row the pack read takes that `language` as its `lang`. Under `builtin`, a file no built-in
  extractor reads keeps its file-level row, and `code_meta.languages` lists its extension with the
  extractor `none`, the state TOOL-dLinkedLibrary-14 reads as "not extracted". Observed by AC4.
- **S6** — Version skew. A blob's ctags rows are cached stamped with the version that wrote them; a
  run under another version re-parses those blobs, so one record never mixes two ctags versions,
  and `code_record.py --check` on a node with a different version re-derives rather than reading a
  stale cache as fresh. Observed by AC6.
- **S7** — The fixture, `python code_ctags.py --fixture --plant <case>`, its plants run together by
  `code_ctags.py --selftest`, which `code_record.py --selftest` calls: a scratch repository holding `a.go` (a function, a method on a
  struct, a type), `b.java` (a class with two overloads), `c.rs` (a function ctags gives no `end`),
  `d.py` (a function and a call), and a committed `.governance/policy.toml` naming the value; a stub
  `ctags` written onto a private `PATH` (a script and a `.cmd` shim, so `shutil.which` finds it on
  both hosts) answering `--version` and printing canned JSON for each file. The plants are §6's.
  Observed by AC1 to AC6.
- **S8** — The page `help/code-languages.md`: the three values of `memory.code-languages`, what each
  extracts, that the pack needs Universal Ctags on `PATH` on every node, that a missing ctags stops
  the record, and that the record names the version; linked from `help/README.md`. The memory-tree
  README's code-record section gains one paragraph pointing at it. Observed by AC7.

## 4. Design

### Evidence

- No ctags reader exists: `git grep -i ctags -- tools skills` finds only the catalogue row
  `tools/policy/catalogue.toml:1411` (`allowed = ["builtin", "builtin+ctags", "ctags"]`, owner
  dTotalRecall, default `builtin`, verified at base).
- ctags is not installed on node d: `command -v ctags` prints nothing (re-run at base), so every
  criterion runs the stub, as TOOL-dTotalRecall-8 AC8 does.
- The owner's NP-10 answer, "Built-in, ctags pack opt-in (Recommended)", and the session's stated
  costs: no calls or docstrings from ctags, a binary on every node, version skew, a GPL licence, and
  "a missing ctags must stop the run rather than degrade" (night-pass.md:673-679).

### The kinds

`CTAGS_DEFINITION_KINDS` is the closed set of ctags kind names that define a named body: `function`,
`method`, `class`, `struct`, `interface`, `enum`, `trait`, `type`, `typedef`, `module`, `namespace`,
`subroutine`, `procedure`, `constructor`, `union`, `implementation`, `protocol` and `package`.
Variables, fields, members, locals, parameters and macros are not definitions of a body and give no
row. A kind outside the set is counted per language in `--check`'s output, so a language whose
definitions ctags names differently is visible rather than silently empty.

### The run

```
blobs not yet holding ctags rows at this version
  -> mkdtemp(): <blob><.ext> per blob
  -> ctags --options=NONE --output-format=json --fields=+nel -f - -L -   (cwd = the temp dir, no shell)
  -> one JSON object per line: {"_type":"tag","name","path","line","end","kind","scope","language"}
  -> code_row(blob, kind, key, name, line, end_line, hash, text) per S3
```

The environment handed to ctags is the caller's with `CTAGS` and `ETAGS` removed, so no variable
adds options. One spawn per run, whatever the blob count, the batched shape of the primitive's
`git cat-file --batch` read.

### Inventory

Minted: `tools/memory-tree/code_ctags.py` with `read_ctags_version`, `extract_ctags_defs`,
`CtagsRefused` and `CTAGS_DEFINITION_KINDS`; the fixture plants of §6; `help/code-languages.md`.
Naming cells: `read_ctags_version` and `extract_ctags_defs` are asked of the lexicon's `--suggest`
under `--as py.function` at the pass.

### Migration

None. A repository under `builtin`, the default, never imports the pack; one switching to a ctags
value re-derives its record on the next run, since its cache holds no ctags rows.

### Rollout

Dark by default: the pack runs only under a ctags value an adopter commits to its policy file.

### Files touched (estimate)

- `tools/memory-tree/code_ctags.py` (new)
- `tools/memory-tree/code_record.py`
- `tools/memory-tree/README.md`
- `tools/memory-tree/check-memory-hygiene.sh`: `KIT_MEMORY_TREE_VERSION` moved with the kit's shipped bytes
- `help/code-languages.md` (new)
- `help/README.md`

### Alternatives rejected

- **The pack inside the `extract_code` canonical block.** Only the `code` record reads ctags; the
  lexicon's and the codebase map's copies would carry a reader they never call (§8 F1).
- **Read blobs through ctags's standard input.** Universal Ctags picks a parser by file name, and a
  stream has none; one temporary directory named by blob and extension gives it one.
- **Fall back to `builtin` when ctags is missing.** The clause and NP-10 forbid it: a silent
  fallback reads as a record that covers the language.

## 5. Production-readiness checklist

- security — ctags runs from `PATH` with no shell, `--options=NONE`, a temporary working directory
  and `CTAGS`/`ETAGS` dropped, so neither an adopter's option files nor its environment add flags;
  it writes nothing outside the temporary directory, which is removed.
- perf / scale — one ctags spawn per run over the uncached blobs only; S6's version stamp re-parses
  only when the version moves.
- error / empty / loading states — absent, failing or non-Universal ctags is exit 2 naming the key;
  an unknown kind is counted, never dropped silently; a tag with no `end` is a never-fresh row.
- observability — `code_meta` names the extractors, the version and each language's extractor;
  `--check` prints per-language counts and the uncounted kinds.
- risks — version skew between nodes (S6); a language whose ctags parser gives no `end` yields
  hashless rows that enrichment never marks fresh; ctags is GPL, run as a separate program and never
  linked or shipped.
- testing — the plants of S7, red and green, each run by `code_ctags.py --fixture --plant`.
- migration — none.
- user docs — `help/code-languages.md`, S8.

## 6. Acceptance criteria

- **AC1** — When `python code_ctags.py --fixture --plant missing` runs the fixture with
  `memory.code-languages = "builtin+ctags"` committed and no `ctags` on its `PATH`, the derivation
  exits 2 naming `memory.code-languages` and writes no record; with the plant `exuberant`, a stub
  answering `Exuberant Ctags 5.8` exits 2 the same way; with the plant `fails`, a stub exiting 1
  mid-run exits 2 naming its stderr line.
  Red when: any of the three degrades to file level and the run exits 0.
  fixture: the stub is the fixture's; node d has no ctags.
- **AC2** — When the plant `rows` runs under `builtin+ctags` with the stub, `code_record.py --dump`
  holds `a.go::Run`, `a.go::Server.Start` and `a.go::Config`, each with `line`, `end_line` and a
  hash; `b.java::Shop.add` and `b.java::Shop.add#2` for the overloads; and `d.py`'s rows come from
  the built-in extractor, not the stub.
  Red when: a ctags language stays at file level, a scoped name loses its scope, or ctags reads a
  file the built-in extractors arm under `builtin+ctags`.
- **AC3** — When the plant `hash` edits one line inside `Server.Start`'s range in a second commit,
  its hash moves and `Run`'s does not; `c.rs::main`, given no `end` by the stub, has an empty hash.
  Red when: a hash covers more than its range, or a row without an end carries a hash.
- **AC4** — When the plant `ctags-all` runs under `ctags`, `d.py`'s definition rows come from the
  stub, the `calls` edge from its call site has a `src` the record holds, and `code_meta` reads
  `extractors` naming `ctags`, `ctags` naming the stub's version and `languages` naming `Go`;
  under `builtin` the plant finds `a.go` at file level and `go` listed with extractor `none`.
  Red when: a call's `src` names a definition no row holds, or the meta omits the version.
- **AC5** — When the plant `options` places a `.ctags.d` directory in the fixture repository whose
  option file would add a regex kind, the stub's recorded argv starts `--options=NONE` and its working
  directory is not the repository.
  Red when: the run's argv or working directory lets the repository's option files apply.
- **AC6** — When the plant `skew` derives the record under a stub reporting `6.1.0`, then runs
  `code_record.py --check` under a stub reporting `6.2.0`, the second run re-parses the ctags blobs
  and the record's `code_meta.ctags` reads `6.2.0`.
  Red when: rows written under one version are read as fresh under another.
- **AC7** — When `grep -n "builtin+ctags" code-languages.md` runs over the help page, it finds the
  section naming all three values and the stop on a missing ctags, and `grep -n "code-languages.md"
  README.md` over `help/` finds the link.
  Red when: the page is missing or does not describe the stop.
