## 1. Goal

The memory plan's `[cycle]` walks the owner's loop hop by hop, and two hops relate to nothing: a decision
row names no node it decides, the `decides` edge on 0 of the decision rows, and a bug class names no
cause, language, platform or the finding it came from (`from:` on 0 of 151 records) (gap-mem-39,
gap-tool-17, P37). This unit gives every decision row a `decides` target, reads every `Decided:` trailer
as a decision row through dDeclaredLoop's one trailer reader, and gives every bug class four fields the
gotchas module parses and checks, registering `gotcha` as a record kind.

## 4. Design

### The vocabularies

`CAUSES` takes the causes the compatibility research tabled over the bug classes
(`memory/builds/dClosedLoop/build/2026-10-18-build-PLAY-dClosedLoop-1-research-compatibility.md:84-96`)
and adds the three that hold the rest of the catalogue:

| key | values |
|---|---|
| `cause` | `line-endings`, `quoting`, `shell`, `process-cost`, `interpreter-discovery`, `paths`, `encoding`, `concurrency`, `logic`, `method` |
| `language` | `python`, `bash`, `javascript`, `powershell`, `awk`, `any`, `none` |
| `platform` | `any`, or a member of `platforms.supported`'s allowed set (`windows-gitbash`, `linux`, `macos`, `pwsh-launch` at `tools/policy/catalogue.toml:1615-1619`) |
| `from` | `<review stem>#<finding id>[, …]`, or `none — <reason>` |

`concurrency` holds the race classes, `logic` a computation that answers wrong, and `method` a rule or
record that failed rather than code; `none` as a language marks a `method` class. `CAUSES` and
`LANGUAGES` are tuples in `gotchas.py` beside `KINDS` (:75); the platform set is read, never typed.

### A record after the backfill

```yaml
---
name: a-folded-field-leaves-its-row-shape-docs-behind
description: a review fold adds a key to a declared row shape in the code and its gate, …
kind: class
universal: false
cause: method
language: none
platform: any
from: 2026-09-20-review-TOOL-aWindowedPass-1-closing-diff-round2#M10
---
```

The stem is checked against `git ls-files 'memory/builds/*/reviews/*.md'` and the finding id against
that file's text, so a `from` naming a review that was never written, or a finding it does not hold, is
refused.

### The decision rows

```
$ python row_grammar.py --decisions
TOOL-aUnmannedHelm-5 · log · decides=3f9c2a71e0b4
3f9c2a71e0b4:1 · trailer · decides=3f9c2a71e0b4
…
decisions — 292 log row(s), 1829 trailer row(s), 0 with no decides target
```

The log rows' commits come from one `git log --reverse --format=%H -p -- memory/DECISIONS.md
'memory/archive/DECISIONS.*'` pass: the first commit whose added lines carry a row's text is its target.
A shallow clone that cannot reach a row's first commit leaves that row with no target, which the
summary counts and the exit reds. Figures in the sample are illustrative; the CLI derives them.

### Alternatives rejected

- **A free-text `cause:`.** The record's `## Cause` section already holds the prose; a second free
  text is one fact twice, and the portability lens the research asked for needs a closed set to select
  by.
- **A required `from:` with no escape.** 119 of the 148 classes cite no review record, many filed from
  an incident; a forced value would be invented.

## 5. Production-readiness checklist

- security — no new write path; the reader runs git read-only and parses trailers through the one
  reader.
- perf / scale — one `git log -p` over the decision log's 200-odd commits and one `read_commits` call
  over HEAD's history per `--decisions` run; `gotchas.py --check` adds one `ls-files` and a read per cited
  review.
- error / empty / loading states — every refusal names the record, the key and the value; a blank
  `GOTCHA_FIELDS` is announced; a row with no reachable commit is counted, never skipped silently.
- observability — the `--decisions` summary line; `gotchas.py --report` gains a count per cause.
- risks — the backfill is 148 judged values; a wrong `cause` misdirects a lens but reds nothing, and
  each value is reviewable in one diff.
- testing — AC1 to AC9 by a pass; the arms of §7 at the close.
- migration — §4.
- user docs — no page under `help/` covers bug classes or the decision log.
