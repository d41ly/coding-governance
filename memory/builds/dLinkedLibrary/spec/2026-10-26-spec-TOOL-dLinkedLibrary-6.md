## 1. Goal

Research returns are found across builds only through recall, an optional component, or by file
name, and 9 of 72 at `1b759b620` were cited from another build (gap-mem-15). Layer-memory `[views]`
names a generated research view, "every research return by build, date and question", beside the
other owner views, and layer-library `[research-view]` makes it the planner's core source and holds
it to a byte compare and a red on an empty render. This unit renders that view over the
`research-return` kind TOOL-dLinkedLibrary-13 lands, and lands with it the one seam every library
view renders through, so TOOL-dLinkedLibrary-5's holds-now and reuse views are two rows of it rather
than two more copies.

## 4. Design

### Evidence

- The generator already renders two kinds of tree-wide file: the family views through `render_views`
  (`gen_build_index.py:1425`), joined to the artifacts `plan()` returns, and the as-built view through
  `render_asbuilt_view` (:1474), called once from `cmd_check` (:2886) and `cmd_write` (:3195) so its
  findings block no other artifact's write. The library views take the second shape: their findings
  are verdicts `--write` cannot cure.
- Check 3 sanctions the memory root's entries by name (`check-memory-hygiene.sh:770-771`); `views` is
  not among them, so a view file would red the lint at its first commit.
- Generated files carry `merge=ours` (`.gitattributes:90-92`).

### The seam

```python
VIEWS = {
    "research": ("views/research.md", render_research, "red"),   # an empty render is red
}

def render_library_views(root, conf):
    names = read_armed_views(conf)            # LIBRARY_VIEWS; [] -> off; unknown -> Problem
    if not names:
        return {"state": "off", "line": "build-index: library views off — LIBRARY_VIEWS is blank"}
    views, findings = {}, []
    for name in names:
        text, rows = render_view(name, root, conf)
        rel = f"{conf['MEMORY_ROOT']}/{VIEWS[name][0]}"
        views[rel] = text
        findings += check_view(name, rows)
    return {"state": "armed", "views": views, "findings": findings}
```

### Alternatives rejected

- **Joining the views to `plan()`'s artifacts, as the family views are.** A finding would then have no
  home but `plan()`'s verdict list, whose codes are the backlog fold's; the as-built view's shape keeps
  a view's verdict apart from drift.
- **One module per view.** Three renderers sharing the off line, the switch, the orphan scan and the
  empty red would be the third copy `[reuse]` forbids.
- **The view under a build's folder.** It spans every build, and a build folder is one build's record.
