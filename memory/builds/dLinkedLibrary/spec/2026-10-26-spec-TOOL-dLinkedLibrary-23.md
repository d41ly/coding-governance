## 1. Goal

An adopter's own `CLAUDE.md`, `GEMINI.md` and Copilot instructions stay unwired at install until
`--force` overwrites them (gap-deploy-26,
`memory/builds/dClosedLoop/build/2026-10-14-build-PLAY-dClosedLoop-1-gap-register.md:416`): today's
installer refuses an existing harness file (`tools/agent-instructions/adopt-agent-instructions.sh:114-115`)
and, forced, replaces it (:133-140). This unit makes install keep every such file's bytes as a legacy
block after the project block, wire every harness file at once, hold the block on the shrink-only
legacy list from install on, and propose each paragraph as a repository unit, an amendment of a gov
unit or a drop for the owner to rule once (IA-5, the adopter-instructions record item 15,
`memory/builds/dClosedLoop/build/2026-10-19-build-PLAY-dClosedLoop-1-adopter-instructions.md:180-184`).

## 4. Design

### Evidence

- `wire()` refuses an existing non-wiring harness file without `--force` (:114-115), and with it
  removes the file before writing the alias (:133-140); govkit runs the script with no flags
  (`tools/agent-instructions/kit.toml:36-38`).
- `build_region` keeps every authored byte before and after the `gov:playbook` region and replaces
  only its contents (`tools/playbook/render_playbook.py:757-775`), so bytes in the charter's tail
  survive every re-render.
- `instructions.legacy` allows `shrink-only` and `refuse`, default `shrink-only`, owner dOrderedCharter
  (`tools/policy/catalogue.toml:1361-1365`); v2's strict preset sets `refuse` (v2:1680).
- A `project-owned` rule means "the target authors it — gov supplies no bytes for this source, ever"
  (`tools/govkit/govkit.py:406`), the carve-out the codebase-map and workflows kits already use.
- TOOL-dWitnessedBar-18 §4 registers `instructions-legacy` at `tools/playbook/instructions-legacy.txt`,
  shrink-only, key `site · path`, in `tools/playbook/kit.toml`.

### The legacy pair (I23, refined)

```
<!-- gov:playbook -->
…the rendered charter, the project block among it…
<!-- /gov:playbook -->
<!-- gov:legacy src=CLAUDE.md -->
…CLAUDE.md's bytes, verbatim…
<!-- /gov:legacy src=CLAUDE.md -->
<!-- gov:legacy src=GEMINI.md -->
…
<!-- /gov:legacy src=GEMINI.md -->
```

The close marker carries `src=` so each pair has its own open and close line, the one-open-one-close
contract of I14; I23 proposed a bare close, which two pairs would share (§8 F3). A file whose bytes
lack a final newline gains one before the close line; nothing else changes.

### Paragraphs

A paragraph is a run of lines between blank lines, a fenced block kept whole. Its key is
`<src>#p<sha8>`, the first eight hex of the SHA-256 of its text with whitespace runs folded to one
space, so a key survives a re-wrap and two identical paragraphs share one ruling.

### Alternatives rejected

- **The block inside the region, re-emitted from a store.** A second copy of the bytes beside the
  charter; the authored tail already survives every render.
- **`--force` with a backup file.** Leaves the adopter's rules unrendered and unwired, the gap itself.
- **One proposal record per paragraph written at install.** The pair already holds each paragraph
  and its key derives from the text; a record is written when the owner rules, the fact that changes.

## 5. Production-readiness checklist

- security — install writes only the charter's tail, the list and the harness files the scope
  owns; captured bytes are data between markers and are never executed or rendered as gov rules;
  `--rule` passes the owner proof, so no automated caller rules a paragraph.
- perf / scale — one read per harness file at install; one region rewrite and one row write per
  ruling.
- error / empty / loading states — no harness file: nothing captured, exit 0 with `legacy — none`;
  an unparseable pair: exit 2 naming its line; an absent list: an empty population.
- observability — `adopt instructions` prints each paragraph's key and the count left.
- risks — a harness file over a harness's own size limit stays captured whole, and the renderer's
  limit refusal (PLAY-dOrderedCharter-34) names the legacy block's contribution.
- testing — the plants below, red and green, and the base installer's refusal.
- migration — none in gov.
- user docs — `help/adopting-instructions.md`, S10.
