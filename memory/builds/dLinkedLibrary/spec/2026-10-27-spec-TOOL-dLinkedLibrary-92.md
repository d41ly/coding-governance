## 1. Goal

The spec audit of units 87 to 91
(`memory/builds/dLinkedLibrary/reviews/2026-10-27-review-TOOL-dLinkedLibrary-87-spec-audit.md`) confirmed
finding **id 7 at HIGH**, report item **H1**. No other id shares the item.

`TOOL-dLinkedLibrary-90` S3 plants BOM-led CRLF CI files, and unit 8 S11's fixture commits each plant
into a scratch repository. Git for Windows sets `core.autocrlf=true` at system and global level, so
`git add` folds every CR LF to LF in the blob. The census reads the blob at the scanned SHA, so on a
Windows node 90's per-line CR strip is never exercised: a `ci_lines` that strips no CR passes 90 AC1 to
AC3, and 90 AC2's red arm, a CR on `- bash: |`, cannot fire.

This unit makes the fixture's scratch repository commit raw bytes, and makes the fixture refuse to run
any plant whose committed blob differs from the bytes it planted. It repairs `TOOL-dLinkedLibrary-90`
and builds one step after it (order 35).

## 2. Scope (IN)

- **S1** — Raw commits. The scratch repository `python adopt_program.py --fixture --plant <case>` builds
  (unit 8 S11) sets `core.autocrlf` to `false` in its own repository config before its first `git add`,
  as `tools/govkit/matrix.py:453` does for its fixture. A repository-level value outranks the system and
  global ones, so the setting holds on every node. Observed by AC1 and AC2.
- **S2** — The round-trip proof. After each plant's commit, and before the census runs over it, the
  fixture compares, for every file the plant wrote, `git hash-object --no-filters <path>` with `git
  rev-parse HEAD:<path>`. On a match it prints `fixture: blob kept <case> <path> bom=<0|1> cr=<n>`,
  `bom` saying whether the planted bytes open `EF BB BF` and `cr` counting the planted CR bytes. On a
  mismatch it exits non-zero, printing `fixture: committed blob differs from planted bytes <case>
  <path>`, and grades no plant. Observed by AC1 to AC3.
- **S3** — Every plant. S1 and S2 cover every case of the fixture, so 90 S3's three trees and every
  later plant holding a CR, a BOM or any other byte git could filter are committed and proved the same
  way. Observed by AC1 and AC3.

## 3. Non-goals (OUT)

- A repo-wide gate that every selftest's scratch repository sets `core.autocrlf=false` or `* -text`: the
  report's left-shift gate, a separate mechanism this unit does not build. It is a follow-up for the
  owner's wrap-up.
- Reading a blob's bytes: S2 compares object ids and reads no blob, so the kit's one bytes reader,
  `read_blobs_at` (`tools/memory-tree/tree_lib.py:328`), gains no sibling.
- What the census reads: 90 S1's decoder is unchanged.

## 4. Design

### Evidence

- `git config --show-origin --get-all core.autocrlf` on this node printed `true` from both
  `C:/Program Files/Git/etc/gitconfig` and `C:/Users/d41ly/.gitconfig` (PINNED, 2026-10-27).
- A scratch repository under `%TEMP%` on this node, holding `EF BB BF` then `jobs:\r\n  t:\r\n`:
  committed under the inherited `core.autocrlf=true`, `git rev-parse HEAD:b.yml` printed `1e65d824`
  while `git hash-object --no-filters b.yml` printed `38f47949`; re-committed after `git config
  core.autocrlf false`, both printed `38f47949` (PINNED, 2026-10-27). The object id compare tells a
  folded blob from a kept one, and the repository-level setting keeps it.
- `tools/govkit/matrix.py:453` and `tools/branch-reconcile/selftest.py:58` each set `core.autocrlf` to
  `false` for a scratch repository they commit into.
- Unit 8 S11 (`2026-10-26-spec-TOOL-dLinkedLibrary-8.md:131-133`) builds the fixture as a scratch
  repository with committed files; `tools/memory-tree/adopt_program.py` is absent at base.

### Why the proof and not only the setting

The setting closes the Windows case. A `core.attributesFile` or a planted `.gitattributes` holding
`text` would still fold the bytes, and a plant would grade green over a blob it never held. The S2
compare names that case wherever it happens, so no plant is certified over bytes the census never
read.

### Rollout

Order 35, one step after `TOOL-dLinkedLibrary-90`, beside `TOOL-dLinkedLibrary-91` and
`TOOL-dLinkedLibrary-93`. All three write `adopt_program.py`, so BUILD-METHOD M6's clause 1 sequences
the passes; none reads another's plant. If the pass adds a function, it re-renders the generated map
with `python tools/codebase-map/gen_map.py --write` where its `--check` exits 1, in the pass commit.

### Files touched (estimate)

- `tools/memory-tree/adopt_program.py`: S1 to S3
- `memory/map/generated/inventories.json`, `memory/map/generated/MAP.md`,
  `memory/map/generated/CARDS.md`, `memory/map/generated/symbols.json`: the Rollout re-render

### Alternatives rejected

- **A committed `.gitattributes` holding `* -text` in each scratch tree.** It adds a file to every
  plant's tree that the census then scans; the repository config does the same work with no planted
  file, and S2 catches what either misses.
- **Reading each blob back and comparing bytes.** It needs a `<rev>:<path>` bytes read beside
  `read_blobs_at`, which decodes and folds CRLF; the object id compare needs neither.
- **An `od -c` precondition typed into each criterion of 90.** It checks three files by hand once;
  S2 checks every planted file on every run.

## 5. Production-readiness checklist

- security — keeps 90's deny-by-default plants honest on Windows nodes; no census behaviour changes.
- perf / scale — two git calls per planted file.
- error / empty / loading states — a mismatch stops the fixture naming the case and path; a plant
  writing no file prints no line.
- observability — one `fixture: blob kept` line per planted file.
- risks — a node whose attributes fold bytes now fails the fixture loudly instead of passing it.
- testing — AC1 to AC3 over the fixture and a scratch copy.
- migration — none.
- user docs — none under `help/`: the fixture is a developer surface.

## 6. Acceptance criteria

- **AC1** — When `python adopt_program.py --fixture --plant ci-census` runs on a node whose global
  `core.autocrlf` is `true`, it prints `fixture: blob kept` with `bom=1` and a non-zero `cr=` for each of
  90 S3's three BOM-led CRLF files, before the census lines 90 AC1 to AC3 read.
  Red when: the blob lost its CRs and the plant is graded anyway.
- **AC2** — When a scratch copy of `adopt_program.py` without S1's config call runs the same plant by
  `python -I`, with `GIT_CONFIG_GLOBAL` pointing at a scratch gitconfig holding `autocrlf = true`, it exits
  non-zero printing `fixture: committed blob differs from planted bytes` and the case and path of 90's
  GitLab plant.
  Red when: a folded blob passes the compare on any node, Linux included.
- **AC3** — When a scratch copy whose S2 compare is absent runs under the same scratch gitconfig, it
  exits 0 and prints no `fixture: blob kept` line, while the unmodified fixture under that gitconfig
  prints one for every planted file.
  Red when: the `blob kept` line prints with no compare behind it.
