## 1. Goal

No cell shows the retrofit's progress (gap-mem-24,
`memory/builds/dClosedLoop/build/2026-10-14-build-PLAY-dClosedLoop-1-gap-register.md:207`). A
session starts without knowing how much legacy each check still carries or whether it is draining.
This unit derives, from the ledger's own files and their history, each population's count when
seeded, its count now and its drain over the period, and renders them as the orientation card's
`retrofit —` cell (retrofit.md `[progress]`,
`memory/builds/dClosedLoop/build/2026-10-17-build-PLAY-dClosedLoop-1-retrofit.md:516-521`).

## 2. Scope (IN)

Build-run preconditions this unit calls and does not build, each specced and DEFERRED at base: the
ledger factory, its `[[ledger]]` registrations, `read_registrations`, `read_rows` and the memory-tree
kit's inline copy `tools/memory-tree/legacy_ledger.py` (TOOL-dWitnessedBar-13 S1, S2, S8); the seed
and its `armed` and `unarmed` states (TOOL-dWitnessedBar-15 S1, S2); and the `baseline` kind, which
declares the ledger's files as records (TOOL-dLinkedLibrary-8).

- **S1** — The derivation, `derive_progress(root, days)` in a new
  `tools/memory-tree/retrofit_progress.py`, per §4 "The derivation": for each registration
  `read_registrations(root)` returns, its state (`armed`, `unarmed` or `absent`), its count when
  seeded, its count now and its drain over the last `days` days. The CLI `python
  retrofit_progress.py [--days <n>]` prints one TAB-separated line per population, `<population>
  <state> <seeded> <now> <drained>`, `-` for a count an `absent` or `unarmed` population cannot have,
  exit 0; exit 2 on a refusal, naming it. Observed by AC1 and AC2.
- **S2** — The period, `RETROFIT_PERIOD_DAYS = 30` in `retrofit_progress.py`, the window
  `test.seed` already measures an adopter's drain load over (retrofit.md:341-343); `--days` overrides
  it for a caller and a fixture. Observed by AC1.
- **S3** — The cell, `derive_retrofit_line` in `skills/session-kickoff/manifest-check.sh`, called by
  `render_card` (:517) after `render_health_cell` and directly above `recent —`. It resolves the
  module with `resolve_kit_file memory-tree retrofit_progress.py` (:854), runs it under a kill bound
  into a scratch file as `derive_overlaps_line` (:555) does, and prints I22's form:
  `retrofit — <k> populations · <seeded>→<now> · drained <d> this period · reads not installed`, the
  sums over the armed populations, then one indented row per armed population,
  `  <population> <seeded>→<now> · drained <d>`, largest count now first, at most
  `CARD_RETROFIT_ROWS=5`, and `  … <n> more` past them. Observed by AC3 and AC5.
- **S4** — The cell's other states, each its own line, the card written either way: `retrofit — not
  seeded: <k> populations registered, none armed`; `retrofit — skipped: no ledger population is
  registered`; `retrofit — skipped: no retrofit_progress.py resolves in this tree`; `retrofit —
  skipped: the progress read did not answer within <n>s`, the bound `CARD_RETROFIT_BOUND=10`; and
  `retrofit — skipped: <the module's first stderr line>` on exit 2. Observed by AC4.
- **S5** — The read share. The fourth segment reads `reads not installed` until dTendedCadence's
  `maintain.retrofit-heat` reading exists (retrofit.md:531), which owns the share and the segment's
  other form, `reads <share>`. Observed by AC3.
- **S6** — The docs: a new page `help/retrofit.md` describing the cell, each state, the period and
  what the cell does not show, with its line in `help/README.md`; the cell list in the comment above

  `KIT_MANIFEST_VERSION` (:46) moves. Observed by AC6.

## 4. Design

### Evidence

- `render_card` (`skills/session-kickoff/manifest-check.sh:517-546`) prints the cells as hard-wired
  calls, `render_health_cell` last before `printf 'recent —\n'` (:542). Everything after the
  `recent —` block is the tail an append replaces (:596-597), so a cell sits above it.
- `derive_overlaps_line` (:555-589) is the bounded-read pattern: a kill bound into a `mktemp` file
  under `CARD_DIR`, stdin from `/dev/null`, every failure its own `skipped:` line.
- `resolve_kit_file <home> <anchor>` (:854-866) finds a sibling kit's file in this repository.
- `read_adding_commits` and `read_blobs_at` (`tools/memory-tree/tree_lib.py:302`, :328) read a
  path's adding commit and `<rev>:<path>` bytes in one call each.
- A ledger row is `<fields> TAB <count> TAB <sha> TAB <disposition>` under a `# ledger · …` header,
  and an unarmed home holds the header and one `# unarmed · <reason> · <sha>` line
  (TOOL-dWitnessedBar-13 §4 "The ledger file", -15 S2).
- No "cell point" exists: `git grep -n "cell point"` finds only retrofit.md:520 (scout D row 10).

### The derivation

For each registration `R` with home `H`:

| Quantity | Derived from |
|---|---|
| state | `absent` when `H` is not tracked; `unarmed` when `H` holds an `# unarmed` line; `armed` otherwise |
| seeded | the sum of row counts in `H`'s blob at its adding commit, `read_adding_commits(root, H, {H})` then `read_blobs_at` |
| now | the sum of row counts `read_rows(H, …)` returns for the working file |
| drained | the sum, over each key, of the count at the period start less the count now when positive; a key gone now counts its whole period-start count |
| period start | `git rev-list -1 --first-parent --before=<now − days> HEAD`; with no such commit, or one older than the seed, the seed commit |

All period-start and seed blobs are read in one `read_blobs_at` batch. A widened key (`widened:<record>`)
raises `now`; the cell shows the rise as it is and never reads it as a drain.

### Alternatives rejected

- **A new verb on the ledger factory.** The factory is a `tools/lib/` block with two inline copies
  under `PARITY_ROWS`; a history read there would add git calls to every copy-installed kit that
  carries it, where the memory-tree kit already holds the history readers.
- **Parsing the ledger files in the card's shell.** A second reader of the row grammar beside
  `read_rows`.
- **A cell per population with no head line.** Twenty-seven populations at gov would cost the card
  most of `CARD_CAP_BYTES` (:216); the head line totals them and the rows are capped (§8 F3).

## 5. Production-readiness checklist

- security — read-only: git reads with argv lists over registered homes; the card's read runs with
  stdin closed and `GOV_RUNLOG=0`, as the `overlaps —` read does.
- perf / scale — one adding-commit read per registration, one `rev-list` and one blob batch per
  card; bounded by `CARD_RETROFIT_BOUND`.
- error / empty / loading states — S4's four `skipped:` forms and `not seeded`; never a zero line for
  an unread population.
- observability — the cell itself; a refusal prints the module's own first stderr line.
- risks — a registration whose home moved without a rename carry reads its seed from the new path's
  first add, so its seeded count is the count at the move; the help page says so.
- testing — the module's plants and the card arm, red and green.
- migration — none.
- user docs — `help/retrofit.md`, S6.

## 6. Acceptance criteria

- **AC1** — When `python retrofit_progress.py --fixture --plant two-populations` builds a scratch
  repository under `%TEMP%/rp` whose population `pa` was seeded 40 days back with rows summing 9, held
  7 thirty days back and holds 5 now, and whose population `pb` is registered with no home, it prints
  `pa armed 9 5 2` and `pb absent - - -`, and `--days 45` prints `pa armed 9 5 4`.
  Red when: the drain is read from the seed instead of the period start, or an absent home prints a
  zero.
- **AC2** — When `--plant unarmed` runs over a population whose home holds only the header and an
  `# unarmed` line, it prints `<population> unarmed - - -`.
  Red when: an unarmed population prints counts.
- **AC3** — When `bash manifest-check.sh --card --write --session <sid>` runs in a fixture
  repository whose tracked stub `retrofit_progress.py` prints the AC1 lines, the card holds
  `retrofit — 1 populations · 9→5 · drained 2 this period · reads not installed`, then
  `  pa 9→5 · drained 2`, directly above `recent —`.
  Red when: the line is absent, lands after `recent —`, or counts the absent population.
- **AC4** — When the same run's stub prints only `absent` and `unarmed` lines, the card reads
  `retrofit — not seeded: 2 populations registered, none armed`; when no stub resolves it reads
  `retrofit — skipped: no retrofit_progress.py resolves in this tree`; when the stub sleeps past
  `CARD_RETROFIT_BOUND` it reads `retrofit — skipped: the progress read did not answer within`, and
  the card is written each time.
  Red when: a failed read prints a counted line or stops the card.
- **AC5** — When the stub prints seven armed populations, the cell shows five rows by count now and
  `  … 2 more`.
  Red when: the rows exceed `CARD_RETROFIT_ROWS`.
- **AC6** — When `grep -n "retrofit —" retrofit.md` runs over the help page, it finds the cell's
  section naming each state and the 30-day period.
  Red when: the page is absent or omits a state.
