### M2: 80 S12's POSIX visibility arm can never see a correct grandchild, and is not `read_pid_image`'s rule [medium] (ids 2, 16, 22, 40)

- **Where:** spec 80 §2 S12 (POSIX arm); §6 AC8/AC9.
- **What:** On POSIX, S12 takes the image from the first element of `/proc/<pid>/cmdline` and requires it to equal the basename of `sys.executable`. S12 cites `read_pid_image` (`tools/unattended/lib-unattended.sh:595-618`), whose POSIX arm uses `kill -0` plus `ps -o comm=` and is marked UNVERIFIED.
- **Consequence:** On any POSIX host `observe-tree-hang` reads its own live grandchild as `grandchild not visible`. AC9's unmodified `ok` cannot pass on a correct build, and the gotchas selftest is red for POSIX adopters. The pid-image question gets two different rules.
- **Fix (the skeptic judged id 16's proposal unsound; this is the corrected fix, consistent with the sound fixes on ids 2, 22 and 40):** Where `/proc` exists, compare `os.path.realpath('/proc/<pid>/exe')` with `os.path.realpath(sys.executable)`. Elsewhere, compare `os.path.basename` of `ps -o comm= -p <pid>` with `os.path.basename(sys.executable)`, unresolved, allowing for comm's 15-character truncation. Do not compare `comm` with `basename(realpath(sys.executable))`, which fails when `sys.executable` is a symlink. Mark the POSIX arm UNVERIFIED as `read_pid_image` does. State that a platform without the probe yields a harness "cannot look" result, not "not visible". Either cite the result as the POSIX half of the rule or drop the `read_pid_image` citation and state the rule as new.
- **Left-shift gate:** a spec-audit rule that a clause citing an existing seam ("by X's rule") must match that seam's code on every platform arm, or say where it departs.
