## The four attacks, and what each returned

**Is `renderCodeView` sufficient?** No, in two places, and both are new in rev-2. It inherits `blankLiterals`' missing regex-literal mode (blocker 1+37) and its interpolation body-copy is unspecified on brace depth with a live instance in this repo's own shipped harnesses (finding 27). §4's "Comments and quoted strings are handled exactly as `blankLiterals` handles them; that half is not re-derived" is the sentence that carries both: it inherits a state machine's blind spots without enumerating them, on a rule whose new failure mode is fail-closed rather than fail-open.

**Does its fail-closed branch deny any legal script?** Yes, measured, and this is blocker 1+37. The narrow class matters less than the shape: S3 was added to close round-1 blocker 1 and it closes it by trusting an EOF mode flag produced by a scanner that does not model every construct a backtick can sit in. a `s.replace()` whose regex literal holds a markdown fence is an ordinary orchestration line, not an exotic one.

**Does the six-field profile implement its own class table for shell?** Yes. This attack returned nothing confirmed. `marker_needs_word_start` is the field AC7 needs, the hash-comment row sets it and the Python row deliberately does not, F3 records why, and §4's class-5 backtick row and F1's resolution agree with each other. Round-1 finding 28 is genuinely closed. The only shell-adjacent defect below is finding 17, and that is a citation error in §5, not a gap in the table.

**Are the rev-2 criteria falsifiable?** Unevenly, and this is where the round concentrated. One is unsatisfiable by the design it grades (blocker 26+30). One scope item has no criterion at all (finding 7). One §5 claim cites a criterion that covers a different arm (finding 17). Two whole criterion SETS ride gate legs that a default bar holds (findings 5 and 6), so most of §6 is falsifiable in principle and unobserved in practice. And the ADMIT direction is systematically thinner than the DENY direction in both units, which is what let blocker 1+37 through.

**Do the two specs contradict each other?** No — again. `-1` touches `map_lib.py` and `selftest.py`, `-2` touches `agent-cap.js` and its test, and the only shared surface remains `-1`'s §10 citing `blankLiterals` as a SHAPE precedent. That citation is now stronger than round 1's, because `-1`'s §10 explicitly inherits the warning and S5 exists because of it, which is the cross-spec reference working as intended.

**But they fail in the same direction again, independently, and it is a different direction from round 1's.** Round 1's shared class was a safety property asserted in §5 with no arm in §6. This round's is that the arms which DO exist run on a held leg (findings 5 and 6), and that the direction each spec's §5 does not name is the direction that broke (`-2`'s §5 names only fail-open, and the fail-CLOSED regression is blocker 1+37; `-1`'s §5 names three error states and mis-cites one). Neither author checked their §7 against `tools/gate-legs.json` and neither checked the unnamed direction. Gate the pair together.
