# dFoldedVerdict — a FOLD becomes recordable, and the contract stops outgrowing its cap

## The problem this build exists to solve
`BUILD-METHOD.md` M4 admits two dispositions at a non-convergent review exit, FOLD and PROMOTE, and
this kit can observe only the second. The Skill tells a run to record the choice with
`--disposition fold|promote` and says the merge bar reads that field; the driver refuses the flag and
the checker contains the word zero times. So check 2 guesses from a unit-id delta, which is wrong in
both directions: it passed `dBriefedPass` vacuously and it reds `dMispairedQuote`, whose six blockers
were all legitimately folded. Separately `agent-cap.js` forbids the one dispatch shape the ratified
parallelism verdict permits, and the protocol renders at its byte cap.

## Expected improvements
- A run that FOLDS at the exit can say so, and the bar reads the record rather than a proxy.
- `origin/main` stops carrying a red leg earned by a correctly-folded build.
- A harness may dispatch sequentially, under a marker that names a bound the hook resolves.
- The protocol gains roughly 13 KB and its fastest-growing section leaves the capped file.

## Detriments if this is not built
- Every folded exit keeps reading as an abandoned one, and main stays red.
- The check keeps passing prompt-mode runs vacuously, which this build measured on its own predecessor.
- The next verb added to the kit reds the bar before its documentation is written.
- A harness that iterates units keeps having no legal shape.

## Build-level rules
- **Owner rulings, 2026-09-01, all four taken against a stated cost.** Build the flag AND its gate;
  teach the hook with a marker that NAMES A BOUND; compress every section AND split section 7; clear
  the red here rather than waiting for node `a`.
- **This build takes `TOOL-aClosedDocket-4`'s scope**, ratified 2026-08-31 and the READY next unit of
  a run stalled 29 hours at BUILDING. Unit 3 supersedes it. The owner authorized the collision after
  being shown it; M3 does not delegate a sibling build's scope, so this is an owner act and not mine.
- **The ruling EXCEEDS `-4` as ratified.** Its S3 makes the disposition an OR-arm beside the id
  proxy; the ruling REPLACES the proxy. `-4` also has no date cutoff, and 13 tracked records carry an
  exited subject that no verb can retrofit, so a cutoff is mandatory rather than optional.
- **A compression that drops or reverses a claim is a worse defect than the verbosity.** Two parity
  legs compare the two copies to each other, so a claim false in both is green.
- **At CEILING the driver accepts EITHER disposition.** Owner ruling. A forced value is a constant,
  and a constant is not evidence for the clause that reads it — so the field stays evidence at every
  exit, and the specs say plainly that this permits something M4's sentence does not describe.
- **The kit version moves ONCE, on the build's last landing unit.** Owner ruling. Nine carriers that
  `check-kit-versions.sh` asserts AGREE rather than MOVE; an adopter sees one release, not six.
