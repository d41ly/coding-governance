## 1. Goal

A receipt row carrying `evidence: "unattributed"` is a row `update` will never grade and never
re-stamp, and the count only appears when an operator runs `govkit update` by hand. 47 of inCMS's 95
rows were in that state when `DEPL-dGaugedVintage-8` measured it. This unit adds one loop to the
receipt leg so the count reaches an adopter's own bar, as a NOTE rather than a failure.

## 2. Scope (IN)

- **S1** `tools/run-gates/check-receipt.py` gains one loop over every receipt row with
  `f.get("evidence") == "unattributed"`, keyed on that exact string and never on field absence —
  absence is the synthesized-class state and is not a synonym. Observed by AC1.
- **S2** With one or more such rows the run prints the NOTE §4 spells — two lines, the first naming
  the DERIVED count and the second the remedy `govkit adopt --re-adopt --pin <path>=<rev> --write`
  — and the exit status is unchanged by the loop. Observed by AC1 and AC3.
- **S3** With zero such rows the loop prints nothing. A line that always appears carries no
  information and trains a reader to skip it. Observed by AC2.
- **S4** A fifth built-in fixture arm covers the populated case and a sixth covers the empty case,
  in the harness `TOOL-cMendedVintage-6` ships. Observed by AC4.
- **S5** The script's header gains one sentence saying this arm is a NOTE and naming the follow-up
  that would make it a failure, so a reader is not left deciding whether a silent note is a bug.
  Observed by AC5.

## 3. Non-goals (OUT)

- The note does not fail the leg, and does not become a failure in this build. `DEPL-cMendedVintage-4`
  has already landed, so the remedy is live rather than a no-op — and the reason to stay advisory is
  the other one: an adopter pulling this release has had no EARLIER release in which to clear their
  rows, so the release that fixes a remedy must not also be the release that starts redding on it.
- No change to `govkit check`, which needs the gov checkout and is invoked automatically by nothing.
  A count added there never reaches an adopter's bar, which is the reason this loop is here.
- No change to `_cmd_update`'s own withholding of the `gov_commit` re-stamp, and no change to the
  `--allow-ungraded` override. Both are `DEPL-cMendedVintage-4`'s subject.
- The loop does not attempt to attribute a row, pin one, or suggest a `<rev>`. It counts and points
  at the verb that grades them.
- No new gate leg, no new descriptor row, no new pin row. The leg this loop lives in already exists
  after the preceding unit.

### Edges

- **consumes-from** `TOOL-cMendedVintage-6` — the shipped file, its receipt reader, its summary line
  and its fixture harness. Without that unit there is nothing for this loop to live in.
- **consumes-from** `DEPL-cMendedVintage-4` — the remedy string. Until that unit lands, the printed
  remedy is `govkit adopt --re-adopt --write`, which re-runs the identical attribution walk over
  identical bytes and returns nothing. Printing a no-op on an adopter's bar is worse than printing
  nothing.
- **hands-off** external — promoting this note to a leg failure one release later, once adopters
  have had a release in which to clear their rows. Nobody in this build carries it.

## 4. Design

### Data model

`EVIDENCE_STATES` at `govkit.py:8765` is the closed set `("apply", "vintage-match", "pinned",
"unattributed")`, and the comment above it names ABSENCE as a fifth state that is deliberately NOT a
synonym for `"unattributed"`. The loop therefore compares the value and never tests for the key.

| receipt reading | what the loop does |
|---|---|
| `evidence` absent | nothing — a synthesized row, not an ungraded one |
| `evidence` is `apply`, `vintage-match` or `pinned` | nothing |
| `evidence` is `"unattributed"` | counted |

The count is over EVERY row, not only engine rows. `govkit.py:8723` counts the same way
(`sum(1 for f in receipt.get("files", []) if f.get("evidence") == "unattributed")`) and it is that
count which decides whether the re-stamp is withheld, so a differently scoped count here would
report a number the operator's own `update` run disagrees with.

### The line

Two lines, printed after the integrity findings and before the summary, so a real failure stays at
the top of the output. Their text names the count and the working remedy, and the count below is an
ILLUSTRATION taken from the historical inCMS reading — the shipped code derives its own:

```
check-receipt: NOTE - 47 row(s) carry evidence "unattributed"; govkit update will not re-stamp
check-receipt: NOTE - clear them with: govkit adopt --re-adopt --pin <path>=<rev> --write
```

`--pin` is what sets `evidence = "pinned"` (`govkit.py:9056`). The bare `--re-adopt --write` form
walks the same bytes against the same history and leaves the row exactly as it found it. That is
`DEPL-cMendedVintage-4`'s finding, and that unit has already landed: `govkit.py:8723` now prints the
corrected `--pin` spelling itself. This unit prints the same corrected form, so the two agree.

### Inventory

| identifier | cell | what it is |
|---|---|---|
| `print_unattributed` | `py.function` | the loop and its two lines |

`python tools/lexicon/lexicon.py --suggest report_unattributed --as py.function` refused `report`
and named `print` — "write to stdout for a human, never a return value in disguise". The name follows
the refusal rather than the first instinct.

### Rollout

Inert until an adopter holds a receipt with such rows. In gov's tree the receipt half always takes
the announced-skip path, so this loop is exercised here only by its fixture arms, which is the same
shape every other arm of this leg has and is why the harness exists.

### Alternatives rejected

Putting the count in `govkit check`. It already has one reader of the field and the verb needs a gov
checkout beside the target; nothing invokes it automatically, so the count would keep arriving only
when somebody already suspected the problem.

Failing the leg on a non-zero count. That is the intended end state and it is wrong for this
release: an adopter pulling both units at once gets a red bar whose remedy they have never had a
chance to run. Landing the note first gives them one release to clear it.

Reusing `install.sums` to find the rows. The sidecar carries `<sha256>  <path>` and no `evidence`
field at all, so it cannot answer this question.

## 5. Production-readiness checklist

- security — none. One string comparison over a file the leg already reads.
- perf / scale — one pass over the same rows list. Measured against inCMS's 95-row receipt, the cost
  is below the resolution of the leg's own timing.
- error / empty / loading states — the empty case prints nothing by design (S3); a receipt with no
  `files` key is already handled by the reader this loop sits inside.
- observability — the count is DERIVED at print time and never stated in prose anywhere. The line
  carries the remedy, so the reader's next step is on the same line as the finding.
- risks — the note is advisory, so an adopter can ignore it indefinitely and the drift the count
  measures keeps growing. That is accepted for this release and is exactly what the follow-up in the
  Edges section closes. Second risk: this unit ships a remedy string, and a remedy string that goes
  stale is what `DEPL-cMendedVintage-4` exists to fix — so the string is asserted by AC3 rather than
  only read by a human.
- testing — two fixture arms (S4), one populated and one empty. AC1 and AC2 observe them directly.
- migration — none.
- user docs — the script header sentence (S5). No other page states the leg's evidence arm.

## 6. Acceptance criteria

The file this unit edits is named here without backticks, for the reason the preceding unit's §6
states: `tools/check-spec-tokens.py` grades every backticked path-shaped word in this section against
`git ls-files`, and the file does not exist until that unit lands.

- **AC1** — When check-receipt.py runs with `--selftest`, the arm whose fixture receipt carries two
  rows with `evidence` set to `unattributed` prints a `NOTE` line naming the count 2, and the run's
  exit status is 0.
  Red when: the loop tests for the key rather than the value, so a synthesized row with no
  `evidence` field is counted and the number disagrees with `govkit update`'s own.
  figure: DERIVED — the 2 is the fixture's own row count, read from the printed line.
- **AC2** — When the same `--selftest` run reaches the arm whose fixture receipt carries no such row,
  no `NOTE` line about evidence is printed.
  Red when: the line is printed unconditionally with a zero, which makes its presence carry no
  information.
- **AC3** — When the populated arm's output is read, the remedy it prints contains `--pin` and does
  not contain the string `--re-adopt --write` unaccompanied by `--pin`.
  Red when: the loop copies the remedy sentence from `govkit.py:7853`, which is the no-op form.
- **AC4** — When check-receipt.py runs with `--selftest`, its printed arm count is two higher than
  the count the preceding unit's AC2 observed.
  Red when: an arm is added to the harness without being registered in it, so it never runs and the
  count does not move.
  figure: DERIVED — both counts are read from the runs, never asserted from this document.
- **AC5** — When the head of check-receipt.py is read, it states that the `evidence` arm is a note
  and names the condition under which it becomes a failure.
  Red when: the header claims the leg verifies the receipt without qualifying which arm decides and
  which only reports, which is the overstated-name class a gate header is supposed to close.

target. The seam this unit extends is therefore the file `TOOL-cMendedVintage-6` creates,
`tools/run-gates/check-receipt.py`, by path. Re-verified against source at BUILD time, addresses
corrected per rev-2:
