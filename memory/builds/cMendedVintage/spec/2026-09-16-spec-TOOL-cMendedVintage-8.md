## 1. Goal

`tools/process-monitor/scope.py:276` returns 1 when the declared roots admit no live process AT THAT
MOMENT, and `tools/process-monitor/adopt-process-monitor.sh:228` folds that into the same `else`
branch as a genuine conf refusal and exits 1. So the kit's `[check]` verdict depends on what is
running on the machine, and `govkit update` — which re-runs each kit's `[check]` and rolls the kit
back on a red — can withdraw a correctly installed process-monitor for the time of day. This unit
gives the empty case its own exit code and has the adopter treat it as a self-announcing skip.

## 2. Scope (IN)

- **S1** `tools/process-monitor/scope.py`'s `--check-conf` empty-scope branch returns 3 instead of 1.
  The message stays, and gains the word the operator needs: this is machine state, not a bad
  declaration. Observed by AC1.
- **S2** `scope.py`'s module docstring gains an exit-code contract line — `0` admitted, `1` refused,
  `3` the declaration is well formed and nothing live matches it. It carries none today, which is
  why a second reader could fold three outcomes into one. Observed by AC5.
- **S3** The `except (ScopeRefused, census.CensusRefused)` handler at `scope.py:267-269` keeps
  returning 1, unchanged. A duplicate `PROCMON_ROOTS` assignment, an unparseable conf, an absent
  conf, a census that cannot run — all of them stay failures. Observed by AC2.
- **S4** `adopt-process-monitor.sh:228-232` captures the child's exit status instead of branching on
  a bare `if`, and dispatches on it: 0 keeps today's agreement note, 3 prints an announced SKIP
  naming the case and the command to re-run, and every other value keeps today's refusal note and
  `exit 1`. Observed by AC3 and AC4.
- **S5** The adopter's own exit contract at its header stays true: 0 is still adopted or wired, 1 is
  still unwired or refused. The skip path exits 0 and says which arm went unexercised, which is what
  distinguishes it from a pass. Observed by AC3.
- **S6** Two arms are added: one in `tools/process-monitor/selftest.py` over `scope.main` with a conf
  whose single root is a real directory nothing runs under, and one in
  `tools/process-monitor/adopt-process-monitor.test.sh` whose scratch repo copies `scope.py` and
  `census.py` beside the adopter so the delegation is actually reached. `FLOOR_ASSERTIONS` moves with
  it. Observed by AC6.

## 3. Non-goals (OUT)

- No change to what `--check-conf` MEANS when the roots do admit live work. Exit 0 and the existing
  count line are untouched.
- No demotion of the adopter's exit status by itself. A single-line change there would demote the
  conf-parse refusal with it, and that refusal is the one thing in this path that must survive —
  which is why the discriminator is built in the engine and only read in the adopter.
- No capture of the child's stderr into the adopter's note. `aReapedSpinner`'s closing review asked
  for that in the same finding; it is a separate change to a different line and this unit does not
  smuggle it in.
- No fix for the path-SPELLING dependency the same review recorded — a root declared in MSYS form
  never matches a census carrying Windows spellings, and gov survives only because
  `.process-monitor.conf` declares both. This unit makes that case a skip instead of a red, which
  narrows its cost and does not close it.
- No new `[[outcome]]` row in `tools/process-monitor/kit.toml`. The adopter still exits 0, so
  govkit's existing `code = 0` probe reads `adopted` unchanged.
- No new gate leg and no predicate over descriptors. A check arm whose verdict depends on machine
  state is caught by review, not by a predicate — inventing one here would mean writing a gate that
  cannot fail, which is the defect one level up.

### Edges

- **hands-off** external — capturing the child's stderr into the adopter's note, and the root-spelling
  dependency. Both are recorded findings from the `aReapedSpinner` closing review and neither is
  carried by anybody in this build.

## 4. Design

### Data model

Three outcomes share one integer today. After this unit each has its own.

| condition | where it is raised | code before | code after |
|---|---|---|---|
| the roots admit live work | `scope.py:277` | 0 | 0 |
| `ScopeRefused` or `CensusRefused` | `scope.py:267-269` | 1 | 1 |
| the declaration is well formed, nothing live matches | `scope.py:272-276` | 1 | 3 |

3 rather than 2 because `adopt-process-monitor.sh` already spends 2 on "wrong invocation or not a
repo". The two files are read together by anyone debugging this path, and one integer meaning two
different things across them is the confusion this unit exists to remove.

### The adopter's branch

```sh
PROCMON_ROOT="$ROOT" "$PY" "$KIT_DIR/scope.py" --check-conf >/dev/null 2>&1
_sc=$?
case "$_sc" in
  0) print_note "the engine's own reader agrees, and those roots admit live work on this machine" ;;
  3) print_note "SKIP: the engine's reader accepted this conf, and nothing live matches those roots
                 right now — the live-admission arm went unexercised, not passed" ;;
  *) print_note "the engine's reader REFUSES this conf — run: ..." ; exit 1 ;;
esac
```

`set -u` is in force and `set -e` is not, so capturing `$?` on the line after the call is safe. The
skip text names the arm that did not run, because a skip that reads like a pass is indistinguishable
from coverage.

### Why the discriminator lives in the engine

The adopter cannot tell the cases apart from outside: both arrive as a non-zero status from one
command. Building the discriminator in `scope.py` also gives it a stated exit contract it does not
have, and keeps one reader of the declaration rather than two — the rule this kit's own
`read_roots` docstring already invokes.

### What this does NOT make deterministic

`scope.py --check-conf` still calls `census.scan_processes`, so the run still depends on the machine.
What changes is the DIRECTION of the dependency's effect: a machine with nothing running under the
declared roots now produces a skip instead of a red, and only a real declaration fault or a census
that cannot run produces a failure. The census refusal remains a failure deliberately: a census that
cannot run is a probe that cannot move, and reporting it as a skip would be the reassuring zero §7
names.

The other half of the same seam, recorded and not fixed here: the review that found this also found
that the `if not scope` branch has no reachable failing case under gov's SHIPPED declaration,
because the checker's own process tree sits under the declared root and seeds the scope itself. That
is why AC1's fixture declares a directory the kit is NOT under.

### Inventory

Minted by this unit: no new identifier. One integer literal changes, one `case` replaces one `if`,
and two test arms take names in the suites' existing `test_*` convention. `.lexicon.conf` grades
`py.function` at `snake` over its verb table and `scope.py` gains no function.

### Rollout

An adopter takes this on their next `update`, and the visible change is that a
`process-monitor wiring` leg which had been red on quiet machines becomes green with a named skip
line. Nothing they configured changes. gov's own tree is unaffected in the ordinary case because
`.process-monitor.conf` here declares roots that do admit live work.

### Alternatives rejected

Lowering the adopter's `exit 1` to a note. It cannot distinguish the cases, so it would also silence
a duplicate `PROCMON_ROOTS` assignment and an unreadable conf — the exact refusals the kit's own
`read_roots` docstring was written to preserve.

Declaring a `[[outcome]]` row mapping the new code. The outcome table reads the ADOPTER's status, and
the adopter exits 0 on the skip path, so there is no new code for govkit to interpret. A row would
be a declaration for a state that never reaches it.

Making `--check-conf` not call the census at all and grade the declaration only. That deletes the
only live-admission check the kit has, and the note in the adopter that advertises it would then be
the thing that is false.

### Files touched (estimate)

| Path | Change |
|---|---|
| `tools/process-monitor/scope.py` | one return value, one docstring contract line |
| `tools/process-monitor/adopt-process-monitor.sh` | the `if` becomes a status capture and a `case` |
| `tools/process-monitor/selftest.py` | one arm over `scope.main` |
| `tools/process-monitor/adopt-process-monitor.test.sh` | one arm, a scratch repo variant, `FLOOR_ASSERTIONS` |

## 5. Production-readiness checklist

- security — none. No path, credential or process is touched; one integer and one branch move.
- perf / scale — unchanged. The same single `--check-conf` call on the same schedule.
- error / empty / loading states — this unit IS the empty-state handling. The refusal states are
  listed in §4's table and each keeps its own code.
- observability — the skip line names the arm that went unexercised and the command to re-run, so a
  reader can reproduce the observation rather than infer it. The engine's message is unchanged in
  substance so existing operator notes stay recognisable.
- risks — an adopter whose roots are declared in the wrong path spelling now gets a permanent green
  with a permanent skip line instead of a permanent red. That is a real loss of signal and it is
  accepted here: the alternative is a leg that reds on a correct configuration, and the spelling
  defect has its own recorded row. Second risk: exit 3 reaching a caller that treats any non-zero as
  failure. The only callers are the adopter, which this unit changes, and
  `tools/run-gates/run-gates.sh:545`, which calls `--explain` rather than `--check-conf`.
- testing — two arms (S6). AC1 through AC4 observe both branches directly, and AC1 carries a liveness
  companion so the observation cannot pass by the census being dead.
- migration — none. No file format and no declaration changes.
- user docs — `scope.py`'s exit contract (S2) and the adopter's skip text. The kit README states what
  `--check-conf` grades and needs one sentence saying an empty live match is a skip.

## 6. Acceptance criteria

- **AC1** — When a conf declaring one real directory that the kit is NOT under and that has no live
  process beneath it is placed in a scratch tree and
  `PROCMON_ROOT=<that tree> python tools/process-monitor/scope.py --check-conf` runs, the exit status
  is 3.
  Red when: the empty-scope branch keeps returning 1, so the adopter cannot tell it from a refusal —
  which is the state this unit exists to leave.
  Liveness: the same command against this repo's own `.process-monitor.conf` exits 0 in the same
  session. Without that companion a dead census would also produce a non-zero status and the arm
  would grade nothing.
  fixture: the scratch tree does not exist today; the arm creates it under this run's scratchpad.
- **AC2** — When the same command runs against a conf carrying two `PROCMON_ROOTS=` assignments, the
  exit status is 1 and stderr names the duplicate declaration.
  Red when: the new code is returned from the shared handler as well, demoting every `ScopeRefused`
  and `CensusRefused` with it.
- **AC3** — When `bash tools/process-monitor/adopt-process-monitor.sh --check` runs in a scratch
  repo holding the adopter, `scope.py`, `census.py`, a wired `.claude/settings.json` and the AC1
  conf, it exits 0 and its output carries a line naming the unexercised live-admission arm.
  Red when: the adopter still folds 3 into its refusal branch and exits 1, which is the verdict
  `govkit update` rolls the kit back on.
  cost: building the scratch repo, tens of seconds; the repo goes under a SHORT path because a
  deep one fails to initialise on Windows.
  fixture: the adopter suite's `run_against` helper builds a scratch repo today and deliberately
  copies ONLY the adopter, so the engine is absent and the branch is never reached. The arm needs a
  variant that copies the engine too. The suite is named in section 7, where it is a declaration.
- **AC4** — When that scratch repo's conf instead carries TWO `PROCMON_ROOTS=` assignments, the same
  adopter invocation exits 1.
  Red when: the `case` routes an unrecognised status to the skip arm, so a real declaration fault
  reports as machine state.
  amended rev-3: the fault was "a root that is not a directory", which the adopter's own root rules
  refuse several sections BEFORE the delegation, so the arm never reached the `case` it claims to
  grade and would have stayed green with the `*` arm deleted outright. A duplicate assignment is a
  fault only the ENGINE sees — the shell sources the conf and the later assignment wins — so it is
  the one shape that arrives at the `case` carrying status 1.
- **AC5** — When the head of `tools/process-monitor/scope.py` is read, it states the three exit codes
  and what each means.
  Red when: the code is changed and the contract is not written down, leaving the next reader of the
  adopter to infer it from one branch.
- **AC6** — When `grep -c '^def test_' tools/process-monitor/selftest.py` runs, the count is one
  higher than at base `859daa67`, and `FLOOR_ASSERTIONS` in the adopter suite named in section 7
  reads higher than 31.
  Red when: an arm is written and never registered — the engine suite discovers its arms by scanning
  module globals for a `test_` prefix, so a helper defined under another name never runs, and an
  adopter arm added without moving the floor leaves the floor certifying a count it no longer
  bounds.
  figure: DERIVED — the grep count and the floor are both read at observation time; 31 is the value
  PINNED at base `859daa67` and is named so the comparison has a fixed left side.

## 8. Open questions

- **F1 — the value of the new code.** 2 is free in `scope.py` but is spent in
`adopt-process-monitor.sh` on "wrong invocation or not a repo", and the two files are read together.
RESOLVED (agent, 2026-09-16, delegated): 3, so no integer means two things across the pair. It passes
all three of M3's vetoes — no new dependency, no new surface, no widened write path — and it is the
option with fewer follow-ups, because reusing 2 leaves a note somebody must write explaining that the
two files disagree.

## 10. Reuse audit

`python tools/codebase-map/reuse_lookup.py "a check arm whose verdict depends on live machine state
and must announce a skip"` returned the `process-monitor` affordance seam itself — `scope.py`, with
`TOOL-aReapedSpinner-8`, `-9` and `-10` attached — plus `derive_verdict` and `scan_verdicts` in
`tools/process-monitor/classify.py`. Neither classifier is the seam: they grade census rows against
an age ceiling, not an exit status. The seam this unit extends is `scope.py`'s own `main` dispatch by
path, `tools/process-monitor/scope.py:262-280`, which already separates a refusal path from a verdict
path and needs one more return value rather than a new mechanism. The probe reported `.sh` as an
unscanned layer, so the adopter half is invisible to the map by construction and was read from source
instead. Verified against source at writing time: `scope.py:267-269` is the shared refusal handler,
`:272-276` is the empty-scope branch, and `adopt-process-monitor.sh:228-232` is the bare `if` that
collapses them.

Recall terms used: `--terms "process-monitor scope.py check-conf ScopeRefused CensusRefused adopter
exit code skip liveness DEAD PROBE kit check rollback govkit update"`, with the question "why must a
kit check arm that depends on live machine state announce a skip instead of exiting non-zero, and how
does an adopter check distinguish a refusal from an empty observation". It returned
`memory/builds/aReapedSpinner/reviews/2026-09-08-review-TOOL-aReapedSpinner-1-closing-diff-round2.md`,
whose finding R5 is this defect diagnosed at HIGH with a staged reproduction, and whose R6 records
that the empty-scope branch has no reachable failing case under the shipped declaration — the fact
AC1's fixture is shaped around.
