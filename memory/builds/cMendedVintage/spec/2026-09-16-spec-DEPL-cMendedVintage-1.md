## 1. Goal

`update --write` declines to re-render a kit, then runs that kit's own `[check]` — the program whose
job is to ask whether the render happened — and rolls the kit's writes back on the red it caused
itself. Make a kit whose check reds because of a step THIS RUN DECLINED report that fact instead of
reverting correct bytes.

## 2. Scope (IN)

- **S1** A `_rr_stale` mapping of kit id to decline string, populated at the two RENDER-STALENESS
  declines in `tools/govkit/govkit.py` — `:7409` (the kit ships `rendered` rows and declares no
  `[[regenerate]]`) and `:7416` (the flag is off) — and at neither the inert decline `:7387` nor any
  future decline that is not about staleness. Observed by AC1 and AC3.
- **S2** The green-to-red arm at `tools/govkit/govkit.py:7553` branches on membership in `_rr_stale`
  before it enters the restore loop: no path is restored, no receipt row is reverted, an order is
  written whose FIRST sentence is the decline string, and the existing `r.fail` still fires so the
  receipt is not re-stamped. Observed by AC1 and AC2.
- **S3** The verify tally line gains a count for this disposition, so a zero prints like every other
  count on that line rather than being absent. Observed by AC4.
- **S4** The decline print at `tools/govkit/govkit.py:7471` loses its `_rerender_on` gate and runs on
  every `--write`. Observed by AC3.
- **S5** The one shipped selftest arm that asserts a flag-off run prints no decline
  (`tools/govkit/selftest.py:9490`) is rewritten to assert what is now true: no regenerate ran AND
  the decline is named. Observed by AC5.

## 3. Non-goals (OUT)

- The inert decline at `tools/govkit/govkit.py:7387` is NOT added to `_rr_stale`. A target holding a
  kit inert chose that posture; if its check reds after this run moved bytes, this run is what broke
  it and the rollback is correct.
- No change to the rollback for any other cause. A kit that went green-to-red for a reason this run
  did not decline is still rolled back, byte for byte, as today.
- No suppression of the `r.fail`. The run still ends with findings and the receipt still withholds
  its `gov_commit` re-stamp — this unit changes what is UNDONE, never what is reported.
- The declared-but-failing regenerate at `tools/govkit/govkit.py:7440` is out of scope: that path ran
  the argv and it failed, which is not a decline.

### Edges

- **consumes-from** external — the re-render and decline block landed by `DEPL-dRetiredFork-3` and
  the verify/rollback pass landed by `DEPL-dCarriedReceipt-14`, both present at this build's BASE.
- **hands-off** `DEPL-cMendedVintage-2` — after this unit the green-to-red arm has two exits, and
  only one of them enters the restore loop. That unit's receipt-row gating therefore grades the kits
  this unit did not divert, and must not assume every rolled-back kit walked the loop.

## 4. Design

### Data model

`_rr_declined` is today a `list[tuple[str, str]]` of every decline, consumed only by the print at
`tools/govkit/govkit.py:7471`. It stays. `_rr_stale: dict[str, str]` is added beside it and is a
strict subset keyed by kit id, appended at the two staleness sites only. A dict rather than a set
because the verify pass needs the decline STRING to put in the order's first sentence, and re-deriving
it there would be a second copy of the same prose.

### The branch

```
if was == "adopted" and now == "landed-but-inert":
    if eid in _rr_stale:
        <write the declined-red order; count it; r.fail; continue>
    <the existing restore loop, unchanged>
```

Placing the test at the top of the arm rather than inside the path loop is what makes the receipt
row untouched as well as the bytes: the `for k in ROLLBACK_FIELDS` block that reverts the row sits
INSIDE that loop, so skipping the loop skips the revert for free and no second guard is needed.

### The order file

A distinct name, `update-declined-red-<eid>.md`, not the existing `update-rollback-<eid>.md`. The
rollback order's body is six sentences about paths that were put back, and every one of them is false
here; reusing the name would make the operator's only record of the event a document that describes
something that did not happen. The shape is modelled on the neighbouring
`update-preexisting-red-<eid>.md` writer at `tools/govkit/govkit.py:7533`, which already exists for
exactly this class — a red that is not this run's doing — and is the seam this unit extends rather
than a new mechanism.

Body, in order: the decline string as the first sentence; the check argv; both exit codes; the
vintage pair; then the statement that nothing was rolled back, that the writes stand, and that the
receipt is NOT re-stamped. It names the flag or the missing `[[regenerate]]` as the thing to fix,
because that is the difference between this and the pre-existing-red case, where nothing gov ships
is the cause.

### Un-gating the decline print

`tools/govkit/govkit.py:7471` reads `for _eid, _why in (_rr_declined if _rerender_on else [])`. With
the flag off — the default at this unit's BASE — a decline that can now decide a rollback is
invisible. The gate goes; the two lines above it that count runs and declines stay gated, because
those are the re-render step's own report and a flag-off run ran nothing.

This SUPERSEDES half of `DEPL-dRetiredFork-3`'s AC6, which asked for output byte-identical to the
pre-change run while the flag is off. That criterion bought a safe dark landing for a step that
printed nothing and did nothing. Once a decline decides whether bytes are reverted it is no longer
decoration, and silence is the defect. The amendment is recorded here rather than asserted: the
superseded criterion is named, and the arm that graded it is rewritten by S5 rather than deleted.

### Inventory

| Identifier | Kind | Where |
|---|---|---|
| `_rr_stale` | local dict in `_cmd_update` | `tools/govkit/govkit.py`, beside `_rr_declined` |
| `n_declined_red` | local counter in `_cmd_update` | beside `n_rolled` and `n_preexisting` |
| `update-declined-red-<eid>.md` | outbox filename | written under the target's `.governance` outbox |

All three are locals or a filename inside an existing directory; no public surface, no flag, no
config key. The counter's name follows its four siblings on the same tally line.

### Files touched (estimate)

`tools/govkit/govkit.py` — about 30 lines: the dict, two appends, the branch and its order writer,
one counter, one tally field, one gate removed. `tools/govkit/selftest.py` — one arm rewritten
(S5) and two arms added (AC1, AC4).

### The shipped arms this moves, named rather than discovered

`grep -c 'role = "rendered"' tools/govkit/selftest.py` returns 5, and none of the five belongs to a
rollback fixture: the `-14` rollback fixture kit `demo` ships `conf.txt`, `moved.txt` and
`renamed.txt`, all engine rows, and the `landkit` and `sib` fixtures the same. So `_rr_stale` is
empty in every existing rollback arm and none of them changes verdict. The figure is DERIVED by that
grep at build time, not pinned here.

The one arm that DOES move is `tools/govkit/selftest.py:9490`, which asserts
`"DECLINED" not in _pvoff.stdout` on a deliberately flag-off update over a kit that declares a
`[[regenerate]]`. S4 makes that string appear. Its subject — that no render RAN — is still correct
and still worth asserting, so the arm keeps `"ran review-harness" not in _pvoff.stdout` and its
decline half inverts to a positive assertion that the decline is named.

### Alternatives rejected

- **Suppress the kit's `[check]` for a declined kit.** That trades a wrong rollback for no
  verification at all, and the run would then report the kit verified or not-run, both false.
- **Make the decline set the baseline to red.** Forcing `was` to `landed-but-inert` routes it into
  the pre-existing-red arm, which reuses an order that says "this run did not break it" — true of the
  bytes and false of the cause. It also mutates a measurement to obtain a disposition.
- **Reuse `update-rollback-<eid>.md` with amended prose.** One filename for two dispositions makes
  the outbox unreadable and defeats any later reap keyed on name.

### Migration

None. No receipt field, descriptor key or on-disk schema changes. A target that has already been
rolled back for this reason is repaired by the next `update --write`, which reclassifies its rows
from the vintage they are actually at.

### Rollout

Lands ahead of the flag flip deliberately. With the flag off the `:7416` decline is the common case,
so this unit's branch is exercised at every adopter the moment it lands, which is the in-place
verification the flip needs behind it.

## 5. Production-readiness checklist

- **security** — no new write path. The branch writes one file into the outbox directory this verb
  already owns, through the same writer the two neighbouring orders use.
- **perf / scale** — one dict lookup per touched kit; the order file is written only on the branch.
- **error / empty / loading states** — a kit in `_rr_stale` with no snapshot rows still writes its
  order and still fails; an empty `_rr_stale` leaves every existing path byte-identical.
- **observability** — the tally line gains a fifth count and prints it including the zero; the
  decline lines print on every `--write`. This unit exists because a skip looked like a pass.
- **risks** — the supersession of `DEPL-dRetiredFork-3` AC6 is the substantive one, and S5 is its
  discharge. The second is scope creep in `_rr_stale`: a future decline added to the wrong list
  silently stops rolling a kit back, which is why §3 names the inert site as excluded.
- **testing** — AC1 through AC5 are direct selftest arms over fixtures; no bar and no suite verdict
  is an acceptance here.
- **migration** — N/A, nothing stored changes shape.
- **user docs** — `WIRE-INTO-PROJECT.md`'s maintenance section describes what an operator does with
  an outbox order; it gains the new filename and what it means. Two lines.

## 6. Acceptance criteria

- **AC1** — When a fixture kit ships a `rendered` row, declares no `[[regenerate]]`, and has a
  `[check]` that reds on the stale render, `python tools/govkit/govkit.py update --target <fixture> --write`
  leaves that kit's written bytes in place, leaves its receipt row at this run's values, writes
  `update-declined-red-<kit>.md`, and still exits non-zero.
  Red when: the branch tests the wrong list, so the kit walks the restore loop and the fixture's
  bytes revert to their pre-run index entry.
  fixture: none exists today; the arm builds one from the `-14` rollback fixture by adding a
  `rendered` row and a check that reads it.
- **AC2** — When that order file is read, its FIRST sentence is the decline string this run recorded
  for that kit, and the file does not contain the word `restored`.
  Red when: the order is written from a template that describes a restore, so an operator reads a
  revert that did not happen.
- **AC3** — When the same fixture runs with the re-render flag OFF, the run's stdout carries a
  `DECLINED <kit>:` line naming that kit.
  Red when: the print keeps its `_rerender_on` gate, so the decline that decided the disposition is
  absent from the only record the operator sees.
- **AC4** — When any `update --write` completes, its verify tally line carries the new count, and it
  reads `0` on a run where nothing was declined-red.
  Red when: the count is printed only when non-zero, which is the silent-zero shape this file's own
  neighbouring comment refuses.
- **AC5** — When the flag-off arm at `tools/govkit/selftest.py:9490` runs, it asserts that no
  regenerate ran and that a decline IS named.
  Red when: the arm is left asserting the absence of `DECLINED`, in which case S4 turns a shipped
  green arm red and the unit lands on a broken suite.

## 7. Gates

`govkit selftest` · `govkit selfcheck` · `govkit refusal join` · `govkit acceptance matrix`

New arm: tools/govkit/selftest.py · a fixture kit with a `rendered` row, no `[[regenerate]]`, and a
`[check]` that reds on the stale render, driven through `update --write` · none

`govkit refusal join` is named because this unit adds no refusal branch — the existing `r.fail` is
reused on the new exit — so its branch pin and anchor set must not move. A build-time reading that
disagrees means a refusal was added that this spec did not price.
