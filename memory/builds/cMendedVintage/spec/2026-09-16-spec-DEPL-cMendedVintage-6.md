## 1. Goal

`tools/unattended/` ships two fixture piece-records whose FILENAMES spell the install prefix, as
engine rows under the descriptor's `**` rule. At any prefix but gov's own, `update` restores gov's
spelling as a `missing` row and the adopter then renames that file over the target's own copy, so
every update destroys whatever the target held there. Close it the way the same descriptor already
closed it for the fixture playbook: make the records a `rendered` row whose destination carries the
prefix, and let the adopter write them instead of renaming them.

## 2. Scope (IN)

- **S1** The two tracked records under `tools/unattended/fixture-records/` gain template sources in
  the kit root, outside the records directory, each carrying `{{KIT_DIR}}` where the piece path is
  spelled today. They sit outside `fixture-records/` because `check-playbook.sh` globs that directory
  and would read a template as a record. Observed by AC3.
  rev-2: each template also carries the kit's `gov:kit unattended@<version>` marker as its first
  line, which the kit-version leg requires of every tracked `*.template.md` in the kit directory, so
  both records gain that line and the "bytes unchanged" clause below is narrowed to the body. The
  alternative was naming the two files out of that leg's population, which is a gate narrowed by
  spelling. `check-playbook.sh` reads a record by `piece:`, `hash:`, `run:` and its verdict lines, so
  a leading comment is inert to it — measured, both in this repo and at a foreign prefix.
- **S2** `tools/unattended/kit.toml` gains one `rendered` rule per template, each declaring
  `placeholders = ["KIT_DIR"]` and `to = "{kit}/fixture-records/{prefix}~{kit_id}~fixture-pieces~<n>~piece.md.md"`,
  which is the name the adopter derives from its own kit path. Observed by AC1.
- **S3** The same descriptor gains one `project-owned` rule naming gov's own two rendered copies, so
  their `{kit}/{relpath}` destination is claimed and the `**` engine pool drops them. Without it the
  wildcard still ships gov's spelling beside the rendered one, because `scan_claimed_paths` claims by
  DESTINATION and the two destinations differ at every foreign prefix. Observed by AC1.
- **S4** `adopt-unattended.sh` renders both records through its existing `render` function and its
  existing refusal on an unfilled placeholder, writing each only when the bytes differ, in the same
  block that renders the fixture playbook. Observed by AC2.
- **S5** The repath loop that renames `*~fixture-pieces~*.md` and rewrites the old prefix out of the
  body is deleted. The render supersedes it: the file is written at the derived name with the derived
  body, so there is nothing left to move. Observed by AC2 and AC5.
- **S6** The kit's version constant is bumped, because this changes which paths the kit lands.
  Observed by AC4.

## 3. Non-goals (OUT)

- No new descriptor token, and no engine change in `tools/govkit/govkit.py`. The destination is
  spelled with `{prefix}` and `{kit_id}`, which `target_context` already seeds.
- No change to the fixture PIECES, to `playbook.fixture.template.md`, or to what
  `check-playbook.sh` checks. The records' BODY is unchanged apart from the placeholder; rev-2's S1
  adds the kit-version marker line above it, which is the only other byte that moved.
- No withdrawal of the old rows at an adopter. An `update` after this lands reports each stale engine
  row as withdrawn and writes an order under the target's outbox; deletion still needs
  `--write-withdrawals`, and that stays the operator's call.
- The `hash:` field inside each record still names gov's piece bytes. A target whose piece copy
  carries a relocation or a line-ending carry will disagree with it, exactly as at BASE.
- No change to `record_path_of` in `tools/unattended/unattended.sh`. The record naming convention is
  the driver's and is shared with every build's records; changing it would rename records in every
  adopter tree.

## 4. Design

### Data model

Three rules over two files, and the reason each exists is a different property of the wildcard pool.

| rule | role | destination | what it buys |
|---|---|---|---|
| template one, template two | `rendered` | `{kit}/fixture-records/{prefix}~{kit_id}~fixture-pieces~<n>~piece.md.md` | gov declares the per-prefix name and never writes it; `update` caps at report |
| gov's own two records | `project-owned` | `{kit}/{relpath}` | claims the gov spelling so the `**` pool drops it, the mechanism this descriptor already uses to withhold its self-tests |

`{prefix}~{kit_id}` reproduces the adopter's `KIT_REL` with `/` written as `~` for every target whose
kit home is the default `prefix/kit_id`. A target that declares `kit.unattended.kit` explicitly
breaks that equality — see section 8.

### Migration

An adopter's first `update` after this lands sees two engine rows whose descriptor no longer claims
them. Those report as withdrawn with an order written to the outbox; nothing is deleted. The adopter
also gains two rendered rows with no receipt entry, which the same run lands through the unclaimed
source path, and the regenerate then writes them at the derived name. The hand-renamed copies an
adopter already holds are overwritten by that render, and the loss is nil: those copies exist only
because somebody repathed gov's bytes by hand, which is the work the render now does.

### Rollout

The descriptor half is inert in this repo — gov keeps no receipt of its own — so the only live effect
here is that `tools/unattended/fixture-records/` keeps the two files it has and gains two templates
beside the kit's other templates. `check-playbook.sh` reads the same corpus it reads today.

### Alternatives rejected

- **Declare the two records `seed`.** `update` never writes a `seed` row, so the churn would stop —
  but `cmd_check`'s evidence loop asserts EXISTENCE for `seed`, and the adopter's rename leaves gov's
  claimed path absent forever. Measured from source: the role tuple at the missing-file arm is
  `engine`, `seed`, `project-owned`, `generated`. That trades a data loss for a permanent red.
- **Keep the engine rows and claim the repathed destination with an explicit `to`.** The `**` rule
  would still pool the source, because a wildcard drops a file only when the destination IT would
  produce is claimed, and the gov spelling is not. Both copies would land.
- **A new `{kit_tilde}` token in the descriptor language.** It is the shortest edit and it widens
  govkit's public surface, which is an owner turn under the fork rule's second veto rather than a
  resolver's call.
- **Withhold the records entirely, as this descriptor withholds its self-tests.** The fixture exists
  precisely so the playbook leg never runs over an empty population — `check-playbook.sh` refuses a
  tree carrying no playbook declaration — and withholding the records would hand every adopter a
  fixture whose pieces nothing covers.

## 5. Production-readiness checklist

- security — no new command, no target-supplied value, and one fewer `mv` over a path composed from a
  filename. The render refuses an unfilled placeholder before it writes, which the rename could not.
- perf / scale — two template renders per adopter run.
- error / empty / loading states — an unfilled placeholder refuses and writes nothing; a records
  directory that does not exist is created by the same `mkdir -p` the fixture playbook uses.
- observability — one line per record written, and silence when the bytes already match.
- risks — the sharp one is the `**` pool: if the project-owned claim in S3 is wrong or absent, an
  adopter receives BOTH spellings and the corpus reports an orphan record. AC1 observes the
  destinations directly rather than trusting the rule to be read correctly.
- testing — AC1 and AC5 run `govkit` against a scratch target; AC2 and AC3 run the adopter and the
  playbook checker against a scratch tree.
- migration — section 4. Reversible: reverting the descriptor restores the engine rows, and the
  withdrawal orders the interim wrote deleted nothing.
- user docs — the kit README's fixture section drops its sentence about renaming records.

## 6. Acceptance criteria

- **AC1** — When `python tools/govkit/govkit.py plan --target <dir> --kits unattended` runs against a
  scratch target whose declared prefix is not `tools`, the two fixture-record destinations it prints
  carry that prefix in their basenames, and no `write` row it prints has a basename opening with
  `tools~`.
  rev-2 narrowed that clause from "no destination it prints" to "no `write` row", because the S3
  claim is what prints the other two: a `project-owned` row is marked `ORDER` by construction,
  exactly as this descriptor's seven withheld self-tests already are, and `apply` writes neither. The
  original wording could not be met by any design that withholds through a destination claim, which
  is the design S3 mandates.
  Red when: the project-owned claim of S3 is missing, so the wildcard pool ships gov's spelling
  alongside the rendered row and both appear in the plan.
  fixture: a scratch target created under the run's scratch root, because this repo keeps no govkit
  receipt of its own and no live install can observe it.
- **AC2** — When `bash tools/unattended/adopt-unattended.sh` runs in that scratch target, both
  records exist at the prefixed name, their `piece:` lines name files that exist in that tree, and
  the repath loop is gone from the script.
  Red when: the render writes gov's body verbatim, which leaves each record naming a piece path the
  target does not have — the orphan-record state the deleted loop existed to prevent.
- **AC3** — When `bash tools/unattended/check-playbook.sh` runs in that scratch target and again in
  this repo, neither run reports an orphan record or an uncovered piece for the fixture.
  Red when: a template is placed inside `fixture-records/`, where the checker's glob reads it as a
  record whose piece does not exist.
- **AC4** — When `python tools/govkit/govkit.py selfcheck` and
  `python tools/check-kit-placeholders.py` run, both exit 0.
  Red when: a `rendered` rule declares a placeholder its adopter does not substitute, or declares
  none while its template carries one.
- **AC5** — When `update --write` is run twice in a row against the scratch target with
  `GOVKIT_RERENDER=1` exported, the second run prints no `missing` row for either record and the two
  files on disk are byte-identical across both runs.
  Red when: any rule still lands gov's spelling, so the adopter's copy is rewritten on every update —
  the churn this unit closes.
  cost: two full update cycles against a scratch install, a couple of minutes.

## 7. Gates

No new arm. The class is already gated from the other side: `playbook validity gate` reports an

## 8. Open questions

- **Q1 — `{prefix}~{kit_id}` is not `{kit}` for a target that declares `kit.unattended.kit`.** Such a
  target installs the kit somewhere other than `prefix/unattended`, so the adopter derives one name
  and the descriptor declares another.
  RESOLVED (agent, 2026-09-16, delegated): declare it with `{prefix}~{kit_id}` and record the
  residue. The rule's role is `rendered`, which `update` caps at report and never writes, so the
  worst case for such a target is a row reported against a path its adopter does not use — a stale
  report line, not a misplaced write. The alternative needs a token that spells `{kit}` with
  separators replaced, which is a widening of the descriptor language and an owner turn.
- **Q2 — should the deleted repath loop leave a one-shot sweep for trees that already hold a
  hand-renamed copy?** RESOLVED (agent, 2026-09-16, delegated): no. The render writes the same
  destination the sweep would produce, so a sweep would be a second spelling of one rule, and the
  stale gov-spelled copies are reported as withdrawn rows with an order rather than left invisible.

### Residue the build measured (rev-2)

The COPY-INSTALL path in `WIRE-INTO-PROJECT.md` is a plain `cp -r` of the kit directory and reads no
descriptor, so a target that installs that way receives gov's two records beside the rendered pair
and `check-playbook.sh` reports each as an orphan record. It does not red — the reader classifies and
only `--close` blocks — and it is the standing of the seven self-tests that same path also copies and
that the descriptor withholds from `apply` alone. Measured at prefix `scripts`: pieces 2, verified 2,
plus two orphan notes naming gov's spelling. Deleting them from the adopter was refused for section
3's reason: an adopter that deletes is the class this unit closes, and a stale copy is the operator's
call through a withdrawal order. The runbook carries no removal step for this kit's withheld files at
all, which predates this unit and is reported rather than widened into here.

## 10. Reuse audit

`python tools/codebase-map/reuse_lookup.py "re-render a kit's rendered artifacts during an update"`
returned no seam and named `.sh` as an unscanned layer, so neither the adopter nor the playbook
checker is in the map's corpus; its ranked output is name-token noise. The seam this unit extends was
read from the descriptor itself: the `rendered` rule for `playbook.fixture.template.md` in
`tools/unattended/kit.toml`, whose adopter block says in as many words that rendering into the kit
directory is what lets `check-playbook.sh` run at any prefix. This unit applies that same rule one
file class further. The withholding half reuses the `project-owned` destination claim the same
descriptor already uses for its self-tests, and the engine behaviour it depends on is documented at
`scan_claimed_paths` in `tools/govkit/govkit.py`, which states that a claim is by destination and not
by source. The recall probe returned `TOOL-dPolishedVitrine-11`, the backlog row that measured this
churn on a fixture installed at prefix `scripts`, and the role table in
`memory/builds/aSealedCaravan/spec/2026-08-10-spec-DEPL-aSealedCaravan-2.md`, which is where the
`seed` alternative was refuted.

Recall terms used: `--terms "seed role engine pool descriptor claim destination project-owned
withheld update reseed receipt row fixture-records repath"`, with the question "what decided that a
seed row is copied once and never rewritten by update, and how is an adopter-renamed file kept out of
the engine pool".
