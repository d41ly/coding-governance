## gov has no receipt, so think about what this leg actually grades HERE

`.governance/install.json` does not exist in this repo. On gov's own bar, S2's `SKIP` path is what
runs — which means the only thing grading your checker on every gov bar is S4's four built-in fixture

## Three requirements that exist because of this repo's own failures

**S2 — the skip announces itself.** The head is the literal word `SKIP`, it names the path it looked
for, and it exits 0. A skip that looks like a pass is indistinguishable from coverage.

**S3 — the probe carries its own liveness.** A receipt that parses but yields ZERO graded rows reds
with `DEAD PROBE`, never a clean report. A signal with no liveness assertion returns a reassuring
zero when it is broken.

**S1 — the repo root is DERIVED through git and never spelled.** A kit file names nothing outside
itself by literal; its own kit dir and tool root are derived, and an empty derivation REFUSES. The
optional positional argument is what makes a fixture observable from the command line, so do not
drop it.

## Stage the failing case before you call any of it a gate

Every one of S1's reds — a missing file, a drifted sha256 — must be OBSERVED red, not reasoned about.
A gate you have only ever seen pass is an assertion about nothing, and that rule is in the charter
because this repo kept breaking it.

## Bans that bite harder on a shipped kit file

`.lexicon.conf` declares Python as a PARSER-mode language, so every function you write is graded —
lead each with a declared verb. `read`, `check`, `scan`, `measure`, `main` and `test` are all in the
table and all fit this file; ask `--suggest` for anything you are unsure of, because three specs in a
row in this build proposed names the gate would have redded.

Spell no `tools/<kit>/…` path in shipped prose or comments. And this is a new `.py` file written on
Windows: `python write_text` emits CRLF unless you pass `newline`, and `git add` hides it. Check the
STAGED bytes.
