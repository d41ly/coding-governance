## What that subject settles, and it is not what it first looks like

The instinct is to exclude `WIRE-INTO-PROJECT.md` from the population. That is WRONG and the
script's own header at `:50-53` says why: it is in the population deliberately, because it
PRESCRIBES install paths, so a root spelling there becomes a root install in every repo that
follows it — "highest leverage member of the set, not an edge case."

The carried ARM's concern is a different one: gov's bytes are written VERBATIM by `apply`, so a
carried literal arrives unchanged in a target installed at another prefix and resolves to nothing.
Nothing copies `WIRE-INTO-PROJECT.md`, so that concern cannot reach it. One file, in the population
for arm 1's reason and immune to arm 3's — which is precisely the shape S3's per-row exception list
with a per-row reason exists to express, and precisely what a blanket exclusion would get wrong.
