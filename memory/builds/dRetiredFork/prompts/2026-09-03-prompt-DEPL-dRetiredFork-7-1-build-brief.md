# Build brief — DEPL-dRetiredFork-7

**Serves:** journal DEPL-dRetiredFork-7

## What the unit is

Every number in this build rests on two adopter registers and BOTH undercount, in the direction that
makes the build look smaller than it is. This unit MEASURES and DECLARES; it fixes none of the files
it finds and edits neither adopter's tree.

It runs FIRST among the sweeps because a sweep that retires a fork nobody counted cannot be
verified.

## The method, and why it is blob-against-full-history

A file is classified by testing its blob against gov's ENTIRE object history, not against HEAD:

- byte-identical to gov HEAD — in sync
- identical to SOME gov vintage — DRIFT, not divergence
- in no gov commit EVER — an UNDECLARED FORK

That distinction is the whole point. Testing against HEAD alone would call every stale copy a fork
and inflate the programme; it is what makes swydee's 32-of-35 read as drift rather than divergence.

## A figure that has already moved

The spec's index is 23,384 blobs, measured at `b0108f13`. gov's history is now 27,729. The census
DERIVES the count and reports it; it must not carry the spec's number, because a number in prose
beside the thing that owns it is wrong on the next commit — and this one already is.

## What each criterion demands, briefly

AC1 eleven inCMS `engine` files in no gov commit · AC2 two NicoCares files in NEITHER register ·
AC3 swydee 32 of 35 identical to a vintage · AC4 a census mapping ZERO files REFUSES · AC4b the
`gen_build_index.py` row named with both symbol counts · AC5 the ledger contract with a worked
retirement · AC6 backlog rows carrying file, line and measurement · AC7 the reverse-direction
contradiction recorded with both registers quoted.

If a measured figure disagrees with the spec's, the MEASUREMENT wins and the difference is recorded.
The spec's own §5 says this census is the input to every other unit's sizing.
