# TOOL-aRuledFrontispiece-11 — the corpus is conformed to the slot contract, by hand

**Status:** CLOSED · rev-1 · 2026-08-17 · node a · Tier-2 · base 96141aed · streams tooling

## 1. Goal

Move authored prose in the build READMEs that violate the slot contract, and wrap each authored unit
plan in its marker pair, so that the corpus satisfies the contract unit 1 defines before the leg that
enforces it lands. This is the only unit in the build that edits an authored byte of another build's
record.

## 2. Scope (IN)

- **S1** — every tracked build README whose authored content violates the slot sequence is
  restructured so that all authored prose precedes the first generated marker. The population is
  DERIVED by running `python tools/memory-tree/gen_build_index.py --check-format` at this unit's
  parent commit and taking the files it names. No count is written in this spec, and no file list is
  copied into it, because both moved twice during the design pass.
- **S2** — every build README carrying an authored unit plan gains a `<!-- roster:units -->` pair
  around that plan. Population derived the same way: the READMEs whose authored plan the
  `--check-format` walk identifies.
- **S3** — DERIVED or MUTABLE columns are moved OUTSIDE the pair before it closes. A plan region is
  frozen for a run's whole life by `check_authorization`, so a status token, a state column or a
  per-row progress marker inside it would freeze a value the build method orders a run to update.
  This is fork 1's Option A split, and S3 is the half that makes it true rather than nominal.
- **S4** — a README whose plan boundary cannot be determined without judgement is NOT edited. It is
  listed in this unit's build record with the reason, and left on unit 1 S5's no-pair branch, which
  is legal. A guessed boundary is worse than an absent pair, because the pair is what a later run
  byte-compares.
- **S5** — this unit changes NO generated byte. Every edit lands outside every generated marker pair,
  and `python tools/memory-tree/gen_build_index.py --check` reports the same artifact count and the
  same clean verdict at this unit's tip as at its parent.
- **S6** — the per-file record of what moved, and why, is written to this build's `build/` folder as
  a recording. A 14-file authored diff is not reviewable from the diff alone.

## 3. Non-goals (OUT)

- Re-rendering anything. The re-render and the kit version bump are position 10; this unit's own
  acceptance requires the generated bytes to be untouched.
- Editing the CONTENT of any authored prose. Sections move; their text does not change. A reworded
  paragraph in another node's build record is not this unit's to write.
- Adding a plan pair to a README that has no authored plan. 26 of the corpus carry none at the time
  of writing, and inventing one would author a roster no build ever declared.
- Inserting any generated marker pair by hand. Unit 1's `--write` creates those; see its S1b.
- Making the plan pair mandatory. That is `TOOL-cBriefedPilot-18` on another node.

## 4. Design

### Migration

One file at a time, each verified before the next begins. The order is the order
`--check-format` names them, so the pass is resumable after an interruption by re-running it.

Per file: read it whole · identify the authored sections after the first generated marker · move them
above it, preserving their relative order · identify the authored plan, if any · wrap it, moving
derived columns out first · re-run `--check-format` on that one file · move on.

### Rollout

A single commit. The alternative — one commit per file — was considered and rejected: the unit's
acceptance is a corpus-wide predicate, and 14 commits each leaving the leg red would violate M6's
rule that a pass whose gate is red is not followed by another. The per-file record in S6 is what
makes the single commit reviewable.

### Alternatives rejected

Scripting the relocation was rejected. The transformation needs a judgement per file about where an
authored section belongs relative to its siblings, and a script that guesses would rewrite another
node's build record silently. The one mechanical half — detecting the violation — is already unit 1's
`--check-format`, and this unit consumes it rather than reimplementing it.

Deferring the surgery into the retrofit unit was the design at the time of the spec audit. It was
rejected because that unit then carried four mechanisms, collided with the leg unit over the same
authored bytes, and made its own "pure re-render" claim false.

### Files touched (estimate)

Build READMEs under `memory/builds/`, restricted to the derived population · one new recording under
`memory/builds/aRuledFrontispiece/build/`.

## 5. Production-readiness checklist

- security — N/A. No executable surface and no new input.
- perf / scale — N/A. A one-time editing pass.
- a11y — N/A.
- i18n — N/A. No text is rewritten, only relocated.
- error / empty / loading states — S4 is the empty case: a file whose plan boundary is ambiguous is
  skipped and recorded, never guessed.
- observability — the S6 recording is the observability, and `--check-format` is the verdict.
- risks — this is the highest-risk unit in the build and the reason it is its own unit. It edits
  authored records belonging to other nodes' builds, in files that carry NO merge driver, so a
  concurrent node's edit to the same README conflicts positionally. The mitigation is that the unit
  is one commit, late in the order, and touches no generated byte, so a conflict resolves by taking
  this unit's side of the authored hunks and re-running `--write` for everything else.
- testing + left-shift gates — `--check-format` over the corpus is the left-shift; the leg at
  position 11 is what makes it permanent.
- migration / rollback — a single-commit revert restores every moved section, because no generated
  byte moved with it.
- user docs — none. The contract is documented by unit 1.

## 6. Acceptance criteria

- **AC1** — When `python tools/memory-tree/gen_build_index.py --check-format` runs over
  `memory/builds/` at this unit's tip, it exits 0 and names no file.
- **AC2** — When `python tools/memory-tree/gen_build_index.py --check` runs at this unit's tip, it
  reports the same artifact count and the same clean verdict as at this unit's parent commit,
  compared by running it at both rather than against a figure quoted here.
- **AC3** — When `git diff <parent>..HEAD` is filtered to the generated regions, it is empty: no
  line between any `<!-- gen:` marker and its close differs, proving S5.
- **AC4** — When a build README carrying a plan pair is inspected at this unit's tip, no derived or
  mutable column appears between its `<!-- roster:units -->` markers, checked on every file the unit
  wrapped.
- **AC5** — When `bash tools/memory-tree/check-memory-hygiene.sh` runs at this unit's tip, it exits 0,
  including check 2's link integrity over every relative link in every relocated section.
- **AC6** — When the S6 recording is read, it names every file the unit edited and every file S4
  skipped with its reason, and the union of those two lists equals the population
  `--check-format` named at the parent commit.

## 7. Gates

`bash tools/memory-tree/check-memory-hygiene.sh` · `python tools/memory-tree/gen_build_index.py --check`
· `python tools/memory-tree/gen_build_index.py --check-format` · `bash tools/run-gates.sh` at the
push boundary. This unit does NOT discharge `tools/memory-tree/check-verdict-epoch.sh`: it moves no
engine line, so it needs no constant move, and the build's one bump is position 10.

## 10. Reuse audit

Recall terms used: `authored derived section front matter schema refused ids roster marker region
truth-blind parity byte-compare generated index`.

| Behaviour needed | Existing seam | Decision |
|---|---|---|
| detect a slot violation | unit 1's `--check-format` | REUSE — this unit is its first consumer and derives its whole population from it |
| freeze an authored region across a base commit | `check_authorization` in `tools/unattended/unattended.sh` | REUSE unchanged — S3 exists to keep what it freezes freezable |
| record a multi-file authored change | this build's `build/` recording convention | REUSE — no new artifact kind |

No seam exists for relocating authored markdown sections, and none should: the reuse probe returned
only marker-region splicers, which operate INSIDE a pair, whereas this unit operates entirely outside
one. That absence is the evidence for the Alternatives-rejected decision not to script the pass.
