## Verdict: BLOCKED

M8 closing review of the cumulative diff `96141aed..HEAD` (tip `fc5393e`, 77 files), four lenses plus
this synthesis. Every BLOCKER and HIGH below was re-run by the synthesis pass against source or in a
throwaway clone of the worktree; the worktree itself was not modified. Two findings survive as
blockers. The first is a records defect the build already knows about and answered three different
ways: a CLOSED Tier-2 spec mandates a `KIT_UNATTENDED_VERSION` bump in two acceptance criteria, the
build README says the park behind it was never put to the owner, and neither literal moved in the
whole range. The second is the one this review exists to catch: the S1c asymmetry — `--write` creates
a missing region pair, `--check` never demands one — was implemented as a skip that is applied to
`build-index` too, so the pre-existing refusal for a README with no marker pair is unreachable from
the corpus path. A build README can now lose its entire generated surface and stay green on
`--check`, on `--check-format`, on hygiene check 9, and on every other leg that could be run.

The seam the per-pass reviews could not see is exactly where both blockers sit. Unit 1 built the
asymmetry; unit 10 re-rendered the corpus over it; nothing between them re-asked whether the
asymmetry had swallowed a refusal that predated the build. Unit 8's spec closed on an owner turn the
build README records as never taken, and no later unit re-read the pair.

The build's central claim — a build README is a mostly-generated, gated surface — holds for the
regions that are present and fails for the region that is absent. Everything downstream of that (the
slot walk, the byte tier, the surgery) is sound where it was tested, and the lenses refuted a long
list of plausible attacks on it, recorded below.

## What the lenses refuted

The attacks below were tried and failed, and are recorded so a later pass does not re-run them.

**The new leg binds.** `tools/gate-legs.json` carries the slot-contract leg with no `guard` key;
appending authored prose to a build README and running it through the runner produces
`GATE FAIL  build README slot contract (exit 1)` naming both offending lines. The `python3` argv is
rewritten through the resolved launcher like every other python leg.

**The cap tier binds where it is present.** A zero line cap really means no cap (the guard
short-circuits), and the build-README branch of both caps is reachable: a 400-char authored line in a
build README reds check 7 at the 350 tier, so the class test fires and the widened cap is the one
applied. The widest generated row in the corpus is 211 chars, so the tier does not put rendered
titles under an invisible budget, and the wrapped roster line cannot exceed its own limit. Both
curation-debt rows are live and non-vacuous — 27013 bytes against the byte tier, and a 419-char
authored row against the width — and neither is a pre-emptive waiver.

**Check 8's population did not starve.** The index set is 67 members including all 39 build READMEs;
the shards keep the guard measuring, and the dead status-file alternatives are unioned with live
selectors so they widen nothing. Check 4 still binds the retirement: a re-added status file is
reported as an illegal folder entry rather than silently readmitted.

**The order verb cannot leak or break the header grammar.** The spec parser matches the header on a
single line, so prose occurrences of the verb in a spec body cannot reach the region; hygiene check
12's grammar is unanchored at the end and accepts the verb, so no landed spec goes retroactively red.
A glob-valued phase cannot escape check 8's case guard — a quoted pattern segment is literal, and both
malformed-marker refusals stay outside the carve-out and were armed in both directions.

**The render is a fixed point and conserves authored bytes.** Write-check-write over the real corpus
leaves the tree unchanged; region insertion lands in declared order over all fifteen non-empty removal
subsets; a full strip-and-restore differs only in blank lines. The roster wrapper never drops or
duplicates an id and cannot exceed its width for any producible roster. CRLF is handled on both halves
of every comparison this diff introduces. Eleven of the twelve new selftest arms red under a targeted
break — only the one named above survives its own defect. `apply_region`'s generalisation is
backward-compatible: the contract test's positional call still works and the reworded refusals name
the pair they were called with.

**No second copy of the single-sourced values.** The roster wrap width is stated relationally
everywhere but its one literal; the memory-tree kit version moved in the constant and all seven
markers together and is deliberately not repeated in prose; the four region names exist only in the
declaration; the leg name is gated by the map. The three superseded specs each carry a machine-checked
successor pointer. The traceback on an absent README predates this range.

**Two lens claims were corrected by this pass.** P5's "unit 2 of the order" is *correct* — position 2
is the unattended unit — so it is excluded from the numbering finding above. And the optional plan
pair is present in 2 of 39 build READMEs, not 1.

## Needing an owner turn

- **The version bump behind P5.** The spec records an owner resolution that the code did not take, and
  the build README says the question was never put to the owner at all. Only the owner can say which
  of those is the record. Everything else in the first blocker follows from that answer.
- **P6 — restructuring roster tables inside build folders owned by other nodes.** Already flagged in
  the build README as an owner item that a spec answered instead; the surgery has now run. The owner
  either ratifies that reading or overrules it.
- **P7 — the byte tier the owner set.** It now binds a file whose generated half grows with every
  record, at 551 bytes of headroom. Bounding the region, exempting generated bytes, or moving the
  number are three different answers and the number is the owner's.
- **Fork 5's "required in a follow-up commit".** The verb cannot be made mandatory while the document
  that owns the header grammar forbids the slot and no spec in the corpus carries it. The owner should
  say whether the follow-up is still wanted, and in what order relative to the grammar fix.
- **The two curation-debt rows.** Both name other builds' READMEs, so draining them is those owners'
  curation, not this build's.
