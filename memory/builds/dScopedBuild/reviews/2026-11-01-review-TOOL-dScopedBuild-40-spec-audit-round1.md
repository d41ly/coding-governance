## High

### H1. AC2's rerun witness is a name-only staged set, so a duplicated ask row stays green (id 14)

- **Where:** spec-41 §2 S1; §6 AC2.
- **What is wrong:** S1 (:65) makes unit 39 AC17 read the staged set by `git diff --cached --name-only`. AC2 (:257-261) asserts that the paths are BACKLOG.md and that "a rerun at the same tip leaves that output unchanged". Its only red is checkout False. `write_ask_rows` appends and then runs `GIT add -- "$bl"` (unattended.sh:9994), so BACKLOG.md is already in the cached name list after run 1. The duplicate guard lives in the caller's reuse loop (:10035-10041, `read_ask_back` over existing ids), and `derive_ask_seq` mints each id fresh (:10057-10058). A writer without the reuse step appends a new-id row on the rerun, and the name-only output does not change.
- **Consequence:** Unit 39 AC17's "stages one ask per finding" and "a rerun at the same tip stages none" (spec-39:362-365) can no longer fail, and neither can unit 27 AC3's "files one per run" red. A writer with no idempotence key passes, both on a first run that files two rows for one finding and on a rerun that duplicates every row. The row is append-only, so a duplicate can only be superseded. The check certifies, on the rerun path, a count it does not read.
- **Fix (judged SOUND by the skeptic):** Keep `--name-only` for AC2's "every path is a BACKLOG.md" half. For the count and the rerun, read the staged content: `git diff --cached -U0 -- <bl> | grep -c '^+- <FAM>-'` (or the ask ids ASKS_CMD reads back) must equal the number of findings after run 1 and be unchanged after run 2. The pattern matches only ask rows, since SEV and KEEP rows open `- SEV ·` and `- KEEP ·` (:10067-10072). Name the key, the ask id per finding, as a one-to-one join. The build must run this probe: a rerun with the reuse check removed from the writer turns AC2 red.
- **Left-shift gate:** a bug-class checklist entry under the class `append-without-an-idempotence-key`: an idempotence criterion over an append-only writer reads row content or ids, never a path set. A spec-lint rule can flag a criterion that pairs `--name-only` with "rerun" or "one per".

## Medium

### M1. Unit 40's S2 class is stated over every path, but is false for a declared directory (ids 8, 15)

- **Where:** spec-40 §2 S1, S2; §4 "The rule, after this unit"; §6 AC1, AC2.
- **What is wrong:** S2 (:43-45) states, for "a population of paths", that no result r ending `/` has an entry equal to r or starting with r. The rule at :84-88 skips the guard when r equals the path, returns the path when the guard fires, and never re-tests S1's "reduces to itself" fallback. So a path ending `/` can come back covering a nested entry. With `["pkg/sub/core/"]`, the declared `pkg/sub/` falls through to `pkg/`, the guard fires, and the result is `pkg/sub/`, which prefixes the entry. With `["packages/core/"]`, the declared `packages/core/` returns as itself and equals the entry. With `["src/app/"]`, the declared `src/` has r equal to the path, so the guard is skipped. The input is reachable: unit 3 S2 (spec-3:73-74) keeps spec words of two or more segments, and `read_spec_writes` applies no shape filter (design_lib.py:528-531). AC2 checks only `git ls-files`, which lists no path ending `/`, plus AC1's four file pairs.
- **Consequence:** AC2 passes while the stated class is false over its real population, the write sets `read_unit_writes` reduces. `check_guard_trips` (design_lib.py:589-598) shows that a declared `pkg/sub/` is meant to admit `pkg/sub/core/x`, so the behaviour is arguably intended. The spec does not say so, though. A builder or later unit that grades S2 over write sets reds on a legitimate directory declaration, or "fixes" it in a way that breaks declared directories.
- **Fix (id 8 judged SOUND; id 15's finder fix judged UNSOUND, and this is the skeptic's corrected fix):** Restate S2's class over results that differ from their path (equivalently, over file paths). In S1, state that a path ending `/` whose guarded or unguarded result is the path itself is the declaration's own grant and stands, by `check_guard_trips`' directory semantics. Add the planted pair `src/lib/` with `["src/lib/core/"]`, expected `src/lib/`, to AC1. Add a directory row such as `pkg/sub/` with `pkg/sub/core/` to the §4 table, so the builder sees the intended behaviour. Keep AC2's assertion scoped to results that differ from their path. Do not make a declared directory refused or narrowed, and do not make every directory input reduce to itself: the first breaks `check_guard_trips`' contract, and the second changes unit 38's reduction (e.g. `docs/guide/` to `docs/`).
- **Left-shift gate:** a spec-audit checklist entry: a reduction rule's class names every input shape it accepts (file, directory, nested entry), and its criterion's population holds at least one of each.
