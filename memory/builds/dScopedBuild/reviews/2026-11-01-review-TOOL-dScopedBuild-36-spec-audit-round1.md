## High

### H1. The fall-through still hands a nested routed root to a unit that declares an unrouted sibling (id 24)

- **Where:** spec-38 §2 S1, S3; §6 AC2.
- **What is wrong:** S1's fall-through reduces any unrouted path holding a `/` to its first segment. When a ROUTED_PATHS entry is nested (e.g. `packages/core/`), or is a file entry under an unrouted directory (e.g. `docs/api.md`), that first segment covers a routed entry. S3 and AC2 only check that no result EQUALS a directory entry, so they cannot see the problem. The skeptic reproduced it: with entries `['packages/core/']`, `packages/README.md` reduces to `packages/`, and `design_lib.check_guard_trips('packages/core/main.py','packages/')` returns True. Spec-3:73-74 keeps any spec word with two or more segments, so such a declaration is reachable.
- **Consequence:** In an adopter whose routed roots are not top-level, one declared sibling file gives a unit the whole parent as its write set. The scope arm passes strays, unit 5's lease admits every write as inside, and unit 8's claim arm reads every key as held. That is the widening unit 38 exists to close, on the narrower path of nested or under-directory entries. AC2 stays green.
- **Fix (the finder's fix was judged UNSOUND; the skeptic's corrected fix):** Keep the class rule: an unrouted path reduces to its first segment only when no ROUTED_PATHS entry starts with that segment plus `/`, and otherwise it reduces to itself. State AC2 as: no result r ending `/` has any ROUTED_PATHS entry equal to r or starting with r. Add the `src/app/` fixture: a spec declares `src/README`, a commit writes `src/app/x`, and `src/app/x` must be listed stray. The staged break restores the first-segment fall-through.
- **Left-shift gate:** a spec-audit checklist entry: a reduction rule over adopter config is stated as a class over every entry shape (top-level, nested, file entry), and its criterion is "covers no entry", never "equals no entry".
