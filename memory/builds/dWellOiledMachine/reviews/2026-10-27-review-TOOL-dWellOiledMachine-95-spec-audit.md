**H1. The amendment-ordering probes can never print the amendment commit (ids 1, 11, 12, 13, 19, 20, 21, 29, 30, 31)**
- Where: spec-95 §6 AC2 (first half), with §2 S3 and §5. Spec-96 §6 AC5, with §2 S4. Spec-97 §6 AC15, with §2 S24 and §5.
- What: each probe is `git log --reverse --format=%s <BASE>..HEAD | grep -E "TOOL-dWellOiledMachine-(...)([^0-9]|$)" | head -1`, and each requires the output to be this unit's amendment commit. With RUN.md:30's base 0689e7fa, the earlier spec-set commits already match first. The (90|95) probe prints 089c397aa, the round-2 spec commit. The (93|96) and (91|92|93|94|97) probes print e446e9582, the round-3 spec commit. Both predate any amendment, so `head -1` cannot reach one.
- Consequence: read literally, the three criteria are red on a correct build. Read loosely, they are green before anything is built. Either way, nothing checks that the amendments land before units 90, 91-94 and 93 build. In 96 and 97 this probe is the only ordering check. §5 of 95 and 97 names it as the detector for a skipped M2 cross-read. A late amendment lets unit 93 build the verbatim parse and publish wrong `yes` cells tree-wide, or lets units 91-94 build uncorrected text (including 94's AC29 writing the live health.log), and nothing catches it. AC2's second half in spec 95, the design_lib history count, still works.
- Fix (skeptics: SOUND for ids 1, 11, 12, 13, 19, 20, 21, 29, 30; UNSOUND for id 31, whose corrected fix follows): replace subject ordering with an ancestry check, per amended spec N.
  - A = the amendment: `git log --reverse --format=%H 0d8692025..HEAD -- <spec N> | head -1`. 0d8692025 is the round-4 spec commit, so every match comes after it. Optionally also require that A's subject names the amending unit (95, 96 or 97).
  - P = unit N's first pass commit: the first `build(<slug>): TOOL-dWellOiledMachine-N` subject (or `Pass: TOOL-dWellOiledMachine-N` trailer), or the first commit touching a file under N's Files touched.
  - Require `git merge-base --is-ancestor A P`. For 95 that is N=90, for 96 N=93, and for 97 each N in 91..94.
  - Stage the red case once: an amendment committed after a scratch pass commit for N must fail the check.
  - Do not anchor A on content strings with `-S`. `fixture-session` is already in spec 91, so `git log -S fixture-session` finds e446e9582 and the check would pass whatever the order. `derive_arm_suite_path` (spec 93) and `NOT BUILT HERE` (spec 90) are absent today and would work, but the scheme is not reliable for every spec.
- Gate: add a checklist entry: a git-log criterion over `<BASE>..HEAD` names the earlier commits in that range that already match, and shows its output against them in §4 Evidence. Ordering claims are checked with `merge-base --is-ancestor`, never by which subject comes first.
