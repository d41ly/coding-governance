## 1. Goal

The project map is delivered by slice: the structural roles receive it in their work order, and the
unit workers, the builder, the tester and the rest, receive no map, so "a `gov map` call from one is
journaled as a read outside its slice"
(`memory/builds/dClosedLoop/build/2026-10-17-build-PLAY-dClosedLoop-1-project-map.md:626`). Nothing
counts such a read today, so no one can tell whether a slice starves its role. This unit adds a
`record`-class hook pack that sees every shell call running `gov map`, judges the calling role
against `memory.project-map`, writes one `map-read-outside-slice` journal line per read outside the
slice, and a reader that counts those lines per role.

## 2. Scope (IN)

- **S1** — The pack, `tools/runtime/map-reads.fragment.json` with its command
  `tools/runtime/map-reads.js`, in unit 10's pack contract (I9): event `PostToolUse`, matcher
  `Bash|PowerShell`, `owner` `dWellOiledMachine`, `class` `record`, `failure` `open`, `budget-ms`
  3000, `key` `memory.project-map`, and a `purpose`. It runs on the dispatcher's `PostToolUse` entry
  (I10, `dispatch.js`). It reads the payload from stdin and acts only when `tool_input.command`
  matches `MAP_CALL_RE`, a call of `gov_map.py` (TOOL-dTotalRecall-14 S2, the stand-in for `gov map`)
  or the words `gov map` at a command position; on a match whose payload carries a non-empty
  `agent_type` it runs `python map_reads.py record --role <agent_type> --session <session_id>`, adding
  `--act <id>` when the environment carries `GOV_ACT`, through the resolved interpreter. It never
  blocks and exits 0 on every path, the record class's rule. Observed by AC1, AC4.
- **S2** — The slice, `check_map_in_slice(role, value, roles)` in `tools/runtime/map_reads.py`,
  `value` the resolved `memory.project-map` (catalogue `tools/policy/catalogue.toml:1444-1448`,
  `structural-roles`, `every-role`, `owner-only`) read through `resolve` (I31,
  `tools/policy/policy.py:752`), `roles` the roles kit's `load_roles` (`tools/roles/roles_lib.py:355`):
  `every-role` puts the map in every role's slice; `owner-only` in none; `structural-roles` in every
  role whose `writes` key is not `product`. A role the catalogue does not name has no declared slice
  and reads outside it: deny by default. Observed by AC2.
- **S3** — The line. `python map_reads.py record` writes, when S2 answers outside, one line through
  `write_journal_line("map-read-outside-slice", fields)` (I3, TOOL-dWellOiledMachine-16 S3), the
  fields `session`, `act` when given, `role` and `slice=<value>`, and nothing of the command's text,
  which can carry a secret. Inside the slice it writes nothing. A refused write prints one stderr line
  and exits 0, so the record class never fails the call. Observed by AC1, AC2.
- **S4** — The count, `measure_map_reads(journal, since=None, role=None)` in `map_reads.py`, read only
  through `read_journal` (`point.journal-readers`' contract, TOOL-dWellOiledMachine-16 S7). `python
  map_reads.py count [--since <utc>] [--role <role>]` prints
  `map reads outside a slice — <n> · <role> <k> · …`, roles ordered by count then name, or
  `map reads outside a slice — 0` on none. Observed by AC3.
- **S5** — The page `help/runtime.md` gains a section on the count: what a map read is, which slice
  each `memory.project-map` value gives a role, and the count command. Observed by AC5.

## 4. Design

### Evidence

- The delivery table names who receives the map and says the unit workers receive none
  (project-map.md:614-627); the work-order slot it names sits beside `reuse`, and at this base
  `tools/roles/handoff.py:97` is `TASK_FIELDS` with no `map` field (scout D's disagreement, verified).
- `memory.project-map`'s row is at `tools/policy/catalogue.toml:1444-1448`, owner dFurnishedOrders,
  whose `cl-dClosedLoop-0203` gives the slot "for the roles `memory.project-map` names"
  (`memory/builds/dClosedLoop/build/2026-10-19-build-PLAY-dClosedLoop-1-as-built.md:214`).
- A subagent's tool-call payload carries `agent_type`, which the write gate already reads
  (`tools/hooks/scratch-guard.js:1168`); the main loop's carries none (`:96`).
- The roles catalogue's `writes` class is `product` for the builder (`.claude/roles.json:17`) and
  `none` or `spec` for the structural roles beside it.

### The flow

```
shell call ──▶ dispatch.js PostToolUse ──▶ map-reads.js
                                             │ no MAP_CALL_RE match, or no agent_type ─▶ exit 0
                                             ▼
                                python map_reads.py record --role R --session S [--act A]
                                             │ check_map_in_slice(R, memory.project-map, roles)
                                             │ inside ─▶ nothing written
                                             ▼
                          write_journal_line("map-read-outside-slice", session, act, role, slice)
```

### Inventory

| `measure_map_reads` | Python function | `py.function`, `measure`, OK |

The lexicon refused `count_map_reads` for `measure`, which counts a population and decides nothing.

### Rollout

Live at landing for every act session and Workflow agent whose calls pass the dispatcher. Under the
default `structural-roles` a builder's `gov map` call writes a line from the first call.

### Files touched (estimate)

- `tools/runtime/map-reads.js`
- `tools/runtime/map-reads.fragment.json`
- `tools/runtime/map_reads.py`
- `tools/runtime/kit.toml`: the fragment declared with the kit's others
- `.claude/settings.json` and `.claude/hook-packs.json`: renders of the fragment through the settings
  merge (TOOL-dWellOiledMachine-10 S3), never edited by hand
- `help/runtime.md`

### Alternatives rejected

- **Count inside `gov_map.py`.** One choke point, but `gov_map.py` sees no `agent_type`: it runs in
  the caller's environment, and a Workflow agent shares its session's. The payload is where the role
  is.
- **A Python pack with no JS filter.** Every shell call would start an interpreter; the JS filter
  starts one only on a match.
- **A typed list of structural roles.** A second list beside the roles catalogue, which the slot's
  owner will declare; §8 F2.

## 5. Production-readiness checklist

- security — the line carries the session, act, role and key value, never the command's text; the
  pack writes only through the journal's one writer.
- perf / scale — one regular-expression test per shell call; an interpreter start only on a `gov
  map` call by a role.
- error / empty / loading states — a payload that is not JSON, a refused journal write or an
  unreadable key exits 0 with one stderr line: a record pack never fails the call (§8 F3).
- observability — the count command and `gov trace` (TOOL-dWellOiledMachine-34) read the lines.
- risks — the stand-in reading counts a structural role whose `writes` is `product`; none exists at
  this base. A `gov map` call spelled through a variable or a script escapes `MAP_CALL_RE`, stated in
  the help page.
- testing — the fixture plants under §6 and the arm in §7.
- migration — none: a new journal class and a new pack.
- user docs — `help/runtime.md`.

## 6. Acceptance criteria

The fixture is `python map_reads.py --fixture --plant <case>`: a scratch git repository with the
roles index and agent files of this base, a planted policy file, the journal root under its git
common dir, and a payload fed to `map-reads.js` as the dispatcher feeds it.

- **AC1** — When `--plant builder-reads` feeds a `PostToolUse` payload whose `agent_type` is
  `gov-builder` and whose command is `python gov_map.py`, under `memory.project-map`
  `structural-roles`, the journal gains exactly one `map-read-outside-slice` line carrying
  `role=gov-builder`, `slice=structural-roles` and a `session`, and no field holding the command.
  Red when: the pack's matcher is emptied, so the builder's call writes no line.
- **AC2** — When `--plant spec-writer-reads` feeds the same call from `gov-spec-writer`, no line is
  written; `--plant every-role` writes none for `gov-builder`; `--plant owner-only` writes one for
  `gov-spec-writer`; `--plant unknown-role` writes one for `agent_type` `stub-role`.
  Red when: a structural role under `structural-roles` is counted, or an unnamed role is read inside
  its slice.
- **AC3** — When `--plant three-reads` writes two lines for `gov-builder` and one for `gov-skeptic`
  under `owner-only`, `python map_reads.py count` prints `map reads outside a slice — 3 · gov-builder
  2 · gov-skeptic 1`, and over an empty journal it prints `map reads outside a slice — 0`.
  Red when: the count reads a line `read_journal` refuses, or prints a role it never saw.
- **AC4** — When `--plant main-loop` feeds the builder's call with no `agent_type`, and `--plant
  not-map` feeds `git status` from `gov-builder`, no line is written and `map-reads.js` exits 0; when
  `--plant bad-payload` feeds bytes that are not JSON, it exits 0 with one stderr line.
  Red when: a non-map call writes a line, or a malformed payload exits non-zero.
- **AC5** — When `grep -n "memory.project-map\|map reads outside a slice" runtime.md` runs over the help
  page, both are named.
  Red when: the page omits the count command or the slice rule.
