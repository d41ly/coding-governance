## 1. Goal

Two builds that wait on each other wait until both deadlines pass, and nothing names the cycle; a
dependent held on a parent that ends incomplete waits for ever (gap-rt-38, gap-flow-10). This unit
builds the wait graph across builds when any wait passes half its deadline, over parent holds,
interface waits, lease waits and open mailbox questions, raises one owner item naming every build of
each cycle, and releases the dependents of a parent that ended incomplete to
`deps.on-parent-withdrawn` (the stall-and-loop record's item 9, P39).

## 2. Scope (IN)

- **S1** — The trigger: `waits.py sweep` (TOOL-dWellOiledMachine-18 S3) ends by asking, for each
  `open` wait, `check_deadline_passed <wait ref> <declaration commit> <deadline-seconds / 2>`
  (TOOL-dPlacedRequest-17 S4); when any answers rc 0, it runs `derive_wait_graph(repo)` in
  `tools/runtime/wait_graph.py` once for that sweep, printing `graph — <n> build(s) · <m> edge(s) ·
  <k> cycle(s)`. With no wait past half, no graph is built. `python wait_graph.py show` builds and
  prints it on demand, one `edge — <waiter> → <awaited> · <source>` line per edge. Observed by AC1.
- **S2** — The edges, a waiter build to the build it waits on, from four sources: parent holds, each
  open build's README `parents:` front matter naming a parent whose last transition, read through
  `read_transitions` (TOOL-dDeclaredLoop-3 S7), is not terminal; interface and lease waits, each
  `open` wait record whose `on` ref names another build, the slug the segment after the namespace in
  `refs/gov/leases/<slug>/`, `refs/gov/mail/<slug>/`, `refs/gov/life/<slug>`, `refs/gov/waits/<slug>/`
  or `refs/gov/builds/<slug>/`; and open mailbox questions, each `open` `question` row of `--mail read`
  (KICK-dKeptSession-5 S6, S8) from one build addressed to `build:<other>` or to a `unit:` id of
  another build (KICK-dKeptSession-28 S4). A source that cannot be read is named in the summary line
  and contributes no edge. Observed by AC1, AC2.
- **S3** — The cycles, `scan_cycles(edges, live)`: the hold-cycle walk of
  `tools/memory-tree/backlog.py:1271` (`_scan_cycles`), extracted at its second instance into
  `tools/lib/scan_cycles.py` between `# >>> scan_cycles_py` and `# <<< scan_cycles_py`, carried
  inline in `backlog.py` and `wait_graph.py` under a `scan_cycles_py` row of
  `tools/lib/resolve-python.test.sh`'s `PARITY_ROWS`. Each cycle is reported once, rotated to its
  smallest member; `_scan_cycles` keeps its name and its terminal filter by passing the live set, so
  the backlog's verdicts do not move. Observed by AC2, AC5.
- **S4** — One owner item per cycle: `raise_owner_item("cycle", <smallest member>, ["replan:<slug>"
  for each member], "replan:<newest member>", key=<members joined by +>)`
  (TOOL-dWellOiledMachine-48 S1), its body line `cycle: <a> → <b> → <a>` naming every build, the
  newest member read from its README's `opened:` front matter. The key makes a cycle met again post
  nothing new; the kind `cycle` joins `OWNER_ITEM_KINDS`. Acting on the decision is the named build's
  own driver's. Observed by AC2, AC3.
- **S5** — A parent ending incomplete. For each parent-hold edge whose parent's last transition is
  `incomplete` (TOOL-dDeclaredLoop-31) or `withdrawn`, the graph runs `python loop_parents.py route
  --build <dependent> --state <its state>` (TOOL-dDeclaredLoop-15 S6), whose answer reads
  `deps.on-parent-withdrawn`; a move answer is recorded through `write_transition` on row P1, and an
  owner-item answer raises `raise_owner_item("owner-write", <dependent>, ["withdraw", "keep"],
  "keep", key=<parent>)`. `read_withdrawn_parents` (TOOL-dDeclaredLoop-15 S5) reads a parent whose
  last transition is `incomplete` as withdrawn, beside its stand-in. A dependent already moved off
  the parent's interface is skipped, so each dependent is released once per parent ending. Observed by
  AC4.
- **S6** — `help/runtime.md` gains a wait-graph section: the trigger, the four sources, one item per
  cycle, and the release to `deps.on-parent-withdrawn`. Observed by AC6.
- **S7** — The fixture, `tools/runtime/graph_fixture.py --case <name>`: a scratch repository with
  planted build folders and READMEs, a bare remote holding planted wait records, leases and mail, and
  `loop_parents.py` resolved through `resolve_kit_dir`. It prints the graph's lines, the owner items
  posted and the transitions written. Observed by AC1 to AC5.

## 3. Non-goals (OUT)

- No journal line: a node-tick sweep carries neither the `act` nor the `session` key

  relation, and stays as it is.

## 4. Design

### Evidence

- No graph across builds exists: `git grep -n "wait graph" -- tools` finds nothing.
- Two cycle walks exist: `_scan_cycles` (`tools/memory-tree/backlog.py:1271-1290`), a Python walk
  over a dict of edges reporting each cycle once and rotated, and `scan_consumes_cycles`
  (`tools/unattended/lib-unattended.sh:399`), an awk walk over one build's spec edges that stops at the
  first cycle. The Python one is this unit's shape, so this is its second instance.
- The parent read and route are dDeclaredLoop's (TOOL-dDeclaredLoop-15 S5, S6), the read standing in
  on `RUN.md`'s `phase: ABORTED`, and `deps.on-parent-withdrawn` is a row
  (`tools/policy/catalogue.toml:704`, `replan`, `adopt-parent-work`, `withdraw-too`).
- The design: "When a wait passes half its deadline, the supervisor builds the wait graph across
  builds (parent holds, interface waits, lease waits, open mailbox questions). A cycle raises one owner
  item naming every build in it" (stall-and-loop.md:246-248).

### Data model

```
graph — 2 build(s) · 2 edge(s) · 1 cycle(s)
edge — fx → fy · mail question 1a2b3c4d5e6f
edge — fy → fx · wait refs/gov/waits/fy/9e8d7c6b5a41
owner item — cycle · fx · deadline 2026-10-27T14:03:07Z
```

- `help/runtime.md`: the section

### Alternatives rejected

- **A third cycle walk written for the graph.** The reuse rule extracts the factory at the second
  instance; `_scan_cycles` already reports each cycle once and canonically, which one item per cycle
  needs.
- **The graph built at every sweep.** The clause builds it when a wait passes half its deadline, and a
  graph built on every tick reads every mailbox for nothing.

## 5. Production-readiness checklist

- security — read-only over refs and READMEs; its writes are owner items and a recorded move, each
  through its own unit's guarded path.
- perf / scale — built only when a wait passes half its deadline; one mailbox read and one wait-ref
  read per build.
- error / empty / loading states — an unreadable source is named and contributes no edge; no wait
  past half builds nothing.
- observability — the `graph —` and `edge —` lines and the cycle's owner item.
- risks — an edge from a stale mailbox question can close a false cycle; the owner item names its
  source so the owner can see it.
- testing — the fixture cases under AC1 to AC5 and the arm in §7.
- migration — none: the backlog's cycle verdicts are byte-identical through the extracted walk.
- user docs — `help/runtime.md`.

## 6. Acceptance criteria

Each case runs `python graph_fixture.py --case <name>` in its scratch repository.

- **AC1** — When `--case half` plants a wait at 40% of its deadline and runs `waits.py sweep`, no
  `graph —` line is printed; past 50% the sweep prints `graph —` with the planted edges.
  Red when: the graph is built before any wait passes half, or never after.
- **AC2** — When `--case two-builds` plants `fx` with an open question to `build:fy` and `fy` with an
  open wait on `refs/gov/leases/fx/build`, both past half, the sweep prints `1 cycle(s)` and posts one
  owner item whose body names `fx` and `fy`.
  Red when: the two planted builds each waiting on the other raise no owner item, or one naming only
  one of them.
- **AC3** — When `--case two-builds` runs the sweep three times, exactly one `owner item cycle`
  message exists.
  Red when: the cycle is raised twice.
- **AC4** — When `--case parent-incomplete` plants `fz` with `parents: fx` and `fx`'s last transition
  `incomplete`, under each value of `deps.on-parent-withdrawn`, `replan` and `adopt-parent-work`
  record `fz`'s move to `planning` and `withdraw-too` posts one `owner-write` item for `fz`; a second
  sweep records nothing new.
  Red when: a dependent of a parent ending incomplete stays held, or is released twice.
- **AC5** — When `--case backlog-parity` runs `backlog.py`'s `_scan_cycles` and the inline
  `scan_cycles` over one planted edge set holding a three-member hold cycle entered from each member,
  both return the same one cycle, rotated to its smallest member.
  Red when: the extracted walk moves a backlog verdict or reports one cycle twice.
- **AC6** — When `grep -n "deps.on-parent-withdrawn" runtime.md` runs over the help page, it names
  the section, and the page names the four edge sources and the half-deadline trigger.
  Red when: the key, a source or the trigger is absent.
