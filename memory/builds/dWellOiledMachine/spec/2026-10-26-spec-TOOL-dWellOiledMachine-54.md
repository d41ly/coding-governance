## 1. Goal

No node can find work it does not hold: nothing reads released or expired leases across builds, a
node "with quota takes the build over" with no way to find it, and today's resume tick skips every
lease another node hosts (gap-conc-16; `tools/unattended/resume-tick.sh:285`). Nothing matches work to
what a node can run (gap-rt-46). This unit gives a project one read of its claimable ready set, a
pure, replaceable pick that first drops work the node profile cannot run and then orders the rest,
the node tick claiming what it picks, and the preset check refusing a role set to a harness that has
no model for it (P40; the owner's CL-3 and FK-3-2; cloud-and-scale items 8 and 18).

## 2. Scope (IN)

- **S1** — Discovery, `derive_claimable_set(repo)` in the new `tools/runtime/discover.py`, one read
  per call: the repository's own leases through the one lease reader, `unattended.sh --claims`
  (`read_claims`, `tools/unattended/unattended.sh:2118`, one bounded fetch), and its builds' units
  through the build index's `collect` (`tools/memory-tree/gen_build_index.py:1106`). A row is
  claimable when it is (a) a unit whose spec status is `SPECCED` or `INPROGRESS`, with no live,
  held or offered lease, whose build's every parent the dependency gate of KICK-dKeptSession-7 reads
  `confirmed` or `landed`; or (b) a lease released as a hand-over, or expired by
  TOOL-dPlacedRequest-17's observer rule, whose build has an (a) row. Never a lease whose `status` is
  `landed`, `aborted` or `withdrawn`, and never a build whose state TOOL-dDeclaredLoop-31 S7 reads
  `parked`. It reads no other project's leases: the remote is this repository's own, through its
  remote ladder. Observed by AC1, AC4.
- **S2** — What a row's work needs, `read_unit_needs(row)` in `discover.py`: the roles of every
  `[[workflow]]` row of `tools/roles/workflows.toml` whose `driver` is `workflow` and whose `stage` is
  at or after `build`'s, read through `load_workflows` (`tools/roles/roles_lib.py:364`); for each role,
  its harnesses from `resolve_role_harness` (TOOL-dWellOiledMachine-56 S1), its model on each harness
  from `resolve_role_model` (TOOL-dBoundRoles-21 S5) reading `roles.model.<role>.<harness>`, and its
  `hardware` field (S5). Observed by AC2.
- **S3** — The pick, `derive_pick(rows, needs, profile, plans, fleet_tag)` in the new
  `tools/runtime/pick.py`: pure, reading nothing and writing nothing, the function the built-in
  `node-pick` adapter at `point.offer-sources` names (TOOL-dWellOiledMachine-55 S2), so another adapter
  row there replaces it. In order:
  1. set a row aside when some role of its work has no harness in the profile's `[[harness]]` names
     (`harness`), no model on the harness kept (`model`, the resolver raising), or needs more
     `cpus` or `memory-gb` than the profile's `[hardware]` (`hardware`);
  2. order by plan priority, then the oldest released, a fresh unit ordered by its build's `opened:`
     date and then its `order`;
  3. keep a recorded stream plan's units in its order: a unit of a `[[stream]]`
     (TOOL-dTotalRecall-25 S2) is eligible only once every lower-`order` unit of that stream is
     closed or leased;
  4. start from a spread start: the fresh units sharing the head's priority rotate by
     `derive_spread_start(fleet_tag, n)`, the first eight hex digits of the SHA-256 of the fleet tag
     modulo `n`;
  5. move a row whose `offer` names this node, or this node and session, to the front: an offer only
     reorders and never restores a row set aside.
  Observed by AC2, AC3, AC5.
- **S4** — The claim at the node tick. `python pick.py next --repo <root>` reads the profile through
  `read_node_profile` (TOOL-dWellOiledMachine-61 S3) at `resolve_node_home`, refusing
  `pick — refused · profile <state>` unless its state is `read`, prints one `pick — set aside · <slug>/<unit>
  · <why>` per row set aside and the ordered rows, and `tools/unattended/resume-tick.sh` runs it once per
  tick after its own leases, claiming the first row through `unattended.sh --lease acquire` for a
  fresh or released row and `--lease take-over` for an expired one, under `RUN_CLAIMS`. The acquisition
  is the witness; a lost compare-and-swap moves to the next row. Observed by AC1, AC3.
- **S5** — A role's hardware, a `[[field]]` row `hardware` in `tools/roles/role-schema.toml`
  (TOOL-dBoundRoles-2 S1): optional, `cpus=<n>, memory-gb=<n>`, each a positive integer; absent
  means no need. Observed by AC2.
- **S6** — The preset check widened. `check_role_models(assignment)` in `tools/policy/presets.py`,
  run beside `check_repo_presets` (KICK-dKeptSession-1 S3) over the effective assignment, refuses a
  role whose `roles.harness.<role>` set names a harness with neither a `roles.model.<role>.<harness>`
  value nor an adapter equivalent: `roles.harness.<role> names <harness>, which has no model for
  <role>; set roles.model.<role>.<harness>`, at the line `derive_key_line` finds. The equivalent is
  asked of `python roles_lib.py model <role> <harness>`, a CLI this unit adds over
  `resolve_role_model`, exit 2 on its `RolesError`, found through `resolve_kit_dir` since a kit
  imports no sibling kit. Observed by AC6.
- **S7** — The page `help/runtime.md` gains discovery and the pick: what is claimable, the three
  filters, the order, the spread start and what an offer may do; `help/policy.md` gains S6's refusal.
  Observed by AC7.

## 4. Design

### Evidence

- The tick skips a lease another node hosts: `case "$host" in ""|absent|"$me") ;; *) … skip · leased on
  $host` (`tools/unattended/resume-tick.sh:285`).
- `--claims` prints one row per claim on the remote (`print_claims`, `tools/unattended/unattended.sh:2200`),
  over `read_claims`; TOOL-dPlacedRequest-1 widens its rows to eighteen fields with `kind`, `epoch` and
  `offer`.
- `roles.harness.<role>` is a set of harness names, never set by a preset
  (`tools/policy/catalogue.toml:319-324`, v2:1191); `roles.model.<role>.<harness>` derives from the
  adapter's equivalent (`:313-317`), and `HARNESS_MODEL_EQUIVALENT` holds `claude-code` alone
  (TOOL-dBoundRoles-21 §4 "The model").
- The node profile holds `[hardware]` `cpus` and `memory-gb` and `[[harness]]` names
  (TOOL-dWellOiledMachine-61 S2); no role declares a hardware need at this base
  (`git grep -n hardware -- tools/roles` finds none).

### The pick, by example

```
rows (after S1):  fx/TOOL-fx-2 fresh   gy/build released 09:10   gy/TOOL-gy-4 fresh (codex-only role)
profile:          harness claude-code; hardware cpus 8, memory-gb 16
drop:             gy/TOOL-gy-4 · harness
order:            gy/build (released 09:10) · fx/TOOL-fx-2 (fresh, opened 2026-10-20)
offer to me:      fx/TOOL-fx-2 -> front
pick:             fx/TOOL-fx-2, gy/build
```

### Migration

Additive. The `hardware` field is optional, so no role file changes; a policy file whose
`roles.harness.<role>` names a harness without a model is refused at its next validation, naming the
key to set, which is the clause's red case.

### Alternatives rejected

- **The tick claiming every lease it can.** Without an order every node races for the same head and
  the oldest released work starves; the spread start and the age order are the clause's.
- **A model list in the node profile.** The profile's schema is closed (TOOL-dWellOiledMachine-61
  S2), and a role's model on a harness is already one key the resolver reads.
- **The preset check reading the roles kit by import.** A kit imports no sibling kit; the CLI keeps
  the resolver the one answer.

## 6. Acceptance criteria

The fixture is a bare remote and two clones, `na` on node `a` and `nb` on node `b`, under `%TEMP%`
with short names, each with a planted node profile under its own `GOV_NODE_HOME`, the runtime,
policy, roles, memory-tree and unattended kits installed, and planted builds `fx` and `gy`.

- **AC1** — When `na` releases `gy`'s build lease as a hand-over and `nb`'s tick runs, `nb` prints
  `gy/build` among its rows from `python pick.py next`, then `lease — gy/build` from its acquisition,
  and `git ls-remote` shows the lease held by `b`.
  Red when: a released lease whose build has ready work is left unclaimed by every node.
- **AC2** — When `fx/TOOL-fx-2` is offered to `b` and its builder role's `roles.harness.<role>` names
  only `codex`, which `nb`'s profile lacks, `python pick.py next` in `nb` prints
  `pick — set aside · fx/TOOL-fx-2 · harness` and never lists the unit; with a role needing
  `cpus=32` it prints `hardware`.
  Red when: a unit offered to a node without its harness is picked.
- **AC3** — When a stream plan records `TOOL-fx-3` at order 1 and `TOOL-fx-4` at order 2 and neither
  is leased, `python pick.py next` lists `TOOL-fx-3` and not `TOOL-fx-4`; once `TOOL-fx-3` is leased it
  lists `TOOL-fx-4`.
  Red when: a stream's units are picked out of its order.
- **AC4** — When `fx`'s planted unit lease carries `status: landed`, `derive_claimable_set` returns no
  row for it, and a build whose state reads `parked` contributes no row.
  Red when: a terminal tombstone is offered as claimable.
- **AC5** — When `derive_pick` runs twice over the same input it returns the same list and touches no
  file, and over three fresh units of one tier the fleet tags `a` and `b` start at the rotations
  `derive_spread_start` computes.
  Red when: the pick reads or writes state, or every node starts at the same unit.
- **AC6** — When `python policy.py check` reads a planted policy file setting
  `roles.harness.gov-builder = ["claude-code", "codex"]` with no `roles.model.gov-builder.codex`, it
  refuses naming `roles.harness.gov-builder`, `codex` and the key to set, at its line; with
  `roles.model.gov-builder.codex = "gpt-5"` it admits the file.
  Red when: a role set to two harnesses with no model for the second is admitted.
- **AC7** — When `grep -n "spread start"` runs over the runtime kit's page `runtime.md`, the section
  names the three filters and what an offer may do.
  Red when: a drop or the offer rule is missing.
