## 1. Goal

A node's runtime facts go unrecorded: node d's clock runs 8 to 13 seconds slow and its `autocrlf`
differs from CI's, and nothing writes either down (gap-rt-08, gap-register:273); the registry that
exists holds free text (gap-tool-18, :249). A lease's expiry is judged today by the reader's raw clock
against the writer's stamp (`tools/unattended/unattended.sh:2177-2186`), which TOOL-dPlacedRequest-17
replaces with an observer rule and leaves the second rule of v2:1160 to this build: the holder's
stamp on its last renewing beat corrected by the clock offset its supervisor measures against the
remote host's time. This unit records the node's runtime facts at its home, measures the offset at
each beat through the host adapter, publishes it in the beat, and adds the corrected-stamp rule
beside the observer's, either expiring the lease as `leases.expiry-hours` says.

## 2. Scope (IN)

- **S1** — The facts file (I8): `<home>/facts.toml` at `resolve_node_home()` (I5,
  TOOL-dWellOiledMachine-61), `schema = "1.0"`, holding `[clock]` `offset-seconds`, `read-utc`,
  `source`; `[git]` `autocrlf`; `[process]` `start-ms`; `[[user-guard]]` rows `event`, `command`,
  `on-failure`; and the `[[binary]]` rows TOOL-dWellOiledMachine-36 writes, `binary`, `version`, `os`,
  `shell`, `bash`, `path`, `interpreters`, `measured-utc`. The file lives outside every repository and
  is never committed. Observed by AC1.
- **S2** — The one writer, `write_node_fact(section, value)` in `tools/runtime/facts.py`: it parses
  the whole file, replaces that section or that `[[binary]]` row keyed by `binary` and `path`, and
  writes through a temp file and an atomic replace. `read_node_facts()` returns the parsed file, an
  empty one when absent, and refuses a file that does not parse or whose `schema` major is newer than
  `1`, naming the file. A credential shape `scan_secrets` finds in any value is refused at write.
  Observed by AC1 and AC2.
- **S3** — The clock offset, `measure_clock_offset()`: the host adapter is the `point.host-adapters`
  row `run.host` names (TOOL-dWellOiledMachine-13 S2, read through `resolve("run.host")`, I31), and its
  `remote-time` reader decides how the remote host's time is read. `http-date`, this unit's reader
  `read_remote_time`, takes the remote the remote ladder resolves (`resolve_remote`,
  `tools/lib/resolve_remote.py`, carried inline as `remote_ladder_py`), maps an `https://` or ssh URL
  to its host, and sends one HTTPS `HEAD /` with redirects refused and a 5-second bound, reading the
  `Date` header. The offset is the remote time minus the midpoint of the local send and receive,
  whole seconds, written to `[clock]` with `source = "http-date"`. A local-path remote, `none`, a
  timeout or a missing header writes `offset-seconds = "-"` with the reason as `source`, never `0`.
  Observed by AC2.
- **S4** — At each beat: `write_claim_beat` (`tools/unattended/unattended.sh:2469-2500`), the beat
  TOOL-dPlacedRequest-1 carries onto the lease record, runs `python facts.py measure-clock` before it
  writes, and the one record writer `write_claim` (`:2396`) adds the key `clock-offset: <seconds>|-`
  to every record it writes, read from `[clock]` with no network call. The key is additive: a reader
  that does not know it skips it (the reader's key filter, `:2168`). Observed by AC3.
- **S5** — The corrected stamp where expiry is judged, in `read_claims`' age pass (`:2155-2186`, the
  pass TOOL-dPlacedRequest-17 S3 rewrites to the observer clock): the reader also carries the
  renewing beat's `clock-offset` as a twelfth `CLAIM_ROWS` column, and when that and this node's own
  `[clock] offset-seconds` are both numeric, the corrected age is `(now + own offset) - (beat-utc +
  holder offset)`. The verdict reads `stale` when the observer age OR the corrected age exceeds
  `leases.expiry-hours` (v2:1160, "either rule expiring the lease"); with either offset `-`, the
  observer rule alone judges. Observed by AC4 and AC5.
- **S6** — The node's other runtime facts (layer-runtime `[harness]`), `python facts.py measure-node`:
  `[git] autocrlf` from `git config --get core.autocrlf`, `-` when unset; `[process] start-ms`, the
  median wall time of five `python -c pass` launches; `[[user-guard]]` one row per hook in the user's
  harness settings, with whether it sets `onFailure`. The node tick runs it when the file's
  `measured-utc` is over a day old, from `tools/unattended/resume-tick.sh`'s `run_tick` (:279).
  Observed by AC6.
- **S7** — `help/runtime.md` gains a section on the node's facts file, the clock offset, the
  `clock-offset` beat key and the two expiry rules. Observed by AC7.

## 4. Design

### Evidence

- No skew code exists: `git grep -i -n "skew\|clock offset\|remote time" -- tools .githooks` finds
  nothing (scout D row 2, rerun 2026-10-26).
- The age pass compares the reader's `date` with the holder's `beat-utc` (`unattended.sh:2177-2185`),
  and the record's keys are filtered through `want` (`:2168`), so an unknown key is ignored.
- `resolve_remote(root)` returns `(remote, branch, observed, refusal)` and fetches nothing
  (`tools/lib/resolve_remote.py:17-30`).
- `resolve_state_dir` is the precedent for a per-user home outside the tree
  (`tools/runlog/extract.py:201-229`); I5 refactors it into `resolve_node_home`.

### The rule

```
observer age   = now(this node) - first sighting of the renewing beat     (TOOL-dPlacedRequest-17)
corrected age  = (now + own offset) - (beat-utc + holder offset)          (this unit)
stale          = observer age > expiry  OR  corrected age > expiry         (v2:1160)
```

A holder whose clock runs an hour ahead stamps its beats an hour late in true time; its measured
offset is -3600 and the correction restores the true stamp. A holder that misreports its offset can
make its corrected age read fresh, but it cannot renew: the observer saw no renewing beat, so the
observer rule expires it.

### Alternatives rejected

- **Correcting the stamp at write time.** The holder would write true time into `beat-utc`, changing
  the meaning of a parent's field, and a reader could not tell a corrected stamp from a raw one.
- **An NTP query.** It measures against a time server, and the design measures against the remote
  host the leases live on.
- **Reading the offset from the holder's facts file.** It never leaves the holder's node; the beat is
  the record every observer already reads.

## 5. Production-readiness checklist

- security — the HTTPS request goes to the repository's own remote host only, `https` only, no
  redirect, bounded; it carries no credential and reads one header. The facts file holds no credential
  (S2 refuses one).
- perf / scale — one HEAD request per beat, a beat a quarter of `RESUME_STALE_BOUND` apart; the node
  facts once a day.
- error / empty / loading states — an unmeasured offset is `-`, never `0`, and leaves the observer rule
  judging alone.
- observability — `[clock] source` names how the offset was read or why it was not.
- risks — the `Date` header's one-second resolution bounds the offset to about a second, against an
  hours-scale expiry; a remote behind a CDN reports the edge's clock.
- testing — the arm in §7, with the remote time and the stamps planted.
- migration — additive, §4.
- user docs — `help/runtime.md`, S7.

- **AC2** — When `python facts.py measure-clock` runs with `read_remote_time` stubbed to answer the

  local path it reads `-` with `source` naming the local remote.
  Red when: the unmeasured case writes `0`.
- **AC3** — When `write_claim` writes a claim in a fixture clone whose facts read `offset-seconds =

  `clock-offset: -`.
  Red when: the key is absent.
- **AC4** — When `unattended.sh --claims` reads a planted holder stamp skewed by an hour, its clock
  an hour ahead and its record's `clock-offset: -3600`, whose last renewing beat was 90 true minutes
  ago, under `leases.expiry-hours = 1` and with this node's first sighting 5 minutes old, the row
  reads `stale` by the corrected rule.
  Red when: the correction is stubbed out and the row reads `live`.
- **AC5** — When a planted holder that misreports its own offset as `clock-offset: 360000` has
  written no renewing beat this node has seen for 25 hours under `leases.expiry-hours = 24`, the row
  reads `stale` and the holder still loses its lease.
  Red when: the corrected rule's fresh reading keeps the row `live`.
- **AC6** — When `python facts.py measure-node` runs in a fixture with `core.autocrlf=true` and a user
  settings file holding one hook without `onFailure`, the file reads `autocrlf = "true"`, a numeric
  `start-ms`, and one `[[user-guard]]` row with `on-failure = "absent"`.
  Red when: an unset autocrlf is written as `false`.
- **AC7** — When `grep -n "clock-offset"` runs over the runtime kit's help page, `runtime.md`, it
  finds S7's section.
  Red when: the page does not name the key.

## 8. Open questions

- **F1 — How does an observer learn the holder's offset?** The facts file is node-local, and the
  correction needs the holder's offset, not the observer's. Options: (a) the holder writes its offset
  into each beat record as an additive key; (b) the holder writes a corrected `beat-utc`; (c) each node
  publishes its facts to a shared registry. (b) changes a parent field's meaning; (c) needs a shared
  write surface no clause names. Recommendation: (a). RESOLVED (agent, 2026-10-26, delegated): (a),
  rung 3, the most capable option surviving the vetoes; it widens no surface and keeps every landed
  record readable.
- **F2 — How is the remote host's time read?** The design names the remote host and the host adapter,
  not a protocol. A `git` transport exposes no server clock; the `Date` header of an HTTPS request to
  the remote's host is the one standard-library read. Recommendation: `http-date`. RESOLVED (agent,
  2026-10-26, delegated): `http-date`, rung 3; a local-path remote reads `-`, never a guess.
