## 1. Goal

New publishing boundaries go unscanned: lease, mail and mirror payloads, and the request records P40
adds, sit outside the secret scan's population, and no door refuses a token shape in a coordination
record (gap-rt-44). This unit brings each of those payloads, and every adapter's publishing boundary,
under one scan, makes the record door refuse a token shape before a coordination write leaves the
node, and publishes a request record with its redacted text, bound to its hook-written intake by the
owner binding's proof, which a claiming node checks before it acquires the request.

## 2. Scope (IN)

- **S1** — One payload scan, `scan_payload(population, text)` in `tools/runtime/secret_scan.py`,
  TOOL-dWellOiledMachine-17's module, beside its value scan. `population` is one of the closed
  `PAYLOAD_POPULATIONS = ("lease", "mail", "beat", "mirror", "request", "adapter")`; the scan is I12's
  `scan_secrets(text)`, imported from `tools/runtime/redaction.py`, the same kit's file
  TOOL-dWellOiledMachine-16 moves it into, and it returns the sorted class ids it found, never a value.
  The CLI
  `python secret_scan.py payload <population> <file>` exits 0 clean, 1 printing
  `scan — refused · <population> · <class id> …`, 2 on an unknown population or an unreadable file.
  Observed by AC1, AC5.
- **S2** — The door's token-shape arm. `check_writer_binding` (TOOL-dWellOiledMachine-58 S1) runs
  `secret_scan.py payload` on the message of every coordination write's `<src>`, a subprocess resolved
  by `resolve_kit_dir`, after its binding verdict admits the write: `refs/gov/mail/` reads `mail`,
  `refs/gov/requests/` reads `request`, a lease or run claim reads `beat` when `GOV_DOOR_VERB` is
  `lease.beat` or `lease.renew` and `lease` otherwise. A hit refuses the write with
  `door — refused · <ref> · token-shape <class id> …`, so nothing is pushed. `write_claim_beat`
  (`tools/unattended/unattended.sh:2469`) sets `GOV_DOOR_VERB=lease.beat`. Observed by AC1, AC2.
- **S3** — Every adapter's publishing boundary. An adapter of the git-refs lease store
  (TOOL-dWellOiledMachine-55) writes through `write_gov_ref`, so S2 scans it; an adapter that publishes
  anywhere else runs `secret_scan.py payload <population> <file>` on the bytes it is about to send and
  sends nothing on exit 1: the memory-mirror adapter with `mirror` (TOOL-dWellOiledMachine-44) and the
  notification channel with `adapter` (TOOL-dWellOiledMachine-48). Observed by AC3.
- **S4** — The request text, the verb `unattended.sh --request-publish <content key>`, which
  TOOL-dPlacedRequest-19 S2's `--request` runs last in the session that typed the request. In order:
  the writer's I17 binding (TOOL-dWellOiledMachine-12 S1) must read `owner: yes`, else
  `request — <key> · not published: not the owner's session`, exit 2, nothing written; the session must
  pass `check_request_consent <key>` (TOOL-dPlacedRequest-19 S5); the local text
  `<git-common-dir>/requests/<key>.md` is rendered through I12's `render_redacted`; one commit
  `gov-request <key>`, built by `build_gov_commit` on the ref's tip read (TOOL-dPlacedRequest-11 S2), its
  lines `text · <redacted-sha>`, `intake-sha`, `session`, `fleet-tag` and `proof`, a blank line and
  the redacted text, is written through `write_gov_ref` under `GOV_DOOR_VERB=request.publish`, so S2
  scans it too. It prints `request — <key> · published · <redacted-sha>`. Observed by AC4, AC6.
- **S5** — The proof, `derive_request_proof(key, intake_sha, redacted_sha, session, fleet_tag)` in
  `tools/runtime/secret_scan.py`: the first 12 hex of SHA-256 over the five values joined by LF.
  `intake-sha` is the first 12 hex of SHA-256 over the intake file's bytes, the hook-written intake
  once TOOL-dWellOiledMachine-4 writes it, and `redacted-sha` over the published text's UTF-8 bytes.
  The CLI `python secret_scan.py proof <five values>` prints it. Observed by AC6.
- **S6** — The claiming node's check, `check_request_proof <key>` in `tools/unattended/unattended.sh`,
  run by `--lease acquire request <key>` (TOOL-dPlacedRequest-19 S4) after its bounded fetch and before
  any write. It reads the ref's first-parent chain and requires exactly one `text ·` commit; its
  `session` and `fleet-tag` equal to the root record's (TOOL-dPlacedRequest-19 S3); both commits by the
  `gov-claim` identity; the body's SHA-256 equal to `redacted-sha`; the body clean under
  `secret_scan.py payload request`; and `derive_request_proof` over the commit's own values equal to
  `proof`. Any miss prints `request — <key> · unproven: <reason>` and exits 1, and nothing is acquired.
  Observed by AC6.
- **S7** — The fixture cases, added to `tools/memory-tree/door_fixture.py` (TOOL-dWellOiledMachine-58
  S10): a planted token in a lease payload, a mail message, a beat, a mirror event, an adapter's
  boundary and a request record, and an agent-forged request record in two forms, each run through
  the coordination verbs or the adapter's own call, never through the door itself. Observed by AC1 to
  AC6.
- **S8** — The documentation: `help/runtime.md` gains the payload populations, the door's
  `token-shape` refusal, the request proof and the limit S6 shares with the door; the verbs guide
  `tools/unattended/VERBS.template.md` (rendered to `memory/guides/UNATTENDED-VERBS.md`) gains
  `--request-publish` and the `unproven` reasons. Observed by AC7.

## 3. Non-goals (OUT)

  `pre-push` scan still runs over every commit these payloads ride.
- The intake record's own fields, its hook and its redaction at write: TOOL-dWellOiledMachine-4, which
  writes the file `intake-sha` digests.
- The mirror adapter and the notification channel themselves: TOOL-dWellOiledMachine-44 and -48, which
  call S3's scan at their boundary.
- A proof a writer outside the door cannot recompute. The proof binds what the door admitted to what
  the claimer reads; a process outside the door that holds push rights and computes it is not stopped,
  the limit TOOL-dWellOiledMachine-58 states (the owner's FK-5-3 declined signed commits).
- No change to TOOL-dPlacedRequest-19's root record: the text rides a second commit on the same ref,
  as TOOL-dPlacedRequest-14's draw rows do.

### Alternatives rejected

- **Scanning in the pre-push hook only.** TOOL-dWellOiledMachine-17's hook scan reports shapes and
  refuses only a known value; the clause asks the door to refuse a token shape in a coordination
  record before it is written.
- **The text in the root commit.** TOOL-dPlacedRequest-19 S3 fixes the root at three lines; widening
  it is a parent change, where a second commit on the same ref is additive.
- **An HMAC proof under a per-node salt.** No claiming node on another node holds the salt, so the
  check the clause names could not run there.

## 5. Production-readiness checklist

- security — a deny path on every coordination write and every non-git adapter send; the request text
  is published only redacted and only from the owner-bound session; a claimer refuses an unproven
  request. The limit is stated: a writer outside the door with push rights who computes the proof.
- perf / scale — one more Python spawn per coordination write, inside the door that already spawns,
  and one chain read per request claim.
- error / empty / loading states — an unknown population and an unreadable payload exit 2; a request
  with no text commit is `unproven: no text`, never claimable.
- observability — each refusal names its population and class ids, never a value; each request
  refusal names one reason.
- risks — a scan rule that flags a legitimate payload refuses its write; the class table's negatives
  (`tools/runlog/redaction.tsv`) are what keep that rare, and the refusal names the class to fix.
- testing — the fixture cases under AC1 to AC6 and the arm in §7.
- migration — a request recorded before this unit carries no text commit and is unclaimable until its
  typing session runs `--request-publish`; the verbs guide says so.
- user docs — `help/runtime.md` and the verbs guide.

## 6. Acceptance criteria

Each case runs `python door_fixture.py --case <name>` over the fixture's clones, through the verbs.

- **AC1** — When `--case token-lease` and `--case token-mail` plant a `github-token`-class value in a
  lease record's `witness` key and in a mail body, `--lease renew` and `--mail post` each exit 2
  printing `token-shape github-token` and the remote ref is unchanged; the same payloads without the
  token are written.
  Red when: either payload reaches the remote, as a door with the arm removed shows.
- **AC2** — When `--case token-beat` plants the value into the beat `write_claim_beat` writes, the beat
  is refused `token-shape` under population `beat`.
  Red when: a beat carrying a token is pushed, or the refusal names another population.
- **AC3** — When `python secret_scan.py payload mirror <file>` and `payload adapter <file>` run over a
  planted mirror event and an adapter's outgoing payload each holding the token, each exits 1 naming
  its population and the class; over the clean files each exits 0.
  Red when: a planted token passes either population.
- **AC4** — When `--case token-request` runs `--request <file>` over text holding the token in the
  owner-bound session, the published `text ·` commit's body carries `<redacted:github-token>` and not
  the value, and `secret_scan.py payload request` over that body exits 0.
  Red when: the published text carries the value.
- **AC5** — When `python secret_scan.py payload chat <file>` runs, it exits 2 naming the six
  populations.
  Red when: an unknown population is scanned as if it were known.
- **AC6** — When `--case forged-request-act` runs `--request-publish <key>` in a session whose binding
  reads `owner: act-0a1b2c3d4e5f`, it exits 2 printing `not the owner's session` and the ref gains no
  commit; when `--case forged-request-raw` pushes a text commit outside the verbs whose `proof` does
  not recompute, `--lease acquire request <key>` on the second clone exits 1 printing `unproven: proof`;
  and over the owner's published request the same acquire succeeds.
  Red when: either forged record is claimable, or the owner's is refused.
- **AC7** — When `grep -n "token-shape" runtime.md tools/unattended/VERBS.template.md` runs over the
  help page and the guide, both name the refusal, and the guide names `--request-publish` and each
  `unproven` reason.
  Red when: either file omits the refusal or the guide omits the verb.
