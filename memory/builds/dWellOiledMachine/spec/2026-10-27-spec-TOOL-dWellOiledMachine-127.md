### The value

`--check` passes a leg when its ceiling is at least its evidenced maximum plus
`max(floor, fraction × max)` (`derive-ceilings.py:663`, `:683`). The margin file declares a floor
of 120 s and a fraction of 1.0 (`tools/run-gates/ceiling-margin.txt:26`). Every ceiling in
`tools/gate-legs.json` is a multiple of 10 (60 distinct values from 120 to 16040 at 0075cd1c). So
each C is the least multiple of 10 at or above R + max(120, R). For R of 120 s or more, that is
10 × ⌈R / 5⌉.

The out-of-band row falls to the headroom branch, never the REACHED one, which grades runner rows
alone (`:679`).

From the inputs:
- **C1 = 940.** R1 + max(120, R1) = 465.2 + 465.2 = 930.4, and 10 × ⌈465.2 / 5⌉ = 10 × 94 = 940.
- **C2 = 760.** R2 + max(120, R2) = 378.7 + 378.7 = 757.4, and 10 × ⌈378.7 / 5⌉ = 10 × 76 = 760.

The builder re-derives both values from R1 and R2 by this rule before editing, and stops if either
differs from the figure here.

**The stop rule.** Each raise must move its ceiling up. C1 exceeds 390 exactly when R1 exceeds
195.0, which is also the condition under which the monotone refusal at `derive-ceilings.py:581-586`
does not fire. C2 exceeds 300 exactly when R2, the larger of R2a and R2b, exceeds 150.0. Had R1 or
R2 fallen at or under its bound, the kill at the close would have been contention rather than the
leg's own work, and no raise could be derived from it. The inputs clear both bounds: 465.2 exceeds
195.0, and 378.7 exceeds 150.0.

### The writes

The evidence rows come first, from a run record holding no admitted reading, so no runner row moves.

`--observed` takes one leg per call (`derive-ceilings.py:736`), so there are two writes, R1's first.

**What `--observed` writes for a leg with no row.** `rows.get` finds nothing, so the monotone
refusal is skipped and the row is written as `(R2, 1, <node>, <date>, <how2>)` (`:576-588`). The
date is HEAD's commit date (`:527-528`), and the row is placed by the writer's sort (`:625-627`).

Each write prints a summary line reading `0 raised` and `1 raised by --observed` (`:633-639`).
`--write` re-reads the run record and carries every stored row it does not re-derive (`:552-562`),
so the second write keeps R1's row as written. A `raised` count above 0 means the run record held an
admitted reading after all: the builder restores the file and writes from the clone. Only after both
rows are written does the builder edit the two `"ceiling":` values.

### When each ceiling comes back down

- **Spec tokens.** Once `TOOL-dGroundRules-112` lands and the owner repins the instrument, a reading
  of the leg alone over a live chain run supports a lower bound. Until then, every chain build's
  close pays the join's cost under this ceiling, and a larger chain build pays more.
- **Routed commits.** Its cost does not fall when this run lands: the WHOLE history only grows, and
  the join reads every chain build in the design view whatever its phase. It comes down only once a
  unit batches the join's per-row pickaxe, and no ask carries that today (§8). A reading of the leg
  alone after that unit then supports a lower bound.

Lowering either one takes `--write --reset <leg>` with `--observed` from a record holding no
admitted reading, as `9c756ce7d` lowered the foreign-prefix parity leg. The ceiling then falls to
the margin's value for that reading.

### What this does not check

- **The cost.** Each raise bounds a hang and leaves the work where it is. The spec tokens spawns are
  `TOOL-dGroundRules-112`'s. No unit owns the routed commits pickaxes.
- **The leg's contended duration.** Only the solo reading is measured. The margin's fraction is the
  whole of the headroom above it, so a bar contended past 2R still kills the leg.
- **The landing push's bar beyond R2b.** R2b reads the push's population alone on a free host. It
  does not read that bar's contention: the pre-push bar runs the leg beside its other legs, and only
  the margin covers that. It also does not read the RANGE as it will stand at the real push. The
  build commit and the close's record commits land after R2b and lengthen it. If the remote's main
  moves before the land, the lander lands onto a different tip, and the RANGE starts from that tip
  instead.
- **The load R was taken under.** An `--observed` row is admitted uncensused, and its `--how` text is
  the only record of the host (`derive-ceilings.py:49-52`). On Windows, `ps -ef` sees only processes
  an MSYS shell spawned. Foreign gate work overlapped the tail of R1 and of R2a. That can only
  lengthen them, so C1 and C2 are at worst loose, never short. R2b ran clean at both ends.
- **Whether R was taken as `--how` says.** `--check` reads the two tracked files alone
  (`derive-ceilings.py:643-647`). The builder did not take the readings, so the main loop's record
  and the `--how` text are the only account of them.
