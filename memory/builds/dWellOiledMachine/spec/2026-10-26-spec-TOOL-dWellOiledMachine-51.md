## 1. Goal

An act records no cost or duration, and committed cost covers review acts' output tokens only
(gap-rt-26), so no build's spend is known and no bound can be set from evidence. This unit derives
each build's spend from its acts' `trace.cost` rows and trends it across builds, keeps
`build.spend-cap` at `measured` until the owner sets it from that evidence, as `memory.item-budget`
was measured first, refuses a build's close while any of its acts' spend is unrecorded, and ends a
build that reaches a set cap as `flow.on-exhausted` says, never running on (P39; the owner's SL-8;
the parked debt's review).

## 2. Scope (IN)

- **S1** — The key's reader. `read_spend_cap(repo)` in the new `tools/runtime/spend.py` reads
  `build.spend-cap` (`tools/policy/catalogue.toml:1009-1013`: `measured`, or a count of tokens, the
  default `measured` in every preset, v2:1621) through
  `python <prefix>/policy/policy.py get build.spend-cap` (I31) as a subprocess; a refused read takes
  `measured` with one `spend — NOTE · <why>` line, so a read failure never invents a cap. Observed by
  AC1, AC3.
- **S2** — A build's spend, derived and never typed. `derive_build_spend(root, slug)` sums
  `Tokens-In` plus `Tokens-Out`, and `Wall`, over the build's act records, kind `act`
  (TOOL-dWellOiledMachine-32 S7, S8), read through `record find` (TOOL-dTotalRecall-9 S3), and
  returns the totals with the acts that went unrecorded: an act record whose token fields read
  `withheld` or are absent, and an act whose node-local pending record reads `state: ended` through
  `read_act` (TOOL-dWellOiledMachine-32 S2) with no act record written. Observed by AC1, AC2.
- **S3** — The trend. `python spend.py trend` prints one `spend — <slug> · <tokens> tokens · <wall> ·
  <n> act(s)` row per build with act records, then over the closed builds, those the build index
  derives `CLOSED`, one `spend — trend · <n> closed build(s) · p50 <x> · p90 <y>` line and, while
  the key reads `measured`, `build.spend-cap — measured · the evidence suggests <p90>; the owner sets
  it`. Setting the key stays the owner's write to the guarded policy file. It is a `[[command]]` row
  of `tools/runtime/kit.toml`, `verb = "spend"`, `terminal = true`. Observed by AC1.
- **S4** — Unrecorded spend refused at the close. `python spend.py check <slug>`, `check_spend_recorded`,
  prints one `spend — unrecorded · <act> · <why>` line per S2 act and exits 1, and exits 1 with
  `spend — cap unenforceable · trace.cost none` when a cap is set while `trace.cost`
  (`catalogue.toml:1571-1575`) reads `none`; under `none` with the key at `measured` it prints
  `spend — not recorded · trace.cost none` and exits 0, the owner's choice. `verb_close`
  (`tools/unattended/unattended.sh:10765`) runs it before it closes and refuses on exit 1, naming the
  lines. Observed by AC2.
- **S5** — A set cap ends the build. `check_spend_cap(root, slug)` runs after every act record
  `write_act_record` (TOOL-dWellOiledMachine-32 S7) writes: under a count, when the build's spend
  reaches it, it prints `spend — cap reached · <slug> · <tokens> of <cap>` and runs
  `unattended.sh --exhausted <slug> --by spend-cap`, TOOL-dDeclaredLoop-31 S3's verb, which reads
  `flow.on-exhausted`, picks the ending through `derive_ending` (its S2) and writes the exhaustion
  record; the `--by spend-cap` form is the ask §8 F1 files. Under `measured` it does nothing.
  Observed by AC3.
- **S6** — The page `help/runtime.md` gains the spend: how it is derived, the trend and its
  suggestion, the close refusal, and the cap's ending. Observed by AC4.

## 4. Design

### Evidence

- Today's spend measure is the run record's `usage main/agent/workflow`
  (`tools/runlog/record.py:237-239`), built by `build_run_usage` (`tools/runlog/model.py:1055`) over a
  run window, not a build's acts; scout D cites it as the only measure at this base.
- `measured` before a set value is `memory.item-budget`'s rule: it reads a stated figure until a role
  has 30 measured work orders (TOOL-dTotalRecall-9 S6).
- `--exhausted <slug>` refuses while `budget_state` reads `open` (TOOL-dDeclaredLoop-31 S3), so a cap
  reached with rework budget left cannot reach an ending through it unchanged.

### The trend, by example

```
spend — fx · 41200 tokens · 1h12m · 9 act(s)
spend — gy · 88010 tokens · 2h40m · 17 act(s)
spend — trend · 2 closed build(s) · p50 41200 · p90 88010
build.spend-cap — measured · the evidence suggests 88010; the owner sets it
```

### Alternatives rejected

- **A spend row written per act into the transition record.** The act record already holds the
  figures; a second copy is a fact twice (charter `[one-fact]`), so the spend is derived.
- **Checking the cap before each launch.** The launch is TOOL-dWellOiledMachine-1's and runs before
  the act's cost exists; the act record is where the spend moves.
