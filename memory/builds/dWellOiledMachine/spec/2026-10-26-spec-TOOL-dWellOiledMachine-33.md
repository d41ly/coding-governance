## 1. Goal

No commit names the act or session that made it: the trailers in the last 500 commits are
`Co-Authored-By`, `Pass:`, `Decided:` and `manifest-audit` only, and no `Gov-*` key appears in
`tools/` or `.githooks/` (gap-rt-25, gap-rt-27). This unit writes the `Gov-*` trailers at every commit
site from the binding the site runs under (the commit queue, a `prepare-commit-msg` filler in the
owner's session, and the lander's four commits) and checks them at the push and, where
`commits.edge-check` says, in `commit-msg`, `Gov-Session` written as `trace.identity` says (AP-8,
SA-4; memory-plan `[doors]`).

## 2. Scope (IN)

- **S1** — The one trailer writer, `derive_gov_trailers(binding, identity)` in the new
  `tools/runtime/commit_keys.py`: from an act binding it returns `Gov-Act: <act>`,
  `Gov-Unit: <unit>` and `Gov-Item: <instance key>` (I14), each only where the binding names it, and
  from the owner's session binding no `Gov-Act:`, since a commit carrying neither act mark is the
  owner's (§8 F3); then `Gov-Session` as S5 says. The CLI
  `python <prefix>/runtime/commit_keys.py trailers` prints them one per line for the current
  session's binding, or `--act <act>` for an act's. Every site in S2 to S4 writes through it.
  Observed by AC1, AC2, AC3.
- **S2** — The commit queue: `enqueue_commit(repo, build, workspace, paths, message, act)` in
  `commit_queue.py` (I19, TOOL-dWellOiledMachine-11 S6) appends
  `derive_gov_trailers(<the act's binding>, identity)` to `message`'s trailer block on every commit
  it makes, beside `Pass:` and the attribution trailer. Observed by AC1.
- **S3** — The lander, a commit site of its own: `tools/push-main.sh` asks `commit_keys.py trailers`
  once per run, under the binding it runs under, an act's or the owner's, and writes the lines into
  the prepared merge's message (`git merge --no-ff` at `:881` and the `commit-tree` rewrite at
  `:921` share `msg`), the reconcile merge (`:1070`), and the `mint:` (`:1092`) and `regen:`
  (`:1111`) commits, in the same trailer paragraph as their `Pass: none`. No binding found prints
  `push-main: no binding to take Gov-* trailers from (<why>)` and writes none. Observed by AC2.
- **S4** — The filler: a new `.githooks/prepare-commit-msg` that, in a session whose I17 session
  binding reads `owner: yes`, appends the missing `Gov-*` lines from `commit_keys.py trailers` to
  the message file with `git interpret-trailers --in-place --if-exists doNothing`. It never edits a
  message that already carries a `Gov-*` trailer, never runs for a merge or squash source, and with no kit
  or no binding announces its skip and lets the commit through. Observed by AC3.
- **S5** — `trace.identity` (`act-only`, `session`, `salted`; default `session`; never set by a
  preset), read through the policy kit's `policy.py get trace.identity` as a subprocess: `act-only`
  writes no `Gov-Session`; `session` writes `Gov-Session: <harness session id>`; `salted` writes
  `Gov-Session: <64 hex>`, the HMAC-SHA256 of the harness session id under the node salt (S6) in
  lowercase hex, the value `derive_session_digest(session)` returns and the shape
  TOOL-dWellOiledMachine-39 S2 validates for the binding's `digest:`. Observed by AC1, AC6.
- **S6** — The node salt: `read_node_salt()` reads a per-node salt from the node's credential store
  and never from a file: Windows Credential Manager through `ctypes` `CredReadW` and `CredWriteW` on
  the target `gov-node-salt`; a Linux desktop's libsecret through
  `secret-tool lookup service gov key node-salt` and `secret-tool store`; and, where
  `runtime.secret-home` reads `env-injected`, the variable `GOV_NODE_SALT` the service manager hands
  the process. A store holding none is written once with 32 random bytes from `secrets.token_hex`.
  No store reachable is exit 2, `commit keys — salted needs a node salt: <why>`. The binding's
  `digest:` (I16) is this function's value, which `write_binding`'s caller passes as its digest
  argument (TOOL-dWellOiledMachine-39 S1), printed for a shell caller by
  `commit_keys.py digest <session>`. Observed by AC7.
- **S7** — The check, `check_commit_keys(repo, rng, identity)`, in two halves. The `Gov-Act:` half
  is TOOL-dWellOiledMachine-39's `check_bindings` over the act-made commits `read_act_commits` reads
  (a `Gov-Act:` trailer or the committer email `<act>@gov-act.invalid`), called and never copied:
  its verdicts `no act`, `unmarked` and `malformed` are red and `not-local` is counted and never
  passed, so a planted act commit with no `Gov-Act:` reads `unmarked`. The `Gov-Session` half is
  this unit's, one line per finding naming the sha and the rule: `gov-session-under-act-only`, a
  `Gov-Session` under `act-only`; `no-gov-session`, an act-made commit without one under `session`;
  and `raw-or-foreign-digest`, under `salted` a value that is not 64 hex or differs from the
  binding's `digest:` that `read_binding` returns. A commit carrying neither act mark is the owner's,
  is not act-made, and is graded by the `Gov-Session` half's `act-only` and `salted` rules alone.
  Observed by AC4, AC5, AC6.
- **S8** — The commit-key leg at the push: `python <prefix>/runtime/commit_keys.py --check` reads
  the commits of the range TOOL-dWellOiledMachine-39's `derive_act_range` gives every binding
  reader, `<current default>..HEAD` with `--no-merges`, its `Gov-Session` trailers through
  `read_commits(repo, revs, keys)` (TOOL-dDeclaredLoop-23 S3), and runs S7; exit 1 on a finding, 0
  clean, 2 on a refusal. It is a new manifest leg, `commit keys name their act`, in
  `tools/gate-legs.json` and as a `[[gate_leg]]` row of `tools/runtime/kit.toml`, with its row in
  `tools/govkit/subject-pins.tsv`. Observed by AC4.
- **S9** — `commits.edge-check` (`push-leg`, `commit-msg`, `off`; default `push-leg`; strict's cell
  `commit-msg`, v2:1474-1722): `push-leg` runs S8 only; `commit-msg` runs S8 and arms
  `.githooks/commit-msg` to run `commit_keys.py --message "$1"`, S7 over the one commit being made,
  its act-made mark read from `git var GIT_COMMITTER_IDENT` and the message's `Gov-Act:`; `off` runs
  neither and each prints `commit keys — off (commits.edge-check: off)`, exit 0 (§8 F1). Observed by
  AC5, AC8.
- **S10** — The registered keys: the four `[[trailer]]` rows `Gov-Unit`, `Gov-Item`, `Gov-Act` and
  `Gov-Session` of `tools/playbook/edges.toml` are PLAY-dOrderedCharter-28's; this unit asserts they
  are present and adds none, so `read_commits` reads only registered keys. Observed by AC9.
- **S11** — The act record under `salted`: TOOL-dWellOiledMachine-32 S9 writes `Session: withheld`
  until this unit supplies the digest; `write_act_record` (`tools/runtime/act.py`) writes
  `Session: <derive_session_digest(harness session)>` under `salted`, its `Transcript` staying
  `withheld` because the path carries the raw id. Observed by AC11.
- **S12** — The page `help/runtime.md` gains a section on the `Gov-*` trailers: the four keys, where
  each site writes them, the three values of `trace.identity` and of `commits.edge-check`, and where
  the salt lives. Observed by AC10.

## 4. Design

### Evidence

- The lander's four commit sites append `Pass: none` and nothing else: the prepared merge's message
  `msg` (`tools/push-main.sh:880`) used by `git merge` (`:881`) and the `commit-tree` rewrite
  (`:921`); the reconcile merge (`:1070`); `mint:` (`:1092`) and `regen:` (`:1111`), each

- `.githooks/commit-msg` runs `unattended.sh --check-commit "$1"` on every commit before its

  there is no `prepare-commit-msg` hook in `.githooks/`.
- The catalogue rows exist: `commits.edge-check` (`tools/policy/catalogue.toml:1554`) and

- `git grep -i -E "cmdkey|libsecret|secret-tool|CredRead|keyring"` over `tools`, `skills` and
  `.githooks` finds nothing: no credential-store reader exists to extend.
- The routed-commits leg is the shape of a history leg: argv in `tools/gate-legs.json:1095`, a
  `[[gate_leg]]` row in `tools/memory-tree/kit.toml:334`, its pin row in
  `tools/govkit/subject-pins.tsv:113`.

### The trailer block

```
mint: kit versions onto origin/main at 1a2b3c4d for TOOL-x-3

Pass: none
Gov-Session: 6c1f0b8e-2a7d-4f43-9e0b-1d2c3b4a5f60
```

An act's commit from the queue carries `Gov-Act: act-<12 hex>`, `Gov-Unit: <unit id>`, `Gov-Item:
<instance key>` and `Gov-Session` as S5 says, in that order, before the attribution trailer.

### The check, by value

| `trace.identity` | `Gov-Session` on an act commit | Verdict |
|---|---|---|
| `act-only` | absent | pass |
| `act-only` | present | `gov-session-under-act-only` |
| `session` | the raw id | pass |
| `session` | absent | `no-gov-session` |
| `salted` | 64 hex equal to the binding's `digest:` | pass |
| `salted` | a raw id, or a digest the binding does not hold | `raw-or-foreign-digest` |

The `Gov-Act:` half comes first and is TOOL-dWellOiledMachine-39's verdicts: `bound local` and `bound
ref` pass, `no act`, `unmarked` and `malformed` red, `not-local` counted and never passed.

### Alternatives rejected

- **A commit-key arm inside `routed_commits.py`.** That leg answers whether a routed commit names a
  specced unit; a second question in it would be a second mechanism graded by one verdict.
- **The salt in a file under the node home.** The clause says "never in a file"; a file is read by
  any process with the user's rights and copied by every backup.
- **`commit-msg` replacing the push leg.** Strict would then grade less at the push than standard
  does (§8 F1).

## 5. Production-readiness checklist

- security — the salt never leaves the credential store and is never logged; a raw session id is
  refused under `salted`; the filler only appends lines and never rewrites a message.
- perf / scale — one `read_commits` call per leg run over the range; one `read_binding` per distinct
  act; the hook reads one message.
- error / empty / loading states — no binding, no kit, no store and `off` each print one named line;
  an empty range prints `commit keys — 0 act-made commits in <range>`, never a silent green.
- observability — every finding names the sha, the key and the rule; `not-local` is counted apart.
- risks — a commit made outside any binding carries no trailer and is graded only if act-made.
- testing — the fixture cases AC1 to AC9 and the arms in §7.
- migration — none.
- user docs — `help/runtime.md`'s section (S11).

## 6. Acceptance criteria

The fixture is a bare remote and a clone under `%TEMP%` with short names, the runtime and policy
kits installed, an act binding for `act-0a1b2c3d4e5f` written by `write_binding`, a session binding
for `CLAUDE_CODE_SESSION_ID`, and a stub credential store reached through `GOV_NODE_SALT` under
`runtime.secret-home: env-injected`.

- **AC1** — When `commit_queue.py` commits a planted return for `act-0a1b2c3d4e5f` under
  `trace.identity: session`, `git log -1 --format=%B` shows `Gov-Act: act-0a1b2c3d4e5f`,
  `Gov-Unit:`, `Gov-Item:` and `Gov-Session: <sid>` in one trailer block with `Pass:`.
  Red when: any of the four is missing, or the block is split from `Pass:`.
- **AC2** — When `bash push-main.sh --prepare` runs in the clone under the owner's binding, the
  prepared merge, the reconcile merge, and the `mint:` and `regen:` commits each carry
  `Gov-Session:` and no `Gov-Act:` in the paragraph holding `Pass: none`; run again under the act
  binding with the act's committer identity, each carries `Gov-Act: act-0a1b2c3d4e5f` too; both read
  by `git log --format=%(trailers)`.
  Red when: a site writes `Pass: none` alone.
- **AC3** — When `git commit -m x` runs in the owner's session with the filler installed, the
  commit carries `Gov-Session: <sid>` and no `Gov-Act:`; with a `Gov-Session:` already in the
  message, the message is unchanged byte for byte.
  Red when: the filler is absent, or it edits a message that already carries a `Gov-*` trailer.
- **AC4** — When `python commit_keys.py --check` runs over a range holding a planted act commit
  under the act committer identity with no `Gov-Act:`, it exits 1 naming that sha and `unmarked`;
  over the lander's commits of AC2 and the queue's of AC1 it exits 0.
  Red when: the planted commit passes, or the clean range reds.
- **AC5** — When the policy file names `preset = "strict"` and a planted act commit with no
  `Gov-Act:` is made, `.githooks/commit-msg` refuses it, exit 1, and `git rev-parse HEAD` is
  unmoved; under the default preset the same commit is made and AC4's leg reds it at the push.
  Red when: the strict commit is created.
- **AC6** — When `commit_keys.py --check` runs over four planted act commits, it names
  `gov-session-under-act-only` under `act-only`, `no-gov-session` under `session`, and
  `raw-or-foreign-digest` under `salted` for a raw id and for a digest the binding lacks; a fifth
  commit whose digest equals the binding's `digest:` passes under `salted`.
  Red when: any of the four passes, or the matching digest reds.
- **AC7** — When `python commit_keys.py digest <sid>` runs twice under the stub store, both print
  the same 64 lowercase hex; `grep -r` for the salt value over the clone and the node home finds
  nothing; with no store reachable it exits 2 printing `salted needs a node salt`.
  Red when: the salt appears in a file, or a missing store yields a digest.
- **AC8** — When `commits.edge-check` is `off`, `commit_keys.py --check` prints
  `commit keys — off (commits.edge-check: off)` and exits 0, and the commit-msg arm does not run.
  Red when: a check runs under `off`.
- **AC9** — When `python commit_keys.py --check` runs against a copy of `edges.toml` holding no
  `Gov-Item` row, it exits 2 naming the unregistered key.
  Red when: an unregistered key is read.
- **AC10** — When `grep -n "Gov-Session"` runs over the runtime kit's page `runtime.md`, the section
  names the four keys, the three `trace.identity` values, the three `commits.edge-check` values and
  the salt's home.
  Red when: a key or value is missing.
- **AC11** — When `write_act_record` writes a planted act under `salted` with the stub store, the
  record's `Session` line equals `commit_keys.py digest <sid>` and its `Transcript` reads
  `withheld`.
