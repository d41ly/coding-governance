## 1. Goal

No fixture measures what a harness can do, so the Codex row went stale within days and nothing
separates a harness's ability from an adapter's claim (gap-rt-31); the CLI on PATH and the
application's bundled CLI drift apart, 2.1.292 against 2.1.299, the PATH one lacking a hook field the
design needs (gap-rt-29); node runs ten of thirteen hook commands and no toolchain fact names it
(gap-tool-14); and which bash a hook runs in is not pinned (gap-rt-32). This unit is the one
conformance fixture (v2 P36): it launches each harness binary by a program through the act launcher,
measures the rows the clause names, writes them into TOOL-dWellOiledMachine-14's capability table and
TOOL-dWellOiledMachine-15's node facts, and reads them for `runtime.binary` and
`runtime.owner-harness`, the rows `runtime.act-harness` also reads.

## 2. Scope (IN)

- **S1** — The fixture, `tools/runtime/conformance.py`: `python conformance.py run --live [--binary
  <path>] [--write]` launches each discovered binary through `launch_act` (I2,
  `tools/runtime/launch.py`, TOOL-dWellOiledMachine-1) in a scratch fixture repository whose own
  `.claude/settings.json` holds the probe hooks and the allow rules its calls need; it never passes a
  permission- or hook-skipping flag (`--dangerously-skip-permissions`, `bypassPermissions`, `--bare`,
  `--safe-mode`), which TOOL-dWellOiledMachine-37's preflight refuses. Discovery reads the binaries on
  PATH (`claude`, `codex`), the application-bundled binary from the adapter table's `[binary]
  app-paths` globs, and the pinned path `runtime.binary` names. Observed by AC2 and AC11.
- **S2** — The rows, one `[[capability]]` name each, added to `CAPABILITY_NAMES`
  (`tools/runtime/harness.py`, TOOL-dWellOiledMachine-14 S1) where absent: `program-launch`;
  `preset-session-id` (`yes` preset, `returned` from the start event, `no`); `resume`;
  `headless-fork`; `schema-return`; `hook-events`, the events that fired and whether each carried the
  payload fields the packs read (`REQUIRED_HOOK_FIELDS`); `on-failure`, a crashing hook under
  `onFailure` denying the call; `hook-trust`, a hook edited after Codex trusted it seen skipped;
  `live-inbox`; `transcript-home` and `transcript-retention`, the node's `cleanupPeriodDays` and
  Codex's rollout retention; `hook-bash`, which bash a hook runs in and the PATH inside it, with which
  of `sed`, `awk`, `grep`, `mktemp` resolve and whether `timeout` is coreutils'. Observed by AC1, AC3,
  AC4 and AC5.
- **S3** — The offline arm: `python conformance.py run --replay <dir>` derives the same rows from
  recorded launch output, stream-json and the probe hooks' payload logs, under
  `tools/runtime/fixtures/conformance/<adapter>-<version>/`, through the one derivation the live arm
  uses. The claude-code 2.1.292 record is captured by S1's live run on this node; the codex record is
  composed from Codex's documented event shapes, marked `synthetic` in its directory's `source` file,
  until a node with Codex records one. Observed by AC1, AC3, AC4 and AC5.
- **S4** — The writes: under `--write`, each row lands in the binary's adapter table as
  `[[capability]]` with `measured-on` and `binary-version` (I7), replacing that name's row for that
  version only; and each binary's `[[binary]]` row, `binary`, `version`, `os`, `shell`, `bash`,
  `path`, `interpreters` (python through `resolve_python`, node through `node --version`),
  `measured-utc` and `conforms`, lands in the node facts through `write_node_fact` (I8). `conforms` is
  true when every row of `ACT_ROWS` (`program-launch`, `preset-session-id` not `no`, `schema-return`,
  `hook-events`, `on-failure`) passes on that binary. Observed by AC2.
- **S5** — `runtime.binary` (`policy-key.runtime.binary`, catalogue
  `tools/policy/catalogue.toml:1590-1594`), read through `resolve` (I31) by `resolve_binary(adapter)`:
  `newest-conforming`, the default, takes the `conforms = true` binary of that adapter with the
  highest version; `path` the PATH binary; `app-bundled` the discovered application binary; a pinned
  path that path. Each answer must carry a `conforms = true` facts row, or the reader refuses, exit 1,
  `binary — none conforming · <adapter> · <value>`. `python conformance.py binary <adapter>` prints
  the path and version. Observed by AC6.
- **S6** — `runtime.owner-harness` (`policy-key.runtime.owner-harness`, catalogue `:1596-1600`), read by
  `resolve_owner_harness()`: `auto`, the default, takes the harness whose adapter table's `[detect]`
  row matches the running session, claude-code's being the `AI_AGENT` prefix `claude-code_` that
  `read_cli_version` already parses (`tools/unattended/unattended.sh:8936-8942`); a registered name is
  taken as named; either is refused when it is not in `runtime.harnesses` or detection matches no
  adapter. Observed by AC7.
- **S7** — The retention warning at preflight: `verb_preflight` (`tools/unattended/unattended.sh:7341`)
  prints `preflight — warn · <adapter> transcripts kept <n> days, shorter than runtime.journal <m>` when
  a measured `transcript-retention` is shorter than `runtime.journal` (catalogue `:512-517`); under
  `all` any finite retention warns; an unmeasured one warns that it is unmeasured. It refuses nothing.
  Observed by AC8.
- **S8** — node declared, measured and floored (AP-16): the floor is declared once, `[toolchain] node`
  in `tools/runtime/kit.toml`; each kit shipping a fragment whose `interpreter` is node (the default,

  `tools/hooks/kit.toml`, `tools/memory-recall/kit.toml`, `tools/process-monitor/kit.toml` and

- **S9** — `help/runtime.md` gains a section on the fixture: how to run it, what each row means, the

## 4. Design

### Evidence

- The one live launcher today is `run_live_session` (`tools/policy/check_policy.py:4289-4302`), which
  passes `--permission-mode bypassPermissions`; I2 extracts `launch_act` from it, and S1 drops the flag
  (scout A, "The live fixture conflicts with unit 37").
- `resolve_bash` finds the bash that can see a script by running each candidate
  (`tools/lib/resolve_bash.py:15-36`); it answers what gov runs, not what a harness hook runs in, so
  S2's `hook-bash` row is measured inside the hook.
- On node a at writing: `claude --version` on PATH prints `2.1.292 (Claude Code)`, the session's
  `AI_AGENT` names 2.1.308, `node --version` prints `v22.22.3`, and no `codex` is on PATH (PINNED,
  measured 2026-10-26).
- A fragment's `interpreter` defaults to `node` (`tools/settings-merge.py:48,270`), and nine of the
  twelve tracked fragments declare none (`git ls-files '*.fragment.json'`, 2026-10-26).

### The run

```
discover binaries ── for each: launch_act(probe item, work order, harness, env) in a scratch repo
                                ├─ program-launch, preset-session-id, resume, headless-fork, schema-return
                                ├─ probe hooks log each event's payload keys, the bash and PATH they ran in
                                ├─ a crashing hook under onFailure, an edited hook after trust (codex)
                                └─ transcript home and retention read from the harness's own settings
derive rows (one function, live and replay) ── --write ─▶ [[capability]] rows + [[binary]] facts row
```

## 5. Production-readiness checklist

- security — no permission-skipping flag ever (AC11); the fixture repository is scratch, outside the
  tree; probe hooks log key names, never payload values.
- perf / scale — the live arm launches about ten short sessions per binary; the replay arm reads files.
- error / empty / loading states — a row the run could not observe is `unmeasured`, never `no`; no
  conforming binary is a refusal naming the key's value.
- observability — every row carries the binary version and date it was measured on.
- risks — the synthetic codex record can disagree with a real Codex; its `source` file says so, and
  a live record replaces it.
- testing — the arm in §7 over the replay records; the live arm on demand.
- migration — none, §4.
- user docs — `help/runtime.md`, S9.
