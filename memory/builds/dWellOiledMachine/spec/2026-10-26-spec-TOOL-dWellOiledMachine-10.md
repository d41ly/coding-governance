## 1. Goal

Every enforcement hook fails open today: no entry sets `onFailure`, all 31 failures of one burst
admitted the call, and pre-commit, commit-msg and pre-rebase trap no signal (gap-rt-02). The hook
surface spans five kits, each wiring its own entries (gap-tool-03), and a killed hook on Windows still
lands an ungated push while the lander is unversioned (gap-deploy-07). This unit makes the kits'
fragments packs behind one dispatcher entry per event, makes the dispatcher's PermissionRequest entry
the only allow path for gated tools, judges an attended session's gated call as
`runtime.attended-judge` says, fails every entry closed or open as `runtime.hook-failure` says, and
hardens the git hooks and the lander (layer-runtime `[enforce]`, :592-717; RT-2, RT-4).

## 2. Scope (IN)

- **S1** — The pack contract (I9). A `*.fragment.json` keeps its five required keys and two optional
  ones (`tools/settings-merge.py:242-282`), keeps the optional `purpose` TOOL-dWellOiledMachine-22
  admits, and gains six: `owner` (the chain build or kit that owns
  it), `class` (`refuse`, `warn` or `record`), `failure` (`closed` or `open`, the pack's own default
  when `runtime.hook-failure` is unset), `budget-ms` (a positive integer), `key` (the policy key it
  reads, or `none`) and `witness`, an object `{record, reader}` or absent. `load_fragment`
  (`tools/settings-merge.py:252`) and `read_fragment_keys` (`tools/check-wiring.sh:159`) change
  together: check-wiring reads the pack fields by calling `settings-merge.py --resolve-pack <file>`,
  which prints them one `key=value` per line, as it already calls `--resolve-hook`, so one parser
  grades a pack. A pack missing a field, or carrying a value outside its set, is refused naming the
  file and the field. The twelve tracked fragments and the built-in `AGENT_CAP` (`:231-241`) gain the
  fields. Observed by AC1.
- **S2** — The dispatcher (I10), `tools/runtime/dispatch.js <Event>`, in the runtime kit (I1). It
  reads the pack table (S3) for its event, filters packs by matcher against the payload's `tool_name`
  or `source`, and runs each pack's rendered command (`render_command`, `:282`) in registration order
  with the payload on stdin, each bounded by its `budget-ms`. It reads a pack's verdict as the harness
  reads it today: exit 2 with a stderr reason, or stdout JSON carrying `decision`, `reason`,
  `hookSpecificOutput` or `additionalContext`. The first `refuse` verdict ends the run and is the
  dispatcher's output, in the event's shape; `warn` and `record` packs never block; context outputs
  are joined in order. Observed by AC2.
- **S3** — Rendering. `settings-merge.py`, called once by govkit's `run_fragment_merges`
  (`tools/govkit/govkit.py:6109`) with every fragment, writes one entry per event whose matcher is the
  union of its packs' matchers and whose command is
  `node "${CLAUDE_PROJECT_DIR}/<prefix>/runtime/dispatch.js" <Event>`, and writes the pack table
  `.claude/hook-packs.json`: per event, each pack's name, matcher, command and S1 fields in
  registration order, which is the order `run_fragment_merges` passes the fragments. `--check`
  compares both files. `remove_wired_fragments` (`:6180`) unwires a pack by removing its row and
  re-rendering. Observed by AC3.
- **S4** — The owner-pack table, both ways: check-wiring's new arm `check_packs` reds a settings hook
  entry that is not a dispatcher entry, a dispatcher entry for an event with no pack in the table, and
  a table row whose fragment is not installed. It prints its population, `<n> pack(s) over <m>
  event(s)`, and a population of zero is `unarmed`, never green. Observed by AC4.
- **S5** — `onFailure` on every entry. Under `runtime.hook-failure` `closed`, the default
  (`tools/policy/catalogue.toml:472-475`), settings-merge writes `"onFailure": "block"` on every
  dispatcher entry; under `open` it writes none, and check-wiring's session arm prints
  `hook-failure — open · <n> entr(ies) fail open` (§8 F2). The value is read at render through `resolve`
  (I31), run as `python <prefix>/policy/policy.py get runtime.hook-failure`. Observed by AC5.
- **S6** — A failing pack. The dispatcher counts a pack failed when it cannot start, exits other than
  0 or 2, overruns `budget-ms`, or prints output it cannot parse. Under `runtime.hook-failure`
  `closed` it refuses the call with `BLOCKED by dispatch: pack <name> failed (<why>) · hook-failure
  closed`; under `open` it continues and writes `hook-failure` through `write_journal_line` (I3). The
  value is read once per run through `readPolicy("runtime.hook-failure", {repo})` (I31). The pack's
  own `failure` field decides only where the key is unset in every source. Observed by AC6.
- **S7** — The permission baseline. `tools/runtime/baseline.settings.json` is the one source of the
  gated tools, `Bash`, `PowerShell`, `Write`, `Edit`, `MultiEdit`, `NotebookEdit`, `Agent` and
  `Workflow`, as a `permissions.ask` list. `launch_act` (I2) passes it to every act session as an extra
  settings source, `--settings <file>`, and sets `GOV_SESSION_KIND=act` in the launch environment.
  Tracked `.claude/settings.json` carries the same ask rules only under `runtime.attended-judge`
  `allowance` or `person`; under `classifier-or-person` it carries none. A dispatcher entry for
  `PermissionRequest` is rendered whenever the baseline exists. Observed by AC7.
- **S8** — The PermissionRequest decision, the gated tools' only allow path. The dispatcher's
  `PermissionRequest` run first runs its event's packs (act binding registers here later); a pack's
  `allow` or `deny` is the answer. With none, in an act session (`GOV_SESSION_KIND=act`) it answers
  `deny`, so an unbound gated call never runs; in any other session it decides by
  `runtime.attended-judge`: `classifier-or-person` and `person` make no decision; `allowance` answers
  `allow` only for a call matching an entry of `runtime.attended-allowance`, a tool name or
  `Tool(pattern)` matched as the harness matches a permission rule, and makes no decision otherwise,
  so a planted call outside it goes to the person (RT-4). Observed by AC8.
- **S9** — The allow-path class check, in `check_packs`: an allow rule on a gated tool in tracked
  settings, a second `PermissionRequest` hook, and a gated tool in the baseline with no
  `PermissionRequest` dispatcher entry each red, naming the file and the rule. Observed by AC9.
- **S10** — Witnesses with named readers. `tools/runtime/witnesses.toml` holds one `[[witness]]` row
  per event that cannot fail closed (`SessionStart`, `SubagentStart`, `SubagentStop`, `Stop`,
  `StopFailure`, `PreCompact`, `PostCompact`, `SessionEnd`, `pre-commit`, `commit-msg`, `pre-push`):
  `event`, `record`, `reader`, and `armed-by`, the unit id that ships the reader where it is not yet
  built. `check_packs` reds an event of that set with no row, and a pack on such an event whose
  `witness` names a record no row declares. The `pre-push` row names the allow record and push-main,
  built today (`.githooks/pre-push:69,490`). Observed by AC10.
- **S11** — The commit witness. `.githooks/pre-commit` and `.githooks/commit-msg` each append, at
  their one success exit and nowhere else, one line `<utc> <hook> <tree8> <message8>` to
  `<git-common-dir>/gov/commit-witness.log`, `<tree8>` from `git write-tree` and `<message8>` the
  message file's SHA-1 prefix (commit-msg only, `-` in pre-commit). Observed by AC11.
- **S12** — Signal traps on every git hook. `.githooks/pre-commit`, `.githooks/commit-msg` and
  `.githooks/pre-rebase` trap `HUP`, `INT`, `QUIT`, `PIPE` and `TERM`, as `.githooks/pre-push:72-85`
  does, each exiting 128 plus the signal number with one stderr line naming the signal, and writing no
  witness. Each hook carries its traps inline, as every copy-installed hook does. Observed by AC12.
- **S13** — The trusted hooks copy. check-wiring's session arm copies every hook tracked under
  `.githooks/` from the default branch's tree, `git show <remote>/<default>:.githooks/<file>`, into
  `<git-common-dir>/gov/hooks/` and sets `core.hooksPath` to it; a branch's own `.githooks/` is never
  copied. Check H (`tools/check-wiring.sh:746-775`) reds a `core.hooksPath` that resolves into a
  checkout, and the pre-push rollout and fallback (`.githooks/pre-push:243,876`) and govkit's matrix
  (`tools/govkit/matrix.py:144`) follow the copy. Observed by AC13.
- **S14** — Lander hardening. `tools/push-main.sh` gains the constant `PUSH_MAIN_VERSION`, read by its
  descriptor's `version_from` (`tools/govkit/entries/push-main.kit.toml:7`, today `none`), and the
  descriptor declares `requires = ["run-gates"]`, the bar's kit (`:8`, today empty). The lander
  refuses a landing, exit 2, when `core.hooksPath` is not the trusted copy S13 sets, naming both paths.
  Its existing `landed UNGATED` refusal of a push with no allow record (`.githooks/pre-push:66-70`)
  stands. Observed by AC14.
- **S15** — The `[[point]]` row `point.hook-packs` in `points.toml` (I4), `purpose` "a fragment with its
  owner, class, failure mode, budget and key", `contract` this spec's S1, and each pack's tag
  `hook.<fragment name>` in the `hook` namespace (`tag-namespace.hook`). Observed by AC15.
- **S16** — The page `help/runtime.md` gains a section on the packs, the two keys of the attended

## 4. Design

### Evidence

- Twelve fragments and the built-in `AGENT_CAP` render 13 commands across 7 events in
  `.claude/settings.json:3-121`; `grep -c onFailure .claude/settings.json` is 0 at this base.
- No `PermissionRequest`, `SubagentStop`, `PreCompact`, `PostCompact` or `SessionEnd` entry exists.
- Today's packs answer in two shapes: exit 2 with a stderr reason (`tools/hooks/scratch-guard.js:1559`,
  `tools/unattended/gate-guard.js:777`, `tools/hooks/agent-cap.js:1850`) and stdout JSON
  `{decision, reason}` (`tools/unattended/stop-guard.js:193`, `tools/hooks/format-guard.js:547`).
- Only `block` is a documented `onFailure` value, from 2.1.295
  (`memory/builds/dClosedLoop/build/2026-10-15-build-PLAY-dClosedLoop-1-research-runtime-floor.md:15`;
  `…-research-runtime-hooks.md:74`); 2.1.292 ignores the key.
- pre-push alone traps signals (`.githooks/pre-push:72-85`); `grep -c trap` over `pre-commit`,
  `commit-msg` and `pre-rebase` is 0 each.
- `core.hooksPath` in this clone is the absolute path of the primary tree's `.githooks`, the
  `hookspath-resolves-into-another-checkout` class.
- push-main's descriptor declares no version and no dependency
  (`tools/govkit/entries/push-main.kit.toml:7-8`).
- The three keys' catalogue rows exist (`tools/policy/catalogue.toml:472`, `:492`, `:498`); nothing
  reads them.

### The pack table

```json
{"schema": 1,
 "events": {"PreToolUse": [
   {"name": "scratch-guard", "matcher": "Bash|PowerShell|Edit|Write|MultiEdit|NotebookEdit",
    "command": "node \"${CLAUDE_PROJECT_DIR}/tools/hooks/scratch-guard.js\"",
    "owner": "hooks", "class": "refuse", "failure": "closed", "budget-ms": 2000, "key": "none"}]}}
```

The dispatcher reads only this file and the policy; it never globs for fragments.

### The decision, per event shape

| Event | A pack refuses by | The dispatcher emits |
|---|---|---|
| `PreToolUse`, `PermissionRequest` | exit 2 and stderr, or `hookSpecificOutput.permissionDecision` | the first refusal, unchanged |
| `Stop`, `SubagentStop` | stdout `{"decision":"block","reason":…}` | the first block, unchanged |
| `SessionStart`, `SubagentStart`, `PreCompact`, `PostCompact` | never; context only | contexts joined in registration order |

### The attended judge

| `runtime.attended-judge` | Tracked ask rules | Dispatcher on a gated call in a non-act session |
|---|---|---|
| `classifier-or-person` (default) | none | no decision; the classifier or the person judges |
| `allowance` | the baseline | `allow` inside `runtime.attended-allowance`, else no decision |
| `person` | the baseline | no decision; the person answers every call |

### Migration

Additive for adopters: govkit's next `update` re-renders `.claude/settings.json` from the same
fragments, now as dispatcher entries, and writes the pack table. A fragment without the S1 fields is
refused at render, so every shipped fragment gains them in this unit. The first session-arm run copies
the hooks to the trusted path and moves `core.hooksPath`; a clone whose `core.hooksPath` names a
deliberate other directory is reported, never overwritten, as Check H does today.

### Rollout

`runtime.hook-failure` defaults to `closed`, the catalogue's value. `runtime.attended-judge` defaults
to `classifier-or-person`, under which tracked settings gain no ask rule, so an attended session's
judging is unchanged until the owner sets another value.

### Alternatives rejected

- **An in-process dispatcher requiring each pack as a module.** Two of today's packs are bash
  (`manifest-check.sh`, `check-wiring.sh`), and every node pack is a standalone script; running the
  rendered command keeps each pack byte-unchanged.
- **The dispatcher globbing fragments at call time.** It would run packs a target never installed and
  pay a directory walk per call; the rendered table is the installed set.
- **A second `PermissionRequest` hook per kit.** Two allow paths are exactly what S9 refuses.

## 5. Production-readiness checklist

- security — the dispatcher becomes the one allow path for gated tools; an act session denies any
  gated call no pack approves; S9 refuses an allow rule on a gated tool in tracked settings; the trusted
  copy stops a branch weakening its own hooks.
- perf / scale — one process spawn per matching pack, as today, plus one dispatcher spawn per event;
  each pack bounded by its `budget-ms`.
- error / empty / loading states — an unreadable pack table refuses under `closed` and journals under
  `open`; an event with no pack renders no entry; `check_packs` on zero packs prints `unarmed`.
- observability — each failed pack is a `BLOCKED by dispatch` line or a `hook-failure` journal line;
  the session arm names the policy in force.
- risks — under `closed`, a broken pack denies every call it matches until repaired from the owner's
  terminal; the repair path is the exception register (layer-runtime :705-709).
- testing — the fixture cases under AC1 to AC16 and the arms in §7.
- migration — one re-render per adopter on `update`; §4 Migration.
- user docs — `help/runtime.md`, S16.
