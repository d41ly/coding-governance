## 1. Goal

A session today has two per-session records, the orientation card under `<git-common-dir>/orientation/`
and, from TOOL-dWellOiledMachine-12, its binding. The memory plan's `[pockets]` retires the card into
the binding: the card's bytes move into the binding record, and every reader moves with them in this
unit, the write gate's `readCard`, `extractRouteUnits` and the route notice, and
`manifest-check.sh --card --write` with its siblings, with `check-wiring.test.sh`,
`format-guard.test.sh`, `scratch-guard.test.sh` and `manifest-check.test.sh` re-pointed beside them.
The old path is still read for `install.deprecation-window` releases as an upgrade step.

## 2. Scope (IN)

- **S1** — The card's home. The card's bytes move into the session binding
  `<git-common-dir>/gov/session-bindings/<sid>.md` (I17), after a marker line `<!-- card -->` that
  closes the binding's own header and runtime sections; the card view is every byte after that line,
  identical to what the card file held. `tools/runtime/session_binding.py` gains `read <sid> --card`,
  printing the card view, and `put-card <sid>`, replacing it from stdin under the record's lock and
  keeping every byte above the marker; `put-section` inserts above the marker. The per-session file
  `<git-common-dir>/orientation/<sid>.md` is retired as a write home: nothing writes it after this unit.
  **Readers:** by name: `skills/session-kickoff/manifest-check.sh` (:32, `CARD_DIR` :312-316),
  `skills/session-kickoff/manifest-check.test.sh` (:861-1077, fourteen lines),
  `tools/hooks/scratch-guard.js` (:52, `readCard` :671), `tools/hooks/scratch-guard.test.sh` (:540,
  :542, :740), `tools/hooks/format-guard.test.sh` (:255, :258, :287), `tools/hooks/README.md` (:285,
  :429) and `memory/map/features/agent-cap.md` (:109), each re-pointed in this unit · by value:
  `tools/hooks/format-guard.js` (:91, :479), which reads the card through `readCard`;
  `tools/roles/handoff.py` `resolve_card_path` (:255), which reads the path `--card --path` prints and
  parses its `## task` section; and `tools/check-wiring.test.sh`, whose fixtures plant the card and
  assert the two orientation fragments. Observed by AC1, AC2 and AC7.
- **S2** — The writer re-pointed. `manifest-check.sh`'s card home resolves to the binding
  (`CARD_DIR` :312-316 and `CARD_FILE` :316): `--card --write` (:1220) and `--card --replay` store the
  card view through `put-card`, `--card --append` (:1143) reads it with `read <sid> --card` and stores
  the appended view through `put-card`, `--card --check` (:1198) grades the card view, and
  `--card --path` prints the binding's path. Every derivation, cell and cap of the card stays byte
  for byte. Observed by AC1 and AC2.
- **S3** — The gate's reads re-pointed. `readCard(commonDir, sessionId)` in `tools/hooks/scratch-guard.js`
  reads the binding and returns the card view as `text`, the binding's path as `path` and `shown`, and
  `owner` from the header; `extractRouteUnits` (:839) is called on that text unchanged; the route notice
  in `renderRouteContext` (:1494-1500) names the binding's path. `tools/hooks/format-guard.js` keeps its
  import (:91) and reads the binding through it. Observed by AC3, AC4, AC5 and AC6.
- **S4** — A binding is a card's presence. In the orientation check (`scratch-guard.js:767-788`), a
  session whose binding exists is never witnessed as `orientation card absent`: an `owner: yes` binding
  with no card view denies the commit as a card that carries no `## task`, and an act binding (`owner`
  an act id) is witnessed `orientation exempt — act session <act>`, since an act's work order carries
  its facts (layer-runtime `[sessions]`). In the route gate (:1180-1190), a routed write is allowed when
  the binding's `## route` names a buildable unit, and refused, naming the binding, when the session
  has neither a binding nor a legacy card. Observed by AC3, AC4 and AC5.
- **S5** — The old path, read as an upgrade step. When the binding holds no card view and
  `<git-common-dir>/orientation/<sid>.md` exists, `readCard` and `read <sid> --card` read the legacy
  file and name it `(legacy card)` on `shown`; nothing writes it. An `[[upgrade]]` row in
  `tools/govkit/entries/kickoff-manifest.kit.toml` (TOOL-dSafePassage-1 S1) declares the move, from
  `<git-common-dir>/orientation/<sid>.md` to the binding, and the legacy read stays until that row
  closes under `install.deprecation-window` by TOOL-dSafePassage-6 S5's release count; the unit that
  closes the row takes the read out. Observed by AC6 and AC8.
- **S6** — The four suites re-pointed in this unit: `manifest-check.test.sh` reads cards at the binding
  through `read <sid> --card`, `scratch-guard.test.sh` and `format-guard.test.sh` plant bindings
  carrying the card view where they planted card files, and `check-wiring.test.sh` plants the binding
  where its card fixtures planted the card. Each keeps one legacy arm for S5. Observed by AC7.

## 4. Design

### Evidence

The card lives at `<git-common-dir>/orientation/<sid>.md` (`manifest-check.sh:312-316`), written by
`--card --write` at SessionStart and read by `readCard` (`scratch-guard.js:667`), called at :774, :1176,
:1180 and :1495, and by `format-guard.js:479` through the import at :91. The route is read by
`extractRouteUnits` (:839) from the card's `## route`. The orientation check witnesses an absent card
and allows (:775), which is the "witnessed" the clause forbids once a binding exists. `handoff.py`
locates the card only through `--card --path` (:255-270), so it moves with S2 and needs no edit.
`git grep -c "orientation/" -- . ':!memory/builds' ':!memory/ledger'` lists the seven by-name readers
of S1; the four suites carry 6 to 23 `orientation` references each.

### The record after this unit

```
session: 5e1d…
owner: yes
build: fx
…
bound-utc: 2026-10-26T22:40:51Z

## delivery
delivered — startup · 3911 · 2026-10-26T22:40:52Z
<!-- card -->
orientation — session 5e1d… · node a · … (the card, byte for byte)
## task
…
## route
- build: fx
- unit: TOOL-fx-1 · spec memory/builds/fx/spec/…
```

One marker line splits the record in both languages, so the card view has one definition: Python
`str.partition("\n<!-- card -->\n")` and JS `text.split("\n<!-- card -->\n")`, each taking the tail.
A binding with no marker has no card view.

### Alternatives rejected

- **The card as a `## card` section of the binding.** The card carries its own `## task` and
  `## route` headings, so a section cannot hold it without renaming them, and `extractRouteUnits` would
  no longer read it unchanged.
- **A card file beside the binding.** Two records per session is the state the clause retires.
- **Deleting the legacy read now.** A session started before the upgrade would lose its route until it
  restarted, which the deprecation window exists to prevent.

## 5. Production-readiness checklist

- security — the write gate's deny is unchanged in strength and gains one case (S4); the record home
  is node-local and the session id is validated by unit 12's rule before any join.
- perf / scale — one file read per gate call, as today.
- error / empty / loading states — no binding and no legacy card keeps today's behaviour; a binding
  with no card view denies an owner's commit and names the binding; an unreadable binding reads as
  absent and says so on `shown`.
- observability — `shown` names the binding or `(legacy card)`, so every deny says which was read.
- risks — a session started before the upgrade reads its legacy card until it restarts; the legacy
  read outlives its need until a release closes the row.
- testing — the four suites' arms in §7 and AC1 to AC8.
- migration — the `[[upgrade]]` row of S5; no card is copied, since a card lives one session.
- user docs — `tools/hooks/README.md` (:285, :429) names the binding as the card's home.

## 6. Acceptance criteria

The fixture is a scratch repository with the kickoff kit, the hooks and unit 12's writer installed.

- **AC1** — When `bash manifest-check.sh --card --write --session t1` runs in the fixture, the binding
  for `t1` carries the `<!-- card -->` line and a card view byte-equal to the card the base script
  writes for the same inputs, and no file appears under the common dir's `orientation/`.
  Red when: the card is written to the legacy path, or its bytes change.
- **AC2** — When `bash manifest-check.sh --card --path --session t1` runs, it prints the binding's path,
  and `--card --append --session t1` of a body with a `## route` leaves both the header and the
  `## delivery` section in place.
  Red when: the path is the legacy one, or an append loses a byte above the marker.
- **AC3** — When `node scratch-guard.js` grades a commit of a path outside the route in a session with
  a binding, an `owner: yes` header, no card view and no legacy card, it denies naming the binding and
