## 1. Goal

P39's rework budget is keyed to builds and intake content only, so a cadence run's loop, Maintain's,
the Loop Review's or any registered program's, has no bound (gap-rt-45, gap-register:310): a period
whose program never converges is run again at every wake. This unit gives the scheduler its
cadence-items point, where a program registers with its host key, its period, its argv and its
events; runs every registered item once per period at the node tick through unit 13's period witness;
and bounds each period by a budget of its own, derived from its period lease's history, whose
exhaustion ends the period as `flow.on-exhausted` says.

## 2. Scope (IN)

- **S1** — The point (I4): the `[[point]]` row `name = "point.cadence-items"` in
  `tools/runtime/points.toml`, `purpose` "a program with its host key, its period, its lease and its
  events" (layer-runtime `[extend]`, :870), `contract` this spec's S2. Its `[[adapter]]` rows carry,
  beside I4's fields, `host-key` (the catalogue key whose value names the host adapter it runs on,
  `maintain.host`, `kits.host` or `run.host`, since "Runtime adds no host key", layer-runtime
  `[schedule]` :791-798), `period` (`daily` or `weekly`, the kinds `derive_period` takes,
  TOOL-dWellOiledMachine-13 S5), `run` (a non-empty argv list) and `events` (the core record events it
  names, possibly empty). The row's `name` is its cadence segment. Observed by AC1.
- **S2** — The row check, `check_cadence_row(row, catalogue)` in `tools/runtime/cadence.py`: it
  refuses a `host-key` the policy catalogue holds no row for, a `period` outside `derive_period`'s
  kinds, an empty or non-list `run`, and a `name` the lease grammar refuses, asked of
  `check_cadence_segment` (TOOL-dPlacedRequest-18 S1) through `bash` as `hosts.py ready` asks the
  tick probe. `python cadence.py --check` runs it over every row at the point, prints one line per refused
  row naming it, exits 1 on any, and prints `cadence — <n> item(s) registered`, `0 item(s) registered
  · unarmed` on an empty point. Observed by AC1.
- **S3** — The tick, `run_cadence_tick(now)` in `cadence.py`, run as `python cadence.py tick [--now
  <utc>] [--dry-run]`. For each registered row in file order: read the `host-key`'s value through
  `resolve` (I31, `tools/policy/policy.py:752`); ask `python hosts.py ready <value>`
  (TOOL-dWellOiledMachine-13 S4), printing `cadence — <name> · host <value> not ready` and running
  nothing on exit 1 or 2; derive the period key with `derive_period(row.period, now)`; read S4's
  budget; and while it is open run `run_cadence_period(name, period, run)` (TOOL-dWellOiledMachine-13
  S6), which reads the period's witness, takes the period lease, runs the argv and releases. `--dry-run`
  prints each row's decision and writes nothing. Observed by AC2, AC5.
- **S4** — The period's budget, `derive_period_budget(cadence, period)` in `tools/loop/budget.py`
  (TOOL-dDeclaredLoop-30's module): its total is `flow.rework-budget`'s base, read through that
  unit's parser (its S1), a period having no units and so no per-unit share (its S2, "the base for a
  build with no units"); its spend is the number of `released` records (TOOL-dPlacedRequest-16 S1, the
  hand-over `run_cadence_period` writes on a failed run) on the first-parent chain of
  `refs/gov/leases/run/<cadence>/<period>`, read from the cache ref the lease read fetches
  (TOOL-dPlacedRequest-13 S3). Each lap that ended without the period's witness is one draw, derived
  from the lease and never typed beside it. `budget_state` gains the key form `run/<cadence>/<period>`,
  answering `open` or `exhausted` with `<spent>/<total>`, as it answers for a build. Observed by AC2,
  AC4.
- **S5** — The ending. When S4 reads `exhausted`, the tick reads `flow.on-exhausted` (catalogue
  `tools/policy/catalogue.toml:766-770`) through `resolve` and calls `derive_ending(value, [], state)`
  (TOOL-dDeclaredLoop-31 S2) with no units: `best-effort-ending` and `close-incomplete` answer
  `close-incomplete`, and the tick takes the period lease and releases it `--as aborted`
  (TOOL-dPlacedRequest-1 S5), a terminal record, so no later wake runs the period, printing
  `cadence — <name> <period> · budget spent <s>/<t> · ending close-incomplete`; `park-for-owner` writes
  nothing and prints `cadence — <name> <period> · parked · budget spent <s>/<t>` at every wake while
  the period stays exhausted and unwitnessed, the park derived from the lease and left by the owner's
  `--lease release run <name> <period> --as withdrawn` or by the next period's key. Observed by AC3.
- **S6** — The node tick. `tools/unattended/resume-tick.sh` runs `python cadence.py tick` once per
  tick, after its worktree scan and the supervisor step, through the inline `resolve_python` block the
  kit's scripts carry; `--dry-run` passes through; a failed tick prints one line and leaves the tick's
  exit unchanged. Observed by AC5.
- **S7** — The page `help/runtime.md` gains a section on cadence items: the row fields, the tick, the

## 4. Design

### Evidence

- No cadence item registers anywhere today: gap-rt-15 (gap-register:280) says "no extension point
  takes one", and layer-runtime's `[extend]` table names the point and its four fields (:870).
- The tick is the only scheduler (`gov-resume-tick`, `tools/unattended/README.md:224-232`), and unit
  13's `run_cadence_period` runs one period of one argv, leaving "which items run at the tick" to
  this point (TOOL-dWellOiledMachine-13 §3).
- A run lease's history is a first-parent chain of `gov-claim` commits (TOOL-dPlacedRequest-1 S2), and
  a failed period ends in a `released` hand-over (TOOL-dWellOiledMachine-13 S6 step 5), so the chain
  already holds every failed lap.
- `flow.rework-budget` and `flow.on-exhausted` have catalogue rows owned by dDeclaredLoop
  (`tools/policy/catalogue.toml:766-770` for the latter); the budget module keys on a build only
  (TOOL-dDeclaredLoop-30 S2).

### Data model

```toml
# tools/runtime/points.toml
[[point]]
name = "point.cadence-items"
purpose = "a program with its host key, its period, its lease and its events"
contract = "an [[adapter]] row carries host-key, period, run and events (TOOL-dWellOiledMachine-59 S1)"

[[adapter]]                      # the fixture's plant; this unit registers no real item
point = "point.cadence-items"
name = "fx-loop"
host-key = "run.host"
period = "daily"
run = ["python", "fx_loop.py"]
events = []
tenancy = "local"
retention = "none"
region = "local"
grant = { service = "local", scopes = [], secret = "anonymous" }
```

### One period's life

| Wake | Lease chain before | Budget | What the tick does |
|---|---|---|---|
| 1 | none | 0/4 open | lap 1 runs, fails, releases |
| 2 to 4 | 1 to 3 `released` | open | laps 2 to 4 run, fail, release |
| 5 | 4 `released` | 4/4 exhausted | the ending: `aborted`, or parked |
| 6 | `aborted` | — | the lease read refuses the tombstone; nothing runs |

The total of 4 is the catalogue default `4+2`'s base (DERIVED from `flow.rework-budget` at the tick).

### Alternatives rejected

- **Authored draw rows on the lease record.** A `draws` field on each lease commit types beside the
  chain what the chain already holds, and changes TOOL-dPlacedRequest-1's record; §8 F1.
- **A node-local draw ledger.** A period handed to another node would start its budget from zero, so
  two nodes alternating would never exhaust it.
- **A budget per cadence, not per period.** A weekly program that failed one week would start the
  next week spent; the clause keys the budget to the period lease.

## 5. Production-readiness checklist

- security — rows carry argv and key names, never a secret, and I4's `grant` is checked on each row
  by TOOL-dWellOiledMachine-17's `check_adapter_grant`; the ending writes only through `--lease`.
- perf / scale — one lease read and one chain walk per registered row per tick; a chain holds at most
  the budget's total plus two commits per period.
- error / empty / loading states — an empty point prints `unarmed`; an unready host and an unreadable
  key each print their row and run nothing; a chain the cache lacks reads as no laps, never as spent.
- observability — one `cadence —` line per row per tick, and the period lease's chain is the record.
- risks — a program that fails fast exhausts its period in five wakes, about fifty minutes on the
  ten-minute tick (DERIVED from the default budget and the tick's period); that is the bound working,
  and the next period runs again.
- testing — the fixture plants under §6 and the arm in §7.
- migration — none: no row is registered before this unit, and the build budget's form is unchanged.
- user docs — `help/runtime.md`.

- **AC2** — When `--plant never-converges` runs the tick six times with a program that always exits 1,
  the program runs exactly four times, the period lease's chain holds four `released` records and then
  one `aborted`, and the fifth tick prints `budget spent 4/4 · ending close-incomplete`.
  Red when: `derive_period_budget` is stubbed to answer `open`, so the program runs on every tick.
- **AC3** — When `--plant park` sets `flow.on-exhausted` to `park-for-owner` and runs the tick six
  times, the program runs four times, the fifth and sixth ticks each print `parked · budget spent 4/4`,
  and the chain's tip stays `released`.
  Red when: a parked period runs again, or the park writes a terminal record.
- **AC4** — When `--plant converges` runs a program that exits 0, the first tick runs it once and every
  later tick in the period prints `witnessed by` and runs nothing; when `--plant next-period` advances
  `--now` a day past an exhausted period, the new period's first tick runs the program with its budget
  at `0/4`.
  Red when: a witnessed period runs again, or one period's spend carries into the next.
- **AC5** — When `--plant host-not-ready` stubs `hosts.py ready` to exit 1, the tick prints `host
  requesting-node not ready` and the program does not run; when `bash resume-tick.sh --dry-run` runs
  over the fixture, it prints the `fx-loop` row's decision and writes nothing.
  Red when: a row runs on a host that refused, or the dry run writes a lease.
- **AC6** — When `grep -n "point.cadence-items\|flow.on-exhausted" runtime.md` runs over the help page,
  both are named.
  Red when: the page omits the point or the ending.
