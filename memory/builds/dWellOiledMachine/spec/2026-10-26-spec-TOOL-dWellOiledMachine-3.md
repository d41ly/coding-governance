## 1. Goal

A build can end today only by landing: the owner's pause, resume and abort exist for unattended runs
alone (`--hold`, `--resume`, `--abort`), supersede does not exist, a pause has no ceiling, and nothing
closes a withdrawn build's leases and mailbox (gap-flow-10). This unit gives the owner one guarded
command for pause, resume, withdraw and supersede, mapped onto those verbs and the loop's rows; a
pause is a declared wait within `flow.wait-ceiling` that `leases.renewal: progress` renews, past
which an owner item asks to resume, withdraw or stay paused, and that item unanswered at
`run.owner-deadline` parks the build with its lease released (the owner's FK-4-10); a withdrawal or
supersession closes the build's leases with terminal tombstones and its mailbox, every message
copied into the build folder first; and attend and unattend each write an `attendance override`
record scoped by `attendance.scope` (the night pass, point 1).

## 2. Scope (IN)

- **S1** — The guarded command, `python tools/runtime/lifecycle.py <verb> <slug> [--by <slug>]
  [--value <attendance value>]`, verbs `pause`, `resume`, `withdraw`, `supersede`, `attend` and
  `unattend`. Every verb first runs `check_terminal_proof` (TOOL-dDeclaredLoop-2 S5); without it the
  command prints the request it would write and exits 2, writing nothing. `supersede` requires `--by`
  naming a build folder that exists. Observed by AC1, AC7.
- **S2** — The lifecycle request, `record-kind.lifecycle-request`: one commit per request on the
  append-only ref `refs/gov/life/<slug>`, built by `build_gov_commit` parented on the tip read and
  written by `write_gov_ref` (TOOL-dPlacedRequest-11 S1, S2), its message the header `gov-life
  <slug>/<id>` and the keys `id` (the first 12 hex of SHA-256 over verb, slug, session and the request's
  UTC second), `verb`, `build`, `by`, `session`, `fleet-tag` and `requested-utc`. A `[[record-kind]]`
  row `lifecycle-request` in `tools/memory-tree/record-kinds.toml` (TOOL-dTotalRecall-1 S1) names that
  home, its writer `lifecycle.py` and its check the `runtime selftest` leg. `read_life_requests(slug)`
  is the one reader. Observed by AC1.
- **S3** — The mapping, `apply_request(request)`, one idempotent step list per verb (§4 "The
  mapping"): `pause` holds the run through `run_hold` (`tools/unattended/unattended.sh:6848`) under
  `host-owner-action` where a run-state file exists, records B19 (TOOL-dDeclaredLoop-13) through
  `write_transition` with item `item.life.request`, and declares S4's wait; `resume` releases the run
  through `verb_resume` (`:9149`), records B20 and the pause wait reads woken; `withdraw` and
  `supersede` end the run through `verb_abort` (`:6678`) and run S5. Each step prints `life — <item
  tag> · <slug> · <outcome>`. Observed by AC2, AC3, AC4.
- **S4** — The pause wait: `declare_wait("pause", <request id>, <slug>, on="refs/gov/life/<slug>",
  seconds=flow.wait-ceiling × 3600, outcome="pause-ceiling")` (TOOL-dWellOiledMachine-18 S2), the
  ceiling read through `resolve`. The kind `pause` joins `WAIT_KINDS` with no wake, and the outcome
  `pause-ceiling` joins `WAIT_OUTCOMES`: it raises `raise_owner_item("owner-write", <slug>, ["resume",
  "withdraw", "stay-paused"], "stay-paused", key=<wait id>)` (TOOL-dWellOiledMachine-48 S1), whose
  owner-only kind parks the build with its lease released when it is still unanswered at
  `run.owner-deadline` (TOOL-dWellOiledMachine-48 S5). The owner answers by running the verb:
  `resume` or `withdraw` answers the open item with its own name, and `pause` on a paused build
  answers `stay-paused` and declares a fresh pause wait. Observed by AC2.
- **S5** — The close program for `withdraw` and `supersede`, in flow-steps' `[lifecycle]` order:
  `life.quiesce`, `unattended.sh --quiesce <slug> --request <id>` (TOOL-dWellOiledMachine-58 S7), which
  exits 3 while a unit holder has neither acked nor passed `runtime.act-ceiling`, the command then
  printing `life — waiting · <n> unit lease(s)` and exiting 3 for the owner to run again;
  `life.notify`, `notify_dependents(<slug>, <verb>, <by>)` (TOOL-dWellOiledMachine-48 S12);
  `item.life.snapshot` (S6); `life.unlease`, `unattended.sh --unlease <slug>`
  (TOOL-dWellOiledMachine-58 S9), which writes every unit lease and the build lease `withdrawn`, gives
  every message a `mailbox-message` record in the build folder, the undisposed ones titled `<id> —
  undisposed at close`, and only then prunes the mail refs; and `item.life.close`, T11 (`withdrawn`)
  or T12 (`superseded`, carrying `by`) through `write_transition` (TOOL-dDeclaredLoop-15 S3). Every step
  is skipped when its witness already stands, so a re-run finishes a close a crash left half done.
  Observed by AC3, AC4.
- **S6** — `item.life.snapshot`, the card's terminal snapshot committed while the build still holds
  its lease: `manifest-check.sh --card --follow --build <slug> --to <withdrawn|superseded> --terminal`

  `snapshot — <slug> · <state> · <record>`. A follow that writes no record stops the close before

- **S7** — A request on a build no lease holds. Where `unattended.sh --claims` reads the build lease
  absent, `released` or terminal, the command declares an `owner-request` wait keyed by the request id

- **S8** — The `attendance override`, `record-kind.attendance-override`: `attend` and `unattend` write

## 4. Design

### Evidence

- The three verbs exist for unattended runs only: `--hold` → `run_hold`, `--resume` → `verb_resume`
  and `--abort` → `verb_abort` (`tools/unattended/unattended.sh:14562-14567`), and no verb supersedes.
  `run_hold`'s usage line requires a keepalive witness, `--reaped <id>` or `--keepalive-unreachable
  <node>` (`:24`); which one a pause passes is UNVERIFIED, and the build pass reads `:6848` before the
  call.
- The loop already names the moves: B19 `@open` → `paused` and B20 `paused` → `@prior` on
  `item.life.request` (TOOL-dDeclaredLoop-13 §4), T11 and T12 into `withdrawn` and `superseded` on
  `item.life.close` (TOOL-dDeclaredLoop-15 §4).
- The catalogue holds `attendance.scope` (`tools/policy/catalogue.toml:66`, `session`, `build`,
  `repository`, default `build`) beside KICK-dKeptSession-17's `attendance` (:60).
- The program is flow-steps' `[lifecycle]` table
  (`memory/builds/dClosedLoop/build/2026-10-15-build-PLAY-dClosedLoop-1-flow-steps.md:677-692`):
  `life.request`, `life.quiesce`, `life.notify`, `life.snapshot` ("commits the card's terminal
  snapshot"), `life.unlease` and `life.close`, attend and unattend stopping at the record.
- The queued claim's replay is refused by the parents once the tombstone stands: a queued write is a
  compare-and-swap on its recorded tip, so it yields on the moved tip, and an acquisition over a
  `withdrawn` build lease is refused `tombstone` (TOOL-dPlacedRequest-16 S3, S6).

## 5. Production-readiness checklist

- security — every verb needs the terminal proof; every lease, mail and tombstone write passes the
  record door, whose prune rule refuses a mail ref whose messages were not copied first.
- perf / scale — one request commit per verb; a close is the three parent verbs and one transition.
- error / empty / loading states — a waiting quiesce exits 3 and re-runs; every step is skipped once
  its witness stands; a refused proof writes nothing.
- observability — one `life —` line per step, the request on its ref, the `snapshot —` line.
- risks — an owner who never re-runs a waiting withdraw leaves the wait to raise its item at
  `flow.wait-ceiling`.
- testing — the fixture cases under AC1 to AC8 and the arm in §7.
- migration — none: no request or override exists; `--hold`, `--resume` and `--abort` keep working.
- user docs — `help/runtime.md`.

## 6. Acceptance criteria

Each case runs `python lifecycle_fixture.py --case <name>` in its scratch clones.

- **AC1** — When `--case request-record` runs `lifecycle.py pause fx` with the terminal proof, the
  remote's `refs/gov/life/fx` tip carries `verb: pause` and `read_life_requests` prints it; without
  the proof it exits 2 and the ref is absent.
  Red when: a request is written without the proof.
- **AC2** — When `--case pause-ceiling` pauses `fx` with `flow.wait-ceiling` planted at `0.0003` and
  runs `waits.py sweep` past it, one `owner item owner-write fx` is posted with the options `resume`,
  `withdraw` and `stay-paused`, and past `run.owner-deadline` `owner_items.py decide` parks `fx` with
  its build lease `released`; `lifecycle.py resume fx` before the ceiling wakes the wait and posts none.
  Red when: the planted pause past the ceiling raises no owner item, or the item is decided `resume`.
- **AC3** — When `--case withdraw` runs `lifecycle.py withdraw fx` over three messages, one of them
  `open`, with one dependent build `fz`, it prints `snapshot — fx · withdrawn` before any mail ref is
  pruned, `fz`'s mailbox holds one `withdrawn` message, `memory/builds/fx/` holds three
  `mailbox-message` records with one titled `undisposed at close`, every lease of `fx` reads
  `withdrawn`, and the transition record names `withdrawn` on `item.life.close`.
  Red when: a mail ref is pruned before its messages are copied, the snapshot is missing, or a lease
  is left live.
- **AC4** — When `--case queued-replay` queues an offline claim on `fx`'s build lease in the second
  clone, withdraws `fx` from the first, then flushes the queue, the flush prints `yield` and the lease
  still reads `withdrawn`, and `--lease acquire build fx` there is refused `tombstone`; `--case
  supersede` writes T12 with `by: fy`.
  Red when: the queued claim replayed against the withdrawn build lands.
- **AC5** — When `--case unleased-withdraw` runs `lifecycle.py withdraw fx` on a build whose lease is
  `released`, the command prints `life — requested` and writes no tombstone, and the next
  `waits.py sweep` closes `fx` under `refs/gov/leases/run/wake/<wait id>`; a second sweep runs nothing.
  Red when: the request is never applied, or applied twice.
- **AC6** — When `--case attend-<scope>` runs `lifecycle.py attend fx --value confirm-steps` under each
  value of `attendance.scope`, `lifecycle.py attendance --build fx` answers `confirm-steps` for the
  writing session, for another session only under `build` and `repository`, and for another build only
  under `repository`; `unattend` answers `unattended`.
  Red when: an override is read outside its scope, or `attend` writes no override record.
- **AC7** — When `--case supersede-no-by` runs `lifecycle.py supersede fx` with no `--by`, it exits 2
  naming the flag and writes nothing.
  Red when: a supersession is recorded with no successor.
- **AC8** — When `--case witnesses` runs `check_life_witness fx item.life.close` after AC3's
  withdrawal, it answers witnessed, and before it answers not witnessed.
  Red when: the reader answers witnessed with a lease still live.
- **AC9** — When `grep -n "attendance.scope" runtime.md` runs over the help page, it names the
  section, and the page names the six verbs and `flow.wait-ceiling`.
  Red when: any verb, the scope key or the ceiling is absent.
