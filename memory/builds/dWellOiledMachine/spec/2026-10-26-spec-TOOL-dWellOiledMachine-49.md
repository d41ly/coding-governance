## 1. Goal

No refusal is counted: every PreToolUse and git hook refuses afresh, a builder was refused 10 times
in a row by one rule, and the stop guard's cap resets with each session (gap-rt-39). This unit
journals every refusal with its rule, ends an act whose one rule refuses `runtime.refusal-repeats`
times with a typed refusal return naming the remedy's actor, and refuses at registration a remedy
another registered guard refuses (P39; the owner's SL-7; stall-and-loop item 7).

## 2. Scope (IN)

- **S1** — The key's reader. `runtime.refusal-repeats` (`tools/policy/catalogue.toml:456-461`, a
  `retry-count` from 1 to 10, default 3, `raise-loosens`) is read once per breaker call by
  `derive_refusal_limit(repo)` in the new `tools/runtime/breaker.py`, which runs
  `python <prefix>/policy/policy.py get runtime.refusal-repeats` (I31) as a subprocess, a kit importing
  no sibling kit. A refused read takes the catalogue default 3 and prints one
  `breaker — NOTE · runtime.refusal-repeats unreadable, read 3 · <why>` line. Observed by AC3, AC5.
- **S2** — Every hook-pack refusal journaled with its rule. `write_refusal_line(act, session, pack,
  rule, actor)` in `breaker.py`, run as
  `python breaker.py refusal --pack <p> --rule <r> --actor <a> --remedy <m> [--session <id>]`, writes
  one line through `write_journal_line("refusal", …)` (I3, TOOL-dWellOiledMachine-16 S3) carrying
  `act=<GOV_ACT>` where the environment names an act, else `session=<id>`, and `rule=<pack>/<rule>`
  and `actor=<a>`. The dispatcher (`tools/runtime/dispatch.js`, TOOL-dWellOiledMachine-10 S2) runs it
  once for each refusal it emits, after composing TOOL-dWellOiledMachine-31 S3's
  `refusal — <pack> · rule <rule> · actor <actor> · remedy <remedy>` line, from that line's fields
  and the payload's `session_id`. A failed run never turns a refusal into an admission: the call is
  still refused, and `breaker — not recorded · <why>` goes to stderr. Observed by AC1.
- **S3** — Every git-hook refusal journaled the same way. `.githooks/pre-commit` collects the basename
  of each gate that set `rc=1`, plus `worktree` for its work-tree refusal (`:17-22`) and
  `codebase-map` for that leg's refusals; `.githooks/commit-msg` names `check-commit` (`:60`) and
  `.githooks/pre-rebase` names `straggler-rebase` (`:65`). At its refusing exit each hook runs
  S2's command once per rule, `--pack git:<hook>`, `--actor self` and its own printed remedy line,
  through the python its tree resolves (`tools/lib/resolve-python.sh`). With neither `GOV_ACT` nor
  `CLAUDE_CODE_SESSION_ID` in the environment the command writes nothing and exits 0, so a commit
  typed at a terminal is refused exactly as before. Observed by AC2.
- **S4** — The breaker, keyed on the rule. In S2's call, when the environment names an act, the
  count is the act's `refusal` lines carrying the same `rule`, read through `read_journal` over
  `runtime.log`, this one included. When the count reaches S1's limit, or at the first refusal
  whose `actor` is not `self` (v2:1213, "a refusal its target cannot act on routes there at once"),
  `write_breaker_return(act, rule, remedy, actor, count)` writes the typed refusal return
  `<git-common-dir>/gov/breaker/<act>.json`, TOOL-dBoundRoles-26 S1's arm,
  `{"outcome": "refused", "rule": …, "remedy": …, "actor": …, "breaker": "open", "count": <n>}`,
  writes one `breaker-open` journal line with the same fields, prints
  `breaker — open · <act> · rule <pack>/<rule> · <n> of <limit> · actor <a>` and exits 3; under the
  limit it exits 0. An owner session, with no act, is journaled and never broken. Observed by AC3,
  AC5.
- **S5** — The act ended. A pack `breaker` in the runtime kit, `tools/runtime/breaker-gate.js`
  with its fragment `tools/runtime/breaker-gate.fragment.json`, registered first on `PreToolUse`
  over the gated tools of TOOL-dWellOiledMachine-10 S7's baseline, class `refuse`, refuses every call
  of an act whose `<act>.json` exists, a file read and no spawn:
  `BLOCKED by breaker: act <act> ended by rule <pack>/<rule>`, its reason carrying the typed return
  verbatim and the instruction to return it as the act's final answer, under its one declared
  refusal row `breaker-open` (actor `driver`, `remedy-call` `none`). S2 journals these refusals and
  S4 never counts `breaker/breaker-open`. The act's return is the typed refusal, which
  TOOL-dBoundRoles-26 S2's `validate_return` reads and S4's `handoff.py route-refusal` routes to the
  remedy's actor. Observed by AC4.
- **S6** — The draw on the build's budget. The return's `breaker: open` is what the driver's door
  reads: TOOL-dBoundRoles-26 S4's `route-refusal`, given such a return, draws once through
  TOOL-dDeclaredLoop-30's `budget.py draw --build <slug> --cause re-dispatch --item <item>` before it
  routes. That door is a parent's, so the change is an ask (§8 F3). NOT OBSERVED by this unit's
  criteria: the door and the draw are parent code; the field they read is observed by AC4.
- **S7** — A remedy another registered guard refuses, refused at registration. TOOL-dWellOiledMachine-31
  S1's refusal row gains `remedy-call`, required on every row whose `actor` is `self` and refused on
  any other: the tool call the remedy makes, `{"tool": "<name>", "input": {…}}`, or the string `none`
  where the remedy is to refrain or is no tool call. `check_refusal_fields` (31's, in
  `tools/settings-merge.py`) grades it with the other fields. Every render then runs

- **S8** — Today's rules declared. Each of the 18 refusal rules TOOL-dWellOiledMachine-31 S5 declares

## 4. Design

### Evidence

- The only refusal counter is the stop guard's, per session and per run, with no rule key:
  `measureBlocks` (`tools/unattended/stop-guard.js:129`) over its sidecar, capped at 8
  (`:92`).
- The breaker must key on the rule: keyed on the action, a rephrased refused write never tripped;
  keyed on the rule, it tripped at event 4 (stall-and-loop P4,
  `memory/builds/dClosedLoop/build/2026-10-19-build-PLAY-dClosedLoop-1-stall-and-loop.md:151-152`).
- Six refusal cycles between guards were found, T5 to T6 and V28 to V27 among them
  (`memory/builds/dClosedLoop/build/2026-10-19-build-PLAY-dClosedLoop-1-research-stall-refusals.md:192-198`).
- The git hooks refuse at `.githooks/pre-commit:20,22,310`, `.githooks/commit-msg:60` and
  `.githooks/pre-rebase:65`, with pre-commit's gates each setting `rc=1`.
- The launch environment names the act as `GOV_ACT=<act>` (TOOL-dWellOiledMachine-12 S3,
  TOOL-dWellOiledMachine-6), which a hook and a git hook run inside the act's session inherit.
- Preset cells: `velocity` 5, `standard` 3, `strict` 2, `guarded` 3 (v2:1536).

### The count, by example

```
v=1	t=…	p=runtime	ev=once	class=refusal	act=act-0123456789ab	rule=fx-guard/locked-file	actor=self
v=1	t=…	p=runtime	ev=once	class=refusal	act=act-0123456789ab	rule=fx-guard/locked-file	actor=self
v=1	t=…	p=runtime	ev=once	class=refusal	act=act-0123456789ab	rule=fx-guard/locked-file	actor=self
v=1	t=…	p=runtime	ev=once	class=breaker-open	act=act-0123456789ab	rule=fx-guard/locked-file	actor=self	count=3
```

Three writes with three different contents to one locked path are three lines of one rule, so the
third trips the breaker at the default limit; the action and its input never enter the key.

### The typed return

```json
{"outcome": "refused", "rule": "fx-guard/locked-file", "remedy": "write the change to src/open.txt",
 "actor": "self", "breaker": "open", "count": 3}
```

The fields are TOOL-dBoundRoles-26 S1's arm, so the return is valid wherever that arm is read;
`breaker` and `count` are the two this unit adds, which S6's ask asks the door to read.

### The registration probe

```
for row in every refuse pack's refusal rows with a remedy-call object:
    payload = {hook_event_name: PreToolUse, tool_name: row.call.tool, tool_input: row.call.input,
               session_id: "remedy-probe"}
    for pack in refuse packs on PreToolUse, pack != row.pack, matcher matches row.call.tool:
        verdict = run the pack as the dispatcher runs it, env GOV_PACK_PROBE=1
        refused -> "remedy — refused · <row.pack>/<row.rule> remedy refused by <pack>/<its rule>"
```

`ponytail:` the probe runs each pack once per remedy, a product of two small numbers; a cache keyed
by payload digest if the pack count grows past what one render can afford.

### Alternatives rejected

- **Counting per session, as the stop guard does.** One session holds many acts, and the clause
  bounds one act; a session count would end an owner's session on a builder's refusals.
- **Keying on the call's input.** Measured not to trip on a rephrased write (P4).
- **A breaker pack that counts by itself.** The count needs the journal reader; the gate pack only
  reads the marker, so the hot path spawns nothing.
- **A declarative "refuses" pattern per rule, joined against every remedy.** Every pack would carry a
  second description of its own logic, which can drift from the code; replaying the remedy through
  the pack observes the code itself.

## 5. Production-readiness checklist

- security — the breaker only adds refusals; a failed journal write still refuses; the probe runs
  tracked packs on a synthetic payload under `GOV_PACK_PROBE=1`.
- perf / scale — one subprocess per refusal, none per admitted call; the gate pack is one file stat.
- error / empty / loading states — an unreadable key reads 3 with a NOTE; no act means journal only;
  no refusing row prints `unarmed`.
- observability — every refusal is a `refusal` line; every trip a `breaker-open` line and a
  `breaker —` line.
- risks — a pack with side effects run by the probe; S7's `GOV_PACK_PROBE=1` is the pack's cue to
  write nothing, and the help page says so.
- testing — the fixture cases AC1 to AC6 and the arms in §7.
- migration — §4 Migration.
- user docs — `help/runtime.md` (S9).

## 6. Acceptance criteria

The fixture is a scratch clone under `%TEMP%` with a short name, the runtime and policy kits
installed, and a planted pack `fx-guard` on `Write|Edit` refusing any write to the clone's
`locked.txt` under rule `locked-file`, actor `self`, remedy "write the change to src/open.txt" and
`remedy-call`
`{"tool": "Write", "input": {"file_path": "src/open.txt"}}`.

- **AC1** — When `node dispatch.js PreToolUse` runs a write to the locked file with
  `GOV_ACT=act-0123456789ab`, the clone's `runtime.log` gains one `class=refusal` line carrying that
  `act`, `rule=fx-guard/locked-file` and `actor=self`; with `GOV_ACT` unset and the payload's
  `session_id` set, the line carries `session=` instead.
  Red when: a refusal writes no line, or the line carries no rule.
- **AC2** — When `git commit` runs in the clone with a planted pre-commit gate `fx-gate.sh` that
  exits 1 and `GOV_ACT` set, `runtime.log` gains one `rule=git:pre-commit/<gate>` line naming that
  gate; with neither `GOV_ACT` nor `CLAUDE_CODE_SESSION_ID` set, the commit is refused and no line is written.
  Red when: a git-hook refusal goes unjournaled, or a terminal commit writes a line.
- **AC3** — When a planted builder sends three calls refused by `locked-file`, a `Write` of one

- **AC4** — When the act then calls `Bash`, `node dispatch.js PreToolUse` refuses it

  line while the count of `fx-guard/locked-file` lines stays 3.
  Red when: a call passes after the trip, or the breaker's own refusals count toward a rule.
- **AC5** — When a planted rule with actor `owner` refuses once, `breaker.py` prints
  `1 of 3 · actor owner` and opens; when the planted policy file names `preset = "strict"`, the

  preset store.
  Red when: a refusal its target cannot act on waits for the count, or strict's value trips at 3.
  fixture: KICK-dKeptSession-1's `presets.toml`, a parent's, landed before this build runs.
- **AC6** — When `python settings-merge.py` renders a planted pair, `fx-a` refusing a write to
  `a.txt` with `remedy-call` a write to `b.txt` and `fx-b` refusing a write to `b.txt` with

- **AC7** — When `grep -n "refusal-repeats"` runs over the runtime kit's page `runtime.md`, the
