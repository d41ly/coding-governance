## 1. Goal

A session is no node: its id keys a per-session card and a run claim and joins nothing else
(gap-orient-19). This unit derives the session node from the binding records, joins it to its act by
`runs-in` and to its predecessor by `after`, registers acts and sessions as native-id classes read
beside the one index and never written into it, delivers a mail ring live through a session's inbox
where the harness's conformance row passes, and fills the card's session list through the harness
adapter (P33, P36; memory-plan `[sessions]`).

## 2. Scope (IN)

- **S1** — The two classes, as PLAY-dOrderedCharter-28 S2's `[[native]]` rows in
  `tools/playbook/namespaces.toml`: `class = "act"` with `pattern = "act:ACT_RE"` and
  `resolver = "session_node:resolve_act"`, and `class = "session"` with
  `pattern = "handoff:SESSION_ID_RE"` and `resolver = "session_node:resolve_session"`, each
  `owner = "dWellOiledMachine"`. `SESSION_ID_RE` is the existing lowercase-UUID pattern
  (`tools/roles/handoff.py:119`); `ACT_RE`, compiling I15's act id `act-<12 hex>`, is added to
  `tools/runtime/act.py` beside TOOL-dWellOiledMachine-32's `mint_act`, which mints no pattern of
  its own. Each is the one compiled form of its id (§8 F1). Observed by AC1.
- **S2** — The node, `read_session_node(repo, session)` in the new `tools/runtime/session_node.py`,
  derived from the bindings alone: the I17 session binding
  `<git-common-dir>/gov/session-bindings/<session>.md`, read through TOOL-dWellOiledMachine-12's
  `session_binding.py read <sid>`, for `node`, `build`, `owner`, `started-utc` and `after`; the acts
  that run in it, each the binding's `act` field and every I15 act record whose `harness-session`
  names the session, as `runs-in` edges from act to session; its predecessor through a resume or a
  fork, the binding's `after` field, as an `after` edge from session to session; and the commits
  whose `Gov-Session` trailer (TOOL-dWellOiledMachine-33) names it, or under `salted` its digest,
  read through `read_commits`, as `runs-in` edges from commit to session. Observed by AC2.
- **S3** — The resolvers: `resolve_session(repo, token)` answers the node of S2, and
  `resolve_act(repo, token)` the act's minimal binding through `read_binding(repo, act)` (I16,
  TOOL-dWellOiledMachine-39 S6) with the session it runs in. An act whose binding reads
  `bound local` or `bound ref` and whose session binding this node lacks answers
  `not-local: node <x>`, the node the I16 binding's `node:` names; an act `read_binding` answers
  `not-local` for answers `not-local: node unknown`; an id no binding names answers `unresolved`.
  Neither resolver writes a row into the index PLAY-dOrderedCharter-19's `build_index` writes.
  Observed by AC1, AC3, AC4.
- **S4** — The CLI: `python <prefix>/runtime/session_node.py show <session|act>` prints one
  `session — <id> · node <tag> · build <slug> · owner <yes|act>` line, one `runs-in — <act>` line
  per act, one `after — <session|none>` line and one `commit — <sha8>` line per commit, or the
  single line `not-local: node <x>`; exit 0 resolved, 1 `unresolved`, 2 refused. Observed by AC2,
  AC4.
- **S5** — The live inbox. KICK-dKeptSession-6's `run_mail_ring <ref> <id>` in
  `tools/unattended/unattended.sh` gains its first live channel: it runs
  `session_node.py ring <ref> <id>`, which reads the message's `to` from `read_mailbox`'s row for
  `<id>` (KICK-dKeptSession-5 S6), selects the live sessions bound to that recipient, and for each
  one whose harness adapter's I7 row `live-inbox`, read through
  `read_capability(adapter, "live-inbox")` (TOOL-dWellOiledMachine-14 S3, measured by
  TOOL-dWellOiledMachine-36), reads `script`, posts the one line `mail — <id> · <ref>` through that
  adapter's `[inbox] argv`, passing no other fact. A row reading `model` or `none`, or `unmeasured`
  and so absent, posts nothing and prints `ring — none · <adapter> live-inbox reads <value>`. A ring
  never fails the post. Observed by AC5.
- **S6** — The card's session list. KICK-dKeptSession-13's `render_pointers` gains the line
  `sessions — <session8> <status> · …`, its word `sessions` appended to `POINTER_LINES`, filled by
  `session_node.py sessions <slug>`: every session binding whose `build` is the slug, each with the
  status its harness adapter's `[sessions] argv` reports (`claude agents --json` for `claude-code`,
  an id-to-status map), `unlisted` where the adapter has no such table; `sessions — none` with no
  binding and `sessions — skipped: <why>` on a failure. Observed by AC6.
- **S7** — The page `help/runtime.md` gains a section on the session node: its sources, the two
  edges, the two classes, `not-local`, the live inbox's three row values and the card's
  `sessions —` line. Observed by AC7.

## 4. Design

### Evidence

- `git grep -n -E "Gov-Session|session-bindings|\[\[native\]\]"` over `tools`, `skills` and
  `.githooks` finds nothing at this base: no session node, binding or native class exists.
- A session id keys the per-session card `<git-common-dir>/orientation/<sid>.md`, read by
  `tools/hooks/scratch-guard.js`, and run claims; nothing else joins on it (gap-orient-19).
- The research measured that a script can resume, fork, read transcripts and list sessions with
  `claude agents --json`, and that only a model was observed sending into another session's inbox; a
  script posting into another session's inbox was not tested
  (`memory/builds/dClosedLoop/build/2026-10-18-build-PLAY-dClosedLoop-1-research-harness-cli.md:98-102`).
  So the post is gated on the measured row and never assumed.
- PLAY-dOrderedCharter-28 S2 says each later native class "is registered, and its resolution armed,
  by the build that brings it", and S1 widens `after` to session to session.

### The node

```
session — 6c1f0b8e · node a · build fx · owner act
runs-in — act-0a1b2c3d4e5f
after — 2b9d4e11
commit — 1a2b3c4d
```

| Edge | From | To | Source read |
|---|---|---|---|
| `runs-in` | act | session | the session binding's `act`; the act record's `harness-session` |
| `runs-in` | commit | session | the `Gov-Session` trailer, or its digest under `salted` |
| `after` | session | session | the session binding's `after` |

### The adapter tables this unit reads

```toml
# tools/runtime/harnesses/<adapter>.toml, beside TOOL-dWellOiledMachine-14's [[capability]] rows
[inbox]                       # read only where the live-inbox row reads "script"
argv = ["<binary>", "...", "{session}", "{line}"]

[sessions]
argv = ["claude", "agents", "--json"]
```

The `live-inbox` row's three values, `script`, `model` and `none`, are the reading this unit gives
TOOL-dWellOiledMachine-14's `value` field for that one name; its return proposes them to that unit.

### Alternatives rejected

- **Writing sessions and acts into the one index.** The memory plan reads them "beside a tree's
  index from the binding records"; an index row would go stale the moment a binding is written on
  another node.
- **Posting to every live session on the node.** A ring for one build's mailbox would wake sessions
  of other builds; the recipient's `to` selects them.
- **Assuming Claude's inbox takes a script's post.** Untested in the research; the measured row
  decides it.

## 5. Production-readiness checklist

- security — the inbox line carries only the message id and its ref, never a body or a field; the
  session list prints an eight-character prefix.
- perf / scale — one directory read of the session bindings and one `read_commits` call per node;
  one adapter listing call per card render.
- error / empty / loading states — an unbound id is `unresolved`, a foreign one
  `not-local: node <x>`, no sessions `sessions — none`, a failed listing
  `sessions — skipped: <why>`.
- observability — every ring prints one `ring —` line naming the adapter and its row value.
- risks — a stale session binding lists a dead session; its listed status shows it.
- testing — the fixture cases AC1 to AC6 and the arms in §7.
- migration — none.
- user docs — `help/runtime.md`'s section (S7).
