## 1. Goal

Hook text is unregistered instruction: SubagentStart context, Stop-hook block reasons, PreToolUse deny
reasons and SessionStart output are composed in code, outside the unit registry, its grammar and its
budgets (gap-rt-13), and Workflow harness prompts are a load point with no grammar, budget or parity
(gap-rt-20). The systems record gives dWellOiledMachine the hook-message and harness-prompt templates
(`memory/builds/dClosedLoop/build/2026-10-16-build-PLAY-dClosedLoop-1-systems.md:421`), and
TOOL-dBoundRoles-15 §3 hands the harness prompts here. This unit moves both kinds of text into
PLAY-dOrderedCharter-20 S7's slot-line templates over instruction units, renders them through the one
renderer of record, and has each hook and harness fill only the run-time values.

## 2. Scope (IN)

- **S1** — The two templates, `tools/playbook/templates/hook-message.template.md` and
  `tools/playbook/templates/harness-prompt.template.md`. Each holds one `## <key>` section per message
  and nothing but slot lines in it, in PLAY-dOrderedCharter-20 S7's grammar: `<!-- units: <selector> -->`
  for fixed text and `<!-- slot: <name> -->` for a value filled at run time. A hook message's key is
  `hook.<pack>.<rule>` for a refusal, the pack and rule of its `refusal` row (TOOL-dWellOiledMachine-31
  S1), or `hook.<pack>.<name>` for a context or block text; a harness prompt's key is
  `harness.<script>.<label>`, `<label>` the `agent()` call's label. Observed by AC1.
- **S2** — The `message` tag namespace, one `[[namespace]]` row in `tools/playbook/namespaces.toml`
  (PLAY-dOrderedCharter-19 S2): `ns = "message"`, `role = "selects"`, `source` the two templates,
  `extractor = "tag_index:extract_message"`, one member `message.<key>` per `## <key>` section. A
  section's units line selects `message.<key>`, so each message selects exactly its own units.
  Observed by AC2.
- **S3** — The fixed text as instruction units, rows of the owning kit's manifest
  (PLAY-dOrderedCharter-9 S1): `tools/hooks/instructions.toml`, `tools/unattended/instructions.toml`
  and `tools/workflows/instructions.toml`, each unit's `scope` the `message.<key>` it serves, its
  `budget` `line` or `block`, its `type` one of `STATEMENT_TYPES`, a refusal's statement a `constraint`
  whose `enforced-by` opens with the pack's `.js` file name and its remedy a `pointer`. The schema and
  grammar checks (PLAY-dOrderedCharter-20 S1, PLAY-dOrderedCharter-12 S2) grade them as every unit.
  Observed by AC3.
- **S4** — The render, a scope `messages` of the renderer of record
  (`render_playbook.py --render-scope messages`, PLAY-dOrderedCharter-20 S5): each hook kit gets one
  generated table `<kit>/messages.json`, `{"schema": 1, "messages": {"<key>": "<text>"}}`, a units
  line rendered by `render_units` and a slot line as `{<name>}`; each harness script gets the region
  between `/* gov:harness-prompts */` and `/* /gov:harness-prompts */` rewritten as one `PROMPTS`
  object of the same shape, in its `.template.js` where one exists and in the script itself otherwise.
  `--check-render --scope messages` compares every table and region; `tools/playbook/renderers.toml`
  gains the `[[target]]` row claiming them. Observed by AC4.
- **S5** — The hook side. Each hook kit carries one module, `<kit>/render-message.js`, exporting
  `renderMessage(key, slots)`, which reads the kit's own `messages.json` once per run, filling each `{name}` from `slots`, and, for a
  `hook.<pack>.<rule>` key, ending the text with TOOL-dWellOiledMachine-31 S3's `rule — <rule>` line.
  A missing table, key or slot still refuses where the call refuses, with `BLOCKED by <pack>: message
  <key> unavailable (<why>)` and the rule line, so a missing render opens no path. Every deny, block and
  context text of S7's population is produced through it. Observed by AC5.
- **S6** — The harness side. Each harness script carries inline `renderHarnessPrompt(key, slots)` over its
  `PROMPTS` region, and every `agent()` prompt of S7's population is produced through it; the run-time
  values a prompt carries today (a diff, a path, a unit id, the args) are its slots. Observed by AC6.
- **S7** — The population, derived at the pass and listed in §4: every refusal site of
  TOOL-dWellOiledMachine-31's inventory, scratch-guard's `renderRouteContext` (`tools/hooks/scratch-guard.js:1470`),
  stop-guard's and format-guard's block reasons, and every `agent()` call in
  `tools/workflows/tier2-review.template.js`, `unattended-build.template.js`,
  `drift-audit-code.template.js`, `drift-audit-state.template.js`, `unattended-unit.js` and
  `orient-counterfactual.js`. Observed by AC7.
- **S8** — The refusal check re-pointed. TOOL-dWellOiledMachine-31 S4's source direction reads a
  source's rules from its `renderMessage("hook.<pack>.<rule>"` calls, since the `rule — <rule>` line is
  now appended by `renderMessage`; a declared rule no call names, and a call naming an undeclared rule,
  stay red. Observed by AC8.
- **S9** — The page `help/runtime.md` gains how a hook or a harness adds a message: a section, its
  units, its slots and the render. Observed by AC9.

## 4. Design

### Evidence

- Every hook text is a template literal in code: scratch-guard's `renderDeny` (`:540`),
  `renderOrientationDeny` (`:733`), `renderRouteDeny` (`:930`), `renderRoleDeny` (`:1039`),
  `renderGateDeny` (`:1381`) and `renderRouteContext` (`:1470`); stop-guard's reasons
  (`tools/unattended/stop-guard.js:135-160`) and format-guard's (`tools/hooks/format-guard.js:547`).
- Workflow scripts cannot import (`tools/workflows/tier2-review.template.js:16`), so a harness reads
  its prompts only from text inside its own file.
- The six harness sources hold 18 `agent()` prompt sites at this base, PINNED 2026-10-26 by
  `git grep -n "agent("` over them less comment lines: tier2-review 4, unattended-build 5, unattended-unit
  1, drift-audit-code 3, drift-audit-state 3, orient-counterfactual 2.
- The workflows kit renders each `.template.js` to its `.js` by placeholder fill
  (`tools/workflows/kit.toml:41-92`), so a region written into a template reaches its render.
- PLAY-dOrderedCharter-20 S7: "A template holds slot lines and no prose", expanded by
  `render_units(derive_unit_selection(units, selector))`; its selector is a tag a unit's `scope` holds.

### A section, by example

The section for gate-guard's lease refusal is its heading `## hook.gate-guard.run-lease` followed by
three slot lines, in order:

```text
<!-- units: message.hook.gate-guard.run-lease -->
<!-- slot: slug -->
<!-- slot: phase -->
```

`messages.json` then holds `"hook.gate-guard.run-lease": "<unit lines>\n{slug}\n{phase}"`, and
gate-guard calls `renderMessage("hook.gate-guard.run-lease", {slug, phase})`.

### Alternatives rejected

- **Hooks rendering units at call time through Python.** A refusal would then depend on an
  interpreter in the hook's hot path; the rendered table needs none.
- **Selecting a message's units by the `hook` namespace.** Its members are packs, so one selector
  would load every message of the pack (§8 F1).

## 5. Production-readiness checklist

- security — a missing table, key or slot never turns a refusal into an admit (S5); the tables are
  generated and checked, never hand-edited.
- perf / scale — one JSON read per hook run that composes a message; harness prompts are inline
  constants.
- error / empty / loading states — S5's fallback line names the key and the cause.
- observability — `--check-render --scope messages` names a drifted table or region by path.
- risks — re-expressed text can lose a fact a reader relied on; each suite re-pointed in the same pass
  is the check.
- testing — the fixture cases under AC1 to AC8 and the arms in §7.
- migration — §4 Migration.
- user docs — `help/runtime.md`, S9.
