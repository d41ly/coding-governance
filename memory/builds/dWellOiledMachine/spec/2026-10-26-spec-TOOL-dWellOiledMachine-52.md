## 1. Goal

No node publishes its presence, capacity or plan, so a limit is seen only after it is hit
(gap-rt-40). The beat exists, `write_claim_beat` (`tools/unattended/unattended.sh:2469`), and renews
one run's claim, carrying no capacity, load, plan or tag. This unit makes the supervisor's beat,
pushed with each pass to the remote of every project the node serves, the node's beat: its fleet
tag, free agent slots against the node profile's capacity, hardware load read with the standard
library, any limit hold with its reset time, and each harness's plan allowance with the reading's
source and age and the plan's pool label, never a credential and nothing of another project's names
or work, with membership derived from live beats (v2 P40, cloud-and-scale item 6).

## 2. Scope (IN)

- **S1** — The payload, `render_node_beat(home=None, repo=None)` in `tools/runtime/beat.py`, printing
  one `key: value` line per member of the closed `NODE_BEAT_KEYS`: `node-capacity`, the profile's
  `capacity` (`read_node_profile`, I6, TOOL-dWellOiledMachine-61); `node-free-slots`, that less
  every live reservation's `slots` across all the node's projects in the hardware ledger
  (`read_node_ledgers`, I23, TOOL-dWellOiledMachine-53), floored at 0; `node-load` and
  `node-load-source` (S2); `node-hold`, `none` or `<pool>@<reset utc>` for each pool whose
  `hold-until` lies ahead; one `node-plan` line per profile harness, `<harness> · <allowance hours
  or unknown> · <source> · <age seconds or -> · <pool>`, from the plan ledger's pool the harness
  draws on; and `node-unaccounted`, the count of profile projects that never charged (TOOL-dWellOiledMachine-53
  S7). The fleet tag is the record's own `fleet-tag`. Every value is a count, a decimal, a UTC
  stamp, `none`, `-` or a profile harness name or pool label; no project name, build, unit, act or
  path is read into it. With no profile it prints `node-capacity: -` and the rest `-`. Observed by
  AC1.
- **S2** — The load, `measure_node_load(home=None)`, standard library only: where `os.getloadavg`
  exists, its one-minute figure over `os.cpu_count()`, source `loadavg`; on Windows the busy
  fraction since the previous beat from `GetSystemTimes`, called through `ctypes`, source
  `system-times`, the previous sample kept in the node facts as a `[load]` section, `idle`,
  `kernel`, `user` and `read-utc`, written through `write_node_fact` (I8,
  TOOL-dWellOiledMachine-15 S2), and `-` on the first beat with no sample. Never a subprocess and
  never a CIM call. Observed by AC2.
- **S3** — The check at render, `check_node_beat(lines, profile)`: a key outside `NODE_BEAT_KEYS`, a
  value outside its key's grammar, or a harness or pool label the profile does not declare is
  refused `beat — refused · <key> · not a node value`, and the beat then carries no node line at
  all, its renewal unaffected. So a beat that names another project's build is never written.
  Observed by AC3.
- **S4** — The wiring. `write_claim_beat` runs `python beat.py render` before it writes, and the one
  record writer `write_claim` (`:2396`) appends the printed lines to the record of a beat, never of
  another write, after the keys it writes today, as TOOL-dWellOiledMachine-15 S4 adds
  `clock-offset`; a reader that does not know a key skips it (the claim reader's key filter,
  `:2168`). The write goes through `write_gov_ref` under `GOV_DOOR_VERB=lease.beat`, so the door's
  token-shape arm scans it under population `beat` (TOOL-dWellOiledMachine-57 S2). Each project's
  supervisor beats its own remote, so the node is published to every project it serves.
  Observed by AC4.
- **S5** — Membership from live beats, `python beat.py members [--repo <root>]`: one line per fleet
  tag whose lease record carries a node beat the lease reader judges live, `<tag> · capacity <n> ·
  free <m> · load <x> · beat <utc>`, read through `unattended.sh --claims`; nothing is stored, and a
  node whose beats went stale is no member. Observed by AC5.
- **S6** — The page `help/runtime.md` gains the node beat's keys, what each counts, the load's two
  sources and `beat.py members`. Observed by AC6.

## 3. Non-goals (OUT)

- A beat for a node holding no lease in a project: the clause's beat is the supervisor's, pushed
  with each pass, and a project with no live build on the node has no supervisor there.
- The secret scan of the beat: TOOL-dWellOiledMachine-57 scans every `lease.beat` write.
- The clock offset in the beat: TOOL-dWellOiledMachine-15's `clock-offset` key.
- Choosing work from the members' beats: TOOL-dWellOiledMachine-54's discovery and pick.
- A plan allowance read from a harness account: the plan ledger's readings, TOOL-dWellOiledMachine-53.

## 4. Design

### The record

```
gov-claim <slug>

slug: …  node: …  host: …  session: …  status: live  beat-utc: 2026-10-26T21:00:00Z  …
clock-offset: 1                                  (TOOL-dWellOiledMachine-15)
node-capacity: 6
node-free-slots: 2
node-load: 0.25
node-load-source: system-times
node-hold: none
node-plan: claude-code · unknown · none · - · personal
node-unaccounted: 0
```

### The Windows load

`GetSystemTimes` returns idle, kernel and user times in 100-nanosecond units, kernel including idle;
the busy fraction between two samples is `1 - Δidle / (Δkernel + Δuser)`. One call costs well under a
millisecond, so the reading is the interval since the previous beat rather than a timed sleep.

### Alternatives rejected

- **A node ref of its own, `refs/gov/nodes/<tag>`, written by the node tick.** The clause names the
  beat the supervisor's, and the tick runs with no session, so its write would need a door path no
  coordination writer has (TOOL-dWellOiledMachine-58 S1 refuses a write with no session).
- **`tools/process-monitor/census.py`'s process scan for load** (`:260`). It spawns a CIM or `ps`
  subprocess per read, which the clause's "read with the standard library" and cloud-and-scale
  item 6's "never a PowerShell CIM call per item" refuse.

## 5. Production-readiness checklist

- security — a closed key set and per-key grammars keep project names, work and credentials out,
  and the door's scan runs over every beat write besides.
- perf / scale — one TOML read, one JSON read and one system call per beat.
- error / empty / loading states — no profile, no ledger and no previous sample each print `-`; a
  refused payload drops the node lines and keeps the renewal.
- observability — the record's node lines and `beat.py members`.
- risks — the beat reaches only projects with a live build on the node (§3).
- testing — the criteria of §6 and the arm in §7.
- migration — none: the keys are additive and unknown keys are skipped by every reader.
- user docs — `help/runtime.md` (S6).

## 6. Acceptance criteria

Each case runs `python beat.py fixture --case <name>` from the runtime kit directory over a scratch
`GOV_NODE_HOME` holding a planted profile and ledgers.

- **AC1** — When `--case render` plants capacity 6, two projects' reservations of 3 and 1 slots and a
  pool `personal` with no reading, `python beat.py render` prints `node-capacity: 6`,
  `node-free-slots: 2` and `node-plan: claude-code · unknown · none · - · personal`, and no line names
  either project.
  Red when: a project's name, build or act appears in the output.
- **AC2** — When `--case load` runs two renders a second apart on this node, the second prints a
  `node-load` between 0 and 1 and `node-load-source: system-times` on Windows or `loadavg` elsewhere,
  and the first prints `node-load: -` with no `[load]` sample planted.
  figure: DERIVED, the load is read at observation time.
  Red when: a render spawns a subprocess, as the fixture's patched `subprocess.Popen` counts, or the
  first beat prints a number with no sample.
- **AC3** — When `--case foreign-build` plants a plan-ledger pool named for another project's build,
  `fy-TOOL-fy-1`, with a hold ahead, `python beat.py render` prints `beat — refused · node-hold · not
  a node value`, and the record the fixture's beat writes carries no `node-` line.
  Red when: the planted beat is written naming `fy`.
- **AC4** — When `--case wired` runs `unattended.sh --beat fx` in a scratch clone with a live run, the
  record on the remote's lease ref carries the seven node keys after `beat-utc`, and a non-beat write
  of the same record carries none.
  fixture: needs TOOL-dPlacedRequest-1's lease record and TOOL-dWellOiledMachine-58's door, specced
  and unbuilt at this base.
  Red when: a beat writes no node line, or a release or tombstone carries one.
- **AC5** — When `--case members` plants two leases, one beating now and one whose last beat is past
  `leases.expiry-hours`, `python beat.py members` prints one line, the live node's tag.
  Red when: the stale node is printed, or the live one is missing.
- **AC6** — When `grep -n "node-free-slots" runtime.md` runs over the runtime help page, it names the
  seven keys and `beat.py members`.
  Red when: a key or the verb is missing.

## 8. Open questions

- **FACT-QUESTION · F1 — Can a Windows node read its hardware load with the standard library?**
  Scout D found `os.getloadavg` POSIX-only and read no Windows source. The probe:
  `python -c "import os, ctypes; print(hasattr(os, 'getloadavg')); print(ctypes.windll.kernel32.GetSystemTimes)"`,
  then two `GetSystemTimes` samples a second apart on this node. It decides the fork: a nonzero
  return and a busy fraction between 0 and 1 mean `ctypes` reads it; a missing `GetSystemTimes` or a
  zero return mean no standard-library reading exists and the beat publishes `-` on Windows.
  Liveness: the probe's first line reads `False` on this node, a negative it produced, and a zero
  return would be the second. Run 2026-10-26 on node a, Python 3.15.2 on win32: `getloadavg` absent,
  `GetSystemTimes` returned 1, busy 0.248 over one second. RESOLVED (agent, 2026-10-26, delegated):
  `ctypes` and `GetSystemTimes` on Windows, `os.getloadavg` elsewhere, both standard library, rung 2.
  widens: none · relaxes: none
- **F2 — Where does the node beat travel?** Options: (a) as keys on the supervisor's lease beat;
