## 1. Goal

Promoted from the spec audit of this build, round 1
(`memory/builds/dWellOiledMachine/reviews/2026-10-27-review-TOOL-dWellOiledMachine-1-spec-audit.md`),
finding 3, item H2, at HIGH. TOOL-dWellOiledMachine-34 S7 replaces the stall sidecar
`<git-dir>/unattended/stall.<slug>.log` with a journal line holding only `session`, `slug` and
`error`, and its reader list leaves out `tools/runtime/supervise.py`, whose limit hold
(TOOL-dWellOiledMachine-6 S9) reads that sidecar for a session limit and its reset time. From unit 34
on the limit hold, the hold-ceiling hand-over that rests on it (TOOL-dWellOiledMachine-47) and the plan
reading at a limit (TOOL-dWellOiledMachine-53 S8) stop firing. This unit puts the reset on the journal
line and points every reader of the retired sidecar at the journal.

## 2. Scope (IN)

- **S1** — The line carries the reset. `tools/unattended/stall-recorder.js`, which
  TOOL-dWellOiledMachine-28 moves into `tools/runtime/` only later, at order 61, writes
  `journal.py write stall session=<id> slug=<slug> error=<class> reset=<utc|none>`. The value comes
  from `extractResetUtc(data)`, exported beside `extractErrorClass`: the payload field
  TOOL-dWellOiledMachine-6 S9's sidecar parser in `supervise.py` reads for the reset, moved into the
  recorder so one parser of the payload exists, rendered as a UTC instant in ISO 8601 basic form with a trailing `Z` (as `2026-10-27T09:00:00Z`), and
  `none` when the payload carries no reset. Observed by AC1.
- **S2** — The limit hold re-pointed. `supervise.py`'s limit hold reads the slug's last stall through
  `journal.py read --class stall --key slug=<slug> --last 1` (TOOL-dWellOiledMachine-34 S7) and takes
  `error` and `reset` from it; its sidecar parser is deleted. The plan reading at a limit
  (TOOL-dWellOiledMachine-53 S8), called from that hold, receives the same `reset`. Observed by AC2.
  **Readers:** by name: READER NOT IN TREE — the supervisor (TOOL-dWellOiledMachine-6 S9, the sidecar path
  and its parser) and the limits fixture (TOOL-dWellOiledMachine-47 S10, whose stub writes the sidecar
  line) are unbuilt at HEAD, each re-pointed in this unit. by value: `supervise.py`'s hold, which
  decides on `error` and `reset`, re-pointed above; TOOL-dWellOiledMachine-53 S8's
  `write_plan_reading`, which receives the reset from that hold.
- **S3** — The limits fixture's stub re-pointed. `tools/runtime/limits_fixture.py`'s stub `claude`
  plants a limit by running `stall-recorder.js` on a StopFailure payload, never by writing a sidecar
  line, so the fixture exercises the recorder and the hold together. Observed by AC3.
- **S4** — No reader of the sidecar is left: `git grep -n "stall\.<slug>\.log\|'stall', l.slug\|deriveSidecarPath(.*'stall'"`
  over `tools/` prints nothing outside a retirement note. Observed by AC4.

## 4. Design

### Evidence

- The recorder writes the whole payload into the sidecar line,
  `` `${renderUtc()} ${sessionId} ${cls} ${JSON.stringify(data)}` `` (`tools/unattended/stall-recorder.js:74`),
  which is where any reset the payload carries lives today.
- TOOL-dWellOiledMachine-6 S9 reads that sidecar for "a session limit with a reset time"
  (`spec-6.md:104-108`); TOOL-dWellOiledMachine-53 S8 (`spec-53.md:87-90`) and the fixture of
  TOOL-dWellOiledMachine-47 S10 (`spec-47.md:91-96`) rest on it.
- TOOL-dWellOiledMachine-34 S7's readers name `stall-recorder.js`, the README and `unattended.sh`, and
  no `supervise.py` (`spec-34.md:73-81`).

### Files touched (estimate)

- `tools/unattended/stall-recorder.js`
- `tools/runtime/supervise.py`
- `tools/runtime/limits_fixture.py`

### Alternatives rejected

- **The journal line carrying the whole payload.** A JSON value breaks the grammar's one-token
  `key=value` fields and would carry the prompt-adjacent text the sidecar never needed to publish.

## 5. Production-readiness checklist

- security — the line carries a class and an instant, never payload text.
- perf / scale — one journal read per beat that finds a stall, bounded by `--last 1`.
- error / empty / loading states — `reset=none` with a limit class makes the hold wait for the next
  stall line rather than invent an instant, as the sidecar parser did on a payload with no reset.
- observability — the `limit-hold` journal line names the reset it holds to.
- risks — a payload field renamed by the harness reads `reset=none` everywhere at once, which AC1's
  planted payload pins to today's field.
- testing — AC1 to AC4 and the arms in §7.
- migration — none: the sidecar is already retired by TOOL-dWellOiledMachine-34.
- user docs — none: no verb or key a user types changes.

## 6. Acceptance criteria

- **AC1** — When `node stall-recorder.js` gets a planted StopFailure limit payload
  with its reset an hour ahead, `journal.py read --class stall
  --last 1` prints one line carrying `reset=` that instant; on a payload with no reset it carries
  `reset=none`.
  Red when: the reset is dropped from the line.
- **AC2** — When `python supervise.py --fixture --plant limit` plants the stall through
  `stall-recorder.js` with a reset an hour ahead, the beat journals `limit-hold` naming that reset and
  launches nothing.
  Red when: the hold reads no stall, as a hold still parsing the retired sidecar does.
- **AC3** — When `python limits_fixture.py --case hold-ceiling` runs, its stub plants the limit through
  `stall-recorder.js`, and the fixture still reaches the hand-over line `hand-over — fx`.
  Red when: the fixture plants a sidecar line the supervisor no longer reads.
- **AC4** — When `git grep -n "deriveSidecarPath(repo.gitDir, 'stall'" -- tools` runs after the unit,
  it prints nothing.
  Red when: a reader of the retired sidecar remains.
