## 1. Goal

The scheduler has one host today, the node tick an adopter registers by hand as `gov-resume-tick`,
and nothing names it as a host: `run.host` lists literal names (`tools/policy/catalogue.toml:537-540`)
that no registry backs, and a cadence item keyed by its period has no witness, so a node that wakes
late cannot tell that another already ran the period (gap-rt-15, gap-register:280). This unit
registers the host adapters at `point.host-adapters`, the OS scheduler first, and gives every cadence
period a witness on its lease ref that is read before the lease is taken and again after.

## 2. Scope (IN)

- **S1** — The point (I4): the `[[point]]` row `name = "point.host-adapters"` in
  `tools/runtime/points.toml`, `purpose` "where the supervisor and its sessions run" (layer-runtime
  `[extend]`), `contract` this spec's S2 and S3. Observed by AC1.
- **S2** — The two host adapter rows, `[[adapter]]` with `point = "point.host-adapters"`:
  `os-scheduler` and `requesting-node`, both the node tick (layer-runtime `[schedule]`, "os-scheduler
  and requesting-node are the node tick"). Each carries `tick = "gov-resume-tick"`, the task name the
  tick is registered under (`tools/unattended/README.md:224-232`); `remote-time`, how a node reads the
  remote host's clock through this adapter, one of the closed list `REMOTE_TIME_READERS` in
  `tools/runtime/hosts.py`, `http-date` or `none`, both rows `http-date`; `grant = { service = "local",
  scopes = [], secret = "anonymous" }`; and `tenancy`, `retention` and `region` as I4 spells them.
  Observed by AC1.
- **S3** — The row check, `check_host_row(row)` in `hosts.py`: it refuses a host row with no `tick`, a
  `remote-time` outside `REMOTE_TIME_READERS`, and any string field in which `scan_secrets` finds a
  span, so a host whose URL or command carries a credential is refused at registration. `python
  hosts.py --check` runs it, and TOOL-dWellOiledMachine-17's `check_adapter_grant`, over every host
  row, exit 1 on a refusal naming the row. Observed by AC2.
- **S4** — Readiness: `python hosts.py ready <name>` asks the one tick probe, `read_tick_registration`
  (`tools/unattended/lib-unattended.sh:674-686`), through `bash`, and prints `host — <name> · ready`
  (exit 0), `host — <name> · not registered` (exit 1) or `host — <name> · could not ask · <TR_WHY>` (exit
  2). It never reads "could not ask" as either answer. A name with no row exits 2 naming the registry.
  Observed by AC3.
- **S5** — The period key, `derive_period(kind, at)` in `tools/runtime/cadence.py`: `weekly` gives the
  ISO week, `2026-W44`, through `date.isocalendar()`, `daily` the ISO date, `2026-10-26`, both of the
  UTC instant `at` (layer-runtime `[schedule]`, "ISO week or date"). The key is the `<period>` segment of
  `refs/gov/leases/run/<cadence>/<period>` (TOOL-dPlacedRequest-1 S1, TOOL-dPlacedRequest-18 S1).
  Observed by AC4.
- **S6** — The per-period witness, `run_cadence_period(cadence, period, argv)` in `cadence.py`, run as
  `python cadence.py run <cadence> --period <key> -- <argv>`. The witness is the lease record on
  `refs/gov/leases/run/<cadence>/<period>` whose status reads `landed`. In order: (1) read the lease
  through `unattended.sh --claims`; a `landed` record prints `cadence — <cadence> <period> ·
  witnessed by <fleet-tag>` and runs nothing; (2) take it with `unattended.sh --lease acquire run
  <cadence> <period>` (TOOL-dPlacedRequest-1 S5); a refusal or a lost compare-and-swap prints
  `cadence — <cadence> <period> · held by <holder>` and runs nothing; (3) read again: when the record
  the take parented on reads `landed`, a witness appeared between the read and the take, so it
  releases `--as landed`, keeping the witness, and runs nothing; (4) run `argv`; (5) on exit 0 release
  `--as landed`, the period's witness; on any other exit release with no `--as`, a hand-over, so the
  next wake runs the period again. Observed by AC5, AC6 and AC7.
- **S7** — `help/runtime.md` gains a section on host adapters, `hosts.py ready` and the cadence witness
  lines. Observed by AC8.

## 4. Design

### Evidence

- The tick probe asks `schtasks //query //tn gov-resume-tick` under MSYS and the crontab listing
  elsewhere, and returns 0, 1 or 2 with `TR_WHY` (`tools/unattended/lib-unattended.sh:674-686`).
- `run.host` admits `requesting-node`, `os-scheduler` and `cloud-routine` and names "another registered
  host" as a registry no reader consults (`tools/policy/catalogue.toml:537-540`,
  `tools/policy/policy.py:155-159`).
- The run lease's grammar is `refs/gov/leases/run/<cadence>/<period>`, any tag-grammar cadence
  (TOOL-dPlacedRequest-1 S1, TOOL-dPlacedRequest-18 S1), and a cadence run lease keeps today's terminal
  take rather than reading as a tombstone (TOOL-dPlacedRequest-16 S3), so the witness must be read
  before the take: the lease verbs alone would take a `landed` period and run it again.
- The only heartbeat audit is per slug, not per period (`print_task_audit`,
  `tools/unattended/unattended.sh:8520-8573`).

### The witness run

```
read lease run/<c>/<p> ── landed ──▶ witnessed, run nothing
        │ none, released or stale
acquire (CAS, epoch+1) ── refused or lost ──▶ held, run nothing
        │ taken
parent landed? ── yes ──▶ release --as landed, run nothing
        │ no
run argv ── exit 0 ──▶ release --as landed      (the period's witness)
        └── else ────▶ release                  (hand-over; the next wake runs it)
```

Two supervisors released together on one period: the compare-and-swap lets one take; the other's step
2 loses, or its step 3 finds the landed parent. One run, one witness.

### Alternatives rejected

- **A separate witness ref beside the lease.** It doubles the writes and needs its own compare-and-swap;
  the lease's terminal record already says the period ran, at the epoch the take fenced.
- **Reading a `landed` cadence lease as a tombstone.** TOOL-dPlacedRequest-16 S3 keeps the terminal
  take for run leases on purpose; S6 reads the witness instead of changing a parent's rule.
- **Week numbers through `strftime("%U")`.** It counts Sunday weeks from 00; the design names ISO
  weeks.

## 5. Production-readiness checklist

- security — host rows are scanned for credential shapes at registration (S3); rows are `anonymous`.
- perf / scale — one lease read, one compare-and-swap and one release per period per node.
- error / empty / loading states — "could not ask" is its own exit; a run that fails hands the period
  over rather than witnessing it.
- observability — each outcome prints one `cadence —` or `host —` line naming the period and holder.
- risks — the period is read on this node's clock, so two nodes skewed across a period boundary may
  key one wake to two periods; TOOL-dWellOiledMachine-15's offset narrows it, and the witness keeps
  either period to one run.
- testing — the arms in §7, the cadence cases over two fixture clones of one bare remote.
- migration — none.
- user docs — `help/runtime.md`, S7.
