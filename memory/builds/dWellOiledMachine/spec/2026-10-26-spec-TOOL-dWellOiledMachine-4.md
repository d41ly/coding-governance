## 1. Goal

The intake record is the mandate to land, yet no prompt-submit event is wired, nothing scopes the
hook to the owner's sessions, and nothing notices when it crashes or never fires (gap-rt-14; probe:
`git grep -i "UserPromptSubmit\|prompt-submit"` over `tools`, `skills` and `.claude` finds nothing at
this base). Until it lands, `--request` trusts its caller that a file is the owner's words
(TOOL-dPlacedRequest-19 §3). This unit is `entry.intake`'s hook (PM-9): a pack on the dispatcher's
`UserPromptSubmit` entry that writes each owner prompt verbatim, its secrets redacted and its size
capped, into the intake record (I27) beside the request's local text, and refuses the prompt rather
than lose it when it cannot write.

## 2. Scope (IN)

- **S1** — The record (I27), node-local under `<git-common-dir>/requests/`, the directory
  TOOL-dPlacedRequest-19 S2 already keeps per content key, and never committed: `<key>.md`, the
  prompt's text, and `<key>.intake`, the receipts, one line per receipt, `origin=<origin>
  session=<id> received-utc=<utc> redacted=<n> bytes=<n> capped=<yes|no>`. `<key>` is
  `derive_request_content_key(text)` (TOOL-dPlacedRequest-19 S1) over the prompt as typed, reached
  through `resolve_kit_dir` from the loop kit, so a prompt and a later `--request` of the same words
  key alike. The `.md` is written once, the first copy kept as `--request` keeps it; a prompt typed
  again appends a receipt. I27's fields are refined here, as its owner: the record is the two files,
  and `redacted`, `bytes` and `capped` sit on the receipt. Observed by AC1.
- **S2** — The writer, `write_intake(text, origin, fields, root=None)` in `tools/runtime/intake.py`,
  the one write path of the record: it renders the text through `render_redacted` (I12, in
  `tools/runtime/redaction.py`, TOOL-dWellOiledMachine-16 S2) and counts the spans `scan_secrets`
  found as `redacted`; it cuts the result to `INTAKE_CAP_BYTES` (65536) at a UTF-8 boundary, setting
  `capped=yes` and `bytes` to the prompt's own length; it writes through a temp file and
  `os.replace`, and appends the receipt with one write. An empty prompt writes nothing. The origin
  this unit writes is `hook`. Observed by AC1, AC2, AC3.
- **S3** — The reader, `read_intake(key, root=None)`, returning the text and the parsed receipts, or
  None for a key with no record; `python intake.py show <key>` prints them, exit 0, or `intake —
  <key> · none`, exit 1; `python intake.py log --session <id>` prints that session's receipts, the
  session's intake log. Observed by AC1.
- **S4** — The owner's sessions only. The hook reads the session's binding
  (`<git-common-dir>/gov/session-bindings/<id>.md`, I17, TOOL-dWellOiledMachine-12 S1) through
  `session_binding.py read <id>`: `owner: yes` writes; an act's binding writes nothing, since an act
  session's prompt is its work order, never the owner's words; no binding writes nothing and prints
  `intake — not written · no session binding for <id>`, exit 0. Observed by AC4.
- **S5** — The pack, `tools/runtime/intake.fragment.json` (I9): event `UserPromptSubmit`, matcher
  `*`, `owner` `dWellOiledMachine`, `class` `record`, `failure` `closed`, `budget-ms` 5000, `key`
  `none`, run as `intake.py hook` through `tools/runtime/pyrun.sh`, the Python pack shim
  TOOL-dWellOiledMachine-8 S3 ships, the payload's `session_id` and `prompt` on stdin. Under
  `runtime.hook-failure` `closed`,
  the dispatcher refuses a prompt whose pack fails (TOOL-dWellOiledMachine-10 S6), so an intake that
  cannot be written is a refused prompt the owner sees, never a mandate silently lost. The payload's
  field names are the harness's hook reference, UNVERIFIED at this base, since no hook in the tree
  reads a `UserPromptSubmit` payload; the claude-code adapter's `prompt-submit` row is the measured
  fact the build pass records. Observed by AC5.
- **S6** — The kind's registry row: `[[record-kind]]` `intake` in
  `tools/memory-tree/record-kinds.toml` (TOOL-dTotalRecall-1), `tag = "record.intake"`, `layer =
  "runtime"`, `home = ""`, `id-rule = "<content key>.md and <content key>.intake under
  <git-common-dir>/requests/"`, `schema = { form = "rows" }`, `writer = "intake.py"`, `check =
  "runtime selftest"`. And the item: `item.entry.intake`'s witness is the receipt this pack writes,
  named in the pack's `witness` field as `{"record": "requests/<key>.intake", "reader":
  "intake.py show"}`. Observed by AC6.
- **S7** — The page `help/runtime.md` gains the intake record, its two files, the cap, the owner
  scoping and what a failing pack does to the prompt. Observed by AC7.

## 3. Non-goals (OUT)

- Intake from the mailbox or a cadence filer, and which origins ratify: TOOL-dWellOiledMachine-27.
- Plan's ratification and the placement dispositions read from the record: TOOL-dWellOiledMachine-5.
- Publishing the text: TOOL-dWellOiledMachine-57's `--request-publish`, which digests the `.md`
  this unit writes as `intake-sha`.
- A harness without the event: the fallback stays in force for it (TOOL-dWellOiledMachine-5).
- Byte-identity with `--request` for a redacted or capped prompt: such a prompt's `.md` differs from
  the typed words, so a later `--request` of them meets TOOL-dPlacedRequest-30's collision refusal,
  which names the stored copy; a secret is not stored to make the bytes agree.

## 4. Design

### The record

```
<git-common-dir>/requests/3f2a9c01b4de.md        the prompt, redacted and capped, written once
<git-common-dir>/requests/3f2a9c01b4de.intake    one receipt per arrival:
origin=hook session=6c1e…-… received-utc=2026-10-26T21:00:00Z redacted=0 bytes=412 capped=no
<git-common-dir>/requests/3f2a9c01b4de.typed     TOOL-dPlacedRequest-19's, untouched by this unit
```

### The hook

```
UserPromptSubmit -> dispatch.js -> pyrun.sh intake.py hook
  binding = session_binding.py read <session_id>
  none            -> "intake — not written · no session binding for <id>", exit 0
  owner != yes    -> exit 0, nothing written
  key = derive_request_content_key(prompt); empty -> exit 0
  write_intake(prompt, "hook", {session}) ; any error -> exit 2, the dispatcher refuses the prompt
```

| Minted | Kind | Lexicon cell |

| `INTAKE_CAP_BYTES` | constant | none |
| `hook`, `show`, `log` | `intake.py` verbs | none |
| `intake` | hook pack `hook.intake`, record kind row | none |

### Alternatives rejected

- **One log file per session.** The request's text already has one home per content key
  (TOOL-dPlacedRequest-19 S2), and `--request`, placement and publishing all key by it; a second home
  keyed by session would be the same words twice. The session's view is `intake.py log`.
- **Fields in the `.md`'s head.** `--request` compares the stored copy's bytes with the file it is
  given (TOOL-dPlacedRequest-30 S1), and TOOL-dWellOiledMachine-57 digests those bytes; a header
  would make every request a collision and every digest disagree with the words.
- **A `warn` pack failing open.** The record is the mandate; a prompt whose intake was lost would
  look ratified to nobody and be refused at Plan's exit with no trace of why.

## 5. Production-readiness checklist

- security — a new stored-content class: the text is redacted at the write boundary, once, through
  I12, capped after the transform, and kept node-local, never pushed; the hook writes only for an
  owner-bound session.
- perf / scale — one subprocess for the binding, one hash and one append per prompt, under 5 s.
- error / empty / loading states — an empty prompt writes nothing; no binding writes nothing and
  says so; a write error refuses the prompt.
- observability — the receipt line, `intake.py show` and `log`, and the dispatcher's refusal.
- risks — a redacted or capped prompt's later `--request` collides (§3).
- testing — the criteria of §6 and the arm in §7.
- migration — none: the record is new and `requests/` already exists where requests were recorded.
- user docs — `help/runtime.md` (S7).

## 6. Acceptance criteria

Each case runs `python intake.py fixture --case <name>` from the runtime kit directory in a scratch
repository with a planted session binding, feeding the pack the payload the case names.

- **AC1** — When `--case owner` submits the prompt `please land dFoo` from a binding reading `owner:
  yes`, the record's `.md` file holds those bytes, `<key>` is `derive_request_content_key` of them, and
  `python intake.py show <key>` prints one receipt `origin=hook` with `redacted=0` and `capped=no`;
  submitting it again adds a second receipt and leaves the `.md` unchanged.
  Red when: the text is altered, the key differs, or a repeat rewrites the `.md`.
- **AC2** — When `--case secret` submits a prompt carrying a token of a class `scan_secrets` flags,
  the `.md` carries the redaction placeholder in its place, never the token, and the receipt reads
  `redacted=1`.
  Red when: the token's bytes appear anywhere under `requests/`.
- **AC3** — When `--case oversize` submits 70000 bytes, the `.md` is 65536 bytes or fewer, ends on a
  whole UTF-8 character, and the receipt reads `bytes=70000 capped=yes`.
  Red when: the stored text exceeds the cap, or splits a character.
- **AC4** — When `--case act` submits from a binding whose `owner` is an act id, nothing is written,
  and `--case unbound` prints `intake — not written · no session binding` and writes nothing.
  Red when: an act session's prompt is recorded as the owner's.
- **AC5** — When `--case unwritable` makes `requests/` read-only and runs the pack through the
  dispatcher under `runtime.hook-failure` `closed`, the prompt is refused with `BLOCKED by dispatch:
  pack intake failed`.
  fixture: needs TOOL-dWellOiledMachine-10's dispatcher, specced and unbuilt at this base.
  Red when: the prompt passes with no receipt written.
- **AC6** — When `grep -n -A3 'name = "intake"' record-kinds.toml` runs over the registry, it prints
  the row with `writer = "intake.py"`, and `grep -c '"witness"' intake.fragment.json` prints 1.
  Red when: the kind has no row, or the pack declares no witness.
- **AC7** — When `grep -n "INTAKE_CAP_BYTES\|65536" runtime.md` runs over the runtime help page, it
  names the cap, and the page names the owner scoping and the refused prompt.
  Red when: the page omits the cap or the failure behaviour.
