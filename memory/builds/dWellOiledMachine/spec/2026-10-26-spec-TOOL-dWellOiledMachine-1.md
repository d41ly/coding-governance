## 1. Goal

Nothing on this platform has measured whether a role-typed Workflow agent run inside a headless
act session fires SubagentStart and SubagentStop, persists its return, and hands it back as the
session's `structured_output`, nor how long a PreToolUse entry may hold a call (layer-runtime
`[tests]` `spike`, LR:1089-1100). This unit is that spike, the build's first artifact: it founds the
runtime kit (I1), extracts the one act launcher `launch_act` (I2) at its second instance, records
each measured fact as a capability row the in-flight ledger and the admission queue arm on, and
sets `runtime.spawn-backend`'s default for single-agent acts from the cheaper feasible backend,
the key `launch_act` reads at each act's launch (v2:1208, the clause's "the answers' review").

## 2. Scope (IN)

- **S1** — The runtime kit (I1). `tools/runtime/` with `kit.toml` (`id = "runtime"`,
  `home = "runtime"`, `scope = "repo"`, `version_from` the `KIT_RUNTIME_VERSION` line of
  `launch.py`, `requires = ["policy"]`, every file `engine` but `selftest.py` and `fixtures/`,
  which are `project-owned` as the runlog descriptor withholds its suite), `README.md` carrying the
  `gov:kit runtime@<version>` marker, `adopt-runtime.sh` with `--scaffold` (writes nothing, reports
  the kit wired) and `--check` (exit 2 naming the sibling when `policy.py` does not resolve through
  the inlined `resolve_kit_dir`), and an `[[entry]]` `id = "runtime"` in
  `tools/govkit/registry.toml`. Observed by AC8.
- **S2** — The act launcher (I2). `launch_act(item, work_order, harness, env)` in
  `tools/runtime/launch.py` returns `(argv, env, backend)` and starts nothing. `item` is the loop
  item's tag; `work_order` a mapping carrying `role`, `fan` (default 1), `schema` (a JSON Schema
  object) and `text`, and `script` for a Workflow act. dBoundRoles' work order renders `item`,
  `inputs`, `allowance`, `return` and `witness` alone (TOOL-dBoundRoles-3, br3:48-61), so `fan` is the
  act's stage row's, read through the verb TOOL-dWellOiledMachine-43 §8 F3 asks for, beside the `cap`
  TOOL-dWellOiledMachine-9 S5 reads the same way, and `script` comes from TOOL-dWellOiledMachine-7 §8
  F5's pick; `harness` an adapter name, `claude-code`
  the only one this unit launches, any other refused; `env` the caller's environment, returned as
  a copy. The argv is `claude -p <text> --output-format json --json-schema <schema JSON>`, plus
  `--agent <role>` under the `headless` backend, and never carries
  `--dangerously-skip-permissions` or `--permission-mode bypassPermissions`. Its argv core is
  `build_headless_argv(prompt, output_format, schema=None, agent=None)` beside it, the factory
  S7's second caller uses. Observed by AC5.
- **S3** — The key read at each act's launch. `launch_act` reads `runtime.spawn-backend` for an
  act whose `fan` is 1 by running `<sys.executable> <policy kit>/policy.py get
  runtime.spawn-backend` as a bounded subprocess in the repository, the policy kit found through
  the inlined `resolve_kit_dir` block, since a kit imports no sibling kit (PLAY-dOrderedCharter-7,
  oc7:202-205, :379-380). `in-session` builds the Workflow form: the text names `script` and its args, and the
  role-typed `agent()` runs inside the act session. `headless` builds the `--agent <role>` form.
  An act whose `fan` exceeds 1 is `in-session` under every value, since a fan's harness script
  lives in a Workflow (layer-runtime `[spawn]`). A value the catalogue row refuses makes `get`
  exit 2 with the refusal on stderr (`cmd_get`, `tools/policy/policy.py:1332-1355`), and the
  launch is refused with `launch — refused · runtime.spawn-backend <value> · <reason>`, the reason
  being `get`'s stderr line; no policy kit found refuses it the same way. Observed by AC6.
- **S4** — The spike, `tools/runtime/spike.py`, two arms over one decoder. `--live` builds a scratch
  repository under `%TEMP%/<short name>` from `tools/runtime/fixtures/spike/repo/` (a role

## 4. Design

### The launch

```
launch_act(item, work_order, harness, env)
  harness != "claude-code"                 -> refused · harness <h> has no launcher
  fan = work_order.get("fan", 1)
  backend = "in-session" if fan > 1 else `policy.py get runtime.spawn-backend`; exit 2 -> refused
  in-session -> build_headless_argv(<text naming script + args>, "json", schema)
  headless   -> build_headless_argv(text, "json", schema, agent=role)
  -> (argv, dict(env), backend)
```

`--agent <agent>`, `--json-schema <schema>` and `--output-format <format>` are in `claude --help` on
2.1.292, read 2026-10-26. `build_headless_argv` and `launch_act` name the argv; neither spawns. `launch.py argv` prints the
factory's argv for a caller in another kit, and spawns nothing either.

### A case directory

```
<case>/hooks.jsonl     one hook payload per line, as the capture hook received it
<case>/stream.jsonl    the act session's stream, where agent() resolved
<case>/result.json     the --output-format json result: structured_output, total_cost_usd
<case>/case.toml       name, backend, and what the case planted (kill, owner-stop, stalls, hold)
```

The decoder reads every case the same way under both arms, so the offline fixtures under
`tools/runtime/fixtures/spike/` are recorded case directories, and a planted red is one edited file.

### The cases the live arm triggers

| Case | Trigger | Row |
|---|---|---|
| workflow-agent | the act as written | `subagent-start`, `subagent-stop`, `return-byte-match`, `schema-return` |
| killed | the act's process tree killed after SubagentStart is captured | `subagent-stop-killed` |
| owner-stopped | none a program reaches: a headless session has no owner turn | `subagent-stop-owner-stopped`, `unmeasured` unless an owner runs the printed step |
