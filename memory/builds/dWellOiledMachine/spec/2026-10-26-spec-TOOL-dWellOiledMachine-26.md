## 1. Goal

Nothing tells an attending owner which step, item and role gov is about to take, or why: the
recommendation explains only a step's exit, and `notify.owner` only transitions and parks
(gap-orient-16, gap-register:147). The night pass fixes the announcement: before each act while
attended, and once when attendance begins, gov prints
`step — <build> · <step> · <item> · <role> · <why> · writes <set>`, rendered from `next` and the
item's declaration and never typed by a model
(`memory/builds/dClosedLoop/build/2026-10-18-build-PLAY-dClosedLoop-1-night-pass.md:97-99`). This unit
defines the shape once in the charter's micro-format fence, renders it from the position engine's
answer and the loop definition, writes it before each act the supervisor runs while the attendance
value announces, and arms KICK-dKeptSession-17's `announce` member, a stand-in until now.

## 4. Design

### Evidence

### Alternatives rejected

- **A journal class for the announcement.** The journal is a node-local machine record with a closed
  grammar; the announcement is owner-facing text the client tails, so it keeps its own log, which also
  carries the attendance value S5 compares.
- **A typed format string in `step.py`.** A second definition beside the fence; S2 reads the fence.
- **Announcing only role acts.** The design's announcement precedes each act, and a command item the
  supervisor runs is one (layer-runtime `[terms]`, the actor kinds).

## 5. Production-readiness checklist

- security — the line carries tags, a role, the engine's reason and a write class, never a payload or a
  secret; the log is node-local.
- perf / scale — one fence read and one line per act while attended; nothing while unattended.
- error / empty / loading states — a fence with no `step` shape refuses with exit 2 and the act is
  still launched, the refusal printed, since an announcement never blocks work; a non-`act` answer
  prints the `next —` line.
- observability — the announce log is the record of what was announced and when attendance began.
- risks — an owner attending through a session that does not tail the log sees nothing until the
  client of TOOL-dWellOiledMachine-25 lands; the log still holds every line.
- testing — the fixture plants under §6 and the arm in §7.
- migration — none: the default `unattended` announces nothing.
- user docs — `help/runtime.md`.
