## 1. Goal

Promoted from the spec audit of this build, round 1
(`memory/builds/dWellOiledMachine/reviews/2026-10-27-review-TOOL-dWellOiledMachine-1-spec-audit.md`),
finding 64, item H15, at HIGH. TOOL-dWellOiledMachine-6 S2 starts a supervisor unless
`check_pid_alive` reads `yes`, without passing the image and start stamp S1 records, without handling
`unknown`, and with no exclusion between overlapping ticks. An `unknown` probe or two overlapping
scheduler ticks start a second supervisor on one epoch, which defeats S7's fence and launches a second
act on the item; a recycled pid reads `yes` and stalls the build. This unit makes the liveness read
exact, treats `unknown` as live, and lets exactly one tick start a supervisor.

## 2. Scope (IN)

- **S1** — The exact read. `run_supervisors` (`resume-tick.sh`, 6 S2) passes the pid file's recorded
  image and start stamp to `check_pid_alive <pid> <image> <stamp>`
  (`tools/unattended/lib-unattended.sh:661`), so a recycled pid reads `no`. Observed by AC2.
- **S2** — `unknown` is live. A read of `unknown` starts nothing and prints
  `supervisor — <slug> · liveness unknown · not started`, so a probe that cannot look never doubles a
  supervisor. Observed by AC3.
- **S3** — The exclusive start. Before it starts a supervisor, the tick claims
  `<git-common-dir>/gov/supervisors/<slug>.starting` with one `mkdir`, an atomic create, writing its
  own pid and UTC stamp inside. A tick that loses the `mkdir` prints
  `supervisor — <slug> · starting elsewhere` and starts nothing. The winner re-reads the pid file under
  its claim, starts nothing when it now reads `yes` or `unknown`, otherwise starts S1 of 6 through
  `run_detached`, waits up to `SUPERVISOR_BEAT_SECONDS` for the pid file to name the new pid, and
  removes its claim. Observed by AC1.
  **Readers:** by name: READER NOT IN TREE — the supervisor and its pid file are TOOL-dWellOiledMachine-6's, unbuilt at HEAD; `tools/unattended/resume-tick.sh` gains the claim. by value: NO VALUE READERS — the claim directory is read only by the ticks that race for it.
- **S4** — A claim left by a dead tick. A `.starting` directory whose recorded tick pid
  `check_pid_alive` reads `no` and whose stamp is older than two `SUPERVISOR_BEAT_SECONDS` is removed
  by renaming it to `<slug>.starting.stale.<own pid>` and deleting that, so of two ticks reaping one
  claim exactly one rename wins, and the tick retries the claim once. Observed by AC4.

  **Readers:** by name: `tools/unattended/resume-tick.sh`, the tick that reaps the claim. by value: NO VALUE READERS — the stale name is deleted by the tick that made it.
## 3. Non-goals (OUT)

- No change to the supervisor's own beat, fence or reconcile: 6 S1, S6 and S7 stand.
- No restart cap: TOOL-dWellOiledMachine-47's `runtime.restarts`.
- No lock in Python: the tick is bash, and `mkdir` is the turnstile's atomic claim.

## 4. Design

### Evidence

- `check_pid_alive <pid> [image] [not-after]` answers `no` for a pid held by another image or by a
  process started after the stamp, and `unknown` when the probe cannot look
  (`tools/unattended/lib-unattended.sh:645-669`).
- 6 S1 records pid, image and start stamp (`spec-6.md:30-36`); 6 S2 starts on anything but `yes` and
  passes neither (`spec-6.md:38-46`).
- `grep -n "lock\|overlap" tools/unattended/resume-tick.sh` names no tick lock at this base, and 6 adds
  none.

### Inventory

| Minted | Kind | Lexicon cell |
|---|---|---|
| `<slug>.starting` | directory claim under `gov/supervisors/` | none |
| `double-tick`, `unknown-probe`, `recycled-pid`, `stale-claim` | `supervise.py --fixture` plants | none |

### Files touched (estimate)

- `tools/unattended/resume-tick.sh` (or `tools/runtime/resume-tick.sh` once TOOL-dWellOiledMachine-28
  moves it): S1 to S4
- `tools/runtime/supervise.py`: the fixture plants

### Alternatives rejected

- **`locks.py hold_lock` per slug.** It waits, where a tick that loses should start nothing, and it
  needs a Python spawn on every tick for a claim bash makes with one `mkdir`.

## 5. Production-readiness checklist

- security — none beyond exactly one act session per item, which the fence relies on.
- perf / scale — one `mkdir` and one `rmdir` per start, none on a live supervisor.
- error / empty / loading states — S2 and S3 each print why nothing started.
- observability — every tick decision is one `supervisor —` line.
- risks — a persistently `unknown` probe starts no supervisor at all; the line repeats every tick, so
  the stall is visible.
- testing — AC1 to AC4 and the arm in §7.
- migration — none.
- user docs — `help/runtime.md`'s supervisor section names the claim.

## 6. Acceptance criteria

- **AC1** — When `python supervise.py --fixture --plant double-tick` starts two ticks together twenty
  times over one build lease with no supervisor running, every run ends with exactly one supervisor
  process and one `started` line.
  Red when: two supervisors run on one epoch.
- **AC2** — When `--plant recycled-pid` plants a pid file whose pid now belongs to another image, the
  tick reads `no` and starts one supervisor.
  Red when: the recycled pid reads `yes` and no supervisor starts.
- **AC3** — When `--plant unknown-probe` makes the image probe fail, the tick prints
  `liveness unknown · not started` and starts nothing.
  Red when: an `unknown` read starts a supervisor.
- **AC4** — When `--plant stale-claim` leaves a `.starting` directory from a dead tick older than two
  beats, the next tick removes it and starts one supervisor.
  Red when: a dead tick's claim blocks every later start.
