## 1. Goal

No harness declares a browser and nothing captures a visual witness: the atlas's visual check was
done by hand and recorded as prose, with no screenshot and no assertion a re-run could repeat
(gap-rt-23, gap-register:288; the testing record's row,
`memory/builds/dClosedLoop/build/2026-10-18-build-PLAY-dClosedLoop-1-research-testing-anywhere.md:17`,
cited below by its short name). This
unit adds the `visual.capture` command adapter, which serves the tree pinned at a SHA, busts the
browser's cache, takes each declared viewport, keeps each screenshot by hash only after the secret
scan, and returns the console and the DOM probe results; and a `browser` row in each harness
adapter's capability table, measured by running that adapter end to end inside an act session, never
claimed.

## 2. Scope (IN)

- **S1** — The adapter, `tools/runtime/visual_capture.py`, run as `python visual_capture.py run --sha
  <sha> --root <dir> --page <path>… --viewport <W>x<H>… [--probe <name>=<expression>…]`. In order:
  the tree at `<sha>` under `<root>` is extracted by `git archive` into a fresh scratch directory;
  served by the standard library's `ThreadingHTTPServer` on `127.0.0.1` at a free port; and opened,
  page by page and viewport by viewport, by the driver S2 names, each URL carrying `?v=<sha8>`. Its
  result, printed as one JSON object: `sha`, `browser` and its version, and per page and viewport the
  `screenshot` hash or `null`, `console` (each entry's `level` and `text`), `probes` (each probe's
  name and returned value) and `scan`. Exit 0 when every probe returned `true` and no console entry is
  an `error`; 1 when one did not or one is; 2 when the tree could not be served or the browser failed;
  3, printing `visual — unrunnable · no browser`, when S3 resolves none. Observed by AC1, AC3, AC6.
- **S2** — The driver, `tools/runtime/visual-capture.js`, on node's built-in `WebSocket` (node 22, the
  floor TOOL-dWellOiledMachine-36 §8 F1 declares): it starts the browser headless with
  `--remote-debugging-port=0` and a fresh `--user-data-dir`, reads the DevTools endpoint from its
  stderr, and over the DevTools protocol disables the cache (`Network.setCacheDisabled`), sets each
  viewport (`Emulation.setDeviceMetricsOverride`), navigates and waits for the load event, collects
  `Runtime.consoleAPICalled`, `Runtime.exceptionThrown` and `Log.entryAdded`, evaluates each probe
  with `Runtime.evaluate` by value, reads `document.body.innerText`, and captures the page
  (`Page.captureScreenshot`). It kills the browser's tree on every exit path. Observed by AC1, AC6.
- **S3** — The browser, `resolve_browser(row)`: `GOV_BROWSER` when set, else the first existing path
  of the adapter row's `browsers` list of globs, Chromium-family binaries such as Edge and Chrome.
  None found is S1's exit 3. Observed by AC3.
- **S4** — The scan, before anything is kept: each page's text and console text pass `scan_secrets`
  (TOOL-dWellOiledMachine-17, I12); a span found keeps no screenshot, writes `screenshot: null` and
  `scan: hit <class ids>`, and the PNG never leaves the scratch directory, which is cleared at exit. A clean capture is
  written once to `<git-common-dir>/gov/captures/<sha256>.png`, node-local and never committed, named
  by the SHA-256 of its bytes. Observed by AC2.
- **S5** — The registration: an `[[adapter]]` row at `point.command-adapters`
  (TOOL-dWellOiledMachine-6 S8) in `tools/runtime/points.toml`, `name = "visual.capture"`, `run =
  ["python", "visual_capture.py", "run"]`, `class = "idempotent"`, a re-run at one SHA reading the
  same tree and keeping a capture once by its hash, `browsers` the globs S3 reads, `tenancy = "local"`,
  `retention = "forever"`, `region = "local"` and `grant = { service = "local", scopes = [], secret =
  "anonymous" }`. Observed by AC4.
- **S6** — The `browser` row (I7's name, already in `CAPABILITY_NAMES`, TOOL-dWellOiledMachine-14
  S1): a `browser` case in the conformance fixture's derivation `derive_conformance_rows`
  (TOOL-dWellOiledMachine-36 S1, S3), whose act session runs S1 over the fixture page
  `tools/runtime/fixtures/visual/page/` and returns its result. The row is `yes` when the result holds
  all six abilities, in order `served`, `navigated`, `viewport`, `screenshot`, `console` and `probe`: a
  served page, a navigation, a set viewport, a screenshot hash, the page's planted console entry and a
  probe's value; `no · <first missing>` otherwise; `unmeasured` when the case did not run.
  The live arm writes it with `--write`; the offline arm derives it from a recorded case under
  `tools/runtime/fixtures/conformance/`. Observed by AC5.
- **S7** — The page `help/runtime.md` gains a section on visual capture: the command, its exit codes,
  where captures are kept, and what the `browser` row measures. Observed by AC7.

## 3. Non-goals (OUT)

- Installing a browser: gov installs none; S3 reads what the node has.

## 4. Design

### Evidence

- The atlas check was run by hand and recorded as prose; the browser pane refused a `file://` open of
  the 4 MB page and served a stale page after a regeneration until a query string was added
  (`memory/builds/dClosedLoop/build/2026-10-16-build-PLAY-dClosedLoop-1-atlas-instruments.md:18-21`).
  S1's HTTP serving and S2's cache bust answer those two observations.
- `git grep -i "playwright\|screenshot\|viewport"` finds no capture code (scout B's row).
- On node a at writing, `node --version` prints `v22.22.3` with a global `WebSocket`, and Edge and
  Chrome are installed at their default Windows paths (PINNED, 2026-10-26).

### The flow

```
visual_capture.py run --sha S --root R --page P --viewport WxH --probe n=expr
  git archive S R ─▶ scratch dir ─▶ ThreadingHTTPServer 127.0.0.1:0
  resolve_browser ─▶ none ─▶ exit 3 unrunnable
  node visual-capture.js ─▶ headless browser ─▶ per page × viewport:
       cache off · viewport · navigate ?v=<sha8> · console · probes · innerText · screenshot
  scan_secrets(text + console) ─▶ hit ─▶ screenshot null
                              └─ clean ─▶ <git-common-dir>/gov/captures/<sha256>.png
  JSON result ─▶ exit 0 | 1 | 2
```

### Alternatives rejected

- **The browser's headless command-line flags** (`--screenshot`, `--dump-dom`): they evaluate no probe
  and read the console only from log lines, so the witness the design asks, DOM and console
  assertions, cannot be taken; §8 F1.
- **A browser automation library.** A new external dependency for what the DevTools protocol and
  node's own `WebSocket` already give.
- **Keeping captures in the build folder.** A screenshot is a large binary a run regenerates; the design
  keeps it uncommitted, by hash (`research-testing-anywhere.md:144`).

## 5. Production-readiness checklist

- security — the server binds `127.0.0.1` only and serves the extracted pinned tree, never the
  checkout; a page whose text or console carries a token shape keeps no screenshot; the browser runs
  with a fresh profile and no credential.
- perf / scale — one browser per run, one navigation per page and viewport; the driver is bounded by
  `VISUAL_BOUND_SECONDS` per navigation and kills the browser past it.
- error / empty / loading states — no browser is exit 3, named; a page that never loads or a server
  that cannot bind is exit 2, named; an empty probe set returns no probes and judges console errors
  alone.
- observability — the JSON result is the record; the capture's hash names its file.
- risks — a Chromium-family flag can change between versions; the `browser` row is re-measured per
  harness binary by the conformance fixture, and S3 reads the browser's version into the result.
- testing — the live plants on a node with a browser, the offline plants on the recorded driver
  results, and the arm in §7.
- migration — none: a new adapter and a row whose name the table already admits.
- user docs — `help/runtime.md`.

`VISUAL_BOUND_SECONDS` is PINNED at 60 per navigation, the 4 MB atlas page loading in under ten on
node a (UNVERIFIED: measured by the build pass's first live plant, which records the figure).

## 6. Acceptance criteria

The fixture is `python visual_capture.py --fixture --plant <case>`: a scratch repository holding the
fixture page at two commits, its second changing a version marker the page writes into its body and
its console. A `--live` plant needs a Chromium-family browser on the node and reads it through S3; an
offline plant sets `GOV_VISUAL_DRIVER` to a stub that replays recorded driver results.

- **AC1** — When `--plant page --live` captures the page at its second commit at `1440x900` and
  `375x812` with the probe `fits=document.documentElement.scrollWidth <= window.innerWidth`, the result
  holds two distinct screenshot hashes, each file present under `captures/`, the page's planted console
  entry at both viewports, `fits` `true` at both, and the run exits 0.
  fixture: needs a browser; the tree holds none, so the build pass records the node and its version.
  Red when: the driver's viewport call is removed, so both captures hash the same.
- **AC2** — When `--plant token` replays a page whose text carries a planted token, the result reads
  `screenshot: null` and `scan: hit` with the class id, and no file is added under `captures/`.
  Red when: the screenshot is kept.
- **AC3** — When `--plant no-browser` sets `GOV_BROWSER` to a missing path and empties the row's
  `browsers`, the run prints `visual — unrunnable · no browser` and exits 3.
  Red when: it exits 0 or 2.
- **AC4** — When `python supervise.py --check-adapters` runs over the registry, the `visual.capture`
  row passes with `class` `idempotent`; with its `class` removed it is named and exits 1.
  Red when: a row with no class registers.
- **AC5** — When `python conformance.py run --replay <dir>` derives rows from the recorded claude-code
  case, `browser` reads `yes`; over a planted case whose act's shell call to the adapter was refused, it
  reads `no · served`; over a case that never ran, `unmeasured`.
  Red when: a refused case reads `yes`.
- **AC6** — When `--plant pinned --live` captures the first commit while the working tree holds the
  second, the probe reading the version marker returns the first commit's; when `--plant cache --live`
  captures the first commit and then the second in one browser profile, the second run's marker is the
  second commit's.
  Red when: the working tree is served, or the second run reads the first commit's marker from the
  cache.
- **AC7** — When `grep -n "visual.capture\|browser" runtime.md` runs over the help page, both are named.
  Red when: the page omits the command or the row.

## 10. Reuse audit

The seams extended are unit 6's command-adapter point and its `--check-adapters`, where the adapter
registers; unit 14's capability table and unit 36's `derive_conformance_rows`, where the `browser`
row is measured as every other row is, live and offline; and unit 17's `scan_secrets`, the one
scanner. The pinned tree comes from `git archive` and the server from the standard library, so no
serving code is written. `python tools/codebase-map/reuse_lookup.py "take a headless browser
screenshot of a served tree with console output"` ranked `tree`, `read_git_output`, `load_map_tree`
