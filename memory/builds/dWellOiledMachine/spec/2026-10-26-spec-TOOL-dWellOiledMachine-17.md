## 1. Goal

No adapter declares a grant and nothing scans what gov publishes for a secret: the lander's push rides
an ambient credential helper, and none of the bar's legs looks for a secret value (gap-rt-17,
gap-register:282). This unit gives every `[[adapter]]` row of the point registry a `grant` that
registration enforces, and binds a secret VALUE scan at the one boundary every gov publication crosses,
the pre-push hook, with runlog's SHAPE scan reporting beside it as `runtime.secret-scan:
value-gate+shape-report` says, seen on a planted token shape.

## 2. Scope (IN)

- **S1** — The grant field (I4's `grant`, this unit's half of I4). Every `[[adapter]]` row in
  `tools/runtime/points.toml` carries `grant = { service = "<name>", scopes = [<scope>…], secret =
  "<ref>" | "anonymous" }`. `check_adapter_grant(row)` in `tools/runtime/grants.py` returns the reason
  it refuses a row, or None: a row with no `grant`, an empty `service`, `scopes` that is not a list of
  non-empty strings, a `secret` that is neither `anonymous` nor a reference matching
  `[A-Za-z0-9][A-Za-z0-9_.-]*`, and a `secret` in which `scan_secrets` finds a span, which is a value
  written where a reference belongs. `python grants.py --check <points file>` applies it to every
  `[[adapter]]` row, prints one line per refused row naming its `point` and `name`, and exits 1 on
  any. Observed by AC1.
- **S2** — The scope probe at registration. A row whose `scopes` is non-empty declares `grant.probe`,
  an argv that prints the scopes the credential actually grants, one per line. `python grants.py
  register <point> <name>` runs S1's check, then the probe in its own process with the row's secret
  resolved into that process alone (S4), and refuses, exit 1, when a granted scope is absent from the
  declared `scopes` ("wider than declared"), naming that scope. A probe that cannot run, exits non-zero
  or prints nothing is a dead probe and refuses, never a pass. A row with `secret = "anonymous"` and
  no scopes registers with no probe. On success it prints `grant — <point> <name> · scopes <list>`.
  Observed by AC2.
- **S3** — `runtime.secret-scan` read (`policy-key.runtime.secret-scan`, catalogue
  `tools/policy/catalogue.toml:525-528`, owner dWellOiledMachine), through `resolve("runtime.secret-scan")`
  (I31, `tools/policy/policy.py:752`). `value-gate` runs S5's value scan alone; `value-gate+shape-report`,
  the default, runs it and S6's shape report beside it. Neither value turns the value scan off. Observed
  by AC5.
- **S4** — The secret resolver, `read_secret_ref(name)` in `tools/runtime/secret_scan.py`, the one
  reader of a secret by reference, where `runtime.secret-home` says (catalogue `:519-523`, read
  through `resolve`): `env-injected` reads `GOV_SECRET_<NAME>`, the variable the service manager hands
  the process; `os-keychain` reads the OS store, Credential Manager on Windows through the standard
  library's `ctypes` call `CredReadW` on the target `gov:<name>`, libsecret through `secret-tool lookup
  service gov name <name>` on a Linux desktop. It returns the value or None; it never writes the value
  to a file, an argument list, the environment of a child it starts, or any output. gov reads and
  copies no credential file. Observed by AC4.
- **S5** — The value scan, `scan_values(text, value)` in `secret_scan.py`: the count of occurrences of
  the value and of each of its encodings `derive_value_encodings(value)` builds — the raw value,
  standard and URL-safe base64 with and without padding, percent-encoding and lowercase hex. It runs
  in the process that resolved the value, once per adapter row whose `secret` is a reference, so the
  value never leaves that process. Observed by AC3.
- **S6** — The shape report: under `value-gate+shape-report`, `scan_secrets` (runlog's closed class
  list, `tools/runlog/runlog_lib.py:418-420,522`, which TOOL-dWellOiledMachine-16 moves verbatim into
  the core's `tools/runtime/redaction.py`) runs over the same population and prints one line per
  class it found, `secret-shape — <boundary> · <class id> <count>`. It refuses nothing: a shape scan
  alone reds on examples and fixtures (layer-expansions `[design-integrations]`). Observed by AC5.
- **S7** — The publishing boundary, `.githooks/pre-push`. Every gov publication leaves the node by `git
  push`: the lander's landing, a run branch pushed as `build.push` says, and every `refs/gov/*` object
  (claims today through `write_claim`, `tools/unattended/unattended.sh:2396-2430`, which names the
  remote so the tracked hook sees it). After the ref-update loop (`.githooks/pre-push:609-616`) and
  before any gate decision, the hook runs `python secret_scan.py publish` over `push_refs`, every
  update alike, and refuses the push, exit 1 with the refusal file's token `secret-value`, on a hit.
  `--decide` mode skips it: that mode runs no push. Observed by AC3, AC6 and AC7.
- **S8** — The population and the dead probe. For each ref update `<old>..<new>` (a new ref: the
  commits `git rev-list <new> --not --remotes=<remote>` reads), the population is each commit's
  message and every blob it adds or changes, `memory/` records included. The EXPECTED count comes
  from the ref update itself, `git rev-list --count` over the same range, never from the scanner's own
  enumerator. An unresolved value is a dead probe and refuses; a zero read against a non-zero expected
  count is a dead probe and refuses; an empty expected population reads `none carried`; a row with
  `secret = "anonymous"` reads `not applicable`, never zero (layer-runtime `[extend]`, revised
  2026-10-17). Observed by AC4 and AC6.
- **S9** — The witness, one line per adapter row and boundary: `secret-scan — <boundary> · <point>/<name>
  · value <yes|no|anonymous> · commits <read>/<expected> · blobs <n> · matches <m> · id <salted>`,
  where the match id is the first 12 hex of HMAC-SHA256 over the value under a salt drawn per run
  from `secrets.token_bytes` and never printed, so a witness names that a value matched and never which.
  Printed to stderr and kept in the hook's run log lines. Observed by AC3 and AC7.
- **S10** — `measure_legs.derive_redacted` (`tools/run-gates/measure_legs.py:531`) is declared, in a
  comment at its definition, a deliberate subset of `scan_secrets`: the url-userinfo class only, ported
  byte for byte to run-gates' shell `redact`, kept so a copy-installed bar carries no runlog import. It
  is not folded. NOT OBSERVED: a comment is read, not run.
- **S11** — `help/runtime.md` gains a section on grants, `runtime.secret-scan`, `runtime.secret-home`,
  the witness line and what a `secret-value` refusal asks the owner to do. Observed by AC8.

## 4. Design

### Evidence

- `scan_secrets(text, rules=None)` returns sorted `(start, end, rule_id)` spans over a closed class
  list of 19 ids, and `render_redacted` replaces each with `<redacted:<id>>`
  (`tools/runlog/runlog_lib.py:418-420,522,553`). It scans SHAPES; it holds no value.
- `check_value`'s `registry` arm admits only the literal members of `of` today and names the registry
  in its refusal (`tools/policy/policy.py:143-159`); unit 20 makes it read the point registry.
- The pre-push hook reads every pushed ref into `push_refs` before deciding anything
  (`.githooks/pre-push:609-616`), and a claim push names the remote so the hook sees it
  (`tools/unattended/unattended.sh:2369-2375`).
- No OS-store reader exists: `git grep -i "secret-tool\|CredRead\|keyring" -- tools skills` returns
  nothing (run 2026-10-26).

### The row

```toml
[[adapter]]
point = "point.notification-adapters"
name = "push-service"
grant = { service = "push.example", scopes = ["notify:send"], secret = "push-service-token",
          probe = ["python", "{kit}/push_probe.py", "--scopes"] }
```

### The publish run

```
pre-push ─ push_refs ─▶ secret_scan.py publish
             for each [[adapter]] row with a secret reference:
               child process: read_secret_ref → scan_values over each update's population
                              → one witness line, the value never leaving the child
             shape report (value-gate+shape-report): scan_secrets over the same population
             refuse on a match, an unresolved value, or a zero read against a non-zero expected count
```

The child is `python secret_scan.py scan --row <point>/<name> --population <scratch file>`, its
population file listing commit shas and blob ids, its environment the parent's minus every
`GOV_SECRET_*` but the one it resolves.

### Alternatives rejected

- **A second scanner beside `scan_secrets`.** The class list and its table would be stated twice; the
  shape half reuses runlog's.
- **Binding at `push-main.sh --prepare` alone.** A run-branch push and every `refs/gov/*` push would go
  unscanned; the hook is the one point every `git push` crosses.
- **Resolving the value in the hook's own bash.** The value would cross a shell variable and the
  hook's environment; one child per row keeps it in one process.
- **A shape scan that refuses.** It reds on examples and fixtures, which is why the design reports it.

## 5. Production-readiness checklist

- security — the value lives in one child process; the witness carries a per-run salted id and counts
  only; S2 refuses a probe it cannot run; the pre-push refusal is fail-closed.
- perf / scale — one `git cat-file --batch` read per update and a substring search per encoding; the
  shape scan is runlog's, hint-gated. A landing of a large range costs seconds beside its bar.
- error / empty / loading states — unresolved value and zero-against-expected are dead probes that
  refuse; `none carried` and `not applicable` are named states, never zero.
- observability — one witness line per row and boundary, kept in the pre-push run log.
- risks — an encoding outside S5's set passes; base64 embedded at another alignment inside a longer
  base64 run is not matched (`ponytail:` the ceiling, three-offset matching if a leak shows it).
- testing — the arms in §7, each planted case generated at run time from a template, never a literal
  credential in a committed file.
- migration — none.
- user docs — `help/runtime.md`, S11.

## 6. Acceptance criteria

- **AC1** — When `python grants.py --check` runs over a fixture registry holding a row with no
  `grant`, a row with `service = ""` and a row whose `secret` is a generated `ghp_`-shaped value, it
  prints three refusals naming each row and exits 1; over the same file with the three rows corrected
  it exits 0.
  Red when: a row with no `grant` passes.
- **AC2** — When `python grants.py register` runs on a fixture row declaring `scopes = ["repo:read"]`
  whose stub probe prints `repo:read` and `repo:write`, it exits 1 naming `repo:write`; with the probe
  printing `repo:read` alone it prints `grant —` and exits 0; with the probe exiting 3 it refuses as a
  dead probe.
  Red when: `check_adapter_grant` or the scope compare is stubbed to accept, and the wider grant
  registers.
- **AC3** — When the fixture remote receives a push through the tracked `.githooks/pre-push` under
  `runtime.secret-home = "env-injected"` with `GOV_SECRET_FIXTURE` set to a value generated per run,
  each of five plants refuses its push with token `secret-value` and a witness reading `matches 1`: the
  value in a tracked file, in a `memory/` record, in a commit message, base64-encoded in a file, and in
  a `refs/gov/runs/<slug>` commit message.
