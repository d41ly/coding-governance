## 1. Goal

Promoted from the spec audit of the round-1 promotions
(`memory/builds/dWellOiledMachine/reviews/2026-10-27-review-TOOL-dWellOiledMachine-63-spec-audit.md`),
finding 40, item H6, at HIGH. TOOL-dWellOiledMachine-33 S6 (order 21) stores the node salt under the
Windows target `gov-node-salt`, libsecret `service gov key node-salt` and the variable
`GOV_NODE_SALT`. TOOL-dWellOiledMachine-79 S7 (order 63) re-points `read_node_salt` at
`read_secret_ref("node_salt")`, which reads `gov:node_salt`, `name node_salt` and
`GOV_SECRET_NODE_SALT`, and creates a salt on first use. Its migration names only the environment
rename, and spec 33 takes no rev bump. On every node that ran between the two units the stored salt is
orphaned and a new one minted: every binding `digest:` and salted `Gov-Session` value written before
can no longer be re-derived, and 33 S7's `check_commit_keys` over a spanning range refuses valid
commits. This unit reads the old names when the new ones hold nothing, copies the value across once,
and proves a seeded old salt yields the same digest afterwards.

## 2. Scope (IN)

- **S1** — The fallback read. `read_node_salt` (`tools/runtime/commit_keys.py`) first calls
  `read_secret_ref("node_salt")`; when that finds nothing it reads the old name of the same home
  `runtime.secret-home` names: under `os-keychain`, the Windows target `gov-node-salt` or libsecret
  `service gov key node-salt`; under `env-injected`, the variable `GOV_NODE_SALT`. Observed by AC1,
  AC3.
- **S2** — The one-time copy. A salt found under an old name in a writable home is written under the
  new name through `write_secret_ref("node_salt", <salt>)` (79 S7) before it is returned, and the old
  entry is left in place, so a rollback to unit 33's reader still finds it. Under `env-injected`,
  where nothing is writable, the old variable is read on every call and the tool prints once per
  process `commit keys — node salt read from GOV_NODE_SALT; set GOV_SECRET_NODE_SALT`. Observed by
  AC1, AC2.
- **S3** — Creation only when both names are empty. 79 S7's first-use creation runs only after S1's
  fallback found nothing under either name. Observed by AC1.
- **S4** — Spec 33 corrected. TOOL-dWellOiledMachine-33 takes a rev bump at this unit's pass: its S6
  names the old store names as the ones S1 here migrates from, and its §9 line names this unit and
  finding 40, and its S6 gains the sentence "`read_node_salt` migrates these names to
  `read_secret_ref`'s at first read (TOOL-dWellOiledMachine-85)". Observed by AC4.
  **Readers:** by name: READER NOT IN TREE — `commit_keys.py` (`read_node_salt`), TOOL-dWellOiledMachine-33's, unbuilt
  at HEAD, the one reader of the old names, kept here as a fallback rather than retired. by value: `write_binding`'s caller, which passes
  the salt-derived digest (TOOL-dWellOiledMachine-39 S1), and `check_commit_keys` (33 S7), which
  re-derives it; both see the same salt before and after.

## 5. Production-readiness checklist

- security — the salt never leaves the credential store or the process environment; no file is
  written. The fixture runs under a scratch policy with `env-injected` and never touches the real
  keychain.
- perf / scale — one extra store read on the first call of a migrated node.
- error / empty / loading states — S3: creation only when both names are empty.
- observability — S2's one notice under `env-injected`.
- risks — a node holding different salts under both names keeps the new one; the old one is never
  consulted again once the new name reads.
- testing — AC1 to AC4 and the arm in §7.
- migration — S1, S2.
- user docs — none: the variable rename is already 79's §5 line.

## 6. Acceptance criteria

- **AC1** — When `python commit_keys.py --fixture --case seeded-old-salt`, under a scratch policy whose
  `runtime.secret-home` is a fixture store, seeds `ab` under the old name only and runs
  `commit_keys.py digest s1` twice, both digests equal the HMAC of `s1` under `ab`, and the store
  then holds `ab` under the new name.
  Red when: a new salt is minted and the digest changes.
- **AC2** — When `--case seeded-old-env` sets `GOV_NODE_SALT=ab` with `GOV_SECRET_NODE_SALT` unset under
  `runtime.secret-home = "env-injected"`, the digest is the HMAC under `ab` and the notice names
  `GOV_SECRET_NODE_SALT`.
  Red when: the old variable is ignored.
- **AC3** — When both names hold different salts, the digest `commit_keys.py --digest` prints is the one under the new name's salt.
  Red when: the old name wins over the new.
- **AC4** — When `grep -c "migrates these names" 2026-10-26-spec-TOOL-dWellOiledMachine-33.md` runs, it
  prints 1. Red when: spec 33 still describes the old names as the live store, as it does at this
  spec's base, where only its §3 edge names this unit.
