## 1. Goal

Nothing describes a node outside one repository: its hardware, its harnesses and their plans, and
the projects it serves with the owner's share of each live nowhere a node unit can read
(gap-rt-46). This unit gives the node one home outside every repository (I5) and one profile there
(I6): read whole by every node unit, an owner-held fact no preset and no repository sets, never
holding a credential, validated against its versioned schema at write and at read, and written only
through its guarded owner command, as the policy file is (v2 P40; cloud-and-scale item 18).

## 2. Scope (IN)

- **S1** — The node home (I5). `resolve_user_state_dir(override_var, name, env=None,
  platform=None)` and `resolve_node_home(env=None, platform=None)`, canonical in
  `tools/lib/node_home.py` between `# >>> node_home_py` and `# <<< node_home_py`, refactored out of
  `resolve_state_dir` (`tools/runlog/extract.py:201-229`): the override, refused when relative; else
  `LOCALAPPDATA` on Windows, `~/Library/Application Support` on macOS, `XDG_STATE_HOME` or
  `~/.local/state` elsewhere; then `name`. `resolve_node_home` is the call with `GOV_NODE_HOME` and
  `gov`. `extract.py` carries the block inline and its `resolve_state_dir` becomes the call with
  `RUNLOG_STATE_DIR` and `runlog`, its messages still naming the override, `LOCALAPPDATA`, `HOME`
  and `relative`, as runlog's own cases read them (`tools/runlog/selftest.py:2114-2133`);
  `tools/runtime/profile.py` carries it too, under a `node_home_py` row of
  `tools/lib/resolve-python.test.sh`'s `PARITY_ROWS`. The home holds `profile.toml` (this unit),
  `facts.toml` (TOOL-dWellOiledMachine-15) and `ledgers/` (TOOL-dWellOiledMachine-53).
  Observed by AC1.
- **S2** — The schema (I6), `check_profile(doc)` in `profile.py`, the one judge at write and at
  read: `schema` a string `<major>.<minor>` whose major is `PROFILE_SCHEMA_MAJOR`, 1; `fleet-tag`
  one lowercase letter, the fleet registry's tag shape (`tools/playbook/render_playbook.py:360`);
  `capacity`, the node's agent capacity, an integer of at least 1; `[hardware]` with `cpus` and
  `memory-gb`, integers of at least 1; `[[harness]]` rows with `name`, `plan-tier` and `pool`, each
  matching `[a-z0-9][a-z0-9-]*`, names unique; `[[project]]` rows with `name` matching
  `[A-Za-z0-9][A-Za-z0-9._-]*`, unique, and an optional `share`, an integer of at least 1. Any other
  key, at any level, is refused: the schema is closed, so a field that could carry a credential
  cannot be added. Every string value passes `scan_secrets` (TOOL-dWellOiledMachine-16's
  `tools/runtime/redaction.py`) with no span, a hit refused naming its class and never its value.
  Observed by AC3, AC4, AC5.
- **S3** — The read, `read_node_profile(home=None, repo=None)`, returning `(state, profile,
  reason)`: `absent` when the file does not exist, `read` with the validated profile, and `invalid`
  with the reason for a file that does not parse as TOML, fails `check_profile`, or names a newer
  major. It reads the file whole, once, and never substitutes a default for an invalid profile. A
  project with no `share` reads 1, so shares are equal unless the owner sets them. With `repo`, the
  profile's `fleet-tag` is compared with the tag `render_playbook.py --fleet-tag --user <u> --host
  <h>` answers in that repository (`resolve_fleet_tag`, TOOL-dPlacedRequest-1 S11), and a
  disagreement is `invalid` naming both; where the repository's fleet answers no tag, nothing is
  compared. `python profile.py show [--repo <root>]` prints the profile and exits 0, prints
  `profile — absent · <path>` and exits 1, or prints `profile — invalid · <path> · <reason>` and
  exits 2. Observed by AC2, AC3, AC6.
- **S4** — The guarded owner write, `python profile.py set <field> <value>`, over the fields
  `fleet-tag`, `capacity`, `hardware.cpus`, `hardware.memory-gb`, `harness.<name>.plan-tier`,
  `harness.<name>.pool` and `project.<name>.share`. A `set` on an absent harness or project row
  creates it; `set project.<name> equal` adds a project at the equal share; and
  `set harness.<name> absent` or `set project.<name> absent` takes that row out. Before anything
  is written: `check_terminal_proof` (TOOL-dDeclaredLoop-2 S5, the inline `guarded_write_py` block) must
  return a proof, so an agent's call, which holds no terminal, prints
  `profile — refused · the owner's terminal proof is absent` and the proposed document, writes
  nothing and exits 1; then the whole would-be document passes `check_profile`, a refusal naming the
  rule and writing nothing; then it is written through a temp file and `os.replace`, creating the
  home, and `profile — set · <field>` is printed. An invalid profile already on disk is refused
  before any `set`, since a partial edit of it cannot be judged. Observed by AC4, AC5.
- **S5** — The command's name. I6 spells it `gov profile set`; no `gov` front command exists at
  this base, so `profile.py` stands in for it as `gov_tag.py` stands in for `gov tag`
  (PLAY-dOrderedCharter-19 S6). NOT OBSERVED by a criterion: a name, and a front command routing to
  it is the one that lands it.

## 3. Non-goals (OUT)

- A direct file write by an agent's Write or shell tool to the node home, which bypasses the
  command: like the policy file's guard (`tools/policy/guard.py:18-23`, "it stops forgetting, not
  evasion"), S4 refuses an agent's use of the owner's command and S2 and S3 refuse what a bypass
  leaves malformed or credentialed. A hook refusing a write to the home's path is a hook pack, unit
  10's surface.
- Measuring hardware into the profile: the owner writes it; measured node facts are
  TOOL-dWellOiledMachine-15's `facts.toml`.
- A row for this kind in `tools/memory-tree/record-kinds.toml`: the record door writes repository
  records, and this one lives outside every repository (cloud-and-scale item 18).
- Validating `[[harness]]` names against the harness adapters: they land at TOOL-dWellOiledMachine-14,
  after this unit; the profile's name grammar matches theirs.
- What the readers do with the profile: the beat (52), admission (53) and discovery (54).

## 4. Design

### Data model

```toml
# <node home>/profile.toml
schema = "1.0"
fleet-tag = "d"
capacity = 6

[hardware]
cpus = 16
memory-gb = 32

[[harness]]
name = "claude-code"
plan-tier = "max"
pool = "personal"

[[project]]
name = "coding-governance"
share = 2

[[project]]
name = "another-repo"        # no share: equal, read as 1
```

### The write, in order

```
profile.py set F V
  check_terminal_proof() is None      -> refused · the owner's terminal proof is absent   (exit 1)
  on-disk profile invalid             -> refused · <reason>; fix the file at a terminal  (exit 2)
  doc' = apply(F, V); check_profile(doc') refuses  -> refused · <rule>                    (exit 2)
  write temp, os.replace              -> profile — set · F                                (exit 0)
```

`render_profile(doc)` writes the closed schema's keys in the order above; the stdlib reads TOML and
writes none, and a closed schema needs no general writer.

## 5. Production-readiness checklist

- security — owner-only writes through the terminal proof, a closed schema, and a secret scan at
  both ends; the reason for a credential refusal names the class, never the value.
- perf / scale — one small file read whole; S3's tag comparison is one subprocess, only with `repo`.
- error / empty / loading states — `absent`, `read` and `invalid` are three states, and `invalid`
  never degrades to defaults.
- observability — the `profile —` lines.
- risks — a direct file write bypasses the command (§3); S3 refuses what it leaves malformed.
- testing — the criteria of §6 and the arm in §7.
- migration — none (§4).
- user docs — `help/runtime.md` gains the profile: where it lives, its fields and `profile.py set`.

## 6. Acceptance criteria

Each command runs with `GOV_NODE_HOME` naming a scratch directory, from the runtime kit directory.

- **AC1** — When `resolve_node_home` runs under `{"GOV_NODE_HOME": "rel/x"}` it raises naming
  `relative`; under `{"LOCALAPPDATA": L}` on `win32` it returns `L/gov`; and the `node_home_py` row
  finds `extract.py`'s block byte-identical to the canonical.
  Red when: a relative override resolves, or a one-byte change to `extract.py`'s copy passes.
- **AC2** — When `python profile.py show` runs over the §4 profile, it exits 0 and reports
  `another-repo`'s share as 1; over no file it prints `profile — absent` and exits 1.
  Red when: an absent file exits 0, or the omitted share reads anything but 1.
- **AC3** — When `profile.py show` runs over each malformed profile — a TOML syntax error,
  `schema = "2.0"`, `capacity = "six"`, and an unknown key `token = "x"` — it prints
  `profile — invalid` naming the rule and exits 2.
  Red when: any of the four exits 0 or 1, or prints a default profile.
- **AC4** — When `profile.py set capacity 8` runs with standard error not a terminal, as an agent's
  call runs, it prints `profile — refused · the owner's terminal proof is absent`, exits 1, and the
  file's bytes are unchanged; with `check_terminal_proof` patched to return `tty-cli`, the same
  call writes `capacity = 8` and `show` exits 0.
  Red when: the call without a terminal changes the file.
- **AC5** — When `profile.py set harness.claude-code.pool` runs, under the patched proof, with a
  value `scan_secrets` classes as `sk-key`, it exits 2 naming `sk-key`, the file unchanged; and when
  that value is planted in the file by hand, `show` prints `profile — invalid` naming `sk-key`.
  Red when: the value is written, or the planted file reads `read`.
- **AC6** — When `profile.py show --repo <scratch>` runs over a profile with `fleet-tag = "d"` in a
  scratch repository whose fleet answers `a` for this user and host, it prints `profile — invalid`
  naming `d` and `a`.
  Red when: the disagreeing tags read `read`.
  fixture: needs TOOL-dPlacedRequest-1 S11's `--fleet-tag`, specced and unbuilt at this base.
