## 1. Goal

A session today is keyed only by its per-session card, no matcher covers `fork`, a resume missed its
card 7 times in 14 with the cause unknown, and a compaction re-injects the kickoff's card and leaves no
record (gap-orient-12, gap-orient-14, gap-orient-18, gap-rt-07). Every SessionStart source writes the
session binding (I17); the replay can no longer end with nothing delivered, and a miss is listed by
session; the compact hook re-injects the build's current card; a PreCompact hook checkpoints the work in
flight and journals the compaction with its session, build, item and trigger; the keep-list names what a
summary drops; and the card is held under the harness's re-attachment cap (night pass, point 5).

## 2. Scope (IN)

- **S1** — The record (I17), `<git-common-dir>/gov/session-bindings/<session id>.md`: a header of
  `key: value` lines `session`, `owner` (`yes`, or the act id), `build` (a slug or `none`), `act` (an act
  id or `none`), `node` (the fleet tag), `started-utc`, `after` (a session id or `none`), `source`,
  `transcript` and `bound-utc`, then any `## <name>` sections, kept byte for byte by every write that
  does not name them. `source`, `transcript` and `bound-utc` refine I17's proposed field list, which
  this unit owns. The session id is refused unless it matches `^[A-Za-z0-9][A-Za-z0-9._-]*$`, the
  card's rule (`skills/session-kickoff/manifest-check.sh:304`). Observed by AC1.
- **S2** — The one writer, `tools/runtime/session_binding.py`, with the verbs `bind` (the hook entry,
  the payload JSON on stdin), `set <sid> <key> <value>`, `put-section <sid> <name>` (the body on
  stdin), `path <sid>` and `read <sid>`. Every write holds `<sid>.lock` beside the record through
  `hold_lock(path, wait_s=2, stale_s=10)` in the new `tools/runtime/locks.py`, an exclusive create
  recording pid and start time as govkit's `take_write_lock` does (`tools/govkit/govkit.py:7409`), but
  waiting instead of refusing and breaking a lock older than `stale_s`; it replaces the record by a
  rename in its own directory, so two hooks of one SessionStart never lose each other's write.
  Observed by AC1, AC9.
- **S3** — Bound on every source. `bind` reads `session_id`, `source` and `transcript_path`; writes
  `started-utc` once and `source`, `transcript` and `bound-utc` on every call; sets `owner` and `act` to
  the act id when the launch environment carries `GOV_ACT=<act>`, else `owner: yes` and `act: none`;
  and on `resume` or `fork` sets `after` to the first `sessionId` the transcript's first line carries when
  it differs from this session's id. The pack `tools/runtime/session-binding.fragment.json` runs it on
  SessionStart with matcher `startup|resume|clear|compact|fork`, class `record`, failure `open` (I9).
  `skills/session-kickoff/orientation-replay.fragment.json` gains `fork` in its matcher, so an owner's
  forked session gets the replay; an act session (`owner` not `yes`) gets no card, its work order
  carrying every fact. Observed by AC1 and AC2.
- **S4** — The route names the build. `--card --append`, when the body it stores carries a `## route`
  with a `- build: <slug>` line, runs `session_binding.py set <sid> build <slug>`. Observed by AC5.
- **S5** — A replay that cannot end silent. `print_replay` (`manifest-check.sh:721`) and `write_card`
  (`:706`), run as a hook, never exit non-zero: an over-cap card, a session id refused by
  `read_session_id` (`:293`) or an unwritable home prints `card — not delivered · <reason>` and the
  `now —` line, exit 0, since a SessionStart hook's stdout reaches the session only on exit 0. The
  `--card --write` and `--card --replay` commands run by hand keep exit 2. Each replay and each write
  run as a hook records `delivered — <source> · <bytes> · <utc>` or `not delivered — <reason>` through
  `put-section <sid> delivery`. Observed by AC3.
- **S6** — Misses diagnosed. `python session_binding.py misses [--since <utc>]` prints one
  `card miss — <sid> · <source> · <bound-utc> · <why>` line per binding whose `source` is `resume`,
  `compact` or `fork`, `owner` is `yes`, and whose `## delivery` holds no line within 60 s of its
  `bound-utc` (`why` = `hook never ran`) or holds `not delivered` (`why` = its reason), then
  `card misses — <n>`, exit 0. Observed by AC4.
- **S7** — The build's current card at compact and resume. When the session card's `## route` names no
  build and the binding's `build` is not `none`, `print_replay` runs TOOL-dPlacedRequest-2 S6's
  `--card --lookup --build <slug>` for that build before printing, so the build card's current tail is
  what returns, never the session's startup card alone; with a route naming a build, S7 of that spec
  already runs the lookup. Observed by AC5.
- **S8** — The PreCompact flush. `python session_binding.py precompact`, run by
  `tools/runtime/precompact.fragment.json` on PreCompact (failure `open`), reads `session_id`,
  `transcript_path` and `trigger`; when the session's tree holds uncommitted changes it records
  `git stash create`'s commit under the local ref `refs/gov/checkpoints/<sid>/<n>` and as
  `checkpoint — <sha12> · <k> path(s) · <utc>` in the binding's `## checkpoint` section, touching neither
  the tree, the index nor any branch; then it writes one journal line through
  `write_journal_line compaction session=<sid> build=<slug|none> item=<item tag|none> trigger=<auto|manual>`
  (I3, TOOL-dWellOiledMachine-16). The item is the act record's `item` for an act session, else the item
  TOOL-dDeclaredLoop-7's `position.py <slug> --json` names for the binding's build, else `none`.
  Observed by AC6.
- **S9** — The keep-list. One instruction unit, `runtime.compact-keep-list`, a row of
  `tools/runtime/instructions.toml` (PLAY-dOrderedCharter-9 S1) written through
  `python tools/playbook/instructions_edit.py` (PLAY-dOrderedCharter-15 S2), rendered as the
  `# Compact instructions` section of root `CLAUDE.md` by the one renderer's entry-files scope
  (PLAY-dOrderedCharter-43). It tells the summary to keep the card's pointers, the build, the item and
  the open asks verbatim, and names the classes a summary loses: handles (SHAs, ids, `file:line`), each
  decision's condition, rejected options and open forks. Observed by AC7.
- **S10** — The card's size check. `write_card` and `--card --append` refuse a card over
  `min(CARD_CAP_BYTES, reattach)`, `reattach` the `reattach-cap-bytes` row's value in the session
  harness's capability table (I7, TOOL-dWellOiledMachine-14). This unit adds that row to
  `tools/runtime/harnesses/claude-code.toml`: `value = 20000`, `measured-on = "documented"`,
  `binary-version = "unrecorded"`, PINNED from the runtime layer's "a file returns only under about 5,000
  tokens" (layer-runtime :776) at 4 bytes a token. The refusal names the row and both numbers. A missing
  row reads `CARD_CAP_BYTES` alone and says so on the card's `cap —` line. Observed by AC8.
- **S11** — The fixture, `python tools/runtime/session_binding.py --fixture --plant <case>`: a scratch
  repository with a stub harness payload per source, a stub capability table and a stub journal writer,
  printing the case's observation, exit 0 when it holds; the leg `runtime session-binding fixtures` in
  `tools/gate-legs.json` runs every case. Observed by AC1 to AC9.

## 4. Design

### Evidence

SessionStart is wired at `.claude/settings.json:32-50`: `startup|clear` writes the card, `resume|compact`
replays it, and no entry matches `fork`. `write_card` exits 2 on an over-cap card (`manifest-check.sh:712`)
and `read_session_id` exits 2 on a missing or refused id (`:296-304`); a SessionStart hook's output
reaches the session only on exit 0, so each of these returns nothing to the session, which is one
reading of the resume misses (research-runtime-sessions :85, 7 of 14 since 2026-09-15). The cause of
those seven is not on this node (their transcripts `2588f719`, `b710e9c3` and `1799cb98` are absent
from `~/.claude/projects/C--projects-coding-governance/`), so S5 closes the failure modes the code can
produce and S6 names every later miss by session. The only size check is the byte literal
`CARD_CAP_BYTES=8192` (`:216`), not a harness figure. No PreCompact entry exists. Matching hooks run
in parallel (research-runtime-hooks :49), which is why S2 locks.

### Alternatives rejected

- **The binding written by `manifest-check.sh`.** Act sessions bind and get no card, so the binding
  cannot ride the card's hook; and the kickoff kit is the owner session's, not the runtime's.
- **A commit at PreCompact.** It would land outside the commit queue with no witness and no pass
  trailer; a stash commit under a local ref keeps the work with no history written.
- **A journal class for a card miss.** I3's classes are unit 16's; the miss lives in the record it is
  about, and `misses` reads it there.

## 5. Production-readiness checklist

- security — a node-local record keyed by a validated session id; no secret is read or written;
  checkpoint refs are never pushed.
- perf / scale — `bind` is one read and one rename; `precompact` adds one `git status` and at most one
  `git stash create`; the lock waits at most 2 s.
- error / empty / loading states — a hook that fails here fails open and never blocks a session start;
  a refused id writes nothing and the card hook says `not delivered`; an absent capability row falls
  back and says so.
- observability — the `## delivery` section per start, `card miss —` lines, and one `compaction`
  journal line per compaction.
- risks — `after` depends on the transcript's shape (§4); the keep-list's effect on a summary is
  unmeasured until TOOL-dWellOiledMachine-36's fixture runs a compaction.
- testing — the fixture plants of AC1 to AC9 and the arms in §7.
- migration — none: the record home and the packs are new; the replay's exit change applies to hook
  runs only.
- user docs — `skills/session-kickoff/SKILL.md`'s resume paragraph names the delivery line and `misses`.

## 6. Acceptance criteria

The fixture is a scratch repository, a stub payload per source, a stub capability table and a stub
`write_journal_line` that appends to a file.

- **AC1** — When `python session_binding.py --fixture --plant sources` runs `bind` once per source of
  `startup`, `resume`, `clear`, `compact` and `fork`, the record exists after the first, keeps its
  `started-utc`, and reads each source in turn; with `GOV_ACT=act-0123456789ab` set it reads
  `owner: act-0123456789ab`; a session id carrying `..` writes nothing.
  Red when: a source leaves no record, or a refused id is joined into a path.
- **AC2** — When `grep -c fork orientation-replay.fragment.json` runs it prints 1, and the binding
  fragment's matcher reads `startup|resume|clear|compact|fork`.
  Red when: a SessionStart source has no binding entry.
- **AC3** — When `python session_binding.py --fixture --plant silent-replay` replays with the stored
  card absent and a planted over-cap render, the hook run prints `card — not delivered` and a `now —`
  line and exits 0, and the binding's `## delivery` holds `not delivered`; the same command run by hand
  exits 2.
  Red when: a hook run exits non-zero, or prints nothing.
- **AC4** — When `python session_binding.py --fixture --plant miss` plants a `resume` binding with no
  delivery line and a `compact` one with a delivery 5 s after it, `misses` prints exactly one
  `card miss —` line naming the first with `hook never ran`, then `card misses — 1`.
  Red when: the delivered compaction is listed, or the miss is not.
- **AC5** — When `python session_binding.py --fixture --plant compact-card` appends a route naming
  `fx`, advances `fx`'s build card ref, then replays with source `compact`, the binding reads
  `build: fx` and the replay prints the advanced card's last step and a `card —` line.
  Red when: the replay prints the session's startup card without the build card.
- **AC6** — When `python session_binding.py --fixture --plant precompact` runs `precompact` with
  `trigger` `auto` over a tree with two uncommitted files, the journal stub holds one
  `compaction session=<sid> build=fx item=<tag> trigger=auto` line, `refs/gov/checkpoints/<sid>/1`
