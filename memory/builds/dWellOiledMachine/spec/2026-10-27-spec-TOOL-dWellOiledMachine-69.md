## 1. Goal

Promoted from the spec audit of this build, round 1
(`memory/builds/dWellOiledMachine/reviews/2026-10-27-review-TOOL-dWellOiledMachine-1-spec-audit.md`),
finding 29, item H6, at HIGH. TOOL-dWellOiledMachine-10 S13 sets `core.hooksPath` to the trusted
copy without naming a scope. On this node `extensions.worktreeConfig` is true and every linked
worktree overrides the shared value in its own `config.worktree`, each naming the primary checkout's
`.githooks`; a plain `git config` write lands in the shared config, which every worktree overrides,
so worktrees keep running the primary tree's hooks and S14 then refuses every landing from a
worktree, which is where every unattended run lands from. This unit writes the value where it takes
effect and proves it on a pre-seeded worktree.

## 2. Scope (IN)

- **S1** — The write scope. check-wiring's session arm (10 S13) reads the effective value and its
  origin with `git config --show-origin core.hooksPath`, the reading `tools/check-wiring.sh:621`
  documents. It writes the trusted path with `git config --worktree core.hooksPath <path>` when
  `git config --bool extensions.worktreeConfig` reads `true`, else with `git config --local`, so the
  value lands in the scope git reads first for this worktree. Observed by AC1, AC2.
- **S2** — What it overwrites. A value whose path resolves into a checkout, Check H's class
  (`tools/check-wiring.sh:746-775`), the primary tree's `.githooks` included, is replaced in the scope
  S1 names; any other value that is not the trusted copy is reported as 10 §4 Migration says and never
  overwritten. Observed by AC1, AC3.
  **Readers:** by name: `tools/check-wiring.sh`, Check H's reader of the value. by value: `tools/check-wiring.sh`, whose session arm re-reads the effective value after the write.
- **S3** — The record corrected. TOOL-dWellOiledMachine-10's §4 Evidence bullet calls the value one
  per clone; spec 10 takes a rev bump at this unit's pass saying the value lives in each linked
  worktree's `config.worktree` where `extensions.worktreeConfig` is set, its §9 line naming this unit
  and finding 29. Observed by AC4.

## 4. Design

### Evidence

- `git config --show-origin core.hooksPath` in this worktree prints
  `file:C:/projects/coding-governance/.git/worktrees/unattended-dwelloiledmachine-b9baed/config.worktree`
  with the value `C:\projects\coding-governance\.githooks`, and `git config extensions.worktreeConfig`
  prints `true` (probed 2026-10-27, PINNED).
- `tools/check-wiring.sh:621` states that the shared value applies unless a worktree's
  `config.worktree` sets its own.
- 10 S13 says only "sets `core.hooksPath` to it" (`spec-10.md:110-115`), and §4 calls the value one
  per clone (`spec-10.md:178-179`).

### Files touched (estimate)

- `tools/check-wiring.sh`: the session arm's read and write of `core.hooksPath`
- `tools/check-wiring.test.sh`: S4's planted worktree, the arm in §7
- `memory/builds/dWellOiledMachine/spec/2026-10-26-spec-TOOL-dWellOiledMachine-10.md` (S3's rev bump)

### Alternatives rejected

- **Clearing every worktree's `config.worktree` value so the shared one wins.** It rewrites the
  config of worktrees no session is running in and removes a deliberate per-worktree value the
  migration promises to report rather than overwrite.

## 5. Production-readiness checklist

- security — the trusted copy actually governs each worktree, closing the bypass in which a worktree
  ran the primary branch's own hooks.
- perf / scale — two `git config` reads per session-arm run.
- error / empty / loading states — a write that fails is reported by the session arm and the lander
  still refuses, as 10 S14 says.
- observability — the session arm names the scope it wrote.
- risks — a worktree no session has opened since this unit keeps its old value until one does, and
  the lander refuses a landing from it with both paths named, which is the intended stop.
- testing — AC1 to AC4 and the arm in §7.
- migration — the first session-arm run per worktree moves its value.
- user docs — `help/runtime.md`'s trusted-copy section (10 S16) names the scope.

## 6. Acceptance criteria

- **AC1** — When `bash tools/check-wiring.sh --session` runs in a scratch clone's linked worktree whose
  `config.worktree` holds `core.hooksPath` naming the primary's `.githooks`, with
  `extensions.worktreeConfig` true, then `git -C <wt> config --show-origin core.hooksPath` names
  `config.worktree` and a path under `<git-common-dir>/gov/hooks`.
  Red when: the write lands in the shared config and the worktree still runs the primary's hooks.
- **AC2** — When the same runs in a scratch clone with `extensions.worktreeConfig` unset, the value
  lands in the clone's local config.
  Red when: a `--worktree` write is attempted where the extension is off.
- **AC3** — When the planted worktree's value names a directory outside every checkout, the session
  arm reports it and `git config core.hooksPath` is unchanged.
  Red when: a deliberate value is overwritten.
- **AC4** — When `grep -n "config.worktree" 2026-10-26-spec-TOOL-dWellOiledMachine-10.md` runs over
  spec 10, its §4 names the per-worktree scope and its §9 the rev line naming this unit.
  Red when: spec 10 still calls the value one per clone.
