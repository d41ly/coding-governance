## 1. Goal

No item lets a session that does not hold a build drive one of its units, though unit leases carry
host and session fields (gap-conc-11). This unit lets the build's driver offer a unit at placement to
another session or node as `build.unit-holders` says, has that unit's holder drive only the unit's
passes on its own branch, pushed as `build.push` says, brings its returns and registered decisions to
the driver through the branch and the registers, and leaves every transition to the driver; under
`driver-only` an offer to a session that does not hold the build is refused (the night pass two,
point 4; the owner's NT-20).

## 2. Scope (IN)

- **S1** — The key's reader. `read_unit_holders(repo)` in the new `tools/runtime/unit_holder.py`
  reads `build.unit-holders` (`tools/policy/catalogue.toml:1003-1007`: `any-session` or
  `driver-only`, default `any-session`; `strict`'s cell `driver-only`, v2:1620) once per verb, through
  `python <prefix>/policy/policy.py get build.unit-holders` (I31) as a subprocess. A refused read takes
  `driver-only`, the narrower value, with one `unit holders — NOTE · <why>` line: deny by default.
  Observed by AC1, AC2.
- **S2** — The offer at placement, `python unit_holder.py offer <slug> <unit> --to <target>`, the
  target a fleet tag or `<fleet tag>/<session>`. `run_unit_offer` first reads the build lease
  `refs/gov/leases/<slug>/build` through the one lease reader (`unattended.sh --claims`, `read_claims`
  at `tools/unattended/unattended.sh:2118`) and refuses `offer refused — not the driver · <slug>`
  unless this session holds it. `check_unit_offer(value, target, holder)` then refuses, under
  `driver-only`, every target that is not the build lease's own holder:
  `offer refused — driver-only · <slug>/unit/<unit> · <target>`, exit 1, before any write. Otherwise
  it writes the offer through `unattended.sh --lease offer unit <slug> <unit> --to <target>`
  (TOOL-dPlacedRequest-20 S1), whose `offer` field and `offered` class are the token this unit hands
  to discovery. A session target is the ask §8 F1 files. Observed by AC1, AC2, AC5.
- **S3** — The holder's write refused at the boundary. `check_holder_lease(ref, record, value)` is a
  rule of TOOL-dWellOiledMachine-58's door `check_writer_binding` (`tools/memory-tree/gov_record.py`):
  under `driver-only`, a write to `refs/gov/leases/<slug>/unit/<id>` whose record's `session` and
  `fleet-tag` are not the build lease's holder is refused `door — refused · <ref> · driver-only`, so a
  session that skips the offer verb cannot acquire the unit. Under `any-session` the rule admits it
  and the door's other rules decide. Observed by AC2.
- **S4** — The holder's branch and push. A held unit's workspace is `allocate_workspace`'s per-unit
  worktree on `gov/<slug>/<unit>` (TOOL-dWellOiledMachine-11 S3), whatever `build.worktree` says (its
  §3); the holder's role returns are committed there through `enqueue_commit` (its S6) and pushed by
  `run_build_push(repo, "gov/<slug>/<unit>")` as `build.push` says (TOOL-dWellOiledMachine-40 S1, S3),
  and each push renews the unit lease with `--witness <pushed tip>` (TOOL-dPlacedRequest-1 S5).
  Observed by AC3.
- **S5** — Returns and decisions reach the driver. The holder registers each decision through
  `unattended.sh --register decision <slug> <item> <fork> <file>` (TOOL-dPlacedRequest-12 S4).
  `integrate_unit` (TOOL-dWellOiledMachine-11 S7) merges the unit branch, carrying the returns' rows,
  and calls `read_holder_decisions(repo, slug, unit)`, which prints one
  `holder decision — <unit> · <key>` line for each register under `refs/gov/decisions/<slug>/` whose
  `session` is the holder's and each `Decided:` trailer on the merged range, before the driver's next
  transition. Observed by AC3.
- **S6** — The driver alone runs transitions. `integrate_unit` first calls
  `check_holder_branch(repo, build_branch, unit_branch, unit)`, which reads
  `read_commits(repo, ["<build tip>..<unit tip>"], ["Pass", "Gov-Transition", "Decided"])`
  (TOOL-dDeclaredLoop-23 S3) and refuses the merge,
  `integrate — refused · holder-transition · <sha8>` for any `Gov-Transition:` trailer
  (TOOL-dDeclaredLoop-3 S1), and `integrate — refused · holder-scope · <sha8>` for a `Pass:` naming
  another unit, so a holder's branch can carry only its own unit's passes. Observed by AC4.
- **S7** — The page `help/runtime.md` gains a section on unit holders: the two values, who may offer,
  the holder's branch and push, how decisions reach the driver, and the two integration refusals.
  Observed by AC6.

- **AC1** — When `python unit_holder.py offer fx TOOL-fx-2 --to b` runs in `na` under
  `build.unit-holders = "any-session"`, it writes the offer, and `unattended.sh --lease acquire unit fx

  Red when: either step is refused under `any-session`.
- **AC2** — When the planted policy file sets `build.unit-holders = "driver-only"`, or names
  `preset = "strict"` with the key's strict cell read from KICK-dKeptSession-1's preset store, the

  Red when: an offer or a holder's write lands under `driver-only`.
- **AC3** — When `nb` commits a return on `gov/fx/TOOL-fx-2`, pushes it and registers a decision,
  then `na` runs `integrate_unit` for `TOOL-fx-2`, the build branch holds the return's file and the run
  prints `holder decision — TOOL-fx-2` with the decision's key.
  Red when: the return is missing from the build branch, or the decision is not printed.
- **AC4** — When the unit branch carries a planted commit with a `Gov-Transition:` trailer,

- **AC5** — When `nb`, holding no build lease, runs `python unit_holder.py offer fx TOOL-fx-3 --to a`,

  Red when: a session other than the driver writes an offer.
- **AC6** — When `grep -n "unit-holders"` runs over the runtime kit's page `runtime.md`, the section
