## HIGH

### H1. The build-index classifier reads `.git/index` while the hygiene shell reads the hook's index (id 1)

`tools/memory-tree/gen_build_index.py:883` (and the `cat-file` call at 901-903).

`check_staged_render` runs both of its git calls with `_build_git_env()`, which strips `GIT_INDEX_FILE`. `check-memory-hygiene.sh:525` builds `STAGED_SET` and `STAGED_MD` with a bare `git diff --cached`, which reads whatever index it inherits. Under `git commit -a`, `git commit <paths>` or `git commit -i`, git hands the pre-commit hook a `GIT_INDEX_FILE` pointing at `index.lock` or a temporary next-index, and `.git/index` does not yet hold the auto-staged edits. The adopter pre-commit snippets in `tools/memory-tree/README.md:122-128` and `WIRE-INTO-PROJECT.md:229-236` do not unset it. So in an adopter, `STAGED_MD` is non-empty, check 9 calls `--check --staged`, and the generator lists the old index and prints "render SKIPPED … nothing is staged under the memory root". At BASE the same hook ran a full `--check` and went red on a stale `LIVE.md`. HIGH, not BLOCKER, because the path needs an adopter, the snippet and `commit -a` or paths, and the push-boundary run still catches the drift.

**Fix (skeptic judged SOUND):** in `check_staged_render`, keep the leak-scrubbed environment but carry `GIT_INDEX_FILE` through when it is set, so both readers honour the hook's index. The alternative is to have the hygiene shell pass its already-computed name-status list on stdin, which makes the shell the one reader.

**Left-shift gate:** a `--selftest` arm that builds a temporary index holding a structural edit, sets `GIT_INDEX_FILE` to it, and asserts a render is owed. Also a hygiene arm that runs the leg with `GIT_INDEX_FILE` set to a temp index whose content differs from `.git/index`, asserting check 9 renders.

### H2. With `LIVE_LANDED_UNCLOSED=1`, the render reads product source the classifier never sees (id 12)

`tools/memory-tree/gen_build_index.py:880`.

Under `LIVE_LANDED_UNCLOSED="1"` (`.memory-tree.conf:924`), `read_landed_unclosed` calls drift-audit's `signal_spec_status`, which runs `git grep -w -F <unit id>` over `EVIDENCE_GLOBS` (tools/, skills/, .claude/, the charter template, `memory/guides/SESSION-KICKOFF.md`). `derive_landed_counts` turns that into `LIVE.md`'s Landed-unclosed column. The classifier diffs only the memory root, the conf and the kit. A commit that stages a non-structural memory edit with no id change, plus a `tools/` or `skills/` line that first cites a non-terminal unit's id, now prints "render SKIPPED … none a build-index input". At BASE it ran the full `--check`, which reads the worktree, and check 9 went red. Spec N3 covers a product-source-only commit, which never reached check 9 at base, and not this mixed one. Code-plus-ledger commits that first cite a unit id are routine in this repo, so the path is reachable. The AC6 parity arm checks render outputs against `check_index_input`, never render inputs, so nothing tests this. HIGH because it is a false certification on a routine path here, contained only by the push-boundary render.

**Fix (skeptic judged SOUND):** when `LIVE_LANDED_UNCLOSED` is set, answer "render" whenever anything outside the memory root is staged, or, more precisely, widen the diff to the drift layer's `EVIDENCE_GLOBS` plus the drift-audit conf and kit and render on any hit.

**Left-shift gate:** a `--selftest` arm with `LIVE_LANDED_UNCLOSED=1` that stages a product-source line beside a non-structural memory edit and asserts a render is owed. Longer term, derive the classifier's input set from the same declaration `plan()` uses, so the two answers to "what moves the render" cannot drift.

## MEDIUM

### M1. Name checks 1, 3, 4 and 5 ignore a staged edit to `legacy-files.txt` (ids 3, 5, 10, 15)

`tools/memory-tree/check-memory-hygiene.sh:539-544`.

The gate's premise, "a commit can make one wrong only by staging a NEW name", is false. Checks 3 and 5 skip grandfathered paths through `in_legacy`, check 4 builds its `LEG` set from the same list, and check 3 also reads `PROJECT_REGISTRY_EXTRA`, `FAMILIES`, `BUILD_SLUG_RE` and `MAP_SUB` from the conf. A commit that stages only an `M` to `memory/project/legacy-files.txt`, dropping the row for a still-misnamed file or folder, leaves `STAGED_NEW` empty. `NAMES_GRADED` goes to 0 and the hook says "this commit stages no new name". At BASE the staged leg graded every tracked name and went red. Even with the gate open, the narrowed `FILES` would not hold the de-grandfathered path, because `legacy-files.txt` has no build folder. This commit causes the violation, so the by-design carve-out for pre-existing violations does not cover it. The same file already re-arms the stale-line guard at line 2732, so the author treats it as an input there but not here.

**Fix (skeptic judged SOUND):** when `STAGED_SET` holds `$M/project/legacy-files.txt` (and the conf, if it is passed in), set `NAMES_GRADED=1` and run checks 1, 3, 4 and 5 over `FILES_ALL`, or at least over the paths whose legacy rows were removed between HEAD and the index. Correct the comment's premise.

**Left-shift gate:** a paired hygiene arm that drops the legacy row for a committed free-named file, stages only the list, and expects check 5 (and, for a build folder, check 4) to red.

### M2. The legacy/debt stale-line guard ignores a staged rename's source path (ids 6, 16)

`tools/memory-tree/check-memory-hygiene.sh:2731`.

The guard is held unless a list file is staged, and its comment says a listed path can go stale only by deletion, which `--staged` does not grade. But a rename is an `R` row inside the ACMR set, and the parse at lines 519-524 reads its old path into `_p1` and then drops it. So `git mv` of a grandfathered file to a conforming name, without editing `legacy-files.txt`, passes: check 5 grades the new name, and the guard prints HELD. At BASE the guard ran under `--staged` against the index listing and redded with "legacy-files.txt lists paths that no longer exist". The same holds for a renamed index file listed in `curation-debt.txt`. This is a common clean-up path.

**Fix (skeptic judged SOUND):** in the `STAGED_SET` loop, when `_st` is `R*` and `_p1` is in `LEGACY_SET` or `DEBT_SET`, set `_C5L=1`, or record those old paths and run the guard over them only. Both sets are built at line 348, before the parse, so the lookup is fork-free. The skeptic adds a portability note: pass `-M` to the `git diff` call, so an adopter with `diff.renames=false` still sees an `R` row instead of a filtered-out `D` plus an `A`. Reword the comment so it no longer claims only a deletion can make a line stale.

**Left-shift gate:** a hygiene arm that `git mv`s a legacy-listed file to a conforming name, stages nothing else, and expects the stale-line red.

### M3. `os.path.relpath` raises across Windows drives and turns `--check --staged` into a traceback (ids 11, 17)

`tools/memory-tree/gen_build_index.py:877`.

`os.path.relpath(here, root)` raises `ValueError` on Windows when the kit and the repo root are on different drives. Nothing in `check_staged_render` catches it, and `main()` catches only `Problem`. Two routes reach it. In hook use, `resolve_kit_gate` can resolve the kit from an install receipt or `GOV_KITROOT` on another drive; the hygiene leg then reports the traceback as fail 9 "generated build index differs from a fresh render" on every memory commit, while the full run never calls this code, so the two legs disagree (id 11). In the selftest, `test_staged_render` always passes a `tempfile` root, so a checkout on D: with TEMP on C: reds every in-process arm as "UNEXPECTED ValueError" on a correct tree (id 17). It breaks the spec's error rule, "a git failure is a render, never a skip", because this is neither. The effect is a false red, never a wrong pass.

**Fix (skeptic judged SOUND):** wrap the call: on `ValueError` set `kit = None`, the same answer the existing `..` branch gives for a kit outside the repo. Alternatively, derive `kit` from `tree_lib.kit_rel()`, whose ancestor walk already guards this `ValueError`.

**Left-shift gate:** a `--selftest` arm that monkeypatches `os.path.relpath` to raise `ValueError` and asserts `check_staged_render` returns an answer rather than raising. A static rule is also cheap: grep the kit for bare `os.path.relpath(` outside `tree_lib`, so the next caller goes through the guarded helper.

### M4. The `LIVE_LANDED_UNCLOSED` evidence population is outside the classifier's pathspec (id 2)

`tools/memory-tree/gen_build_index.py:880`.

This is the same defect as H2, found by the security lens and bound at MEDIUM. It adds one input to H2's list: the drift-audit conf and kit, which also feed the Landed-unclosed column and are also absent from the staged pathspec. The impact and the commit shape are those of H2.

**Fix (skeptic judged SOUND):** as H2. Answer "render" when the key is set and any staged path is in the evidence population or is the drift-audit conf or kit. The cheaper form is to render whenever the key is set and anything outside the memory root, the conf and the kit is staged.

**Left-shift gate:** the H2 arm, with a second case that stages only the drift-audit conf beside a non-structural memory edit.

## LOW

### L1. A non-UTF-8 modified path crashes the classifier instead of answering "render" (id 7)

`tools/memory-tree/gen_build_index.py:900`.

Line 887 decodes the `-z` output with `surrogateescape`, but line 900 encodes the `cat-file` request with strict UTF-8 outside the `try`, which catches only `OSError`, `CalledProcessError` and `ValueError`. On POSIX, a modified non-structural memory path with non-UTF-8 bytes raises an uncaught `UnicodeEncodeError`. The hygiene leg reports it as fail 9 with the wrong label. The docstring promises any decode failure answers "render". The failure is in the safe direction and the path is very narrow.

**Fix (skeptic judged SOUND):** encode with `encode("utf-8", "surrogateescape")`, or move the encode inside the `try` and add `UnicodeError` to the caught exceptions.

**Left-shift gate:** a POSIX-only `--selftest` arm that stages a modified file whose name holds a non-UTF-8 byte and asserts "render". On node `a` that arm skips, and the skip must announce itself.

### L2. C6 undercounts quoted non-ASCII paths, and a partial undercount stands in the full run too (id 8)

`skills/session-kickoff/manifest-check.sh:1293`.

C6 now runs one `git ls-files -- "${WATCH[@]}"` without `-z`. With `core.quotePath` at its default, non-ASCII paths come out C-quoted, so the `"$w"|"${w%/}"/*` case patterns never match them. The git re-ask runs only when a count is zero. A directory spec with more than 100 tracked files, some non-ASCII, can count at or under 100, and the full run (`STAGED=0`) loses the "overly broad" WARN that BASE printed. The dead-spec verdict is unaffected.

**Fix (skeptic judged SOUND):** build the listing with `git -c core.quotePath=false ls-files -z` and split on NUL, or re-ask git whenever the listing holds a line starting with a double quote.

**Left-shift gate:** a manifest-check arm with a watch directory of 101 tracked files, one with a non-ASCII name, asserting the WARN fires.

### L3. No hygiene arm reaches the check-9 SKIPPED relay or the `--staged` pass-through (id 13)

`tools/memory-tree/check-memory-hygiene.sh:1164`.

The relay matches the literal prefix "build-index: render SKIPPED" at the start of the merged stdout and stderr. Every new `--staged` arm stages a spec edit, which is structural, so check 9 always renders in the suite. A respelled message, or a Python warning printed first on the merged stream, would make the skip exit 0 silently. Removing `--staged` from `_c9` would also leave the suite green. The generator's own selftest asserts the substring, but not the relay or the pass-through. The skeptic re-graded this from medium to low, and that is the binding grade: the current code is correct, and neither regression changes a verdict.

**Fix (skeptic judged SOUND):** add two hygiene arms. One stages a no-id edit to a non-structural memory file and asserts "memory-hygiene: check 9: render SKIPPED". The other stages a line citing a new `FAMILY-slug-N` id in that file and asserts check 9 goes red. Match the relay per line, for example `grep -m1 '^build-index: render SKIPPED'`, not as a prefix of the whole output.

**Left-shift gate:** the two arms above are the gate.

### L4. No arm stages a rename through the new three-field parse (id 14)

`tools/memory-tree/check-memory-hygiene.sh:525`.

The parse moved from `--name-only` to `--name-status` read as `_st _p1 _p2`, keyed on `${_p2:-$_p1}`. It is correct today. No arm stages a rename, so a future edit that keys on `_p1` or drops the tab `IFS` would grade the old path of every `git mv`, and checks 2, 5, 6 and 7 would skip the new name silently. That includes RUN.md retirement to `RUN.<PHASE>.<hex>.md`, which is a rename.

**Fix (skeptic judged SOUND):** add an arm that `git mv`s a correctly named recording file to a malformed name and asserts check 5 names the new path, and that the narrowing line still prints.

**Left-shift gate:** that arm. It pairs naturally with the M2 rename arm, so one fixture can serve both.

### L5. AC4's "stages a kit-directory file" is observed only through a synthetic prefix (id 18)

`tools/memory-tree/gen_build_index.py:3881`.

Spec AC4 says selftest arms stage a kit-directory file and see a render owed, and claims S3 (the kit derivation and the kit pathspec) is observed by it. The arm built instead calls `check_index_input` with a synthetic `pfx/kit` prefix. In the fixture the kit always lands outside root, so only the `None` branch runs. A broken derivation, such as wrong separators or an adopter's bare-prefix layout, would pass the gate that claims to cover it. The TOOL-aTrimmedHook-2 ledger records why: the install-prefix ban. There is no runtime effect today.

**Fix (skeptic judged SOUND):** add an arm that stages a file under the derived kit path in a fixture where the kit sits under the fixture root, building the path from `os.path.dirname(__file__)` so no install prefix is spelled. Otherwise, revise AC4 in a spec rev-3 to state the narrower predicate-level observation actually made.

**Left-shift gate:** the arm above. Fixing M3 through `tree_lib.kit_rel()` would let this arm exercise the shared derivation instead of a local copy.
