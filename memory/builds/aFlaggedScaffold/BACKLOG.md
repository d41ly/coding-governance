- TOOL-aFlaggedScaffold-3 · filed 2026-08-29 · `govkit update` CANNOT LAND A SOURCE GOV STARTED SHIPPING. Measured on the inCMS adopter: the lexicon kit's `canon.py` was added upstream at `dec46b82`, was present in gov at the exact sha that adopter pulled (`136d26f8`), is claimed by `include = "**"`, and `plan --coverage` reports it as a GAP — and `update --write --to 136d26f8` still left it out. `lexicon.py` imports canon at MODULE level, so every entry point of that adopter's kit died with ModuleNotFoundError for six days under a green bar. Twelve of its fourteen claimed kits have descriptor sources with no receipt row; how many are real gaps versus sanctioned divergence needs per-kit judgement and was not measured. `apply` is not the workaround — it also runs the kit's `[adopt]`, which for an adopter holding a kit deliberately INERT is a posture flip. There is no verb that lands new kit bytes without adopting. PARTIALLY ADDRESSED 2026-09-04 by `TOOL-aWeldedTribunal-6`, and the row stays OPEN deliberately: `update` now REPORTS every source gov ships that the target does not hold, grades it through the decline registry, and says the install is INCOMPLETE. It does not LAND the bytes, which is what this row asks for. Landing means synthesising a receipt row — its role, its commit, its gov_oid, whether the target ever declined it — and the verb has evidence for none of those, so it is an owner decision and a follow-up. What changed is that the gap is legible when the verb runs instead of at the next ImportError. → tools/govkit/govkit.py
- TOOL-aFlaggedScaffold-4 · filed 2026-08-29 · `govkit apply` CRASHES WITH A TRACEBACK on a large adopter under Windows: the renormalize step's dirty check passes every lf-pinned path as argv (`git diff --name-only HEAD -- <lf_paths>`), which exceeds the 32 KiB command line. Measured on inCMS, whose `.gitattributes` is 28 KB: `FileNotFoundError: [WinError 206] The filename or extension is too long`. WORSE THAN A REFUSAL, because it fires AFTER the write loop and AFTER configure: the observed target was left with its new files staged, `.lexicon.conf` scaffolded, a Skill rendered, a stale write lock under its governance dir, and no receipt update — a half-applied install from a verb that reported nothing. Candidate: `--pathspec-from-file=-` with `--pathspec-file-nul` over stdin, which removes the argv bound entirely. The failing case is any adopter with more lf pins than the OS will carry. CLOSED 2026-09-04 by `TOOL-aWeldedTribunal-8`, on evidence: `DEPL-dRetiredFork-4` built `git_pathspec` in `tools/govkit/govkit.py`, at line 3724, using the exact `--pathspec-from-file=-` plus `--pathspec-file-nul` candidate this row proposed, and added a subcommand allowlist and an empty-list refusal the row did not ask for. → tools/govkit/govkit.py
