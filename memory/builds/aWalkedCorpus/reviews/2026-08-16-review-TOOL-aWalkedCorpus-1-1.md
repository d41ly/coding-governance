## Answering the question this pass was convened on

**A fixture-plus-floor is NOT buildable against `bench.py` as it exists.** Measured, not argued:

```
$ python tools/memory-recall/bench.py <data> <all-miss fixture> --sets records --subs fts5 --ks 1,5,10
=== records: 252 docs, 110695 chars, index 0.00s, ceiling 0.00
substrate    r@1     r@5     r@10    f@5     MRR    b@10
fts5        0.00    0.00    0.00    0.00   0.000  2,651
ALLMISS EXIT=0
```

Total miss on every metric, exit 0. `bench.py` has no floor concept — `main()` ends `return 0`
(bench.py:483) and the only other exit is the `return 2` usage guard. It cannot GAIN one: it is
byte-pinned at `tools/memory-recall/verbatim.json` (`"bench.py": "5a46060ffb2008fc"`) and asserted by
`selftest.py:1057 t_verbatim_files`, a leg unit 2's own §7 and AC5 require green. It also cannot read
the live index — it `load()`s `<data-dir>/<set>.jsonl` plus `anchors.json`, artifacts only an
`extract.py` run produces and which this repo commits nowhere. The unit therefore needs **two**
executables it names in no scope item, no Files-touched row and no AC: a data-dir producer and a
floor comparator. The naive build — one leg whose argv is `python bench.py <data> <fixture>` — is
green at score 0.00 forever, which is this repo's own `fixture-passes-by-finding-nothing` class
shipped as the closure of that class.

The fix is small and the material is already there: `bench.py --json` emits
`sets.<set>.substrates.<sub>["r@k"]` and `sets.<set>.ceiling`, so one committed comparator that
builds a temp data dir via `extract`, runs bench with `--json`, reads the named cell and compares it
to `RECALL_FLOOR` closes F1, F2's observability and F3 at once.
