## High

### H1 — the signature comes from a row the run can edit, and a changed signature is not OWN (46)

**Where.** Unit 23 (`2026-09-14-spec-TOOL-dDerivedDocket-23.md`) §4 "The classifier", steps 3 and 5;
§2 S3 and S6.

**Defect.** Step 3 reads OWN when a leg's "argv differs from R's". It compares argv only. S3 defines
the signature as "an argv, run in the tree being graded", and §4 never says which manifest row
supplies the signature at L and at R. S1 reads R's row for the re-run, but says nothing about the
signature. S6's forced-OWN list names the runner, `gate-fingerprint.sh`, `.githooks/pre-push` and
the attribution module. It does not name `tools/gate-legs.json`. The comparator clause reads only
tracked files in the leg's argv, and the manifest is not one of them.

**Impact.** A run can rewrite a red leg's `signature` in its own `tools/gate-legs.json` and leave
the argv alone. Two readings of S3 both open the hole.

- If L's row supplies both ends, a signature that prints one constant line makes S(L) equal S(R).
- If each side uses its own row, a wrapper that filters the run's own offender out of the real list
  mode makes S(L) a non-empty subset of S(R). This works as soon as H4's fold removes the count lines.

Either way the leg reads INHERITED and unit 24 lands the run's own red under `land`. The push
boundary re-attributes with the same pushed manifest, so the hook reads the same INHERITED, and
there is no second layer. This is the grader-editing hole KF3 exists to close, reached through the
one grader input KF3's list omits. The first landings also mix two rules, because R's rows carry no
signature until this unit lands.

**Fix.** State that S(L) and S(R) are both computed with R's row's `signature`, read by `git show
R:tools/gate-legs.json`, the way S1 reads R's argv. A leg with no signature at R takes the
byte-identical rule. Read OWN, printing the reason, for any leg whose manifest row differs between L
and R in any field other than `ceiling`. Alternatively, add `tools/gate-legs.json` to S6's forced-OWN
list, which is blunter. Add an AC5-style arm where L edits only the red leg's signature and the leg
reads OWN.

**Left-shift.** One arm per grader input: for each input the classifier reads (argv, signature,
comparator files, normaliser, policy), an arm edits the L copy alone and asserts OWN. Stage each RED
by removing the rule it grades. The class is item 1 below.

### H2 — the override refusal consults a bar nothing ties to the tree being closed (51)

**Where.** Unit 24 (`2026-09-14-spec-TOOL-dDerivedDocket-24.md`) §2 S7; §6 AC6 and AC7. Read against
`tools/unattended/unattended.sh:2977`, where the Definition-of-Done loop skips an overridden item, and
`tools/run-gates/run-gates.sh:1057,1878`, the `GATE_RUN_KEEP=5` rotation.

**Defect.** S7 admits `--close --override gates-green` and `--abort --code gate-red-out-of-scope`
when "the newest attributed bar reads every red leg INHERITED". The close skips an overridden item
before its checker runs (`is_overridden "$item" && continue`, `unattended.sh:2977`), so an override
runs no bar. The record S7 consults is therefore always an earlier one. The run record's header
carries `head`, `fingerprint` and `tree_clean` (checked in a record on this node), and S7 compares
none of them with HEAD. It does not require the run's own pinned `GATE_RUN_ID` either. Records rotate
at five, and every session working in one tree shares that tree's `gate-run/`.

**Impact.** Take a run whose earlier bar read all-INHERITED and which then committed its own red. It
is admitted to override `gates-green`, which is the i12 path S7 exists to close. The override also
writes a park row claiming an inherited red. AC6 and AC7 plant the attribution directly, so both stay
green. The push-boundary bar remains as a second, different check. Its scoped gate runs only the
legs the pushed diff selects, and it records nothing on the run's close.

**Fix.** Require the consulted record to be the run's own pinned `GATE_RUN_ID`. Its header must show
`head` equal to HEAD and `tree_clean yes`, and its verdict must show `tree_moved no`. Otherwise refuse
with a numbered code that names the bar to run first. Add an AC: an all-INHERITED record at an
earlier HEAD, then a commit, then the override, which must refuse.

**Left-shift.** A driver arm per refusal that reads a run record: plant a matching record at a
different `head`, and assert the refusal. The documented check is that every S-item consulting a run
record names which record, by id, and which tree it must describe.

### H3 — the serial retry treats every rc 137 as a timeout (60)

**Where.** Unit 26 (`2026-09-14-spec-TOOL-dDerivedDocket-26.md`) §2 S1 and §7, against its own §3
non-goal "retrying a non-timeout failure". Read against `tools/run-gates/run-gates.sh:1485-1493` and
`tools/run-gates/run-gates.test.sh:976-977`, `:1144`, `:1162-1172` and `:1175-1206`.

**Defect.** S1 defers "a leg that ends with status 124 or 137 while its recorded ceiling is above
zero". BASE separates the two on purpose. rc 124 means `timeout` fired its own TERM. rc 137 "says
nothing about who sent it": `timeout -k`, an operator, an OOM killer and a CI cancel all arrive
identically (`run-gates.sh:1485-1491`). A positive `.bound` is true for every leg that declares a
ceiling, whether or not the ceiling fired. So S1 retries a self-killed or OOM-killed leg, and prints
both of its tails as "timed out after <n>s", which its own §3 rules out.

**Impact.** Three held canary arms red at the post-build bar, and §7 names an edit to none of them.

- 4h-kill: a leg that SIGKILLs itself at about 2 s under a 600 s ceiling must be a FAIL whose tail
  never says "timed out" (`run-gates.test.sh:1175-1206`). S1 retries it and prints "timed out".
- 4h: pins the exact tail `(timed out after 3s)$` (`:1144`), which the new "…, again on its serial
  retry" tail fails.
- stubborn: pins `(timed out after 3s|killed after …, ceiling 3s)` (`:1172`), with the same result.

There is also a wrong green. Under D12-i6 a retry that passes counts green. An OOM-killed leg on a
loaded host is retried alone, passes, and the bar is green over a real memory failure, with
`legs_retried_after_timeout` as its only trace.

**Fix.** Defer only when the ceiling fired: rc 124 with a positive bound, or rc 137 whose `.sec` is
at or above the bound, which is `timeout -k`'s kill after an ignored TERM. Every other 137 stays a
FAIL with today's `killed after` tail. Name the three arms in §7. 4h and stubborn gain the retry
tail. 4h-kill stays as it is and becomes the staged-RED arm for the narrowed predicate.

**Left-shift.** 4h-kill already is the gate, and the fold's job is to keep it. The spec-format rule
it shows: a unit that changes a printed tail lists every existing arm that pins that tail, found by
grepping the suites for the tail's literal. That join is item 6 below.

### H4 — the two existing list modes do not print one line per offender (1, 45)

**Where.** Unit 23 (`2026-09-14-spec-TOOL-dDerivedDocket-23.md`) §2 S3; §4 "The classifier" step 5
and "The `--offenders` modes"; §6 AC1 and AC6. Measured by running
`python tools/lexicon/lexicon.py --list` and `bash tools/check-install-prefix.sh --list` for this
report, and read at `tools/lexicon/lexicon.py:2745-2802`. Both tools are unchanged since BASE.

**Defect.** S3 declares signatures on four legs, two of them "through their existing `--list`
modes". Those two modes print much more than one line per offender.

- `lexicon.py --list` prints every offender keyed `path:line:`, each ending "N definition(s)
  corpus-wide lead with it", which is 989 rows on this tree. It also prints one `.conv` row per cell
  carrying `population X of Y` and teeth counts, and the lines `graded=2111 offenders=983`,
  `armed 172 of 173` and `1964 tracked file(s)`. In list mode too, `.conv` violations print only
  `bad[:40]` then `… and N more` (`:2799-2802`), and the over-pin re-list is cut at 40 the same way
  (`:2761-2764`).
- `check-install-prefix.sh --list` opens with `install-prefix: 34 hit(s) over 257 shipped files`,
  keys each hit by `path:line`, and prints a second carried-prefix section.

Unit 1's normaliser strips roots, mktemp names, durations and trailing whitespace, and nothing else
(unit 1 §4 "The normaliser"). So one added function, tracked file or shipped file anywhere, or one
line inserted above an inherited offender, puts a line in S(L) that S(R) lacks.

**Impact.** These two legs read MIXED on almost every real branch. INHERITED is effectively
unreachable for them, so unit 24's `land` never fires. The lexicon leg is the leg the recorded stops
were about. The aStagedLane override (`aStagedLane/RUN.md:51`, 463 offenders over a pin of 461) and
the dCarriedReceipt decision (`dCarriedReceipt/RUN.md:89`) both concern it, and unit 24 §4 cites its
435 inherited offenders at `dFramedEntrypoint/RUN.md:41`. When that leg's red really is inherited,
as it was there, it would read MIXED and park.

The direction is mostly the safe one, `park`, except at the truncation. A branch that fixes one
`.conv` violation and adds one past row 40 in the same cell leaves every count and the first 40 rows
unchanged, and it can read INHERITED. That is the unsound direction S3's own F2 names. No criterion
runs any of the four real signature argvs: AC1 uses a fixture leg, and AC6 counts manifest keys. The
two new `--offenders` modes have no arm that pins their output shape, their exit code, or that
default output is unchanged.

**Fix.** Give `lexicon.py` and `check-install-prefix.sh` an `--offenders` mode of the kind S3 already
specifies for drift and hygiene. It prints one stable key per offender, a path plus an identifier or
spelling, with no line number, no count and no summary line, and truncates nothing. Then add ACs.

- Run each of the four declared signature argvs on the real tree and on a fixture with a known
  offender set. Assert that every stdout line is an offender line and that the set is complete.
- Add an unrelated function and an unrelated file between R and L, and assert the leg still reads
  INHERITED.
- Name the arms for the two new modes, in `tools/drift-audit/selftest.py` and
  `tools/memory-tree/check-memory-hygiene.test.sh`.

The fold moves the lexicon kit's and the install-prefix gate's shipped bytes, so it owes their
version moves. If the fold instead drops the two legs from the signature set, D12-i4's `land` never
engages for them. That narrows the ruling's reach and should be decided, not folded.

**Left-shift.** A canary arm that runs every manifest `signature` on the real tree and refuses a
line that matches a summary shape, such as a count, a colon-terminated header or `… and`. Stage it
RED by declaring `lexicon.py --list` as a signature. The class is item 2 below.

### H5 — unit 27 rewrites `gates-green` with no attribution arm, so `land` ends UNMET (29)

**Where.** Unit 24 (`2026-09-14-spec-TOOL-dDerivedDocket-24.md`) §2 S6 and §3 Edges. Read against
