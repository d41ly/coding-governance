## 1. Goal

`.governance/policy.toml` gets one reader that every consumer calls. This unit builds it in
`tools/policy/policy.py`: `resolve(key, repo=".", rev=None)` and the CLI verb `get`. Both read the
file as committed at the landed revision, never from the working tree, and parse it with `tomllib`,
never by sourcing it. That is `read_policy_key`'s contract (`tools/unattended/unattended.sh:9494-9532`)
carried to TOML, while the shell parser and its three byte-identical copies stay as they are for the
legacy homes.

## 2. Scope (IN)

- **S1** — `derive_landed_revision(repo)` returns the landed revision's full sha and a phrase naming
  how it was found. It calls `resolve_remote`, the `remote_ladder_py` block `TOOL-dGroundRules-1`
  inlines in `policy.py` from `tools/lib/resolve_remote.py:16-68`, and adds no second ladder. The
  landed ref is `refs/remotes/<remote>/<branch>`, the branch being the ladder's, else `main`. With no
  remote at all it is the local `refs/heads/<branch>`, and the phrase says so. A ladder refusal, or a
  ref that does not resolve to a commit, is a `Refusal`. Observed by AC1, AC5, AC6, AC7.
- **S2** — `read_policy_text(repo, rev)` returns the text of `.governance/policy.toml` at the commit
  `rev` resolves to, decoded as UTF-8, or `None` when that commit holds no such path. A `rev` that
  names no commit is a `Refusal`. Nothing in the module opens the working-tree path.
  Observed by AC1, AC2.
- **S3** — `parse_policy(text)` returns a dict from each leaf's key path, a tuple of segments, to its
  value, through `tomllib.loads` alone. A table is never a value. Text that is not TOML raises
  `tomllib.TOMLDecodeError` to the caller. `parse_key(key)` turns a CLI key into its path by TOML's
  own key grammar, so a quoted segment holding a dot is one segment; a string that is not one TOML
  key is a `Refusal`. Observed by AC3, AC4.
- **S4** — `read_catalogue_row(path, catalogue)` returns the catalogue row a key path names, by
  `TOOL-dGroundRules-1`'s name rule: an exact `name` first, else a `name` whose `<word>` or final `*`
  segment stands for any one segment, compared as segment tuples. No row is a `Refusal` naming
  `tools/policy/catalogue.toml`. It is the module's one key-to-row matcher: where unit 1's
  `arm_schema` matches inline, this unit lifts that code into it and points the arm at it. The rows
  come from unit 1's `load_catalogue(kit)`; this unit adds no second read. Observed by AC4.
- **S5** — The data shapes: `Resolution`, a named tuple `(value, source, reason)`, and `Refusal`, an
  exception carrying a path, a line and a reason, rendered as
  `policy: refused · <path>:<line> · <why>`, the line `0` when the refusal names no line.
  `read_file_value(path, row, table, sha, how)` returns `Resolution(value, "file", reason)` when the
  parsed table sets the key, else `None`; it takes `row` unread, so every step `TOOL-dGroundRules-3`
  orders shares one signature. Observed by AC1, AC2, AC4.
- **S6** — `resolve(key, repo=".", rev=None)`: the key's path and catalogue row, the revision (`rev`
  resolved to a full sha, or the landed one when `rev` is `None`), the text, the parse, then
  `read_file_value`. Until `TOOL-dGroundRules-3` and `TOOL-dGroundRules-4` land in this run, three
  outcomes refuse, each naming the line it can: an absent file, a key the file does not set, and text
  that does not parse. Observed by AC1, AC2, AC3.
- **S7** — The CLI verb `python tools/policy/policy.py get <key> [--rev <rev>] [--explain]`, added as
  `cmd_get` to the subcommand table `main` dispatches. It prints the value on stdout: a string as
  itself, a number in TOML's spelling, a boolean as `true` or `false`, and a list one member per line.
  `--explain` adds one stderr line, `policy: <key> · <source> · <reason>`. A `Refusal` prints its line
  on stderr and exits 2. Observed by AC1, AC2, AC4.
- **S8** — `read_policy_key` and its copies in `.githooks/pre-push:1306`, `tools/push-main.sh:404`
  and `tools/run-gates/post-merge.sh:171` keep their `KEY=value` contract and gain no TOML parse.
  Observed by AC8.
- **S9** — Cases in `CASES` of `tools/policy/check_policy.py`, grouped as `reader-landed` and
  `reader-parsed`, each building its repositories under `--fixture` and printing its
  `policy-fixture:` line with the outcome it observed. Observed by AC1, AC3, AC5, AC6.
- **S10** — The help page `help/policy.md`, with its line in `help/README.md`: what the reader reads,
  the `get` verb, and why a working-tree edit does not change what it prints. This unit creates the
  page when no earlier unit has. Observed by AC9.

## 4. Design

### Evidence

- `read_policy_key` reads a policy from file text a caller took with `git show <R>:<path>`, matches
  one anchored line per key, strips one trailing comment and one pair of quotes, and executes nothing
  (`tools/unattended/unattended.sh:9494-9532`). Its caller reads the text at R, the tip the remote
  advertised: "THE POLICY IS READ AT R AND NEVER FROM THE TREE" (`:9494`; `read_gate_policy` at
  `:9545-9585`). The lander states the same contract for its copy: "AS COMMITTED AT THE LANDED TIP
  ... Never the working tree" (`tools/push-main.sh:399-403`).
- The parser is spelled four times, byte-identical, because the pre-push hook ships verbatim and
  sources no kit (`.githooks/pre-push:1299-1302`); `tools/push-main.test.sh:849-853` holds the pair.
- The remote ladder has one Python canonical, `tools/lib/resolve_remote.py:16-68`, which every
  consumer carries inline. The parity arm finds each copy by `git grep` over `*.py`
  (`tools/lib/resolve-python.test.sh:218`), so a new copy joins its population with no table edit.
- A kit may not import a sibling kit (`tools/codebase-map/map_lib.py:1505-1506`); each consumer of
  the ladder applies its own rule for the branch afterwards, as `resolve_default` does in
  `tools/branch-reconcile/branch_reconcile.py:137-160`.
- Kits already import `tomllib` unconditionally (`tools/roles/roles_lib.py:25`).
- `tomllib.TOMLDecodeError` carries `lineno` from Python 3.14; on 3.11 to 3.13 the line is in its
  message as `at line <n>`.

### The contract, carried

| `read_policy_key` | this reader |
|---|---|
| text read at R with `git show` by its caller | `read_policy_text` at the landed sha, or at `--rev` |
| one anchored `KEY=` match; nothing executes | `tomllib.loads`; nothing executes |
| the LAST assignment wins | a repeated key is not TOML, so it never parses |
| an unassigned key prints nothing | an unset key refuses here, and reads the order unit 3 builds |
| a trailing comment and one pair of quotes stripped | TOML's own comment and string grammar |

### Data model

```python
Resolution = namedtuple("Resolution", "value source reason")   # source: file | preset | default | last-valid

class Refusal(Exception):            # path, line, why
    def __str__(self): return f"policy: refused · {self.path}:{self.line} · {self.why}"
```

A reason names the path, the sha8 and how the revision was found:
`set in .governance/policy.toml at 3708a705, <remote>/main, the landed revision`. With `--rev` the
tail is `--rev <rev>`; with no remote it is `local main: this clone has no remote`.

### Behaviour

- **Every git call** runs with `-C <repo>` and with the location variables the memory-tree kit strips
  (`tools/memory-tree/tree_lib.py:262-270`) removed from its environment, so a reader started inside
  a hook or a fixture never reads another repository. The list is spelled in this module, since the
  kit cannot import that one.
- **The revision.** `rev` given: `git rev-parse --verify -q <rev>^{commit}`, a `Refusal` when it
  prints nothing. `rev` absent: `derive_landed_revision`. Either way the reader then holds a full sha,
  so every reason names an immutable commit.
- **The text.** `git show <sha>:.governance/policy.toml`; a path the commit does not hold is `None`.
  The working-tree file is never opened, and no line of it reaches a shell, `eval` or `exec`.
- **The key.** `parse_key` loads `<key> = 0` with `tomllib` and walks the one-key result, so
  `budgets."CLAUDE.md"` is two segments. A catalogue `name` is split on `.`, since catalogue names
  carry no quoted segment.
- **Interim refusals.** Absent file: `.governance/policy.toml:0 · absent at <sha8>; no default is read
  until TOOL-dGroundRules-3`. Unset key: the same, `<key> is not set`. Not TOML: the decoder's line
  and message. The builder of `TOOL-dGroundRules-3` and `TOOL-dGroundRules-4` removes them; none
  reaches a landing, because the run lands its units together.

### Alternatives rejected

- **Import the memory-tree kit's `read_blobs_at`.** It is the one batched blob reader in that kit,
  and a kit may not import a sibling. One blob per call needs no batch.
- **Read the working tree when no remote resolves.** That reopens what the clause closes. A clone
  with no remote reads its local default branch, a commit, and says so in the reason.
- **Call `read_policy_key` from Python.** It is shell, it answers for `KEY=value` lines only, and the
  brief keeps it for the legacy homes.

## 5. Production-readiness checklist

- security — the reader executes nothing from the file: `tomllib` only, and no working-tree read, so
  an uncommitted edit cannot change a value a gate reads. Git runs with the location variables
  stripped. An unknown key refuses rather than reading as unset.
- perf / scale — a handful of git calls per `resolve`: `rev-parse`, the remote ladder's reads and
  `show`. Tens of milliseconds is an estimate, UNVERIFIED until the build measures it; no consumer
  calls the reader in a loop.
- error / empty / loading states — every failure is a `Refusal` with exit 2 and one line: a refused
  ladder, a revision that is no commit, an unknown key, and the three interim refusals of S6.
- observability — `--explain` names the source, the sha8 and how the revision was found.
- risks — a clone that never fetched reads a stale landed tip. That is the contract `read_policy_key`
  has today; the reason names the sha so it is visible.
- testing — AC1 to AC9; the two fixture arms under §7.
- migration — none: no consumer reads the file before this build.
- user docs — `help/policy.md` and its line in `help/README.md`.

## 6. Acceptance criteria

arm CLI as python tools/policy/check_policy.py. The criteria spell both by bare name, `policy.py` and
`check_policy.py`, and the help page as `policy.md` under `help/`, because this run creates them and
the spec-token checker grades a path-shaped token in a criterion against the tracked set. Each
fixture builds its repositories under `%TEMP%`, short-named, and names any remote through a variable
(`tools/check-remote-literals.sh:14-15`).

  remote whose `main`
