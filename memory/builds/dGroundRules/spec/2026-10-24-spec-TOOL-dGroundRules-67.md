### The bar predicate

The close's own run of the spec-token checker's suite at `df4912bda` failed 2 of 204 arms. One is
its parity arm (`tools/check-spec-tokens.test.sh:872-898`). That arm joins each whole-suite
`selftests` argv of the manifest with spaces and requires `BAR` to match it (`:888`). It printed
`BAR-MISS` for
`python {prefix}/policy/check_policy.py --fixture --strict-from memory/builds/dClosedLoop/build/`.
The `policy fixtures` leg is absent at base `3c2b69be`, so the miss is this build's own.

The kit's usage line is `--fixture [--strict-from <dir>] [<case>]` (`tools/policy/check_policy.py:4488`).
A run with no case is the whole suite, and this build's criteria name the one-case form often:
`adopter-fresh-target` alone appears in 14 of them. So the new member stops after the optional
`--strict-from <dir>` and requires that nothing but the end of the command, a shell separator or an
output redirection follows. A case name, or a `<case>` placeholder, fails that lookahead. The
member goes into `BAR`'s suite-name group (`tools/check-spec-tokens.py:391`), after the `selftest.py`
alternative and inside the group's own trailing `(?=\s|$)`:

```
|check_policy\.py\s+--fixture(?:\s+--strict-from\s+\S+)?(?=\s*$|\s*[|;&)]|\s+\d*>)
```

The comment above `BAR` (`:370-387`) gains one sentence: the policy kit's `check_policy.py --fixture`
with no case is a suite, because it runs every case, while naming one case makes it the direct check
a criterion may name.

This spec measured the member on 2026-10-25 at `df4912bda` with the checker's own functions. It
matches the manifest argv above, a bare `--fixture` and `--fixture 2>&1 | grep`. It does not match
`--fixture adopter-fresh-target`, `--fixture --strict-from <dir> adopter-fresh-target` or
`--fixture <case>`. Among the manifest's `selftests` legs, only `policy fixtures` is newly matched.
Over every live spec's acceptance tokens and leg lines, no token is newly matched, so the bar join
gains no hit.
