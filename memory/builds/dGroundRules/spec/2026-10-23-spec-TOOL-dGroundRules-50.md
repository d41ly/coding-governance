(`memory/builds/dGroundRules/reviews/2026-10-23-review-TOOL-dGroundRules-35-43-spec-audit-round1.md`)

(`TOOL-dGroundRules-48`) and 11 (`TOOL-dGroundRules-49`). Id 22 is H2 seen from reuse:
`TOOL-dGroundRules-41` reads the `## Install` section of `help/policy.md` twice, once in
`adopter-fresh-target`'s parity (S1) and once in its `INSTALL_LINES` literal (AC4). The audit read
the second spelling as the one that lost its path; `TOOL-dGroundRules-41` rev-4 already spells that

twice, by two rules that each bound it, and that double read is the reuse argument. This unit is id

line, so a criterion that wants the section's content reads the case's own output, and the section
bounds are spelled once, in the case. It extends `TOOL-dGroundRules-41`, which sits at order 13, so
it builds at order 14.

## 4. Design

### Evidence

Read on 2026-10-24 at `9bcca6523`, cited by symbol, because the line numbers move.

- `run_fresh_target` in `tools/policy/check_policy.py` runs the install-day `--scaffold` and tests
  only whether `mirror deferred` is a substring of its output, at the assignment of `deferred` and
  `mirrored`; it reads no help page. `TOOL-dGroundRules-41` S1's parity is not built at HEAD, so no
  found-line index exists yet.
- The same function prints each `WRONG` as `policy-fixture: <case> · WRONG: <what>` after its target
  is removed, and its clean summary only when no `WRONG` was recorded; S1's line takes that shape.
- `help/policy.md` holds the deferral line under its `## Install` heading.
- `TOOL-dGroundRules-41` rev-4 S1 asserts that one line of the section holds both halves; it states
  the test, not whether the found line's index is kept.

### The witness

```text
adopter-fresh-target, inside TOOL-dGroundRules-41's parity:
    section = (index, line) pairs of help/policy.md after "## Install", up to the next "## "
    n = the 1-based index of the first section line holding head then tail    # the parity's find
    no n -> TOOL-dGroundRules-41's WRONG, and no witness
    n    -> print "policy-fixture: adopter-fresh-target · help/policy.md:<n> carries the deferral line"
```

The found-line index is what `TOOL-dGroundRules-41` S1's parity produces when it finds the line. Where
that unit's build keeps it, this unit reads it there. Where that build tests the section by a truth
value alone, this unit makes the same find yield the index, in place, so the page is still read once
and the section still bounded once.

### Alternatives rejected

- **A second scan of the section for the index.** A second bound beside the parity's is the double
  read id 22 names.
