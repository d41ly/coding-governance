## 1. Goal

The round-1 spec audit of this build
(`memory/builds/dGroundRules/reviews/2026-10-23-review-TOOL-dGroundRules-1-11-spec-audit-round1.md`)
exited BOUNDED with finding **id 1 at BLOCKER**, which shares item **B1** with id 31
(`TOOL-dGroundRules-14`). This unit is id 1's promotion, and it repairs `TOOL-dGroundRules-5`, so it
builds at order 4, one step after that unit.

The defect: every mirror key stores its `Resolution.reason`, and units 2 to 4 spell each reason with
the sha8 of the revision read (`set in .governance/policy.toml at 3708a705, ...`). A render at the
commit that carries the mirror therefore never matches the bytes committed, and the lander's
`commit-tree` rewrite of the merge (`tools/push-main.sh:921`) makes the landed mirror stale at
birth. `mirror --check`, the parity arm and the bar's `regen.py --check` preflight
(`tools/run-gates/run-gates.sh:1449-1458`) would then red on every commit after unit 5 lands.

This unit makes the mirror's bytes a function of what the rendered revision's tree and its
first-parent history hold, never of the rendered commit's own id. The render writes each reason's
revision phrase as the fixed placeholder `{rev}`; the helper `readPolicy` fills it with the landed
revision it read.

## 2. Scope (IN)

- **S1** — One spelling of the revision phrase. Every reason the reader builds names the revision
  it read through one field of the per-revision read that `TOOL-dGroundRules-5` §4 "The render"
  defines, `read.rev_phrase`, never by formatting the sha and how-phrase itself. `resolve` sets it
  to `<sha8>, <how>`, so `get --explain` prints exactly what it prints before this unit, and every
  reason table of units 2, 3 and 4 holds unchanged. Observed by AC3.
- **S2** — The render's placeholder. `render_mirror(repo, rev)` builds its read with
  `rev_phrase = "{rev}"`, so no reason in `.governance/policy.json` carries the rendered commit's
  sha8. A `last-valid` reason keeps the last valid revision's sha8, an ancestor the rewrite does not
  change, and names the invalid revision as `{rev}`. Observed by AC1, AC2.
- **S3** — The invariant, stated in the header comment of `render_mirror` and in
  `tools/policy/README.md`: two commits with the same policy blob, the same catalogue blob and the
  same first-parent history render byte-identical mirrors. Observed by AC2.
- **S4** — The helper fills it. `readPolicy` in `tools/policy/policy-mirror.js` returns a fresh
  mirror key's reason with each `{rev}` filled with `<L8>, the landed revision`, `L` being the
  landed sha it read; `get --explain` prints the filled reason. A fallback read through the shim is
  unchanged. Observed by AC4.
- **S5** — The case `mirror-commit-rewrite` in `CASES` of `tools/policy/check_policy.py`: in its
  temporary repository it renders the mirror at a commit, commits it, rewrites that commit with
  `git commit-tree` over the same tree and parents, and runs `mirror --check` at each. Observed by
  AC1, AC2.

## 4. Design

### Evidence

- `TOOL-dGroundRules-5` §4 Data model shows a key's reason as
  `set in .governance/policy.toml at 3708a705, ...`, and its S1 stores every key's whole
  `Resolution`. `TOOL-dGroundRules-2` §4 Data model spells every reason with the sha8 and the
  how-phrase, and `TOOL-dGroundRules-3`'s reason table writes `at <sha8>, <how>` in every row.
- `TOOL-dGroundRules-4` §4 spells a `last-valid` reason as
  `.governance/policy.toml at 9f2c41aa is invalid, line 2: ...; read from the last valid revision
  51b0e7d3: ...`, the first sha8 being the revision read.
- `--prepare` merges with `git merge --no-ff`, regenerates over the merged tree, then folds the
  result into `git commit-tree "$(git write-tree)" -p "$R" -p "$oldb"`
  (`tools/push-main.sh:881`, `:911`, `:921`). The rewritten commit has the merge's parents and
  a tree that differs only in generated outputs, so its first-parent history equals the merge's.
- The bar runs `regen.py --check` before its first leg and exits 2 on a stale output
  (`tools/run-gates/run-gates.sh:1449-1458`).

### The read and the reason

`TOOL-dGroundRules-5` splits `resolve` into a per-revision read and `resolve_read(path, row, read)`.
This unit gives the read one more field and routes every reason through it:

| Field | Set by `resolve` | Set by `render_mirror` |
|---|---|---|
| `rev_phrase` | `f"{sha[:8]}, {how}"` | the literal `{rev}` |

Each reason builder in `tools/policy/policy.py` that names the revision read takes
`read.rev_phrase`. The last-valid builder names the last valid revision by its own sha8, because
that revision is history and not the one rendered. The help page and `--explain` output do not
change, because `resolve` fills the field with the phrase the builders spelled before.

### The helper's fill

`readPolicy` already holds `L` (step 2 of `TOOL-dGroundRules-5` §4 "The reader for hooks"). On a
fresh key it returns `reason.split("{rev}").join(L.slice(0, 8) + ", the landed revision")`. A value
never carries `{rev}`; only reasons are filled.

### Inventory

| Identifier | Kind | Where |
|---|---|---|
| `rev_phrase` | field of the per-revision read | `tools/policy/policy.py` |
| `mirror-commit-rewrite` | `CASES` entry | `tools/policy/check_policy.py` |

No function is minted. Each edited function keeps its name.

### Files touched (estimate)

- `tools/policy/policy.py`
- `tools/policy/policy-mirror.js`
- `tools/policy/check_policy.py`
- `tools/policy/README.md`
- `.governance/policy.json`

### Alternatives rejected

- **Store `value` and `source` only.** Fails `TOOL-dGroundRules-5` AC1, which requires `reason` on
  every key (§8 F1).
- **Strip the sha8 after rendering with a string replace.** A last-valid reason holds two sha8s,
  and a text replace cannot tell the rendered one from the ancestor's without parsing the phrase
  back; one field set at its source is the shape the reason builders already share.
- **Render at the landed commit after `commit-tree`.** A commit cannot carry its own id, the reason
  `TOOL-dGroundRules-5` §8 F2 gives for blob ids.

## 5. Production-readiness checklist

- security — no change to what the helper trusts: a key is taken only while both blob ids match the
  landed revision, and the fill reads `L`, which the helper already resolved.
- perf / scale — none: one string field per reason, and one split per fresh read in the helper.
- error / empty / loading states — a mirror whose reason lacks `{rev}` is returned as it stands; a
  stale or absent mirror takes the shim path, unchanged.
- observability — `--explain` from either reader names an immutable sha8, the reader's the
  revision read and the helper's the landed revision.
- risks — a reason builder added later that formats the sha itself would bring the blocker back;
  `mirror-commit-rewrite` reds it, because the rewritten commit's sha8 differs.
- testing — `mirror-commit-rewrite` under `--fixture`, with AC1 to AC4.
- migration — `.governance/policy.json` is re-rendered in this unit's commit; no reader parses its
  reasons.
- user docs — N/A: the help page prints `--explain`, which this unit leaves unchanged.
