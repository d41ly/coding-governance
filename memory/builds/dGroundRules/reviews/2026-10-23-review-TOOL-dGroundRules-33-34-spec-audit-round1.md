### H1 — The source-read trace keeps bytecode-cache paths that no guard can cover (ids 1, 7, 22)

- **Where:** spec 33, §2 S2 and S4, §4 "The trace" (`path, mode = args[0], args[1] or "r"`), §6 AC3.
- **What is wrong:** S2 keeps every read-mode `open` audit event under the source top level that is outside a case temp dir. It has no tracked-file filter and says nothing about bytecode caches. `budgets-ships-join` loads `tools/govkit/govkit.py` in process through importlib (unit 23 S1, unit 34 S7). Every such load raises an `open` event in mode `'r'` for `tools/govkit/__pycache__/govkit.cpython-3XX.pyc`. The event fires on the attempt, so it fires on a cold load with no `.pyc` present. On a warm cache the load opens only the `.pyc` and never opens `govkit.py`. The `policy fixtures` guard holds `{prefix}/govkit/govkit.py` exactly. `--legs-for` prints the pyc path as `(not tracked at HEAD)` with `no guarded leg`. `.gitignore:1:__pycache__/` ignores it.
- **Consequence:** A correct build prints `guard-trace · WRONG` for the pyc on every run, so AC3 cannot pass. S4's only remedy is to add that path to the guard in `tools/gate-legs.json`. The path is gitignored and names the interpreter version, so it never appears in the runner's `git diff` and does not match on CI's Python. On a warm run the `govkit.py` read the guard exists to hold is never traced at all. Id 1 also reports the `os.open` mode-None misclassification; that defect is item M6.
- **Fix (judged sound by the skeptic):** In S2 and the §4 pseudocode, keep a path only when it is tracked at HEAD, by joining the kept set against `git ls-files` before the `--legs-for` pipe. Before that join, map each `__pycache__/<stem>.<tag>.pyc` path, and its `.pyc.<n>` temporary, to its source `<dir>/<stem>.py`, so a warm load still records the `.py` read. Forbid S4 from adding any `__pycache__` path to the guard. Add a criterion the build must run: `--fixture budgets-ships-join` twice, once cold and once with a warm `tools/govkit/__pycache__`. Both runs must keep `tools/govkit/govkit.py`, neither may keep a `.pyc` path, and neither may print a guard-trace WRONG.
- **Left-shift gate:** add a checklist entry. Any audit-hook or file-access trace states how it treats bytecode caches and untracked paths, and its criteria run once cold and once warm.

### M6 — The trace classifies `os.open` writes and failed opens as source reads (id 20)

- **Where:** spec 33, §4 "The trace" (:95, `path, mode = args[0], args[1] or "r"`), §2 S2.
- **What is wrong:** `os.open` raises the `open` audit event with mode None and carries the write intent in its flags. `args[1] or "r"` turns that None into a read. The importlib `.pyc.<n>` atomic write also arrives with mode None. A failed open of a missing file raises its event before it fails, and S2 keeps it, because S2 tests only the mode and the location. Id 1 (item H1) reports the same mode-None gap.
- **Consequence:** An in-process `os.open(..., O_CREAT|O_WRONLY)` under the source, such as govkit's lock at `govkit.py:7420`, or a probe of an absent file, becomes a guard-trace WRONG. Under S4 it becomes a guard line for a file the case writes or never found. The effect is limited to false reds and guard noise.
- **Fix (judged sound by the skeptic):** Keep an event only when `args[1]` is a str that contains none of `w`, `a`, `x` or `+`. When `args[1]` is None, decide from the flags in `args[2]`, keeping only an O_RDONLY open with no O_CREAT, O_WRONLY or O_RDWR. Optionally drop a path that does not exist after the case. State the rule in S2.
- **Left-shift gate:** add a checklist entry. An audit-hook filter names every event signature it consumes, including `os.open`'s None mode, with a criterion for each.

### M8 — S3 leaves the `--legs-for` output parse unspecified (id 27)

- **Where:** spec 33, §2 S3 (:87) and §4 "The trace" (:106, "for each kept path whose lines in out name no "policy fixtures"").
- **What is wrong:** The spec says only that `--legs-for` "prints, per path, the legs whose guard it trips". Spec 25 S25, which S3 reuses, also leaves the parse unspecified.
- **Consequence:** A builder who matches header lines to kept paths exactly finds no block for an untracked file. - **Fix (judged sound by the skeptic):** In S3, specify the parse. A header is a non-indented line, and its path is the text before an optional ` (not tracked at HEAD)`. Add a criterion in which a case reads in process an untracked source file that is under the guard, and expect no WRONG.
- **Left-shift gate:** add a checklist entry. A spec that consumes another tool's text output states that output's grammar, including suffixes and footers.
