## High

### H1 — `adopter-fresh-target` grades gov's committed HEAD, not the tree under test (ids 1, 7, 23)

- **Where:** spec 24, §2 S1 to S3, §4 Evidence and 'The case after this unit' (steps 1 to 6), §6 AC1. Spec 25 inherits it in S5 to S9 and S12, and in AC5 to AC9 and AC12.
- **What is wrong:** `govkit.py apply` lands bytes from the source repository's HEAD commit. `_cmd_apply` sets `commit = git(root, "rev-parse", "HEAD")` (govkit.py:7533) and reads each file through `blob_at(root, commit, src)` (:6706-6716, documented 'never from the working tree'). Neither spec says this.
- **Consequence:** On any bar run before a commit, the case grades the last committed policy kit. An uncommitted break in `adopt-policy.sh`, `policy.py` or `check_policy.py` reads green. Meanwhile run-gates records that green against the working tree, so the check certifies bytes it never read. In the other direction, a new uncommitted file that an include rule matches makes `apply` fail with 'does not resolve at <sha8>' (:7882-7884). A correct uncommitted change also reds, for example spec 25 S7 and AC7. CI runs at a commit, so the path is narrow.
- **Fix (judged sound by the skeptic):** State the source revision in S1 and §4. Then pick one of two options. (a) Commit the working tree under test into a scratch clone or worktree of gov and pass it as `gov_source`. (b) Have the case refuse with WRONG, naming the paths, when `git status --porcelain` over the paths the selected descriptors resolve is non-empty. Either way, add a criterion: in a scratch copy, stage a one-byte break in the installed `adopt-policy.sh`, leave it uncommitted, and assert that `--fixture adopter-fresh-target` goes red. The build must run that probe. Note from id 12: matrix.py also applies from HEAD, so moving the case there does not cure this.
- **Left-shift gate:** add a bug-class checklist entry, "test oracle read from a historical sha". It asks every spec that drives `govkit apply` from gov's own tree to name the source revision.

### H2 — The census arm treats every receipt-less target as gov's source tree (id 17)

### H3 — The writer-marker floor is read at build, before the version it names is minted (id 18)

- **Where:** spec 25, §2 S18, §5 risks and §6 AC18.
- **What is wrong:** S18 gates the `gov:fixed-writers` render on 'the version TOOL-dGroundRules-18 ships', 'read at build'. Kit versions are minted at landing, not on a branch (push-main.sh:26-31). `KIT_AGENT_CAP_VERSION` therefore still reads `1.40` (agent-cap.js:104) when this unit builds.
- **Consequence:** If the floor is read at build, it is 1.40, which is the version of every adopter hook that predates `WRITER_MARK`. Those skewed adopters get `gov:fixed-writers`, and their hook denies every `unattended-build` call. If the floor is guessed ahead (1.41), AC18 cannot hold on the branch. The minted value may also end up 1.42 or later.
- **Fix (judged sound by the skeptic):** Define the floor by feature detection: the first version whose hook source defines `WRITER_MARK`. Alternatively, have the mint write the floor through a `[[regenerate]]` row that runs after `govkit.py mint`. Re-word AC18 to stage a hook without `WRITER_MARK` rather than 'below the version TOOL-18 ships', and drop 'read at build' from §5.
- **Left-shift gate:** add a checklist entry: a spec may not key behaviour on a kit version that the lander has not yet minted.

### H4 — The first `--scaffold` refuses on any adopter repository with history (id 24)

- **Where:** spec 25, §2 S7 and AC7, read together with spec 24 §4 steps 1 to 4.
- **What is wrong:** S7 runs `policy.py mirror --write` 'whenever HEAD resolves'. It never handles `--write`'s `uncommitted changes` refusal (exit 2), which TOOL-dGroundRules-5 §4 applies whenever the policy file or the catalogue differs from HEAD. Spec 24's flow produces exactly that state: a committed target, the install staged but uncommitted, and the policy file just scaffolded.
- **Consequence:** The first `--scaffold` exits 2, so spec 24 step 4's 'exit 0 expected' cannot be met. Every real adopter hits the same failure on install day.
- **Fix (the finder's fix was judged UNSOUND; this is the skeptic's corrected fix):** `--scaffold` runs `policy.py mirror --write` when HEAD resolves. When that call refuses with `uncommitted changes` over any recorded input, S20's `legacy_blobs` keys included, `--scaffold` prints one line and exits 0. The line names the deferred mirror and the remedy: commit, then re-run `--scaffold`. The scaffold never compares inputs itself. Re-word AC7's second clause so the write of `policy.json` is asserted on the re-run after the first commit. Add a criterion: over a committed target with the install staged and uncommitted, the first `--scaffold` exits 0 and prints the deferral line.
- **Left-shift gate:** add a checklist entry: a spec that calls a verb with a refusal branch must state how that refusal propagates.
