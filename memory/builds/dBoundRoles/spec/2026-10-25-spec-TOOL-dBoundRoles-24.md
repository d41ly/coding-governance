## 1. Goal

The prompt writer points at handed facts by anchor instead of retyping them (layer-roles R3-E,
`memory/builds/dClosedLoop/build/2026-10-15-build-PLAY-dClosedLoop-1-layer-roles.md:531-535`), and
nothing checks that an anchor resolves: the framing is prose hashed into the spawn marker, and no code
reads it (`gap-roles-28`, gap register line 180). This unit checks the framing at render: every anchor
the rendered task points at must resolve to a fact the work order hands, so a planted anchor to
nothing refuses the render instead of reaching an agent that would then go and read it.

## 2. Scope (IN)

- **S1** — The anchor grammar, `ANCHOR_RE` in `tools/roles/roles_lib.py`. An anchor is a backticked
  span whose text opens with one of the three fact-key prefixes of shared interface I13, `blob:`,
  `record:` or `cmd:`. A well-formed anchor is the whole I13 key:
  `blob:<path>@<blob12>:<lo>-<hi>`, `record:<id>@<sha12>` or `cmd:<argv12>:<out12>`. A span with the
  prefix and any other shape is a malformed anchor. Observed by AC3 and AC4.
- **S2** — The check, `check_anchors(text, handed)` in `tools/roles/roles_lib.py`: one refusal line per
  anchor span in `text` that is malformed, or well-formed and absent from `handed`, the set of keys
  the work order hands. Fenced code blocks are stripped before the scan, so an example key inside one
  is never graded. It returns the lines in first-seen order, each anchor once, and writes nothing.
  Observed by AC1 and AC4.
- **S3** — The call at render. `render_handoff` (`tools/roles/handoff.py:312`), as TOOL-dBoundRoles-23
  leaves it, calls `check_anchors` over the whole `## Task` section it assembled, with `handed` the
  keys `derive_fact_key` computed for the facts that work order hands (TOOL-dBoundRoles-13), after
  every block is added and before the marker is hashed. Each refusal line joins the render's
  `refusals`, so the render raises `RolesError` naming every unresolved anchor and writes no file.
  Observed by AC2.
- **S4** — Parity between the writer of a key and the reader of an anchor. Every key
  `derive_fact_key` returns for a fact of each class fully matches `ANCHOR_RE`, so the grammar this
  unit reads and the grammar unit 13 writes cannot drift apart unseen. Observed by AC3.
- **S5** — `tools/roles/README.md` gains one paragraph under the handoff verb: an anchor's grammar,
  that the render refuses an anchor to nothing, and what the check does not see (§4). Observed by AC5.

## 4. Design

### What an anchor is, and why it is a backticked key

[trust] item 4 says a producing role "cites a handed excerpt by its key"
(layer-roles.md:263-264), and R3-E says the prompt writer "points at handed facts by anchor". The two
name one thing: an anchor is the fact's key, written where the framing refers to it. A key is code,
so the house style backticks it, and the check reads backticked spans only.

The predicate was run over the real tree first. Over the 1297 tracked files under
`memory/builds/*/prompts/` (PINNED, measured 2026-10-25 at `4283cb44`), an unbackticked token
`(blob|record|cmd):<non-space>` matched 4 lines: three are the prose `record:**` and one is this
build's brief spelling the I13 grammar. Restricted to backticked spans, the only hits are the brief's
three grammar spans, and the brief is not a rendered work order. So the backticked form has no false
red on today's corpus, and the unbackticked form would have three.

```
ANCHOR_RE   = `(blob|record|cmd):[^`]*`                 the span, prefix-detected
KEY_FORMS   = blob:<path>@<12 hex>:<lo>-<hi>            lo <= hi, both positive integers
              record:<id>@<12 hex>
              cmd:<12 hex>:<12 hex>
```

A span that opens with a prefix and fails its form is refused as malformed rather than skipped: a
skipped malformed anchor is an anchor nobody checked, which is the vacuous-selector shape.

### The check

```python
def check_anchors(text, handed):
    """One line per anchor span in text that is malformed or names no key in handed:
    'anchor `<span>` — malformed: <form expected>' or
    'anchor `<span>` — resolves to no fact this work order hands'. [] when every anchor resolves."""
```

`render_handoff` already collects refusals and raises them together (`handoff.py:329-409`), and a
refusal leaves no file behind. The anchor lines join that list, so an author sees every bad anchor in
one run, beside any key that refused for another reason.

Why the whole `## Task` section and not a framing block alone: the framing's block name is
TOOL-dBoundRoles-4's and its position TOOL-dBoundRoles-23's, and a check keyed to one block's name
breaks silently when either renames it. Checking the section gates the class. A handed fact's own
block carries its key, which resolves by construction, so the wider scope costs nothing on a correct
order. An upstream row or an input value that cites a key the order does not hand is refused too,
which is the clause's rule read strictly: an anchor that resolves to no handed fact sends the role to
read it, the reference-not-content shape gap-roles-11 measures.

### What the check does not see

- A reference without the key shape, such as "see the spec's §4", is prose and is never graded.
- Whether the fact behind a resolving anchor says what the framing claims of it.
- The `## Role` section, which is the role's static text and carries no work-order anchors.
- A span inside a fenced code block, stripped before the scan so an example key never refuses.

### Alternatives rejected

- **An anchor in its own token syntax**, such as `{{fact:<key>}}`. `render_role` refuses every
  `{{...}}` token but `{{MEMORY_ROOT}}` in a role text (`roles_lib.py:586-590`), and a second token
  grammar would be a second way to spell a key the executor already writes.
- **Checking only the prompt writer's framing block.** It depends on a block name two other units own,
  and passes an anchor placed one block over.
- **A check at spawn in the hook.** The hook cannot recompute the handed keys without the render's
  inputs, and the task-sha already pins the file it would read.

## 5. Production-readiness checklist

- security — no new write path; the check reads the text the render composed and refuses before the
  only write the render makes.
- perf / scale — one regex pass over a task section of a few kilobytes per render.
- error / empty / loading states — an empty `handed` refuses every anchor and refuses nothing in a task
  that carries none; a malformed anchor is named, never skipped.
- observability — each refusal names the anchor span and why it failed.
- risks — a block that quotes a key as an example would refuse. Examples belong in a fenced block,
  so the scan strips fenced blocks first, and AC4 pins that a fenced span is not graded.
- testing — the probes of §6, and the arm of §7 observed RED then GREEN by the main loop at the close.
- migration — none, per §4.
- user docs — `help/roles.md` gains one sentence under "How a task reaches an agent" that the render
  refuses an anchor to a fact the work order does not hand.
