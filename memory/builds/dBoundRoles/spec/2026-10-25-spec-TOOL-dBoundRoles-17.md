## 1. Goal

A work order names the item it was cut for, and a return names the work order it `answers`, so the
hop from a handoff to its return is a typed edge rather than prose (gap-roles-23: 59 of 595 handoffs
marked when measured, and a return naming its work order only in prose). Today's unmarked handoffs
and returns are a legacy population `test.seed` seeds, so the check refuses only what is written after
it arms (the memory plan's `[sites]` work-order row and its `[gates]` "work orders" arm).

### The marker regex

```python
MARKER_RE = re.compile(r"^<!-- gov:handoff role=(?P<role>\S+) build=(?P<build>\S+) "
                       r"unit=(?P<unit>\S+)(?: item=(?P<item>\S+))? path=(?P<path>\S+) "
                       r"role-sha=(?P<role_sha>[0-9a-f]{12}) task-sha=(?P<task_sha>[0-9a-f]{12}) -->$", re.M)
```

The JavaScript copy is the same with `(?<role>…)` groups and `roleSha`, `taskSha` as names; a kit
imports no sibling kit, so the two copies stay and TOOL-dBoundRoles-25 decides which file holds the
JavaScript one once the guard moves. A legacy marker's `item` reads as absent; R16 is the one place
that tells absent from `-`.

### The answers value

`derive_answers_value(path, task_sha)` returns `<path> task-sha=<task_sha>`, `path` repo-relative and
forward-slashed. `ANSWERS_RE = ^\*\*Answers:\*\* (?P<path>\S+) task-sha=(?P<task_sha>[0-9a-f]{12})$`.
R16 resolves the path, reads its marker through `MARKER_RE` and compares the `task_sha` groups. A
harness return's `answers` field is graded by the same regex body without the bold prefix.

### The legacy home

```
# work-order legacy population — seeded once by test.seed at <sha>; never re-seeded over
```

summary count as stale and never red: the seed is absent-only, and re-seeding is the laundering
