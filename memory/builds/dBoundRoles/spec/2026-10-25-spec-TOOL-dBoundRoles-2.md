## 1. Goal

Make a role's limits, its ceiling and its return data rather than prose: every limit a `never` entry
paired with the enforcer that refuses it, a ceiling of tools, write class and gate legs rendered from
the fields that grant them, and a typed `return` template in place of the prose `returns` line no code
reads. Today 58 of the 59 prohibitions in role bodies name no enforcer (gap-roles-03) and every
direct-spawn return is free text against a line nothing parses (gap-roles-04).

## 4. Design

### The schema

```toml
# tools/roles/role-schema.toml — the role kind's fields, read through roles_lib.load_role_schema only
[kind]
name = "role"

[[field]]
key = "name"
owner = "claude"
shape = "slot"
required = "every"
# ... one row per key, in this order: name description tools model maxTurns workflow reads writes
# rules mandatory output never return agent
```

| `shape` | Grammar | Keys at landing |
|---|---|---|
| `slot` | the file stem | `name` |
| `text` | one line, non-empty unless `required = "optional"` | `description`, `model`, `maxTurns`, `mandatory`, `output`, `workflow` |
| `list` | comma-separated on one line, `rules` alone may be empty | `tools`, `reads`, `rules` |
| `class` | one of `WRITES` (`check_roles.py:94`) | `writes` |
| `bool` | `true` or `false` | `agent` |
| `entries` | `;`-separated `<limit> — <enforcer>` | `never` |
| `template` | the return grammar below | `return` |

`required = "agent"` marks `tools` and `model`, which R2 demands only of an agent role, as at base
(`tools/roles/check_roles.py:193-196`). `rules` keeps its one licence to be empty through an
`empty = true` field on its row. `load_role_schema` reads the file beside the library, refuses an
absent or invalid file with an R2 `RolesError` naming it, and returns the rows; the two tuples are
derived from them at import, so the closed key set has one home.

### The never list

```
never:   edits the spec — unenforced — the spec is the design and a divergence is returned; writes a path outside ROUTED_PATHS — scratch-guard.js role arm; runs a gate leg — leg: memory hygiene
```

Each entry splits at its first ` — `. The enforcer is one of three forms, checked in this order:

| Form | Example | Graded |
|---|---|---|
| a script | `scratch-guard.js role arm`, `check_roles.py R5` | its first word ends in `.js`, `.py` or `.sh`, and a file of that name sits in the tool root or one directory under it |
| a gate leg | `leg: memory hygiene` | the name after `leg: ` is a leg of the tool root's `gate-legs.json`, checked only when the manifest reads, a note otherwise, as `load_policy` treats `[gates]` (`tools/roles/roles_lib.py:456-480`) |
| a stated absence | `unenforced — <why>` | the `UNENFORCED_RE` spelling R13 already reads (`check_roles.py:105`), its reason non-empty |

An entry with no ` — `, an enforcer of none of the three forms, a script no kit holds or a leg the
manifest lacks is one R13 line naming the role file and the entry. The stated absence is legal
because it is an honest pairing that a reader can count: the summary line prints the count of
`unenforced` entries beside the graded total, so the 58 of 59 that gap-roles-03 measured become a
printed figure rather than prose.

### The body arm

R5 gains one test, a body line matching `(?i)\b(never|do not|don't|must not)\b`. The match is a
defect naming the line number, so each limit lives in `never` and the body states the job. Gov's ten
bodies are rewritten in this unit; the count of flagged lines at base is DERIVED by the arm on its
first run, never typed here. It sees only those four words: a limit phrased otherwise ("you are not
designing in this pass") passes, said in the checker's WHAT THIS DOES NOT CHECK paragraph.

### The return template

```
return := entry ("," entry)*
entry  := name ":" type ["?"]
name   := [a-z][A-Za-z0-9-]*
type   := "text" | "sha" | "path" | "list" | "int" | value ("|" value)+
value  := [a-z][a-z0-9-]*
```

`parse_return_template(value)` returns the entries in order as `(name, type, optional)`, a closed set
as a tuple of values. A repeated name, an unknown type, a set of one value, or no required `outcome`
whose type is a closed set is an R2 defect. A name may be camel-cased so a template can spell the
fields a harness schema already returns (`alreadyPresent`, `tools/workflows/unattended-build.template.js:719`).
Gov's templates at landing, written from each role's base `returns` sentence:

| Role | `return` |
|---|---|
| `gov-builder` | `outcome:committed\|returned, commit:sha?, why:text?, checks:list` |
| `gov-spec-writer` | `outcome:done, authored:list, alreadyPresent:list, refused:list, summary:text` |
| `gov-spec-reviewer`, `gov-diff-reviewer` | `outcome:findings\|clean, findings:list` |
| `gov-skeptic` | `outcome:judged, verdicts:list` |
| `gov-synthesizer` | `outcome:reported, report:path, items:list` |
| `gov-orienter` | `outcome:oriented, card:text` |
| `gov-researcher` | `outcome:picked\|none, candidates:list, pick:text?, reason:text` |
| `gov-reuse-scout` | `outcome:seam\|none-fits, seam:path?, evidence:text` |
| `gov-session` | `outcome:sent` |

The cells escape the bar a closed set spells, which the file writes bare. The prose these replace
said what each field means; that meaning moves into the role's body, beside the job.

### The rendered block

`render_role(kit_dir, name, memory_root, gates=())` appends, after `## House rules`:

```
## Never

- edits the spec — unenforced: the spec is the design and a divergence is returned
- writes a path outside ROUTED_PATHS — enforced by scratch-guard.js role arm

## Ceiling

- tools: Read, Grep, Glob, Bash, Write, Edit
- writes: product, in ROUTED_PATHS
- gate legs: lexicon naming predicates

## Return

Return one object holding these fields, in this order: outcome (one of committed, returned); ...
```

The write class's folder is `WRITE_FOLDERS`' spelling for it (`tools/roles/check_roles.py:99-101`),
`none` rendering "writes: none". `gates` is the role's granted list, `none` when empty; the two
callers read it from `load_policy`'s `[gates]` table, the grant TOOL-dBoundRoles-21 re-points to the
role field. Both routes call this one composition, so a role reaches an agent the same way by each.

### Alternatives rejected

- **A multi-line YAML list for `never`.** The front-matter grammar refuses an indented key on purpose
  (`tools/roles/roles_lib.py:16-19`), and a second grammar for one key would be two parsers.
- **Keeping `returns` beside `return`.** Two fields stating one fact drift, and the prose one is the
  one no code reads.
- **A JSON Schema typed in the front matter.** It cannot sit on one line legibly, and the five types
  above are what every role's return needs.
