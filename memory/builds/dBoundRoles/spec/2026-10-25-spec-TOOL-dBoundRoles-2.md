## 1. Goal

Make a role's limits, its ceiling and its return data rather than prose: every limit a `never` entry
paired with the enforcer that refuses it, a ceiling of tools, write class and gate legs rendered from
the fields that grant them, and a typed `return` template in place of the prose `returns` line no
check parses. Today 58 of the 59 prohibitions in role bodies name no enforcer (gap-roles-03, PINNED at
`memory/builds/dClosedLoop/build/2026-10-14-build-PLAY-dClosedLoop-1-gap-register.md@cd15c089:155`),
and every direct-spawn return is free text against a line nothing parses (gap-roles-04).

## 4. Design

### The schema

```toml
# tools/roles/role-schema.toml — the role kind's fields, read through roles_lib.load_role_schema only
[kind]
name = "role"

[[field]]
key = "name"
owner = "claude"
shape = "slot"
required = "every"
# ... one row per key, in this order: name description tools model maxTurns workflow reads writes
# rules mandatory output never return agent
```

| `shape` | Grammar | Keys at landing |
|---|---|---|
| `slot` | the file stem | `name` |
| `text` | one line, non-empty unless `required = "optional"` | `description`, `model`, `maxTurns`, `mandatory`, `output`, `workflow` |
| `list` | comma-separated on one line, `rules` alone may be empty | `tools`, `reads`, `rules` |
| `class` | one of `WRITES` (`tools/roles/check_roles.py@abcde1da:110`) | `writes` |
| `bool` | `true` or `false` | `agent` |
| `entries` | `;`-separated `<limit> — <enforcer>` | `never` |
| `template` | the return grammar below | `return` |

`required = "agent"` marks `tools` and `model`, which R2 demands only of an agent role, as at HEAD
(`tools/roles/check_roles.py@abcde1da:210-213`). `rules` keeps its one licence to be empty through an
`empty = true` field on its row. `load_role_schema` reads the file beside the library, refuses an
absent or invalid file with an R2 `RolesError` naming it, and returns the rows; the two tuples are
derived from them at import, so the closed key set has one home.

The item schema's rows name their field `name`, and `tools/playbook/overlay_rows.py#read_kind_schema`
reads it there. This file's rows name it `key`, the spelling its consumers' specs write
(TOOL-dBoundRoles-15, TOOL-dBoundRoles-20, TOOL-dBoundRoles-43). The `kind.role` row gains no
`schema` here, and this file joins that reader only when TOOL-dBoundRoles-20 S2 registers it.

### The never list

```
never:   edits the spec — unenforced — the spec is the design and a divergence is returned; writes a path outside ROUTED_PATHS — scratch-guard.js role arm; runs a gate leg — leg: memory hygiene
```

Each entry splits at its first ` — `. The enforcer is one of three forms, checked in this order:

| Form | Example | Graded |
|---|---|---|
| a script | `scratch-guard.js role arm`, `check_roles.py R5` | its first word ends in `.js`, `.py` or `.sh`, and a file of that name sits in the tool root or one directory under it |
| a gate leg | `leg: memory hygiene` | the name after `leg: ` is a leg of the tool root's `gate-legs.json`, checked only when the manifest reads, a note otherwise, as `load_policy` treats `[gates]` (`tools/roles/roles_lib.py@a3e28716:680-708`) |
| a stated absence | `unenforced — <why>` | the `UNENFORCED_RE` spelling R13 already reads (`tools/roles/check_roles.py@abcde1da:121`), its reason non-empty |

An entry with no ` — `, an enforcer of none of the three forms, a script no kit holds or a leg the
manifest lacks is one R13 line naming the role file and the entry. The stated absence is legal
because it is an honest pairing that a reader can count: the summary line prints the count of
`unenforced` entries beside the graded total, so the gap-roles-03 figure becomes a printed count,
DERIVED by each run, rather than prose.

The script form reads the install, so gov's own entries name only an enforcer every default install
holds. A script is one the roles kit or a kit of the registry's `default` list ships
(`tools/govkit/registry.toml`, whose list carries `agent-cap`, the home of `scratch-guard.js` and
`agent-cap.js`). A leg is one whose kit that list carries, since govkit's runner install
(`tools/govkit/selftest.py#check_roles_install`) runs `check_roles.py` at exit 0 over a manifest of
the installed kits' legs. An adopter that installs the roles kit without `agent-cap` reds R13 on each
gov entry naming its script: the enforcer that entry claims is absent there.

### The body arm

R5 gains one test, a body line matching `(?i)\b(never|do not|don't|must not)\b`. The match is a
defect naming the line number, so each limit lives in `never` and the body states the job. Every gov
body under `tools/roles/agents/` is rewritten in this unit; the count of flagged lines at HEAD is
DERIVED by the arm on its first run, never typed here. It sees only those four words: a limit
phrased otherwise ("you are not designing in this pass") passes, said in the checker's WHAT THIS
DOES NOT CHECK paragraph.

### The return template

```
return := entry ("," entry)*
entry  := name ":" type ["?"]
name   := [a-z][A-Za-z0-9-]*
type   := "text" | "sha" | "path" | "list" | "int" | value ("|" value)*
value  := [a-z][a-z0-9-]*
```

`parse_return_template(value)` returns the entries in order as `(name, type, optional)`, a closed set
as a tuple of values, one value legal (§8 F6). A bare word that is none of the named types is a
one-value set, so `outcome:done` reads `('done',)`. A repeated name, a value named twice in one
set, an empty set, or no required `outcome` whose type is a closed set is an R2 defect. A name may be
camel-cased so a template can spell the fields a harness schema already returns (`alreadyPresent`,
`tools/workflows/unattended-build.template.js@55695bb4:800`). Gov's templates at landing, written
from each role's `returns` sentence at HEAD:

| Role | `return` |
|---|---|
| `gov-builder` | `outcome:committed\|returned, commit:sha?, why:text?, checks:list` |
| `gov-spec-writer` | `outcome:done, authored:list, alreadyPresent:list, refused:list, summary:text` |
| `gov-spec-reviewer`, `gov-diff-reviewer` | `outcome:findings\|clean, findings:list` |
| `gov-skeptic` | `outcome:judged, verdicts:list` |
| `gov-synthesizer` | `outcome:reported, report:path, items:list` |
| `gov-orienter` | `outcome:oriented\|placed, card:text?, disposition:text?, reason:text?, evidence:text?, observations:text?, scenarios:text?, facts:text?` |
| `gov-researcher` | `outcome:picked\|none, candidates:list, pick:text?, reason:text` |
| `gov-reuse-scout` | `outcome:seam\|none-fits, seam:path?, evidence:text` |
| `gov-session` | `outcome:sent` |
| `gov-tester` | `outcome:code-miss\|spec-wrong\|answered, evidence:text, answer:text?` |

The cells escape the bar a closed set spells, which the file writes bare. The prose these replace
said what each field means; that meaning moves into the role's body, beside the job.

The orienter's `returns` gained its placement half after base, at `c64f7c3e6`
(TOOL-dPlacedRequest-4): "handed a request to place, its disposition · reason · evidence ·
observations · scenarios · facts", the scout's return whose keys `tools/loop/placement.py#RETURN_KEYS`
closes. `placed` is that act's outcome, and each placement field is optional `text`, since a
disposition's closed set is the loop definition's and is not copied here. The body says which fields
each outcome carries, as it does for the tester's `answer` (§8 F4).

### The rendered block

`render_role(kit_dir, name, memory_root, gates=())` appends, at the end of the role, after the body
and its `## House rules` when the overlay is non-empty (`tools/roles/roles_lib.py#render_role`):

```
## Never

- edits the spec — unenforced: the spec is the design and a divergence is returned
- writes a path outside ROUTED_PATHS — enforced by scratch-guard.js role arm

## Ceiling

- tools: Read, Grep, Glob, Bash, Write, Edit
- writes: product, in ROUTED_PATHS
- gate legs: lexicon naming predicates

## Return

Return one object holding these fields, in this order: outcome (one of committed, returned); ...
```

The write class's folder is `WRITE_FOLDERS`' spelling for it
(`tools/roles/check_roles.py@abcde1da:115-117`), `none` rendering "writes: none". `gates` is the
role's granted list, `none` when empty; the callers read it from `load_policy`'s `[gates]` table, the
grant TOOL-dBoundRoles-21 re-points to the role field. `render_agent_file` and `run_mode` take it from
the catalogue's loaded policy, and `render_handoff` loads the policy through `load_policy`, as
