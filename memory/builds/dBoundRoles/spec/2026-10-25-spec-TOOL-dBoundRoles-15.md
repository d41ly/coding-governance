## 1. Goal

A role agent's charter blocks reach it once per spawn: from the file its backend loads, and from its
task only where the backend loads none, the choice read from `instructions.task-charter` and the
harness kind, and `always` refused where it would carry the charter twice (gap-roles-19). The static
block's budget is measured over the whole rendered block, its `## Charter` included, so a charter
block that pushes a role over its ceiling is seen (gap-roles-20).

## 4. Design

### The harness kind

`derive_harness_kind(keys, stand_in)` in `roles_lib.py` reads what loads the role's charter at spawn,
and returns the kind and that file, the carrier:

| Route | `agent` | Kind | Carrier | Why |
|---|---|---|---|---|
| `Agent` call with `subagent_type` the role | `true` | `static` | `.claude/agents/<slot>.md` | Claude Code loads the agent file, whose body is S1's block |
| `handoff.py render --stand-in` | either | `static` | the charter file `resolve_charter_path` names | the main loop does the work, and Claude Code loads the charter at level 0 every session (PLAY-dOrderedCharter-5 F2) |
| any render of an `agent: false` role | `false` | `static` | the charter file | the same main loop; no agent file renders for it (`tools/roles/render_agents.py#run_mode` renders only `agent` true) |

`inline` is a backend that loads neither file, which no route of today's one adapter derives. Today
only Claude Code exists as an adapter, so the route decides the carrier. The hand-over is the
adapter's own flag: once dWellOiledMachine registers a second adapter, its row says whether it loads a
static block, and this function reads that row instead of the route.

### The single carry

| `instructions.task-charter` | `static` | `inline` |
|---|---|---|
| `when-not-static` (default, `tools/policy/catalogue.toml@25076c3d:1501`) | no charter block in the task | charter blocks in the task |
| `always` | refused, `RolesError`, exit 1 | charter blocks in the task |

The refusal line: `instructions.task-charter is always, and <role> loads the charter from <carrier>:
the charter would reach the agent twice; set when-not-static`. Over gov at base, 48 of 60 handoffs
carried the duplicate, median 2,880 B (PINNED, scout A's reading of
`research-instruction-writing-b.md:210`); PLAY-dOrderedCharter-5 S3 removed it, and this check keeps
a policy value from putting it back.

With no policy kit found, `read_policy_setting` yields `None` and its one note (TOOL-dBoundRoles-21
S1), and the render prints one note beside it, `handoff: note — instructions.task-charter unread: no
policy kit; the single carry takes when-not-static`, and proceeds under that value (§8 F2). A reader
exit 2 is `read_policy_setting`'s `RolesError`, which refuses the render with the reader's line.

### Pricing

Each role's `budget` is its `BODY_CEILINGS` row plus its measured charter block, with no rounding
(§8 F3). The charter block is every byte the whole block holds beyond `render_role`'s output: the
`## Charter` heading, the blocks, and, where the registry reads, the envelope lines. So the headroom
left over the rendered role is exactly what the load-set check grants today, which measures
`render_role`'s bytes against the same row (`tools/roles/render_agents.py#run_mode`,
PLAY-dOrderedCharter-11 S4), the tighter of today's two measures, since the rendered role adds the
house overlay to R5's base body. Measured over gov at `a01362eb` on 2026-11-22, ranked as gov renders
(PINNED; the pass re-derives every row with `render_static_block` and prices every role present then,
