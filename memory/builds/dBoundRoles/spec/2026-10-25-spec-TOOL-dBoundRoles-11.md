## 1. Goal

P18 makes the decision principles outrank practices in an unattended fork: the role that meets a fork
resolves it by the most feature-rich option, then the most expandable, among the options the core
admits, with a full record, and `run.on-owner-question` lets the owner choose to hold instead (v2:907-913,
v2:1231). Today a resolved fork is a mark naming its resolver and nothing else: `check_mark` reads
`RESOLVED (agent, <date>, delegated)` (`tools/memory-tree/check-memory-hygiene.sh:1854`) and no record
names the admitted options, their ranking or the pick, so a pick outside the admitted set, or one
that is not the ranking's first, passes. No reader of `run.on-owner-question` exists, and `--dispatch`
admits a FORKED unit. This unit lands the record and its grade, the key and its one reader, and the
hold at the one admission point.

## 4. Design

### The record

```
- **F2 — <question>** <options and tradeoffs> RESOLVED (agent, 2026-10-25, delegated): (a), rung 3.
  options: (a) > (c) > (b) · pick: (a) · admitted-by: principle.p18 · widens: none · relaxes: none
```

The tail is read from the F-item span as check 12 already builds it: lines joined, whitespace
squeezed, code spans and double-quoted spans removed (`check_span_mark`, `check-memory-hygiene.sh:1856`),
so a record quoted as an example records nothing, exactly as a quoted mark resolves nothing.

```
record   = "options: " opt { " > " opt } " · pick: " opt " · admitted-by: " tag
opt      = one or more characters, none of them the separators " > " or " · "
tag      = "principle." seg, the registry's own tag grammar
```

The ranking is the order of `options`. A one-option record (`options: (a) · pick: (a)`) is legal: one
option surviving the vetoes is a ranking of one. The README's `widens:` and `relaxes:` fields follow
the tail and are not read by this grade.

### Why only `agent` marks

v2's P18 binds the role that meets the fork; the owner resolving a fork is the owner's choice, and an
`(owner, …)` mark already names that resolver (`memory/TEMPLATE-SPEC.md:155-160`). Grading an owner pick
against a ranking would make the gate the owner's judge.

### The two readers, one grammar

`check_mark` and the planning verb's `plan_state` already spell the mark twice, and the marker-contract
suite is what proves they agree (the comment at `check-memory-hygiene.sh:1849-1853`). The record joins
that pair the same way: one more row in the contract table, one more predicate in each reader, and
`plan_state` reading FORKED for a failing record, so `--dispatch`'s new FORKED case sees exactly what
the hygiene gate sees.

### The admitted set

"Only options the core admits are options" (v2:907-913). The record cannot prove an option was
admissible; it names what admitted the set, and the grade checks that the name is a real principle.
The registry is read from `tools/playbook/principles.toml`; when the file is absent, as at base, the
grade checks the tag's shape and prints one `note` line naming the absent registry, never green
silence.

### The reader

```python
def resolve_owner_question(kind, attended, repo, rev="HEAD"):
    """'resolve' | 'park-item' | 'park-build' | 'stop-run' | 'owner', read once through resolve()."""
```

| kind | owner attends | owner away |
|---|---|---|
| `fork`, `owner-gate` | `owner` | the key's value, `best-effort-recorded` answered as `resolve` |
| `ratification`, `owner-write` | `owner` | `owner` |

`--attended` is the caller's to pass: an attended session has no run-state file, and the driver passes
it there. The shell door exists because the driver is bash and the roles library is Python; it is a
thin adapter that prints the function's answer and holds no logic, so the rule lives once.

### The hold

`--dispatch` refuses MISSING and THIN at `tools/unattended/unattended.sh:13606-13616` and admits a
FORKED unit today, though M2 sends FORKED to M3 before any code. The new case reads the reader once per
dispatch. A `park-item` answer writes one `decision` row, `<ts> decision · item <unit> · reason open
fork <F-ids> held by run.on-owner-question`, through the existing `park`, whose kind is already in
`PARK_KINDS` and `PARK_KINDS_OWED` (:875, :893), so the close owes the owner that row as it owes every
parked decision.
