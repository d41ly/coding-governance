## 1. Goal

RL-1 merged the two reviewer roles into one reviewer with a lens per step. TOOL-dBoundRoles-1 ships it
as `gov-reviewer` and merges gov's own catalogue (its S3 and §4 "The merge"). This unit ships the
merge's own upgrade step (P38), so an adopter gets the same merge on `govkit update`. Its rendered
`gov-spec-reviewer` and `gov-diff-reviewer` agent types become `gov-reviewer`, its role index
`.claude/roles.json` is re-rendered, and every key that spells an old stem is re-keyed: policy rows,
house overlays and overlay `select` values. Every workflow stage keeps the effort it ran at. Gov runs
the step on its own tree first, where it finds the merge already done. `gov-session` is not touched:
its retirement moved to Runtime (the night pass two's point 4, the owner's NT-21; brief D3).

## 4. Design

### The step row

```toml
# tools/roles/kit.toml, after every [[upgrade]] row already in the file
[[upgrade]]
id = "roles/reviewers-to-gov-reviewer"
up = ["python", "{gov}/govkit/steps/reviewer_merge.py", "up", "{target}", "{prefix}"]
down = ["python", "{gov}/govkit/steps/reviewer_merge.py", "down", "{target}", "{prefix}"]
witness = ["python", "{gov}/govkit/steps/reviewer_merge.py", "witness", "{target}", "{prefix}"]
surfaces = ["agent:gov-spec-reviewer", "agent:gov-diff-reviewer",
            "installable:{prefix}/roles/agents/gov-spec-reviewer.agent.md",
            "installable:{prefix}/roles/agents/gov-diff-reviewer.agent.md"]
needs-target = true
```

`surfaces` names every member TOOL-dSafePassage-10's step gate reads as vanished when the two role
files leave: the `agent` class reads each stem of a tracked `tools/roles/agents/<name>.agent.md`, and
the `installable` class reads each installed destination (its §4 class table). Where
TOOL-dBoundRoles-20's `role` step-gate class exists at the build run's base, the row also names
its member for each of the two `role.<slot>` tags, spelled as that class's reader names a member
(§8 F4). Where this landing also removes the two house seeds, the row names their `installable`
members too. TOOL-dBoundRoles-1 removes the files in the same landing, and this row is the witness
the step gate reads for them. `needs-target` is true because the `up` runs the target's own
`render_agents.py` and `policy.py`.

### The program

`reviewer_merge.py <verb> <target> <prefix>`, imported helpers taken from `upgrade_steps.py` by its
own file's path, as TOOL-dSafePassage-1 §4 requires under the runner's `-I`.

**up.** With no old stem in any carrier and no old type under `.claude/agents`, it exits 0 and writes
nothing. Otherwise:

1. It reads every carrier and computes every write before touching a file. A conflict under S5, or a
   carrier differing from its blob at HEAD, exits 1 and writes no byte.
2. It writes the before-image `.governance/steps/roles/reviewers-to-gov-reviewer.before.json`,
   covering every path it will write or remove: the house file, `.governance/policy.toml`,
   `.governance/instructions.toml`, the three types under `.claude/agents`, `.claude/roles.json`,
   any old stem's house text file with `house/gov-reviewer.md`, and the two old role files under
   `<prefix>/roles/agents/`.
3. It re-keys the house file, the policy file and the overlay, and carries any old house text (S6).
   The policy file goes through `render_policy_text`, gaining an unset mode in this unit, and the
   overlay through the value edit below.
4. It removes the two old role files from `<prefix>/roles/agents/` where an update left them for a
   later withdrawal. They are engine files gov no longer ships, and the render would otherwise render
   them again. Govkit's withdrawn arm then finds them gone.
5. It runs `python <prefix>/roles/render_agents.py --write` in the target.

**down.** It restores every path from the before-image under TOOL-dSafePassage-1's rule: a path whose
bytes are neither the image's after-hash nor its before bytes stops the down, exit 1, naming it.

**witness.** It exits 0 when four things hold. No carrier spells an old stem. No type of either stem
is under `.claude/agents`. `.claude/roles.json` lists neither stem. Where the target installs the
roles kit, the index lists `gov-reviewer`. A target with no roles kit and no carrier is applied by
definition.

### Effort

The house file today maps each slot to a level (`tools/roles/house/policy.toml:8-15`, `gov-spec-reviewer
= "medium"`, `gov-diff-reviewer = "high"`). `resolve_stage_efforts` (`tools/roles/roles_lib.py:571-576`)
gives each stage its `[effort.stages.<workflow>]` entry, else its slot's level. The shipped seeds
already differ, so one role entry would move one stage's level on every default install.

Per carrier, the `up` applies the rule TOOL-dBoundRoles-1 §4 "The merge" applies to gov's seed, so
an adopter's file ends in the shape a new install receives:

1. it records, for every workflow entry and every stage whose role is an old stem, the level that
   carrier's resolution gives it;
2. it removes the old stems' role entries or keys, and, where no `gov-reviewer` entry exists, writes
   one at the higher of the two old levels by `EFFORT_LEVELS` order (`tools/roles/roles_lib.py:45`);
3. it resolves every such stage again with the stage now mapped to `gov-reviewer`, and writes a stage
   entry with the recorded level wherever the two differ and no stage entry was set.

The house file gains `[effort.stages.<workflow>]` rows, and the policy file gains
`roles.effort.<workflow>.<stage>` keys (brief I9). Over the old seed the result is TOOL-dBoundRoles-1's:
`gov-reviewer = "high"`, with `specFinder = "medium"` under `spec-review` and `spec-write`. A direct
spawn of `gov-reviewer` takes the role entry.

### Re-keying the other keys

The `<role>` families are read from `tools/policy/catalogue.toml`: every catalogue `name` holding a
`<role>` segment, through TOOL-dGroundRules-2 S4's `read_catalogue_row`, so a family a later build adds
is re-keyed without an edit here. The catalogue's other placeholders are kept as they are. Values are
compared as parsed TOML, never as text.

The overlay edit is a value edit. It parses the file with `tomllib`, replaces each quoted string
exactly equal to an old tag, parses again, and refuses its own output unless the two documents are
equal once the mapped values are mapped. A comment or a key is never edited.

### Gov's tree

TOOL-dBoundRoles-1 removes the two role files, re-keys `tools/roles/workflows.toml`,
`tools/roles/house/policy.toml`, `tools/roles/kit.toml`'s seed list and `BODY_CEILINGS`, and
re-renders the agent types, the index, the README's catalogue region and `AGENTS.md`'s roster. This
pass runs the `up` on gov's tree, which must be the no-op exit, and the `witness`, which must exit 0.
Then it runs AC7's grep. A hit outside this unit's files is returned to the main loop as
TOOL-dBoundRoles-1's defect, never fixed here, so this pass's write set stays its own.

### Migration

The step is the migration. A target whose receipt predates TOOL-dBoundRoles-1 reaches it through the
walk. A fresh install never holds an old stem, so its `up` is the no-op exit.

### Rollout

Live at the landing. A session started before an adopter's update keeps the old agent types it
loaded until it restarts. The harness reads `.claude/agents` at session start
(`memory/gotchas/settings-edit-takes-effect-mid-session.md` is the same class for settings).

### Files touched (estimate)

- `tools/govkit/steps/reviewer_merge.py` (new)
- `tools/govkit/upgrade_steps.py` (the unset mode)
- `tools/govkit/selftest.py`
- `tools/roles/kit.toml` (the `[[upgrade]]` row)
- `help/roles.md`

### Alternatives rejected

- **One role entry carrying the higher of the two levels, with no stage entries.** It raises the spec
  reviewer's stages on
  every default install, and the lower would cut the diff reviewer's (§8 F2).
- **A `[[retired]]` row per old stem.** That row's grammar admits an entry id or a step id only (§8 F4).
- **Leaving the old keys beside the new.** A key for a role the catalogue no longer holds is a second
  answer to one question, and R12 reads it as an unknown slot.

## 5. Production-readiness checklist

- security — no grant widens. A gate grant or any other `<role>` key whose two values differ stops
  the step with nothing written (S5). The policy file is written only through `render_policy_text`,
  which reads its own output back.
- perf / scale — one pass over three small files and one render, once per target.
- error / empty / loading states — no old stem: exit 0. A conflict, a carrier edited since HEAD or an
  unreadable carrier: exit 1 naming it, nothing written. A down over a later edit: exit 1 naming the
  path.
- observability — each verb prints one line per carrier it re-keyed or skipped, and the witness names
  the first carrier still spelling an old stem.
- risks — an adopter whose two reviewers held different grants must act before the update completes;
  that stop is the price of never widening one. A spelling TOOL-dBoundRoles-1 left in gov's tree is
  reported by AC7, not fixed here. A carrier added by a later build that spells a slot
  outside the `<role>` families is not re-keyed; the witness names it.
- testing — the selftest cases of §7's arm, each on a scratch target, observed by a pass running
  `python tools/govkit/selftest.py` filtered to its cases. The arm is observed RED then GREEN by the
  main loop at the close.
- migration — the step itself, as §4 Migration says.
- user docs — `help/roles.md`, S8.
