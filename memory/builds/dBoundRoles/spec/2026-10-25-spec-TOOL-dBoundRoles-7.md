## 1. Goal

A role agent's Bash or PowerShell write reaches no write gate today: the hook's header says so ("a
Bash or PowerShell write (`sed -i`, an interpreter, a redirect) is never seen",
`tools/hooks/scratch-guard.js:85-87`), and 66 typed-role shell writes passed the role arm after it
landed (gap-roles-03, gap register `:155`). This unit holds every shell write a role agent makes to the
same verdict an `Edit` or `Write` of that target would get, and, where the agent's work order hands an
`allowance`, to that allowance as well. The scanner that finds shell write targets is widened to the
shapes that were measured escaping it: `sed -i`, an interpreter's write call and `git apply`
(research-roles-coverage P4, `:105`).

## 2. Scope (IN)

- **S1** — `scanWriteTargets` (`scratch-guard.js:339-384`), the one shell write-target scanner, gains
  three shapes, each target carrying its `why`: the file operands of `sed -i` and `sed --in-place`
  (and of `perl -i`); the first string-literal argument of an interpreter's write call inside a
  `python`, `python3` or `py` `-c` body, a `node -e` body, or the heredoc body of `python -`,
  `python3 -` or `node`, the calls being `open(<lit>, "w"|"a"|"x"…)`, `Path(<lit>).write_text(`,
  `Path(<lit>).write_bytes(`, `writeFileSync(<lit>` and `appendFileSync(<lit>`, plus PowerShell's
  `[IO.File]::WriteAllText(<lit>`, `WriteAllBytes(<lit>` and `AppendAllText(<lit>`; and each path a
  `git apply` patch names on a `+++ b/<path>` or `rename to <path>` line, read from the patch file
  operand resolved against the payload `cwd` or from the command's own heredoc body. Observed by AC1,
  AC2 and AC3.
- **S2** — `checkCommand` (`:500-528`) reads the same scanner, so its temp, home and drive-root rules
  see the three shapes too, with no second scanner. Observed by AC8.
- **S3** — `checkShellWrites(cmd, data, env)`, a third Bash and PowerShell check in `main`
  (`:1529-1611`), run after `checkRoleGate` and only for a payload carrying an `agent_type`. Each target
  S1 finds is resolved against the payload `cwd`; a target in no repository, or in one that is not the
  session's, is not this check's. Every other target is judged by `checkRouted` (`:1113`) on a
  synthetic `Write` payload carrying the target as `tool_input.file_path` and the payload's `cwd`,
  `session_id` and `agent_type`, so the route arm, the role arm and TOOL-dBoundRoles-9's step 6b with
  its `classes` map class the shell target exactly as they class an `Edit`. Observed by AC4 and AC7.
- **S4** — The allowance. `readWorkOrderAllowance(data)` locates the agent's work order as it was
  spawned: the agent transcript `<session dir>/subagents/agent-<agent_id>.jsonl`, else
  `<session dir>/subagents/workflows/<run id>/agent-<agent_id>.jsonl`, the session dir being the
  payload's `transcript_path` without `.jsonl`, and `agent_id` and each run id admitted only in the
  shape `[A-Za-z0-9_-]{1,64}`; its first `user` record is the prompt, and the `allowance` block of that
  prompt's `## Task` section is the allowance, a list of repo-relative prefixes in the `ROUTED_PATHS`
  grammar (shared interface I12). When it is found, a target the class verdict admits is admitted only
  when it lies under one entry; an empty list admits no repository write. When no block, no transcript
  or no readable first record is found, the class verdict of S3 stands alone and one witness line
  names why. Observed by AC5 and AC6.
- **S5** — `matchRoutedEntry(rel, entries)`, the one matcher of a repo-relative path against a list in
  the `ROUTED_PATHS` grammar (a trailing `/` meaning the folder and everything under it, any other entry
  the exact path), extracted from `checkRouted`'s inline `entry` search (`:1163-1166`) and called by
  both that search and S4, so the two never disagree on what an entry covers. Observed by AC5.
- **S6** — Fail-closed for a role agent: a throw in `checkShellWrites` refuses the call, as the
  role-gate arm's throw does (the catch at `:1604`); the main loop is never refused by this check.
  Observed by AC7.
- **S7** — Every refusal names the command's target, the shape that wrote it, the verdict `checkRouted`
  gave or the allowance it fell outside with the work order it came from, and the remedy's actor: the
  driver, which re-scopes the work order or routes the write to a role whose class covers it.
  Observed by AC4 and AC5.
- **S8** — The hook's header paragraph "WHAT ESCAPES THE WRITE GATE" (`:85-90`) and
  `tools/hooks/README.md`'s section on what the guard cannot see (`:556`) state what is now held and
  what still escapes (§4 "What it does not check"), and the user page `help/roles.md` amends its
  sentence that the hooks "do not see writes made through Bash or PowerShell" (`:116-118`) to say a
  role agent's are held. Observed by AC9.

## 3. Non-goals (OUT)

- The main loop's shell writes. The driver's shell is bound by its act's allowance in
  dWellOiledMachine's act binding (`layer-runtime.md:530-531`); a payload with no `agent_type` meets
  only `checkCommand` and `checkOriented`, as at base, and the push-time leg keeps that guarantee.
- The work order and its `allowance` block: TOOL-dBoundRoles-3 renders both. This unit reads the block
  as that unit spells it (§8 F2).
- An `Edit` or `Write` held to the allowance. The clause is the shell; the tool-call write gate's own
  allowance join is not this unit's.
- A write a script makes from inside a file it runs (`python tools/x.py`), a write through a variable
  the command computes, `rm`, `git checkout -- <path>`, `git stash` and every other shape S1 does not
  name: the hook "stops forgetting, not evasion" (`scratch-guard.js:85`), and §4 lists them.
- The write classes and their map: TOOL-dBoundRoles-9's.

### Edges

- **consumes-from** `TOOL-dBoundRoles-3` — the work order's `allowance` block in the `## Task` section of each rendered prompt, which S4 reads; without it every role agent is held to its class alone
- **consumes-from** `TOOL-dBoundRoles-9` — the index's `classes` map with `checkRoleClass` and `matchWriteClass`, through `checkRouted`'s step 6b; without it a `none` or `review` role's shell write outside spec and product paths is admitted as at base
- **hands-off** `TOOL-dBoundRoles-43` — `readWorkOrderAllowance`, which unit 43 holds to one unfenced `### allowance` heading, reads whole and re-points to the shared session layout (ids 41, 54 and 59 of the round-1 spec audit)

## 4. Design

### The evaluation order

```
checkShellWrites(cmd, data, env)
 1. agent_type absent or empty                       -> null   (the main loop: not this check's)
 2. scanWriteTargets(cmd) finds no target            -> null, no file read
 3. each target, resolved against the payload cwd:
    a. in no repository, or not the session's        -> skip   (checkCommand's rules own it)
    b. v = checkRouted({ tool_name: "Write", tool_input: { file_path: target },
                         cwd, session_id, agent_type }, env)
       v.deny                                        -> deny, S7's text around v.deny
    c. allowance = readWorkOrderAllowance(data)      (read once per call)
       found, and matchRoutedEntry(rel, allowance) false -> deny, naming the allowance
 4. any target skipped at 3c for want of an allowance -> one witness line naming why
```

The synthetic payload carries no `content`, so `checkStatusOnlyEdit` cannot prove a status-only flip and
a shell edit of a spec by a role outside the spec class is refused; the one admitted flip stays the
`Edit` route (`scratch-guard.js:1075-1083`).

### The allowance as the hook reads it

The prompt a role agent was spawned with is its transcript's first `user` record: rule 6 of
`tools/hooks/agent-cap.js` admits a direct spawn only when that prompt is the marker line and the
`## Task` section of its prompt file byte for byte, with its task-sha verified
(`agent-cap.js:2089-2148`), so the transcript holds the admitted work order and the hook needs no copy
of the marker grammar. The layout was read on this node at 2026-10-25: a direct spawn's transcript is
`subagents/agent-<id>.jsonl` beside a `.meta.json`, its first record a `user` record whose content opens
with the `gov:handoff` marker, and a harness agent's is under `subagents/workflows/<run id>/`. A hook
payload carries `transcript_path` and, inside a subagent, `agent_id` (the probe records
`memory/builds/aOrientedCast/build/2026-10-11-build-TOOL-aOrientedCast-3-agent-type-probe.md:48-51`).

The block S4 reads, in the spelling TOOL-dBoundRoles-3's §4 "The blocks" states at its rev-1, one
prefix per `- ` bullet, a backtick pair around an entry stripped if present:

```
### allowance

- tools/hooks/
- tools/hooks/README.md
```

Only an allowance narrows: a target the class verdict refuses is refused whatever the block says, so a
harness prompt that carried a wider block gains nothing.

### What it does not check

Stated in S8's two places: a write from inside a script file the command runs; a target computed at
run time (a variable, `os.path.join`, a glob); a heredoc fed to an interpreter the S1 list does not
name; `rm`, `mv` of a file out of a folder, `git checkout`, `git restore`, `git stash`, `git merge` and
`git am`; a patch read from a pipe; and a transcript an agent rewrites, since the transcript lives
outside the repository and the guard stops forgetting, not evasion.

### Inventory

Minted: `checkShellWrites`, `readWorkOrderAllowance`, `matchRoutedEntry`; the three `why` values
`sed -i`, `interpreter write` and `git apply`; the fixture plants of §7's arm (`sed-in-place`,
`py-write`, `node-write`, `ps-write`, `git-apply-file`, `git-apply-heredoc`, `none-role-shell`,
`allowance-in`, `allowance-out`, `allowance-absent`, `home-sed`). Each function name is asked of
`python tools/lexicon/lexicon.py --suggest <name> --as js.function` at the pass, and each joins
`module.exports`.

### Migration

None: no stored state. A role agent whose work order carries no allowance block is held to its class,
which is what an `Edit` already meets.

### Rollout

Live at landing in the hooks kit; no switch. The newly refused population is shell writes a role's
`Edit` of the same target would already have been refused.

### Files touched (estimate)

- `tools/hooks/scratch-guard.js`
- `tools/hooks/scratch-guard.test.sh`
- `tools/hooks/README.md`
- `help/roles.md`

### Alternatives rejected

- **A second classing routine for shell targets.** Two orders that must agree are the defect
  `checkRouted`'s "THE ONE EVALUATION ORDER" comment exists to prevent; the synthetic payload reuses it.
- **Reading the allowance from the prompt file the marker names.** It needs the marker grammar in this
  hook, a third copy beside `MARKER_RE` and `HANDOFF_MARK_RE`; the transcript holds the same bytes rule
  6 verified.
- **Refusing an unplaceable target.** Every interpreter call with a computed path, including each
  role's own scratch writes, would refuse.

## 5. Production-readiness checklist

- security — narrows the write surface: a role's shell write meets the verdict its `Edit` meets, and its
  work order's allowance where one is handed; a transcript path is built only from ids in a fixed shape.
- perf / scale — the transcript's first record is read once per typed Bash call that writes into a
  repository, bounded to its first 256 KB; a call writing nothing reads no file.
- error / empty / loading states — no transcript, no first record or no block each fall back to the
  class verdict with one witness line; a throw refuses a role agent (S6).
- observability — each refusal names target, shape, verdict and the remedy's actor (S7).
- risks — a role whose legitimate work shells a write outside its class is refused; the class is the
  one its `Edit` already meets, so the work had no sanctioned route at base either.
- testing — the plants of §4's inventory through `node -e` over a fixture repository; the suite arm in
  §7 is observed RED then GREEN by the main loop at the close.
- migration — none.
- user docs — `help/roles.md` and `tools/hooks/README.md` (S8).

## 6. Acceptance criteria

Each criterion runs the exported functions of `tools/hooks/scratch-guard.js` through `node -e`, over a
fixture repository made under `%TEMP%` with `git init`, a `.memory-tree.conf`, a rendered
`.claude/roles.json` and, where named, a fixture agent transcript.

- **AC1** — When `scanWriteTargets` reads `sed -i 's/a/b/' a.py`, it returns `a.py` with `why`
  `sed -i`; reading `sed 's/a/b/' a.py`, it returns no target.
  Red when: `sed -i` is not a shape the scanner knows, as at base.
- **AC2** — When it reads `python -c "open('a.py','w').write('x')"`, a `python3 -` heredoc calling
  `Path('b.txt').write_text('x')`, and `node -e "require('fs').writeFileSync('c.js','')"`, it returns
  `a.py`, `b.txt` and `c.js` with `why` `interpreter write`; reading
  `python -c "print(open('a.py').read())"`, it returns none.
  Red when: a read-mode `open` is taken for a write, or a write call is missed.
- **AC3** — When it reads `git apply` with a fixture patch file whose `+++` header line names `d.py`
  under its `b/` prefix, and `git apply` fed the same patch in a heredoc, it returns `d.py` with `why`
  `git apply` both times.
  Red when: the patch's paths are not read, so `git apply` writes nothing the scanner sees.
- **AC4** — When `checkShellWrites` reads `sed -i 's/a/b/' a.py` at the fixture root from a payload
  whose `agent_type` is `gov-researcher` (`writes = none`), it returns a `deny` naming the target,
  `sed -i` and the driver as the remedy's actor.
  Red when: `checkShellWrites` is not called from `main`, or it judges by anything but `checkRouted`.
- **AC5** — When a `gov-spec-writer` payload's fixture transcript hands an allowance of
  `memory/builds/x/spec/` and the command writes a file under `memory/builds/x/spec` by a redirect, it
  returns null; writing under `memory/builds/y/spec`, which the spec class admits, it returns a `deny`
  naming the allowance and the work order.
  Red when: the allowance is not read, so a write the class admits outside the work order passes.
- **AC6** — When the same payload carries no `transcript_path`, the write under `memory/builds/y/spec`
  returns a `witness` naming `allowance not located`, and no `deny`.
  Red when: a missing transcript refuses a write its class admits, or admits it silently.
- **AC7** — When the payload carries no `agent_type`, `checkShellWrites` returns null for
  `sed -i 's/a/b/' a.py` whatever the target; and when `checkRouted` is stubbed to throw, a typed
  payload's call is refused through `main`'s catch.
  Red when: the main loop is judged by this check, or a throw admits a role agent's write.
- **AC8** — When `checkCommand` reads `sed -i 's/a/b/' ~/x`, it returns a finding of kind `home`.
  Red when: `checkCommand` reads a scanner of its own that lacks the new shapes.
- **AC9** — When `grep -n "sed -i" tools/hooks/scratch-guard.js` runs over the header block, the
  "WHAT ESCAPES THE WRITE GATE" paragraph names the shapes now held and those that still escape, and
  `tools/hooks/README.md`'s section at `:556` and `help/roles.md`'s closing paragraph of "What the
  hooks refuse" name the same.
  Red when: the header or the page still says a role agent's Bash or PowerShell write is never seen.
