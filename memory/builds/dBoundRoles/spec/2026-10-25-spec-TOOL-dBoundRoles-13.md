## 1. Goal

The part of the trust mechanism (P29, v2:993-1010) this clause carries: a work order hands its inputs
as content, never as a path the role must open; each handed fact carries a key naming what it was cut
from and a class, `witnessed`, `decided` or `claimed`, written by the executor and typed by no agent;
and every key is re-derived when the work order reaches its act, so a fact whose source moved is cut
again before the role sees it. Today 42.0% of the files directly spawned role agents read were files
their parent had read before the dispatch (gap-roles-11), agents read their own prompt file 10 times
(gap-orient-07), and `unattended-unit.js` hands the brief and the spec by path.

## 2. Scope (IN)

- **S1** — The fact key (I13): `derive_fact_key` in `tools/roles/roles_lib.py`, the one deriver, with
  three forms: `blob:<path>@<blob12>:<lo>-<hi>` for an excerpt of a file, `record:<id>@<sha12>` for a
  record or a section of one, and `cmd:<argv12>:<out12>` for a command's output or a typed argument.
  `blob12` and `sha12` are the first 12 hex digits of the git blob id of the file's bytes with CRLF
  folded to LF; `argv12` and `out12` the first 12 hex digits of the SHA-256 of the argv joined by NUL
  and of the output. A record's id is its repo-relative path, or `card/<session id>` for the session's
  orientation card. Observed by AC2.
- **S2** — The class: `derive_fact_class(key)` in `roles_lib.py` by §4 "The classes", so no agent
  types one. Observed by AC1.
- **S3** — Inputs handed as content: `render_handoff` (`tools/roles/handoff.py:312`) renders each
  `reads` value as a block holding a fact line `<!-- gov:fact key=<key> class=<class> -->` and then
  the content. The two path inputs, `spec` and `prompt` (`PATH_INPUTS`, `handoff.py:99`), today handed
  as the path string (`handoff.py:330-335`), hand the file's content keyed `record:<path>@<sha12>`; the
  card's and the brief's values keep their content and gain their record key. `FACT_RE` in
  `roles_lib.py` is the fact line's one grammar. Observed by AC1.
- **S4** — Re-cut at the direct route's act launch: `checkHandoffSpawn`
  (`tools/hooks/agent-cap.js:2089-2148`), after the task digest, reads every fact line of the task
  section through a JavaScript copy of `FACT_RE` and re-derives each `blob:` and `record:` key from
  the bytes at the spawn, the card through scratch-guard's exported `readCard`. A key that moved
  refuses, naming the key, the blob now at its source and the re-render that cuts it fresh. A `cmd:`
  key is covered by the task-sha and is not re-run. Observed by AC3.
- **S5** — The same cut for a caller that is not the direct route: `python handoff.py facts --build
  <slug> [--unit <id>] --input <key>=<value>…` prints, as one line of JSON, the list
  `[{name, key, class, text}]` `render_handoff` would hand, refusing as it refuses. Observed by AC4.
- **S6** — The unit harness hands its brief and spec as content: `tools/workflows/unattended-unit.js`
  takes a required `facts` argument, the list S5 prints for `--input prompt=<briefPath> --input
  spec=<specPath>`, and its prompt (`unattended-unit.js:257-266`) carries each as its content under
  its key and class in place of "the BRIEF at <path> and the SPEC at <path>"; it refuses a `facts`
  missing either input or naming a path other than `briefPath` or `specPath`. The build harness's
  dispatch row (`tools/workflows/unattended-build.template.js:2470-2490`) adds `facts` to `perUnit`
  and names the command that cuts it, which the main loop runs immediately before each unit's
  `Workflow` call: that call is the unit's act launch. Observed by AC5.
- **S7** — The callers and docs: the two Skill templates that dispatch the unit harness
  (`tools/roles/SKILL.template.md`, `tools/unattended/SKILL.template.md`), `tools/unattended/VERBS.template.md`'s
  dispatch section, `tools/workflows/README.md`, `tools/roles/README.md`'s handoff section and the
  rule-6 paragraph of `tools/hooks/README.md`. Observed by AC6.

## 4. Design

### The fact line

```
### input:spec

<!-- gov:fact key=record:memory/builds/tFix/spec/2026-10-25-spec-TOOL-tFix-1.md@3b18e512cc0f class=claimed -->

<the spec's bytes, CRLF folded>
```

`FACT_RE = ^<!-- gov:fact key=(?P<key>\S+) class=(?P<class>witnessed|decided|claimed) -->$`. The
heading stays the `reads` key, so every reader of today's blocks keeps its anchor. The line sits inside
the `## Task` section, so the task-sha covers it.

### The classes

| Source | Key | Class |
|---|---|---|
| an excerpt the renderer cuts from a file | `blob:` | `witnessed` |
| a command the renderer runs | `cmd:` | `witnessed` |
| `.governance/policy.toml`, a row of `memory/DECISIONS.md`, or a record whose status header tail carries `ratified <date>` | `record:` or `blob:` | `decided` |
| the card's `task:` and `card:` values | `record:card/<sid>` | `claimed` |
| a brief's `brief:` sub-head, `input:prompt`, `input:spec` | `record:<path>` | `claimed` |
| a typed `--input` value (`question`, `diff`) | `cmd:` over the argument | `claimed` |

The rule reads the key and the source's own bytes, never an agent's word: P29's "the executor writes
keys and classes, and no agent types one" (`layer-roles.md:249`). A spec's statements are `claimed`,
P29's own example.

### The re-cut

At the direct route the spawn is the act launch, and the guard re-derives each `blob:` and `record:`
key with the git blob id of the bytes now at its source. A moved key refuses with `… <key> was cut at
<old>, and its source now reads <new>: re-render the handoff, which cuts it fresh`. At the harness
route the main loop cuts `facts` by S5 immediately before each unit's call, so the cut is the launch;
the harness cannot read files, so it compares the paths and trusts the cut, as it trusts `briefPath`
today.

### Inventory

`facts` verb of `handoff.py`, the `facts` argument of `unattended-unit.js`, the refusal line above.
Naming cells: each is asked of `python tools/lexicon/lexicon.py --suggest <name> --as py.function`, or
`--as js.function` for the JavaScript, at the pass.

### Migration

command, and the two Skill templates name it. Prompt sizes grow by the handed bytes: a unit's spec is
under 49152 bytes by the spec cap, and its build brief is the build's.

### Alternatives rejected

- **A SHA-256 of the bytes for every key.** It hashes the same bytes, and the git blob id is the one a
  later reader finds in history when a fact's file is renamed, which P29's vanished-anchor route needs.
- **The harness re-cutting the facts itself.** A `Workflow` script cannot read files (measured:
  `research-orientation-determinism.md:92`, no `require` or `child_process` in the harnesses), so its
  caller cuts them at the call.
