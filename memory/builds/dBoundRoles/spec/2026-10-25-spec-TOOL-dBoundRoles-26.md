## 1. Goal

A refusal today names no actor for its remedy: three guards name remedies their target cannot perform,
a spawn, a parent's kickoff and an owner write, and a refused builder's only exit is a free-text
divergence (`gap-roles-31`, gap register line 183). P39 says every refusal names a remedy its target
can perform or goes at once to an actor who can (v2:1068-1074), and the stall-and-loop record's item 7
types it: the rule, the remedy and the remedy's actor, who is the refused agent, its producer, the
driver, the owner or another build. This unit puts that typed refusal into every role's return
template, routes each refusal by its actor through one outcome table that never hands the item back to
the agent that refused it unless the remedy is its own, and gives `run.on-owner-question`'s best effort
its spent-budget branch: once the build's budget is spent it chooses only among endings.

## 4. Design

### The arm

```toml
# tools/roles/role-schema.toml, beside unit 2's field declarations
[return.refusal]
outcome = "refused"
fields = ["rule", "remedy", "actor"]
actors = ["self", "producer", "driver", "owner", "build:<slug>"]
```

Declared once, composed into every template: a role file never repeats it, and a role whose `return`
redeclares `outcome: refused` is refused by the catalogue checker, so the arm cannot drift per role.
The rendered agent file carries it under the role's own return template, which is what the agent reads.

### The outcome table

| `actor` | Route | Re-offer to the refused agent | Draw (TOOL-dDeclaredLoop-30) |
|---|---|---|---|
| `self` | `retry`: the same item, the remedy the agent's own | bounded by `roles.retries` | `re-dispatch` |
| `producer` | `route-back` to the item that produced the refused input | never | `route-back` |
| `driver` | `driver`: the driver performs the remedy, then a fresh dispatch | never | `re-dispatch` |
| `owner` | `owner`: `resolve_owner_question(kind="refusal")` answers | never | none |
| `build:<slug>` | `ask`: an ask row for that build, filed by the main loop | never | none |

"A remedy the refused actor cannot perform within its grant routes at once to that actor": the actor
field is the refusal's own statement of who can perform the remedy, so any actor but `self` is one the
refused agent cannot be, and its route is taken in the same driver step that read the return. "Never
re-offering the item to the refused agent" is the second column: only `self` sends the item back, and
then only as many times as `roles.retries` allows, after which the route is the driver's, as a
residual failure is (TOOL-dBoundRoles-5).

A `producer` route needs the producing item: it is the upstream item the refused input came from,
read from the work order's upstream rows (TOOL-dDeclaredLoop-29 S5). A work order with no upstream
item answers `driver` instead and says so on the route line.

### The spent budget

v2:1231 reads "once a build's rework budget is spent, best effort chooses only among endings, never
another lap" (the owner's SL-2). Unit 11's reader answers `resolve` for `best-effort-recorded`; this
unit adds the branch before that answer:

```
resolve_owner_question(kind, attended, repo, rev, budget_spent=False)
  ... unit 11's table ...
  value == best-effort-recorded and budget_spent  ->  "choose-ending"   # options: park-item > park-build > stop-run
```

`budget_spent` is the caller's, read from `budget.py`'s `exhausted` answer for the build. The driver
picks one ending and records it with unit 11's fork record, the ranking `park-item > park-build >
stop-run` (most work kept first), so the pick is graded like any other fork.

### The record

`park` writes `<ts> refusal · item <tag> · step <key> · reason <text>` with the reason line-final, and
two live readers strip a trailing reason (`tools/unattended/unattended.sh:12534-12538`). The three
fields therefore ride inside the reason, after its text, as ` · rule <r> · remedy <m> · actor <a>`:
no reader of the row's earlier fields moves, and `read_refusals` splits the reason's tail. A remedy
carrying ` · ` is refused, as `--park` refuses the separator in an item.

### Inventory

Minted: the `[return.refusal]` table; `REFUSAL_ROUTES`; `route_refusal`; the `route-refusal` verb of
`handoff.py`; the route words `retry`, `route-back`, `driver`, `owner`, `ask`; the answer
`choose-ending`; the question kind `refusal`; the `--rule`, `--remedy` and `--actor` flags of
`--refused`. Each name is asked of `python tools/lexicon/lexicon.py --suggest <name>` at the pass.

### Alternatives rejected

- **The arm written into each role file.** Twelve copies of one fact; a role that drifts from the arm
  is a role whose refusals route wrongly.
- **Inferring the actor from the remedy's text.** A remedy is one line of prose; only its writer knows
  who can perform it, so the actor is declared.
- **A second refusal record.** TOOL-dDeclaredLoop-14's `refusal` row exists for exactly this; the brief's
  I17 extends it.

## 5. Production-readiness checklist

- security — no new write surface: the record rides the existing `park` row, under its newline,
  carriage-return and separator refusals; the route names a remedy and never performs it.
- perf / scale — one table lookup per refused return.
- error / empty / loading states — an unknown actor, an empty remedy and a malformed `build:` slug each
  refuse by name; a `producer` route with no upstream item says so and answers `driver`.
- observability — every route prints one `refusal —` line, and every recorded refusal carries its actor.
- risks — a role that marks a remedy `self` it cannot perform loops until `roles.retries` is spent, then
  routes to the driver; the bound is what keeps it finite.
- testing — the plants of §6, one per actor kind, and the arms of §7, observed RED then GREEN by the
  main loop at the close.
- migration — none, per §4.
- user docs — `help/roles.md` per Files touched.
