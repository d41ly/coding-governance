## High

### H1 — AC13's worktree check compares two path spellings that never match (id 11)

- **Where:** spec 64 §2 S18 and §6 AC13, the `git worktree list --porcelain` half under a `%TEMP%` prefix (lines 115-120, 414-418). Spec 63 lines 87 and 211 say only `%TEMP%` too.
- **What is wrong:** on this host `%TEMP%` is `C:\Users\d41ly\AppData\Local\Temp`, with backslashes. `git worktree list --porcelain` prints forward-slash paths such as `C:/projects/coding-governance`. Neither spec says which spelling to compare, or to normalise slashes or case.
- **Consequence:** a literal prefix check built from `%TEMP%` never matches. AC13's built-tree half, and the half S18 adds to spec 63's AC11, then pass even when a staged break or failed import leaves a worktree registered. The check certifies the cleanup without checking it, on the one path it exists for. It grades high, not blocker: a careful builder may normalise anyway, and the miss bites only when a cleanup actually fails.
- **Fix (skeptic judged SOUND):** state that both sides are normalised before comparing: backslashes to slashes and case folded (for example `os.path.normcase` on each side, or `cygpath -m` on the prefix). Add a positive control to AC13: with a worktree left under the prefix on purpose in a scratch repository, the probe must report it. It is a write probe, so the build runs it.
- **Left-shift gate:** a bug-class checklist entry, "a path comparison across a Windows env var and git output normalises both sides, and its check carries a positive control".
