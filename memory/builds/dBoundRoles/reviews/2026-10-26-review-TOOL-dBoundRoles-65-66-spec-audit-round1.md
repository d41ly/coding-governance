### M3 — S2 defines `<TEMP>` from two sources that diverge under TMPDIR (ids 7, 21)

- **Where:** spec 65 §2 S2 (lines 48-49).
- **What is wrong:** `<TEMP>` is `tempfile.gettempdir()` in Python or `cygpath -m "$TEMP"` in bash. Python's `tempfile` reads TMPDIR before TEMP, so the two differ wherever TMPDIR names another directory. They agree on this host today.
- **Consequence:** under a per-session TMPDIR, which agent harnesses commonly set, a bash probe makes its worktree under `$TEMP/dbr63obs` while a Python check compares against `<TMPDIR>/dbr63obs`. AC4 and S12's check then report nothing while a leftover stays registered: a vacuous pass. The path is narrow and the harm stays in scratch.
- **Fix (skeptic judged SOUND on both):** name one source. Preferably the probe prints the absolute root it used and every check reads that value. Otherwise both sides derive it from `os.environ['TEMP']`, normalised in Python and `cygpath -m "$TEMP"` in bash, never from `gettempdir`. Add an AC1 half requiring S2 to name a single source. Add an AC4 half asserting that the root the probe used equals the root the check compared.
- **Left-shift gate:** a checklist entry: "an operand shared by a producer and a checker has one source, and the checker reads the producer's value rather than recomputing it".
