## 1. Goal

A spec scope item that retires a name, a row kind or a vocabulary member must carry a `**Readers:**`
clause with a `by name:` half and a `by value:` half, and a new numbered hygiene check refuses the
item that carries neither. The class behind three consecutive spec audits of `dLoggedFlight` is a
reader the author never typed, and no predicate over prose can find one; what a predicate CAN do is
refuse to let the question go unasked, which is what those three audits had to ask by hand.

## 4. Design

### The trigger, and what the dry run measured

The trigger is two tests over one accumulated scope item. Both were measured over the live corpus
before being written down, per this build's own rule, and both hit lists and near-miss lists are
below rather than summarised away.

**EVERY FIGURE IN THIS SUB-SECTION AND THE TWO BELOW IT IS OWN-PROBE**, not journal, and the probe is
named: `probe_reader_trigger.py`, written to this session's scratchpad and re-run at rev-2. It is
UNTRACKED, so nothing in the tree resolves it and a later reader cannot re-open it — which is why
the reproducibility band below is stated rather than a single number. The dry-run journal reports a
SPECS-level pair over the same corpus and not an items-level one: "the raw verb vocabulary flagged
19 of 24 live specs, requiring a backticked NAME brought it to 14". Those 19 and 24 are specs; the
19 below is items. Do not conflate them.

**THE ITEM COUNTS DO NOT REPRODUCE TO THE ITEM, AND THAT IS THE FINDING, NOT A CAVEAT.** Three
faithful reimplementations of the rule as this section states it give 9, 10 and 11 items strict and
19, 20 and 21 with the stems: rev-1's probe, the cross-read's independent reimplementation, and this
rev-2 re-run. So the rule as PROSE underdetermines its own population by about 10%, which is the
same defect the control revision recorded one level up and is exactly why the shipped artifact is
the awk and not this paragraph. What DOES reproduce, identically in all three, is stated as the
figure this design rests on.

The VERB list is closed, and it is the strict list the dry run stated literally: `retires`,
`is replaced by`, `are replaced by`, `removes`, `deletes`, `drops`, `no longer exists`,
`no longer carries`, `no longer reads`, `stops being`, `ceases`, `goes away`, and
`leaves the` followed by `layouts`, `set` or `vocabulary`. To that list this unit ADDS the four bare
imperative stems `retire`, `delete`, `remove` and `drop`, matched case-insensitively, and the
addition is the single most consequential decision in this spec.

Measured over the 24 live specs, OWN-PROBE: the strict list alone triggers 9 to 11 items across 7 or
8 specs, and adding the imperative stems triggers 19 to 21 items across 12 or 13 specs. THE DELTA IS
THE STABLE FIGURE and all three readings agree on it exactly: the stems add 10 items and 5 specs,
whichever absolute count you start from. So the decision does not rest on a number that moves.

The 10 items the stems add include every one of the three items the dry run named as a real,
uninventoried retirement that a whole-spec predicate could not red — `aMendedLedger-3-u2` S6, where
`tools/workflows/drift-audit-state.js` has ten reference sites and no named reader,
`aMendedLedger-3-u2` S3, and `aMendedLedger-4-u3` S3, where `index_set()` loses two session-ledger
lines. All three are absent from the strict set and present in the stems set in every one of the
three readings, so the coverage claim itself is invariant. The strict list misses all three, because
this corpus opens a retirement scope item in the imperative and the strict list holds only
third-person and passive forms.

Two forms the dry run's lenient vocabulary admitted are deliberately REFUSED, and the reason is the
skeptic's own finding. `stops` followed by a gerund and `no longer` followed by any word both match
prose describing a runtime behaviour rather than a retirement. The measured instance is
`dPolishedVitrine-14` S5, verified at
`memory/builds/dPolishedVitrine/spec/2026-09-13-spec-TOOL-dPolishedVitrine-14.md:41`, where a test
arm "stops copying the cwd-relative `$LEG`" — a behaviour change inside a fixture, not a retirement
of anything. That item is in the lenient trigger set and out of the set this unit ships, and the
rev-2 re-run confirms it: that spec is live and triggers under neither the strict vocabulary nor the
strict-plus-stems one.

The IDENTIFIER test is a closed set of five shapes, and a bare word is not one of them:

| shape | admitted because | measured instance |
|---|---|---|
| contains an underscore | snake case and shouted constants | `split_regions`, `SHARD_ARITY` |
| contains a slash, and does not end in `.md` | a code-file path | `tools/check-kit-versions.sh` |
| contains a dot whose tail segment is word characters other than `md` | a qualified symbol or a script | `merge.conflictStyle`, `inventories.json` |
| carries an internal case transition, a lowercase letter immediately followed by an uppercase one | camel and Pascal identifiers | `conflictStyle` |
| two dashes then a letter | a long option | `--write-ratchet` |

Three token classes are EXCLUDED by shape, and each exclusion answers a measured finding:

- **A `.md` path is never an identifier.** The dry run's own hit 2 turned on this: `aMendedLedger-1`
  S1 deletes three `.md` stub files and retires no name, while the genuine retirement one bullet
  lower is invisible because its only backticked token is an `.md` path. The exclusion keeps the
  innocent item out. It does NOT recover the genuine one, and that is a NAMED GAP below.
- **A family-slug-seq id is never an identifier.** Measured: exactly one backticked id sits inside a
  verb-bearing live item, `PLAY-aPrunedCeremony-5` in `aMendedLedger-1` S7, whose item closes a
  decision row and retires no name. That item is the only thing the exclusion costs and the only
  thing it buys, in this corpus.
- **A token that is only dashes and digits is never an identifier.** This is the skeptic's
  elided-slug class. §2 of the charter sanctions family-plus-seq shorthand in prose, so the pair
  `TOOL-dLoggedFlight-21` and `-24` puts a bare `-24` in backticks, and a flag-shaped test reads it
  as a retired name. Measured over the 24 live specs: ZERO such tokens sit inside a verb-bearing
  item, so the exclusion changes no verdict today and is a forward guard. It is written anyway,
  because the skeptic found the instance in the control revision, which is exactly where this check's
  first real subject will look.

### The bare-word class, and why shape 6 is not built

The skeptic's other finding is that a permissive identifier test admits row-layout vocabulary words:
over the control spec it collected 42 "retired names" including `commit`, `push`, `phase`, `brief`,
`gate`, `idle`, `verb`, `UTC`, `event`, `elided`, `checks` and `label`. Those recur in every spec
touching the runlog, so a name-bound reader test can never fail once one of them is in the set.

The owner's ruling names three kinds of retired thing, and one of them — a vocabulary member — is
often spelled as a bare lowercase word. So a sixth conditional shape was drafted: admit a bare word
when the same item also carries a kind noun from a closed list. It is MEASURED AND DROPPED.

All four figures in this paragraph are OWN-PROBE from `probe_reader_trigger.py` and appear in
neither journal. Over the 24 live specs the number of items whose only backticked identifier is a
bare word AND which carry a kind noun is ZERO, under the strict vocabulary and under the lenient one
alike — the one figure that is a clean zero and reproduces in both runs. Admitting bare words
unconditionally instead adds between 1 and 4 items depending on where the probe draws the boundary
of "bare", and the distinct bare words appearing inside verb-bearing items number 17 under the
strict vocabulary and 19 with the stems at rev-2 against rev-1's 22. The RANKING is invariant across
both readings: `ledger`, `in-flight`, `memory-tree` and `worktree` lead in each. Those counts turn
on whether a hyphenated word and a multi-word phrase count as bare, which the prose does not pin,
and nothing here rests on them: what rests on this paragraph is the DROP, and the drop rests on the
zero. A conditional shape that fires on nothing is a clause nobody can observe; an unconditional one
is the class the skeptic named. Neither is built.

**NAMED GAP, pinned rather than implied away.** A retirement whose only backticked token is a bare
word, a hyphenated bare word such as `check-brief-recorded`, or an `.md` path is NOT triggered, so
its author is never asked the by-value question. Measured size in the live corpus, OWN-PROBE: 3
items at rev-1 and 5 at rev-2, the two extra being `aGradedDoorway-7` S4 on `run()` and
`aMendedLedger-6-u6` S1 on a template `.md` path. The size figure is therefore a lower bound of 3
rather than a count, and the gap is at least that wide. Its MEMBERSHIP is what matters and it is
stable: the dry run's `aMendedLedger-1` S2 — "Retire the authored session ledger to
`memory/archive/ledger/{a,b,c}.md`" — is a genuine retirement inside that gap in both runs. Closing it needs a
kind-noun vocabulary the corpus does not yet use, and inventing one to satisfy a gate is the mirror
this repo already forbids elsewhere.

### The clause, and what is graded

The shape, with invented identifiers so that nothing here reads as a claim about this tree:

```markdown
- **S4** — retire the `shard_arity` pin and the two rows it carried.
  - **Readers:** by name: `check_shard_split` and `report_shard_rows` spell the pin.
    by value: `test_fresh_three_shapes` reads a Coverage row by a cell count of six, and
    `parse_floor_raise` knows only the word `RAISED`.
```

The clause sits on the item's own opening line or on any line beneath it, which is the latitude the
acceptance-witness and failure-mode rules already grant and matches this corpus's wrap style. A
sub-bullet indented beneath a column-0 item is a continuation of that item, so the form above is one
item and is graded as one.

GRADED: the literal `**Readers:**`, then the literal `by name:`, then the literal `by value:`, and
then — for the by-value half alone — either a backticked token or the literal `NO VALUE READERS`
followed by at least one further non-space character.

**The escape spelling is exactly one string, and it is `NO VALUE READERS`.** No synonym, no `N/A`,
no `none`, and no second marker for a false trigger. A false red names its own remedy and a false
pass is silent, which is the ruling check 12's scope-join arm already records for its own single
escape. A false trigger's remedy is the clause itself, whose halves are free prose, and not a second
marker that would have to be told apart from the first.

NOT GRADED, and the check's header says so: the CONTENT of the `by name:` half. Grep answers that
half, an author who wrote the marker has already run grep, and a retirement with genuinely no
by-name reader is ordinary — a freshly private helper has none — so grading it would need a second
escape marker on a half that buys nothing by being graded.

### SHAPE ONLY — the control, and why the header must say it

`TOOL-dLoggedFlight-22` at rev-3 is the document that defines this class. Its by-name inventory
missed `test_fresh_ac4_three_shapes`, `parse_floor_raise` and `test_record_placement_windows`, and it
blocked three consecutive spec audits. Both stages of the dry run implemented a reader predicate over
it independently and both PASSED it, and both also passed rev-4, the fix. The two implementations
disagreed on the count — stage 1 counted reader-naming sentences per retirement clause as
15, 4, 6, 14, 14, 1 and 7 against rev-4's 18, 5, 7, 15, 15, 2 and 9, while the skeptic counted 10
whole-spec against 12 — and the figure to carry forward is the VERDICT, not either count, because
three faithful readings of one paragraph produced 1, 2 and 3 hits. The skeptic also ran a per-item
quantifier over the control: rev-3, the defect, reds 4 items and rev-4, the fix, reds 3. Tightening
the quantifier reds the remedy.

So the check grades that the by-value question was ANSWERED, never that the answer is right, and
check 25's own header states that in those terms. This is the house idiom rather than a concession:
check 12's witness arm grades that a bullet names something backticked and never that the named thing
exists, and check 22 grades the verdict token and never the judgement behind it.

### Where the arm lives — the seam RE-DERIVED, and the design re-stated against what is there

**rev-1 said the arm rides an item accumulator at `tools/memory-tree/check-memory-hygiene.sh:1316`.
THAT IS WRONG, and it was the load-bearing claim rather than a citation slip.** Re-derived from
source at rev-2: line 1316 is `if (jcut != "" && fdate != "" && fdate >= jcut) {`, the
`SCOPE_JOIN_CUTOFF` date guard itself. The accumulator — `sj_hasS` / `sj_hasA` at
`tools/memory-tree/check-memory-hygiene.sh:1317`-`:1321` and `sj_in` / `sj_ni` / `sj_txt` / `sj_lbl`
at `:1323`-`:1335` — is built INSIDE that guard and inside a second test, `if (sj_hasS && sj_hasA)`
at `:1322`, which demands the spec carry BOTH a `## N. Scope (IN)` and a `## N. Acceptance criteria`
heading. And it is the ONLY such walker in the file: `grep -n 'Scope' tools/memory-tree/check-memory-hygiene.sh`
returns three lines, one canon literal at `:1134` and the two regexes of this one accumulator.

So rev-1's two sentences could not both be built. "Ride the accumulator" and "beyond the shared
outer guard the arm reads `READER_INVENTORY_CUTOFF` and no other key" name different arms. Riding it
as it stands makes check 25's real dependency set `SPEC_FORMAT_CUTOFF` AND `SCOPE_JOIN_CUTOFF` AND
an Acceptance heading, of which rev-1's S8, AC11 and F3 declared exactly one — which is the
dead-invisibly class this whole unit exists to close, and which the accumulator's own comment at
`tools/memory-tree/check-memory-hygiene.sh:1304` forbids in as many words.

**The design is therefore the HOIST, S10.** The accumulator moves out of both enclosing conditions
to the awk's per-file level, and each consumer applies its own guard to the shared items:

```awk
if ((jcut  != "" && fdate != "" && fdate >= jcut) ||
    (ricut != "" && fdate != "" && fdate >= ricut)) {
  sj_hasS = 0; sj_hasA = 0; ...the heading scan, unchanged...
  if (sj_hasS) { ...accumulate sj_txt / sj_lbl, unchanged... }
  if (jcut  != "" && fdate >= jcut  && sj_hasS && sj_hasA) { ...check 12 verdict, unchanged... }
  if (ricut != "" && fdate >= ricut && sj_hasS)            { ...check 25 verdict... }
  ...delete, after the LAST consumer...
}
```

Three properties, each checkable rather than asserted. Check 12's verdict keeps its identical
composite condition, so no check-12 verdict moves and `tFixture-115` — "no Acceptance heading, so
not graded at all", at `tools/memory-tree/check-memory-hygiene.test.sh:1050` — stays a `miss`; AC16
observes that. Check 25 does NOT inherit `sj_hasA`, because whether a spec has an acceptance section
has nothing to do with whether it inventoried a retirement's readers. And the accumulation guard is
