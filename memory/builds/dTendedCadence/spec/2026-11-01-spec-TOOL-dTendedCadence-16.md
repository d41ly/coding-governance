## 1. Goal

Four things a node leaves behind go unseen: an act launched with no outcome past
`runtime.act-ceiling`, a run whose node died before its journal reader wrote the run record
(gap-maint-14, gap-register:433), a pushed commit missing a required key, and a standing directive in
the node's auto-memory never promoted (the memory plan's `[gates]`, memory-plan:376-378). Each is
recorded where only one node, or only the history after a push, can see it, so none can be a bar or
push leg. This unit adds the four as Maintain readings, each filed as an ask (P35, v2:1049), and
`maintain.node-readings`, which says whether every node reads its own node-scoped readings or only the
period's lease holder does.

## 4. Design

### Evidence

The one node-scoped reading at this base is `signal_dangling_pointers`
(`tools/drift-audit/drift_report.py:968`), whose docstring says why it never gates: "the notes live on
this machine, so the value is this machine's and the record never gates". The same holds for an act's
journal lines and a run's journal close, which live under one clone's git common dir
(TOOL-dWellOiledMachine-16 S7), and for the auto-memory. The commit reading is not node-scoped, since
pushed commits are every node's; it is kept off the bar because the push leg already grades the push
(TOOL-dWellOiledMachine-33 S8), and a bar leg over pushed history would red a branch for a commit it
did not make. `build_nonterminal_merged_runs` (`drift_report.py:2512`) reads run state, not
journals, and none of the four readings exists. TOOL-dWellOiledMachine-39 §3 hands "Maintain's commit
reading" to this build by name (`:106-107`, `:121`).

### The four readings

| Signal | Scope | Kind | Population | Offender |
|---|---|---|---|---|
| `acts_past_ceiling_with_no_outcome` | node | `act` | `act-launch` lines older than `runtime.act-ceiling` | an act with no `act-exit` or `act-killed` after it |
| `closed_runs_with_no_run_record` | node | `run-record` | closed runs owing a record, closed over 24 hours ago | a run with no record at its path |
| `pushed_commits_missing_required_keys` | repo | `commit` | `<start>..HEAD`, `--no-merges` | a commit with a finding of `commit_keys.py --check` |
| `standing_directives_not_promoted` | node | the auto-memory's | `type: feedback` index entries | an entry with no `promoted-to:` |

### Alternatives rejected

- **The commit reading as a second push leg.** Rejected by the clause, "never a bar or push leg", and
  by its population: the push leg grades the unpushed range, and this reading grades what landed
  without it, from another node or before a hook was installed.
- **One reading over all four.** Rejected: the four have four kinds and so four owners, and admission
  derives one owner per reading (layer-expansions:200-205).
- **Reading the journal's files directly.** Rejected by `point.journal-readers`' contract: a reader
  opens a producer file only through `read_journal` and parses no line itself
  (TOOL-dWellOiledMachine-16 S7).
- **Taking the directives from the index by a second parser.** Rejected: `scan_directives` is the one
  reader (PLAY-dOrderedCharter-14 S2), and its CLI is the sibling-kit door.

## 5. Production-readiness checklist

- security — the readings read this node's journal, its auto-memory index through the playbook kit and
  git history, and write nothing; an ask carries an act id, a slug, a short sha or a directive's name,
  never a directive's text or a transcript line.
- perf / scale — one journal pass for S1 and S2, one bounded `commit_keys.py` run over the range since
  registration, one bounded `memory_index.py` run.
- error / empty / loading states — no journal, no registration commit, no playbook kit or
  `observability.run-record: none`: `not asked`, naming which; a subprocess that exits 2 or times out:
  a dead probe, filed to its source past `maintain.dead-after`.
- observability — each reading's line and journal line (I9), the asks filed, the `unread-nodes:` line and the node pass's `node readings —` line.
- risks — the 24-hour grace can file a run whose node is merely offline for a day; the ask's
  acceptance, back under its pin, closes once the record is written.
- testing — the probes of §6; the arm of §7.
- migration — N/A: four new rows and one module, no data moved; history before the commit-key leg's
