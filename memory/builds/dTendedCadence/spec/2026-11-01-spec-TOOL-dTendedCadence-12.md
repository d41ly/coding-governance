## 1. Goal

A `gov:note` head line describes the code beneath it, and nothing notices when that code changes and
the line does not (night pass point 4, `:243-268`; annotations-b:76, "a head line older than its
block's body"). This unit adds the detector: a Maintain reading over every bundle member a note heads,
filing each one whose code moved since its head line last changed. The test "did this definition's
body move since commit X" gains its second caller here, so it is extracted into one helper both callers
share, the charter's reuse rule at the kind's second instance.

- **S3** — The detector, a verb `python annotations.py behind --json` in
  `tools/memory-tree/annotations.py`. For each `gov:note` row `scan_annotations(root)` returns at HEAD:
  - its head commit `X`, the commit that last changed the note's own line, from one `git blame
    --porcelain` per file over every note line in it;
  - its span, as `annotations.py spans --json` derives it through `derive_note_span`;
  - a definition span, where the note heads a definition or sits in its body, has moved when
    `check_body_moved(<path at X>, <path at HEAD>, ext, <qualified name>)` is `True`;
  - a span closed by `gov:end <tag>` has moved when `git log -L <line+1>,<end_line>:<path> X..HEAD`
    names a commit, so a body line edited, added or taken out after `X` counts;
  - a note with no span, a definition the text at `X` lacks, or a path `X` does not hold is
    `unjudgeable`.

  It prints one object, `{"live", "note", "of", "unjudgeable", "members"}`, `of` the notes judged and
  each member `{"path", "line", "tags", "key", "head"}`, `key` the definition's `<path>::<qualified
  name>` or `null` for a `gov:end` span and `head` the sha of `X`. A shallow clone prints `live: false`
  with a note, since a cut history blames every line to its boundary and would read every member
  fresh; a tree with no `gov:note` row prints `of: 0` with a note saying so. `gov:feature` anchors are
  not members it judges (§8 F2). Observed by AC3, AC4 and AC5.
- **S4** — The reading. `measure_notes_behind_code(ctx)` in `tools/drift-audit/drift_report.py`,
  signal `notes_older_than_their_code`, runs the verb as a bounded subprocess in `ctx.root`, found

  the map (`:3423-3438`), never by import. It reads `not asked` when the kit or the verb is absent or

  `of`, `unjudgeable`, `detail` the members, `tolerance` 0 and `gateable` false. The `line` field is a
  line locator, so the I5 offender key of a member is its path, tags, key and head commit, constant
  until the head line is edited, which is the fix. Observed by AC6.

## 4. Design

### Evidence

At this base nothing under `tools/` names a `gov:note` line: `git grep -n "gov:note" -- tools` finds
nothing, and `parse_note_line`, `scan_annotations`, `derive_note_span`, `code_record.py` and
`tools/lib/extract_code.py` are all specced and unbuilt (scout C's record, row 3). The closest built
rule is `measure_dossier_staleness` (`tools/codebase-map/map_lib.py:1812-1858`): prose older than the
code it claims, by ancestry. TOOL-dTotalRecall-8 S12 gives that rule its body-hash form for an anchored
dossier; this unit applies the same test per note span.

### Which commit, which span

| Member | Head commit `X` | Code moved when |
|---|---|---|
| a note heading a definition, or inside its body with no `gov:end` | `git blame --porcelain` of the note line | `check_body_moved` over the file at `X` and at HEAD is `True` |
| a note whose span ends at `gov:end <tag>` | the same | `git log -L` over the span's body lines names a commit in `X..HEAD` |

A note inside a definition's body is part of that body, and at `X` its line is what it is at HEAD, so
the note itself never moves the hash. A commit that edits the head line and the body together moves
`X` with it, and the member is fresh: the author touched both.

### The helper's home

Codebase-map's `map_lib.py` and memory-tree's `annotations.py` each need the test, and a kit imports no
sibling kit (TOOL-dGroundRules-1 §4), so the helper cannot sit in `code_record.py`, I16's proposed home,
where codebase-map could not reach it. The `extract_code` block is the shared primitive both kits
already carry inline, beside `extract_ranges`, which the helper calls; the block's parity row holds the
copies equal. The interface is I16's question, answered with the home refined (§8 F1).

### Inventory

Minted, each asked of `python tools/lexicon/lexicon.py --suggest <name> --as py.function` at this base
and answered OK: `check_body_moved`, `measure_notes_behind_code`. The verb `behind` of
`annotations.py`. The signal name `notes_older_than_their_code`, a record value and no identifier.
Fixture plants `behind-definition`, `behind-region`, `behind-fresh` and `behind-head-only`.

### Rollout

S1 and S2 land in one commit, so no tree holds the comparison twice; S3 to S6 follow in a second.

### Alternatives rejected

- **The helper in `code_record.py`** (§8 F1 option b). Rejected: `measure_dossier_staleness` lives in
  codebase-map, which may not import memory-tree, so the first caller could not call it.
- **A copy of the comparison in `annotations.py`** (§8 F1 option c). Rejected by the charter's reuse
  rule: the second instance of a kind extracts its factory, never a copy.
- **Blame alone for every span.** Rejected: blame names the commit of each surviving line, so a body
  line taken out after `X` leaves no trace, and a definition span would read fresh after a deletion
  that the body hash sees.
- **`git log -L` for every span.** Rejected: one history walk per definition span, where
  `check_body_moved` reads two texts the run already holds for the file.
- **One bundle at a time through `gov tag bundle`.** Rejected: every note is a member of its tags'
  bundles, so walking bundles reads each multi-tag note once per tag.

## 6. Acceptance criteria

The note fixture is a scratch git repository under `%TEMP%` with a short name. Its first commit adds
`a.py`: a `gov:note unit.x` line heading `def f()`, a `def g()`, and at module level a `gov:note
unit.y` line over two assignments closed by `gov:end unit.y`. Each command runs with the fixture as its
working directory; the probes import the worktree's modules.

- **AC1** — When a probe calls `check_body_moved` from `extract_code.py` with two texts of `a.py`
  differing only in `f`'s return value, it returns `True` for `f` and `False` for `g`; with `f` absent
  from the first text it returns `None`.
  Red when: a change outside `f`'s range, the comment above it included, reads `True` for `f`.
- **AC2** — When `grep -n "check_body_moved" tools/codebase-map/map_lib.py` runs, the call is found
  and no second body-hash comparison is; over TOOL-dTotalRecall-8 AC9's fixture the dossier anchored to
  `a.py::f` reads stale after `f`'s body changes and fresh after only `g` changes.
  Red when: `map_lib.py` keeps its own comparison beside the helper, or AC9's verdicts move.
- **AC3** — When `python annotations.py behind --json` runs after a second commit changing only
  `f`'s body, it prints one member, `key` `a.py::f` and `head` the first commit's sha, and `of` 2.
  Red when: the member is missing, or its `head` is the second commit.
- **AC4** — When `python annotations.py behind --json` runs after a second commit changing only the
  second assignment of the `unit.y` region, it prints one member with `key` `null` and tags
  `["unit.y"]`.
  Red when: a `gov:end` span is never judged.
- **AC5** — When `python annotations.py behind --json` runs after a second commit changing `f`'s head
  line and its body together, or only the head line, or only `g`, it prints no member; in a
  `git clone --depth 1` of AC3's tree it prints `live: false`.
  Red when: any of the three lists a member, or the shallow clone reads every member fresh.
- **AC6** — When a probe calls `measure_notes_behind_code` with a namespace ctx rooted at AC3's tree,
  it reads `notes_older_than_their_code` at value 1 of 2; rooted at a scratch repository with no
  `gov:note` line, it reads `not_asked`; at the shallow clone, `live` false with a `DEAD PROBE` note.
  Red when: an empty tree reads a clean 0, or the shallow clone reads a value.
- **AC7** — When `grep -n -A5 'name = "notes_older_than_their_code"' tools/drift-audit/kit.toml` runs,
  the row carries `scope = "repo"`, `kind = "annotation-index"`, its pin and `edges = [0, 0]`; `grep -n "notes_older_than_their_code" tools/drift-audit/README.md` and
  `grep -n "behind" annotations.md` in `help/` each match.
  Red when: the row lacks its kind, its pin or its edges, or a page omits the reading.
