## 1. Goal

The retrofit drains legacy only where a unit touches it, so legacy that is read often and changed
never is never drained, and nothing measures how much of the reading lands there (retrofit.md
`[cadence]` :485-502, RF-6). This unit adds `maintain.retrofit-heat`, a Maintain reading of the share
of the period's code reads that land on baselined files no unit touched in the prior 30 days, ranking
what remains by reads times touches. Each period it files a sweep of the top-ranked path, as a patch
build under `retrofit.cadence: hot-first`'s standing ask and as a sweep ask only under `off`. It
edits nothing itself, and the progress cell shows the share of reads.

## 4. Design

### Evidence

Nothing of the reading exists at this base. The retrofit research counted reads with scratch code in a
record (`research-retrofit-instruments.md:843-909`), and runlog's one classifier of tool calls keeps
no input (`tools/runlog/extract.py:532-537`), so a per-path count is a new reader beside it. The
catalogue row exists (`tools/policy/catalogue.toml:1541-1545`) with no summary
(`unsummarised-keys.txt:170`). v2's presets set the key `off` under velocity and `hot-first` under the
other three (v2:1709). The cell's segment reads `reads not installed` until this reading exists
(TOOL-dLinkedLibrary-10 S5).

### The reading, per period

```
reads    = runlog.py reads --days RETROFIT_PERIOD_DAYS   # {path: count}, Read calls only
baselined = { site.path : armed registration, site row }
untouched = { p : no commit changed p in the window }
value     = sum(reads[p] for p in baselined & untouched)
of        = sum(reads[p] for p tracked, outside the memory root)
target    = argmax over baselined & untouched with reads[p] > 0 of reads[p] * touches(p)
```

`touches(p)` is `git log --format=%H -- <p>` counted, every commit that ever changed the path.

### Alternatives rejected

- **The counter inside drift-audit.** Rejected by §8 F5's test: a second transcript reader beside
  runlog's would parse the session records a second way, and runlog is the observability engine kit
  that reads them (layer-expansions:211).
- **Widening `derive_tool_class` to keep a path.** Rejected: its contract is that nothing of a tool's
  input survives, and every caller of it relies on that (`extract.py:532-537`).
- **One sweep per untouched path.** Rejected by the design: a sweep is the period's, one population or
  path (retrofit.md:495-496), and a filing per path would file hundreds of intakes in an adopter's
  first period.

## 5. Production-readiness checklist

- security — the counter keeps a repository-relative path and a count, never a transcript's text, a
  command or a path outside the tree; the intake names a population and a path; a sweep under `off`
  never builds, and under `hot-first` builds only what the owner's standing ask, the policy value,
  names (retrofit.md `[never]`).
- perf / scale — one pass over the window's session files, the per-path `git log` counts bounded to
  the untouched baselined paths that were read; both under one subprocess bound per period.
- error / empty / loading states — no armed population: `not asked`; no transcript in the window: `0 of
  0`, live, and the cell reads `reads none this period`; no committed record: `reads not yet read`;
  observability absent: `reads not installed`.
- observability — the reading's line and journal line (I9), the record's `retrofit-heat:` line, the
  intake's receipt.
- risks — reads measure one node's sessions only, since transcripts live on the node, so the row is
  `scope = "node"` and each node's share is its own; two nodes ranking one target file one intake, the
  second a `seen` row on it, since the key is (reading, offender key).
- testing — the probes of §6; the arms of §7.
- migration — N/A: a new reader, a new row in each registry, no data moved.
- user docs — `help/maintain.md` and `help/retrofit.md` (S9).
