## 1. Goal

Deliver Maintain's reading half as a cadence step of the observability expansion: every detector is a
registered `[[reading]]` row naming the layer that registers it, `SIGNALS`
(`tools/drift-audit/drift_report.py:3521-3538`) becomes the registry's reader, joined to it both ways,
every reading over its pin yields offender keys, a patch-routed offender becomes one keyed patch intake
whose recurrence is a receipt on that intake, and an event run reads only the readings its event names,
under a key of event and SHA. Today the 27 signals are one hard-coded list with no owner, layer or scope
(gap-maint-02, research-maintain:142-170), `--offenders` keys only gateable signals (`:4358-4372`), and
nothing renders an intake from a reading.

## 4. Design

### The row

```toml
# tools/drift-audit/kit.toml
[[reading]]
name = "run_records_nonterminal_but_merged"   # the engine's long signal name (I4), required
scope = "repo"                                # repo | node | outside, required
# layer  = "layer.observability"              # optional: the registering layer; default the descriptor's `layer`
# kind   = "<record-kinds.toml name>"         # optional here: TOOL-dTendedCadence-4 admits on it
# pin    = "<drift-pins key>"                 # optional: default the row's name
# fix    = "close finished run records"       # optional: one name of I11
# route  = "patch"                            # optional: patch | file, only on a row with no fix
# events = ["default-branch-red"]             # optional: a subset of the three events
# edges  = [<e1>, <e2>]                       # optional here: TOOL-dTendedCadence-14 defines and grades it (I8)
# live   = "gh"                               # optional here: TOOL-dTendedCadence-18 defines and grades it
```

The row admits the nine keys I3 lists and `route`, and this unit grades only their presence in that
set and the shapes §4 "The check" states: `edges` is TOOL-dTendedCadence-14's to define and grade, as
I8's owner, which settles it as a row key beside `pin`; `live` is TOOL-dTendedCadence-18's, the
command a reading's liveness needs. `layer` is typed only to name a registrant other than the
descriptor's layer, its default derived. `outside` joins `repo` and `node` because layer-expansions
`[core-points]` names three scopes and the remote-CI reading is the third. `route` is the one key added
beyond I3: TOOL-dTendedCadence-17 files an intake for a reading with no fix, so a row with no `fix` may
name `patch`, and with neither key the route is `file`.

### The check

`check_reading_rows(rows, names)` returns one finding per fault, each naming the row:

| Fault | Finding |
|---|---|
| a key outside the ten | `<name>: unknown key <key>` |
| `name` or `scope` absent, or `scope` outside the three | `<name>: scope <value> is not repo, node or outside` |
| a second row with one `name` | `<name>: registered twice` |
| an `events` member outside the three | `<name>: event <value> is not a Maintain event` |
| `route` outside `patch`, `file`, or beside a `fix` | `<name>: route <value> …` |
| a typed `layer` not of the `layer.<seg>` shape | `<name>: layer <value> is not a layer tag` |
| a signal the report emitted with no row | `<signal>: emitted, and no [[reading]] row registers it` |
| a row naming no signal the report emitted | `<name>: registered, and no signal of SIGNALS emits it` |

`names` is the set of `signal` values of one report's records, which `main` already builds as
`ctx.signal_names` (`drift_report.py:4320`), so the join reads what the engine emitted and never a
second list. A reading's function joins `SIGNALS` taking `ctx`, as all 27 do, and its row names the
`signal` it returns: that is how a later unit's reading is reached by its row's name.

### The keyed reading

```json
{"signal": "run_records_nonterminal_but_merged", "value": 10, "of": 89, "tolerance": null,
 "gateable": false, "live": true, "unjudgeable": 0, "detail": [], "pin": 0,
 "layer": "layer.observability", "scope": "repo", "kind": null, "fix": null, "route": "file",
 "events": [], "over": true, "keys": ["run_records_nonterminal_but_merged\t{…}"]}
```

`keys` uses `derive_offender_keys`, so a key in `--readings` is byte-equal to the key `--offenders`
prints for the same record when it is gateable (I5). `--readings` reads online, as the report does
(`ctx.offline` is set only under `--check` and `--offenders`, `:4315`), so the remote-CI reading is
asked. A reading whose record is not asked or not live carries `over` false and no keys.

### The patch intake

```
render_patch_intake(reading, key):
    Maintain reading <name> stands over its pin.
    Offender: <key>                       # the I5 offender key, verbatim
    Fix: <fix or "none">, registered by <layer>.
    Accept: the reading's next value carries no offender under this key.

write_patch_intake(root, reading, key):
    text = render_patch_intake(reading, key)
    ck   = request.py key -  <text>                                  # TOOL-dPlacedRequest-19 S1
    a build README naming **Caused-by:** ck whose **Build status:** reads CLOSED or WONTDO
                                    -> "survivor"   (its patch landed; item.maintain.file files it)
    intake.py show ck  exit 0       -> "seen"   after filing    (the record exists)
                       exit 1       -> "filed"  after filing
    filing: intake.py file --origin cadence --filer item.maintain.patch  <text on stdin>
```

The text carries no value, period or SHA, so one (reading, offender key) pair always renders the same
bytes and keys to one content key: a second filing of a standing offender appends one receipt line to
that record's `<key>.intake` (TOOL-dWellOiledMachine-4 S1), and that receipt, with its
`received-utc`, is the recurrence's `seen` row. The `seen` clause of an ask, `render_scope_row(target,
[("seen", …)])` (`tools/memory-tree/backlog.py:1528`), is `item.maintain.file`'s (TOOL-dTendedCadence-15).
A run files each key once: `--readings` prints each key once per run, an identical row carrying its
`#<k>` ordinal (`drift_report.py:4016-4019`), and the period lease's witness stops a second run of the
same period. Each subprocess is bounded (30 s), its kit found through drift-audit's inline
`resolve_kit_dir` (`drift_report.py` carries the canonical block); a refused call returns `refused` with
its reason, and nothing is filed.

A `cadence` receipt never ratifies (TOOL-dWellOiledMachine-27 S3), so placement refuses the patch
disposition for such an intake and routes it to an ask or a breakpoint (S4): ask TOOL-dTendedCadence-21, which the main loop
files, makes the receipt ratify under the policy value naming the run (§8 F7).

## 5. Production-readiness checklist

- security — `--readings` runs only `SIGNALS`' own functions; no row names a command, so the registry
  adds no execution path. The patch intake's text is built from tracked readings and passes the
  intake writer's own redaction and cap (TOOL-dWellOiledMachine-4 S2); every subprocess is an argv
  list, never a shell.
- perf / scale — `--readings` costs one report, the price of `--json`; the check is linear in rows.
- error / empty / loading states — a descriptor with no `[[reading]]` table yields 27 join findings,
  never a silent pass; a refused intake call files nothing and says why.
- observability — every registration fault is a named `# readings:` line and an offender key.
- risks — the 27 scopes are a reading of source at base, re-derived at the pass; a later signal added
  without a row reds `drift-audit records` by design. UNVERIFIED: no govkit check refusing an unknown
  descriptor table was found by `grep -n "unknown key\|unknown table" tools/govkit/govkit.py`, so the
  new table is assumed to ship as data.
- testing — each criterion is a probe or a fixture over this unit's code; the arm in §7 is observed RED
  then GREEN by the main loop at the close.
- migration — none: an adopter's drift-audit descriptor is engine and arrives with its rows.
- user docs — no page under `help/` covers drift-audit or Maintain; the kit README carries it (S8).
