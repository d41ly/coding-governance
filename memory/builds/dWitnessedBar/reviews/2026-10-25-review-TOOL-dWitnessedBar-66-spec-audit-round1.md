## Blocker

### B1. The CR plant cannot reach the hook's strip on the bar's platform (id 10)

- **Where:** spec-66 §4 Evidence (second bullet), S2, AC1/AC2 Red when, §7 New arm. The same defect is in spec-67 S2 and AC2.
- **What is wrong:** §4 says the hook's per-key awk read "keeps a CR", so a CRLF `sha` line would give `rec_sha` a trailing CR. On this repo's platform that is false. Git-for-Windows gawk reads input in text mode and drops the CR before LF. MSYS bash's `$(...)` also strips a trailing CR-LF. With the strip removed, `rec_sha` and `rec_fp` are still exactly 40 bytes, so the staged break "CR strip removed" stays green. Every remote-ci job is `runs-on: windows-latest`.
- **Consequence:** The arm vouches for a CR strip it never exercises, which is the defect unit 66 was promoted to fix. Only the last-wins half (two `sha` lines) can go red.
- **Fix (judged SOUND by the skeptic):** Correct §4 to say what the platform does: gawk in text mode drops CR before LF, and MSYS `$(...)` strips a trailing CR-LF, so the strip in `read_green_file` cannot be seen through `rec_sha` on Git for Windows. Then re-plan the CR half so it can be seen. Option (a): run the cut function's awk program with stdout going to a scratch file checked with `od -c`, not through `$(...)`, over a line whose CR does not sit right before LF (e.g. `sha<TAB><40 b><CR><TAB>x<LF>`). Option (b): state that the CR half is observable only on a host whose awk and bash keep CR, and name such a leg. Stage the "strip removed" break on a scratch copy and record that it turns red on windows-latest. Apply the same change to spec-67 S2/AC2 (`rec_fp`). Check whether unit 66 AC3's local-hook Python reader opens the file in text mode, because universal newlines would hide its CR strip the same way.
- **Caveat on the fix:** Option (a)'s mid-field CR reaches the strip only if unit 65 S15 applies the strip to the stored value (`$2`/`v`) rather than to `$0`. The required staged red on windows-latest exposes a mismatch either way.
- **Left-shift gate:** Add a bug-class checklist entry: "a CR or CRLF plant read through awk or `$(...)` on Git for Windows never reaches the reader". Pair it with a selftest canary that asserts a planted CR survives the reader's own I/O path before any CR-strip assertion is counted.

### H3. Unit 66's CR plant is removed by the I/O layer before the reader sees it (id 19)

- **Where:** spec-66 §4 Evidence (second bullet), S2, AC1, AC2, AC3.
- **What is wrong:** Git-for-Windows gawk reads files in text mode and drops the CR. Python's default text-mode open does the same on every platform. Bash `$( )` drops a trailing CRLF. Only a bash `IFS=$'\t' read -r` keeps it. The base hook reads with `rec_sha=$(awk ...)` (`.githooks/pre-push:1354`). So S1's `sha<TAB>b…<CR><LF>` reaches `read_green_file` with no CR, and removing the strip cannot turn the arm red. AC3's "Red when: the local-hook reader keeps the CR on verdict" cannot fire either if `verdict_backends.py`, not yet built, opens the record in text mode.
- **Consequence:** The arm cannot see a strip regression, the same defect moved down to the I/O layer. That matters where the CR survives the reads (a Linux adopter), and there a stale CR fails closed. The skeptic re-graded this from blocker to high for that narrow path, and because the §4 Evidence will mislead the next change.
- **Fix (finder's fix REJECTED; skeptic's corrected fix):** Correct spec-66 §4 Evidence: on Git-for-Windows, gawk's text-mode input drops the CR and bash `$( )` drops a trailing CRLF, so on the bar's platform an awk read inside command substitution never shows a CR. Require unit 65 S15's hook reader to read the record with a bash `while IFS=$'\t' read -r k v || [ -n "$k" ]` loop, which keeps the CR on this platform, so that the `${v%$'\r'}` strip is the only thing removing it. Have the arm first assert, through that same read form, that a planted CR survives, and fail loudly naming the platform if it does not. Require the local-hook reader to open the record with `newline=''` (or read it in binary) for AC3's CR half. Observe AC2's CR-strip break red on a Windows node before counting it.
- **Left-shift gate:** The same checklist entry and CR-survival canary as B1. Also add a selftest that greps the hook's record reader for the `read -r` form and refuses `$(awk` for record keys.
