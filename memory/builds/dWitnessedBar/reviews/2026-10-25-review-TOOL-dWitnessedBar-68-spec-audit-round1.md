## High

### H1 — Unit 70 AC2's first staged break never reaches the canary's 41-byte `rec_sha` assertion (ids 10, 24)
- **Where:** spec-70 §2 S1-S2, §6 AC2 (lines 143-150), the §7 New-arm line (line 167) and the §4 Evidence second bullet.
- **What is wrong:** AC2's first plant is a scratch hook whose `read_green_file` reads `sha` through `rec_sha=$(awk ... END{print v}' "$1"); rec_sha=${rec_sha%$'\r'}`. AC2 does not say how the other keys are read. Built from the post-69 hook, the natural copy keeps unit 69's loop for those keys, and that loop carries its own `_rg_v=${_rg_v%$'\r'}` strip. The copy then holds two strip lines. S1's `sed 's/%[$].[\]r.}/}/'` changes both lines (a skeptic's probe printed 2), so S1's exactly-one-line count fails before any byte check runs. A copy that uses unit 65 S15's full awk form changes one line per key. Over today's whole hook the sed changes 3 lines. Only a sha-only reader beside strip-less reads reaches the byte check (it printed 1), and that is the reader the §4 Evidence prototype used. The spec does not require it.
- **Consequence:** Both of AC2's plants fail at the count step. S2 prints the same fixed line for every failure mode, so AC2 passes anyway. The 41-byte `rec_sha` assertion, the check that a read keeps the CR, is never seen red, while §7 says the break "reaches the canary's 41-byte assertion". A vacuous or off-by-one byte comparison would land with AC1 and AC2 green. On the narrow path where a later read eats the CR, the arm again certifies a strip it never exercised. That is the B1 blocker this unit exists to fix.
- **Fix (skeptic: sound, for both findings):** Stage the 41-byte break as a mutant that changes exactly one line but loses the CR in I/O. One option is a scratch hook whose loop reads `done < <(tr -d '\r' < "$1")`, with the single `%$'\r'` strip kept. Another is unit 69's loop with the `sha` case removed and `sha` read by `$(awk ...)` with NO strip of its own. Either leaves one strip line, so the count passes and the mutant's `rec_sha` is 40 bytes. Give S2 two distinct failure lines, one for the count and one for the byte check. AC2 should require the byte-check line for the I/O break and the count line for the no-strip break. At the close the build must run both staged breaks and record which line each printed.
- **Left-shift gate:** a checklist entry, "a staged break claimed to reach assertion X must be shown to pass every earlier assertion in the same arm". The spec audit should require each New-arm line's break to state its expected printed line, and the build should record it.

### H2 — Unit 72 AC1's staged break never reaches the `rec_fp` 41-byte assertion, and the line it must print has no slot for `rec_fp` (ids 9, 25)
- **Where:** spec-72 §2 S1 (lines 39-40), §5 observability (line 103), §6 AC1 (lines 111-114) and the §7 New-arm line (line 133); against spec-70 §2 S2 (line 45).
- **What is wrong:** AC1 stages a copy whose `fingerprint` read is `$(awk ...)` "followed by the strip". The canary must still read `rec_sha` correctly, so the copy keeps unit 69's loop and its strip. That gives two strip lines, and unit 70 S1's sed changes both (probes printed 2, and sourcing the mutant gave `sha 41 fp 40`). The canary fails at its count step before the `rec_fp` byte check. Unit 70 S2 also fixes the failure line as `gov-canary: the planted CR never reached read_green_file on <uname -s>; the CR-strip assertion is not counted`, which names no variable. Spec-72 nevertheless says that line names `rec_fp`, and its Inventory mints nothing.
- **Consequence:** The new `rec_fp` assertion is never seen red. AC1 either fails on a correct build, or the builder makes every count failure name `rec_fp`, which grades nothing about `rec_fp`. Either way a canary that never checks `rec_fp` passes AC1. The Red-when, "the canary checks `rec_sha` alone", is the very build AC1 cannot catch.
- **Fix (id 9 skeptic: sound; id 25 skeptic: unsound, the skeptic's corrected fix):** Keep unit 70 AC2's literal prefix and add the slot after it: `gov-canary: the planted CR never reached read_green_file on <uname -s> for <rec_sha|rec_fp|count>; ...`. Amend unit 70 S2 and its §4 Inventory to mint the slot. Stage spec-72 AC1's break as a scratch hook where `fingerprint` has its own `rec_fp=$(awk -F'\t' '$1=="fingerprint"{print $2}' "$1")` line, with no `%$'\r'}` on that line, and with the `fingerprint)` case removed from the loop. The sed then changes one line (the loop's strip), `rec_sha` reads 41 bytes and `rec_fp` reads 40. The count failure must print its own line naming the changed-line count, so a red at the count step cannot pass for a red at the `rec_fp` check. Record as a build probe that the failing line names `rec_fp` and not `rec_sha` or the count.
- **Left-shift gate:** the same checklist entry as H1. Add one more: "a criterion that requires a printed line to name a value cites a line whose specified text has a slot for it".
