### H1 — The adopter's `conf-scalar-pins` seed reads only tracked confs, so a fresh install seeds nothing (ids 1, 13)
- **Where:** spec-46 §2 S2 and §6 AC2. Unit 14 S11 and its table row (:119) say the same of the leg.
- **What is wrong:** S2 has the memory-tree adopter seed `conf-scalar-pins` right after it scaffolds, measuring "the tree's tracked root confs". At that moment `.memory-tree.conf` has just been copied from the example (adopt-memory-tree.sh:97-101). It is untracked: the scaffold stages only `git add "$M"` (:688-690), and :694 tells the user to commit the conf later. Unit 47 §1 also says govkit apply runs adopters before anything is committed. The adopter's own comment at :645-649 records the same class already met once in this file.
- **Consequence:** The seed writes an armed, empty population. Because the seed is absent-only (unit 15 §4), it never runs again. Once the conf is committed, `ratchet (keys, not a scalar)` reds on the example's `ROW_DUPLICATE_PIN="0"`. That is the very defect this unit exists to close. AC2 ("naming one row") cannot pass, or passes only on a build that departs from S2's text.
- **Fix (skeptic: sound):** State in S2 that the `--measure` seed reads the root confs present in the working tree, tracked or not, the same directory-exists rule unit 47 gives homes. Alternatively, seed from the conf the adopter has just written, or seed after the first commit. Make AC2 run the seed in an uncommitted scratch target, commit it, and run `keys-not-scalar` both before and after the commit, expecting exit 0 with the one row both times.
- **Left-shift gate:** a bug-class checklist entry, "an adopter seed reads tracked files before the target's first commit". Pair it with an adopter-suite arm that runs every seeding adopter in an uncommitted scaffold and asserts a non-empty population where the example carries the measured key.

### H2 — The new `when = "exists:<path>"` spelling strands two other readers (id 42)
- **Where:** spec-45 §2 S1; §4 "The `when` grammar" and "Files touched".
- **What is wrong:** Only regen.py is migrated to the new spelling. Two other readers of `[[generated]]` `when` exist, and neither is named. First, govkit.py:2469-2476 requires `when` to fullmatch `[^:\s]+:[A-Z_][A-Z0-9_]*=\S+`, which `exists:{prefix}/govkit/govkit.py` does not. Second, `resolve_generated_indexes` in lib-unattended.sh (:882-885) splits the value into conf `exists` and key `{prefix}/govkit/govkit.py`, compares an empty value and `continue`s.
- **Consequence:** govkit's descriptor check fails on gov's own tree; that half fails closed. The other half is silent: the leg factory's generated manifest drops out of `GENERATED_INDEXES` with no message, so the unattended driver's handling of generated files stops covering it.
- **Fix (skeptic: sound):** Name both readers in S1 and Files touched. `tools/govkit/govkit.py`'s `_gwbad` fullmatch must admit `exists:<path>`. `tools/unattended/lib-unattended.sh`'s `resolve_generated_indexes` must test path existence for the `exists:` form, with tokens resolved as regen resolves them. Add an AC: in gov's tree, `GENERATED_INDEXES` as resolved by lib-unattended includes the factory row's path, and `govkit.py selfcheck` stays green with the row present. Stage it red by restoring the conf-only parse.
- **Left-shift gate:** a parity arm that feeds every `when` form in the grammar to all three readers (regen.py, govkit selfcheck, lib-unattended) and asserts they agree. Add the bug-class entry "a spelling change strands its readers": a spec that adds a grammar form must list every reader a `git grep` of the key finds.

### H3 — The INHERITED_RED step never states which assignment line the readers take (id 43)
- **Where:** spec-44 §2 S1-S2; §4 "The mapping" (:82-91).
- **What is wrong:** The step maps the readers' value table but not their line-selection rule. `read_policy_key` (.githooks/pre-push:1306-1320, and unattended.sh:9517/9575) takes the LAST line that begins exactly `INHERITED_RED=` at column 0. It strips CR, a whitespace-led `#` comment and surrounding quotes. The spec says nothing about a file with two assignments, an `export INHERITED_RED=` line, or a commented line.
- **Consequence:** For a file holding `INHERITED_RED=land` and then `INHERITED_RED=park`, both readers park today. A step that takes the first assignment writes `own-mixed-contended`, so MIXED and CONTENDED reds that blocked yesterday land silently. That is the loosening this unit exists to prevent. An `export` line is invisible to both readers, so a step that honours it diverges from what was enforced.
- **Fix (skeptic: sound):** S2 states the reader rule: the value is the last line that begins exactly `INHERITED_RED=`, cleaned as `read_policy_key` cleans it (CR, trailing comment, surrounding quotes), and other spellings such as `export` are not assignments. S4 states that `up` deletes every such line and that `witness` counts every remaining one. AC2 gains two fixtures. One has `land` then `park` in one file and writes `every-red`. One has `export INHERITED_RED=park` alone and reads as undeclared, as the readers do.
- **Left-shift gate:** a step-suite arm that runs the step's reader and `read_policy_key` over a shared fixture set (duplicate, export, commented, quoted, CRLF) and asserts equal values. Add the bug-class entry "a record file read by line position".

### M2 — The selection hash round-trip is lossy on ` · `, CR and ignored rows (ids 2, 16, 47)
- **Where:** spec-41 §4 "The canonical text" (:74-77) and §2 S1/S2.
- **What is wrong:** The hook rebuilds the canonical text by turning every ` · ` in a `selection.<n>` value back into a TAB. Unit 5 (:174-175) refuses ` · ` only in a leg name, so a free-text note may hold one. The spec also never says whether the runner strips a trailing CR before hashing, though the record readers strip it (run-gates.sh:2392; pre-push :270, :279, :1309). Nor does it say whether malformed or ignored `held` rows, which unit 5 §5 prints and ignores, enter the canonical text.
- **Consequence:** A note with ` · `, or a CRLF selection file (a Windows Python text-mode write), rebuilds to text the runner never hashed. Every such GREEN is refused as "a key was edited or lost", which reads as tampering, and each push pays a full bar. On malformed rows the builder must guess. One guess makes `select --check` refuse rows R never derives; the other makes runner and hook disagree on the text.
- **Fix (skeptic: sound):** Define the canonical text over the rows the runner accepted: exactly four TAB fields, `\r` stripped, malformed and ignored rows excluded and counted under their own key. Encode losslessly. Either store the fields TAB-separated after the key, as unit 5's run-record rows do, or refuse (or escape) ` · ` in `<source>` and `<note>` at write time, or rebuild with at most three splits. Add AC cases: a CRLF selection file that adopts, and a note holding ` · ` that either adopts or is refused at write time with its reason.
- **Left-shift gate:** a round-trip arm in run-gates.evidence.test.sh: for a fixture set of selection files (CRLF, ` · ` in a note, a malformed row), the hook's rebuilt text hashes equal to the runner's.

- **What is wrong:** S34 cuts at 8192 bytes and then decodes with `errors='replace'`, so each invalid byte becomes a 3-byte U+FFFD. It says nothing about ANSI escapes, lone CR or NUL, which pass into the tracked `leg-tail` markdown record.
- **Consequence:** A tail can be stored at up to about 24 KB, against the 8192 bytes stated in unit 42 §5 (:112) and unit 25 (:43, :105). NUL makes git treat the record as binary, and a lone CR survives `eol=lf`. The record grows or garbles; no verdict changes.
- **Fix (skeptic: sound):** S34 states the order: cut, decode with replace, strip or escape C0 controls other than TAB and LF (CR included), re-cut to 8192 bytes, and hash the stored bytes. AC30's tail gains an ANSI colour sequence, a lone `\r` and a NUL, and asserts that the stored record holds none of them and is at most 8192 bytes.
- **Left-shift gate:** a memory-hygiene check that refuses NUL and C0 control bytes, other than TAB and LF, in tracked `memory/**/*.md` records.

### L17 — The tail sweep misses suffixless temps, and its pseudo-code contradicts its prose (id 52)
- **Where:** spec-42 §4 "The sweep" (:80-81), §6 AC3 (:134).
- **What is wrong:** The sweep and AC3 identify a temp by a `.tmp` suffix. `derive_temp_path` (run-gates.sh:782) appends `.tmp` only when `SRANDOM` exists; its `mktemp -u "$2.XXXXXXXX"` fallback has none. The pseudo-code skips `.tmp` files while the prose says an old temp is removed with the rest.
- **Consequence:** On a bash without SRANDOM a leftover temp is invisible to AC3 and is treated as a tail. Read literally, `.tmp` leftovers are never removed. The grace period contains the effect.
- **Fix (skeptic: sound):** Make the sweep recognise both temp spellings (`<hash>.*`, a tail name plus a suffix), or make the tail writer always add `.tmp`. Make the pseudo-code agree with the prose and remove temps older than the grace. AC3 checks for no sibling of any `<hash>.*` name.
- **Left-shift gate:** an evidence-suite arm that runs the tail writer with `SRANDOM` unset and asserts the sweep removes the aged leftover.
