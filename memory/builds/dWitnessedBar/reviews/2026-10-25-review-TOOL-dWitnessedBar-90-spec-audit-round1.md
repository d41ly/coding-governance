## High

### H1. AC2's `rec_sha="` count cannot pass on a correct build (id 1)

- **Where:** spec-90 §6 AC2, and §2 S2.
- **What is wrong:** AC2 requires `grep -c 'rec_sha="'` over each clone's `.githooks/pre-push` to print 1. The hook already holds two `rec_sha=""` initialisers: one at top level (:1350) and one inside `read_green_file` (:1352). Unit 69 S1 keeps them ("An unreadable file leaves all seven empty, as today"), and no spec touches the top-level one. Each clone adds one quoted `sha)` arm, so the count is 3.
- **Consequence:** A correct build fails AC2. To make it pass, a builder may delete the resets, which ships a reader that keeps stale values for an unreadable record. The other way out is waiving the criterion, which leaves S2 unobserved.
- **Fix (judged SOUND by the skeptic):** Count only the arm. For example, `grep -c 'sha)[[:space:]]*rec_sha="'` over the clone's hook prints 1. Alternatively, cut `read_green_file` and count `sha) *rec_sha="` inside the cut. Then check that the edited line is the only `sha)` arm.
- **Left-shift gate:** a spec-lint rule that every `grep -c` criterion with an exact expected count has that count re-derived against the current tree at spec time, printing the baseline beside the expected value.
