### H2 — The INHERITED_RED step never names its line separator, so a lone CR loosens the policy (id 13)
- **Where:** spec-55 §2 S1 and S4, §6 AC4.
- **What is wrong:** S1 says the step reads "per line, one trailing CR cut" and never says lines split on LF only. The hook's `read_policy_key` splits on LF alone (a here-string with `read -r`). Python's text mode and `str.splitlines()` also split on a lone CR. None of S4's eight parity fixtures holds a lone CR.
- **Consequence:** Over `INHERITED_RED=park<CR>INHERITED_RED=land<LF>`, the hook reads `park<CR>INHERITED_RED=land`. Its `*` arm (pre-push:1339-1343) maps that to park, so it blocks every red. A text-mode Python step takes `land` and writes `own-mixed-contended`, so MIXED and CONTENDED reds that blocked yesterday would land. That is the loosening this unit exists to prevent, on a narrow path.
- **Fix (skeptic: sound):** In S1, state that lines split on LF only. The step reads bytes, or opens with `newline=''`, and splits with `read().split('\n')`. It never uses `splitlines()`, universal newlines, or line iteration over the file object, because iterating a file opened with `newline=''` still splits on a lone CR. In S4, add a ninth fixture with a lone CR between two assignments, whose agreed value is the hook's (park). Stage the break with a text-mode open.
- **Left-shift gate:** a bug-class checklist entry, "a Python port of a bash line reader splits on CR". Pair it with a parity-fixture rule that every bash/Python reader pair carries a lone-CR row.

### H4 — The seed has no rule for an unborn HEAD, yet the before-first-commit fixtures seed in one (id 35)
- **Where:** spec-53 §2 S1 and §4 "The arm"; spec-52 §6 AC1.
- **What is wrong:** Both fixtures are a fresh `git init` with nothing committed, so HEAD is unborn (`git rev-parse HEAD` exits 128). Add a criterion that seeds in an unborn repo and asserts the row parses.
