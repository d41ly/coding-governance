## Medium

### M1. S4 never states the canary's verdict on return code 3 (id 17)

- **Where:** spec-89 §2 S4 and §6 AC4.
- **What is wrong:** S4 tells the liveness loop to set `fail=1` on the new return code 3. For the canary it says only that it prints no `unread` line, and it gives no verdict. S4 also moves the visited line to stderr, so the canary's captured output stays empty.
- **Consequence:** Unit 76 S2 says the canary "requires empty output on its mutant". A canary call site built to that rule, or a `case` with arms for 0, 1 and 2 and no default, passes on "the canary visited 1 of 2". AC4 cannot catch it. Its unit clause checks only the function's return code. Its clone stops both loops, so the liveness loop's own `fail=1` makes the arm red regardless.
- **Grade:** re-graded high to medium by the skeptic. Spec-84 S14 says each visited check "fails", so the spec set implies the canary must fail, which narrows the wrong build.
- **Fix (the finder's fix was judged UNSOUND; this is the skeptic's corrected fix):** State in S4 that the canary's top-level call site, on a 3, sets `fail=1` and counts no pass, and that any code outside 0, 1 and 2 fails. Add an AC4 probe that isolates that call site. One way: cut the canary's call-site block and run it against a stub `check_canary_keys` that returns 3 with empty stdout, requiring `fail=1`. The other way: a scratch clone whose `check_canary_keys` stops after the first pair only when called from the canary's top-level call site (gated on a variable that call site alone sets), with the liveness loop's calls unaffected. Require the arm to print "the canary visited 1 of 2", print no liveness-loop failure line, and exit non-zero.
- **Left-shift gate:** a spec-lint rule that every new return code a spec introduces names an action at each caller the spec lists, with a criterion that observes each caller separately.

### M2. AC6 grades the spec's regex, not the built suite's match (id 4)

- **Left-shift gate:** the existing checklist class `fixture-passes-by-finding-nothing`. Extend its spec-lint check to flag any criterion whose probe text is copied from the spec rather than cut from the built artefact.

### M3. AC6's fixture arms lack the `sha)` prefix that S6's match requires (id 18)

- **Where:** spec-89 §6 AC6.
- **What is wrong:** AC6 writes the first four scratch arms as `rec_sha=$_rg_v`, `rec_sha="$_rg_v"`, `rec_sha=${_rg_v}` and `rec_sha="${_rg_v}"`, with no `sha)` prefix. Only the fifth, aligned arm carries `sha)`. S6's match requires `sha)` before the assignment, so it edits none of the four bare lines. The two modifier arms are also spelled without the prefix, so their "counts none" holds even under a broken match.
- **Consequence:** Read literally, each `diff` counts 0 changed lines where AC6 requires 1, so AC6 is red on a correct build. It can go green only if the builder rewrites the fixture or drops the `<key>)` anchor. Dropping the anchor lets a match edit an assignment outside its arm, which is the regression S6 exists to prevent.
- **Caveat:** refuted id 10 read the same text as the "arm reading X" convention of sibling 88 AC10. The fix removes the ambiguity either way.
- **Fix (judged sound by the skeptic):** Spell AC6's fixture arms in full, as §4 Evidence's probe did: `sha) rec_sha=$_rg_v ;;`, `sha) rec_sha="$_rg_v" ;;`, `sha) rec_sha=${_rg_v} ;;`, `sha) rec_sha="${_rg_v}" ;;` and `sha)   rec_sha=$_rg_v`. Spell the two modifier arms with the same prefix.
- **Left-shift gate:** a spec-lint rule that every fixture line a criterion quotes is a verbatim, complete line the match under test can hit, checked by running the spec's own match over the quoted fixture.

### L10. The owner derivation reports every failure as `MALFORMED REGION` (id 21)

- **Where:** spec-89 §4 "The owner derivation" and §2 S12.
- **What is wrong:** The derivation runs `r=$(region ...) || { echo 'MALFORMED REGION'; exit 3; }`, so any non-zero exit reads as malformed. That includes a sed cut that finds no `region() {` (exit 127) and a missing README (awk exits 2). Both were reproduced. The script also calls a bare `python`, not the interpreter chosen by `tools/lib/resolve-python.sh`, which on a node with the MS-Store stub prints the stub's message and no length.
- **Consequence:** A dead dependency is reported as a malformed index, which sends whoever debugs it to the README rather than to the moved function or the missing interpreter. AC12's malformed-clone clause could pass with `region` never defined. On the built tree an undefined `region` still reds AC12's first clause, so nothing ships a wrong result.
- **Fix (judged sound by the skeptic):** Before calling `region`, check that the cut defined it (`declare -F region >/dev/null || { echo 'REGION READER NOT FOUND'; exit 4; }`). Map only exit 3 to `MALFORMED REGION`. Resolve the interpreter through `tools/lib/resolve-python.sh` instead of the bare `python`.
- **Left-shift gate:** a spec-lint rule that flags a bare `python` or `python3` in any spec script, and that flags `|| { ...; exit N; }` guards mapping every exit code to one diagnosis.
