### M1 — Unit 60's class gate reads the four-line `PM_SCRUB` with a one-line `sed` cut (ids 9, 15, 26)
- **Where:** spec-60 §2 S4, §6 AC2 and §10 Reuse audit.
- **What is wrong:** S4 says to read `PM_SCRUB` off `tools/run-gates/post-merge.sh` "by the `sed` cut the driver suite's parity arm already uses" (`tools/unattended/unattended.test.sh:4337`, `:4341`). That cut, `s/^NAME="\([^"]*\)"$/\1/p`, matches only a quoted value on one line. `PM_SCRUB` spans post-merge.sh:35-38. Run on the tree, the cut prints nothing. A prefix cut prints only the five `GIT_*` names on line 35, which include no `GATE_` name.
- **Consequence:** S4's own rule, "It fails too when any of the four lists reads empty", makes the arm red on every tree, the correct built tree included. AC2's staged cut of `GATE_SELECTION` then reports an empty list and never names the knob. The builder is left to weaken the empty-list guard, reflow `PM_SCRUB`, or invent a reader the spec never states. A loosened cut that reads only part of the list would name missing knobs for the wrong reason.
- **Fix (skeptic: sound, all three):** Read `PM_SCRUB` the way its only consumer does (post-merge.sh:40-43, `${PM_SCRUB//$'\n'/ }`). Take the range `sed -n '/^PM_SCRUB="/,/"$/p'` (or an awk range from `^PM_SCRUB="` to the closing quote), strip the quotes and fold newlines to spaces. Keep the one-line cut for `BAR_SCRUBBED_KNOBS`, `BAR_CLEARED_KNOBS` and `_gknobs`. Add to AC2 that the arm prints the count of names read from each of the four lists. On the built tree, `PM_SCRUB` must read non-empty, hold `GIT_DIR` and `GATE_TURNSTILE_HOLDER` (its first and last names), and count at least 22 names.
- **Left-shift gate:** a spec-audit check that every cited reuse seam is run, as cited, against the target it will read, with its output pasted into the Reuse audit. Add a checklist entry: "a single-line cut cited for a multi-line assignment".

### M3 — Unit 61's "any other failure" row stamps no SHA, yet sends the run down an unarmed path whose line needs one (ids 5, 13, 31)
- **Where:** spec-61 §2 S1 and §4 "The rule" (last row, and the unborn row).
- **What is wrong:** The last row reads `absent | any other failure | none: unarmed, reason no HEAD: <stderr line>`, and S1 routes it to unit 15's unarmed path. Unit 15 S2 (spec-15:38) defines that path two ways: a home holding `# unarmed · <reason> · <sha>`, which needs a SHA, or, for a refused home only, no file and the reason on stderr. Unit 61 picks neither, and S1 also says every `# unarmed` line the run writes carries the SHA. Separately, S1's unborn predicate, "exits non-zero with nothing printed", also matches a non-repository on stdout alone. AC1 covers only a true unborn HEAD, so neither path is observed.

### M4 — Unit 62's `exists:` containment splits on `/` only, so backslash paths escape the tree on Windows (ids 11, 17, 29)
- **Where:** spec-62 §2 S22, §5 security, §6 AC2, §10 Reuse audit.
- **What is wrong:** S22 has govkit selfcheck's `_gwbad`, `regen.check_when` and lib-unattended refuse an escaping `exists:` path "by the pattern `read_gate_policy` uses" (`tools/unattended/unattended.sh:9566-9567`: `/*|[A-Za-z]:*|..|../*|*/..|*/../*`). That pattern knows only `/` as a separator. It is safe where it already lives, feeding `git show r:path`, but not for a filesystem stat. Probed on this host, it admits `..\secret`, `sub\..\..\secret` and `\secret`. Bash `[ -e ]` and Python both resolve the first two outside the root, and Python resolves `\secret` to `C:\secret`. govkit already owns this question in `demand_contained_dest` (govkit.py:1304). That function normalises backslashes and tests `ntpath.isabs`, and govkit.py:1292 and :1370 say it owns the escape check. S22 would put a second, weaker rule beside it.
- **Consequence:** §5's claim that S22 contains the path to the work tree is false on the platform the repo and its CI run on. An `exists:..\x` row is admitted by all three readers, so they agree and the parity arm stays green. The row's applicability is then decided by a file outside the tree. The effect is contained: `exists:` only stats the path and runs nothing.
- **Fix (ids 11 and 29: skeptic sound; id 17: skeptic unsound, corrected fix used):** Have all three readers normalise `\` to `/` before testing containment, or refuse any `exists:` path holding a backslash. govkit selfcheck grades the token-stripped path through `demand_contained_dest`, catching `Refusal` into `r.fail`. `regen.check_when` (copy-installed, unable to import govkit) applies the same normalise-then-test rule. lib-unattended tests `${path//\\//}` against `read_gate_policy`'s pattern. Add a `..\x` tree, a `\x` tree and a `\\server\share` (UNC) tree to S3's refused forms and to AC2. Containment by `realpath` plus `commonpath` is an alternative, but it inherits M5's cross-drive ValueError and must handle it.
- **Left-shift gate:** a checklist entry, "a path-containment rule ported from a `git show` context to a filesystem stat must name backslash, drive and UNC forms". Pair it with a spec-audit check that any new containment rule reuses `demand_contained_dest` or says why it cannot.
