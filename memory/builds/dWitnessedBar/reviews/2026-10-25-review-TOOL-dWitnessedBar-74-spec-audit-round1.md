### H1 — Unit 74's liveness variant fails both halves of the check, so AC2's break cannot print its line (ids 1, 7, 18)
- **Where:** spec-74 §2 S1-S2 (lines 37-48), §6 AC2 (lines 159-163), the §7 New-arm line (line 181) and §1 Goal ("a vacuous or off-by-one comparison").
- **What is wrong:** S1's `check_cr_reached` returns 0 only when the value is forty-one bytes AND its last byte is CR. AC1 pins the `tail -c1` tail test inside the function, so both conditions are mandated. S2's single liveness variant is `rec_sha=${_rg_v%?}`, which yields forty `b` bytes. That value fails both conditions at once. AC2 stages a break that weakens only the count to `-ge 0`. Skeptic probes on a unit-69-shaped loop showed both seds change 1 line. The tail test still rejects the variant (rc=1), so liveness passes and the line `(it passed a value that lost its CR)` never prints.
- **Consequence:** AC2 is red on a correct build. A builder who chases it will drop the tail test, which weakens the comparison this unit exists to keep live. Worse, no variant run can see a vacuous or off-by-one count red. That is the hole §1 says the unit closes. A count comparison made vacuous would land green, and the ledger would record a seen-red that never happened. The §7 New-arm claim is false.
- **Fix (id 1 skeptic: sound; ids 7 and 18 skeptic: unsound, the skeptics' corrected fixes):** Give each condition its own liveness variant:
  1. `rec_sha=${_rg_v:1}` (equivalently `${_rg_v#?}`). It is 40 bytes still ending in CR, so it fails only the length test. Probed: real check rc=1, `-ge 0` break rc=0.
  2. `rec_sha=${_rg_v%?}x`. It is 41 bytes not ending in CR, so it fails only the tail test.

  Each variant goes under S2's two one-line counts. S2 requires a non-zero return from both mutants, and S3 gets a reason that names which variant passed. Restate AC2 as two staged breaks, each with its own expected S3 line. The first is the `-ge 0` count, red through variant 1. The second removes the tail test, red through variant 2. State in §7 which break reaches which reason, and carry both variants into unit 76 S3's per-key loop. Do not keep `${_rg_v%?}` as the CR-isolating variant. The id 18 skeptic probed it with the tail test removed and it still returned 1, because it is also 40 bytes. A smaller alternative, from id 1, leaves the count hole open. It stages one break that makes `check_cr_reached` return 0 regardless, or stages `-ge 0` plus the tail test removed and requires the S3 line only from the combined break. Either way, the build must run each staged break in a scratch clone at the close and record the line it printed.
- **Left-shift gate:** a checklist entry, "a liveness variant for a multi-condition check fails exactly one condition, with one variant per condition". This repeats round 7's H1 class: a staged break that never reaches the assertion it claims. Promote that class's checklist entry into the spec template's New-arm line, so each break states which condition it defeats and its expected printed line.
