## High

### H1 — S8's unborn predicate also matches a broken branch ref, so the seed stamps the null SHA into a tree git cannot read (id 20)
- **Where:** spec-63 §2 S8, and §6 AC4.
- **What is wrong:** S8 defines unborn as `git rev-parse --verify --quiet HEAD` exiting 1 with empty stdout and empty stderr. A `git init` whose `refs/heads/master` holds garbage gives the same result: rc=1, no stdout, no stderr. In that repository `git log -1` fails with `fatal: your current branch appears to be broken`. `git for-each-ref refs/heads/master` prints `warning: ignoring broken ref` on stderr there, and prints nothing in a truly unborn repository.
- **Consequence:** A repository with a corrupt HEAD branch ref is read as unborn. The seed writes rows saying "seeded before any commit", and a rerun treats them as a seeded state. That is the conflation S8 and §8 F2 set out to forbid, and it makes §5's claim that S6 and S8 "stamp nothing in a tree git refuses to read" false. AC4 covers only a non-repository and a clean `git init`, so no arm catches it. The path needs a corrupt ref, so it is unlikely, but the result is wrong.
- **Fix (skeptic: sound):** Make S8 name the class "HEAD that git cannot resolve" rather than relying on the exit code alone. Unborn holds only when `git symbolic-ref -q HEAD` names a ref AND that ref does not exist: `git for-each-ref <ref>` prints nothing on stdout and nothing on stderr. A broken ref prints `warning: ignoring broken ref` and must take S6's no-HEAD path. Add an AC4 case: a scratch `git init` whose `.git/refs/heads/<branch>` holds garbage must print `unarmed p no HEAD: …` and write no null SHA.
- **Left-shift gate:** add a checklist entry, "a git state predicate defined by exit code and silence alone, with no plant of a corrupt or broken neighbour state". The spec audit should require one corrupt-state fixture beside each clean-state fixture.

### M1 — The three `exists:` readers split onto two containment rules that disagree both ways (ids 2, 7, 21)
- **Where:** spec-63 §2 S9, S10 and S11, §5 security, §6 AC5 and §10.
- **What is wrong:** §5 claims S9 to S11 contain `exists:` paths "through one rule". They use two. S9 keeps lib-unattended on `read_gate_policy`'s case pattern, `/*|[A-Za-z]:*|..|../*|*/..|*/../*` (`tools/unattended/unattended.sh:9566-9567`). S10 and S11 move govkit selfcheck and regen onto `demand_contained_dest`'s normpath rule (`tools/govkit/govkit.py:1329-1331`). A scratch probe gave these results:
  - `a/../b`, `a\..\b`, `a/..` and `x/..`: the bash pattern refuses each, and the Python rule admits each (they normalise to `b` or `.`).
  - `1:x`: the bash pattern admits it, and the Python rule refuses it (`dest[1]==':'`).
  
  The split also departs from unit 62 S22, which refuses any `..` segment in all three readers. AC5's four trees (`..\x`, `a\..\..\x`, `\x`, `\\server\share`) are refused by both rules, so the arm cannot see the split.
- **Consequence:** A row such as `when = "exists:a/../kit.toml"` is skipped by lib-unattended with S21's line, and regen and govkit selfcheck admit it. Regen then generates or checks an index that the unattended driver never resolves. Unit 54's "three readers agree" (Red when any two readers disagree on one form) is defeated, and S10's justification ("govkit keeps one containment rule") does not hold across the kit. Every disputed path stays inside the tree, so the readers disagree about which rows are live, and nothing escapes.
- **Fix (ids 2 and 21: skeptic sound; id 7: skeptic unsound, corrected fix below):** Use one rule in all three readers, and name the chosen rule in §10. Either:
  - Have lib-unattended (S9) apply `demand_contained_dest`'s predicate in bash. Fold `\` to `/` and refuse when any segment is `..`. This differs from normpath only for paths that normalise inside the tree, so state which behaviour is chosen. Widen `[A-Za-z]:*` to `?:*` so the second-character colon test matches govkit's `dest[1]==':'`.
  - Or keep the segment rule. In S10 and S11, refuse any `..` segment before calling `demand_contained_dest`, which keeps unit 62 S22 standing. Also widen bash's `[A-Za-z]:*` to `?:*`.
  
  Add AC5 rows `a/../b`, `a\..\b`, `a/..`, `x/..` and `1:x`, each with one expected outcome stated once for all three readers. Stage the red by restoring the other rule in one reader. If the readers are left to differ, delete §5's "through one rule" wording.
- **Left-shift gate:** the checklist classes `two-readers-of-one-config-one-re-derived` and `invariant-held-on-one-admission-path` already name this. Add a mechanical arm that feeds one shared table of `exists:` forms to all three readers and fails on any disagreement, in place of per-reader fixtures.

### M7 — S33 checks a given `--sha` only against the hex grammar, so the null SHA and nonexistent commits get stamped (id 24)
- **Where:** spec-63 §2 S33 and §6 AC23.
- **What is wrong:** S33 checks `--sha` only against unit 13's grammar, "the 8 to 40 hex SHA" (13.md:152), with no rule on existence or case. AC23 tests only `--sha HEAD`.
- **Consequence:** `seed --sha 0000000000000000000000000000000000000000` in a repository with commits writes rows saying "seeded before any commit", which is the claim F2 refuses to write where it is false. A mistyped hex `--sha` writes rows at a commit that does not exist. The row reader accepts both, because both are grammatical. - **Left-shift gate:** add a checklist entry, "an operator-supplied identifier validated by grammar only where the stamp asserts it exists". The spec audit should require an existence check, or a stated reason for its absence, at every write boundary that stamps a SHA.

### M8 — S20's stale signer sweep runs on every peer read, and the spec never says a failed unlink is non-fatal (id 22)
- **Where:** spec-63 §2 S20, with §6 AC12 and §8 F5.
- **What is wrong:** Each peer read first unlinks any `peer-signers-` temp older than PEER_SIGNERS_GRACE_S. The spec has no clause on an unlink that fails, on entries that are not regular files, or on whether a sweep failure can affect the read's verdict. Unit 56 S15 (56.md:99-104) maps failures to DEAD PROBE. AC12 uses a single reader and plain files.
- **Consequence:** Two concurrent peer reads race on one stale file, a race F5 itself names, and the loser's `os.unlink` raises FileNotFoundError. On Windows a sharing violation, or an entry that is a directory, raises PermissionError or IsADirectoryError. Built as written, a housekeeping sweep turns a valid peer verdict read into a traceback or a DEAD PROBE. The path is narrow, and the effect is one failed read.
- **Fix (skeptic: sound):** Add to S20: the sweep runs on regular files only. Each unlink catches OSError. FileNotFoundError is silent, and any other error writes one stderr line naming the file. The read goes on either way, and its verdict never depends on the sweep. Extend AC12 with a plant where the stale entry is deleted between the scan and the unlink, or a stand-in `os.unlink` that raises FileNotFoundError and PermissionError. The read must return its normal verdict.
- **Left-shift gate:** add a checklist entry, "a best-effort cleanup inlined into a read path with no stated failure isolation". Require a concurrent-or-raising plant for every sweep a reader runs.
