## 1. Goal

Make "held" a policy over any leg, not a property of the kit self-test class. One hold predicate,
extended by a held-source word, decides which legs a bar holds; `test.select` writes the selection
record naming each held leg and its source; `verdict.held` decides when a held leg runs; and the
runner's verdict record carries each held leg's result (`held.<n>`), so a later step can read a held
leg's history. Today the predicate "subject `kit` or chunk `selftests`" is spelled three times in
`tools/run-gates/run-gates.sh`, and a held leg leaves no row in any record.

## 4. Design

### Evidence

- The predicate `{ [ "${subjects[$i]}" = kit ] || [ "${chunks[$i]}" = selftests ]; }` is spelled at
  `run-gates.sh:2982` (the `changed` selection), `:3129` (the hold, writing `ondemand` to the leg's
  `.rc`) and `:5429` (the last-run record writer).
- `report_one` prints `GATE held  <name>  (self-test, …)` (`:4038-4047`); the verdict record counts
  `held` (`:5560`) and names no held leg; the summary note says "subject kit or chunk selftests"
  (`:5293`).
- `GATE_SELFTESTS=changed` selects held legs by their kit's shipped bytes (`:2950-2990`), and owner
  ruling F1 keeps every push boundary from setting it (`tools/run-gates/README.md:108-111`).
- The verdict record grammar is `<key>TAB<value>`, read by `read_record_keys` (`:2387`), whose
  reader takes only the keys it names, so new keys are additive; an all-digit suffix is an index
  (`tools/runlog/README.md:22`).
- v2's `[policies]`: `verdict.held` values `peer-or-cadence`, `push-selected`, `on-demand`, default
  `on-demand` (v2:1272).

### The predicate

```bash
HOLD_SOURCES="kit quarantine level"
derive_hold_source() { # leg index -> HOLD_SRC (a word of HOLD_SOURCES) and HOLD_NOTE, or both empty
  HOLD_SRC=""; HOLD_NOTE=""
  if [ -n "${SEL_SRC[$1]:-}" ]; then HOLD_SRC=${SEL_SRC[$1]}; HOLD_NOTE=${SEL_NOTE[$1]}; return 0; fi
  { [ "${subjects[$1]}" = kit ] || [ "${chunks[$1]}" = selftests ]; } && HOLD_SRC=kit
  return 0
}
```

`SEL_SRC` and `SEL_NOTE` are filled once from `GATE_SELECTION`, keyed by the leg's manifest index
through its `name`, the join key of every name-keyed file (I2). The hold site at `:3129` holds a
`kit` leg exactly as today; a `quarantine` or `level` leg is held whatever `GATE_SELFTESTS` says,
because a request to run the kit class is not a request to run a flaky or deferred leg.

### The selection record

```
# <run dir>/selection, and the file GATE_SELECTION names
# verdict.held <value> · tests.landing-levels <values> · tests.without-cadence <value> · rev <R sha>
held	<leg name>	<source>	<note>
```

`select` reads at R: the manifest `tools/gate-legs.json` by `git show <R>:<path>`, the policy by
`policy.py get <key> --rev <R>`, and each `SELECT_SOURCES` reader's own inputs at R. `SELECT_SOURCES`
is a tuple of `(source word, reader)` pairs; this unit ships it holding `level` alone.

### The verdict keys

```
held	3
held.1	unit-heavy suite · level · unrun
held.2	kit selftest a · kit · unrun
held.3	flaky leg · quarantine · ok
```

The separator is ` · `, which no leg name may hold: the manifest parser already refuses a name with a
TAB or a newline, and `select` refuses to write a row whose leg name holds ` · `.

### Held legs guarded (S8)

The eight held legs with no guard at `19d6aae6`, measured as the manifest rows whose `subject` is
`kit` or whose `chunk` is `selftests` and whose `guard` is absent or empty (71 held rows of 142, PINNED
2026-10-25): `template size gate selftest` and `method-carriers self-test` and `roles adopter
self-test` (`[[exempt_leg]]` rows of `tools/govkit/registry.toml`), `review-replay selftest`,
`held-halves selftest`, `agent-cap restatement self-test`, `testsuite counts self-test` and `roles

one. A guard is not free: it makes every live spec whose Files touched trips it name the leg, the cost
`tools/workflows/kit.toml:161-163` records, so the pass picks per leg and writes the reason where it
keeps none. `unguarded_why` is descriptor-only, as `history_depth` is, so it never reaches the
manifest or an adopter.

word; a reader of `held` reads the same count. S8 adds a key no existing declaration carries, and the
eight rows it touches gain a guard or a reason in the commit that adds the arm.

### Alternatives rejected

- **The runner derives the quarantine set itself.** It would read committed asks on every bar and
  decide a loosening in the code being graded; the selection is derived at R by one command and
  checked again at the push.
- **`level` legs as `skip`.** A skip is conjoined into the full-green stamp and says "unchanged vs
  <branch>", which is false for a deferred level.

## 5. Production-readiness checklist

- security — a hold is a loosening, so its inputs are read at R and never from the pushed tree, the
  hook re-derives the selection before admitting a verdict made under one, and an unreadable row runs
  its leg rather than holding it.
- perf / scale — one file read per bar; `select` reads one manifest and the policy at R.
- error / empty / loading states — an absent `GATE_SELECTION` is today's behaviour; a malformed row is
  printed and ignored; `peer-or-cadence` with no runner declared refuses with exit 2.
- observability — the held line names each source, the summary counts by source, and `held.<n>`
  names every held leg.
- risks — a held leg is a leg nobody ran at this bar: `held.<n>` makes that visible to every reader of
  the record, which today counts it only.
- testing — the probes of §6; the suite arms of §7 at the close.
- migration — additive, as §4 says.
- user docs — none owed under `help/`: no help page describes held legs; the run-gates README's
  held section is updated in place.
