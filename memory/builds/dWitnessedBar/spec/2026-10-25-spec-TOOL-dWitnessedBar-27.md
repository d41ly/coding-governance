## 1. Goal

Make a gov script started by WSL's bash on a Windows checkout refuse at once and name Git's bash,
instead of running against a `/mnt/` path, a Linux interpreter and another filesystem's view of the
tree (AP-33). The deliberate WSL mirror of `tools/run-gates/run-held-wsl.sh`, on WSL's own disk, and a
Linux node's own bash stay green.

## 2. Scope (IN)

- **S1** — The canonical shell block `# >>> refuse_wrong_shell` in `tools/lib/refuse-wrong-shell.sh`:
  a pure predicate `wrong_shell_at <path> <wsl>` and its caller `refuse_wrong_shell`, per §4 "The
  predicate". Builtins only, so it adds no fork to any entry point. Observed by AC1, AC2 and AC3.
- **S2** — `refuse-wrong-shell.sh` runs as a probe: `bash refuse-wrong-shell.sh` judges its own
  location, and `--probe <path>` judges that path, each exit 0 when clean and 2 with the refusal.
  Observed by AC1, AC2 and AC3.
- **S3** — Every entry point in the population of §4 "The population" carries the block inline (or,
  where it sources `resolve-python.sh`, sources `refuse-wrong-shell.sh` beside it) and calls
  `refuse_wrong_shell || exit 2` before its first `resolve_python` call. Observed by AC4 and AC5.
- **S4** — The `resolve_bash_py` and `resolve_bash_js` blocks of TOOL-dWitnessedBar-26 gain the
  same predicate as `wrong_shell_at(path, wsl)` and `wrongShellAt(path, wsl)`, judged on the hosting
  file (`__file__`, `__filename`) on a `posix` host, and return the same refusal before any candidate
  is tried. Observed by AC6.
- **S5** — `tools/lib/resolve-python.test.sh` gains the parity row `refuse_wrong_shell`, a
  both-ways coverage arm over the population of §4, and a section `2k` running the three twins over
  one truth table. Observed by AC5 and AC7.

## 3. Non-goals (OUT)

- The bash resolver itself, its candidate order and its refusals: TOOL-dWitnessedBar-26's.
- A Python or JavaScript entry point that starts no bash. The clause names a gov script "started by
  WSL's bash"; a Python tool reached through WSL's python is reached through a shell entry or the
  resolver, both covered.
- WSL configured with an automount root other than `/mnt/`: the clause keys on a `/mnt/` path.
- Records under `memory/builds/*/build/*.sh`: frozen research scripts, outside the population.
- The WSL mirror's setup and its leg: `tools/run-gates/run-held-wsl.sh` and
  `tools/run-gates/held_halves.py` keep their behaviour; the mirror's worktree sits on ext4, so the
  predicate never fires there.

## 4. Design

### The predicate

```bash
# >>> refuse_wrong_shell — canonical copy: refuse-wrong-shell.sh in gov's lib dir (byte-identical; gated)
wrong_shell_at() {   # <abs path> <wsl 0|1>; returns 0 when the path is a Windows checkout under WSL
  [ "$2" = 1 ] || return 1
  case "$1" in /mnt/[a-z]/*) return 0 ;; esac
  return 1
}
refuse_wrong_shell() {
  _rws_wsl=0
  { [ -n "${WSL_DISTRO_NAME:-}" ] || [ -e /proc/sys/fs/binfmt_misc/WSLInterop ]; } && _rws_wsl=1
  _rws_p=${BASH_SOURCE[0]:-$0}
  case "$_rws_p" in /*) ;; *) _rws_p=$PWD/$_rws_p ;; esac
  wrong_shell_at "$_rws_p" "$_rws_wsl" || return 0
  echo "refuse_wrong_shell: WSL's bash is running $_rws_p from a Windows checkout under /mnt/;" >&2
  echo "refuse_wrong_shell: run it with Git's bash (C:/Program Files/Git/bin/bash.exe)." >&2
  return 1
}
# <<< refuse_wrong_shell
```

Two facts decide it, each read without a fork. The path is the hosting file's own location: an
inline block's `BASH_SOURCE[0]` is the entry script, and a sourced canonical's is the canonical,
which sits in the same checkout. The WSL marker is `WSL_DISTRO_NAME` or WSL's interop entry under
`/proc`. A `/mnt/<drive>/` path is WSL's mount of a Windows drive, so the pair is "a `/mnt/` path
over a Windows gitdir".

| Host | Path | Verdict |
|---|---|---|
| WSL | `/mnt/c/<repo>/tools/x.sh` | refuse, exit 2 |
| WSL, the held mirror | `/home/<u>/<mirror>.held/<stamp>/tools/x.sh` | green |
| Linux node, no WSL marker | `/mnt/c/<anything>` or any other path | green |
| Git's bash on Windows | `C:/...` or `/c/...` | green |
| WSL | `/mnt/data/<x>` (not a single drive letter) | green |

The Python and JavaScript twins take the same two inputs: the path is `os.path.abspath(__file__)`
or `__filename`, the marker `os.environ.get("WSL_DISTRO_NAME")` or the interop entry's existence.
They sit inside the resolver blocks, so every adapter of TOOL-dWitnessedBar-26 §4 "The sites"
inherits the refusal with no line of its own.

### The population

Every tracked file under `tools/`, `skills/` and `.githooks/` that carries a `# >>> resolve_python`
block, plus every one that sources `resolve-python.sh`. At `cdfbd1cf` that is 70 inline carriers
and 5 more files naming `resolve-python.sh`, 75 in all (PINNED, measured 2026-10-25 by `git grep -l`;
the 5 include test files that copy the canonical rather than source it, which the arm's source
pattern will not count). The coverage arm re-derives the set at every run and asserts, both ways,
that the set carrying `refuse_wrong_shell` (block or source) equals it and that each member calls
the function outside the block, so a new entry point that resolves python without the refusal reds.

### Inventory

Minted: `tools/lib/refuse-wrong-shell.sh`, the block `refuse_wrong_shell`, the functions
`wrong_shell_at`, `refuse_wrong_shell`, `wrongShellAt` and their `--probe` mode, the `PARITY_ROWS`
row, the coverage arm and section `2k`. Naming cells: each function is asked of the lexicon's
`--suggest` under `--as sh.function`, `py.function` or `js.function` at the pass.

### Migration

None. A node that ran gov scripts from WSL over `/mnt/` was running them wrongly; it now refuses
with the remedy.

### Rollout

Live at landing in every entry point. No switch: the refusal fires only on the defect.

### Alternatives rejected

- **Ask git for the gitdir.** It costs a fork per entry point, which the spawn budget leg ceilings,
  and the script's own path already answers where the checkout is.
- **Key on `uname -s` alone.** A Linux node's bash and the WSL mirror both answer `Linux` and must
  stay green; the path is what separates them.
- **Fold the predicate into `resolve_python`.** It would refuse only where python is resolved, and
  I7 fixes a sibling block.

## 5. Production-readiness checklist

- security — no new write path; the predicate reads one environment variable and one `/proc` entry.
- perf / scale — builtins only, no fork, in every entry point; the spawn budget leg holds its
  ceilings.
- error / empty / loading states — the refusal names the script and Git's bash; an empty population
  reds the coverage arm, never passes it.
- observability — the refusal is two stderr lines prefixed `refuse_wrong_shell:`.
- risks — a WSL user with a drive mounted at `/mnt/<letter>/` who runs gov scripts from it by
  intent now refuses; that is the clause's case.
- testing — AC1 to AC7 by a pass; the arm of §7 at the close.
- migration — none, as §4 says.
- user docs — none under `help/`: no page describes launching gov scripts; the refusal states the
  remedy.

## 6. Acceptance criteria

- **AC1** — When `wsl.exe -e bash refuse-wrong-shell.sh` runs with its working directory at this
  worktree's `tools/lib/` on node d, it exits 2 and its stderr names `Git's bash`.
  Red when: the WSL-bash-over-`/mnt/` plant passes, because the predicate reads no path or no marker.
  fixture: a Windows node with WSL; node d has one (measured 2026-10-25: WSL's `pwd` there is a

- **AC2** — When `wsl.exe -e bash refuse-wrong-shell.sh --probe` runs on node d with the path
  /home/u/mirror.held/s/tools/x.sh, it exits 0: the held mirror's own-disk path is green.
  Red when: the predicate keys on the WSL marker alone, so the mirror leg would red.
  fixture: the real mirror leg needs `run-held-wsl.sh --setup`, the owner's; the probe judges its
  path shape.
- **AC3** — When `bash refuse-wrong-shell.sh --probe` runs under Git's bash on node d with the path
  /mnt/c/r/tools/x.sh, where no WSL marker exists, it exits 0: a non-WSL bash is green on any path, as a Linux

  Red when: the predicate keys on the path alone.
- **AC4** — When `wsl.exe -e bash merge-rows.sh` runs with its working directory at this worktree's

  Red when: the entry point calls the refusal after its own work, or not at all.
- **AC5** — When the files `git grep -l '^# >>> resolve_python'` lists under `tools/`, `skills/` and
  `.githooks/` are compared with those `git grep -l 'refuse_wrong_shell || exit 2'` lists, after the

  comparison names that file, and with a new `.sh` carrying only a `resolve_python` block, it names
  that file too.
  Red when: an entry point resolves python with no refusal before it.
- **AC6** — When `python resolve_bash.py` and `node resolve_bash.js` run under `wsl.exe` from this
  worktree's `tools/lib/`, each exits 2 with the wrong-shell refusal and no `tried:` line.
  Red when: the resolver tries a candidate before judging its own location.
  fixture: a WSL distribution with `python3` and `node`; where WSL lacks `node`, the truth table of
  AC7 observes the JavaScript twin.
- **AC7** — When each row of §4's verdict table is put to the three twins (the shell through
