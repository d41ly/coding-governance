## 1. Goal

dOrderedCharter lands three keyed lists, each "until dWitnessedBar's migration registers it": the live
positional references (PLAY-dOrderedCharter-19 S11, -26 S2), IW-1's legacy list of instruction files not
yet rendered from units (PLAY-dOrderedCharter-20 S8), and the unpinned facts (PLAY-dOrderedCharter-29
S4). dSafePassage lands step rows whose landed state it hands to "dWitnessedBar's append-only factory"
(TOOL-dSafePassage-1 §3). This unit registers the four on the ledger factory, so each is graded by the
one engine and the `ratchet` pack, and adds no check of its own (retrofit.md:145-148, :158-159).

## 4. Design

### The populations

| Population | Home | Direction | Key kind · fields | Seed | Registered in |
|---|---|---|---|---|---|
| `positional-refs` | `tools/playbook/positional-refs.txt` | shrink-only | site · citing path, ref | `positional.py list` | `tools/playbook/kit.toml` |
| `instructions-legacy` | `tools/playbook/instructions-legacy.txt` | shrink-only | site · path | `render_playbook.py --list-legacy` | `tools/playbook/kit.toml` |
| `unpinned-facts` | `tools/playbook/unpinned-facts.txt` | shrink-only | site · path, fact | `writing_practice.py check pinned-facts --list` | `tools/playbook/kit.toml` |
| `landed-steps` | `tools/govkit/landed-steps.txt` | append-only | key · id | `upgrade_steps.py list --ids` | `tools/govkit/registry.toml` |

Directions: the three lists are shrink-only by their own specs (PLAY-dOrderedCharter-26 S3 "`shrink` only
ever shortens the list", -20 S8's `instructions.legacy: shrink-only`, -29 S4 "the list never grows by
the check"); a landed step row is frozen (TOOL-dSafePassage-1 S9), which is an append-only history.
Drain: `key` for the three lists, `none` for `landed-steps`. The three lists' registrations name the leg
of the check that reads them; `landed-steps` names none, so `ratchet (both ways)` grades it.

### The reference field

A file:line row of `positional-refs` quotes a reference such as `tools/x.py:120`, the population's own
subject; I4's factory refuses a key field ending in `:<digits>` as a line number (unit 13 §4). The
registration declares `verbatim = ["ref"]`, a field the line-number refusal skips, because the number is
the text being tracked and not the row's position (§8 F1).

### Inventory

Minted: four `[[ledger]]` tables; `tools/govkit/landed-steps.txt`; the verbs `positional.py list`,
`render_playbook.py --list-legacy`, `writing_practice.py check pinned-facts --list` and
`upgrade_steps.py list --ids`. Naming cells: each verb and flag is asked of
`python tools/lexicon/lexicon.py --suggest <name> --as cli.flag` at the pass.

### Migration

One commit converts the three lists and writes `landed-steps.txt` at the build run's base, keeping every
key; an adopter's lists convert through the playbook kit's `[[upgrade]]` row running
`python tools/memory-tree/convert_registry.py --home <home>` (unit 16 S10), and its steps' ledger is
written by the same row from `upgrade_steps.py list --ids`.

### Rollout

Live at landing; the populations join the `ratchet` pack's legs as data. The pass runs
`python tools/run-gates/owed_rows.py --base HEAD` before its commit (PLAY-dOrderedCharter-50 S6).

### Alternatives rejected

- **Register the lists in their own grammars.** The factory reads one grammar; a second parser per list
  is the six-grammar state gap-test-14 names.
- **Point `landed-steps` at the step files themselves.** I4 holds one ledger file per population with a
  header its registration renders; the step rows live across every descriptor and `steps.toml`.
- **Re-seed each list at the base.** A re-seed admits what grew since the list was written, the
  `seed laundering` row.

## 6. Acceptance criteria

- **AC1** — When `python legacy_ledger.py read <population>` runs for each of the four populations on the
  landed tree, each exits 0, and its row count equals the line count of its §4 seed run at the same SHA.
  Red when: a list was re-keyed or lost a row in conversion, so its seed and its rows disagree.
  figure: both counts DERIVED at observation.
- **AC2** — When `python gov_tag.py check` runs on the landed tree, its positional arm exits 0, and in a
  scratch clone a new `§9` reference planted in a tracked doc makes it exit 1 naming the citing path and
  the reference.
  Red when: the re-pointed arm reads the rows but not the scan, so a new reference passes.
- **AC3** — When `python legacy_ledger.py read positional-refs` runs on a list holding a file:line row
  whose reference is `x.py:120`, the row is read and not refused as a line number; a `site` key field `120` in any
  other population is still refused.
  Red when: `verbatim` is read as a population-wide waiver of the refusal.
- **AC4** — When `python render_playbook.py --check-render` and `python writing_practice.py check pinned-facts`
  run on the landed tree, each exits 0; in a scratch clone an instruction file neither rendered nor
  listed makes the first exit 1, and a planted unpinned fact makes the second exit 1.
  Red when: a re-pointed reader grades only the listed rows, so a new offender passes.
- **AC5** — When a scratch clone removes one landed `[[upgrade]]` row and runs
  `python ratchet.py never-gains`, it exits 1 naming `landed-steps` and the id `removed`; adding a new
  step row and its ledger row exits 0.
  Red when: an append-only population accepts a removal, so a landed step leaves silently.
- **AC6** — When `git check-attr merge -- positional-refs.txt` runs in `tools/playbook/` and the same
  for `landed-steps.txt` in `tools/govkit/`, each prints `merge: rows`.
  Red when: a home lacks the line.
