## 1. Goal

"Shrink-only" is enforced for the map's baseline alone (gap-test-15): `unarmed-branches.txt` grew from 9
rows to 159 unseen, and a count pin acts as a waiver because a fixed offender and a new one net to zero
(gap-test-16). This unit ships the `ratchet` leg pack, one leg per row of retrofit.md's `[ratchet]`
table, grading every population the ledger factory registers, and admits a population's growth only
through a widen record carrying its reason, or refuses it, as `retrofit.widen` says.

## 2. Scope (IN)

- **S1** — The checker, `tools/memory-tree/ratchet.py`, one verb per pack row, each reading every
  registration through `read_registrations` and every population through the factory's `read_rows`,
  `compare_counts`, `compare_to_base` and `carry_renames` (unit 13's `legacy_ledger.py`, its memory-tree
  copy). It mints no compare of its own. Observed by AC1 to AC9.
- **S2** — The pack's legs, each a declaration through `leg_factory.py` in `tools/memory-tree/kit.toml`
  carrying `pack = "ratchet"`, a `leg.memory-tree.ratchet-<row>` tag, a `purpose` and `enforces`, per §4
  "The pack". Observed by AC10.
- **S3** — `never gains`: a `shrink-only` key or count above the base's, and a `ceiling` row raised
  above the base's, each red unless its row's disposition is `widened:<record>` and `retrofit.widen`
  admits that record; and every other refusal `compare_to_base` names for a population's direction,
  so a base row of an `append-only` population that the tree rewrote or no longer holds reds too, and
  a population no check of its own grades is still held to its direction. Observed by AC1 and AC2.
- **S4** — `retrofit.widen`, read through `python tools/policy/policy.py get retrofit.widen`
  (TOOL-dGroundRules-2 S7) once dGroundRules lands, and until then at v2's default `record-reason`
  (v2:1384). `record-reason` admits a widened row whose `<record>` names a tracked widen record holding
  that population, that key and a non-empty `**Reason:**`; `refuse` admits none. Observed by AC2.
- **S5** — The widen record and its door. The record kind `widen` joins PLAY-dOrderedCharter-7 S7's
  factory `tools/memory-tree/build_records.py`, fields `Population`, `Keys`, `Reason` and `Caused-by`;
  `python tools/memory-tree/ratchet.py widen <population> --key <k> --reason <text> --unit <id>` writes
  the record through that factory and the row `widened:<record stem>` through the ledger's `write_rows`,
  and refuses under `refuse`. Observed by AC2.
- **S6** — `both ways`: for a registration naming no `leg`, its `seed` run at HEAD against its rows
  through `compare_counts`; a registration naming a leg is graded by that leg through the same call, and
  this leg prints it `graded by <leg>` so no population is measured twice. Observed by AC3.
- **S7** — `unarmed`: a registration with `seed = []`, or whose home holds the `# unarmed · <reason> ·
  <sha>` line `test.seed` leaves for a failed or dead-probe seed (I5, unit 15 S2), reading anything but
  `unarmed`. Observed by AC4.
- **S8** — `populated`: an empty population after a live seed reading armed. It reads `unarmed` until the
  leg its registration names has a seen-red record (I16), which unit 7 defines and this leg reads as data
  once any exists. Observed by AC4.
- **S9** — `seed laundering`: against the base, a surviving key whose SHA or disposition was rewritten
  (re-dated, or turned back to `seeded`) or a row removed while its seed still measures the key.
  Observed by AC5.
- **S10** — `rename`: over the base range, a `git mv` of a file holding `site` rows that reads as a gain
  or a drain, the rows not carried by `carry_renames`. Observed by AC6.
- **S11** — `keys, not a scalar`: a tracked root `.<name>.conf` assigning a `*_PIN` key a scalar count.
  Its day-one population is the nine pins retrofit.md's `[ledger]` lists, held on a `shrink-only`
  population `conf-scalar-pins` keyed by conf and key, home `memory/project/conf-scalar-pins.txt`, which
  TOOL-dWitnessedBar-17 drains by seven and dMindYourWords by two. Observed by AC7.
- **S12** — `key shape`: a key field holding a number where its kind holds a label (gap-test-17), read
  as the factory's line-number refusal over every population. Observed by AC8.
- **S13** — The fixture arms. `python tools/memory-tree/ratchet.py --fixture --plant <case>` builds a
  scratch repository with a registration, a population and a base commit, and runs the case's leg; the
  `untouched quiet` and `merge` rows live here, the second replaying two branches that drain one
  population and merge through `merge-rows.sh`. Observed by AC9.

## 4. Design

### The pack

| Row (retrofit.md:426-438) | Leg | Live or fixture |
|---|---|---|

| both ways | `ratchet (both ways)` | live, populations no check of their own grades |
| touch join | none here | `build.scope`'s, printed `unarmed` |

| unarmed | `ratchet (unarmed)` | live |
| populated | `ratchet (populated)` | live |
| seed laundering | `ratchet (seed laundering)` | live, against the base |

| keys, not a scalar | `ratchet (keys, not a scalar)` | live, over the tracked root confs |

Every live leg is `subject = "repo"`, `chunk = "declarations"`, `enforces` naming the practice the
pass's enforces rule (unit 11) derives; `ratchet selftest` is `subject = "kit"`, `chunk = "selftests"`.
Each prints its population count and, with no base, `unresolved` naming `compare_to_base`'s reason,
never green (retrofit.md:440-442).

### The widen route

```
python tools/memory-tree/ratchet.py widen unarmed-branches --key "tools/x.sh	exit	fail-sig" --reason "a new fail branch the arm lands with in unit TOOL-dY-4" --unit TOOL-dY-4
  -> memory/builds/dY/build/<date>-build-TOOL-dY-4-widen-1.md   (**Population:** · **Keys:** · **Reason:** · **Caused-by:**)
  -> unarmed-branches row: tools/x.sh	exit	fail-sig	1	<sha>	widened:<date>-build-TOOL-dY-4-widen-1
```

`<record stem>` is the record's file name without `.md`, so the disposition names one tracked file the
leg resolves. `never gains` admits the row only when that file is tracked, its `**Population:**` names
the population, its `**Keys:**` holds the key, and its `**Reason:**` is non-empty; under `refuse` it
reds the row whatever the record says.

## 5. Production-readiness checklist

- security — `widen` writes one record and one row in the working tree; it runs no seed argv itself.

- error / empty / loading states — no base reads `unresolved`; an empty population reads `unarmed`; a
  registration that fails to parse is unit 13's refusal, printed.
- observability — every leg prints its population count and each finding's population and key.
- risks — the touch join stays unarmed until dScopedBuild; said on every `--list`.

## 6. Acceptance criteria

- **AC1** — When `python ratchet.py --fixture --plant gain` runs, a `shrink-only` population gaining a
  key with disposition `seeded` against its base, `never-gains` exits 1 naming the population and the
  key; under `--plant ceiling-raised` it exits 1 naming the raised row, and under `--plant
  append-edited`, an `append-only` base row rewritten, it exits 1 naming the row `edited`.
  Red when: `never gains` reads only counts, so a swapped key at an equal count passes.
- **AC2** — When `python ratchet.py --fixture --plant gain-widened` runs under `retrofit.widen`
  `record-reason`, with a tracked widen record naming the key and a reason, it exits 0; with the
  record's `**Reason:**` empty it exits 1; under `--plant gain-refused`, the same widened row under
  `refuse`, it exits 1 and `ratchet.py widen` refuses to write.
  Red when: a `widened:` disposition naming no tracked record is admitted.
- **AC3** — When `python ratchet.py --fixture --plant both-ways` runs, a measured key with no row and a
  row no seed finds each make `both-ways` exit 1 naming it; a registration naming a leg prints
  `graded by <leg>`.
  Red when: a population whose own leg grades it is measured a second time here.
- **AC4** — When `python ratchet.py --fixture --plant unarmed-green` runs, a registration whose seed
  `test.seed` recorded failed reading armed makes `unarmed` exit 1; under `--plant
  populated-empty-armed`, an empty population after a live seed reading armed makes `populated` exit 1.
  Red when: an empty population reads green.
- **AC5** — When `python ratchet.py --fixture --plant laundering` runs, a re-seed at a later SHA
  re-dating one row and rewriting another's disposition to `seeded` makes `seed-laundering` exit 1
  naming both; a row drained because its seed no longer measures it reads green.
  Red when: a re-dated row passes because its key and count are unchanged.
- **AC6** — When `python ratchet.py --fixture --plant rename` runs, a staged `git mv` of a baselined
  file with its rows re-keyed reads green, and the same rename with the rows left on the old path makes
  `rename` exit 1 naming the rename.
  Red when: a rename reads as a gain on the new path.
- **AC7** — When `python ratchet.py keys-not-scalar` runs on the landed tree, it exits 0 and prints nine
  rows held by `conf-scalar-pins`; with `FOO_PIN="3"` planted in a scratch clone's `.memory-tree.conf`
  it exits 1 naming `FOO_PIN`.
  Red when: the leg reads only the nine named keys, so a tenth pin passes.
  figure: nine is PINNED, measured at `19d6aae6`; the row count is DERIVED from the file at observation.
- **AC8** — When `python ratchet.py --fixture --plant key-number` runs, a `key` kind row whose field is
  `412` makes `key-shape` exit 1 naming it.
  Red when: a numeric label passes as a key.
- **AC9** — When `python ratchet.py --fixture --plant untouched-quiet` runs, a baselined offense outside
  the unit's hunks reads green and an unbaselined one there makes `never-gains` exit 1; under `--plant
  merge`, two branches each draining a different row of one population merge through `merge-rows.sh`
  and `never-gains` and `both-ways` both exit 0.
  Red when: a merged drain leaves a stale row or reads as a gain.
- **AC10** — When `python -c "import json,sys; print(sorted(l['name'] for l in json.load(open(sys.argv[1], encoding='utf-8')) if l.get('pack') == 'ratchet'))" tools/gate-legs.json`
