## 4. Design

### Why one unit

M4 admits a second unit only so that the two halves build concurrently. The seed half (ids 4, 13, 15,
16, 21 and 22) writes the three `legacy_ledger.py` copies and `tools/lib/resolve-python.test.sh`. The
rest writes four other files, so the two write sets are disjoint. Dispatch is strictly sequential, a
shared order included (`tools/workflows/unattended-build.js@248c8263:78`), so a split would buy no
concurrency. One unit holds all 19 findings.

### Evidence

Read at HEAD `248c8263a` on 2026-11-21; each probe ran on git 2.54.0.windows.1, GNU bash 5.3.9
(`x86_64-pc-cygwin`) and Python 3.15.2, PINNED 2026-11-21.

  `tools/run-gates/verdict_backends.py` holds no `fingerprint`, so the line S2 adds never moves the
