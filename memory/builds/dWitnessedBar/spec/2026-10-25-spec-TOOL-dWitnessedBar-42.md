## 1. Goal

The round-1 spec audit (`memory/builds/dWitnessedBar/reviews/2026-10-25-review-TOOL-dWitnessedBar-1-spec-audit-round1.md`)
confirmed finding **id 60 at HIGH**, its item **H3**, alone in that item. `TOOL-dWitnessedBar-25`, landed at
`55d911b39`, writes tails to the shared `<common-dir>/gate-tails/` so they outlive their worktree, and its S4
makes the run sweep keep "exactly the tails some retained run record names". That sweep reads only the
running worktree's `RUNROOT` (`tools/run-gates/run-gates.sh@4430926f:6013`), and its own comment says so
(`tools/run-gates/run-gates.sh@4430926f:6009-6010`). A bar finishing in worktree A deletes tails only worktree B's
retained runs name, or a tail B wrote a moment ago for a run whose verdict is not yet written, and B's
`keep_tails.py --run <id>` finds the file gone. Unattended runs sit in parallel worktrees by design. This
unit takes the report's fix. It repairs `TOOL-dWitnessedBar-25`.

## 2. Scope (IN)

- **S1** — The retained set is every worktree's. The tail sweep reads the `tail.<n>` keys of the
  `verdict` file of every run dir under `<common-dir>/gate-run/` and under each
  `<common-dir>/worktrees/<id>/gate-run/`, the git dir of every worktree of the clone, linked ones
  included. Observed by AC1.
- **S2** — A fresh tail is never swept. A tail file whose modification time is younger than
  `TAIL_GRACE_S`, 604800 seconds (seven days, PINNED by §8 F2), is kept whether or not a verdict names
  it, so a tail written by a bar still running in another worktree survives. Observed by AC2.
- **S3** — A re-hashed tail is freshened. Where a failing leg's tail hashes to a file
  `<common-dir>/gate-tails/` already holds, the runner sets that file's modification time to now with
  `touch -c` where unit 25's writer only unlinks its temp (`tools/run-gates/run-gates.sh@4430926f:5783`), so S2's
  grace runs from the newest bar that produced the tail. Rev-2's S3, the temp from `derive_temp_path`
  renamed into place, landed with `TOOL-dWitnessedBar-25` (`tools/run-gates/run-gates.sh@4430926f:5777-5784`) and
  is not rebuilt (§8 F3). Observed by AC3.
- **S4** — Unit 25's sweep arm ages its tails. The evidence-suite case for `TOOL-dWitnessedBar-25` AC5
  (`tools/run-gates/run-gates.evidence.test.sh@461e6c98:767-777`) sets the modification time of every file in
  `<common-dir>/gate-tails/` past `TAIL_GRACE_S` before each run of its sweep loop, so the case still
  observes removal of an unnamed tail and its exact named-equals-on-disk check holds. Observed by AC1.

## 4. Design

### Evidence

- The run sweep: `ls -1t "$RUNROOT" | grep -v '^current$' | tail -n "+$((GATE_RUN_KEEP+1))"` removes the
  worktree's own older run dirs (`tools/run-gates/run-gates.sh@4430926f:6001-6004`); `RUNROOT="$gd/gate-run"`
  (`tools/run-gates/run-gates.sh@4430926f:2765`); `GATE_RUN_KEEP` defaults to 5 (`tools/run-gates/run-gates.sh@4430926f:2736`).
- The tail sweep unit 25 landed runs inside that block: it resolves the tails directory as
  `$(cd "$RG_COMMON_RAW" && pwd -P)/gate-tails`, gathers the kept hashes from `"$RUNROOT"/*/verdict` alone,
  skips a name that is not all hex digits and removes every other unnamed file
  (`tools/run-gates/run-gates.sh@4430926f:6011-6019`).
- The tail write: a temp from `derive_temp_path _tp "$_td/tail"`, hashed, renamed to `<hash>` where no file
  holds it, else the temp removed and the existing file left untouched
  (`tools/run-gates/run-gates.sh@4430926f:5777-5784`).
- A linked worktree's git dir is `<common-dir>/worktrees/<id>`, the main worktree's is the common dir
  itself, which is git's own layout; the runner resolves the common dir once (`RG_COMMON_RAW`,
  `tools/run-gates/run-gates.sh@4430926f:119-123`).
- `tools/run-gates/run-gates.sh#derive_temp_path` is the runner's existing temp-name helper.

### The sweep

```
named  = tail.<n> hashes in  <common>/gate-run/*/verdict  and  <common>/worktrees/*/gate-run/*/verdict
for each file t in <common>/gate-tails/ whose name is all hex digits:
    keep  if t in named
    keep  if now - mtime(t) < TAIL_GRACE_S
    else  remove t
```

Reading `<common>/worktrees/*/` rather than `git worktree list` costs no fork and keeps the run dirs of
a worktree whose directory was removed but not yet pruned, which errs toward keeping. `<common>` is the
directory the tail block already resolves, so both globs and the tails directory share one spelling. The
comment above the sweep drops its "another worktree's retained runs" limit and states what this one does
not check: a sweep in A that reads a tail's time just before B freshens it can still remove it.

### The write

On the branch where `<common>/gate-tails/<hash>` exists, the runner runs `touch -c` on that file before it
removes its temp; `-c` so a file another sweep removed between the test and the touch is not recreated
empty. Nothing else in the writer moves.

  turnstile keys on its common dir and does not see the host beacon

## 5. Production-readiness checklist

- security — the sweep removes only files under `<common-dir>/gate-tails/`; nothing outside it is read
  for removal.
- perf / scale — one directory listing per worktree's `gate-run/`; a tail is cut to at most 8192 bytes
  (`tools/run-gates/run-gates.sh@4430926f:5778`), so a week of red bars costs megabytes at most.
- error / empty / loading states — an unreadable `verdict` file names nothing and its tails fall to the
  grace; an absent `worktrees/` directory is no linked worktree.
- observability — the sweep prints the count it removed and kept.
- risks — a tail lives at least seven days (PINNED, §8 F2) after its last naming run is swept, which is
  the cost of never racing a running bar.
- testing — AC1 to AC3 by fixture; the arm of §7 at the close.
- migration — none.
- user docs — `tools/run-gates/README.md`'s tails paragraph names the grace and the every-worktree
  reading at the pass, and drops its "What the sweep does not check: another worktree's retained runs"
  sentence; no page under `help/` names the tails directory (`git grep -n gate-tails HEAD -- help/`
  prints nothing, DERIVED at `ebe139e1` on 2026-11-20).

## 6. Acceptance criteria

- **AC1** — When a scratch repository with a linked worktree B holds a tail named only by B's retained
  run, aged past the grace, and worktree A completes more runs than `GATE_RUN_KEEP`, the tail survives; a
  tail aged past the grace and named by no run of either worktree is removed; and unit 25's AC5 case
  still passes with its tails aged.
  Red when: the sweep reads only the running worktree's `RUNROOT`, so B's tail is removed.
  fixture: the suite's `rec_repo` scratch repository (`tools/run-gates/run-gates.evidence.test.sh@461e6c98:502-524`) and a
  `git worktree add "$REC_T.wt"`, as unit 4's arm makes one; the tree holds none.
- **AC2** — When the same sweep meets a tail named by no run whose modification time is one minute old,
  the tail survives, and `grep -c 'TAIL_GRACE_S' run-gates.sh` in `tools/run-gates/` prints at least 2.
  Red when: a fresh tail of a bar still running in another worktree is removed.
- **AC3** — When a red run's failing leg hashes to a tail already on disk whose modification time was
  set past the grace, that file's modification time after the run is within the grace, and
  `<common-dir>/gate-tails/` holds no `tail.*` temp.
  Red when: the existing tail keeps its old time, so another worktree's sweep can remove it before this
  run's verdict names it.
