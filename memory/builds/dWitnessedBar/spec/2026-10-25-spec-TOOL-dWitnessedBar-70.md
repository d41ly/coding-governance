## 1. Goal

The round-1 spec audit of units 66 and 67
(`memory/builds/dWitnessedBar/reviews/2026-10-25-review-TOOL-dWitnessedBar-66-spec-audit-round1.md`)
confirmed finding **id 10 at BLOCKER**, report item **B1**, the round's one blocker. No other id
shares that item.

When `TOOL-dWitnessedBar-66` was built (`e3cdc2201`), the hook read each key through `$(awk ...)`. On
Git for Windows, and on the `windows-latest` CI the bar runs on, gawk reads in text mode and bash
`$(...)` drops a trailing CR-LF. So with the CR strip removed `rec_sha` stayed forty bytes, unit 66's
staged red "CR strip removed" stayed green, and its ledger records that half as owed to this unit's
S3. `TOOL-dWitnessedBar-69` (`9ff80bb15`) replaced those reads with one `IFS= read -r` loop and one
`${_rg_v%$'\r'}` strip. The break now reds on this node: unit 67's builder saw it red on `rec_fp`,
and this re-ground's probe saw it red on `rec_sha` (§4 Evidence). Nothing keeps it that way. A later
read that eats the CR again would leave the arm green and the strip unexercised.

This unit makes the arm PROVE that the planted CR reaches `read_green_file`, on every run and on
whatever platform runs it, before the strip assertion counts. It also makes each staged red a record
of the failing line rather than a claim. It repairs `TOOL-dWitnessedBar-66` and builds at order 39,
after unit 69 within that order.

## 2. Scope (IN)

- **S1** — The CR-reach canary. The AC12 arm in `tools/run-gates/run-gates.gov.test.sh` cuts
  `read_green_file` into `rgf_fn` and then counts unit 66 S2's `rec_sha` compare. Between those two
  steps it builds a mutant of the cut that lacks its CR strip, made by `sed 's/%[$].[\]r.}/}/'` over
  `rgf_fn`. At HEAD that edit rewrites the loop's `_rg_v=${_rg_v%$'\r'}` to `_rg_v=${_rg_v}`. The
  canary checks that the mutant differs from the cut in exactly one line, counting `diff` output lines
  that open `>`, as the evidence suite counts its broken copy's variants
  (`tools/run-gates/run-gates.evidence.test.sh@d31bef203:2983`). It sources the mutant in a subshell,
  calls it on the arm's record `$rgf_rec`, and asserts that `rec_sha` is forty-one bytes whose last
  byte is CR. The arm's comment names the canary and the breaks S3 stages, in place of its two
  awk-era breaks. Its WHAT THIS DOES NOT CHECK clause no longer says the CR is lost on Git for
  Windows, which unit 69's loop made false. In that sentence's place it says that a strip spelled
  other than `%$'\r'}`, or spelled twice, fails the canary at its count rather than grading the CR.
  Observed by AC1.
- **S2** — The canary's failure is loud and stops the count. When the mutant changed a number of lines
  other than one, or its `rec_sha` is not forty-one bytes ending in CR, the arm prints one line,
  `gov-canary: the planted CR never reached read_green_file on <uname -s>; the CR-strip assertion is not counted`,
  sets `fail=1`, and does not increment the executed count for unit 66 S2's assertion. That compare
  still runs and prints its own failure line (§8 F3). Observed by AC2 and AC3.
- **S3** — The staged reds are records with their failing line. At the close, on a Windows node, the
  main loop stages unit 66 §7's two breaks, each in a scratch copy of `.githooks/pre-push` that `diff`
  shows one line away from the hook:
  - a `read_green_file` that lacks its CR strip: a copy without the line
    `    _rg_v=${_rg_v%$'\r'}`, as unit 67's builder staged it;
  - a `read_green_file` whose `sha` case keeps the first of a repeated key: `sha) rec_sha=$_rg_v ;;`
    read as `sha) rec_sha=${rec_sha:+$rec_sha$'\n'}$_rg_v ;;`, unit 66 §7's print-every-match
    carried onto unit 69's loop.

  Unit 66's acceptance ledger records each red as an OBSERVED line opening `- AC2 — `, under its
  `**Evidences:** TOOL-dWitnessedBar-66` block. Each line carries the arm's failing lines as printed
  and the `uname -s` the break ran under. A break with no captured failing line is not recorded as
  red. Observed by AC3.
- **S4** — The record is corrected. Unit 66 rev-3 already rewrote its §4 Evidence's "keeps a CR" as
  this node's probe. Its ledger line for AC2 still records the CR-strip half as green and owed, and
  names no cause. That line, rewritten in place, states the platform fact: at unit 66's build, gawk's
  text-mode input and `$(...)` lost the CR on Git for Windows, and unit 69's loop now passes it on.
  It cites this spec's §4 Evidence. Observed by AC4.

## 4. Design

### Evidence

- At the base, `x=$(awk -F'\t' '$1=="sha"{print $2}' rec)` over a record whose second `sha` line
  ends in CR-LF gave 81 bytes with no CR on this node (PINNED 2026-10-25, GNU Awk 5.4.0).
  Unit 66's ledger, beside AC2, records the strip-less copy green under unit 66's awk reads, at
  40 bytes (PINNED 2026-11-21 by that ledger).
- Probed at `09b2a2c2e` (PINNED 2026-11-21) under `uname -s` `MINGW64_NT-10.0-22621`, bash 5.3.9
  `x86_64-pc-cygwin` and git 2.54.0.windows.1 (PINNED 2026-11-21). The arm's own lines, cut from the
  gov suite from `rgf_t=$(mktemp -d)` to `rm -rf "$rgf_t"`, built the `clean` plant's record. A
  prototype canary over HEAD's cut had its `diff` count one line, and the mutant read `rec_sha` as
  41 bytes ending in `\r`, and `rec_fp` as 41 (PINNED 2026-11-21, this probe).
- Four scratch copies of the hook, each one `diff` line from it (PINNED 2026-11-21, this probe):

  | copy | the arm's compares | canary count | mutant `rec_sha` |
  |---|---|---|---|
  | `sha` case through `$(awk ...)` with its own strip | both hold | 2 | 40 bytes, ending `b` |
  | strip line deleted | `rec_sha` and `rec_fp` red, each value ending `\r` | 0 | unchanged |
  | S3's print-every-match | `rec_sha` red, printing both values | 1 | 82 bytes (PINNED 2026-11-21, this probe) |
  | `sha) rec_sha=${rec_sha:-$_rg_v} ;;` | `rec_sha` red, printing `a…a` | 1 | 40 bytes, ending `a` |

  So both of S3's breaks trip the canary as well as unit 66 S2's compare. The print-every-match copy
  reaches the canary's byte check, and the `$(awk ...)` copy stops at its count, as
  `TOOL-dWitnessedBar-74` §1 states.
- Unit 67's builder staged the strip-less break and the arm printed `set rec_fp to '...\r'`
  (`memory/builds/dWitnessedBar/build/2026-11-19-build-TOOL-dWitnessedBar-67-1-acceptance-ledger.md`,

  applies it to the cut function only, where the count it checks is one.
