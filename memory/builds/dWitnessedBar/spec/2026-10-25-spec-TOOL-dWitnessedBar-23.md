## 1. Goal

Add one role slot, `gov-tester`, to today's roles kit: an agent whose allowance is scratch only and
whose judgment set is closed at `code-miss` and `spec-wrong`. It plays `test.attribute` (judging an
OWN or a blocking MIXED red), `test.reason` (answering the Test step's one question) and the fix pass's
wrong-spec judgment, until dBoundRoles re-founds it with the other roles (WK-1). Today the loop names
`role:gov-tester` as the actor of `item.test.reason` and prints it `pending`, because no slot exists.

### The role file

```markdown
---
name: gov-tester
description: Judges a red the bar attributed to this build, and answers the Test step's question.
tools: Read, Grep, Glob, Bash
model: inherit
workflow: gate-bar
reads: input:spec, input:diff?, input:question?
writes: none
rules: verify, spec, gate, class, risk
returns: for each red handed, one judgment, code-miss or spec-wrong (the closed outcomes of the item.test.attribute row), with the evidence observed; for the Test step's question, its answer and the evidence
mandatory: no — when Test hands it an OWN or blocking MIXED red, a fix pass asks whether the spec is wrong, or the reason stage asks its question
output: judgments, to its harness
---
```

The body, under the 3072-byte ceiling, says: you judge each red you are handed against the unit's
spec and its diff, and return exactly one of the two judgments per red; `code-miss` when the code does
not do what the spec's criterion says, `spec-wrong` when the criterion or the leg asks for something
the goal does not need or contradicts another criterion; you never fix code, edit a spec or a test,
or run a gate (BUILD-METHOD M6), and you write only under the scratch path your task names; a red you
cannot judge from the evidence is `code-miss`, the conservative route, with the reason said.
