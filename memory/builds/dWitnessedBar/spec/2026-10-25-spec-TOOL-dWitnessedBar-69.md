## 1. Goal

The round-1 spec audit of units 66 and 67
(`memory/builds/dWitnessedBar/reviews/2026-10-25-review-TOOL-dWitnessedBar-66-spec-audit-round1.md`)
confirmed finding **id 19 at HIGH**, report item **H3**. No other id shares that item. Its defect
also underlies blocker id 10 (item B1, `TOOL-dWitnessedBar-70`) and id 20 (item H4,
`TOOL-dWitnessedBar-72`), which each take their own unit.

On the bar's platform the I/O layer removes the CR before either reader's strip sees it. Git for
Windows gawk reads its input in text mode and drops the CR before an LF, and bash `$(...)` drops a
trailing CR-LF. The hook reads each key with `rec_<x>=$(awk ...)` in
`.githooks/pre-push#read_green_file`, so deleting the CR strip `TOOL-dWitnessedBar-65` S15 landed
there changes nothing (§4 Evidence). The local-hook reader opens the record in Python's default text
mode, which translates `\r\n` and a lone `\r` too, and `tools/run-gates/verdict_backends.py#read_tag_lines`
splits it with `splitlines()`, which takes CR-LF as one break even under `newline=""`. Its strip is
unreachable on every platform. Every `remote-ci` job is `runs-on: windows-latest`.

This unit changes how both readers read the record, so the bytes reach the strip: the hook through
one bash loop that reads whole lines, the local-hook reader through an open that keeps line endings
and a split on LF alone. It repairs `TOOL-dWitnessedBar-66`, whose arm grades that strip, and builds
at order 39.

## 2. Scope (IN)

- **S1** — The hook's `read_green_file` reads the record in one loop,
  `while IFS= read -r _rg_l || [ -n "$_rg_l" ]; do ... done 2>/dev/null < "$1"`, in place of its seven
  `$(awk ...)` reads, each the `END`-print form unit 65 S15 landed. For each line:
  - a line holding no TAB is skipped, as unit 63 S19 rules;
  - the key is the text before the first TAB, `${_rg_l%%$'\t'*}`, and the value the text after it,
    `${_rg_l#*$'\t'}`, as unit 62 S24 rules;
  - the value is stripped of one trailing CR, `${_rg_v%$'\r'}`, as unit 65 S15 rules;
  - a `case` on the key assigns the value to the one of the seven `rec_*` variables that key names,
    each arm spelled `<key>) rec_<x>=$_rg_v ;;` unquoted, so `sha) rec_sha=$_rg_v` and
    `fingerprint) rec_fp=$_rg_v`, and a later line of a repeated key overwrites an earlier one, as unit
    65 S15 rules.

  `_rg_l`, `_rg_k` and `_rg_v` are `local`. An unreadable file leaves all seven empty, as today. The
  function's comments move beside their `case` arms and name no `awk`, and its closing `}` stays the
  only column-0 `}` in it, so the `awk '/^read_green_file\(\)/,/^}/'` cut the gov and pre-push suites
  take still holds the whole function. Observed by AC1, AC2 and AC3.
- **S2** — The local-hook reader. `tools/run-gates/verdict_backends.py#read_local_verdict` opens the
  per-tree record with `open(slot, encoding="utf-8", errors="replace", newline="")` in place of
  `slot.read_text(...)`, keeping its `OSError` outcome. `read_tag_lines`, the parse it goes through,
  splits its text on `"\n"` only in place of `splitlines()`, skips a line whose `partition("\t")`
  separator is empty as it does today, and strips one trailing `"\r"` in place of `rstrip("\r")`,
  which strips every one. A lone CR inside a value stays data (§8 F3). Observed by AC4.

## 4. Design

### Evidence

Probed on this node at `9fde76576` (PINNED 2026-11-21): GNU Awk 5.4.0, GNU bash 5.3.9
(`x86_64-pc-cygwin`), git 2.54.0.windows.1. The record held `sha<TAB>` forty `a` `<LF>`, `sha<TAB>`
forty `b` `<CR><LF>`, `manifest<TAB>x<TAB><LF>`, a bare `fingerprint<LF>` and `selftests<TAB>on`.

- HEAD's `read_green_file`, cut by its awk range and sourced, read `rec_sha` as 40 bytes. With each
  ` sub(/\r$/, "", v);` deleted, seven lines changed and `rec_sha` still read 40 bytes, so the strip
  unit 65 S15 landed is unreachable here. A later bare `sha` line after a `sha<TAB>` line read
  `rec_sha` empty, since `v=$2` runs with no second field (PINNED 2026-11-21).
- `while IFS=$'\t' read -r k v` kept the CR, but split `note<TAB>a<TAB>` into a value `a` and
  `x<TAB><TAB>y` into `y`: TAB is IFS whitespace, so a trailing TAB is trimmed and a run collapses.
  The base form `x=$(awk -F'\t' '$1=="sha"{print $2}' rec)` gave the value with no CR.
- A prototype of S1's loop gave `rec_sha` forty `b`, `printf %s "$rec_man" | od -c` gave `x \t`, and
  `rec_st` `on`. With `%$'\r'` deleted by `sed 's/%[$].[\]r.}/}/'`, which changed exactly one line,
  `rec_sha` was 41 bytes ending in `\r`. The bare later `sha` line left the earlier value standing.
- Python's `open(p).read()` ended `...bbb\n`, and `open(p, newline="").read()` ended `...bbb\r\n`.
  `memory/gotchas/text-mode-read-eats-a-bare-cr.md` records that the default mode also turns a lone CR
  into a newline. Over the `newline=""` text, a `splitlines()` parse with no strip still read `verdict`
  as `GREEN`, and a `split("\n")` parse with no strip read `GREEN\r`.
- In a scratch `git init`, a per-tree record of AC4's shape read `GREEN` through
  `read_local_verdict`, and read `GREEN` again from a scratch copy whose `.rstrip("\r")` was deleted,
  one line changed (PINNED 2026-11-21).
- `grep -c 'runs-on: windows-latest' .github/workflows/remote-ci.yml` prints 4 (PINNED 2026-11-21).
- The hook calls `read_green_file` once, at `.githooks/pre-push@9fde76576:2074`, and sources nothing
  from `tools/`: its one `.` line, `.githooks/pre-push@9fde76576:681`, sources `.githooks/gate-env.sh`.

### Alternatives rejected

- **`while IFS=$'\t' read -r k v`, the report's form.** It keeps the CR but trims a trailing TAB and
  collapses a run of TABs (§4 Evidence), so the hook would part from unit 62 S24's value rule and
  from the local-hook reader on a value holding a TAB.
- **Keep awk and stage the CR mid-field, the report's option (a).** The plant then reaches the strip
  only if unit 65 S15 strips the stored value rather than `$0`, and `$(...)` still eats a trailing
  CR-LF, so the arm would grade a fixture shape rather than the read.
- **`BINMODE=3` on each awk call.** It keeps the CR through awk, but `$(...)` still drops a trailing
  CR-LF in MSYS bash, and the variable is gawk-only.
- **`newline=""` alone, `read_tag_lines` unchanged.** `splitlines()` still eats the CR (§4 Evidence),
  so AC4's red never shows (§8 F3).

## 5. Production-readiness checklist

- security — the hook's push decision reads the same seven values from every record the runner
  writes. A record with a CR now has it removed by the strip rather than by the platform.
- perf / scale — one read of the file replaces seven awk processes, each a fork (DERIVED by
  `grep -c 'awk -F'` over HEAD's cut function).
- error / empty / loading states — an absent file returns early as today, and an unreadable one leaves
  every variable empty, its error discarded as `2>/dev/null` discards awk's today. S2 keeps its
  `OSError` read as `DEAD PROBE`.
- observability — none changes: the hook's refusal messages name the predicates, not the read.
- risks — at HEAD a bare key line after a TAB'd one blanks that variable (§4 Evidence); S1 skips it,
  so the earlier value stands, unit 63 S19's absent-key rule and `read_tag_lines`'s reading.
- testing — AC1 to AC4 by probe and scratch copy. The pre-push suite's `TOOL-dWitnessedBar-63` AC11
  arm and the gov canary's AC12 arm and `key-no-tab` plant re-observe S1 and S2 at the close.
- migration — none.
- user docs — none under `help/`; no user-facing surface changes.
