## 1. Goal

dGroundRules landed `tools/policy/legacy-homes.txt`, the shrink-only list of every key a legacy policy
home holds, in a grammar of its own (`<home> <key> <mark>`, TOOL-dGroundRules-7 §4 "Data model",
rendered under `tools/policy/policy.py#LEGACY_HEADER`). Now that the ledger factory exists, this unit
converts that list into one ledger population keyed by conf and key, homed beside gov's other
registries under `memory/project/` (§8 F7), so the list is graded by the one engine every tolerated
population shares (the recut's M4; gap-test-14's "27 registries in at least 6 grammars").

## 4. Design

### The registration

```toml
# tools/govkit/registry.toml, beside the other gov-own [[ledger]] tables (§8 F4)
[[ledger]]
population = "legacy-homes"
leg = "policy check"
seed = ["python", "{prefix}/policy/policy.py", "lists", "--derive", "legacy-homes"]
key = "key"
fields = ["conf", "key"]
drain = "key"
direction = "shrink-only"
home = "memory/project/legacy-homes.txt"
```

| Field | Why |
|---|---|
| `population` | the list's own name, which `check_policy.py` already uses for its fixture case |
| `seed` | the derivation is the population; the factory runs it rather than reading prose |
| `key`, `fields` | the clause's "keyed by conf and key"; a legacy home key is a conf key, never a site |
| `drain` | a row leaves when its key leaves its home, which is a fold, never a hunk |
| `direction` | TOOL-dGroundRules-7 S4: the homes only shrink until dConvergedCharter folds them |
| `home` | gov's own lists' home outside the tool root, as units 16 and 18 placed theirs (§8 F7) |
| `leg` | the leg that runs the `legacy-homes` arm, so `test.seed` finds the check at that leg's row |

The table's grammar is unit 13's (its §4 "The registration"). `conf` names the legacy home's path,
`.githooks/gate-env.sh` and `<tool-root>/roles/house/policy.toml` included, which are homes and not
conf files: the clause's word is kept so the key field reads as the clause does. A home is written as
`derive_legacy_homes` writes it, so the roles kit's house file keeps its `<tool-root>/` token

### The row

```
# ledger · legacy-homes · key key conf,key · direction shrink-only · drain key
.unattended.conf	ANCHOR_SCOPE	1	<sha40>	seeded
<tool-root>/roles/house/policy.toml	[effort]	1	<sha40>	seeded
```

The first line is the header the factory renders from the registration, which its reader compares
(TOOL-dWitnessedBar-13 §4 "The ledger file"). It is the file's only `#` line:
`tools/lib/legacy_ledger.py#write_rows` writes the header and the rows alone, so TOOL-dGroundRules-7's
never-by-hand note would not survive the first write, and it moves to the README and the help page
(S9, S10). Rows sort by conf then key. The count is always `1`: a key is assigned in its home once, and
a second assignment is the same key. The conversion is a regrammar, never a re-seed: it writes the key
set the list held at the build run's base, each row `seeded` at that base SHA, through `write_rows`
over the registration, and adds or drops no key.

declared `requires` (the comment above `tools/policy/policy.py#resolve_kit_dir`). The policy kit
already requires `memory-tree` (`tools/policy/kit.toml`), and the memory-tree kit carries the factory
inline in `tools/memory-tree/legacy_ledger.py`, whose docstring names the converting kits that require
it as its callers. `policy.py` loads that module through `resolve_kit_dir("memory-tree",
"legacy_ledger.py", KIT)`, the way `tools/policy/check_policy.py#load_tree_lib` loads `tree_lib`,
putting that directory on `sys.path` so the copy's own imports of `backlog` and `coverage_join`
resolve.

`policy.py` never spells the list's path: a new `read_legacy_registration(repo)` returns the factory
and the `[[ledger]]` registration whose `population` is `legacy-homes` at `repo`, read by
`read_registrations`, or None where none names it; a refused registration is a `Refusal`.
`check_legacy_graded(repo, kit)` holds where `derive_census_tree` answers `source`, a registration is
found, and its home is a file. `read_registrations` reads tracked files alone, so a tree whose
