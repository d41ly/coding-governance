## 1. Goal

dGroundRules landed `tools/policy/legacy-homes.txt`, the shrink-only list of every key a legacy policy
home holds, in a grammar of its own (`<home> <key> <mark>`, TOOL-dGroundRules-7 §4 "Data model",
rendered under `tools/policy/policy.py#LEGACY_HEADER`). Now that the ledger factory exists, this unit
converts that list in place into one ledger population keyed by conf and key, so the list is graded
by the one engine every tolerated population shares (the recut's M4; gap-test-14's "27 registries in
at least 6 grammars").

## 4. Design

### The registration

```toml
# tools/govkit/registry.toml, beside its [[exempt_leg]] rows (§8 F4)
[[ledger]]
population = "legacy-homes"
leg = "policy check"
seed = ["python", "{prefix}/policy/policy.py", "lists", "--derive", "legacy-homes"]
key = "key"
fields = ["conf", "key"]
drain = "key"
direction = "shrink-only"
home = "tools/policy/legacy-homes.txt"
```

| Field | Why |
|---|---|
| `population` | the list's own name, which `check_policy.py` already uses for its fixture case |
| `seed` | the derivation is the population; the factory runs it rather than reading prose |
| `key`, `fields` | the clause's "keyed by conf and key"; a legacy home key is a conf key, never a site |
| `drain` | a row leaves when its key leaves its home, which is a fold, never a hunk |
| `direction` | TOOL-dGroundRules-7 S4: the homes only shrink until dConvergedCharter folds them |
| `home` | the list stays where its check keeps it (retrofit.md `[ledger]`, "No population moves") |
| `leg` | the leg that runs the `legacy-homes` arm, so `test.seed` finds the check at that leg's row |

The table's grammar is unit 13's (its §4 "The registration"). `conf` names the legacy home's path,
`.githooks/gate-env.sh` and `<tool-root>/roles/house/policy.toml` included, which are homes and not
conf files: the clause's word is kept so the key field reads as the clause does. A home is written as
`derive_legacy_homes` writes it, so the roles kit's house file keeps its `<tool-root>/` token
(`tools/policy/policy.py#HOUSE_HOME`).

### The row

```
# ledger · legacy-homes · key key conf,key · direction shrink-only · drain key
.unattended.conf	ANCHOR_SCOPE	1	<sha40>	seeded
<tool-root>/roles/house/policy.toml	[effort]	1	<sha40>	seeded
```

The first line is the header the factory renders from the registration, which its reader compares
(TOOL-dWitnessedBar-13 §4 "The ledger file"). It is the file's only `#` line:
`tools/lib/legacy_ledger.py#write_rows` writes the header and the rows alone, so TOOL-dGroundRules-7's
never-by-hand note would not survive the first write, and it moves to the README and the help page
(S9, S10). Rows sort by conf then key. The count is always `1`: a key is assigned in its home once, and
a second assignment is the same key. The conversion is a regrammar, never a re-seed: it writes the key
set the list held at the build run's base, each row `seeded` at that base SHA, and adds or drops no key.

### The mark

TOOL-dGroundRules-7 stored each row's mark beside its key. The ledger row has no field for it (I4:
key fields, count, SHA, disposition), and the mark is already derived from `GATE_ENV_MARKS` and the
home's kind every time `lists --check` runs. Storing it was the same fact typed twice ([one-fact]), so
it leaves the file and `lists --marks legacy-homes` prints it on demand (§8 F1).

### Reaching the factory

`tools/lib/` ships nothing, and a kit may not import a sibling except through `resolve_kit_dir` and a
declared `requires` (the comment above `tools/policy/policy.py#resolve_kit_dir`). The policy kit
already requires `memory-tree` (`tools/policy/kit.toml`), and the memory-tree kit carries the factory
inline in `tools/memory-tree/legacy_ledger.py`, whose docstring names the converting kits that require
it as its callers. `policy.py` loads that module through `resolve_kit_dir("memory-tree",
"legacy_ledger.py", KIT)`, the way `tools/policy/check_policy.py#load_tree_lib` loads `tree_lib`, and
takes its registration from `read_registrations` over the repository top. It loads it only after
`check_legacy_graded` holds, so an install, which holds no list, never needs the factory (§8 F5).

### The check and the write

| Finding | Before (`tools/policy/policy.py#check_legacy_homes`) | After |
|---|---|---|
| a typed row the derivation does not yield | report (1), its own compare | `compare_counts`: an `unmeasured row` |
| a derived key the list lacks | report (2), stale list | `compare_counts`: an `undeclared site` |
| a new key past the base | report (3), its own compare against `read_base_pairs` | `compare_to_base` under `shrink-only`: `gained`, a key above the base's with no `widened` disposition |
| a header that disagrees with the registration | none | `render_header` compared with the first line |
| a gate-env key with no mark | report (4) | unchanged, read from the derivation |

`lists --check` keeps its `legacy homes:` prefix and the remedy text for a new key ("carry it as a key
in `tools/policy/catalogue.toml` instead"), because that remedy is this population's own; the grading
is the factory's. `lists --write` still grows the list by no command: the only way a key enters the population is
the factory's widen route, which writes the row `widened:<record>` (§8 F2).

### The fixture

`build_legacy_repo` copies the kit's files into a scratch repository at the kit's own path. For the
converted verbs to run there, it also writes a `govkit/registry.toml` under the copy's tool root
holding only the one `[[ledger]]` table, and copies `legacy_ledger.py` and `coverage_join.py` from the
memory-tree kit `resolve_kit_dir` finds into the directory its probe reads from the kit copy. Its
seed step writes the header the registration renders, where today it writes `LEGACY_HEADER`. `widened`
types the `growth` case's row with the disposition `widened:<record>`. `drain-merge` configures
`merge.rows.driver` and the attribute in the scratch repository, drains a different key on each of
two branches, and merges them.

### Inventory

Minted: the population name `legacy-homes` in the factory's registry; the `lists` flags `--derive
<list>` and `--marks <list>`; the fixture cases `widened` and `drain-merge`. Naming cells: each flag is
asked of `python tools/lexicon/lexicon.py --suggest <name> --as cli.flag` at the pass.

### Migration

One commit converts the file, registers it and re-points both readers together, so no tree holds the
old grammar beside the new readers. A branch cut before the conversion that edits the list conflicts on
the whole file once; the driver refuses the mixed grammar and `lists --write` re-renders it.

### Rollout

Live at landing on the `policy check` leg, which runs `arm_legacy_homes` (`tools/gate-legs.json`, its
row declared by `tools/policy/kit.toml`'s `[[gate_leg]]`), and on unit 14's `ratchet` legs, which grade
every registered population.

### Alternatives rejected

- **Register the list as its own key kind** (the brief's second option): a fifth row grammar beside
  I4's, the defect gap-test-14 names, and a key kind outside I4's closed four
  (`tools/lib/legacy_ledger.py#KEY_KINDS`).
- **Keep the mark as a fourth key field**: a mark change would read as a key gain and a key drain, and
  the clause keys the population by conf and key alone.
