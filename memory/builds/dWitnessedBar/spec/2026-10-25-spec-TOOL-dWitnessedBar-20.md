## 1. Goal

dGroundRules lands `tools/policy/legacy-homes.txt`, the shrink-only list of every key a legacy policy
home holds, in a grammar of its own (`<home> <key> <mark>`, TOOL-dGroundRules-7 §4 "Data model"). Once
the ledger factory exists, this unit converts that list in place into one ledger population keyed by
conf and key, so the list is graded by the one engine every tolerated population shares (the recut's
M4; gap-test-14's "27 registries in at least 6 grammars").

## 2. Scope (IN)

- **S1** — The registration. One `[[ledger]]` table in `tools/policy/kit.toml`, the registration the
  ledger factory `tools/lib/legacy_ledger.py` reads through `read_registrations` (shared interface I4,
  TOOL-dWitnessedBar-13 S2), its fields as §4 "The registration" gives them: `population`
  `legacy-homes`, `seed` the argv of S3, `key` kind `key` with `fields` `conf` and `key`, `drain` `key`,
  `direction` `shrink-only`, `home` `tools/policy/legacy-homes.txt`, and `leg` the `policy check` leg.
  Observed by AC8.
- **S2** — The list converted in place. `tools/policy/legacy-homes.txt` keeps its path and its key set,
  and each row takes I4's grammar, TAB-separated: `<conf>`, `<key>`, the count `1`, the SHA the row was
  seeded at, and its disposition, with no line number in any field. Observed by AC1 and AC2.
  **Readers:** by name: READER NOT IN TREE — the list and its two readers, `policy.py lists` and the
  `legacy-homes` arm of `check_policy.py`, land with dGroundRules' build run, which the chain runs
  before this unit; both are re-pointed by S4 and S5 · by value: NO VALUE READERS — no reader outside
  `tools/policy/` compares, counts or derives from the mark column; TOOL-dSafePassage-1 S5 states it
  does not read the list, measured by `git grep -n legacy-homes -- memory/builds/dSafePassage/spec`.
- **S3** — The seed argv. `python tools/policy/policy.py lists --derive legacy-homes` prints one
  `<conf>TAB<key>TAB1` line per key `derive_legacy_homes` yields, the seed output the factory reads
  (the key's fields then the count, TOOL-dWitnessedBar-15 §4) (TOOL-dGroundRules-7 §4 "The
  derivation"), sorted, the same rows the population holds, so the factory measures the population
  by running it at a SHA. Observed by AC3.
- **S4** — `lists --write` through the factory. The legacy-homes half of `policy.py lists --write`
  writes the population through the factory's row writer: a key the derivation no longer yields leaves
  with its row, every other row keeps its bytes, and a derived key the population lacks is refused with
  nothing written, as TOOL-dGroundRules-7 S4 states. Observed by AC4 and AC6.
- **S5** — `lists --check` through the factory. The legacy-homes half of `policy.py lists --check`
  grades the population by the factory's grade for its registration (both ways, and the
  `shrink-only` direction against the factory's compare base), printing each finding under the
  `legacy homes:` prefix with the remedy TOOL-dGroundRules-7 §4 states for a new key; the `unmarked`
  report (TOOL-dGroundRules-7 S3) stays, read from the derivation. Observed by AC4, AC5 and AC7.
- **S6** — The mark derived, never stored. A row's mark, `owner-policy`, `mechanic` or `unmarked`, is
  read from `derive_legacy_homes` and its table `GATE_ENV_MARKS`, the one declaration of it, and
  `policy.py lists --marks legacy-homes` prints `<conf>TAB<key>TAB<mark>` for a reader that wants it.
  Observed by AC7.
- **S7** — The merge attribute. `.gitattributes` gains `tools/policy/legacy-homes.txt merge=rows`, so a
  conflict on the list reaches the row-keyed driver `tools/memory-tree/merge-rows.py`, whose ledger
  class `check_ledger(path)` keys a row by its key fields (I4). Observed by AC9.
- **S8** — The fixture cases. The `legacy-homes` arm's `--fixture` cases of TOOL-dGroundRules-7 S5
  (`planted-row`, `growth`, `shrink`, `retrofit`, `unmarked`, `absent-homes`) re-pointed onto the
  ledger grammar, plus two new cases, `widened` and `drain-merge`. Observed by AC4, AC5, AC6, AC7 and
  AC9.
- **S9** — The help page. The list's section of `help/policy.md` (TOOL-dGroundRules-7 S6) states the
  ledger row, where the mark is read now, and that a new legacy key is refused unless the ledger's widen
  route admits it. NOT OBSERVED — prose, read by the closing review; no command observes a page's
  content.

## 4. Design

### The registration

| Field | Value | Why |
|---|---|---|
| `population` | `legacy-homes` | the list's own name, which `check_policy.py` already uses for its arm |
| `seed` | `python tools/policy/policy.py lists --derive legacy-homes`, measured at a SHA | the derivation is the population; the factory runs it rather than reading prose |
| `key`, `fields` | `key`, its fields `conf` and `key` | the clause's "keyed by conf and key"; a legacy home key is a conf key, never a site |
| `drain` | `key` | a row leaves when its key leaves its home, which is a fold, never a hunk |
| `direction` | `shrink-only` | TOOL-dGroundRules-7 S4: the homes only shrink until dConvergedCharter folds them |
| `home` | `tools/policy/legacy-homes.txt` | the list stays where its check keeps it (retrofit.md `[ledger]`, "No population moves") |
| `leg` | `policy check` | the leg that runs the `legacy-homes` arm, so `test.seed` finds the check at that leg's row |

The table's grammar is unit 13's (its §4 "The registration"); this unit writes one table with these
values. `conf` names the legacy home's path, `.githooks/gate-env.sh` and
`tools/roles/house/policy.toml` included, which are homes and not conf files: the clause's word is kept
so the key field reads as the clause does.

### The row

```
# ledger · legacy-homes · key key conf,key · direction shrink-only · drain key
# written by `python tools/policy/policy.py lists --write` through the factory; never edited by hand
.unattended.conf	REVIEW_ROUNDS	1	<sha40>	seeded
tools/roles/house/policy.toml	[effort]	1	<sha40>	seeded
```

The first line is the header the factory renders from the registration and its reader compares both
ways (TOOL-dWitnessedBar-13 §4 "The ledger file"); a second `#` line is ignored by that reader and
keeps TOOL-dGroundRules-7's never-by-hand note. Sorted by conf then key. The count is always `1`: a key is assigned in its home once, and a second
assignment is the same key. The conversion is a regrammar, never a re-seed: it writes the key set the
list held at the build run's base, each row `seeded` at that base SHA, and adds or drops no key.

### The mark

TOOL-dGroundRules-7 stored each row's mark beside its key. The ledger row has no field for it (I4:
key fields, count, SHA, disposition), and the mark is already derived from `GATE_ENV_MARKS` and the
home's kind every time `lists --check` runs. Storing it was the same fact typed twice ([one-fact]), so
it leaves the file and `lists --marks legacy-homes` prints it on demand (§8 F1).

### The check and the write

| Finding | Before (TOOL-dGroundRules-7 §4) | After |
|---|---|---|
| a typed row the derivation does not yield | `lists --check` item 1, its own compare | the factory's both-ways arm: a row no scan finds |
| a derived key the list lacks | item 2, stale list | the factory's both-ways arm: a measured instance with no row |
| a new key past the base | item 3, its own landed-revision compare | the factory's `shrink-only` rule against its base: a key above the base's with no `widened` disposition |
| a gate-env key with no mark | item 4 | unchanged, read from the derivation |

`lists --check` keeps its `legacy homes:` prefix and the remedy text for a new key ("carry it as a key in
`tools/policy/catalogue.toml` instead"), because that remedy is this population's own; the grading is the
factory's. `lists --write` still grows the list by no command: the only way a key enters the population
is the factory's widen route, which writes the row `widened:<record>` (§8 F2).

### Inventory

Minted: the population name `legacy-homes` in the factory's registry; the `lists` flags `--derive
<list>` and `--marks <list>`; the fixture cases `widened` and `drain-merge`. Naming cells: each flag is
asked of `python tools/lexicon/lexicon.py --suggest <name> --as cli.flag` at the pass.

### Migration

One commit converts the file, registers it and re-points both readers together, so no tree holds the
old grammar beside the new readers. A branch cut before the conversion that edits the list conflicts on
the whole file once; the driver refuses the mixed grammar and `lists --write` re-renders it.

### Rollout

Live at landing on dGroundRules' `policy check` leg, which runs the `legacy-homes` arm, and on unit 14's
`ratchet` legs, which grade every registered population.

### Files touched (estimate)

- `tools/policy/legacy-homes.txt`
- `tools/policy/policy.py`
- `tools/policy/check_policy.py`
- `tools/policy/kit.toml` (the `[[ledger]]` table)
- `.gitattributes`
- `help/policy.md`

### Alternatives rejected

- **Register the list as its own key kind** (the brief's second option): a fifth row grammar beside
  I4's, the defect gap-test-14 names, and a key kind outside I4's closed four.
- **Keep the mark as a fourth key field**: a mark change would read as a key gain and a key drain, and
  the clause keys the population by conf and key alone.
