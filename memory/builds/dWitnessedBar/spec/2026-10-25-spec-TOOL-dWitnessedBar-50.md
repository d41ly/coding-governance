## 1. Goal

The round-1 spec audit (`memory/builds/dWitnessedBar/reviews/2026-10-25-review-TOOL-dWitnessedBar-1-spec-audit-round1.md`)
confirmed finding **id 50 at HIGH**, its item **H11**, alone in that item. `.githooks/pre-commit`
sources `resolve-python.sh` from a path it derives at run time (`. "./$r"`) and calls `resolve_python`
(`.githooks/pre-commit#resolve_hook_python`), but `TOOL-dWitnessedBar-27` lists its population, and
the list leaves the hook out. The arm's "sources" predicate is never stated, and unit 27's AC5
compares only listed sets. Built to the list, the hook a WSL user meets on `git commit` in a
`/mnt/c` checkout gets no refusal while AC5 stays green. This unit takes the skeptic's corrected fix:
the population becomes a predicate the arm derives, and the hook gains its refusal. It repairs
`TOOL-dWitnessedBar-27`.

## 2. Scope (IN)

- **S1** — The predicate, stated. The population is every tracked shell file under `tools/`, `skills/`
  and `.githooks/`, a shell file being one named `*.sh` or whose first line is a `bash` or `sh` shebang,
  that carries a `# >>> resolve_python` block or calls `resolve_python` at command position (`$(resolve_python`
  or a line beginning `resolve_python`) outside such a block. The canonical `tools/lib/resolve-python.sh`
  is outside it. Observed by AC1.
- **S2** — The named exclusions. Three files the predicate selects are outside (S2's own list, §8 F2
  and F3), each because a member it sources or is sourced by refuses before its first call. The arm
  prints each exclusion and its reason on every run, and refuses an exclusion written without one.
  Observed by AC1 and AC3.
  - `tools/unattended/lib-unattended.sh` is sourced by members, and its two calls each sit behind
    `declare -F resolve_python` (`tools/unattended/lib-unattended.sh@1c5ed3436d86:191`, `:1181`).

    refuses as it is sourced, before its call (`tools/unattended/pass-tree.sh@7b91eac6f001:75`, `:158`).
  - `tools/unattended/pass-tree.test.sh` does the same
    (`tools/unattended/pass-tree.test.sh@b14326f31d52:37`, `:44`).
- **S3** — The member unit 27 did not list. `.githooks/pre-commit` carries the `# >>> refuse_wrong_shell`
  block inline, directly after `set -u` (`.githooks/pre-commit@9b80d8a208e1:4`), and the line after
  `# <<< refuse_wrong_shell` is `refuse_wrong_shell || exit 2`, so the hook refuses before its first
  command on every commit, whether or not a leg resolves python (§8 F4). Unit 27's
  `refuse_wrong_shell` parity row grades that copy. `tools/check-line-length.sh` and

  `tools/playbook/adopt-playbook.sh@360efa7064bd:18`): they are unit 27's inline members and leave
  this unit. Observed by AC1 and AC2.
- **S4** — The arm derives, never lists. `bash tools/lib/refuse-wrong-shell.sh --coverage` derives the
  population from S1, prints its count and the named exclusions, and exits 1 naming each member that

## 4. Design

### Evidence

Measured at `d08ded6f1` on 2026-11-19, the tree as built through unit 26:

- The hook resolves python lazily. `resolve_hook_python` (`.githooks/pre-commit#resolve_hook_python`)
  runs `r=$(git ls-files -- '*resolve-python.sh' | head -n 1)`, then `. "./$r"` and
  `p=$(resolve_python)` (`.githooks/pre-commit@9b80d8a208e1:214`, `:215`). A leg calls it only when it
  needs python, after the branch guard (`.githooks/pre-commit@9b80d8a208e1:25`) has run git.
- `git grep -l 'resolve-python\.sh' -- tools skills .githooks` lists 95 files (PINNED): 83 carrying
  the block (PINNED) and 12 without it (PINNED). Of the 12 (PINNED), seven are S1 callers (PINNED):
  `.githooks/commit-msg`, `.githooks/pre-commit`, `.githooks/straggler-guard.test.sh`,
  `tools/lib/pyrun.sh`, `tools/lib/python-floor.sh`, `tools/lib/resolve-python.test.sh` and
  `tools/memory-tree/transition-audit.test.sh`. The other five (PINNED) are S4's outside files.
- S1's predicate, by the probe below, yields 93 files (PINNED): 83 block carriers (PINNED) and 10
  callers carrying no block (PINNED), the seven above, `tools/unattended/lib-unattended.sh`,
  `tools/unattended/pass-tree.sh` and `tools/unattended/pass-tree.test.sh`. Less the canonical, 92
  (PINNED); less S2's three exclusions, 89 (PINNED). That is unit 27's 88 (PINNED, its §4 "The
  population") plus `.githooks/pre-commit`. The arm re-derives it at every run.

```bash
git ls-files -- tools skills .githooks | while IFS= read -r f; do
  case $f in *.sh) ;; *) head -n 1 "$f" | grep -qE '^#!.*\b(ba)?sh\b' || continue ;; esac
  awk -v f="$f" '/^# >>> resolve_python/{b=1;i=1;next} /^# <<< resolve_python/{i=0;next}
    !i && (/\$\(resolve_python/ || /^resolve_python([ \t;|&]|$)/){c=1}
    END{if(b)print "block " f; else if(c)print "call " f}' "$f"
done
```

### The hook's shape

The hook is neither of unit 27's two shapes. It carries no `resolve_python` block, and its one source
of the canonical sits inside `resolve_hook_python`, which an ordinary commit never reaches. So it
carries the refusal block inline at its top, as it already carries the `remote_ladder_sh` block
(`.githooks/pre-commit@9b80d8a208e1:28`), and the parity rows' copy grep reads `.githooks/*`
(`tools/lib/resolve-python.test.sh@caa9482acf3a:483`), so unit 27's `refuse_wrong_shell` row grades
the copy with no new row. Git starts a hook at the work tree's top
(`.githooks/pre-commit@9b80d8a208e1:8`), so the block's relative `BASH_SOURCE[0]` joins `$PWD` into
the hook's own `/mnt/` path. Unit 27's coverage arm admits a refusal block only in an inline member
(`TOOL-dWitnessedBar-27` §4 "The coverage arm", its assertion 2), which would red the hook.
This unit widens that assertion to the population S1 derives, the one edit §8 F4 leaves.
