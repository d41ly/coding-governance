## 1. Goal

An override of a gov leg other than its ceiling withholds the whole manifest, a deleted gov leg is
re-appended with no line naming it, and an adopter's own leg is registered and checked by nothing
(gap-test-21). The emitter's drift refusal (`tools/govkit/govkit.py:4486-4490`) withholds every leg
the step built (`:4555-4578`), and its `else` branch re-appends a vanished gov row silently (`:4506`).
This unit makes the gate leg a row kind of the overlay mechanism dOrderedCharter lands: a
repository's legs are `[[gate-leg]]` rows of its overlay, composed with gov's packs and registered at
`point.flow.leg-pack` as the `adopter` pack; a gov leg's arguments, guard and ceiling change only by
a pinned patch and leave only through `instructions.exclude`; the kind's fixed set and widening
directions are declared; and every other leg lands (FA-1, FA-2, FA-5, the flow adoption's review).

## 4. Design

### The open fields

```toml
# tools/run-gates/leg-schema.toml (excerpt)
[kind]
name = "gate-leg"
owner-seat = 1

[[field]]
name = "argv"            # what the leg runs: any change is reported as a widening
shape = "scalar"
widens = "changes"

[[field]]
name = "guard"           # removing a path lets the leg skip more
shape = "set"
widens = "remove"

[[field]]
name = "doc_reads"       # removing a doc lets a docs-only run skip the leg
shape = "set"
widens = "remove"

[[field]]
name = "ceiling"         # a ceiling widens as it rises
shape = "scalar"
widens = "rises"

[[field]]
name = "name"            # undeclared class: fixed, the join key of every name-keyed file (I2)
shape = "scalar"

[[fixed-row]]
tag = "<the tag TOOL-dWitnessedBar-12 gives run-gates canary>"
fixed-by = ["principle=principle.p16"]
```

The rest of `LEG_KEYS` is declared as `name` is. A repository row is a `[[gate-leg]]` table of
the overlay, the kind's name as PLAY-dOrderedCharter-35 S1 spells its tables; a patch is such a row
whose `edges` holds `amends=<gov leg tag>@<hash8>` and only the fields it changes, as
PLAY-dOrderedCharter-35 S3 reads it; the classifier's widening list names every `argv` change and
every `ceiling` rise.

### The legacy list

```toml
# tools/run-gates/kit.toml
[[ledger]]
population = "hand-added-legs"
leg = "leg sources"
seed = ["python3", "{prefix}/run-gates/leg_factory.py", "--legacy-rows"]
key = "key"
fields = ["name"]
drain = "key"
direction = "shrink-only"
home = ".governance/legacy-legs.tsv"
```

An adopter's first composed update finds no list and no overlay leg rows: `test.seed` seeds the list
from its hand rows, which keep landing as written, and every gov row lands as gov's. A hand-edited gov
row is seeded onto the list too, so no adopter edit is overwritten by the first run; the owner drains
it into an `amends` patch.

Live at the next `govkit update` of each adopter. The run-gates kit's version moves, and the new
row keys reach a target only at or above `LEG_KEY_FLOORS`' floor (TOOL-dWitnessedBar-12 S5).

## 5. Production-readiness checklist

- security — the overlay is read at the landed revision only, through PLAY-dOrderedCharter-35's
  reader; a repository row may not claim gov's tag (`owned`), a fixed row refuses every patch, and
  every widening is named in the report; the emitter writes no overlay.
- perf / scale — one composition per update over the selected kits' rows and the overlay; `leg
  sources` reads the manifest, the receipt, the overlay and one ledger file.
- error / empty / loading states — no overlay reads `searched-empty`; no memory tree reads
  `seen-red unarmed` once; a malformed `[[gate-leg]]` row is refused by the composer, naming the row.
- observability — the slot line with the pack's counts, one line per held, refused, restored or
  legacy row, and the widening list.
- risks — `argv` widens on any change, so a patch that only reorders arguments is reported as a
  widening; reporting a narrowing as wider is the safe direction.
- testing — AC1 to AC12 by fixture and probe; the arms in §7.
- migration — per §4.
- user docs — `help/overlay-rows.md` (S13).
