## 1. Goal

Seed every registered population once, at a recorded SHA, and never again over an existing one, so
that a re-seed cannot launder an offence into the baseline; and record a seed that failed or found a
dead probe as unarmed, never as green. Today four adopters seed four ways, and two of them guard the
absent-only rule with their own shell test (`research-retrofit-a.md:31`).

## 4. Design

### The rule

For each registration selected, with `sha` the commit being seeded:

| State of the home | `widen` | Act | Prints |
|---|---|---|---|
| absent, or unarmed | none | run `seed`; on a live result write header and rows, each `<sha>` and `seeded` | `armed <population> <rows>` |
| absent, or unarmed | given | as above; the widen record is not needed for a first seed | `armed …` |
| present and armed | none | nothing | `present <population>` |
| present and armed | `<record>` | run `seed`; append only keys the file lacks, each `<sha>` and `widened:<record>`; never rewrite, remove or re-date a row | `widened <population> <keys>` |
| any, `seed = []` | any | nothing; reported per S3 | `unarmed <population> no seed` |

A seed argv prints one row per key on stdout, the key's fields then the count, TAB-separated; the
factory writes the header, the SHA and the disposition. The seed runs with a 600 s bound (PINNED;
the clause names a timeout and no figure, and one bar leg's ceiling is the nearest measure).

A result is live when the argv exits 0 within the bound and prints no line starting `dead probe:`.
Otherwise the population is unarmed with the reason `exit <n>`, `timed out` or `dead probe`. A live
result with zero rows is written armed and empty; whether an empty population may read armed is
the `populated` row's question (TOOL-dWitnessedBar-14).

The home test: the home's parent directory must already hold a tracked file, so the hygiene
check's structure check has admitted that directory. What it does not check: a file name the
structure check refuses inside an admitted directory. A home failing it is never written.

A rerun at the same SHA writes nothing new and leaves every armed file byte-identical; it seeds the
populations a failed run left absent or unarmed.

## 5. Production-readiness checklist

- security — writes only a registered home, or the `--home` path an adopter names, after the home
  test, through `write_rows`'s temp file and `os.replace`.
- perf / scale — one seed run per absent population; a present one costs a stat.
- error / empty / loading states — every failure is `unarmed` with its reason, never a partial file.
- observability — one line per population: `armed`, `present`, `widened` or `unarmed`.
- risks — a seed argv that prints a key in the wrong shape is refused by the reader, so the
  population reads unarmed with that line, which is the safe side.
- testing — AC1 to AC8 by a pass; the arms of §7 at the close.
- migration — as §4 says.
- user docs — none under `help/`; the codebase-map and drift-audit READMEs name `seed` at the pass.

## 6. Acceptance criteria

- **AC1** — When `python legacy_ledger.py seed --population p` runs in a fixture repo under
  `%TEMP%` whose `[[ledger]]` table `p` has no home yet and a seed printing two rows, it prints
  `armed p 2` and the home holds the header and two rows, each with HEAD's SHA and `seeded`.
  Red when: the factory writes rows without the SHA, or a partial file survives a killed run.
- **AC2** — When an offence is planted in the fixture so the seed measures a third key, committed,
  and `seed --population p` runs again, it prints `present p` and the home is byte-identical.
  Red when: the planted key enters the population, which is seed laundering.
- **AC3** — When the same rerun is given `--widen R1`, it prints `widened p` naming the third key,
  which is appended with the new SHA and `widened:R1`, and the first two rows are unchanged.
  Red when: an existing row is rewritten or re-dated.
- **AC4** — When the fixture's seed exits 1, and separately prints `dead probe: no files`, `seed`
  prints `unarmed p exit 1` and `unarmed p dead probe`, and the home holds the header and one
  `# unarmed` line and no row; with the seed repaired, a rerun prints `armed`.
  Red when: a failed seed leaves rows, reads armed, or blocks the resume.
- **AC5** — When the fixture's registration names a home in a directory holding no tracked file,
  `seed` writes nothing there and prints `unarmed` with the home-test reason.
  Red when: the home is created.
- **AC6** — When a fixture registration declares `seed = []`, `seed --all` prints
  `unarmed q no seed` and exits 0; with the fixture's policy reading `retrofit.unseeded = "refuse"`, it exits 2
  naming `q`.
  Red when: the unseeded check reads green, or `refuse` lets the registration through.
  fixture: until `policy.py` lands, the `refuse` half stages the value through the reader's
  documented test seam, which the build run takes from TOOL-dGroundRules-3.
- **AC7** — When `adopt-codebase-map.sh` runs twice over a fixture adopter, the second run leaves
  `affordance-exempt.toml` byte-identical with a planted dossier violation present; and
  `adopt-drift-audit.sh` run twice leaves a tuned `drift_signals.py` byte-identical.
  Red when: either adopter re-seeds a present population.
- **AC8** — When `grep -n 'item.test.seed' loop.toml` runs in the loop kit's directory after the
  pass, it names one row, and TOOL-dDeclaredLoop-12's program check reads it with no finding.
  Red when: the row is absent, so the owned node has no declaration.
  fixture: the loop definition is TOOL-dDeclaredLoop-1's file, landed by that build's run.
