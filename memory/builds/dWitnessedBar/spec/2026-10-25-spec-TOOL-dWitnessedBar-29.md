## 1. Goal

A size warning printed inside a leg that passes reaches nobody today: `report_one` prints only
`GATE ok <name>` (`tools/run-gates/run-gates.sh#report_one`) and the leg's output stays in
`$WORK/$i.out` (`tools/run-gates/run-gates.sh#runleg`), so two `TEMPLATE-SIZE WARN` lines fired unseen
when `research-caps.md` test A1 measured them (gap-test-22). This unit makes every size warning shown
on a passing run, in the runner's summary and its verdict record, attributed to the unit that grew the
file (the owner's NT-23, "Shown, priced, trended"; this build carries the "shown" and "attributed"
halves).

## 2. Scope (IN)

- **S1** — The warning marker, one machine line an emitter prints on the line after its human
  warning, on the same stream (§8 F4): `gate-warn<TAB>size<TAB><subject><TAB><detail>`, the class
  word `size`. The subject is the path the warning measured, repo-relative inside the repository,
  and otherwise the warning's own subject as its human line names it (§8 F5); it carries no TAB. The
  detail is free text. `tools/check-template-size.sh` prints it after its `TEMPLATE-SIZE WARN` line
  (`tools/check-template-size.sh@c76defce:520`), subject `$key`, detail
  `<recorded> -> <bytes> (+<delta>) over high-water`. Observed by AC1.
- **S2** — Every size-warning emitter the census of §4 names carries the marker, the thirteen files of
  §4's site table at HEAD `a4fd535ed` (PINNED, measured 2026-11-20). A `BUDGET WARN` site's detail is
  `<cap> · <measured> <unit> over <value>`, the tail of the grammar `tools/policy/README.md` states
  (`tools/policy/README.md@76690102:493`). Python sites build the line through S9's factory and the
  four shell sites print it with one `printf` each (§8 F6). A site that gathers its lines into a list
  prints the marker where that list is printed, so no list reader takes it for a line of its own.
  Observed by AC2.
- **S3** — `scan_leg_warnings` in `tools/run-gates/run-gates.sh`: after the pool drains, the serial
  retry, the reuse sample and the red legs' same-tree re-run, ONE `grep -F` over the copies of the
  legs that passed, `<i>.out` where `<i>.rc` reads `0` and `<i>.retry.out` where `<i>.retry.rc` reads
  `0`, keeping every line that opens with the marker, in manifest order, as rows
  `<leg index><TAB><class><TAB><subject><TAB><detail>`. A marker line from a failed, skipped, held or
  reused leg, from a sample's second look (`<i>.sample.out`) or from a red leg's re-run
  (`<i>.rerun.out`) is not read. Observed by AC3 and AC4.
- **S4** — Attribution: for each distinct subject, `routed_commits.py --newest-unit HEAD <subject>`,
  the unit id of the newest non-merge commit touching that path whose id a spec defines, or `-` with
  the reason when the memory-tree kit is absent, the attribution fails, or no commit names a specced
  unit. One spawn per distinct subject, none on a run with no warning. Observed by AC5 and AC6.
- **S5** — `routed_commits.py --newest-unit <range> [<path>]`: the optional third argument limits the
  log walk of `read_newest_unit` to that path (`git log ... <range> -- <path>`); with two arguments
  the verb is unchanged (`tools/memory-tree/routed_commits.py#main`). Observed by AC5.
- **S6** — The summary: one line per warning, `GATE warn  <leg name>  (<subject>: <detail>; grown by
  <unit>)`, the verb padded to the leg-name column as `GATE skip  ` is, printed after the last leg
  line and before the closing `gates GREEN` or `gates RED` line, on stdout and in the summary file
  `$sfile`, and the closing line's note gains `(<n> warned)`. Observed by AC3.
- **S7** — The verdict record (shared interface I8): `warned<TAB><n>` and one
  `warn.<k><TAB><leg name><TAB><class><TAB><subject><TAB><unit>` per warning, `<k>` from 1, written
  in the block that writes `verdict` to the run record
  (`tools/run-gates/run-gates.sh@a405580b:5943-5979`), after unit 25's `run_id`, `cause` and
  `tail.<n>` keys. The keys are additive and `schema` does not bump, the reasoning the header block
  states (`tools/run-gates/run-gates.sh@a405580b:3807-3808`). Observed by AC4.
- **S8** — `tools/run-gates/README.md` states the marker grammar, the `GATE warn` line and the two
  keys; `tools/check-template-size.sh`'s header names the marker it prints; and `help/size-caps.md`
  shows the marker beside its `BUDGET WARN` example and says a passing bar shows it as `GATE warn`.
  Observed by AC7.
- **S9** — `render_warn_marker(subject, detail)` in `tools/policy/budgets.py`, beside `check_cap`:
  the marker line of S1, each TAB, CR or LF in either field written as a space. The `check` verb
  (`tools/policy/budgets.py#main`) prints it after a warned verdict's line, so the size gate's
  warned-budget branch, which prints that output whole (`tools/check-template-size.sh@c76defce:436`),
  carries it with no line of its own. `tools/policy/README.md`'s `budgets.py` row names it. Observed
  by AC9.
- **S10** — `tools/run-gates/profile_bar.py` carries `warn` in `PINNED_VERBS` and `VERDICT` as an
  annotation, a line naming no new leg and moving no verdict, since `derive_runner_verbs` refuses a
  verb the runner prints that its pin lacks (`tools/run-gates/profile_bar.py#derive_runner_verbs`).
  Observed by AC8.

## 3. Non-goals (OUT)

- Pricing a breach by its bytes and its reads (dCalibratedLens) and raising an owner item for a
  breach that persists or grows (the Loop Review): NT-23's other two halves, named by its fold.
- Changing any cap, its mode or its value: `budgets.enforce` and `budgets.*` are TOOL-dGroundRules-9's.
- Turning a warning into a red. A marked warning never moves the verdict or the exit code.
- Warnings of a class other than `size`. The runner reads any class word the marker carries, but
  this unit adds the marker to size warnings only.
- Capturing a leg's two streams apart: `runleg` already writes stderr into the `.out` copy (§8 F4).
- The policy kit's switch fixtures in `tools/policy/check_policy.py`: their `warn` strings are the
  output they expect of each enforcer, not an emitter, and they stay as they are.

### Edges

- **consumes-from** `TOOL-dWitnessedBar-25` — `run_id`, the verdict-record key unit 25 adds in the block this unit's `warned` and `warn.<k>` keys join, so a breach trended across runs is joined to the run that showed it
- **hands-off** `TOOL-dWitnessedBar-51` — the round-1 minor id 14: the `warn.<k>` value's fields read by their grammar positions, a scope item of that unit

## 4. Design

### The marker

```
TEMPLATE-SIZE WARN — BUILD-METHOD.md grew past its recorded high-water: 28351 -> 29326 (+975). ...
gate-warn	size	memory/guides/BUILD-METHOD.md	28351 -> 29326 (+975) over high-water
BUDGET WARN — line-length · tools/x.sh · 512 chars over 450 · 2 line(s) · budgets.enforce is warn
gate-warn	size	tools/x.sh	line-length · 512 chars over 450
```

The human line stays as it is: the high-water suite reads it (arms A6 and A7 of
`tools/check-template-size.test.sh`), and the policy fixtures read every `BUDGET WARN` line. The
marker is a line of its own because a reader then needs one fixed prefix and no list of human
spellings (§8 F1). It follows its human line on the same stream, because the runner's capture merges
the two streams and only one stream keeps two writes in order (§8 F4).

### The emitter census

```bash
git grep -nE '(TEMPLATE-SIZE|BUDGET) WARN —|BUDGET \{word\}|past its recorded high-water' -- tools .githooks skills ':!*.test.sh' ':!*selftest*' ':!*.md' ':!tools/policy/check_policy.py'
git grep -nE 'check_cap|verdict\.line|budgets\.py" check' -- tools .githooks skills ':!*.test.sh' ':!*selftest*' ':!*.md' ':!tools/policy/check_policy.py'
```

The first query finds every line that writes a size warning, the two that compose the word `WARN`
from a variable included. The second finds the printers of `check_cap`'s verdict line, which the
first cannot see. At HEAD `a4fd535ed` the first prints thirteen lines in twelve files, and the second
adds one file, `tools/check-spec-tokens.py` (PINNED, measured 2026-11-20). The pathspec exclusion of
`tools/policy/check_policy.py` drops eleven expected-output strings of the switch fixtures (PINNED,
measured 2026-11-20); a comment or docstring naming `BUDGET WARN` carries no dash after it and is not
matched. A site the pass finds at its own base that this table lacks is marked too and named in the
pass's return.

### The runner

`scan_leg_warnings` runs once, after the same-tree re-run (`GATE_RERUN`, TOOL-dWitnessedBar-8) and
before the verdict write. A leg that passed on its retry is read from `$WORK/<i>.retry.out`, the
attempt that passed (`tools/run-gates/run-gates.sh#run_leg_retry`). It spawns one `grep` and, per
distinct subject, one `routed_commits.py`. It is self-contained, so a slice of it runs alone, as the
suite slices `run_leg_reap` out of the runner (arm 9e of `tools/run-gates/run-gates.test.sh`). The
memory-tree kit is a sibling kit, reached through `resolve_kit_dir` as the held census reaches govkit
(`tools/run-gates/run-gates.sh#resolve_kit_dir`), never by literal. A row's subject is its third
field and its detail every field after it.

```
GATE warn  build-method size  (memory/guides/BUILD-METHOD.md: 28351 -> 29326 (+975) over high-water; grown by TOOL-dX-4)
gates GREEN — 141/141 legs passed (1 warned)
```

```
warned	1
warn.1	build-method size	size	memory/guides/BUILD-METHOD.md	TOOL-dX-4
```

`read_record_keys` (`tools/run-gates/run-gates.sh#read_record_keys`) reads the line into a key and a
value, so a `warn.<k>` value keeps its inner TABs; a reader splits the value on TAB itself.

### Inventory

Minted: the marker prefix `gate-warn`, its class word `size`; `scan_leg_warnings`; the summary verb
`warn` on a `GATE` line; the verdict keys `warned` and `warn.<k>`; the optional path argument of
`--newest-unit`; `render_warn_marker`. Naming cells:
`python tools/lexicon/lexicon.py --suggest scan_leg_warnings --as sh.function` and
`python tools/lexicon/lexicon.py --suggest render_warn_marker --as py.function` each print OK at HEAD
`a4fd535ed`, measured 2026-11-20. The rev-3 name `collect_leg_warnings` is refused there, since
`collect` is not a declared verb.

### Migration

Additive. A run with no marked warning prints what it prints today and writes `warned 0`.

### Rollout

Live at landing. Every kit whose shipped bytes move carries a version above its landing base's,
which the `kit epoch` leg grades from that base: the set is DERIVED by that leg at the pass, and the
pass moves each version it names at the kit's own version home.

### Alternatives rejected

- **A regex over the human lines in the runner.** It types the emitters' spellings into the runner,
  a list that grows with every emitter and goes stale silently (§8 F1).
- **A distinct exit code for a passing leg with a warning.** It changes every leg's rc contract,
  and `report_one` reads any non-zero rc as a failure.
- **A marker inside `check_cap`'s verdict line.** Eleven of the thirteen files of the site table
  print a line `check_cap` never builds (PINNED, measured 2026-11-20), so the marker would still be
  typed at each of them.

## 5. Production-readiness checklist

- security — the marker's subject is printed and recorded, never executed; `routed_commits.py`
  receives it as one argv word after the range and the `--` separator, never through a shell string.
- perf / scale — one `grep` per run and one python spawn per distinct warned subject; a run with no
  warning spawns the `grep` alone. An emitter adds one line per warning and no spawn.
- error / empty / loading states — an absent memory-tree kit or a failed attribution writes `-` and
  names why on the `GATE warn` line; no `.out` file for a passing leg writes no row; a subject that is
  not a path finds no commit and writes `-`.
- observability — the `GATE warn` lines, the closing line's `(<n> warned)` note and the two keys.
- risks — the newest commit touching a file may have shrunk it, so `grown by` names the newest unit
  that changed it, not a proven grower (said in the README).
- testing — AC1 to AC9 by fixture and probe; the `New arm:` lines in §7.
- migration — none, per §4.
- user docs — `help/size-caps.md` shows what a breach prints, so S8 adds the marker there; no page
  under `help/` describes the runner's leg lines, and `tools/run-gates/README.md` is updated by S8.

## 6. Acceptance criteria

- **AC1** — When `bash tools/check-template-size.sh <fixture> "" <highwater>` runs on a fixture file
  no census row names, under its hard default, whose row in the planted high-water file is below its
  size, its output carries the `TEMPLATE-SIZE WARN` line and, on the next line, a line opening
  `gate-warn` whose third TAB field is the key the gate read that row by; at the high-water it carries
  neither.
  Red when: the marker line is missing, so the runner has nothing to read.
- **AC2** — When the two census queries of §4 run at the build's tip, every file either names also
  matches `git grep -c 'gate-warn'`.
  Red when: an emitter prints a size warning with no marker, so its breach stays unseen.
  figure: the hit set is DERIVED at observation.
- **AC3** — When the slice of `scan_leg_warnings` is run over a planted work directory holding
  `0.rc` = `0` and a `0.out` with one marker line, under a planted name list, it prints one `GATE warn`
  line naming the leg, the subject and the detail; with `0.rc` = `1` it prints none, and a marker line
  in a `0.rerun.out` beside a red `0.rc` prints none.
  Red when: a failed leg's marker is shown, or a passing leg's marker is dropped.
  fixture: the planted directory is built by the probe under the run's scratch path.
- **AC4** — When the planted breach of AC3 is run through the verdict-write block's slice, the
