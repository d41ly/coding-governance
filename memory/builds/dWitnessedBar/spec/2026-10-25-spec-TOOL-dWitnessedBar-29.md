## 1. Goal

A size warning printed inside a leg that passes reaches nobody today: `report_one` prints only
`GATE ok <name>` (`tools/run-gates/run-gates.sh:4059`) and the leg's output stays in `$WORK/$i.out`
(`:3932`), so two `TEMPLATE-SIZE WARN` lines fired unseen when `research-caps.md` test A1 measured
them (gap-test-22). This unit makes every size warning shown on a passing run, in the runner's
summary and its verdict record, attributed to the unit that grew the file (the owner's NT-23,
"Shown, priced, trended"; this build carries the "shown" and "attributed" halves).

## 2. Scope (IN)

- **S1** — The warning marker, one machine line a leg prints beside its human warning:
  `gate-warn<TAB>size<TAB><subject path><TAB><detail>`, the class word `size`, the subject a
  repo-relative path, the detail free text with no TAB. `tools/check-template-size.sh` prints it on
  the line after its `TEMPLATE-SIZE WARN` line (`:221`), detail `<recorded> -> <bytes> (+<delta>)
  over high-water`. Observed by AC1.
- **S2** — Every size-warning emitter carries the marker: the pass runs the query of §4 "The
  emitter census" over its base and adds the marker beside each hit, `BUDGET WARN` lines of
  TOOL-dGroundRules-9 S5 included once that unit has landed. Observed by AC2.
- **S3** — `collect_leg_warnings` in `tools/run-gates/run-gates.sh`: after the pool drains, ONE
  `grep -F` over the `.out` files of the legs whose rc is `0`, keeping every line that opens with the
  marker, in manifest order, as rows `<leg index><TAB><class><TAB><subject><TAB><detail>`. A marker
  line from a failed, skipped, held or reused leg is not read. Observed by AC3 and AC4.
- **S4** — Attribution: for each distinct subject, `routed_commits.py --newest-unit HEAD <subject>`,
  the unit id of the newest non-merge commit touching that path whose id a spec defines, or `-` with
  the reason when the memory-tree kit is absent or no commit names a specced unit. One spawn per
  distinct subject, none on a run with no warning. Observed by AC5 and AC6.
- **S5** — `routed_commits.py --newest-unit <range> [<path>]`: the optional third argument limits the
  log walk to that path (`git log ... <range> -- <path>`); with two arguments the verb is unchanged.
  Observed by AC5.
- **S6** — The summary: one line per warning, `GATE warn   <leg name>  (<subject>: <detail>; grown by
  <unit>)`, printed after the last leg line and before the closing `gates GREEN` or `gates RED` line,
  on stdout and in the summary file `$sfile`, and the closing line's note gains `(<n> warned)`.
  Observed by AC3.
- **S7** — The verdict record (shared interface I8): `warned<TAB><n>` and one
  `warn.<k><TAB><leg name><TAB><class><TAB><subject><TAB><unit>` per warning, `<k>` from 1, written
  in the block that writes `verdict` (`run-gates.sh:5554-5569`), after unit 25's `run_id`. The keys
  are additive and `schema` does not bump, the reasoning at `:3512-3513`. Observed by AC4.
- **S8** — `tools/run-gates/README.md` states the marker grammar, the `GATE warn` line and the two
  keys, and `tools/check-template-size.sh`'s header names the marker it prints. Observed by AC7.

## 3. Non-goals (OUT)

- Pricing a breach by its bytes and its reads (dCalibratedLens) and raising an owner item for a
  breach that persists or grows (the Loop Review): NT-23's other two halves, named by its fold.
- Changing any cap, its mode or its value: `budgets.enforce` and `budgets.*` are TOOL-dGroundRules-9's.
- Turning a warning into a red. A marked warning never moves the verdict or the exit code.
- Warnings of a class other than `size`. The runner reads any class word the marker carries, but
  this unit adds the marker to size warnings only.
- A warning printed on stderr only: the runner's `.out` copy is what it reads (§8 F4).

### Edges

- **consumes-from** `TOOL-dWitnessedBar-25` — `run_id`, the verdict-record key unit 25 adds in the block this unit's `warned` and `warn.<k>` keys join, so a breach trended across runs is joined to the run that showed it
- **hands-off** `TOOL-dWitnessedBar-51` — the round-1 minor id 14: the `warn.<k>` value's fields read by their grammar positions, a scope item of that unit

## 4. Design

### The marker

```
TEMPLATE-SIZE WARN — BUILD-METHOD.md grew past its recorded high-water: 28351 -> 29326 (+975). ...
gate-warn	size	memory/guides/BUILD-METHOD.md	28351 -> 29326 (+975) over high-water
```

The human line stays as it is: the high-water suite reads it (`check-template-size.test.sh:205`).
The marker is a line of its own because a reader then needs one fixed prefix and no list of human
spellings (§8 F1). Its subject is the path the leg measured, which is the argument
`check-template-size.sh` was given, made repo-relative.

### The emitter census

```bash
git grep -nE '(TEMPLATE-SIZE|BUDGET) WARN' -- tools .githooks skills ':!*.test.sh' ':!*selftest*'
```

At base `cdfbd1cf` it prints one site, `tools/check-template-size.sh:221` (PINNED, measured
2026-10-25). TOOL-dGroundRules-9 S5 adds `BUDGET WARN — <cap> · <subject> · <measured> <unit> over
<value>` at each re-pointed enforcer; that chain build lands before this one, so the build pass
re-runs the census and marks every hit. A hit the pass cannot mark (a subject that is not a path) is
a deviation record, never a silent skip.

### The runner

`collect_leg_warnings` runs once, after the retry pass and before the verdict write, so a leg that
passed on its retry is read from `$WORK/<i>.retry.out`, the attempt that passed. It spawns one `grep`
and, per distinct subject, one `routed_commits.py`; it is self-contained, so a slice of it runs
alone, as `write_bar_green`'s header states for the hook (`.githooks/pre-push:2285`). The memory-tree
kit is a sibling kit, reached through `resolve_kit_dir` as the held census reaches govkit
(`run-gates.sh:2966`), never by literal.

```
GATE warn   build-method size  (memory/guides/BUILD-METHOD.md: 28351 -> 29326 (+975) over high-water; grown by TOOL-dX-4)
gates GREEN — 141/141 legs passed (2 warned)
```

```
warned	1
warn.1	build-method size	size	memory/guides/BUILD-METHOD.md	TOOL-dX-4
```

`read_record_keys` (`run-gates.sh:2387`) splits on the first TAB, so a `warn.<k>` value keeps its
inner TABs; a reader splits the value on TAB itself.

### Inventory

Minted: the marker prefix `gate-warn`, its class word `size`; `collect_leg_warnings`; the summary
verb `warn` on a `GATE` line; the verdict keys `warned` and `warn.<k>`; the optional path argument of
`--newest-unit`. Naming cells: `collect_leg_warnings` is asked of
`python tools/lexicon/lexicon.py --suggest collect_leg_warnings --as sh.function` at the pass.

### Migration

Additive. A run with no marked warning prints what it prints today and writes `warned 0`.

### Rollout

Live at landing. The run-gates kit's version moves (`KIT_RUN_GATES_VERSION`, `run-gates.sh:36`) and
so does the memory-tree kit's (`KIT_MEMORY_TREE_VERSION`, `check-memory-hygiene.sh:68`), the two
kits whose shipped bytes move.

### Files touched (estimate)

- `tools/run-gates/run-gates.sh`
- `tools/run-gates/README.md`
- `tools/run-gates/run-gates.test.sh`
- `tools/check-template-size.sh`
- `tools/check-template-size.test.sh`
- `tools/memory-tree/routed_commits.py`
- `tools/memory-tree/check-memory-hygiene.sh` (the version line only)

### Alternatives rejected

- **A regex over the human lines in the runner.** It types the emitters' spellings into the runner,
  a list that grows with every emitter and goes stale silently (§8 F1).
- **A distinct exit code for a passing leg with a warning.** It changes every leg's rc contract,
  and `report_one` reads any non-zero rc as a failure.

## 5. Production-readiness checklist

- security — the marker's subject is printed and recorded, never executed; `routed_commits.py`
  receives it as one argv word after the range, never through a shell string.
- perf / scale — one `grep` per run and one python spawn per distinct warned subject; a run with no
  warning spawns the `grep` alone.
- error / empty / loading states — an absent memory-tree kit or a failed attribution writes `-` and
  names why on the `GATE warn` line; no `.out` file for a passing leg writes no row.
- observability — the `GATE warn` lines, the closing line's `(<n> warned)` note and the two keys.
- risks — the newest commit touching a file may have shrunk it, so `grown by` names the newest unit
  that changed it, not a proven grower (said in the README).
- testing — AC1 to AC7 by fixture and probe; the `New arm:` lines in §7.
- migration — none, per §4.
- user docs — none owed: no page under `help/` describes the runner's output lines;
  `tools/run-gates/README.md` is updated by S8.

## 6. Acceptance criteria

- **AC1** — When `bash tools/check-template-size.sh <fixture> 100 <highwater>` runs on a fixture
  file under 100 bytes whose row in the planted high-water file is below its size, its output
  carries the `TEMPLATE-SIZE WARN` line and, on the next line, a line opening `gate-warn` whose third
  field is the fixture's repo-relative path; at the high-water it carries neither.
  Red when: the marker line is missing, so the runner has nothing to read.
- **AC2** — When the census `git grep -nE '(TEMPLATE-SIZE|BUDGET) WARN'` of §4 runs at the build's
  tip, every hit's file also matches `git grep -c 'gate-warn'`.
  Red when: an emitter prints a size warning with no marker, so its breach stays unseen.
  figure: the hit set is DERIVED at observation.
- **AC3** — When the slice of `collect_leg_warnings` is run over a planted work directory holding
  `0.rc` = `0` and a `0.out` with one marker line, under a planted name list, it prints one `GATE warn`
  line naming the leg, the subject and the detail; with `0.rc` = `1` it prints none.
  Red when: a failed leg's marker is shown, or a passing leg's marker is dropped.
  fixture: the planted directory is built by the probe under the run's scratch path.
- **AC4** — When the planted breach of AC3 is run through the verdict-write block's slice, the
  written `verdict` file holds `warned` `1` and a `warn.1` line whose value's fourth TAB field is the
  subject, and the `verdict` line still reads `GREEN`.
  Red when: the warning moves the verdict, or no `warn.<k>` line is written.
- **AC5** — When `python routed_commits.py --newest-unit HEAD memory/guides/BUILD-METHOD.md` runs in
  `tools/memory-tree/`, it prints the first specced id among the subjects that
  `git log --no-merges HEAD -- memory/guides/BUILD-METHOD.md` lists, and with two arguments it
  prints what it printed at base.
  Red when: the path argument is ignored, so the newest unit of the whole history is named.
- **AC6** — When `collect_leg_warnings` runs with its kit lookup pointed at a directory holding no
  memory-tree kit, the `GATE warn` line ends `grown by -` and names the missing kit.
  Red when: the attribution step aborts the summary, or prints an empty unit.
- **AC7** — When `grep -n 'gate-warn' tools/run-gates/README.md tools/check-template-size.sh` runs,
  each file names the marker, and the README names `warned` and `warn.<k>`.
  Red when: the grammar is stated nowhere a reader of the runner looks.

## 8. Open questions

- **F1 — What carries a warning to the runner?** Options: (a) a machine line of its own,
  `gate-warn<TAB><class><TAB><subject><TAB><detail>`, beside the human line; (b) the human lines'
  prefixes (`TEMPLATE-SIZE WARN —`, `BUDGET WARN —`) typed into the runner as a pattern list; (c) a
  distinct exit code for a pass with a warning. (b) is a hand-typed list of spellings the class gate
  rule refuses, and it reds nothing when a new emitter is added unlisted; (c) breaks the rc contract
  `report_one` reads. RESOLVED (agent, 2026-10-25, delegated): (a), rung 3, the most capable option
  surviving the vetoes and the brief's "a machine marker on check-template-size.sh's WARN line".
  widens: none · relaxes: none
- **F2 — Which unit is "the unit that grew the file"?** Options: (a) the newest specced unit among the
  commits touching the subject in HEAD's history, through `--newest-unit`; (b) the units of the commits
  since the subject's high-water row was recorded; (c) the unit the current run is building. (b) exists
  only for the high-water ratchet, not for a `BUDGET WARN` breach; (c) misnames a breach inherited from
  the default branch. RESOLVED (agent, 2026-10-25, delegated): (a), rung 3, the reader the brief names,
  `routed_commits.py --newest-unit`, extended by a path argument rather than copied. widens: none ·
  relaxes: none
- **FACT-QUESTION · F3 — How many size-warning emitters exist at base?** Probe: the census of §4.
  Observation, 2026-10-25: one, `tools/check-template-size.sh:221`. Liveness: the same query prints
  `check-template-size.test.sh:205` when the test-file exclusion is dropped, so it can find a hit.
  RESOLVED (agent, 2026-10-25, delegated): S2 marks every hit the census finds at the build's base,
  which includes TOOL-dGroundRules-9's `BUDGET WARN` sites once that unit lands. widens: none ·
  relaxes: none
- **F4 — Does a warning on stderr count?** The runner's `.out` copy holds whatever the leg's argv
  wrote to the stream the runner captures. Options: (a) read the `.out` copy only, and every marker is
  printed on stdout; (b) capture stderr separately for markers. (b) changes `runleg`'s capture for one
  line class. RESOLVED (agent, 2026-10-25, delegated): (a), rung 3, the fewest moving parts; S1 prints
  the marker on stdout. widens: none · relaxes: none
