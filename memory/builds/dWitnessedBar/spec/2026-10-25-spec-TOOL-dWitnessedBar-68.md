## 1. Goal

The round-1 spec audit of units 66 and 67
(`memory/builds/dWitnessedBar/reviews/2026-10-25-review-TOOL-dWitnessedBar-66-spec-audit-round1.md`)
confirmed finding **id 1 at HIGH**, report item **H1**. No other id shares that item.

`TOOL-dWitnessedBar-65` AC12 expects `read --backend local-hook` to read the AC12 record as `GREEN`
with the second `sha`. The CLI reads `<common-dir>/gate-verdict/<tree hash>`, never a scratch file,
and prints the QUERIED SHA, never the record's `sha` key (`tools/run-gates/verdict_backends.py#run_read`,
`#read_local_verdict`). On a record with no reuse pair or no `selection` key it reads `NONE`
(`#check_local_record`). Unit 66 rev-3 landed its AC3 on `read_tag_lines`, the parse, instead
(`a04b24c97`). So the AC12 arm writes its record to a scratch file at no path the reader reads, and
`read_local_verdict` never runs over it. Unit 65's acceptance ledger still records AC12's local-hook
half on the `sha` that `read_tag_lines` returns.

This unit builds the record from the plant the local-hook reader admits, puts it where that reader
looks, and grades the local-hook half on the state the CLI prints. The reader's CR strip and
last-wins rule are graded through keys that change that state. It repairs `TOOL-dWitnessedBar-66` and
builds one step after it (order 39).

## 2. Scope (IN)

- **S1** — The record. The AC12 arm in `tools/run-gates/run-gates.gov.test.sh`
  (`@248c8263a:817-841`) builds its record through one `"$PYBIN" -c` call, with `$KITDIR` first on
  `sys.path`. The call first clears the git variables `verdict_backends.py#run_fixture` clears. It then
  calls `verdict_backends.run_local_plant("clean", <top>, <runner>)`. `<top>` is the arm's own
  `mktemp -d` directory, and `<runner>` accepts the plant's scenarios and runs none of them (§8 F3).
  The record is the `clean` plant's last write, at the fixture's `<common-dir>/gate-verdict/<tree hash>`,
  where `<tree hash>` is the fixture HEAD's tree. Its lines carry `reused 0`, `reused_cache 0`, and
  `selection` with its `selection.1` row, which is the one row R derives
  (`verdict_backends.py#run_local_plant`). The call reads that file's bytes and writes back, in binary
  mode, each plant line whose key is not `verdict`, `sha` or `reused_cache`, its bytes unchanged,
  followed by these lines in this order:

  | line | bytes |
  |---|---|
  | 1 | `verdict<TAB>GREEN<CR><LF>` |
  | 2 | `sha<TAB>` followed by forty `a` characters, then `<LF>` |
  | 3 | `sha<TAB>` followed by forty `b` characters, then `<CR><LF>` |
  | 4 | `reused_cache<TAB>1<LF>` |
  | 5 | `reused_cache<TAB>0<CR><LF>` |

  The call's last stdout line names the record's path and the fixture's HEAD sha. Every line before it
  is the plant's own output, which `run_fixture_command` echoes. The arm's closing `rm -rf` takes `<top>`.
  A call that exits non-zero fails the arm and prints the call's output. Observed by AC1.
- **S2** — Both of the arm's existing halves read the same file. Unit 66 S2's cut-and-source call to
  `read_green_file` and unit 66 S3's `read_tag_lines` compare are both given S1's record path in place
  of `$rgf_t/record`. Their assertions are unchanged: `rec_sha` equals forty `b`, and the compare reads
  `'GREEN'` and forty `b`. Observed by AC2.
- **S3** — The local-hook half is graded on the state the CLI prints. The same `"$PYBIN" -c` call runs
  `verdict_backends.py read --backend local-hook --sha <fixture HEAD>` through
  `verdict_backends.py#run_fixture_command` from the fixture's work tree, as the `clean` plant runs its
  own read. The arm gives this read its own `a=$((a+1))` and asserts that the CLI line reads
  `verdict: local-hook · GREEN · <sha8>`. Its failure line prints the line the CLI printed. It asserts
  nothing about the record's `sha` key, which the CLI line does not print. Two of S1's lines make that
  state depend on the reader's normalisations:
  - line 1 reads `GREEN` only once its CR is gone. At HEAD the default-newline `read_text` in
    `read_local_verdict` turns its CR-LF into LF. Once `TOOL-dWitnessedBar-69` S2 lands, only `read_tag_lines`'s
    one-CR strip does, and staging that strip's deletion red is unit 69's close (its §7);
  - lines 4 and 5 read as an admitted `reused_cache 0` only when the last line wins. A kept `1` is a
    non-zero `reused_cache`, which `check_local_record` reads as `NONE`.

  The arm's comment names the `clean` plant's record in place of the `key-no-tab` lines. Its WHAT THIS
  DOES NOT CHECK clause adds that the CLI half reads no `sha` key. Observed by AC3.
- **S4** — The criterion that expected the record's `sha` from the CLI is answered by name.
  The line for AC12 in `memory/builds/dWitnessedBar/build/2026-11-19-build-TOOL-dWitnessedBar-65-1-acceptance-ledger.md`
  gains a sentence naming this unit's AC3 as the observation of AC12's local-hook half, replacing
  "the second `sha`". Unit 66's AC3, as landed at rev-3, grades `read_tag_lines`, which does return
  `sha`, so its ledger line stands. Observed by AC4.

## 4. Design

### Evidence

- `run_local_plant` builds one fixture at `<top>/work` under the `top` it is given, pushed to a bare
  remote, so R is its `main`. For `clean` it writes the record twice, first with `selection none`,
  then with the hashed row R derives, and hands each read to the runner it is given
  (`verdict_backends.py#run_local_plant`). Only `run_fixture` makes and removes a `mkdtemp` scratch
  (`#run_fixture`), so `--fixture --plant clean` leaves no record behind for the arm to rewrite.
- `read_local_verdict` and `check_local_record` read `tree`, `verdict`, `run_id`, `reused`,
  `reused_cache`, `selection` and `selection.<n>`, and no `sha`:
  `awk '/^def read_local_verdict/,/^def read_landed_revision/' tools/run-gates/verdict_backends.py | grep -c "\"sha\"\|'sha'"`
  prints 0 (PINNED 2026-11-21).
- At HEAD the arm writes `printf 'verdict\tGREEN\r\nsha\t%s\nsha\t%s\r\n'` to `$rgf_t/record`, and
  its two compares count one assertion each (`run-gates.gov.test.sh@248c8263a:829-840`).
- A probe at `248c8263a` ran S1's call over `tools/run-gates` (PINNED 2026-11-21). It printed
  `verdict: local-hook · GREEN · <sha8> · witness witnessed`. The plant's own lines ended in CR-LF on
  this Windows node, its `write_text` passing `newline=None`. `od -c` showed `\r \n` after `GREEN`,
  after the forty `b` and after `reused_cache<TAB>0`. The record's name equalled the fixture's
  `HEAD^{tree}`, and the cut `read_green_file` set `rec_sha` to forty `b`. Over a scratch `tools/`
  holding copies of `run-gates/` and `policy/`, with `out[k] = v` changed to `out.setdefault(k, v)` in
  `read_tag_lines` (`diff` counted 1 line opening `>`, PINNED 2026-11-21), the call printed `· NONE ·`, naming
  `reused 1 leg(s) from the cache`.
