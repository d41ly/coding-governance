## 1. Goal

Refusing hook bypass is a policy, `hooks.bypass`, allowed by default until gate reliability is fixed,
and "each bypass is recorded" (v2:1727-1728, R5.1). Today nothing records one: the lander prints
`landed UNGATED` when a push lands with no allow record from the hook
(`tools/push-main.sh#check_push_allow`) and writes nothing, and a commit made past the hooks never
reaches the commit check (`tools/unattended/unattended.sh#check_commit_message`). This unit records
both kinds of bypass in one grammar under `hooks.bypass = allowed`, and under `refused` holds them
through the off-node verdict, because a hook on the bypassing node cannot refuse its own bypass.

## 4. Design

### The record

```
v=1	t=1761400000.123456	p=pushes	ev=once	decision=bypass	bypass=ungated-landing	sha=<40 hex>	policy=allowed	tree_verdict=GREEN
v=1	t=1761400100.000001	p=pushes	ev=once	decision=bypass	bypass=unwitnessed-commit	sha=<40 hex>	policy=allowed
```

The journal is evidence, never an input (`.githooks/pre-push@8454b004:222`): nothing branches on a
bypass line, so a record that fails to append prints the hook's one `pre-push: run log` line and
changes no exit. The refusals of S5 to S7 read the commit history and the policy, never the journal.

### Where each kind is seen

| Kind | Seen by | Under `allowed` | Under `refused` |
|---|---|---|---|
| `ungated-landing` | the lander, after git reports the push | recorded, exit 4 | recorded, exit 4; prevented upstream by S6 |
| `unwitnessed-commit` | the pre-push hook, over the pushed range | recorded, push proceeds | recorded, push refused |
| either, with every local hook skipped | the off-node backend's bar, through S7's arm | printed as a note | leg red, no off-node GREEN |

### The two verbs

`verdict_backends.py off-node [--backend <name>]` reads `verdict` as `read` does where no
`--backend` is given (`tools/run-gates/verdict_backends.py#read_backend_name`), finds its row by
`check_backend`, and prints one line, `verdict-backends: off-node · <name> · <true|false> · off-node
backends: <names>`, the names every declared row with `off_node = true`. It exits 0 when the row is
off-node, 1 when it is not, and 2 on a refusal, as `read` does
(`tools/run-gates/verdict_backends.py#run_read`). The lander passes the `verdict` value it already
read; the hook passes none.

`commit_trailers.py unchecked <git-log revision arguments>` reads `Pass` and `Commit-Checked` in one
`read_commits` call and prints `<sha> <ids>` for each commit with one parent whose `Pass:` values
hold an id, `none` among them holding none, and whose `Commit-Checked:` values are empty. A range
git cannot read prints nothing and exits 0, as `tokens` does. The verb lives in the
`commit_trailers_py` block, so its three copies stay byte-identical under
`tools/lib/resolve-python.test.sh`'s parity table. The hook resolves the memory-tree kit's copy, the
kit it already resolves for `transition_audit.py`; the leg runs its sibling copy, as
`read_attribution_tokens` does (`tools/unattended/lib-unattended.sh#read_attribution_tokens`).

### The hook's refusal

Both hook refusals, S5's and S6's, write the token `bypass-refused` through `write_refusal`, which
pairs it with the run-log decision `refuse-bypass` (`.githooks/pre-push#write_refusal`). Each site is
`write_refusal bypass-refused "$why"; RUNLOG_CLEAN=1; exit 1`, so the run-log suite's exit table
gains one row for that code, at a count of 2.

- **A per-commit witness file under the common dir.** It is node-local, so a run resumed on another
  node reads every earlier commit as unwitnessed; the trailer travels with the commit.
