## 1. Goal

Refusing hook bypass is a policy, `hooks.bypass`, allowed by default until gate reliability is fixed,
and "each bypass is recorded" (v2:1727-1728, R5.1). Today nothing records one: the lander prints
`landed UNGATED` when a push lands with no allow record from the hook (`tools/push-main.sh:342-352`)
and writes nothing, and a commit made past the hooks never reaches the commit check
(`tools/unattended/unattended.sh:13473`). This unit records both kinds of bypass in one grammar under
`hooks.bypass = allowed`, and under `refused` holds them through the off-node verdict, because a hook
on the bypassing node cannot refuse its own bypass.

## 2. Scope (IN)

- **S1** — The key `hooks.bypass`, values `allowed` and `refused`, read through dGroundRules' reader,
  `python tools/policy/policy.py get hooks.bypass` (TOOL-dGroundRules-2 S7), default `allowed`
  (v2:1155) until that reader lands. Observed by AC1.
- **S2** — The bypass record: one `ev=once` line in the pushes journal, `pushes.log` under `runlog/`
  in the git common dir, in the runlog kit's grammar (`tools/runlog/README.md`, "The grammar"), with
  the fields `decision=bypass`, `bypass=<kind>`, `sha=<40 hex>`, `policy=<allowed|refused>` and, for a
  landing, `tree_verdict=<GREEN|RED|none>`. `write_bypass_line` writes it, byte-identical in
  `tools/push-main.sh` and `.githooks/pre-push`, the pair held as `read_policy_key`'s pair already is
  (`push-main.sh:396-404`). Each record also prints one `bypass:` line on stderr. Observed by AC2,
  AC3 and AC4.
- **S3** — Kind `ungated-landing`: `check_push_allow` (`push-main.sh:342`), on the path where git
  reports a push and the hook left no allow record for it, writes the record before its return 1,
  `tree_verdict` read from the runner-written per-tree verdict `<common-dir>/gate-verdict/<tree hash>`
  of the pushed SHA's tree (shared interface I8, unit 4's), so a hook killed after a green bar is told
  from a push no bar judged. Its exit stays 4. Observed by AC2.
- **S4** — The commit check's witness: `check_commit_message` (`unattended.sh:13475`), on the path
  where it admits a commit whose `Pass:` trailer names an open dispatched pass, appends the trailer
  `Commit-Checked: unattended@<KIT_UNATTENDED_VERSION>` to the message file with `git
  interpret-trailers --in-place`. A commit the hook never saw carries no such trailer. Observed by AC3.
- **S5** — Kind `unwitnessed-commit`: the pre-push hook walks the pushed range's non-merge commits
  whose `Pass:` trailer names a unit (`none` excluded) and records each one with no `Commit-Checked:`
  trailer. Under `allowed` the push proceeds; under `refused` the hook refuses it, naming each SHA.
  Observed by AC3 and AC4.
- **S6** — `refused` needs an off-node witness: under `refused` the lander and the pre-push hook ask
  the verdict registry (unit 6's, `verdict_backends.py`) whether the `verdict` value's row is
  `off_node`, and refuse every landing while it is not, naming `verdict` and the off-node names the
  registry declares. Observed by AC5.
- **S7** — The history arm in `tools/unattended/check-pass-order.sh`: every non-merge commit in a
  run's range whose `Pass:` trailer names a unit and that lacks `Commit-Checked:` is listed; under
  `refused`, read at the graded commit, the leg exits 1 on any; under `allowed` it prints them as a
  note and exits 0. Run inside the bar an off-node backend runs, this is the refusal no local bypass
  reaches. Observed by AC6.
- **S8** — `help/policy.md` states what each value records and refuses, and `tools/runlog/README.md`
  names the `decision=bypass` line among the pushes producer's lines. Observed by AC7.

## 3. Non-goals (OUT)

- Undoing a landing: an UNGATED landing is already on the remote; it is recorded and the lander keeps
  its exit 4 and its refusal to write the lander marker.
- A server-side required check: a repository setting, the owner's (`remote-ci.yml:11`).
- The verdict backends and the off-node verifier: TOOL-dWitnessedBar-6's.
- `core.bypass`, whether a bypass may skip the core legs: PLAY-dOrderedCharter-7 S10's.
- Witnessing commits outside an unattended run: the commit check runs only for a run bound to the
  worktree's branch, so an attended commit is graded by S5 only when it carries a `Pass:` trailer.
- Proof that a `Commit-Checked:` trailer was written by the hook: it is text, and a forged one is a
  deliberate act beyond a bypass (§5 risks).

### Edges

- **consumes-from** `TOOL-dWitnessedBar-6` — `verdict`, the backend registry's `off_node` field that `hooks.bypass = refused` requires of the `verdict` value, and `read_verdict`, through which the lander admits a landing only on that off-node backend's `GREEN` (unit 6 S10), the witness `refused` relies on

## 4. Design

### The record

```
v=1	t=1761400000.123456	p=pushes	ev=once	decision=bypass	bypass=ungated-landing	sha=<40 hex>	policy=allowed	tree_verdict=GREEN
v=1	t=1761400100.000001	p=pushes	ev=once	decision=bypass	bypass=unwitnessed-commit	sha=<40 hex>	policy=allowed
```

The journal is evidence, never an input (`.githooks/pre-push:222-224`): nothing branches on a bypass
line, so a record that fails to append prints the hook's one `pre-push: run log` line and changes no
exit. The refusals of S5 to S7 read the commit history and the policy, never the journal.

### Where each kind is seen

| Kind | Seen by | Under `allowed` | Under `refused` |
|---|---|---|---|
| `ungated-landing` | the lander, after git reports the push | recorded, exit 4 | recorded, exit 4; prevented upstream by S6 |
| `unwitnessed-commit` | the pre-push hook, over the pushed range | recorded, push proceeds | recorded, push refused |
| either, with every local hook skipped | the off-node backend's bar, through S7's arm | printed as a note | leg red, no off-node GREEN |

### Inventory

Minted: `write_bypass_line`; the journal fields `decision=bypass`, `bypass`, `policy` and
`tree_verdict`; the kinds `ungated-landing` and `unwitnessed-commit`; the trailer `Commit-Checked:`;
the arm `unwitnessed pass commits` of `check-pass-order.sh`. Naming cells: `write_bypass_line` is
asked of `python tools/lexicon/lexicon.py --suggest write_bypass_line --as sh.function` at the pass.

### Migration

Additive. Pass commits landed before this unit carry no `Commit-Checked:` trailer, so S5 and S7 read
only commits after the pinned BASE of the run that graded them, and S7 grades a run's range only
when its BASE descends from this unit's landing commit.

### Rollout

Live at landing under the default `allowed`: records only. `refused` is opt-in and refuses itself
until `verdict` names an off-node backend (S6). The unattended and run-gates kits' versions move.

### Alternatives rejected

- **A run-state row per bypass.** It records only inside an unattended run, and an attended landing
  is the commoner bypass.
- **A per-commit witness file under the common dir.** It is node-local, so a run resumed on another
  node reads every earlier commit as unwitnessed; the trailer travels with the commit.

## 5. Production-readiness checklist

- security — narrows: under `refused` a landing needs an off-node witness and a pushed pass commit
  needs the commit check's trailer. The journal line carries no URL and no credential, under the
  hook's rule (`.githooks/pre-push:217-220`), and no field spells the declared bypass flag.
- perf / scale — one `git log` over the pushed range in the hook, one over a run's range in the leg.
- error / empty / loading states — an unreadable policy reads the catalogue default `allowed` and
  says so once; an absent registry under `refused` refuses the landing naming the missing kit.
- observability — the `bypass:` stderr line, the journal line, and the leg's note.
- risks — the trailer is text, so an agent may type it; S7 then reads a forged witness as real. The
  trailer keeps the honest bypass visible and makes a forged one a deliberate act in history.
- testing — AC1 to AC7 by fixture and probe; the arms in §7.
- migration — per §4, pre-BASE commits are not graded.
- user docs — `help/policy.md` (S8).

  fixture: the lander suite's killed-hook fixture, which exists today for check_push_allow.
- **AC3** — When a fixture run's pass commit made past the hooks, so carrying no `Commit-Checked:`
  trailer, is pushed under `allowed`, the fixture's `pushes.log` gains a `bypass=unwitnessed-commit`
  line naming it and the push proceeds; a pass commit made through `check_commit_message` carries the
  trailer and records nothing.
  Red when: the hook greps a trailer the commit check never writes, so every pass commit reads as a
  bypass.
- **AC4** — When the AC3 push runs under `hooks.bypass = refused` with an off-node `verdict`, the
  pre-push hook exits non-zero naming the unwitnessed SHA, and the record is still written.
  Red when: `refused` records and admits.
- **AC5** — When the fixture lander runs under `hooks.bypass = refused` and `verdict = local-hook`, it
  exits non-zero before any push, naming `verdict` and `peer-node` and `remote-ci` as the off-node
  names `verdict_backends.py` declares.
  Red when: `refused` is honoured on the node it claims to guard, which its own bypass skips.
- **AC6** — When `bash check-pass-order.sh --preview` runs in `tools/unattended/` over a fixture run
  whose range holds one pass commit with no `Commit-Checked:` trailer, it lists the SHA, exiting 1
  under `refused` and 0 with a note under `allowed`.
  Red when: the arm reads only the trailer's absence and not the policy, so `allowed` reds.
- **AC7** — When `grep -n 'hooks.bypass' policy.md` runs in `help/` and
  `grep -n 'decision=bypass' tools/runlog/README.md` runs, each prints at least one line.
  Red when: a user cannot learn what a bypass records without reading the hook.
