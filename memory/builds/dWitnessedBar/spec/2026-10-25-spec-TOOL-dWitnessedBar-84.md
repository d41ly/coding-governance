## 4. Design

### Why one unit

M4 admits a second unit only so that the two halves build concurrently. The suite half, S2, S6, S10,
S11, S13 and S14, writes `tools/run-gates/run-gates.gov.test.sh`; S7 renders
`memory/map/generated/symbols.json` from that suite, so S7 reads the suite half's output as generator
input, M6 clause 2. S9 writes `tools/gate-legs.json`, which the suite reads as its manifest, clause 2
again. The ledger items write acceptance records the suite half's AC runs feed. No split leaves two
disjoint write sets, and dispatch is strictly sequential, a shared order included
(`tools/workflows/unattended-build.js:76`), so a split would buy no concurrency. One unit holds all
16 findings, as `TOOL-dWitnessedBar-78` §4 held its 20.

### Evidence

  (`:34`), `resolve_python` (`:58`) and `read_derivation` (`:167`), and `symbols.json` lists all
  three. `tools/codebase-map/map_extractors.py:299` and `:332` skip a name opening with `_` as private,
  so S10's helper adds no symbol-tier key.
