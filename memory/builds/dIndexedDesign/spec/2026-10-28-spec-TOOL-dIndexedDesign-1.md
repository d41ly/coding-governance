## 1. Goal

The hand-off from Design to Build reads the unit's design state as the policy key `design.handoff`
says: `derived-ready` admits a unit only when its derived state is READY, `ready-plus-audit` also
wants a spec-audit record pinning a Tier-2 unit's current revision, and `status-and-tier` keeps
today's floor. Today `--dispatch` refuses only MISSING and THIN, so a FORKED unit is built
(gap-design-04); this unit closes that gap at the Design exit and at every dispatch.

### The hand-off table

`check_handoff_unit` reads the tier from the spec's status header (`Tier-1` or `Tier-2`) and grades:

| Value | State | Audit verdict | Verdict |
|---|---|---|---|
| any | `MISSING` or `THIN` | not read | refuse: M2's hard floor holds under every value |
| `derived-ready` | `READY` | not read | admit |
| `derived-ready` | `FORKED` or `UNCARRIED` | not read | refuse |
| `ready-plus-audit` | not `READY` | not read | refuse, as under `derived-ready` |
| `ready-plus-audit` | `READY`, Tier-1 | not read | admit |
| `ready-plus-audit` | `READY`, Tier-2 | `current` | admit |
| `ready-plus-audit` | `READY`, Tier-2 | `past <N>`, `none` or unread | refuse |
| `status-and-tier` | `FORKED`, `UNCARRIED` or `READY` | not read | admit |
| a value outside the three | any | not read | refuse, naming the value |

A refusal line reads `hand-off refused — <unit> · <state> · design.handoff <value>[ · audit <verdict>]:
<remedy>`. The remedies: resolve the §8 forks (FORKED), carry the clause (UNCARRIED), run a spec audit
pinning `<unit>@rev-<N>` (an audit verdict), or set `design.handoff` in `.governance/policy.toml`.
Under `ready-plus-audit` a generator that does not resolve, or a mode that exits 2, is the verdict
`unread` and refuses: the gate denies by default rather than reading an unknown as an audit.

### The audit-pin mode

`--audit-pins <slug>` plans the tree as `--check` does and takes that slug's build: its units, with
their header `rev`, and its `records`, each with the `pins` `read_bindings` gave it. For each unit, in
unit order, the highest pin any `spec-audit` record gives it decides the verdict; `past` is exactly
the set `derive_past_pin_ids` returns, and a unit with no pin is `none`. A slug the plan does not hold
is exit 2 naming it. The mode writes nothing.

### The calls

S2's arms sit inside `check_design_exit` after its own coverage reading:

```bash
_hov=$("$_hopy" "$_hopol/policy.py" get design.handoff) || { fail 49 "...the policy read refused..."; return 1; }
# per graded unit:
_hoa=-; [ "$_hov" = ready-plus-audit ] && _hoa=$(audit verdict of $u from --audit-pins, or unread)
check_handoff_unit "$_hov" "$u" "$spec" "$(derive_ready_state "$spec" "$FORK_CUTOFF")" "$_hoa" || refuse
```

`_hopy` and `_hopol` are the python and the policy kit directory I3's shell form resolves; the call
keeps `policy.py get design.handoff` literal so the reader-coverage arm sees it. The pin mode runs once
per call, never per unit.
