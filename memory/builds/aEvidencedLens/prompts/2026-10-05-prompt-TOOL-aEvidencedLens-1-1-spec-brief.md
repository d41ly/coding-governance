## The evidence this build stands on

The mandate's five points come from a read-only study of the tree, and its numbers are below. Cite
them as "measured 2026-10-05, session study", never as a gate figure.

- **Defects that got past the audit.** 91 were found across 13 audited builds. About 37 needed
  evidence no lens was allowed to gather: running a command at BASE, grepping consumers, a staged
  break, or a timing. About 29 sat in places no lens was aimed at: carriers and consumers of a changed
  rule, gate legs and budgets, degenerate inputs, and cost. Skeptics wrongly refuted none.
- **Confirmed spec-audit defects by class**, 343 findings over 42 records:
  - wrong claim about existing code: 14.5%
  - design defect or missing edge or failure mode: 13.7%, no brief names it
  - fallout on the repo's own machinery (legs, version carriers, map keys): 11%, no brief names it
  - criterion that cannot fail: 10.5%
  - scope item with no criterion: 9.3%
  - units disagree on ownership or landing order: 7.3%
  - criterion that cannot pass on a correct build: 7%, no brief names it
  - sections disagree: 6.7%
  - text left stale by the last fold: 6.1%
  - wrong number: 4.9%
  - prior decision ignored: 4.9%
  - adopter breakage or security: 4.1%
- **Prior art is the noisiest lens.** Its precision is 0.58 and about 60% of its confirmed output
  belongs to other lenses' classes. Its refutations are mostly "a real neighbouring record exists,
  but it does not bind this spec".
- **The `aBlindedTrial` report** (`memory/builds/aBlindedTrial/build/2026-09-20-build-TOOL-aBlindedTrial-1-trial-report.md` §4.3):
  a spec is followed as a ceiling. When a spec named the class for one input file and not the other,
  the builder handled exactly the file the spec named.
- **The current prompts.** The only automated caller, `tools/workflows/unattended-build.template.js`'s
  Audit stage, passes `{kind, repo, round, reviewDir, subjects}` and nothing else. The finder text
  says "nothing outside the spec set". The round-N brief says "this is a FOLD review" and also "none
  - this is a first-round review". The spec skeptic confirms only what "makes the spec unbuildable or
  wrong", so a LOW can never be confirmed. A moved blob is hard-coded BLOCKER.

## Shared invariants — every spec states the ones it touches, and none contradicts one

1. **The source is the template.** Edit `tools/workflows/tier2-review.template.js` and
   `tools/workflows/unattended-build.template.js`. Their renders are regenerated by
   `bash tools/workflows/check-protocol-parity.test.sh --render`, never hand-edited, and the template
   and its render land in the same commit.
2. **Spec kind only.** No prompt, lens, schema or return field of `kind: 'diff-review'` changes
   meaning. Where shared code moves, such as the review key, the diff kind's prompts stay
   byte-identical. Every unit touching `tier2-review.template.js` has an acceptance criterion that
   proves it: the diff-kind finder and skeptic prompts rendered by a stub run are byte-identical
   before and after.
3. **Probes are READ-ONLY.** No write to any path under `repo`. Temporary files go only under the
   new `scratch` arg. Every command a lens or skeptic runs is bounded by a stated timeout. No merge
   bar, no `*.test.sh` and no self-test runner run inside a lens; the gate guard refuses those before
   `VERIFYING` anyway, and the brief says so rather than leaning on it. A probe that needs a write,
   such as a staged break, is DESCRIBED in the finding as the probe the build must run. It is never
   performed.
4. **New `args` fields.** `scratch` (absolute path), `prevBlob` on a spec subject (7 to 40 hex), and
   whatever else a unit adds. Absent means a documented default, announced by a `log('WARNING: …')`
   line and in the synthesis's RUN INTEGRITY block when it degrades the review. Present but malformed
   means a `throw new Error('tier2-review: …')` naming the field, the legal set and what was given,
   before any agent spawns. Each field is added to the `args` header comment in the same commit,
   because the self-test arm "args header documents every field read" must keep passing.
5. **The review key.** `REVIEW_SHAPE` moves ONCE for this build, from `'lenses5-r1'` to
   `'lenses5-r2'`, in unit 1, the first to change a spec prompt. Later units do not move it again.
   Every new input that reaches a prompt (`prevBlob`, the probe policy) joins `inputPrint` in the unit
   that adds it. `scratch` is a location, not content, and does NOT join the print.
6. **Fan-out.** `tools/hooks/agent-cap.js` is not edited. `SPEC_LENSES` stays an array LITERAL of at
   most five elements, and `const LENSES = isSpec ? SPEC_LENSES : DIFF_LENSES // gov:fixed-verifiers`
   stays the receiver. No `.map` or `.filter` reshapes the receiver.
7. **Versions move once, at the close.** No unit bumps a kit version. The main loop bumps every kit
   this build touched in one commit after the last move, because
   [stamps are not one stamp]: each move after a bump re-owes it.
8. **Lexicon.** Every new function name leads with a verb from `.lexicon.conf`'s `VERBS:` table. Check
   it with `python tools/lexicon/lexicon.py --suggest <name> --as <cell>` before writing it. This
   includes records-only Python in unit 10.
9. **Verification inside a pass is direct.** It is a stub run of the workflow script with recording
   `agent()` globals: the AsyncFunction shape `tools/workflows/tier2-review.test.sh` already uses, run
   from a scratch script and not from the suite. Or it is a staged break of a checker, or a `--selftest`
   flag. The `*.test.sh` suites are EDITED in the unit that changes what they pin, and run once at
   `VERIFYING` by the main loop.
10. **A gate clause is observed RED** on a staged break before it lands, and the spec's §6 names that
    break.
11. **Governance carriers.** Only unit 11 edits `memory/guides/BUILD-METHOD.md` (through
    `tools/memory-tree/BUILD-METHOD.template.md`), the unattended Skill (through
    `tools/unattended/SKILL.template.md`), the verbs entry and `memory/DECISIONS.md`. Those edits are
    limited to stating what units 1 to 9 built and the owner's answered question. That scope is the
    owner's mandate, so it is not a veto-2 fork; anything beyond it is.

## Unit 1 — `TOOL-aEvidencedLens-1` — the spec-audit lens catalogue (Tier 2)

**Mechanism.** Replace `SPEC_LENSES` with FIVE lenses whose briefs name the measured classes:

- `coherence` — every §2 item has a §6 criterion. Every criterion names an observation that can
  FAIL on today's tree AND can PASS on a correct build (both halves; "cannot pass" is 7% and no brief
  named it). §2 against §3, §4 against §7, and M2's four axes across units: scope, interface,
  ordering and acceptance, ownership and landing order included.
- `grounding` — every claim §4 and §10 make about existing code, tools, platform and cost is TRUE at
  BASE. This is today's unstated-assumption lens, widened to platform traps (MSYS argument rewriting,
  drive-letter paths, CRLF) and stated wall-clock goals.
- `reuse` — prior art, reshaped for the product's rule that functionality is reused and extended,
  never rebuilt.
  - It finds a design that builds what already exists: a function, a checker, a leg, a verb, a
    record shape. It finds a §10 seam that is cited but not the one extended, or one that does not
    exist at BASE. And it finds a decision record that already decided the question (decided asks
    included).
  - It probes with `python tools/codebase-map/reuse_lookup.py "<phrase>"`, with
    `python tools/memory-recall/query.py "<question>" --terms "<8-14 terms>"`, and with grep (the
    lookup cannot see shell; it says `unscanned layers: .sh`).
  - It also reads `python tools/memory-tree/gen_build_index.py --asks --json --all`.
  - The STRICTER BAR: a reuse finding names the existing seam or record by path, AND the spec text
    that duplicates or contradicts it. "A related record exists" is not a finding.
- `blast-radius` (new) — what the change trips that the spec does not list.
  - Consumers and carriers of every renamed or changed name, value or rule, found by grepping the
    name and the value.
  - Gate legs whose guard the files-touched list matches (`tools/gate-legs.json`), and size and time
    budgets (`tools/run-gates/selftest-budgets.txt`, template size limits).
  - Version carriers, codebase-map keys, the hygiene record rules, `--dispatch` write sets, and
    adopter renders.
- `failure-envelope` (new) — what the built thing will meet that the spec does not cover.
  - Empty, malformed, multi-line, unterminated, huge and concurrent input; signals and partial
    failure.
  - A security or write surface §5 did not price.
  - A spec that names one INSTANCE where the class was meant: one file of two, one caller of three.
    That is the `aBlindedTrial` §4.3 shape, and the brief cites it.

The harness becomes the ONE source of the catalogue. `tools/memory-tree/README.md`'s M4 list is
reduced by unit 11 to a pointer at it, and this unit's spec says so as a hands-off. The comment
"COPIED from <prefix>/memory-tree/README.md" is deleted.

The meta `Find` detail names both kinds' lens counts. `tools/workflows/README.md`'s "A spec audit

## Unit 2 — `TOOL-aEvidencedLens-2` — spec lenses probe read-only, and every spec finding carries its evidence (Tier 2)

**Mechanism.**

- The spec acquire sentence and the spec finding line drop "nothing outside the spec set". In its
  place: every finding is ABOUT the spec set, and its evidence may come from anywhere in `repo` at
  HEAD.
- A PROBE POLICY block, spec kind only, is rendered once and sits under the LENS line. It says:
  - run read-only commands to establish every claim;
  - run each §6 criterion's own command or check at BASE when it is read-only and bounded, and
    record what it printed (a criterion green before the change is built is the cannot-fail class);
  - grep consumers of every name the spec renames or changes;
  - time any stated wall-clock goal once;
  - never write under `repo`; temporary files go under `scratch`;
  - bound every command, and never run a merge bar, a `*.test.sh` or a self-test runner;
  - a probe needing a write is described, not run.
- `SPEC_FINDING_SCHEMA` gains a REQUIRED `evidence` string per finding: the command run and what it
  printed, or `read: <path>:<line>` for a finding resting on reading alone. The JSON return line
  names it.
- New arg `scratch`, an absolute path refused by shape exactly as `unattended-build.template.js`
  refuses its own. It is required on the spec kind and ignored by the diff kind. Absent on the spec
  kind → refuse. The decision on refuse versus warn is this spec's; recommend refuse, because a
  probing lens with no scratch has nowhere legal to write.

The skeptic's use of `evidence` is unit 3's.

## Unit 3 — `TOOL-aEvidencedLens-3` — the spec skeptic (Tier 2)

**Mechanism.** The spec skeptic sentence is rewritten.

- **Confirm** when the finding's claim is true of the spec set, and of the tree where it makes a
  claim about the tree, at any rubric severity. The rubric grades it; confirmation no longer requires
  "unbuildable or wrong". This removes the contradiction with "grade confirmed findings down to low".
- **Refute** in five named cases:
  - a non-goal or parked fork withholds what it asks;
  - the cited section already says it;
  - the premise is false on re-probe;
  - by design (BY DESIGN block);
  - a duplicate of a prior-round original, or of another finding in this batch, with the surviving id
    named.
- **For every finding the skeptic RE-RUNS or re-reads the finder's `evidence`**, with the same
  read-only policy as unit 2, and says in `reason` what it observed. A finding whose evidence does not
  reproduce is refuted.
- A claim about code or a record is checked against the code or the record, not against the spec.
- The verdict schema is unchanged. The `uncertain` default by finder grade is unchanged.

## Unit 6 — `TOOL-aEvidencedLens-6` — lens yield, per lens, unique defects counted (Tier 2)

**Mechanism.** The synthesis's `items` already group confirmed raw ids into adjudicated defects. From
those items and the ledger, the harness derives `lensYield`, one row per lens that RAN:

- `raw`, `confirmed`, `refuted`, `uncertain`, `unverified`;
- `precision` = confirmed / (confirmed + refuted), null when both are 0;
- `defects` = items holding at least one confirmed id from this lens;
- `unique` = items whose every confirmed id is from this lens.

It is returned on every path that ran a synthesis and logged as one line per lens. It is derived
after the synthesis returns, so it cannot be in the report the synthesis writes. The spec decides
whether the counts known before synthesis (`raw` to `precision`) go into the prompt as a verbatim
block, as the appendix does, with `defects` and `unique` returned only; recommend that split. It
applies to BOTH kinds: it is a return field and a verbatim block, it moves no prompt text a lens or
skeptic reads, and invariant 2 is about lens and skeptic prompts.
