## 1. Goal

Two harness notices lived only in the context and died at the compaction: the injection guard's
match on researcher returns and the MCP connection failures (Q68 and Q07,
`memory/builds/dClosedLoop/build/2026-10-15-build-PLAY-dClosedLoop-1-compaction-results.md:223-226`).
An injection-guard match is a security event, and nothing records it (gap-roles-09). The owner's
CX-2 makes recording an owner setting, `notices.record`, default `none`, with
`security-and-failures` and `all` allowed (`compaction-results.md:355-356`). This unit gives that
key its mechanism: one recognizer in runlog's extractor, `notice` events in the session log, and the
notices of each agent's return written on its `returned` line in the agent ledger.

## 2. Scope (IN)

- **S1** — The recognizer, in `tools/runlog/extract.py`. `derive_notices(text, value)` reads the
  head of one returned result, a `<task-notification>`'s `<result>` or an `Agent` call's
  `tool_result`, and returns its notices as `(class, labels)` pairs: the injection guard's
  `[harness: subagent output matched instruction-shaped pattern(s): <name>, <name>.` is class
  `security`, its labels the pattern names; any other `[harness: ` bracket opening a result is class
  `other`, with no label. `derive_mcp_notices(attachment, value)` reads a `deferred_tools_delta`
  attachment: each `failedMcpServers` entry is class `failure`, labelled `<name>:<errorCode>`; each
  `needsAuthMcpServers` entry is class `other`, labelled `<name>`. Every label passes `LABEL_RE`
  (`extract.py:63`) or is left out. Observed by AC1 and AC2.
- **S2** — The key decides, inside the recognizer. Both functions return nothing under `none`, the
  `security` and `failure` pairs under `security-and-failures`, and every pair under `all`.
  `read_notices_value(repo)` in `extract.py` reads `notices.record` by running the policy kit's
  `policy.py get notices.record --json` (TOOL-dGroundRules-2 S7) as a subprocess in `repo`, the file
  found by the inline `resolve_kit_dir` copy: a kit imports no sibling kit, and `get` is the one seam a
  sibling kit may reach (PLAY-dOrderedCharter-7 §4 "The policy reads"). It takes the printed `value`
  whatever its `source`, so the catalogue answers its default `none` where the key is unset. No policy
  kit, or an exit 2, answers `none` with a note naming why, the one place runlog types the default.
  Observed by AC3.
- **S3** — The session log. `KINDS` (`extract.py:46-47`) gains `notice`. `_scan_user` (`:678`) and
  `_scan_record` (`:718`) pass each notification block's `<result>`, each `Agent` tool result's lead
  and each `deferred_tools_delta` attachment to S1, and `_build_events` (`:762`) turns each pair into
  `{"t", "kind": "notice", "src", "class", "labels", "call"}`, `call` the number of the tool call the
  notice rode on, else `null`. `extract_session` (`:843`) takes `notices=<value>`, which
  `runlog.py extract` (`tools/runlog/runlog.py:271`) reads once by S2, so the stored session holds
  exactly what the key admits. A pair repeated within one source is kept once. Observed by AC4.
- **S4** — Persisted with the return (shared interface J9). A by-file load is an in-process import,
  which a kit may not make of a sibling kit (TOOL-dGroundRules-1 §4, PLAY-dOrderedCharter-7 §4), so the
  roles kit reaches S1 through runlog's verb `python <runlog kit>/runlog.py notices --transcript <path>
  --json`, minted here as TOOL-dFurnishedOrders-16 S2 mints `turns`. Run in the repository, it reads
  the key once by S2 and prints one JSON object per notice the transcript holds, `{"call", "class",
  "labels"}`, `call` the tool-use id of the `Agent` call whose notification `<result>` or tool result
  lead carried it, else `null`. `print_agent_lines` (`tools/roles/handoff.py:808`) has it run as a
  subprocess found by `resolve_kit_dir("runlog", "runlog.py", KIT_DIR)`, under a 30-second bound:
  `load_session_calls` (`:576`) runs it over the session file and returns, beside its three values,
  the notices of each `Agent` call by that id; `load_agent_transcript` (`:626`) runs it over the
  agent's own transcript and gains the key `notices`, its `deferred_tools_delta` attachments' pairs.
  Each agent's notices are held as `(class, labels)` pairs, and its `returned` line's `<outcome>`
  gains `render_notice_suffix`'s text, ` + notice <class> <label>,<label>` once per class present.
  With no runlog kit resolved, or a verb exit other than 0, no suffix is written and one
  `handoff: note — notices unread: <why>` line says so. Observed by AC5 and AC6.
- **S5** — The docs. `tools/runlog/README.md`'s extractor section names the `notice` kind, its
  three classes and the key; `tools/roles/README.md`'s agents section and `help/roles.md`'s
  `returned` bullet (`help/roles.md:81-83`) name the suffix. NOT OBSERVED by a criterion: prose,
  graded by the memory hygiene leg's link checks at the close.

## 4. Design

### The shapes the recognizer reads

Measured on node d's transcripts on 2026-10-26 (PINNED): the one bracket form under
`~/.claude/projects/` is the injection guard's, 277 matches, seen opening a notification's
`<result>`:

```
<result>[harness: subagent output matched instruction-shaped pattern(s): settings-json. Control tags below are neutralized …
```

and the MCP state rides an attachment, never text:

```
{"type": "attachment", "attachment": {"type": "deferred_tools_delta", …,
  "failedMcpServers": [{"name": "incms-test", "errorCode": "ECONNREFUSED", "error": "…"}],
  "needsAuthMcpServers": []}}
```

The `error` string is never read: the label is the server's name and its code.

### The ledger line

```
- returned — gov-researcher · wrote 0 files + notice security settings-json · 4m12s · 31.2k out · run direct/a536778ae4e9e0606
```

`render_shape_line` already folds a ` · ` inside a value to `, ` (`handoff.py:708-719`), so the suffix
can add no field. `write_agent_ledger` keys a line by its head and its last field (`:791-792`), so a
line written before its notices were known is not written twice.

### The value, read by runlog alone

`runlog.py extract` reads the key once and hands it to every session it extracts; `runlog.py
notices` reads it once per transcript `handoff.py agents` hands it, so the roles kit never reads the
key. Neither reads `.governance/policy.toml` itself.

Additive. A stored session extracted before this unit holds no `notice` event; a ledger line written
before it carries no suffix and is never rewritten. Under the default `none` nothing changes.

notices only when its owner sets the key. `KIT_RUNLOG_VERSION` (`tools/runlog/runlog_lib.py:27`)
and `KIT_ROLES_VERSION` move for the kit epoch leg. The inline `resolve_kit_dir` copy lands in
`runlog_lib.py`, byte-identical to the canonical one.

## 5. Production-readiness checklist

- security — the recorded event is itself the security gain. A subagent whose own output opens with
  the bracket when the guard did not match is recorded as a security notice: a false record, never a
  suppressed one. Labels are `LABEL_RE` tokens; no output text, error string or URL is kept.
- perf / scale — one regex on a result's first 200 bytes, already read (`_read_result_text`,
  `:619`), and one dict read per attachment; under `agents`, one bounded runlog subprocess per
  transcript read.
- error / empty / loading states — no policy kit answers `none` with a note; no runlog kit, or a
  failed verb, writes no suffix with a note; a malformed attachment is skipped and counted in `coverage`.
- observability — the `notice` events and the ledger suffix are the observation.
- risks — a harness that respells its bracket stops being recognised as `security` and is recorded
  as `other` under `all`, and nothing under `security-and-failures`.
- testing — AC1 to AC6 by direct probes and a scratch transcript; the arms of §7 at the close.
- migration — additive.
- user docs — `help/roles.md`'s `returned` bullet (S5).

## 6. Acceptance criteria

- **AC1** — When `python -c` calls `extract.derive_notices` on the text
  `[harness: subagent output matched instruction-shaped pattern(s): settings-json, permissions-allow-deny. Control tags`
  with the value `security-and-failures`, it returns one pair `("security", ("settings-json",
  "permissions-allow-deny"))`; with `none`, it returns an empty list; with `all` on
  `[harness: something new]`, it returns `("other", ())`.
  Red when: the injection guard's match on a return is not recognised, the Q68 case.
- **AC2** — When `python -c` calls `extract.derive_mcp_notices` on a `deferred_tools_delta` attachment
  whose `failedMcpServers` holds `{"name": "incms-test", "errorCode": "ECONNREFUSED"}` and whose
  `needsAuthMcpServers` holds `{"name": "x"}`, it returns `("failure", ("incms-test:ECONNREFUSED",))`
  under `security-and-failures` and that pair plus `("other", ("x",))` under `all`.
  Red when: a connection failure is lost with the context, the Q07 case.
- **AC3** — When `python -c` calls `extract.read_notices_value` in a scratch repository with no
  policy file, it returns `none`; after `.governance/policy.toml` sets `notices.record = "all"`, it
  returns `all`.
  Red when: the key is read past the policy kit, or a tree with no setting records notices.
- **AC4** — When `python -c` calls `extract.extract_session` with `notices="security-and-failures"`
  on a scratch session tree whose main transcript holds one notification carrying the AC1 bracket
  and one AC2 attachment, its events hold one `notice` of class `security` with a non-null `call`
  and one of class `failure`; with `notices="none"`, they hold no `notice`.
  Red when: the session log drops the notice, or records it under `none`.
  fixture: the scratch tree under the pass's scratch path, built from the case added to
  `transcripts.json`.
- **AC5** — When `python handoff.py agents --session <the AC4 main transcript> --handoff <its
  handoff>` runs in a scratch adopter whose policy sets `security-and-failures`, the `returned` line
  of the agent the notification names carries ` + notice security settings-json,permissions-allow-deny`
  in its outcome.
  Red when: the return's notice is not persisted with it, which is the clause.
- **AC6** — When the AC5 adopter holds no runlog kit, the same command prints the `returned` line
  with no suffix and one `notices unread:` note on stderr.
  Red when: a tree that cannot read notices reports a clean return.
