## 1. Goal

The round-1 spec audit of the 20 unit specs
(`memory/builds/dFurnishedOrders/reviews/2026-10-26-review-TOOL-dFurnishedOrders-1-spec-audit-round1.md`)
confirmed finding **id 50 at HIGH**, report item **H3**. No other id shares it.

`TOOL-dFurnishedOrders-4` §4 "The upgrade steps" has `witness` and `up` of
`unattended/retire-pass-checklist` and `review-harness/retire-prebuild` scan every tracked file of the
target outside its installed kit files, and `up` exits 1 listing each hit. Records are not excluded.
On this repository `git grep -l 'for-diff HEAD~1..HEAD' | grep -v '^tools/'` prints 127 files, every
one a markdown record, most under `memory/builds/` (measured at `5ff43572`; PINNED). A frozen record
may not be edited, so gov's own update walk, and any adopter's with a records tree, stops on hits
nobody may clear: `up` can never pass.

This unit bounds the scan to executable call sites, matched on the argument key rather than on prose,
and states the population it reads. It repairs `TOOL-dFurnishedOrders-4` and builds one step after it
(order 5).

## 2. Scope (IN)

- **S1** — The population. `derive_call_sites(target, memory_root)` in
  `tools/govkit/steps/retired_dispatch_args.py` (`TOOL-dFurnishedOrders-4` S7's program) returns the
  target's tracked files, `git -C <target> ls-files`, less its installed kit files as unit 4 already
  excludes them, less every path under `<memory_root>/`, and less every `*.md` file. Observed by AC1
  and AC4.
- **S2** — The key hit. A file of the population is a call site when its text names
  `unattended-unit.js`, and it hits for a key the step names when it spells that key as an object key,
  `(^|[^A-Za-z0-9_$])["']?<key>["']?\s*:`, so a comment or a sentence naming the key is no hit.
  Observed by AC2.
- **S3** — The command hit, for `checklist` only: a file of the population spelling
  `gotchas.py --for-diff HEAD~1..HEAD`, the per-pass command unit 4 S6 takes out of the method's text. Observed by AC3.
- **S4** — The memory root. The program reads `MEMORY_ROOT` from the target's `.memory-tree.conf`
  through the memory-tree kit's own conf parser, `parse_conf` (`tools/memory-tree/tree_lib.py:135-147`),
  loaded by its file path under the private module name `gov_tree_lib` as govkit already loads
  `check-arms.py` (`tools/govkit/govkit.py:3145`); an absent conf or key reads `memory`. A value that is
  absolute or carries a `..` segment refuses the step at exit 1 naming the key, before any scan.
  Observed by AC4.
- **S5** — The step says what it read. `witness` and `up` print one line,
  `retired_dispatch_args: scanned <n> call site(s) of <t> tracked file(s); excluded <m> under
  <memory_root>/ and <k> markdown`, before any hit, so a run that scanned nothing is visible as such.
  `up` still writes nothing and exits 1 listing each hit with its remedy; `down` is unchanged.
  Observed by AC1 and AC5.

## 4. Design

### The population

```
git ls-files                      every tracked file of the target
  - installed kit files           as TOOL-dFurnishedOrders-4 §4 already excludes them
  - <MEMORY_ROOT>/**              frozen records and the live ones alike: no record is a call site
  - *.md                          prose quotes a command; it never passes an argument
  = the population
key hit      a population file naming unattended-unit.js and spelling <key> as an object key
command hit  (checklist) a population file spelling gotchas.py --for-diff HEAD~1..HEAD
```

On this repository the 127 files of §1 all fall under the second and third subtractions; the
population that names `unattended-unit.js` outside `tools/` is one rendered file, `.claude/roles.json`,
which spells neither key (measured at `5ff43572`; PINNED).

### What it does not check

- A call site in a file the target leaves untracked: the walk updates tracked trees.
- A retired key passed through a variable whose name differs, `args[k]` with `k = 'prebuild'`: the
  key pattern reads spellings, not values.
- An adopter's markdown that instructs a run to use the per-pass command (§3).

### Inventory

Minted: `derive_call_sites`, asked of `python tools/lexicon/lexicon.py --suggest derive_call_sites --as
py.function`, which answered OK; the private module name `gov_tree_lib`; the scan line of S5.

### Migration

None: the steps have never run, since unit 4 lands them in the same build.

### Rollout

Live at landing, beside unit 4's step rows.

### Files touched (estimate)

- `tools/govkit/steps/retired_dispatch_args.py`
- `tools/govkit/selftest.py`

### Alternatives rejected

- **Waive the 127 records in a list.** A list typed beside the tree it describes grows with every
  build that quotes the command, and an adopter would need its own.
- **Exclude `memory/` by literal.** An adopter's `MEMORY_ROOT` may be another directory; S4 reads it.
- **Scan only files whose extension is a source kind.** A record under the memory root can be a
  `.py` probe or a `.json` capture, and S1's memory subtraction is what keeps every record out.

## 5. Production-readiness checklist

- security — the program reads the target and writes nothing; a `MEMORY_ROOT` that leaves the target
  refuses (S4), so the subtraction cannot be aimed outside it.
- perf / scale — one `git ls-files` and one read per population file; records, the bulk of a mature
  tree, are never opened.
- error / empty / loading states — S5's line names an empty population; a refused conf names its key.
- observability — S5's counts on every `witness` and `up`.
- risks — an adopter that drives the unit harness from a markdown-embedded script is not scanned
  (§4); the walk still renders the kit's own files, so only the adopter's copy is missed.
- testing — AC1 to AC5 by fixtures a pass builds; the arm of §7 at the close.
- migration — none.
- user docs — none: the step's printed line and remedy are what the update walk shows.
