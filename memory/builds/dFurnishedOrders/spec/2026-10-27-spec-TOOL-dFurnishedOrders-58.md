## 4. Design

### Why one unit

The minors land on units 48 and 50 to 52. M4 admits two batch units only when the halves split into
two disjoint write sets by M6. A roles half (`tools/roles/adopt-roles.test.sh`, the budgets file and
the ledgers) and a govkit half (`tools/govkit/`, `tools/gate-legs.json`, the waivers and `BACKLOG.md`)
would split on clause 1, but clause 2 fails: S7's `u` times the `witness` and `apply` runs that S18
adds to `tools/govkit/selftest.py`, so the roles half reads the govkit half's cost as an acceptance
input. One unit at order 31, after every unit it lands on, sequences that.

### The interrupt probe's state, after this unit

```
state(pid)  : Windows -> (s, c) := read_process_created(api, pid)
                         "dead" if s == "live" and recorded c and c != recorded c, else s     S3
              POSIX   -> os.kill(pid, 0): ok -> "live" · ProcessLookupError -> "dead" ·
                         PermissionError -> "unknown"                                        S5
first wait  : pid file non-empty; pid == self.pid (unit 51 S1); if self.poll() is not None
              within 2 s -> state(pid) -> DEAD PROBE: stub pid <n> not live ...              S1 S2
cleanup     : kill only if state(pid) == "live" with recorded c; POSIX then proc.wait       S3 S5
```

### The readers, after this unit

```
R           := max(float(f[3]) for f in lines if f[1] == "ok" and f[3] parses), skips named    S8
receipt     := read_receipt_lines(stdout) -> [lines holding "/RECEIPT]"];
               check_receipt_reached(stdout) := bool(read_receipt_lines(stdout))                S19
problems    := the n lines before the total; any without "govkit: " -> DEAD PROBE               S21
pass(X)     := Pass: names X  or  (no Pass:, X a whole subject token, a write under ROUTED_PATHS) S15
```
