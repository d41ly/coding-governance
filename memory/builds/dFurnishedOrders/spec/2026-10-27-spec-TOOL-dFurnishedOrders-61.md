## 4. Design

### Why one unit

The minors land on units 59 and 60. M4 admits two batch units only when the halves split into two
disjoint write sets by M6. The unit-59 half (S7 to S9, S18 to S20) writes the guard arm's one-way case
in `tools/govkit/selftest.py`. The unit-60 half writes the same file for S10's caught refusal and for
S12, S13 and S27's deploy targets. Clause 1 fails, so one unit sequences both. It repairs two units,
so it takes order 33, one above the highest order in this build (unit 60's 32).

### The landing walk, after this unit

```
range   := git rev-list --no-merges <BASE>..<tip>                         S4
for c in range where guard(c)["govkit selftest"] gains a row:
    pass(c) by derive_pass_units names unit 50 or unit 58                 unit 60 S10, S13
    owed    := reach57(c) - waived57(parent(c)), other builds' specs only  S14
    added   := waiver rows c adds with prefix "govkit selftest <- "
    assert added == owed                                                  (empty == empty passes)
```

target_context(target, deploy, eid, desc): check_deploy_shapes(deploy); ...   S12
