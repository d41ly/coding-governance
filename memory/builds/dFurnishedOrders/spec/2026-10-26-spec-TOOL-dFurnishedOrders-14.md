## 1. Goal

v2's RC-7 hands three questions to the roles layer's lower-level design (v2:1965-1969): how the
answered-call hook matches a read's range against the handed ranges at the blob SHA and which Bash
readers it parses; how the executor cuts and keys excerpts; and how a repair's ask carries the
repaired fact onward until the producer's record is fixed. Clause `cl-dClosedLoop-0205` designs them
"in its own unit specs", and this is that unit: the excerpt cut, the read a call makes, the handed
ranges a work order holds, the one matcher between them, and the carry that hands an open repair
in every work order that cuts the repaired fact. TOOL-dFurnishedOrders-6's hook is the matcher's
reader; nothing here refuses a call.

## 2. Scope (IN)

- **S1** — The excerpt cut, `read_excerpt(root, path, lo, hi)` in `tools/roles/roles_lib.py`,
  returning `(key, text)`: `text` is lines `lo` to `hi` of the file, 1-based and inclusive, CRLF
  folded to LF; `key` is `blob:<path>@<blob12>:<lo>-<hi>` built by TOOL-dBoundRoles-13 S1's
  `derive_fact_key`, never respelled. A whole file is the range `1-<N>`, so no excerpt key lacks a
  range. An anchor (a heading's section, a symbol's definition) is resolved to its line range at the
  cut and the key names the range. A range with `lo` below 1, `hi` past the last line or `lo` above
  `hi` is refused naming it. Observed by AC1.
- **S2** — The read a call makes, `deriveCallRead(data, root)` in `tools/roles/answered-calls.js`
  (a new module, its hook arm TOOL-dFurnishedOrders-6's): a `Read` is `[offset, offset + limit - 1]`,
  `offset` defaulting to 1 and an absent `limit` reading to the last line; a `Grep` whose
  `output_mode` is `content` over one file is that whole file, `1-<N>`; a `Bash` call is the range
  S3 parses; every other call, a path outside the repository, a directory and a glob are no read.
  The path is resolved against the payload's `cwd` and made repo-relative with `/` separators.
  Observed by AC2.
- **S3** — The shell readers, one table `SHELL_READERS` beside `scanCommandHeads`
  (`tools/hooks/scratch-guard.js:1279`), exported with `scanShellReads(cmd)`, which walks
  `scanCommandHeads`' argv: `cat <file>`, `head [-n <k>|-<k>] <file>`, `tail [-n <k>|-n +<k>] <file>`,
  `sed -n '<a>[,<b>]p' <file>` and `grep <pattern> <file>`, each with one file operand and no other
  option. A command of more than one simple command is no read, and a `sed` carrying `-i` is a write,
  TOOL-dBoundRoles-7's to scan, never a read, so the read and write scans walk one argv and never
  claim one shape twice. Observed by AC2.
- **S4** — The handed ranges, `read_handed_ranges(text)` in `roles_lib.py` and its JavaScript copy
  `readHandedRanges(text)` in `answered-calls.js`: every fact line of a rendered work order, read
  through TOOL-dBoundRoles-13's `FACT_RE` and its JavaScript copy, whose key opens `blob:`, as
  `{key, path, blob12, lo, hi, block, section}`, `block` the nearest `### ` heading above it and
  `section` the nearest `## ` heading. Observed by AC3.
- **S5** — The matcher (shared interface J11), `check_answered_range(handed, path, blob12, lo, hi)` in
  `roles_lib.py` and its JavaScript copy `checkAnsweredRange`: the first handed entry with the same
  path, the same `blob12`, `lo_h <= lo` and `hi <= hi_h`, else none. A read that only partly overlaps
  a handed range, or reads its file at another blob, is not answered. The blob at the call is
  `deriveBlob12(bytes)`, the git blob id of the LF-folded bytes, 12 hex digits, the derivation
  TOOL-dBoundRoles-13 S4 makes at the spawn, exported from where that unit leaves it. The two copies
  are held to one case table. Observed by AC2 and AC4.
- **S6** — The repair's carry. `read_open_repairs(root, memory_root)` in `roles_lib.py` reads every
  OPEN ask whose `data` clause opens `handed=` (TOOL-dFurnishedOrders-7's repair ask, the `repair:`
  line in its parts) from memory-tree's ask verb, `python <memory-tree kit>/gen_build_index.py --asks
  --json` (`tools/memory-tree/gen_build_index.py:3235`), run once per render as a subprocess found by
  `resolve_kit_dir`, since a kit imports no sibling kit (TOOL-dGroundRules-1 §4, PLAY-dOrderedCharter-7
  §4). It keeps the rows whose `status`, which that verb folds by `derive_statuses`, reads `OPEN`. A
  row carries no `data` clause today (`:3346-3375`); the field is §8 F8's ask. Until it lands, or where
  the verb exits non-zero, no repair is carried and the render prints one `roles: note — repairs
  unread: <why>` line. `render_handoff` (`tools/roles/handoff.py:312`)
  checks each fact it cuts against them by §4 "The carry", and hands each open repair the fact covers,
  classed `claimed`, keyed by the repair's `read=` key and carrying TOOL-dFurnishedOrders-1's
  ` stale=<source path>@<blob12>` mark when that source moved. Observed by AC5.
- **S7** — The docs: `tools/roles/README.md`'s handoff section (the excerpt cut and the carry) and
  `tools/hooks/README.md`'s section on scratch-guard's scanner (`SHELL_READERS`, and that a read
  scan claims no write shape). Observed by AC6.

## 4. Design

### The excerpt key

```
read_excerpt(root, "tools/x.py", 40, 44)
  -> ("blob:tools/x.py@9f0c1d2e3a4b:40-44", "<lines 40..44, LF>")
```

Lines are counted in the LF-folded bytes, so the key and the hook's read range count one way on
every checkout. The key's grammar is TOOL-dBoundRoles-13's; this unit fixes what its range means:
1-based, inclusive, at most the file's line count, and present on every excerpt.

### The read a call makes

| Call | Range read | No read when |
|---|---|---|
| `Read` | `offset` to `offset + limit - 1`, or to the end | the path is outside the repository |
| `Grep`, `output_mode: content` | `1-<N>` of its one file | `path` is a directory, or `glob` or `type` is set |
| `Bash`, `cat f` | `1-<N>` | more than one simple command |
| `Bash`, `head -n k f` | `1-min(k,N)`, `k` 10 when absent | any option but `-n` |
| `Bash`, `tail -n k f`, `tail -n +k f` | `max(1,N-k+1)-N`, `k-N` | any option but `-n` |
| `Bash`, `sed -n 'a,bp' f` | `a-min(b,N)` | `-i`, or a script other than one print range |
| `Bash`, `grep pat f` | `1-<N>` | any option, or more than one file |

`grep` and the `Grep` tool return lines from anywhere in the file, so only a handed whole file can
answer them.

### The matcher

```
check_answered_range(handed, path, blob12, lo, hi)
  for h in handed:
      if h.path == path and h.blob12 == blob12 and h.lo <= lo and hi <= h.hi:
          return h          # answered: the hook names h.key and h.block as the anchor
  return None               # not covered, partly covered, or moved: the call runs
```

A moved fact is read fresh, never refused (`layer-roles.md:255-258`): the blob at the call differs
from the handed key's, so nothing matches. The Python copy's reader is the carry below; the
JavaScript copy's is the hook. One case table of at least eight cases, each a handed list and a read
with its expected answer, lives in `tools/roles/adopt-roles.test.sh` and runs through both.

### The carry

For each fact `render_handoff` cuts with key `K`, an open repair whose `handed` is `H`:

| `K` against `H` | What the work order hands |
|---|---|
| `K == H` | the repaired fact in place of the original, under the original's heading |
| `K` is a `blob:` whose range `check_answered_range` finds covering `H` at the same blob | the original, then a `### repair:<ask id>` block |
| `K` is the `record:` of the file `H` names, at the same blob | the original, then a `### repair:<ask id>` block |
| otherwise | the original alone |

The repaired fact's fact line is `<!-- gov:fact key=<read key> class=claimed -->`, with
` stale=<source path>@<blob12>` when the `read` key's source now has another blob, and its body is
`handed <H> · found <found line> · ask <ask id>`. A repair of a `witnessed` fact is handed `claimed`:
a role's correction is a judgment until its producer's record is fixed (the roles round's review L2,
`2026-10-15-review-PLAY-dClosedLoop-1-roles-b.md:222`). The carry ends when the ask is CLOSED, which
`derive_statuses` reads, so nothing removes a carried block by hand.

### What it does not check

- A read through any program `SHELL_READERS` does not name (`awk`, `python`, `less`, `nl`) is no read,
  and runs.
- A compound command reading a handed range (`cat f | head`) is no read, and runs.
- A PowerShell read is no read, and runs.
- A `Read` past a 2000-line default the tool applies is matched as a read to the end, so a handed
  range ending at line 2000 does not answer it, and it runs.

Each of these errs toward running the call, never toward refusing one the packet does not answer.

### Inventory

`deriveCallRead`, `readHandedRanges`, `checkAnsweredRange`, `deriveBlob12` where TOOL-dBoundRoles-13
has not already exported one, `scanShellReads`, `SHELL_READERS` (JavaScript); the module

of `python tools/lexicon/lexicon.py --suggest <name> --as py.function` or `--as js.function` and

### Alternatives rejected

- **A second shell scanner for reads.** `scanCommandHeads` already resolves every launcher, prefix and
  `-c` body; a second walk would disagree with it on the first unusual quoting.
- **Answering a partly overlapping read.** The role needs the lines outside the packet; refusing it
  would push the role to read around the hook.
- **A repair overlay store.** The ask already carries the repair; a second store is a second record of
  one fact (review L2).
- **The matcher in Python alone, the hook shelling out to it.** A Python start on every role agent's
  read costs more than the read it would save.

## 5. Production-readiness checklist

- security — no write path: the cut reads repository files the renderer already reads; the carry reads
  open asks through memory-tree's `--asks` verb, which parses every `BACKLOG.md`. `scanShellReads`
  runs no command.
- perf / scale — one blob hash per read the hook sees, only when the work order holds a handed range
  of that path; one `--asks` subprocess per render.
- error / empty / loading states — a work order with no `blob:` fact yields no handed range and every
  read runs; a failed `--asks` run, or rows with no `data` field, carry no repair and print one note.
- observability — a carried block names its ask id; the matcher returns the handed key the hook names.
- risks — the Python and JavaScript copies drifting, held by AC4's one case table.
- testing — AC1 to AC6 by probes and fixtures a pass runs; the arms of §7 at the close.
- migration — none, per §4.
- user docs — none owed by this unit: the refusal a user meets is TOOL-dFurnishedOrders-6's, whose
  `help/roles.md` section names it.
