## 1. Goal

The owner's FK-4-1 settled what attendance does to an owner item: "While the owner attends, a
confirm-steps or confirm-acts gate, or a live question, is held … and `run.on-owner-question` decides
only unattended items", and a late answer is placed by `entry.place` "as an amendment that re-enters
the item it answers, drawing on `flow.rework-budget`"
(`memory/builds/dClosedLoop/build/2026-10-20-build-PLAY-dClosedLoop-1-fold-return-w4.md:82-94`,
`memory/builds/dClosedLoop/build/2026-10-15-build-PLAY-dClosedLoop-1-flow-steps.md:543-547`). Today
nothing reads whether the owner attends: TOOL-dBoundRoles-11's reader takes `attended` from its caller,
`attendance` has no reader (scout C), and no route places an answer that arrives after its item was
decided. This unit derives `attended` at one site, holds and asks live every owner item raised while
the owner attends, and places a late answer as an amendment re-entering the item it answers.

## 4. Design

### The flow

```
owner item raised
  --dispatch FORKED unit            --phase past a gated exit
        |                                   |
  handoff.py owner-question --kind fork|owner-gate [--session <sid>]
        |   derive_attended: attendance adds ask-live?  newest turn owner?  unread?
        v
  owner  -> write_owner_hold: decision row "· asked live", "owner question — asked live" line, refuse
  away   -> fork: TOOL-dBoundRoles-11 S6's answer (resolve, park-item, park-build, stop-run)
            gate: TOOL-dDeclaredLoop-19 S6's hold, as today

owner answer arrives
  item held           -> check_owner_disposition releases it (TOOL-dDeclaredLoop-31 S6)
  item decided (agent) -> placement.py place --late <record>
                            reenters: <unit id>#<F-id> · draw · route-back · <item> · n/total
  item re-enters nothing -> refused, no block, no draw
```

### The attended table

| `attendance` adds `ask-live` | newest turn | `attended` | source |
|---|---|---|---|
| yes | any | yes | `attendance=<value>` |
| no | `owner` | yes | `owner-turn <via>` |
| no | `keepalive` or none | no | `away: attendance=<value>, last turn keepalive` |
| unreadable | any | yes | `unread: <why>` |
| any | unreadable | yes, unless the posture says yes first | `unread: <why>` |

A session with no mandate is one the owner opened, so its newest turn is the owner's and it reads
attended with no special case; an unattended run's turns are opened by keepalive fires, which
`scan_owner_turns` already tells apart (`tools/runlog/extract.py:52`, `OWNER_VIA`).

### The owner item of a fork

A fork is an owner item named `<unit id>#<F-id>`, TOOL-dDeclaredLoop-29 S3's `<item>#<row id>` form with
the unit as the item and the F-id as the row, so a disposition record's `Item` names exactly the span
`--fork-state` reads.

The placement block's `reenters:` line is additive: a block without it reads `none`. No decision row
already parked changes.

turns read away and nothing changes for it; an owner who types into a run's session, or sets an
attended posture, is asked live from the next raise.

  driver.

- security — no new write surface: `write_owner_hold` appends through `park`, which refuses a line end;

  the arms of §7 at the close.
- migration — additive, as §4 says.
