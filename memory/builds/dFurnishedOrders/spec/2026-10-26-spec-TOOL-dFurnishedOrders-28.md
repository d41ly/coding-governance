Id 52 is the failure envelope of the item: an owner question held asked live with nobody present is
never released, because `TOOL-dFurnishedOrders-16` §3 leaves every timeout to dWellOiledMachine, so the
run stalls. Units 26 and 27 stop the launch turn from reading as presence. One path to the same stall
remains: unit 16's table answers attended, `unread: <why>`, whenever the turns cannot be read, on the
argument that "holding decides nothing for the owner". Inside an unattended run that argument fails:
the hold is the stall. A session id the harness does not export, a transcript root the run cannot find,
a runlog kit an adopter did not install or a `turns` read that hangs each holds every fork and gated
phase of the run.

This unit decides the unreadable row inside a window: away, naming why, so `run.on-owner-question`
routes the question as the owner configured it. It repairs `TOOL-dFurnishedOrders-16` and builds one
step after it (order 21), after units 26 and 27 by the dispatch's id sort.

## 4. Design

### The row, in the table with a window

| `attendance` adds `ask-live` | turns after `since` | `attended` | source |
|---|---|---|---|
| yes | any | yes | `attendance=<value>` |

| no | unreadable, no `since` | yes | `unread: <why>` (unit 16) |

### Why away inside a window and attended outside it

Outside a run, a held question is in front of an owner who opened the session, so holding decides
nothing and costs nothing. Inside a run the driver holds a lease that the owner's launch prompt
created, and every later owner turn is the only evidence of presence: with none readable, a hold has
no reader and the run stalls until a deadline this build does not own. Away hands the question to
`run.on-owner-question`, whose values the owner set for exactly the absent case
(TOOL-dBoundRoles-11 S5), so the run still decides nothing the owner did not delegate.

### Alternatives rejected

- **Refuse the dispatch on an unread presence.** It stalls the run the same way, with a different
  message.
- **Away on every unread presence, run or not.** An owner's own session would then decide a fork for
  the owner whenever a transcript is briefly unreadable.
