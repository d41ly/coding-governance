## 1. Goal

Role metrics per role and item into the value ledger, written to a plain metrics file this build owns
until dCalibratedLens's value ledger lands and reads it: answered calls from the hook's records and the
other classes from runlog's extractor, accepted against `role_orientation.py`'s baseline (R3-F,
`memory/builds/dClosedLoop/build/2026-10-15-build-PLAY-dClosedLoop-1-layer-roles.md:539-554`). Today
nothing counts a role's calls by class: the baseline's 811 method, 300 locate and 250 state reads
(`layer-roles.md:987-1021`) were measured once by an instrument that lives only in that record, and
runlog's extractor, which R3-F names as the classifier, has no such class.

## 4. Design

### The orientation class

The instrument classed each call in this order (`layer-roles.md:802-810`): `state`, `locate`,
`method`, else `content`. S1 keeps the order and the instrument's vocabulary, and reads the call
through runlog's own readers rather than over the input's JSON text:

| Class | Decided when | Read by |
|---|---|---|
| `state` | a shell tool's command (`SHELL_TOOLS`, `extract.py:94`) has a segment running `git` with a subcommand in `ORIENTATION_GIT_STATE`: `status`, `log`, `branch`, `worktree`, `rev-parse`, `fetch`, `remote`, `show-ref`, `merge-base`, `describe` (`layer-roles.md:744`) | `extract_segments` (`:372`), `_derive_program` (`:479`), `_derive_git_subcommand` (`:438`) |
| `locate` | a scanned word matches `ORIENTATION_LOCATE_RE`, the instrument's alternation (`layer-roles.md:745`) | the scan below |
| `method` | a scanned word matches `ORIENTATION_METHOD_RE` (`layer-roles.md:746`) | the scan below |
| `content` | none of the above | |

The scanned words are a shell segment's words joined by one space, and for any other tool the
string values of its path-bearing keys, `file_path`, `notebook_path`, `path`, `pattern` and `glob`,
each with `\` folded to `/`. The instrument matched the whole input's JSON, so a `Write` whose body
names `LIVE.md` read as `locate`; S1 reads only where a call is pointed, and AC2 names that divergence
rather than hiding it.

### The rows

```
role	item	task-sha	agent	class	count
gov-spec-writer	item.design.unit-spec	3b18e512cc0f	a1b2c3d4e5f6a7b8c	method	4
gov-spec-writer	item.design.unit-spec	3b18e512cc0f	a1b2c3d4e5f6a7b8c	answered-refused	2
gov-builder	-	-	af00aa11bb22cc33d	content	57
```

Class values, a closed list in `handoff.py`: the four of S1, `answered-refused`, `answered-warned`,
`answered-recorded`, `hook-failed`, `notice-security`, `notice-failure`. Every agent written gets its
four orientation rows, zeros included, so a missing row means "not measured" and never "none".

### Alternatives rejected

- **The instrument's regexes over the whole input's JSON.** Parity would be exact, but a `Write`
  whose content quotes a method document counts as orientation, and the classifier would be a second
  reading of a call beside runlog's segment reader: the `metrics-extractor-seam` finding
  (`layer-roles.md:1814`).
- **Counting per role and item in the file instead of per agent.** A second `--write` over one
  session would double every count, or a retried task-sha would lose its first agent's.

## 5. Production-readiness checklist

- security — no new surface: the counts come from transcripts `agents` already reads, and S1 keeps no
  command text, so no secret in a call reaches the file.
- perf / scale — one extra pass over each agent's `tool_use` blocks, which `load_agent_transcript`
  already walks; the file grows by at most eleven rows per agent.
- error / empty / loading states — no runlog kit: no class rows, a note; no answered-call record: no
  answered rows, a note; no loop kit: `matrix unarmed`.
- observability — this unit is observability: per-agent rows a reader sums by role and item.
- risks — the locate and method alternations name gov's own documents; an adopter's differently named
  method files count as `content`, as the instrument would have counted them.
- testing — AC1 to AC9 by `python -c` probes and scratch fixtures; the arms of §7 at the close.
- migration — as §4 says.
- user docs — `help/roles.md` by S8.
