## Blocker

### B1 — Unit 52 S16's `--legs-for` route reads every home directory as covered by its own descriptor row (id 11)

- **Where:** spec-52 section 2 S16; section 4 Alternatives rejected, "Keep unit 48 S16's own covered rule"; section 6 AC6.
- **What is wrong:** S16 passes the required set to `check-spec-tokens.py --legs-for -`, and that set is unit 48 S14's `{prefix}/<home>/kit.toml` keys plus S17's `{prefix}/<home>/` dirs. `check_guard_trips` (design_lib.py:589-598) is symmetric for a directory: a path ending in `/` trips any guard below it. The skeptic's re-run printed `tools/hooks/` with `govkit selftest <- tools/hooks/kit.toml`. tools/gate-legs.json already carries the descriptor rows (:1446, :1800-1836).
- **Consequence:** Deleting any `{prefix}/<home>/` row leaves the home reading as covered, so the arm never reds. A change to, say, `tools/roles/roles_lib.py` then skips `govkit selftest` while the arm stays green. The arm certifies the coverage unit 50 exists to enforce, and it never checks it. Unit 48's own one-way rule (spec-48 :264) would have caught this.
- **Fix (skeptic judged SOUND):** Keep the one-way direction for a required directory. Use `--legs-for` only for required FILE paths. For a required directory, test whether `govkit selftest` carries a guard equal to it or above it (`p == g or p.startswith(g + '/')` after rstrip), never a guard below it. Add an AC: over a scratch legs copy that keeps `{prefix}/roles/kit.toml` and drops `{prefix}/roles/`, the arm names `tools/roles/` as uncovered. The build runs the staged break: it removes one home row and observes the arm red.
- **Left-shift gate:** a bug-class checklist entry: "a coverage check over directory paths uses a one-way rule, never the symmetric trip". Back it with a check_policy fixture that feeds a directory plus only a child guard to every coverage arm and expects `uncovered`.

### M2 — Unit 51's liveness read drops the creation time, so the cleanup kill can hit a reused pid (id 2)

- **Where:** spec-51 section 2 S2 and S5; section 4 design line `state(pid)` (:93); section 5 (:142).
- **What is wrong:** `read_process_created` (measure_legs.py:1466-1493) returns `(state, creation FILETIME)` specifically because pids are reused. The design takes `[0]` and discards the creation time. S5 runs `taskkill /F /PID <pid>` "whatever the verdict", even after the stub is dead and reaped.
- **Consequence:** Once the Popen handle is released, Windows may reuse the pid during the 15 s poll. The path is narrow.
- **Fix (skeptic judged SOUND):** In S2, keep the `(state, created)` pair. Record `created` at the pre-interrupt `live` read, and treat a later `live` with a different `created` as `dead`. In S5, kill only when the state is `live` with the recorded `created`. Add an AC case that monkeypatches the reader to return a different creation time and asserts that no kill is issued.
- **Left-shift gate:** a policy check that flags `read_process_created(...)[0]` (the creation time dropped) at any call site that later kills that pid.
