- **Fix (judged SOUND by the skeptic):** Grade the content, not the prefixed line. ### H2. The single bounded runner does not bound a child whose descendant holds stdout open on Windows (id 27)

- **Where:** `2026-10-26-spec-TOOL-dFurnishedOrders-37.md` §2 S12, with unit 34 S2 and AC2 and unit 37 AC8.
- **What is wrong:** S12 makes `run_slot_reader` the one runner, and it copies handoff.py:268-276's shape: `subprocess.run(..., capture_output=True, timeout=...)`. On a timeout, CPython 3.14's `run()` kills only the direct child. On Windows it then calls `communicate()` with no timeout, which waits until every holder of the pipe closes it.
- **Consequence:** Suppose `breakpoints.py list`, the `turns` read, a git read or the bash kickoff checker leaves a descendant holding the pipe. Then `derive_attended`, and the dispatch that asked the owner door, hang with no bound. That is the hang unit 34 S2 and unit 37 S12/S26 exist to close. Unit 34 AC2 and unit 37 AC8 stub only a sleeping direct child, so both go green. Unit 37 S14 prices the stdout-holder case, but only for the card's shell bound.
- **Fix (judged SOUND by the skeptic):** State in S12 that `run_slot_reader` must bound a child whose descendant holds the pipe. One way is to write output to a scratch file instead of a pipe, as manifest-check.sh:405-409 does. Another is Popen with its own `wait(timeout)` plus a process-tree kill (CREATE_NEW_PROCESS_GROUP/`taskkill /T` on Windows, a process group on POSIX), with no untimed `communicate()` after the kill. Add a stub to unit 34 AC2 and unit 37 AC8 that backgrounds a sleeper holding stdout and exits 0, run it on Windows, and assert that the call returns within the bound plus a grace period.
- **Left-shift gate:** a bug-class checklist entry for "bounded through a pipe is unbounded" (C14). Pair it with a lint that flags `subprocess.run(..., capture_output=True, timeout=...)` in kit code that claims a wall-clock bound.
- **Related:** M16 (id 21) reports the same mechanism at medium.
