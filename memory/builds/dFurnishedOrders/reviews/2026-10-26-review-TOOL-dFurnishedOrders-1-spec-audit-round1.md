## Blocker

### B1. Unit 6's verifier exemption never fires on a real work order, and AC2 certifies it on a block name nothing produces (ids 1, 48)

- **Where:** spec-6 §2 S4, §4 "The decision" (:120), §6 AC2 (:241-244), §8 F6; against spec-5 §2 S1 and §4 "The values".
- **What is wrong:** S4 exempts a read only when it sits under a `### input:<name>` block whose `<name>` is in the role's `verifies`. Unit 5 fixes `verifies` to the class words `subject`, `claim` and `verdict`. Real work orders name their input blocks after the slot: every `reads:` line under tools/roles/agents/ names only `input:spec`, `input:diff`, `input:question` or `input:prompt`. No role reads `input:subject`, `input:claim` or `input:verdict`, and `input:claim` appears in the spec set only in spec-6 AC2.
- **Consequence:** Under the default `refuse` (spec-6:184), a reviewer's read of the spec or diff it reviews, and a skeptic's or tester's read of what it checks, is refused as an answered call. The clause names exactly this independence case as never answered. AC2 passes only because it plants an `### input:claim` block, so it certifies an exemption on a population the hook never sees.
- **Fix (judged SOUND by the skeptic, both findings):** Key the exemption on the input slots a role reads, not on class words. Either have unit 5 S4 write a per-role mapping from VERIFY_CLASS to `reads` keys into the role index (for example `gov-reviewer: input:spec, input:diff`), or spell `verifies` entries as input keys. Rewrite AC2 on the shipped values: a gov-spec-reviewer (`verifies: subject`) reading a range handed under `### input:spec` exits 0, and gov-builder reading the same range is refused.
- **Left-shift gate:** a spec-lint rule that every block name a criterion plants as `### input:<x>` appears on some shipped role's `reads:` line, so a fixture cannot certify a synthetic population.

## High

### H1. The run's launch prompt reads as owner presence, so an unattended run holds forks "asked live" until its first keepalive (ids 3, 19, 52)

- **Where:** spec-16 §2 S1, §4 "The attended table" and the paragraph after it, §4 "Rollout" (:189-191).
- **What is wrong:** `derive_attended` answers attended whenever the session's newest turn is owner-opened. `scan_owner_turns` (tools/runlog/extract.py:946-949) returns every owner event of the main file, and OWNER_VIA counts `typed`. An unattended run is launched by the owner's typed prompt, and keepalive fires only on idle. The skeptic reproduced this on the live session: the first event is `owner typed` and every later one is `keepalive`. The spec's claim that "an unattended run's turns are opened by keepalive fires" and "nothing changes for it" is false for the whole first turn. F1 chose option (a) without excluding the opening prompt.
- **Consequence:** Under `attendance = unattended`, every FORKED `--dispatch` and gated `--phase` before the first keepalive fire takes S4's `write_owner_hold` path and is refused for an absent owner. `run.on-owner-question` never decides it, nothing times the hold out, and the run stalls. On a host with cron disabled (CLAUDE_CODE_DISABLE_CRON), no keepalive ever fires and the whole run reads attended.
- **Fix (judged SOUND by the skeptic, all three findings):** Do not count the launch turn as presence. Read attended only from an owner turn newer than the run's start: after the run-state file's START stamp, after the mandate turn, or after the most recent keepalive arm. Alternatively, treat a session holding the build's unattended lease as away until an owner turn postdates the lease's start. Add an AC1 case: a planted transcript whose only owner turn is the typed launch prompt, with no keepalive, under `attendance = unattended` (and an active run lease), reads away.
- **Left-shift gate:** a bug-class checklist entry, "presence derived from the newest owner turn must exclude the turn that launched the unattended run", with a required AC shape covering the launch-only transcript.

### H2. Unit 19's per-order schema has no rule for alternative outcome arms, so a valid refused or probe return fails or goes unvalidated (id 4)

- **Where:** spec-19 §2 S4, §4 "The type map" (:113-124) and SCHEMA_KEYWORDS (:126-127); against spec-15 §4 "Rendered return".
- **What is wrong:** S4 builds the schema from "the role's composed template", and that template carries alternative arms (`- or outcome: refused — rule, remedy, actor`, `- or outcome: probe — ...`, and unit 7's `contradicted`). The type map has no row for an arm. The closed SCHEMA_KEYWORDS set has no `anyOf`, `oneOf` or `if/then`, and AC10 makes any such keyword raise. No criterion checks an arm return against `check_return_schema`.
- **Consequence:** If the template's non-optional fields are `required`, a valid `refused`, `probe` or `contradicted` return lacking `evidence` fails the schema and is retried until `roles.retries` is spent. If the arm fields are dropped, the arms go unvalidated. The builder must invent one of these.
- **Fix (finder's proposal REJECTED by the skeptic; the skeptic's corrected fix):** Admit `anyOf` to SCHEMA_KEYWORDS and evaluate it in `check_return_schema`. Render the return schema as `anyOf` over one branch per outcome: the template's branch, with `outcome` an enum of the template's own outcomes and its non-optional fields required, plus one branch per arm, with `outcome` const to the arm's outcome and the arm's fields required. Put `establishes` and `upstream` in a shared `allOf` part. Add an AC: well-formed refused, probe and contradicted returns pass `check_return_schema` for gov-builder, and a refused return missing `remedy` fails.
- **Left-shift gate:** a spec-lint rule that a schema derived from a composed template carries one criterion per outcome arm, run against the derived schema.

### H3. Unit 4's upgrade-step scan flags frozen records, so `up` fails on every update (id 50)

- **Where:** spec-4 §4 "The upgrade steps" (:186-190), §2 S7.
- **What is wrong:** For `checklist` and `prebuild`, `witness` and `up` scan every tracked file outside the installed kit files for the per-pass command or the retired key, and `up` exits 1 listing each hit. - **Fix (judged SOUND by the skeptic):** Limit the scan to executable call sites: files that invoke `unattended-unit.js` (Workflow scripts, and shell or JS sources outside `<MEMORY_ROOT>/`), matched on the args key, not on prose. State that records under MEMORY_ROOT and markdown are out of scope. Add a fixture with a record quoting the command, where `witness` must exit 0.
- **Left-shift gate:** a bug-class checklist entry (class absence-assertion-over-whole-file-text): an upgrade-step witness must name the file population it scans and exclude frozen records, with a fixture that plants a quoting record.
