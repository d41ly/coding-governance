## 1. Goal

Gov's own flow and role settings ship as every adopter's defaults, and the legs no descriptor declares
sit in its manifest (gap-found-32). This unit gives the owner the census the clause names: the legs no
descriptor declares, gov's efforts and grants, and its run conf and gate environment values, one row
each, keyed as an owner item, ruled once, and the rows the owner rules gov-only moved to gov's own
overlay and policy file. It changes nothing on its own: a row moves only on the owner's ruling, through
the door that owns its destination (IA-6, FA-1, flow-roles-adoption item 18).

## 2. Scope (IN)

Build-run preconditions this unit calls and does not build, each specced and unbuilt at base
`0d1c1dda`: the `ruling` record kind and its door `gov_record.py new ruling` (TOOL-dLinkedLibrary-8
S1, S5; TOOL-dTotalRecall-2 S1 to S4) with the `accept|decline` values a `<source>#<name>` subject takes
(DEPL-dShippedRelease-28 S3); the overlay `.governance/instructions.toml`, `read_overlay_rows` and
`instructions_edit.py add --manifest overlay` (PLAY-dOrderedCharter-31 S4, -35 S1, -15); the
`[[gate-leg]]` overlay row `leg.adopter.<name>` (TOOL-dWitnessedBar-28 S10); `policy_edit.py set`
(TOOL-dDeclaredLoop-2 S4). S1, S2 and S5 need none of them; S3 and S4 announce each absent one and
move nothing (§4 "Absent parents").

- **S1** — The census verb, `python tools/govkit/settings_census.py --report [--root <dir>]`,
  gov-internal and read-only. It prints one row per member of the four populations of §4 "The
  populations", each keyed `<source>#<name>` (the ruling key DEPL-dShippedRelease-28 S2 spells), with
  its population, gov's value where it has one, and its state (§4 "The states"), then one summary line
  `census: <n> rows · <u> unruled · <a> accepted · <d> declined · <o> owed · <x> undeclared`. Every
  count is derived on each run and none is typed. Observed by AC1.
- **S2** — The leg population is derived, never read from the exemption list. `derive_leg_claims(root)`
  is extracted from govkit selfcheck's check 7h (`tools/govkit/govkit.py:2535-2690`): it returns the
  manifest's leg names, the descriptor claims and the `[[exempt_leg]]` rows. Check 7h calls it in place
  of its inline reading, its findings and its note unchanged, and the census calls it too. A manifest
  leg no descriptor claims is a census row; one no `[[exempt_leg]]` row covers either reads
  `undeclared · govkit selfcheck 7h reds it`, and `--check` exits 0 on it: check 7h
  (`tools/govkit/govkit.py:2686-2690`) already fails that leg, so the census reports the row and never
  reds the same fact a second time with a second remedy. Observed by AC2, AC3.
- **S3** — The ruling join. `read_census_rulings(root)` reads every `ruling` record whose `Subject` is a
  census key, through the record factory's reader, and the census reads each row `unruled`, `accepted`
  or `declined`. A ruling is the owner's, written through the door on the owner path; for each unruled
  row `--report --commands` prints the one `gov_record.py new ruling` command that rules it, and the
  census writes no ruling itself. A row with no ruling is left as it is and reads `unruled`; the census
  exits 0 over any number of them. A ruling whose subject names no census row is printed `stale ruling`
  and is not a red. Observed by AC4.
- **S4** — The moves, `--apply <key>`, for an `accepted` row only, through the door its population
  names in §4 "The populations": a leg as a `[[gate-leg]]` row tagged `leg.adopter.<slug>` in gov's
  `.governance/instructions.toml` through `instructions_edit.py add --manifest overlay`, its
  `[[exempt_leg]]` row then taken out of `tools/govkit/registry.toml` only once the overlay is read to
  hold the row; an effort as a
  `roles.effort.<slot>` or `roles.effort.<workflow>.<stage>` value in gov's `.governance/policy.toml`
  through `policy_edit.py set`; a grant as a `[[role]]` patch `amends=role.<slot>@<hash8>` adding the
  leg to `gates`, through `instructions_edit.py add`; a run conf or gate environment value is moved by
  PLAY-dConvergedCharter-11's fold, which writes gov's value into gov's policy file, so `--apply` on one
  prints `moved by the fold` and writes nothing. An `unruled` or `declined` key, or an absent door,
  exits 2 naming why and writes nothing. An `accepted` row whose door is installed and whose move is not
  done reads `owed`, and `--check` exits 1 naming it. Observed by AC5, AC6.
  After every door call `--apply` re-reads the destination, the overlay through `read_overlay_rows`,
  the policy file through `policy.py get`, and reads the move done only where the destination holds
  the row. A door that printed a proposal and wrote nothing, which is what `instructions_edit.py` does
  for an agent caller under `instructions.edit`'s default `owner-command-agents-propose`
  (`tools/policy/catalogue.toml:647-649`), leaves the row `accepted · held: the door proposed`, exit 0
  naming the proposal, and nothing else is written: the `[[exempt_leg]]` row stays. The two writes of
  a leg's move are ordered and reversible: before the door runs, `--apply` takes before-images of
  `.governance/instructions.toml` and `tools/govkit/registry.toml` through TOOL-dSafePassage-1's
  helpers, writes the overlay row through the door, confirms it, then removes the exempt row; on any
  failure after the first write it restores both before-images byte for byte and exits 2 naming the
  step that failed, so no leg is left both overlay-claimed and exempt, nor neither. Observed by AC9 and
  AC10.
  **Readers:** by name: `tools/govkit/registry.toml`, which holds the `[[exempt_leg]]` row a moved leg
  leaves. by value: `tools/govkit/govkit.py` (check 7h, through `derive_leg_claims`, which reads the
  moved leg as claimed by gov's overlay row once TOOL-dWitnessedBar-28's composition lands) and
  `settings_census.py` itself.
- **S5** — The run conf's extension keys are not owner items. The `.unattended.conf` keys matching
  `_EXTRA` or `_EXTRA_TABLE` (`DIRECTIVES_EXTRA`, `DIRECTIVES_EXTRA_TABLE`, `PHASES_EXTRA`, `DOD_EXTRA`,
  `HALT_CODES_EXTRA`, `HOLD_CODES_EXTRA` at base) read `leaves-with PLAY-dConvergedCharter-12`, the unit
  whose kit takes the conf with it, and take no ruling. Observed by AC7.
- **S6** — `help/policy.md` gains a section "Gov's own settings census": the four populations, the
  states, how the owner rules a row, and that an unruled row stays as it is. Observed by AC8.

## 3. Non-goals (OUT)

- Ruling any row. The owner rules; the census reads and reports, and `--apply` moves only what the
  owner accepted.
- The fold of the run conf and gate environment keys into the policy file, their catalogue rows and
  their readers: PLAY-dConvergedCharter-11. The census reads gov's values; it never folds one.
- Removing `.unattended.conf` and its extension keys with the kit: PLAY-dConvergedCharter-12.
- The house file's retirement as a seed and gov's defaults shipped in the role definitions:
  PLAY-dConvergedCharter-21. The census rules gov's own values, not an adopter's.
- An adopter's customizations: DEPL-dShippedRelease-28's `adopt declarations`, which proposes nothing
  for gov while gov's house file reads gov's own seed (its §4 Rollout).
- IA-6's census of the charter's practices: dOrderedCharter's. This unit is the flow and role half.
- Shipping the census to adopters. It reads gov's registry and manifest, which no target holds.

### The populations

| Population | Read by | Key | Gov's value | Door for an accepted row |
|---|---|---|---|---|
| a leg no descriptor declares | `derive_leg_claims` | `gate-legs.json#<leg name>` | its manifest argv | `instructions_edit.py add --manifest overlay`, a `[[gate-leg]]` row `leg.adopter.<slug>`, then its `[[exempt_leg]]` row taken out |
| an effort | `load_policy`'s `effort` tables | `house/policy.toml#effort.default`, `#effort.roles.<slot>`, `#effort.stages.<workflow>.<stage>` | the level | `policy_edit.py set roles.effort.<…> <level>` |
| a grant | `load_policy`'s `gates` table | `house/policy.toml#gates.<slot>` | the leg names | `instructions_edit.py add`, a `[[role]]` patch adding to `gates` |
| a run conf or gate environment value | `legacy-homes.txt` rows of `.unattended.conf` and of `.githooks/gate-env.sh` marked `owner-policy` | `.unattended.conf#<KEY>`, `.githooks/gate-env.sh#<KEY>` | the home's last `<KEY>=` line, parsed as text | none: PLAY-dConvergedCharter-11's fold |

`<slug>` is the leg name lower-cased, every run of characters outside `[a-z0-9]` one `-`, trimmed of
`-` at both ends. `roles_lib` is loaded through the inlined `resolve_kit_dir("roles", "roles_lib.py",
here)` as `check_policy.load_tree_lib` loads `tree_lib`, and `load_policy` is called with the roles and
workflows `roles_lib.load_roles` and `load_workflows` return, as `check_roles.py:367` calls it.

### The states

| State | When | `--check` |
|---|---|---|
| `unruled` | no ruling names the key | 0 |
| `declined · kept` | a `decline` ruling: read as a drop, the row stays where it is | 0 |
| `accepted · held: <door> not installed` | an `accept` ruling and the population's door absent | 0 |
| `accepted · held: the door proposed` | an `accept` ruling, and the door printed a proposal and wrote nothing | 0 |
| `accepted · moved` | an `accept` ruling and the destination holds the row: an overlay row with the tag, a policy value, a role patch, or for a value the folded key in gov's policy file | 0 |
| `owed` | an `accept` ruling, the door installed, the destination not holding the row | 1 |
| `leaves-with PLAY-dConvergedCharter-12` | a run conf extension key (S5) | 0 |
| `undeclared · govkit selfcheck 7h reds it` | a leg no descriptor claims and no `[[exempt_leg]]` row covers | 0, check 7h owns the red |

A mechanic gate environment key is no item: the summary line counts them as
`<m> mechanic keys stay`, since v2 folds only the owner-policy keys (§8 F3).

### Absent parents

Until the `ruling` kind lands, `read_census_rulings` prints `rulings: not installed — every row reads
unruled` once and returns none; until a door lands, an `accept` row reads `held`. Each absent parent is
named, never read as an empty population. With no `.unattended.conf` or no gate file the population
prints one line naming the absent home, as `derive_legacy_homes` notes it.

### Alternatives rejected

- **The exempt set as the leg population.** It equals the undeclared set only while check 7h is green,
  so a leg added with no exemption would never reach the census. Rejected by AC2's planted leg.
- **A source mode of `adopt declarations`.** DEPL-dShippedRelease-28 reads a repository's values
  against gov's and proposes nothing for gov itself, so a gov mode re-specs a parent's unbuilt verb;
  §8 F1.
- **A ruling vocabulary of its own, `gov-only|shipped`.** It needs a third closed set on the `ruling`
  kind; `accept|decline` on the same `<source>#<name>` subject already reads "move it" and "drop the
  proposal". §8 F2.
- **A census verb that writes the ruling.** The door's owner path is the one writer of a ruling;
  printing the door command keeps the census read-only. §8 F4.

## 5. Production-readiness checklist

- security — read-only except `--apply`, which writes only an owner-accepted row and only through the
  door that guards its destination, refusing an unruled or declined key; the census writes no ruling,
  and never removes an exempt row the door's write did not replace.
- perf / scale — one pass over the manifest, the registry, the descriptors, the house file and two
  homes; about 150 rows at base.
- error / empty / loading states — an absent home, kind or door is one named line (§4 "Absent
  parents"); a manifest that does not parse exits 2 naming it. A door that proposes reads `held`; a
  failed write after the first restores both files from their before-images and exits 2 naming the
  step (S4).
- observability — the summary line, and one row per member with its state.
- risks — a ruling naming a leg that later leaves the manifest prints `stale ruling`; the owner rules
  again or not at all.
- testing — the fixture cases of §6 and the arm in §7.
- migration — none: gov's tree only; the run conf and gate rows move by unit 11's fold.
- user docs — `help/policy.md`, S6.

## 6. Acceptance criteria

tree under `%TEMP%` with a short name: a manifest of three legs, a registry with one descriptor
claiming one leg and one `[[exempt_leg]]` row, a house file, a run conf with two keys and one `_EXTRA`
key, and a gate file with one `owner-policy` and one `mechanic` key. Case `baseline` is that tree;
each other case plants one change.

  `grep -c '^\[\[exempt_leg\]\]' tools/govkit/registry.toml`, it prints one row per house effort and grant, one per
  `owner-policy` row of the two homes in `legacy-homes.txt`, every key in `<source>#<name>` form, and
  the summary line's counts sum to the rows printed.
  Red when: a population is read from a typed list, or a `mechanic` key prints as a row.
  figure: DERIVED, every count re-read at observation.
