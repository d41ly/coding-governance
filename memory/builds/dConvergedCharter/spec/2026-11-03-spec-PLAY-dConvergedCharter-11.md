## 1. Goal

v2 keeps every key in `.governance/policy.toml`, but five kit confs and the gate environment file still
hold about a hundred keys beside it, on the shrink-only list dGroundRules derived (v2:1126-1134,
v2:2006-2008; RC-3, M7). This unit folds every key that list holds, the retrofit's cutoffs and pins
excepted, into the policy file with a catalogue row, gives every reader one way to read a folded home
before and after the fold, inventories a folded key's readers by value, re-points the readers that
inventory derives, and reds a reader still on its old home (DA-H5, DA-M6). The readers the clause
names and the house-file arm are PLAY-dConvergedCharter-41's, by the owner's split of 2026-11-04.

## 5. Production-readiness checklist

- security — no reader sources a home: S3 prints shell-quoted `KEY=<value>` lines for keys matching
  `[A-Z][A-Z0-9_]*`, and reads the policy file as committed, at `--rev` or `HEAD`, never the working
  tree. The policy file is written only by the owner's terminal commit (S2's commit route), never past
  the policy guard; scratch-guard's write gate stays armed when a home is deleted (S4).
- perf / scale — one interpreter start per reader per home in place of a `source`; none for the bar's
  procmon question, answered in the legs-parse python; `readFoldedKey` spawns git twice per hook call,
  never bash.
