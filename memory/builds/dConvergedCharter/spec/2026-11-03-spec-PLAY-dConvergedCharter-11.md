## 1. Goal

v2 keeps every key in `.governance/policy.toml`, but five kit confs and the gate environment file still
hold about a hundred keys beside it, on the shrink-only list dGroundRules derived (v2:1126-1134,
v2:2006-2008; RC-3, M7). This unit folds every key that list holds, the retrofit's cutoffs and pins
excepted, into the policy file with a catalogue row, gives every reader one way to read a folded home
before and after the fold, inventories a folded key's readers by value, re-points the readers that
inventory derives, and reds a reader still on its old home (DA-H5, DA-M6). The readers the clause
names and the house-file arm are PLAY-dConvergedCharter-41's, by the owner's split of 2026-11-04.

## 5. Production-readiness checklist

- security — no reader sources a home: S3 prints shell-quoted `KEY=<value>` lines for keys matching
  `[A-Z][A-Z0-9_]*`, and reads the policy file as committed, at `--rev` or `HEAD`, never the working tree.
- perf / scale — one interpreter start per reader per home in place of a `source`.
- error / empty / loading states — an absent home with no policy value prints nothing and each reader's
  default stands; a reader whose `legacy` call fails, or a hook whose mirror does not parse, refuses (S4).
- observability — `policy.py get --explain` names a folded key's source; the arm prints every exempt row.
- risks — a reader that read its home from the working tree now reads the policy file at `HEAD`, so an
  uncommitted policy edit takes effect at its commit; a hook reads the working tree's mirror, so an edit
  reaches it once `mirror --write` renders it, which mirror parity holds at each commit.
- testing — the fixtures of §6 and the arms of §7. migration — §4 Migration; adopters:
  PLAY-dConvergedCharter-20. user docs — `help/policy.md`.
