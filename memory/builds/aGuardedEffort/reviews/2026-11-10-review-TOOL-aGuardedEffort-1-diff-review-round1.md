## HIGH

### 1. Rule 8 grades an unset Workflow stage from the policy's slot, never from the call's own `roles` (ids 1, 5)

**Where:** `tools/hooks/agent-cap.js:893-897`, in `checkEffortLevel`'s Workflow loop.

**What is wrong:** For a stage that carries no `efforts` value, the rule takes the level from `e.unset[w][key]`. That is the level of the slot the POLICY maps the stage to. The harness spawns the stage as `args.roles[key]`, and falls back to `workerType` or `general-purpose` when the key is left out (`tools/workflows/tier2-review.js:540-543`; `unattended-build.js:581` and `unattended-unit.js` likewise). Rule 6 (lines 766-774) only requires each `args.roles` value to be some agent-true role, in any mapping and with keys left out. So the level rule 8 grades is not the level the stage runs at whenever the call's map differs from the table's.

**Consequence:** The rule certifies a level it did not check. Read-only probes of the exported `checkEffortLevel` over the committed `.claude/roles.json` all returned null (admitted):

- `unattended-unit.js`, `roles:{builder:'gov-skeptic'}`, no `efforts`, model `claude-opus-4-8`. gov-skeptic renders at medium; the table expects high.
- `tier2-review.js` with synthesis remapped to `gov-skeptic`, no `efforts`. Synthesis runs at medium against the expected high.
- `tier2-review.js`, `roles:{skeptic:'gov-skeptic'}` alone. The finder and synthesis stages spawn untyped at the session's level, which no table holds.
- Model `claude-fable-5-2`, `diffFinder` and `skeptic` mapped to `gov-builder`, `efforts:{synthesis:'medium'}`. Two stages run at high where the profile expects medium.

The reverse also holds: on `claude-fable-5-2`, `roles:{builder:'gov-researcher'}` is refused as "would run at high" although that type renders at medium. The refusal text would name a level the stage does not run at. Neither the header's WHAT IT DOES NOT CHECK list nor the spec names the gap. Graded high, not blocker: the call must depart from what `handoff.py harness-args` prints, a narrow path.

**Fix (id 5: the finder's fix was REJECTED by the skeptic; this is the skeptic's corrected fix. id 1: fix judged SOUND by its skeptic):** In the Workflow loop, for a stage key with no `efforts` value, take the seen level from the call: `e.default.roles[a.roles[key]]` when `a.roles` holds the key. When it does not, push the key to that workflow's `differing` list, since the stage would spawn untyped at the session's level. Do not return or refuse at once. The call is then admitted only when one whole workflow has no differing key, as now. Word the refusal from the role the call names. Keep `unset` only if it is still needed as a cross-check, or drop it from the index.

The two judged fixes differ on one point. Id 1's fix refuses outright when `args.roles` leaves a key out. The id 5 skeptic showed that an immediate refusal on a two-workflow harness refuses every `tier2-review.js` call, because a spec-review call carries no `diffFinder` and a closing-review call no `specFinder`. Use the `differing`-list form, which gives id 1's refusal on a one-workflow harness and stays correct on a two-workflow one.

Add arms to the rule 8 section of `tools/hooks/agent-cap.test.sh`: a swapped role with no `efforts`, and an omitted role key with no `efforts`, each on a one-workflow and a two-workflow harness, each exit 2. Stage each red against the current code first.

**Left-shift:** The arms above land in the `agent-cap self-test` leg. Add a checklist entry: a guard that grades a value derived from the policy must read the value the call itself carries. Class `invariant-held-on-one-admission-path`.

### 3. A workflow with no `stages` entry admits every call to its harness, silently (ids 4, 6)

**Where:** `tools/hooks/agent-cap.js:890-899`; the shape is produced by `tools/roles/render_agents.py:220-236` and accepted by `tools/roles/check_roles.py:277`.

**What is wrong:** `const stages = (table.stages && table.stages[w]) || {}` fails open. The loader (`tools/hooks/scratch-guard.js:990-995`) checks only that four keys are plain objects. Every sibling lookup in this function throws (lines 868, 879, 894), and its own comment at 835-837 says a missing stage throws.

**Consequence:** Contained today: all four shipped driven workflows carry `stages`. A partial or older-shape index, or the next stageless workflow driver, opens it. A harness serving one staged and one stageless workflow then admits every call at any level. A sole stageless harness is admitted with an empty stderr, although `tools/hooks/README.md` promises one stderr line for a level the rule cannot check. Reproduced both ways: with `effort.profiles.fable.stages.build` deleted, and with a `nostage` workflow added to the `tier2-review.js` harness in memory.

**Fix (id 4: the finder's fix was judged INSTANCE-ONLY; this is the skeptic's class-level fix. id 6: fix judged SOUND, with one renderer option excluded):** Grade over the keys of `e.unset[w]` unioned with the keys of `table.stages[w]`. Throw when either side lacks a key the other holds; that covers a missing `stages[w]` entry and a partial one. A workflow with an entry in neither map has no stage keys. Do not let it satisfy the at-least-one-workflow admit while a sibling workflow of the same harness is staged. When no workflow of the harness has any stage key, admit with a not-checked note that says so. In `derive_effort_index`, keep the harness entry and emit an explicit empty `stages`/`unset` entry for a stageless workflow. Do not build `harnesses` from `staged` alone: a stageless-only harness would then hit the throw at line 879 and be refused on every call.

Add arms: a deleted `stages.build`, and a deleted single stage key, each exit 2 naming `render_agents.py --write`; and a hand-written index holding a keyed and an unkeyed workflow on one harness.

The finder's proposal for id 4 (throw only when `e.unset` has an entry for `w` and `table.stages` has none) cures the cited instance alone. It still skips a `stages[w]` that lacks one key, and a stageless sibling still admits silently.

**Left-shift:** The arms land in the `agent-cap self-test` leg. Add a checklist entry for the new class `lookup-defaults-to-empty-and-admits`: an `|| {}` on a table lookup inside a guard is an admit, and needs either a throw or a printed not-checked note.
