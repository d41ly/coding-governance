## 1. Goal

The design as built becomes a product artifact: `DESIGN_VIEW` is rendered by the memory-tree kit from
`DESIGN_RECORD` at `DESIGN_BASELINE` with each deviation record's `amends` or `supersedes` row
applied, each changed clause citing its record, and the build-index generator's `--check` refuses a
hand edit, a deviation with no row and a changed clause with no citation. It closes `gap-mem-47`'s
"no view gives the design as built", and is the product successor the retirement table names for
the bootstrap instrument `asbuilt.py`.

## 2. Scope (IN)

- **S1** — The generator, `tools/memory-tree/asbuilt_view.py`. It reads the three S2 keys of
  `.memory-tree.conf` through `design_lib.py` (TOOL-dTrueNorth-1): the clauses from `DESIGN_RECORD`
  at `DESIGN_BASELINE` (`git show`), parsed by `read_chain_clauses`, and every deviation record
  through `deviation_join.read_records`, each record's `**Departs from:**`, `**After:**` and
  `**Follow-through:**` as `read_record` returns them (TOOL-dTrueNorth-4). Observed by AC1 and AC6.
- **S2** — The row, read from the record's `**Follow-through:**` line as the bootstrap instrument
  reads it (`asbuilt.py:58`): `amends <clause id>@<hash8>` puts the record's `**After:**` in the
  clause's place; `supersedes <clause id>@<hash8> by <clause id>` puts the new id and its `**After:**`
  there. The row's last cell cites `deviation` and the record's id, an unchanged row `baseline`.
  When two records name one clause, the later file by path supplies the row, as the instrument's
  ordering does. Observed by AC7 and AC9.
- **S3** — The identity (brief S8): on the same records the generator renders, byte for byte, what

## 4. Design

### The module, `tools/memory-tree/asbuilt_view.py`

- `read_view_inputs(root, conf)` → `(sha, clauses, records, serves, findings)`: `sha` is
  `DESIGN_BASELINE`; `clauses` are `design_lib.read_chain_clauses` over `git show
  <DESIGN_BASELINE>:<DESIGN_RECORD>`, `(build, clause id, text, hash8)` in row order; `records` are
  `deviation_join.read_records(root, conf)`, every file the instrument's glob
  `<MEMORY_ROOT>/builds/*/build/*-deviation-*.md` matches, sorted by path; `serves` is the first
  `**Serves:**` line of `DESIGN_RECORD`'s working tree, verbatim; and `findings` holds the moved
  `Baseline:` line when it differs from the pin.
- `render_view(sha, clauses, records, serves)` → `(text, findings)`, a port of `asbuilt.py:54-79`
  that keeps every byte: the four head lines, the table head `| Build | Clause | Text | Since |`, one
  row per baseline clause, the record count over every record read, a trailing newline.
- `check_view(body, rendered, clauses)` → findings, a port of `asbuilt.py:82-93`: the first
  differing line, and each `baseline` row whose text differs from its clause's, read with the
  instrument's row regex (`asbuilt.py:33`).
- `VIEW_HEAD`, one constant holding the head's prose with three slots, the `**Serves:**` line, the
  sha and the record count. Its `Generated by` names
  `build/2026-10-19-build-PLAY-dClosedLoop-1-asbuilt.py`, the instrument's own head (§8 F2).

The CLI, from the worktree root:

```
python3 tools/memory-tree/asbuilt_view.py --write [--out <path>]
python3 tools/memory-tree/asbuilt_view.py --check [--out <path>]
python3 tools/memory-tree/asbuilt_view.py --fixture [--plant <case>]
python3 tools/memory-tree/asbuilt_view.py --selftest
```

`--out` defaults to `DESIGN_VIEW`, as the instrument's `--out` defaults to its `OUT`. Exit 0 green, 1
on a finding, 2 when the pin's design record cannot be read. The fixture renders in memory from the
tree's own `DESIGN_RECORD` at its pin, never a synthetic chain, damaged one way per plant:
`hand-edit`, `no-row`, `no-citation`, `baseline`, `pin-mismatch`, `supersedes` and `amends-reader`,
the first four ported from `asbuilt.py:96-122`.

### The host, `gen_build_index.py`

`cmd_check` and `cmd_write` each call `asbuilt_view` once, after every artifact `plan()` returns, so a
view finding never blocks another artifact's write; `plan()`'s five-value return is left as it is.
Drift of the view joins the existing `build-index DRIFT` list under its `--write` remedy; the other
findings print under `as-built VERDICT`, whose remedy is the record or the design record the line
names, because `--write` cannot cure them. Off, the host prints the one off line and calls nothing.

### The readers

`read_design_view` in `design_lib.py` (TOOL-dTrueNorth-1) reads the rendered table, so the coverage join, the
packet's Items hashes and the later help and atlas renders all read the view as built. The
`amends-reader` plant renders a view with one `amends` record into a temporary file and reads it back
through that reader, to observe the hash and the since cell the coverage join will read.

### Migration

None. At landing the view's bytes are the instrument's, so the file is not rewritten; from the next
record on, whichever of `asbuilt.py --write` and `gen_build_index.py --write` runs writes the same
bytes, until the report-switch step.

### Rollout

Live at landing in the dogfood tree. In an adopter the S2 keys ship blank, so the host prints its
off line and the generator reads nothing.

### Inventory

Minted: the module `tools/memory-tree/asbuilt_view.py`, its functions `read_view_inputs`,
`render_view` and `check_view`, its constant `VIEW_HEAD`, its flags `--write`, `--check`, `--out`,
`--fixture`, `--plant` and `--selftest`, and the host's `as-built VERDICT` block heading. No conf key,
no leg, no `[[generated]]` row. Naming cells: the three functions pass `py.function`
(`tools/lexicon/lexicon.py --suggest <name> --as py.function`, OK for each); a module file and a
constant fall in no declared cell.

### Alternatives rejected

- **A `[[generated]]` row of its own in `tools/memory-tree/kit.toml`.** Its `path` takes only the
  `{memory_root}`, `{map_root}` and `{kit}` tokens (`tools/govkit/govkit.py:2421-2477`) and no conf
  key, so it would spell gov's dClosedLoop path in a shipped descriptor, a `when` repeating it. The
  build-index generator already reads the conf and already has its own `[[generated]]` item.
- **A check in `check-memory-hygiene.sh`.** It is the stale-output refusal's job, and `--regen`
  cannot cure a hygiene red.
- **A head of the product's own, naming this module.** The instrument's `--check` would then red the
  view at every close until the report-switch step, and the retirement condition, byte identity,
  could not be met (§8 F2).
