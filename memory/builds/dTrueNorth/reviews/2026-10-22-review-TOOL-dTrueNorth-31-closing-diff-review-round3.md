**Where:** `tools/memory-tree/asbuilt_view.py:222` (`check_view_merge`, and `read_info_merge`); the env handling is `tools/memory-tree/design_lib.py:152-160` (`run_git`).
**What is wrong:** Round-2 M3 asked that check 30 read the view's `merge` attribute from tracked state alone. None of them neutralises a local or global `attr.tree` config or an exported `GIT_ATTR_SOURCE`. Either one sends `git check-attr` to an arbitrary tree. `run_git` strips only `GIT_ENV_LEAKS`, so `GIT_ATTR_SOURCE` passes through.

The path needs a node to set `attr.tree` or `GIT_ATTR_SOURCE`.
**Fix (skeptic judged SOUND):** In `check_view_merge` and `read_info_merge`, run the attribute reads with `-c attr.tree=` beside `-c core.attributesFile=/dev/null`, and with `GIT_ATTR_SOURCE` removed from the env. `design_lib.run_git`'s `extra_env` can only add keys, so give it a way to drop one (for example an `unset_env` tuple), or add `GIT_ATTR_SOURCE` to the strip for this call. In the probe, `-c attr.tree=` restored `unspecified`.
**Left-shift gate:** Extend `check_node_merge_arm` with a third half that sets `attr.tree` in the fixture's `.git/config` to a commit carrying the line and expects the unguarded-view finding. Observe it red against the current call.
