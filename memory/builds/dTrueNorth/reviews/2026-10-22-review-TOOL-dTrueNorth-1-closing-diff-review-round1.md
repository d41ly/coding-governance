## HIGH

### H1 — `:(glob)` revision readers read zero revisions under an ambient `GIT_LITERAL_PATHSPECS` (finding 2)

**Where:** `tools/memory-tree/design_lib.py:491` (`read_spec_revisions`, :465-508), and `tree_lib.read_adding_commits`.
**What is wrong:** Both readers depend on `:(glob)` pathspec magic. Both run git through `read_git_output`, which keeps every variable outside `GIT_ENV_LEAKS`, `GIT_LITERAL_PATHSPECS` included. With that variable set, the magic is off, the log matches nothing, and no error is raised. The docstring says an unmatchable pathspec is refused because it "would read as no revisions". The in-Python `inside` refusal does not catch it, because the path still matches the regex.
**Consequence:** A probe showed a spec with two commits reading as `{path: 2}` unset and `{path: 0}` with `GIT_LITERAL_PATHSPECS=1`, exiting cleanly. `check-spec-tokens.read_carries_specs` (check-spec-tokens.py:880) feeds those revisions to `scan_carries`, so its `stopped` arm cannot fire and the carries join reports green over a population it never read. The deviation join's spec-revision population and pin anchors (deviation_join.py:529-544) read empty in the same way. That is a check certifying what it did not read. The path is narrow, since the variable is rarely set.
**Fix (skeptic judged SOUND):** In `read_git_output`, or at least on every `:(glob)` caller, also drop `GIT_LITERAL_PATHSPECS`, `GIT_GLOB_PATHSPECS`, `GIT_NOGLOB_PATHSPECS` and `GIT_ICASE_PATHSPECS` from the env. The alternative is to pass the pathspecs without magic and filter in Python, which `read_spec_revisions` already does with `inside`.
**Left-shift gate:** An arm that runs the AC10 revision probe under `GIT_LITERAL_PATHSPECS=1` and expects the same revision count. Add the class `fixture-inherits-ambient-machine-state` to the checklist if it is absent.

### H2 — Rescope rows in a rotated RUN archive are dated by the rotation commit (finding 4)

**Where:** `tools/memory-tree/deviation_join.py:595`, calling `read_row_commit` (:316-319).
**What is wrong:** The rescope arm calls `read_row_commit(root, m.group(0), rel)`, where `rel` is the single RUN file. `RUN_FILE` also matches rotated `RUN.LANDED.*` and `RUN.ABORTED.*` archives. For an archive, the per-file pickaxe finds the commit that rotated the file, not the commit that wrote the row. The instrument it ports (`deviations.py`'s `read_row_commit(root, row, folder)` in `memory/builds/dClosedLoop/build/2026-10-19-build-PLAY-dClosedLoop-1-deviations.py`) searches the build folder. **Consequence:** Every chain build runs twice, so the spec run's RUN.md is rotated at the build run's preflight. **Fix (skeptic judged SOUND):** Run the pickaxe over the build folder, as the instrument does: `read_row_commit(root, row, f"{memory_root}/builds/{b}")`. Then the commit that first wrote the row into RUN.md wins.
**Left-shift gate:** A fixture plant that rotates RUN.md to `RUN.LANDED.<blob8>.md` after a rescope row and asserts the member's sha is the row's commit.
