# build-readme-slot-limits.txt — the HARD per-slot byte ceiling for a build README's authored half.
# TOOL-dFramedEntrypoint-2. One row per canonical slot: `<heading text>\t<ceiling in bytes>`.
#
# TWO FILES, not one. The advisory high-waters live in build-readme-slot-highwater.txt because the
# `--bump` verb WRITES that file, and a ceiling sitting inside the write path of the thing that must
# never move it is guarded only by whoever reads the diff. `tools/check-template-size.sh` splits the
# same pair for the same reason and is the seam this copies.
#
# A ceiling that FAILS the bar, measured over the AUTHORED slice only — a slot's heading line to the
# line before the next canonical heading, or before the authored roster pair where one is present.
# Never over generated bytes: every backfire of a character cap in this tree has been a generated row
# blowing an authored-prose cap, and the only remedy available silenced three checks on a whole file.
#
# A ROW WITH NO CEILING is the ANNOUNCED UNARMED state and is legal: the leg names how many slots are
# unarmed on every run. A MISSING row is a refusal, because a slot nobody priced is a slot nobody
# decided about. The two are different states and the check reports them differently.
#
# THE VALUES BELOW ARE PROVISIONAL and bind nothing today: the declared registry is empty until
# TOOL-dFramedEntrypoint-3 writes it and TOOL-dFramedEntrypoint-7 seeds it, and unit 7 owns the one
# real seeding event. They come from the corpus census this build ran — the preamble class measures a
# 525 B median and an 802 B p75, and the 45 existing build-rule bullets a 360 B median — and they are
# written here so an implementer has a shape to argue with rather than a blank.
#
# ADOPTERS DO NOT INHERIT THESE. `adopt-memory-tree.sh` scaffolds this file with its rows and NO
# ceilings, because a pin measured against this corpus and shipped into a tree that never measured it
# is either vacuous or permanently red. `kit.toml` carries the declared hole and its discharge probe.
