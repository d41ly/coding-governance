# template-size-limits.txt — the DECLARED size ceilings, keyed by measured file.
#
# GRAMMAR: `<repo-relative-path>\t<bytes>` per row. Comments carry the justification for a value and
# every movement of it, because a number with no history beside it is a number nobody can question.
# Modelled on `.memory-tree.conf`'s per-class caps, which are this tree's established answer to the
# same problem: a budget whose every movement is argued in the conf next to the figure. The original
# model was READ_PATH_CEILING, retired by TOOL-dSpentCeiling-1 after 27 movements bought no trim —
# the LESSON kept here is the argued-in-place justification, not the summed budget.
#
# WHO WRITES THIS FILE: a person, deliberately. This is NOT the high-water record — that one is
# `tools/template-size-highwater.txt`, which `--bump` WRITES as a side effect of measuring. Keeping
# them apart is the point: a mode that can move a ceiling while recording a measurement would destroy
# the ratchet's only real property, which is that raising a ceiling is a visible, deliberate act.
#
# RESOLUTION: positional $2, then THIS declaration, then the MAX_BYTES environment variable, then the
# gate's hard default. The declaration sits ABOVE the environment on purpose — see the kickoff-engine
# row below, whose insulation from the environment is a property a landed unit built and verified.
#
# A subject with no row here falls through to the environment and then the default, unchanged.
